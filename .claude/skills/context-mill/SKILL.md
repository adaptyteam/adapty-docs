# Context Mill — Docs Knowledge Map

Fast, cheap lookups over the docs tree via two committed files in
`.claude/context-mill/`:

- `docs-map.jsonl` — mechanical layer, one JSON line per article
  (id, path, sidebars, headings, symbols from code fences, components,
  links, content hash). Regenerated by script. NEVER hand-edit.
- `docs-enrichment.jsonl` — thinking layer, one JSON line per article
  (`gist`, `terms`, `update_triggers`, `for_hash`). Written by Claude
  in refresh mode. NEVER touched by the script.
- `aliases.md` — global term equivalences (task language ↔ doc language).

## Mode detection

- **Lookup** (default): user provides a dev task, Jira link, feature
  description, or symbol and wants affected articles.
- **Refresh**: user asks to update/refresh the map, or you just finished
  editing articles.

## Lookup mode

1. **Freshness check**: run `npm run mill` (fast, always safe), then
   `npm run mill:status`. If STALE/NEW lists are long and relevant to the
   task's area, warn the user that results may be incomplete.
2. **Gather the task**: if given a Jira/GitLab link, fetch it (Jira MCP or
   WebFetch). Extract: feature names, SDK method/class names, endpoint
   names, UI labels, platform scope.
3. **Expand terms**: read `aliases.md`; add doc-language equivalents for
   every extracted term.
4. **Search the map**: `grep -i` each term over BOTH jsonl files. Collect
   matching ids. Symbols and headings hit in `docs-map.jsonl`; conceptual
   phrasing hits in `docs-enrichment.jsonl` (`gist`/`terms`/
   `update_triggers`).
5. **Rank and confirm**: for each candidate, judge from its map line +
   enrichment line whether the task plausibly touches it. Read the actual
   article (path is in the map line) ONLY for candidates you're unsure
   about or that need section-level detail. Do not read the whole docs tree.
6. **Report**: a checklist table — article id, why it's affected, which
   section(s) likely need the change, confidence. List platforms whose
   sidebar has NO matching article (possible coverage gap) when the task
   is platform-spanning.

## Refresh mode

1. Run `npm run mill` then `npm run mill:status`.
2. For every id under NEW or STALE: read the article (path from its
   `docs-map.jsonl` line) and write/replace its line in
   `docs-enrichment.jsonl`:
   - `id` — article id
   - `for_hash` — copy the CURRENT `hash` from the article's map line
   - `gist` — 1–2 sentences: what the article actually covers
   - `terms` — 4–8 task-language terms a dev ticket would use, including
     ones NOT literally in the article (synonyms, old feature names,
     related endpoints)
   - `update_triggers` — 1–3 kinds of product/SDK change that would make
     this article stale
3. For every id under DELETED: remove its line.
4. Keep the file sorted by id, one JSON object per line.
5. Re-run `npm run mill:status` — must end with "Enrichment is up to date."
6. If the batch is >15 articles, dispatch parallel subagents (~15–20
   articles each writing to separate temp files under the scratchpad),
   then concatenate, sort, and validate with `npm run mill:status`.

## Rules

- Never hand-edit `docs-map.jsonl`; regenerate it.
- Never let the script or any tool overwrite `docs-enrichment.jsonl`
  except through refresh mode.
- Orphan (`"orphan":true`) and draft articles get no enrichment; they
  still surface in symbol grep.
- Enrichment `terms` must NOT repeat what's already greppable in the map
  line (title words, headings, symbols) — they exist to cover language
  the map can't match.
