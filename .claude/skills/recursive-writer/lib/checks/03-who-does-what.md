# 03 Who does what

**Applies when:** always.
**Requires:** each sentence names who acts, and that actor can do the verb.
**Evidence:** actor + verb + object (+ destination for verbs of movement).

- The reader is the subject where the reader acts or runs into a limitation ("You can't select a
  profile attribute in a condition", not "The variable picker doesn't list profile attributes");
  Adapty, the SDK, or the app's code only where it acts and the reader doesn't. In an article about X,
  make X the subject.
- Things don't act like people: a flow, event, case, or app doesn't know, ask, answer, use, offer, or
  behave. "Who" is for people, not companies. One object doesn't "become" another: name the actor and
  the action. Don't credit Adapty with what the SDK does natively. Users act; events don't happen to
  them. A summary over several actors' actions names the actor in each item.
- The verb names the actual action, with object and destination (not handles, processes, manages).
  Between systems: the sender, the data, and the receiver, with a transfer verb.
- No hand-offs between whoever works in the dashboard and whoever writes the code ("ask your
  developer", "send the names to whoever writes your app's code"): say what the app's code must do.
- Conditions are something the reader has, not something the system detects. Name the reader's
  situation, not a thing by an attribute it lacks.
- State verbs (use, have, contain, support) with a thing as subject are fine for a plain fact. If a
  person caused the state, or the reader must act on it, name that action. Evidence: who actually
  does something here.
- Active voice. Passive only when naming the actor again would be tiring (usually late in a
  paragraph), or the active version gets complicated and splitting doesn't help. Version support stays
  passive: "X is supported in SDK vN and later".
