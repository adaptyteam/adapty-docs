These Adapty CLI commands manage [products](product), map them to their App Store and Google Play product IDs, add 12-month commitment plans to yearly products, and link store offers to them.

## Products

### adapty products list

List all [products](product) for an app.

```bash
adapty products list --app <app-id>
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

Accepts [pagination flags](developer-cli-reference#global-flags).

### adapty products get

Get details for a specific [product](product).

```bash
adapty products get --app <app-id> <product-id>
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

### adapty products create

Create a new [product](product).

:::important
The store product and price IDs cannot be changed after creation. To use different store IDs, create a new product.
:::

```bash
adapty products create --app <app-id> --title "Monthly" --access-level-id <access-level-id> --period monthly --ios-product-id com.example.monthly
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--title` | Yes | Product title |
| `--access-level-id` | Yes | [Access level](access-level) ID (UUID) this product unlocks |
| `--period` | Yes | Subscription period: `weekly`, `monthly`, `two_months`, `trimonthly`, `semiannual`, `annual`, `lifetime` |
| `--ios-product-id` | At least one store required | Product ID from App Store Connect |
| `--android-product-id` | At least one store required | Product ID from Google Play Console |
| `--android-base-plan-id` | Required with `--android-product-id` unless `--period lifetime` | Base plan ID from Google Play Console |
| `--stripe-product-id` | At least one store required | Product ID from Stripe |
| `--stripe-price-id` | Required with `--stripe-product-id` | Price ID from Stripe |
| `--paddle-product-id` | At least one store required | Product ID from Paddle |
| `--paddle-price-id` | Required with `--paddle-product-id` | Price ID from Paddle |

Every product needs at least one store: `--ios-product-id`, `--android-product-id`, `--stripe-product-id`, or `--paddle-product-id`. A single product can carry IDs for several stores at once.

To sell a product on the web through Stripe or Paddle, connect the payment provider to Adapty first: see [Stripe](stripe) and [Paddle](paddle). For each of these stores, pass the product ID and the price ID together. The command fails if you pass only one of the pair.

```bash
adapty products create --app <app-id> --title "Monthly" --access-level-id <access-level-id> --period monthly --stripe-product-id prod_xxx --stripe-price-id price_xxx
```

A web-only product is valid: you can create a product with Stripe or Paddle IDs and no App Store or Google Play IDs.

### adapty products update

Update an existing [product](product).

Store product and price IDs cannot be changed after creation and are not available in this command. To use different store IDs, create a new product.

```bash
adapty products update --app <app-id> <product-id> --title "Monthly" --access-level-id <access-level-id>
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--title` | No | Product title |
| `--access-level-id` | No | [Access level](access-level) ID (UUID) this product unlocks |

## Commitment plans

A [12-month commitment plan](app-store-12-month-commitment) lets subscribers pay for a yearly App Store subscription in 12 monthly payments. To display the commitment plan in flows and custom paywalls, add it to the yearly product in Adapty with these commands. For the full setup, see [Set up a 12-month commitment plan](set-up-12-month-commitment).

Adapty doesn't add the commitment plan to App Store Connect. In App Store Connect, set up monthly billing for the subscription too, with the same monthly price. The commitment plan isn't available in the United States and Singapore, and requires iOS 26.4 or later.

The product needs the `annual` period, an App Store product ID, and a USD price. To set the USD price, use `--price-usd` of `adapty products create` or `adapty products update`.

`adapty products list` and `adapty products get` show the commitment plan of each product in the `Monthly plan` line: its monthly price, `price not set in Adapty`, or `none`. With `--json`, the plan is in `app_store_monthly_plan`: `vendor_product_id` and `price_usd`, or `null` when the product has no commitment plan. `price_usd` is `null` when the plan came from the first commitment-plan purchase and nobody has set its price in Adapty.

:::important
You can't remove a commitment plan from Adapty, and the CLI has no command for it. To stop the monthly payments, turn off monthly billing for the subscription in App Store Connect.
:::

### adapty products monthly-plan prices

List the monthly prices that the commitment plan of a product can have.

```bash
adapty products monthly-plan prices --app <app-id> <product-id>
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

The command prints the USD price of the yearly product, then the App Store price points from 1/12 to 1/8 of that price, one per line. For example, for a yearly price of $59.99, the list runs from $5.00 to $7.49. With `--json`, the command returns `annual_price_usd` and the `prices` array.

When the product can't have a commitment plan, the command lists no prices and exits with code 4. The message gives the same error code as [`adapty products monthly-plan set`](#errors-of-commitment-plan-commands).

### adapty products monthly-plan set

Add a commitment plan to a yearly product, or change the monthly price of its commitment plan.

```bash
adapty products monthly-plan set --app <app-id> <product-id> --price-usd 5.99
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--price-usd` | Yes | Monthly price in USD. Use a price from `adapty products monthly-plan prices`. The price is a reference value: Adapty doesn't send it to App Store Connect |
| `--yes` | No | Add the commitment plan without asking. Required with `--json` or in a pipe when the product has no commitment plan |

When the product has no commitment plan, the command adds one, and you can't remove it from Adapty. So the command shows this effect before it sends anything:

| How the command runs | What happens |
|---|---|
| In a terminal | The CLI prints the effect and asks `Apply? [y/N]`. If you answer `y` or `yes`, the CLI adds the commitment plan. For any other answer, the CLI exits with code 1 and sends nothing. |
| With `--yes` | The CLI adds the commitment plan without asking. |
| With `--json`, in a pipe, or with no terminal | The CLI sends nothing and exits with code 6. The message describes the effect. With `--json`, the error code is `confirm_required`. |

An agent shows the effect from the message to the user, and runs the command again with `--yes` only after the user agrees.

When the product has a commitment plan, the command changes its monthly price without asking.

#### Errors of commitment plan commands

When the product or the price doesn't meet a rule, Adapty refuses the request and changes nothing. The command exits with code 4 and prints the error code with the message from Adapty:

| Error code | Cause | What to do |
|---|---|---|
| `monthly_plan_requires_annual_product` | The product period isn't `annual`. | Use a yearly product. |
| `monthly_plan_requires_product_price` | The product has no USD price. | Set the price with `--price-usd` of `adapty products update`. |
| `monthly_plan_has_no_price_points` | No App Store price point is in the range from 1/12 to 1/8 of the yearly price. | Use a yearly product with a higher USD price. |
| `monthly_plan_price_out_of_range` | The monthly price is outside that range. The message gives the range. | Use a price from `adapty products monthly-plan prices`. |
| `monthly_plan_invalid_price_point` | The monthly price isn't an App Store price point. | Use a price from `adapty products monthly-plan prices`. |
| `monthly_plan_requires_app_store_product` | The product has no App Store product ID. | Use a product with an App Store product ID. |

## Product offers

Link the offers you created in App Store Connect or Google Play Console to an Adapty product, so Adapty can apply them. For what each offer type does and how to create the offer in the store, see [Add offers to Adapty](create-offer).

Add these offers:

- App Store promotional and win-back offers.
- All Google Play offers, free trials included. Google Play has no introductory offer type, so a trial is an offer on a base plan, and it applies only after you link it in Adapty.

Don't add App Store introductory offers: they apply automatically to eligible users.

A linked offer still has to be selected for the product in a flow or a paywall before users see it. To select it in a paywall, use the Adapty dashboard: see [Display offer](create-offer#2-display-offer).

`adapty products list` and `adapty products get` show how many offers are linked to each product in `offers_count`. The count includes only offers linked in Adapty, not the offers that exist in the stores.

In App Store Connect, each offer belongs to one billing plan of the subscription: the upfront plan or the [commitment plan](#commitment-plans). The App Store side of an offer in Adapty has the same billing plan. `adapty product-offers list` and `adapty product-offers get` show it as `Plan: Upfront` or `Plan: Monthly`. With `--json`, it's `billing_plan_type` in `store_offers.app_store`: `monthly`, or `null` for the upfront plan. A Google Play offer has no billing plan.

### adapty product-offers list

List all offers linked to a [product](product).

```bash
adapty product-offers list --app <app-id> --product <product-id>
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--product` | Yes | Product ID (UUID) |

Returns every offer on one page and doesn't accept [pagination flags](developer-cli-reference#global-flags).

### adapty product-offers get

Get details for a specific offer.

```bash
adapty product-offers get --app <app-id> <offer-id>
```

| Argument | Description |
|---|---|
| `offer-id` | Offer ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

### adapty product-offers create

Link a store offer to a [product](product).

```bash
adapty product-offers create --app <app-id> --product <product-id> --title "Spring" --type promotional --ios-offer-id spring_ios --android-offer-id spring-android
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--product` | Yes | Product ID (UUID) |
| `--title` | Yes | Offer name, shown only in the Adapty dashboard |
| `--type` | Yes | Offer type: `promotional` or `win_back` |
| `--ios-offer-id` | At least one store required | Offer ID from App Store Connect |
| `--android-offer-id` | At least one store required | Offer ID from Google Play Console |
| `--billing-plan` | No | Billing plan of the App Store offer: `upfront` (default) or `monthly` |

Win-back offers are App Store only, so `--type win_back` takes only `--ios-offer-id`. For any Google Play offer, a free trial included, use `--type promotional`.

```bash
adapty product-offers create --app <app-id> --product <product-id> --title "Come back" --type win_back --ios-offer-id winback_ios
```

For an offer that you set up for the commitment plan in App Store Connect, pass `--billing-plan monthly`. The billing plan applies only to the App Store side of the offer, so `monthly` requires `--ios-offer-id`. The product must also have a [commitment plan](#commitment-plans): without one, Adapty refuses the request.

```bash
adapty product-offers create --app <app-id> --product <product-id> --title "Spring monthly" --type promotional --ios-offer-id spring_monthly_ios --billing-plan monthly
```

### adapty product-offers update

Update an existing offer.

```bash
adapty product-offers update --app <app-id> <offer-id> --title "Spring 2"
```

| Argument | Description |
|---|---|
| `offer-id` | Offer ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--title` | No | Offer name |
| `--type` | No | Offer type: `promotional` or `win_back`. To change an offer to `win_back`, also remove its Google Play side with `--clear-android-offer-id` |
| `--ios-offer-id` | No | New App Store offer ID |
| `--android-offer-id` | No | New Google Play offer ID |
| `--clear-ios-offer-id` | No | Remove the App Store side of the offer |
| `--clear-android-offer-id` | No | Remove the Google Play side of the offer |
| `--billing-plan` | No | New billing plan of the App Store offer: `upfront` or `monthly`. `monthly` requires a [commitment plan](#commitment-plans) on the product |

At least one flag besides `--app` is required. Fields you leave out keep their current values. Every offer keeps at least one store offer ID, so the command fails if it would remove the last one.

To change the billing plan of an offer that a paywall displays, remove the offer from that paywall first. Otherwise, Adapty refuses the change with the `store_offer_billing_plan_in_use` error, and the message names the paywalls.

:::warning
The command reads the offer and saves it whole. If someone edits the same offer in the Adapty dashboard between that read and the save, their change is overwritten.
:::

Introductory offers can't be updated. An offer that has a store other than the App Store or Google Play can't be updated from the CLI either: edit it in the Adapty dashboard.

To delete an offer, use the Adapty dashboard. The CLI has no delete command.
