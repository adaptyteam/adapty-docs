These Adapty CLI commands manage [products](product), map them to their App Store and Google Play product IDs or push them to the stores, set their prices by country, and link store offers to them.

## Products

### adapty products list

List all [products](product) for an app.

```bash
adapty products list --app <app-id>
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

Accepts [pagination flags](developer-cli-reference#global-flags).

### adapty products get

Get details for a specific [product](product).

```bash
adapty products get --app <app-id> <product-id>
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

The output includes `price_usd`, the price a [push](#adapty-product-push) sends to the stores, and, for each store product, `store_status`: the review status of a product that Adapty pushed or that the status sync found in the store.

| `store_status` | Meaning |
|---|---|
| `draft` | Created in the store but not submitted. After an App Store push, a step after Apple created the product failed: finish it in App Store Connect |
| `in_review` | Waiting for the store's review |
| `approved` | Approved and available for purchase |
| `rejected` | Rejected by the store's review |
| `action_required` | The store needs you to act. After a Google Play push, the base plan was created but not activated: activate it in Google Play Console |
| `null` | Adapty has no status for this store product |

### adapty products create

Create a new [product](product).

:::important
The store product and price IDs cannot be changed after creation. To use different store IDs, create a new product.
:::

```bash
adapty products create --app <app-id> --title "Monthly" --access-level-id <access-level-id> --period monthly --ios-product-id com.example.monthly
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--title` | Yes | Product title |
| `--access-level-id` | Yes | [Access level](access-level) ID (UUID) this product unlocks |
| `--period` | Yes | Subscription period: `weekly`, `monthly`, `two_months`, `trimonthly`, `semiannual`, `annual`, `lifetime` |
| `--ios-product-id` | No | Product ID from App Store Connect |
| `--android-product-id` | No | Product ID from Google Play Console |
| `--android-base-plan-id` | Required with `--android-product-id` unless `--period lifetime` | Base plan ID from Google Play Console |
| `--stripe-product-id` | No | Product ID from Stripe |
| `--stripe-price-id` | Required with `--stripe-product-id` | Price ID from Stripe |
| `--paddle-product-id` | No | Product ID from Paddle |
| `--paddle-price-id` | Required with `--paddle-product-id` | Price ID from Paddle |

A single product can carry IDs for several stores at once. Leave out a store's ID only when you [push the product](#adapty-product-push) to that store next: the push creates the store product and links it. A product with no store ID that you never push can't be completed from the CLI, and the CLI can't delete it.

To sell a product on the web through Stripe or Paddle, connect the payment provider to Adapty first: see [Stripe](stripe) and [Paddle](paddle). For each of these stores, pass the product ID and the price ID together. The command fails if you pass only one of the pair.

```bash
adapty products create --app <app-id> --title "Monthly" --access-level-id <access-level-id> --period monthly --stripe-product-id prod_xxx --stripe-price-id price_xxx
```

A web-only product is valid: you can create a product with Stripe or Paddle IDs and no App Store or Google Play IDs.

### adapty products update

Update an existing [product](product).

Store product and price IDs cannot be changed after creation and are not available in this command. To use different store IDs, create a new product.

```bash
adapty products update --app <app-id> <product-id> --title "Monthly" --access-level-id <access-level-id>
```

To give a product the USD price a push needs:

```bash
adapty products update --app <app-id> <product-id> --price-usd 9.99
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--title` | No | Product title |
| `--access-level-id` | No | [Access level](access-level) ID (UUID) this product unlocks |
| `--price-usd` | No | Price in USD that a [push](#adapty-product-push) sends to the stores |

Fields you leave out keep their current values.

:::important
`--price-usd` sets the price only while the product has none. Once set, it stays: a later `--price-usd` leaves it unchanged, as in the dashboard. To change what buyers pay in a country, use [`product-prices set`](#adapty-product-prices-set).
:::

## Push to the stores

Create a product in App Store Connect or Google Play from an existing Adapty product. The push does what **Create a new product and push to stores** does in the dashboard: see [Create product](create-product#create-product-and-push-to-store).

Before you push:

- **Connect the store with write access**: For the App Store, add the App Store Connect API key in the app settings, on top of the In-App Purchase key. For Google Play, the service account needs the **Manage store presence** permission. See [App Store](app-store-connection-configuration) and [Google Play](google-play-store-connection-configuration).
- **Give the product a USD price**: Use [`products update --price-usd`](#adapty-products-update). The store spreads it to every country; to set country prices afterwards, use [`product-prices set`](#adapty-product-prices-set).
- **For Google Play, upload a build first**: Google Play blocks creating products until the app has a signed AAB with the billing permission on a track.

The first App Store product of an app must be submitted for review together with an app version, in App Store Connect.

### adapty product-push

Push a [product](product) to one store.

```bash
adapty product-push <product-id> --app <app-id> --store app_store --store-product-id com.example.monthly --group <group-id> --screenshot review.png
adapty product-push <product-id> --app <app-id> --store play_store --store-product-id com.example.monthly --base-plan monthly
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--store` | Yes | `app_store` or `play_store` |
| `--store-product-id` | Yes | Product ID to create in the store. It can't be changed after the push |
| `--group` | App Store subscriptions | Subscription group ID, from [`product-groups list`](#adapty-product-groups-list). Not accepted for a lifetime or one-time product |
| `--screenshot` | App Store | Review screenshot: a PNG or JPEG file at one of Apple's screen sizes, with no transparency |
| `--base-plan` | Google Play subscriptions | Base plan ID to create. Lowercase letters, digits, and hyphens. Not accepted for a lifetime or one-time product |

What the push creates:

- **App Store**: The subscription or in-app purchase, with an en-US localization named after the product's [access level](access-level), the price, and the review screenshot. It then submits the product for review.
- **Google Play**: For a subscription, the base plan. If `--store-product-id` names a subscription that already exists, the base plan is added to it; otherwise the subscription is created with a listing in each of the app's languages. The product title becomes the listing title.

The command waits for the store and prints the product with its `store_status`. Read the status again later with [`products get`](#adapty-products-get).

Adapty refuses a PNG screenshot that has an alpha channel, even when every pixel is opaque. Screenshots from a simulator or a browser usually have one, so save the screenshot as JPEG.

A refused push exits with code 4 and prints the error code (in `error_code` with `--json`):

| Error code | Cause |
|---|---|
| `missing_store_credentials` | The app has no store connection with write access |
| `missing_product_price` | The product has no USD price |
| `duplicate_vendor_product_store` | The Adapty app already has a product with this store product ID |
| `product_already_exists` | The store already has a product with this ID |
| `incompatible_product_type` | A subscription without `--group` or `--base-plan`, or a lifetime or one-time product with one |
| `review_screenshot_validation_error` | The screenshot isn't a PNG or JPEG, isn't one of Apple's sizes, or has transparency |

### adapty product-groups list

List the App Store subscription groups, or the Google Play subscriptions, of an app.

```bash
adapty product-groups list --app <app-id> --store app_store
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--store` | Yes | `app_store` or `play_store` |

Each row has a `group_id` and a `group_name`. For Google Play, a row is a subscription: its `group_id` is the subscription ID to pass as `--store-product-id` when you add a base plan to it.

The command reads the store, so it fails with `missing_store_credentials` until the store is connected.

### adapty product-groups create

Create an App Store subscription group.

```bash
adapty product-groups create --app <app-id> --store app_store --name "Premium"
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--store` | Yes | `app_store`. Google Play has no groups: the command refuses `play_store` with `unsupported_store_operation` |
| `--name` | Yes | Group name, at most 64 characters |

A name that already exists in App Store Connect fails with `subscription_group_already_exists`.

## Prices by country

Read and change a product's prices in each country of the App Store and Google Play. These commands do what **Download** and **Upload** do in the product's sidebar in the dashboard: see [Set country-specific prices](edit-product#set-country-specific-prices).

### adapty product-prices list

List a product's prices by country, with each price's sync status.

```bash
adapty product-prices list <product-id> --app <app-id>
adapty product-prices list <product-id> --app <app-id> --csv > prices.csv
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--csv` | No | Print the CSV file that **Download** gives in the dashboard |

The command prints one row per country, sorted by country name, with every country on one page. It doesn't accept [pagination flags](developer-cli-reference#global-flags).

The CSV columns are `region_name`, `region_code`, then for each store (`app_store_`, `play_store_`): `currency`, `requested_price`, `synced_price`, `sync_status`.

- **`requested_price`**: The price you set, or the store's price when you haven't set one.
- **`synced_price`**: The price the store charges now.
- **`sync_status`**: The status of the price you set: `pending`, `synced`, `failed`, or `subscribers_migration_failed`. Empty when you haven't set a price. With `--json`, a failed row also has `sync_error` with the store's reason.

A product with no prices prints the header only.

### adapty product-prices set

Change a product's prices in one or more countries.

```bash
adapty product-prices set <product-id> --app <app-id> --country DE --app-store-price 9.99 --dry-run
adapty product-prices set <product-id> --app <app-id> --file prices.csv --wait
```

| Argument | Description |
|---|---|
| `product-id` | Product ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--file` | `--file` or `--country` | CSV file in the format that [`product-prices list --csv`](#adapty-product-prices-list) prints |
| `--country` | `--file` or `--country` | Two-letter country code, for one country |
| `--app-store-price` | With `--country` | New App Store price, in the country's currency |
| `--play-store-price` | With `--country` | New Google Play price, in the country's currency |
| `--dry-run` | No | Show the preview and save nothing |
| `--apply-to-existing-subscribers` | No | Move current subscribers to the new price too. Off by default: they keep their price |
| `--wait` | No | Wait until the stores accept or refuse the new prices |
| `--timeout` | No | Seconds to wait with `--wait`. Default `300` |

The command always previews first, as the dashboard does: it shows each country's current, new, and rounded price, and then saves the rounded prices. The App Store rounds a price to its nearest price point; Google Play rounds prices in currencies without decimals.

- **A file**: The command reads each country's currency and `requested_price` and ignores the synced and status columns, so you can edit the file that `list --csv` printed and pass it back. Countries you leave out of the file keep their prices. Every row you send goes to the store again, even if its price didn't change, so send only the countries you change.
- **A missing currency** becomes the store's default currency for that country.
- **A preview with errors** in any row prints them and saves nothing. **A preview with no change** prints that and saves nothing.

Saved prices are `pending` until the stores receive them, about a minute later. Then each becomes `synced` or `failed`, with the store's reason. Without `--wait`, the command returns right after the save. With `--wait`, it reads the prices again every 10 seconds and exits with:

- `0` when every row is `synced`;
- `4` when a row is `failed` or `subscribers_migration_failed`, or still `pending` when the timeout runs out. The command prints those rows.

`--wait` and `--dry-run` can't be used together.

On the App Store, a new price of an approved subscription takes effect two days after you save it; a product that isn't approved gets it right away. On Google Play, it takes effect right away. Current subscribers keep their price unless you pass `--apply-to-existing-subscribers`: on the App Store they move at their next renewal, and on Google Play they must accept a price increase or their subscription ends.

The preview needs the store connection, like a push. Without it, every row fails with "Missing App Store credentials" or "Missing Play Store credentials".

Row errors, with the command's exit code 4:

| Error code | Cause |
|---|---|
| `invalid_region_code` | The country code isn't a store region |
| `invalid_price` | The price isn't a positive number |
| `invalid_currency_code` | The currency isn't one the store accepts in that country |
| `missing_currency` | The store has no default currency for that country, and the row names none |
| `duplicate_region` | The file has the same country twice |

## Product offers

Link the offers you created in App Store Connect or Google Play Console to an Adapty product, so Adapty can apply them. For what each offer type does and how to create the offer in the store, see [Add offers to Adapty](create-offer).

Add these offers:

- App Store promotional and win-back offers.
- All Google Play offers, free trials included. Google Play has no introductory offer type, so a trial is an offer on a base plan, and it applies only after you link it in Adapty.

Don't add App Store introductory offers: they apply automatically to eligible users.

A linked offer still has to be selected for the product in a flow or a paywall before users see it. To select it in a paywall, use the Adapty dashboard: see [Display offer](create-offer#2-display-offer).

`adapty products list` and `adapty products get` show how many offers are linked to each product in `offers_count`. The count includes only offers linked in Adapty, not the offers that exist in the stores.

### adapty product-offers list

List all offers linked to a [product](product).

```bash
adapty product-offers list --app <app-id> --product <product-id>
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--product` | Yes | Product ID (UUID) |

Returns every offer on one page and doesn't accept [pagination flags](developer-cli-reference#global-flags).

### adapty product-offers get

Get details for a specific offer.

```bash
adapty product-offers get --app <app-id> <offer-id>
```

| Argument | Description |
|---|---|
| `offer-id` | Offer ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

### adapty product-offers create

Link a store offer to a [product](product).

```bash
adapty product-offers create --app <app-id> --product <product-id> --title "Spring" --type promotional --ios-offer-id spring_ios --android-offer-id spring-android
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--product` | Yes | Product ID (UUID) |
| `--title` | Yes | Offer name, shown only in the Adapty dashboard |
| `--type` | Yes | Offer type: `promotional` or `win_back` |
| `--ios-offer-id` | At least one store required | Offer ID from App Store Connect |
| `--android-offer-id` | At least one store required | Offer ID from Google Play Console |

Win-back offers are App Store only, so `--type win_back` takes only `--ios-offer-id`. For any Google Play offer, a free trial included, use `--type promotional`.

```bash
adapty product-offers create --app <app-id> --product <product-id> --title "Come back" --type win_back --ios-offer-id winback_ios
```

### adapty product-offers update

Update an existing offer.

```bash
adapty product-offers update --app <app-id> <offer-id> --title "Spring 2"
```

| Argument | Description |
|---|---|
| `offer-id` | Offer ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |
| `--title` | No | Offer name |
| `--type` | No | Offer type: `promotional` or `win_back`. To change an offer to `win_back`, also remove its Google Play side with `--clear-android-offer-id` |
| `--ios-offer-id` | No | New App Store offer ID |
| `--android-offer-id` | No | New Google Play offer ID |
| `--clear-ios-offer-id` | No | Remove the App Store side of the offer |
| `--clear-android-offer-id` | No | Remove the Google Play side of the offer |

At least one flag besides `--app` is required. Fields you leave out keep their current values. Every offer keeps at least one store offer ID, so the command fails if it would remove the last one.

:::warning
The command reads the offer and saves it whole. If someone edits the same offer in the Adapty dashboard between that read and the save, their change is overwritten.
:::

Introductory offers can't be updated. An offer that has a store other than the App Store or Google Play can't be updated from the CLI either: edit it in the Adapty dashboard.

To delete an offer, use the Adapty dashboard. The CLI has no delete command.
