The CLI requires authentication to call the Adapty API.

One login covers the whole CLI. The [Ads Manager commands](developer-cli-ads-manager) reach a different service, but they use the same stored token — there is no second login step. For an account on the EU servers, the login names the region; see [Log in to an EU account](#log-in-to-an-eu-account).

## Log in

To log in:

1. In your terminal, run:
   ```bash
   adapty auth login
   ```
2. The CLI prints a verification code in `XXXX-XXXX` format and opens the Adapty Dashboard in your browser.
3. On the authorization page, confirm the code matches your terminal output.
4. Click **Authorize**. The browser shows "CLI authorized! You can close this tab."
5. Back in the terminal, the CLI confirms you are authenticated.

If the code expires before you authorize, or if you click **Deny**, run the following command again to restart the flow:

```bash
adapty auth login
```

### Log in to an EU account

Logging in to an account on the [EU servers](eu-cluster) requires CLI 0.30.0 or later.

To log in to an EU account:

1. In your terminal, run:
   ```bash
   ADAPTY_REGION=eu adapty auth login
   ```
2. Open the link in a browser signed in through [https://app.adapty.io/eu-login](https://app.adapty.io/eu-login). If you aren't signed in there, or you're signed in to a US account, sign in there first.
3. Confirm the code and click **Authorize**, as in [Log in](#log-in).

The CLI saves the region with the login, so later commands go to the EU servers without `ADAPTY_REGION`. In the `adapty auth status` output, a `Region: eu` line confirms it.

In a script that sets `ADAPTY_TOKEN`, also set `ADAPTY_REGION` to `us` or `eu`. Without it, the command uses the region of the login saved on that computer, which can belong to another account.

If the CLI reports that the session file is corrupted, run `adapty auth login` again with `ADAPTY_REGION` set to the region of your account. The new login replaces the file.

The [Ads Manager](developer-cli-ads-manager) and [attribution](developer-cli-attribution) commands aren't available for EU accounts. They stop with an error before sending any request, for example: `Apple Search Ads commands are not available for EU accounts.`

## Manage authentication

### Check authentication status

To see your current authentication state, run:

```bash
adapty auth status
```

When authenticated, the output shows your name, a masked token prefix, and the path to the local config file:

```
User: Jane Doe
Token: abcd1234****
Config: ~/.config/adapty/config.json
```

Starting with CLI 0.9.1, a login stores your name and no email. An `Email:` line appears only for a session saved by an earlier version. In scripts that read `adapty auth status --json`, use the `name` field to identify the user.

When not authenticated:

```
Not authenticated. Run `adapty auth login`.
```

### Verify your token

To confirm your token is valid and see your account details, run:

```bash
adapty auth whoami
```

Unlike `adapty auth status`, this command makes a live request to the server to verify the token.

### Log out

To clear your stored credentials locally, run:

```bash
adapty auth logout
```

This clears `~/.config/adapty/config.json` and the migration saved by `adapty migrations create` or `adapty migrations use`. The token remains valid server-side until it expires — if you need to invalidate it immediately, use `adapty auth revoke` instead.

### Revoke your token

To invalidate the token on the server and clear it locally, run:

```bash
adapty auth revoke
```

If the token has a saved migration, the CLI clears it too, but only after the server confirms the revocation. Use this when you want to fully invalidate a token — for example, if your credentials may have been compromised. After revoking, run `adapty auth login` to authenticate again.

## Token lifetime

A token from `adapty auth login` is valid for 90 days after you log in. Using the token doesn't extend this period, and the CLI has no refresh token. When the token expires, CLI commands return a 401 error, and you log in again in the browser.

A scheduled job that runs without a person to approve the login can't renew the token. For such a job, use the [Export Analytics API](export-analytics-api), which authenticates with your app's secret API key.

## Token errors

If a token is revoked, expires or becomes invalid, CLI commands return a 401 error. To re-authenticate, run:

```bash
adapty auth login
```
