This article lists every [Ads Manager](adapty-ads-manager) command in the Adapty CLI, with its arguments, flags, and accepted values. Ads Manager commands start with `adapty asa`.

:::link
For prerequisites, safe write practices, and task-based examples, see [Manage Ads Manager from the CLI](developer-cli-ads-manager).
:::

These commands need a connected Apple Ads account and an active Ads Manager subscription. Run [`adapty asa whoami`](#adapty-asa-whoami) to check both. For the rest of the CLI, see the [command reference](developer-cli-reference).

## Global flags \{#global-flags\}

These flags are available on all Ads Manager commands.

| Flag | Description |
|---|---|
| `--json` | Output as JSON instead of formatted text |
| `--help` | Show command help |

All `list` commands also accept pagination flags:

| Flag | Default | Description |
|---|---|---|
| `--page` | `1` | Page number |
| `--page-size` | `100` | Items per page (max: 1000) |

Ads Manager pages are larger than in the rest of the CLI. Prefer one large page over a loop of small ones.

All commands that change your account accept these flags:

| Flag | Description |
|---|---|
| `--yes`, `-y` | Apply without asking for confirmation. Required when the output is piped or `--json` is used |
| `--idempotency-key` | Fixed key for this write. A repeat with the same key and body within 24 hours returns the stored result instead of applying the change again |

Ads Manager commands take no `--app` flag. The scope is the company that your token belongs to. `--app` exists on some `list` commands as a filter only. The [segments](#segments) commands are the exception: there, `--app` is the Adapty app that the segment belongs to.

## List filters \{#list-filters\}

Filters narrow the query itself, not the printed page. An unfiltered `keywords list` pages through every keyword in the account, so scope each read to the level you need.

| Filter | Accepted by |
|---|---|
| `--campaign-group` | `campaigns`, `ad-groups`, `keywords`, `negative-keywords`, `search-terms`, `ads`, `creatives`, `product-pages` |
| `--app` | `campaigns`, `ad-groups`, `keywords`, `negative-keywords`, `search-terms`, `creatives`, `product-pages` |
| `--campaign` | `ad-groups`, `keywords`, `negative-keywords`, `search-terms`, `ads` |
| `--ad-group` | `keywords`, `negative-keywords`, `search-terms`, `ads` |
| `--status` | `campaigns`, `ad-groups`, `ads` (`ENABLED` or `PAUSED`), `keywords` (`ACTIVE` or `PAUSED`) |
| `--search` | `campaigns`, `ad-groups`, `keywords`, `negative-keywords`, `search-terms`, `ads`. Case-insensitive substring match on the name |

`adapty asa apps list`, `orgs list`, `automations list`, and `automations runs` take no filters. They accept pagination flags only.

`--campaign-group`, `--app`, `--campaign`, and `--ad-group` take the UUIDs printed by the matching `list` command, and each one is repeatable:

```bash
adapty asa keywords list --ad-group <ad-group-id> --ad-group <other-ad-group-id>
```

An ID that belongs to another company matches nothing, so the page comes back empty instead of returning an error.

## Account \{#account\}

### adapty asa whoami

Show the company, how Ads Manager access was granted, and whether Apple Ads is connected.

```bash
adapty asa whoami
```

Run this command first. It reports whether the two prerequisites for every other command are met.

### adapty asa connect

Link an Apple Ads account to Adapty.

```bash
adapty asa connect
```

The command prints an Apple authorization link and waits until Apple reports the account as connected.

| Flag | Default | Description |
|---|---|---|
| `--wait` / `--no-wait` | `--wait` | Wait until Apple Ads reports as connected. `--no-wait` returns immediately |
| `--timeout` | `300` | Seconds to wait for the browser step |

### adapty asa orgs list

List the campaign groups (Apple Ads organizations) available to your company.

```bash
adapty asa orgs list
```

Each row carries two identifiers, and they are not interchangeable:

| Field | Used as |
|---|---|
| `internal_id` | The UUID that `--org` takes on [`campaigns create`](#adapty-asa-campaigns-create), and that `--campaign-group` takes as a [list filter](#list-filters) |
| `org_id` | Apple's numeric organization ID, taken by `--org-id` on [`campaigns bulk-create`](#adapty-asa-campaigns-bulk-create). `--org` and `--campaign-group` reject it |

`--org` exists only on `campaigns create`. No list command accepts it.

Each row also carries a `payment_model`. When it is `LOC`, the organization bills by line of credit, and every campaign in it needs the [`--invoice-*` flags](#adapty-asa-campaigns-create).

Accepts [pagination flags](#global-flags).

### adapty asa apps list

List the apps promoted in Apple Ads.

```bash
adapty asa apps list
```

Each row carries two identifiers, and they are not interchangeable:

| Field | Used as |
|---|---|
| `internal_id` | The UUID that `--app` takes as a [list filter](#list-filters) |
| `adam_id` | Apple's numeric App Store ID, taken by `--adam-id` on [`campaigns create`](#adapty-asa-campaigns-create) and [`product-pages sync`](#adapty-asa-product-pages-sync) |

Accepts [pagination flags](#global-flags).

```bash
adapty asa campaigns get <campaign-id>
```

| Argument | Description |
|---|---|
| `campaign-id` | Campaign ID (UUID) |

### adapty asa campaigns create

Create a campaign.

```bash
adapty asa campaigns create --org <campaign-group-id> --name "Winter push" --adam-id 123456 --country US --daily-budget 50
```

| Flag | Required | Description |
|---|---|---|
| `--org` | Yes | Campaign group ID (UUID). See [`orgs list`](#adapty-asa-orgs-list) |
| `--name` | Yes | Campaign name |
| `--adam-id` | Yes | App Store app ID (`adam_id`) |
| `--country` | Yes | Country or region code. Repeat for several: `--country US --country CA` |
| `--daily-budget` | Yes | Daily budget as a plain amount, for example `50` or `12.50` |
| `--budget` | No | Lifetime budget |
| `--target-cpa` | No | Target cost per acquisition. Must be lower than `--daily-budget` |
| `--currency` | No | Currency code for the amounts in this call. Default: the currency of the campaign group. A different currency is rejected |
| `--bidding-strategy` | No | `MANUAL_CPT` or `MAX_CONVERSIONS`. Apple defaults to `MANUAL_CPT` |
| `--ad-channel-type` | No | `SEARCH` or `DISPLAY`. Default: `SEARCH` |
| `--billing-event` | No | `TAPS` or `IMPRESSIONS`. Default: `TAPS` |
| `--supply-source` | No | Supply source, repeatable. Default: `APPSTORE_SEARCH_RESULTS` |
| `--status` | No | Initial status: `ENABLED` or `PAUSED` |
| `--invoice-advertiser` | Line of credit | Invoicing Options: advertiser name |
| `--invoice-order-number` | Line of credit | Invoicing Options: order number |
| `--invoice-contact-name` | Line of credit | Invoicing Options: buyer contact name |
| `--invoice-contact-email` | Line of credit | Invoicing Options: buyer contact email |
| `--invoice-billing-email` | Line of credit | Invoicing Options: billing contact email |

An organization whose `payment_model` is `LOC` bills by line of credit, and Apple requires Invoicing Options on each of its campaigns. Pass all five `--invoice-*` flags in one call — a partial set is rejected before the request is sent. See [Set Invoicing Options for a line of credit](developer-cli-ads-manager#invoicing-options).

The response carries `serving_status` and `serving_state_reasons`. A campaign can be created and still not serve: a `MAX_CONVERSIONS` campaign waits for an [automated ad group](#adapty-asa-ad-groups-create), and a line-of-credit campaign waits for its Invoicing Options. In both cases the command prints the reason and the command that resolves it.

### adapty asa campaigns update

Update an existing campaign.

```bash
adapty asa campaigns update <campaign-id> --daily-budget 80 --status PAUSED
```

| Argument | Description |
|---|---|
| `campaign-id` | Campaign ID (UUID) |

| Flag | Description |
|---|---|
| `--name` | New campaign name |
| `--status` | `ENABLED` or `PAUSED` |
| `--country` | Replaces the country list. Repeat for several |
| `--daily-budget` | New daily budget |
| `--budget` | New lifetime budget |
| `--target-cpa` | New target cost per acquisition |
| `--bidding-strategy` | `MANUAL_CPT` or `MAX_CONVERSIONS` |
| `--currency` | Currency code for the amounts in this call. Default: the currency of the campaign group. A different currency is rejected |
| `--invoice-advertiser` | Invoicing Options: advertiser name |
| `--invoice-order-number` | Invoicing Options: order number |
| `--invoice-contact-name` | Invoicing Options: buyer contact name |
| `--invoice-contact-email` | Invoicing Options: buyer contact email |
| `--invoice-billing-email` | Invoicing Options: billing contact email |

At least one flag is required.

The five `--invoice-*` flags go together and replace the stored Invoicing Options as a set, so pass all five even to change one of them. A partial set is rejected before the request is sent.

### adapty asa campaigns bulk-create

Create a whole campaign structure — campaigns with nested ad groups, keywords, negative keywords, and ads — in one operation.

```bash
adapty asa campaigns bulk-create --file structure.json
```

Convert a native Apple Ads bulk template instead of writing the JSON:

```bash
adapty asa campaigns bulk-create --from-file Campaign_And_Adgroup_Template.xlsx --org-id 1234567
```

| Flag | Default | Description |
|---|---|---|
| `--file` | — | JSON file with the campaign structure, or `-` to read from standard input |
| `--from-file` | — | Apple Ads bulk template to convert on the server: [`Campaign_And_Adgroup_Template.xlsx`](https://ads.apple.com/app-store/help/campaigns/0089-make-edits-in-bulk) or a [keywords `.csv`](https://ads.apple.com/app-store/help/keywords/0014-add-and-manage-keywords) |
| `--org-id` | — | Apple's numeric organization ID (`org_id`). See [`orgs list`](#adapty-asa-orgs-list). Required with `--from-file` |
| `--preview` | — | With `--from-file`: print the converted structure and stop. Nothing is created |
| `--wait` / `--no-wait` | `--wait` | Poll the operation until it finishes. `--no-wait` prints the operation ID and returns |
| `--poll-interval` | `5` | Seconds between progress polls |
| `--timeout` | `900` | Maximum seconds to wait for the operation to finish |

Exactly one of `--file` and `--from-file` is required.

The structure names the campaign group at the top level and nests everything else:

```json title="structure.json"
{
  "campaign_group_id": 555777,
  "campaigns": [
    {
      "payload": {
        "name": "US Search",
        "adam_id": 123456,
        "countries_or_regions": ["US"],
        "daily_budget_amount": { "amount": "100", "currency": "USD" },
        "status": "ENABLED",
        "ad_channel_type": "SEARCH",
        "billing_event": "TAPS",
        "supply_sources": ["APPSTORE_SEARCH_RESULTS"]
      },
      "ad_groups": [
        {
          "payload": { "name": "Brand", "start_time": "2026-08-01T00:00:00Z", "status": "ENABLED" },
          "keywords": [{ "text": "meditation app", "match_type": "BROAD" }]
        }
      ]
    }
  ]
}
```

`campaign_group_id` takes Apple's numeric organization ID; use `campaign_group_internal_id` to pass the UUID instead. A node with a `payload` is created. A node that names an existing entity by its `id` is an anchor — use one to add ad groups to an existing campaign, and add `update_payload` to change the entity in the same operation. Each campaign nests `ad_groups`, and each ad group nests `keywords`, `negative_keywords`, and `ads`. A campaign also takes `negative_keywords` directly for campaign-level ones.

The whole structure is validated before anything is created, and a rejection lists every invalid node. With `--from-file`, conversion issues are reported with their sheet, row, and column; conversion warnings do not stop the submission, but conversion errors abort it. Before sending, the command reports how many campaigns, ad groups, keywords, negative keywords, and ads the structure contains and asks for confirmation.

The command then polls the operation and prints progress until one of three final statuses:

| Status | Meaning |
|---|---|
| `success` | Every object was created |
| `partial` | Some objects were not created. Each failure is printed with Apple's error |
| `failed` | The operation failed, and the command exits non-zero |

If the operation has not finished after `--timeout` seconds, the command returns and prints the [`bulk-status`](#adapty-asa-campaigns-bulk-status) call to run later.

### adapty asa campaigns bulk-status

Show the progress of one bulk operation: the status, the object counts, and the per-object log.

```bash
adapty asa campaigns bulk-status <operation-id>
```

| Argument | Description |
|---|---|
| `operation-id` | Operation ID (UUID) printed by [`campaigns bulk-create`](#adapty-asa-campaigns-bulk-create) |

The `status` field is `pending`, `running`, `success`, `partial`, or `failed`. The `counts` block reports how many objects are applied, failed, and pending out of the total.

Accepts [pagination flags](#global-flags).

### adapty asa ad-groups create

Create an ad group in a campaign.

```bash
adapty asa ad-groups create --campaign <campaign-id> --name "Brand terms" --default-bid 1.20
```

| Flag | Required | Description |
|---|---|---|
| `--campaign` | Yes | Campaign ID (UUID) |
| `--name` | Yes | Ad group name |
| `--default-bid` | Unless `--automated` | Default bid as a plain amount, for example `1.20` |
| `--cpa-goal` | No | Cost per acquisition goal |
| `--pricing-model` | No | `CPC` or `CPM`. Apple requires one on every ad group. Default: `CPC` |
| `--start-time` | No | Schedule start (`YYYY-MM-DD`). Defaults to today |
| `--end-time` | No | Schedule end (`YYYY-MM-DD`) |
| `--automated-keywords` / `--no-automated-keywords` | No | Let Apple add keywords automatically |
| `--automated` | No | Create the automated ad group that a `MAX_CONVERSIONS` campaign needs |
| `--currency` | No | Currency code for the amounts in this call. Default: the currency of the campaign group. A different currency is rejected |
| `--status` | No | Initial status: `ENABLED` or `PAUSED` |

`--automated` opts the ad group into automated keywords, so it cannot be combined with `--automated-keywords`. Apple schedules an automated ad group itself and keeps it enabled, so `--start-time` and `--status PAUSED` are rejected — pause the campaign instead. See [Create a Max Conversions campaign](developer-cli-ads-manager#max-conversions).

|---|---|

| Flag | Description |
|---|---|
| `--name` | New ad group name |
| `--status` | `ENABLED` or `PAUSED` |
| `--default-bid` | New default bid |
| `--cpa-goal` | New cost per acquisition goal |
| `--start-time` | Schedule start (`YYYY-MM-DD`) |
| `--end-time` | Schedule end (`YYYY-MM-DD`) |
| `--automated-keywords` / `--no-automated-keywords` | Let Apple add keywords automatically |
| `--currency` | Currency code for the amounts in this call. Default: the currency of the campaign group. A different currency is rejected |

At least one flag is required. The parent campaign is resolved on the server and is never passed.

## Keywords \{#keywords\}

Keyword commands are applied as a batch of at most 100 items per call. See [Manage keywords](ads-manager-manage-keywords) for the dashboard equivalent.

### adapty asa keywords list

List targeting keywords. Returns metadata only — read performance numbers with [`asa metrics`](#adapty-asa-metrics).

```bash
adapty asa keywords list --ad-group <ad-group-id> --status ACTIVE
```

| Flag | Description |
|---|---|
| `--live-only` | Only keywords that can serve: `ACTIVE`, in an `ENABLED` ad group and an `ENABLED` campaign, with nothing deleted |

Accepts [pagination flags](#global-flags) and the `--campaign-group`, `--app`, `--campaign`, `--ad-group`, `--search`, and `--status` [list filters](#list-filters). Filter by `--ad-group` — without a filter, this is the widest read in the topic.

### adapty asa keywords duplicates

Find the keywords of one app that are repeated across ad groups and campaigns: the same text, country, and level.

```bash
adapty asa keywords duplicates --app <app-id> --country US --country DE
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID). See [`apps list`](#adapty-asa-apps-list) |
| `--country` | No | Two-letter ISO country code. Repeat for several. Scans only these countries |
| `--ignore-match-type` | No | Group by country and text only, merging match types |

Each group lists its instances with their campaign, ad group, match type, and bid. The command returns at most 500 groups. When the list is capped, `truncated` is `true` and the command prints a warning.

### adapty asa keywords recommend

Get a ready-made keyword pool for one of your apps. These are the same pools that Ads Manager uses when you set up a campaign in the dashboard.

```bash
adapty asa keywords recommend --adam-id <adam-id> --type generic --country US
```

| Flag | Required | Description |
|---|---|---|
| `--adam-id` | Yes | Apple App Store ID (`adam_id`) of your app, from [`asa apps list`](#adapty-asa-apps-list) |
| `--type` | Yes | `brand`, `generic`, or `competitor` |
| `--country` | No | Two-letter ISO country code. Repeat for several. Default: every country in the pool |

The `--type` flag selects the pool:

| Type | Keywords |
|---|---|
| `brand` | Your app's brand terms, their spelling variants, and organic terms that contain the brand. The output also lists the brand terms themselves |
| `generic` | Non-brand terms that your app and its top organic competitors rank for, with every known brand term removed. `relevance_tier: top_organic` marks the terms where your app already ranks in the organic top 10 |
| `competitor` | The brand terms of each competitor selected for the app, one pool per competitor. Empty until you select competitors |

Each keyword comes with its country, popularity, score, and median organic rank. The keywords have no bids or match types. Choose those yourself, then add the keywords with [`asa keywords add`](#adapty-asa-keywords-add).

Check the pool `status` before you use its keywords:

| Status | Meaning |
|---|---|
| `ready` | The pool is built |
| `building` | The pool is still being built. Retry in about a minute |
| `empty` | The pool is built and has no keywords |
| `failed` | The build failed. Retry later |

The first `brand` or `generic` call for an app builds the pool during the request and can take tens of seconds. The command has a budget of 10 calls per minute per company, and only one `brand` or `generic` build runs at a time per company. A second build during that time returns `429 cli_analytics_busy` with `Retry-After: 5`.

### adapty asa keywords add

Add targeting keywords to an ad group.

```bash
adapty asa keywords add --ad-group <ad-group-id> --text "running shoes" --text "trail shoes" --bid 1.20
```

Read the keywords from a file instead, one per line:

```bash
adapty asa keywords add --ad-group <ad-group-id> --from-file keywords.txt
```

| Flag | Required | Description |
|---|---|---|
| `--ad-group` | Yes | Ad group ID (UUID). The campaign is resolved from it |
| `--text` | Yes, unless `--from-file` is used | Keyword text. Repeat for several |
| `--from-file` | No | File with one keyword per line. Combined with any `--text` values |
| `--bid` | No | Bid per keyword as a plain amount |
| `--match-type` | No | `BROAD` or `EXACT`. Default: `BROAD` |
| `--currency` | No | Currency code for the amounts in this call. Default: the currency of the campaign group. A different currency is rejected |
| `--status` | No | `ACTIVE` or `PAUSED`. Default: `ACTIVE` |

One invalid ID fails the whole batch before Apple is called. Apple can still reject individual keywords, and each rejection is reported with its reason.

### adapty asa keywords update

Change the bid, status, text, or match type of one or more keywords.

```bash
adapty asa keywords update <keyword-id> <keyword-id> --bid 2.00 --status PAUSED
```

| Argument | Description |
|---|---|
| `keyword-id` | Keyword ID (UUID). Pass several as extra arguments |

| Flag | Description |
|---|---|
| `--bid` | New bid |
| `--status` | `ACTIVE` or `PAUSED` |
| `--match-type` | `BROAD` or `EXACT` |
| `--text` | New keyword text. Only meaningful for a single keyword |
| `--currency` | Currency code for the amounts in this call. Default: the currency of your campaign groups. Required when your campaign groups use different currencies |

One change is applied to every ID passed.

List negative keywords. Rows with an empty `ad_group_id` are campaign-level.


|---|---|

### adapty asa negative-keywords add

Add negative keywords to an ad group or a campaign.

```bash
adapty asa negative-keywords add --ad-group <ad-group-id> --text free
```

Apply them to every ad group of a campaign instead:

```bash
adapty asa negative-keywords add --campaign <campaign-id> --all-ad-groups --text free
```

| Flag | Required | Description |
|---|---|---|
| `--ad-group` | One of `--ad-group` or `--campaign` | Ad group ID (UUID). The campaign is resolved from it |
| `--campaign` | One of `--ad-group` or `--campaign` | Campaign ID (UUID) |
| `--text` | Yes | Keyword text. Repeat for several |
| `--all-ad-groups` | No | Apply to every ad group of the campaign instead of the campaign itself. Requires `--campaign` |
| `--match-type` | No | `BROAD` or `EXACT`. Default: `EXACT` |
| `--status` | No | `ACTIVE` or `PAUSED`. Default: `ACTIVE` |

`--ad-group` and `--campaign` are mutually exclusive. Pass exactly one.

## Search terms \{#search-terms\}

### adapty asa search-terms list

List the search terms that triggered your ads. Use it to find new keywords and new negative keywords.

```bash
adapty asa search-terms list --ad-group <ad-group-id> --date-from 2026-07-01 --date-to 2026-07-31
```

| Flag | Default | Description |
|---|---|---|
| `--date-from` | Today | Start of the reporting period (`YYYY-MM-DD`) |
| `--date-to` | Today | End of the reporting period (`YYYY-MM-DD`) |
| `--overlap-only` | Off | Only Search Match and Max Conversions terms that match a live `EXACT` keyword of the same app, in a campaign that covers the term's country, and are not blocked by a negative keyword |

Accepts [pagination flags](#global-flags) and the `--campaign-group`, `--app`, `--campaign`, `--ad-group`, and `--search` [list filters](#list-filters).

Besides its performance metrics, each search term row carries Apple's insights for the term:

| Field | Value |
|---|---|
| `impression_share_all`, `impression_share_first` | Impression share in any ad position, or in the first ad position |
| `impression_midpoint_all`, `impression_midpoint_first` | Impression share as a single percentage |
| `rank_all`, `rank_first` | Your app's rank against other apps for the term, in any ad position or in the first one |
| `search_popularity` | Search popularity from 1 to 5 |

Each field is `null` when Apple has no data for the term. See [Insights](adapty-ads-manager-metrics#insights) for how Apple defines these values.

This command shares an analytics pool with [`asa metrics`](#metrics). See [Errors](#errors).

## Segments \{#segments\}

These commands create Adapty [segments](segments) from Apple Ads campaigns, ad groups, or keywords, the same way as **Create segment from…** in [Ads Manager](ads-manager-create-segments). Use the segments as audiences in placements and A/B tests to show users from a specific campaign a different paywall.

Each segment has one attribution filter over the Apple IDs of the entities you choose. The CLI looks up those IDs, so you pass the UUIDs printed by the `list` commands.

Unlike other `adapty asa` commands, these take `--app`: the ID of the Adapty app that the segment belongs to, from [`adapty apps list`](developer-cli-apps#adapty-apps-list). They don't accept `--idempotency-key`. For segments with other filters, such as country or install date, use [`adapty segments create`](developer-cli-placements#adapty-segments-create).

### adapty asa segments create

```bash

adapty asa segments create --app <app-id> --ad-group <ad-group-id> --keyword <keyword-id> --keyword <other-keyword-id>
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | Adapty app ID (UUID) |
| `--campaign` | One entity type | Campaign ID (UUID). Repeatable |
| `--ad-group` | One entity type | Ad group ID (UUID). Repeatable. With `--keyword`, pass exactly one: the ad group that contains the keywords |

## Automations \{#automations\}

The CLI stores the rule JSON you give it, with one exception: the settings of an **Add as keyword** action come from flags. See [Automations](ads-manager-automations) for what each rule type does, and [Run automation rules](developer-cli-ads-manager#run-automation-rules) for how to produce a rule file.

### Add-as-keyword action flags \{#add-keyword-flags\}

`automations create` and `automations update` share a set of flags that set `actions[0].params` for an `add-as-keyword-to` action — **Add as keyword** in a [search terms rule](ads-manager-automations-search-terms), **Add as keyword to…** in a [keyword rule](ads-manager-automations-keyword-rules). Passing any of them replaces the whole `params` object, so this action needs no hand-written JSON.

| Flag | JSON field | Description |
|---|---|---|
| `--target-ad-group` | `targets.internal_ids` | Ad group that receives the keyword (UUID), repeatable. A rule with no target ad group does nothing |
| `--match-type` | `match_type` | `BROAD` or `EXACT` |
| `--cpt-bid-type` | `cpt_bid.type` | Where the bid of the new keyword comes from: `ad_group_default_bid`, `set_to`, `search_term_current_cpt`, or `keyword_current_bid` |
| `--cpt-bid` | `cpt_bid.value` | With `set_to`, the bid itself. With `search_term_current_cpt` or `keyword_current_bid`, a percentage markup on the bid being copied. Not accepted with `ad_group_default_bid` |
| `--negate` | `negate` | Also add the search term as a negative keyword, in its own `ad-group` or its own `campaign`. `--no-negate` leaves none behind. Search terms rules only |
| `--skip-enable-duplicates` | `skip_enable_duplicate_keywords` | Skip a keyword that already exists in the target ad group instead of enabling it. Search terms rules only |
| `--pause-original` | `pause_in_original_ad_group` | Pause the source keyword in its own ad group. Keyword rules only |

`--cpt-bid-type` and `--match-type` have no default, so both are required when the rule file contains no `params` of its own.

Four of these flags depend on the rule's `operate_with` field: `--negate`, `--no-negate`, and `--skip-enable-duplicates` belong to a `search-term` rule, `--pause-original` to a `targeting-keyword` one. A flag from the other set fails with exit code `2` and a list of the flags that do apply.

:::warning
Take this action's `params` from the flags, never from a rule that carries a different action. The API resolves `params` by shape rather than by a named variant, so a key belonging to another action makes it choose that action and drop the rest — answering `200` and storing a rule that adds keywords to no ad group at all.
:::

## Keyword autopilot \{#keyword-autopilot\}

The [keyword autopilot](ads-manager-autopilot) sets the bids of the keywords you enroll in it, and can pause them in Apple Ads. These commands enroll or unenroll one keyword per call, and read the state and decisions of the autopilot. The `keyword-autopilot` commands need CLI version 0.34.0 or later. To see your version, run `adapty --version`.

The commands take two kinds of keyword ID:

- **Autopilot keyword ID**: The `internal_id` that [`keyword-autopilot list`](#adapty-asa-keyword-autopilot-list) prints. It identifies the enrollment of the keyword in the keyword autopilot. `get`, `unenroll`, and `decisions --keyword` take it.
- **Targeting keyword ID**: The `internal_id` that [`keywords list`](#adapty-asa-keywords-list) prints. It identifies the Apple Ads keyword. Only `enroll --targeting-keyword` takes it.

### Keyword statuses and pause codes \{#keyword-autopilot-statuses\}

`status` shows [what the keyword autopilot does with a keyword](ads-manager-autopilot#how-the-keyword-autopilot-sets-bids) at the moment. While `enabled` is `true`, the dashboard shows the following label for each status:

| `status` | Dashboard label | Meaning |
|---|---|---|
| `ramp` | **Warming up** | The autopilot raises the bid step by step, up to the [bid cap](#adapty-asa-keyword-autopilot-enroll), until the keyword receives impressions. Every keyword starts here |
| `learning` | **Testing** | The autopilot counts taps, installs, trials, and payments to judge the keyword |
| `working` | **Optimizing** | Payments confirmed that the keyword meets the target. The autopilot keeps the bid where the cost per paying user meets the target |
| `provisional` | **Optimizing (early data)** | Early signals look good, but payments don't confirm them yet. The autopilot delays bid raises |
| `dormant` | **Sleeping** | Even at the bid cap, the keyword enters no auction. The autopilot acts on it again when impressions appear |
| `paused` | **Paused by autopilot** | The autopilot paused the keyword in Apple Ads. `paused_code` gives the reason |
| `human_review` | **Waiting for review** | Apple Ads didn't accept a change. The autopilot stops changing the keyword until you unenroll it and enroll it again |

`enabled: false` means that the autopilot doesn't manage the keyword. The dashboard then shows the label of `disabled_reason`:

| `disabled_reason` | Dashboard label | Meaning |
|---|---|---|
| `awaiting_activation` | **Starting** | The keyword waits until it's active in an enabled campaign in Apple Ads |
| `external_pause` | **Paused in Apple Ads** | Someone paused the keyword or its ad group in Apple Ads. When the keyword runs again, the autopilot still doesn't manage it |
| `unenrolled` | **Off autopilot** | Someone ran `unenroll` for the keyword, or clicked **Take off** in the dashboard |

`paused_code` gives the reason the autopilot paused the keyword:

| `paused_code` | Dashboard label |
|---|---|
| `no_download` | **No installs** |
| `spend_guard_no_trials` | **Spend without trials** |
| `trials_dont_convert` | **Trials don't convert** |
| `weak_proxies` | **Weak early signals** |
| `no_volume` | **Too little traffic** |
| `no_auction` | **No auction** |
| `degraded` | **Got worse over time** |
| `funnel_tap_to_install` | **Taps don't turn into installs** |
| `funnel_install_to_trial` | **Installs don't turn into trials** |
| `funnel_trial_to_paid` | **Trials don't turn into payments** |

The autopilot doesn't resume a keyword that it paused. After you resume the keyword in Apple Ads, it stays `paused` until you unenroll it and enroll it again.

`tier` shows how much data the autopilot has on the keyword: from `t0` (none) through taps (`t1`) and installs (`t2`) to confirmed payments (`t3`). The dashboard shows `tier` as **Data confidence**: **None**, **Low**, **Medium**, or **High**.

In dry run mode, the keyword autopilot changes `status` but sends nothing to Apple Ads. Each decision then ends with "(dry run: not sent to Apple)". You can't read or switch this mode from the CLI. To see what reached Apple Ads, read `apple_status` and `apple_bid` in [`keyword-autopilot list`](#adapty-asa-keyword-autopilot-list).

| `--page` | Page number. Default: `1` |

### adapty asa keyword-autopilot enroll

Enroll one Apple Ads keyword in the keyword autopilot.

```bash
adapty asa keyword-autopilot enroll --targeting-keyword <targeting-keyword-id> --target-cpp 12.50 --country US
```

| Flag | Required | Description |
|---|---|---|
| `--targeting-keyword` | Yes | Targeting keyword ID (UUID) from [`keywords list`](#adapty-asa-keywords-list), not the autopilot keyword ID |
| `--target-cpp` | Yes | Target cost per paying user, not a custom product page |
| `--country` | No | Two-letter country code. Required when the campaign of the keyword targets more than one country |
| `--cap` | No | Bid cap, shown as **Max bid** in the dashboard. Without `--cap`, the autopilot computes the cap itself |
| `--aggressiveness` | No | Multiplier for the computed bid cap. Default: `1.0`. Has no effect with `--cap` |

`--target-cpp` and `--cap` are amounts in the currency of your Apple Ads account, which is also the currency of the keyword bid. The CLI converts nothing. These two flags and `--aggressiveness` take a positive number with up to 6 decimal places, such as `12.50`.

`--cap` only limits bid raises in `ramp` and `learning`. The autopilot can bid a `working` or `provisional` keyword above the cap, up to several times its value. The autopilot doesn't cut a bid that is above the cap at enrollment.

To enroll several keywords, run `enroll` once per keyword.

The response shows the new enrollment. Its `internal_id` is the autopilot keyword ID.

`enroll` sets no bid and sends nothing to Apple Ads. The autopilot acts at its next scheduled run, and only counts results from the moment of enrollment.

You can enroll a paused keyword, or a keyword in a paused campaign. The keyword waits with `enabled: false` and `disabled_reason: awaiting_activation` until it and its campaign are both active in Apple Ads. Then the next daily run of the autopilot starts to manage the keyword.

`enroll` returns `409` for a keyword that is already enrolled, even when its `status` is `paused` or `human_review`. The enrollment stays as it was. To enroll the keyword again with new settings, run `unenroll` first, then `enroll` with its targeting keyword ID. The new enrollment starts again from `ramp`, with the target and cap of the new call.

`enroll` returns `422` when:

- The campaign targets several countries, and `--country` is missing.
- The app has no Adapty data.
- The country has too little funnel data for the autopilot.

### adapty asa keyword-autopilot decisions


| Flag | Description |
|---|---|
| `--date-from` | Start of the period: `YYYY-MM-DD` (the start of that UTC day), or an ISO 8601 date and time with `Z` or a UTC offset. Default: 7 days before `--date-to` |
| `--date-to` | End of the period: `YYYY-MM-DD` (the end of that UTC day), or an ISO 8601 date and time with `Z` or a UTC offset. Default: the moment of the call |
| `--keyword` | Autopilot keyword ID (UUID) |

Each decision in the list has properties such as the following:

- `text.saw`: What the autopilot saw, shown as the **Saw** line on the **Activity** tab.
- `text.why`: Why the autopilot made the decision, shown as the **Why** line.

The command exits with code `2` when the period is empty or reversed, or when a date doesn't exist in the calendar.

## Budget autopilot \{#budget-autopilot\}

The [budget autopilot](ads-manager-autopilot) moves daily budget between the campaigns of a company. Its spend guard pauses campaigns that spend without trials or payments. These commands read the state of the budget autopilot, turn it on or off, switch its mode, and exclude or include campaigns. The `budget-autopilot` commands need CLI version 0.34.0 or later. To see your version, run `adapty --version`.

The autopilot has two modes:

- **`dry_run`**: The autopilot plans its changes and shows them as decisions, but sends nothing to Apple Ads. The dashboard calls this mode **Preview**.
- **`live`**: The autopilot changes campaign budgets in Apple Ads, and its spend guard can pause campaigns.

### adapty asa budget-autopilot status

Show the settings and state of the budget autopilot.

```bash
adapty asa budget-autopilot status
```

The response includes the following properties:

- `enrolled`: `true` when Adapty connected the company to the budget autopilot. When it's `false`, the command prints "The company is not connected to the budget autopilot." To connect the company, contact your Adapty manager.
- `enabled`: `true` while the autopilot is on.
- `dry_run`: `true` when the stored mode is `dry_run`, and `false` when it's `live`.
- `mode`: The mode in effect, `dry_run` or `live`. It reads `dry_run` while the autopilot is off or Live isn't available, whatever the stored mode.
- `live_available`: `true` when the company can switch to Live.
- `next_run_at` and `next_guard_check_at`: The time of the next weekly run and of the next spend guard check.

The response also shows the last weekly run, the managed campaigns, the open decisions, and the spend guard alerts of the last 7 days.

### adapty asa budget-autopilot update

Turn the budget autopilot on or off, or switch its mode.

```bash
adapty asa budget-autopilot update --enable --mode dry_run
```

| Flag | Description |
|---|---|
| `--enable` | Turn the autopilot on, in the stored mode |
| `--disable` | Turn the autopilot off. The stored mode doesn't change |
| `--mode` | `dry_run` or `live`. The autopilot stays on or off as it is |

Pass at least one flag. Without a flag, the command exits with code `2`. `--enable` and `--disable` are mutually exclusive.

To turn the autopilot on without changes in Apple Ads, pass `--enable --mode dry_run`. `--enable` alone keeps the stored mode. The stored mode can be `live` even while `mode` in [`status`](#adapty-asa-budget-autopilot-status) reads `dry_run`. While the autopilot is off, `--mode` only changes the stored mode.

The command compares the result of your flags with the current state:

- **The company isn't connected**: The command exits with code `1` and changes nothing.
- **The state is already as requested**: The command prints "Nothing to change" and exits with code `0`.
- **The result is Live, and `live_available` is `false`**: The command exits with code `1` and changes nothing.
- **The result is Live**: The command lists the campaigns that Live mode will change, up to 20, on standard error. Then it asks for confirmation, like every write.

Under `--json`, the command returns the state of the budget autopilot in the shape of [`status`](#adapty-asa-budget-autopilot-status), also when there's nothing to change.

In Live, budget changes start with the [next Monday run](ads-manager-autopilot#start-or-stop-budget-changes-in-apple-ads). When you turn the autopilot off or switch back to `dry_run`, budgets stay as they are. Campaigns that the autopilot paused stay paused.

### adapty asa budget-autopilot fronts

List the campaigns that the budget autopilot manages or has excluded.

```bash
adapty asa budget-autopilot fronts --adam-id 123456
```

| Flag | Description |
|---|---|
| `--campaign-group` | Organization ID (UUID) from [`orgs list`](#adapty-asa-orgs-list) |
| `--adam-id` | Apple App Store ID of the app, from [`apps list`](#adapty-asa-apps-list) |

`fronts` returns the whole list in one response, sorted by monthly budget, largest first. Each row is one campaign, with properties such as the following:

- `status`: The state of the campaign.
- `daily_budget`, `monthly_budget`, and `currency`: The budget of the campaign.
- `pending_change`: A budget change that the autopilot hasn't applied yet.
- `excluded`: Present when the campaign is excluded, with the `reason`.
- `cpp`, `payers`, `spend`, and `target_cpp`: The cost per paying user, the paying users, the spend, and the target cost per paying user, as of the last weekly run.
- `skip_kind`: The reason the autopilot skipped the campaign this week.
- `shrink_state`: `dialog` when the dashboard shows **Needs your decision** for the campaign.

The dashboard shows `status` under the following labels:

| `status` | Dashboard label |
|---|---|
| `active` | **Optimizing** |
| `building` | **Collecting data** |
| `shrinking` | **Reducing step by step** |
| `closed_no_demand` | **Reducing, no payers** |
| `null`, with `skip_kind` set | **Skipped this week** |

`excluded.reason` is `manual` for a campaign excluded with `exclude` or in the dashboard. It's `external_change` when someone changed the daily budget or status of the campaign outside the autopilot while it was Live. To return the campaign, make sure that no other person or tool changes it, then run [`include`](#adapty-asa-budget-autopilot-include).

### adapty asa budget-autopilot decisions

List the decisions of the budget autopilot, newest first: budget transfers, skipped campaigns, and spend guard pauses.

```bash
adapty asa budget-autopilot decisions --severity critical --execution-status failed
```

| Flag | Description |
|---|---|
| `--date-from`, `--date-to` | Period, in the same format as in [`keyword-autopilot decisions`](#adapty-asa-keyword-autopilot-decisions). Default: `--date-to` is the moment of the call, and `--date-from` is 7 days before `--date-to` |
| `--campaign` | Campaign ID (UUID) from [`campaigns list`](#adapty-asa-campaigns-list) |
| `--campaign-group` | Organization ID (UUID) from [`orgs list`](#adapty-asa-orgs-list) |
| `--adam-id` | Apple App Store ID of the app, from [`apps list`](#adapty-asa-apps-list) |
| `--severity` | `routine`, `notable`, or `critical`. Repeatable |
| `--decision-kind` | Decision kind, such as `transfer` or `spend_guard_triggered`. Repeatable |
| `--execution-status` | `planned`, `sending`, `retry_wait`, `applied`, `failed`, `dry_run`, or `observation`. Repeatable |
| `--limit` | Decisions per call. Default: `20`, max: `200` |
| `--offset` | Decisions to skip. Max: `10000` |

`critical` marks a spend guard pause. `notable` marks one of the following decisions:

- An exclusion with the reason `external_change`.
- A budget reduction that needs your decision.
- A change that the autopilot didn't send because the campaign budget had changed.

In `--execution-status`, `dry_run` marks a decision that the autopilot made in **Preview** mode. `retry_wait` marks a change that the autopilot retries after an Apple Ads error.

`--decision-kind` accepts the following values:

| Decisions | Values |
|---|---|
| Budget transfers | `transfer`, `transfer_blocked` |
| Campaign tests | `test_batch`, `test_giveback` |
| Step-by-step reductions | `shrink_step`, `shrink_exit`, `shrink_dialog` |
| Spend guard pauses | `spend_guard_triggered` |
| Exclusions and inclusions | `excluded_external_change`, `campaign_excluded`, `campaign_included` |
| Skipped campaigns | `skipped_no_economics`, `skipped_locked`, `skipped_ab_test`, `skipped_data_stale`, `skipped_invalid_state`, `skipped_c_revised`, `skipped_budget_changed`, `skipped_metadata_stale`, `skipped_no_data`, `skipped_unsupported_type`, `skipped_multi_country` |

To read every decision in a period, pass a fixed `--date-to` and raise `--offset` page by page, as for the [keyword autopilot decisions](#adapty-asa-keyword-autopilot-decisions).

### adapty asa budget-autopilot exclude

Stop the budget autopilot for one campaign.

```bash
adapty asa budget-autopilot exclude <campaign-id>
```

| Argument | Description |
|---|---|
| `campaign-id` | Campaign ID (UUID) from [`campaigns list`](#adapty-asa-campaigns-list) |

The campaign keeps its current budget. The autopilot cancels its planned changes for the campaign, but doesn't undo the changes that already reached Apple Ads. The spend guard no longer pauses the campaign.

A second `exclude` of the same campaign returns the same row. For a campaign that the autopilot neither manages nor excludes, `exclude` returns `404`.

Under `--json`, the command returns the campaign row, in the same shape as a [`fronts`](#adapty-asa-budget-autopilot-fronts) row.

### adapty asa budget-autopilot include

Return an excluded campaign to the budget autopilot.

```bash
adapty asa budget-autopilot include <campaign-id>
```

| Argument | Description |
|---|---|
| `campaign-id` | Campaign ID (UUID) from [`campaigns list`](#adapty-asa-campaigns-list) |

The command removes the exclusion, whatever its reason, and succeeds even when the campaign wasn't excluded. At the next weekly run, the autopilot decides whether to manage the campaign again, with its current budget as the starting point.

Under `--json`, the command returns `{"campaign_id": "<campaign-id>", "included": true}`.

## Metrics \{#metrics\}

### adapty asa metrics

Query metrics for any level of the account over a date range.

```bash
adapty asa metrics --entity campaign --date-from 2026-07-01 --date-to 2026-07-31
```

| Flag | Required | Description |
|---|---|---|
| `--entity` | Yes | What to report on: `campaign`, `ad-group`, `keyword`, or `ad` |
| `--date-from` | Yes | Start of the period (`YYYY-MM-DD`) |
| `--date-to` | Yes | End of the period (`YYYY-MM-DD`) |
| `--metric` | Yes | Metric name, repeatable |
| `--app` | No | Report only on these apps. Repeatable |
| `--campaign` | No | Report only on these campaigns. Repeatable |
| `--ad-group` | No | Report only on these ad groups. Repeatable |
| `--group-by` | No | Break the rows down by `country`, `day`, `week`, `month`, `quarter`, or `year`. Repeatable |
| `--by-days` | No | Renewal window in days for cohort metrics, repeatable. Maximum 16 per call. Omit for the dashboard defaults |
| `--order-by` | No | Metric or field to sort by |
| `--order-by-day` | No | Rank by a cohort metric at this renewal window. Must be one of the `--by-days` values |
| `--order` | No | `asc` or `desc`. Default: `desc` |

Accepts [pagination flags](#global-flags). Of the [list filters](#list-filters) it takes only `--app`, `--campaign`, and `--ad-group`; there is no `--search` and no `--status`. Narrow the report on anything else by matching the rows against the IDs from a scoped `list` command.

Each row is one entity, aggregated on the server and sorted by `--order-by`. A top-N question is therefore a single call — set `--order-by` and `--page-size N` rather than paging through the results and adding them up:

```bash
adapty asa metrics --entity campaign --date-from 2026-07-01 --date-to 2026-07-31 --order-by spend --page-size 5
```

`--metric` takes the metric names that Ads Manager tracks, in dashboard nomenclature — for example `spend`, `taps`, or `gross_roas`. See [Metrics](adapty-ads-manager-metrics) for the full list and how each one is calculated. A name that does not exist fails with the valid names listed in the error.

With `--entity keyword`, `--metric` also accepts the keyword-only metrics. Apple reports impression share and rank both for any ad position and for the first ad position, so each comes in two versions: `_all` and `_first`. See [Insights](adapty-ads-manager-metrics#insights) for how Apple defines them.

| Metric | Value |
|---|---|
| `impression_midpoint_all`, `impression_midpoint_first` | Impression share over the reporting period, in percent |
| `rank_all`, `rank_first` | Your app's rank against other apps for the keyword. The latest value, regardless of `--date-from` and `--date-to` |
| `search_popularity` | Search popularity from 1 to 5 |

A keyword with no report data returns `0` for these metrics. Since CLI 0.9.2, these names replace `rank` and `impression_midpoint`.

Every metric you name is computed across the whole entity level before the page is cut, so ask for the columns you read rather than the whole catalog. `subscribers` and `paid_subscribers` count unique profiles per entity, which costs around seventeen times a plain spend-and-installs call, and so do `arppu` and `arpas`, which are derived from them. At any `--entity`, those four names need `--campaign` or `--ad-group` to narrow the call:

```bash
adapty asa metrics --entity keyword --date-from 2026-07-01 --date-to 2026-07-31 --metric arpas --campaign <campaign-id>
```

Without one of those two filters the call fails with `422 cli_metric_scope_too_wide`. Scoping is the cheapest way to speed up any metrics call, because cost follows the number of entities aggregated rather than the size of the page.

The length of the reporting period is capped by the finest `--group-by` value. To report on a longer period, coarsen the grouping rather than splitting the request into several calls:

| Finest `--group-by` | Maximum period |
|---|---|
| `day` | 28 days |
| No period grouping | 90 days |
| `week` | 180 days |
| `month` and coarser | 365 days |

Day grain therefore covers four weeks at most. For a longer period ask at `week` grain, which fits half a year into one call.

Each page is capped at 5000 breakdown rows as well, a row being one entity × country × period. A page over the cap fails with `422 cli_response_too_large`. Coarsen the grouping, narrow the date window, or lower `--page-size`; when the call groups by `day`, the error names the page size that fits, so retry with that number rather than one you work out yourself. `metrics overview` returns no per-entity breakdown, so this cap never applies to it.

There is no `ltv` metric. Lifetime value is a cohort metric read at a renewal window, so `--by-days` is how you ask for the day-7 or day-90 value:

```bash
adapty asa metrics --entity campaign --date-from 2026-07-01 --date-to 2026-07-31 --metric roas --by-days 7 --by-days 90
```

`--order-by-day` ranks the rows by one of those windows, which returns the top campaigns by day-90 ROAS in a single call.

### adapty asa metrics overview

Query totals for a period, bucketed by a unit of time.

```bash
adapty asa metrics overview --entity campaign --date-from 2026-07-01 --date-to 2026-07-31 --period-unit week
```

| Flag | Required | Description |
|---|---|---|
| `--entity` | Yes | What to report on: `campaign`, `ad-group`, `keyword`, or `ad` |
| `--date-from` | Yes | Start of the period (`YYYY-MM-DD`) |
| `--date-to` | Yes | End of the period (`YYYY-MM-DD`) |
| `--period-unit` | No | Bucket size: `day`, `week`, `month`, `quarter`, or `year`. Default: `day` |
| `--metric` | No | Metric name, repeatable. Omit for every metric |
| `--by-days` | No | Renewal window in days for cohort metrics, repeatable. Maximum 16 per call |

This command returns the totals for the whole entity level plus a per-period series, so it answers "how much did I spend or earn overall" in one call. It has no ordering flags and no pagination.

On this command, `--metric` accepts cohort roots only — `revenue`, `roas`, and `arpu` — not their `gross_`, `proceeds_`, or `net_` variants. It doesn't accept the [keyword-only metrics](#adapty-asa-metrics) either.

The length of the reporting period is capped by `--period-unit`:

| `--period-unit` | Maximum period |
|---|---|
| `day` | 90 days |
| `week` | 180 days |
| `month` and coarser | 365 days |

## Competitors \{#competitors\}

### adapty asa competitors summary

Summarize the Apple Ads keywords that a set of App Store apps bid on. This returns the same competitor data as [Market Intelligence](ads-manager-market-intelligence) in the dashboard.

```bash
adapty asa competitors summary --app-ids 1668337467,6503873027
```

| Flag | Required | Description |
|---|---|---|
| `--app-ids` | Yes | Apple App Store IDs (`adam_id`), comma-separated. Between 1 and 5 values |

The reporting period and the country set are fixed on the server — the last full month, across every country. This command has no period, country, or pagination flags.

## Change history \{#change-history\}

Change history comes live from the Apple Ads API. Adapty does not store it, and Apple keeps it for 6 months. It covers every change in the organization, including changes made in Apple Ads directly, by Apple Support, or by other API tools.

### adapty asa change-history list

List the changes made in one Apple Ads organization, newest first.

```bash
adapty asa change-history list --campaign-group <campaign-group-id> --date-from 2026-10-01 --entity-type Campaign --event-type UPDATE
```

| Flag | Required | Description |
|---|---|---|
| `--campaign-group` | Yes | Organization to read (UUID from [`orgs list`](#adapty-asa-orgs-list)). One organization per call. To read several, run the command for each one |
| `--date-from` | No | Start of the period (`YYYY-MM-DD`). Default: 7 days ago |
| `--date-to` | No | End of the period (`YYYY-MM-DD`). Default: today. The period can span at most 14 days |
| `--entity-type` | No | `Campaign`, `AdGroup`, `Keyword`, `NegativeKeyword`, `Ad`, `Creative`, `LocationGroup`, `Org`, or `AdAccount`. Repeatable. Default: every type except `Org` and `AdAccount`. `Org` and `AdAccount` can't be combined with the other types |
| `--event-type` | No | `CREATE`, `UPDATE`, or `DELETE`. Repeatable |
| `--user-type` | No | Who made the change: `CUSTOMER` (in Apple Ads), `CUSTOMER_API` (through the Apple Ads API), or `APPLE_SUPPORT`. Repeatable |
| `--campaign`, `--ad-group`, `--entity-id` | No | Apple's numeric IDs of the campaign, the ad group, or the changed entity. Repeatable |
| `--user` | No | Apple user ID of the person who made the change. Repeatable |
| `--txn` | No | Apple transaction ID. Repeatable |
| `--fields` | No | Expand each change into one row per changed field, with its old and new values |

:::important
Unlike the [list filters](#list-filters) of other commands, `--campaign`, `--ad-group`, and `--entity-id` take Apple's numeric IDs, as printed in the change history rows — not UUIDs. Likewise, `modified_by` in each row is an Apple user ID, not an email.
:::

Each row is one transaction: who made it (`modified_by`, `user_type`), when (`event_time`), and the entities it changed. Every entity carries a `detail_id` for [`change-history get`](#adapty-asa-change-history-get).

With `--fields`, the page size defaults to 10, and a larger `--page-size` is refused. A page that would need more than 20 lookups fails: narrow the filters, or drop `--fields` and read single changes with `change-history get`.

Accepts [pagination flags](#global-flags). `--page` × `--page-size` can't exceed 1000.

### adapty asa change-history get

Show the field-level changes of one entity in one transaction.

```bash
adapty asa change-history get Campaign.444555666.TXN_ID --campaign-group <campaign-group-id>
```

| Argument | Description |
|---|---|
| `detail-id` | `detail_id` from [`change-history list`](#adapty-asa-change-history-list), in the form `EntityType.entityId.txnId` |

| Flag | Required | Description |
|---|---|---|
| `--campaign-group` | Yes | Organization the change belongs to. Take it from `campaign_group_id` in the list row |

The response lists each changed field with its `old_values` and `new_values`, plus the entity's metadata in `entity_metadata`. A `detail_id` that Apple has no record of returns `404`.

## Errors \{#errors\}

| Status | Code | Meaning |
|---|---|---|
| `402` | `ads_manager_subscription_required` | The company has no active Ads Manager subscription |
| `403` | `cli_ad_account_unreadable` | `change-history` can't read the organization: the Apple Ads token is revoked, the organization is no longer linked, or Apple denied access |
| `404` | — | The entity does not exist, or it belongs to another company. For [`budget-autopilot exclude`](#adapty-asa-budget-autopilot-exclude), the autopilot neither manages nor excludes the campaign |
| `409` | `cli_idempotency_in_progress` | A write with the same idempotency key is still running |
| `409` | — | The keyword passed to [`keyword-autopilot enroll`](#adapty-asa-keyword-autopilot-enroll) is already enrolled. The enrollment stays as it was |
| `422` | `cli_idempotency_key_reuse` | The same idempotency key was used with a different request body |
| `422` | `cli_metric_scope_too_wide` | A profile-counting metric was requested without `--campaign` or `--ad-group` |
| `422` | `cli_response_too_large` | A `metrics` page would exceed 5000 breakdown rows |
| `422` | — | [`keyword-autopilot enroll`](#adapty-asa-keyword-autopilot-enroll) can't enroll the keyword, or a [`keyword-autopilot report`](#adapty-asa-keyword-autopilot-report) is over its limits |
| `429` | `cli_analytics_busy` | The analytics pool is busy, or another keyword pool build or `keyword-autopilot report` for the company is still running. The wait is in the `Retry-After` header |
| `429` | `cli_cooldown_active` | Too many rejected requests put the token into a cool-down |
| `429` | `cli_rate_limit_exceeded` | The command used up its rate limit. The wait is in the `Retry-After` header |
| `429` | `cli_upstream_rate_limited` | Apple rate-limited a `change-history` request. The wait from Apple is in the `Retry-After` header |
| `504` | `cli_read_timeout` | A `change-history` request or a `keyword-autopilot report` took longer than 50 seconds. Narrow the period or the filters |

Metrics and the search terms list share one analytics budget per company: 5 calls per minute, and at most 2 in any 10 seconds. `change-history` has its own budget: 30 calls per minute, at most 5 in any 10 seconds, and one request at a time per company. `keyword-autopilot report` has its own limit: 6 calls per minute, and one report at a time per company. The autopilot commands that only read data, except `keyword-autopilot report`, have one shared limit with most `list` and `get` commands: 120 calls per minute in total. `keywords list` and `change-history` have limits of their own. All commands that change your account, the autopilot ones included, have one shared limit: 20 calls per minute in total. A rejected request counts toward a cool-down only when the same command is refused again before the `Retry-After` of its previous refusal has run out, so a request sent after that wait doesn't count. 20 such rejections within 5 minutes start an escalating cool-down of 5 minutes, then 30 minutes, then 3 hours. Retrying during the pause does not extend it, but the fix is to correct the failing request rather than repeat it.

The CLI handles short waits for you. On a `429` that is not a cool-down, if `Retry-After` is 60 seconds or less, the command waits for that long and retries once, reporting the wait on standard error.
