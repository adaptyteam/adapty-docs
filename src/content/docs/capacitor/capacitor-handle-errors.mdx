Every error returned by the SDK is an `AdaptyError` instance. Here is an example:

:::tip
**Enable verbose logs before debugging.** Most `AdaptyError`s wrap an underlying StoreKit, Play Billing, network, or backend error. With verbose logs on (`adapty.setLogLevel({ logLevel: 'verbose' })` — see [Logging](sdk-installation-capacitor#logging)), that wrapped error is printed to the console, which usually tells you the actual cause. The `detail` property on `AdaptyError` is populated regardless of log level — verbose logs just surface it in the console.
:::

```typescript showLineNumbers
import { adapty, AdaptyError, ErrorCodeName } from '@adapty/capacitor';

try {
  const result = await adapty.makePurchase({ product });
  
  // Handle purchase result
  if (result.type === 'success') {
    console.log('Purchase successful:', result.profile);
  } else if (result.type === 'user_cancelled') {
    console.log('User cancelled the purchase');
  } else if (result.type === 'pending') {
    console.log('Purchase is pending');
  }
} catch (error) {
  if (error instanceof AdaptyError) {
    console.error('Adapty error:', error.adaptyCode, error.localizedDescription);
    
    // Handle specific error codes
    switch (error.adaptyCode) {
      case ErrorCodeName.cantMakePayments:
        console.log('In-app purchases are not allowed on this device');
        break;
      case ErrorCodeName.notActivated:
        console.log('Adapty SDK is not activated');
        break;
      case ErrorCodeName.productPurchaseFailed:
        console.log('Purchase failed:', error.detail);
        break;
      default:
        console.log('Other error occurred:', error.detail);
    }
  } else {
    console.error('Non-Adapty error:', error);
  }
}
```

## Error Properties

The `AdaptyError` class provides the following properties:

| Property | Type | Description |
|----------|------|-------------|
| `adaptyCode` | `number` | Numeric error code (e.g., `1003` for cantMakePayments) |
| `codeName` | `ErrorCodeName \| undefined` | Name of the error code (e.g., `'cantMakePayments'`), or `undefined` for a code unknown to your SDK version. Available starting from SDK version 4.3.0 |
| `localizedDescription` | `string` | User-friendly error message |
| `detail` | `string \| undefined` | Additional error details (optional) |
| `message` | `string` | Full error message including code and description |

## Error Codes

The SDK exports constants and utilities for working with error codes:

### ErrorCodeName Constant

Maps string identifiers to numeric codes:

```typescript
import { ErrorCodeName } from '@adapty/capacitor';

ErrorCodeName.cantMakePayments // 1003
ErrorCodeName.notActivated // 2002
ErrorCodeName.networkFailed // 2005
```

### ErrorCode Constant

Maps numeric codes to string identifiers:

```typescript
import { ErrorCode } from '@adapty/capacitor';

ErrorCode[1003] // 'cantMakePayments'
ErrorCode[2002] // 'notActivated'
ErrorCode[2005] // 'networkFailed'
```

### Helper Functions

```typescript
import { getErrorCode, getErrorPrompt } from '@adapty/capacitor';

// Get numeric code from string name:
getErrorCode('cantMakePayments') // 1003

// Get string name from numeric code:
getErrorPrompt(1003) // 'cantMakePayments'
```

Native SDKs can return codes that are newer than your installed Capacitor SDK, and `error.adaptyCode` passes them through. Starting from SDK 4.3.0, its TypeScript type admits these codes too. To tell a known code from a new one, use `isKnownErrorCode` and `getErrorCodeName`:

```typescript
import { getErrorCodeName, getErrorPrompt, isKnownErrorCode } from '@adapty/capacitor';

isKnownErrorCode(1003) // true
getErrorCodeName(1003) // 'cantMakePayments'
getErrorCodeName(9999) // undefined: a code unknown to this SDK version
getErrorPrompt(9999)   // 'Unknown code: 9999'
```

New codes for 4.3 features:

| Name | Code | Description |
|------|------|-------------|
| `billingPlanUnavailable` | 1060 | iOS only. The product doesn't offer the requested billing plan on this device or in this storefront. A [12-month commitment](app-store-12-month-commitment) plan requires iOS 26.4 or later, and an app built with Xcode 26.5 or later. |
| `operationInProgress` | 3201 | iOS only. Returned by `showStoreMessages` when a previous call is still showing [store messages](capacitor-store-messages). Wait for it to finish, then try again. |
| `resolverFailure` | 3202 | iOS only. Returned by `showStoreMessages` when no foreground-active window scene exists. Call the method again when the app is in the foreground. |

SDK 4.3.0 also names codes that earlier versions reported as unknown: 2, 1020, 1030, 1050, 3020, and 4104–4107. For example, `getErrorPrompt(1050)` now returns `'paymentPendingError'` instead of `'Unknown code: 1050'`.

### Comparing Error Codes

**Important:** `error.adaptyCode` is a **number**, so compare it directly with numeric codes:

```typescript
// Option 1: Use ErrorCodeName constant (recommended) ✅
if (error.adaptyCode === ErrorCodeName.cantMakePayments) {
  console.log('Cannot make payments');
}

// Option 2: Compare with numeric literal ✅
if (error.adaptyCode === 1003) {
  console.log('Cannot make payments');
}

// NOT like this ❌ - compares number to string and will never match
if (error.adaptyCode === ErrorCode[1003]) {
}
```

## Global Error Handler

You can set up a global error handler to catch all Adapty errors:

```typescript showLineNumbers
import { AdaptyError, ErrorCodeName } from '@adapty/capacitor';

// Set up global error handler
AdaptyError.onError = (error: AdaptyError) => {
  console.error('Global Adapty error:', {
    code: error.adaptyCode,
    message: error.localizedDescription,
    detail: error.detail
  });
  
  // Handle specific error types globally
  if (error.adaptyCode === ErrorCodeName.notActivated) {
    // SDK not activated - maybe retry activation
    console.log('SDK not activated, attempting to reactivate...');
  }
};
```

## Common Error Handling Patterns

### Handle Purchase Errors

```typescript showLineNumbers
import { adapty, AdaptyError, ErrorCodeName } from '@adapty/capacitor';
import type { AdaptyPaywallProduct } from '@adapty/capacitor';

async function handlePurchase(product: AdaptyPaywallProduct) {
  try {
    const result = await adapty.makePurchase({ product });
    
    if (result.type === 'success') {
      console.log('Purchase successful:', result.profile);
    } else if (result.type === 'user_cancelled') {
      console.log('User cancelled the purchase');
    } else if (result.type === 'pending') {
      console.log('Purchase is pending');
    }
  } catch (error) {
    if (error instanceof AdaptyError) {
      switch (error.adaptyCode) {
        case ErrorCodeName.cantMakePayments:
          console.log('In-app purchases not allowed');
          break;
        case ErrorCodeName.productPurchaseFailed:
          console.log('Purchase failed:', error.detail);
          break;
        default:
          console.error('Purchase error:', error.localizedDescription);
      }
    }
  }
}
```

### Handle Network Errors

```typescript showLineNumbers
import { adapty, AdaptyError, ErrorCodeName } from '@adapty/capacitor';

async function fetchFlow(placementId: string) {
  try {
    const flow = await adapty.getFlow({ placementId });
    return flow;
  } catch (error) {
    if (error instanceof AdaptyError) {
      switch (error.adaptyCode) {
        case ErrorCodeName.networkFailed:
          console.log('Network error, retrying...');
          // Implement retry logic
          break;
        case ErrorCodeName.serverError:
          console.log('Server error:', error.detail);
          break;
        case ErrorCodeName.notActivated:
          console.log('SDK not activated');
          break;
        default:
          console.error('Paywall fetch error:', error.localizedDescription);
      }
    }
    throw error;
  }
}
```

## Custom UI codes

Starting from SDK 4.4.0, `getErrorCode` accepts the names of codes 4001–4003, 4103, 4108, and 4200.

| Error | Code | Solution |
|:---|:---|:---|
| platformNotSupported | 4001 | iOS only. Flows require iOS 16 or later, and the device runs iOS 15. <br/> Show your own content instead, such as a [custom paywall](capacitor-implement-paywalls-manually). |
| adaptyNotActivated | 4002 | iOS only. Your app requested an onboarding while AdaptyUI wasn't activated: before `adapty.activate()` completed, or after activation with `activateUi: false`. <br/> Request the onboarding after activation completes. |
| adaptyUINotActivated | 4003 | iOS only. Your app requested a flow view while AdaptyUI wasn't activated: before `adapty.activate()` completed, or after activation with `activateUi: false`. <br/> Request the flow view after activation completes. |
| wrongComponentType | 4103 | iOS only. The flow has an element of an unexpected type. |
| wrongAssetType | 4104 | The flow has an asset of an unexpected type. |
| jsException | 4105 | The flow script threw an exception. <br/> [Enable verbose logging](sdk-installation-capacitor#logging) to see the underlying JavaScript error. |
| navigatorNotFound | 4106 | The flow script opened a navigator that the flow doesn't have. |
| invalidActionUrl | 4107 | An open-URL action of the flow has no valid URL. <br/> In the Flow & Paywall Builder, verify the URL of the action. |
| unsupportedUrlScheme | 4108 | iOS only. The in-app browser can't open a URL that isn't `http` or `https`, such as a `mailto:` URL. <br/> To open such URLs, select **Open in external browser** in the **Open URL** action. |
| webKit | 4200 | iOS only. The web view of an onboarding failed. <br/> [Enable verbose logging](sdk-installation-capacitor#logging) to see the underlying error. |
