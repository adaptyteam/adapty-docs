If you've created a flow, or a paywall in the old Paywall Builder, you don't need to worry about rendering it in your mobile app code to display it to the user. Such a flow contains both what should be shown within it and how it should be shown.

Before you start, ensure that:

1. You have created a [flow](paywall-builder-templates) or a [paywall](create-paywall).
2. You have added it to a [placement](placements).
3. You have [fetched the flow and prepared the view](capacitor-get-pb-paywalls).

   <CapacitorFlowsRequireIos16 />

:::warning

This guide is for **flows and paywalls rendered by Adapty** only, which require SDK v4.0 or later. The process for presenting flows differs for custom paywalls.

- To present custom paywalls, see [Present custom paywalls](present-remote-config-paywalls-capacitor).

:::

To display a flow or paywall as a standalone screen, use the `view.present()` method on the `view` created by the [`createFlowView`](capacitor-get-pb-paywalls#fetch-the-view-configuration) method. By default, a dismissed `view` is destroyed. To display the flow again, call `createFlowView` one more time to create a new `view` instance, or [keep the closed flow](#keep-a-closed-flow-for-later) when you dismiss it.

:::warning
Reusing a destroyed `view` results in an error.
:::

```typescript showLineNumbers
import { createFlowView } from '@adapty/capacitor';

const view = await createFlowView(flow);

// Optional: handle flow events (close, purchase, restore, etc)
// await view.setEventHandlers({ ... });

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

:::important
Calling `setEventHandlers` multiple times will override the handlers you provide, replacing both default and previously set handlers for those specific events.
:::

## Configure iOS presentation style

Configure how the flow is presented on iOS by passing the `iosPresentationStyle` parameter to the `present()` method. The parameter accepts `'full_screen'` (default) or `'page_sheet'` values. On Android, flows are always shown full screen inside your app's Activity.

```typescript showLineNumbers
try {
  await view.present({ iosPresentationStyle: 'page_sheet' });
} catch (error) {
  // handle the error
}
```

## Keep a closed flow for later

:::info
The `destroy` option and the `destroy()` method are available starting from SDK version 4.3.0.
:::

Keep a flow when the user can reopen it soon — for example, a paywall behind a button in your settings screen — so it opens without loading again and where the user left it.

By default, `view.dismiss()` closes the flow and destroys its native view, so the `view` can't be presented again. To present the same flow again later, pass `destroy: false`. The next `present()` call opens the flow on the screen where the user closed it, with the state the user left it in, and your event handlers stay set:

```typescript showLineNumbers
// Close the flow and keep its native view in memory
await view.dismiss({ destroy: false });

// Later: open the flow again on the same screen
await view.present();
```

The native view stays in memory until you release it. When you no longer need the flow, call `destroy()`:

```typescript showLineNumbers
await view.dismiss({ destroy: false });
// ...
await view.destroy();
```

`destroy()` dismisses the view first if it's still on screen, and clears its event handlers. Call it only for a view that you closed with `destroy: false`: a regular `dismiss()` releases the view on its own, and a `destroy()` call after it fails.

Release a kept view when the component that owns it goes away — in Angular's `ngOnDestroy`, a React `useEffect` cleanup, or Vue's `onUnmounted`. Otherwise the native view stays in memory for the rest of the session. Catch the error: the view may already be released, for example after an event handler returned `true`.

```typescript showLineNumbers
// For example, in a React useEffect cleanup
return () => {
  view.destroy().catch(() => {
    // the view was already released
  });
};
```

An event handler that returns `true` closes the flow with a regular `dismiss()`, which destroys the native view even if you kept it earlier. The default `onCloseButtonPress` and `onError` handlers return `true`. The same applies to any handler you make return `true`, such as `onAndroidSystemBack`. To keep the flow when the user closes it, close the flow yourself and return `false`:

```typescript showLineNumbers
await view.setEventHandlers({
  onCloseButtonPress() {
    view.dismiss({ destroy: false }).catch(error => {
      // handle the error
    });
    return false;
  },
});
```

## Use developer-defined timer

Use this section for a timer with the **Developer defined** behavior in the Flow & Paywall Builder. In the builder, each such timer has a **Timer ID** (see [Let your app set the end date](flow-timer#let-your-app-set-the-end-date)), and your app sets the end date for it. Use the same Timer ID in your code as in the builder, character for character, including letter case and spaces. If the IDs differ, the timer gets no end date from your app.

To set the end dates, pass the `customTimers` parameter to `createFlowView`: an object that maps each Timer ID to a `Date`, the end date of the timer.

```typescript showLineNumbers
import { createFlowView } from '@adapty/capacitor';

const customTimers = {
  CUSTOM_TIMER_NY: new Date(new Date().getFullYear() + 1, 0, 1), // next New Year's Day
};

try {
  const view = await createFlowView(flow, { customTimers });
  await view.present();
} catch (error) {
  // handle the error
}
```

In this example, `CUSTOM_TIMER_NY` is the Timer ID of a **Developer defined** timer in the builder. The timer shows the time left until the next New Year's Day, for example `13d 09h 03m 34s`.

The SDK reads `customTimers` once, when it creates the view, so a date that you compute, such as 6 hours from now, counts from that moment. If the date is in the past, the timer shows zero at once and its **On timer end** trigger runs. If `customTimers` has no key for a Timer ID, the timer counts down one hour from the screen open.

## Show dialog

Use this method instead of native alert dialogs when a flow view is presented on Android. On Android, regular alerts appear behind the flow view, which makes them invisible to users. This method ensures proper dialog presentation above the flow on all platforms.

```typescript showLineNumbers
try {
  const action = await view.showDialog({
    title: 'Close paywall?',
    content: 'You will lose access to exclusive offers.',
    primaryActionTitle: 'Stay',
    secondaryActionTitle: 'Close',
  });

  if (action === 'secondary') {
    // User confirmed - close the flow
    await view.dismiss();
  }
  // If primary - do nothing, user stays
} catch (error) {
  // handle error
}
```

## Send messages to a flow

The `sendAppMessage` method of a flow view sends a message to the flow, as a JSON object. The method is reserved for future Flow & Paywall Builder capabilities. Flows ignore these messages, so you don't need to call the method.

## Replace one subscription with another

When a user attempts to purchase a new subscription while another subscription is active on Android, you can control how the new purchase should be handled by passing subscription update parameters when creating the flow view. To replace the current subscription with the new one, use `productPurchaseParams` in `createFlowView` with the `oldSubVendorProductId` and `prorationMode` parameters.

```typescript showLineNumbers
import { Capacitor } from '@capacitor/core';
import { createFlowView } from '@adapty/capacitor';
import type { MakePurchaseParamsInput } from '@adapty/capacitor';

const productPurchaseParams = flow.paywalls
  .flatMap((paywall) => paywall.productIdentifiers)
  .map((productId) => {
    const params: MakePurchaseParamsInput = {};
    if (Capacitor.getPlatform() === 'android') {
      params.android = {
        subscriptionUpdateParams: {
          oldSubVendorProductId: 'PRODUCT_ID_OF_THE_CURRENT_ACTIVE_SUBSCRIPTION',
          prorationMode: 'with_time_proration',
        },
      };
    }
    return { productId, params };
  });

const view = await createFlowView(flow, { productPurchaseParams });
```

If you've customized a paywall using the Paywall Builder, you don't need to worry about rendering it in your mobile app code to display it to the user. Such a paywall contains both what should be shown within the paywall and how it should be shown.

:::warning
This guide is for paywalls built in the old Paywall Builder only. To present custom paywalls, see [Present custom paywalls](present-remote-config-paywalls-capacitor).
:::

To display a paywall, use the `view.present()` method on the `view` created by the [`createPaywallView`](capacitor-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder) method. Each `view` can only be used once. If you need to display the paywall again, call `createPaywallView` one more time to create a new `view` instance.

:::warning

Reusing the same `view` without recreating it may result in an error.
:::

```typescript showLineNumbers
import { adapty, createPaywallView } from '@adapty/capacitor';

const view = await createPaywallView(paywall);

view.setEventHandlers({
  onUrlPress(url) {
    window.open(url, '_blank');
    return false;
  },
});

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

## Use developer-defined timer

To use developer-defined timers in your mobile app, use the `timerId`, in this example, `CUSTOM_TIMER_NY`, the **Timer ID** of the developer-defined timer you set in the Adapty dashboard. It ensures your app dynamically updates the timer with the correct value—like `13d 09h 03m 34s` (calculated as the timer's end time, such as New Year's Day, minus the current time).

```typescript showLineNumbers
const customTimers = { 'CUSTOM_TIMER_NY': new Date(2025, 0, 1) };

const view = await createPaywallView(paywall, { customTimers });
```

In this example, `CUSTOM_TIMER_NY` is the **Timer ID** of the developer-defined timer you set in the Adapty dashboard. The timer ensures your app dynamically updates the timer with the correct value—like `13d 09h 03m 34s` (calculated as the timer's end time, such as New Year's Day, minus the current time).
