A [flow](adapty-flow-builder) can ask users for a system permission with the **Request permission** action, for example push notifications on an onboarding screen that explains what the notifications are for, or camera access before a feature that scans documents. The Adapty SDK doesn't show the system permission dialog itself. It passes the request to an `IAdaptyUISystemRequestsHandler` in your app. Your app shows the dialog and returns the user's answer, and the flow continues.

## Before you start

You need:

- **Adapty Unity SDK 4.1.0 or later**: Earlier versions don't have `IAdaptyUISystemRequestsHandler` with this signature. The latest stable release is 4.1.2. On Android, the changelog of 4.3.0-beta.1 lists two fixes for permission requests in 4.1.x:
  - **GameActivity**: In an app with the GameActivity entry point, the default for new Unity 6 projects, no event reaches C#, so your handler is never called.
  - **Answers from another thread**: A `respond` call made off Unity's main thread while a flow is on screen reaches the flow only after the flow closes.

  The fixes ship in 4.3.0-beta.1, a pre-release that requires Unity 6.
- **A flow with the Request permission action**: In the Flow & Paywall Builder, add the **Request permission** action to an element's **On Tap** or **On Screen Appear** trigger. In the action, select the permission in the **Permission** field, and add the actions to run after the user answers to its outcome sections, such as **Navigate Next** in **After response**. For the action settings, see [Request permission](onboarding-actions#request-permission).
- **For notifications on iOS**: The [Mobile Notifications](https://docs.unity3d.com/Packages/com.unity.mobile.notifications@latest) package, which the handler in this guide uses to show the iOS dialog. In **Project Settings > Mobile Notifications > iOS**, turn off **Request Authorization on App Launch**, so that the dialog appears when the flow asks for it.
- **For tracking on iOS**: The `com.unity.ads.ios-support` package, which the code in this guide uses to show the App Tracking Transparency alert.
- **The declarations of the permissions that your handler requests**: A purpose string in `Info.plist` on iOS, and a permission in the Android manifest. See [Declare the permissions](#declare-the-permissions).
- **For notifications on Android**: A target API level of 33 or higher in **Player Settings**. Only apps that target Android 13 or later choose when the notification permission dialog appears.

## How the flow requests a permission

1. The flow reaches the **Request permission** action: the user taps the element, or the screen appears.
2. The Adapty SDK calls `FlowViewDidAskPermission` on your handler with the permission selected in the action, such as `push` or `camera`.
3. Your app requests the permission from the OS and calls `respond` once with the answer and a status.
4. The flow runs the actions of one outcome section.

<FlowPermissionAnswers />

The flow waits on the screen until your app calls `respond`. If your app never calls it, the flow stays on the screen. If the OS doesn't show the dialog, for example because the user already answered it, your app gets the answer at once, and the flow runs the outcome actions right away. If those actions leave the screen, the user sees the screen that requests the permission only for a moment.

With **On Screen Appear**, the flow doesn't send the request again when the user comes back to the screen with a **Navigate back** action, unless every outcome section of the action is empty. With **On Tap**, each tap sends a new request. The flow sends one permission request at a time: while a request waits for your answer, a tap on an element that requests a permission does nothing.

## Implement the handler

:::warning
**Request only the permissions that your app declares, and answer `respond(false, "unsupported")` for any other permission.** For most permissions, iOS terminates the app when the app requests a permission whose purpose string is missing from `Info.plist`. A flow author can add a request for any permission at any time, and the flow also reaches app versions released before the request was added.
:::

To answer permission requests, implement the `IAdaptyUISystemRequestsHandler` interface. The handler below passes each permission to its own method, such as `RequestPush()` or `RequestCamera()`, and answers any other value as unsupported without a dialog:

```csharp showLineNumbers title="FlowSystemRequestsHandler.cs"
using System;
using System.Collections.Generic;
using AdaptySDK;
using UnityEngine;

public partial class FlowSystemRequestsHandler : MonoBehaviour, IAdaptyUISystemRequestsHandler
{
    public void FlowViewDidAskPermission(
        AdaptyUIFlowView view,
        string permission,
        IReadOnlyDictionary<string, string> customArgs,
        Action<bool, string> respond
    ) {
        try
        {
            switch (permission)
            {
                case "push": RequestPush(respond); return;
                case "tracking": RequestTracking(respond); return;
                case "location_when_use": RequestLocationWhenInUse(respond); return;
                case "location_always": RequestLocationAlways(respond); return;
                case "location_full_accuracy": RequestLocationFullAccuracy(respond); return;
                case "camera": RequestCamera(respond); return;
                case "microphone": RequestMicrophone(respond); return;
                case "photos": RequestPhotos(respond); return;
                case "media_library": RequestMediaLibrary(respond); return;
                case "music": RequestMusic(respond); return;
                case "speech": RequestSpeech(respond); return;
                case "contacts": RequestContacts(respond); return;
                case "calendar": RequestCalendar(respond); return;
                case "reminders": RequestReminders(respond); return;
                case "health": RequestHealth(respond); return;
                case "motion": RequestMotion(respond); return;
                case "bluetooth": RequestBluetooth(respond); return;
                case "local_network": RequestLocalNetwork(respond); return;
                case "homekit": RequestHomeKit(respond); return;
                case "focus_status": RequestFocusStatus(respond); return;
                case "siri": RequestSiri(respond); return;
                default:
                    // A permission this app version doesn't request: answer without a dialog.
                    respond(false, "unsupported");
                    return;
            }
        }
        catch (Exception e)
        {
            // Without an answer, the flow stays on the screen.
            Debug.LogException(e);
            respond(false, null);
        }
    }

    public void FlowViewDidRequestAppReview(AdaptyUIFlowView view)
    {
        // Shows the native store review prompt, as the SDK does without a handler.
        AdaptyUI.RequestAppReview(null);
    }
}
```

Copy the code only for the permissions that your app requests from [Code for each permission](#code-for-each-permission), and delete the other cases from the `switch`, so that the handler answers them `unsupported`. Your app then doesn't need the frameworks and purpose strings of those permissions. The class is `partial`, so the code of each permission is a separate file.

`FlowViewDidAskPermission` receives:

- **`view`**: The flow view that sent the request.
- **`permission`**: The permission selected in the action, as a string from the **Value** column in [Declare the permissions](#declare-the-permissions).
- **`customArgs`**: Custom arguments of the request. The **Request permission** action sends none, so the value is `null`.
- **`respond`**: The callback that returns the answer to the flow. Pass `true` if the user allowed the permission and `false` otherwise. The second argument is the status of the answer, such as `"granted"` or `"permanently_denied"`.

Call `respond` exactly once for each request. The Adapty SDK ignores a second call and prints a warning to the Unity console. `respond` is safe to call from any thread. On Android in 4.1.x, call it on Unity's main thread: an answer from another thread reaches the flow only after the flow closes.

If `FlowViewDidAskPermission` throws before it calls `respond`, the Adapty SDK logs the exception and sends no answer, so the flow stays on the screen. Catch exceptions and call `respond(false, null)`, as the handler above does.

A granted notification permission lets your app show notifications. To receive push notifications, register the device with your push provider, as your app does outside flows.

`IAdaptyUISystemRequestsHandler` also requires `FlowViewDidRequestAppReview`. With a handler registered, the Adapty SDK doesn't request a store review on its own, so call `AdaptyUI.RequestAppReview(null)` in it to keep the native review prompt, as in the example.

The code of each permission uses shared methods. Add them once:

- **On Android**: `RequestAndroid()` requests runtime permissions with a small Java plugin. When the user doesn't allow access, it decides the status with the [rules for every permission](flow-permissions#rules-for-every-permission): it reads `shouldShowRequestPermissionRationale()` before and after the request, and keeps a flag in `SharedPreferences` for each permission that the app requested before.
- **On iOS**: Unity has no API for most permissions, so a [native plugin](https://docs.unity.com/en-us/engine/current/manual/platform-specific/iphone/ios-developing/plugins-for-ios/ios-native-plugin-call) requests them. The plugin of each permission is an Objective-C or Swift file in `Assets/Plugins/iOS`, which Unity adds to the Xcode project. Its C# code calls the plugin with `[DllImport("__Internal")]`, and `RequestNative()` passes the status from the plugin's callback to the flow. The plugins use iOS 15 APIs: set **Target minimum iOS Version** in **Player Settings > iOS > Other Settings** to 15.0 or later.

```csharp showLineNumbers title="FlowSystemRequestsHandler.Helpers.cs"
using System;
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
#if UNITY_ANDROID
using UnityEngine.Android;
#endif

public partial class FlowSystemRequestsHandler
{
#if UNITY_IOS
    // The callback of every native function in Assets/Plugins/iOS.
    public delegate void NativePermissionCallback(int requestId, string status);

    static readonly Dictionary<int, Action<bool, string>> nativeRequests = new Dictionary<int, Action<bool, string>>();
    static int lastNativeRequestId;

    // Calls a native request function and passes its status to the flow.
    static void RequestNative(Action<int, NativePermissionCallback> nativeRequest, Action<bool, string> respond)
    {
        int requestId;
        lock (nativeRequests)
        {
            requestId = ++lastNativeRequestId;
            nativeRequests[requestId] = respond;
        }
        nativeRequest(requestId, OnNativeAnswer);
    }

    [AOT.MonoPInvokeCallback(typeof(NativePermissionCallback))]
    static void OnNativeAnswer(int requestId, string status)
    {
        Action<bool, string> respond;
        lock (nativeRequests)
        {
            if (!nativeRequests.TryGetValue(requestId, out respond)) return;
            nativeRequests.Remove(requestId);
        }
        respond(status == "granted" || status == "limited" || status == "provisional", status);
    }

    // Runs a coroutine that answers a request, and answers without a status if it throws.
    static IEnumerator AnswerOnException(IEnumerator routine, Action<bool, string> respond)
    {
        while (true)
        {
            object current;
            try
            {
                if (!routine.MoveNext()) yield break;
                current = routine.Current;
            }
            catch (Exception e)
            {
                Debug.LogException(e);
                respond(false, null);
                yield break;
            }
            yield return current;
        }
    }
#endif

#if UNITY_ANDROID
    // The Java plugin in Assets/Plugins/Android/FlowPermissions.androidlib.
    const string FlowPermissionsPlugin = "com.example.flowpermissions.FlowPermissions";

    // Starts tracking the activity on screen, so that a request goes to the flow's activity.
    [RuntimeInitializeOnLoadMethod]
    static void StartFlowPermissionsPlugin()
    {
        if (Application.platform != RuntimePlatform.Android) return;
        using (var plugin = new AndroidJavaClass(FlowPermissionsPlugin))
        using (var activity = AndroidActivity())
            plugin.CallStatic("start", activity);
    }

    static int AndroidSdkInt()
    {
        using (var version = new AndroidJavaClass("android.os.Build$VERSION"))
            return version.GetStatic<int>("SDK_INT");
    }

    static AndroidJavaObject AndroidActivity()
    {
        using (var player = new AndroidJavaClass("com.unity3d.player.UnityPlayer"))
            return player.GetStatic<AndroidJavaObject>("currentActivity");
    }

    static int AndroidTargetSdk()
    {
        using (var activity = AndroidActivity())
        using (var info = activity.Call<AndroidJavaObject>("getApplicationInfo"))
            return info.Get<int>("targetSdkVersion");
    }

    static bool AndroidHasFeature(string feature)
    {
        using (var activity = AndroidActivity())
        using (var packageManager = activity.Call<AndroidJavaObject>("getPackageManager"))
            return packageManager.Call<bool>("hasSystemFeature", feature);
    }

    // Requests one permission: granted when the user allows it.
    static void RequestAndroid(string permission, Action<bool, string> respond)
    {
        RequestAndroid(
            new[] { permission },
            () => Permission.HasUserAuthorizedPermission(permission) ? "granted" : null,
            respond);
    }

    // Requests several permissions in one dialog. currentStatus returns "granted" or "limited"
    // for access, "denied" for a refusal, or null for no access: then the rationale rules decide.
    static void RequestAndroid(string[] permissions, Func<string> currentStatus, Action<bool, string> respond)
    {
        if (currentStatus() == "granted")
        {
            respond(true, "granted");
            return;
        }
        var rationaleBefore = ShouldShowRationale(permissions);
        var requestedBefore = MarkRequested(permissions);
        var callback = new PermissionResultCallback(outcome =>
        {
            try
            {
                var status = currentStatus();
                if (status == "granted" || status == "limited") respond(true, status);
                else if (status != null) respond(false, status);
                // No activity on screen could show the dialog.
                else if (outcome == "failed") respond(false, null);
                // A rationale before or after the request: the user declined the dialog.
                else if (rationaleBefore || ShouldShowRationale(permissions)) respond(false, "denied");
                // Android returned no result: the user closed the dialog without a choice.
                else if (outcome == "dismissed") respond(false, null);
                // No rationale before or after a repeated request: Android showed no dialog.
                else if (requestedBefore) respond(false, "permanently_denied");
                // No rationale before or after the first request: the user closed the dialog.
                else respond(false, null);
            }
            catch (Exception e)
            {
                Debug.LogException(e);
                respond(false, null);
            }
        });
        using (var plugin = new AndroidJavaClass(FlowPermissionsPlugin))
            plugin.CallStatic("request", permissions, callback);
    }

    static bool ShouldShowRationale(string[] permissions)
    {
        using (var plugin = new AndroidJavaClass(FlowPermissionsPlugin))
            return plugin.CallStatic<bool>("shouldShowRationale", new object[] { permissions });
    }

    // The plugin calls it on Unity's thread when a request ends.
    class PermissionResultCallback : AndroidJavaProxy
    {
        readonly Action<string> onOutcome;

        public PermissionResultCallback(Action<string> onOutcome)
            : base(FlowPermissionsPlugin + "$Callback")
        {
            this.onOutcome = onOutcome;
        }

        [UnityEngine.Scripting.Preserve]
        public void onResult(string outcome) => onOutcome(outcome);
    }

    // Returns whether the app requested any of the permissions before, and remembers this request.
    static bool MarkRequested(string[] permissions)
    {
        using (var activity = AndroidActivity())
        using (var preferences = activity.Call<AndroidJavaObject>("getSharedPreferences", "flow_permissions", 0))
        using (var editor = preferences.Call<AndroidJavaObject>("edit"))
        {
            var requestedBefore = false;
            foreach (var permission in permissions)
            {
                requestedBefore |= preferences.Call<bool>("getBoolean", permission, false);
                editor.Call<AndroidJavaObject>("putBoolean", permission, true).Dispose();
            }
            editor.Call("apply");
            return requestedBefore;
        }
    }
#endif
}
```

:::warning
**On Android, request permissions with the Java plugin below, not with `Permission.RequestUserPermissions()`.** In Adapty Unity SDK 4.1.x, a flow on Android is a separate activity. `Permission.RequestUserPermissions()` requests from the Unity activity behind the flow, so the answer reaches your handler only after the flow closes, and the flow stays on the screen. The plugin requests from the activity on screen and returns the answer on Unity's thread.
:::

```java showLineNumbers title="Assets/Plugins/Android/FlowPermissions.androidlib/src/main/java/com/example/flowpermissions/FlowPermissions.java"
package com.example.flowpermissions;

import android.app.Activity;
import android.app.Application;
import android.os.Bundle;
import android.os.Handler;
import android.os.Looper;

import androidx.activity.ComponentActivity;
import androidx.activity.result.ActivityResultLauncher;
import androidx.activity.result.contract.ActivityResultContracts;

import java.util.Map;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.AtomicReference;

// Requests runtime permissions from the activity on screen. With a flow on screen,
// that is the flow's activity, not the Unity activity behind it.
public final class FlowPermissions {
    public interface Callback {
        // "answered", "dismissed" when the user closed the dialog without a choice,
        // or "failed" when no activity on screen can request permissions.
        void onResult(String outcome);
    }

    private static final AtomicInteger lastRequestId = new AtomicInteger();
    private static volatile Activity resumedActivity;
    private static boolean started;

    // Call once, from Unity's thread, before a flow opens.
    public static synchronized void start(Activity activity) {
        if (started) return;
        started = true;
        resumedActivity = activity;
        activity.getApplication().registerActivityLifecycleCallbacks(new Application.ActivityLifecycleCallbacks() {
            @Override public void onActivityResumed(Activity a) { resumedActivity = a; }
            @Override public void onActivityDestroyed(Activity a) { if (resumedActivity == a) resumedActivity = null; }
            @Override public void onActivityCreated(Activity a, Bundle state) {}
            @Override public void onActivityStarted(Activity a) {}
            @Override public void onActivityPaused(Activity a) {}
            @Override public void onActivityStopped(Activity a) {}
            @Override public void onActivitySaveInstanceState(Activity a, Bundle state) {}
        });
    }

    public static boolean shouldShowRationale(String[] permissions) {
        Activity activity = resumedActivity;
        if (activity == null) return false;
        for (String permission : permissions) {
            if (activity.shouldShowRequestPermissionRationale(permission)) return true;
        }
        return false;
    }

    // Calls back on the calling thread: Unity's thread, where respond reaches the flow at once.
    public static void request(String[] permissions, Callback callback) {
        Looper callerLooper = Looper.myLooper();
        Handler caller = new Handler(callerLooper != null ? callerLooper : Looper.getMainLooper());
        new Handler(Looper.getMainLooper()).post(() -> {
            Activity activity = resumedActivity;
            if (!(activity instanceof ComponentActivity)) {
                caller.post(() -> callback.onResult("failed"));
                return;
            }
            String key = "flow_permissions_" + lastRequestId.incrementAndGet();
            AtomicReference<ActivityResultLauncher<String[]>> launcher = new AtomicReference<>();
            launcher.set(((ComponentActivity) activity).getActivityResultRegistry().register(
                key,
                new ActivityResultContracts.RequestMultiplePermissions(),
                (Map<String, Boolean> result) -> {
                    launcher.get().unregister();
                    // Android returns no results for a dialog closed without a choice.
                    String outcome = result.isEmpty() ? "dismissed" : "answered";
                    caller.post(() -> callback.onResult(outcome));
                }));
            launcher.get().launch(permissions);
        });
    }
}
```

The Objective-C files of the plugins import this header:

```objectivec showLineNumbers title="Assets/Plugins/iOS/FlowPermissions.h"
#import <Foundation/Foundation.h>

// The C# callback: the request ID and the status of the answer, or NULL for no status.
typedef void (*FlowPermissionCallback)(int requestId, const char *status);

// Answers on the main thread, where Unity runs C# scripts on iOS.
static inline void FlowPermissionAnswer(FlowPermissionCallback callback, int requestId, const char *status) {
    dispatch_async(dispatch_get_main_queue(), ^{
        callback(requestId, status);
    });
}
```

## Code for each permission

Each section has the C# file of one permission and, where iOS needs it, the native plugin file. A file answers `unsupported` on the OS that has no such permission.

### Push notifications \{#push\}

Declare `POST_NOTIFICATIONS` on Android. iOS needs no `Info.plist` key. See [System permissions](flow-permissions#push).

```csharp showLineNumbers title="FlowSystemRequestsHandler.Push.cs"
using System;
using System.Collections;
using UnityEngine;
#if UNITY_IOS
using Unity.Notifications.iOS;
#endif

public partial class FlowSystemRequestsHandler
{
    void RequestPush(Action<bool, string> respond)
    {
#if UNITY_IOS
        StartCoroutine(AnswerOnException(RequestPushOnIOS(respond), respond));
#elif UNITY_ANDROID
        if (AndroidSdkInt() < 33)
        {
            // Android 12 and earlier show no dialog: answer whether notifications are on.
            using (var activity = AndroidActivity())
            using (var compat = new AndroidJavaClass("androidx.core.app.NotificationManagerCompat"))
            using (var manager = compat.CallStatic<AndroidJavaObject>("from", activity))
            {
                var enabled = manager.Call<bool>("areNotificationsEnabled");
                respond(enabled, enabled ? "granted" : "permanently_denied");
            }
            return;
        }
        RequestAndroid("android.permission.POST_NOTIFICATIONS", respond);
#else
        respond(false, "unsupported");
#endif
    }

#if UNITY_IOS
    IEnumerator RequestPushOnIOS(Action<bool, string> respond)
    {
        switch (iOSNotificationCenter.GetNotificationSettings().AuthorizationStatus)
        {
            case AuthorizationStatus.Authorized:
            case AuthorizationStatus.Ephemeral:
                respond(true, "granted");
                yield break;
            case AuthorizationStatus.Provisional:
                respond(true, "provisional");
                yield break;
            case AuthorizationStatus.Denied:
                // The user declined earlier: iOS shows no alert.
                respond(false, "permanently_denied");
                yield break;
        }

        var options = AuthorizationOption.Alert | AuthorizationOption.Badge | AuthorizationOption.Sound;
        using (var request = new AuthorizationRequest(options, false))
        {
            while (!request.IsFinished)
            {
                yield return null;
            }
            if (!string.IsNullOrEmpty(request.Error)) respond(false, null);
            else respond(request.Granted, request.Granted ? "granted" : "denied");
        }
    }
#endif
}
```

- On iOS, the code uses the [Mobile Notifications](https://docs.unity3d.com/Packages/com.unity.mobile.notifications@latest) package. Turn off **Request Authorization on App Launch** in **Project Settings > Mobile Notifications > iOS**. The package reads the notification settings when the app becomes active, and `GetNotificationSettings()` returns that copy. If the user changed the setting in Settings just before the request, the copy can be stale: an earlier refusal then arrives as `denied`.
- On Android, the code requests `POST_NOTIFICATIONS` without Mobile Notifications. Its `PermissionRequest` waits for the answer in a coroutine and saves it with `PlayerPrefs`, which run only on Unity's main thread, and on Android Unity pauses its player loop while a flow is on screen.

### App tracking (ATT) \{#tracking\}

Declare `NSUserTrackingUsageDescription` on iOS. Android has no such permission. See [System permissions](flow-permissions#tracking).

```csharp showLineNumbers title="FlowSystemRequestsHandler.Tracking.cs"
using System;
using System.Collections;
using UnityEngine;
#if UNITY_IOS
using Unity.Advertisement.IosSupport;
#endif

public partial class FlowSystemRequestsHandler
{
    void RequestTracking(Action<bool, string> respond)
    {
#if UNITY_IOS
        StartCoroutine(AnswerOnException(RequestTrackingOnIOS(respond), respond));
#else
        // Android has no tracking permission.
        respond(false, "unsupported");
#endif
    }

#if UNITY_IOS
    IEnumerator RequestTrackingOnIOS(Action<bool, string> respond)
    {
        switch (ATTrackingStatusBinding.GetAuthorizationTrackingStatus())
        {
            case ATTrackingStatusBinding.AuthorizationTrackingStatus.AUTHORIZED:
                respond(true, "granted");
                yield break;
            case ATTrackingStatusBinding.AuthorizationTrackingStatus.DENIED:
                respond(false, "permanently_denied");
                yield break;
            case ATTrackingStatusBinding.AuthorizationTrackingStatus.RESTRICTED:
                respond(false, "restricted");
                yield break;
        }

        // iOS shows the alert only while the app is active.
        yield return new WaitUntil(() => Application.isFocused);
        try
        {
            ATTrackingStatusBinding.RequestAuthorizationTracking(status =>
            {
                switch ((ATTrackingStatusBinding.AuthorizationTrackingStatus)status)
                {
                    case ATTrackingStatusBinding.AuthorizationTrackingStatus.AUTHORIZED: respond(true, "granted"); break;
                    case ATTrackingStatusBinding.AuthorizationTrackingStatus.DENIED: respond(false, "denied"); break;
                    case ATTrackingStatusBinding.AuthorizationTrackingStatus.RESTRICTED: respond(false, "restricted"); break;
                    // iOS closed the prompt without a decision.
                    default: respond(false, null); break;
                }
            });
        }
        catch (InvalidOperationException)
        {
            // Another tracking request waits for an answer.
            respond(false, null);
        }
    }
#endif
}
```

- The code uses the `com.unity.ads.ios-support` package. After the user answers, send the ATT status to Adapty: see [Deal with ATT](unity-deal-with-att).
- In the EU, iOS lets the app ask again a year after the user's answer. For how to handle it, see [System permissions](flow-permissions#tracking).

### Location while using the app \{#location_when_use\}

Declare `NSLocationWhenInUseUsageDescription` on iOS, and `ACCESS_COARSE_LOCATION` and `ACCESS_FINE_LOCATION` on Android. See [System permissions](flow-permissions#location_when_use).

```csharp showLineNumbers title="FlowSystemRequestsHandler.LocationWhenInUse.cs"
using System;
using System.Runtime.InteropServices;
#if UNITY_ANDROID
using UnityEngine.Android;
#endif

public partial class FlowSystemRequestsHandler
{
#if UNITY_IOS
    [DllImport("__Internal")]
    static extern void FlowPermissions_requestLocationWhenInUse(int requestId, NativePermissionCallback callback);
#endif

    void RequestLocationWhenInUse(Action<bool, string> respond)
    {
#if UNITY_IOS
        RequestNative(FlowPermissions_requestLocationWhenInUse, respond);
#elif UNITY_ANDROID
        // Request both: some Android 12 releases ignore a request for precise location alone.
        RequestAndroid(
            new[] { Permission.FineLocation, Permission.CoarseLocation },
            () => Permission.HasUserAuthorizedPermission(Permission.FineLocation)
                || Permission.HasUserAuthorizedPermission(Permission.CoarseLocation) ? "granted" : null,

    }];
}

import Foundation
import MusicKit

@_cdecl("FlowPermissions_requestMusic")
public func FlowPermissions_requestMusic(
    _ requestId: Int32,
    _ callback: @escaping @convention(c) (Int32, UnsafePointer<CChar>?) -> Void
) {
    // Answers on the main thread, where Unity runs C# scripts on iOS.
    func answer(_ status: MusicAuthorization.Status, denied: String) {
        let detail: String?
        switch status {
        case .authorized: detail = "granted"
        case .restricted: detail = "restricted"
        case .denied: detail = denied
        default: detail = nil
        }
        DispatchQueue.main.async {
            guard let detail else { return callback(requestId, nil) }
            detail.withCString { callback(requestId, $0) }
        }
    }

    let before = MusicAuthorization.currentStatus
    guard before == .notDetermined else {
        return answer(before, denied: "permanently_denied")
    }
    Task {
        answer(await MusicAuthorization.request(), denied: "denied")
    }
}
```

    switch (status) {
        case EKAuthorizationStatusRestricted: return "restricted";
        case EKAuthorizationStatusDenied: return denied;
        case EKAuthorizationStatusNotDetermined: return NULL;
        default: return "granted"; // full access, or EKAuthorizationStatusAuthorized on iOS 16 and earlier
    }
}

void FlowPermissions_requestReminders(int requestId, FlowPermissionCallback callback) {
    EKAuthorizationStatus before = [EKEventStore authorizationStatusForEntityType:EKEntityTypeReminder];
    if (before != EKAuthorizationStatusNotDetermined) {
        FlowPermissionAnswer(callback, requestId, FlowRemindersStatus(before, "permanently_denied"));
        return;
    }
    static EKEventStore *store;
    store = [EKEventStore new];
    void (^completion)(BOOL, NSError *) = ^(BOOL granted, NSError *error) {
        EKAuthorizationStatus status = [EKEventStore authorizationStatusForEntityType:EKEntityTypeReminder];
        FlowPermissionAnswer(callback, requestId, error != nil ? NULL : FlowRemindersStatus(status, "denied"));
    };
    if (@available(iOS 17.0, *)) {
        [store requestFullAccessToRemindersWithCompletion:completion];
    } else {
        [store requestAccessToEntityType:EKEntityTypeReminder completion:completion];
    }
}

#import <HomeKit/HomeKit.h>
#import "FlowPermissions.h"

@interface FlowHomeKitRequest : NSObject <HMHomeManagerDelegate>
@property (nonatomic) FlowPermissionCallback callback;
@property (nonatomic) int requestId;
@property (nonatomic) const char *refusal;
@end

// iOS reports the HomeKit status only after the app creates a manager, so the app keeps a flag.
static NSString *const FlowHomeKitRequestedKey = @"FlowHomeKitRequested";

static HMHomeManager *homeManager; // one manager for the life of the app
static FlowHomeKitRequest *activeRequest;

static const char *FlowHomeKitStatus(HMHomeManagerAuthorizationStatus status, const char *denied) {
    if (status & HMHomeManagerAuthorizationStatusAuthorized) return "granted";
    if (status & HMHomeManagerAuthorizationStatusDetermined) return denied;
    return NULL; // not determined when the timeout ends
}

@implementation FlowHomeKitRequest
- (void)homeManager:(HMHomeManager *)manager didUpdateAuthorizationStatus:(HMHomeManagerAuthorizationStatus)status {
    if (status & HMHomeManagerAuthorizationStatusDetermined) [self finish];
}

- (void)finish {
    if (activeRequest != self) return;
    activeRequest = nil;
    homeManager.delegate = nil;
    FlowPermissionAnswer(self.callback, self.requestId, FlowHomeKitStatus(homeManager.authorizationStatus, self.refusal));
}
@end

void FlowPermissions_requestHomeKit(int requestId, FlowPermissionCallback callback) {
    dispatch_async(dispatch_get_main_queue(), ^{
        // iOS has no request method: creating the manager shows the alert.
        if (homeManager == nil) homeManager = [HMHomeManager new];
        if (homeManager.authorizationStatus & HMHomeManagerAuthorizationStatusDetermined) {
            FlowPermissionAnswer(callback, requestId, FlowHomeKitStatus(homeManager.authorizationStatus, "permanently_denied"));
            return;
        }
        NSUserDefaults *defaults = NSUserDefaults.standardUserDefaults;
        FlowHomeKitRequest *request = [FlowHomeKitRequest new];
        request.callback = callback;
        request.requestId = requestId;
        // Requested in an earlier session: a refusal now is the earlier one, without an alert.
        request.refusal = [defaults boolForKey:FlowHomeKitRequestedKey] ? "permanently_denied" : "denied";
        [defaults setBool:YES forKey:FlowHomeKitRequestedKey];
        activeRequest = request;
        homeManager.delegate = request;
        dispatch_after(dispatch_time(DISPATCH_TIME_NOW, 50 * NSEC_PER_SEC), dispatch_get_main_queue(), ^{
            [request finish];
        });
    });
}

## Register the handler

:::warning
**Without a handler, the flow stops at the permission request.** If your app registers no handler, the Adapty SDK sends the flow no answer, on iOS and on Android, and the Unity console shows the warning `System requests handler is not set`. The flow stays on the screen that sent the request and doesn't run the outcome actions.
:::

To send the permission requests from all flows to your handler, register it with `Adapty.SetSystemRequestsHandler()` before you present a flow, in the same place where you register the [flows events listener](unity-handle-paywall-actions#set-up-the-flows-events-listener). Attach the handler to a GameObject that lives as long as your app, and add these methods to the handler class:

```csharp showLineNumbers title="Unity"
void Awake()
{
    DontDestroyOnLoad(gameObject);
    Adapty.SetSystemRequestsHandler(this);
}

void OnDestroy()
{
    Adapty.SetSystemRequestsHandler(null);
}
```

`Adapty.SetSystemRequestsHandler()` keeps one handler for every flow in the app. A second call replaces the first handler, and `null` removes it.

## Test the permission request

iOS shows most permission dialogs only once per app install. Android stops showing a permission dialog after the user allows the permission or denies it twice. To see the dialog again while you test the flow, delete the app from the device and install it again. Then open the flow and reach the **Request permission** action. If the screen stays and no dialog appears, the flow got no answer: make sure that your app registers the handler before it presents the flow. If the flow moves on without a dialog, make sure that the app declares the permission on both platforms. For notifications, the Android app must also target API level 33 or higher, and **Request Authorization on App Launch** must be off.

To see how users answer permission requests, read the flow's analytics events in the `FlowViewDidReceiveAnalyticEvent` method of your flows events listener. For details, see [Handle flow & paywall events](unity-handling-events).
