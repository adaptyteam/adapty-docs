A formula is a [custom variable](onboarding-variables#custom-variables) with a calculated value: a number or a date. A formula can read the answers users give in the flow, other custom variables, the prices of the products in your Adapty catalog, and the current day. With formulas in the Flow & Paywall Builder, a flow can show calculated values without code in your app:

- **A result from answers**: A sum of quiz scores, a BMI from a weight and a height, or a height in feet and inches.
- **A price**: The selected product's price after a 20% discount, or how much users save with the annual plan compared to the weekly plan.
- **A date**: The end date of a free trial.
- **A time between dates**: The number of days left in a trial, or the age of a user from a birth date.

The flow calculates the result of a formula on the device. When a value that the formula reads changes, the flow updates the result. You can show the result in a text element, and you can use it in conditions.

## Create a formula

1. Open the <Inline id="variables.svg" alt="Variables" /> Variables panel in the flow builder.
2. Add a new variable — click <Inline id="plus.svg" alt="Plus" />.
3. Enter the variable **Name**, such as `bmi`. Other formulas use this name to read the result.
4. In the **Value Type** dropdown, select **Formula**.
5. In the **Expression** field, enter the formula, such as `round({{weight}} * 10000 / ({{height}} * {{height}}), 1)`, where `weight` and `height` are Number variables. For the rules, see [Write a formula](#write-a-formula).
6. Click **Create variable**.

<ZoomImage id="flow-formula-create.webp" width="300px" alt="The Create variable dialog with the Formula type, a BMI formula in the Expression field, the Number output type, and a preview of 22.9" />

When you leave the **Expression** field, the builder validates the formula. If the formula has an error, the error text appears under the field. While the error shows, the **Create variable** button, or **Save** for an existing variable, is disabled. When you edit the expression, the error disappears and the button is available again.

Without an error, a hint shows under the field. For a Date formula, the hint is "Use a formula to set a date that updates automatically. Use negative n to go back in time". For other formulas, the hint is "Use round(x, 2) to set the decimals".

Under the field, the builder also shows:

- **Output type**: **Number** or **Date**, the type of the result. The builder sets it from the formula: the result is a Date when the formula is a [date function](#date-functions) that gives a date, such as `addDays`, or a Date value alone, such as `{{trial_start}}`. Any other formula gives a Number, also a formula that counts the time between two dates, such as `daysBetween`.
- **Date format**: Only for a Date formula. How text elements show the result. See [Show a date in a text element](#show-a-date-in-a-text-element).
- **Preview**: The result, calculated from Initial values and product prices. See [Preview a formula in the builder](#preview-a-formula-in-the-builder).

A formula always depends on other values, so it has no **Initial value**. For the same reason, your app can't set a formula.

### Insert references and functions

In the **Expression** field, each reference shows as a chip with the name of the value, such as **weight** for a custom variable or **Weekly · prod_price** for the price of a product. A chip is one unit: Backspace or Delete removes the whole reference, and the arrow keys move the cursor over the chip.

To add a reference without the exact name, type `{{` in the **Expression** field. A list of the values that fit at the cursor opens. Type a part of the name to filter the list, and select a value to insert its reference. The list also opens when you type a function name. After a Number value, such as `{{weight}}` or `5`, and a space, the list offers the operators `+`, `-`, `*`, and `/`. To close the list, press Escape.

The list shows only the values and the functions that the formula accepts at the cursor. For example, in the first argument of `addDays`, the list offers Date values, `today()`, and the functions that give a date. In the second argument of `round`, the list offers nothing, because the number of decimals is a number that you type.

You can also use the two buttons on the **Output type** line. Each button adds text at the cursor in the **Expression** field:

- <Inline id="variables.svg" alt="Insert variable" /> **Insert variable**: Opens a list with four tabs. Select a value to insert its reference, or a function to insert its name and an opening parenthesis:
  - **Functions**: The functions of formulas.
  - **Elements**: The answers in inputs and pickers, such as `weight.value`.
  - **Products**: The prices of the selected product in each product group, then the products of your Adapty catalog. See [Read the price of any product](#read-the-price-of-any-product).
  - **Custom**: The Number, Date, and Formula custom variables.
- <Inline id="function.svg" alt="Insert function" /> **Insert function**: Lists the functions, each with a description and an example. To find a function, type its name in the search field. Select a function to insert its name and an opening parenthesis, such as `addDays(`. Then type the arguments and the closing parenthesis.

The **Insert variable** list shows only the values that the formula can read. It doesn't show String, Boolean, or Array variables, or the formula that you edit.

## Write a formula

A formula combines numbers, references to values, operators, and functions. Function names and variable names are case-sensitive: `Round(2.5)` is an error.

### References

Put each reference in double braces:

| Reference | What the formula reads | Example |
| :--- | :--- | :--- |
| `{{<variable name>}}` | A custom variable of type Number, Date, or Formula | `{{discount}}` |
| `{{<Element ID>.value}}` | The answer in a [Text or Number input](builder-inputs-and-forms), a [Number picker](builder-number-picker), or a Date or Date & Time input | `{{weight.value}}` |
| `{{<Group ID>.selectedProduct.prod_price}}` | The price of the product that users selected in a product group, as a number | `{{products.selectedProduct.prod_price}}` |
| `{{<Group ID>.selectedProduct.prod_price_per_week}}` | The price of the selected product for one week. Also `prod_price_per_day`, `prod_price_per_month`, and `prod_price_per_year`. See [Per-period prices](#per-period-prices). | `{{products.selectedProduct.prod_price_per_month}}` |
| `{{<Group ID>.selectedProduct.offer_price}}` | The offer price of the selected product, as a number | `{{products.selectedProduct.offer_price}}` |
| `{{<Group ID>.selectedProduct}}` | The selected product, only as the second argument of `addOfferDuration` | `{{products.selectedProduct}}` |
| `{{<Adapty product ID>.prod_price}}` | The price of a product from your Adapty catalog, as a number. Also the per-period prices of the product, such as `prod_price_per_week`. See [Read the price of any product](#read-the-price-of-any-product). | **Weekly · prod_price** in the **Expression** field |

A formula reads a typed answer as a number when the answer is digits, with an optional minus in front and an optional fraction after one decimal point or one decimal comma. The formula ignores spaces at the start and the end. For example, `12`, `-5`, `1.5`, and `1,5` are numbers. Any other answer, such as `abc`, `1,5,0`, or `1e3`, gives the formula [no value](#formulas-without-a-value). In a Number input that a formula reads, users can type only a number. With the **Decimal (Point)** and **Decimal (Comma)** formats, users can type a decimal point or a decimal comma, so the decimal key of every keyboard works.

A Date or Date & Time input gives the calendar day that users picked.

A formula can read another formula, but not itself, and two formulas can't read each other. When you rename a variable, an **Element ID**, or a **Group ID**, the formula shows the new name and reads the same value. When you delete a variable that a formula reads, the formula shows a **deleted variable** chip in its place and has an error.

A name that matches two values is an error. For example, if a custom variable is named `age.value` and an input has the Element ID `age`, `{{age.value}}` matches both. Rename the custom variable.

### Numbers and operators

- **Numbers**: Always use a decimal point, such as `0.8`. Inside a function, a comma separates the arguments: `round(2,5)` is `round(2, 5)`, which gives 2, not 2.5. Outside a function, a comma in a number is an error. A minus before a number or a reference makes it negative, such as `-3`.
- **Operators**: `+`, `-`, `*`, and `/`. The flow calculates `*` and `/` before `+` and `-`, and operators of the same level from left to right. Use parentheses to change the order: `({{a}} + {{b}}) / 2`.

## Number formulas

A Number formula returns a number.

### Number functions

| Function | Result | Example |
| :--- | :--- | :--- |
| `round(n)` | `n` rounded to a whole number. A value exactly in the middle rounds away from zero. | `round(2.5)` = 3, `round(-2.5)` = -3 |
| `round(n, digits)` | `n` rounded to `digits` decimal places. `digits` is a whole number from 0 to 6 that you type in the formula, not a reference or a calculation. | `round(23.12, 1)` = 23.1, `round(1.005, 2)` = 1.01 |
| `floor(n)` | The largest whole number that isn't larger than `n` | `floor(2.7)` = 2, `floor(-2.5)` = -3 |
| `mod(a, b)` | The remainder of `a` divided by `b`, with the sign of `b`, as the MOD function of spreadsheets | `mod(7, 3)` = 1, `mod(-7, 3)` = 2, `mod(5.5, 2)` = 1.5 |

A zero result of `round`, `floor`, and `mod` is always 0, never -0.

### Show a number in a text element

To show a formula or a Date variable, [insert the variable](onboarding-variables#use-variables-in-text) into a text element from the **Custom** tab of the variable picker. Dates and numbers with `round` on the top level appear in the language of the device, not in the language of the flow.

How a Number formula appears depends on the function on the top level of the formula:

- **`round` on the top level**: The number has exactly the number of decimals that `round` sets. It uses the decimal separator of the device language, without thousands separators or a currency sign. For example, `round(23.12, 1)` shows "23.1" in English and "23,1" in Russian, and `round(15.04, 1)` shows "15.0" in English.
- **Any other formula**: The number appears in its plain form, with a decimal point in every language and with up to 15 significant digits. For example, `9.99 * 0.8` shows "7.992", and `1 - 1 / 3` shows "0.666666666666667". To set the number of decimals, put `round` on the top level of the formula, such as `round(1 - 1 / 3, 2)`.

A Number variable and a formula with `floor` or `mod` on the top level appear in the plain form too.

### Compare numbers in conditions

You can select a formula or a Date variable in a condition, such as a [conditional visibility](onboarding-element-visibility) rule or a conditional action:

- **Number formulas**: Use the same operators as for a Number variable: **Equals**, **Does not equal**, **Greater than**, **Less than**, **Is empty**, and **Is not empty**. Compare the formula with a number or with another Number value, such as `bmi` **Greater than** `25`. The operators don't include "greater than or equal" or "less than or equal". To match a whole number of 10 or more, such as a quiz score, use `score` **Greater than** `9`.

## Product prices

A formula reads product prices as numbers, from two sources:

- **The selected product of a product group**: The price changes when users select another product in the group, such as `{{products.selectedProduct.prod_price}}`.
- **A product from your Adapty catalog**: The price of one product, also a product that the screen doesn't display. Use it to compare plans, such as the saving of the annual plan compared to the weekly plan.

On the device, the flow uses the store price in the currency of the user. When the product prices load, the flow calculates the formula again.

### Read the price of any product

1. In the **Expression** field, put the cursor where the price goes.
2. Click <Inline id="variables.svg" alt="Insert variable" /> **Insert variable**, and open the **Products** tab. The **This flow** group lists the products that you added to the screens of the flow. The **Other** group lists the rest of your Adapty catalog. Each product shows its access level and its price in USD.
3. Point to the product, and select the price: `prod_price`, or a [per-period price](#per-period-prices), such as `prod_price_per_week`.

The chip shows the product title and the price field, such as **Weekly · prod_price**. When two products have the same title, the list and the chip tooltip also show the store product ID.

To show the price on the device, the flow needs the product on the list of products of each screen that reads the formula. The builder adds the product by itself. When a text element or a condition on a screen reads the formula, the builder adds the product to the end of the screen's list, without an offer. The builder also adds the product when the screen reads the formula through another formula. If the screen has the product only with an offer or a billing plan, the builder adds one more entry of the product, without an offer or a billing plan. The same happens on each screen that shows a reusable component with such a text.

The product that the builder adds is an ordinary product of the screen. You see it in the **Products** panel, your app code receives it with the other products of the flow, and the flow analytics show it as a product of the screen. The screen doesn't select the product, and a tap on the text with the formula doesn't start a purchase. To learn how a screen uses its list of products, see [Set up purchases](paywall-product-block).

The builder only adds products. When you remove the price from the formula, the product stays on the list of the screen. If no element of the screen uses the product, remove it in the **Products** panel. If you keep it and later delete the product from your Adapty catalog, the entry blocks publishing. If you remove the product from a screen that still reads the formula, the screen shows the **This product is off this screen** issue, and the builder doesn't add the product again. To fix the issue, add the product back in the **Products** panel.

When you delete a product from your Adapty catalog, the chip of its price shows **Missing product**, and the formula has an error. Replace the price with the price of another product. Published versions of the flow keep the product that they have.

If you create a flow with the [Adapty CLI](developer-cli-flows), add the product, without an offer or a billing plan, to the products of each screen that reads the formula, as the builder does. Publishing fails with the `formula_undeclared_product` error only when the flow reads the formula and no screen of the flow has the product without an offer or a billing plan.

### Per-period prices

A per-period price is the price of a subscription product for one day, week, month, or year. A formula can read these prices for a catalog product and for the selected product of a product group:

| Price | Example for a monthly product with the price 9.99 |
| :--- | :--- |
| `prod_price_per_day` | 9.99 / 30 = 0.333 |
| `prod_price_per_week` | 9.99 × 7 / 30 = 2.331 |
| `prod_price_per_month` | 9.99 |
| `prod_price_per_year` | 9.99 × 12 = 119.88 |

The flow divides the price by the number of days, weeks, months, or years in the subscription duration of the product. A month is 30 days, so a month is 30/7 weeks. A year is 365 days, 52 weeks, or 12 months. The [price variables of text elements](onboarding-variables#product-variables) use the same conversion. For example, an annual product with the price 120 gives 10 for `prod_price_per_month` and 120 / 52 for `prod_price_per_week`.

The formula keeps all decimals of a per-period price. To show the price with two decimals, put `round` on the top level of the formula. When users select the annual product, `round({{products.selectedProduct.prod_price_per_week}}, 2)` shows "2.31".

A product that isn't a subscription, such as a lifetime product or a consumable product, gives the per-period prices [no value](#formulas-without-a-value).

## Date formulas

A Date formula returns a date. To use a fixed day in a formula, such as a trial start date, store it in a Date variable.

### Create a Date variable

1. Open the <Inline id="variables.svg" alt="Variables" /> Variables panel, and click <Inline id="plus.svg" alt="Plus" />.
2. Enter the variable **Name**, such as `trial_start`.
3. In the **Value Type** dropdown, select **Date**.
4. (Optional) In the **Initial value** field, enter a date as `DD.MM.YYYY`, such as `17.11.2026`, or click the field and pick the day in the calendar, then click **Apply**. The builder doesn't accept a date that doesn't exist, such as `31.02.2027`. Without an Initial value, the variable has no value until a [**Set variable** action](onboarding-actions) sets it.
5. (Optional) In the **Date format** dropdown, select how text elements show the date. See [Show a date in a text element](#show-a-date-in-a-text-element).
6. Click **Create variable**.

<ZoomImage id="flow-date-variable-create.webp" width="300px" alt="The Create variable dialog with the Date type and the Initial value 17.11.2026" />

A Date variable holds a day without a time or a time zone.

To change a Date variable when users tap an element, add a [**Set variable**](onboarding-actions) action, select the Date variable, and enter the new date as `DD.MM.YYYY` or pick it in the calendar. A **Set variable** action can't change a formula, because a formula always depends on other values.

### Date functions

| Function | Result | Example |
| :--- | :--- | :--- |
| `today()` | The current day on the device | `today()` |
| `addDays(date, n)` | `date` plus `n` days | `addDays(today(), 7)` |
| `addWeeks(date, n)` | `date` plus `n` weeks | `addWeeks({{trial_start}}, 2)` |
| `addMonths(date, n)` | `date` plus `n` months | `addMonths({{trial_start}}, 1)` |
| `addYears(date, n)` | `date` plus `n` years | `addYears({{birth_date.value}}, 18)` |
| `addOfferDuration(date, product)` | `date` plus the length of the product's offer | `addOfferDuration(today(), {{products.selectedProduct}})` |
| `daysBetween(start, end)` | The number of calendar days from `start` to `end`, as a Number | `daysBetween(today(), {{trial_end}})` |
| `weeksBetween(start, end)` | The number of whole weeks from `start` to `end`, as a Number | `weeksBetween({{trial_start}}, today())` |
| `monthsBetween(start, end)` | The number of whole months from `start` to `end`, as a Number | `monthsBetween({{trial_start}}, today())` |
| `yearsBetween(start, end)` | The number of whole years from `start` to `end`, as a Number | `yearsBetween({{birth_date.value}}, today())` |

The date functions follow these rules:

- **`today()`**: Gives the start of the current day in the time zone of the device. The flow reads the day when it opens, so the value doesn't change at midnight while the flow is open.
- **Negative and fractional `n`**: A negative `n` moves the date back. The flow drops the fractional part of `n`: `addWeeks(date, 1.5)` adds 1 week, and `addDays(date, -1.9)` moves the date back 1 day.
- **Short months**: When the target month doesn't have the day, the result is the last day of that month. For example, January 31, 2027 plus 1 month is February 28, 2027, and February 29, 2028 plus 1 year is February 28, 2029.
- **`addOfferDuration`**: Adds each phase of the product's offer that the Adapty SDK passes to the flow, in order. For each phase, the function adds the phase's period multiplied by its number of periods in one step: a 7-day free trial that starts on November 10, 2026 ends on November 17, 2026. If the product has no offer, or a phase of the offer has an unknown period, the result has no value.
- **Time between dates**: `daysBetween`, `weeksBetween`, `monthsBetween`, and `yearsBetween` count only whole units and drop the rest:
  - `weeksBetween` divides the number of days by 7: 13 days is 1 week.
  - `monthsBetween` and `yearsBetween` count a month or a year when `addMonths` or `addYears` of `start` by that number isn't later than `end`. For example, from January 31, 2027 to February 28, 2027 is 1 month, by the rule for short months.
  - When `end` is earlier than `start`, the result is negative: the result for the two dates in the other order, with a minus. For example, `daysBetween` from December 1, 2026 to November 24, 2026 gives -7, and `weeksBetween` gives -1 for an `end` 10 days earlier than `start`.

Inside a formula, a Date can only be the first argument of a function that adds time to a date, or an argument of a function that counts the time between two dates. A Date in a calculation, such as `{{trial_start}} + 1`, is an error. A Number can't be an argument where a function needs a date. A String, Boolean, or Array variable can't be a part of a formula.

### Show a date in a text element

To show a formula or a Date variable, [insert the variable](onboarding-variables#use-variables-in-text) into a text element from the **Custom** tab of the variable picker. Dates and numbers with `round` on the top level appear in the language of the device, not in the language of the flow.

A Date variable and a Date formula have a **Date format** in the variable settings. Each text element that shows the variable uses this format, and when you change it, all these text elements change. A new variable has the **Medium** format.

To use another format in one text element, in the **Content** field, click the variable, and select a format. To return to the format of the variable, select **Variable default**. The formats are:

| Date format | English example |
| :--- | :--- |
| **Short** | 11/17/26 |
| **Medium** | Nov 17, 2026 |
| **Long** | November 17, 2026 |
| **Month D** | November 17 |
| **Mon D** | Nov 17 |

**Short**, **Medium**, and **Long** follow the date order of the device language. **Month D** and **Mon D** show the month before the day in every language, such as "ноября 17" in Russian.

### Compare dates in conditions

You can select a formula or a Date variable in a condition, such as a [conditional visibility](onboarding-element-visibility) rule or a conditional action:

- **Date variables and Date formulas**: Use **Equals**, **Does not equal**, **Earlier than**, **Later than**, **Is empty**, or **Is not empty**. Compare the date with another date, or with a date that you enter as `DD.MM.YYYY` or pick in the calendar. **Is empty** is true while the date has no value, such as a Date variable without an Initial value before a **Set variable** action sets it.

A date comparison compares calendar days, not times. For example, a date that users picked at 21:00 on November 17, 2026 equals `17.11.2026`. You can't compare a date with a number.

## Formulas without a value

A formula has no value when one of its values is not available on the device:

- An answer is empty, or isn't a number.
- The product prices didn't load, or the store didn't return a product that the formula reads. For example, when Google Play doesn't return the product, the formula has no value on Android. On iOS, the same formula has a value when the App Store returns the product.
- The product isn't a subscription, and the formula reads a [per-period price](#per-period-prices).
- The selected product has no offer, and the formula reads `offer_price` or calls `addOfferDuration`.
- The formula divides by zero, as in `{{a}} / 0` or `mod({{a}}, 0)`.
- A Date variable that the formula reads has no value.

A formula that reads a formula without a value has no value too. Without a value, a formula works this way:

- **Text elements**: The formula shows nothing.
- **Conditions**: **Is empty** is true. **Equals**, **Does not equal**, and all comparisons of the formula are false.

The flow updates the result of a formula when a value that the formula reads changes: when users type an answer, a **Set variable** action changes a variable, or the product prices load. If users go back and clear an answer, the formula has no value on the next screen. Until the flow changes a custom variable, a formula reads the variable's Initial value.

## Preview a formula in the builder

The builder calculates the result of a formula from the Initial values of custom variables and the USD prices of products in your Adapty catalog. For a per-period price, the builder takes the period from the **Subscription duration** of the product in Adapty: **Weekly**, **Monthly**, **2 Months**, **3 Months**, **6 Months**, or **Annual**. The **Preview** under the **Expression** field shows **No value** when the formula reads any of the following:

- An answer that users type or pick
- `offer_price`
- The offer of `addOfferDuration`
- A variable without a value, such as a Date variable without an Initial value
- The price of a product from your Adapty catalog without a USD price, or with a USD price of 0
- A per-period price of a product with another **Subscription duration** in Adapty, or without one. On the device, the flow takes the subscription period from the store, so a subscription product gets a per-period price there.

In these cases, a text element on the canvas shows the variable name in braces, such as `{{trial_end}}`. To see the values of answers, [preview the flow in the Adapty mobile app](paywall-device-compatibility-preview). Offer values need a build of your app with real products.

On the canvas, dates and numbers with `round` on the top level appear in the language that you select for the preview.

## Examples

### Show a sum of answers

On a screen, add three Number inputs with the Element IDs `a1`, `a2`, and `a3`. Create a formula `sum`:

```
{{a1.value}} + {{a2.value}} + {{a3.value}}
```

On the next screen, insert `sum` into a text element. If users enter 2, 3, and 4, the text shows "9". If users go back and change 4 to 5, the text shows "10".

### Show a BMI and a "High" label

Add a Number input with the Element ID `weight` for the weight in kilograms, and one with the Element ID `height` for the height in centimeters. Create a formula `bmi`:

```
round({{weight.value}} * 10000 / ({{height.value}} * {{height.value}}), 1)
```

Insert `bmi` into a text element. For a BMI of 23.12, users see "23.1" with an English device language, and "23,1" with a Russian one. To show a "High" label only for a BMI over 25, add a text element with the word "High", and give it a [conditional visibility](onboarding-element-visibility) rule: `bmi` **Greater than** `25`.

### Show a discounted price

Create a formula `discounted` that takes 20% off the price of the selected product:

```
{{products.selectedProduct.prod_price}} * 0.8
```

Then create a formula `shown` that rounds it to two decimals:

```
round({{discounted}}, 2)
```

Insert `shown` into a text element. For a product with the price 9.99, the text shows "7.99". When users select a product with the price 100, the text shows "80.00". The number has no currency sign. If the price of the selected product didn't load, the text is empty.

### Show the saving of the annual plan

A paywall screen displays only the annual product, with the price 120. Your Adapty catalog also has a weekly product with the price 5, and no screen of the flow displays it. To show how much users save with the annual plan compared to 52 weeks of the weekly plan, create a formula `saving`:

1. In the **Expression** field, click <Inline id="variables.svg" alt="Insert variable" /> **Insert variable**. In the **Products** tab, point to the weekly product, and select `prod_price`.
2. Type `* 52 -`.
3. Insert `prod_price` of the annual product the same way.

The **Expression** field shows **Weekly · prod_price** `* 52 -` **Annual · prod_price**, and the **Preview** shows 140. The builder saves the expression with the Adapty product IDs:

```
{{<weekly product ID>.prod_price}} * 52 - {{<annual product ID>.prod_price}}
```

To show the saving in percent, create a formula `saving_percent`. Insert the two prices from the **Products** tab, the same way as for `saving`. The builder saves the expression as:

```
round((1 - {{<annual product ID>.prod_price}} / ({{<weekly product ID>.prod_price}} * 52)) * 100)
```

For these prices, `saving_percent` is 54. Insert `saving` or `saving_percent` into a text element on the paywall screen. The builder adds the weekly product to the end of the screen's list of products. On the device, the formula uses the store prices in the currency of the user. The purchase button of the screen starts the purchase of the annual product.

### Show the end of a trial and a reminder date

Create a formula `trial_end`:

```
addOfferDuration(today(), {{products.selectedProduct}})
```

Then create a formula `reminder` for three days before the trial ends:

```
addDays({{trial_end}}, -3)
```

For a product with a 7-day free trial, on November 10, 2026, `trial_end` is November 17, 2026, and `reminder` is November 14, 2026. With the **Medium** date format, the text shows "Nov 17, 2026". With **Month D**, it shows "November 17".

### Show the length of a trial and an age

Use the formula `trial_end` from [Show the end of a trial and a reminder date](#show-the-end-of-a-trial-and-a-reminder-date), and create a formula `trial_days`:

```
daysBetween(today(), {{trial_end}})
```

In a text element, type "Free for", insert `trial_days`, and type "days". For a product with a 7-day free trial, the text shows "Free for 7 days". When the selected product has no offer, `trial_end` has no value. To show the text only for a product with an offer, give the text element a [conditional visibility](onboarding-element-visibility) rule: `trial_end` **Is not empty**.

To calculate an age, add a Date input with the Element ID `birth`, and create a formula `age`:

```
yearsBetween({{birth.value}}, today())
```

For users born on November 25, 2000, `age` is 25 on November 24, 2026, and 26 on November 25, 2026. While the answer is empty, `age` has no value.

### Show a height in feet and inches

Add a Number input with the Element ID `height` for the height in centimeters. Create three formulas:

- `total`: `round({{height.value}} / 2.54)`, the height in whole inches.
- `feet`: `floor({{total}} / 12)`.
- `inches`: `mod({{total}}, 12)`.

In a text element, insert `feet`, type "ft", insert `inches`, and type "in". For 180 cm, the text shows "5 ft 11 in". For 140 cm, it shows "4 ft 7 in".

## Troubleshooting

When you leave the **Expression** field, the builder shows the first error of the formula under the field. Some examples:

| Error text | Cause and fix |
| :--- | :--- |
| `addDays() needs a date and a number` | A function has a wrong number of arguments or an argument of the wrong type. Use the arguments from the [Number functions](#number-functions) or [Date functions](#date-functions) table. |
| `Unknown function "flor". Use one of: …` | The function name is misspelled, or its letter case is different. Use a function from the list in the error. To read a variable, put its name in `{{ }}`. |
| `Use a dot in a decimal number, like 1.5` | A number outside a function has a comma. Replace the comma with a decimal point. Inside a function, the builder reads a comma as the separator between arguments, so use a decimal point there too. |
| `{{…}} is not a variable, an answer or a product field of this flow` | No variable, Element ID, or product group has this name. Fix the name, or create the variable. |
| `{{…}}: the product … is not in the product catalog of the app` | The product was deleted from your Adapty catalog. The chip shows **Missing product**. Replace the price with the price of another product. |
| `Offers, billing plans and fields other than prod_price, … of a catalog product are not supported yet` | The formula reads an offer, a billing plan, or another field of a product from your Adapty catalog. Insert the price from the **Products** tab of **Insert variable**. |
| `This variable no longer exists. Pick another one.` | You deleted a variable that the formula reads. The **Expression** field shows it as a **deleted variable** chip. Replace it with another reference. |
| `{{…}} is the name of a variable and of an element answer: rename the variable` | The name matches two values. Rename the custom variable. |
| `{{…}} uses this formula: formulas cannot use each other in a loop` | Two or more formulas read each other. Remove one of the references. |

A formula with an error blocks publishing. The **Can't publish yet** dialog lists each formula with an error under **Variables**. For the errors that can appear when you publish, see [Common issues](flow-common-issues#a-flow-wont-preview-or-publish).

## Limitations

- **Numbers and dates only**: A formula only returns a number or a date. To show text that depends on the result, add [conditional text](onboarding-text#add-conditional-text) to a text element. For example, to show "High" for a BMI over 25, set the **if** condition to `bmi` **Greater than** `25`, and enter "High" under **then**.
- **Catalog products**: A formula reads only the price and the per-period prices of a product from your Adapty catalog, without an offer or a billing plan. To use an offer price, read `offer_price` of the selected product in a product group.
- **Selected product**: A formula that reads the selected product has no value until users select a product. To show the result when the screen opens, select **Set as default** on one of the product cards.
- **Offers on iOS and Android**: On iOS, the Adapty SDK passes one offer to the flow. Among the offers available to the user, a win-back offer comes first, then a promotional offer, then an introductory offer. On Android, the Adapty SDK passes only the first phase of the introductory offer. For a free trial followed by a discounted price, `addOfferDuration` on Android adds only the trial.
