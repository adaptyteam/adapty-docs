You can animate the transitions between screens — how one screen disappears and the new one appears. The available animations depend on the particular navigation action:

- [**Navigate to Screen**](onboarding-actions#navigate-to-screen): Open the [action settings](#customize-a-transition) and select from the [full range of animation types](#animation-types). Different steps can use different transitions.
- **Navigate Next**: Only the default push animation.
- **Navigate back**: Plays the transition navigation that was used when arriving at the current screen, but in reverse and with no delay. If there was no animation on arrival, there is no animation on return.
- **Close Flow**: No animation of its own. Your app is responsible for the transition between the flow and your native UI.

A delayed **Navigate to Screen** action can [move users off a splash or loading screen automatically](#move-users-to-another-screen-automatically).

## Animation types

The **Animation** dropdown of the **Navigate to Screen** action has five options:

- **Push**: The new screen enters from one edge and pushes the current screen out the other.
- **Slide in**: The new screen slides and fades in over the current screen, which moves a short way in the same direction.
- **Slide out**: The current screen slides away and fades out, uncovering the new screen underneath.
- **Fade through**: The new screen fades in over the current screen.
- **None**: The new screen replaces the current one instantly.

## Customize a transition

You can only change the animation in a **Navigate to Screen** action.

<ZoomImage id="navigate-to-screen-settings.webp" width="300px" float="right" alt="Edit action window for Navigate to Screen with Paywall as the destination, Slide in upward with Ease out bounce, a 400 ms duration, and no delay" />

1. Select the element that triggers a navigation action.
2. In the **Interactions** panel, click the navigation action.
3. If the action is **Navigate Next**, select **Navigate to Screen** from the **Action** dropdown. Then select the next screen as the **Destination**.
4. Select an animation from the **Animation** dropdown.
5. If the animation has **Direction**, **Easing**, or **Duration** settings, adjust them.
6. To keep the current screen visible before the animation starts, set a value in the **Delay** field. For example, use a delay to keep a [loading screen](builder-loaders-and-progress-bars#loaders) on for a few seconds before it [moves on automatically](#move-users-to-another-screen-automatically). [Actions listed after the navigation](onboarding-actions#action-order) don't wait for the delay.
7. To see the transition on your own screens, [test the flow on a device](paywall-device-compatibility-preview#preview-on-devices).

## Move users to another screen automatically

To move users off a splash or loading screen, delay a **Navigate to Screen** action by up to 5 seconds.

1. Select any element on the screen, such as a loader.
2. In the **Interactions** panel, [add an **On Screen Appear** trigger](onboarding-actions#set-up-interactions) with a **Navigate to Screen** action.
3. In the **Destination** dropdown, select the next screen.
4. The **Delay** field does not appear unless you set an **Animation**. Select any **Animation** except **None**. To switch screens without a visible animation, set the **Duration** field to 0.
5. In the **Delay** field, set how long the screen stays, up to 5000 ms. Use whole seconds: on iOS, a delay rounds up to a whole second.
6. To see the screen move on, [test the flow on a device](paywall-device-compatibility-preview#preview-on-devices). The canvas doesn't run actions.

While the screen waits, some taps cancel the delayed **Navigate to Screen** action:

- If users tap a button that navigates, they move on at once.
- If users do any of the following, the screen stays:
  - Open an alert, a bottom sheet, a date picker, or a web page.
  - Start a purchase or a restore.

If users can do any of these on the screen, add a button that navigates, so they can move on.

When users return to the screen, the delay starts again.

For a delay longer than 5 seconds, add a [Countdown timer](flow-timer) with an **On Timer End** trigger that navigates to the next screen. To keep the timer out of sight, make its text fully transparent, and leave **Visibility** set to **Show**, so that the trigger fires.
