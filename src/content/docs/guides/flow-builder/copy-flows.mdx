Copy the flow and change a few elements to tweak it for a specific [audience](add-audience-paywall-ab-test), [A/B test](ab-tests), or app version. Copy the flow to another app of your account to publish it there, for example in your production app after you test it in a test app. Copy a single screen to reuse it in another flow.

<ZoomImage id="flow-copy-archive.webp" width="700px" alt="Flows list with the context menu open, showing Metrics, Edit, Copy, Copy to app…, and Archive" />

## Copy a flow

### From the Flow & Paywall Builder

1. Open the flow in the Flow & Paywall Builder.
2. In the top bar, click the flow actions button <Inline id="context.svg" alt="Flow actions" />, and select **Duplicate flow**. The copy opens in a new tab.

To copy an earlier version, [duplicate it as a new flow](flow-version-history#restore-an-earlier-version).

### From the Flows list

1. Go to [**Flows & Paywalls**](https://app.adapty.io/flows) in the Adapty main menu and open the **Flow & Paywall builder** tab.
2. In the flow's row, open the context menu <Inline id="context.svg" alt="Context menu" /> and select **Copy**. You can't copy an archived flow — [restore](archive-flows#restore-a-flow) it first.

### What the copy contains

The Flow & Paywall Builder opens the copy as a new **Draft** with the name of the original plus a `_copy` suffix. [Give the copy a unique name](paywall-builder-templates#create-flow) to avoid confusion.

The copy contains everything stored in the flow itself:

- **Screens and elements**: Every screen, with its layout, elements, and interactions.
- **Assigned products**: The connections between your product cards and your store products.
- **Design**: Saved color and text styles, backgrounds, and dark mode values.
- **Custom fonts**: All flows in one app share the same [custom fonts](using-custom-fonts-in-flow-builder), so the copy keeps them.
- **Variables**: [Custom, element, and product variables](onboarding-variables).
- **Localizations**: Every locale, with its translated text and media.
- **Remote config**: Every locale's [JSON payload](customize-flow-with-remote-config).

Anything stored outside the flow stays behind:

- **Placements**: The copy belongs to no [placement](placements).
- **A/B tests**: The copy joins no [A/B test](ab-tests).
- **Metrics**: The copy starts with an empty [analytics history](flow-metrics).

### Show the copy to users

1. [Publish the copy](builder-save-publish#publish-a-flow).
2. Add the copy to a [flow placement](placements).

## Copy a flow to another app

Copy a flow to another app of the same account, for example from your test app to your production app.

:::tip
To copy a flow to another app from the terminal, use [`adapty flows copy`](developer-cli-flows#adapty-flows-copy). The [flow-generator skill](flow-generator-skill) runs this command when you ask your coding agent to copy a flow to another app.
:::

### Copy the flow

Adapty copies the saved version of the flow: the draft, or the live version when the flow has no draft. To include unsaved changes, save the flow first. To copy an earlier version, first [duplicate it as a new flow](flow-version-history#restore-an-earlier-version), then copy the new flow. To copy an archived flow, [restore](archive-flows#restore-a-flow) it first.

1. Open one of these menus:
   - In the Flow & Paywall Builder, in the top bar, click the flow actions button <Inline id="context.svg" alt="Flow actions" />.
   - In the **Flows & Paywalls** list, find the flow. In its row, click the context menu button <Inline id="context.svg" alt="Context menu" />.
2. Select **Copy to app…**.
3. Select the app to copy the flow to. The list shows the other apps of this account that you can access.

   <ZoomImage id="flow-copy-to-app.webp" width="500px" alt="Copy flow to another app window with Production App selected and the Copy button" />

4. Click **Copy**.

Adapty shows the **Flow copied to &lt;app name&gt;** message. To open the copy, in the message, click **Open**. The dashboard switches to the other app and opens the copy in the Flow & Paywall Builder.

### What goes into the copy

The copy is a new **Draft** in the other app, with the same name as the original flow. Each time you copy the flow, the other app gets one more draft with that name.

The copy contains the same parts as a [copy in the same app](#what-the-copy-contains), except products and [custom fonts](#custom-fonts-in-the-copy). Adapty removes the products, because each app has its own products:

- Product cards, product groups, purchase buttons, and text that shows a product value, such as a price, stay on the screens with no product.
- Adapty removes product variables, and formula variables that use a product. Text that shows one of these variables keeps the variable placeholder.

The copy uses the same image and video files as the original flow. Adapty doesn't upload them to the other app.

The copy also uses the same [custom tags](flow-custom-tags) and custom action IDs. Make sure that the code of the other app passes values for these custom tags and responds to these custom actions. When the other app passes no value for a custom tag, users see the tag's fallback.

### Custom fonts in the copy

For each [custom font](using-custom-fonts-in-flow-builder) of the flow, Adapty looks for a font family with the same name in the other app:

- **The other app has no font family with this name**: Adapty adds the font family to the other app, with the same files and the same iOS and Android font names.
- **The other app has a font family with this name**: The copy uses that family. Adapty adds the faces that the family lacks.

In these cases, the copy uses the system font instead of the custom font:

- The font family with the same name in the other app has a different file for a face with the same weight and style.
- Another font of the other app already uses the iOS or Android font name of the custom font.
- Adapty couldn't add the font family to the other app.

Adapty doesn't send the font files to users' devices. To show a custom font in the other app, [add the font files to the bundle](using-custom-fonts-in-flow-builder#add-the-font-files-to-your-apps-bundle) of that app.

### Review and publish the copy

When you open the copy, the Flow & Paywall Builder shows an [Import review](convert-paywall-to-flow#import-review) checklist of what to do before you publish the copy:

- The products that Adapty removed.
- Each custom font that Adapty replaced with the system font.
- The custom fonts to add to the bundle of the other app.

Adapty keeps the checklist in your browser: only you see it, and only in the browser that you used to copy the flow.

To show the copy to users:

1. In the Adapty Dashboard, switch to the other app, and open the copy in the Flow & Paywall Builder.
2. [Add the products](paywall-product-block) of the other app to the product cards, product groups, and purchase buttons.
3. Recreate the product variables that Adapty removed, or delete the text that shows them.
4. For each custom font that Adapty replaced with the system font, upload the font to the other app, or select another font.
5. [Publish the copy](builder-save-publish#publish-a-flow).
6. Add the copy to a [flow placement](placements).

## Copy screens between flows

To move a screen into another flow, [**Copy**](paywall-layout-and-products#screen-actions) it to your clipboard, open the destination flow, and paste it into the **Screens** panel. The clipboard allows you to transfer the screen between different flows or even browsers.

Adapty doesn't copy what the screen references at flow level. A pasted screen can end up incomplete, and may include broken references. For example, a condition that uses an element of another screen is a broken reference. You can't [publish](builder-save-publish#troubleshooting) the flow until you fix each condition with a broken reference.

Review each of these after you paste:

- **Variables**: Text bindings, conditions, and actions no longer resolve. Replace the references with variables from the destination flow.
- **Text styles**: Elements lose their text styles. Apply a text style from the destination flow.
- **Navigation actions**: **Navigate to screen** actions lose their destination. Point each one at a screen in the destination flow.
- **Localizations**: Only the locales both flows share keep their translations. Users in any other locale see the destination flow's default.
- **Products and custom fonts**: Every flow in an app can use the same products and fonts. A screen pasted from a different flow in the same app keeps its products and fonts. Pasting a screen from a different app will break its product and font references.

Replace each broken reference with a working equivalent in the destination flow.

:::tip
Copying by hand is the fastest way to move a screen once. To reuse the same block again and again — the plan selection, the trial timeline, the comparison table — the [flow-generator skill](reuse-flow-elements) saves it to a file and adds it to any other flow, resolving the styles, fonts, icons, and product bindings on the way in. It lists anything it can't resolve instead of leaving you a broken reference to find.
:::
