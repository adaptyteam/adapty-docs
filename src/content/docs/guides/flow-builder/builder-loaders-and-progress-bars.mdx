The **Progress** category provides two element types — one for step-based progress through a multi-screen flow, and one for in-place busy indicators.

## Progress indicators

<ZoomImage id="builder-progress-indicator.webp" width="700px" alt="A progress indicator at the top of a screen with the settings panel open" />

### Indicator styles

<ZoomImage id="flow-indicators.webp" width="300px" alt="Progress indicator variants" float="right" />

A **Progress** element shows the user's position in a multi-screen flow. The category provides three visual variants:

- **Linear** — A single bar that fills as the user advances.
- **Segmented** — Separate bars for each step that fill one by one.
- **Connectors** — Labeled circles connected by lines (e.g., Step 1, Step 2, Step 3 in sequence).

### Match steps to screens

<ZoomImage id="builder-progress-indicator-settings.webp" width="280px" float="right" alt="Progress indicator settings panel with variant picker, One segment per screen toggle, and Screens dropdown" />

By default, the Progress Indicator tracks every screen in the flow. To restrict it to a subset, pick from the **Screens** dropdown. Alternatively, open the screen you want to exclude, and uncheck the **Include screen in progress indicator** checkbox.

Toggle **One segment per screen** off if you need finer control over the step count.

:::warning
Step position follows the screen list — not the order the user actually sees. In non-linear flows, the indicator's displayed step can jump ahead or backtrack.
:::

### Step states

<ZoomImage id="builder-progress-indicator-step-settings.webp" width="280px" float="right" alt="Step-level settings panel with ID, Screens, and Completed/Current/Upcoming state tabs" />

Each step has three states — **Completed**, **Current**, and **Upcoming**. Select a step inside the Progress Indicator to edit a state's styling in the right panel. Use **Apply changes to all states** to copy your edits to the other two.

Editing one step affects every step inside the same indicator.

### Layout and positioning

The Progress indicator is a global element, so you can't place it inside a [container](builder-containers). You also can't set its position — it uses absolute positioning by default. When the user scrolls the screen, the indicator stays in place and the content scrolls beneath it.

To control the space around the indicator, use the **Margin** and **Padding** controls in the **Spacing** section instead of moving the element. If the layout looks wrong, adjust the margin or padding on both the indicator and its neighboring element.

## Loaders

<ZoomImage id="flow-loaders.webp" width="220px" alt="The Loaders templates in the Add element panel: Spinner, Spinner with label, Progress bar, and Progress bar with label" float="right" />

A **Loader** is an animated element that suggests that work is happening: for example, processing a user's quiz answers to prepare a personalized plan.

The category provides four templates:

- **Spinner** — A circular spinner.
- **Spinner with label** — A circular spinner with a caption (e.g., "Loading...").
- **Progress bar** — A horizontal bar that fills from 0 to 100%.
- **Progress bar with label** — A horizontal bar with a caption and a percentage (e.g., "Analyzing... 47%").

### Spinners

A spinner rotates for as long as its screen is open. To change its look, pick one of six styles in the **Spinner** section. In the **Animation** section, **Duration** sets the time of one full rotation.

A spinner's **Duration** doesn't set how long the screen stays open. An **On screen appear** trigger with a **Navigate to Screen** action moves users on at once. To keep a loading screen open for up to 5 seconds, add a **Delay** to the [screen transition](flow-screen-transitions#move-users-to-another-screen-automatically) of that action. For a longer wait, add a [Timer](flow-timer) with an **On timer end** trigger that navigates to the next screen, or use a [progress bar](#run-actions-when-a-progress-bar-is-full) instead.

### Progress bars

<ZoomImage id="builder-loader-settings.webp" width="280px" float="right" alt="Loader settings with Type set to Radial, Show percentage on, and the Typography, Progress color, and Animation sections" />

A progress bar fills from 0 to 100% each time its screen opens. In the **Loader** section, set **Type** to **Linear** for a bar or to **Radial** for a ring. For a ring, **Thickness** sets the width of its line.

In the **Animation** section:

- **Duration** sets how long the bar takes to fill.
- **Easing** sets how the fill speeds up and slows down.

To set the color of the fill, use the **Progress color** section. To set the color of the unfilled track, use the **Fill** section.

On the canvas, a progress bar is full. To see it fill, play the canvas animations.

### Show the percentage

To show the percentage inside the bar or the ring, in the **Loader** section, turn on **Show percentage**. To change its font and color, use the **Typography** section.

To show the percentage in a separate text, for example next to a caption:

1. In the **Loader** section of the progress bar, enter an **Element ID**, for example `analysis`.
2. In the text, insert the `analysis.progress` variable, and type `%` after it.

The text then counts up together with the bar. The **Progress bar with label** template is set up this way. A text that shows this variable can't show other variables or product values.

### Run actions when a progress bar is full

The **On Load Complete** trigger runs its actions once, when the progress bar reaches 100%. For example:

- To move users to the next screen when the bar is full, add a **Navigate to Screen** action.
- To keep a **Next** button unavailable until the bar is full, create a Boolean variable with the initial value `false`, and add a **Set Variable** action that sets it to `true`. Then, [add a **Disabled** state](builder-element-states#condition-driven-disabled-state) to the button that applies while the variable is `false`.

### Play progress bars one after another

<ZoomImage id="builder-loader-start-loader.webp" width="500px" alt="An On Load Complete trigger with a Start loader action that starts a second loader" />

To fill several progress bars in sequence, for example one bar for each step of an analysis:

1. Select every progress bar except the first one. In the **Loader** section, turn off **Autostart**. These bars stay at 0 when the screen opens.
2. Select the first progress bar. Under **On Load Complete**, add a **Start loader** action, and select the second bar.
3. Repeat step 2 for the second bar to start the third one, and so on.

**Start loader** only lists progress bars on the same screen that have **Autostart** turned off. You can select several bars in one action to fill them at the same time.

### Delay or hide a loader

To show a spinner or a progress bar some time after the screen opens, in the **Animation** section, set **Show after delay** in milliseconds. A progress bar starts to fill when the delay ends.

To show a loader only when users tap an element, set the loader's **Visibility** to **Hide**. Then, select the element that should show the loader, and [add a **Show element** action that runs **On Tap**](flow-show-hide-animations#show-or-hide-an-element). A hidden progress bar starts to fill when it appears, not when its screen opens.

### When users leave the screen

- If users come back to a screen after a progress bar is full, the bar stays at 100%. Its **On Load Complete** actions don't run again.
- If users leave a screen before a progress bar is full, the bar stops. When they come back, it fills again from 0.

A progress bar that's part of a [reusable component](reuse-flow-elements) can't have **On Load Complete** actions inside a bottom sheet that an action opens. A flow with such a bar doesn't publish.
