Use inputs to collect data from users — such as a name, email address, or date of birth. Store responses and reference them elsewhere in the flow, such as addressing the user by name on a later screen.

## Add an input

<ZoomImage id="add-input.webp" width="400px" float="right" alt="Add input" />

1. Open the **Add element** panel.
2. In the **Forms & Quiz** category, click **Input**.
3. Choose the input type:
   - **Text:** Any short text entry.
   - **E-mail:** Email addresses, with optional format validation.
   - **Password:** Secure text entry, with configurable requirements.
   - **Number:** Numeric values, with configurable format.
   - **Phone number:** Telephone numbers.
   - **Date:** Opens a date picker.
   - **Time:** Opens a time picker.
   - **Date & Time:** Opens a combined picker.
   - **[Number picker](builder-number-picker):** You set the minimum value and the maximum value for a wheel. Users pick a number between them.

## Configure an input

:::link
For more details about visual settings — layout, style, and visibility — see [Styles and appearance](builder-styling).
:::

For all input types, you can configure the following in the **Design** tab:

- **Type:** Switch a text field between Text, E-mail, Password, Number, and Phone number. Switch a date or time picker between Date, Time, and Date & Time.
- **Element ID:** Identifier used to reference the input's value elsewhere in the flow. See [Use input values](#use-input-values) below.
- **Placeholder:** Hint text displayed inside the empty field.
- **State:** Define how the input looks in different situations. Switch between **Default**, **Active**, **Invalid**, and **Disabled** and apply different visuals to each.
- **Typography:** Text styling for the value displayed in the field.
- **Leading and trailing icons:** Add icons inside the input field. For a Password input, you can only add a leading icon.

A [Number picker](builder-number-picker) only has the **Element ID** and **Typography** settings from this list.

## Use input values

:::tip
Your app can receive input values too. To collect them, [handle the SDK's analytics callback](ios-flow-input). Each time a user leaves an input, the callback delivers the input's value, and your app can process it internally.

For a Number picker, the callback delivers the value when the user taps a button that opens another screen. A tap on a quiz option or a toggle on the same screen delivers it too.
:::

Every input is automatically available as a variable — there's no setup or **On Submit** action required. The value is referenced through the input's **Element ID**, which you set in **Input Settings** or **Picker Settings**.

To use an input value elsewhere in the flow (for example, to personalize copy, populate another field, or drive conditional navigation), insert a variable and choose:

**Element > Screen > `<elementId>.value`**

:::link
See the relevant guides to understand how to use saved input values:
- [Conditional navigation](onboarding-navigation-branching)
- [Variables](onboarding-variables)
:::

## Input validation

Validation behavior depends on input type. Every input except the Number picker exposes a read-only Boolean variable, `<elementId>.isValid`. It reflects whether the entered value passes the input's validation rules. Use it in conditional actions or conditional visibility — for example, to hide a Next button until an email's format is valid.

:::note
- The `isValid` variable is read-only — you can't set it.
- An empty input is always considered valid.
- Text inputs have no validation rules. `textInput.isValid` always returns `True`.
:::

| Input type | Validation behavior |
|---|---|
| Text | No built-in validation rules. |
| E-mail | Optional. Enable **Validate email format** in the **Design** panel to check the entered value against an email-format check. |
| Phone number | Built-in phone-number format check. Not configurable in the Builder — the rule is evaluated at runtime. |
| Password | Configurable. See [Password requirements](#password-requirements) below. |
| Number | Format-based. The entered value must match the selected number format. See [Number format](#number-format) below. |
| Date, Time, Date & Time | Built-in. The picker only accepts valid date or time values. |

The **Invalid** [visual state](builder-styling#input-states) activates when the user submits the form — for example, by pressing Enter or Done on the keyboard. Until then, the input shows the **Active** or **Default** state.

### Password requirements

Password inputs support configurable validation rules. Click **Edit password requirements** in the **Design** panel to open the rule editor. Enabled rules display as a live checklist below the input — each item gets a check mark the moment its rule is satisfied.

Available rules:

- **Min length** — minimum number of characters. Default: 8.
- **Max length** — maximum number of characters. Default: 32.
- **Uppercase letter** — at least one A–Z character.
- **Lowercase letter** — at least one a–z character.
- **Number** — at least one digit.
- **Special character** — at least one non-alphanumeric character (for example, `!@#$%`).

The password is valid only when every enabled rule is satisfied.

### Number format

The **Format** dropdown in **Number** input settings controls how the entered value is parsed:

- **Integer** — whole numbers only (for example, `4`).
- **Decimal (Point)** — decimals with a period as the separator (for example, `4.89`).
- **Decimal (Comma)** — decimals with a comma as the separator (for example, `4,89`).

Values that don't match the selected format are considered invalid.

## Trigger actions on input events

:::link
Main article: [Actions](onboarding-actions)
:::

You can run actions in response to the user's input via the **Interactions** panel:

- **On changed** — fires when the user changes the input's value. Available on all input types.
- **On submit** — fires when the user submits a text input by pressing Enter or Done on the keyboard. Date and time pickers and the Number picker don't have this trigger.
