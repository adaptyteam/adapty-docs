The [Flow & Paywall Builder](adapty-flow-builder) separates saving from publishing. Drafts preserve your work in the Adapty Dashboard, and publishing makes the current version available to users through the SDK. This article covers both actions and when to use each.

## Save a flow as a draft

:::warning
An invalid [Remote Config](customize-flow-with-remote-config) prevents you from saving the draft.
:::

The Flow & Paywall Builder autosaves your progress once a minute.

To save a draft manually, click **Save draft** in the top right of the Flow & Paywall Builder, or press **Cmd/Ctrl + S**.

Drafts are private to the Dashboard. They don't change what users see in your app, even if the flow is already assigned to a [placement](placements).

<ZoomImage id="flow-builder-save-draft.webp" width="700px" alt="Save draft button in the Flow & Paywall Builder top toolbar" />

## Publish a flow

Publishing makes the current version of your flow available to users through the SDK, in place of any previously published version. To bring back an earlier version, [restore it](flow-version-history#restore-an-earlier-version).

:::note
To add a flow to a [placement](placements), publish it first. A flow in Draft status can't be added.
:::

To publish your flow, click **Publish to Live** in the top right of the Flow & Paywall Builder. After you publish a flow, the button stays disabled until you edit the flow.

What happens next depends on whether the flow is already assigned to a placement:

- **Flow already in a placement**: Users start seeing the new version on their next request to that placement.
- **Flow not in a placement**: Add the flow to a [flow placement](create-placement) to start showing it to users. A flow needs a placement of its own — it can't go on a placement you already use for a paywall or an onboarding.

:::tip
A flow is ready to publish once every action, screen, and product is fully configured. Until then, you can still save the draft. To see what to fix, [open the **Issues** panel](#fix-issues-before-publishing). The common gaps are in [Troubleshooting](#troubleshooting).
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Publish to Live button in the Flow & Paywall Builder top toolbar" />

:::warning
[Custom fonts](using-custom-fonts-in-flow-builder) don't ship with the flow — you must add each font file to your app bundle. Without the file, users see the system fallback.

To change a font on a published flow without breaking older app versions: [copy the flow](copy-flows), change the font in the copy, and target the copy to an [audience](add-audience-paywall-ab-test) on app versions that include the font.
:::

## Fix issues before publishing

<ZoomImage id="flow-builder-issues-panel.webp" width="500px" alt="Issues panel with two issues under Blocks publishing, a flow size warning under Won't block publishing, and the flow size at the bottom" />

The **Issues** panel lists the issues of a flow in one place. To open the panel, click **Issues** in the top bar. The button appears only when the flow has issues. The button counts the issues that block publishing and the warnings separately.

The panel splits the issues into two groups:

- **Blocks publishing**: A product or an action that isn't fully set up. For example, a product card with no product, a deleted product or offer, or an **Open URL** action with no link. When you click **Publish to Live** with such an issue, the builder doesn't publish the flow. The **Fix N issues before publishing** message appears instead. To open the panel from the message, click **Show issues**. For an action that isn't set up, the builder opens the **Interactions** tab of its element, and the **Complete the selected action before publishing.** message appears.
- **Won't block publishing**: Warnings about a product with no App Store or Play Store product ID, or about a [heavy flow](flow-size). Without the ID, the price of the product stays empty on that platform. A heavy flow opens late.

To fix an issue, click it. The builder selects the element and opens the tab with the setting, for example the **Interactions** tab for a **Purchase** action. The setting with the issue has a red outline.

<ZoomImage id="flow-builder-issues-purchase-action.webp" width="400px" alt="Interactions tab with a Purchase action outlined in red and marked with a warning icon" />

Other issues, such as a condition that uses a deleted element, don't appear in the panel. The **Can't publish yet** dialog lists them when you publish the flow.

## Flow status

Each flow shows a status in the [Flows list](filter-flows). The status reflects where the flow is in the save and publish lifecycle.

| Status | Meaning |
| :----- | :------ |
| **Draft** | The flow has never been published. Only a draft exists, so users don't see it yet. You need to publish the draft first to add it to a [placement](placements). |
| **Dirty** | The flow was published, but it has saved edits that aren't published yet. Users still see the last published version until you publish again. |
| **Publishing** | A publish is in progress. |
| **Failed** | The last publish attempt failed. Users keep seeing the last published version, if there is one. |
| **Published** | The latest saved version is live. There are no unpublished edits. |
| **Archived** | The flow was [archived](archive-flows#archive-a-flow) and can't be edited until you [restore](archive-flows#restore-a-flow) it. |

## Troubleshooting

An incomplete action, an empty screen, a missing or deleted product or offer, or invalid remote config JSON blocks both previewing and publishing. The full list and the fix for each case are in [Common issues](flow-common-issues#a-flow-wont-preview-or-publish).

You can't publish a flow while a condition uses a deleted element, state, or variable. The **Can't publish yet** dialog lists these conditions under **Broken references**. To publish the flow, pick an existing element, state, or variable in each condition, or remove the condition.

Preview your flow in the [Adapty app](paywall-device-compatibility-preview) to catch any issues before publishing. If the flow fails to load in the preview, see the error message for more details.

A flow can clear all of this and still not be safe to publish — a dead restore button, a missing terms link, an untranslated screen. The [flow-audit skill](flow-audit-skill) checks for exactly that, from the terminal, and ends in a verdict rather than a list.
