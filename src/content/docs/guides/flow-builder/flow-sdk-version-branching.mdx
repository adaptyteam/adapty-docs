Flows were introduced with Adapty SDK v4.0, but some of their features may require a later version. If you want to use these capabilities, you need to update the Adapty SDK bundled with your app. However, not all users are quick to update to the latest app version.

To show each user the screens their app build can display, update your flow to branch based on its Adapty SDK version:

- **New Adapty SDK**: The flow shows the new feature
- **Old Adapty SDK**: The flow does not show the new feature

Your metrics and A/B tests stay intact. You don't need to [copy the flow](copy-flows) or split your user traffic across multiple flows with [audiences](audience).

## 1. Set up the screens

Create at least three screens:

1. Set up the welcome screen. The users will see it before the flow branches. It is required to check the Adapty SDK version before presenting version-specific content.
2. Set up the new Adapty SDK route — one or more screens that take advantage of the new feature. Connect the screens in the route with [**Navigate to Screen**](onboarding-navigation-branching#static-navigation), not [**Navigate next**](onboarding-actions#navigate-next). This will make the navigation independent of the screen order, which may change when you introduce a fallback route.
3. Set up the fallback route for the other users. To speed up the process, you can duplicate screens from the first route, rename them, and remove the incompatible elements. Don't forget to change the navigation **Destination** on each screen copy — otherwise the two routes will clash.

To tell the two routes apart when you set up navigation or view [flow metrics](flow-metrics), give their screens distinct names.

## 2. Branch the flow by Adapty SDK version

On the welcome screen, select the element that moves users forward, such as the "Continue" button. Set it to trigger a [conditional action](onboarding-actions#conditional-actions) with the following rules:

- **if**: `sdk.version` ≥ the minimum Adapty SDK version that supports the feature (ex: `4.3.0`)
- **then**: Navigate to the first screen of the new Adapty SDK route.
- **else**: Navigate to the first screen of the fallback route, or end the flow with **Close Flow**.

When the flow is ready, [publish it](builder-save-publish#publish-a-flow). To test each branch, use live app builds. The Adapty app preview doesn't allow you to mock the Adapty SDK version, so the conditional action always follows its **else** section.
