The growth-advisor skill answers "what should I test next?" from your own subscription numbers. Your AI coding tool reads your analytics, placements, paywalls, and products through the [Adapty CLI](developer-cli-analytics), follows the biggest signal down to a cause, and returns a short list of hypotheses to A/B test, ranked by the purchases each one puts at stake.

:::note
growth-advisor changes nothing in your account without your yes. Every analytics read is read-only, and each write — a new flow copy, a new segment, a placement change — waits for you to confirm it.
:::

## What you can ask

Ask the way you'd brief a colleague. You don't need to name the skill:

```
Audit my app. What should I test next to grow revenue?

Revenue dropped last month. Why?

My A/B test on the onboarding paywall ended and the new version won. What now?

I have three ideas: a weekly plan, a trial on annual, and a second placement.
Which one should I test first?

Which country refunds the most, and do people who start a trial renew better?

We launch next month and have no data yet. Where should we start?
```

A question about your numbers gets an answer from your numbers, with no audit attached. An app with no data yet gets a starting plan built from market medians in Adapty's State of Paywalls 2026 report, with every number labeled as an estimate.

## Before you start

- **An Adapty account with data**: The skill reads the same analytics your dashboard shows. Without data, it can only give you a starting plan.
- **An AI tool that can run terminal commands**: For example, Claude Code, Codex, Copilot CLI, or Gemini CLI. Chat tools like claude.ai or ChatGPT can't run the CLI, so they can't reach your Adapty account.

## Install the skill

growth-advisor is part of the [`adapty-skills` plugin](https://github.com/adaptyteam/adapty-skills). To install the plugin, in your terminal, run:

```bash
npx adapty skills install
```

Restart your agent to load the skills. For other installation methods, see the [plugin README](https://github.com/adaptyteam/adapty-skills/blob/main/plugin/README.md#install).

## How the audit works

When you ask what to do without a specific question, the skill runs an audit. It reads your numbers and your placement setup, works out what you've already tried, and follows the biggest change down to the store, channel, country, or placement that explains it. Before it says anything about a screen, it looks at the live flow, or asks you for a screenshot of a paywall your app draws itself.

## What you get back

The skill replies with a short answer, then a list of hypotheses grouped by placement, in the order to test them. Each hypothesis says why your app needs it, what result to expect and where that estimate comes from, how long the A/B test would take, and who does what. A hypothesis can target everyone at a placement or one [segment](segments), such as former subscribers.

You pick which hypothesis to start with. If you're not sure, the skill names its own pick and why. The skill keeps no backlog, so save the reply if you want to come back to the other hypotheses later.

## From hypothesis to A/B test

Once you pick a hypothesis, the skill sets up the parts the CLI can reach, each after your yes:

- **A new flow design or product set**: The skill builds a copy of the flow through the [flow-generator skill](flow-generator-skill), with one change per hypothesis, so the A/B test shows what that change did. Before you publish the copy, it offers to review the copy with the [flow-audit skill](flow-audit-skill).
- **A different audience**: The skill creates the segment and adds its audience to the placement through the `audiences` skill.

Then you choose how users get the change. An [A/B test](ab-tests) in the dashboard is the default, and the only way to measure what the change did. You can also show it now, on a new placement or to some or all users of an existing one.

Before the skill changes an existing placement, it saves the placement to a file so you can roll it back, and it asks whether an A/B test is running there. The CLI can't see A/B-test audiences, and a placement update replaces every audience, so a running test would be deleted without an error. Before you confirm, open the placement's page in the dashboard to see whether a test is running.

New plans, trials, and A/B tests stay in your hands. For each, the skill gives you the steps in App Store Connect, Google Play Console, or the Adapty dashboard. On the App Store, a trial needs a new product; on Google Play, it's an offer on the existing plan. You set the price of any new product.

When an A/B test ends, tell the skill what ran and what won. It suggests the next hypothesis from there.

## Limits

- **No pricing analysis yet**: The skill doesn't read, compare, or suggest prices. When your numbers point at price, it says so and says that pricing analysis isn't supported yet.
- **No A/B test history**: The CLI doesn't return past A/B test results. The skill infers past tests from paywalls that ran side by side, and relies on you to say which version won.
- **No ad spend**: The skill can split installs, trials, and revenue by attribution channel, but not spend or ROAS. For those, use the [adapty-attribution skill](developer-cli-attribution-skill).

To query your analytics yourself, without the skill, see the [CLI analytics reference](developer-cli-analytics). To pull analytics from a server or a scheduled job, where no one can log in through a browser, use the [Export Analytics API](export-analytics-api) with a secret API key.
