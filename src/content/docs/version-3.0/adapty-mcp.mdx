The Adapty MCP server connects an AI assistant to your Adapty account. Ask about revenue and conversions, set up products and placements, publish flows, start an A/B test, or run your Apple Ads campaigns from a chat, in plain language. The assistant signs in with your Adapty account in the browser and gets your permissions. No API key is needed.

| | |
|---|---|
| Server URL | `https://mcp.adapty.io/mcp` |
| Protocol | MCP over Streamable HTTP, OAuth 2.1 sign-in in the browser |
| Works with | claude.ai, Claude desktop, Claude Code, Codex, and other MCP clients that support OAuth sign-in |

:::important
The MCP server gives your assistant access to your Adapty account. To give it the know-how — the flow config rules, tested methods for your analytics, and a confirmation before each step that reaches your users — install the [Adapty plugin](manage-adapty-with-ai#install-the-plugin) first. In Claude Code and Codex, the plugin adds this server for you, so you only [sign in](#connect-your-assistant).
:::

## What the assistant can do

The server's tools follow the Adapty Dashboard and the [Adapty Developer CLI](developer-cli). The assistant picks the tools for your request; you don't name them.

| Area | What the assistant can do | Try asking |
|---|---|---|
| Apps and access levels | List, create, and update apps and access levels | "Create an access level `premium` in Fitness Pro." |
| Products and offers | Create products with their store product IDs, and link store offers to them | "Which of my products have no Google Play product ID?" |
| Paywalls | Create and update paywalls, and find the placements that show each one | "Which placements show the paywall Annual sale?" |
| Flows | Create flows, read and write their builder configs, validate, preview, publish, and read flow metrics | "Publish the flow Onboarding v2 and tell me which placements show it." |
| Placements and audiences | Create placements and change who sees what, and read the metrics of flow placements | "Who sees what on the `onboarding` placement?" |
| Segments | Read segments and their filters | "List my segments and what each one filters on." |
| A/B tests | Create, start, stop, replace, and archive paywall and flow A/B tests | "Start the draft test Weekly vs annual for users in Germany." |
| Analytics | Read revenue, MRR, conversions, the funnel, retention, LTV, and install cohorts | "Compare trial-to-paid conversion by country for last month." |
| Apple Ads | Run campaigns, ad groups, keywords, and automation rules in [Adapty Ads Manager](adapty-ads-manager), and read their metrics | "Which keywords spent the most last week with no installs?" |
| Migration from RevenueCat | Create and run a migration of your RevenueCat catalog to a new Adapty app | "Move my RevenueCat project to a new Adapty app." |

Adapty Mail has its own MCP server. To connect an assistant to your Adapty Mail project, see [Manage Adapty Mail with AI assistants](mail-mcp).

## Choose the MCP server or the CLI

The MCP server and the [Adapty Developer CLI](developer-cli) reach the same Adapty account. With neither, the Adapty plugin asks which one to set up and gives you the steps. With both, it chooses one for each task:

| | Adapty MCP server | Adapty CLI |
|---|---|---|
| Runs in | Any MCP client, including claude.ai and Claude desktop | Agents that run terminal commands, and your own scripts |
| Sign-in | Once per client, in the browser | `adapty auth login`, once per machine |
| Best for | Questions and changes from a chat | Editing flow configs, bulk changes, and scripts |
| Install | Nothing to install | `npm install -g adapty` |

In claude.ai and Claude desktop, the MCP server needs less setup than the CLI: the CLI has to be installed and authorized in every conversation, as [Set up the Adapty CLI in the Claude app](developer-cli-cowork) describes.

<Details summary="Which skills use the MCP server and which use the CLI">

Before its first step, each skill detects whether your assistant has the MCP server, the CLI, or both. With one, the skill uses it. With both, the skill uses the one that suits its work:

- **MCP server**: Running A/B tests, running Apple Ads, integrating the SDK, and testing purchases.
- **Adapty CLI**: Building and auditing flows, finding what to test next, moving placements to flows, and creating segments. These skills run their own scripts and files, and the CLI hands them files directly.

</Details>

## Before you start

- **Adapty account**: The assistant works in the companies and apps your Adapty account can open, with your permissions.
- **MCP client with OAuth**: Your client supports remote MCP servers that sign in with OAuth.

:::warning
The assistant acts with your rights, and its changes are real. A started A/B test or a changed placement reaches your users, and a changed Apple Ads bid or budget spends real money. Before the assistant starts or stops an A/B test, or changes who sees what on a placement, the server asks it to describe the exact effect and wait for your yes. Read the plan before you approve it.
:::

## Connect your assistant

<Tabs groupId="mcp-client" queryString>
<TabItem value="claude-app" label="claude.ai" default>

claude.ai and Claude desktop add remote MCP servers as custom connectors.

1. To add the server, open **Settings → Connectors** and click **Add custom connector**.
2. Enter a name, for example `Adapty`, and the URL `https://mcp.adapty.io/mcp`.
3. Keep the default authentication settings and click **Add**.
4. Sign in to Adapty in the browser tab that opens. See [Sign in](#sign-in).

Workspace admins can add the connector once for the whole organization. Each member then signs in with their own Adapty account the first time they use it.

</TabItem>
<TabItem value="claude-code" label="Claude Code">

If you installed the Adapty plugin, Claude Code already lists the server as `plugin:adapty-skills:adapty`, with the status **Needs authentication**. To sign in, run `/mcp` in Claude Code, select `plugin:adapty-skills:adapty`, and choose **Authenticate**.

Without the plugin, add the server first:

```bash
claude mcp add --transport http --scope user adapty https://mcp.adapty.io/mcp
```

Then run `/mcp` in Claude Code, select `adapty`, and choose **Authenticate**. If the Adapty tools don't appear in the current session, start a new session.

</TabItem>
<TabItem value="codex" label="Codex">

If you installed the Adapty plugin, the plugin adds the server, and Codex asks you to sign in when it connects.

Without the plugin, add the server and sign in:

```bash
codex mcp add adapty --url https://mcp.adapty.io/mcp
codex mcp login adapty
```

The login command opens your browser. To configure the server by hand instead, add it to `~/.codex/config.toml`, then run the login command:

```toml
[mcp_servers.adapty]
url = "https://mcp.adapty.io/mcp"
```

Start a new `codex` session to load the Adapty tools.

</TabItem>
<TabItem value="other" label="Other clients">

Add `https://mcp.adapty.io/mcp` as a remote MCP server in your client's settings or MCP configuration file. The client opens your browser for sign-in the first time it connects.

The server identifies each client by its Client ID Metadata Document, the client registration method of the current MCP specification. A client that doesn't support this method can't complete the sign-in. In that case, use the [Adapty Developer CLI](developer-cli-quickstart) from a terminal agent instead.

</TabItem>
</Tabs>

## Sign in

Every client ends in the same place: the Adapty sign-in page in your browser.

1. Log in with your Adapty account, if you aren't logged in already.
2. Allow the client to access your Adapty account.

The client then reads and changes data in the companies your account can open, and it stays signed in until you disconnect it. Approve only a sign-in that you started yourself.

To verify the connection, ask the assistant which Adapty account it's signed in to. The answer should name you and the companies your account can open.

## Start working

Ask the assistant which apps it can see, then name the app to work on. Some requests to try:

```text
List my Adapty apps and their placements.
How did revenue and new subscriptions change last month compared with the month before?
Which products in Fitness Pro have no App Store product ID?
Show who sees what on the onboarding placement, including any A/B test.
Create a draft A/B test on main_paywall: the current paywall against Annual sale, 50/50.
```

The assistant asks for confirmation before the steps that change what users see. A request that only reads data runs without questions.

After a task of several steps, the assistant can send the Adapty team a short note about how the task went. The note contains no personal data of your app's users.

## Disconnect

To disconnect, remove the server in the client:

- **claude.ai**: In **Settings → Connectors**, remove the Adapty connector.
- **Claude Code**: Run `claude mcp remove adapty`. If the server came with the Adapty plugin, disable it in `/mcp` instead.
- **Codex**: Remove the `adapty` server from `~/.codex/config.toml`.

To connect again, add the server and sign in once more.

## Troubleshooting

| Issue | Solution |
|---|---|
| Claude Code shows the server as **Needs authentication** | The client added the server but didn't sign in. Run `/mcp`, select the Adapty server, and choose **Authenticate**. |
| The client lists no Adapty tools | Finish the sign-in, then start a new session. Some clients load tools only at the start of a session. |
| The assistant can't find an app | The app belongs to a company your Adapty account can't open. Ask a company owner for access. |
| The client can't complete the sign-in | The client doesn't support the sign-in method the server uses. Connect from claude.ai, Claude Code, or Codex, or use the [Adapty Developer CLI](developer-cli-quickstart). |
