A **Segment** is a set of filters that groups users with shared properties. Use segments to target paywalls and A/B tests more effectively.

<SegmentViewDelay />

After you create a segment, you can [use it as an **audience** in Placements and A/B tests](audience) to control which paywall users see (single or multiple). Examples:

- Show a standard paywall to non‑subscribers and offer a discount to users who previously canceled a subscription or trial.
- Display different paywalls to users from different countries.
- Target users based on Apple Search Ads attribution data.
- Ensure users on older app versions keep seeing the existing paywall, while newer versions get the updated one.
- Offer a coin pack to users who are running low on [virtual currency](#virtual-currency-balance), and a subscription to users who have plenty.
- [In Analytics](controls-filters-grouping-compare-proceeds#filter-and-group-data), filter by segments to view performance for specific user groups. Group by segment to compare performance or contribution within **All users**.

## Creation

To create a segment, enter a name and select the attributes that define its filters. When you select multiple attributes, users must match all conditions. Adapty applies AND logic between attributes.

## Available attributes

:::note
While many user attributes are set automatically (like **Country** or **Calculated total revenue USD**), **Age**, **App user ID**, **Attribution** data, **Gender**, and **Custom attributes** are not defined automatically. You must [set user attributes](setting-user-attributes) or [pass the attribution data](attribution-integration) if you want to use it for segmentation.
:::

:::tip
For date-based attributes, you can filter using:

- **Fixed date**: Select specific dates from a calendar (e.g., show a special offer to users who installed between Black Friday and Cyber Monday)
- **Relative range**: Set dynamic time windows like "Last 7 days" or "Last 3 months" (e.g., re-engage users who were last seen 30+ days ago, or target recent installs)

Relative ranges automatically update, making them ideal for ongoing campaigns. Fixed dates work best for time-bound promotions.
:::

## Custom attributes

Define custom attributes to build more targeted segments based on properties unique to your app or business.

:::note
- You can set up custom attributes in the mobile SDK or the Adapty Dashboard. For SDK setup, follow the instructions [here](setting-user-attributes#custom-user-attributes).
- Changing a custom attribute after it's used in a segment may unsync the user from that segment in [analytics](controls-filters-grouping-compare-proceeds#filter-and-group-data). Data will reflect the previous value.
:::

### How to configure a custom attribute

In the Adapty Dashboard, select **Create custom attributes** from the attribute dropdown menu.

| Field  | Description                                                                                                                          |
| ------ |--------------------------------------------------------------------------------------------------------------------------------------|
| **Name**   | A label for the custom attribute, used only in the Adapty Dashboard.                                                                 |
| **Key**    | A unique identifier for the attribute. This must match the key used in the SDK.                                                      |
| **Type**   | Choose between:<ul><li>String: Requires a predefined list of possible values.</li><li>Number: Accepts only numeric values.</li></ul> |
| **Values** | If you select `String`, enter the list of possible values. If you choose `Number`, the attribute will only accept numeric input. Numeric attributes support decimal values and can be used with comparison operators.    |

Once you save a custom attribute, its **Key** and **Type** are permanent — both fields are disabled if you reopen the attribute for editing. To use a different key or type, create a new custom attribute rather than trying to edit the existing one; only **Name** and **Values** (for a String attribute) can be changed after creation.

After you fill in the required fields, you can use custom attributes in your segments, [A/B tests](ab-tests), and more.

Each profile can have up to 30 custom attributes.

### How operators match missing attributes

The **≠** operator matches only profiles where the attribute is set: a profile with no value for the attribute doesn't match `attribute ≠ value`. The same applies to the comparison operators (`>`, `<`, `≥`, `≤`, `between`). To match profiles without the attribute, use the **is not set** operator. To target every profile except those with a specific value, combine `≠` with **is not set** — or set an explicit value on every profile and filter with `≠` alone.

The comparison is also typed: if a profile stores the attribute with a different type than the segment compares — for example, a string value where the segment expects a number — the profile counts as not having the attribute.

## Virtual currency balance

To show a different paywall, onboarding, or A/B test to users depending on how many credits they have, filter a segment by their [virtual currency](virtual-currencies) balance. Each currency in your app adds its own attribute, **Virtual currency: &lt;name&gt; (&lt;code&gt;)**, for example **Virtual currency: Coins (COINS)**. The code tells apart two currencies with the same name.

<ZoomImage id="segment-vc-balance-attribute.webp" width="700px" alt="The attribute list in the segment editor, with Virtual currency: Coins (COINS) and Virtual currency: Gems (GEMS) below the other attributes" />

The filter compares the user's current balance, the amount they can spend right now:

- **Operators**: **=** (one or more values), **≠**, `>`, `<`, `≥`, `≤`, and `between`.
- **Values**: Whole numbers from 0. The dashboard doesn't accept fractions or negative numbers.
- **No balance counts as 0**: A user who has never received the currency has a balance of 0, so `Virtual currency: Coins (COINS) < 10` includes them. This differs from [other attributes](#how-operators-match-missing-attributes), where a missing value matches no comparison. For the same reason, there is no **is set** or **is not set** operator.

You can combine a balance filter with any other filter, and use several currencies in one segment. For example, **Calculated subscription state** = active and **Virtual currency: Coins (COINS)** `< 10` targets subscribers who are running low on coins.

<ZoomImage id="segment-vc-balance-filter.webp" width="700px" alt="A segment filtered by Virtual currency: Coins (COINS) less than 10, with the message that profile count and profile list are unavailable for segments with a virtual currency balance filter" />

Adapty reads the balance each time the SDK fetches a profile or a paywall, so a credit or debit counts right away, however it happened: a purchase, a subscription renewal, a [server-side API](getting-started-with-server-side-api) transaction, or expiring credits. The event-feed delay that applies to other attributes doesn't apply here. When the app fetches a paywall, Adapty selects the audience by the current balance, even if the SDK hasn't refreshed the profile yet.

A segment with at least one balance filter has these limits:

- **No user count or sample**: The **Segments** list shows **—** instead of the number of users, and the segment page shows no total or [random sample](#total-number-and-random-sample). Adapty reads the balance only at fetch time, so it can't count the users in advance.
- **Not in charts**: You can't filter or group [analytics charts](controls-filters-grouping-compare-proceeds) by the segment. The **Virtual currency** chart filter doesn't replace it: that filter selects purchases by the currency the product grants, not users by their balance.
- **Crossplacement A/B tests keep their users**: After a user enters a [Crossplacement A/B test](ab-test-types#crossplacement-ab-test-limitations) through this segment, the user keeps the variant even when the balance no longer matches the segment. The variant stays until the [stickiness period](general#9-cross-placement-variation-stickiness) after the test stops runs out. Other A/B tests match the user against the segment again at each fetch.

<ZoomImage id="segment-vc-balance-list.webp" width="700px" alt="The Segments list, where a segment with a balance filter shows a dash instead of the number of users" />

A balance belongs to one [profile](virtual-currency-balance#balances-profiles-and-devices). An anonymous user who reinstalls your app or opens it on another device gets a new profile with a balance of 0, and falls into `< 10` again. To keep balance segments consistent across devices, identify your users.

If Adapty can't read the balance during a fetch, the user matches no balance segment and gets the next audience by [priority](change-audience-priority).

Adapty also shows a random sample of 40 users who fit the criteria. Use it to test your segment and ensure it’s configured correctly.

## Duplicate segments

If you need a segment similar to an existing one, duplicate it instead of building it from scratch. This saves time for teams that run multiple campaigns or A/B tests with overlapping user groups.

Duplicating a segment creates a copy with all its filters and description. The new segment will have "(copy)" added to its name so you can tell it apart from the original. The new segment is independent of the original. Changes to one do not affect the other.

To duplicate a segment in the Adapty Dashboard:

1. Open the **Profiles & Segments** section in the Adapty main menu and switch to the [**Segments**](https://app.adapty.io/segments) tab.
2. Click the **3-dot** button next to the segment and select **Duplicate**.

## Delete segments

When you no longer need a segment, you can delete it permanently.

Adapty blocks deletion if the segment is currently used as an audience by either of the following:

- **A placement**: At least one non-deleted placement uses the segment as its audience.
- **An A/B test (Live or Completed)**: At least one non-deleted A/B test uses the segment as its audience.

For segment deletion, Adapty treats both **Live** and **Completed** A/B tests as active. A Completed test still uses the audience to show the post-test paywall or onboarding to matching users, and historical metrics for the test are scoped to that segment. The segment is released only when the A/B test itself is deleted.

:::warning
Segment deletion is permanent. The segment cannot be restored.
:::

To delete a segment in the Adapty Dashboard:

1. Go to **Profiles & Segments** in the Adapty main menu and switch to the [**Segments**](https://app.adapty.io/segments) tab.
2. Click the **3-dot** button next to the segment and select **Delete**.
3. Type the segment name in the confirmation field, then click **Delete forever**.

:::info
If the segment is in use, the dialog lists the placements and A/B tests that reference it.

To unblock deletion, open each placement or A/B test from the list and either remove the segment from its audience or delete the placement or A/B test entirely. Once nothing references the segment, you can delete it.
:::
