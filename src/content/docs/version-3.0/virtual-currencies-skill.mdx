[Virtual currencies](virtual-currencies) grant credits to your users when they buy a product or renew a subscription. The virtual-currencies skill manages them from your AI tool. Your agent lists your currencies, shows how many credits each linked product grants, creates a currency, and adds, changes, or removes its linked products. It also reads the credit transactions and the balances of a user, so it can tell you why that user has a balance. After your yes, it credits or debits the balance of one user. It works through the [`adapty virtual-currencies` CLI commands](developer-cli-virtual-currencies) or the [Adapty MCP server](adapty-mcp).

:::note
The skill asks before each change. It shows you what changes: each linked product with its credits before and after, the new currency with its products, or a user's balance before and after. It runs the change only after your yes. New credit amounts of linked products apply from the next purchase or renewal: current subscribers get the new amount at their next renewal. A balance correction applies at once.
:::

## What you can ask

Ask the way you'd brief a colleague. You don't need to name the skill:

```
Which virtual currencies does my app have?

How many gems does the Starter pack give?

Give the Starter pack 50 gems.

Create a currency "Gems" and give 100 gems for each Gem pack purchase.

Stop giving gems for the Weekly subscription.

Why does user 4512 have 40 coins?

User 4512 should have 50 gems, not 40. Correct the balance.

A player's 400 coins disappeared after they reinstalled the app. Why?
```

## Before you start

- **Products in Adapty**: A currency grants credits through its linked [products](create-product) in Adapty.
- **An AI tool connected to your Adapty account**: The skill works through the [Adapty MCP server](adapty-mcp) or the [Adapty CLI](developer-cli). In Claude Code and Codex, the plugin adds the MCP server, so you only sign in. The skill checks which of the two your AI tool has and uses it. With both, it uses the MCP server. With neither, the skill asks which one to set up.

## Install the skill

## What the skill asks before each change

The skill reads the currency right before each change, and shows you what changes. Only your answer to the skill's question counts. A general "go ahead" before the skill shows the change doesn't. If you say no, the skill changes nothing.

| Change | What the skill tells you |
|---|---|
| Create a currency | The code, the name, and its linked products. You can't delete a currency or change its code, and an app can have up to 20 currencies. A balance belongs to one user profile, so if your users don't sign in, they lose their credits when they reinstall the app or move to a new device. |
| Add or change linked products | Each product that changes: new, or its credits before and after, for each purchase or each subscription period. Current subscribers get the new amount at their next renewal. The other linked products stay as they are. |
| Remove a linked product | The product with its credits now. Its purchases stop granting credits of this currency, and no transaction records the purchases that grant none. Credits already granted stay. |
| Change the name or the description | The name or the description before and after. The rest stays as it is. |
| Correct a user's balance | The user, the balance before and after, the currency code, the direction, and the operation, for example `4512: 40 → 50 GEMS, credit, adjustment`. Each change corrects one currency of one user. To undo a correction, ask for a correction in the other direction. |

If the currency changes between the skill's read and its write, in the dashboard or from another tool, the skill doesn't overwrite that change. Adapty refuses the write, or, for a name change through the CLI, the skill's read right before the write shows the change. Nothing changes. The skill shows you the change again and waits for a new yes.

If Adapty doesn't answer a change, the skill doesn't send it again at once. It reads the currency first and tells you what was saved. For a part of the change that is still missing, it shows you a new question and waits for a new yes.

A balance correction is different: if Adapty doesn't answer it, the skill sends the same correction one more time, with the same idempotency key, within one hour. Adapty applies a key only once, so the balance doesn't change twice. The skill never sends the correction again with a new key, because a new key makes a second correction. If no key is known, one hour has passed, or the second send gets no answer too, the skill doesn't send the correction again. It reads the user's balances and transactions and tells you what Adapty saved.

## How the skill explains a balance

Ask why a user has a balance, and the skill reads the user's credit transactions and balances, by the profile ID or by your own user ID. It tells you which purchases, spends, and grants gave the balance, and which credits expire and when. The [user's profile](virtual-currency-balance) in the dashboard shows the same data.

If a user's credits disappear after a reinstall, on a new device, or after a login, the skill asks you for the user's previous profile and reads its balance. A balance belongs to one profile and doesn't move to another, so the credits stay on the previous profile. To keep each user's balance on every device, [identify your users](virtual-currency-balance#balances-profiles-and-devices).

To correct the balance after the explanation, ask the skill for the fix. The skill shows you the correction and waits for your yes.

## Limits

- **No deletion of a currency**: You can't delete a currency or change its code, in the skill or in the dashboard.
- **One user for each correction**: The skill corrects one currency of one user for each change, as the [Adjust balance](virtual-currency-balance#adjust-a-balance-manually) form of the dashboard does. Your server spends and grants credits through the server-side API: see the [Virtual currency quickstart](virtual-currency-quickstart) and [Grant an initial balance](grant-initial-balance).
- **Idempotency key for one hour**: Adapty applies the key of a correction once for each user, for one hour, and doesn't compare the rest of the request. For the details, see [Send a correction only once](developer-cli-virtual-currencies#send-a-correction-only-once).
- **No unattended changes**: In a scheduled run or a script, with no one to answer, the skill only reads. For a change, it reports what the change does and the command for you to run.

To run the commands yourself, without the skill, see [Manage virtual currencies from the CLI](developer-cli-virtual-currencies).
