[Virtual currencies](virtual-currencies) grant credits to your users when they buy a product or renew a subscription. The virtual-currencies skill manages them from your AI tool. Your agent lists your currencies, shows how many credits each linked product grants, creates a currency, and adds, changes, or removes its linked products. It also reads the credit transactions and the balances of a user, so it can tell you why that user has a balance. With your approval, it credits or debits the balance of one user. It works through the [`adapty virtual-currencies` CLI commands](developer-cli-virtual-currencies) or the [Adapty MCP server](adapty-mcp).

:::note
Before each change, the skill shows you what will change and waits for your approval. When the skill changes how many credits a product grants, the change applies from the next purchase or renewal. A balance correction applies right away.
:::

## What you can ask

Ask the way you'd brief a colleague. You don't need to name the skill:

```
Which virtual currencies does my app have?

How many gems does the Starter pack give?

Give the Starter pack 50 gems.

Create a currency "Gems" and give 100 gems for each Gem pack purchase.

Stop giving gems for the Weekly subscription.

Why does user 4512 have 40 coins?

User 4512 should have 50 gems, not 40. Correct the balance.

A player's 400 coins disappeared after they reinstalled the app. Why?
```

## Before you start

- **Products in Adapty**: A currency grants credits through its linked [products](create-product) in Adapty.
- **An AI tool connected to your Adapty account**: The skill works through the [Adapty MCP server](adapty-mcp) or the [Adapty CLI](developer-cli). In Claude Code and Codex, the plugin adds the MCP server, so you only sign in. The skill checks which of the two your AI tool has and uses it. With both, it uses the MCP server. With neither, the skill asks which one to set up.

## Install the skill

## What the skill asks before each change

Right before each change, the skill loads the latest data from Adapty and shows you what will change. The skill then waits for your approval, even if you said "go ahead" before it showed the change. If you say no, the skill changes nothing.

| Change | What the skill tells you |
|---|---|
| Create a currency | The code, the name, and its linked products. You can't delete a currency or change its code, and an app can have up to 20 currencies. A balance belongs to one user profile, so if your users don't sign in, they lose their credits when they reinstall the app or move to a new device. |
| Add or change linked products | Each product that changes: new, or its credits before and after, for each purchase or each subscription period. Current subscribers get the new amount at their next renewal. The other linked products stay as they are. |
| Remove a linked product | The product with its credits now. Its purchases stop granting credits of this currency, and no transaction records the purchases that grant none. Credits already granted stay. |
| Change the name or the description | The name or the description before and after. The rest stays as it is. |
| Correct a user's balance | The user, the balance before and after, the currency code, the direction, and the operation, for example `4512: 40 → 50 GEMS, credit, adjustment`. Each correction changes the balance of a single currency for a single user. You can't undo a correction. To offset it, ask for a second correction with the same amount in the other direction. |

Someone else can edit the name, description, or linked products of a virtual currency at the same time as the skill. If that edit happens while the skill waits for your approval, the skill doesn't overwrite it and saves nothing. The skill then shows you its change again, based on the latest data, and asks for your approval.

When a change fails with a network or server error, the skill can't tell whether Adapty saved the change. Instead of sending it again, the skill loads the latest data from Adapty and tells you what Adapty saved. If anything you approved isn't saved, the skill shows you what still needs to change and asks for your approval again.

A balance correction is the exception, because Adapty makes one correction for each idempotency key. When a correction fails with a network or server error, the skill sends that correction to Adapty once more with the same key, within one hour of the first send:

- If the first send made the correction, the second send changes nothing.
- If the first send didn't make the correction, the second send makes it.

The skill never sends a correction again with a new key, because a new key makes a second correction. If the skill has no key for the correction, an hour has passed, or the second send also fails, the skill doesn't send the correction again. It reads the user's balances and transactions, tells you what Adapty saved, and stops. If Adapty didn't save the correction, ask the skill for it again. The skill shows you the correction and waits for your approval.

## How the skill explains a balance

Ask why a user has a balance, and the skill reads the user's credit transactions and balances, by the profile ID or by your own user ID. It tells you which purchases, spends, and grants gave the balance, and which credits expire and when. The [user's profile](virtual-currency-balance) in the dashboard shows the same data.

If a user's credits disappear after a reinstall, on a new device, or after a login, the skill asks you for the user's previous profile and reads its balance. A balance belongs to one profile and doesn't move to another, so the credits stay on the previous profile. To keep each user's balance on every device, [identify your users](virtual-currency-balance#balances-profiles-and-devices).

To correct the balance after the explanation, ask the skill for the fix. The skill shows you the correction and waits for your approval.

## Limits

- **No deletion of a currency**: You can't delete a currency or change its code, in the skill or in the dashboard.
- **One user for each correction**: Each correction changes the balance of a single currency for a single user, as the [Adjust balance](virtual-currency-balance#adjust-a-balance-manually) form of the dashboard does. Your server spends and grants credits through the server-side API: see the [Virtual currency quickstart](virtual-currency-quickstart) and [Grant an initial balance](grant-initial-balance).
- **Idempotency key for one hour**: Adapty applies the key of a correction once for each user, for one hour, and doesn't compare the rest of the request. For the details, see [Send a correction only once](developer-cli-virtual-currencies#send-a-correction-only-once).
- **No unattended changes**: Every change requires human approval. If the skill runs where no one can approve a change, such as in a scheduled task or a script, it changes nothing in Adapty. Instead, it replies with a CLI command that you can run yourself. To automate changes, skip the skill and run the [CLI commands with `--yes`](developer-cli-virtual-currencies#confirmation-in-scripts-and-agents) in your script.

To run the commands yourself, without the skill, see [Manage virtual currencies from the CLI](developer-cli-virtual-currencies).
