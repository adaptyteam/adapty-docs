Use purposes to control when Adapty Mail emails your users: which events start a sequence, which ones stop it early, and when a user can receive it again. Every flow belongs to one purpose and follows its rules. The flows of a purpose send the emails, one flow for each segment, so a purpose without flows sends nothing. To send one segment different emails, [add a flow](mail-flows#audience-and-content) for that segment, not a new purpose.

Every project starts with eight purposes, each with its own [default rules](#default-rules-of-the-standard-purposes). You can edit or delete any of these standard purposes except **Double opt-in**. When none of them fits, create a purpose, for example to start emails on an event from your app.

## Marketing vs. transactional purposes

Each purpose is marketing or transactional, with a tab for each class on the **Purposes** page. The two classes differ as follows:

| | Marketing | Transactional |
| --- | --- | --- |
| Used for | Offers and reminders to buy, stay, or come back | Service messages, such as an address confirmation, access to the app after a purchase, or a purchase receipt. Keep offers out: these emails reach unsubscribed users too. |
| Email sequences at a time | One per user. [The order of marketing purposes](#change-the-order-of-marketing-purposes) decides from which purpose the user receives a sequence. | Several, with no order. A user can receive a sequence from each transactional purpose they match, alongside any marketing sequence. |
| Not sent to | Users who are suppressed, declined email consent, or wait for [double opt-in](mail-double-opt-in) | Users [suppressed after a bounce, a spam report, or a failed address verification](mail-suppression#what-still-reaches-a-suppressed-profile) |

## Match users to a purpose

The rules of a purpose decide which users receive the emails of its flows, and when.

### Entry rules: events and conditions that activate a purpose

The entry rule of a purpose has two parts: entry events, which can include [events from your app](#event-triggers-from-your-app), and an optional profile [condition](#profile-conditions). A user matches a purpose when they trigger one of its entry events. If the purpose has a condition, the user has to also meet that condition at the moment of the event. A condition alone starts nothing: a user who already meets it when you create the purpose still has to trigger one of its entry events.

A change to any of these profile fields counts as a **Profile updated** event:

- Name, gender, and birthday
- Country and store country
- Email consent
- Custom attributes
- Device info

A change of email address doesn't count as **Profile updated**.

Among the standard purposes, **Never purchased** alone has **Profile updated** in its default entry events. As a result, users without a purchase can receive a sequence from **Never purchased** on their next profile change, even if they arrived before its flow existed.

#### Event triggers from your app

Custom events are events from your app, such as a completed onboarding. Your server reports them to Adapty Mail through the [API](mail-send-data-via-api#report-events-from-your-app).

To use a custom event as an entry event, in the **Entry rule** field, type the event name under **Custom**. The dashboard doesn't compare the name with your API requests, so keep it identical to their `event_type`.

To show the `payload` of a custom event in generated emails, in the **Payload fields** section, describe the fields of the event. Each field has three settings:

- **Field name**: The name of the field in `payload`. The field appears in emails through the placeholder [`{{ custom_event.<field> }}`](mail-email-data#custom-event-placeholders).
- **What it holds**: A description of what the field contains. Adapty Mail reads this description when it generates emails for the purpose.
- **May be missing**: The custom event can come without the field. Generated emails then only show the field when the event has it. In HTML you write, [hide such a field](mail-email-data#hide-a-part-when-its-value-is-missing) yourself.

#### Profile conditions

A **Condition** limits a purpose to users whose profile is in a given state, such as **Subscription state** = Auto-renew off. When Adapty Mail receives the entry event, it compares the condition with the profile, not with the data of the event.

In a condition, you can use these [segment filter fields](mail-segments#available-filter-fields): **Email confirmed at**, the **Purchase state** fields, and **Custom event**. You can't use a custom attribute in a condition. Instead, filter by it in the segment of a flow.

### Exit rules

With nothing selected in the **Exit rule** field, a sequence continues after a purchase. The field has two reasons that stop a sequence before its last email:

- **When the profile stops meeting the entry condition**: Adapty Mail compares the profile with the condition again on every event about the user.
- **When one of these events happens**: The sequence stops when the user triggers one of the selected events. For a custom event, type its name under **Custom**.

To stop a marketing sequence once a user buys, under **When one of these events happens**, select **Subscription started** and **One-time purchase**.

The event that stops a sequence can start a sequence from another purpose. For example, with the default rules, a user in a **Billing issue** sequence triggers **Subscription expired**. The sequence stops, and the user receives a sequence from **Expired**.

After any exit, the email that didn't go out appears as **Cancelled** in the [activity journey](mail-profiles#email-events), with the outcome **Stop condition met**.

### Re-entry rules: when the purpose can apply again

The re-entry rule of a purpose decides when a user can receive a sequence from it again.

The rule counts every sequence the user had in the purpose, whichever flow sent it. A new flow or campaign doesn't reset the count.

**On every entry event** is the default for a new transactional purpose. With this option, each purchase or custom event among the entry events starts its own sequence, even while an earlier sequence still runs. Marketing purposes are the exception: each user has one marketing sequence at a time.

For a purpose with **Profile updated** among its entry events, select **Never** or **After a number of days**. These options limit how many sequences a user receives, however often their profile changes.

## Create a purpose

1. In Adapty Mail, go to **Purposes**.
2. **You create a purpose on the tab of its [class](#marketing-vs-transactional-purposes), and you can't change the class later.** Open the **Marketing** or **Transactional** tab, then click **Create**.
3. Fill in the **Name** and **Brief for AI** fields. Adapty Mail [generates campaign emails](mail-create-campaign) for the purpose from the brief and the rules.
4. In the **Entry rule** field, select the [entry events](#entry-rules-events-and-conditions-that-activate-a-purpose). For an [event from your app](#event-triggers-from-your-app), type its name under **Custom**. Then, in the **Payload fields** section, describe the fields of the event.
5. To limit the purpose to users in a given state, in the [**Condition**](#profile-conditions) field, click **Add filter**.
6. In the **Exit rule** field, select the [reasons](#exit-rules) that stop a sequence early. In a new marketing purpose, a sequence stops on **One-time purchase**.
7. In the **Re-entry rule** field, select when a user can [receive a sequence from the purpose again](#re-entry-rules-when-the-purpose-can-apply-again). A new marketing purpose starts with **Never**.
8. Click **Create**.

The new purpose stays a **Draft** until one of its flows sends an email. Next, [create a campaign](mail-create-campaign) for the purpose, then a [flow](mail-create-flow#create-a-flow) that sends the campaign.

A new marketing purpose goes last in the [order](#change-the-order-of-marketing-purposes). To have users receive a sequence from it rather than from a purpose above it, move it up.

## Change the order of marketing purposes

When several marketing purposes share an entry event, their order decides from which purpose a user receives a sequence. On such an event, Adapty Mail:

1. Tries the purposes in order of their **Priority**, from 1 up.
2. Skips a purpose if the user doesn't meet its condition, or isn't in the segment of any of its flows.
3. Stops at the first purpose it doesn't skip. If the [re-entry rule](#re-entry-rules-when-the-purpose-can-apply-again) of that purpose allows a new sequence, the user receives it. Otherwise, the user receives no sequence from that purpose or from the purposes after it.

During a marketing sequence, the user receives no other marketing sequence, even from a purpose higher in the order.

To change the order:

1. On the **Purposes** page, open the **Marketing** tab, then click **Change order**.
2. Drag the purposes into the order you need.
3. Click **Save**.

## Edit and delete a purpose

To edit a purpose, on the **Purposes** page, click its name. You can change everything except the class, standard purposes included. Unlike a [flow edit](mail-flows#flow-lifecycle), a change to the rules also applies to the sequences already running.

You can't change or delete the **Double opt-in** purpose: the [double opt-in](mail-double-opt-in) setting relies on it.

To prevent new sequences of a purpose, [delete its flows](mail-create-flow#delete-a-flow). Only delete the purpose itself when you won't need it again: a deleted standard purpose doesn't come back.

You can delete a purpose once it has no flows: in its row menu, select **Delete**. A deleted purpose becomes **Archived**. To see it, in the state filter, select **Archived**.

## Default rules of the standard purposes

To set an edited standard purpose back, change its rules to these values.

The standard marketing purposes start with the following rules:

| Purpose | Entry events | Condition | Exit rule | Re-entry rule |
| --- | --- | --- | --- | --- |
| Never purchased | Profile created, Email confirmed, Profile updated | Subscription state = Never purchased and One-time purchase state = Never purchased | The profile stops meeting the entry condition | Never |
| Renewal cancelled | Renewal cancelled | Subscription state = Auto-renew off | The profile stops meeting the entry condition; One of: One-time purchase | On every entry event |
| Expired | Subscription expired | Subscription state = Expired | Same as Renewal cancelled | On every entry event |
| Billing issue | Billing issue detected, Entered grace period | Subscription state = Billing issue, Grace period | Same as Renewal cancelled | On every entry event |
| Refunded | Subscription refunded | Subscription state = Refunded | Same as Renewal cancelled | On every entry event |

The standard transactional purposes start with the following rules:

| Purpose | Entry events | Condition | Exit rule | Re-entry rule |
| --- | --- | --- | --- | --- |
| Double opt-in | Profile created | Email confirmed at is not set | The profile stops meeting the entry condition | Never |
| App activation, Cancellation page | Subscription started, One-time purchase | None | Only when all emails are sent | Never |

## Troubleshooting

- **A user doesn't receive a sequence from a purpose they went through before**: Its [re-entry rule](#re-entry-rules-when-the-purpose-can-apply-again) counts every past sequence. To let users receive a sequence from it again, change the rule. To [test](mail-testing) the purpose again, sign up with a new email address.
- **Nobody receives a sequence from a marketing purpose**: A purpose higher in the order has the same entry event. Users who meet its condition receive no sequence from the purposes after it, if a flow of that purpose has them in its segment. [Move your purpose up](#change-the-order-of-marketing-purposes), or narrow the higher purpose with a condition.
- **Nobody matches a purpose on its custom event**: The name under **Custom** differs from the `event_type` your server sends. Make the two names identical.
- **A user meets the condition but enters no flow**: No flow of the purpose has the user in its segment. To reach such users, [add a flow](mail-flows#audience-and-content) for **All Users**.
