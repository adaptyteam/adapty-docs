[Singular](https://www.singular.net/) is one of the leading Mobile Measurement Partner (MMP) platforms, that collects and presents data from marketing campaigns. This helps companies track their campaign performance. 

Adapty provides a complete set of data that lets you track [subscription events](events) from stores in one place. With Adapty, you can easily see how your subscribers are behaving, learn what they like, and use that information to communicate with them in a way that's targeted and effective. Therefore, this integration allows you to track subscription events in Singular and analyze precisely how much revenue your campaigns generate.

Adapty can send all subscription events which are configured in your integration to Singular. As a result, you'll be able to track these events within the Singular dashboard. This integration is beneficial for evaluating the effectiveness of your advertising campaigns.

## Set up integration

### Connect Adapty to Singular

<ZoomImage id="singular-creds.webp" />

To set up the integration with Singular, go to [Integrations > Singular](https://app.adapty.io/integrations/singular) in your Adapty Dashboard, turn on a toggle, and fill out the fields.

The following credentials are available:

- **Singular SDK Key**: Required. The production SDK key for your Singular app.
- **Singular SDK Key (Sandbox)**: Optional. The SDK key for your sandbox Singular app. If not set, sandbox events will not be sent to Singular.

Both keys can be found in the Singular dashboard under **Developer tools -> SDK Keys -> SDK Key (**not** SDK Secret)**:

We recommend using the default event names provided by Adapty. But you can change the event names based on your needs.

Adapty sends subscription events to Singular server-to-server, so you can view all subscription events in your Singular dashboard and link them to your acquisition campaigns. If your Singular account uses SDID, your app also needs to pass the SDID to Adapty. See [Connect your app to Singular](#connect-your-app-to-singular).

:::warning
Profiles created prior to configuring the integrations will not be able to deliver their events to Singular. 
:::

### Connect your app to Singular

Singular enables the Singular Device ID (SDID) by default for accounts created on or after July 15, 2026. These accounts accept events only through the v2 Event API, and Adapty sends an event to v2 only when the user's profile has an SDID. To deliver events to such an account, pass the SDID to Adapty from your app.

If your Singular account doesn't use SDID, skip this step. Adapty sends your events to the v1 Event API, and no app code is needed.

1. Activate Adapty, then start the Singular SDK with an SDID callback: `sdidReceivedHandler` on iOS, `SDIDAccessorHandler` on Android, `sdidReceivedCallback` on React Native and Flutter, and `SingularSdidAccessorHandler` on Unity.
2. Wait for Singular to call the callback. The SDID reaches your app asynchronously, not at launch. Singular calls the callback on every launch, including when the SDID is already stored on the device.
3. Inside the callback, pass the SDID to Adapty with `setIntegrationIdentifier()` and the `singular_sdid` key. No Adapty SDK has a predefined constant for this key, so pass it as a string.
4. Call `Adapty.identify()` only after `setIntegrationIdentifier()` completes. Adapty creates an anonymous profile at activation, then switches to the identified profile once `identify()` resolves. An SDID set during that switch can be lost.

For the full sequence, see call order in the [iOS](ios-sdk-call-order), [Android](android-sdk-call-order), [React Native](react-native-sdk-call-order), [Flutter](flutter-sdk-call-order), [Unity](unity-sdk-call-order), [Capacitor](capacitor-sdk-call-order), and [Kotlin Multiplatform](kmp-sdk-call-order) SDKs.

## Event structure

Adapty picks the Singular Event API version for each event by whether the user's profile has an SDID:

- **With an SDID**: Adapty sends a `POST` request to `https://s2s.singular.net/api/v2/evt` with a form-urlencoded body. The `sdid` parameter replaces the device identifiers `idfa`, `idfv`, `aifa`, `andi`, and `asid`. Booleans are sent as `true` or `false`.
- **Without an SDID**: Adapty sends a `GET` request to `https://s2s.singular.net/api/v1/evt` with query parameters.

Both versions carry the same parameters otherwise. A v1 event is structured like this:

```json
{
  "n": "subscription_renewed",
  "a": "singular_sdk_key_123",
  "p": "iOS",
  "i": "com.example.app",
  "ip": "192.168.100.1",
  "idfa": "00000000-0000-0000-0000-000000000000",
  "idfv": "00000000-0000-0000-0000-000000000000",
  "ve": "17.0.1",
  "att_authorization_status": 3,
  "custom_user_id": "user_12345",
  "utime": 1709294400,
  "partner": "adapty",
  "use_ip": false,
  "is_revenue_event": true,
  "amt": 9.99,
  "cur": "USD",
  "purchase_product_id": "yearly.premium.6999",
  "purchase_transaction_id": "GPA.3383...",
  "e": "{\"is_revenue_event\":true,\"amt\":9.99,\"cur\":\"USD\",\"purchase_product_id\":\"yearly.premium.6999\",\"purchase_transaction_id\":\"GPA.3383...\"}"
}
```

Where:

| Parameter                  | Type    | Description                                          |
|:---------------------------|:--------|:-----------------------------------------------------|
| `n`                        | String  | The event name (mapped from Adapty event).           |
| `a`                        | String  | Your Singular SDK Key.                               |
| `p`                        | String  | Platform ("iOS" or "Android").                       |
| `i`                        | String  | Store App ID (Bundle ID).                            |
| `ip`                       | String  | User's IP address.                                   |
| `sdid`                     | String  | **v2 only**. Singular Device ID, from the `singular_sdid` integration identifier. |
| `idfa`                     | String  | **iOS, v1 only**. ID for Advertisers (uppercase).    |
| `idfv`                     | String  | **iOS, v1 only**. ID for Vendors (uppercase).        |
| `aifa`                     | String  | **Android, v1 only**. Google Advertising ID (lowercase). |
| `andi`                     | String  | **Android, v1 only**. Android ID (lowercase).        |
| `asid`                     | String  | **Android, v1 only**. App Set ID (lowercase).        |
| `ve`                       | String  | OS version.                                          |
| `att_authorization_status` | Integer | **iOS only**. ATT status (e.g., `3` for authorized). |
| `custom_user_id`           | String  | The user's Customer User ID.                         |
| `utime`                    | Long    | UNIX timestamp of the event in seconds.              |
| `partner`                  | String  | Always `adapty`. Identifies the event as sent by Adapty. |
| `use_ip`                   | Boolean | `true` when Adapty has no IP address for the user, so Singular uses the request's IP address instead. |
| `is_revenue_event`         | Boolean | `true` if the event contains revenue. Sent only with revenue events. |
| `amt`                      | Float   | Revenue amount.                                      |
| `cur`                      | String  | Currency code (e.g., "USD").                         |
| `purchase_product_id`      | String  | The Product ID from the store.                       |
| `purchase_transaction_id`  | String  | Original transaction ID.                             |
| `e`                        | String  | JSON string containing event details (see below).    |

The `e` parameter (custom event data) is a JSON-encoded string containing:

| Parameter                 | Type    | Description                           |
|:--------------------------|:--------|:--------------------------------------|
| `is_revenue_event`        | Boolean | `true` if the event contains revenue. |
| `amt`                     | Float   | Revenue amount.                       |
| `cur`                     | String  | Currency code.                        |
| `purchase_product_id`     | String  | The Product ID from the store.        |
| `purchase_transaction_id` | String  | Original transaction ID.              |

## Troubleshooting

### Events fail with `invalid api version: v1`

Your Singular account was created on or after July 15, 2026, and accepts events only through the v2 Event API. Adapty sent the event to v1 because the user's profile has no SDID. To fix this, pass the SDID to Adapty from your app, as described in [Connect your app to Singular](#connect-your-app-to-singular).
