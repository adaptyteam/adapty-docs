To fix an App Store integration problem, find the section that names the symptom you see.

## "The provided field values are incorrect" when saving credentials

When you save the In-App Purchase key, Adapty builds an authentication token from the **Issuer ID**, **Key ID**, and **Private key (.p8 file)** fields, and validates it against Apple. This error means Apple rejected the token. Verify the values in this order:

1. **Key type.** The key must be an **In-App Purchase** key from **Users and Access** > **Integrations** > **In-App Purchase** in App Store Connect. A key from the **Team Keys** tab (the App Store Connect API key) has its own **Issuer ID** and **Key ID**, but Apple rejects it here. [Connect that key](app-store-connect-api-key#connect-the-key-in-adapty) in the **App Store Connect API key** section instead.
2. **Same account and team.** The Issuer ID, Key ID, and .p8 file must come from the same App Store Connect team as the app. A key generated in another team's account — for example, an agency account — fails validation.
3. **The .p8 file itself.** Upload the file exactly as downloaded from App Store Connect. A file recreated from pasted key contents often fails. You can only download each key once, so if the original file is lost, generate a new key.
4. **Bundle ID.** The Bundle ID must match your app's bundle ID in App Store Connect exactly — reverse-DNS format with no spaces, for example, `com.company.app`.
5. **Hidden characters.** Re-copy each ID directly from App Store Connect. Stray whitespace or lookalike characters — for example, a lowercase `l` in place of the digit `1` — make validation fail.

This validation uses only the three In-App Purchase key fields and the Bundle ID. The App-Specific Shared Secret and the [App Store Connect API key](app-store-connect-api-key) take no part in it, so re-entering either one won't change the outcome.

If every value matches App Store Connect and you still see the error, contact Adapty support at [support@adapty.io](mailto:support@adapty.io).

## Products don't appear or show no App Store status

When Adapty can't read your products from App Store Connect, you see one or more of the following signs:

- The **App Store Product ID** dropdown doesn't list your product.
- The product list shows a dash or "Not Connected" in the **App Store status** column, or the product page stays on "Status pending".
- The **Associated plan** list of a retention message shows "No options".
- The price CSV that you download for a product only contains column headers.

Review the following causes in order:

- **The app has no App Store Connect API key**: [Connect a team key](app-store-connect-api-key).
- **Apple rejects the App Store Connect API key**: The key belongs to another team, was revoked, or its Key ID doesn't match its .p8 file. [Replace the key](app-store-connect-api-key#replace-the-key) with one from the team that owns the app.
- **The Apple App ID is empty or wrong**: [Copy the Apple ID of the app](app-store-connection-configuration#enter-the-bundle-id-and-apple-app-id) from App Store Connect into the **Apple App ID** field.
- **The product is in another app**: Adapty only looks for products in the App Store Connect app with your Apple App ID. Verify that the product belongs to that app.
- **The product is less than 10 minutes old**: Wait 10 minutes after you create it in App Store Connect, then look for it in the **App Store Product ID** dropdown again.

## "403 Client Error: Forbidden" when you push a product

When you push a product, App Store Connect returns this error if the Account Holder hasn't accepted the latest Paid Apps Agreement. To accept the agreement, the Account Holder opens **Business** > **Agreements** in App Store Connect. There, they click **View and Agree to Terms** for Paid Apps.

A revoked App Store Connect API key causes the 403 error too: [replace the key](app-store-connect-api-key#replace-the-key).

## The notifications status reads "Delayed" or "Stalled"

The notifications status on **App settings** > **iOS SDK** reads "Delayed" when the last notification arrived over 24 hours ago. After 72 hours, it reads "Stalled". [Verify that **Production Server URL** and **Sandbox Server URL** in App Store Connect both match the **URL for App Store server notifications** in Adapty](enable-app-store-server-notifications#check-that-notifications-reach-adapty).

## A purchase succeeds but the customer loses access

A customer pays and may briefly have access, but has none after your app refreshes the profile from Adapty.

The cause is usually one of these:

- **The In-App Purchase key stopped working**: Adapty couldn't validate the transaction with Apple. [Replace the key](generate-in-app-purchase-key#replace-the-key).
- **The product isn't linked in Adapty**: The store product ID the customer bought isn't linked to an Adapty product, so no access level exists to grant. Confirm the product exists with the exact **App Store Product ID** and has an [access level](access-level) assigned.

After you replace the In-App Purchase key, ask the customers who bought while it was broken to restore purchases. A restore brings their access back at once.

## Prices in Adapty don't match App Store

If Adapty and the App Store show different prices for a product, review how you added it. The **price** field on the product page in Adapty has a different purpose in each case.

If you create a product in Adapty and push it to the store from the dashboard, this price is used as the initial store price.

If you add a product that already exists in the store, this price is a placeholder. Adapty's analytics, integrations, and SDK use the real prices fetched from the App Store regardless. Changes to App Store prices don't sync back to update the placeholder, and you can't currently edit the placeholder from the dashboard.
