This quickstart sets up a token currency end to end: a monthly subscription grants users 1000 tokens each billing period, and paid actions in your app cost tokens. Adapty keeps every balance, so your backend only reads and spends them.

1. Follow the [Create virtual currency](create-virtual-currency) guide to create a `TOKENS` currency. Link it to your Pro subscription and set **Credit per cycle** to 1000. Adapty grants the **Credit per cycle** once per billing period of the subscription: every month for a monthly subscription, every week for a weekly one. To sell extra tokens, link one-time token pack products as well.

   <ZoomImage id="new-currency-combined.webp" width="700px" alt="New virtual currency creation screens" />

2. Call [List virtual currency balances](api-adapty/operations/listVirtualCurrencyBalances) to read the user's balance, for example, before starting a generation:

   ```bash title="Read balances"
   curl https://api.adapty.io/api/v2/server-side-api/vc/balances/ \
     -H "Authorization: Api-Key {your secret key}" \
     -H "adapty-customer-user-id: user-42"
   ```

   The response lists every currency in your app, including currencies with a balance of 0. For example, 1000 `TOKENS`:

   ```json title="Response"
   {
     "response_created_at": 1794477600123,
     "data": [
       {
         "code": "TOKENS",
         "name": "Tokens",
         "balance": 1000,
         "held": 0,
         "available": 1000,
         "expiry": { "non_expiring": 1000, "expiring": [], "expiring_later": 0, "expired": 0 }
       }
     ]
   }
   ```
3. When the user runs a generation, spend the tokens by calling [Create virtual currency transaction](api-adapty/operations/createVirtualCurrencyTransaction) with a negative `amount`. In this example, one image generation costs 100 tokens. To show what the tokens were spent on, the request also sets `operation` to `spend` and `feature` to `image_generation` (see [Label transactions](virtual-currencies#label-transactions)):

   ```bash title="Spend tokens"
   curl -X POST https://api.adapty.io/api/v2/server-side-api/vc/transactions/ \
     -H "Authorization: Api-Key {your secret key}" \
     -H "adapty-customer-user-id: user-42" \
     -H "Content-Type: application/json" \
     -d '{
           "items": [{"currency_code": "TOKENS", "amount": -100}],
           "operation": "spend",
           "feature": "image_generation"
         }'
   ```

   The transaction is atomic and returns the updated balance. One transaction can change up to 20 currencies, each listed once in `items`. If the user can't cover the cost, the request returns `insufficient_balance` and nothing changes. Include an `Idempotency-Key` header to safely retry requests. To open a top-up flow when the balance can't cover a spend, follow the recipe for [iOS](ios-virtual-currency-top-up).
4. To run a win-back promo, grant tokens through the same endpoint with a positive `amount`. Credits you grant this way never expire. To give users a balance before their first purchase, see [Grant an initial balance](grant-initial-balance).
5. Review every change in the user's [profile](virtual-currency-balance) or in the [transaction history](api-adapty/operations/listVirtualCurrencyTransactions), so you can audit the economy at any time.
