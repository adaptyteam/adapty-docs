Adapty Mail runs an MCP server, so an AI assistant can work in your project the way you do in the dashboard: generate and localize campaigns, launch flows, set up a sending domain, look up profiles and read analytics. The assistant signs in with your own Adapty Mail account and gets your permissions once you approve the connection in the dashboard. No API key is needed.

| | |
|---|---|
| Server URL | `https://api-mail.adapty.io/mcp` |
| Protocol | MCP over Streamable HTTP, OAuth 2.1 sign-in |
| Works with | Claude (web and desktop), ChatGPT, Claude Code, Codex CLI, GitHub Copilot CLI, Gemini CLI, Cursor, Windsurf, and any client that supports remote MCP servers with OAuth |

:::tip
For the best results in a coding agent, add the [Adapty Mail skill](mail-skill) too. It connects the server for you, asks before anything that emails real people, and covers the work after launch: results, A/B tests, and why someone didn't get an email.
:::

## What the assistant can do

The server's tools mirror the dashboard:

| Area | Examples |
|---|---|
| Orientation | Find your companies and projects, see which setup steps are missing |
| Brand | Build the brand from a store listing, review and edit it |
| Sending domains | Add a domain, get its DNS records, check verification, read domain health |
| Destinations | Create and update the pages your emails link to |
| Campaigns | Generate a campaign from a brief, edit emails, translate them, send a test email |
| Flows and segments | Create segments and launch or change flows |
| A/B tests | Create, launch, and finish tests |
| Profiles | Look up a profile and its journey, unsubscribe a profile |
| Analytics | Campaign metrics over time, breakdowns, A/B test funnels |
| Settings | Sender name, reply-to address, double opt-in, image uploads |

Three guided workflows are available as prompts in clients that support them. In Claude Code, they appear as slash commands, for example `/mcp__adaptymail__campaign_to_flow`:

- **campaign_to_flow**: Generate a campaign from a brief, pick a destination and a segment, and launch the flow.
- **campaign_localization**: Translate a saved campaign into more languages.
- **domain_onboarding**: Add a sending domain, publish its DNS records, and verify it.

Some setup steps are dashboard-only: your [company address](mail-get-started#5-add-your-company-address), the [web checkout](mail-checkout), and [turning on data sending](mail-entry-points).

## Before you start

- **Project membership**: Your Adapty Mail account is a member of the project you want to work on. The assistant sees only the companies and projects your account can open.
- **Client support**: Your client supports remote MCP servers with OAuth.

:::warning
The assistant has the same rights as you, and everything it does is real: saving a flow starts sending emails to real people. The server marks its destructive tools, and the assistants we tested ask for confirmation before running them. Read the assistant's plan before you approve it.
:::

## Connect your assistant

### Claude (claude.ai and Claude desktop)

1. To add the server, open **Settings → Connectors** and click **Add custom connector**.
2. Enter a name, for example `Adapty Mail`, and the URL `https://api-mail.adapty.io/mcp`.
3. Leave **Authentication** on **Sign in now** and the OAuth client on the detected default, then click **Add**.
4. In the Adapty Mail tab that opens, log in if asked, and click **Approve**.

Workspace admins can add the connector once for the whole organization. Each member then signs in with their own Adapty Mail account the first time they use it.

### ChatGPT

ChatGPT adds custom MCP servers from the connectors page in **Settings**. Developer mode must be enabled for your workspace.

1. To add the server, click **Create**.
2. Enter a name, for example `Adapty Mail`, and the server URL `https://api-mail.adapty.io/mcp`. Keep **Authentication** on **OAuth**.
3. Expand **Advanced OAuth settings**. Under **Client registration**, set **Registration method** to **Dynamic Client Registration (DCR)**.
4. Accept the custom MCP server warning and click **Create**.
5. When ChatGPT asks, connect the server. In the Adapty Mail tab that opens, log in if needed, and click **Approve**.

:::important
Step 3 is required. With ChatGPT's default registration method, the connection fails with an `invalid_request` error saying the client ID was not found.
:::

### Claude Code

```bash
claude mcp add --transport http --scope user adaptymail https://api-mail.adapty.io/mcp
```

To sign in, run `/mcp` in Claude Code, pick `adaptymail`, and choose **Authenticate**. Then log in to the Adapty Mail dashboard in your browser and click **Approve**.

### Codex CLI

```bash
codex mcp add adaptymail --url https://api-mail.adapty.io/mcp
codex mcp login adaptymail
```

The login command opens your browser, where you approve the connection. To configure the server by hand instead, add it to `~/.codex/config.toml`, then run the login command:

```toml
[mcp_servers.adaptymail]
url = "https://api-mail.adapty.io/mcp"
```

### GitHub Copilot CLI

```bash
copilot mcp add --transport http adaptymail https://api-mail.adapty.io/mcp
```

The first time the server connects, your browser opens for sign-in.

### Gemini CLI

```bash
gemini mcp add --transport http --scope user adaptymail https://api-mail.adapty.io/mcp
```

Start a new session, then run `/mcp auth adaptymail` and approve the connection in your browser.

### Cursor, Windsurf, and other clients

Add the server to the client's MCP configuration file, for example `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "adaptymail": {
      "url": "https://api-mail.adapty.io/mcp"
    }
  }
}
```

The client opens your browser for sign-in the first time it connects. Clients that don't support OAuth for remote servers can't connect to Adapty Mail.

## Approve the connection

Every client ends on the same screen in the Adapty Mail dashboard. It names the application asking for access and the address where the application receives that access. For desktop tools, that address is on your own computer (`localhost`), so approve only a connection you started yourself. To finish, click **Approve**.

The connection request expires after 10 minutes. If the screen says **This request has expired**, start again from the client.

## Start working

Ask the assistant to list your projects, then name the one you want to work on. Some requests to try:

- "Show the onboarding status of my project and tell me what is missing."
- "Generate a win-back campaign for users whose trial expired, in English, and show me the first email."
- "Translate the campaign Trial expired into German and French."
- "Add `mail.example.com` as a sending domain and give me the DNS records."
- "Compare open and click rates of my live campaigns for the last 30 days."

## Disconnect

To disconnect, remove the connector in the client's settings. In Claude, it's in **Settings → Connectors**; in ChatGPT, on the connector's page; in Claude Code, run `claude mcp remove adaptymail`.

The client's access token expires within an hour. The refresh token is revoked when the client disconnects; an unused one expires after 90 days. To connect again, add the server and approve the connection once more.

## Troubleshooting

| Issue | Solution |
|---|---|
| ChatGPT fails with `invalid_request` and "Client ID ... not found" | In the connector's settings, set **Registration method** to **Dynamic Client Registration (DCR)**. See [ChatGPT](#chatgpt). |
| The dashboard says the connection request has expired | Start the connection again from the client, and approve it within 10 minutes. |
| The assistant says the project was not found | Your account is not a member of that project. Ask a company owner for access. |
| The assistant was logged out | Access expires after a long idle time or after you disconnect. Reconnect from the client. |
| The client lists no tools | The client connected without signing in. Run its sign-in step, for example `/mcp` in Claude Code. |
