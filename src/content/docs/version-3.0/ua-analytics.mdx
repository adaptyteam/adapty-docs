[Analytics](https://app.adapty.io/ua/analytics) is the section of the Adapty Attribution Dashboard where you see the metrics of all your campaigns in one place. You can choose which metrics and charts to show. The data includes organic installs and their revenue, so you can use the section for an app with no ad campaigns too.

The Analytics section has two tabs:

- **Analytics**: A cohort-based table of your campaign metrics.
- **Charts**: Line charts for individual metrics over time.

<ZoomImage id="ua-analytics.webp" width="900px" />

:::tip
The same data is available from the terminal through the [Attribution CLI commands](developer-cli-attribution). To have an AI coding tool read it and answer questions like "Should we kill this campaign?", install the [Attribution skill](developer-cli-attribution-skill).
:::

## Metrics

Adapty Attribution provides comprehensive **metrics** to measure campaign performance and user behavior. These metrics are available as standard values, with key metrics also offered as **cohort metrics** for time-based analysis of user groups.

To read the metrics correctly:

- **Expect recent campaign results to change**: For up to 30 days after an install, Adapty Attribution can still credit the install and its revenue to another channel or campaign.
- **Don't use spend-based metrics for Apple Search Ads**: Adapty Attribution doesn't import Apple Search Ads spend, so these metrics, such as cost per install (CPI) and return on ad spend (ROAS), don't include it.
- **Look for web purchases by their purchase date**: Purchases from [Stripe](ua-stripe), [Paddle](ua-paddle), or [FunnelFox](ua-funnelfox) only appear in Adapty Attribution analytics, not in Adapty analytics. They have no app install, so Adapty cohorts them by the date of the first trial start or purchase. Pick a date range that includes that date. If you filter by platform, include the web funnel.
- **Expect one person to count twice for a web and an in-app purchase**: If a person buys on the web and later in the app, Adapty Attribution counts that person as two paying users. Each purchase has its own attribution and cohort date.

See the complete metric list [here](ua-metrics).

## Customize which metrics to show

To choose which metrics the table shows and in what order:

1. In the top-right corner, click the name of the current preset. It's **Default** at first.
2. Select **Edit columns**.
3. Remove the metrics you don't need, add new ones, or drag them into a new order.

<ZoomImage id="ua-customize.gif" width="900px" />

A cohort period limits a metric to a number of days after the install:

| Cohort period | What the metric counts | Example |
|---|---|---|
| None | All revenue and events so far | **ROAS** |
| **D0** | Revenue and events on the install day | **D0 ROAS** |
| **D3**, **D7**, **D30**, **D60**, **D90**, **D180**, **D360** | Revenue and events up to that many days after the install | **D3 ROAS**: up to 3 days after the install |
| Custom | Revenue and events up to the number of days that you set | — |

To compare a recent date range with an older one, add a cohort period to the metric, so that every install gets the same number of days. The **Default** preset already shows **D3 ROAS** next to **ROAS**.

<ZoomImage id="ua-cohorts.webp" width="500px" />

You can also save views you use most as presets, so you can switch between them quickly anytime. Click the current preset name and click the **Save** icon or, in the **Edit columns** window, click **Save as preset**.

<ZoomImage id="ua-preset.webp" width="900px" />

## Controls

The **Analytics** page has four main controls.

<ZoomImage id="ua-controls.webp" width="900px" />

### Time ranges

Adapty Attribution shows installs and revenue by day in UTC, not in the [reporting timezone](general#3-reporting-timezone) of your app. It shows ad spend by day in the time zone of each ad account. To show installs and revenue in another time zone, contact [Adapty support](mailto:support@adapty.io).

You can [set the date range](controls-filters-grouping-compare-proceeds#set-the-date-range) the same way as in Adapty analytics.

### Filters

Filter by metrics, so you can see only those values that are above or below some threshold.

### Group by

You can group rows by channel, campaign, ad set, ad, keyword, country, or time period. By default, the table has one row per campaign name:

- If you rename a campaign, its data splits into two rows, one for each name.
- If two campaigns have the same name, their data shares one row.

To give each campaign, ad set, ad, or keyword its own row, select **Campaign**, **Adset**, **Ad**, or **Keyword** in **Group by**.

### Gross revenue or proceeds

In the revenue dropdown, select **Gross revenue**, **Proceeds after store commission**, or **Proceeds after store commission and taxes**. These options work the same way as in [Adapty analytics](controls-filters-grouping-compare-proceeds#display-gross-or-net-revenue).

## Filter sets

Filter sets let you save a group of filters and switch between them with a single click. Use them to keep the views you check most often, like "Campaigns above $1,000 spend" or "iOS only".

Beneath the main filter controls, each saved filter set appears as a chip. Click a chip to apply its filters, or click the **×** on a chip to delete it. The active set is highlighted.

To save the current filters as a new set:

1. Set up the filters you want to save.
2. Click **+** at the end of the filter sets row.
3. Enter a name and click **Save**.

<ZoomImage id="ua-filter-set.gif" width="900px" />

## Charts

The **Charts** tab shows a line chart for a single metric over the selected time range. Use the left navigation to switch between metrics.

Available chart metrics:

- Spend
- Impressions
- Clicks
- CPC
- CPM
- CTR
- Installs
- Total Revenue
- ARPU
- CPI
- ARPPU
- ROAS
- ICR
- Cost Per Trial
- Cost Per Subscription

The same time range, group by, filters, and filter sets apply on both the **Analytics** and **Charts** tabs.

<ZoomImage id="ua-charts.webp" width="900px" />
