To connect your iOS app to Adapty, enter its App Store credentials in **App settings** > **iOS SDK**. Adapty then:

- Validates purchases.
- Receives subscription events.
- Keeps your products in sync with App Store Connect.

If purchases or subscription events stop reaching Adapty, [check each credential](#check-each-credential).

Before you start:

- You need access to the target application in App Store Connect. If the app isn't there yet, [Set up App Store Connect](set-up-app-store-connect). If you don't have access to the platform, request it.
- Your team needs access to the App Store Connect API — it's necessary to generate the required access key. If your team doesn't have it yet, ask the Account Holder to [request it](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api). Apple reviews each request.
- Open two browser tabs: your app in [App Store Connect](https://appstoreconnect.apple.com/apps) in one, and [**App settings** > **iOS SDK**](https://app.adapty.io/settings/ios-sdk) in Adapty in another. You will copy values between the two tabs throughout this guide.

## Overview

Every credential in this guide is required. Adapty uses each one for [a different part of the data exchange with the App Store](store-sync#if-updates-stop-arriving). To complete the setup, follow these seven steps:

1. Enter [the Bundle ID and Apple App ID](#enter-the-bundle-id-and-apple-app-id)
2. Enter [the app-specific shared secret](#enter-the-app-specific-shared-secret)
3. Enable [App Store server notifications](#enable-app-store-server-notifications) with the URL from Adapty
4. Add the [In-App Purchase key](#add-the-in-app-purchase-key)
5. Add the [App Store Connect API key](#add-the-app-store-connect-api-key)
6. Install the [Adapty SDK and make a sandbox purchase](#check-each-credential)
7. [Verify all the credentials](#check-each-credential)

## Enter the Bundle ID and Apple App ID

Two values identify your app in App Store Connect: the Bundle ID and the Apple ID, labeled **Apple App ID** in Adapty. Adapty needs the Bundle ID to process purchases. With the Apple ID, Adapty:

- Finds your products in App Store Connect and [creates new ones there](create-product#create-product-and-push-to-store).
- Shows the App Store status and prices of your products.
- Serves real-time messages for [Retention Messaging](retention-messaging-setup).
- Runs the [AI Growth Advisor](autopilot) analysis.
- Identifies your app to attribution integrations, such as AppsFlyer.

Apple assigns the Apple ID when you add the app to App Store Connect, so enter it even before your app is on the App Store.

## Enter the app-specific shared secret

Adapty needs the app-specific shared secret to validate purchase receipts and to create products in App Store Connect.

1. In [App Store Connect](https://appstoreconnect.apple.com/apps), open the **App Information** page of your app. In the **App-Specific Shared Secret** section, click **Manage**.

   <ZoomImage id="asc-app-information-shared-secret.webp" width="700px" alt="App-Specific Shared Secret section on the App Information page in App Store Connect" />

2. Copy the secret. If the app has no secret yet, click **Generate** first. To generate a secret, you need the Account Holder or Admin role in App Store Connect. Without either role, ask someone who has one to generate the secret and send it to you.

   Unless you received the app in an [app transfer](transfer-apps#app-store-ios-transfer), don't click **Regenerate**: the current secret then stops working everywhere it's in use.

   <ZoomImage id="asc-shared-secret-dialog.webp" width="700px" alt="App-Specific Shared Secret window with the secret" />

3. In Adapty, paste the secret into the **App Store Connect shared secret** field.

   <ZoomImage id="app-settings-shared-secret.webp" width="700px" alt="App Store Connect shared secret field in Adapty" />

4. Click **Save**.

## Enable App Store server notifications with the URL from Adapty \{#enable-app-store-server-notifications\}

:::link
Main article: [Enable App Store server notifications](enable-app-store-server-notifications)
:::

Apple sends server notifications to Adapty about renewals, refunds, and other subscription events as they happen. Adapty records these events even when your app reports no transaction.

If Apple already sends these notifications to a server, set up forwarding to that server before you replace its URL in App Store Connect. In Adapty, enter the URL of that server in the **URL for forwarding raw Apple events** field, and click **Save**. Adapty then [forwards the notifications it receives from Apple](enable-app-store-server-notifications#raw-events-forwarding) to that server.

If your backend must keep its URL in App Store Connect, [pass the notifications to Adapty from your backend](forwarding-events-to-adapty) instead.

## Add the App Store Connect API key

:::link
Main article: [Add the App Store Connect API key to Adapty](app-store-connect-api-key)
:::

Adapty uses the App Store Connect API key to [create products in App Store Connect](create-product#create-product-and-push-to-store) and to keep their status and prices in sync. It's a different key from the In-App Purchase key, though the two share the field names **Issuer ID** and **Key ID**.

Adapty needs a team key with **Admin** access. If you don't have one yet, [generate it in App Store Connect](app-store-connect-api-key#generate-a-team-key-in-app-store-connect) first. To connect the key in Adapty:

## Check that each credential works \{#check-each-credential\}

To confirm that Adapty validates purchases, [install the Adapty SDK](installation-of-adapty-sdks) in your app and [make a sandbox purchase](test-purchases-in-sandbox).

The sandbox purchase only uses some of the credentials. Verify each one after the purchase, and again whenever purchases or subscription events stop reaching Adapty:

- **Bundle ID**, **Apple App ID**, and **App Store Connect shared secret**: Compare the three values with the **Bundle ID**, the **Apple ID**, and the secret under **App-Specific Shared Secret** on the **App Information** page in App Store Connect.
- **App Store server notifications**: The status in this section reads **Active** once a notification about a purchase or a renewal reaches Adapty. If it reads anything else, [check the server URLs](enable-app-store-server-notifications#check-that-notifications-reach-adapty).
- **In-app purchase API (StoreKit 2)**: Adapty verifies the key with Apple when you save it. If purchases in your app later unlock no access, the key may have stopped working: [replace the key](generate-in-app-purchase-key#replace-the-key).
- **App Store promotional offers**: Make sure the **Subscription key ID** matches the **Key ID** in the **In-app purchase API (StoreKit 2)** section. If they differ, [enter the same key in both sections](generate-in-app-purchase-key#add-the-key-to-adapty).
- **App Store Connect API key**: Each App Store product shows a status in the **App Store status** column on the **Products** page. If a product shows a dash or **Not Connected**, [check the key and the Apple App ID](troubleshoot-app-store-integration#products-dont-appear-or-show-no-app-store-status).

Right after setup, Analytics can count more trials and purchases than installs, and more than the Event Feed shows. The difference is [transactions without profiles](how-profiles-work#transactions-without-profiles): purchases of users who haven't opened a version of your app with the Adapty SDK yet.

Other differences between Adapty and store reports come from [how each one counts purchases](discrepancies-and-troubleshooting), not from the credentials.
