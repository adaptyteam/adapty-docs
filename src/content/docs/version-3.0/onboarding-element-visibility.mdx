You can control whether an element appears by adding a condition to it. A conditional element is only visible to users who meet the specified criteria.

A condition can also evaluate the [state of another element](element-states-in-conditions). For example, you can show a hint only if a button is **Disabled**.

:::important
If you show or hide an element using the **Show element** or **Hide element** [action](onboarding-actions), the action overrides the **Visibility** condition set on that element. The override lasts until a variable or element state in the condition is updated.

On an element with a **Visibility** condition, these actions change the element at once, [without animation or delay](flow-show-hide-animations#when-animation-and-delay-dont-apply).

Use **Visibility** conditions for elements that should appear or hide based on a criterion, such as a quiz answer. Use actions when visibility should change at a specific moment, such as [when the screen opens or users tap an element](flow-show-hide-animations#show-or-hide-an-element).
:::

To add a condition to an element:

1. Select the element in the canvas or layer panel.
2. In the **Visibility** section of the right panel, select **Conditional**.

<ZoomImage id="flow-conditional-visibility.webp" width="500px" alt="Conditional visibility settings" />

3. To set up the condition, select a property type from one of the following tabs:
   - **Custom**: Variables you create and manage; their values can be updated via user interactions. See [Variables](onboarding-variables) for details.
   - **Product**: Properties of the products in your flow, such as price or name.
   - **Elements**: Variables of other elements, such as a quiz answer or whether a toggle is on.
   - **States**: The [state of another element](element-states-in-conditions) on the screen, such as a **Disabled** button.
   - **System**: Values that the Adapty SDK reports about the user's device: the platform (`system.platform`), **Device region**, and **Device language**. See [Show an element on one platform only](#show-an-element-on-one-platform-only) and [Show an element by device region or language](#show-an-element-by-device-region-or-language).
4. Enter the **Value** to match.
5. Click the operator to change it if needed.
6. (Optional) Click **Add condition** to add more conditions. Use the selector to require all conditions to match, or any one of them.

## Show an element on one platform only

To keep one flow for iOS and Android, show platform-specific elements only on their platform. For example, show "Manage your subscription in App Store settings" on iOS, and "Manage your subscription in Google Play" on Android.

1. Select the element, and in the **Visibility** section, select **Conditional**.
2. Click the **Variable** field, open the **System** tab, and select `system.platform`.
3. In the value dropdown, select **iOS** or **Android**. With `=`, the element shows only on that platform. With `!=`, it shows only on the other platform.

<ZoomImage id="flow-condition-system-platform.webp" width="500px" alt="Show element if editor with the System tab open and system.platform selected" />

The Adapty SDK reports the platform, so your app doesn't need to pass it. Android devices, including Huawei devices, match **Android**.

The canvas shows the element if the condition matches the platform of the [preview device](paywall-device-compatibility-preview#preview-in-the-adapty-dashboard). To preview the other platform, select a device of that platform in the preview controls.

To show a whole screen on one platform only, use a [conditional action](onboarding-actions#show-a-screen-on-one-platform-only).

## Show an element by device region or language

Use one flow to show content based on the device region or language. For example, show distances in miles for selected device regions and in kilometers for all other devices.

1. Select the element. In the **Visibility** section, select **Conditional**.
2. In **Show element if**, open the variable picker. On the **System** tab, select **Device region** or **Device language**.
3. Select the operator:
   - `=` (**Equals**) shows the element when the device value equals the selected value.
   - `!=` (**Does not equal**) shows the element when the device value differs from the selected value.
   - **Is any of** shows the element when the device value is in the selected list.
   - **Is none of** shows the element when the device value is outside the selected list.
4. In the **Region** or **Language** dropdown, select one value for `=` or `!=`. For **Is any of** or **Is none of**, select one or more values.

:::note
flow-device-region-visibility.webp
:::

Regions use two-letter country codes, such as `US` and `DE`. Languages use two- or three-letter codes, such as `en`, `es`, and `fil`.

For the miles and kilometers example, use two elements with opposite conditions:

- **Element with miles**: **Device region**, **Is any of**, `US`, `GB`, `LR`, `MM`.
- **Element with kilometers**: **Device region**, **Is none of**, `US`, `GB`, `LR`, `MM`.

Each device shows one of the two elements, including a device that reports no region.

### Where the values come from

The Adapty SDK supplies the region and language for these conditions. Your app selects the [flow localization](localizations-and-locale-codes) separately. These conditions require native Adapty SDK v4.0 or later on iOS and Android. Cross-platform apps use the native SDK bundled with their integration.

The values come from the language and region settings of the device. They aren't the country of the user's IP address or of the user's App Store or Google Play account. A user who travels or turns on a VPN keeps the same device region. To target users by IP country or store country, show each flow to an [audience](audience) built from a [segment](segments) on **Country** or **Country from store account**.

The flow uses the first locale the SDK reports.

- **iOS**: Both values come from the first preferred-language tag the SDK reports. For example, `ru-GE` gives language `ru` and region `GE`. If the tag has no two-letter region code, **Device region** has no value.
- **Android**: On Android 7.0 and later, the SDK reports Android's default locale list. The flow uses the first locale. On Android 6.0 and earlier, the SDK uses the app's current locale when available. Otherwise, it reports only the default language. The region comes from the two-letter country code of the selected locale, when present.

**Device language** is the language code only. Spanish (Mexico) and Spanish (Spain) both give `es`. To match devices configured for Portuguese and Brazil, add **Device language** `=` `pt` and **Device region** `=` `BR`. Require both conditions to match.

### When the device reports no value

Region and language can be missing independently. For example, `es-419` gives language `es` and no two-letter region. When the device reports no value for the field in a condition:

- `=` and **Is any of** fail to match.
- `!=` and **Is none of** match.

The flow shows the screen without an error.

### Preview a region or language

To preview a condition, open **Preview settings** in the toolbar below the canvas. Set **Device region** or **Device language**. The defaults are `US` and `en`. To simulate a missing value for either field, select **Not set** for that field.

:::

In the units example, the canvas shows miles for `US` and kilometers for `DE` or **Not set**. Use the separate flow locale selector to preview localized content.

To send users to a different screen by region or language, use a [conditional action](onboarding-actions#route-users-by-device-language-or-region).
