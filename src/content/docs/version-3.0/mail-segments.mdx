A **segment** is a reusable audience slice. You define it once — in **Segments** — and reference it from flows and A/B tests. Segments are filter definitions, not snapshots: they're evaluated on demand when a user matches the [purpose](mail-purposes) of a flow, so membership always reflects the latest profile data.

## Create a segment

1. In Adapty Mail, go to **Segments** and click **+ Create**. The create page opens with the title **New Segment**.
2. Give the segment a **Name** (required) and an optional **Description**.
3. Under **Filters**, click **Add filter** for each [rule](#available-filter-fields) you want. Each filter becomes a collapsible card labeled **Filter 1**, **Filter 2**, and so on.
4. For each filter, pick a field, pick an operator, and enter the comparison value.
5. Save the segment.

:::important
Filters are combined with **AND** — a user must match every filter to be in the segment. OR logic and nested groups aren't supported. Each field except [**Custom event** and **Custom attribute**](#available-filter-fields) can only appear once per segment. To match several values of one field, enter them all in its `=` filter.
:::

## Import a segment from Adapty

Instead of building a segment from filters, you can import an existing audience segment from the main Adapty dashboard.

1. On the **Segments** page, click **Import**.
2. Review the list. **Importable segments** show a checkbox and their filter conditions. Segments that **can't be imported** are grayed out with the specific reason, such as an unsupported field (for example, Apple Ads attribution data), an unsupported operator, or a subscription state with no Adapty Mail equivalent.
3. Check the segments you want and click **Import**.

<ZoomImage id="mail-import-segments.webp" width="500px" alt="Import segments dialog with importable segments checked and unimportable segments grayed out with rejection reasons" />

:::important
Import creates an independent copy of the segment's filters at the time of import — it isn't kept in sync with the original Adapty segment, and importing the same segment again creates a separate copy each time, since Adapty Mail doesn't detect duplicates.
:::

Imported segments start in **Draft** state, the same as segments you build manually, so you can edit their filters right away.

In the condition of a [purpose](mail-purposes#profile-conditions), you can use the Purchase state fields, **Email confirmed at**, and **Custom event**. The other fields only work in segments.

Notes on the fields:

- **Source**, **Subscription source**, and **One-time purchase source**: Adapty, FunnelFox, FunnelFox Billing, or Custom (API).
- **Email confirmed at**: When the recipient confirmed their address through [double opt-in](mail-double-opt-in).
- **Device info** fields: Not set unless your entry point sends device data to Adapty Mail. With the API, send it in the [`device_info` object](mail-send-data-via-api#send-user-profiles).
- **Subscription state**: Never purchased, Subscribed, Auto-renew off, Billing issue, Grace period, Expired, or Refunded.
- **Subscription purchases**: How many times the user paid for their current subscription. The number includes the first purchase, unless it was a free trial, and every renewal. A user on a free trial has 0 subscription purchases. Refunds don't lower the number, and payments for an earlier subscription don't add to it.
- **One-time purchase state**: Never purchased, Purchased, or Refunded.
- **One-time purchases**: How many one-time purchases the user made, whatever the product. Refunds don't lower the number.
- **Custom event**: Filters users by the [custom events](mail-send-data-via-api#report-events-from-your-app) you send to Adapty Mail, such as `onboarding_completed`. Select **Custom event** as the field. Type the event name, then select the operator: `is set` matches users who have had the event, and `is not set` matches the rest.

  One segment or condition can hold several **Custom event** filters, each with a different event name. Adapty Mail keeps the last 50 custom event names of each user. For an event name outside those 50, `is not set` matches the user, even if they had the event.
- **Custom attribute**: Filters users by a [custom attribute](mail-profiles#the-profile-card) on their profile. Select **Custom attribute** as the field. Enter the key of the attribute in the **Attribute key** field. Then select **String** or **Number** in the **Type** field.

Operators available per field type:

- **String**: `=`, `≠`, `is set`, `is not set`.
- **Number**: `=`, `≠`, `<`, `>`, `≤`, `≥`, `between`, `is set`, `is not set`.
- **Date**: The same operators as Number. For a date, `<` means before and `>` means after.
- **Version**: The same operators as Number, applied in version order — `1.10.0` ranks above `1.9.0`.

## The All Users system segment

Adapty Mail ships with a built-in **All Users** segment that has no filters — every user in the project qualifies. You can't edit or delete it. A flow with **All Users** always goes last in [priority](mail-flows#priority) among the flows of its purpose.

## Lifecycle

A segment's state is calculated from the flows that use it now:

- **Draft**: No flow uses it. A segment goes back to draft when you delete its last flow. A draft A/B test that names the segment doesn't change its state.
- **Live**: A flow uses it.
- **Archived**: Soft-deleted and hidden from the main list.

The Segments page has a state filter in the toolbar so you can narrow the list to any of these states.

## Edit and delete a segment

- **Name and description**: Editable unless the segment is archived.
- **Filters**: Editable while the segment is a **Draft**. While a flow uses it, the filters are read-only. To change the targeting of a flow, create a segment with the filters you need, then [replace the flow](mail-create-flow#send-a-flow-to-another-segment).
- **Delete**: Soft-deletes the segment. You can't delete a segment while a flow uses it, or while an A/B test that isn't finished names it, a draft included. Delete those flows, and finish or delete those A/B tests, first.

## Limitations

- **No OR logic, no nesting**: Filters combine with AND only.
- **One field per segment**: A segment can't have two filters on the same field (for example, two country checks). The exceptions are **Custom event** filters with different event names and **Custom attribute** filters with different keys.
- **No size preview**: The editor doesn't show how many users currently match the filters.
- **Filters locked after first use**: Only a **Draft** segment's filters can change. Any segment that has been used is read-only except for its name and description.
