Adapty React Native SDK 4.4 changes the fallback file format, requires iOS 16 for flows, and reports more flow errors to your app. To update your app to 4.4, install the latest `react-native-adapty` package, and replace both fallback files in the same build. SDK versions 4.1–4.3 reject the new files. Then review each flow error change in this guide.

If you're still on 4.0, start with [Migrate to v4.1](migration-to-react-native-sdk-41) and then follow this guide.

:::warning
The fallback file format changed in 4.4, and the compiler can't detect a fallback file for SDK 4.1–4.3. Without [new fallback files](#replace-the-fallback-files), every placement loses its fallback.
:::

## Quick reference

| v4.3 | v4.4 |
|---|---|
| Fallback files downloaded for 4.1–4.3 | New fallback file format; download both files again |
| Flows open on iOS 15 | Flows require iOS 16 |
| On iOS, `AdaptyFlowView` stays empty when its flow can't load | It reports the error to its `onError` handler |
| On iOS, flow and onboarding calls made while AdaptyUI isn't activated throw errors with the `unknown` code | They throw errors with `adaptyUINotActivated` or `adaptyNotActivated` |
| On Android, the SDK only logs flow script errors | They reach the `onError` handler as `jsException` |

## Installation

Update the `react-native-adapty` package:

```bash showLineNumbers
npm install react-native-adapty@latest
# or
yarn add react-native-adapty@latest
```

The requirements are unchanged: **iOS 15.0** and **React Native 0.75**. Flows are the exception: they require iOS 16.0. See [Install Adapty SDK](sdk-installation-reactnative) for the full setup.

## Replace the fallback files

To download the [fallback files](react-native-use-fallback-paywalls) again, in **[Placements](https://app.adapty.io/placements)**, click **Fallbacks** > **Download iOS Fallback**. In the **Adapty SDK v4.4.0 and higher** row, click **Download**. Repeat with **Download Android Fallback**.

The downloaded files are named `ios_4_4_0_fallback.json` and `android_4_4_0_fallback.json`. Use them in place of your fallback files for SDK 4.1–4.3:

- **Pure React Native project**: Add the iOS file to your Xcode project. Put the Android file in the folder of the Android fallback file for 4.1–4.3, as in [Use fallback paywalls in a pure React Native project](react-native-use-fallback-paywalls-pure).
- **Expo project**: Put each file in the folder of its fallback file for 4.1–4.3, as in [Use fallback paywalls in an Expo project](react-native-use-fallback-paywalls-expo).

Give each file the name that your app passes to `adapty.setFallback`, or update the names in that call. In an Expo project, use these names in the `fallbackFile` option too, and run `npx expo prebuild` again.

With a fallback file for SDK 4.1–4.3, `adapty.setFallback` throws an `AdaptyError`. To verify the new files, run the app on iOS and on Android, and make sure that this call throws no error.

## Flows require iOS 16

Starting from 4.4, flows require iOS 16 or later. On iOS 15, `createFlowView` throws an `AdaptyError` with the `platformNotSupported` code, and `AdaptyFlowView` stays empty and reports the same error. Other SDK features, such as purchases and custom paywalls, still work on iOS 15.

When your app receives this error, show your own content instead, such as a [custom paywall](react-native-implement-paywalls-manually).

## Flow load errors reach onError on iOS

On iOS, when `AdaptyFlowView` can't show its flow, it reports the error to its `onError` handler. Each time your app renders a new `AdaptyFlowView`, it reports the error once. Before 4.4, the component stayed empty. The component reports the following errors:

- On iOS 15: `platformNotSupported`.
- On iOS 16 and later, when the flow fails to load: the error that `createFlowView` throws for that flow. For example, the flow fails to load while AdaptyUI isn't activated, or for a `customLayoutId` that the flow doesn't have.

Your flow error handling now runs in these cases too. The return value of the `onError` handler doesn't close an embedded flow. To close it, stop rendering the component, and show your own content.

## AdaptyUI errors have new codes on iOS

On iOS, a flow or onboarding call throws an error with a new code when AdaptyUI isn't activated: before `adapty.activate()` completes, or after activation with `activateUi: false`. What your app requests determines the code:

- A flow view: `adaptyUINotActivated`.
- An onboarding: `adaptyNotActivated`.

Before 4.4, these errors had the `unknown` code. If your code handles `unknown` for them, handle the new codes too. For `platformNotSupported`, read [Flows require iOS 16](#flows-require-ios-16).

## Flow script errors reach onError on Android

On Android, the flow script can throw an exception while it handles an SDK event. Starting from 4.4, this exception reaches the `onError` handler as `jsException`, the same as on iOS. Before, the SDK only logged it.

The default `onError` handler returns `true`, so a flow from `createFlowView` closes on this error. To keep the flow open, set an `onError` handler that returns `false`, and handle the error there.
