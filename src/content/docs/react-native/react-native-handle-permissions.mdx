A [flow](adapty-flow-builder) can ask users to allow push notifications with the **Request permission** action, for example on an onboarding screen that explains what the notifications are for. The Adapty SDK doesn't show the system dialog itself. It passes the request to the `onRequestPermission` handler in your app. Your app shows the dialog and returns the user's answer, and then the flow continues.

## Before you start

You need:

- **Adapty React Native SDK v4 or later**: The `onRequestPermission` handler doesn't exist in earlier versions.
- **A flow with the Request permission action**: In the Flow & Paywall Builder, add the action to an element's **On Tap** or **On Screen Appear** trigger, and select **Push notifications**. Add the actions that run after the user answers to the **After response** section. See [Actions](onboarding-actions) for how to add actions to triggers.
- **A library that shows the notification dialog**: The example in this guide uses [react-native-permissions](https://github.com/zoontek/react-native-permissions). To set it up, follow its [setup guide](https://github.com/zoontek/react-native-permissions#setup), and add `Notifications` to the iOS permissions it sets up. Any other library that shows the dialog works too, for example `expo-notifications` in an Expo app.
- **The `POST_NOTIFICATIONS` permission in your Android manifest**: Android 13 and later shows the notification dialog only for apps that declare it:

  ```xml title="android/app/src/main/AndroidManifest.xml"
  <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
  ```

## How a flow requests a permission

1. The flow reaches the **Request permission** action: the user taps the element, or the screen opens.
2. The Adapty SDK calls your `onRequestPermission` handler with the permission `push`.
3. Your app shows the system dialog. When the user answers, the handler's promise resolves with `granted` or `denied`.
4. The flow runs the actions in the **After response** section. These actions are the same for both answers.

The flow waits on the screen until your handler returns the answer. If the OS doesn't show the dialog, for example because the user answered it before, the library returns the earlier answer at once. The flow then runs the **After response** actions right away. So when a screen requests the permission on **On Screen Appear** and the **After response** actions open the next screen, a user who answered before sees that screen only for a moment.

With **On Screen Appear**, the flow doesn't send the request again when the user comes back to the screen with a back action. With **On Tap**, each tap sends a new request to your handler.

## Answer the permission request

The `onRequestPermission` handler is asynchronous, unlike the other flow handlers. It returns a promise that resolves to an object with the user's answer. Write the handler once and register it for every flow that requests a permission:

```typescript showLineNumbers title="permissions.ts"
import { requestNotifications } from 'react-native-permissions';
import type { FlowEventHandlers } from 'react-native-adapty';

export const onRequestPermission: FlowEventHandlers['onRequestPermission'] = async (permission) => {
  if (permission !== 'push') {
    // Answer every request: the flow waits on the screen until it gets the answer.
    return { status: 'denied' };
  }

  // Shows the system dialog, or returns the earlier answer without showing it.
  const { status } = await requestNotifications(['alert', 'badge', 'sound']);
  return { status: status === 'granted' ? 'granted' : 'denied' };
};
```

`onRequestPermission` receives:

- **`permission`**: The permission the flow requests. The **Request permission** action sends `push`.
- **`customArgs`**: Custom string arguments of the request. The **Request permission** action sends none, so the object is empty.

The promise resolves to an object with these properties:

- **`status`**: The user's answer: `granted` if the user allowed the permission, and `denied` otherwise.
- **`detail`**: Optional. A string with more information about the answer, such as the status the library returned.

Without an `onRequestPermission` handler, the Adapty SDK answers `denied` and writes a warning to the SDK log. The user sees no dialog, and the flow runs the **After response** actions right away. The SDK also answers `denied` when your handler throws an error or its promise rejects.

:::note
The `onRequestPermission` handler only returns the user's answer to the flow. After the user allows notifications, registering the device for push notifications and sending the device token to your push provider are your app's job.
:::

## Test the permission request

After the user answers the notification dialog, iOS doesn't show it again. Android stops showing it after the user allows notifications, or denies them twice. To see the dialog again while you test the flow, delete the app from the device and install it again.
