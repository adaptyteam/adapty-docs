Follow this recipe to build a virtual currency top-up screen as a flow in your iOS app. The recipe shows how to:

- Show the currency balance in the flow, and keep it current while the flow is open.
- Offer currency packs and a subscription in the flow.
- Offer subscribers a higher-tier subscription.
- Add currency to the balance for a watched ad.
- Retry a spend after a top-up.

Because the top-up screen is a flow, you can change its offers without an app release, and [A/B test](ab-tests) them.

By the end of this recipe, you have a top-up screen for a game. In the game, players tap a button to spend 30 diamonds on an hour of unlimited energy. The finished example works as follows:

## Before you start

- Have players sign in, so that they [keep their balance](virtual-currency-balance#balances-profiles-and-devices) on every device and after a reinstall. When a player signs in, [identify the player](identifying-users) in your app code with a customer user ID. Your backend identifies the player to Adapty by this ID.
- To show the balance in the flow, update your app to Adapty iOS SDK 4.4 or later.
- Set up your app to [fetch](get-pb-paywalls) and [display](ios-present-paywalls) flows.
- Set up a backend that calls the server-side API with your [secret API key](ss-authorization). Keep the key on your backend: anyone with the key can add diamonds to any balance.
- In App Store Connect, create a consumable product for each diamond pack, and two auto-renewable subscriptions for a lower and a higher tier. For the App Store to treat a purchase of the higher tier as an upgrade, put both tiers in one [subscription group](app-store-products). In the group, [rank](https://developer.apple.com/app-store/subscriptions/) the higher tier above the lower tier. Then [add each product to Adapty](create-product).
- [Create a virtual currency](create-virtual-currency) with the code `DIAMONDS`. [Link](create-virtual-currency#link-products) each product to `DIAMONDS`, and set how many diamonds Adapty adds to the balance:
  - **Diamond pack**: The **Credit amount**, for each purchase.
  - **Subscription tier**: The **Credit per cycle**, for each billing period. When a player starts a free trial, Adapty only adds the **Credit on trial start**.

  Set each of the three values to at least 30 diamonds, the price of the energy. With these values, every purchase in the flow covers the missing diamonds.

## 2. Create the balance view

Create a model for the diamond balance, and a SwiftUI view for the custom element. The code in steps 3 and 5 sets the balance in the model from the responses of your backend. The view observes the model, so it redraws when the balance changes:

```swift showLineNumbers title="Swift"
import Combine
import SwiftUI

// The diamond balance that your app keeps up to date
@MainActor
final class DiamondWallet: ObservableObject {
    @Published var balance: Int? // nil until your backend returns a balance
}

struct DiamondBalanceView: View {
    @ObservedObject var wallet: DiamondWallet

    var body: some View {
        Label(wallet.balance?.formatted() ?? "—", systemImage: "diamond.fill")
    }
}
```

`DiamondBalanceView` uses the system text color, which turns white when the device is in dark mode. A flow keeps its light colors unless you [add a dark theme](paywall-dark-mode#add-a-dark-theme) to it. If your flow has no dark theme, set a fixed text color in the view, such as `.foregroundStyle(.black)`.

To display the view in the custom element, return it from your [app-wide resolver](ios-flow-custom-elements#set-an-app-wide-resolver), which matches each custom element to a view by its Type and ID. Add a `wallet` property of the `DiamondWallet` type, and a case that returns `DiamondBalanceView` for the `currency_balance` Type and the `diamonds` ID. The highlighted lines show what to add. If your app has no app-wide resolver yet, copy the whole code:

```swift showLineNumbers title="Swift" {5,13-14}
import AdaptyUIBuilder
import SwiftUI

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    let wallet: DiamondWallet

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "currency_balance" where id == "diamonds":
            return AnyView(DiamondBalanceView(wallet: wallet))
        // the other cases of your resolver
        default:
            return nil
        }
    }
}
```

Create the resolver with a `DiamondWallet`, and set it as the app-wide resolver. Call `AdaptyUI.setCustomElementsResolver(_:)` once, such as at app launch:

```swift showLineNumbers title="Swift"
import AdaptyUI

@MainActor let diamondWallet = DiamondWallet()

// keep this instance: a resolver for one flow can reuse it
@MainActor let customElementsResolver = CustomElementsResolver(wallet: diamondWallet)

// at app launch, such as in application(_:didFinishLaunchingWithOptions:)
AdaptyUI.setCustomElementsResolver(customElementsResolver)
```

## 3. Open the flow when a player doesn't have enough diamonds

### Open the flow from your app code

Add the following UIKit code to the view controller that shows the unlimited energy button. When a player taps the button, call `spendDiamondsOnEnergy` to spend 30 diamonds through your backend. If your backend returns how many diamonds the player needs, `openOutOfDiamondsFlow` passes this number to the `diamonds_needed` tag, and opens the flow:

```swift showLineNumbers title="Swift"
private var pendingSpendKey: UUID? // kept until the spend goes through: a retry reuses it
private var requiredBalance = 0 // the balance that covers the spend, from the last failed spend
private var isSpending = false

// openFlow: false for the retry after a top-up (step 4)
func spendDiamondsOnEnergy(openFlow: Bool = true) async {
    guard !isSpending else { return } // ignore repeat taps while a spend runs
    isSpending = true
    defer { isSpending = false }
    let spendKey = pendingSpendKey ?? UUID() // UUID() creates a version 4 UUID
    pendingSpendKey = spendKey
    do {
        // the client of your backend: your backend sends the spend to Adapty
        let result = try await GameBackend.shared.spendDiamonds(
            on: "unlimited_energy",
            idempotencyKey: spendKey
        )
        switch result {
        case let .spent(balance):
            pendingSpendKey = nil
            diamondWallet.balance = balance
            // your backend granted the energy: show it
        case let .insufficientBalance(diamondsNeeded, balance):
            diamondWallet.balance = balance
            requiredBalance = balance + diamondsNeeded
            guard openFlow else { return } // the diamonds are late: tell the player in your UI
            await openOutOfDiamondsFlow(diamondsNeeded: diamondsNeeded)
        }
    } catch {
        // handle the error
    }
}

func openOutOfDiamondsFlow(diamondsNeeded: Int) async {
    // with no value, players see the Initial value of the tag
    let tags = diamondsNeeded > 0 ? ["diamonds_needed": diamondsNeeded.formatted()] : [:]
    do {
        let flow = try await Adapty.getFlow(placementId: "out_of_diamonds")
        let flowConfiguration = try await AdaptyUI.getFlowConfiguration(
            forFlow: flow,
            tagResolver: tags
        )
        let flowController = try AdaptyUI.flowController(
            with: flowConfiguration,
            delegate: self
        )
        present(flowController, animated: true)
    } catch {
        // handle the error
    }
}
```

As the delegate of the flow, the view controller must also implement the [delegate methods](ios-handling-events#handling-events-in-uikit) for purchases and restores. For `didFinishPurchase`, use the code from [step 4](#4-retry-the-spend-after-a-purchase).

In SwiftUI, present the flow configuration with the `.flow` modifier, and use its closures instead of the delegate methods. The closures receive no view controller. To close the flow, set `isPresented` to `false`. To present a rewarded ad over the flow, pass your ad SDK the topmost view controller.

To show the upgrade copy to a new subscriber of the lower tier the next time the flow opens, keep the default `fetchPolicy` of `getFlow`. A cache-first policy, such as `.returnCacheDataElseLoad`, can return the original flow from the cache.

## 4. Retry the spend after a purchase

When a player buys a pack or a subscription in the flow, Adapty usually adds the diamonds to the balance first. Then the Adapty SDK calls `didFinishPurchase`, but doesn't close the flow. To give the player the energy without a second tap, the following code closes the flow and retries the spend:

```swift showLineNumbers title="Swift"
func flowController(
    _ controller: AdaptyFlowController,
    didFinishPurchase product: AdaptyPaywallProduct,
    purchaseResult: AdaptyPurchaseResult
) {
    // canceled or pending: the flow stays open
    guard purchaseResult.isPurchaseSuccess else { return }
    closeFlowAndRetrySpend(controller)
}

func closeFlowAndRetrySpend(_ controller: AdaptyFlowController) {
    controller.dismiss(animated: true) {
        Task { await self.spendDiamondsOnEnergy(openFlow: false) } // with the kept key
    }
}
```

The Adapty SDK also calls `didFinishPurchase` when the player cancels the purchase, or when the purchase is pending. In both cases, the balance stays the same, so the code leaves the flow open.

If the Adapty SDK can't validate the purchase with Adapty right away, it still reports a successful purchase. The retry then fails: Adapty adds the diamonds later, when the App Store notifies Adapty of the purchase. For this retry, the code doesn't open the flow again. Tell the player in your own UI that the diamonds are on the way.

Don't add diamonds from your backend for a purchase of a [linked product](create-virtual-currency#link-products): Adapty adds these diamonds, and the player would receive them twice.

## 5. Add diamonds for a watched ad

When a player taps the ad button, your app code receives the action ID `watch_ad`. A custom action doesn't close the flow. Your app code then asks your ad SDK to present a rewarded ad over the flow. When the ad closes, the player sees the flow again.

<VcTopUpRewardCredit />

Until your backend returns the balance, the following code ignores more taps on the ad button. Then it sets the balance in `diamondWallet`, and players see the new balance in the open flow. If the balance now covers the spend, the code closes the flow and retries the spend.

Your `flowController(_:didPerform:)` method replaces the default handling of all actions. To keep the close button and links working, include the `.close` and `.openURL` cases. Put `import SafariServices` at the top of the file, and the rest of the code inside the view controller.

```swift showLineNumbers title="Swift"
import SafariServices

private var isWatchingAd = false

func flowController(
    _ controller: AdaptyFlowController,
    didPerform action: AdaptyUI.Action
) {
    switch action {
    case .close:
        controller.dismiss(animated: true)
    case let .openURL(url, presentation) where presentation == .inAppBrowser:
        controller.present(SFSafariViewController(url: url), animated: true)
    case let .openURL(url, _):
        UIApplication.shared.open(url)
    case let .custom(id, _) where id == "watch_ad":
        guard !isWatchingAd else { return } // ignore repeat taps until your backend returns the balance
        isWatchingAd = true
        Task {
            defer { isWatchingAd = false }
            // your ad SDK: returns after the ad closes, true if the player earned the reward
            guard await AdNetwork.shared.showRewardedAd(from: controller) else {
                return // no ad to show, or no reward: tell the player, such as in an alert
            }
            do {
                // your backend returns the balance after the server of your ad network confirms the reward
                let balance = try await GameBackend.shared.balanceAfterAdReward()
                diamondWallet.balance = balance
                if balance >= requiredBalance { closeFlowAndRetrySpend(controller) }
            } catch {
                // handle the error
            }
        }
    default:
        break
    }
}
```

If your ad SDK presents the ad with the `.fullScreen` presentation style, the ad covers the flow. The Adapty SDK then calls `flowControllerDidDisappear`, and calls `flowControllerDidAppear` after the ad closes. To detect that the player closed the flow, use the `.close` action, not `flowControllerDidDisappear`.

## 6. Test on a device

The Flow & Paywall Builder can't run your app code, so its canvas only shows the fallback of the custom element.

To see the diamonds from purchases, test with a [sandbox account](test-purchases-in-sandbox). In the sandbox, a subscription renews every few minutes, and Adapty adds diamonds at each renewal. With a StoreKit configuration file in Xcode, the Adapty SDK doesn't validate purchases with Adapty, and Adapty adds no diamonds.

To test the recipe:

1. [Publish the flow and its copies](builder-save-publish). To see the latest published versions instead of cached ones, register the device as a [test device](test-devices).
2. Run your app with the recipe code, and sign in as a player with no diamonds. Tap the unlimited energy button. Verify that the flow opens with the text "You need 30 more diamonds" and a balance of 0.
3. Tap the ad button, and watch the ad. Verify that the balance in the open flow grows by 5.
4. Buy a diamond pack. Verify that the flow closes and the player receives the energy.
5. In the Adapty Dashboard, open the profile of the player. [Debit the balance](virtual-currency-balance#adjust-a-balance-manually) to less than 30 with the **Adjustment** operation. Tap the unlimited energy button, and buy the lower tier.
6. Debit the balance to less than 30 again. Tap the unlimited energy button. Verify that the flow opens with the purchase button of the higher tier and no list of subscription tiers.
7. Buy the higher tier. In the [event history](virtual-currency-balance#review-balance-changes-in-the-event-history) of the profile, verify that Adapty added the full **Credit per cycle** of the higher tier.

To find out why the fallback appears instead of the balance, follow the [steps to test custom elements](ios-flow-custom-elements#test-on-a-device).
