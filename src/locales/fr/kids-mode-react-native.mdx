Si votre application React Native est destinée aux enfants, vous devez respecter les politiques d'[Apple](https://developer.apple.com/kids/) et de [Google](https://support.google.com/googleplay/android-developer/answer/9893335). Si vous utilisez le SDK Adapty, quelques étapes simples vous permettront de le configurer pour satisfaire ces politiques et réussir les validations des stores.

:::important
Sur iOS, le mode Enfants est activé via le trait Swift package `KidsMode`, qui supprime à la compilation tout le code IDFA, AdSupport et AppTrackingTransparency. Il nécessite le SDK v4 et **Xcode 26** ou une version ultérieure. La façon d'appliquer le trait dépend du gestionnaire de packages utilisé par votre projet iOS — voir [Mises à jour dans votre projet iOS](#updates-in-your-ios-project).
:::

## Qu'est-ce qui est requis ? \{#whats-required\}

Vous devez configurer le SDK pour désactiver la collecte des éléments suivants :

- [IDFA (Identifier for Advertisers)](https://en.wikipedia.org/wiki/Identifier_for_Advertisers) (iOS)
- [Android Advertising ID (AAID/GAID)](https://support.google.com/googleplay/android-developer/answer/6048248) (Android)
- [Adresse IP](https://www.ftc.gov/system/files/ftc_gov/pdf/p235402_coppa_application.pdf)

De plus, nous vous recommandons d'utiliser l'identifiant utilisateur client avec précaution. Un identifiant au format `<FirstName.LastName>` sera clairement considéré comme une collecte de données personnelles, tout comme l'utilisation d'une adresse e-mail. Pour le Mode Enfants, la bonne pratique consiste à utiliser des identifiants aléatoires ou anonymisés (par exemple, des identifiants hachés ou des UUID générés par l'appareil) afin de garantir la conformité.

## Activer le mode enfant \{#enabling-kids-mode\}

### Mises à jour dans l'Adapty Dashboard

Dans l'Adapty Dashboard, vous devez désactiver la collecte des adresses IP. Pour ce faire, accédez à [App settings](https://app.adapty.io/settings/general) et cliquez sur **Disable IP address collection** sous **Collect users' IP address**.

### Mises à jour dans le code de votre application mobile

Pour respecter les politiques en vigueur, désactivez la collecte de l'IDFA de l'utilisateur (iOS), du GAID/AAID (Android) et de l'adresse IP lors de l'activation du SDK Adapty :

```typescript showLineNumbers title="App.tsx"

adapty.activate('YOUR_PUBLIC_SDK_KEY', {
  // Disable IP address collection
  ipAddressCollectionDisabled: true,

  // Disable IDFA collection on iOS
  ios: {
    idfaCollectionDisabled: true,
  },

  // Disable Google Advertising ID collection on Android
  android: {
    adIdCollectionDisabled: true,
  },
});
```

### Mises à jour dans votre projet iOS

Pour la catégorie Kids de l'App Store (ou conformité COPPA), le SDK iOS natif doit être compilé avec le trait Swift Package `KidsMode`, qui exclut tout le code lié à l'IDFA, AdSupport et AppTrackingTransparency. Cette étape nécessite **Xcode 26** ou une version ultérieure.

Swift Package Manager ne peut pas transmettre les traits de package via aucun des deux chemins d'intégration, c'est pourquoi le SDK Adapty React Native fournit un outil qui applique le trait à votre place. Choisissez celui qui correspond à la configuration de votre projet iOS, comme décrit dans [Installer le SDK Adapty](sdk-installation-react-native-pure#install-adapty-sdk).

<Tabs groupId="ios-package-manager" queryString>

<TabItem value="cocoapods" label="CocoaPods" default>

Le SDK inclut un helper Podfile. Dans `ios/Podfile`, importez le helper et appelez-le **après** `react_native_post_install` :

```ruby showLineNumbers title="ios/Podfile"
require Pod::Executable.execute_command('node', ['-p',
  'require.resolve(
    "react-native-adapty/ios/adapty_kids_mode.rb",
    {paths: [process.argv[1]]},
  )', __dir__]).strip

# ...

post_install do |installer|
  react_native_post_install(
    installer,
    config[:reactNativePath],
    :mac_catalyst_enabled => false
  )

  adapty_enable_kids_mode(installer)
end
```

Puis exécutez `pod install` :

```sh showLineNumbers title="Shell"
cd ios && pod install
```

Conservez l'appel à l'helper dans `post_install` de façon permanente — React Native recrée les références de package Swift à chaque `pod install`, et l'helper réapplique le trait à chaque fois.

</TabItem>

<TabItem value="spm" label="Swift Package Manager (experimental)">

Le SDK fournit la commande `adapty-spm-kids-mode`. Exécutez-la comme hook postinstall dans le `package.json` de votre application :

```json showLineNumbers title="package.json"
{
  "scripts": {
    "postinstall": "adapty-spm-kids-mode enable"
  }
}
```

Ensuite, réinstallez vos dépendances pour exécuter le hook pour la première fois :

```sh showLineNumbers title="Shell"
npm install

# or using yarn
yarn install
```

Le hook doit rester dans `package.json` de façon permanente. L'autolinking de Swift Package Manager de React Native ne tient pas compte des traits de package et régénère le package agrégateur à chaque synchronisation. La commande active donc le trait dans le manifeste propre du SDK dans `node_modules` — remplacé à chaque installation.

Après avoir activé ou désactivé le mode Kids, videz le dossier de build avant la prochaine compilation iOS (**Product → Clean Build Folder** dans Xcode).

:::note
`adapty-spm-kids-mode enable` affiche un avertissement, sans faire échouer l'installation, lorsqu'il ne peut pas confirmer une intégration Swift Package Manager ou détecte une app CocoaPods — React Native ne lit pas de `Package.swift`, donc le paramètre n'a aucun effet. Si votre projet iOS se trouve en dehors du répertoire depuis lequel vous installez, passez `--app-root=path/to/app`.
:::

Pour désactiver Kids Mode, remplacez le hook par `adapty-spm-kids-mode disable`.

</TabItem>

</Tabs>

Pour confirmer que Kids Mode est actif, vérifiez que la ligne de log `adapty.activate(...)` indique `kids_mode_enabled: true`.

### Mises à jour dans votre manifeste Android \{#updates-in-your-android-manifest\}

:::note
Si votre application cible **uniquement** les enfants et compile contre Android 13 (API 33) ou supérieur, Google Play exige que vous ne demandiez pas la permission `AD_ID`. Un autre SDK de votre application (analytics, attribution ou publicité) peut ajouter cette permission via la fusion de manifestes. Définir `adIdCollectionDisabled` empêche Adapty de collecter l'identifiant, mais cela ne supprime pas une permission déclarée par un autre SDK.
:::

Pour supprimer la permission, ajoutez ce qui suit à l'intérieur de l'élément `<manifest>` du fichier `android/app/src/main/AndroidManifest.xml`. L'élément `<manifest>` doit déclarer `xmlns:tools="http://schemas.android.com/tools"`.

```xml showLineNumbers title="AndroidManifest.xml"
<uses-permission
    android:name="com.google.android.gms.permission.AD_ID"
    tools:node="remove" />
```
