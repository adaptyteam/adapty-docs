Bienvenue ! Nous sommes là pour rendre vos achats intégrés aussi simples que possible 🚀

Nous avons conçu le SDK Adapty pour Android afin de vous décharger de la gestion des achats intégrés, pour que vous puissiez vous concentrer sur ce que vous faites de mieux : créer des applications exceptionnelles. Voici ce que nous prenons en charge pour vous :

- Gestion des achats, validation des reçus et gestion des abonnements sans configuration
- Créer et tester des flows & paywalls sans mettre à jour l'application
- Obtenez des analyses d'achats détaillées sans aucune configuration — cohortes, LTV, taux de désabonnement et analyse d'entonnoir inclus
- Gardez le statut d'abonnement de l'utilisateur toujours à jour entre les sessions et les appareils
- Intégrez votre application aux services d'attribution marketing et d'analytique en une seule ligne de code

:::note
Avant de plonger dans le code, vous devez intégrer Adapty avec Google Play Console et configurer les produits dans le tableau de bord. Consultez notre [guide de démarrage rapide](quickstart) pour tout configurer d'abord.
:::

## Concepts clés \{#main-concepts\}

Avant de plonger dans le code, familiarisons-nous avec les concepts clés qui font fonctionner Adapty.

L'approche d'Adapty a ceci d'élégant : seuls les placements sont codés en dur dans votre app. Tout le reste – produits, designs de paywall, tarifs et offres – peut être géré librement depuis l'Adapty Dashboard sans mise à jour de l'app :

1. [**Produit**](product) - Tout ce qui peut être acheté dans votre app – abonnement, produit consommable ou accès à vie.

2. **Flows & paywalls** - Produits regroupés avec une configuration, attachés à un placement. Deux façons de les créer, comparées dans [Flows & paywalls](flows-and-paywalls) :
   - **[Flow & Paywall Builder](adapty-flow-builder)** - Interface visuelle sans code. Adapty affiche l'UI et gère l'achat pour vous.
   - **[Paywalls personnalisés](paywalls)** - Pas de configuration visuelle ; vous construisez l'UI dans votre propre code et appelez `makePurchase` vous-même. Voir [Implémenter des paywalls personnalisés](android-quickstart-manual).

   Dans le code SDK, les deux sont récupérés via la même méthode `getFlow`.

3. [**Placement**](placements) - Un point stratégique dans le parcours utilisateur où vous souhaitez afficher un flow ou un paywall. Les placements représentent le « où » et le « quand » de votre stratégie de monétisation. Les placements courants incluent :
   - `main` - L'emplacement principal de votre paywall
   - `onboarding` - Affiché pendant le flow d'onboarding utilisateur
   - `settings` - Accessible depuis les paramètres de votre application

   Commencez par les bases comme `main` ou `onboarding` pour votre première intégration, puis [réfléchissez aux autres endroits de votre application où les utilisateurs pourraient être prêts à acheter](choose-meaningful-placements).

4. [**Profil**](profiles-crm) - Lorsqu'un utilisateur achète un produit, son profil se voit attribuer un **niveau d'accès** que vous utilisez pour définir l'accès aux fonctionnalités payantes.
