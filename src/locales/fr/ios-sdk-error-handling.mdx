Le SDK Adapty dispose de son propre wrapper pour tous les types d'erreurs, appelé `AdaptyError`. En pratique, toute erreur retournée par un SDK est une `AdaptyError`. Elle possède deux propriétés utiles : `originalError` et `adaptyErrorCode`, décrites ci-dessous.

**originalError** contient l'erreur d'origine au cas où vous en auriez besoin. Il peut s'agir d'une [SKError](https://developer.apple.com/documentation/storekit/skerror), d'une [NSError](https://developer.apple.com/documentation/foundation/nserror) ou d'une [Error](https://developer.apple.com/documentation/swift/error) Swift générique. Cette propriété est optionnelle, car certaines erreurs peuvent être générées directement par le SDK — par exemple en cas de données incohérentes ou manquantes — et n'auront pas d'erreur d'origine autour de laquelle le wrapper a été construit.

**adaptyErrorCode** peut être utilisé pour gérer les problèmes courants, comme :

- identifiants invalides
- erreurs réseau
- paiements annulés
- problèmes de facturation
- reçu invalide
- et bien plus encore

Il est assez facile de vérifier le code d'erreur et d'y réagir en conséquence.

```swift showLineNumbers title="Swift"
do {
    let info = try await Adapty.makePurchase(product: product)
} catch {
    if error.adaptyErrorCode == .paymentCancelled {
        // purchase was cancelled
        // you can offer discount to your user or remind them later
    }
}
```

:::tip
**Activez les logs verbeux avant de déboguer.** La plupart des `AdaptyError`s encapsulent une erreur StoreKit, réseau ou backend sous-jacente. Avec les logs verbeux activés (`Adapty.logLevel = .verbose` — voir [Logging](sdk-installation-ios#logging)), cette erreur encapsulée est affichée dans la console, ce qui révèle généralement la cause réelle. La propriété `originalError` est renseignée quel que soit le niveau de log — les logs verbeux la font simplement apparaître dans la console.
:::

Si ces solutions ne résolvent pas votre problème, consultez [Autres problèmes](#other-issues) pour connaître les étapes à suivre avant de contacter le support afin de nous aider à vous assister plus efficacement.

## Erreurs réseau \{#network-errors\}

| Erreur          | Code | Solution                                                                                                                                                                                                     |
| :------------- | :--- |:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| notActivated   | 2002 | Le SDK Adapty n'est pas activé. <br/> Se produit le plus souvent quand un écran de démarrage ou un hook UI précoce appelle des méthodes Adapty avant que `Adapty.activate` ne se termine. Le symptôme est intermittent et peut ne pas se reproduire sur simulateur car le timing diffère sur un appareil réel. Attendez le handler de complétion ou le résultat async d'`activate` avant de planifier tout autre appel SDK. Consultez [Ordre d'appel dans le SDK iOS](ios-sdk-call-order) pour la séquence complète. |
| badRequest     | 2003 | Requête incorrecte. <br/> Avec `getPaywall`, cela signifie le plus souvent que le placement demandé n'existe pas dans l'app associée à votre clé API. Vérifiez que l'ID de placement est copié exactement et que la clé API et le placement proviennent de la même app dans l'Adapty Dashboard. |
| serverError    | 2004 | Erreur serveur. <br/> Réessayez après quelques instants. Si le problème persiste, contactez l'équipe support Adapty. <br/> Ce code couvre également le throttling : si vous appelez le même endpoint trop fréquemment (par exemple, des mises à jour de profil répétées), le serveur répond avec un 429 et le SDK bloque cet endpoint jusqu'à l'expiration de l'intervalle de réessai. |
| networkFailed  | 2005 | Cette erreur indique des problèmes de connexion réseau sur l'appareil de l'utilisateur. <br/> Essayez de désactiver le VPN ou de passer du réseau cellulaire au Wi-Fi, ou inversement.                                             |
| decodingFailed | 2006 | Cette erreur indique que le décodage de la réponse a échoué — le SDK a reçu des données qu'il ne peut pas analyser. <br/> Si elle survient lors du chargement d'un fichier [de secours](fallback-paywalls) local, le fichier est plus ancien que ce qu'attend le SDK : téléchargez un nouveau fichier depuis la page **Placements**. Un décalage de version du paywall de secours peut également se manifester sous la forme de l'erreur 3001. |
| encodingFailed | 2009 | Cette erreur indique que l'encodage de la requête a échoué.                                                                                                                                                           |

## Autres problèmes \{#other-issues\}

Si vous n'avez pas encore trouvé de solution, voici quelques pistes à explorer :

- **Mettre à jour le SDK vers la dernière version** : nous recommandons toujours de mettre à jour vers les dernières versions du SDK, car elles sont plus stables et incluent des correctifs pour les problèmes connus.
- **Contacter l'équipe support ou obtenir de l'aide auprès d'autres développeurs** dans le [forum de support](https://adapty.featurebase.app/).
- **Contacter l'équipe support via [support@adapty.io](mailto:support@adapty.io) ou via le chat** : si vous n'êtes pas prêt à mettre à jour le SDK ou que cela n'a pas résolu le problème, contactez notre équipe support. Notez que votre problème sera résolu plus rapidement si vous [activez la journalisation verbose](sdk-installation-ios#logging) et partagez les logs avec l'équipe. Vous pouvez également joindre des extraits de code pertinents.
