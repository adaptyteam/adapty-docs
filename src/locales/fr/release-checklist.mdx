Parcourez cette liste de vérification avant de publier, afin de confirmer que le flow de monétisation fonctionne de bout en bout dans une version réelle.

## Prérequis essentiels \{#pre-flight-essentials\}

Ce dont vous avez besoin avant de commencer la validation :

- Un vrai appareil avec un compte sandbox

- L'accès à l'Adapty Dashboard

- L'accès à App Store Connect / Google Play Console

:::note
Les achats sandbox peuvent s'effectuer sur des simulateurs, mais un vrai appareil est nécessaire pour tester tous les flows dans leur intégralité, notamment les dialogues de paiement et les invites biométriques.
:::

## Validations universelles \{#universal-validations\}

- [ ] **Connexion au store** : Assurez-vous d'avoir connecté Adapty à l'App Store et/ou Google Play :
    - [ ] [App Store](initial_ios)
    - [ ] [Google Play](initial-android)
- [ ] **Transmission des événements d'abonnement** : Confirmez que les notifications serveur sont configurées :
    - [ ] [Notifications serveur App Store](enable-app-store-server-notifications)
    - [ ] [Notifications développeur en temps réel (RTDN)](enable-real-time-developer-notifications-rtdn)
- [ ] **Identification du profil** : Validez la logique d'identification des utilisateurs et assurez-vous que les achats sont associés au bon profil :
    - [ ] [Vérifiez que la logique d'identification dans votre code correspond à votre cas d'usage](ios-quickstart-identify)
    - [ ] [Assurez-vous de comprendre la logique parent/héritier pour le partage de l'accès payant entre profils utilisateur](sharing-paid-access-between-user-accounts)
- [ ] **Offres** : Si vous avez des offres promotionnelles App Store dans l'application, vérifiez que vous avez [ajouté votre clé d'achat intégré](app-store-connection-configuration#step-4-for-trials-and-special-offers--set-up-promotional-offers) à la fois dans le champ principal et dans la section **App Store promotional offers**.
- [ ] **Collecte de données** : Assurez la conformité en matière de confidentialité :
    - [ ] Si vous devez vous conformer à des réglementations comme le RGPD ou le CCPA, ou si votre application est destinée aux enfants, contrôlez si vous [activez la collecte et le partage de l'IDFA et de l'adresse IP](sdk-installation-ios#data-policies).
    - [ ] Si votre application utilise AppTrackingTransparency, assurez-vous d'[envoyer le statut d'autorisation à Adapty](ios-deal-with-att).
- [ ] **Étiquettes de confidentialité** : [En savoir plus](apple-app-privacy) sur les données collectées par Adapty et les indicateurs à renseigner lors d'une révision.

## Validation des achats \{#purchase-validations\}

<SupportForum />

Avant de passer en production, vérifiez que les achats dans votre application fonctionnent correctement et que votre paywall est prêt pour la revue du store.

La façon de valider les achats intégrés dépend de la manière dont vous les avez implémentés :

- Vous affichez un paywall créé dans le Adapty Paywall Builder
- Vous avez implémenté votre propre paywall et utilisez la méthode `makePurchase` pour gérer les achats
- Vous utilisez Adapty en mode observateur (que ce soit avec le Adapty Paywall Builder ou votre paywall personnalisé)

<Tabs groupId="paywall" queryString>
<TabItem value="builder" label="Adapty Paywall Builder" default>

**Objectif** : Adapty affiche le paywall, les utilisateurs peuvent acheter des produits, l'accès se déverrouille et le flow de restauration fonctionne.

- [ ] Votre application [affiche le paywall](ios-present-paywalls) depuis le même placement que vous allez déployer.
    - [ ] Le paywall s'affiche à l'écran. Si le chargement prend trop de temps (par exemple, si vous ou vos utilisateurs êtes sur une connexion instable), pensez à [ajuster votre politique de récupération](get-pb-paywalls#fetch-paywall-designed-with-paywall-builder).
    - [ ] Le paywall correspond à la variante attendue (audience/locale le cas échéant). Vous pouvez [modifier la priorité de l'audience](change-audience-priority) si nécessaire.
- [ ] Les produits et les prix s'affichent sur le paywall. Notez que l'API d'Apple peut parfois fournir des prix inexacts lors des tests (notamment avec différentes configurations de région) ; privilégiez donc le test du flux d'achat plutôt que l'exactitude des prix, car Adapty n'a aucune influence sur les prix du Store.
- [ ] L'achat en sandbox se termine avec succès. Le callback d'achat réussi est bien reçu.
- [ ] L'accès est débloqué et persiste. Vérifiez que [l'accès payant est accordé en fonction du profil Adapty actuel](ios-check-subscription-status#connect-profile-with-paywall-logic).
    - [ ] Après l'achat, le profil Adapty dispose d'un niveau d'accès actif.
    - [ ] Les fonctionnalités payantes se débloquent lorsque le profil contient ce niveau d'accès (et pas uniquement lors du callback d'achat).
- [ ] La restauration des achats fonctionne. Lorsque vous réinstallez l'application ou l'installez sur un nouvel appareil, la restauration automatique des achats fonctionne conformément au paramètre [Partage de l'accès payant](sharing-paid-access-between-user-accounts). Si vous n'avez pas d'authentification backend, les achats sont restaurés automatiquement quel que soit le paramètre. Dans les autres cas, assurez-vous que les utilisateurs peuvent restaurer leurs achats après une réinstallation.
- [ ] Exigences pour la validation par le Store :
    - [ ] Le bouton **Restore purchases** est présent sur le paywall. Vous pouvez l'ajouter dans le Paywall Builder, et il traitera automatiquement les restaurations d'achats lorsqu'on appuie dessus.
    - [ ] Les Conditions d'utilisation et la Politique de confidentialité sont accessibles depuis l'écran du paywall, et cliquer sur ces liens les ouvre dans un navigateur.

</TabItem>
<TabItem value="makepurchase" label="Custom paywall (makePurchase)" default>

**Objectif** : Vous gérez l'affichage de l'interface ; Adapty s'occupe des achats, des mises à jour de profil et des restaurations.

- [ ] Les IDs des produits ne sont pas codés en dur dans votre code. Vous codez en dur uniquement les IDs de [placement](placements).
- [ ] Votre application [récupère les produits](fetch-paywalls-and-products) depuis le même placement que vous allez déployer.
    - [ ] La liste des produits se charge correctement. Si le chargement prend trop de temps (par exemple, si vous ou vos utilisateurs avez une connexion instable), envisagez d'[ajuster votre politique de récupération](fetch-paywalls-and-products#fetch-paywall-information).
    - [ ] Les produits récupérés correspondent à la variante attendue (audience/locale si applicable). Vous pouvez [modifier la priorité d'audience](change-audience-priority) si nécessaire.
- [ ] Les produits et les prix apparaissent sur le paywall. Notez que l'API d'Apple peut parfois fournir des prix inexacts lors des tests (notamment avec différentes configurations de région), il est donc préférable de tester le bon fonctionnement du flux d'achat plutôt que l'exactitude des prix, car Adapty n'affecte pas les prix du Store.
- [ ] L'achat en sandbox avec [makePurchase](making-purchases) s'effectue correctement :
    - [ ] Le résultat d'un achat réussi est bien géré.
    - [ ] Les résultats en attente, échoués ou annulés sont gérés correctement.
- [ ] Si vous [utilisez un Remote Config](present-remote-config-paywalls), ses valeurs sont bien transmises à votre paywall.
- [ ] Lorsqu'un paywall est affiché, la méthode [`logShowFlow` (iOS SDK v4+) / `logShowPaywall`](present-remote-config-paywalls#track-paywall-view-events) est appelée.
- [ ] L'achat en sandbox s'effectue correctement. Le callback d'achat réussi est bien reçu.
- [ ] L'accès est déverrouillé et persiste. Vérifiez que [l'accès payant est accordé en fonction du profil Adapty actuel](ios-check-subscription-status#connect-profile-with-paywall-logic).
    - [ ] Après l'achat, le profil Adapty dispose d'un niveau d'accès actif.
    - [ ] Les fonctionnalités payantes se déverrouillent lorsque le profil contient ce niveau d'accès (pas uniquement lors du callback d'achat).
- [ ] La restauration des achats fonctionne. Lorsque vous réinstallez l'application ou l'installez sur un nouvel appareil, la restauration automatique des achats fonctionne conformément au paramètre [Partage de l'accès payant](sharing-paid-access-between-user-accounts). Si vous n'avez pas d'authentification backend, les achats sont restaurés automatiquement quel que soit ce paramètre. Dans les autres cas, assurez-vous que les utilisateurs peuvent restaurer leurs achats après avoir réinstallé l'application.
- [ ] Exigences de la revue du Store :
    - [ ] Le bouton **Restore purchases** est accessible et [gère les restaurations](restore-purchase).
    - [ ] Les Conditions d'utilisation et la Politique de confidentialité sont accessibles depuis l'écran du paywall, et cliquer sur ces liens les ouvre dans un navigateur.

</TabItem>
<TabItem value="observer" label="Mode observateur">

**Objectif** : Vous gérez vous-même les achats, les mises à jour de profil et les restaurations ; Adapty reçoit les rapports de transactions.

- [ ] **Votre app complète les achats avec votre propre flow d'achat** (StoreKit / BillingClient / backend) :
    - [ ] L'achat sandbox réussit dans l'interface du store.
    - [ ] Les résultats en attente/échoués/annulés sont gérés correctement dans votre app.
- [ ] **Les transactions sont signalées à Adapty**.
    - [ ] Le mode observateur est [activé dans le code de votre app](implement-observer-mode).
    - [ ] L'achat apparaît dans l'Event Feed d'Adapty.
    - [ ] Les renouvellements, annulations et remboursements sont reflétés au fil du temps (le cas échéant).
- [ ] **Les vues de paywall sont suivies**. La [méthode `logShowFlow` (iOS SDK v4+) / `logShowPaywall`](present-remote-config-paywalls#track-paywall-view-events) est appelée lors de l'affichage d'un paywall.
- [ ] **La restauration des achats fonctionne pour votre implémentation**. La réinstallation de l'app ou le changement d'appareil restaure l'accès correctement.
- [ ] **Exigences de révision du store** :
    - [ ] L'action **Restore purchases** est accessible et déclenche votre flow de restauration.
    - [ ] Les conditions d'utilisation et la politique de confidentialité sont accessibles depuis le paywall ou l'écran d'achat et s'ouvrent dans un navigateur.
</TabItem>
