Une condition dans le Flow & Paywall Builder peut évaluer l'[état](builder-element-states) d'un autre élément sur le même écran. Par exemple, afficher le message « Acceptez les conditions pour continuer » uniquement si le bouton **Continuer** est **Désactivé**.

Les conditions suivantes permettent d'évaluer l'état des éléments :

- [Visibilité conditionnelle](onboarding-element-visibility) : afficher ou masquer un élément.
- La condition d'un [état **Disabled**](builder-element-states#add-the-disabled-state) : désactiver un élément.
- La condition d'un [état personnalisé](builder-element-states#add-a-custom-state) : modifier l'apparence d'un élément.
- [Texte conditionnel](onboarding-text#add-conditional-text) : remplacer le texte d'un élément texte.
- [Actions conditionnelles](onboarding-actions#conditional-actions) : choisir les actions déclenchées par un événement.

Pour les états **Disabled**, **Active** et **custom**, vous ne pouvez utiliser que l'onglet **States** du champ **Variable**. Pour ce que les utilisateurs ont sélectionné ou saisi, comme une réponse à un quiz, utilisez une [variable](onboarding-variables#element-variables) dans l'onglet **Elements**.

## Ajouter un état d'élément à une condition \{#add-an-element-state-to-a-condition\}

Les étapes sont identiques pour les cinq types de conditions :

1. Dans la condition, cliquez sur le champ **Variable**.
2. Ouvrez l'onglet **States**, puis cliquez sur la ligne de l'élément à utiliser dans la condition. Chaque ligne affiche le nom du calque et, s'il diffère, le texte de l'élément. Pour trouver un élément sur le canvas, survolez sa ligne. Dans l'onglet **States**, vous ne pouvez sélectionner que des [éléments avec des états](#which-elements-and-states-you-can-use).

   <ZoomImage id="element-states-in-conditions-picker.webp" width="600px" alt="Condition picker with the States tab open, listing Email field, Terms checkbox, Continue, and Start trial" />

3. Le menu déroulant **State** affiche le premier état de l'élément, par exemple **Disabled** pour un bouton. Pour utiliser un autre état, sélectionnez-le dans le menu déroulant.

Le champ **Variable** affiche maintenant le texte de l'élément suivi de `· state`, par exemple `Continue · state`. Si l'élément n'a pas de texte, `· state` suit le nom du calque.

### Expliquer pourquoi un bouton est désactivé \{#explain-why-a-button-is-disabled\}

Pour expliquer pourquoi un bouton ne répond pas, affichez une indication uniquement si le bouton est **Disabled**. Commencez par [ajouter un état **Disabled** avec une condition](builder-element-states#add-the-disabled-state) au bouton. Ensuite :

1. Sélectionnez l'indication.
2. Dans la section **Visibility** de l'onglet **Design**, sélectionnez **Conditional**.
3. [Ajoutez un état d'élément](#add-an-element-state-to-a-condition) à la condition : le bouton, `=`, **Disabled**.

Pour modifier le moment où les utilisateurs voient l'indication, modifiez uniquement la condition **Disabled** du bouton.

Sur le canvas, l'indice n'apparaît que lorsque vous [activez **Disabled**](#preview-a-condition-before-you-publish) dans la section **States** du bouton. Pour modifier l'indice quand le canvas le masque, sélectionnez-le dans le panneau **Layers**.

### Synchroniser les états des éléments \{#synchronize-element-states\}

Pour garder deux éléments **Disabled** dans les mêmes conditions, basez la condition **Disabled** du deuxième élément sur l'état du premier. Vous n'aurez ainsi à modifier les règles qu'à un seul endroit. Par exemple, le bouton **Continue** est **Disabled** tant que l'utilisateur n'a pas accepté les conditions et saisi une adresse e-mail valide. Si **Continue** est **Disabled**, un bouton **Start trial** l'est également. Commencez par ajouter un [état **Disabled** avec une condition](builder-element-states#add-the-disabled-state) au bouton **Continue**. Ensuite :

1. Sélectionnez le bouton **Start trial**.
2. Dans la section **States**, cliquez sur **Add state** et sélectionnez **Disabled**.
3. Survolez **Disabled** et cliquez sur **Set conditions**.
4. [Ajoutez un état d'élément](#add-an-element-state-to-a-condition) à la condition : le bouton **Continue**, `=`, **Disabled**.
5. Pour indiquer aux utilisateurs qu'ils ne peuvent pas appuyer sur **Start trial**, [appliquez un style à son état **Disabled**](builder-element-states#style-a-state). Par exemple, réduisez son opacité.

### Remplacer le texte selon l'état d'un élément \{#swap-text-based-on-element-state\}

Pour remplacer le texte d'un élément textuel lorsqu'un autre élément change d'état, utilisez le texte conditionnel. Par exemple, les utilisateurs voient « Enter a valid email » si le champ e-mail est en état **Invalid**, et « Enter your email » dans tous les autres états. Pour permettre au champ e-mail de passer en état **Invalid**, sélectionnez le champ puis, dans l'onglet **Design**, activez [**Validate email format**](builder-inputs-and-forms#input-validation). Ensuite :

1. Sélectionnez l'élément texte.
2. Dans la section **Content** de l'onglet **Design**, sélectionnez **Conditional**.
3. Sous **if**, [ajoutez un état d'élément](#add-an-element-state-to-a-condition) à la condition : le champ e-mail, `=`, **Invalid**.
4. Sous **then**, saisissez le texte pour l'état **Invalid**. Sous **else**, saisissez le texte pour tous les autres états.

Pendant que les utilisateurs saisissent dans le champ e-mail, le champ est [**Active**](builder-element-states#when-several-states-apply-to-one-element), ils voient donc le texte de **else**.

## Éléments et états disponibles \{#which-elements-and-states-you-can-use\}

L'onglet **States** liste les éléments de l'écran qui possèdent des états autres que **Default** :

- Les champs de saisie, y compris les sélecteurs de date et d'heure
- Les éléments sélectionnables, comme les options de quiz, les cartes produit, les onglets et les interrupteurs
- Tout élément auquel vous [ajoutez un état](builder-element-states#add-a-state)

Un bouton, une image ou un conteneur ne peut avoir qu'un état **Disabled** s'il possède un [déclencheur **On Tap**](onboarding-actions#set-up-interactions), et un état **custom** si ce déclencheur est associé à une action.

Depuis l'onglet **States**, vous ne pouvez pas sélectionner :

- Les éléments d'autres écrans. Pour une réponse à un quiz ou le texte saisi par l'utilisateur sur un autre écran, utilisez une [variable d'élément](onboarding-variables#element-variables) dans l'onglet **Elements**.
- Les éléments sans état propre, comme une image dans une carte produit. L'image change d'état en même temps que la carte produit, choisissez donc la carte produit à la place.
- Les indicateurs de progression.
- Un élément, lorsque vous modifiez la condition de l'un de ses états.
- Les éléments qui créeraient une boucle de conditions d'état **Disabled** ou **custom**. Par exemple, la condition **Disabled** de **Start trial** évalue l'état de **Continue**. Vous ne pouvez alors pas sélectionner **Start trial** dans la condition **Disabled** de **Continue** : chaque condition dépendrait de l'autre.
- Les éléments situés en dehors d'un composant réutilisable, lorsque vous modifiez la condition d'un élément dans ce composant.

Pour chaque élément, le menu déroulant **State** liste **Default** et les [états de cet élément](builder-element-states#available-states-by-element-kind).

Pour savoir quelles options les utilisateurs ont sélectionnées dans un groupe, utilisez la [variable du groupe](onboarding-variables#element-variables) dans l'onglet **Elements**, par exemple `quiz.selectedOptionIds`, et non l'état **Selected**. Si une option sélectionnée par un utilisateur devient **Disabled**, son état passe de **Selected** à **Disabled**. Un élément ne se trouve [que dans un seul état à la fois](builder-element-states#when-several-states-apply-to-one-element).

## Prévisualiser une condition avant de la publier \{#preview-a-condition-before-you-publish\}

Pour prévisualiser une condition, sélectionnez l'élément que la condition évalue. Ensuite, dans la section **States** de cet élément, activez l'état à prévisualiser.

Par exemple, pour prévisualiser le message d'info de l'exemple [Expliquer pourquoi un bouton est désactivé](#explain-why-a-button-is-disabled), activez **Disabled** pour le bouton. Le canvas affiche alors le message. Pour revenir à l'apparence par défaut du bouton, activez **Default**.

Pour voir l'état réel de chaque élément, [testez le flow sur un appareil](paywall-device-compatibility-preview#preview-on-devices).

## Résolution des problèmes \{#troubleshooting\}

Si vous voyez un libellé rouge dans le champ **Variable** ou dans la liste déroulante **State** d'une condition, c'est que l'élément ou l'état sélectionné n'existe plus. Par exemple, quelqu'un a supprimé l'élément ou retiré son état **Disabled**. Pour corriger la condition, choisissez un autre élément ou état dans le champ signalé en rouge. Vous ne pouvez pas publier le flow tant que la condition n'est pas corrigée : la boîte de dialogue **Can't publish yet** la liste sous **Broken references**.

Lorsque vous supprimez un élément ou un état utilisé par des conditions, le builder vous demande une confirmation. Une boîte de dialogue, comme **Delete "Continue"?** pour le bouton **Continue**, liste les conditions qui l'utilisent. Si vous cliquez sur **Delete**, ces conditions se cassent et vous ne pouvez pas publier le flow tant que vous ne les corrigez pas. Pour garder les conditions intactes, cliquez sur **Cancel**.
