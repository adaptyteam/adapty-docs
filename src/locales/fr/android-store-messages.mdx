Google Play doit parfois afficher un message à vos utilisateurs concernant leur abonnement — par exemple, qu'un paiement d'abonnement a été refusé et que le moyen de paiement doit être mis à jour. Google Play affiche ces messages par-dessus votre application, uniquement lorsque l'application les demande.

Par défaut, le SDK Adapty demande les messages Google Play à chaque démarrage d'une `Activity` de votre application. Le message s'affiche alors par-dessus ce que cette `Activity` présente, y compris un flow, un onboarding ou un écran de paiement. Pour choisir vous-même le moment d'affichage, passez le SDK en mode de gestion manuelle des messages et appelez `showStoreMessages` à un moment où le message n'interrompra pas l'utilisateur.

Google Play décide si un message s'applique à l'utilisateur, donc une requête n'affiche pas toujours un message. Si l'utilisateur corrige son moyen de paiement depuis le message, le SDK synchronise ses achats avec Adapty, et votre [écouteur de profil](android-listen-subscription-changes) reçoit le niveau d'accès mis à jour.

:::warning
En mode manuel, le SDK ne demande jamais les messages Google Play de lui-même. Si votre application n'appelle jamais `showStoreMessages`, les utilisateurs dont le paiement a été refusé ne verront pas la notification dans votre application.
:::

## Avant de commencer \{#before-you-start\}

Vous avez besoin d'Adapty Android SDK 4.3.0 ou version ultérieure. Les versions antérieures ne demandent pas les messages Google Play.

## Activer la gestion manuelle \{#enable-manual-handling\}

Pour ne demander les messages Google Play que lorsque votre application appelle `showStoreMessages`, définissez `withStoreMessagesHandling` sur `MANUAL` lors de l'[activation du SDK](sdk-installation-android#activate-adapty-module-of-adapty-sdk) :

<Tabs groupId="current-os" queryString>
<TabItem value="kotlin" label="Kotlin" default>

```kotlin showLineNumbers

AdaptyConfig.Builder("PUBLIC_SDK_KEY")
    .withStoreMessagesHandling(AdaptyConfig.StoreMessagesHandling.MANUAL) // AUTO is the default
    .build()
```

</TabItem>
<TabItem value="java" label="Java" default>

```java showLineNumbers

new AdaptyConfig.Builder("PUBLIC_SDK_KEY")
    .withStoreMessagesHandling(AdaptyConfig.StoreMessagesHandling.MANUAL) // AUTO is the default
    .build();
```

</TabItem>
</Tabs>

## Afficher les messages \{#show-messages\}

Lorsque votre application atteint un point où un message Google Play n'interrompra pas l'utilisateur — par exemple, après que l'utilisateur a fermé un flow ou terminé un onboarding — appelez `showStoreMessages` avec l'`Activity` qui affiche le message :

<Tabs groupId="current-os" queryString>
<TabItem value="kotlin" label="Kotlin" default>

```kotlin showLineNumbers
Adapty.showStoreMessages(activity)
```

</TabItem>
<TabItem value="java" label="Java" default>

```java showLineNumbers
Adapty.showStoreMessages(activity);
```

</TabItem>
</Tabs>

La méthode ne retourne aucun résultat. Le SDK ne demande pas de message dans ces cas :

- **Le SDK n'est pas activé** : Appelez `showStoreMessages` après `Adapty.activate`.
- **L'`Activity` ne peut pas afficher de message** : L'`Activity` est en cours de fermeture ou détruite, ou sa fenêtre n'est pas encore attachée. Appelez la méthode depuis une `Activity` visible par l'utilisateur.

En mode `AUTO` par défaut, vous pouvez également appeler `showStoreMessages` — par exemple, pour redemander un message sur une `Activity` déjà en cours d'exécution.
