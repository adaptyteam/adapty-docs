Pour résoudre un problème d'intégration App Store, trouvez la section correspondant au symptôme que vous observez.

## "The provided field values are incorrect" lors de l'enregistrement des identifiants \{#the-provided-field-values-are-incorrect-when-saving-credentials\}

Lorsque vous enregistrez la clé d'achat intégré, Adapty construit un jeton d'authentification à partir des champs **Issuer ID**, **Key ID** et **Private key (.p8 file)**, puis le valide auprès d'Apple. Cette erreur signifie qu'Apple a rejeté le jeton. Vérifiez les valeurs dans cet ordre :

1. **Type de clé.** La clé doit être une clé **In-App Purchase** provenant de **Users and Access** > **Integrations** > **In-App Purchase** dans App Store Connect. Une clé de l'onglet **Team Keys** (la clé API App Store Connect) possède son propre **Issuer ID** et **Key ID**, mais Apple la rejette ici. [Connectez cette clé](app-store-connect-api-key#connect-the-key-in-adapty) dans la section **App Store Connect API key** à la place.
2. **Même compte et même équipe.** L'Issuer ID, le Key ID et le fichier .p8 doivent provenir de la même équipe App Store Connect que l'application. Une clé générée dans le compte d'une autre équipe — par exemple, un compte d'agence — échoue à la validation.
3. **Le fichier .p8 lui-même.** Téléchargez le fichier exactement tel qu'il a été téléchargé depuis App Store Connect. Un fichier recréé à partir d'un contenu de clé copié-collé échoue souvent. Vous ne pouvez télécharger chaque clé qu'une seule fois ; si le fichier original est perdu, générez une nouvelle clé.
4. **Bundle ID.** Le Bundle ID doit correspondre exactement au bundle ID de votre application dans App Store Connect — au format DNS inversé sans espaces, par exemple, `com.company.app`.
5. **Caractères cachés.** Recopiez chaque ID directement depuis App Store Connect. Des espaces parasites ou des caractères ressemblants — par exemple, un `l` minuscule à la place du chiffre `1` — font échouer la validation.

Cette validation utilise uniquement les trois champs de la clé d'achat intégré et l'identifiant de bundle. L'App-Specific Shared Secret et la [clé API App Store Connect](app-store-connect-api-key) n'y participent pas, donc les ressaisir ne changera pas le résultat.

Si toutes les valeurs correspondent à App Store Connect et que vous voyez toujours l'erreur, contactez le support Adapty à l'adresse [support@adapty.io](mailto:support@adapty.io).

## Les produits n'apparaissent pas ou n'affichent aucun statut App Store \{#products-dont-appear-or-show-no-app-store-status\}

Quand Adapty ne parvient pas à lire vos produits depuis App Store Connect, vous observez un ou plusieurs des signes suivants :

- Le menu déroulant **App Store Product ID** ne liste pas votre produit.
- La liste des produits affiche un tiret ou « Not Connected » dans la colonne **App Store status**, ou la page du produit reste sur « Status pending ».
- La liste **Associated plan** d'un message de rétention affiche « No options ».
- Le CSV des prix que vous téléchargez pour un produit ne contient que les en-têtes de colonnes.

Passez en revue les causes suivantes dans l'ordre :

- **L'application n'a pas de clé API App Store Connect** : [Connectez une clé d'équipe](app-store-connect-api-key).
- **Apple rejette la clé API App Store Connect** : La clé appartient à une autre équipe, a été révoquée, ou son Key ID ne correspond pas à son fichier .p8. [Remplacez la clé](app-store-connect-api-key#replace-the-key) par une clé de l'équipe propriétaire de l'application.
- **L'Apple App ID est vide ou incorrect** : [Copiez l'Apple ID de l'application](app-store-connection-configuration#enter-the-bundle-id-and-apple-app-id) depuis App Store Connect dans le champ **Apple App ID**.
- **Le produit se trouve dans une autre application** : Adapty ne recherche les produits que dans l'application App Store Connect correspondant à votre Apple App ID. Vérifiez que le produit appartient bien à cette application.
- **Le produit a moins de 10 minutes** : Attendez 10 minutes après l'avoir créé dans App Store Connect, puis recherchez-le à nouveau dans le menu déroulant **App Store Product ID**.

## "403 Client Error: Forbidden" lors de l'envoi d'un produit \{#403-client-error-forbidden-when-you-push-a-product\}

Lors de l'envoi d'un produit, App Store Connect renvoie cette erreur si le titulaire du compte n'a pas accepté le dernier accord Paid Apps. Pour accepter l'accord, le titulaire du compte ouvre **Business** > **Agreements** dans App Store Connect. Là, il clique sur **View and Agree to Terms** pour Paid Apps.

Une clé API App Store Connect révoquée peut aussi provoquer l'erreur 403 : [remplacez la clé](app-store-connect-api-key#replace-the-key).

## Le statut des notifications affiche « Delayed » ou « Stalled » \{#the-notifications-status-reads-delayed-or-stalled\}

Le statut des notifications dans **App settings** > **iOS SDK** affiche « Delayed » lorsque la dernière notification est arrivée il y a plus de 24 heures. Après 72 heures, il affiche « Stalled ». [Vérifiez que **Production Server URL** et **Sandbox Server URL** dans App Store Connect correspondent bien à l'**URL for App Store server notifications** dans Adapty](enable-app-store-server-notifications#check-that-notifications-reach-adapty).

## Un achat réussit mais le client perd l'accès \{#a-purchase-succeeds-but-the-customer-loses-access\}

Un client paie et peut avoir accès brièvement, mais n'a plus accès après que votre application actualise le profil depuis Adapty.

La cause est généralement l'une des suivantes :

- **La clé d'achat intégré ne fonctionne plus** : Adapty n'a pas pu valider la transaction avec Apple. [Remplacez la clé](generate-in-app-purchase-key#replace-the-key).
- **Le produit n'est pas lié dans Adapty** : L'ID de produit du store que le client a acheté n'est pas lié à un produit Adapty, il n'existe donc aucun niveau d'accès à accorder. Vérifiez que le produit existe avec l'**App Store Product ID** exact et qu'un [niveau d'accès](access-level) lui est assigné.

Après avoir remplacé la clé d'achat intégré, demandez aux clients qui ont acheté pendant la panne de restaurer leurs achats. Une restauration rétablit immédiatement leur accès.

## Les prix dans Adapty ne correspondent pas à l'App Store \{#prices-in-adapty-dont-match-app-store\}

Si Adapty et l'App Store affichent des prix différents pour un produit, vérifiez comment vous l'avez ajouté. Le champ **price** sur la page du produit dans Adapty a un rôle différent selon les cas.

Si vous créez un produit dans Adapty et que vous le publiez sur le store depuis le tableau de bord, ce prix est utilisé comme prix initial dans le store.

Si vous ajoutez un produit qui existe déjà dans le store, ce prix est un espace réservé. Les analyses, les intégrations et le SDK d'Adapty utilisent les vrais prix récupérés depuis l'App Store, quelles que soient les valeurs saisies ici. Les modifications de prix effectuées dans l'App Store ne se synchronisent pas pour mettre à jour cet espace réservé, et il n'est actuellement pas possible de le modifier depuis le tableau de bord.
