Un flow peut continuer après un écran de paywall — reprendre l'onboarding, afficher un écran de remerciement aux nouveaux abonnés, ou accueillir de nouveau ceux qui restaurent un achat antérieur.

Vous définissez les résultats dans les paramètres d'action, un pour chaque condition d'achat. Un résultat sans action maintient les utilisateurs sur l'écran du paywall.

- L'action **Purchase** comprend les conditions suivantes : **When succeeded**, **When failed**, **When cancelled by user** et **When pending**.
- L'action **Restore purchases** comprend deux conditions : **When restore completed** et **When restore failed**.

## Avant de commencer \{#before-you-start\}

Assurez-vous que :

- Votre application utilise le SDK Adapty v4.0 ou une version ultérieure.
- Le flow comprend un écran paywall. Pour en créer un, suivez le guide [Créer un écran paywall de base](basic-paywall-screen).
- Un élément de l'écran paywall, tel qu'un bouton, possède une [action **Purchase**](paywall-product-block#trigger-a-purchase).
- Votre application maintient le flow ouvert dans ses <InlineTooltip tooltip="callbacks d'achat et de restauration">[iOS](ios-handling-events), [Android](android-handling-events), [React Native](react-native-handling-events-1), [Flutter](flutter-handling-events), [Unity](unity-handling-events), [Kotlin Multiplatform](kmp-handling-events), et [Capacitor](capacitor-handling-events)</InlineTooltip>.

## Ajouter des actions pour un résultat

:::important
Le flow ne peut répondre qu'aux achats **In-App Store**. Il ne reçoit pas le résultat d'un achat **Web Payment**.
:::

1. Sélectionnez l'élément qui a l'action **Purchase** ou **Restore purchases**.
2. Cliquez sur l'action **Purchase** ou **Restore purchases**.
3. Pour le résultat d'achat ou de restauration souhaité, par exemple **When succeeded**, cliquez sur <Inline id="plus.svg" alt="Add action" />.
4. Dans le menu déroulant **Action**, sélectionnez l'action à exécuter à la place de **Do nothing**.

:::note
Une action de navigation ou **Close Flow** qui suit **Purchase** ou **Restore purchases** dans le même déclencheur s'exécute immédiatement, avant que le résultat ne soit connu. Ajoutez-la plutôt comme action de résultat.
:::

:::tip
Lorsqu'une action **Purchase** possède des actions de résultat, un double appui ne déclenche pas un second achat. Le flow ignore les appuis supplémentaires sur cette action jusqu'à ce que le store renvoie le résultat, pendant 60 secondes maximum. **Restore purchases** fonctionne de la même façon.
:::

Pour voir les actions de résultat dans votre application, [effectuez un achat en sandbox](test-purchases-in-sandbox).

Vous ne pouvez pas effectuer de vrais achats dans l'[aperçu dans l'application mobile Adapty](paywall-device-compatibility-preview#preview-on-devices).

Si le flow ignore les actions de résultat dans votre application, consultez [pourquoi le flow ignore les actions de résultat](flow-common-issues#the-flow-doesnt-run-the-actions-set-for-a-purchase-result).

:::tip
Pour gérer les résultats d'achat dans votre code applicatif, par exemple pour ouvrir un écran natif, utilisez les callbacks d'achat et de restauration du SDK Adapty. Chaque modification de ce code nécessite une mise à jour de l'application. Si votre application ouvre un second flow après un achat, vous pouvez déplacer ses écrans dans le flow qui contient le paywall.
:::

### Afficher l'écran suivant après un achat réussi \{#show-the-next-screen-after-a-successful-purchase\}

Pour continuer l'onboarding ou afficher un écran de remerciement après un achat réussi, associez le résultat **When succeeded** à une action [**Navigate to Screen**](onboarding-actions#navigate-to-screen) et sélectionnez cet écran comme destination.

### Fermer le flow après un achat réussi \{#close-the-flow-after-a-successful-purchase\}

Pour terminer le flow après un achat réussi, ajoutez [**Close Flow**](onboarding-actions#close-flow) pour **When succeeded** plutôt qu'une navigation. Le flow se ferme alors uniquement lorsque l'achat aboutit, donc votre code applicatif n'a pas besoin de le fermer.

### Répondre à un achat échoué, annulé ou en attente \{#respond-to-a-failed-canceled-or-pending-purchase\}

Pour afficher une alerte ou un écran après un achat échoué, annulé ou en attente, ajoutez des actions pour ces résultats de l'action **Purchase** :

- **When failed** : Une erreur a interrompu l'achat. Par exemple, [affichez une alerte](onboarding-actions#show-alert) pour demander à l'utilisateur de réessayer plus tard.
- **When cancelled by user** : L'utilisateur a annulé l'achat. Par exemple, affichez un écran avec une autre offre.
- **When pending** : L'achat est en attente d'approbation, par exemple pendant que la banque confirme le paiement ou qu'un parent l'approuve via Ask to Buy sur iOS. Le flow ne répond pas lorsque la banque ou le parent approuve l'achat, donc affichez un écran expliquant l'attente.

:::tip
Pour permettre aux utilisateurs de réessayer un achat échoué, gardez-les sur le paywall, par exemple avec une alerte pour **When failed**. Vous ne pouvez pas ajouter **Purchase**, **Restore purchases**, ou [**Request permission**](onboarding-actions#request-permission) à un résultat.
:::

### Répondre à une restauration d'achat \{#respond-to-a-purchase-restoration\}

L'action [**Restore purchases**](paywall-product-block#restore-purchases) a deux résultats possibles : **When restore completed** et **When restore failed**.

**When restore completed** signifie que la restauration s'est terminée sans erreur, et non que l'utilisateur a accès au contenu. Il n'est pas possible de vérifier les niveaux d'accès dans un flow. Pour afficher du contenu conditionnel à un accès, ajoutez **Close Flow** pour **When restore completed**, puis vérifiez le [niveau d'accès](access-level) dans l'application.
