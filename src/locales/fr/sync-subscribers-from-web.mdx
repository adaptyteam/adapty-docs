Si vos utilisateurs peuvent acheter un produit sur votre **site web**, vous pouvez maintenir leurs niveaux d'accès automatiquement synchronisés avec votre **application mobile**.

Dans ce guide, vous apprendrez à le faire en utilisant l'API et le SDK Adapty.

#### Exemple d'utilisation \{#sample-use-case\}

Disons que, dans votre application, les utilisateurs peuvent s'inscrire à un plan freemium sur mobile et sur le web. Vous leur permettez de passer à un plan Premium sur votre site via Stripe ou Chargebee.
Une fois qu'un utilisateur s'abonne sur le web, vous voulez qu'il bénéficie immédiatement de l'accès Premium dans l'application mobile — sans attendre ni se reconnecter.

C'est exactement ce qu'Adapty vous aide à automatiser.

## Étape 1. Identifier les utilisateurs \{#step-1-identify-users\}

Adapty utilise `customer_user_id` pour identifier les utilisateurs sur toutes les plateformes.

Vous devez créer cet identifiant une seule fois et le transmettre à la fois à votre SDK mobile et à votre backend web.

### Inscription depuis le web \{#sign-up-from-web\}

Lorsque vos utilisateurs s'inscrivent sur votre site web, vous devez créer un profil pour eux dans Adapty via l'API côté serveur.

Consultez la référence de la méthode [ici](api-adapty/operations/createProfile).

```bash
curl --request POST \
  --url https://api.adapty.io/api/v2/server-side-api/profile/ \
  --header 'Accept: application/json' \
  --header 'Authorization: Api-Key YOUR_SECRET_API_KEY' \
  --header 'Content-Type: application/json' \
  --header 'adapty-customer-user-id: YOUR_CUSTOMER_USER_ID'
```

### Inscription depuis l'application \{#sign-up-from-app\}

Lorsque vos utilisateurs s'inscrivent depuis l'application, vous pouvez transmettre leur ID utilisateur client lors de l'activation du SDK, ou si vous avez activé le SDK Adapty avant l'étape d'inscription, utiliser la méthode `identify` pour créer un nouveau profil et lui attribuer un ID utilisateur client.

:::important
Si vous identifiez de nouveaux utilisateurs après l'activation du SDK, celui-ci créera d'abord un profil anonyme, car il ne peut pas fonctionner sans profil. Ensuite, lorsque vous identifiez l'utilisateur et lui attribuez un nouvel ID utilisateur client, un nouveau profil sera créé.

Ce comportement est tout à fait normal et n'affecte pas la précision des analyses. En savoir plus [ici](ios-quickstart-identify).
:::

## Étape 2. Vérifier le statut de l'abonnement via l'API \{#step-2-check-subscription-status-via-api\}

Lorsqu'un utilisateur se connecte sur votre site web, récupérez son profil Adapty via l'API.

Si l'utilisateur n'a pas d'abonnement actif, vous pouvez afficher un paywall.

Consultez la référence de la méthode [ici](api-adapty/operations/getProfile).

```bash
curl --request GET \
  --url https://api.adapty.io/api/v2/server-side-api/profile/ \
  --header 'Accept: application/json' \
  --header 'Authorization: Api-Key YOUR_SECRET_API_KEY' \
  --header 'adapty-customer-user-id: YOUR_USER_ID' \
```

## Étape 3. Afficher un paywall sur votre site web \{#step-3-display-a-paywall-on-your-website\}

Sur votre site web, affichez un paywall pour les utilisateurs freemium.
Vous pouvez utiliser n'importe quel prestataire de paiement (Stripe, Chargebee, LemonSqueezy, etc.).

## Étape 4. Mettre à jour le statut d'abonnement dans Adapty \{#step-4-update-subscription-status-in-adapty\}

Une fois le paiement effectué sur votre site web, appelez l'API Adapty pour mettre à jour le niveau d'accès de l'utilisateur en fonction du produit acheté.

Consultez la référence de la méthode [ici](api-adapty/operations/grantAccessLevel).

```bash
curl --request POST \
  --url https://api.adapty.io/api/v2/server-side-api/purchase/profile/grant/access-level/ \
  --header 'Accept: application/json' \
  --header 'Authorization: Api-Key YOUR_SECRET_API_KEY' \
  --header 'Content-Type: application/json' \
  --header 'adapty-customer-user-id: YOUR_USER_ID' \
  --data '{
  "access_level_id": "YOUR_ACCESS_LEVEL"
}'
```

## Étape 5. Synchroniser le statut dans l'application \{#step-5-sync-status-in-the-app\}

Lorsque l'utilisateur ouvre votre application mobile, récupérez le profil mis à jour et déverrouillez les fonctionnalités payantes.

Vous devez soit récupérer son profil, soit le synchroniser automatiquement. Ensuite, obtenez le niveau d'accès à partir de celui-ci.

Ci-dessous, vous verrez comment récupérer le profil et vérifier son statut. Pour plus de détails, consultez [cette page](ios-check-subscription-status).
