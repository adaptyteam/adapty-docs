Profils est un CRM pour vos utilisateurs. Avec Profils, vous pouvez :

1. Rechercher des utilisateurs spécifiques par ID de profil, customer user ID, e-mail ou ID de transaction.
2. Consulter la chronologie des événements d'un utilisateur, notamment les problèmes de facturation, les délais de grâce et autres [événements](events).
3. Analyser les propriétés d'un utilisateur : état de l'abonnement, revenus/produits totaux, etc.
4. Accorder un abonnement à un utilisateur.

## Rechercher des utilisateurs \{#finding-users\}

Dans la liste Profils, vous pouvez rechercher un utilisateur spécifique par :

- **Profile ID** : l'identifiant interne d'Adapty pour l'utilisateur (aussi appelé Adapty ID).
- **Customer user ID** : l'identifiant de votre application pour l'utilisateur, si vous en avez défini un.
- **Email** : l'e-mail de l'utilisateur, s'il a été envoyé comme attribut personnalisé.
- **Transaction ID** : l'ID de transaction du store provenant d'un achat.

Cliquez sur n'importe quelle ligne pour ouvrir le profil complet de l'utilisateur.

Vous pouvez envoyer des propriétés utilisateur supplémentaires à Adapty via le SDK.

Par défaut, Adapty définit :

| Propriété        | Description                                                  |
| ---------------- | ------------------------------------------------------------ |
| Customer user ID | Un identifiant de votre utilisateur final dans votre système. |
| Adapty ID        | L'identifiant interne Adapty de votre utilisateur final, appelé Profile ID. |
| IDFA             | L'Identifier for Advertisers, attribué par Apple à l'appareil d'un utilisateur. Nécessite l'autorisation App Tracking Transparency (ATT) sur iOS 14+. Non disponible sur Android. |
| Country          | Le pays de votre utilisateur final.                          |
| OS               | Le système d'exploitation utilisé par l'utilisateur final.   |
| Device           | Le nom de modèle d'appareil visible par l'utilisateur final. |
| Install date     | La date à laquelle l'utilisateur a été enregistré pour la première fois dans Adapty : <ul><li>La date de création de l'utilisateur. </li><li>Si l'utilisateur a installé votre application avant l'intégration d'Adapty, la date d'installation correspond à la date de sa première transaction.</li><li>Le cas échéant, la date fournie lors d'une importation de données historiques.</li></ul> |
| Created at       | La date de création de l'utilisateur.                        |

Envoyez au minimum votre ID utilisateur interne ou l'e-mail de l'utilisateur. Cela vous permet de retrouver les utilisateurs par ces identifiants dans la liste Profils.

Après l'installation du SDK, Adapty collecte automatiquement les événements utilisateur depuis la file de paiement et les affiche dans le profil utilisateur. Les attributs du tableau ci-dessus sont collectés automatiquement — vous n'avez pas besoin de les envoyer.

## Accorder un abonnement \{#granting-a-subscription\}

Dans un profil, vous pouvez prolonger un abonnement actif ou accorder à un utilisateur un accès à vie à un niveau d'accès — sans qu'il ait besoin d'effectuer un achat.

<Zoom>
  <img src="/assets/shared/img/b1d74fd-edit_paid_access_level.webp"
  style={{

  }}
/>
</Zoom>

C'est particulièrement utile pour :
- Dédommager un utilisateur suite à un problème de facturation ou de support.
- Lancer des promotions manuelles ou des programmes bêta.
- Tester des flows d'abonnement sans effectuer de vrai achat.

Pour accorder l'accès, ouvrez le profil de l'utilisateur, rendez-vous dans la section **Access levels** et cliquez sur **Edit**. Définissez la date d'expiration et enregistrez. La date d'expiration doit être dans le futur et ne peut pas être réduite une fois définie. La modifier pour des abonnements actifs n'affecte pas les paiements en cours.

:::note
L'octroi d'un accès ne crée pas d'événements d'achat sur l'App Store ou Google Play. Le fil d'événements et les analyses de l'utilisateur seront différents d'un vrai flow d'achat.
:::

Vous pouvez également accorder un accès par programmation en utilisant la méthode API [Grant access level](api-adapty/operations/grantAccessLevel).

### Historique du partage d'accès \{#access-sharing-history\}

Lorsque des niveaux d'accès sont partagés ou transférés, le profil de l'utilisateur affiche un lien vers le profil connecté — le profil qui a partagé l'accès ou celui qui l'a reçu. Pour consulter le profil connecté, dans le **Profile** de l'utilisateur, cliquez sur le lien à côté du niveau d'accès.
