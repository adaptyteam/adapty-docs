Lorsqu'un utilisateur saisit quelque chose dans un champ de texte, répond à un quiz ou actionne un interrupteur dans un [flow](adapty-flow-builder), le SDK transmet la valeur à votre application via son callback d'analyse.

Les applications utilisent le plus souvent ces données pour :

- **Inscrire les utilisateurs sur votre propre backend** : Récupérez l'adresse e-mail et le nom saisis dans votre onboarding, et créez leur compte à la fermeture du flow.
- **Sauvegarder les réponses et préférences** : Gardez en mémoire les choix de l'utilisateur pour que votre app puisse les exploiter plus tard — par exemple, [écrivez-les dans son profil Adapty](react-native-setting-user-attributes) sous forme d'attributs personnalisés.
- **Personnaliser les flows futurs** : Enregistrez les réponses au quiz comme attributs personnalisés, puis ciblez un placement ultérieur pour que chaque segment voie un flow différent, ou un paywall différent à l'intérieur.
- **Alimenter des plateformes d'analytics tierces** : Transmettez les réponses à Amplitude, Mixpanel, ou toute autre solution d'analytics produit que vous utilisez.

Les champs de saisie et les groupes sélectionnables transmettent automatiquement leurs valeurs. Pour les distinguer dans votre code, attribuez un **Element ID** significatif à chaque champ de saisie et un **Group ID** à chaque groupe sélectionnable dans le builder.

## Recevoir les valeurs saisies \{#receive-input-values\}

Les valeurs saisies parviennent au même gestionnaire que tous les autres événements analytiques d'un flow, sous le nom d'événement `flow_user_input`. Enregistrez `onAnalytics` avec vos autres gestionnaires d'événements de flow :

```javascript showLineNumbers title="React Native"
const unsubscribe = view.setEventHandlers({
  onAnalytics(name, params) {
    handleFlowInput(name, params);
    return false; // keep the flow open
  },
});
```

Le callback `onAnalytics` transmet tous les événements analytiques d'un flow, y compris les [vues d'écran](react-native-flow-screen-views).
- Le paramètre `name` contient le nom de l'événement. Pour filtrer les événements de saisie utilisateur, comparez `name` à `flow_user_input`.
- Le paramètre `element_type` indique la catégorie de l'élément.
- La valeur de la saisie est stockée dans différents paramètres selon le type d'élément :
     - Les champs de texte, les sélecteurs et les interrupteurs stockent la saisie de l'utilisateur dans `value`
     - Les groupes à sélection multiple indiquent les options actives dans `item_ids` et `item_titles`

```javascript showLineNumbers title="React Native"
function handleFlowInput(name, params) {
  if (name !== 'flow_user_input') return;

  // The screen the input sits on. Pair it with element_id to tell apart
  // two fields that share an Element ID on different screens.
  const screenId = params.instanceId;

  switch (params.element_type) {
    case 'text_input':
    case 'email_input':
    case 'number_input':
    case 'phone_input': {
      const text = params.value;
      break;
    }
    case 'date_picker':
    case 'time_picker':
    case 'date_time_picker': {
      // Unix time in milliseconds.
      const date = new Date(params.value);
      break;
    }
    case 'single_choice': {
      const optionId = params.item_ids[0];
      break;
    }
    case 'multi_choice': {
      const optionIds = params.item_ids;
      break;
    }
    case 'toggle': {
      const isOn = params.value;
      break;
    }
  }
}
```

## Livraison et limitations \{#delivery-and-limitations\}

<FlowInputLimitations />

Enregistrez chaque valeur d'entrée au moment où votre handler la reçoit, puis envoyez l'ensemble complet à la fermeture du flow. Pour intercepter ce moment, enregistrez un handler `onDisappeared` en parallèle de `onAnalytics`. Il s'exécute lorsque la vue du flow est rejetée, que l'utilisateur ait terminé le flow ou l'ait fermé en cours de route.

## Cas d'utilisation \{#use-cases\}

### Enregistrer les utilisateurs sur votre backend \{#register-users-on-your-backend\}

Collectez les valeurs au fur et à mesure qu'elles arrivent et envoyez-les en une seule fois quand le flow se ferme, de sorte qu'une seule requête contienne l'ensemble complet des réponses.

Le flow disparaît que l'utilisateur l'ait terminé ou abandonné en cours de route. Vérifiez la présence des champs dont vous avez besoin avant d'appeler votre backend.

Le flow ne peut pas afficher les erreurs provenant de votre backend. La valeur de retour du handler se contente de fermer la vue du flow, et le SDK ne dispose d'aucune méthode pour envoyer des données dans un flow en cours d'exécution. Si l'inscription échoue, par exemple parce que l'adresse e-mail est déjà utilisée, affichez l'erreur dans votre propre interface après la fermeture du flow.

```javascript showLineNumbers title="React Native"
const flowAnswers = {};

const unsubscribe = view.setEventHandlers({
  onAnalytics(name, params) {
    if (name === 'flow_user_input' && typeof params.value === 'string') {
      flowAnswers[params.element_id] = params.value;
    }
    return false;
  },
  onDisappeared() {
    if (flowAnswers.email) {
      // Send flowAnswers to your backend here to create the account.
    }
    return false;
  },
});
```

### Enrichir les profils utilisateur avec des données \{#enrich-user-profiles-with-data\}

Pour associer ce qu'un utilisateur a saisi à son profil et éviter de lui redemander les mêmes informations, [mettez à jour le profil utilisateur](react-native-setting-user-attributes) au fur et à mesure que les valeurs arrivent.

Par exemple, si votre flow comporte un champ texte avec l'ID d'élément `name` et un champ email avec l'ID d'élément `email` :

```javascript showLineNumbers title="React Native"
function handleFlowInput(name, params) {
  if (name !== 'flow_user_input') return;
  if (typeof params.value !== 'string') return;

  const profileParams = {};

  switch (params.element_id) {
    case 'name':
      profileParams.firstName = params.value;
      break;
    case 'email':
      profileParams.email = params.value;
      break;
    default:
      return;
  }

  adapty.updateProfile(profileParams).catch(error => {
    // handle the error
  });
}
```

### Personnaliser les flows affichés ultérieurement \{#customize-flows-shown-later\}

Les réponses au quiz peuvent aussi décider ce qu'un utilisateur verra à un [placement](placements) ultérieur — un flow différent, ou un paywall différent à l'intérieur.

Par exemple, demandez aux utilisateurs leur niveau d'expérience sportive dans votre flow d'onboarding, puis montrez à chaque groupe son propre flow avec des produits et des textes différents.

1. Ajoutez un [quiz](onboarding-quizzes) à votre flow. Donnez au [groupe sélectionnable](flow-selectable-elements) l'ID de groupe `experience`, et à chaque option un ID d'élément explicite.
2. Gérez les réponses et [définissez des attributs personnalisés](react-native-setting-user-attributes) pour l'utilisateur.

```javascript showLineNumbers title="React Native"
function handleFlowInput(name, params) {
  if (name !== 'flow_user_input') return;
  if (params.element_id !== 'experience') return;

  adapty
    .updateProfile({
      // Set the custom attribute 'experience' to the option the user selected
      // (beginner, amateur, or pro).
      codableCustomAttributes: { experience: params.item_ids[0] },
    })
    .catch(error => {
      // handle the error
    });
}
```

3. [Créez un segment](segments) pour chaque valeur d'attribut personnalisé.
4. Créez un [placement](placements) et ajoutez une [audience](audience) pour chaque segment.
5. [Affichez le flow](react-native-present-paywalls) correspondant à ce placement dans votre application.
