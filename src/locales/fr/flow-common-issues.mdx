Cet article regroupe les problèmes les plus fréquents lors de la création d'un flow dans le [Flow & Paywall Builder](adapty-flow-builder), chacun accompagné de sa cause et de sa solution.

## Un flow ne s'affiche pas en aperçu ou ne se publie pas \{#a-flow-wont-preview-or-publish\}

Les problèmes liés aux produits apparaissent dans le [panneau **Issues**](builder-save-publish#fix-issues-before-publishing). Cliquez sur un problème pour ouvrir le paramètre à corriger.

Vous pouvez rencontrer les erreurs suivantes lorsque vous essayez d'afficher un aperçu ou de publier le flow :

| Message | Cause et solution |
|---|---|
| **No product selected** | Une carte produit n'a aucun produit associé. Sélectionnez-en un ou supprimez la carte. |
| **This product no longer exists**, **This offer no longer exists** | Le produit ou l'offre a été supprimé de votre tableau de bord. Choisissez-en un autre à l'endroit où il est utilisé, ou utilisez **Replace in N places** sur l'entrée **Missing** dans le panneau **Products** pour corriger toutes les occurrences à l'écran en une seule fois. |
| **This product is off this screen**, **This offer is off this screen** | Une variable texte, une condition ou une action fait référence à un produit qui ne figure pas dans la liste de l'écran, par exemple après l'avoir retiré depuis le panneau **Products**. Rajoutez le produit dans le panneau ou modifiez la référence. |
| **Product reference is invalid** | Une référence à un produit est malformée. Resélectionnez le produit. |
| **Purchase action has no product to buy** | Une action **Purchase** n'a aucun produit associé : soit le champ est vide, soit il pointe vers une carte supprimée. Dans l'onglet **Interactions** de l'élément, définissez **Product** sur un produit ou sur `products.selectedProduct`. |
| **Select product action has no product to select** | La carte ciblée par une action **Select product** a disparu : supprimée, déplacée hors de son groupe de produits ou placée sur un autre écran. Dans l'onglet **Interactions** de l'élément, faites pointer l'action vers une carte de cet écran. |
| **Flow has no screens**, **Screen "…" has no elements** | Ajoutez du contenu à l'écran vide ou supprimez-le. Un flow qui ne contient que du contenu Remote Config est exempté de cette règle. |
| **Invalid interaction action** | Une action est incomplète : **Open URL** sans URL, **Navigate to screen** sans destination, **Set variable** sans affectation, **Custom** sans identifiant d'action, **Show alert** sans titre ni message, **Show** ou **Hide** sans élément, ou un paiement web **Purchase** sans URL de Web Paywall. Ouvrez les interactions de l'élément et complétez ou supprimez l'action. |
| **"…" has no link to open**, **"…" runs a custom action without an ID**, **"…" shows an alert with no text**, **"…" has an unfinished condition**, **Complete the selected action before publishing.** | Une action n'est pas configurée : une action **Open URL** sans lien, une **Custom Action** sans identifiant, une action **Show alert** sans titre ni message, ou une action **Conditional** avec une condition non remplie. Le panneau **Issues** les liste toutes. Lorsque vous cliquez sur **Publish to Live**, le builder ouvre l'onglet **Interactions** du premier élément concerné. Complétez l'action ou supprimez-la. Pour une action **Conditional**, remplissez toutes les conditions ou supprimez la branche correspondante. |
| **Missing navigation target** | Une action **Navigate to screen** pointe vers un écran qui a été supprimé. Sélectionnez un écran existant ou supprimez l'action. |
| **Missing product target**, **Invalid product target**, **Product target on another screen**, **Ambiguous product target**, **Select Product inside a component** | Une action **Select product** cible une carte qui a été supprimée, qui n'appartient pas à un groupe de produits, qui se trouve sur un autre écran, qui partage son identifiant d'élément avec un élément d'un autre écran, ou qui est intégrée dans un pied de page ou un en-tête partagé entre plusieurs écrans. Faites pointer l'action vers une carte d'un groupe de produits sur le même écran, avec un identifiant unique. |
| **Missing selectable group** | Un élément pointe vers un groupe sélectionnable qui n'existe plus. Reconnectez-le ou recréez le groupe. |
| **Invalid visibility condition** | Une règle de visibilité conditionnelle est incomplète. Complétez-la dans le générateur de conditions. |
| **Broken references**, **Fix the broken reference before publishing.**, **Fix N broken references before publishing.** | Lorsque vous cliquez sur **Publish to Live**, la boîte de dialogue **Can't publish yet** liste les conditions qui utilisent un élément, un état ou une variable qui n'existe plus, par exemple après l'avoir supprimé ou après avoir collé un écran depuis un autre flow. Les lignes de condition ayant une valeur mais aucune variable apparaissent dans la même liste. Cliquez sur **Go to screen** pour ouvrir le premier cas. Ouvrez ensuite la condition et sélectionnez un élément, un état ou une variable existants, ou supprimez la condition. |
| **Condition uses a deleted element or state**, **Condition uses a deleted variable** | La publication a échoué car une condition utilise un élément, un état ou une variable qui n'existe plus. Ouvrez la condition et sélectionnez un élément, un état ou une variable existants, ou supprimez la condition. Relancez ensuite la publication. |
| **Invalid State Condition**, `invalid_state_condition` | L'interface CLI Adapty ou l'API n'a pas pu publier le flow : une ligne dans la condition d'un état **Disabled** ou **custom** a une valeur ou **Is empty** mais aucune variable. Sélectionnez une variable pour cette ligne ou supprimez-la. Relancez ensuite la publication. |
| **Circular state conditions** | Les conditions d'état **Disabled** ou **custom** de plusieurs éléments dépendent mutuellement les unes des autres en formant une boucle. Dans la section **States** de l'un de ces éléments, modifiez ou supprimez la condition qui ferme la boucle. |
| Un nom de formule sous **Variables**, accompagné d'un message d'erreur tel que **This variable no longer exists. Pick another one.** | Une [formule](flow-formulas) contient une erreur. Dans le panneau Variables, la ligne de la formule affiche une icône d'erreur. Ouvrez la variable et corrigez la formule comme indiqué dans la section [Troubleshooting](flow-formulas#troubleshooting). |
| **Formula "…" has a syntax error** | La formule ne respecte pas les règles de syntaxe : par exemple, une parenthèse est manquante, un nombre contient une virgule, ou un nom de fonction est inconnu. Ouvrez la variable et corrigez la formule. |
| **Formula "…" has a wrong number of arguments** | Une fonction de la formule reçoit trop ou pas assez d'arguments. Référez-vous aux listes des [fonctions numériques](flow-formulas#number-functions) et des [fonctions de date](flow-formulas#date-functions). |
| **Formula "…" uses a value of the wrong type** | La formule utilise un texte, une valeur oui/non ou une date là où un nombre est attendu, ou un nombre là où une date est attendue. Ouvrez la variable et corrigez la formule. |
| **Formula "…" uses a deleted value** | La formule lit une variable, une réponse ou un groupe de produits qui n'existe plus dans le flow. Remplacez la référence dans la formule. |
| **Formula "…": the product "…" has no Products row with no offer and no plan on any screen of the flow**, `formula_undeclared_product` | L'interface CLI Adapty ou l'API n'a pas pu publier le flow : un élément texte ou une condition utilise une [formule](flow-formulas#read-the-price-of-any-product) qui lit le prix d'un produit de votre catalogue Adapty, et aucun écran du flow ne contient ce produit sans offre ni plan de facturation. Le Flow & Paywall Builder ajoute ce type de produit automatiquement ; cette erreur ne concerne donc que les flows créés en dehors du builder. Ajoutez le produit, sans offre ni plan de facturation, aux produits de chaque écran qui utilise la formule. Relancez ensuite la publication. |
| **Formula "…" uses a name with two meanings** | Une variable de la formule porte le même nom qu'une réponse d'élément ou qu'un champ de produit. Renommez la variable. |
| **Formula "…" uses itself in a loop** | Des formules du flow se lisent mutuellement en formant une boucle, ce qui empêche le flow de les calculer. Supprimez l'une des références. |
| **Set Variable writes the formula "…"** | Une action **Set variable** modifie une formule. Une formule dépend toujours d'autres valeurs ; une action ne peut donc pas la définir. Sélectionnez une autre variable dans l'action. |
| **Variable "…" cannot show in an action** | Une variable de type Date ou une [formule](flow-formulas) est utilisée dans le titre ou le message d'une action **Show alert**, dans l'adresse d'une action **Open URL**, ou dans la valeur texte d'une action **Set variable**. Ces textes ne peuvent pas afficher une date ou un nombre calculé sur l'appareil. Retirez la variable de l'action. Pour afficher la valeur, insérez-la dans un élément texte. |
| **Missing Default Locale Content** | Une action **Open URL** possède une URL dans une autre langue mais aucune dans la langue par défaut. Ajoutez l'URL par défaut dans le [panneau **Localizations**](add-paywall-locale-in-adapty-paywall-builder). |
| **Missing product reference** | Un flow plus ancien utilise un produit qui n'est pas enregistré sur l'écran. Ouvrez l'écran et ajoutez le produit dans le panneau **Products**. |

[Prévisualisez le flow dans l'application Adapty](paywall-device-compatibility-preview) régulièrement pendant la construction. Un flow qui ne peut pas être publié ne se chargera pas non plus, et le message d'erreur identifie le problème.

:::tip
Pour savoir si votre flow est prêt pour la production, exécutez le [skill flow-audit](flow-audit-skill). Il vérifie ce que les erreurs de publication ne couvrent pas : boutons inactifs, conformité au store, textes inachevés et couverture des traductions. Pour chaque problème, le rapport indique l'élément et son écran.
:::

## La publication échoue avec « Something went wrong » sans détails \{#publishing-fails-with-something-went-wrong-and-no-details\}

<ZoomImage id="flow-publish-error.webp" width="300px" alt="Notification d'échec de publication avec l'adresse du support et le Request ID à copier" float="right" />

La requête de publication a échoué du côté d'Adapty, pas à cause de votre flow. Votre version en ligne reste inchangée. Attendez quelques minutes et publiez à nouveau. Si l'échec persiste, copiez le **Request ID** affiché dans la notification et envoyez-le à [support@adapty.io](mailto:support@adapty.io) pour que l'équipe puisse localiser la requête en échec.

## Une offre ne s'applique pas lors de l'achat \{#an-offer-doesnt-apply-at-purchase\}

Le builder vérifie uniquement que l'offre existe toujours dans Adapty. C'est le store qui décide si la réduction s'applique au moment de l'achat : les offres de lancement dépendent de l'éligibilité du client, et les offres promotionnelles App Store nécessitent une clé d'achat intégré valide. Ces deux cas sont traités dans [Incohérences de produit et de prix](store-sync#product-and-price-discrepancies).

## Le prix d'une offre est vide dans l'aperçu \{#an-offer-price-is-empty-in-the-preview\}

L'aperçu du builder ne peut pas accéder aux stores, donc `offer_price`, `offer_billing_period`, `offer_full_duration` et les variables `intro_*` affichent le nom de la variable entre accolades au lieu d'une valeur. Elles se résolvent quand le SDK affiche le flow dans votre application. Pour prévisualiser les conditions qui dépendent du type d'offre, consultez [Prévisualiser les produits et offres](paywall-device-compatibility-preview#preview-products-and-offers).

## La publication échoue après avoir saisi une couleur hex abrégée \{#publishing-fails-after-entering-a-shorthand-hex-color\}

Saisissez chaque couleur sous la forme de six chiffres hexadécimaux, par exemple `#FFFFFF`. Le champ couleur accepte une valeur plus courte sans jamais la développer : une forme abrégée comme `#FFF` parvient donc à la configuration du SDK sous une forme invalide et la publication est rejetée. L'opacité n'a rien à voir là-dedans — la même valeur échoue à 100 % d'opacité. Le cas le plus trompeur est une valeur à quatre chiffres : elle est publiée, mais affiche une couleur que vous n'avez pas choisie.

## Les modifications typographiques n'atteignent pas un état d'élément \{#typography-edits-dont-reach-an-element-state\}

Une fois qu'un état, comme **Selected**, possède ses propres paramètres typographiques, les modifications apportées à la typographie de l'état **Default** — y compris l'application d'un style de texte différent — n'affectent pas cet état. Modifiez directement la typographie de l'état concerné.

## Les contrôles de position, taille et espacement sont absents pour un élément \{#position-size-and-spacing-controls-are-missing-for-an-element\}

L'élément et son conteneur utilisent tous deux la direction **Free**. Cela ne laisse qu'une seule position et taille possible : **Absolute**, avec une largeur et une hauteur fixes. Adapty masque les contrôles pour tout le reste — le bouton **Position**, la section **Spacing**, ainsi que les options **Fill** et **Hug**. Pour retrouver ces contrôles, changez la [**Direction**](manage-paywall-ui-elements#direction) de l'élément en **Vertical** ou **Horizontal**.

## Une condition cesse de correspondre après avoir modifié l'Element ID d'une option de quiz \{#a-condition-stops-matching-after-you-change-the-element-id-of-a-quiz-option\}

Une condition qui compare l'option choisie par les utilisateurs avec une valeur, par exemple `quiz.selectedOptionId` `=` `option_1`, contient l'**Element ID** de l'option en texte brut. Lorsque vous modifiez l'**Element ID**, le builder ne met pas à jour ce texte, et la condition cesse de correspondre. Définissez l'**Element ID** de chaque option avant de l'utiliser dans une condition. Si vous le modifiez ultérieurement, mettez à jour chaque condition qui compare avec l'ancien ID.

Le builder met à jour automatiquement les autres références : les variables des champs de saisie, les identifiants de groupe, les états d'élément et les segments de barre de progression.

## Une condition ou une variable se résout en valeur vide \{#a-condition-or-variable-resolves-to-an-empty-value\}

Le sélecteur de variables liste les champs de tous les écrans, ce qui permet à une condition ou à une variable de texte de référencer une saisie que l'utilisateur n'a pas encore remplie. Au moment de l'exécution, une telle référence se résout en valeur vide. Ne référencez que les champs collectés plus tôt dans le flow.

La variable d'un [sélecteur numérique](builder-number-picker) n'est jamais vide : elle est égale au nombre par défaut tant que l'utilisateur n'a pas tourné la molette. Une condition qui évalue la variable avant que l'utilisateur n'atteigne le sélecteur peut correspondre à une réponse que l'utilisateur n'a jamais donnée.

## Les utilisateurs voient la valeur initiale d'un tag personnalisé au lieu de celle de votre application \{#users-see-a-custom-tags-initial-value-instead-of-your-apps-value\}

Les utilisateurs voient la valeur initiale d'un [tag personnalisé](flow-custom-tags) dans les cas suivants :

- **Votre application ne passe aucune valeur** : Le code qui ouvre le flow ne passe pas de valeur pour le tag, ou l'utilisateur n'a pas mis à jour votre application vers la version qui le fait.
- **Le nom ne correspond pas** : Le nom dans le code de votre application est différent du nom du tag dans le builder. Les noms sont sensibles à la casse et incluent le groupe. Par exemple, si le groupe `user` contient un tag `streak`, le nom exact du tag est `user.streak`.
- **Un autre tag dans le même élément de texte n'a pas de valeur** : Si un tag personnalisé dans un élément de texte n'a pas de valeur, tous les tags de cet élément affichent leur valeur initiale. Passez une valeur pour chaque tag personnalisé dans l'élément de texte.

L'application mobile Adapty ne transmet aucune valeur pour les tags personnalisés, donc son aperçu n'affiche que les valeurs initiales. Pour voir les valeurs transmises par votre application, ouvrez le flow dans une version de votre application.

## Les utilisateurs ne voient rien à la place d'une balise personnalisée \{#users-see-nothing-in-place-of-a-custom-tag\}

Les utilisateurs ne voient rien à la place d'une [balise personnalisée](flow-custom-tags) dans les cas suivants :

- **Votre application transmet une chaîne vide** : Adapty considère une chaîne vide comme une valeur, donc la valeur initiale n'apparaît pas en tant que solution de repli. Pour afficher la valeur initiale à la place, ne transmettez aucune valeur pour la balise.
- **La balise n'a pas de valeur initiale** : Pour afficher une solution de repli lorsque votre application ne transmet aucune valeur, saisissez une valeur initiale pour la balise.

## L'action Set variable ne change pas le produit sélectionné \{#a-set-variable-action-doesnt-change-the-selected-product\}

Le produit sélectionné n'est pas une variable que vous pouvez affecter, donc **Set variable** ne peut pas modifier la sélection. Utilisez l'action [**Select product**](onboarding-actions#select-product) à la place.

## Le flow n'exécute pas les actions définies pour un résultat d'achat \{#the-flow-doesnt-run-the-actions-set-for-a-purchase-result\}

Le flow exécute les [actions de résultat](respond-to-purchase-outcomes#add-actions-for-a-result) d'un achat ou d'une restauration d'achat lorsque le store renvoie le résultat. À ce moment-là, l'utilisateur doit se trouver sur l'écran où l'achat a démarré. Le flow les ignore dans les cas suivants :

- **Votre application ferme le flow** : Quand un achat ou une restauration se termine, votre application ferme le flow dans son callback. Pour laisser le flow continuer, [gardez le flow ouvert dans ces callbacks](respond-to-purchase-outcomes#before-you-start).
- **Une navigation s'exécute avant le résultat** : Une action **Navigate to Screen**, **Navigate Next**, **Navigate back** ou **Close Flow** suit **Purchase** ou **Restore purchases** dans le même déclencheur. Cette action s'exécute au moment du tap, donc l'utilisateur quitte l'écran avant que le store renvoie le résultat. Déplacez l'action dans un résultat, par exemple **When succeeded**.
- **L'utilisateur quitte l'écran** : L'utilisateur accède à un autre écran avant que le store renvoie le résultat, par exemple en appuyant sur le bouton retour.
- **L'achat est un achat Web Payment** : Le flow ne reçoit pas le résultat d'un achat **Web Payment**, donc une action **Purchase** configurée en **Web Payment** n'a pas de résultats. Quand vous passez l'action en **Web Payment**, le Flow & Paywall Builder supprime ses actions de résultat.

Vous ne pouvez pas effectuer de vrais achats dans l'aperçu de l'application mobile Adapty. Pour tester les actions de résultat, [effectuez un achat sandbox](test-purchases-in-sandbox) dans une version de votre application.

## Le bouton Achat ne fait rien sur Android \{#a-purchase-button-does-nothing-on-android\}

Sur Android, un appui sur le bouton **Purchase** ne fait rien si l'utilisateur appuie avant que Google Play renvoie les produits. Une fois les produits chargés, le bouton fonctionne. Sur iOS, le même appui prématuré fait échouer l'achat, et le flow exécute les actions **When failed**.

Le bouton ne fonctionne jamais dans les cas suivants :

- **Google Play ne renvoie pas le produit** : Vérifiez que le produit est actif dans Google Play Console et que le produit dans Adapty utilise le même identifiant de produit Google Play. Pour consulter le produit dans Adapty, voir [Créer un produit](create-product).
- **Les produits n'ont pas pu se charger** : Dans une application Android native, le SDK ne recharge pas les produits par défaut. Pour réessayer, retournez `true` depuis [`onLoadingProductsFailure`](android-handling-events#product-loading-errors).
- **Votre application transmet des produits au flow sans celui-ci** : Lorsque votre application transmet des [`products`](android-present-paywalls) au flow, le SDK n'en charge aucun depuis Google Play. Ajoutez chaque produit du flow à cette liste.
- **Un achat précédent n'a jamais été finalisé** : Le SDK ignore les nouveaux achats tant que le précédent n'est pas finalisé. En mode Observer, appelez `onFinishPurchase()` après chaque achat. Dans [`onAwaitingPurchaseParams`](android-handling-events#upgrade-subscription), appelez toujours `onPurchaseParamsReceived`.

Sur iOS, si l'App Store ne renvoie pas le produit, chaque tentative d'achat échoue et le flow exécute les actions **When failed**. Pour en identifier la cause, consultez [Les produits n'apparaissent pas](troubleshoot-app-store-integration#products-dont-appear).

## Une image ou une vidéo ne se télécharge pas \{#an-image-or-video-wont-upload\}

Un fichier qui dépasse les limites du Flow & Paywall Builder ne se téléchargera pas. Vérifiez le fichier par rapport aux exigences d'[Image](custom-media#image) et de [Vidéo](custom-media#video) :

| Élément | Formats | Taille maximale | Autres limites |
| :--- | :--- | :--- | :--- |
| Image | `.JPG`, `.PNG`, `.WEBP` | 20 Mo | — |
| Vidéo | `.MP4`, `.WEBM` | 50 Mo | 30 secondes maximum ; 640×640 pixels minimum |

Ces formats ne sont pas pris en charge :

- **GIF animés et WEBP animés** : pour ajouter du mouvement, utilisez un élément Vidéo à la place.
- **SVG** : exportez le fichier en PNG ou WEBP. Pour les icônes, vous n'avez rien à uploader — l'élément Icône puise dans la bibliothèque [Tabler Icons](custom-media#icon) intégrée.

## Un pied de page ne s'affiche pas \{#a-footer-doesnt-render\}

Dans un flow publié avant le 27 novembre 2026, un pied de page ne s'affiche pas sur un écran avec **Vertical scroll** désactivé. Pour afficher le pied de page, publiez à nouveau le flow : ouvrez-le dans le Flow & Paywall Builder, apportez une modification mineure pour activer [**Publish to Live**](builder-save-publish#publish-a-flow), puis cliquez dessus.
