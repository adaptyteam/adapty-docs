Cet article répertorie les problèmes les plus fréquemment rencontrés lors de la création d'un flow dans le [Flow Builder](adapty-flow-builder), avec leur cause et leur solution.

## Un flow ne peut pas être prévisualisé ou publié \{#a-flow-wont-preview-or-publish\}

<ZoomImage id="flow-publish-error.webp" width="300px" alt="Message d'erreur de publication dans l'interface web du Flow Builder lorsqu'un flow contient des actions incomplètes" float="right" />

Vous ne pouvez pas publier ni prévisualiser votre flow si l'un des problèmes suivants est présent.

- Une interaction avec une configuration incomplète. Cas fréquents :
    - Une action **Open URL** sans URL cible.
    - Une action **Navigate to screen** sans destination — se produit aussi lorsque l'écran de destination est supprimé après la configuration de l'action.
    - Une **action conditionnelle** sans opérateur ni valeur.
    - Une action **Set variable** sans assignation de variable/valeur.
    - Une action **Purchase** sans produit (store intégré) ou sans URL de Web Paywall (paiement web).
    - Une action **Custom** sans identifiant d'action (Action ID).
    - Une action **Show alert** avec un Titre ou un Message vide.
    - Une action **Show** ou **Hide** sans élément sélectionné.
    - Une action **Select product** sans produit cible — se produit aussi lorsque l'élément produit cible est supprimé, déplacé hors de son groupe de produits, ou laissé sur un autre écran.
    - Une action **Select product** enregistrée dans un composant réutilisable, ou ciblant un identifiant d'élément présent sur plusieurs écrans.
- Un **écran sans éléments**.
- Un élément produit **sans produit associé** — peut survenir si vous supprimez le produit référencé.
- Un JSON de **Remote Config** invalide bloque l'ensemble du processus de livraison — il est même impossible d'enregistrer le brouillon.

Pour détecter ces problèmes avant publication, [prévisualisez le flow dans l'application Adapty](paywall-device-compatibility-preview). Si le flow ne se charge pas, le message d'erreur vous donnera plus de détails.

## La publication échoue avec "Something went wrong" \{#publishing-fails-with-something-went-wrong\}

Cette erreur signifie que la requête de publication a échoué côté Adapty, et non que votre flow est mal configuré — c'est pourquoi le message est générique. Votre version en production reste inchangée. Copiez le **Request ID** indiqué dans le message d'erreur et envoyez-le à [support@adapty.io](mailto:support@adapty.io) pour que l'équipe puisse retrouver la requête en échec.

## Une offre ne s'applique pas lors de l'achat \{#an-offer-doesnt-apply-at-purchase\}

Le Builder vérifie que chaque élément produit est bien associé à un produit, mais ne valide pas l'offre du produit. Si l'offre est modifiée ou supprimée ultérieurement dans le store ou dans Adapty, le flow continue d'être publié et l'achat s'effectue sans l'offre. Après avoir modifié des offres, rouvrez le flow, resélectionnez l'offre pour chaque élément produit concerné, puis republiez.

## Le prix d'une offre est vide dans l'aperçu \{#an-offer-price-is-empty-in-the-preview\}

L'aperçu du builder ne peut pas accéder aux stores, donc `offer_price`, `offer_billing_period` et `offer_full_duration` affichent le nom de la variable entre accolades au lieu d'une valeur. Ces variables sont résolues lorsque le SDK affiche le flow dans votre application. Pour prévisualiser les conditions qui dépendent du type d'offre, consultez [Prévisualiser les produits et offres](paywall-device-compatibility-preview#preview-products-and-offers).

## Une couleur s'affiche mal quand l'opacité est définie \{#a-color-renders-wrong-when-opacity-is-set\}

Saisissez les couleurs sous forme de codes hexadécimaux à 6 chiffres, par exemple `#FFFFFF`. Un code abrégé comme `#FFF` combiné à une opacité inférieure à 100 % produit une couleur invalide.

## Les modifications typographiques n'atteignent pas un état d'élément \{#typography-edits-dont-reach-an-element-state\}

Une fois qu'un état, comme **Selected**, possède ses propres paramètres typographiques, les modifications apportées à la typographie de l'état **Default** — y compris l'application d'un style de texte différent — n'affectent pas cet état. Modifiez directement la typographie de l'état concerné.

## Les éléments perdent leur style après la suppression d'un style de texte \{#elements-lose-their-styling-after-a-text-style-is-deleted\}

Supprimer un [style de texte](builder-styling#text-styles) ne copie pas ses paramètres dans les éléments qui l'utilisent : ces éléments reviennent à la typographie par défaut. Avant de supprimer un style, réaffectez les éléments concernés à un autre style ou définissez manuellement leur typographie.

## Les conditions et variables se cassent après un changement d'identifiant d'élément \{#conditions-and-variables-break-after-an-element-id-change\}

Les conditions et variables texte référencent les éléments par leur **Element ID** (identifiant d'élément). Si vous modifiez cet identifiant, les références ne sont pas mises à jour automatiquement — elles cessent silencieusement de fonctionner. Définissez l'identifiant avant de l'utiliser comme référence. Si vous devez le modifier, mettez à jour chaque condition et variable qui s'y réfère. Exception : les segments de barre de progression — renommer un segment met automatiquement à jour ses références.

## Une condition ou variable renvoie une valeur vide \{#a-condition-or-variable-resolves-to-an-empty-value\}

Le sélecteur de variables liste les champs de tous les écrans, donc une condition ou une variable texte peut faire référence à une saisie que l'utilisateur n'a pas encore remplie. À l'exécution, cette référence renvoie une valeur vide. Ne faites référence qu'aux champs collectés plus tôt dans le flow.

## L'action Set variable ne change pas le produit sélectionné \{#a-set-variable-action-doesnt-change-the-selected-product\}

Le produit sélectionné n'est pas une variable que vous pouvez affecter, donc **Set variable** ne peut pas modifier la sélection. Utilisez l'action [**Select product**](onboarding-actions#select-product) à la place.

## Une image ou une vidéo ne se charge pas \{#an-image-or-video-wont-upload\}

Un fichier qui dépasse les limites de médias du Flow Builder ne sera pas chargé. Vérifiez le fichier par rapport aux exigences pour les [Images](custom-media#image) et les [Vidéos](custom-media#video) :

| Élément | Formats | Taille maximale | Autres limites |
| :--- | :--- | :--- | :--- |
| Image | `.JPG`, `.PNG`, `.WEBP` | 20 Mo | — |
| Vidéo | `.MP4`, `.WEBM` | 50 Mo | 30 secondes maximum ; 640×640 pixels minimum |

Ces formats ne sont pas pris en charge :

- **GIF animés et WEBP animés** : pour ajouter du mouvement, utilisez un élément Vidéo à la place.
- **SVG** : exportez le fichier en PNG ou WEBP. Pour les icônes, vous n'avez rien à uploader — l'élément Icône puise dans la bibliothèque [Tabler Icons](custom-media#icon) intégrée.

## Un pied de page ne s'affiche pas \{#a-footer-doesnt-render\}

Un pied de page s'affiche uniquement sur un écran où le **Défilement vertical** est activé. Activez le **Défilement vertical** dans [**Screen settings** > **Scroll**](paywall-layout-and-products#scroll).
