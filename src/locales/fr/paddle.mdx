Adapty prend en charge les flows web2app en suivant les paiements et abonnements web effectués via [Paddle](https://www.paddle.com/).

Cette intégration couvre les achats initiés depuis le web et les synchronise avec l'accès à l'application mobile et les analytics, en complément des achats intégrés depuis les stores.

Cela s'avère utile dans les scénarios suivants :

- Collecter les données d'abonnement provenant à la fois des achats intégrés et des achats effectués sur le site web dans un seul système
- Accorder l'accès aux fonctionnalités payantes de votre application mobile aux utilisateurs ayant acheté sur votre site web
- Consulter les analyses et les données d'abonnement de tous les canaux de vente dans un seul tableau de bord

:::note
Apple autorise désormais les applications de l'App Store américain à inclure des liens vers des systèmes de paiement externes, bien que les applications puissent encore avoir besoin de proposer des achats intégrés en parallèle des options externes. Consultez les directives App Store en vigueur pour votre région et votre catégorie d'application.
:::

:::note
Cette intégration porte sur le suivi et la synchronisation des achats web Paddle. Si vous souhaitez rediriger les utilisateurs de l'application vers une page de paiement web, utilisez les [paywalls web](web-paywall) d'Adapty.
:::

Pour configurer l'intégration Paddle, suivez ces étapes :

## 1\. Connecter Paddle à Adapty \{#1-connect-paddle-to-adapty\}

L'intégration utilise des webhooks pour envoyer les données d'abonnement de Paddle vers Adapty. Pour connecter vos comptes Adapty et Paddle, vous devez :

1. Fournir vos clés API Paddle.
2. Ajouter l'URL du webhook Adapty à Paddle.

:::note
Les étapes ci-dessous s'appliquent à la fois à la Production et au Test. Vous pouvez configurer les deux simultanément. Les liens fournis correspondent à l'environnement de Production — pour obtenir les liens de l'environnement de Test, ajoutez simplement `sandbox-` au début de chaque URL. Par exemple, utilisez `https://sandbox-vendors.paddle.com/authentication-v2` à la place de `https://vendors.paddle.com/authentication-v2`.
:::

### 1.4. Associer les clients Paddle aux profils Adapty \{#14-match-paddle-customers-with-adapty-profiles\}

Adapty doit lier chaque achat à un [profil client](profiles-crm) pour qu'il puisse être utilisé dans votre application. Par défaut, les profils sont créés automatiquement lorsque Adapty reçoit des webhooks de Paddle. Vous pouvez choisir la valeur à utiliser comme `customer_user_id` dans Adapty :

1. **Par défaut et recommandé :** Le `customer_user_id` que vous passez dans le champ `custom_data` (voir [la documentation Paddle](https://developer.paddle.com/build/transactions/custom-data))
2. L'`email` de l'objet Paddle Customer (voir [la documentation Paddle](https://developer.paddle.com/paddle-js/methods/paddle-checkout-open/#parameters))
3. L'identifiant Paddle Customer au format `ctm-...` (voir [la documentation Paddle](https://developer.paddle.com/paddle-js/methods/paddle-checkout-open/#parameters))
4. Ne pas créer de profils. Choisissez cette option si vous souhaitez avoir plus de contrôle sur vos profils client et les gérer vous-même.

Vous pouvez configurer la valeur à utiliser dans le champ **Profile creation behavior** dans [App Settings → Paddle](https://app.adapty.io/settings/paddle).

## 2. Ajouter les produits Paddle à Adapty

:::warning

Assurez-vous d'ajouter vos produits Paddle à l'Adapty Dashboard ou d'associer un identifiant de produit Paddle à vos produits existants. Adapty ne suit les événements que pour les transactions liées à ces produits. Si vous sautez cette étape, aucun événement de transaction ne sera créé.

:::

Paddle fonctionne dans Adapty exactement comme l'App Store et Google Play — c'est simplement une autre plateforme sur laquelle vous vendez des produits numériques. Pour le configurer, ajoutez les valeurs `product_id` et `price_id` correspondantes depuis Paddle dans la section [Products](https://app.adapty.io/products) d'Adapty.

## 3\. Accorder l'accès aux utilisateurs sur mobile \{#3-provide-access-to-users-on-the-mobile\}

Pour que les utilisateurs qui achètent sur le web obtiennent un accès sur mobile, appelez `Adapty.activate()` ou `Adapty.identify()` en utilisant le même `customer_user_id` que celui transmis lors de l'achat. Consultez [Identifier les utilisateurs](identifying-users) pour en savoir plus.

## 4\. Testez votre intégration \{#4-test-your-integration\}

Une fois tout configuré, vous pouvez tester votre intégration. Les transactions effectuées dans l'environnement Test de Paddle apparaîtront comme **Test** dans Adapty. Les transactions de l'environnement Production apparaîtront comme **Production**.

Votre intégration est maintenant terminée. Les utilisateurs peuvent acheter des abonnements sur votre site web et accéder automatiquement aux fonctionnalités premium dans votre application mobile, pendant que vous suivez toutes les analyses d'abonnements depuis votre tableau de bord Adapty unifié.

## Considérations importantes \{#important-considerations\}

- Dans les analyses d'Adapty, les montants des transactions incluent les taxes et les frais Paddle, contrairement au tableau de bord Paddle où les montants sont affichés après déduction des taxes et frais. Les chiffres affichés dans Adapty seront donc plus élevés que ceux de votre tableau de bord Paddle.
- Contrairement aux autres stores, les remboursements dans Paddle n'affectent que la transaction concernée et n'annulent pas automatiquement l'abonnement. L'abonnement reste actif sauf s'il est explicitement annulé.
- Vous pouvez également inclure `variation_id` dans le champ `custom_data` pour attribuer les achats à des instances de paywall spécifiques. Adapty traitera ces données depuis les webhooks et les inclura dans les analyses.

### Essais payants \{#paid-trials\}

Lorsque vous utilisez des essais payants dans Paddle, vous devez créer deux produits dans Adapty :

1. Créez un produit non-abonnement et liez-le au prix Paddle qui facture la période d'essai.
2. Créez ensuite un produit d'abonnement (mensuel/hebdomadaire/etc.) et liez-le au prix Paddle qui comporte le composant d'essai gratuit.

Du point de vue de Paddle, il s'agit d'un seul produit avec deux prix dans une même transaction : un prix pour la facturation de l'essai (par exemple, 0,99 $) et un autre prix pour l'essai gratuit (0,00 $).

Du point de vue d'Adapty, cela crée deux événements distincts : un achat unique pour le paiement de l'essai et un événement de démarrage d'essai pour le produit d'abonnement.

Par exemple, quand un utilisateur commence un essai payant à 0,99 $ pour un abonnement à 9,99 $/mois, Paddle crée une seule transaction avec les deux prix, tandis qu'Adapty traite cela comme un achat unique de 0,99 $ (paiement immédiat) et un événement de démarrage d'essai à 0,00 $ (abonnement futur à 9,99 $/mois).

:::note
Lorsque des utilisateurs annulent un essai payant, vous recevez les événements **Trial expired** et **Trial renewal canceled**.
:::

## Tirez le meilleur parti de vos données Paddle \{#get-more-from-your-paddle-data\}

:::important
Pour que vos événements Paddle fonctionnent avec les intégrations, vos utilisateurs doivent s'être connectés à l'application avec leur compte App Store/Google Play au moins une fois.
:::

Une fois l'intégration Paddle effectuée, Adapty est prêt à vous fournir des insights immédiatement. Pour exploiter au maximum vos données Paddle, vous pouvez configurer des intégrations Adapty supplémentaires afin de transférer les événements Paddle — et centraliser toutes vos analyses d'abonnements dans un seul Adapty Dashboard.

Intégrations disponibles pour transmettre et analyser vos événements Paddle :
- [Amplitude](amplitude)
- [AppsFlyer](appsflyer)
- [Firebase / Google Analytics](firebase-and-google-analytics)
- [Mixpanel](mixpanel)
- [Posthog](posthog)
- [Webhook](webhook)

Amplitude, Firebase / Google Analytics et Mixpanel conservent des identifiants distincts par plateforme. Renseignez les champs **Paddle** sur la page d'intégration — les événements Paddle n'utilisent pas vos identifiants iOS ou Android.

## Limitations actuelles \{#current-limitations\}

- **Annulations** : Paddle propose deux options d'annulation d'abonnement :

  1. Annulation immédiate : L'abonnement est annulé immédiatement.

  2. Annulation en fin de période : L'abonnement est annulé à la fin de la période de facturation en cours (comme les abonnements intégrés sur les stores).

- **Remboursements** : Adapty suit les remboursements complets et partiels.

- **Délai de grâce** : Par défaut, Paddle applique un délai de grâce fixe de 30 jours pour les problèmes de facturation, pendant lequel l'abonnement reste actif. Vous pouvez [personnaliser la durée du délai de grâce et l'action à effectuer à son terme (suspension ou annulation de l'abonnement)](https://developer.paddle.com/build/retain/configure-payment-recovery-dunning#prerequisites).

**Essais** : Si la collecte du paiement échoue après la fin d'un essai, le statut de l'abonnement passe à `past_due`. En production, Retain de Paddle applique une fenêtre de relance pour tenter de récupérer le paiement avant que l'abonnement ne soit annulé ou mis en pause. En sandbox, Retain n'est pas disponible, donc aucune nouvelle tentative de paiement n'est effectuée et l'abonnement reste `past_due` indéfiniment.
