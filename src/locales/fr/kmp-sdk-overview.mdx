Bienvenue ! Nous sommes là pour simplifier vos achats intégrés 🚀

Nous avons conçu le SDK Kotlin Multiplatform d'Adapty pour vous éviter les tracas liés aux achats intégrés, afin que vous puissiez vous concentrer sur ce que vous faites le mieux : créer des applications extraordinaires. Voici ce que nous prenons en charge pour vous :

- Gérez les achats, la validation des reçus et la gestion des abonnements sans configuration
- Créez et testez des paywalls sans mise à jour de l'application
- Accédez à des analyses d'achats détaillées sans aucune configuration — cohortes, LTV, churn et analyse des entonnoirs inclus
- Gardez le statut d'abonnement des utilisateurs toujours à jour entre les sessions et les appareils
- Intégrez votre application aux services d'attribution marketing et d'analyse avec une seule ligne de code

:::note
Avant de plonger dans le code, vous devrez intégrer Adapty avec Google Play Console et configurer les produits dans le tableau de bord. Consultez notre [guide de démarrage rapide](quickstart) pour tout configurer en premier.
:::

## Concepts principaux \{#main-concepts\}

Avant de plonger dans le code, familiarisons-nous avec les concepts clés qui font fonctionner Adapty.

L'avantage de l'approche d'Adapty, c'est que seuls les placements sont codés en dur dans votre application. Tout le reste – produits, designs de paywall, tarifs et offres – peut être géré de façon flexible depuis l'Adapty Dashboard sans mise à jour de l'application :

1. [**Produit**](product) - Tout ce qui est disponible à l'achat dans votre application – abonnement, produit consommable ou accès à vie.

2. **Flow ou paywall** - Produits regroupés avec une configuration, attachés à un placement. Deux possibilités :
   - **[Flow](adapty-flow-builder)** - Interface visuelle sans code, créée dans le Flow Builder. Adapty génère l'UI et gère l'achat pour vous.
   - **[Paywall](paywalls)** - Pas de configuration visuelle ; vous construisez l'UI dans votre propre code et appelez `makePurchase` vous-même. Voir [Implémenter les paywalls manuellement](kmp-quickstart-manual).

   Dans le code du SDK, les deux sont récupérés via la même méthode `getFlow`.

3. [**Placement**](placements) - Un point stratégique dans le parcours utilisateur où vous souhaitez afficher un flow ou un paywall. Les placements représentent le « où » et le « quand » de votre stratégie de monétisation. Voici quelques placements courants :
   - `main` - Votre emplacement principal de paywall
   - `onboarding` - Affiché pendant le flow d'onboarding
   - `settings` - Accessible depuis les paramètres de votre application

   Commencez par les bases comme `main` ou `onboarding` pour votre première intégration, puis [réfléchissez aux autres endroits de votre application où vos utilisateurs pourraient être prêts à acheter](choose-meaningful-placements).

4. [**Profil**](profiles-crm) - Quand des utilisateurs achètent un produit, leur profil se voit attribuer un **niveau d'accès** que vous utilisez pour définir l'accès aux fonctionnalités payantes.
