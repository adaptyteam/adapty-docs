Avec l'intégration TikTok for Business d'Adapty Attribution, vous pouvez suivre et optimiser vos campagnes TikTok.

:::tip
Consultez notre [guide de configuration des publicités dans TikTok for Business](tiktok-create-campaign).
:::

## Étape 1. Connecter votre compte TikTok \{#step-1-connect-your-tiktok-account\}

1. Accédez à **Integrations > TikTok Ads** depuis la barre latérale gauche et cliquez sur **Continue with TikTok**.

<ZoomImage id="ua-connect-tiktok.webp" width="700px" />

2. Connectez-vous avec votre compte TikTok et cliquez sur **Continue**.

3. Vérifiez les autorisations demandées et cliquez sur **Save**.

<ZoomImage id="ua-tiktok-sign.webp" width="500px" />

Ensuite, tous vos comptes publicitaires seront ajoutés à Adapty Attribution. Vous pouvez alors passer à l'ajout de campagnes.

## Étape 2. Ajouter des campagnes \{#step-2-add-campaigns\}

Une seule campagne peut couvrir l'App Store, le Google Play et votre funnel web en même temps. Deux éléments assurent la connexion :

- **Lien de suivi** : À intégrer dans votre annonce. Quand un utilisateur appuie sur l'annonce, Adapty enregistre le clic, redirige l'utilisateur vers la destination, puis attribue l'installation et les achats à cette annonce. Chaque destination possède son propre lien.
- **Pixel** : Sélectionné dans la campagne, parmi les pixels de votre compte TikTok. Renvoie ces conversions à TikTok afin que TikTok puisse optimiser la campagne sur la base d'achats réels. Un seul pixel peut couvrir les trois destinations, ou chaque destination peut avoir le sien.

Pour ajouter une campagne TikTok for Business à Adapty Attribution et suivre les performances de vos annonces TikTok dans Adapty :

1. Basculez vers l'application que vous souhaitez promouvoir.

2. Ouvrez l'onglet **Web Campaigns** et cliquez sur **Create configuration**. Cette configuration ne comptabilise que les installations de l'application vers laquelle vous avez basculé.

   <ZoomImage id="ua-new-campaign-tiktok.webp" width="500px" />

3. Dans l'onglet **General**, développez la section **iOS** et/ou **Android** et collez les URL de l'application depuis l'App Store et/ou Google Play.

   <ZoomImage id="ua-url.webp" width="900px" />

4. Copiez la valeur du champ **Click link**. Ensuite, dans TikTok Ads Manager, lors de la création de votre annonce, collez cette valeur dans le champ **Destination URL**, comme décrit dans [Ajouter le contenu de l'annonce](tiktok-create-campaign#step-5-add-ad-content). Cela permettra à Adapty de relier les installations et les achats aux annonces dans TikTok. Adapty ne relie les installations à votre annonce que lorsque les utilisateurs passent directement de celle-ci au store via ce lien.

   <ZoomImage id="ua-lnk.webp" width="900px" />

5. (Optionnel) Pour renvoyer les événements de conversion à TikTok, associez vos pixels TikTok à cette configuration :
   1. Dans le menu déroulant **Pixel**, sélectionnez le pixel utilisé par votre campagne dans TikTok Ads Manager. Si vous n'avez pas encore de pixel, [créez-en un dans TikTok](tiktok-create-campaign#step-2-create-a-pixel).
   2. Pour vérifier la connexion, cliquez sur **Send test event**.

6. Si vos publicités mènent à un funnel web, développez la section **Web funnel** de la configuration :
   1. (Facultatif) Dans le menu déroulant **Pixel**, sélectionnez le pixel pour les achats web. TikTok ne prend connaissance des achats sur votre funnel que via ce pixel.
   2. Pour installer le [pixel web Adapty](ua-web-pixel), collez le **Pixel snippet** sur chaque page de votre funnel.
   3. Pour [taguer les URL de vos publicités](ua-tag-ad-urls), copiez les **Ad URL parameters**.

   Si votre funnel fonctionne sur [FunnelFox](ua-funnelfox), ignorez l'extrait. Adapty n'envoie pas les achats FunnelFox à TikTok. Pour les envoyer, configurez l'[intégration TikTok Pixel](https://funnelfox.com/docs/integrations/tracking/tiktok-pixel) dans FunnelFox.

Pour configurer vos pixels correctement :

- **Faites correspondre les pixels à vos campagnes** : si une campagne couvre l'App Store, Google Play et votre funnel web, sélectionnez le même pixel dans les trois sections. Si vous gérez une campagne distincte pour chacun, sélectionnez un pixel distinct pour chacun, afin que chaque campagne optimise sur ses propres achats. La liste **Web Campaigns** affiche les pixels de chaque configuration dans les colonnes **Pixel (iOS)**, **Pixel (Android)** et **Pixel (Web)**.
- **Modifiez la configuration existante pour changer de pixel** : les publicités en cours conservent le lien de clic de leur configuration, donc leurs conversions sont attribuées aux pixels de cette configuration. Pour changer le pixel des publicités en cours, sélectionnez un autre pixel dans cette configuration. Une nouvelle configuration ne modifie pas la destination de leurs conversions.
- **Renseignez l'URL source de l'événement** : si vous avez connecté votre pixel à votre site web dans TikTok, saisissez l'adresse du site dans le champ **Event source URL** de la configuration. Sinon, TikTok risque de considérer les conversions provenant d'Adapty comme issues d'un site web inconnu. Ce champ ne modifie pas l'adresse de vos liens de suivi.

## Étape 3. Associer les événements \{#step-3-map-events\}

Adapty envoie les événements que vous sélectionnez, comme les essais démarrés, aux pixels de la configuration. TikTok utilise ces événements pour trouver des personnes susceptibles de démarrer un essai ou de souscrire un abonnement.

Pour sélectionner les événements, dans la section **Events mapping** de la configuration :

1. Activez chaque événement qu'Adapty doit envoyer à TikTok.
2. Pour chaque événement, sélectionnez un événement TikTok dans la liste déroulante, ou saisissez un événement personnalisé. Par défaut, Adapty sélectionne les événements standard de TikTok. **Install** ne peut être envoyé qu'en tant que **Lead**.
3. Cliquez sur **Save**.

## Configuration supplémentaire \{#additional-configuration\}

### Paramètres supplémentaires \{#additional-parameters\}

Le champ **Additional parameter** vous permet d'ajouter des données personnalisées pour une analyse en dehors d'Adapty. C'est utile lorsque vous avez besoin de transmettre des données spécifiques de campagne ou d'utilisateur à des outils d'analyse externes ou à des partenaires d'attribution.

Dans le champ **Additional parameter**, saisissez les données personnalisées que vous souhaitez inclure dans votre suivi d'attribution. Le paramètre supplémentaire sera inclus dans toutes les données d'attribution envoyées à TikTok et peut être utilisé pour une analyse et une optimisation avancées des campagnes.

Par exemple, si vous exécutez plusieurs variations de la même campagne, vous pouvez ajouter `variant=A` ou `variant=B` pour distinguer les différentes approches créatives.

:::important
Les paramètres supplémentaires modifient le **Click link** que vous collez dans TikTok Ads Manager. Si vous avez déjà copié ce lien et ajouté un paramètre personnalisé ensuite, assurez-vous de copier-coller le lien mis à jour qui contient ce paramètre.
:::

### Paramètres \{#settings\}

L'onglet **Settings** d'une configuration détermine comment Adapty associe les installations aux clics sur vos publicités TikTok. Adapty utilise l'une des deux méthodes suivantes :

| Méthode | Installations | Comment Adapty attribue l'installation | Délai entre le clic et l'installation |
|---|---|---|---|
| Correspondance par click ID | Installations Android avec un click ID | Au clic dont l'ID est transmis à votre app par Google Play | 168 heures (7 jours) par défaut, jusqu'à 720 heures |
| Correspondance probabiliste | Installations iOS, et installations Android sans click ID | Au clic récent le plus probable depuis la même plage d'adresses IP et le même système d'exploitation | 6 heures par défaut, jusqu'à 24 heures |

Pour une correspondance probabiliste, Adapty sélectionne le clic qui obtient le meilleur score en fonction du délai depuis le clic, de la langue de l'appareil et du pays. Adapty n'utilise ni l'IDFA ni le Google Advertising ID, donc la correspondance probabiliste couvre les utilisateurs iOS qui n'autorisent pas le suivi.

Adapty ne peut pas associer une installation de manière probabiliste si l'appareil change de réseau entre le clic et l'installation, par exemple de Wi-Fi vers le réseau cellulaire. Sur les réseaux partagés par de nombreux appareils, comme les réseaux des opérateurs mobiles, Adapty associe moins d'installations de manière probabiliste.

Pour modifier les limites de temps, dans la section **New user attribution** de l'onglet **Settings**, saisissez chaque limite en heures :

- **Deterministic Matching Window** : Pour une correspondance par identifiant de clic.
- **Probabilistic Matching Window** : Pour une correspondance probabiliste. Une limite plus longue correspond à davantage d'installations, mais un plus grand nombre de ces correspondances sont incorrectes. Pour les campagnes à fort volume de clics, réduisez-la à 1–2 heures. Si vous définissez plus de 6 heures, les clics survenus plus de 6 heures avant l'installation doivent également correspondre au modèle d'appareil et à la version du système d'exploitation de l'installation.

Gardez les interrupteurs des deux champs activés. Sans correspondance probabiliste, Adapty ne peut pas associer les installations iOS aux liens de cette configuration.

### Revenus envoyés à TikTok \{#revenue-sent-to-tiktok\}

TikTok utilise la valeur de chaque événement pour calculer le ROAS et optimiser les enchères basées sur la valeur. Pour choisir quels revenus Adapty envoie à TikTok comme valeur, dans le menu déroulant **Revenue sent to TikTok**, sélectionnez un type de revenu et cliquez sur **Save**. Pour comparer le ROAS dans TikTok avec le ROAS dans Adapty, sélectionnez le type que vous [affichez dans les analyses Adapty](controls-filters-grouping-compare-proceeds#display-gross-or-net-revenue).

<ZoomImage id="ua-revenue-sent-tiktok.webp" width="700px" alt="Menu déroulant « Revenue sent to TikTok » ouvert, avec les options Gross revenue, Proceeds after store commission et Proceeds after store commission and taxes" />

| Type de revenu | Valeur d'un achat App Store ou Google Play |
|---|---|
| **Revenu brut** (par défaut) | Le prix total payé par l'utilisateur, avant commission du store et taxes. |
| **Recettes après commission du store** | Le prix moins la commission de l'App Store ou de Google Play. Les taxes sont toujours incluses. |
| **Recettes après commission du store et taxes** | Le prix moins la commission du store et les taxes. |

Pour en savoir sur le calcul des commissions et taxes par Adapty, consultez [Commissions et taxes](how-adapty-analytics-works#commissions-and-taxes).

Comment ce type s'applique dans les autres cas :

- **Achats web** : pour les achats Stripe et Paddle, les deux types de recettes envoient la même valeur, comme dans l'analyse Adapty Attribution : le prix moins 4,5 % pour Stripe, et le prix total pour Paddle. Adapty ne déduit pas les taxes des achats web.
- **Remboursements** : TikTok reçoit les événements de remboursement sans valeur, quel que soit le type.
- **Événements d'essai** : le pourcentage de [Remplacement de revenus](#revenue-override) s'applique au prix d'abonnement du type sélectionné.
- **Achats sans montant du type sélectionné** : Adapty envoie à TikTok le revenu brut de l'achat.

Un nouveau type de revenus prend effet dans les 5 minutes suivant l'enregistrement et s'applique uniquement aux nouveaux événements. Adapty ne renvoie pas les événements déjà envoyés, et un événement d'essai qu'Adapty conserve pour un [Essai qualifié](#qualified-trial) est envoyé avec le type sélectionné au début de la période de rétention.

Si plusieurs configurations envoient des événements au même pixel, sélectionnez le même type de revenus dans chacune d'elles, afin que les valeurs dans ce pixel soient d'un seul et même type.

:::warning
Les revenus nets sont inférieurs au chiffre d'affaires brut. Si vous passez de **Gross revenue** et qu'une campagne utilise un ROAS minimum, réduisez ce ROAS minimum dans TikTok, sinon la campagne risque de s'arrêter.
:::

### Remplacement du revenu \{#revenue-override\}

Par défaut, Adapty envoie l'événement **Trial started** à TikTok sans valeur de revenu, car aucun paiement n'a lieu au démarrage d'un essai. Avec un remplacement du revenu, Adapty envoie la valeur que vous définissez : un pourcentage du prix de l'abonnement. Adapty applique ce pourcentage sur le prix selon le type sélectionné dans [Revenue sent to TikTok](#revenue-sent-to-tiktok). Par exemple, à 30 %, Adapty envoie 30 % du prix de l'abonnement. **Trial converted** et **Subscription started** conservent toujours leur revenu réel.

Un remplacement de revenu modifie la valeur envoyée à TikTok pour un essai. Un [essai qualifié](#qualified-trial) modifie le moment où TikTok le reçoit. Vous pouvez utiliser les deux pour le même événement.

Pour signaler des revenus à TikTok pour les essais démarrés :

1. Dans la section **Events mapping**, activez l'événement **Trial started**. La section **Revenue override** apparaît.
2. Dans la section **Revenue override**, cliquez sur **Add event**.
3. Sélectionnez l'événement TikTok que vous avez mappé à **Trial started**, par exemple **StartTrial**.
4. Saisissez le pourcentage du prix de l'abonnement à envoyer, de 0 à 100.
5. Cliquez sur **Save**.

<ZoomImage id="revenue-override.webp" width="500px" />

### Essai qualifié \{#qualified-trial\}

:::important
Les rapports sur les essais qualifiés nécessitent les [Notifications du serveur App Store](enable-app-store-server-notifications) pour iOS et les [Notifications en temps réel pour les développeurs](enable-real-time-developer-notifications-rtdn) pour Android. L'App Store et Google Play signalent les annulations d'essai à Adapty via ces canaux.
:::

Par défaut, Adapty envoie chaque essai démarré à TikTok immédiatement, même si l'utilisateur l'annule peu après. Avec un essai qualifié, TikTok ne comptabilise que les essais que les utilisateurs conservent — c'est-à-dire ceux dont le renouvellement automatique n'a pas été désactivé dans un délai défini après le début de l'essai. Adapty envoie l'événement avec l'heure de début d'essai d'origine, de sorte que TikTok le rapporte à la date à laquelle l'essai a commencé. Si l'événement comporte également un remplacement de revenus, Adapty l'envoie avec les revenus remplacés.

Pour n'envoyer à TikTok que les essais que les utilisateurs conservent :

1. Dans la section **Events mapping**, activez l'événement **Trial started**.
2. Dans la section **Qualified trial**, cliquez sur **Add event**.
3. Sélectionnez l'événement TikTok que vous avez associé à **Trial started**, par exemple **StartTrial**.
4. Entrez le nombre d'heures d'attente, de 1 à 24. Adapty envoie l'événement environ 45 minutes après la fin de l'attente.
5. Cliquez sur **Save**.

<ZoomImage id="qualified-trial.webp" width="700px" alt="Section Qualified trial avec un événement cible retenu pendant deux heures dans une configuration de campagne" />

Si l'utilisateur réactive le renouvellement automatique avant la fin du délai, Adapty envoie l'événement comme prévu. Les trials qualifiés s'appliquent uniquement aux trials de l'App Store et de Google Play.

#### Trials qualifiés vs. l'événement Trial still active \{#qualified-trials-vs-the-trial-still-active-event\}

Adapty propose deux façons de ne signaler que les trials que les utilisateurs conservent. Pour TikTok, utilisez un trial qualifié : Adapty Attribution ne peut pas envoyer l'événement [Trial still active](events#synthetic-events) à TikTok. Si une autre intégration, comme AppsFlyer, envoie également des trials à TikTok, TikTok reçoit le même trial plusieurs fois.

| | Essai qualifié | Événement **Trial still active** |
|---|---|---|
| Où le configurer | Dans Adapty Attribution, dans une configuration Meta, TikTok ou Google Ads | Dans Adapty, dans des intégrations comme AppsFlyer, Adjust, Firebase ou le webhook |
| Ce que ça fait | Retarde l'événement **Trial started** | Ajoute un événement séparé après **Trial started** |
| Délai d'attente | 1 à 24 heures | 1 heure à 90 jours |
| Si l'utilisateur désactive le renouvellement automatique avant la fin du délai | Adapty n'envoie pas l'événement | Adapty n'envoie pas l'événement |
| Envoyé à TikTok par Adapty Attribution | Oui | Non |

### Envoyer des événements depuis tous les utilisateurs \{#send-events-from-all-users\}

Par défaut, Adapty ne rapporte que les événements des utilisateurs qu'il attribue à cette configuration. L'option **Send events from all users** rapporte les événements de tous les utilisateurs de votre application, y compris les utilisateurs organiques, les utilisateurs provenant d'autres réseaux publicitaires et les utilisateurs de vos autres configurations TikTok. Les achats issus des funnels FunnelFox font exception : Adapty les utilise uniquement dans les analyses d'attribution Adapty. Pour les envoyer à TikTok, configurez l'[intégration TikTok Pixel](https://funnelfox.com/docs/integrations/tracking/tiktok-pixel) dans FunnelFox. TikTok décide ensuite lesquelles de ces conversions attribuer à ses publicités. Cette option ne modifie pas l'attribution dans Adapty.

Nous ne le recommandons pas, sauf si vos campagnes envoient trop peu de conversions à TikTok pour permettre une optimisation, car le mélange d'événements organiques et non attribués avec les événements de vos campagnes réduit la précision de l'optimisation TikTok.

Si vous décidez de l'activer, sélectionnez **Send events from all users** dans les paramètres de configuration et cliquez sur **Save**.

## Lire correctement les données TikTok Ads dans Adapty Attribution \{#read-tiktok-ads-data-correctly-in-adapty-attribution\}

Pour comparer les dépenses TikTok avec vos installations et revenus dans [Adapty Attribution analytics](ua-analytics) :

- **Les dépenses récentes peuvent varier** : TikTok continue d'ajuster les dépenses, impressions et clics des derniers jours. Toutes les 4 heures, Adapty actualise ces données pour les 3 derniers jours, y compris aujourd'hui.
- **Les dépenses et revenus quotidiens peuvent utiliser des fuseaux horaires différents** : Adapty Attribution affiche les dépenses TikTok par jour dans le fuseau horaire de votre compte publicitaire. Les installations et revenus sont affichés par jour en UTC. Si les deux fuseaux horaires diffèrent, les dépenses et revenus quotidiens ne couvrent pas les mêmes heures. Pour afficher les installations et revenus dans un autre fuseau horaire, contactez le [support Adapty](mailto:support@adapty.io).
