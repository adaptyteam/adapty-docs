Pour déterminer quels messages améliorent la rétention et lesquels laissent les utilisateurs se désabonner, consultez leurs analyses sur la page Retention Messaging. Le tableau indique combien d'abonnés chaque message actif a atteints, et combien d'entre eux sont restés.

Le tableau ne comporte pas de plage de dates : chaque métrique couvre toute la durée de vie du message. Le bouton **Sandbox mode** permet de basculer le tableau entre la production et le sandbox.

## Ce que signifie chaque métrique \{#what-each-metric-means\}

| Métrique | Ce qu'elle mesure |
| --- | --- |
| **Shown** | Le nombre de fois où un abonné a vu ce message sur l'écran d'annulation d'abonnement. Les vues répétées d'un même abonné le même jour ne sont pas comptabilisées. |
| **Retained** | Les abonnés de la cohorte **Shown** qui ont abandonné l'annulation et ont continué à payer pour l'abonnement qu'ils souhaitaient résilier. |
| **Retention rate** | **Retained** divisé par l'ensemble des membres de la cohorte **Shown** qui ont déjà payé ou annulé. Ceux qui attendent encore leur prochain paiement sont exclus. |

Les trois métriques comptabilisent les tentatives d'annulation, pas les personnes. Un abonné qui revient trois jours différents est comptabilisé trois fois. Ce que fait ensuite l'abonné détermine le résultat des trois tentatives de la même façon. S'il paie, les trois tentatives sont comptabilisées comme **Retained**. S'il annule, les trois comptent comme un churn.

## Dépannage \{#troubleshooting\}

### Les chiffres ne correspondent pas \{#the-numbers-dont-add-up\}

Adapty ne peut pas voir ce qui se passe sur l'écran d'annulation d'abonnement. Il utilise les événements d'abonnement pour déterminer si l'utilisateur a confirmé l'annulation.

- Si l'abonnement a été annulé, l'utilisateur est comptabilisé comme perdu.
- Si l'abonnement a été renouvelé, l'utilisateur est comptabilisé comme retenu.
- Les personnes qui ont fermé l'écran d'annulation sans ni annuler ni renouveler l'abonnement ne contribuent pas au taux de rétention.

Si un utilisateur annule, puis revient — par exemple parce que vous lui avez envoyé un code promo — cet utilisateur **n'est pas** comptabilisé comme retenu.

:::note
Les annulations d'essai sont également soumises aux messages de rétention. Un essai est considéré comme « retenu » si l'utilisateur n'annule pas l'essai et devient abonné payant.
:::

### Un message par défaut affiche moins de vues que le message promotionnel \{#a-default-message-shows-fewer-views-than-the-promo-message\}

Le même produit peut avoir à la fois un message promotionnel et un message par défaut (de secours). Le message par défaut affichera toujours moins de vues.
