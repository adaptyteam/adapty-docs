Lors de l'utilisation d'intégrations d'attribution, de messagerie ou d'analytique, vous pouvez rencontrer certaines erreurs courantes. Consultez ce guide pour les cas de dépannage.

## Écart de données \{#data-discrepancy\}

**Cause** : Cela peut se produire parce que tous vos utilisateurs n'utilisent pas la version de l'application qui intègre le SDK Adapty.

**Solution** : Pour garantir la cohérence des données, vous pouvez forcer vos utilisateurs à mettre à jour l'application vers une version intégrant le SDK Adapty.

## Erreurs réseau \{#network-errors\}

**Raison** : Il est fort probable qu'il n'y ait pas eu de connexion Internet entre le serveur Adapty et le serveur d'intégration.

**Solution** : Ces problèmes ne durent généralement pas longtemps et n'affectent qu'un petit nombre d'événements.

## Le serveur d'intégration n'a pas pu traiter l'événement \{#integration-server-failed-to-process-the-event\}

**Raison** : L'intégration est mal configurée.

**Solution** : Consultez l'article correspondant à l'intégration dans notre documentation. Assurez-vous d'avoir suivi toutes les étapes de configuration dans l'Adapty Dashboard, du côté de l'outil tiers, et dans le code de votre application.

## Données d'intégration manquantes \{#missing-integration-data\}

**Raison** : Le profil ne possède pas certains identifiants propres à l'intégration. Cela peut se produire lorsque l'intégration n'est pas correctement configurée dans le code de l'application.

**Solution** : Consultez l'article correspondant à l'intégration dans notre documentation. Assurez-vous d'avoir implémenté les méthodes issues des extraits de code dans votre application, et que ces méthodes interagissent bien avec les profils utilisateurs.

## Identifiants d'intégration manquants \{#missing-integration-credentials\}

**Raison** : Certains identifiants d'intégration sont manquants ou incorrects.

**Solution** : Vérifiez tous les identifiants pour cette intégration dans l'Adapty Dashboard. Le problème peut survenir en raison d'une incompatibilité de version ou d'environnement.

## L'événement a expiré \{#the-event-has-expired\}

**Raison** : L'option **Exclude historical events** est activée dans les paramètres de l'intégration, et la date de création de l'événement est antérieure à la date de création du profil dans notre système.

Cela peut se produire lorsqu'une chaîne de transactions remontant à plusieurs années arrive dans Adapty via la validation de reçu pour un profil créé récemment.

**Solution** : Assurez-vous que cela ne se reproduit pas pour les nouveaux événements. Si vous souhaitez envoyer des événements historiques vers l'intégration, désactivez **Exclude historical events**.

## Type d'événement désactivé/non pris en charge \{#disabledunsupported-event-type\}

**Raison** : L'événement n'est pas pris en charge pour cette intégration, ou vous l'avez désactivé lors de la configuration de l'intégration.

**Solution** :

1. Vérifiez si l'intégration prend en charge ce type d'événement. Les événements suivants n'atteignent pas toutes les intégrations :

    - `access_level_updated` : le webhook uniquement.
    - [Événements synthétiques](events#synthetic-events) (`trial_active`, `subscription_active`) : AppsFlyer, Adjust, Singular, Branch, et le webhook.

2. Si l'intégration est prise en charge, assurez-vous que l'événement est activé dans les paramètres de l'intégration.

## Un événement synthétique n'est jamais arrivé \{#a-synthetic-event-never-arrived\}

**Raison** : Les [événements synthétiques](events#synthetic-events) se déclenchent une seule fois, sur un minuteur, et quatre situations les empêchent d'arriver sans générer d'erreur :

- L'essai ou l'abonnement a pris fin avant que le délai ne s'écoule. Un achat converti, expiré ou remboursé ne produit rien, et Adapty ne vérifie plus. Cherchez plutôt `trial_converted`, `trial_expired`, `subscription_expired` ou `subscription_refunded`.
- Vous avez activé l'événement après le début de l'achat. Adapty démarre le minuteur à la réception de `trial_started` ou `subscription_started`, donc seuls les achats effectués après l'activation de l'événement en génèrent un.
- Vous avez modifié le délai après le début de l'achat. Les envois déjà planifiés conservent le délai avec lequel ils ont été créés.
- Vous avez désactivé l'événement avant que le délai ne s'écoule. Adapty annule l'envoi.

**Solution** : il ne s'agit pas d'échecs de livraison, donc il n'y a rien à relancer et rien n'apparaît dans l'Event Feed. Pour confirmer que la configuration fonctionne, activez l'événement et observez un achat effectué après ce moment.
