L'intégration d'Adapty Attribution avec Amazon S3 vous permet de stocker les données de vos campagnes d'acquisition utilisateur de manière sécurisée en un seul endroit centralisé. Adapty Attribution enregistre des fichiers .csv dans votre bucket Amazon S3. Chaque ligne correspond à une installation d'application, avec ses identifiants d'appareil et ses données d'attribution, comme le canal et la campagne. Les fichiers ne contiennent aucune donnée de dépenses publicitaires, de revenus ou d'achats.  
Pour configurer cette intégration, vous devrez suivre quelques étapes simples dans la console AWS et le tableau de bord Adapty Attribution.

:::note
Adapty Attribution exporte un ensemble de fichiers par jour calendaire. Le planificateur d'export s'exécute trois fois par jour — à **02h00**, **04h00** et **06h00 UTC**. Chaque exécution crée le job d'export du jour précédent s'il n'existe pas encore, ou le relance si une exécution précédente a échoué. Vos données arrivent donc généralement après l'exécution de 02h00, et les exécutions suivantes servent à récupérer d'éventuels échecs plutôt qu'à ajouter des données.

Chaque export couvre les installations enregistrées par Adapty Attribution au cours de la journée calendaire précédente en UTC. Par exemple, l'export du 8 mars contient les installations enregistrées le 7 mars, de 00:00:00 à 23:59:59 UTC.

Chaque fichier reflète l'attribution au moment de l'export. Jusqu'à 30 jours après une installation, Adapty Attribution peut encore rattacher l'installation à un autre canal ou une autre campagne. Pour actualiser les anciens fichiers avec l'attribution en cours, [lancez un export manuel](#manual-data-export) pour les dates concernées.
:::

:::warning
L'export planifié ne s'exécute que pour les entreprises disposant d'un plan payant ou en période d'essai. Si votre entreprise ne remplit aucune de ces conditions, le planificateur l'ignore et n'écrit aucun fichier, même si l'intégration reste activée dans le tableau de bord. Si votre bucket est vide et que la configuration semble correcte, vérifiez d'abord le statut de votre plan.
:::

## Comment configurer l'intégration Amazon S3 \{#how-to-set-up-amazon-s3-integration\}

Pour commencer à recevoir des données, vous aurez besoin des identifiants suivants :

1. Access key ID
2. Secret access key
3. S3 bucket name
4. Folder name inside the S3 bucket

:::note
Répertoires imbriqués

Vous pouvez spécifier des répertoires imbriqués dans le champ S3 bucket name, par exemple : adapty-ua-events/com.sample-app
:::

### Étape 1. Créer les identifiants Amazon S3 \{#step-1-create-amazon-s3-credentials\}

Ce guide vous aidera à créer les identifiants nécessaires dans votre console AWS.

1. Accédez au [tableau de bord des politiques IAM](https://us-east-1.console.aws.amazon.com/iamv2/home?region=us-east-1#/policies) dans votre console AWS
2. Sélectionnez l'option **Create Policy**

### Étape 2. Configurer l'intégration dans Adapty Attribution

1. Accédez à [**Integrations** -> **Amazon S3**](https://app.adapty.io/ua/integrations/s3)
2. Activez le bouton **Export install events to Amazon S3**.
3. Remplissez les champs suivants pour établir une connexion entre Amazon S3 et les profils Adapty Attribution :

| Champ                        | Description                                                  |
|:-----------------------------| :----------------------------------------------------------- |
| **Access Key ID**            | Un identifiant unique utilisé pour authentifier l'accès d'un utilisateur ou d'une application à un service AWS. Vous trouverez cet identifiant dans le [fichier csv](ua-amazon-s3#step-1-create-amazon-s3-credentials) téléchargé. |
| **Secret Access Key**        | Une clé privée utilisée conjointement avec l'Access Key ID pour authentifier l'accès d'un utilisateur ou d'une application à un service AWS. Vous trouverez cette clé dans le [fichier csv](ua-amazon-s3#step-1-create-amazon-s3-credentials) téléchargé. |
| **S3 Bucket Name**           | Un nom globalement unique qui identifie un bucket S3 spécifique dans le cloud AWS. Les buckets S3 sont un service de stockage simple permettant aux utilisateurs de stocker et de récupérer des objets de données, tels que des fichiers et des images, dans le cloud. |
| **Folder Inside the Bucker** | Le nom du dossier que vous souhaitez créer dans le bucket S3 sélectionné. Notez que S3 simule les dossiers à l'aide de préfixes de clés d'objet, qui sont essentiellement des noms de dossiers. |
| **Region** (Optionnel)        | Obtenez votre région depuis la console de gestion AWS, sous votre compte utilisateur IAM.                                                                                                                                                                                  |

## Exportation manuelle des données \{#manual-data-export\}

Pour exporter des données sur des périodes antérieures, dans la section **Manual file export**, sélectionnez une plage de dates et cliquez sur **Export to S3**. Si votre bucket contient déjà des fichiers pour ces dates, Adapty Attribution les remplace.

## Structure du tableau \{#table-structure\}

Chaque fichier contient une ligne par installation enregistrée par Adapty Attribution au cours d'une journée UTC, avec les données de l'appareil et l'attribution associées. Les fichiers ne contiennent pas de données sur les dépenses publicitaires, les revenus ou les achats.

:::warning
Notez que cette structure peut évoluer avec le temps — de nouvelles données pouvant être introduites par nous ou par les tiers avec lesquels nous travaillons. Assurez-vous que le code qui traite ces données est suffisamment robuste et repose sur des champs spécifiques, et non sur la structure dans son ensemble.
:::

Les fichiers contiennent les colonnes suivantes :

| Colonne                  | Description                               |
|--------------------------|-------------------------------------------|
| `adapty_profile_id`      | Identifiant de profil Adapty unique       |
| `install_id`             | Identifiant d'installation unique         |
| `created_at`             | Horodatage de création de l'enregistrement (ISO 8601) |
| `installed_at`           | Horodatage d'installation de l'application (ISO 8601) |
| `store`                  | Store d'applications (`ios`, `android`)   |
| `country`                | Code pays de l'utilisateur (ISO 3166-1 alpha-2) |
| `ip_address`             | Adresse IP du client                      |
| `idfa`                   | Identifiant iOS pour les annonceurs       |
| `idfv`                   | Identifiant iOS pour les éditeurs         |
| `gaid`                   | Identifiant publicitaire Google (Android) |
| `android_id`             | Identifiant d'appareil Android            |
| `app_set_id`             | Android App Set ID                        |
| `bundle_id`              | Identifiant de bundle de l'application (ex. `com.example.app`) |
| `device_brand`           | Marque de l'appareil (ex. `Apple`, `Samsung`) |
| `device_model`           | Modèle de l'appareil (ex. `iPhone15,2`)   |
| `os_version`             | Version majeure du système d'exploitation |
| `app_version`            | Version de l'application rapportée par le SDK |
| `sdk_version`            | Version du SDK Adapty                     |
| `channel`                | Canal d'attribution                       |

| `keyword_name`           | Nom du mot-clé                            |
| `asa_org_id`             | Identifiant d'organisation Apple Search Ads |

| `asa_attribution`        | Données d'attribution ASA (chaîne JSON)   |

| `utm_content`            | Paramètre UTM content                     |
| `click_time`             | Horodatage du clic attribué, en secondes Unix. Vide si aucun clic n'est attribué à l'installation. |
| `asa_click_time`         | Horodatage du tap Apple Search Ads précédant l'installation, en secondes Unix, arrondi à la minute. Vide si Apple Search Ads ne rapporte aucun tap pour l'installation. Contrairement à `click_time`, cette valeur est renseignée même si l'attribution Adapty crédite l'installation à un autre canal. |
