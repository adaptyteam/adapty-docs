Ce guide de démarrage rapide configure une monnaie en jetons de bout en bout : un abonnement mensuel accorde 1 000 jetons aux utilisateurs à chaque période de facturation, et les actions payantes dans votre application coûtent des jetons. Adapty gère chaque solde, de sorte que votre backend n'a qu'à les lire et les dépenser.

1. Suivez le guide [Créer une monnaie virtuelle](create-virtual-currency) pour créer une monnaie `TOKENS`. Liez-la à votre abonnement Pro et définissez le **Credit per cycle** à 1000. Adapty accorde le **Credit per cycle** une fois par période de facturation de l'abonnement : chaque mois pour un abonnement mensuel, chaque semaine pour un abonnement hebdomadaire. Pour vendre des tokens supplémentaires, liez également des produits de packs de tokens à achat unique.

   <ZoomImage id="new-currency-combined.webp" width="700px" alt="Écrans de création d'une nouvelle monnaie virtuelle" />

2. Appelez [Lister les soldes de monnaie virtuelle](api-adapty/operations/listVirtualCurrencyBalances) pour lire le solde de l'utilisateur, par exemple avant de démarrer une génération :

   ```bash title="Read balances"
   curl https://api.adapty.io/api/v2/server-side-api/vc/balances/ \
     -H "Authorization: Api-Key {your secret key}" \
     -H "adapty-customer-user-id: user-42"
   ```

   La réponse liste toutes les devises de votre application, y compris celles dont le solde est 0. Par exemple, 1000 `TOKENS` :

   ```json title="Response"
   {
     "response_created_at": 1794477600123,
     "data": [
       {
         "code": "TOKENS",
         "name": "Tokens",
         "balance": 1000,
         "held": 0,
         "available": 1000,
         "expiry": { "non_expiring": 1000, "expiring": [], "expiring_later": 0, "expired": 0 }
       }
     ]
   }
   ```
3. Lorsque l'utilisateur lance une génération, débitez les tokens en appelant [Créer une transaction de devise virtuelle](api-adapty/operations/createVirtualCurrencyTransaction) avec un `amount` négatif. Dans cet exemple, une génération d'image coûte 100 tokens. Pour indiquer à quoi les tokens ont été dépensés, la requête définit également `operation` à `spend` et `feature` à `image_generation` (voir [Étiqueter les transactions](virtual-currencies#label-transactions)) :

   ```bash title="Spend tokens"
   curl -X POST https://api.adapty.io/api/v2/server-side-api/vc/transactions/ \
     -H "Authorization: Api-Key {your secret key}" \
     -H "adapty-customer-user-id: user-42" \
     -H "Content-Type: application/json" \
     -d '{
           "items": [{"currency_code": "TOKENS", "amount": -100}],
           "operation": "spend",
           "feature": "image_generation"
         }'
   ```

   La transaction est atomique et retourne le solde mis à jour. Une transaction peut modifier jusqu'à 20 devises, chacune listée une seule fois dans `items`. Si l'utilisateur ne peut pas couvrir le coût, la requête renvoie `insufficient_balance` et rien ne change. Incluez un en-tête `Idempotency-Key` pour relancer les requêtes en toute sécurité. Pour ouvrir un flow de recharge quand le solde est insuffisant, suivez le guide pour [iOS](ios-virtual-currency-top-up).
4. Pour lancer une promo de reconquête, accordez des jetons via le même endpoint avec un `amount` positif. Les crédits accordés de cette façon n'expirent jamais. Pour donner aux utilisateurs un solde avant leur premier achat, consultez [Accorder un solde initial](grant-initial-balance).
5. Consultez chaque modification dans le [profil](virtual-currency-balance) de l'utilisateur ou dans l'[historique des transactions](api-adapty/operations/listVirtualCurrencyTransactions) pour auditer l'économie à tout moment.
