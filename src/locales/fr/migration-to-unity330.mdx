Adapty SDK 3.3.0 est une version majeure qui apporte des améliorations pouvant nécessiter quelques étapes de migration de votre part.

1. Passez au SDK Adapty v3.3.x.
2. Plusieurs classes, propriétés et méthodes ont été renommées dans les modules Adapty et AdaptyUI du SDK Adapty.
3. Désormais, la méthode `SetLogLevel` accepte un callback en argument.
4. Désormais, la méthode `PresentCodeRedemptionSheet` accepte un callback en argument.
5. Modifiez la façon dont la vue du paywall est créée.
6. Supprimez la méthode `GetProductsIntroductoryOfferEligibility`.
7. Enregistrez les paywalls de secours dans des fichiers séparés (un par plateforme) dans `Assets/StreamingAssets/` et transmettez les noms de fichiers à la méthode `SetFallbackPaywalls`.
8. Mettez à jour la procédure d'achat.
9. Mettez à jour la gestion des événements du Paywall Builder.
10. Mettez à jour la gestion des erreurs du paywall Paywall Builder.
11. Mettez à jour les configurations d'intégration pour Adjust, Amplitude, AppMetrica, Appsflyer, Branch, Firebase et Google Analytics, Mixpanel, OneSignal, Pushwoosh.
13. Mettez à jour l'implémentation du mode Observer.
14. Mettez à jour l'initialisation du plugin Unity avec un appel `Activate` explicite.

## Mettre à jour le SDK Unity Adapty vers la version 3.3.x \{#upgrade-adapty-unity-sdk-to-33x\}

Jusqu'à cette version, le SDK Adapty était le SDK principal et obligatoire pour le bon fonctionnement d'Adapty dans votre application, tandis que le SDK AdaptyUI était un SDK optionnel, nécessaire uniquement si vous utilisiez le Paywall Builder d'Adapty.

À partir de la version 3.3.0, le SDK AdaptyUI est déprécié et AdaptyUI est intégré au SDK Adapty en tant que module. En raison de ces changements, vous devez supprimer le SDK AdaptyUI et réinstaller le SDK Adapty.

1. Supprimez les dépendances de packages **AdaptySDK** et **AdaptyUISDK** de votre projet.
2. Supprimez les dossiers **AdaptySDK** et **AdaptyUISDK**.
3. Importez à nouveau le package AdaptySDK comme décrit sur la page [Installation et configuration du SDK Adapty pour Unity](sdk-installation-unity).

## Supprimer la méthode GetProductsIntroductoryOfferEligibility \{#remove-the-getproductsintroductoryoffereligibility-method\}

Avant la version 3.3.0 du SDK Adapty iOS, l'objet produit incluait toujours les offres, quelle que soit l'éligibilité de l'utilisateur. Vous deviez vérifier manuellement l'éligibilité avant d'utiliser l'offre.

Désormais, l'objet produit n'inclut une offre que si l'utilisateur y est éligible. Vous n'avez donc plus besoin de vérifier l'éligibilité — si une offre est présente, l'utilisateur est éligible.

## Méthode de mise à jour pour fournir des paywalls de secours \{#update-method-for-providing-fallback-paywalls\}

Jusqu'à cette version, les paywalls de secours étaient transmis sous forme de JSON sérialisé. À partir de la v 3.3.0, le mécanisme change :

1. Enregistrez les paywalls de secours dans des fichiers situés dans `/Assets/StreamingAssets/`, un fichier pour Android et un autre pour iOS.
2. Transmettez les noms de fichiers à la méthode `SetFallbackPaywalls`.

Votre code sera modifié de la façon suivante :

```diff showLineNumbers
using AdaptySDK;

void SetFallBackPaywalls() {

+ #if UNITY_IOS
+   var assetId = "adapty_fallback_ios.json";
+ #elif UNITY_ANDROID
+   var assetId = "adapty_fallback_android.json";
+ #else
+   var assetId = "";
+ #endif

-   Adapty.SetFallbackPaywalls("FALLBACK_PAYWALLS_JSON_STRING", (error) => {
+   Adapty.SetFallbackPaywalls(assetId, (error) => {
    // handle the error
  });
}
```

Consultez l'exemple de code final sur la page [Utiliser les paywalls de secours dans Unity](unity-use-fallback-paywalls).

## Mise à jour du processus d'achat \{#update-making-purchase\}

Les achats précédemment annulés et en attente étaient considérés comme des erreurs et renvoyaient respectivement les codes `PaymentCancelled` et `PendingPurchase`.

Désormais, une nouvelle classe `AdaptyPurchaseResultType` est utilisée pour traiter les achats annulés, réussis et en attente. Mettez à jour le code d'achat de la façon suivante :

```diff showLineNumbers
using AdaptySDK;

void MakePurchase(AdaptyPaywallProduct product) {
- Adapty.MakePurchase(product, (profile, error) => {
-   // handle successfull purchase
+ Adapty.MakePurchase(product, (result, error) => {
+   switch (result.Type) {
+     case AdaptyPurchaseResultType.Pending:
+       // handle pending purchase
+       break;
+     case AdaptyPurchaseResultType.UserCancelled:
+       // handle purchase cancellation
+       break;
+     case AdaptyPurchaseResultType.Success:
+       var profile = result.Profile;
+       // handle successful purchase
+       break;
+     default:
+       break;
    }
  });
}
```

Consultez l'exemple de code final sur la page [Effectuer des achats dans l'application mobile](unity-making-purchases).

## Mettre à jour la configuration du SDK d'intégration tiers \{#update-third-party-integration-sdk-configuration\}

À partir d'Adapty Unity SDK 3.3.0, nous avons mis à jour l'API publique de la méthode `updateAttribution`. Auparavant, elle acceptait un dictionnaire `[AnyHashable: Any]`, vous permettant de passer directement des objets d'attribution depuis différents services. Désormais, elle requiert un `[String: any Sendable]`, vous devrez donc convertir les objets d'attribution avant de les transmettre.

Pour garantir le bon fonctionnement des intégrations avec Adapty Unity SDK 3.3.0 et versions ultérieures, mettez à jour les configurations de votre SDK pour les intégrations suivantes, comme décrit dans les sections ci-dessous.

## Mettre à jour l'implémentation du mode Observer \{#update-observer-mode-implementation\}

-         return;
-     }

+   "YOUR_TRANSACTION_ID",
