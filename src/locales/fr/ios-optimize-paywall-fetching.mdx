Une récupération fiable de paywall sur iOS repose sur trois éléments : un affichage rapide, le retour du paywall ciblé par audience, et un repli gracieux lorsque le réseau est lent. Les règles ci-dessous couvrent le timing, la mise en cache et les patterns de secours pour y parvenir.

:::tip
Ces règles supposent que `Adapty.activate()` et `Adapty.identify()` ont déjà été résolus. Consultez [Ordre d'appel dans le SDK iOS](ios-sdk-call-order).
:::

## Règles et pièges \{#rules-and-pitfalls\}

| Faites ceci | Évitez cela | Pourquoi |
|---|---|---|
| Récupérez le placement que vous êtes sur le point d'afficher, ou préchauffez le cache avec [`preloadFlows`](#preload-placements) (SDK 4.1+). | Lancez vos propres appels `getFlow` concurrents au démarrage. | Un burst de préchargement fait maison bloque le thread principal et provoque un écran noir. `preloadFlows` est conçu pour ça et partage un seul budget de délai sur toute la liste. |
| Appelez `getPaywall` après que l'attribution a eu le temps de se résoudre — par exemple, 1 à 2 secondes après `activate` ou après le déclenchement de `onProfileUpdate`. | Appelez `getPaywall` dans `App.init()`.                     | L'attribution n'est pas encore arrivée. Le paywall se résout contre l'audience par défaut et contourne silencieusement les segments et la personnalisation ASA. |
| Définissez un `loadTimeout` et configurez un [paywall de secours](fallback-paywalls) pour chaque placement.                             | Attendez `getPaywall` indéfiniment.                     | Sans délai d'expiration, les utilisateurs avec une mauvaise connexion voient un écran blanc jusqu'à ce que le réseau réponde — ou ferment l'application.     |

Quand `loadTimeout` expire lors d'une récupération — y compris un simple `getPaywall` — le SDK retourne la variation en cache si elle existe, sinon il récupère la variation de l'audience par défaut (**All Users**) dans le temps restant. Le ciblage est perdu pour cette requête, pas reporté : les segments et les audiences basées sur l'attribution ne s'appliquent pas au résultat.

Consultez [Récupérer les paywalls et les produits](fetch-paywalls-and-products) pour la référence des paramètres `fetchPolicy` et `loadTimeout`, et [Placements](placements) pour choisir le bon placement.

## Précharger les placements \{#preload-placements\}

:::info
Ces méthodes sont disponibles à partir de la version 4.1 du SDK.
:::

`preloadFlows` et `preloadOnboardings` écrivent le JSON du placement dans le cache du SDK en avance — une requête par placement, rien de plus. Malgré leurs noms, aucune de ces méthodes ne récupère la mise en page de l'interface du flow ni ses médias.

Un appel ultérieur à `getFlow` ou `getOnboarding` ne lit ce cache que si vous passez `fetchPolicy: .returnCacheDataElseLoad` ou `.returnCacheDataIfNotExpiredElseLoad(maxAge:)`. La politique par défaut, `.reloadRevalidatingCacheData`, contacte le réseau à chaque appel : un préchargement combiné à une récupération avec la politique par défaut génère donc une requête supplémentaire sans gain — la copie mise en cache ne sert que de solution de secours hors ligne.

Utilisez cette méthode lorsque vous connaissez les placements dont la session aura besoin, mais que vous ne souhaitez pas encore les afficher — par exemple, juste après la résolution d'`activate` et d'`identify`, pour le paywall derrière un bouton que l'utilisateur n'a pas encore touché.

<Tabs groupId="current-os" queryString>
<TabItem value="swift" label="Swift" default>

```swift showLineNumbers
try await Adapty.preloadFlows(
    placementIds: ["onboarding", "main_paywall"],
    loadTimeout: 5
)

try await Adapty.preloadOnboardings(
    placementIds: ["intro"],
    locale: "en",
    loadTimeout: 5
)

// Plus tard, quand l'utilisateur atteint le paywall :
let flow = try await Adapty.getFlow(
    placementId: "main_paywall",
    fetchPolicy: .returnCacheDataElseLoad
)
```

</TabItem>
<TabItem value="callback" label="Swift-Callback">

```swift showLineNumbers
Adapty.preloadFlows(placementIds: ["onboarding", "main_paywall"], loadTimeout: 5) { error in
    if let error {
        // at least one placement failed to preload
    }
}

// Later, when the user reaches the paywall:
Adapty.getFlow(placementId: "main_paywall", fetchPolicy: .returnCacheDataElseLoad) { result in
    // ...
}
```

</TabItem>

**Paramètres :**

- `placementIds` (requis) : les placements à précharger. Les identifiants vides et en double sont ignorés.
- `locale` (optionnel, `preloadOnboardings` uniquement) : la langue de l'onboarding à mettre en cache.
- `loadTimeout` (optionnel) : délai d'expiration en secondes pour l'ensemble du lot, et non par placement. Par défaut, 5 secondes ; les valeurs inférieures à 1 seconde sont ramenées à 1 seconde.

**Comportement à connaître :**

- Les méthodes ne lèvent une erreur qu'après avoir tenté tous les placements, et l'erreur regroupe les échecs par placement. Un échec sur un placement n'interrompt pas les autres.
- Si un placement expire ou échoue à cause d'une erreur réseau, le SDK utilise la variante de l'audience par défaut pour ce placement. Les autres échecs sont rapportés tels quels.
- Si le délai expire avant que la récupération ciblée par audience ne soit terminée, le SDK tente tout de même la variante de l'audience par défaut dans le budget restant.
- Le préchargement se contente de réchauffer le cache. Il ne retourne pas de contenu — vous appelez tout de même `getFlow` ou `getOnboarding` pour afficher le contenu.

### Ce que couvre un préchargement \{#what-a-preload-covers\}

Un flow s'affiche par couches, et un préchargement ne couvre que la première :

| Couche | Récupérée par | Réchauffée par un préchargement |
|---|---|---|
| Placement JSON — la variation choisie, ses identifiants de produits et le Remote Config | `getFlow` | Oui |
| Mise en page UI — la structure, le style et le texte de l'écran | `getFlowConfiguration` | Non |
| Images, y compris la vignette statique qui remplace un élément vidéo | `getFlowConfiguration`, en arrière-plan | Non |
| Fichiers vidéo | Le lecteur système, au rendu de l'écran | Non mis en cache par le SDK |

`getFlowConfiguration` attend la mise en page, donc en cas de cache vide, cet appel coûte toujours un aller-retour réseau après un préchargement. Une fois que le SDK a la mise en page, il met les images en cache indépendamment de l'appel : il ne bloque pas l'affichage, et aucun callback, méthode de délégué ou erreur ne signale la fin du processus.

### Identifier quel placement a échoué \{#find-out-which-placement-failed\}

L'erreur levée est un `AdaptyError` unique couvrant tout le lot, avec le code `networkFailed` (2005). Pour voir les échecs individuels, consultez sa propriété `preloadErrors` — un dictionnaire indexé par ID de placement :

```swift showLineNumbers
do {
    try await Adapty.preloadFlows(placementIds: ["onboarding", "main_paywall"])
} catch {
    for (placementId, placementError) in error.preloadErrors ?? [:] {
        // log or retry the individual placement
    }
}
```

`preloadErrors` est `nil` pour toute erreur ne provenant pas d'un appel de préchargement ; traitez donc une valeur `nil` comme « pas un échec de préchargement » plutôt que comme « aucune erreur ».

### Ignorer la segmentation d'audience \{#skip-audience-segmentation\}

Pour préchauffer le cache sans attendre la segmentation d'audience, utilisez les variantes de l'audience par défaut :

```swift showLineNumbers
try await Adapty.preloadFlowsForDefaultAudience(placementIds: ["main_paywall"])
try await Adapty.preloadOnboardingsForDefaultAudience(placementIds: ["intro"])
```

## Optimiser pour les connexions instables \{#tune-for-poor-connectivity\}

Pour les marchés avec une connectivité régulièrement mauvaise (zones rurales, transports, régions touchées par des problèmes de routage) :

- Définissez `fetchPolicy: .returnCacheDataElseLoad` sur chaque requête sauf la toute première.
- Configurez un [paywall de secours](fallback-paywalls) pour chaque placement dans le tableau de bord Adapty.
- Définissez `loadTimeout` entre 3 et 5 secondes et acceptez le paywall de secours lorsque le délai expire.
- Ne conditionnez pas l'affichage du paywall à `getProfile()`. Appelez `getPaywall` indépendamment pour qu'un profil lent ne bloque pas l'interface.
