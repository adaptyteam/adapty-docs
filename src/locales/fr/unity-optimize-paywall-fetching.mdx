Une récupération fiable d'un flow ou d'un paywall sur Unity repose sur trois éléments : un affichage rapide, le retour de la variante ciblée selon l'audience, et un basculement en douceur lorsque le réseau est lent. Les règles ci-dessous couvrent le timing, la mise en cache et les patterns de secours pour y parvenir.

:::tip
Les règles supposent que `Adapty.Activate()` et `Adapty.Identify()` ont déjà été résolues. Consultez [Ordre des appels dans le SDK Unity](unity-sdk-call-order).
:::

## Règles et pièges \{#rules-and-pitfalls\}

| Faites ceci | Ne faites pas cela | Pourquoi |
|---|---|---|
| Récupérez le placement que vous allez afficher, ou préchauffez le cache avec [`PreloadFlows`](#preload-placements) (SDK 4.3.0+). | Lancez vos propres appels `GetFlow` concurrents au démarrage. | Un burst de préchargement fait maison bloque le thread principal et produit un écran noir. `PreloadFlows` est conçu pour ça et envoie le lot au SDK natif en un seul appel. |
| Appelez `GetFlow` après que l'attribution a eu le temps de se résoudre — par exemple, 1 à 2 secondes après `Activate` ou après le déclenchement de `OnLoadLatestProfile`. | Appelez `GetFlow` dans `Awake()`. | L'attribution n'est pas encore arrivée. Le flow se résout selon l'audience par défaut et contourne silencieusement les segments et la personnalisation ASA. |
| Définissez un `loadTimeout` et configurez un [paywall de secours](fallback-paywalls) pour chaque placement. | Attendez `GetFlow` indéfiniment. | Sans timeout, les utilisateurs avec une mauvaise connexion voient un écran blanc jusqu'à ce que le réseau réponde — ou ferment l'application. |

Consultez [Récupérer les paywalls personnalisés et les produits](fetch-paywalls-and-products-unity) pour la référence des paramètres `fetchPolicy` et `loadTimeout`, et [Placements](placements) pour choisir le bon placement.

## Précharger les placements \{#preload-placements\}

:::info
`Adapty.PreloadFlows` et `Adapty.PreloadFlowsForDefaultAudience` sont disponibles à partir de la version 4.3.0 du SDK.
:::

`Adapty.PreloadFlows` met en cache le JSON du flow à l'avance. Vous l'utilisez ensuite comme d'habitude : `GetFlow` pour le flow, `CreateFlowView` pour sa vue.

`fetchPolicy` détermine quelle couche un `GetFlow` ultérieur lit en premier, et non s'il peut accéder au cache :

- `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` lit d'abord la copie préchargée et ne contacte le réseau que si rien n'est en cache. `AdaptyPlacementFetchPolicy.ReturnCacheDataIfNotExpiredElseLoad(maxAge)` fait de même tant que la copie est plus récente que `maxAge`.
- Par défaut, `AdaptyPlacementFetchPolicy.Default` contacte d'abord le réseau et se rabat sur la copie préchargée si la requête échoue ou expire.

Un préchargement est toujours bénéfique, mais différemment selon la politique : une politique cache-first supprime la requête, tandis que la politique par défaut la conserve et dispose d'une copie en cache en cas d'échec. Sur un [appareil de test](test-devices), `GetFlow` ignore le cache quelle que soit la politique et n'utilise la copie préchargée que si la requête réseau échoue.

Utilisez-le lorsque vous savez quels placements la session va nécessiter, mais que vous ne voulez pas les afficher encore — par exemple, juste après que `Activate` et `Identify` se terminent, pour le flow derrière un bouton que l'utilisateur n'a pas encore appuyé.

```csharp showLineNumbers title="C#"
Adapty.PreloadFlows(
    new List<string> { "onboarding", "main_paywall" },
    TimeSpan.FromSeconds(5),
    (error) => {
        if (error != null) {
            // at least one placement failed to preload
        }
    }
);

// Later, when the user reaches the paywall:
Adapty.GetFlow(
    "main_paywall",
    AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad,
    TimeSpan.FromSeconds(5),
    (flow, error) => {
        // create the flow view
    }
);
```

**Paramètres :**

- `placementIds` (requis) : les placements à précharger.
- `loadTimeout` (optionnel) : durée d'attente du préchargement pour les flows ciblés par audience. Par défaut 5 secondes si vous passez `null` ou utilisez la surcharge sans ce paramètre. Lorsque le délai est atteint, le SDK peut charger les flows de l'audience par défaut à la place.

**Points importants à connaître :**

- L'appel échoue uniquement après que tous les placements ont été tentés, avec une seule erreur `NetworkFailed` qui liste tous les placements en échec. L'échec d'un placement n'arrête pas les autres, et les placements chargés restent dans le cache.
- Le préchargement passe toujours par le réseau : il n'a pas de `fetchPolicy` propre.
- Le préchargement sert uniquement à alimenter le cache. Il ne retourne pas de contenu — vous appelez toujours `GetFlow` pour l'afficher.
- Le cache appartient au profil actuel. Les flows préchargés avant `Identify` ou `Logout` ne sont plus accessibles après, donc préchargez après le changement de profil.

### Ce que couvre un préchargement \{#what-a-preload-covers\}

Un flow s'affiche à l'écran en plusieurs couches. Un préchargement couvre la première, exactement comme `GetFlow` le fait :

| Couche | Récupérée par | Préchauffée par un préchargement |
|---|---|---|
| JSON du flow — la variante choisie, ses identifiants de produits et la Remote Config | `GetFlow` | Oui |
| Mise en page UI — la structure, le style et le texte de l'écran | `CreateFlowView` | Non |
| Images, y compris la miniature qui remplace un élément vidéo | `CreateFlowView`, en arrière-plan | Non |
| Produits | `CreateFlowView` ou `GetPaywallProducts` | Non |
| Fichiers vidéo | Le lecteur système, au moment du rendu de l'écran | Non mis en cache par le SDK |

Ainsi, le premier `CreateFlowView` pour un layout donné implique toujours un aller-retour réseau après un préchargement. Le SDK natif conserve ensuite ce layout dans son cache disque, qui survit aux redémarrages de l'application, de sorte que ce coût ne tombe que sur la première requête et non sur chacune d'elles.

### Ignorer la segmentation d'audience \{#skip-audience-segmentation\}

Pour réchauffer le cache sans attendre la segmentation d'audience, utilisez la variante d'audience par défaut. Elle ne prend pas de délai :

```csharp showLineNumbers title="C#"
Adapty.PreloadFlowsForDefaultAudience(
    new List<string> { "main_paywall" },
    (error) => {
        // handle the error
    }
);
```

Un appel ultérieur à `GetFlowForDefaultAudience` lit la copie de la même façon que `GetFlow` lit une copie issue de `PreloadFlows`.

## Afficher les médias du premier écran depuis le bundle de l'application \{#show-first-screen-media-from-the-app-bundle\}

Un flow télécharge ses images et vidéos depuis Adapty. Pour afficher instantanément les médias du premier écran, servez-les depuis le bundle de l'application. C'est une bonne façon de réutiliser des médias déjà inclus dans votre app, comme les visuels d'un onboarding natif existant.

1. Dans le Flow & Paywall Builder, définissez un [identifiant de média personnalisé](custom-media#custom-media-id) sur l'image ou la vidéo. Le fichier que vous y chargez reste utilisé comme fallback.
2. Ajoutez le fichier à votre projet Unity.
3. Lors de la création de la vue du flow, transmettez le fichier du bundle pour cet identifiant avec `SetCustomAssets` :

```csharp showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
var bundledAssets = new Dictionary<string, AdaptyCustomAsset>
{
    { "welcome_video", AdaptyCustomAsset.LocalVideoFile("custom_assets/videos/welcome.mp4") }
};

var parameters = new AdaptyUICreateFlowViewParameters()
    .SetCustomAssets(bundledAssets);

AdaptyUI.CreateFlowView(flow, parameters, (view, error) => {
    // handle the result
});
```

Les fichiers intégrés augmentent la taille de téléchargement de votre application, alors n'intégrez que les médias visibles dès le premier écran.

Les médias non intégrés s'affichent quand même immédiatement : la mise en page du flow inclut une petite copie basse résolution de chaque image, y compris l'image fixe d'une vidéo, et l'affiche jusqu'au chargement complet du fichier.

Pour la référence complète de `customAssets`, consultez [Personnaliser les assets](unity-get-pb-paywalls#customize-assets).

## Optimiser pour les connexions défaillantes \{#tune-for-poor-connectivity\}

Pour les marchés où la connectivité est régulièrement mauvaise (zones rurales, transports en commun, régions touchées par des problèmes de routage) :

- Définissez `fetchPolicy` sur `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` à chaque requête, sauf la toute première.
- Configurez un [paywall de secours](fallback-paywalls) pour chaque placement dans l'Adapty Dashboard.
- Définissez `loadTimeout` entre 3 et 5 secondes et acceptez le paywall de secours si le délai expire.
- Ne bloquez pas l'affichage du flow sur `GetProfile`. Appelez `GetFlow` indépendamment pour qu'un profil lent ne bloque pas l'interface.
