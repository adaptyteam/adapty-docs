Le [Flow Builder](adapty-flow-builder) sépare l'enregistrement de la publication. Les brouillons conservent votre travail dans l'Adapty Dashboard, et la publication met la version actuelle à disposition des utilisateurs via le SDK. Cet article couvre ces deux actions et explique quand les utiliser.

## Enregistrer un flow comme brouillon \{#save-a-flow-as-a-draft\}

:::warning
Un [Remote Config](customize-flow-with-remote-config) invalide vous empêche d'enregistrer le brouillon.
:::

Le Flow Builder sauvegarde automatiquement votre progression une fois par minute.

Pour enregistrer un brouillon manuellement, cliquez sur **Save draft** en haut à droite du Flow Builder, ou appuyez sur **Cmd/Ctrl + S**.

Les brouillons sont privés dans le Dashboard. Ils ne modifient pas ce que voient les utilisateurs dans votre application, même si le flow est déjà assigné à un [placement](placements).

<ZoomImage id="flow-builder-save-draft.webp" width="700px" alt="Bouton Save draft dans la barre d'outils supérieure du Flow Builder" />

## Publier un flow \{#publish-a-flow\}

La publication rend la version actuelle de votre flow disponible aux utilisateurs via le SDK. Une fois publié, la nouvelle version remplace toute version précédemment publiée du même flow.

:::note
Pour ajouter un flow à un [placement](placements), publiez-le d'abord. Un flow en statut Brouillon ne peut pas être ajouté.
:::

Pour publier votre flow, cliquez sur **Publish to Live** en haut à droite du Flow Builder.

Ce qui se passe ensuite dépend de si le flow est déjà assigné à un placement :

- **Flow déjà dans un placement** : les utilisateurs voient la nouvelle version dès leur prochaine requête sur ce placement.
- **Flow absent d'un placement** : ajoutez le flow à un [placement de flow](create-placement) pour commencer à le montrer aux utilisateurs. Un flow nécessite son propre placement — il ne peut pas partager un placement déjà utilisé par un paywall ou un onboarding.

:::tip
Un flow est prêt à être publié dès que chaque action, écran et élément produit est entièrement configuré. Consultez [Résolution des problèmes](#troubleshooting) pour les erreurs courantes.
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Bouton Publier en production dans la barre d'outils supérieure du Flow Builder" />

:::warning
Les [polices personnalisées](using-custom-fonts-in-flow-builder) ne sont pas incluses dans le flow — vous devez ajouter chaque fichier de police à votre bundle d'application. Sans le fichier, les utilisateurs voient la police système par défaut.

Pour changer une police dans un flow publié sans casser les versions antérieures : [copiez le flow](copy-flows), modifiez la police dans la copie, et ciblez la copie sur une [audience](add-audience-paywall-ab-test) correspondant aux versions de l'application qui incluent la police.
:::

## Statut d'un flow \{#flow-status\}

Chaque flow affiche un statut dans la [liste des flows](filter-flows). Ce statut indique où en est le flow dans son cycle de vie de sauvegarde et de publication.

| Statut | Signification |
| :----- | :------ |
| **Draft** | Le flow n'a jamais été publié. Seul un brouillon existe, donc les utilisateurs ne le voient pas encore. Vous devez d'abord publier le brouillon pour l'ajouter à un [placement](placements). |
| **Dirty** | Le flow a été publié, mais il contient des modifications enregistrées qui ne sont pas encore publiées. Les utilisateurs voient toujours la dernière version publiée jusqu'à ce que vous publiiez à nouveau. |
| **Publishing** | Une publication est en cours. |
| **Failed** | La dernière tentative de publication a échoué. Les utilisateurs continuent de voir la dernière version publiée, s'il en existe une. |
| **Published** | La dernière version enregistrée est en ligne. Il n'y a aucune modification non publiée. |
| **Archived** | Le flow a été [archivé](archive-flows#archive-a-flow) et ne peut pas être modifié tant que vous ne l'avez pas [restauré](archive-flows#restore-a-flow). |

## Résolution des problèmes \{#troubleshooting\}

Une action incomplète, un écran vide, un élément produit sans produit associé ou un JSON de Remote Config invalide bloquent aussi bien la prévisualisation que la publication. Pour la liste complète et la marche à suivre pour chaque cas, consultez [Problèmes courants](flow-common-issues#a-flow-wont-preview-or-publish).

Prévisualisez votre flow dans l'[application Adapty](paywall-device-compatibility-preview) pour détecter les problèmes avant la publication. Si le flow ne se charge pas lors de la prévisualisation, consultez le message d'erreur pour plus de détails.

Un flow peut passer toutes ces vérifications et ne pas encore être prêt à publier — un bouton de restauration inactif, un lien vers les conditions manquant, un écran non traduit. La [compétence d'audit de flow](flow-audit-skill) vérifie précisément ces points, depuis le terminal, et conclut par un verdict plutôt que par une liste.
