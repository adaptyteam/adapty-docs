Les éléments interactifs d'un flow changent d'apparence selon les actions de l'utilisateur : une option de quiz sélectionnée devient **Selected**, un champ de saisie actif devient **Active**. Stylisez chaque état séparément pour donner un retour visuel aux utilisateurs sans modifier le code de l'application.

Certains états dépendent d'une condition que vous configurez, comme la valeur d'une variable ou l'état d'un autre élément :

- [**Désactivé**](#add-the-disabled-state) : les utilisateurs ne peuvent pas interagir avec l'élément.
- [États personnalisés](#add-a-custom-state) : vous nommez l'état, définissez sa condition et stylez l'élément en conséquence. Aucune action ne bascule un élément vers un état personnalisé. À la place, [modifiez une variable personnalisée au tap](#switch-an-element-to-a-custom-state-on-tap) et basez la condition de l'état sur cette variable.

Un élément [n'est dans un seul état à la fois](#when-several-states-apply-to-one-element).

## États disponibles par type d'élément \{#available-states-by-element-kind\}

| Type d'élément | États intégrés | États ajoutables |
|---|---|---|
| [Éléments sélectionnables](#selectable-element-states) | **Default**, **Selected** | **Disabled**, états **custom** (sauf sur les en-têtes d'onglet) |
| [Champs de saisie](#input-states) | **Default**, **Active**, **Invalid** | **Disabled**, états **custom** (sauf sur les sélecteurs) |
| [Tout élément avec une interaction tactile](#add-a-state) — boutons, images, conteneurs, etc. (sauf les éléments texte et les icônes) | **Default** | **Disabled**, états **custom** (sauf sur les bottom sheets) |
| [Étapes de l'indicateur de progression](#step-states-for-progress-indicators) | **Completed**, **Current**, **Upcoming** | — |

Les états **Addable** n'apparaissent sur un élément qu'après que vous les avez [ajoutés](#add-a-state). Chacun dépend d'une condition que vous configurez.

Les conditions d'autres éléments peuvent également évaluer les états d'un élément. Par exemple, vous pouvez [expliquer pourquoi un bouton est désactivé](element-states-in-conditions#explain-why-a-button-is-disabled).

## Styliser un état \{#style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="Section États dans le panneau droit d'un élément sélectionné" float="right" />


1. Sélectionnez un élément. La section **States** dans le panneau droit affiche un onglet pour chaque état disponible.
2. Dans la section **States**, activez l'état cible. Si aucun onglet ne correspond à cet état, [ajoutez-le](#add-a-state).
3. Modifiez n'importe quelle propriété — remplissage, bordure, typographie, etc. La modification s'applique uniquement à cet état.

    Les éléments imbriqués deviennent avec état aux côtés du parent. Toute modification apportée à un enfant est limitée à l'état actif du parent.

4. Le SDK Adapty applique le style correspondant à l'exécution.

## États d'un élément sélectionnable \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Élément sélectionnable avec l'état Selected activé et un style personnalisé appliqué" />

Les éléments sélectionnables — options de quiz, produits, onglets, bascules et cases à cocher, ainsi que tout [élément sélectionnable personnalisé](flow-selectable-elements#make-an-element-selectable) — disposent de deux états par défaut :

- **Default** : L'apparence au repos de l'élément.
- **Selected** : S'applique lorsque l'utilisateur appuie sur l'élément. L'élément revient à l'état **Default** lorsque l'utilisateur le désélectionne.

Dans un groupe à choix unique, sélectionner un élément désélectionne les autres. Les groupes à choix multiple permettent de sélectionner plusieurs éléments simultanément. Les bascules sont indépendantes — sélectionner une bascule n'a aucun effet sur ses voisins. Voir [types de groupes](flow-selectable-elements#group-types).

:::tip
Pour réutiliser des styles spécifiques à un état, ajoutez-les à un élément, par exemple une fiche produit. Demandez ensuite à l'[éditeur IA](flow-ai-editor) de les appliquer aux autres éléments. Les styles spécifiques à un état ne se propagent pas automatiquement entre les éléments d'un même groupe.
:::

## États des champs de saisie \{#input-states\}

- **Default** : L'apparence par défaut du champ.
- **Active** : S'applique lorsque le champ est actif (focus).
- **Invalid** : S'applique lorsque le contenu du champ ne passe pas la validation, par exemple quand un champ e-mail ne contient pas `@`. Voir [Validation des champs](builder-inputs-and-forms#input-validation).
- **Disabled** : Le champ n'est pas interactif. [Ajoutez cet état](#add-the-disabled-state) manuellement.

Stylisez chaque état de la même façon qu'un élément sélectionnable : activez l'état cible, modifiez les propriétés.

## États des étapes pour les indicateurs de progression \{#step-states-for-progress-indicators\}

:::link
Article principal : [Indicateurs de progression](builder-loaders-and-progress-bars#step-states)
:::

Les indicateurs de progression montrent aux utilisateurs l'avancement dans un onboarding. Chaque étape a trois états :

- **Completed** : les étapes que l'utilisateur a déjà franchies.
- **Current** : l'étape en cours de l'utilisateur.
- **Upcoming** : les étapes que l'utilisateur n'a pas encore atteintes.

## Quand plusieurs états s'appliquent à un même élément \{#when-several-states-apply-to-one-element\}

Plusieurs états peuvent s'appliquer simultanément à un même élément. Par exemple :

- Un utilisateur saisit une adresse invalide dans un champ e-mail, puis retouche le champ pour la corriger. Le champ est actif, donc **Active** s'applique. L'adresse est toujours invalide, donc **Invalid** s'applique aussi.
- Un utilisateur active le toggle d'essai, donc **Selected** s'applique. Il choisit ensuite un plan sans essai. Le toggle a une condition **Disabled** pour ce plan, donc **Disabled** s'applique aussi.

Un élément ne peut être que dans un seul état à la fois. Lorsque plusieurs états s'appliquent, l'élément prend celui qui apparaît en dernier dans cette liste :

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. Les états personnalisés, dans l'ordre où vous les avez ajoutés

Dans les exemples, le champ e-mail est **Active** et le bouton bascule d'essai est **Disabled**. L'élément s'affiche tel que vous avez stylisé cet état. Une condition qui évalue l'état de l'élément ne correspond qu'à cet état. Lorsqu'aucun état de la liste ne s'applique, l'élément est **Default**.

Un état personnalisé modifie uniquement l'apparence. Si **Disabled** s'applique aussi, l'élément est dans l'état personnalisé, mais les utilisateurs ne peuvent pas interagir avec lui.

## Ajouter un état \{#add-a-state\}

### Ajouter l'état Désactivé \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="Le menu Ajouter un état d'un bouton, avec les états Désactivé et Personnalisé" />

Pour empêcher les utilisateurs d'interagir avec un élément, ajoutez l'état **Disabled** :

1. Sélectionnez l'élément cible.
2. Si la section **States** ne contient pas d'onglet **Disabled**, cliquez sur **Add state** et sélectionnez **Disabled**. Si l'élément possède déjà des états autres que **Default**, cliquez sur **Settings** <Inline id="settings.svg" alt="Settings" /> avant **Add state**.
3. Survolez **Disabled** et cliquez sur **Set conditions**.
4. Ajoutez une condition. Si vous souhaitez désactiver le bouton **submit** tant que l'entrée n'est pas validée, comparez la variable `isValid` de l'entrée à `false`. Pour que l'état **Disabled** s'applique, renseignez tous les champs **Value**.
5. Stylisez l'état Disabled pour signaler visuellement la restriction (par exemple, réduisez l'opacité).

<ZoomImage id="element-states-disabled-condition.webp" width="400px" alt="La fenêtre contextuelle Modifier l'état conditionnel avec la condition email.isValid = False" />

Le SDK Adapty évalue la condition à l'exécution et applique l'état Désactivé le cas échéant — aucun code applicatif n'est nécessaire.

Une condition **Désactivé** peut également évaluer l'état d'un autre élément. Par exemple, vous pouvez [désactiver deux éléments ensemble](element-states-in-conditions#synchronize-element-states).

### Ajouter un état personnalisé \{#add-a-custom-state\}

Pour un rendu que les états intégrés ne couvrent pas, ajoutez un état personnalisé : il peut dépendre d'une réponse, d'un appui ou de l'état d'un autre élément. Par exemple :

- Mettre en avant la carte d'un forfait annuel lorsqu'un interrupteur d'essai est activé.
- Changer la couleur d'un bouton **Remind me** après que les utilisateurs l'ont appuyé. Pour configurer cela, [basculez le bouton vers un état personnalisé au moment de l'appui](#switch-an-element-to-a-custom-state-on-tap).

Un état personnalisé modifie uniquement l'apparence. Pour empêcher les utilisateurs d'interagir avec un élément, [ajoutez l'état **Disabled**](#add-the-disabled-state).

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="La liste des états avec l'option État personnalisé désactivée et la légende Ajouter une action de pression pour utiliser les états personnalisés" />

Ces éléments peuvent avoir des états personnalisés :

- **Boutons, images, conteneurs, vidéos, minuteries et carrousels** : Ils nécessitent une [action de pression](onboarding-actions#set-up-interactions). Si vous supprimez l'action de pression, les utilisateurs ne verront plus leurs états personnalisés.
- **Éléments sélectionnables** : Ils nécessitent un groupe ou une action de pression.
- **Inputs** : Champs de texte, e-mail, mot de passe, numérique et téléphone.

Ces éléments ne peuvent pas avoir d'états personnalisés :

- En-têtes d'onglets et contenu des onglets
- Sélecteurs
- Feuilles du bas (bottom sheets)
- Étapes d'indicateur de progression

Un élément peut avoir jusqu'à 5 états personnalisés. Une fois ce maximum atteint, l'option **Custom state** est désactivée avec le message « Up to 5 custom states ». Une config issue de la CLI Adapty ou d'un outil IA peut en contenir davantage, et vous pouvez toujours les modifier.

1. Sélectionnez l'élément cible.
2. Dans la section **States**, cliquez sur **Add state**, puis sélectionnez **Custom state**. Si l'élément possède déjà des états autres que **Default**, cliquez sur **Settings** <Inline id="settings.svg" alt="Settings" /> avant **Add state**.
3. Dans le champ **Name**, entrez un nom pour l'état, par exemple **Locked**. Tant que le nom enfreint l'une de ces règles, une erreur s'affiche sous le champ et **Save** reste désactivé :

    - **Le nom est obligatoire** : Le nom ne peut pas être vide.
   - **30 caractères maximum** : Le nom ne peut pas dépasser 30 caractères.
   - **Ce nom est réservé** : Le nom ne peut pas être **Default**, `focused`, ni le nom d'un état intégré : **Selected**, **Active**, **Invalid**, **Disabled**, **Completed**, **Current** ou **Upcoming**.
   - **Un état portant ce nom existe déjà** : Chaque état personnalisé de l'élément doit avoir son propre nom. La casse des lettres ne différencie pas les noms.

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="The Edit state panel with the name Locked and the condition plan = free" />

4. Ajoutez une condition, par exemple `plan` = `free`. Pour ajouter des lignes supplémentaires, cliquez sur **Add Condition**. Si une seule ligne vraie suffit, cliquez sur **all** pour basculer vers **any**. Pour que l'état s'applique, renseignez tous les champs **Value**.
5. Cliquez sur **Save**.
6. Pour styliser l'état, activez son onglet dans la section **States** et [modifiez les propriétés de l'élément](#style-a-state). Sur un champ texte, un état personnalisé ne modifie que le remplissage, la bordure et le rayon des coins.

Le builder ne prévient pas si le champ **Value** est vide. Si une ligne a une valeur mais pas de variable, vous ne pouvez pas publier le flow : la boîte de dialogue **Can't publish yet** liste cette ligne sous **Broken references**. L'interface CLI Adapty et l'API retournent l'erreur [**Invalid State Condition**](flow-common-issues#a-flow-wont-preview-or-publish) pour cette ligne.

Sur une vidéo ou un carrousel, un changement d'état peut relancer la vidéo ou ramener le carrousel à sa première diapositive.

La condition d'un état personnalisé peut également [évaluer l'état d'un autre élément](element-states-in-conditions#add-an-element-state-to-a-condition), par exemple si un interrupteur est **Selected**.

### Basculer un élément vers un état personnalisé au toucher \{#switch-an-element-to-a-custom-state-on-tap\}

Aucune action ne bascule directement un élément vers un état personnalisé. À la place, modifiez une variable personnalisée au toucher, puis basez la condition de l'état sur cette variable.

1. [Créez une variable personnalisée](onboarding-variables#create-a-custom-variable) de type **Boolean**, avec la valeur initiale `false`.
2. Sélectionnez l'élément sur lequel les utilisateurs appuient. Dans l'onglet **Interactions**, [ajoutez une action **Set variable**](onboarding-variables#update-a-variable-via-an-interaction) à son déclencheur **On Tap**, et définissez la variable sur `true`.
3. [Ajoutez un état personnalisé](#add-a-custom-state) à l'élément qui bascule. Dans la condition, sélectionnez la variable dans l'onglet **Custom** du champ **Variable**. Définissez le champ **Value** sur `true`.

<ZoomImage id="element-states-custom-variable-picker.webp" width="500px" alt="L'onglet Personnalisé du champ Variable, avec la variable reminder.set sélectionnée dans la condition d'un état personnalisé" />

### Modifier ou supprimer un état personnalisé \{#edit-or-delete-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="L'infobulle de l'onglet Verrouillé avec le bouton Modifier l'état" />

Pour renommer un état personnalisé ou modifier sa condition, sélectionnez l'élément. Dans la section **States** du panneau de droite, survolez l'onglet de l'état et cliquez sur **Edit state**. Vous pouvez aussi cliquer sur **Settings** <Inline id="settings.svg" alt="Settings" /> dans cette section, puis sur le nom de l'état. L'état conserve ses styles, et les conditions qui l'évaluent affichent le nouveau nom.

Pour supprimer un état personnalisé, sélectionnez l'élément. Dans la section **States** du panneau de droite, cliquez sur **Settings** <Inline id="settings.svg" alt="Settings" />, puis cliquez sur l'icône corbeille dans la ligne de l'état. Si des conditions utilisent cet état, une boîte de dialogue les liste au préalable. Après avoir cliqué sur **Delete**, ces conditions sont rompues et vous ne pouvez pas publier le flow tant que vous ne les avez pas corrigées. Pour restaurer l'état avec ses styles, annulez la suppression.
