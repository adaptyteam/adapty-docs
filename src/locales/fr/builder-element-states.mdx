Les éléments interactifs d'un flow changent d'apparence selon les actions de l'utilisateur : une option de quiz sélectionnée passe à l'état **Selected**, un champ de saisie actif passe à l'état **Active**. Certains états sont conditionnels : vous pouvez **désactiver** un bouton, ou ajouter un [état personnalisé](#custom-states) avec votre propre nom et condition. Stylisez chaque état séparément pour donner un retour visuel aux utilisateurs, sans code côté application.

## États disponibles par type d'élément \{#available-states-by-element-kind\}

| Type d'élément | États intégrés | États ajoutables |
|---|---|---|
| [Éléments sélectionnables](#selectable-element-states) | **Default**, **Selected** | **Disabled**, [états personnalisés](#custom-states) |
| [Champs de saisie](#input-states) | **Default**, **Active**, **Invalid** | **Disabled** ; [états personnalisés](#custom-states) sur les champs de type texte, e-mail, mot de passe, nombre et téléphone |
| [Tout élément avec une interaction tactile](#condition-driven-disabled-state) — boutons, images, icônes, conteneurs, etc. | **Default** | **Disabled**, [états personnalisés](#custom-states) sur les [éléments compatibles](#elements-that-support-custom-states) |
| [Étapes de l'indicateur de progression](#step-states-for-progress-indicators) | **Completed**, **Current**, **Upcoming** | — |

Les états **Addable** n'apparaissent pas par défaut — ouvrez **States settings** <Inline id="settings.svg" alt="Settings" /> pour les ajouter. Ils sont pilotés par des conditions : vous définissez quand ils s'activent. Consultez [État Désactivé piloté par des conditions](#condition-driven-disabled-state) et [États personnalisés](#custom-states).

Les conditions d'autres éléments peuvent également évaluer les états d'un élément. Par exemple, vous pouvez [expliquer pourquoi un bouton est désactivé](element-states-in-conditions#explain-why-a-button-is-disabled).

## Lorsque plusieurs états s'appliquent à un élément \{#when-several-states-apply-to-one-element\}

Plusieurs états peuvent s'appliquer à un même élément simultanément. Par exemple :

- Les utilisateurs saisissent une adresse invalide dans un champ e-mail, puis appuient à nouveau dessus pour la corriger. Le champ a le focus, donc **Active** s'applique. L'adresse est toujours invalide, donc **Invalid** s'applique aussi.
- Les utilisateurs activent un bouton bascule d'essai, donc **Selected** s'applique. Puis ils choisissent un plan sans essai. Le bouton bascule a une condition **Disabled** pour ce plan, donc **Disabled** s'applique aussi.
- Un bouton **Continue** a un état **Disabled** et un état personnalisé nommé **Locked**. Les deux conditions sont vraies, donc les deux états s'appliquent.

Un élément ne peut être que dans un seul état à la fois. Lorsque plusieurs états s'appliquent, l'élément prend celui qui apparaît en dernier dans cette liste :

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. Un [état personnalisé](#custom-states)

Lorsque plusieurs états personnalisés s'appliquent, l'élément prend celui qui apparaît en dernier dans la liste des paramètres **States**.

Dans les exemples, le champ e-mail est **Active**, le bouton bascule d'essai est **Disabled** et le bouton **Continue** est **Locked**. L'élément s'affiche tel que vous avez stylisé cet état. Une condition qui évalue l'état de l'élément ne correspond qu'à cet état. Lorsqu'aucun de ces états ne s'applique, l'élément est **Default**.

Un état personnalisé définit uniquement l'apparence de l'élément. Un élément **Disabled** ignore toujours les touches, même lorsqu'un état personnalisé en modifie l'apparence.

## Comment styliser un état \{#how-to-style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="Section États dans le panneau droit d'un élément sélectionné" float="right" />


1. Sélectionnez un élément. La section **States** dans le panneau droit liste les états pris en charge par l'élément.
2. Dans la section **States**, activez l'état cible. Si nécessaire, ajoutez [l'état Disabled conditionnel](#condition-driven-disabled-state) ou un [état personnalisé](#custom-states).
3. Modifiez n'importe quelle propriété — remplissage, bordure, typographie, etc. La modification s'applique uniquement à cet état.

    Les éléments imbriqués deviennent avec état en même temps que le parent. Toute modification apportée à un enfant est limitée à l'état actif du parent.

4. Le Builder applique le style correspondant à l'exécution.

## États des éléments sélectionnables \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Élément sélectionnable avec l'état Selected activé et un style personnalisé appliqué" />

Les éléments sélectionnables — options de quiz, produits, onglets, bascules et cases à cocher, et tout [élément sélectionnable personnalisé](flow-selectable-elements#make-an-element-selectable) — disposent de deux états par défaut :

- **Default** : L'apparence au repos de l'élément.
- **Selected** : S'applique lorsque l'utilisateur appuie sur l'élément. Le Builder revient à Default lorsque l'utilisateur désélectionne l'élément.

Dans un groupe à choix unique, sélectionner un élément désélectionne les autres. Les groupes à choix multiple permettent de sélectionner plusieurs éléments simultanément. Les bascules sont indépendantes — sélectionner l'une n'a aucun effet sur les autres. Voir [types de groupes](flow-selectable-elements#group-types).

:::tip
Pour réutiliser des styles propres à un état, ajoutez-les à un élément, par exemple une carte produit. Demandez ensuite à l'[éditeur IA](flow-ai-editor) de les appliquer aux autres éléments. Les styles liés à un état ne se propagent pas automatiquement aux éléments frères.
:::

## États des entrées \{#input-states\}

- **Default** : L'apparence au repos de l'input.
- **Active** : S'applique lorsque l'input est en focus.
- **Invalid** : S'applique lorsque le contenu de l'input échoue à la validation. Par exemple, lorsqu'un champ email ne contient pas `@`. Voir [Validation des inputs](builder-inputs-and-forms#input-validation).
- **Disabled** : L'input n'est pas interactif. Ajoutez cet état manuellement ; voir [État Disabled conditionnel](#condition-driven-disabled-state).
- **Custom states** : Uniquement pour les inputs de type texte, email, mot de passe, nombre et téléphone. Dans un état personnalisé, seuls le remplissage, la bordure et le rayon des coins de l'input changent. Voir [Custom states](#custom-states).

Style each state the same way as a selectable element: activate the target state, change properties.

## État Désactivé basé sur des conditions \{#condition-driven-disabled-state\}

L'état Désactivé empêche l'utilisateur d'interagir avec un élément. Contrairement aux états Default, Selected, Active ou Invalid, l'état Disabled ne s'active pas automatiquement — il nécessite une condition déclencheur définie par l'utilisateur.

Disabled est disponible sur :

- **Inputs** : Tout [champ de saisie](builder-inputs-and-forms) — texte, e-mail, mot de passe, nombre, téléphone, date et/ou heure.
- **Éléments sélectionnables** : Options de quiz, produits, onglets, bascules et cases à cocher, et tout [élément sélectionnable personnalisé](flow-selectable-elements#make-an-element-selectable).
- **Tout élément avec une interaction tactile** : Par exemple, un bouton, une image ou une icône qui déclenche une action de navigation.

### Ajouter l'état Désactivé \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="Section États avec le menu Ajouter un état ouvert et l'option Désactivé" />

Pour ajouter et configurer un état Désactivé :

1. Sélectionnez l'élément cible.
2. Dans la section **States**, cliquez sur **Add state**, puis sélectionnez **Disabled**. Si l'élément possède déjà des états, cliquez d'abord sur **Settings** <Inline id="settings.svg" alt="Settings" /> : **Add state** se trouve sous la liste des états. Sur un élément qui ne peut pas avoir d'états personnalisés, le contrôle est le bouton **Disabled state**.
3. L'état Disabled apparaît dans la section **States**.
4. À côté du nouvel état Disabled, cliquez sur **Edit conditional state** <Inline id="visibility-conditional.svg" alt="Edit conditional state" />.
5. Ajoutez une condition. Si vous souhaitez désactiver le bouton **submit** tant que la saisie n'est pas validée, comparez la variable `isValid` de l'input à `false`.
6. Stylisez l'état Disabled pour signaler visuellement la restriction (par exemple, réduisez l'opacité).

{ <ZoomImage id="set-disabled-condition.webp" width="700px" alt="Set condition for disabled state " />}

Le SDK d'Adapty évalue la condition au moment de l'exécution et applique l'état Disabled quand c'est pertinent — aucun code d'application n'est nécessaire.

Une condition **Disabled** peut aussi évaluer l'état d'un autre élément. Par exemple, vous pouvez [désactiver deux éléments ensemble](element-states-in-conditions#synchronize-element-states).

## États personnalisés \{#custom-states\}

Un état personnalisé est un état avec votre propre nom et votre propre condition. Par exemple, un état **Locked** peut rendre un bouton gris tant que l'utilisateur est sur un plan gratuit. L'élément est dans l'état personnalisé tant que sa condition est vraie.

Chaque élément peut avoir jusqu'à 5 états personnalisés.

### Éléments prenant en charge les états personnalisés \{#elements-that-support-custom-states\}

- **Éléments avec une action au toucher** : Boutons, conteneurs, images, vidéos, minuteurs et carrousels. Commencez par ajouter un [déclencheur **On Tap**](onboarding-actions#set-up-interactions) avec au moins une action dans l'onglet **Interactions**.
- **Éléments sélectionnables** : Éléments d'un groupe sélectionnable, et éléments sélectionnables avec une action au toucher.
- **Champs de saisie** : Champs de texte, e-mail, mot de passe, nombre et téléphone.

Les autres éléments, tels que les icônes, les feuilles de bas de page, les onglets, le contenu des onglets, les sélecteurs et les étapes d'indicateur de progression, ne peuvent pas avoir d'états personnalisés.

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="Add state menu with the Custom state option turned off and the caption Add a tap action to use custom states" />

Pour ajouter un état personnalisé à un bouton, un conteneur, une image, une vidéo, un minuteur ou un carrousel, commencez par ajouter un déclencheur **On Tap** avec au moins une action. Sans cela, la section **States** ne dispose d'aucun contrôle **Add state**. Si l'élément possède déjà des états, l'option **Custom state** est désactivée, avec la mention « Add a tap action to use custom states ». Une fois qu'une action de tap est ajoutée, l'option s'active.

### Ajouter un état personnalisé \{#add-a-custom-state\}

<ZoomImage id="custom-state-add-menu.webp" width="300px" float="right" alt="Section États avec le menu Ajouter un état ouvert, listant Désactivé et État personnalisé" />

1. Sélectionnez l'élément.
2. Dans la section **States**, cliquez sur **Add state**. Si l'élément possède déjà des états, cliquez d'abord sur **Settings** <Inline id="settings.svg" alt="Settings" /> : **Add state** se trouve sous la liste des états.
3. Sélectionnez **Custom state**. Le panneau **Edit state** s'ouvre.

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="Panneau de modification d'état avec le nom Verrouillé et la condition plan est égal à free" />

4. Dans **Name**, saisissez un nom pour l'état, par exemple **Locked**. Le nom suit les [règles de nommage](#name-rules).
5. Ajoutez une condition. Par exemple, comparez la variable `plan` à `free`. Pour ajouter d'autres conditions, cliquez sur **Add Condition** et choisissez si **all** ou **any** d'entre elles doivent être vraies.
6. Cliquez sur **Save**. Le nouvel état apparaît sous forme d'onglet dans la section **States**.
7. Activez l'onglet du nouvel état et [appliquez-lui un style](#how-to-style-a-state). Les styles des éléments imbriqués, comme le texte d'un bouton, s'appliquent également sur l'appareil.

Pour fermer le panneau **Edit state** sans enregistrer, cliquez sur **Cancel** ou le bouton de fermeture, appuyez sur **Escape**, ou cliquez en dehors du panneau.

Lorsqu'un élément possède déjà 5 états personnalisés, l'option **Custom state** est désactivée avec le message « Up to 5 custom states ». Pour ajouter un nouvel état, supprimez-en un d'abord. Si une configuration de flow importée depuis un JSON ou un outil IA contient plus de 5 états personnalisés sur un élément, ces états sont conservés et vous pouvez les modifier.

### Règles de nommage \{#name-rules\}

Le builder ignore la casse : **Locked** et **locked** sont le même nom. Il supprime également les espaces en début et en fin de nom à l'enregistrement. Si le nom enfreint une règle, le bouton **Save** est désactivé et une erreur s'affiche sous le champ :

| Règle | Erreur |
|---|---|
| Le nom n'est pas vide. | **Name is required** |
| Le nom comporte 30 caractères ou moins. | **Max 30 characters** |
| Le nom n'est pas **Default** ni le nom d'un état intégré : **Selected**, **Active**, **Invalid**, **Disabled**, **Completed**, **Current**, **Upcoming** ou `focused`. | **This name is reserved** |
| Le nom est différent des noms des autres états personnalisés de l'élément. | **A state with this name already exists** |

### Modifier un état personnalisé \{#edit-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="Tooltip of the Locked state tab with the Edit state button" />

Pour modifier le nom ou la condition d'un état personnalisé, ouvrez le panneau **Edit state** de l'une des façons suivantes :

- Dans la liste des paramètres **States**, cliquez sur la ligne de l'état, ou cliquez sur l'icône de condition <Inline id="visibility-conditional.svg" alt="Condition" /> dans cette ligne.
- Survolez l'onglet de l'état, puis cliquez sur **Edit state** dans le tooltip.

Après l'enregistrement, l'état conserve ses styles. Les conditions des autres éléments qui évaluent cet état affichent le nouveau nom.

### Supprimer un état personnalisé \{#delete-a-custom-state\}

Dans la liste des paramètres **States**, cliquez sur l'icône de corbeille dans la ligne de l'état concerné. Si des conditions d'autres éléments évaluent cet état, une boîte de dialogue les liste au préalable. Après avoir cliqué sur **Delete**, ces conditions se cassent et vous ne pouvez pas publier le flow tant que vous ne les avez pas corrigées. Voir [Dépannage](element-states-in-conditions#troubleshooting).

Le builder supprime l'état et ses styles. Si l'onglet de l'état supprimé était actif, l'onglet **Default** devient actif.

Pour restaurer l'état, annulez la suppression. L'état réapparaît au même endroit dans la liste, avec ses styles.

### Conditions incomplètes \{#incomplete-conditions\}

Une ligne de condition est incomplète lorsque l'un de ses côtés est vide. Par exemple, vous avez ajouté une ligne sans la remplir, ou vous avez sélectionné une variable sans saisir de valeur. Une condition comportant une ligne incomplète ne devient jamais vraie, même si les autres lignes sont vraies. L'élément n'entre jamais dans cet état, et l'appareil affiche son style **Default**. Cette règle s'applique également aux conditions **Disabled** : l'élément reste interactif.

Le builder n'affiche pas d'avertissement pour une ligne incomplète, alors remplissez ou supprimez chaque ligne avant de publier. Une ligne avec une valeur ou **est vide** mais sans variable bloque la publication avec une [erreur **Invalid State Condition**](flow-common-issues#a-flow-wont-preview-or-publish).

### Limitations \{#limitations\}

<ZoomImage id="custom-state-device-warning.webp" width="300px" float="right" alt="States settings list with the warning Not shown on the device. Add a tap action to the element. under two custom states" />

- **Éléments qui n'affichent pas l'état sur l'appareil** : Le canvas affiche un état personnalisé sur n'importe quel élément. L'appareil ne l'affiche que sur les [éléments supportés](#elements-that-support-custom-states). Un élément non supporté peut avoir un état personnalisé, par exemple via JSON ou un outil IA, ou après la suppression de son action de tap.

    Dans ce cas, la liste des paramètres **States** et l'info-bulle de l'onglet affichent un avertissement : « Not shown on the device. Add a tap action to the element. » ou « Not shown on the device for this element type. » Vous pouvez toujours modifier, supprimer et publier l'état.
- **Inputs** : Dans un état personnalisé, seul le remplissage, la bordure et le rayon de coin d'un input changent. Les autres propriétés, comme la couleur du texte, conservent leurs valeurs **Default**. Le panneau **Edit state** d'un input affiche la légende « Only fill, border and corner radius change in a custom state ».
- **Vidéos et carrousels** : Lorsqu'une vidéo ou un carrousel change d'état sur l'appareil, la vidéo reprend depuis le début et le carrousel revient à sa première diapositive. N'ajoutez pas d'états personnalisés à une vidéo ou un carrousel qui doit conserver sa position de lecture ou sa diapositive actuelle.

## États des étapes pour les indicateurs de progression \{#step-states-for-progress-indicators\}

:::link
Article principal : [Indicateurs de progression](builder-loaders-and-progress-bars#step-states)
:::

Les indicateurs de progression montrent aux utilisateurs où ils en sont dans un flow d'onboarding. Chaque étape possède trois états :

- **Complétée** : les étapes que l'utilisateur a déjà franchies.
- **Actuelle** : l'étape en cours de l'utilisateur.
- **À venir** : les étapes que l'utilisateur n'a pas encore atteintes.
