Vous pouvez animer les transitions entre les écrans — la façon dont un écran disparaît et dont le nouveau apparaît. Les animations disponibles dépendent de l'action de navigation concernée :

- [**Navigate to Screen**](onboarding-actions#navigate-to-screen) : Ouvrez les [paramètres d'action](#customize-a-transition) et choisissez parmi la [gamme complète de types d'animation](#animation-types). Chaque étape peut utiliser une transition différente.
- **Navigate Next** : Uniquement l'animation push par défaut.
- **Navigate back** : Rejoue la transition utilisée à l'arrivée sur l'écran actuel, mais en sens inverse et sans délai. Si aucune animation n'a été appliquée à l'arrivée, il n'y en a pas non plus au retour.
- **Close Flow** : Aucune animation propre. Votre application gère elle-même la transition entre le flow et votre interface native.

Une action **Navigate to Screen** différée peut [déplacer automatiquement les utilisateurs depuis un écran de chargement ou de démarrage](#move-users-to-another-screen-automatically).

## Types d'animation \{#animation-types\}

Le menu déroulant **Animation** de l'action **Navigate to Screen** propose cinq options :

- **Push** : Le nouvel écran entre par un bord et pousse l'écran actuel vers l'autre bord.
- **Slide in** : Le nouvel écran glisse et apparaît en fondu par-dessus l'écran actuel, qui se déplace légèrement dans la même direction.
- **Slide out** : L'écran actuel glisse et disparaît en fondu, révélant le nouvel écran en dessous.
- **Fade through** : Le nouvel écran apparaît en fondu par-dessus l'écran actuel.
- **None** : Le nouvel écran remplace instantanément l'écran actuel.

## Personnaliser une transition \{#customize-a-transition\}

Vous pouvez uniquement modifier l'animation dans une action **Navigate to Screen**.

<ZoomImage id="navigate-to-screen-settings.webp" width="300px" float="right" alt="Fenêtre de modification d'action pour Navigate to Screen avec Paywall comme destination, Slide in upward avec Ease out bounce, une durée de 400 ms et aucun délai" />

1. Sélectionnez l'élément qui déclenche une action de navigation.
2. Dans le panneau **Interactions**, cliquez sur l'action de navigation.
3. Si l'action est **Navigate Next**, sélectionnez **Navigate to Screen** dans le menu déroulant **Action**. Ensuite, sélectionnez l'écran suivant comme **Destination**.
4. Sélectionnez une animation dans le menu déroulant **Animation**.
5. Si l'animation dispose de paramètres **Direction**, **Easing** ou **Duration**, ajustez-les.
6. Pour garder l'écran actuel visible avant le début de l'animation, définissez une valeur dans le champ **Delay**. Par exemple, utilisez un délai pour maintenir un [écran de chargement](builder-loaders-and-progress-bars#loaders) affiché quelques secondes avant qu'il [passe automatiquement à la suite](#move-users-to-another-screen-automatically). [Les actions listées après la navigation](onboarding-actions#action-order) n'attendent pas le délai.
7. Pour voir la transition sur vos propres écrans, [testez le flow sur un appareil](paywall-device-compatibility-preview#preview-on-devices).

## Rediriger les utilisateurs vers un autre écran automatiquement \{#move-users-to-another-screen-automatically\}

Pour faire passer les utilisateurs d'un écran de démarrage ou de chargement, retardez une action **Navigate to Screen** de 5 secondes maximum.

1. Sélectionnez n'importe quel élément à l'écran, par exemple un loader.
2. Dans le panneau **Interactions**, [ajoutez un déclencheur **On Screen Appear**](onboarding-actions#set-up-interactions) avec une action **Navigate to Screen**.
3. Dans le menu déroulant **Destination**, sélectionnez l'écran suivant.
4. Le champ **Delay** n'apparaît que si vous définissez une **Animation**. Sélectionnez n'importe quelle **Animation** sauf **None**. Pour passer d'un écran à l'autre sans animation visible, réglez le champ **Duration** sur 0.
5. Dans le champ **Delay**, définissez la durée d'affichage de l'écran, jusqu'à 5000 ms. Utilisez des secondes entières : sur iOS, un délai est arrondi à la seconde supérieure.
6. Pour voir l'écran passer à la suite, [testez le flow sur un appareil](paywall-device-compatibility-preview#preview-on-devices). Le canvas n'exécute pas les actions.

Pendant que l'écran attend, certaines interactions annulent l'action **Navigate to Screen** différée :

- Si les utilisateurs appuient sur un bouton qui navigue, ils avancent immédiatement.
- Si les utilisateurs effectuent l'une des actions suivantes, l'écran reste affiché :
  - Ouvrir une alerte, une bottom sheet, un sélecteur de date ou une page web.
  - Lancer un achat ou une restauration.

Si les utilisateurs peuvent effectuer l'une de ces actions sur l'écran, ajoutez un bouton de navigation pour qu'ils puissent avancer.

Quand les utilisateurs reviennent sur l'écran, le délai repart de zéro.

Pour un délai supérieur à 5 secondes, ajoutez un [minuteur](flow-timer) avec un déclencheur **On Timer End** qui navigue vers l'écran suivant. Pour masquer le minuteur, rendez son texte entièrement transparent et laissez **Visibility** sur **Show**, afin que le déclencheur se déclenche.
