Un écran de paywall affiche vos produits et permet à l'utilisateur de les acheter. Adapty vous propose deux façons de le créer :

- **Flows et paywalls** : vous concevez les écrans dans le [Flow & Paywall Builder](adapty-flow-builder), et le SDK Adapty les affiche nativement dans votre application. Créez un simple paywall ou un onboarding complet qui se termine par l'un d'eux.
- **Paywall personnalisé** : vous créez l'écran dans le code de votre propre application et enregistrez les produits qu'il vend dans Adapty sous forme de [paywall personnalisé](paywalls). Adapty gère l'achat.

## Comparer les flows et paywalls avec les paywalls personnalisés \{#compare-flows--paywalls-with-custom-paywalls\}

| | Flows & paywalls | Paywalls personnalisés |
|---|---|---|
| **Qui construit l'UI** | Vous, dans un éditeur visuel sans code. Le SDK le rend nativement, sans web views. | Vos développeurs, dans le code de votre app. |
| **Comment démarrer** | Un [modèle](paywall-builder-templates), un canvas vierge, ou une [importation Figma](import-from-figma). | Votre écran existant et votre design system. |
| **Construire avec l'IA dans le tableau de bord** | L'[éditeur IA](flow-ai-editor) restylise, réécrit ou réorganise un écran à partir d'une demande en langage naturel ou d'une capture d'écran de référence. | Non disponible. |
| **Construire avec votre outil IA de code** | Le [skill flow-generator](flow-generator-skill) crée un flow ou un paywall à partir d'une description ou d'une capture d'écran, et modifie les textes, les locales et les écrans. Le [skill flow-audit](flow-audit-skill) le vérifie avant publication. | Le [skill SDK integration](adapty-sdk-integration-skill) crée le paywall personnalisé via le [Developer CLI](developer-cli-reference#adapty-paywalls-create) et écrit le code d'achat dans votre app. |
| **Modifier sans mise à jour de l'app** | Design, textes, écrans, logique et produits. | Les valeurs du [Remote Config](customize-paywall-with-remote-config) que votre code lit. Les modifications de mise en page nécessitent une mise à jour de l'app. |
| **Design différent par audience** | N'importe quel flow que vous créez, assigné à une audience sur le placement. | Uniquement les designs intégrés dans la version de l'app que l'utilisateur utilise. |
| **Parcours multi-écrans** | Écrans d'onboarding, [quiz](onboarding-quizzes) et [branchements](onboarding-navigation-branching) avant le paywall, avec les réponses utilisateur [transmises à votre app](ios-flow-input). | Ce que votre code construit. |
| **Localisation** | [Locales](add-paywall-locale-in-adapty-paywall-builder) par écran dans le builder. | [Remote config](add-remote-config-locale) par locale, avec traduction IA dans le tableau de bord. |
| **Tests A/B** | Entre flows ou paywalls sur un placement de flow. | Entre paywalls personnalisés sur un placement de paywall. |
| **Analytics** | [Métriques de flow](flow-metrics), avec les revenus attribués à chaque écran. Les vues sont suivies automatiquement. | [Métriques de paywall personnalisé](paywall-metrics). Votre code signale chaque vue à Adapty. |
| **Achats web** | Oui, avec un [web paywall](web-paywall). | Oui, avec un [web paywall](web-paywall). |
| **Taille de l'app** | Les écrans et images se chargent depuis Adapty quand votre app récupère le flow, donc un nouveau paywall n'alourdit pas le bundle de l'app. | Chaque écran, image et chaîne est embarqué dans le bundle de l'app. |
| **Type de placement** | [Placement de flow](create-placement). | [Placement de paywall](create-placement). |
| **SDK Adapty** | v4.0 ou ultérieur. | N'importe quelle version. |

Un paywall du Flow & Paywall Builder et un paywall personnalisé ne peuvent pas partager le même test A/B, car chacun nécessite son propre type de placement. Pour les comparer, [déployez progressivement le paywall du builder](flow-gradual-rollout) sur son propre placement.

## Lequel choisir \{#which-one-to-choose\}

- **Choisissez les flows et paywalls** si vous souhaitez concevoir, tester et modifier l'écran d'achat sans écrire de code UI ni publier une nouvelle version de l'app, ou si le paywall fait partie d'un onboarding.
- **Choisissez un paywall personnalisé** si vous souhaitez créer l'écran dans votre propre code — par exemple, pour réutiliser les composants de votre app.

Lorsque votre application affiche l'écran, le paywall personnalisé dans Adapty est l'ensemble fixe de produits que l'écran propose à la vente, comme un forfait hebdomadaire et un forfait mensuel. Adapty rapporte les conversions et les revenus pour chaque paywall, ce qui vous permet de comparer quels ensembles de produits se vendent le mieux. Vous pouvez afficher différents paywalls à différentes audiences sur un même placement, et les tester les uns contre les autres en test A/B. Pour vendre des produits différents, remplacez le paywall sur le placement depuis le tableau de bord. Aucune mise à jour de l'application n'est nécessaire.

Les deux se trouvent dans **Flows & Paywalls** dans le menu principal d'Adapty : les flows et paywalls dans l'onglet **Flow & Paywall builder**, les paywalls personnalisés dans l'onglet **Custom Paywalls**.

Les paywalls créées avec l'[ancien Paywall Builder](adapty-paywall-builder) restent modifiables dans l'onglet **Custom Paywalls & Legacy**, mais il n'est plus possible d'en créer de nouvelles. Pour recréer une paywall conçue pour Adapty SDK 3.x en tant que flow brouillon tout en conservant l'original actif, utilisez l'action **Move to new builder** — voir [Convertir une paywall en flow](convert-paywall-to-flow). Pour la migration complète, incluant les placements et la mise à jour du SDK, voir [Migrer vers les flows](migrate-to-flows).
