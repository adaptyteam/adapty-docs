Pour connecter votre application iOS à Adapty, saisissez ses identifiants App Store dans **App settings** > **iOS SDK**. Adapty peut alors :

- Valider les achats.
- Recevoir les événements d'abonnement.
- Synchroniser vos produits avec App Store Connect.

Si les achats ou les événements d'abonnement cessent d'arriver dans Adapty, [vérifiez chaque identifiant](#check-each-credential).

<YouTube id="VJQbzoTCkqs" />

Avant de commencer :

- Vous devez avoir accès à l'application cible dans App Store Connect. Si elle n'y figure pas encore, [configurez App Store Connect](set-up-app-store-connect). Si vous n'avez pas accès à la plateforme, faites-en la demande.
- Votre équipe doit avoir accès à l'API App Store Connect — elle est nécessaire pour générer la clé d'accès requise. Si ce n'est pas encore le cas, demandez au titulaire du compte de [faire la demande](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api). Apple examine chaque demande.
- Ouvrez deux onglets dans votre navigateur : votre application dans [App Store Connect](https://appstoreconnect.apple.com/apps) dans l'un, et [**App settings** > **iOS SDK**](https://app.adapty.io/settings/ios-sdk) dans Adapty dans l'autre. Vous copierez des valeurs entre les deux onglets tout au long de ce guide.

## Vue d'ensemble \{#overview\}

Chaque identifiant présenté dans ce guide est obligatoire. Adapty utilise chacun d'eux pour [une partie différente de l'échange de données avec l'App Store](store-sync#if-updates-stop-arriving). Pour terminer la configuration, suivez ces sept étapes :

1. Entrez [le Bundle ID et l'Apple App ID](#enter-the-bundle-id-and-apple-app-id)
2. Entrez [le secret partagé propre à l'application](#enter-the-app-specific-shared-secret)
3. Activez [les notifications du serveur App Store](#enable-app-store-server-notifications) avec l'URL d'Adapty
4. Ajoutez la [clé d'achat intégré](#add-the-in-app-purchase-key)
5. Ajoutez la [clé API App Store Connect](#add-the-app-store-connect-api-key)
6. Installez le [SDK Adapty et effectuez un achat sandbox](#check-each-credential)
7. [Vérifiez toutes les informations d'identification](#check-each-credential)

## Saisir le Bundle ID et l'Apple App ID \{#enter-the-bundle-id-and-apple-app-id\}

Deux valeurs identifient votre application dans App Store Connect : le Bundle ID et l'Apple ID, appelé **Apple App ID** dans Adapty. Adapty a besoin du Bundle ID pour traiter les achats. Avec l'Apple ID, Adapty :

- Trouve vos produits dans App Store Connect et [en crée de nouveaux](create-product#create-product-and-push-to-store).
- Affiche le statut App Store et les prix de vos produits.
- Envoie des messages en temps réel pour la [messagerie de rétention](retention-messaging-setup).
- Exécute l'analyse de l'[AI Growth Advisor](autopilot).
- Identifie votre application auprès des intégrations d'attribution, comme AppsFlyer.

Apple attribue l'Apple ID lorsque vous ajoutez l'application à App Store Connect, donc renseignez-le même si votre application n'est pas encore sur l'App Store.

## Saisissez le secret partagé spécifique à l'application \{#enter-the-app-specific-shared-secret\}

Adapty a besoin du secret partagé spécifique à l'application pour valider les reçus d'achat et créer des produits dans App Store Connect.

1. Dans [App Store Connect](https://appstoreconnect.apple.com/apps), ouvrez la page **App Information** de votre application. Dans la section **App-Specific Shared Secret**, cliquez sur **Manage**.

   <ZoomImage id="asc-app-information-shared-secret.webp" width="700px" alt="Section App-Specific Shared Secret sur la page App Information dans App Store Connect" />

2. Copiez le secret. Si l'application n'a pas encore de secret, cliquez d'abord sur **Generate**. Pour générer un secret, vous devez avoir le rôle Account Holder ou Admin dans App Store Connect. Si vous n'avez ni l'un ni l'autre, demandez à quelqu'un qui possède ce rôle de générer le secret et de vous l'envoyer.

   Sauf si vous avez reçu l'application via un [transfert d'app](transfer-apps#app-store-ios-transfer), ne cliquez pas sur **Regenerate** : le secret actuel cesserait alors de fonctionner partout où il est utilisé.

   <ZoomImage id="asc-shared-secret-dialog.webp" width="700px" alt="Fenêtre App-Specific Shared Secret avec le secret" />

3. Dans Adapty, collez le secret dans le champ **App Store Connect shared secret**.

   <ZoomImage id="app-settings-shared-secret.webp" width="700px" alt="Champ App Store Connect shared secret dans Adapty" />

4. Cliquez sur **Save**.

## Activer les notifications serveur App Store avec l'URL d'Adapty \{#enable-app-store-server-notifications\}

:::link
Article principal : [Activer les notifications serveur App Store](enable-app-store-server-notifications)
:::

Apple envoie à Adapty des notifications serveur concernant les renouvellements, les remboursements et d'autres événements d'abonnement au moment où ils se produisent. Adapty enregistre ces événements même lorsque votre application ne signale aucune transaction.

Si Apple envoie déjà ces notifications à un serveur, configurez le transfert vers ce serveur avant de remplacer son URL dans App Store Connect. Dans Adapty, saisissez l'URL de ce serveur dans le champ **URL for forwarding raw Apple events**, puis cliquez sur **Save**. Adapty [transfère alors les notifications reçues d'Apple](enable-app-store-server-notifications#raw-events-forwarding) vers ce serveur.

Si votre backend doit conserver son URL dans App Store Connect, [transmettez les notifications à Adapty depuis votre backend](forwarding-events-to-adapty) à la place.

## Ajouter la clé API App Store Connect

:::link
Article principal : [Ajouter la clé API App Store Connect à Adapty](app-store-connect-api-key)
:::

Adapty utilise la clé API App Store Connect pour [créer des produits dans App Store Connect](create-product#create-product-and-push-to-store) et synchroniser leur statut et leurs prix. Cette clé est différente de la clé d'achat intégré (In-App Purchase), bien que les deux partagent les champs **Issuer ID** et **Key ID**.

Adapty a besoin d'une clé d'équipe avec un accès **Admin**. Si vous n'en avez pas encore, [générez-la dans App Store Connect](app-store-connect-api-key#generate-a-team-key-in-app-store-connect) d'abord. Pour connecter la clé dans Adapty :

## Vérifiez que chaque identifiant fonctionne \{#check-each-credential\}

Pour confirmer qu'Adapty valide les achats, [installez le SDK Adapty](installation-of-adapty-sdks) dans votre application et [effectuez un achat sandbox](test-purchases-in-sandbox).

L'achat sandbox n'utilise que certains identifiants. Vérifiez chacun d'eux après l'achat, et à nouveau chaque fois que les achats ou les événements d'abonnement cessent de parvenir à Adapty :

- **Bundle ID**, **Apple App ID** et **App Store Connect shared secret** : Comparez ces trois valeurs avec le **Bundle ID**, l'**Apple ID** et le secret sous **App-Specific Shared Secret** sur la page **App Information** dans App Store Connect.
- **App Store server notifications** : Le statut dans cette section affiche **Active** dès qu'une notification d'achat ou de renouvellement parvient à Adapty. Si un autre statut est affiché, [vérifiez les URL de serveur](enable-app-store-server-notifications#check-that-notifications-reach-adapty).
- **In-app purchase API (StoreKit 2)** : Adapty vérifie la clé auprès d'Apple lors de l'enregistrement. Si des achats effectués dans votre application ne débloquent aucun accès par la suite, il est possible que la clé ait cessé de fonctionner : [remplacez la clé](generate-in-app-purchase-key#replace-the-key).
- **App Store promotional offers** : Assurez-vous que le **Subscription key ID** correspond au **Key ID** dans la section **In-app purchase API (StoreKit 2)**. S'ils diffèrent, [saisissez la même clé dans les deux sections](generate-in-app-purchase-key#add-the-key-to-adapty).
- **App Store Connect API key** : Chaque produit App Store affiche un statut dans la colonne **App Store status** sur la page **Products**. Si un produit affiche un tiret ou **Not Connected**, [vérifiez la clé et l'Apple App ID](troubleshoot-app-store-integration#products-dont-appear-or-show-no-app-store-status).

Juste après la configuration, Analytics peut comptabiliser plus d'essais et d'achats que d'installations, et plus que ce qu'affiche l'Event Feed. La différence correspond aux [transactions sans profils](how-profiles-work#transactions-without-profiles) : des achats d'utilisateurs qui n'ont pas encore ouvert une version de votre application intégrant le SDK Adapty.

Les autres différences entre Adapty et les rapports du store proviennent de [la façon dont chacun comptabilise les achats](discrepancies-and-troubleshooting), pas des identifiants.
