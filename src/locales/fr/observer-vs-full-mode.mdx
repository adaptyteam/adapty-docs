Adapty est une plateforme d'achats intégrés puissante et flexible, conçue pour augmenter vos revenus et votre base d'abonnés. Grâce à des fonctionnalités telles que des paywalls personnalisables adaptés à des segments d'utilisateurs spécifiques, des tests A/B sur les prix, les durées, les périodes d'essai et les éléments visuels, ainsi que des outils analytiques complets pour la monétisation des applications et des intégrations tierces, Adapty renforce votre stratégie de croissance.

Cependant, si vous disposez déjà de votre propre infrastructure d'achat et que vous n'êtes pas prêt à passer au système d'Adapty, vous pouvez explorer le mode Observer d'Adapty. Ce mode limité n'utilise pas les paywalls d'Adapty, ne cible pas les audiences, ne gère pas les abonnements (renouvellements et nouvelles tentatives de facturation inclus) et se concentre uniquement sur l'analyse. Malgré ses limitations, le mode Observer offre tout de même de solides fonctionnalités analytiques, notamment l'intégration avec les systèmes d'attribution, des analyses avancées, la messagerie et les profils CRM.

Les deux modes sont proposés au même prix et nécessitent une mise à jour de votre application mobile. Le choix revient donc à opter soit pour l'infrastructure d'Adapty afin de bénéficier de toutes les fonctionnalités, soit pour conserver votre infrastructure actuelle tout en profitant uniquement des intégrations tierces et des capacités analytiques.

| Fonctionnalité | Mode Observateur | Mode Complet |
|-------------|-------------|---------|
| **Analyses complètes** | ✅ | ✅ |
| **Intégrations tierces** | ✅ | ✅ |
| **Répondre aux événements d'achat pour accorder/restreindre l'accès payant à vos utilisateurs** | ❌ | ✅ |
| **Responsable de l'infrastructure des achats** | Vous | Adapty |
| **Tests A/B** | <p>Réalisable, mais nécessite une quantité importante de code et de configuration supplémentaires, bien plus qu'en mode complet.</p> | ✅ |
| **Temps de mise en œuvre** | <p>Pour les analyses et les intégrations : moins d'une heure</p><p>Avec les tests A/B : jusqu'à une semaine avec des tests approfondis</p> | Quelques heures |

## Fonctionnement du mode Observateur \{#how-observer-mode-works\}

En mode Observateur, vous signalez les nouvelles transactions Apple/Google au SDK Adapty, qui les transmet ensuite au backend Adapty. C'est vous qui gérez l'accès au contenu payant dans votre application, la finalisation des transactions, le traitement des renouvellements, la gestion des problèmes de facturation, etc.

## Comment configurer le mode Observateur \{#how-to-set-up-observer-mode\}

1. Configurez l'intégration initiale d'Adapty [avec Google Play](initial-android) et [avec l'App Store](initial_ios).
2. Activez-la lors de la configuration du SDK en définissant le paramètre `observerMode` sur `true` : [iOS](implement-observer-mode) | [Android](implement-observer-mode-android) | [React Native](implement-observer-mode-react-native) | [Flutter](implement-observer-mode-flutter) | [Unity](implement-observer-mode-unity) | [Kotlin Multiplatform](implement-observer-mode-kmp) | [Capacitor](implement-observer-mode-capacitor)
3. Transmettez les transactions de votre infrastructure d'achat existante à Adapty : [iOS](report-transactions-observer-mode) | [Android](report-transactions-observer-mode-android) | [React Native](report-transactions-observer-mode-react-native) | [Flutter](report-transactions-observer-mode-flutter) | [Unity](report-transactions-observer-mode-unity) | [Kotlin Multiplatform](report-transactions-observer-mode-kmp) | [Capacitor](report-transactions-observer-mode-capacitor)
4. (facultatif) Si vous souhaitez utiliser des intégrations tierces, configurez-les comme décrit dans la rubrique [Configurer une intégration tierce](configuration).

:::warning
En mode Observateur, le SDK Adapty ne finalise pas les transactions ; veillez à gérer cet aspect vous-même.
:::

## Comment utiliser les flows, paywalls et tests A/B en mode Observer \{#how-to-use-paywalls-and-a-b-tests-in-observer-mode\}

En mode Observer, le SDK Adapty ne peut pas déterminer la source des achats, car ceux-ci sont effectués dans votre propre infrastructure. Par conséquent, si vous souhaitez utiliser des flows, des paywalls et/ou des tests A/B en mode Observer, vous devez associer la transaction provenant de votre store au flow ou paywall correspondant dans le code de votre application mobile au moment où vous signalez une transaction.

De plus, les flows et paywalls créés dans le Flow Builder doivent s'afficher d'une manière particulière lorsque vous utilisez le mode Observer :
