Vous pouvez mesurer l'impact de votre flow ou paywall en exécutant un test A/B contre une variante vide. Une variante affiche votre flow/paywall ; l'autre n'affiche rien. Votre application lit un indicateur depuis le Remote Config pour décider si elle doit effectuer le rendu.

## Fonctionnement \{#how-it-works\}

La configuration utilise deux flows/paywalls dans le même placement :

- **Flow/Paywall A** : le flow ou paywall que vous souhaitez tester, avec `show_paywall` défini sur `true` dans son Remote Config.
- **Flow/Paywall B** : un flow ou paywall vide avec `show_paywall` défini sur `false` dans son Remote Config.

Lorsque le SDK renvoie un flow ou un paywall, votre application lit le flag `show_paywall`. Si le flag est `true`, l'application l'affiche. S'il est `false`, l'application ignore l'affichage et l'utilisateur continue sans rien voir.

## 1. Ajouter le flag show_paywall dans le Remote Config \{#1-add-the-show_paywall-flag-in-remote-config\}

Vous avez besoin de deux flows ou paywalls dans le même placement : Flow/Paywall A (celui que vous souhaitez tester) et Flow/Paywall B (un vide). Ajoutez un champ `show_paywall` à chacun afin que votre application puisse se brancher sur la même clé pour les deux variantes.

Pour ajouter le flag à Flow/Paywall A :

1. Ouvrez la section [**Flows**](https://app.adapty.io/flows)/[**Paywalls**](https://app.adapty.io/paywalls) dans le menu principal d'Adapty et sélectionnez le Flow/Paywall A.
2. Ouvrez la section **Remote config**.
3. Créez un champ avec le nom `show_paywall` et la valeur `true`. Dans la vue **JSON**, l'entrée ressemble à :

   ```json showLineNumbers
   {
     "show_paywall": true
   }
   ```

4. Enregistrez les modifications.

Répétez les mêmes étapes pour le Flow/Paywall B, mais définissez `show_paywall` sur `false`.

Pour tous les détails sur le Remote Config, consultez [Personnaliser un flow avec le Remote Config](customize-flow-with-remote-config) ou [Concevoir un paywall avec le Remote Config](customize-paywall-with-remote-config).

:::tip
Définir `show_paywall` sur les deux variantes conserve un chemin de code identique pour les deux groupes et facilite l'ajout de nouvelles variantes ultérieurement.
:::

## 2. Configurer le test A/B \{#set-up-the-ab-test\}

1. [Créez un test A/B](run_stop_ab_tests) sur le placement et ajoutez les deux flows/paywalls comme variantes.
2. Définissez les pondérations des variantes pour répartir le trafic entre les utilisateurs qui voient le flow/paywall et ceux qui ne le voient pas.

## 3. Vérifier le flag dans votre application \{#3-check-the-flag-in-your-app\}

Lisez `show_paywall` depuis le Remote Config renvoyé par le SDK. Si le flag est `false`, ne rendez pas la paywall et laissez l'utilisateur continuer.

La valeur de repli `true` maintient le flow/paywall visible lorsque l'indicateur est absent, de sorte que les flows/paywalls existants sans cet indicateur ne sont pas affectés.

:::important
Si vous affichez le paywall vous-même (sans qu'Adapty ne le rende), appelez [`logShowFlow` (iOS SDK v4+) / `logShowPaywall`](present-remote-config-paywalls#track-paywall-view-events) lorsque vous affichez le Flow/Paywall A. Sans cela, Adapty ne peut pas comptabiliser les vues dans le test. N'enregistrez pas de vue pour le Flow/Paywall B, car il n'est jamais affiché.
:::
