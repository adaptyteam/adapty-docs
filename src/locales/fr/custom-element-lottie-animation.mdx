Suivez cette recette pour afficher la progression de l'utilisateur sous forme d'animation Lottie — par exemple, un anneau qui se remplit pour indiquer sa série quotidienne. Votre application affiche l'animation comme une vue Lottie native dans un [élément personnalisé](flow-custom-elements).

:::tip
Cette recette ne couvre que les applications iOS. Les applications développées avec d'autres frameworks n'affichent que le [contenu de secours](flow-custom-elements#set-fallback-content) des éléments personnalisés. La prise en charge d'Android et des frameworks multiplateforme est à venir.
:::

## Avant de commencer \{#before-you-start\}

- Mettez à jour votre application avec le SDK iOS Adapty 4.4 ou une version ultérieure. Les versions antérieures du SDK affichent le [contenu de secours](flow-custom-elements#set-fallback-content) pour chaque élément personnalisé.
- Configurez votre application pour [récupérer](get-pb-paywalls) et [afficher](ios-present-paywalls) les flows.
- Ajoutez Lottie à votre application via Swift Package Manager, depuis `https://github.com/airbnb/lottie-spm.git`.
- Préparez une animation Lottie au format `.json`, ou téléchargez l'exemple [`streak_ring.json`](https://raw.githubusercontent.com/adaptyteam/adapty-docs/refs/heads/main/Downloads/streak_ring.json). L'application joue l'animation depuis le début et la stoppe proportionnellement à la progression — par exemple à mi-chemin pour 50 %. Pour afficher la progression exacte, l'animation doit respecter ces conditions :
  - Aucune progression sur sa première image, et une progression complète sur sa dernière image.
  - Une vitesse constante, sans accélération ni décélération. Si l'animation démarre lentement puis accélère, elle affiche moins de la moitié de la progression à mi-chemin.

## 1. Ajouter l'élément personnalisé à l'écran \{#1-add-the-custom-element-to-the-screen\}

Dans le Flow & Paywall Builder, [ajoutez un élément personnalisé](flow-custom-elements#add-and-configure) à un écran de flow, et configurez-le pour l'animation :

- **Type** : `lottie_animation`.
- **ID** : `streak_ring`. Dans cette recette, l'ID est aussi le nom du fichier d'animation.
- **Height** : Conservez la hauteur **Fixed** par défaut. L'animation se redimensionne pour s'adapter à l'élément personnalisé.

Dans l'élément personnalisé, ajoutez une [**Image**](custom-media#image) avec une photo fixe de la bague. Les utilisateurs la voient comme [contenu de secours](flow-custom-elements#set-fallback-content) lorsque leur version de votre application ne prend pas en charge l'animation.

## 2. Ajoutez le fichier d'animation à votre application \{#2-add-the-animation-file-to-your-app\}

Dans Xcode, ajoutez le fichier d'animation à votre cible d'application. Le nom du fichier sans `.json` doit correspondre à l'ID de l'élément personnalisé, par exemple `streak_ring.json` pour `streak_ring`.

## 3. Créer la vue d'animation \{#create-the-animation-view\}

Créez un modèle pour la série, et une vue SwiftUI qui joue l'animation. Votre application met à jour le modèle lorsque la série change. La vue lit le modèle, de sorte que l'anneau affiche la série actuelle à l'ouverture de l'écran :

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// The streak that your app keeps up to date
@MainActor
final class StreakStore: ObservableObject {
    @Published var currentStreak = 0 // days in a row
}

struct StreakRingView: View {
    let animation: LottieAnimation
    @ObservedObject var streakStore: StreakStore

    // 7 days fill the ring: from 0 for an empty ring to 1 for a full one
    private var progress: AnimationProgressTime {
        min(AnimationProgressTime(streakStore.currentStreak) / 7, 1)
    }

    var body: some View {
        LottieView(animation: animation)
            .resizable()
            .playing(.fromProgress(0, toProgress: progress, loopMode: .playOnce))
    }
}
```

</TabItem>
</Tabs>

`.playing(.fromProgress(0, toProgress: progress, loopMode: .playOnce))` remplit l'anneau une fois, de vide jusqu'à `progress`. Si votre application gère déjà la série dans un `ObservableObject`, utilisez cet objet à la place de `StreakStore`.

## 4. Associer l'animation à l'élément personnalisé \{#4-match-the-animation-to-the-custom-element\}

Dans votre [résolveur global](ios-flow-custom-elements#set-an-app-wide-resolver), ajoutez une propriété pour le modèle de série. Ensuite, ajoutez un cas qui renvoie `StreakRingView` pour le Type `lottie_animation` et l'ID `streak_ring`. Les lignes surlignées indiquent ce qu'il faut ajouter. Si votre application n'a pas encore de [résolveur](ios-flow-custom-elements#write-a-resolver-to-match-custom-elements-and-views) global, copiez l'intégralité du code :

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift" {2,6,14-18}

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    let streakStore: StreakStore

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "lottie_animation" where id == "streak_ring":
            guard let animation = LottieAnimation.named(id) else {
                return nil // no animation file: show the fallback
            }
            return AnyView(StreakRingView(animation: animation, streakStore: streakStore))
        // the other cases of your resolver
        default:
            return nil
        }
    }
}
```

</TabItem>
</Tabs>

Placez le cas `streak_ring` avant tout autre cas `lottie_animation`, car Swift n'exécute que le premier cas correspondant. Si le bundle de l'app ne contient aucun fichier pour cet ID, le resolver retourne `nil` et les utilisateurs voient le fallback.

Créez le resolver avec le modèle de streak, puis définissez-le comme resolver global de l'app. Appelez `AdaptyUI.setCustomElementsResolver(_:)` une seule fois, par exemple au lancement de l'app :

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// the streak model that your app updates
@MainActor let streakStore = StreakStore()

// keep this instance: a resolver for one flow can reuse it
@MainActor let customElementsResolver = CustomElementsResolver(streakStore: streakStore)

AdaptyUI.setCustomElementsResolver(customElementsResolver)
```

</TabItem>
</Tabs>

## 5. Tester sur un appareil \{#test-on-a-device\}

Le Flow & Paywall Builder ne peut pas exécuter le code de votre application, donc son canevas affiche uniquement le paywall de secours. Pour prévisualiser l'animation :

1. [Publiez le flow](builder-save-publish). Pour voir la dernière version publiée plutôt qu'une version en cache, enregistrez l'appareil comme [appareil de test](test-devices).
2. Lancez un build de votre application qui inclut le resolver. Définissez la série sur quelques valeurs, par exemple 0, 4 et 7 jours. Ouvrez l'écran pour chaque valeur et vérifiez que l'anneau se remplit jusqu'à celle-ci.

Pour tester le paywall de secours, supprimez le fichier d'animation du build et rouvrez l'écran.

Pour savoir pourquoi le paywall de secours s'affiche à la place de l'animation, suivez les instructions de la section [Tester sur un appareil](ios-flow-custom-elements#test-on-a-device) du guide iOS.
