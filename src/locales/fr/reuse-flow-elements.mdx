La plupart des paywalls d'une application partagent les mêmes éléments : la sélection de forfait, la chronologie d'essai, le bloc de comparaison. Les reconstruire manuellement dans chaque flow est lent, et les copies divergent. La [compétence flow-generator](flow-generator-skill) permet d'enregistrer n'importe quelle partie d'un flow dans un fichier et de l'ajouter à un autre flow — dans la même application ou dans une autre — en résolvant les couleurs, polices, icônes et liaisons de produits dont cette partie dépend.

Le fichier enregistré est du JSON brut. Conservez-le à côté du code de votre application, commitez-le, ou envoyez-le à un collègue.

:::important
Il fait partie de la compétence flow-generator, donc rien à installer en plus — suivez les [étapes d'installation du flow-generator](flow-generator-skill#install-the-skill) et c'est bon. Il enregistre les modifications dans vos flows sur le tableau de bord, donc testez-le d'abord sur un brouillon et vérifiez le résultat dans le Flow Builder avant de publier.
:::

## À quoi ça sert \{#what-its-for\}

- **Une bibliothèque de composants vraiment partagée par votre équipe.** Enregistrez la sélection de plan une seule fois. Chaque nouveau flow démarre avec le vrai composant plutôt qu'une approximation.
- **Corrigez une fois, appliquez partout.** Corrigez la durée d'essai dans un flow, enregistrez-le, puis ajoutez-le aux autres.
- **Réutilisez un bloc éprouvé dans une nouvelle appli.** Un bloc qui convertit dans une application est un bon point de départ pour la suivante. Le skill relie ses produits au catalogue de l'application de destination.
- **Maintenez un design system cohérent.** Enregistrez uniquement les couleurs et les styles de texte — sans aucun élément — et appliquez-les à un autre flow.

## Comment l'utiliser \{#how-to-use-it\}

Demandez-le en langage naturel. La compétence s'occupe du reste.

### Enregistrer une partie d'un flow

```
Save the plan selection from my Premium paywall so I can reuse it.
```

La compétence écrit un fichier et affiche son chemin complet, pour que vous sachiez toujours quel fichier valider ou envoyer. Elle résume aussi ce qui y figure — le nombre d'éléments, ainsi que les couleurs, styles de texte, groupes et produits inclus.

Elle pose une seule question : si vous comptez réutiliser cela dans la même application ou n'importe où. Le fichier est complet dans les deux cas, donc une mauvaise réponse ne coûte rien.

Vous pouvez enregistrer un élément et tout ce qu'il contient, un écran entier, un composant réutilisable, ou un thème seul.

### Ajouter à un autre flow \{#add-it-to-another-flow\}

```
Add the two-plan selection to my onboarding paywall, above the CTA.
```

Avant d'écrire quoi que ce soit, la compétence vous présente un plan : exactement où le bloc sera inséré, ce qu'il ajoute, quelles couleurs et quels styles de texte il emprunte à la destination plutôt que les siens, et quels identifiants il doit renommer pour éviter les conflits. Elle affiche également le texte qu'elle importe, afin que vous puissiez repérer les contenus qui appartenaient à l'ancien flow.

Anything it can't resolve by itself — a product missing from this app's catalog, a
variable with no source here — is listed separately, as something for you to finish
rather than something it guessed at.

Read the plan, then say go. The skill writes the draft and renders the screen so you can
see the result.

## Comment ça fonctionne \{#how-it-works\}

Un élément sauvegardé est rarement autonome. Il fait référence à des couleurs, des styles de texte, des polices, des icônes, des produits et des variables qui existent ailleurs dans le flow. L'outil les classe en deux catégories.

**Ce qu'il peut embarquer.** Les couleurs, les styles de texte, les polices et les icônes sont inclus dans le fichier, avec leurs définitions. À la destination :

| La destination | Ce qui se passe |
| :--- | :--- |
| Signifie déjà la même chose sous ce nom | La réutilise |
| Utilise ce nom pour autre chose | **Adopte la valeur de la destination**, et vous en informe |
| Ne la connaît pas | Ajoute la définition du fichier |

L'adoption est généralement ce que vous souhaitez : une carte déplacée dans une autre application doit ressembler à cette application. Les deux valeurs apparaissent dans le plan, vous pouvez donc modifier ce choix.

**Ce qu'il ne peut pas transférer.** Un ID de produit, la source d'une variable, une cible **Navigate to screen** — ces éléments pointent vers quelque chose de spécifique à un flow ou à une application. La compétence relie ce qu'elle peut, et liste ce qu'elle ne peut pas sous `NEEDS YOU` plutôt que de deviner.

Avant d'enregistrer le brouillon, la compétence vérifie l'ensemble du flow : chaque référence est résolue, chaque locale est remplie, aucun ID n'entre en conflit, et le résultat passe toujours la vérification de publication. Tout ce qui reste est signalé, jamais corrigé en silence.

## Ce qu'il faut vérifier \{#what-to-check\}

- **Le texte doit correspondre au produit.** Un bloc qui s'adapte bien au flow d'origine peut ne pas convenir au flow de destination. Le plan affiche le texte importé, sous `WILL SAY`, pour que vous puissiez le vérifier avant l'écriture.
- **Les prix sont des variables, pas du texte.** Si la destination ne dispose pas du produit auquel un prix fait référence, le prix s'affiche vide. Le plan l'indique.
- **La taille peut dépendre du contexte.** Un élément dimensionné pour remplir son ancien conteneur peut s'étirer dans le nouveau. L'aperçu rendu permet de détecter cela.

## Limitations \{#limitations\}

- **Les produits ne traversent pas les apps automatiquement.** Le skill associe vos identifiants de produits du store pour les relier, et si un produit n'existe pas dans l'app de destination, il supprime la liaison et vous demande d'en attacher une.
- **Les vidéos et les polices personnalisées restent manuelles.** Aucune ne peut être uploadée depuis le terminal.
- **L'aperçu affiche un seul écran, dans un seul état.** Un changement de langue ou un état sélectionné n'y apparaît pas — consultez le plan pour ces éléments.
