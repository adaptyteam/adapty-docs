Afficher des paywalls dans votre application mobile est une étape essentielle pour proposer aux utilisateurs l'accès à des contenus ou services premium. Cependant, se contenter de présenter ces paywalls suffit à gérer les achats uniquement si vous utilisez le [Paywall Builder](adapty-paywall-builder) pour personnaliser vos paywalls.

Si vous n'utilisez pas le Paywall Builder, vous devez utiliser une méthode distincte appelée `.makePurchase()` pour finaliser un achat et débloquer le contenu souhaité. Cette méthode constitue le point d'entrée permettant aux utilisateurs d'interagir avec les paywalls et d'effectuer leurs transactions.

Si votre paywall comporte une offre promotionnelle active pour le produit qu'un utilisateur souhaite acheter, Adapty l'appliquera automatiquement au moment de l'achat.

:::warning
Gardez à l'esprit que l'offre de lancement ne sera appliquée automatiquement que si vous utilisez les paywalls configurés avec le Paywall Builder.

Dans les autres cas, vous devrez [vérifier l'éligibilité de l'utilisateur à une offre de lancement sur iOS](fetch-paywalls-and-products#check-intro-offer-eligibility-on-ios). Ignorer cette étape peut entraîner le rejet de votre application lors de la publication. De plus, cela pourrait conduire à facturer le plein tarif à des utilisateurs éligibles à une offre de lancement.
:::

Assurez-vous d'avoir [effectué la configuration initiale](quickstart) sans sauter une seule étape. Sans cela, nous ne pouvons pas valider les achats.

## Effectuer un achat \{#make-purchase\}

:::note
**Vous utilisez [Paywall Builder](adapty-paywall-builder) ?** Les achats sont traités automatiquement — vous pouvez ignorer cette étape.

**Vous cherchez un guide pas à pas ?** Consultez le [guide de démarrage rapide](ios-implement-paywalls-manually) pour des instructions d'implémentation complètes avec tout le contexte nécessaire.
:::

## Achats intégrés depuis l'App Store \{#in-app-purchases-from-the-app-store\}

Lorsqu'un utilisateur initie un achat dans l'App Store et que la transaction est transmise à votre application, le SDK appelle la méthode delegate `didReceivePromotedPurchase` avec un objet `AdaptyPromotedProduct`. Vous avez deux options :

- **Traiter la transaction immédiatement :** Ne pas implémenter `didReceivePromotedPurchase`. L'implémentation par défaut démarre l'achat immédiatement et l'écran du système d'achat Apple s'affiche automatiquement.
- **Stocker l'objet produit pour un traitement ultérieur :** Implémenter `didReceivePromotedPurchase`, stocker le produit, puis appeler `makePurchase` avec le produit stocké plus tard. Cela peut être utile si vous devez afficher quelque chose de personnalisé à votre utilisateur avant de déclencher un achat.

Si le produit mis en avant comporte une offre d'abonnement, le SDK l'applique automatiquement à l'achat. L'offre est lue depuis l'intention d'achat App Store, qui l'expose sur iOS 18.0 et versions ultérieures. Sur iOS 16.4–17.x, `subscriptionOffer` vaut toujours `nil` et l'achat s'effectue au prix de base.

Voici l'extrait complet :

```swift showLineNumbers title="Swift"
final class YourAdaptyDelegateImplementation: AdaptyDelegate {
    // 1. Store the product object to defer the transaction.
    // To process the transaction immediately instead, don't implement this method —
    // the default implementation starts the purchase right away.
    nonisolated func didReceivePromotedPurchase(_ product: AdaptyPromotedProduct) {
        // store the product object
    }

    // 2. Continue the deferred purchase later on by passing the product to `makePurchase` when the timing is appropriate
    func continueDeferredPurchase() async {
        let storedProduct: AdaptyPromotedProduct = // get the product object from 1.
        do {
            let purchaseResult = try await Adapty.makePurchase(product: storedProduct)
            // process the purchase result
        } catch {
            // handle the error
        }
    }
}
```

:::warning
L'API `didReceivePromotedPurchase` est disponible à partir de la version 4.1 du SDK et nécessite **iOS 16.4** ou une version ultérieure. La version 4.0 du SDK ne prend pas du tout en charge les achats intégrés promus, et sur les appareils antérieurs à iOS 16.4, la méthode ne se déclenche jamais. Si vous avez besoin des achats promus sur des versions iOS antérieures, restez sur le SDK 3.x et utilisez `shouldAddStorePayment` comme indiqué ci-dessous.
:::

<Details summary="Vous utilisez le SDK Adapty 3.x ?">

Dans le SDK 3.x, le SDK appelle la méthode déléguée `shouldAddStorePayment` à la place :

- **Traiter la transaction immédiatement :** Retournez `true` dans `shouldAddStorePayment`. L'écran d'achat Apple s'affichera aussitôt.
- **Stocker l'objet produit pour un traitement ultérieur :** Retournez `false` dans `shouldAddStorePayment`, puis appelez `makePurchase` avec le produit stocké plus tard.

```swift showLineNumbers title="Swift"
final class YourAdaptyDelegateImplementation: AdaptyDelegate {
    nonisolated func shouldAddStorePayment(for product: AdaptyDeferredProduct) -> Bool {
        // 1a.
        // Return `true` to continue the transaction in your app. The Apple purchase system screen will show automatically.

        // 1b.
        // Store the product object and return `false` to defer or cancel the transaction.
        false
    }
    
    // 2. Continue the deferred purchase later on by passing the product to `makePurchase` when the timing is appropriate
    func continueDeferredPurchase() async {
        let storedProduct: AdaptyDeferredProduct = // get the product object from 1b.
        do {
            try await Adapty.makePurchase(product: storedProduct)
        } catch {
            // handle the error
        }
    }
}
```

</Details>

## Utiliser les codes de promotion sur iOS \{#redeem-offer-codes-in-ios\}

<OfferCodesInfo />

Pour afficher la feuille de rachat de codes dans votre app :

```swift showLineNumbers
Adapty.presentCodeRedemptionSheet()
```

:::danger
D'après nos observations, la feuille de rachat de codes de promotion peut ne pas fonctionner de manière fiable dans certaines apps. Nous recommandons de rediriger directement l'utilisateur vers l'App Store.

Pour ce faire, vous devez ouvrir l'URL au format suivant :
`https://apps.apple.com/redeem?ctx=offercodes&id={apple_app_id}&code={code}`
:::
