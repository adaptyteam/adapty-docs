Pour mettre à jour votre application depuis Adapty iOS SDK 4.1 ou 4.2 vers la version 4.4, appliquez chaque modification de ce guide. Si votre application utilise déjà la version 4.3, appliquez uniquement les [modifications introduites dans la v4.4](#changes-in-v44). Une application en version 4.0 doit d'abord appliquer les [modifications de la v4.1](migration-to-ios-sdk-41).

:::warning
Le format du fichier de secours a changé dans la version 4.4, et le compilateur ne peut pas détecter un fichier obsolète. Sans un [nouveau fichier de secours](#fallback-files), chaque placement perd son paywall de secours.
:::

## Référence rapide \{#quick-reference\}

| Avant | Après | Version |
|---|---|---|
| `localizedPrice` et `currencyCode` peuvent être `nil` | Les deux propriétés retournent toujours une chaîne | 4.3.0 |
| Pas de code d'erreur `billingPlanUnavailable` | `AdaptyError.ErrorCode` inclut `billingPlanUnavailable` | 4.3.0 |
| `Adapty.reportTransaction` avec un `Transaction` simple | `Adapty.reportTransaction` avec un `VerificationResult<Transaction>` ; la surcharge `Transaction` est dépréciée | 4.3.2 |
| `case let .custom(id)` | `case let .custom(id, _)` | 4.4.0 |
| `AdaptyUICustomAsset` | `AdaptyUIAsset` ; `AdaptyCustomAsset` est inchangé | 4.4.0 |
| `.color(.uiColor(x))` et `.color(.swiftUIColor(c))` | `.color(Color(uiColor: x))` et `.color(c)` | 4.4.0 |
| `AdaptyUICustomFontAsset(font:defaultColor:defaultLetterSpacing:defaultLineHeight:)` | `AdaptyUIFontAsset(font:color:letterSpacing:lineHeight:)` | 4.4.0 |
| Pas d'assets de données | `AdaptyUIAsset` inclut `.data` pour les assets de données | 4.4.0 |
| `AdaptyProduct.localizedBillingPeriod` | `subscriptionPricingTerms?.localizedBillingPeriod` | 4.4.0 |
| Fichier de secours téléchargé pour les versions 4.1–4.3 | Nouveau format de fichier de secours ; téléchargez à nouveau le fichier | 4.4.0 |

## Changements dans la v4.3 \{#changes-in-v43\}

### localizedPrice et currencyCode ne sont plus optionnels \{#prices-are-no-longer-optional\}

Dans la version 4.3, les propriétés `localizedPrice` et `currencyCode` de `AdaptyPaywallProduct` et `AdaptySubscriptionOffer` retournent toujours une chaîne de caractères, jamais `nil`. Le code qui les vérifie avec `if let`, `guard let` ou `?.` ne compile plus. Supprimez ces vérifications :

```diff showLineNumbers
- if let price = product.localizedPrice {
-     priceLabel.text = price
- }
+ priceLabel.text = product.localizedPrice
```

Supprimez également les valeurs par défaut `??` sur ces propriétés : elles compilent, mais génèrent un avertissement.

### AdaptyError.ErrorCode inclut billingPlanUnavailable \{#new-error-code\}

4.3 ajoute le [code d'erreur](ios-sdk-error-handling#storekit-errors) `billingPlanUnavailable`. Une instruction `switch` qui liste tous les codes d'erreur sans branche `default` ne compile plus. Pour corriger cela, ajoutez une branche `case .billingPlanUnavailable` ou une branche `default`.

### La surcharge Transaction de reportTransaction est dépréciée \{#reporttransaction-overload-is-deprecated\}

Dans la version 4.3.2, la surcharge `Adapty.reportTransaction(_:withVariationId:)` qui accepte un `Transaction` brut, sans signature App Store, génère un avertissement de dépréciation. Pour signaler la transaction avec sa signature App Store, passez le `VerificationResult<Transaction>` retourné par StoreKit :

```diff showLineNumbers
- try await Adapty.reportTransaction(transaction, withVariationId: variationId)
+ try await Adapty.reportTransaction(verificationResult, withVariationId: variationId)
```

## Changements dans la v4.4 \{#changes-in-v44\}

### AdaptyUI.Action.custom contient deux valeurs \{#custom-actions\}

Lorsqu'un utilisateur appuie sur un bouton avec une action personnalisée, votre application reçoit `AdaptyUI.Action.custom`. Depuis la version 4.4, elle contient une deuxième valeur, `arguments`, après l'identifiant de l'action. Dans la closure `didPerformAction` et la méthode délégué `flowController(_:didPerform:)`, ajoutez `_` pour cette deuxième valeur :

```diff showLineNumbers
  switch action {
- case let .custom(id):
+ case let .custom(id, _):
      if id == "openNewPaywall" {
          // Display another flow or paywall
      }
  default:
      break
  }
```

Le code qui compare `id` à une chaîne de caractères ne compile plus tant que vous n'ajoutez pas `_`. L'autre code continue de compiler, avec l'avertissement « enum case 'custom' has 2 associated values; matching them as a tuple is deprecated ». Dans ce code, `id` contient les deux valeurs, pas uniquement l'ID d'action. Ajoutez `_` partout où Xcode affiche cet avertissement.

### Ressources personnalisées \{#custom-assets\}

Dans la version 4.4, `AdaptyUICustomAsset` est renommé en `AdaptyUIAsset`. L'ancien nom déclenche un avertissement de dépréciation.

Les ressources de couleur, de police et de données changent de trois façons :

- **Ressources de couleur** : `.color` prend une `Color` SwiftUI. `AdaptyUICustomColorAsset` est supprimé. Encapsulez une `UIColor` dans `Color(uiColor:)` et passez directement une `Color` SwiftUI :

  ```diff showLineNumbers
  - "brand_color": .color(.uiColor(brandColor)),
  + "brand_color": .color(Color(uiColor: brandColor)),
  ```

- **Ressources de police** : `AdaptyUIFontAsset` utilise `color:`, `letterSpacing:` et `lineHeight:` à la place de `defaultColor:`, `defaultLetterSpacing:` et `defaultLineHeight:`. Le paramètre `color:` accepte une `Color` SwiftUI :

  ```diff showLineNumbers
  - "title_font": .font(AdaptyUICustomFontAsset(font: titleFont, defaultColor: .uiColor(.white), defaultLineHeight: 24)),
  + "title_font": .font(AdaptyUIFontAsset(font: titleFont, color: .white, lineHeight: 24)),
  ```

- **Ressources de données** : `AdaptyUIAsset` inclut un nouveau type de ressource, `.data`. Une instruction `switch` qui liste chaque type de ressource sans branche `default` cesse de compiler. Seuls les [éléments personnalisés](ios-flow-custom-elements) lisent les ressources de données, donc la nouvelle branche peut être vide : `case .data: break`.

### AdaptyProduct.localizedBillingPeriod est déprécié \{#localizedbillingperiod-is-deprecated\}

`AdaptyProduct` possède une propriété [`subscriptionPricingTerms`](fetch-paywalls-and-products) qui décrit chaque paiement pour le produit : son prix et la fréquence à laquelle l'utilisateur paie. Dans la version 4.4, `localizedBillingPeriod`, le texte indiquant la fréquence de paiement, est déplacé d'`AdaptyProduct` vers `subscriptionPricingTerms`. `AdaptyProduct.localizedBillingPeriod` fonctionne toujours, avec un avertissement de dépréciation : il retourne `subscriptionPricingTerms?.localizedBillingPeriod`. Pour supprimer cet avertissement, lisez la propriété depuis les conditions tarifaires :

```diff showLineNumbers
- let period = product.localizedBillingPeriod
+ let period = product.subscriptionPricingTerms?.localizedBillingPeriod
```

### Fichiers de secours

Le format du [fichier de secours](fallback-flows) a changé dans le SDK 4.4. Téléchargez-le à nouveau depuis **[Placements](https://app.adapty.io/placements)** > **Fallbacks**, sélectionnez **Adapty SDK v4.4.0 and higher**, et intégrez-le dans votre application.

Le fichier téléchargé s'appelle `ios_4_4_0_fallback.json`. Donnez-lui le nom que votre application passe à `Bundle.main.url(forResource:withExtension:)`, ou mettez à jour ce nom dans cet appel.

:::warning
Un fichier de secours obsolète ne génère aucune erreur de compilation. Chaque placement perd silencieusement son paywall de secours. Le log du SDK affiche alors « The fallback paywalls version is not correct. Download a new one from the Adapty Dashboard. »
:::
