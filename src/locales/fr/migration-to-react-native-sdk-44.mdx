Adapty React Native SDK 4.4 modifie le format du fichier de secours, requiert iOS 16 pour les flows, et remonte davantage d'erreurs de flow à votre application. Dans la version 4.4, `AdaptyPrice.currencyCode`, `AdaptyPrice.localizedString` et `AdaptySubscription.billingPlan` ne sont plus optionnels en TypeScript. Pour mettre à jour votre application vers la version 4.4, installez le dernier package `react-native-adapty` et remplacez les deux fichiers de secours dans le même build. Les versions antérieures du SDK rejettent les nouveaux fichiers. Consultez ensuite les autres changements de ce guide.

Si vous utilisez encore la version 4.0, commencez par [Migrer vers la v4.1](migration-to-react-native-sdk-41) puis suivez ce guide.

:::warning
Le format des fichiers de secours a changé dans la version 4.4, et le compilateur ne peut pas détecter un fichier de secours pour les SDK 4.1–4.3. Sans [nouveaux fichiers de secours](#replace-the-fallback-files), chaque placement perd son paywall de secours.
:::

## Référence rapide \{#quick-reference\}

| v4.3 | v4.4 |
|---|---|
| Fichiers de secours téléchargés pour les versions 4.1–4.3 | Nouveau format de fichier de secours ; téléchargez à nouveau les deux fichiers |
| Les flows s'ouvrent sur iOS 15 | Les flows nécessitent iOS 16 |
| `AdaptyFlowView` reste vide si son flow ne peut pas se charger | Il signale l'erreur à son gestionnaire `onError` |
| `AdaptyPrice.currencyCode`, `AdaptyPrice.localizedString` et `AdaptySubscription.billingPlan` sont optionnels | Ils sont obligatoires |

## Installation \{#installation\}

Mettez à jour le package `react-native-adapty` :

```bash showLineNumbers
npm install react-native-adapty@latest
# or
yarn add react-native-adapty@latest
```

Les prérequis sont inchangés : **iOS 15.0** et **React Native 0.75**. Les flows font exception : voir [Les flows nécessitent iOS 16](#flows-require-ios-16). Consultez [Installer le SDK Adapty](sdk-installation-reactnative) pour la configuration complète.

## Remplacer les fichiers de secours \{#replace-the-fallback-files\}

Pour télécharger à nouveau les [fichiers de secours](react-native-use-fallback-paywalls), dans **[Placements](https://app.adapty.io/placements)**, cliquez sur **Fallbacks** > **Download iOS Fallback**. Dans la ligne **Adapty SDK v4.4.0 and higher**, cliquez sur **Download**. Répétez l'opération avec **Download Android Fallback**.

Les fichiers téléchargés s'appellent `ios_4_4_0_fallback.json` et `android_4_4_0_fallback.json`. Utilisez-les à la place de vos fichiers de secours pour le SDK 4.1–4.3 :

- **Projet React Native pur** : Ajoutez le fichier iOS à votre projet Xcode. Placez le fichier Android dans le dossier du fichier de paywall de secours pour les versions 4.1–4.3, comme indiqué dans [Utiliser les paywalls de secours dans un projet React Native pur](react-native-use-fallback-paywalls-pure).
- **Projet Expo** : Placez chaque fichier dans le dossier de son fichier de secours pour les versions 4.1–4.3, comme indiqué dans [Utiliser les paywalls de secours dans un projet Expo](react-native-use-fallback-paywalls-expo).

Donnez à chaque fichier le nom que votre application passe à `adapty.setFallback`, ou mettez à jour ces noms dans cet appel. Dans un projet Expo, utilisez ces mêmes noms dans l'option `fallbackFile`, puis relancez `npx expo prebuild`.

Avec un fichier de secours pour le SDK 4.1–4.3, `adapty.setFallback` lève une `AdaptyError`. Pour vérifier les nouveaux fichiers, lancez l'application sur iOS et sur Android, et assurez-vous que cet appel ne lève aucune erreur.

## Les flows nécessitent iOS 16 \{#flows-require-ios-16\}

À partir de la version 4.4, les flows nécessitent iOS 16 ou une version ultérieure. Les autres fonctionnalités du SDK, comme les achats et les paywalls personnalisés, continuent de fonctionner sur iOS 15.

Sur iOS 15, `createFlowView` et `AdaptyFlowView` renvoient une erreur avec le code `platformNotSupported`. Lorsque votre application reçoit cette erreur, affichez votre propre contenu à la place du flow, par exemple un [paywall personnalisé](react-native-implement-paywalls-manually).

## Les erreurs de chargement du flow sont transmises au gestionnaire onError \{#flow-load-errors-reach-the-onerror-handler\}

Le gestionnaire `onError` de `AdaptyFlowView` reçoit une erreur lorsque le composant ne peut pas afficher le flow. Chaque fois que votre application restitue un nouveau `AdaptyFlowView`, l'erreur est signalée une seule fois. Avant la version 4.4, le composant restait vide. Le composant signale les erreurs suivantes :

- Sur iOS 15 : `platformNotSupported`.
- Sur Android, et sur iOS 16 et versions ultérieures, lorsque le chargement du flow échoue : l'erreur que `createFlowView` lève pour ce flow. Par exemple, le flow échoue à se charger si AdaptyUI n'est pas activé, ou pour un `customLayoutId` que le flow ne possède pas.

La gestion des erreurs de votre flow s'exécute désormais dans ces cas également. La valeur de retour du handler `onError` ne ferme pas un flow intégré. Pour le fermer, arrêtez le rendu du composant et affichez votre propre contenu.

## Les propriétés de prix et d'abonnement sont obligatoires \{#price-and-subscription-properties-are-required\}

En TypeScript, `AdaptyPrice.currencyCode`, `AdaptyPrice.localizedString` et `AdaptySubscription.billingPlan` ne sont plus optionnelles. Si votre code crée ces objets, par exemple dans des mocks de tests, définissez-y ces propriétés.

À partir de la version 4.4, chaque abonnement a `billingPlan` : `up_front`, sauf si l'utilisateur a souscrit à un [plan d'engagement](set-up-12-month-commitment). Avant la version 4.4, seuls les abonnements App Store avaient `billingPlan`.
