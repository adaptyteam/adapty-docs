Adapty Mail envoie les campagnes depuis votre propre domaine — pas depuis une adresse partagée — ce qui vous permet de garder le contrôle sur la réputation de l'expéditeur. La configuration se fait une seule fois, et chaque campagne utilise le même domaine vérifié. Pour les étapes minimales, consultez la section domaine dans [Premiers pas avec Adapty Mail](mail-get-started#2-set-up-your-sending-domain). Cet article couvre la configuration complète, le fonctionnement de la vérification et le comportement de préchauffage automatique.

## Prérequis \{#requirements\}

- **Domaine apex** : Saisissez votre domaine racine (par exemple, `yourapp.com`), pas un sous-domaine. Les entrées comme `app.yourapp.com` sont rejetées lors de la validation.
- **Enregistrements NS actifs** : Le domaine doit être résolvable. Adapty Mail effectue une recherche DNS lors de la configuration et refuse les domaines sans enregistrements NS valides.
- **Un domaine par projet Adapty** : Un domaine ne peut pas être partagé entre plusieurs projets. Si le domaine est déjà enregistré dans un projet — le vôtre ou celui d'un autre — la configuration échoue.

## Configurer votre domaine d'envoi \{#set-up-your-sending-domain\}

L'assistant de configuration comporte trois écrans : saisir le domaine, confirmer les sous-domaines générés et ajouter les enregistrements DNS. Les trois se trouvent dans **Settings → DNS**.

1. **Saisissez votre domaine.** Tapez votre domaine racine dans le champ **Domain** et cliquez sur **Preview**. Adapty Mail valide le format (ASCII, deux labels, pas de tirets en début ou en fin, TLD de 2 caractères minimum) et vérifie que le DNS résout correctement.

   <ZoomImage id="mail-email-domains.webp" width="500px" />

2. **Confirmez les sous-domaines.** Adapty Mail génère deux sous-domaines d'envoi avec des préfixes fixes — `mail.yourapp.com` et `email.yourapp.com` — chacun avec sa propre identité SES. Il crée également un sous-domaine Mail-From sous chacun (`hello.mail.yourapp.com` et `hello.email.yourapp.com`). Vérifiez-les et cliquez sur **Confirm**.

   <ZoomImage id="confirm-subdomains.webp" width="500px" />

3. **Ajoutez les enregistrements DNS.** Le dernier écran liste tous les enregistrements à ajouter — 10 au total, 5 par sous-domaine d'envoi, plus un enregistrement DMARC facultatif sur le domaine racine. Utilisez **Download CSV** pour exporter la liste complète, ou copiez les enregistrements un par un dans votre bureau d'enregistrement. Cliquez sur **Done** une fois les enregistrements en place.

   <ZoomImage id="email-domains.webp" width="500px" />

<Details>
<summary>Référence des enregistrements DNS</summary>

Pour chaque sous-domaine d'envoi (`mail.yourapp.com` et `email.yourapp.com`), ajoutez :

**DKIM — 3 enregistrements CNAME.** Signatures cryptographiques qui prouvent que l'e-mail n'a pas été altéré en transit.

| Champ | Format                              |
| ----- | ----------------------------------- |
| Type  | CNAME                               |
| Name  | `{token}._domainkey.{subdomain}`    |
| Value | `{token}.dkim.amazonses.com`        |

**Mail-From — 1 enregistrement MX.** Gère les rebonds.

| Champ    | Format                                                   |
| -------- | -------------------------------------------------------- |
| Type     | MX                                                       |
| Nom      | `hello.{subdomain}` (par exemple, `hello.mail.yourapp.com`) |
| Priorité | `10`                                                     |
| Valeur   | `feedback-smtp.{region}.amazonses.com`                   |

**SPF — 1 enregistrement TXT.** Autorise Adapty à envoyer des e-mails en votre nom.

| Champ | Format                                 |
| ----- | -------------------------------------- |
| Type  | TXT                                    |
| Nom   | `hello.{subdomain}`                    |
| Valeur | `"v=spf1 include:amazonses.com ~all"` |

Sur votre domaine racine, ajoutez l'enregistrement DMARC optionnel :

| Champ | Format                |
| ----- | --------------------- |
| Type  | TXT                   |
| Nom   | `_dmarc.{domain}`     |
| Valeur | `v=DMARC1; p=reject` |

Les tokens, la région et toutes les autres valeurs proviennent d'AWS SES lors de la configuration. Copiez-les toujours depuis l'écran des enregistrements DNS dans Adapty Mail, et non depuis cette référence.

</Details>

## Fonctionnement de la vérification \{#how-verification-works\}

Une fois les enregistrements DNS en place, Adapty Mail interroge automatiquement le DNS, et vous pouvez également déclencher des vérifications manuellement.

- **Sondage automatique** : Le sondage démarre 1 minute après votre soumission, puis double à chaque tour — 2, 4, 8, 16 min — avant de plafonner à 32 min. Il se poursuit jusqu'à ce que des enregistrements soient trouvés ou que la fenêtre de 7 jours se ferme.
- **Vérification manuelle** : Cliquez sur **Check Verification** pour forcer une vérification immédiate. Un délai de 10 secondes s'applique entre les vérifications manuelles — si vous agissez trop vite, le message *"Verification check is on cooldown."* s'affiche.
- **États du statut** : Le DKIM et le Mail-From de chaque sous-domaine sont suivis indépendamment avec les statuts **Pending**, **Success** ou **Failed**. Un domaine est considéré comme entièrement vérifié uniquement lorsque les quatre statuts affichent **Success**.
- **Délai de 7 jours** : Si la vérification ne se termine pas dans les 7 jours, l'identité est marquée **Failed**. Vos enregistrements DNS restent chez votre registrar — saisissez à nouveau le domaine dans **Settings → DNS** pour démarrer une nouvelle fenêtre.
- **Après la vérification** : Si vous supprimez ou modifiez vos enregistrements DNS ultérieurement, AWS SES finira par déclasser l'identité. Conservez les enregistrements en place aussi longtemps que vous prévoyez d'envoyer des e-mails.
- **Propagation DNS** : Prend généralement quelques minutes ; peut aller jusqu'à 48 heures dans de rares cas.

## Réchauffement du domaine \{#domain-warm-up\}

Les nouveaux domaines n'ont aucune réputation auprès des fournisseurs de messagerie comme Gmail ou Yahoo, et les envois en masse depuis un domaine tout neuf risquent d'atterrir dans les spams. Adapty Mail gère le réchauffement automatiquement en augmentant progressivement votre limite d'envoi quotidienne sur 14 paliers. Aucune configuration nécessaire.

### Fonctionnement des niveaux \{#how-tiers-work\}

Votre domaine commence au **Niveau 1** (200 envois/jour) et progresse automatiquement, un niveau à la fois. Un domaine passe au niveau suivant une fois qu'il a épuisé le quota journalier de son niveau actuel — les envois réels et les tentatives limitées comptent tous les deux — et la limite supérieure prend effet le lendemain. La progression repose uniquement sur le volume, et les niveaux n'évoluent que vers le haut : il n'y a pas de retour automatique à un niveau inférieur.

| Tier | Daily limit |
| ---- | ----------- |
| 1    | 200         |
| 2    | 400         |
| 3    | 800         |
| 4    | 1,500       |
| 5    | 2,500       |
| 6    | 4,000       |
| 7    | 6,000       |
| 8    | 8,000       |
| 9    | 10,000      |
| 10   | 13,000      |
| 11   | 16,000      |
| 12   | 20,000      |
| 13   | 25,000      |
| 14   | 30,000      |

Votre niveau actuel et votre limite quotidienne sont affichés dans **Settings → DNS**.

### Impact sur le lancement selon la taille de l'audience \{#impact-on-launch-by-audience-size\}

| Taille de l'audience | Effet au lancement                          |
| -------------------- | ------------------------------------------- |
| Moins de 200 utilisateurs | Audience complète atteinte dès le premier jour |
| 200–2 000 utilisateurs    | Diffusion étalée sur plusieurs jours          |
| 2 000+ utilisateurs       | Diffusion étalée sur 1 à 2 semaines           |

:::tip
Lancez votre première campagne dès que la vérification DNS est terminée. Plus tôt vous commencez à envoyer, plus vite votre domaine progresse dans les paliers et atteint sa capacité journalière maximale.
:::

## Limitations \{#limitations\}

- **Un domaine par projet** : vous ne pouvez avoir qu'un seul domaine d'envoi par projet Adapty. Pour en changer, contactez le support — le tableau de bord ne propose pas d'action « changer de domaine ».
- **Unicité entre projets** : un domaine déjà enregistré dans un autre projet ne peut pas être réutilisé. Si vous voyez *"Domain is already registered to another project"*, choisissez un autre domaine ou contactez le support.
- **Les domaines vérifiés ne peuvent pas être supprimés** : dès qu'un sous-domaine atteint le statut **Success**, le tableau de bord bloque la suppression. Les domaines en attente peuvent être supprimés, mais vous devez tout de même retirer manuellement les enregistrements DNS chez votre registrar.
- **Préfixes de sous-domaines fixes** : `mail.`, `email.` et le préfixe Mail-From `hello.` sont codés en dur — ils ne peuvent pas être personnalisés. Si ces sous-domaines sont déjà utilisés dans votre DNS, la configuration entrera en conflit.
- **Domaines apex uniquement** : les sous-domaines, les points finaux et les noms d'hôte à un seul label sont refusés.
- **Pas de domaines internationalisés** : Punycode et IDN ne sont pas pris en charge. Le domaine doit être en ASCII uniquement.

## Dépannage \{#troubleshooting\}

| Problème                                                                       | Solution                                                                                                                  |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| « Enter a valid domain (e.g. example.com) »                                    | Vérifiez la saisie : domaine apex uniquement, ASCII uniquement, TLD de 2 caractères minimum, sans tiret en début ou fin. |
| « Domain does not have valid DNS records »                                      | Le domaine apex lui-même doit être résolvable. Confirmez que vos enregistrements NS sont actifs avant de réessayer.       |
| « Domain is already registered to another project »                             | Choisissez un autre domaine, ou contactez le support si vous pensez que l'enregistrement est une erreur.                  |
| « Verification check is on cooldown »                                           | Attendez 10 secondes entre deux vérifications manuelles. Le sondage automatique continue en arrière-plan.                 |
| Vérification bloquée sur Pending                                                | Vérifiez que les enregistrements DNS correspondent exactement — pas de point final, cibles CNAME correctes. La propagation DNS peut prendre jusqu'à 48 heures. |
| « Cannot delete domain: one or more identities have been successfully verified » | Un domaine vérifié ne peut pas être supprimé du tableau de bord. Contactez le support pour obtenir de l'aide.             |
| E-mails envoyés en spam                                                         | Confirmez que votre enregistrement DMARC est publié. Les nouveaux domaines ont besoin d'un temps de chauffe — consultez [Chauffe du domaine](#domain-warm-up). |
| Taux de rebond élevé                                                            | Vérifiez que votre liste d'audience contient des adresses valides et ayant consenti. Consultez [Suppression](mail-suppression) pour savoir ce qui arrive à une adresse qui génère un rebond. |
