Dans ce guide, vous allez configurer Adapty Mail et lancer votre premier email flow.

La configuration se déroule en neuf étapes :

1. [Choisissez votre type de compte](#1-choose-your-account-type)
2. [Connectez vos données](#2-connect-your-data)
3. [Configurez votre marque](#3-set-up-your-brand)
4. [Configurez votre domaine d'envoi](#4-set-up-your-sending-domain)
5. [Ajoutez l'adresse de votre entreprise](#5-add-your-company-address)
6. [Créez un paywall web](#6-create-a-web-paywall)
7. [Générez une campagne avec l'IA](#7-generate-a-campaign-with-ai)
8. [Lancez un flow](#8-launch-a-flow)
9. [Commencez à envoyer](#9-start-sending)

Adapty Mail suit votre progression dans la liste de contrôle d'onboarding et la masque une fois toutes les étapes terminées.

## Avant de commencer \{#before-you-start\}

Assurez-vous que les éléments suivants sont en place avant de commencer :

- **Accès DNS** : Vous pouvez ajouter des enregistrements à votre domaine racine.
- **Paiements** : Vous avez un compte Stripe avec vos produits d'abonnement configurés. Pour utiliser un autre fournisseur, hébergez vous-même la page de paiement — consultez [Configurer le paiement](mail-checkout).

## 1. Choisissez votre type de compte \{#1-choose-your-account-type\}

:::warning
Choisissez attentivement — un projet que vous créez vous-même dans Adapty Mail ne peut pas être lié à Adapty ultérieurement.
:::

Le type de compte détermine ce que votre projet Adapty Mail peut faire :

| | Adapty-lié (recommandé) | Autonome |
| --- | --- | --- |
| **Inscription** | Connectez-vous avec votre [compte Adapty](https://app.adapty.io/) et ouvrez **Mail**. Adapty crée un projet lié à votre application. L'échange de données entre Adapty Mail et le SDK est désactivé jusqu'à la dernière étape de la configuration. Vous n'avez pas à migrer vos achats vers Adapty : le [mode observateur](observer-vs-full-mode), simple à configurer et qui se contente de signaler vos transactions, suffit amplement. | [Inscrivez-vous à Adapty Mail uniquement](https://mail.adapty.io/signup) avec une adresse e-mail et un mot de passe. Pas de compte Adapty, rien à installer dans votre application — vous apportez les données vous-même, via FunnelFox ou l'API. |
| **Page de paiement** (Étape 6) | **Générer avec l'IA** — une page de paiement hébergée construite autour de votre marque, avec Stripe intégré — ou votre propre paywall hébergé | Votre propre paywall hébergé |
| **Segments** | Importez depuis Adapty, ou créez dans Mail | Créez dans Mail |
| **Marque** — ce à partir de quoi vos e-mails sont générés : nom, logo, couleurs et ton (Étape 3) | Construite à partir de la fiche store de votre application avant votre arrivée, si elle en possède une | Construite à partir d'une URL de store que vous collez |
| **Données d'achats** (Étape 2) | Un clic dans **Settings** > **Project** ; FunnelFox et l'API fonctionnent aussi | Clé secrète collée dans le tableau de bord Adapty ou FunnelFox, ou l'API |
| **Équipe** | Les coéquipiers rejoignent en ouvrant Mail depuis votre entreprise Adapty ; invitations par e-mail aussi | Invitations par e-mail |

## 2. Connectez vos données \{#2-connect-your-data\}

Avant qu'Adapty Mail puisse envoyer un e-mail à un utilisateur, il lui faut :

- **Leur adresse e-mail** : la destination de vos e-mails.
- **Leur [customer user ID](how-profiles-work)** : l'identifiant unique de l'utilisateur. Adapty le stocke dans le profil de l'utilisateur afin de reconnaître la même personne sur tous ses appareils. Sans cet identifiant, Adapty crée un nouveau profil à chaque fois que l'utilisateur réinstalle votre application ou se déconnecte.
- **Leur flux d'événements d'abonnement** : essais, renouvellements, annulations et remboursements, en temps réel. Ils vous permettent de cibler les utilisateurs en fonction de leur comportement et de rattacher les revenus à l'e-mail qui a déclenché l'achat. Sans le flux d'événements, la seule séquence qu'un utilisateur peut recevoir est celle destinée aux personnes n'ayant jamais effectué d'achat.

Suivez les instructions pour créer un **[point d'entrée](mail-entry-points)** pour ces données :

- **Adapty** : À utiliser si votre application fait déjà tourner le SDK Adapty. Adapty transfère les profils, les adresses e-mail et les événements d'abonnement à votre place — aucun serveur propre n'est nécessaire. Dans votre application, ajoutez l'identification des utilisateurs et la collecte des e-mails. Voir [Connecter Adapty à Adapty Mail](mail-collect-emails).
- **API Adapty Mail** : À utiliser si vous disposez déjà d'un backend contenant ces données, si votre application n'intègre pas le SDK Adapty, ou si vous importez des abonnés depuis une autre source. Vous publiez vous-même les profils et les événements de transaction. La clé secrète dans **Settings** > **Project** authentifie les requêtes. Voir [Envoyer des e-mails et des transactions via l'API Adapty Mail](mail-send-data-via-api).
- **FunnelFox** : À utiliser si vous acquérez et facturez des utilisateurs via les funnels web FunnelFox. FunnelFox détient déjà leurs e-mails, achats et événements d'abonnement, et les transfère lui-même à Adapty Mail — aucun travail côté SDK, aucune requête à écrire. Voir [le guide d'intégration FunnelFox](https://funnelfox.com/docs/integrations/email-providers/adapty-mail).
- **Une combinaison** : Vous pouvez utiliser plusieurs points d'entrée simultanément. Adapty Mail fait correspondre les données utilisateur entrantes sur `customer_user_id` et l'adresse e-mail.

Adapty Mail commence à envoyer des e-mails une fois que le reste de la configuration est en place.

## 3. Configurez votre marque \{#3-set-up-your-brand\}

Adapty Mail ne peut pas générer d'e-mails ou de paywalls web sans une **marque**. Votre marque regroupe toutes les informations dont Adapty Mail a besoin pour correspondre à l'apparence et au ton de votre application — nom, logo, couleurs, polices, ton éditorial, fonctionnalités et avis. Vous fournissez la fiche store, et Adapty Mail construit la marque à partir de celle-ci.

1. Dans Adapty Mail, ouvrez **Brand**.
2. Si la page affiche une marque déjà configurée, vérifiez-la et passez à la suite. Si elle affiche l'écran **Set up your brand**, continuez ci-dessous.
3. Sous **Store**, choisissez **App Store** ou **Google Play**, puis collez l'URL de votre fiche.
   :::note
   L'écran de configuration accepte uniquement une fiche App Store ou Google Play. Si votre application n'a pas de fiche store — un funnel web-to-app, par exemple — contactez le support Adapty avant de continuer.
   :::
4. Cliquez sur **Build my brand**. Adapty Mail récupère la page, analyse les avis et détermine la tonalité de votre marque. L'opération prend généralement moins d'une minute.
5. Pour consulter les sections, les modifier manuellement ou ajouter des sources de landing page et de réseaux sociaux, consultez [Brand](mail-brand).

## 4. Configurez votre domaine d'envoi \{#4-set-up-your-sending-domain\}

Adapty Mail envoie les e-mails depuis votre domaine privé. Vous ajoutez les enregistrements DNS une seule fois, et toutes vos campagnes utilisent le même domaine vérifié.

Pour enregistrer votre premier domaine, dans Adapty Mail, accédez à **Settings** > **DNS** > la section **Email domains**.

1. Dans le champ **Domain**, saisissez votre domaine racine (par exemple, `yourapp.com`). Seuls les domaines apex sont acceptés — les sous-domaines comme `app.yourapp.com` sont refusés à la saisie.
2. Dans le champ **Sending subdomain**, saisissez le préfixe depuis lequel vos e-mails sont envoyés, ou laissez-le vide pour utiliser `mail`. Les e-mails proviendront alors de `hello@mail.yourapp.com`.
3. Cliquez sur **Add domain**.

   <ZoomImage id="mail-email-domains.webp" width="500px" />

4. Dans votre registrar de domaine, ajoutez chaque enregistrement DNS indiqué sur la nouvelle carte de domaine. Ils sont regroupés en trois catégories : les enregistrements DKIM et MAIL FROM de votre sous-domaine d'envoi, les enregistrements pour la boîte mail qui réchauffe le domaine, et les enregistrements pour `go.yourapp.com`, qui sert les images et les liens trackés. Pour comprendre ce que chaque groupe authentifie, consultez [Quels enregistrements ajouter](mail-sending-domain#which-records-you-add). Pour les exporter tous en une fois, cliquez sur **Export**.
5. Vous pouvez également ajouter l'enregistrement TXT DMARC suggéré sur votre domaine racine (recommandé).
6. Cliquez sur **Check** pour vérifier immédiatement, ou quittez la carte et laissez Adapty Mail interroger le DNS.

<ZoomImage id="mail-email-domains.webp" width="700px" />

Récapitulatif des délais de vérification :

- **Vérification automatique** : Le premier contrôle s'effectue 1 minute après l'ajout du domaine, puis les intervalles doublent jusqu'à une fois par heure, jusqu'à ce que les enregistrements soient détectés.
- **Vérification manuelle** : Cliquez sur **Check** à tout moment pour déclencher un contrôle immédiat.
- **Propagation DNS** : Généralement quelques minutes, jusqu'à 48 heures dans de rares cas.
- **Fenêtre de vérification** : 7 jours. Si elle expire, vos enregistrements DNS restent en place — ajoutez à nouveau votre domaine dans **Settings** > **DNS** pour démarrer une nouvelle fenêtre.

Un seul domaine vérifié suffit pour commencer à utiliser Adapty Mail. Un projet peut contenir jusqu'à cinq domaines, et vous pouvez en ajouter d'autres ultérieurement.

Pour plus de détails sur chaque type d'enregistrement et l'échauffement du domaine, consultez [Configurer votre domaine d'envoi](mail-sending-domain).

## 5. Ajoutez l'adresse de votre entreprise \{#5-add-your-company-address\}

Les lois anti-spam exigent une adresse postale physique dans chaque e-mail marketing. Adapty Mail l'insère dans le pied de page de chaque e-mail de campagne et bloque la génération de campagne tant que vous ne l'avez pas renseignée.

1. Dans Adapty Mail, accédez à **Settings** > **Company**.
2. Dans la section **Company address**, remplissez les champs **Legal company name**, **Address line 1**, **City**, **Postal code** et **Country**. Les champs **Address line 2** et **State / Region** sont facultatifs.
3. Cliquez sur **Save**.

## 6. Créer un paywall web \{#6-create-a-web-paywall\}

Quand un destinataire clique sur un CTA dans votre e-mail, il arrive sur un **paywall web** — une page de paiement dans le navigateur. Chaque campagne y est liée, et Adapty Mail rejette une campagne sans paywall web. Ce n'est pas votre paywall intégré à l'application : un achat effectué là est un paiement web, pas une transaction App Store ou Google Play.

Vous avez deux options :

- **Générer avec l'IA** : Générez un paywall avec le builder intégré, propulsé par [FunnelFox](https://funnelfox.com). Le paywall généré utilise Stripe pour traiter les paiements.
- **Utiliser votre propre paywall hébergé** : Pointez Adapty Mail vers une page que vous hébergez déjà, avec le fournisseur de votre choix. Adapty Mail redirige l'utilisateur vers votre paywall, avec les informations de l'utilisateur pré-remplies dans l'URL. Un paywall auto-hébergé peut utiliser n'importe quel fournisseur de paiement.

:::note
**Générer avec l'IA nécessite Stripe et un compte lié à Adapty**. Stripe est le seul prestataire pris en charge par le checkout généré. Si vous utilisez un autre prestataire ou un compte Adapty Mail autonome, utilisez votre propre paywall hébergé.
:::

Pour commencer, dans Adapty Mail, allez dans **Web Paywalls** > **Create**.

<ZoomImage id="new-web-paywall.webp" width="500px" />

### Option A : Générer avec l'IA \{#option-a-generate-with-ai\}

La page affiche une liste de prérequis avec des boutons intégrés — parcourez-la dans l'ordre, puis revenez pour générer. Cette liste couvre la connexion au Paywall Builder, la connexion à Stripe, l'ajout de produits et la vérification du résultat. Consultez [Configurer le paiement](mail-checkout) pour le guide complet. Si vous terminez un prérequis dans un autre onglet, cliquez sur **Refresh** dans la liste pour synchroniser son état.

Lorsque tous les prérequis sont au vert, cliquez sur **Proceed to generation**. Dans la boîte de dialogue **Choose plans** :

1. Choisissez 1 à 3 plans, tous dans la même devise. Chaque plan correspond à une offre que le paywall généré présentera au moment du paiement. Cliquez sur **Add plan** pour ajouter un deuxième ou un troisième plan.
2. Pour chaque plan, choisissez un prix de production, son équivalent sandbox, ou les deux. Un prix de production et un prix sandbox sur la même ligne comptent comme un seul plan.
3. Cliquez sur **Generate paywall**.

Remplissez une colonne pour chaque plan, ou laissez-la entièrement vide — une colonne partiellement remplie bloque la génération. Sans prix sandbox, les [e-mails de test](mail-testing) renvoient vers le paywall de production et les achats de test ne fonctionnent pas.

:::important
Le paywall doit être publié avant de pouvoir gérer le trafic de paiement. Les paywalls non publiés renvoient une erreur lorsque les utilisateurs cliquent sur les liens de paiement par e-mail.
:::

### Option B : Utiliser votre propre paywall hébergé

1. Sélectionnez **Enter URL manually**.
2. Collez l'URL de votre paywall hébergé avec des espaces réservés en tant que paramètres de requête. Adapty Mail les remplace pour chaque destinataire afin que la page de paiement puisse identifier le visiteur. Exemple :

   ```
   https://example.com/paywall?email={email}&adapty_profile_id={adapty.external_profile_id}
   ```

   La page de création liste les espaces réservés disponibles. Consultez [Configurer le paiement](mail-checkout#use-your-own-hosted-paywall) pour savoir ce que chacun résout.
3. Enregistrez et publiez.

Pour comprendre l'anatomie du tunnel de paiement et le fonctionnement de la personnalisation, consultez [Configurer le paiement](mail-checkout).

<ZoomImage id="generate-web-paywall.webp" width="500px" />

## 7. Générer une campagne avec l'IA \{#7-generate-a-campaign-with-ai\}

Une **campagne** est une séquence de 15 e-mails maximum qu'un destinataire reçoit au fil du temps. L'IA rédige toute la séquence à partir de la marque que vous avez configurée à l'[étape 3](#3-set-up-your-brand) : texte, design, images hero et liens de paiement personnalisés.

1. Dans Adapty Mail, accédez à **Campaigns** et cliquez sur **Create**.
2. Définissez le nom de la campagne.
3. Dans le menu déroulant **Web paywall**, sélectionnez le web paywall ajouté à l'étape précédente.

   <ZoomImage id="mail-new-campaign.webp" width="500px" />

4. Cliquez sur **Generate emails**.
5. Remplissez le formulaire de génération — ton, langue, une invite personnalisée optionnelle (jusqu'à 2 000 caractères) et le nombre d'e-mails (1–15, 4 par défaut). Consultez [Créer une campagne](mail-create-campaign) pour en savoir plus sur chaque champ.

   <ZoomImage id="generate-emails.webp" width="500px" />

6. Cliquez sur **Generate**. La génération prend généralement quelques minutes. Le système expire après 5 minutes s'il ne peut pas terminer — relancez si c'est le cas.
7. Prévisualisez chaque e-mail. L'en-tête de prévisualisation comporte un **Theme toggle** (Auto, Light, Dark) qui contrôle l'affichage de la prévisualisation — le contenu généré est identique dans tous les modes. Vous pouvez régénérer des e-mails individuels, modifier le texte ou ouvrir l'éditeur HTML pour un contrôle plus précis.

<ZoomImage id="generated-emails.webp" width="700px" />

8. Cliquez sur **Create** pour enregistrer la campagne.

La campagne est enregistrée comme **brouillon** et n'est pas encore envoyée — les campagnes ne sont actives que lorsqu'elles sont associées à un flow (étape suivante). Il n'y a pas d'action « publier » séparée dans l'éditeur de campagne.

## 8. Lancer un flow \{#launch-a-flow\}

Adapty Mail inclut ses propres **flows**. Un flow connecte des **déclencheurs** (événements d'abonnement) à des **campagnes** (séquences d'e-mails). Chacun des cinq déclencheurs — expiration d'un abonnement, échec d'un paiement, etc. — possède son propre flow. Un flow peut envoyer une campagne à tous les utilisateurs qui déclenchent l'événement, ou utiliser des **segments** pour envoyer des campagnes différentes à des groupes différents.

1. Dans Adapty Mail, rendez-vous dans **Flows**, puis ouvrez le déclencheur que vous souhaitez configurer :
   - **Never purchased** — utilisateurs qui se sont inscrits mais n'ont pas encore effectué d'achat.
   - **Renewal cancelled** — utilisateurs qui ont désactivé le renouvellement automatique mais dont l'abonnement est toujours actif.
   - **Billing issue** — paiement échoué, carte refusée ou expirée, ou délai de grâce.
   - **Expired** — l'abonnement a expiré et l'accès n'est plus disponible.
   - **Refunded** — utilisateurs ayant demandé un remboursement après un achat.

   Consultez [Flows](mail-flows) pour les objectifs et les conseils de ton associés à chaque déclencheur.

2. Cliquez sur **Create** pour ouvrir la boîte de dialogue.

<ZoomImage id="create-flow-mail.webp" width="500px" />

3. Dans la boîte de dialogue :
   - Choisissez un **Segment**. **All Users** cible tous les utilisateurs qui déclenchent ce trigger — c'est suffisant pour démarrer. Pour affiner l'audience plus tard, créez un [segment différent](mail-segments) — un sous-ensemble filtré de vos utilisateurs selon leur pays, leur âge ou leur état d'abonnement.
   - Définissez le type de contenu sur **Campaign** (l'option A/B Test est couverte dans [A/B testing](mail-ab-testing)).
   - Sélectionnez la **Campaign** que vous avez enregistrée à l'étape 7.
4. Cliquez sur **Save**.

Le flow est mis en ligne immédiatement — aucune étape de lancement distincte n'est nécessaire. À partir de ce moment, les utilisateurs correspondant au segment commenceront à recevoir la campagne dès qu'ils déclencheront l'événement.

:::note
Vous pouvez ajouter plusieurs lignes au même déclencheur, chacune avec son propre segment et sa propre campagne. Adapty Mail les vérifie de haut en bas et utilise le premier segment qui correspond. Gardez **All Users** en dernier — Adapty Mail ne sauvegarde pas un flow avec cette valeur ailleurs.
:::

<ZoomImage id="mail-flow-details.webp" width="500px" />

:::tip
Si les nouveaux destinataires doivent confirmer leur adresse avant de recevoir des messages marketing, activez le [double opt-in](mail-double-opt-in) avant cette étape. Seuls les profils créés après l'activation sont invités à confirmer.
:::

## 9. Commencer l'envoi \{#9-start-sending\}

Votre campagne est configurée mais n'est pas encore active — aucune donnée utilisateur n'atteint Adapty Mail. Lancez le flux de données via le [point d'entrée que vous avez choisi](#2-connect-your-data). Que votre projet soit lié à Adapty (Étape 1) ou non ne change que *la façon* dont vous activez le flux Adapty, pas ce qui arrive :

| Vos données proviennent de | Votre projet Mail est lié à une app Adapty | Que faire |
| --- | --- | --- |
| [Le SDK Adapty](mail-collect-emails#5-enable-sending) | Oui | Dans Adapty Mail, allez dans **Settings** > **Project** et cliquez sur **Enable Adapty integration**. Le bouton reste désactivé tant que vous n'avez pas de flow (étape 8). |
| [Le SDK Adapty](mail-collect-emails#5-enable-sending) | Non | Adapty peut alimenter un projet auquel il n'est pas lié — il suffit de la clé. Copiez la clé secrète depuis **Settings** > **Project** et collez-la dans le tableau de bord Adapty sous **Integrations** > **Adapty Mail**. |
| Votre backend, via l'[API Adapty Mail](mail-send-data-via-api) | L'un ou l'autre | Commencez à envoyer des profils et des événements de transaction. Les profils envoyés avant la fin de cette configuration ne recevront jamais rien, c'est pourquoi cette étape vient en dernier. |
| [FunnelFox](mail-funnelfox) | L'un ou l'autre | Copiez la clé secrète depuis **Settings** > **Project** et collez-la dans FunnelFox sous **Integrations** > **Adapty Mail**. Les données commencent à arriver en environ une minute. |

À partir de là, les utilisateurs qui correspondent à votre segment reçoivent la campagne dès qu'ils atteignent le déclencheur. Avant d'ouvrir l'accès aux vrais utilisateurs, [testez toute la chaîne](mail-testing) avec un utilisateur test.

## Dépannage \{#troubleshooting\}

| Problème                                          | Solution                                                                                                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Generate emails** est grisé                     | L'adresse de votre marque ou de votre entreprise est manquante. L'info-bulle du bouton indique laquelle. Voir [Étape 3](#3-set-up-your-brand) et [Étape 5](#5-add-your-company-address) |
| La génération du paywall est bloquée              | Le panneau indique la cause : aucune marque, aucun compte Stripe connecté, ou aucun produit Stripe avec des prix. Corrigez le problème, puis cliquez sur **Refresh** dans la liste de contrôle |
| La campagne ne se sauvegarde pas                  | Chaque campagne nécessite un web paywall. Créez-en un à l'[Étape 6](#6-create-a-web-paywall)                                                                                     |
| **Enable Adapty integration** est grisé           | Adapty Mail nécessite au moins un flow. Voir [Étape 8](#8-launch-a-flow)                                                                                                         |
| Les enregistrements DNS ne se vérifient pas       | Vérifiez qu'ils correspondent exactement — pas de point final, cibles CNAME correctes, une seule valeur par enregistrement. La propagation DNS peut prendre jusqu'à 48 heures    |
| La fenêtre de vérification a expiré               | Ajoutez à nouveau le domaine dans **Settings** > **DNS** pour démarrer une nouvelle fenêtre. Les enregistrements chez votre bureau d'enregistrement sont toujours valides — rien à rajouter |
| La génération d'e-mails a expiré                  | La génération s'arrête après 5 minutes. Réessayez, et contactez le support Adapty si le problème persiste                                                                        |

Pour les erreurs en dehors de la configuration initiale, consultez les sections de dépannage dans [Configurer votre domaine d'envoi](mail-sending-domain#troubleshooting) et [Configurer le paiement](mail-checkout#troubleshooting).
