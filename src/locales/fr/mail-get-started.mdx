Dans ce guide, vous allez configurer Adapty Mail et lancer votre premier flow d'e-mail.

La configuration se divise en six parties :

1. [Connectez vos données](#1-connect-your-data)
2. [Configurez votre domaine d'envoi](#2-set-up-your-sending-domain)
3. [Créez un paywall web](#3-create-a-web-paywall)
4. [Générez une campagne avec l'IA](#4-generate-a-campaign-with-ai)
5. [Lancez un flow](#5-launch-a-flow)
6. [Commencez à envoyer](#6-start-sending)

:::tip
Si vous vous êtes inscrit à Adapty Mail via Adapty, votre **profil de marque** est créé automatiquement à partir de l'URL du store de votre projet. Ouvrez **Brand** à tout moment pour le consulter ou l'affiner — voir [Brand](mail-brand). Si vous vous êtes inscrit de façon indépendante, configurez votre marque sur la même page avant de générer des campagnes ou des paywalls web.
:::

## Avant de commencer \{#before-you-start\}

Assurez-vous que les éléments suivants sont en place avant de commencer :

- **Accès DNS** : Vous pouvez ajouter des enregistrements à votre domaine racine.
- **Paiements** : Vous avez un compte Stripe avec vos produits d'abonnement configurés. Pour utiliser un autre fournisseur, hébergez vous-même la page de paiement — consultez [Configurer le paiement](mail-checkout).

## 1. Connectez vos données \{#1-connect-your-data\}

Adapty Mail a besoin de l'historique d'achats (pour attribuer les revenus à l'e-mail à l'origine de chaque conversion), d'un identifiant utilisateur stable et d'une adresse e-mail pour chaque utilisateur. Préparez le [point d'entrée](mail-entry-points) qui correspond à l'endroit où ces données se trouvent déjà — vous ouvrirez le flux à l'étape 6, une fois que le reste de la configuration pourra agir sur ce qui arrive :

- **Adapty** : Si votre application utilise le SDK Adapty, configurez l'identification des utilisateurs et la collecte des e-mails. Laissez l'intégration elle-même désactivée pour l'instant — Adapty Mail la bloque jusqu'à ce que vous ayez un flow. Voir [Connecter Adapty à Adapty Mail](mail-collect-emails).
- **Adapty Mail API** : Si votre backend est la source de vérité, récupérez votre clé secrète depuis **Settings** et construisez vos requêtes, mais n'envoyez rien encore. Les profils qui arrivent avant la fin de la configuration ne reçoivent rien. Voir [Envoyer des e-mails et des transactions via l'Adapty Mail API](mail-send-data-via-api).

Vous pouvez utiliser plusieurs points d'entrée simultanément. Adapty Mail fait correspondre les données entrantes sur le `customer_user_id` et l'adresse e-mail, de sorte qu'une personne signalée par plusieurs sources n'obtient qu'un seul profil et une seule séquence.

:::important
Adapty Mail est un **produit autonome**. Vous pouvez l'utiliser même si vos paywalls, abonnements ou analytics ne sont pas gérés par Adapty — migrer toute votre infrastructure n'est pas nécessaire.
:::

## 2. Configurez votre domaine d'envoi \{#2-set-up-your-sending-domain\}

Ouvrez Adapty Mail : cliquez sur le logo Adapty dans l'en-tête et choisissez **Mail**.

<ZoomImage id="product-switcher.webp" width="500px" alt="Adapty product switcher" />

Adapty Mail envoie depuis votre propre domaine. Vous ajoutez les enregistrements DNS une seule fois — toutes les campagnes utilisent le même domaine vérifié.

1. Dans Adapty Mail, accédez à **Settings → DNS** et, dans la section **Email domains**, cliquez sur **Add domain**.
2. Dans le champ **Domain**, saisissez votre domaine racine (par exemple, `yourapp.com`). Seuls les domaines apex sont acceptés — les sous-domaines comme `app.yourapp.com` sont rejetés à la saisie.
3. Dans le champ **Sending subdomain**, saisissez le préfixe depuis lequel vos e-mails sont envoyés, ou laissez-le vide pour utiliser `mail`. Les e-mails proviennent alors de `hello@mail.yourapp.com`.
4. Cliquez sur **Add domain**.

<ZoomImage id="mail-email-domains.webp" width="500px" />

5. Dans le bureau d'enregistrement de votre domaine, ajoutez chaque enregistrement DNS que la carte du nouveau domaine liste. Ils sont regroupés en trois catégories : les enregistrements DKIM et MAIL FROM de votre sous-domaine d'envoi, les enregistrements pour la boîte mail qui chauffe le domaine, et les enregistrements pour `go.yourapp.com`, qui sert les images et les liens tracés. Pour savoir ce que chaque groupe authentifie, consultez [Quels enregistrements vous ajoutez](mail-sending-domain#which-records-you-add). Pour tous les récupérer d'un coup, cliquez sur **Export**.
6. Optionnellement, ajoutez l'enregistrement TXT DMARC suggéré sur votre domaine racine (recommandé).
7. Cliquez sur **Check** pour vérifier immédiatement, ou quittez la carte et laissez Adapty Mail interroger les DNS.

<ZoomImage id="email-domains.webp" width="700px" />

Récapitulatif des délais de vérification :

- **Vérification automatique** : la première vérification s'effectue 1 minute après l'ajout du domaine, puis les intervalles doublent jusqu'à une fois par heure, jusqu'à ce que les enregistrements soient détectés.
- **Vérification manuelle** : cliquez sur **Check** à tout moment pour déclencher une vérification immédiate.
- **Propagation DNS** : généralement quelques minutes, jusqu'à 48 heures dans de rares cas.
- **Fenêtre de vérification** : 7 jours. Si elle expire, vos enregistrements DNS restent en place — ajoutez à nouveau votre domaine dans **Settings → DNS** pour démarrer une nouvelle fenêtre.

Un seul domaine vérifié suffit pour commencer à envoyer. Un projet peut en contenir jusqu'à cinq, et vous pouvez ajouter les autres plus tard.

Pour en savoir plus sur chaque type d'enregistrement et le warm-up de domaine, consultez [Configurer votre domaine d'envoi](mail-sending-domain).

## 3. Créer un paywall web \{#3-create-a-web-paywall\}

Chaque e-mail renvoie vers un paywall web — la page de paiement sur laquelle les utilisateurs arrivent en cliquant sur un CTA. Deux options s'offrent à vous :

- **Générer avec l'IA** : laissez le créateur de paywall web intégré en générer un pour votre application.
- **Utiliser votre propre paywall hébergé** : connectez un paywall que vous hébergez déjà.

Pour commencer, dans Adapty Mail, rendez-vous dans **Web Paywalls → Create**.

<ZoomImage id="new-web-paywall.webp" width="500px" />

### Option A : Générer avec l'IA \{#option-a-generate-with-ai\}

La page affiche une liste de contrôle **Prerequisites** avec des boutons intégrés — parcourez-la dans l'ordre, puis revenez pour générer. Cette liste couvre la connexion au Paywall Builder, la connexion à Stripe, l'ajout de produits et la vérification du résultat. Consultez [Configurer le paiement](mail-checkout) pour la procédure complète.

Une fois tous les prérequis validés, cliquez sur **Generate** pour ouvrir la boîte de dialogue de génération :

- **Environment** : Choisissez **Production** ou **Sandbox**. Le sandbox utilise vos produits Stripe en mode test — c'est la valeur par défaut recommandée pour les environnements de développement et locaux.
- **Plans** : Sélectionnez jusqu'à **3 plans Stripe** (chaque plan est un produit + un prix). Ce sont les offres que le paywall généré présente aux utilisateurs lors du paiement.

Cliquez sur **Generate** pour lancer la génération. Une fois terminée, ouvrez l'éditeur pour vérifier et publier.

:::important
Le paywall doit être publié avant de pouvoir traiter le trafic de paiement. Les paywalls non publiés renvoient une erreur lorsque les utilisateurs cliquent sur les liens de paiement par e-mail.
:::

### Option B : Utiliser votre propre paywall hébergé

1. Sélectionnez **Enter URL manually**.
2. Collez l'URL de votre paywall hébergé avec des espaces réservés en tant que paramètres de requête. Adapty Mail les remplace pour chaque destinataire afin que la page de paiement puisse identifier le visiteur. Exemple :

   ```
   https://example.com/paywall?email={email}&adapty_profile_id={adapty.external_profile_id}
   ```

   La page de création liste les espaces réservés disponibles. Consultez [Configurer le paiement](mail-checkout#use-your-own-hosted-paywall) pour savoir ce que chacun résout.
3. Enregistrez et publiez.

Pour comprendre l'anatomie du tunnel de paiement et le fonctionnement de la personnalisation, consultez [Configurer le paiement](mail-checkout).

<ZoomImage id="generate-web-paywall.webp" width="500px" />

## 4. Générer une campagne avec l'IA \{#4-generate-a-campaign-with-ai\}

L'IA crée l'intégralité de la séquence d'e-mails à votre place — textes, design, images hero et liens de paiement personnalisés, le tout adapté à votre marque.

1. Dans Adapty Mail, allez dans **Campaigns** et cliquez sur **Create**.
2. Définissez le nom de la campagne.
3. Dans le menu déroulant **Web paywall**, sélectionnez le web paywall ajouté à l'étape précédente.

<ZoomImage id="mail-new-campaign.webp" width="500px" />

4. Cliquez sur **Generate emails**.
5. Remplissez le formulaire de génération — ton, langue, une invite personnalisée facultative (jusqu'à 2 000 caractères) et le nombre d'e-mails (1–15, par défaut 4). Consultez [Créer une campagne](mail-create-campaign) pour le détail de chaque champ.

<ZoomImage id="generate-emails.webp" width="500px" />

6. Cliquez sur **Generate**. La génération prend généralement quelques minutes. Le système expire après 5 minutes s'il ne parvient pas à terminer — recommencez si cela se produit.
7. Prévisualisez chaque e-mail. L'en-tête de prévisualisation comporte un **Theme toggle** (Auto, Light, Dark) qui contrôle le rendu de l'aperçu — le contenu généré est identique dans tous les modes. Vous pouvez régénérer des e-mails individuellement, modifier le texte ou ouvrir l'éditeur HTML pour un contrôle précis.

<ZoomImage id="generated-emails.webp" width="700px" />

8. Cliquez sur **Create** pour sauvegarder la campagne.

La campagne est enregistrée comme **brouillon** et n'est pas encore envoyée — les campagnes ne sont actives que lorsqu'elles sont associées à un flow (étape suivante). Il n'y a pas d'action « publier » séparée dans l'éditeur de campagne.

## 5. Lancer un flow \{#5-launch-a-flow\}

Un flow associe un **déclencheur** (un événement comme l'expiration d'un abonnement) à un **segment**, et envoie à ce segment la **campagne** de votre choix. Adapty Mail propose cinq déclencheurs fixes, chacun avec sa propre vue de flow.

1. Dans Adapty Mail, rendez-vous dans **Flows**, puis ouvrez le déclencheur que vous souhaitez configurer :
   - **Never purchased** — utilisateurs qui se sont inscrits mais n'ont pas encore effectué d'achat.
   - **Renewal cancelled** — utilisateurs qui ont désactivé le renouvellement automatique mais disposent encore d'un abonnement actif.
   - **Billing issue** — paiement échoué, carte refusée ou expirée, ou délai de grâce.
   - **Expired** — l'abonnement a expiré et l'accès a été révoqué.
   - **Refunded** — utilisateurs ayant demandé un remboursement après leur achat.

   Consultez [Flows](mail-flows) pour en savoir plus sur l'objectif et le ton recommandé pour chaque déclencheur.

2. Cliquez sur **Create** pour ouvrir la boîte de dialogue.

<ZoomImage id="create-flow-mail.webp" width="500px" />

3. Dans la boîte de dialogue :
   - Choisissez un **Segment** (par exemple, **All Users** pour cibler tous ceux qui déclenchent cet événement, ou créez un nouveau segment basé sur les attributs du profil).
   - Laissez le type de contenu sur **Campaign** (l'option A/B Test est abordée dans [les tests A/B](mail-ab-testing)).
   - Sélectionnez la **Campaign** que vous avez enregistrée à l'étape 4.
4. Cliquez sur **Save**.

Le flow est actif immédiatement — il n'y a pas d'étape de lancement séparée. À partir de ce moment, les utilisateurs correspondant au segment commenceront à recevoir la campagne dès qu'ils déclencheront l'événement.

:::note
Vous pouvez ajouter plusieurs lignes segment → campagne au même déclencheur ; elles s'exécutent par ordre de priorité. La ligne **All Users**, si elle est utilisée, doit être la dernière (priorité la plus basse) afin de couvrir tous les utilisateurs non correspondant à un segment plus spécifique.
:::

<ZoomImage id="mail-flow-details.webp" width="500px" />

:::tip
Si les nouveaux destinataires doivent confirmer leur adresse avant de recevoir des e-mails marketing, activez le [double opt-in](mail-double-opt-in) avant cette étape. Seuls les profils créés après l'activation seront invités à confirmer.
:::

## 6. Lancer l'envoi \{#6-start-sending\}

Votre campagne est configurée mais ne se déclenche pas encore — aucune donnée utilisateur n'est transmise à Adapty Mail. Démarrer le flux de données est la dernière étape, et chaque point d'entrée défini à l'étape 1 se lance différemment :

- **Adapty** : Dans Adapty Mail, allez dans **Settings → Project** et cliquez sur **Enable Adapty integration**. Le bouton est désactivé jusqu'à la fin de l'étape 5, avec le message *"Set up at least one flow before enabling Adapty integration"*. Voir [Connecter Adapty à Adapty Mail](mail-collect-emails#4-enable-sending).
- **API Adapty Mail** : Commencez à envoyer des profils et des événements de transaction. Les profils envoyés avant la fin de cette configuration ne reçoivent rien, c'est pourquoi cette étape vient en dernier. Voir [Envoyer des e-mails et des transactions via l'API Adapty Mail](mail-send-data-via-api).

À partir de là, les utilisateurs correspondant à votre segment reçoivent la campagne dès qu'ils atteignent le déclencheur. Avant d'ouvrir l'accès aux vrais utilisateurs, [testez l'ensemble de la chaîne](mail-testing) avec un utilisateur de test.

## Dépannage \{#troubleshooting\}

| Problème                                   | Solution                                                                                                                                                 |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vérification DNS bloquée                   | Vérifiez que les enregistrements correspondent exactement — pas de points finaux, cibles CNAME correctes. Attendez 5 à 10 minutes, puis cliquez sur **Check** à nouveau |
| Fenêtre de vérification expirée            | Vos enregistrements sont toujours en place. Ajoutez votre domaine à nouveau dans **Settings → DNS** pour démarrer une nouvelle fenêtre                  |
| Génération échouée ou expirée              | Vérifiez votre connexion internet et réessayez. Si le problème persiste, contactez le support Adapty                                                    |
