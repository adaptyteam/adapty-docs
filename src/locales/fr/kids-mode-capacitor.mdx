Si votre application Capacitor est destinée aux enfants, vous devez respecter les politiques d'[Apple](https://developer.apple.com/kids/) et de [Google](https://support.google.com/googleplay/android-developer/answer/9893335). Si vous utilisez le SDK Adapty, quelques étapes simples vous permettront de le configurer pour répondre à ces politiques et passer les révisions des stores.

## Qu'est-ce qui est requis ? \{#whats-required\}

Vous devez configurer le SDK Adapty pour désactiver la collecte des éléments suivants :

- [IDFA (Identifier for Advertisers)](https://en.wikipedia.org/wiki/Identifier_for_Advertisers) (iOS)
- [Android Advertising ID (AAID/GAID)](https://support.google.com/googleplay/android-developer/answer/6048248) (Android)
- [Adresse IP](https://www.ftc.gov/system/files/ftc_gov/pdf/p235402_coppa_application.pdf)

De plus, nous vous recommandons d'utiliser l'identifiant utilisateur client avec prudence. Un identifiant au format `<FirstName.LastName>` sera inévitablement considéré comme une collecte de données personnelles, tout comme l'utilisation d'une adresse e-mail. Pour le mode enfants, la bonne pratique consiste à utiliser des identifiants aléatoires ou anonymisés (par exemple, des identifiants hachés ou des UUID générés par l'appareil) afin de garantir la conformité.

## Activation du mode Enfants \{#enabling-kids-mode\}

### Mises à jour dans Adapty Dashboard

Dans Adapty Dashboard, vous devez désactiver la collecte des adresses IP. Pour ce faire, rendez-vous dans [App settings](https://app.adapty.io/settings/general) et cliquez sur **Disable IP address collection** sous **Collect users' IP address**.

### Mises à jour dans le code de votre application mobile

Afin de respecter les politiques en vigueur, désactivez la collecte de l'IDFA, du GAID et de l'adresse IP de l'utilisateur :

```typescript showLineNumbers

try {
  await adapty.activate({
    apiKey: 'YOUR_PUBLIC_SDK_KEY',
    params: {
      // Disable IP address collection
      ipAddressCollectionDisabled: true,

      // Disable IDFA collection on iOS
      ios: {
        idfaCollectionDisabled: true
      },

      // Disable Google Advertising ID collection on Android
      android: {
        adIdCollectionDisabled: true
      }
    }
  });
  console.log('Adapty activated with Kids Mode enabled');
} catch (error) {
  console.error('Failed to activate Adapty with Kids Mode:', error);
}
```

### Configurations spécifiques à la plateforme \{#platform-specific-configurations\}

#### iOS \{#ios\}

<SDKv4>

Même si la collecte d'IDFA est désactivée dans le code (voir ci-dessus), votre build inclut toujours les frameworks `AdSupport` et `AppTrackingTransparency`. La catégorie Kids de l'App Store ne les autorise pas.

Pour respecter les exigences d'Apple, compilez le SDK iOS natif en mode Kids, qui exclut entièrement le code lié à l'IDFA, à AdSupport et à AppTrackingTransparency. La façon de l'activer dépend du gestionnaire de paquets de votre projet iOS, comme décrit dans [Configurer votre projet iOS](sdk-installation-capacitor#set-up-your-ios-project).

<Tabs groupId="ios-package-manager" queryString>

<TabItem value="spm" label="Swift Package Manager" default>

Ajoutez la commande `adapty-kids-mode` fournie avec le SDK au `postinstall` de votre application. Elle active le trait `KidsMode` du SDK. La commande est réappliquée à chaque installation :

```json showLineNumbers title="package.json"
{
  "scripts": {
    "postinstall": "adapty-kids-mode"
  }
}
```

Réinstallez ensuite et re-résolvez les packages iOS, puis compilez avec **Xcode 26** ou une version ultérieure :

```sh showLineNumbers title="Shell"
npm install
npx cap sync ios
```

Pour désactiver le mode enfants, supprimez `adapty-kids-mode` de `postinstall` ou remplacez-le par `adapty-kids-mode disable`, exécutez `npx adapty-kids-mode disable`, puis synchronisez à nouveau. Sinon, le prochain `npm install` réactivera le mode enfants.

:::note
Dans le SDK 4.2.0 et versions ultérieures, `adapty-kids-mode` affiche un avertissement, sans faire échouer l'installation, lorsqu'il ne trouve pas le projet iOS, ou lorsque votre Podfile ne correspond pas à la commande : `enable` sans appel `adapty_enable_kids_mode` dans le Podfile, ou `disable` avec l'appel encore présent. Pour supprimer les avertissements, passez `--no-warnings` ou définissez `ADAPTY_KIDS_MODE_NO_WARNINGS=1`. Si votre application se trouve en dehors du répertoire depuis lequel vous installez, passez `--app-root=path/to/app`.
:::

</TabItem>

<TabItem value="cocoapods" label="CocoaPods">

Cette option nécessite le SDK 4.2.0 ou ultérieur ainsi que les helpers Podfile d'Adapty fournis dans [Configurer votre projet iOS](sdk-installation-capacitor#set-up-your-ios-project). Dans `ios/App/Podfile`, appelez `adapty_enable_kids_mode` dans le bloc `post_install` :

```ruby showLineNumbers title="ios/App/Podfile" {3}
post_install do |installer|
  assertDeploymentTarget(installer)
  adapty_enable_kids_mode(installer)
end
```

Le helper ajoute la condition de compilation `KidsMode` au pod `Adapty` et dissocie le framework AdSupport. Il ne fonctionne que dans `post_install` : depuis `post_integrate`, ses modifications ne sont jamais sauvegardées. Si un autre pod de votre projet lie également AdSupport, `pod install` échoue, car le framework resterait dans le build.

Synchronisez ensuite le projet iOS :

```sh showLineNumbers title="Shell"
npx cap sync ios
```

Pour désactiver le Kids Mode, supprimez la ligne `adapty_enable_kids_mode` et resynchronisez.

</TabItem>

</Tabs>

Pour confirmer que le mode Kids est actif, vérifiez la ligne de log d'activation. Le SDK natif l'écrit au niveau `verbose` avant d'appliquer le `logLevel` que vous passez à `activate`, donc définissez le niveau de log avant l'activation :

```typescript showLineNumbers
await adapty.setLogLevel({ logLevel: 'verbose' });
await adapty.activate({ apiKey: 'YOUR_PUBLIC_SDK_KEY' });
```

Dans la console Xcode, la ligne `Calling Adapty activate` liste `"kids_mode_enabled": true` parmi ses paramètres.

</SDKv4>

<SDKv3>

Si vous utilisez CocoaPods pour iOS, vous pouvez également activer le mode Kids au niveau natif :

1. Mettez à jour votre Podfile :

   - Si vous **n'avez pas** de section `post_install`, ajoutez le bloc de code complet ci-dessous.
   - Si vous **avez déjà** une section `post_install`, intégrez les lignes mises en évidence dans celle-ci.

   ```ruby showLineNumbers title="Podfile"
   def adapty_enable_kids_mode(installer)
     installer.pods_project.targets.each do |target|
       next unless target.name == 'Adapty'
       target.build_configurations.each do |config|
         flags = config.build_settings['OTHER_SWIFT_FLAGS'] || '$(inherited)'
         flags = flags.join(' ') if flags.is_a?(Array)
         config.build_settings['OTHER_SWIFT_FLAGS'] = "#{flags} -DADAPTY_KIDS_MODE"
       end
       target.frameworks_build_phase.files.dup.each do |bf|
         target.frameworks_build_phase.remove_build_file(bf) if bf.display_name.to_s.include?('AdSupport')
       end
     end
     installer.pods_project.save
     Dir.glob(File.join(installer.sandbox.root, 'Target Support Files', '**', '*.xcconfig')).each do |xc|
       File.write(xc, File.read(xc).gsub(/\s*-framework\s+"?AdSupport"?/, ''))
     end
   end

   post_install do |installer|
     # ... keep your existing post_install body (Flutter adds one automatically) ...

     adapty_enable_kids_mode(installer)   # <-- enable Adapty Kids Mode
   end
   ```

2. Exécutez la commande suivante pour appliquer les modifications :

   ```sh showLineNumbers title="Shell"
   pod install
   ```

</SDKv3>

#### Android : supprimer la permission d'identifiant publicitaire \{#android-remove-the-advertising-id-permission\}

Définir `adIdCollectionDisabled: true` (ci-dessus) empêche Adapty de collecter l'identifiant publicitaire, mais le SDK déclare quand même la permission `AD_ID`. Si votre application cible uniquement les enfants et se compile avec Android 13 (API 33) ou supérieur, Google Play vous interdit même de la demander.

Ajoutez deux éléments à votre balise `<manifest>` :

1. Déclarez le namespace `tools` (le manifeste par défaut de Capacitor ne l'inclut pas).
2. Ajoutez une entrée `<uses-permission>` pour `AD_ID` avec `tools:node="remove"` pour la supprimer.

```xml showLineNumbers title="android/app/src/main/AndroidManifest.xml"
<manifest
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">

    <uses-permission
        android:name="com.google.android.gms.permission.AD_ID"
        tools:node="remove" />

    <!-- your existing manifest content -->
</manifest>
```

## Étapes suivantes \{#next-steps\}

Une fois le mode enfants activé, veillez à :

1. Tester votre application en profondeur pour vous assurer que toutes les fonctionnalités fonctionnent correctement
2. Mettre à jour la politique de confidentialité de votre application pour refléter la désactivation de la collecte de données
3. Soumettre votre application à la révision avec une documentation claire sur la conformité au mode enfants

Pour plus d'informations sur les exigences spécifiques à chaque plateforme :
- [Mode enfants dans le SDK iOS](kids-mode) pour des détails de configuration iOS supplémentaires
- [Mode enfants dans le SDK Android](kids-mode-android) pour des détails de configuration Android supplémentaires
