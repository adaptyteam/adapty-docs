Bienvenue ! Notre mission : vous simplifier la vie pour tout ce qui touche aux achats intégrés 🚀

Nous avons conçu le SDK Flutter d'Adapty pour vous éviter les maux de tête liés aux achats intégrés, afin que vous puissiez vous concentrer sur ce que vous faites le mieux : créer des applications exceptionnelles. Voici ce dont nous nous occupons pour vous :

- Gérez les achats, la validation des reçus et la gestion des abonnements sans configuration supplémentaire
- Créez et testez des flows et des paywalls sans mise à jour de l'application
- Obtenez des analyses d'achats détaillées sans aucune configuration — cohortes, LTV, churn et analyse d'entonnoir inclus
- Maintenez le statut d'abonnement des utilisateurs toujours à jour entre les sessions et les appareils
- Intégrez votre application aux services d'attribution marketing et d'analyse en une seule ligne de code

:::note
Avant de plonger dans le code, vous devrez intégrer Adapty avec App Store Connect et Google Play Console, puis configurer des produits dans le tableau de bord. Consultez notre [guide de démarrage rapide](quickstart) pour tout configurer en premier.
:::

## Concepts clés \{#main-concepts\}

Avant de plonger dans le code, familiarisons-nous avec les concepts essentiels qui font fonctionner Adapty.

Ce qui fait la force de l'approche d'Adapty, c'est que seuls les placements sont codés en dur dans votre app. Tout le reste – produits, designs de paywalls, tarifs et offres – peut être géré librement depuis l'Adapty Dashboard sans mise à jour de l'app :

1. [**Produit**](product) - Tout ce qui est disponible à l'achat dans votre app – abonnement, produit consommable ou accès à vie.

2. **Flow ou paywall** - Produits associés à une configuration, rattachés à un placement. Deux variantes :
   - **[Flow](adapty-flow-builder)** - Interface visuelle no-code créée dans le Flow & Paywall Builder. Adapty génère l'interface et gère l'achat pour vous.
   - **[Paywall](paywalls)** - Pas de configuration visuelle ; vous construisez l'interface dans votre propre code et appelez `makePurchase` vous-même. Voir [Implémenter les paywalls manuellement](flutter-quickstart-manual).

   Dans le code SDK, les deux sont récupérés via la même méthode `getFlow`.

3. [**Placement**](placements) - Un point stratégique dans le parcours utilisateur où vous souhaitez afficher un flow ou un paywall. Les placements représentent le « où » et le « quand » de votre stratégie de monétisation. Les placements courants sont :
   - `main` - Votre emplacement de paywall principal
   - `onboarding` - Affiché pendant le flow d'onboarding
   - `settings` - Accessible depuis les paramètres de votre application

   Commencez par les bases comme `main` ou `onboarding` pour votre première intégration, puis [réfléchissez aux autres endroits de votre application où les utilisateurs pourraient être prêts à acheter](choose-meaningful-placements).

4. [**Profil**](profiles-crm) - Lorsque des utilisateurs achètent un produit, leur profil se voit attribuer un **niveau d'accès** que vous utilisez pour définir l'accès aux fonctionnalités payantes.
