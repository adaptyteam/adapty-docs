Apple exige une déclaration de confidentialité pour toutes les nouvelles apps et mises à jour, aussi bien dans la section **App Privacy** d'App Store Connect que dans le fichier manifeste de l'app. Adapty étant une dépendance tierce de votre app, vous devez indiquer comment vous utilisez Adapty en lien avec les données des utilisateurs.

## Manifeste de confidentialité de l'application Apple \{#apple-app-privacy-manifest\}

Le [fichier manifeste de confidentialité](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests), nommé `PrivacyInfo.xcprivacy`, décrit les données privées utilisées par votre application et les raisons de cette utilisation. En tant que propriétaire d'application, vous devez créer un fichier manifeste pour votre app. De plus, si vous intégrez des SDK supplémentaires, assurez-vous que les fichiers manifestes de ceux figurant dans la liste des [SDK nécessitant un manifeste de confidentialité et une signature](https://developer.apple.com/support/third-party-SDK-requirements/) sont bien inclus. Lorsque vous compilez votre application, Xcode fusionne tous ces fichiers manifestes en un seul.

Même si Adapty ne figure pas dans la liste des [SDK nécessitant un manifeste de confidentialité et une signature](https://developer.apple.com/support/third-party-SDK-requirements/), les versions 2.10.2 et supérieures du SDK Adapty l'incluent pour votre commodité. Pensez à mettre à jour le SDK pour obtenir le manifeste.

Le manifeste alimente uniquement le rapport de confidentialité généré par Xcode. L'App Review vérifie vos réponses dans [App Store Connect](#apple-app-privacy-disclosure-in-app-store-connect), donc renseignez cette section en intégralité.

Si vous identifiez vos utilisateurs avec le `customerUserId` d'Adapty, déclarez l'identifiant utilisateur dans votre fichier manifeste :

1. Ajoutez un dictionnaire au tableau `NSPrivacyCollectedDataTypes` dans votre fichier d'informations de confidentialité.
2. Ajoutez les clés `NSPrivacyCollectedDataType`, `NSPrivacyCollectedDataTypeLinked` et `NSPrivacyCollectedDataTypeTracking` au dictionnaire.
3. Ajoutez la chaîne `NSPrivacyCollectedDataTypeUserID` (identifiant du type de données `UserID` dans la [Liste des catégories et types de données à déclarer dans le fichier manifeste](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests#Describe-the-data-your-app-or-third-party-SDK-collects)) pour la clé `NSPrivacyCollectedDataType` dans votre dictionnaire `NSPrivacyCollectedDataTypes`.
4. Ajoutez `true` pour la clé `NSPrivacyCollectedDataTypeLinked`. Ajoutez `false` pour la clé `NSPrivacyCollectedDataTypeTracking`, sauf si vous utilisez l'identifiant utilisateur à des fins de [suivi au sens d'Apple](https://developer.apple.com/app-store/user-privacy-and-data-use/).
5. Utilisez les chaînes `NSPrivacyCollectedDataTypePurposeAppFunctionality` et `NSPrivacyCollectedDataTypePurposeAnalytics` comme valeurs pour la clé `NSPrivacyCollectedDataTypePurposes` dans votre dictionnaire `NSPrivacyCollectedDataTypes`.

Si vous ciblez vos paywalls sur des audiences avec des attributs personnalisés, réfléchissez bien aux attributs que vous utilisez et vérifiez s'ils correspondent aux [catégories et types de données à déclarer dans le fichier manifeste](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests). Si c'est le cas, répétez les étapes ci-dessus pour chaque type de données.

Après avoir déclaré tous les types et catégories de données que vous collectez, créez le rapport de confidentialité de votre application comme décrit dans la [documentation Apple](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests#Create-your-apps-privacy-report).

#### Identifiants \{#identifiers\}

Lorsque vous utilisez Adapty, vous devez déclarer les identifiants suivants :
- **Device ID** — Adapty génère un identifiant d'appareil pour chaque installation et collecte l'IDFV. Il collecte également l'IDFA, sauf si vous [désactivez la collecte des identifiants publicitaires](analytics-integration#disable-collection-of-advertising-identifiers). Vous ne pouvez pas désactiver l'identifiant par installation, donc déclarez **Device ID** dans tous les cas.
- **User ID** — requis si vous identifiez les utilisateurs avec **`customerUserId`**.

#### Données d'utilisation \{#usage-data\}

Lorsque vous utilisez Adapty, vous devez indiquer que votre application collecte des données **Product Interaction**. Adapty enregistre les ouvertures de l'application ainsi que les événements liés aux paywalls et aux flows dans le profil de l'utilisateur.

1. Cliquez sur **Set up purchase history** dans le bloc **Purchases**.

2. Lorsqu'Apple demande comment les données d'historique d'achats sont utilisées, sélectionnez les options suivantes pour Adapty :
    - **Analytics** — Adapty utilise l'historique des achats pour les analyses de revenus, les cohortes et les métriques.
    - **Product Personalization** — Adapty utilise les données d'achats pour la segmentation des audiences et le ciblage des paywalls. Cela ne s'applique que si vous ciblez des placements par audience, mais sélectionner cette option est la valeur par défaut prudente.
    - **App Functionality** — Adapty valide les achats, gère les niveaux d'accès et suit le statut des abonnements.

    Sélectionnez des finalités supplémentaires si votre application utilise les données d'achat d'une autre manière (par exemple, si vous envoyez des événements d'achat à des plateformes publicitaires via les intégrations Adapty).

        - **Analytics** — Adapty utilise les identifiants pour compter les utilisateurs et leur attribuer des événements dans les analyses.

### Liaison et suivi \{#linking-and-tracking\}

Pour chaque type de données, Apple demande également si les données sont liées à l'identité de l'utilisateur et si elles sont utilisées à des fins de suivi. Pour Adapty, répondez comme suit :

- **Lié à l'utilisateur** : **Non**, si vous ne définissez pas `customerUserId`. L'identifiant de l'appareil est un identifiant aléatoire généré pour chaque installation, et rien en lui n'identifie une personne. Si vous définissez `customerUserId`, répondez **Oui** pour chaque type de données Adapty, car l'identifiant utilisateur les relie tous à l'utilisateur.
- **Utilisé pour le suivi** : **Non**. Adapty n'utilise pas ces données pour le [suivi tel qu'Apple le définit](https://developer.apple.com/app-store/user-privacy-and-data-use/). Répondez **Oui** uniquement si votre application utilise ces données à des fins de suivi.
