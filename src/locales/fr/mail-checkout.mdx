Chaque e-mail envoyé par Adapty Mail contient un lien de paiement unique pour le destinataire. Lorsqu'il clique, il arrive sur un tunnel de paiement web qui l'identifie par profil, lui présente votre offre et traite le paiement. Les tunnels de paiement se trouvent dans **Web Paywalls** dans Adapty Mail et sont modifiés dans le **web paywall builder** intégré.

## Prérequis \{#requirements\}

- Un fournisseur de paiement web avec vos produits d'abonnement configurés. **Generate with AI** ne prend en charge que Stripe et la connexion se fait directement dans le builder. **Use your own hosted paywall** accepte n'importe quel fournisseur — Stripe, Paddle, PayPal ou autre — puisque le paiement est géré de votre côté.

Vous n'avez pas besoin d'un compte séparé pour le web paywall builder. Il est intégré à Adapty Mail : un espace de travail est provisionné automatiquement lors de votre première connexion, et vous êtes connecté à l'éditeur avec vos identifiants Adapty. Cela est indépendant de tout paywall web que vous avez pu configurer sur la page paywall du tableau de bord Adapty principal — les paywalls web d'Adapty Mail sont des entités distinctes, gérées entièrement depuis Adapty Mail.

## Configurer votre tunnel de paiement \{#set-up-your-checkout-funnel\}

Dans Adapty Mail, accédez à **Web Paywalls → Create**. Deux options s'offrent à vous :

- **Generate with AI** : le créateur de paywall web intégré à Adapty Mail génère le tunnel pour vous. Stripe uniquement — pour Paddle ou PayPal, utilisez la deuxième option.
- **Use your own hosted paywall** : connectez un paywall que vous hébergez déjà, quel que soit le prestataire de paiement.

### Générer avec l'IA \{#generate-with-ai\}

La page de création affiche un panneau **Prerequisites** en haut avec des boutons d'action intégrés qui vous guident à travers chaque condition préalable — état de la marque, connexion au builder, connexion Stripe, produits, et une étape finale de révision et publication. Parcourez-les dans l'ordre ; le panneau se met à jour à mesure que chaque étape est complétée.

<ZoomImage id="mail-checkout-prerequisites.webp" width="500px" alt="Panneau Prerequisites sur la page de création du Web Paywall avec une liste de vérification et des boutons d'action intégrés" />

Lorsque les prérequis sont au vert, cliquez sur **Generate** pour ouvrir la boîte de dialogue de génération. Deux choix à faire :

- **Environment** : Choisissez **Production** ou **Sandbox**. Sandbox utilise vos produits Stripe en mode test et constitue l'option par défaut recommandée pour le développement et les environnements locaux — son compte est isolé de la production, donc les transactions de test n'affectent jamais les données live.
- **Plans** : Choisissez jusqu'à **3 plans Stripe**. Chaque plan est une combinaison produit + prix. Le paywall présente ces plans comme les offres disponibles au moment du paiement. Si vous en sélectionnez moins de 3, le paywall affiche uniquement les plans choisis.

<ZoomImage id="mail-checkout-generation-dialog.webp" width="500px" alt="Web paywall generation dialog with Environment toggle and Stripe plan selector" />

Cliquez sur **Generate** pour lancer la compilation. Une fois terminée, ouvrez l'éditeur dans le builder pour vérifier le résultat et le publier. Ensuite, cliquez sur **Save**.

:::important
Le paywall doit être publié avant de pouvoir traiter le trafic de paiement. Les paywalls non publiés renvoient une erreur lorsque les utilisateurs cliquent sur les liens de paiement envoyés par e-mail.
:::

Pour les détails concernant le fournisseur de paiement dans le builder (comptes Stripe, mode test ou live, configuration des produits), consultez [Configuration du paywall web](web-paywall-configuration).

### Utilisez votre propre paywall hébergé \{#use-your-own-hosted-paywall\}

Sur cette voie, Adapty Mail envoie les destinataires vers une page que vous hébergez et remplace les valeurs de chaque destinataire dans l'URL. Tout ce qui se passe après le clic — l'offre, le paiement, la personnalisation — se passe de votre côté, avec n'importe quel prestataire de paiement.

1. Dans **Web Paywalls → Create**, sélectionnez **Enter URL manually**.
2. Collez l'URL de votre paywall hébergé avec des espaces réservés en tant que paramètres de requête. Adapty Mail les remplace par destinataire afin que la page puisse identifier le visiteur. Exemple :

```
   https://example.com/paywall?email={email}&adapty_profile_id={adapty.external_profile_id}
   ```
3. Donnez un **Name** au paywall et enregistrez-le. Il est ensuite disponible pour être associé à des campagnes.

La page de création liste les variables que vous pouvez utiliser et coche chacune de celles qu'elle trouve dans l'URL que vous collez :

| Placeholder | Value |
| --- | --- |
| `{email}` | L'adresse e-mail du destinataire. |
| `{adapty.external_profile_id}` | L'ID de profil du destinataire dans Adapty. |
| `{funnelfox.external_profile_id}` | L'ID de profil du destinataire dans FunnelFox. |
| `{custom.external_profile_id}` | L'ID utilisateur que vous avez envoyé via l'[API Mail Adapty](mail-send-data-via-api). |
| `{scheduled_email_id}` | L'ID de l'e-mail qui contenait le lien. |

Les trois paramètres d'ID de profil correspondent chacun à une source depuis laquelle un profil peut arriver, et la page les liste tous, que votre projet les utilise ou non. Choisissez celui qui correspond à la façon dont vous envoyez les données : `{adapty.external_profile_id}` pour l'[intégration Adapty](mail-collect-emails), `{custom.external_profile_id}` pour l'[API](mail-send-data-via-api). Un paramètre pour lequel le destinataire n'a pas de valeur se résout en chaîne vide, il n'apparaîtra donc jamais dans votre page sous forme de texte brut — et un paramètre qu'Adapty Mail ne reconnaît pas est transmis tel quel.

#### Ce que votre page doit faire \{#what-your-page-has-to-do\}

La part d'Adapty Mail s'arrête à la redirection. Deux tâches vous incombent :

- **Identifier le visiteur avant le début du paiement** : lisez l'ID de profil ou l'e-mail depuis la chaîne de requête et associez-le à l'achat, afin que le paiement soit rattaché au client à qui l'e-mail a été envoyé.
- **Signaler l'achat en retour** : Adapty Mail ne voit jamais un paiement effectué via votre propre fournisseur, et un achat qu'il ne connaît pas n'est comptabilisé ni comme conversion ni comme revenu attribué dans [Analytics](mail-analytics) — pire encore, le reste de la séquence continue d'être envoyé à quelqu'un qui a déjà acheté. Transmettez-le via la méthode qui transporte déjà vos données : l'[intégration Adapty](mail-collect-emails), ou un [événement de transaction](mail-send-data-via-api#send-transaction-events) sur l'API Adapty Mail.

#### Testez avant de lancer

**Send test email** vérifie que l'email s'affiche correctement et que votre page encaisse les paiements, mais **Sandbox** n'est pas sélectionnable pour un paywall ajouté par URL — la fenêtre modale indique *"This paywall has no sandbox products, so only production is available."* Un test envoie donc vers votre page de production avec de vrais produits : utilisez une vraie carte et remboursez-la, ou faites pointer l'URL vers votre propre environnement de test le temps de vérifier la configuration. Voir [Testez votre configuration](mail-testing#test-the-email-and-checkout-on-their-own).

## À quoi ressemble le processus de paiement \{#what-the-checkout-looks-like\}

Lorsqu'un utilisateur clique sur un lien de paiement, il arrive sur la **Main conversion page**. Après avoir tenté un paiement, il voit soit **Payment success**, soit **Payment failed** — une seule page s'affiche par tentative.

**Main conversion page**
Une page de vente complète. L'IA génère le texte et les images pour chaque section :

| Section | Ce que l'IA génère |
|---|---|
| Titre principal | Titre accrocheur axé sur les bénéfices |
| Sous-titre | Proposition de valeur complémentaire |
| Badge d'offre | Badge d'urgence (sans prix inventés — utilise un langage promotionnel vague) |
| Bouton CTA | Texte orienté action, 2 à 5 mots |
| Bénéfices | 3 à 6 cartes bénéfices avec emoji et texte |
| Fonctionnalités | 3 à 8 descriptions de fonctionnalités avec titre et sous-titre |
| Forfaits | Titre de sélection du forfait et texte du minuteur d'offre |
| Preuve sociale | Texte de preuve communautaire et 3 à 5 avis d'utilisateurs réalistes |
| FAQ | 3 à 6 questions-réponses courantes |
| Garantie | Texte de garantie satisfait ou remboursé |

**Paiement réussi**
Un message de félicitations avec les prochaines étapes et une image générée par IA.

**Paiement échoué**
Un message bienveillant invitant l'utilisateur à réessayer. L'état du paiement est conservé.

## Comment fonctionne la personnalisation \{#how-personalization-works\}

Le lien CTA de chaque e-mail pointe vers une URL de paiement construite pour son destinataire. Avant l'envoi, Adapty Mail remplace chaque espace réservé dans votre URL de paywall par les valeurs propres à ce destinataire :

```
https://example.com/paywall?email=jane@example.com&adapty_profile_id=6f2a...c91
```

Les paramètres d'un paywall généré sont définis automatiquement — aucune configuration dans le Paywall Builder en ligne n'est requise. Pour un paywall ajouté par URL, vous choisissez les paramètres à inclure. Lorsque l'utilisateur clique, la page de paiement lit ces paramètres pour l'identifier. Une fois l'achat effectué, Adapty associe le revenu à l'adresse e-mail précise qui a déclenché la conversion. Ces données apparaissent dans [Analytique des campagnes](mail-analytics).

## Résolution des problèmes \{#troubleshooting\}

| Problème | Solution |
|---|---|
| Le lien de paiement ne s'ouvre pas | Vérifiez que le paywall est publié dans le constructeur de paywall web |
| L'utilisateur n'est pas identifié au moment du paiement | Confirmez que `Adapty.identify()` a été appelé avec le bon identifiant utilisateur avant l'envoi de l'e-mail |
| L'achat n'est pas attribué à l'e-mail | L'attribution suit le clic sur le CTA de l'e-mail : le destinataire doit accéder au paiement via ce lien, et l'achat doit parvenir à Adapty Mail sur le même profil. Un achat déjà attribué à un e-mail précédent conserve cette attribution |
