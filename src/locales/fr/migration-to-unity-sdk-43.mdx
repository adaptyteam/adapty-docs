Le SDK Adapty Unity 4.3 nécessite Unity 6, supprime `Adapty.GetLogLevel`, affiche les messages intégrés Google Play par défaut, et modifie le type C# de certaines données d'événements de flow sur Android. Consultez chaque changement dans ce guide pour conserver le comportement de votre application.

Si vous êtes encore sur la version 3.x, commencez par [Migrer vers la v4.1](migration-to-unity-sdk-v4), puis suivez ce guide.

## Référence rapide \{#quick-reference\}

| v4.1 | v4.3 |
|---|---|
| Unity 2022.3 ou version ultérieure | Unity 6.0 (6000.0) ou version ultérieure |
| `Adapty.GetLogLevel(...)` | supprimé — gardez une trace du niveau défini avec `builder.LogLevel` ou `Adapty.SetLogLevel` |
| Les messages Google Play ne sont pas demandés | Les messages Google Play sont affichés par défaut sur Android, y compris dans les flows |
| Les paramètres d'événements de flow entiers arrivent en tant que `double` sur Android | Ils arrivent en tant que `long` sur les deux plateformes |

## Installation \{#installation\}

Adapty Unity SDK 4.3 nécessite **Unity 6.0 (6000.0)** ou une version ultérieure. Si votre projet utilise Unity 2022.3, mettez-le à jour en premier, ou restez sur Adapty SDK 4.1.x.

:::warning
Adapty SDK 4.1.x ne fonctionne pas avec GameActivity, le point d'entrée Android par défaut pour les nouveaux projets Unity 6 : les gestionnaires de complétion et les événements n'atteignent jamais C#. Si vous mettez à jour Unity avant le SDK, maintenez **Application Entry Point** sur **Activity** jusqu'à ce que vous passiez à Adapty SDK 4.3. Le SDK 4.3 fonctionne avec les deux points d'entrée.
:::

Pour installer le SDK 4.3 via le Unity Package Manager, utilisez cette URL Git :

```
https://github.com/adaptyteam/AdaptySDK-Unity.git?path=/Packages/com.adapty.unity-sdk#4.3.0-beta.1
```

Si vous installez via le package Unity, téléchargez `adapty-unity-plugin-4.3.0-beta.1.unitypackage` depuis la [version 4.3.0-beta.1](https://github.com/adaptyteam/AdaptySDK-Unity/releases/tag/4.3.0-beta.1). Supprimez le dossier `Assets/AdaptySDK/Plugins/Android/Local` avant de l'importer. Le SDK 4.3 n'embarque plus le wrapper Java Android interne que ce dossier contient, et l'importation d'un `.unitypackage` ne supprime jamais de fichiers — l'ancien wrapper resterait donc dans votre projet sans cette étape.

Les autres exigences restent identiques à la version 4.1 : **iOS 15.0** et **Xcode 26**. Consultez [Installer le SDK Adapty](sdk-installation-unity) pour la configuration complète.

## `GetLogLevel` est supprimé \{#getloglevel-is-removed\}

`Adapty.GetLogLevel` n'est plus disponible. Le niveau de log est celui que vous définissez avec `builder.LogLevel` lors de l'activation du SDK, ou ultérieurement avec `Adapty.SetLogLevel`. Si votre code lit le niveau en retour, stockez plutôt la valeur que vous avez définie :

```diff showLineNumbers
- Adapty.GetLogLevel((level, error) => {
-     // use level
- });
+ var logLevel = AdaptyLogLevel.Verbose;
+ builder.LogLevel = logLevel;
+ // use logLevel
```

## Les messages Google Play s'affichent par défaut \{#google-play-messages-are-shown-by-default\}

À partir de la version 4.3, le SDK demande les messages Google Play in-app, comme les notifications de paiement refusé, à chaque fois qu'une `Activity` de votre application démarre après l'activation. Cela inclut les moments où l'application revient au premier plan et lorsqu'un flow ou un onboarding s'ouvre ou se ferme, ce qui peut afficher un message par-dessus un paywall.

Si cela convient à votre application, aucune modification n'est nécessaire. Pour choisir le moment où les messages s'affichent, activez le SDK avec la gestion manuelle sur Android, et appelez `Adapty.ShowStoreMessages` au moment qui convient à votre application :

```csharp showLineNumbers title="C#"
var builder = new AdaptyConfiguration.Builder("YOUR_PUBLIC_SDK_KEY");
#if UNITY_ANDROID
builder.SetStoreMessagesHandling(AdaptyStoreMessagesHandling.Manual);
#endif

Adapty.Activate(builder.Build(), (error) => {
    // handle the error
});
```

Activez la gestion manuelle uniquement sur Android pour ne pas modifier le comportement sur iOS : à partir d'iOS 16, la gestion manuelle retient également les messages de l'App Store jusqu'à ce que votre application appelle `Adapty.ShowStoreMessages`. Pour l'API complète, consultez [Contrôler les messages du store](unity-store-messages).

:::warning
En mode manuel, les stores n'affichent pas les messages d'eux-mêmes. Si votre application n'appelle jamais `Adapty.ShowStoreMessages`, les utilisateurs ne verront jamais de notification de paiement refusé.
:::

## Les paramètres numériques d'événements flow sont de type `long` sur Android \{#numeric-flow-event-parameters-are-long-on-android\}

Sur Android, les paramètres entiers de `FlowViewDidReceiveAnalyticEvent` arrivaient auparavant sous forme de `double`. À partir de la version 4.3, ils arrivent sous forme de `long`, comme sur iOS. Cela inclut les valeurs de date et d'heure des événements [flow input](unity-flow-input).

Un cast en `double` lève désormais une exception sur Android. Convertissez les paramètres numériques au lieu de les caster :

```diff showLineNumbers
- var timestamp = (double)parameters["value"];
+ var timestamp = Convert.ToInt64(parameters["value"]);
```

## Nouveautés de la version 4.3 \{#new-in-43\}

Ces ajouts sont optionnels. Votre code existant continue de fonctionner sans eux :

- **[Contrôler les messages du store](unity-store-messages)** : Choisissez quand les messages de l'App Store et de Google Play apparaissent.
- **[Précharger les placements](unity-optimize-paywall-fetching#preload-placements)** : `Adapty.PreloadFlows` et `Adapty.PreloadFlowsForDefaultAudience` préchauffent le cache du flow.
- **[Conserver une vue de flow](unity-present-paywalls#keep-the-view-to-present-it-again)** : `view.Dismiss(false, ...)` conserve une vue pour la présenter à nouveau, et `view.Destroy(...)` la libère.
- **[Plans d'engagement de 12 mois](set-up-12-month-commitment)** : La propriété `AdaptySubscription.PricingTerms` décrit le plan sur iOS, et les niveaux d'accès ainsi que les abonnements exposent `BillingPlan` et `CommitmentInfo`.
- **Nouveau code d'erreur** : `AdaptyErrorCode.BillingPlanUnavailable` (1060, iOS uniquement). `MakePurchase` le retourne quand le produit ne propose pas le plan de facturation demandé sur l'appareil ou dans le storefront. Si votre code couvre toutes les valeurs d'`AdaptyErrorCode`, gérez ce nouveau cas.
- **[Mode observateur](report-transactions-observer-mode-unity)** : `Adapty.ReportTransaction` accepte un paramètre optionnel `appleJWSTransaction` sur iOS.
- **Nom de variante** : `AdaptyFlow.VariationName` retourne le nom de variante que vous avez défini dans l'Adapty Dashboard.
