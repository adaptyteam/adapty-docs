Cet article couvre le cycle de vie complet d'un test A/B dans Adapty : créer un test, le lancer et l'arrêter lorsque vous êtes prêt à analyser les résultats.

## Prérequis \{#prerequisites\}

Avant de configurer un test A/B, vous devez avoir :

- Au moins deux [flows](adapty-flow-builder)/[paywalls](paywalls)/[onboardings](onboardings) créés
- Un [placement](placements) configuré dans votre application

:::warning
Si vous n'utilisez pas le [Adapty Flow & Paywall Builder](adapty-flow-builder) ou l'[ancien Adapty Paywall Builder](adapty-paywall-builder), [envoyez les vues de paywall à Adapty](present-remote-config-paywalls#track-paywall-view-events) avec `.logShowFlow()` (SDK iOS v4+) / `.logShowPaywall()`. Sans cette méthode, Adapty ne peut pas comptabiliser les vues de paywall dans le test, et les statistiques de conversion seront inexactes.
:::

:::info
Les tests A/B dans Adapty suivent un processus en deux étapes. Vous créez d'abord un test et l'enregistrez en tant que brouillon — il n'est pas mis en ligne immédiatement. Lorsque vous êtes prêt, vous le lancez séparément. Cela vous permet de vérifier la configuration avant que les utilisateurs ne la voient.
:::

## Créer un test A/B \{#create-an-ab-test\}

Lors de la création d'un nouveau test A/B, vous devez inclure au moins deux [flows](adapty-flow-builder)/[paywalls](paywalls)/[onboardings](onboardings).

Pour créer un nouveau test A/B :

1. Accédez à [A/B tests](ab-tests) depuis le menu principal d'Adapty.

   <Zoom>
     <img src="/assets/shared/img/go-to-abtests.webp"
     style={{
       border: '1px solid #727272', /* border width and color */
       width: '700px', /* image width */
       display: 'block', /* for alignment */
       margin: '0 auto' /* center alignment */
     }}
   />
   </Zoom>

2. En haut à droite, cliquez sur **Create A/B test**.

   <Zoom>
     <img src="/assets/shared/img/create-abtest.webp"
     style={{
       border: '1px solid #727272', /* border width and color */
       width: '700px', /* image width */
       display: 'block', /* for alignment */
       margin: '0 auto' /* center alignment */
     }}
   />
   </Zoom>

3. Dans la fenêtre **Create the A/B test**, saisissez un **Test name**. Ce champ est obligatoire. Choisissez un nom qui décrit clairement l'objet du test afin de l'identifier facilement lors de l'analyse des résultats.
4. Renseignez le **Test goal** pour décrire ce que vous souhaitez accomplir (par exemple, augmenter les abonnements ou réduire le churn).
5. Cliquez sur **Select placement** et choisissez un placement de type flow, paywall ou onboarding.
6. Configurez le contenu du test dans le tableau **Variants**. Chaque ligne correspond à une variante, chaque colonne à un placement. Ajoutez un paywall à chaque intersection.

Par défaut, le tableau comporte 2 variantes et 1 placement. Vous pouvez ajouter jusqu'à 20 variantes. Dès que vous ajoutez un second placement, le test devient un test A/B cross-placement. Notez que les tests A/B cross-placement sont uniquement disponibles pour les paywalls.

Chaque variante peut également avoir un nom, qui apparaît dans la liste des tests A/B et dans les métriques du test. Saisissez-le dans la première colonne de la ligne de la variante. Si vous laissez le champ vide, Adapty nomme la variante selon sa position — `Variant A`, `Variant B`, etc.

Un nom peut comporter jusqu'à 255 caractères, et deux variantes d'un même test ne peuvent pas partager le même nom. Vous ne pouvez pas renommer une variante une fois le test lancé. Pour renommer une variante dans un test en cours, utilisez **Modify**, décrit dans [Modifier un test A/B](#edit-an-ab-test).

   <Zoom>
       <img src="/assets/shared/img/abtest-variants.webp"
       style={{
         border: '1px solid #727272',
         width: '700px',
         display: 'block',
         margin: '0 auto'
       }}
     />
   </Zoom>

7. Enregistrez votre test. Deux options s'offrent à vous :
    1. **Save as draft** : le test ne sera pas mis en ligne immédiatement. Vous pourrez le lancer plus tard depuis le placement ou la liste des tests A/B. Utilisez cette option pour vérifier la configuration avant le lancement.
    2. **Run A/B test** : lance le test immédiatement. Le test est mis en ligne dès que vous cliquez sur ce bouton.

Une fois enregistré en tant que brouillon, passez à [Lancer un test A/B](#run-an-ab-test).

## Modifier un test A/B \{#edit-an-ab-test\}

Vous pouvez uniquement modifier les tests A/B enregistrés en tant que brouillons. Une fois un test en cours d'exécution, il ne peut plus être modifié. Pour mettre à jour un test actif, utilisez l'option **Modify** — cela crée un doublon avec le même nom dans lequel vous pouvez apporter des modifications. Adapty arrête le test d'origine, et les deux versions (originale et modifiée) apparaissent séparément dans vos analyses.

## Lancer un test A/B \{#run-an-ab-test\}

Lancer un test A/B dans Adapty signifie l'assigner à un placement pour qu'il commence à afficher des paywalls et des onboardings aux utilisateurs.

1. Accédez à la section [A/B tests](ab-tests) depuis le menu principal d'Adapty.

2. Vérifiez que vous consultez la bonne liste — les tests A/B **Paywall**, **Flow**, **Onboardings** et **Crossplacement** sont affichés dans des onglets séparés entre lesquels vous pouvez naviguer.

<Zoom>
     <img src="/assets/shared/img/ab-tests-tabs.webp"
     style={{
       border: '1px solid #727272', /* border width and color */
       width: '700px', /* image width */
       display: 'block', /* for alignment */
       margin: '0 auto' /* center alignment */
     }}
    />
   </Zoom>

3. Passez à l'onglet **Drafts**. Seuls les tests en brouillon peuvent être lancés.

4. En regard du test que vous souhaitez lancer, cliquez sur **Run A/B test**.

<Zoom>
     <img src="/assets/shared/img/run-ab-test-2.webp"
     style={{
       border: '1px solid #727272', /* border width and color */
       width: '700px', /* image width */
       display: 'block', /* for alignment */
       margin: '0 auto' /* center alignment */
     }}
   />
   </Zoom>

5. La fenêtre **Edit A/B test** s'ouvre. Vérifiez la configuration et apportez les dernières modifications si nécessaire. Si le placement ou l'audience est manquant, ajoutez-le maintenant.

6. Une fois la configuration vérifiée, cliquez sur **Run A/B test** pour démarrer.

Après le lancement du test, vous pouvez suivre sa progression et consulter les données de performance sur la page [Résultats et métriques du test A/B](results-and-metrics).

## Arrêter un test A/B \{#stop-an-ab-test\}

Lorsque vous arrêtez un test A/B, il se termine et vous pouvez consulter les résultats. Vous décidez également ce qui sera affiché aux utilisateurs dans les placements concernés après la fin du test.

<Zoom>
  <img src="/assets/shared/img/stop-ab-test.webp"
  style={{
    border: 'none', /* border width and color */
    width: '700px', /* image width */
    display: 'block', /* for alignment */
    margin: '0 auto' /* center alignment */
  }}
/>
</Zoom>

1. Ouvrez la section [A/B tests](https://app.adapty.io/ab-tests) et accédez à l'onglet **Live**.

2. À côté du test que vous souhaitez arrêter, cliquez sur le menu à trois points, puis choisissez **Stop A/B test**.

3. Dans la fenêtre **Stop the A/B test**, décidez ce qui doit se passer après la fin du test. Vous avez trois options :

| Option                                                                                      | Description                                                                                                                                                                                                                                                                                                                                                                              |
   |----------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | Afficher l'un des paywalls/onboardings testés                  | Choisissez le paywall ou l'onboarding gagnant en vous basant sur les résultats du test : revenus, probabilité d'être le meilleur (**P2BB**) et revenus pour 1 000 utilisateurs. Ce paywall ou onboarding sera affiché pour le placement et l'audience sélectionnés.                                                                                                                      |
   | Sélectionner des paywalls/onboardings ne participant pas au test A/B | Choisissez n'importe quel paywall ou onboarding qui ne fait pas partie du test A/B en cours. Utilisez cette option si aucune des variantes testées n'a atteint vos objectifs.                                                                                                                                             |
   | Ne pas afficher de paywall/onboarding spécifique               | Pour le placement et l'audience sélectionnés, aucun paywall ni onboarding spécifique ne sera sélectionné à la fin du test A/B. C'est le paywall ou l'onboarding suivant disponible selon la priorité des audiences qui sera affiché. C'est une bonne option si vous préférez laisser votre configuration existante décider quel paywall ou onboarding afficher, sans en sélectionner un manuellement. |

:::note
Arrêter un test A/B est irréversible — il ne peut pas être redémarré. Assurez-vous d'avoir collecté suffisamment de données avant de décider d'arrêter.
:::

4. Cliquez sur le bouton **Stop and complete this A/B test**.

Une fois le test A/B terminé, il ne sera plus actif, et les paywalls ou onboardings qui en faisaient partie ne seront plus affichés aux nouveaux utilisateurs.

Vous pouvez toujours consulter les résultats et les métriques du test A/B sur la [page des métriques du test A/B](results-and-metrics#metrics-controls) pour évaluer les performances des utilisateurs qui y ont participé pendant son exécution. Les métriques peuvent continuer à se mettre à jour au fur et à mesure que de nouveaux événements d'achat ou de revenus sont attribués à ces utilisateurs.
