:::important
Avant de commencer, assurez-vous d'avoir la version requise du SDK Adapty installée :
- **Paywall Builder ou paywalls personnalisés** : 3.6.1 ou ultérieure (iOS), 3.15 ou ultérieure (Android et multiplateforme)
- **Flow & Paywall Builder** : 4.0 ou ultérieure (toutes les plateformes)
:::

Avec Adapty, vous pouvez créer un paywall ou un [flow](adapty-flow-builder) avec un bouton qui redirige vos utilisateurs vers leur navigateur pour effectuer un paiement. Ensuite, lorsqu'ils reviennent dans votre application après un achat réussi, l'abonnement s'active.
Cela vous permet de contourner les frais du store tout en suivant les paiements des utilisateurs.

<ZoomImage id="web_paywall.gif" width="700px" alt="Démonstration d'un web paywall" />

:::tip
L'App Store n'autorise les options de paiement externes qu'aux États-Unis et au Japon.

Pour utiliser un paywall exclusivement pour ces marchés, dupliquez votre paywall actuel et configurez un paywall web. Vous aurez ainsi deux paywalls presque identiques : un pour les États-Unis et le Japon, et un autre pour tous les autres.
:::

## Comment ça fonctionne \{#how-it-works\}

Un paywall web est une URL unique générée pour chacun de vos paywalls intégrés à l'application. Elle s'ouvre dans le navigateur pour le paiement et fonctionne avec différents fournisseurs de paiement (Stripe, Paddle et autres), prenant en charge aussi bien une page simple avec un bouton Apple Pay que des flows plus complexes avec des offres supplémentaires.

<ZoomImage id="web-paywall-promo.png" width="700px" alt="Aperçu du paywall web" />

Les paywalls web fonctionnent de la manière suivante :
1. **Configurez l'apparence et le comportement de la page de paywall web** dans l'éditeur de paywall web.
2. **Liez le paywall web** dans les paramètres du paywall.
3. Dans le paywall de votre application, **ajoutez un bouton** redirigeant les utilisateurs vers le navigateur.
4. Lorsque les utilisateurs appuient sur le bouton, le SDK Adapty **génère une URL unique** qui inclut l'identifiant de profil Adapty de l'utilisateur.
5. Les utilisateurs **accèdent à la page de paywall web** et **paient** leur abonnement via un moyen de paiement externe.
6. Lorsqu'ils reviennent dans l'application, le SDK Adapty **interroge le serveur pour détecter les mises à jour du profil** afin de confirmer l'activation de l'abonnement.
7. Adapty enregistre l'achat et surveille l'abonnement pour détecter tout changement de statut, comme les renouvellements ou les annulations.

L'ID de profil dans l'URL associe l'achat web à l'utilisateur de l'application. L'achat est rattaché au profil déjà utilisé par votre application, vous n'avez donc pas besoin d'appeler `Adapty.identify()` pour un acheteur web.

## Étape 1. Créer un paywall web \{#step-1-create-a-web-paywall\}

1. Préparez un paywall :
   - Pour activer les paiements externes sur un paywall existant, [dupliquez-le](duplicate-paywalls). Cela vous permet d'afficher le web paywall à votre segment cible et l'original à tous les autres.
   - Pour partir de zéro, [créez](create-paywall) un nouveau paywall.
2. Sur la page du paywall, passez à l'onglet **Web paywall** et cliquez sur **Create web paywall**. Vous serez redirigé vers une nouvelle page.
<ZoomImage id="web-paywall-1.png" width="700px" alt="Onglet Web paywall dans les paramètres du paywall" />
3. Configurez le web paywall et connectez un moyen de paiement.
:::tip
Pour obtenir de l'aide sur la configuration de l'éditeur externe et la connexion d'un fournisseur de paiement, consultez le [guide de démarrage rapide](web-paywall-configuration).
:::
4. Retournez sur la page **Web paywall** et collez le lien du paywall.
:::important
Lors du déploiement de votre paywall en production, assurez-vous d'utiliser le lien correct généré après la publication de votre web paywall. Le format du lien est `paywalls-....fnlfx.com`.
:::
5. Cliquez sur **Save**.
<ZoomImage id="web-paywall-4.png" width="700px" alt="Coller le lien du web paywall et enregistrer" />

## Étape 2. Déclencher le paywall \{#step-2-trigger-the-paywall\}

Pour utiliser votre paywall web, vous devez le déclencher, et la manière de procéder dépend de votre configuration :

- Si vous utilisez le Flow & Paywall Builder, il vous suffit d'[ajouter un nouveau bouton](#step-2a-add-a-web-purchase-button) qui utilisera le lien que vous avez fourni pour suivre les achats et renvoyer les données à Adapty.
- Si vous utilisez le SDK, vous devez configurer la méthode [`openWebPaywall`](#step-2b-call-the-sdk-method) pour gérer les paywalls web.

### Étape 2a. Ajouter un bouton d'achat web \{#step-2a-add-a-web-purchase-button\}

Si vous utilisez le **Flow & Paywall Builder**, vous devez ajouter un bouton de paywall web. Ce bouton utilisera le lien que vous avez fourni pour suivre les achats et renvoyer les données à Adapty.

1. Ouvrez le flow et ajoutez un bouton.

   Si vous utilisez un modèle ou un paywall existant, ajoutez un bouton de paywall web à côté du bouton d'achat existant. Vous pouvez le configurer de la même façon.

2. Dans le panneau **Interactions** à droite, cliquez sur **Add trigger**. Ensuite, assignez l'action **Purchase** à ce déclencheur.
   <ZoomImage id="on-tap-purchase.webp" width="500px" />
3. Dans les paramètres de l'action, passez à l'onglet **Web payment**. Là, sélectionnez un produit et—optionnellement—une offre à associer au bouton d'achat web.

4. Collez le lien du paywall web dans le champ **Web paywall URL**.

5. Par défaut, les paywalls web s'ouvrent dans un navigateur intégré à l'application afin que les utilisateurs n'aient pas besoin de quitter votre app. Si vous souhaitez les ouvrir dans un navigateur externe, sélectionnez **Open in external browser**.

<ZoomImage id="web-payment-action.webp" width="500px" />

## Étape 3. Configurer un placement \{#step-3-set-up-a-placement\}

Étant donné que l'App Store n'autorise les options de paiement externe qu'aux États-Unis et au Japon, créez un segment d'utilisateurs distinct pour les utilisateurs iOS sur ces marchés et configurez un placement pour cibler différents paywalls selon les segments. Pour les utilisateurs Android, aucune restriction géographique ne s'applique — créez un segment Android distinct sans filtre de pays.

1. [Créez un nouveau segment](segments) avec les attributs suivants :
   - **Country from store account** : United States, Japan
   - **Platform** : iOS and iPadOS
   - **App version** : La dernière version qui utilise le SDK Adapty.
<ZoomImage id="web-paywall-6.png" width="700px" alt="Segment attributes for web paywall targeting" />
2. [Créez](create-placement) un placement ou [modifiez](edit-placement) un placement existant. [Ajoutez une nouvelle audience](add-audience-paywall-ab-test) avec le paywall web et le segment créé.
<ZoomImage id="web-paywall-7.png" width="700px" alt="Placement with web paywall audience" />

## Ajouter un tunnel d'annulation \{#add-a-cancellation-funnel\}

Un tunnel d'annulation est une page web qu'un abonné ouvre pour annuler son abonnement. Avant que l'annulation ne soit finalisée, le tunnel peut proposer une pause, un forfait à tarif réduit ou une période gratuite. Vous le créez dans le même éditeur que votre paywall web, et votre app l'ouvre via une URL. Le tunnel annule l'abonnement auprès de votre prestataire de paiement, donc votre app n'effectue aucun appel API d'annulation.

Pour créer un entonnoir d'annulation, dans l'éditeur de paywall web, ouvrez l'onglet **Cancellation**. Les actions de rétention sont disponibles uniquement dans les entonnoirs d'annulation, vous ne pouvez donc pas les ajouter à l'entonnoir qui gère votre paywall web. Pour l'entonnoir lui-même, consultez [le guide FunnelFox sur les entonnoirs d'annulation](https://funnelfox.com/docs/dashboard/funnels#cancellation-funnels).

<ZoomImage id="cancellation-funnel.webp" width="700px" alt="Onglet Cancellation dans l'éditeur de paywall web" />

### Obtenir l'identifiant de profil FunnelFox de l'abonné \{#get-the-subscribers-funnelfox-profile-id\}

Un funnel d'annulation identifie l'abonné par son identifiant de profil FunnelFox. Après un achat d'abonnement web, FunnelFox écrit cet identifiant dans le [profil](profiles-crm) Adapty en tant qu'attribut personnalisé `fnlfx_profile_id`, accompagné de `fnlfx_funnel_id`, `fnlfx_session_id`, `vendor_profile_id` et `vendor`.

FunnelFox écrit ces attributs une seule fois, lors du premier achat d'abonnement web. Les achats ultérieurs ne les modifient pas. Pour un achat consommable, FunnelFox ne les écrit que si l'élément de paiement possède un niveau d'accès personnalisé.

Votre application lit `fnlfx_profile_id` depuis `customAttributes` du profil utilisateur. Pour retrouver cette valeur dans Adapty, ouvrez **Profiles** et recherchez le profil de l'utilisateur.

:::note
Adapty stocke jusqu'à 30 attributs personnalisés par profil. Lorsqu'un profil est plein, Adapty ignore les attributs supplémentaires sans renvoyer d'erreur, et FunnelFox ne les renvoie pas. Si votre application définit ses propres attributs personnalisés, laissez de la place pour les cinq attributs FunnelFox.
:::

### Ouvrir le funnel depuis votre application \{#open-the-funnel-from-your-app\}

Votre application construit elle-même l'URL d'annulation. Elle ne va pas dans le champ **Web paywall URL** — ce champ appartient à un paywall qui vend un produit, et Adapty y ajoute `adapty_profile_id`, pas `fpid`.

Combinez l'URL de votre funnel d'annulation publié avec le `fnlfx_profile_id` de l'abonné :

```
https://<your-project>.fnlfx.com/cancel?fpid=<fnlfx_profile_id>
```

Passez la valeur de l'attribut telle qu'elle est stockée, sans préfixe. Ouvrez l'URL quand l'utilisateur appuie sur votre bouton d'annulation.

Les utilisateurs peuvent fermer la page à tout moment, y compris après que le funnel a annulé l'abonnement. Ne considérez pas leur retour dans l'application comme une confirmation. Récupérez le profil pour obtenir l'état actuel. Un abonnement annulé conserve son niveau d'accès jusqu'à la fin de la période payée.
