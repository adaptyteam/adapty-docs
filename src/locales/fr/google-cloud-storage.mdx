Activez l'intégration Google Cloud Storage pour stocker en toute sécurité les [événements d'abonnement](events) et les [données de visites des paywalls](paywall-metrics) dans un emplacement central : votre bucket Google Cloud Storage.

Chaque jour à 4h UTC, Adapty téléverse des fichiers .csv avec les données de la veille dans vos buckets. Vous pouvez choisir de recevoir les données d'**événements**, les données de **visites de paywall**, ou **les deux**. Vous pouvez également exporter ces données [manuellement](#manual-data-export) à tout moment, pour n'importe quelle période.

Pour configurer l'intégration, [générez une clé d'accès au bucket](#create-google-cloud-storage-credentials) dans votre console Google Cloud, puis [ajoutez-la à vos paramètres Adapty](#set-up-google-cloud-storage-integration).

## Calendrier et durée des téléversements \{#upload-schedule-and-duration\}

Adapty téléverse les données vers Google Cloud Storage toutes les 24 heures, à 04:00 UTC.

Les fichiers contiennent les données des événements créés au cours de la journée calendaire précédente (UTC). Le fichier téléversé le 8 mars contiendra tous les événements créés le 7 mars, de 00:00:00 à 23:59:59 UTC.

Le processus peut prendre plusieurs heures, selon le nombre total de fichiers dans la file d'attente ainsi que le volume de données que vous avez demandées. Si Adapty inclut des données historiques dans votre premier téléversement, celui-ci prendra plus de temps que les téléversements quotidiens suivants.

## Configurer l'intégration Google Cloud Storage \{#set-up-google-cloud-storage-integration\}

Vous devez disposer d'une clé de compte de service Google Cloud valide avec un **accès en écriture**. Pour en générer une, suivez les étapes de la section [créer des identifiants](#create-google-cloud-storage-credentials).

:::warning
Vous pouvez utiliser des buckets et des identifiants différents pour les événements, les visites de paywall et les transactions de monnaie virtuelle. Lorsque vous enregistrez les paramètres, Adapty vérifie les identifiants de chaque export actif. Si l'un d'eux est invalide, Adapty n'enregistre les paramètres d'aucun onglet. Voir [Dépannage](#troubleshooting).
:::

Accédez à [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage) et ouvrez l'onglet souhaité (**Events** ou **Paywall visits**). Activez l'intégration.

Importez le fichier contenant votre **clé de compte de service Google Cloud**. Indiquez le **bucket** et le **dossier** cibles. Enregistrez vos modifications.

## Créer des identifiants Google Cloud Storage \{#create-google-cloud-storage-credentials\}

Ce guide vous aidera à créer les identifiants nécessaires dans votre Console Google Cloud Platform.

Pour qu'Adapty puisse téléverser des rapports de données brutes dans votre bucket désigné, la clé du compte de service est requise, ainsi que l'accès en écriture au bucket correspondant. En fournissant la clé du compte de service et en accordant l'accès en écriture au bucket, vous permettez à Adapty de transférer de manière sécurisée et efficace les rapports de données brutes depuis sa plateforme vers votre environnement de stockage.

:::warning
Veuillez noter que nous prenons uniquement en charge l'autorisation par clé HMAC de compte de service. Il est donc essentiel de vous assurer que votre clé HMAC de compte de service dispose des rôles « Storage Object Viewer », « Storage Legacy Bucket Writer » et « Storage Object Creator » pour permettre un accès correct à Google Cloud Storage.
:::

1. Pour commencer, rendez-vous dans la section [IAM](https://console.cloud.google.com/projectselector2/iam-admin/serviceaccounts) de votre compte Google Cloud et sélectionnez le projet concerné ou créez-en un nouveau.

  <ZoomImage id="30a81ef-CleanShot_2023-03-17_at_15.22.142x.webp" width="700px" />


1. Ensuite, créez un nouveau compte de service pour Adapty en cliquant sur le bouton **+ CREATE SERVICE ACCOUNT**.

    <ZoomImage id="98f8ebf-CleanShot_2023-03-17_at_15.40.062x.webp" width="700px" />

2. Remplissez les champs de la première étape — les accès seront configurés plus tard. Pour en savoir plus sur cette page, consultez la documentation [ici](https://docs.cloud.google.com/iam/docs/service-accounts-create).

    <ZoomImage id="2190c50-CleanShot_2023-03-17_at_15.48.552x.webp" width="700px" />

3. Pour créer et télécharger une [clé JSON privée](https://docs.cloud.google.com/iam/docs/keys-create-delete), accédez à la section KEYS et cliquez sur le bouton « ADD KEY ».

    <ZoomImage id="8a45468-CleanShot_2023-03-17_at_15.58.092x.webp" width="700px" />

4. Dans la section DETAILS, repérez la valeur Email associée au compte de service que vous venez de créer et copiez-la. Vous en aurez besoin dans les étapes suivantes pour autoriser le compte et lui permettre d'écrire dans le bucket.

    <ZoomImage id="6ccd0f0-CleanShot_2023-03-17_at_16.03.162x.webp" width="700px" />
    

5. Pour continuer, rendez-vous sur la page [Buckets](https://console.cloud.google.com/storage/browser) de Google Cloud Storage et sélectionnez un bucket existant ou créez-en un nouveau pour stocker les rapports Event ou Visits Data provenant d'Adapty. Accédez ensuite à la section PERMISSIONS et sélectionnez l'option [GRANT ACCESS](https://docs.cloud.google.com/identity/docs/how-to?hl=en).

    <ZoomImage id="3cdd937-CleanShot_2023-03-17_at_16.14.232x.webp" width="700px" />

6. Dans la section PERMISSIONS, saisissez l'e-mail du compte de service obtenu à la cinquième étape mentionnée précédemment, puis choisissez le rôle Storage Object Creator. Enfin, cliquez sur SAVE pour appliquer les modifications.


    <ZoomImage id="62801f4-CleanShot_2023-03-17_at_16.17.312x.webp" width="700px" />

    N'oubliez pas de noter le nom du bucket pour une utilisation ultérieure.

## Exportation manuelle des données \{#manual-data-export\}

En plus de l'exportation automatique des données d'événements vers Google Cloud Storage, Adapty propose également une fonctionnalité d'exportation manuelle de fichiers. Cette fonctionnalité vous permet de sélectionner un intervalle de temps spécifique pour les données d'événements et de les exporter manuellement vers votre bucket GCS. Vous gardez ainsi un meilleur contrôle sur les données exportées et sur le moment où vous les exportez.

La plage de dates spécifiée sera utilisée pour exporter les événements créés depuis la date A à 00:00:00 UTC jusqu'à la date B à 23:59:59 UTC.

## Transactions en devise virtuelle \{#virtual-currency-transactions\}

L'export en devise virtuelle envoie chaque modification du solde d'une [devise virtuelle](virtual-currencies) vers votre bucket Google Cloud Storage. Utilisez-le pour charger l'historique complet des crédits, dépenses, expirations et remboursements dans votre propre entrepôt de données.

Cet export est distinct des exports d'événements et de visites de paywall. Il dispose de son propre interrupteur, de ses propres identifiants, ainsi que de ses propres paramètres de bucket et de dossier.

### Activer l'export \{#turn-on-the-export\}

1. Allez dans [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage) et ouvrez l'onglet **Virtual currency**.
2. Activez **Export virtual currency transactions to Google Cloud Storage**.
3. Importez le fichier contenant votre [clé de compte de service Google Cloud](#create-google-cloud-storage-credentials), puis indiquez le bucket et le dossier. Les champs sont les mêmes que dans l'onglet **Paywall visits**.

Pour exporter les transactions en monnaie virtuelle des jours précédents, utilisez l'[export manuel des données](#manual-data-export).

### Fichier et planification \{#file-and-schedule\}

Chaque jour, Adapty importe 1 fichier contenant les transactions en monnaie virtuelle du jour calendaire précédent en UTC. Une transaction appartient au jour correspondant à son horodatage `created_at` en UTC.

Le nom du fichier est `<app_id>_virtual_currency_<date>.csv`, où `<date>` correspond au jour suivant celui des transactions, au format `YYYY-MM-DD`. Par exemple, le fichier `<app_id>_virtual_currency_2026-03-08.csv` contient les transactions du 7 mars 2026. Chaque export possède son propre nom de fichier. Conservez chaque export dans son propre dossier, afin qu'une table ou un chargeur lisant l'ensemble d'un dossier ne récupère qu'un seul type de fichier. Si les exports partagent un dossier, sélectionnez les fichiers de cet export par nom : `<app_id>_virtual_currency_*.csv`.

Le fichier est un fichier `.csv` encodé en UTF-8 avec une ligne d'en-tête. Pour un jour sans transaction, le fichier ne contient que la ligne d'en-tête.

Chaque ligne correspond à une variation de solde pour une devise donnée. Une transaction qui modifie 2 devises, comme un échange d'or contre des gemmes, génère 2 lignes avec le même `vc_transaction_id`. Les transactions sandbox sont également incluses dans le fichier, avec `is_sandbox` défini à `true`.

Lorsque vous enregistrez les paramètres, Adapty vérifie les identifiants de chaque export activé. Si les identifiants de la devise virtuelle sont invalides, Adapty n'enregistre pas les paramètres. Le bouton **Save** enregistre les paramètres de tous les onglets, donc Adapty n'enregistre pas non plus vos modifications sur les autres onglets.

L'export de devise virtuelle utilise ses propres identifiants. Si son envoi quotidien échoue, les envois d'événements et de visites de paywall de l'application continuent de fonctionner.

| **metadata** | Les `metadata` de la transaction, sous forme d'une valeur JSON dans une seule cellule. Vide si la transaction n'a pas de métadonnées. |

### Jointure avec la table des événements \{#join-with-the-events-table\}

Le fichier de monnaie virtuelle ne contient pas les prix. Pour obtenir le prix d'un achat ayant crédité une devise, joignez la ligne de crédit avec la table des événements :

- Faites correspondre **store_transaction_id** avec **transaction_id** de la table des événements.
- Faites également correspondre **store**, mais uniquement pour `app_store`, `play_store`, `stripe` et `paddle`. Pour `adapty` et les stores personnalisés, la table des événements contient un **store** vide.

Cet exemple de requête suppose que vous avez chargé les fichiers de monnaie virtuelle dans la table `vc_transactions` et les fichiers d'événements dans la table `events` :

```sql title="SQL"
SELECT
  vc.vc_transaction_id,
  vc.created_at,
  vc.profile_id,
  vc.currency_code,
  vc.amount,
  e.event_type,
  e.product_id,
  e.revenue_usd,
  e.currency,
  e.revenue_local
FROM vc_transactions AS vc
LEFT JOIN events AS e
  ON e.transaction_id = vc.store_transaction_id
  AND (
    e.store = vc.store
    OR vc.store NOT IN ('app_store', 'play_store', 'stripe', 'paddle')
  )
  AND e.event_type IN (
    'subscription_initial_purchase',
    'subscription_started',
    'subscription_renewed',
    'trial_started',
    'trial_converted',
    'non_subscription_purchase'
  )
WHERE vc.amount > 0
  AND COALESCE(vc.store_transaction_id, '') <> '';
```

La requête utilise les noms d'événements par défaut. Un début d'abonnement correspond à `subscription_initial_purchase` dans une intégration créée depuis mi-septembre 2025, et à `subscription_started` dans une intégration plus ancienne. Si vous avez modifié les noms d'événements dans les paramètres d'export des événements, utilisez vos propres noms dans la requête.

Une ligne de crédit n'a pas d'événement correspondant si l'export des événements est désactivé, si les paramètres d'export des événements excluent ou renomment le type d'événement de l'achat, ou si **Exclude historical events** exclut l'événement.

Un seul achat peut créditer plusieurs devises. Chaque devise obtient sa propre ligne de crédit, et toutes ces lignes appartiennent au même événement. Pour calculer le chiffre d'affaires total, comptez chaque **store_transaction_id** une seule fois.

### Limitations \{#limitations\}

- **Pas de prix ni de montant de remboursement** : le fichier de monnaie virtuelle ne contient ni prix d'achat ni montant de remboursement. Pour obtenir le prix, [joingnez la ligne de crédit avec la table des événements](#join-with-the-events-table).
- **Ne pas additionner les crédits des deux fichiers** : la colonne **virtual_currency_credits** du fichier [events](#events) et les lignes de crédits du fichier de monnaie virtuelle affichent les mêmes crédits d'achat. Pour comptabiliser les crédits, utilisez l'un ou l'autre, pas les deux. Leurs totaux peuvent différer : le fichier des événements ne contient que les crédits des achats, et uniquement pour les événements que ses paramètres exportent, tandis que le fichier de monnaie virtuelle enregistre chaque modification de solde, y compris les attributions via l'API et les ajustements manuels dans le tableau de bord.
- **Aucun lien entre une dépense et ses crédits** : le fichier n'indique pas quels crédits une dépense a utilisés, par exemple des crédits achetés ou accordés.
- **Les lignes de remboursement n'affichent que les crédits récupérés** : une ligne de remboursement indique les crédits qu'Adapty a repris sur le solde. Son **amount** peut être inférieur aux crédits accordés par l'achat, par exemple si l'utilisateur en a dépensé une partie. Si aucun crédit ne restait, le fichier ne contient aucune ligne de remboursement.
- **Pas de ligne de remboursement pour une mise à niveau d'abonnement** : un remboursement consécutif à une mise à niveau d'abonnement ne reprend aucun crédit. Le fichier ne contient aucune ligne de remboursement pour ce cas.

## Dépannage \{#troubleshooting\}

Lorsque vous enregistrez les paramètres, Adapty vérifie la clé de chaque export activé. Si une clé est invalide, Adapty n'enregistre les paramètres d'aucun onglet et affiche une erreur.

Chaque export utilise sa propre clé pour envoyer ses fichiers, donc une clé expirée ne bloque que les envois de cet export. Pour maintenir les envois, remplacez vos clés avant leur expiration. Si plusieurs onglets utilisent la même clé, remplacez-la sur chacun d'eux : **Events**, **Paywall visits** et **Virtual currency**.
