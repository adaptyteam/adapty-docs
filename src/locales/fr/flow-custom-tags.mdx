Un tag personnalisé est une [variable personnalisée](onboarding-variables#custom-variables) dont la valeur provient de votre application. Après avoir sélectionné **Value comes from outside the app** dans les paramètres d'une variable, votre application peut définir sa valeur via le SDK Adapty. Par exemple, un élément de texte contient « Coins: » et un tag personnalisé. Si votre application transmet « 120 » pour le tag, les utilisateurs voient « Coins: 120 ».

Utilisez des tags personnalisés pour afficher :

- **Qui est l'utilisateur** : Un nom d'utilisateur dans un message de bienvenue, par exemple « Bon retour, DragonSlayer42 ! »
- **Ce que l'utilisateur possède** : Le nombre de jours dans une série, ou le niveau d'un joueur.
- **Ce que votre application calcule** : Une remise pour un pack plus grand, ou un [IMC](ios-flow-custom-tags#example-show-a-bmi-from-onboarding-answers) basé sur les réponses de l'utilisateur dans un flow précédent.

## Valeurs et valeurs de secours \{#values-and-fallbacks\}

Votre application identifie chaque valeur par le nom de son tag personnalisé. La valeur est toujours une chaîne de caractères. Adapty ne formate ni ne traduit la chaîne, donc votre application doit rendre chaque valeur lisible avant qu'elle apparaisse dans le flow. Par exemple, passez "1 250" plutôt que "1250.0".

## 1. Créer un tag personnalisé \{#create-a-custom-tag\}

1. Ouvrez le panneau <Inline id="variables.svg" alt="Variables" /> Variables dans le flow builder.
2. Ajoutez une nouvelle variable — cliquez sur <Inline id="plus.svg" alt="Plus" />.
3. Configurez le **Name** de la variable. Le code de votre application doit y faire référence exactement, en respectant la casse.
   - **Characters** : Utilisez des lettres latines (A–Z et a–z), des chiffres, `_` et `-`. Pour placer le tag dans un groupe, commencez son nom par le groupe suivi d'un point, par exemple `user.streak`.
   - **Reserved names** : Quelle que soit la casse, n'utilisez pas de nom réservé, comme `PRICE`, `TITLE`, `VALUE`, ou un nom commençant par `TIMER_`.
   - **Uniqueness** : Utilisez un nom unique au sein du flow.
4. (Facultatif) Pour distinguer les différentes variables, renseignez le champ **Description**. En survolant le nom de la variable dans le builder, vous verrez la description.
5. Dans le champ **Initial value**, saisissez la valeur de secours affichée aux utilisateurs lorsque votre application ne transmet aucune valeur :
   - **Un mot adapté à tous les utilisateurs** : Pour le tag `username` dans un message d'accueil, saisissez `friend`. Les utilisateurs non authentifiés verront « Welcome back, friend! ». Notez que la valeur initiale ne peut pas être localisée.
   - **Un tiret pour un solde ou un compteur** : Pour éviter d'afficher une valeur de solde incorrecte aux utilisateurs non authentifiés, saisissez un tiret (`—`).

6. (Variables de type **String** uniquement) Cochez la case **Value comes from outside the app**. Cette action est irréversible et verrouille le **Value Type**.
7. Cliquez sur **Create variable**.

<ZoomImage id="flow-custom-tag-create.webp" width="500px" alt="Create variable form with a name, a description, the String value type, and an initial value" />

Les variables sont propres à chaque flow. Pour utiliser un tag personnalisé dans un autre flow, créez-en un avec le même nom dans ce flow.

### Remplacer une variable par un tag personnalisé \{#replace-a-variable-with-a-custom-tag\}

Vous ne pouvez cocher la case **Value comes from outside the app** qu'au moment de la création d'une variable. Pour afficher la valeur de votre application à la place d'une variable personnalisée classique, par exemple issue d'un [paywall converti](convert-paywall-to-flow), remplacez la variable par un tag personnalisé :

1. Supprimez la variable et toutes ses références dans le flow.
2. [Créez un tag personnalisé](#create-a-custom-tag) avec le même nom.
3. [Insérez le tag personnalisé](#add-a-custom-tag-to-a-text-element) dans chaque élément de texte qui utilisait la variable.

## 2. Ajouter un tag personnalisé à un élément texte \{#add-a-custom-tag-to-a-text-element\}

Sélectionnez l'élément texte. Dans la section **Content**, cliquez sur <Inline id="variables.svg" alt="Variables" /> **Add variable**, puis sélectionnez le tag dans l'onglet **Custom**.

<ZoomImage id="flow-custom-tag-full-name.webp" width="500px" alt="Custom tab of the Add variable dropdown with the streak tag in the user group" />

Vous pouvez insérer des tags personnalisés dans chaque branche du [texte conditionnel](onboarding-text#add-conditional-text), mais vous ne pouvez pas les sélectionner dans ses conditions **if**.

## Limitations \{#limitations\}

- **Éléments texte uniquement** : Vous ne pouvez insérer des tags personnalisés que dans des éléments texte. Ils ne sont pas acceptés dans :
  - les actions **Set variable**
  - les actions **Show alert**
  - les actions **Open URL**
  - les placeholders de champs de saisie
- **Pas de conditions sur les tags personnalisés** : Vous ne pouvez pas sélectionner un tag personnalisé dans une condition ou dans la visibilité conditionnelle. Pour décider quelle phrase, quels éléments et quels écrans les utilisateurs voient en fonction d'une valeur provenant de votre app :
  - **Phrase** : Construisez la phrase dans le code de votre app et transmettez-la comme valeur du tag. Par exemple, pour un tag `coins_message`, passez « You have 120 coins » aux joueurs qui ont des coins, et « Get your first coins » aux autres.
  - **Éléments et écrans** : [Définissez la valeur comme attribut personnalisé](setting-user-attributes). Puis affichez un flow séparé à une [audience](audience) construite à partir de cet attribut.
- **Pas de méthode SDK pour mettre à jour les valeurs dans un flow ouvert** : Pour afficher un résultat basé sur ce que les utilisateurs saisissent dans un flow, transmettez le résultat au flow suivant, comme dans l'[exemple IMC](ios-flow-custom-tags#example-show-a-bmi-from-onboarding-answers).
