Adapty propose deux types de tests A/B, chacun adapté à des scénarios de test différents :

- **Test A/B classique :** Un test A/B créé pour un seul placement de [flow](adapty-flow-builder)/[paywall](paywalls)/[onboarding](onboardings).
- **Test A/B crossplacement :** Un test A/B créé pour plusieurs placements de flows ou de paywalls dans votre application. Une fois que le test A/B attribue une <InlineTooltip tooltip="variante">Les variantes d'un test A/B sont des versions alternatives du flow, du paywall ou de l'onboarding à tester.</InlineTooltip>, cette variante est affichée de manière cohérente dans toutes les sections sélectionnées de votre application.

Chaque flow/paywall/onboarding reçoit un poids qui répartit le trafic pendant le test.

Par exemple, avec des poids de 70 % et 30 %, le premier paywall est affiché à environ 700 utilisateurs sur 1 000, le second à environ 300. Dans les tests Cross-placement, les poids sont définis par variante, et non par flow ou par paywall.

Cette configuration vous permet de comparer différents flows et paywalls, et de prendre des décisions basées sur les données pour la stratégie de monétisation de votre application.

## Quand utiliser chaque type \{#when-to-use-each-type\}

Chaque type de test A/B est utile dans les cas suivants :
- **Tests A/B classiques** :
  - Vous n'avez qu'un seul placement dans votre application.
  - Vous souhaitez exécuter votre test A/B sur un seul placement et suivre les changements économiques pour ce placement uniquement, même si votre application en comporte plusieurs.
  - Vous souhaitez exécuter un test A/B sur d'anciens utilisateurs (ceux qui ont déjà vu au moins un paywall Adapty).
- **Test A/B cross-placement** :
  - Vous souhaitez synchroniser les variantes sur plusieurs placements. Par exemple, vous pouvez modifier les prix dans le flow d'onboarding et dans les paramètres de votre application en même temps.
  - Vous souhaitez évaluer l'économie globale de votre application. Exécuter le test sur tous les placements rend les statistiques du test A/B plus faciles à analyser que de tester des placements isolés.
  - Vous souhaitez exécuter un test A/B uniquement sur de nouveaux utilisateurs, c'est-à-dire ceux qui n'ont encore jamais vu un seul paywall Adapty.
  - Vous souhaitez utiliser plusieurs flows ou paywalls au sein d'une même variante :

## Différences clés \{#key-differences\}

| Feature                         | Regular A/B Test                                                                                                   | Crossplacement A/B Test                                       |
| ------------------------------- |--------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------|
| **What is being tested**        | Un flow/paywall/onboarding                                                                                             | Ensemble de flows ou paywalls appartenant à une variante             |
| **Variant consistency**         | La variante est déterminée séparément pour chaque placement                                                               | Même variante utilisée sur tous les placements du test           |
| **Audience targeting**          | Définie par placement de flow/paywall/onboarding                                                                           | Partagée entre tous les placements du test                      |
| **Analytics**                   | Vous analysez un seul placement de flow/paywall/onboarding                                                                       | Vous analysez l'ensemble de l'application sur les placements faisant partie du test |
| **Variant weight distribution** | Par flow/paywall/onboarding                                                                                             | Par ensemble de flows ou paywalls                                  |
| **Users**                       | Pour tous les utilisateurs                                                                                                      | Uniquement les nouveaux utilisateurs (ceux qui n'ont pas encore vu un paywall Adapty)     |
| **Adapty SDK version**          | Pour les flows : v4.0.0+. N'importe laquelle pour les paywalls. Pour les onboardings : v3.8.0+ (iOS, Android, React Native, Flutter), v3.14.0+ (Unity), v3.15.0+ (KMP, Capacitor)                                                          | 4.0.0+ pour les flows, 3.5.0+ pour les paywalls   |
| **Best for**                    | Tester des changements indépendants dans un seul placement de flow/paywall/onboarding sans tenir compte de l'économie globale de l'application | Évaluer les stratégies de monétisation globales à l'échelle de l'application           |

## Logique de sélection des tests A/B \{#ab-test-selection-logic\}

**Les tests A/B interplacements ont la priorité sur les tests A/B classiques.** Cependant, les tests interplacements ne sont affichés qu'aux **nouveaux utilisateurs** — ceux qui n'ont encore vu aucun flow ou paywall Adapty (l'application n'a jamais appelé `getFlow` ou `getPaywall` pour eux). Cela garantit la cohérence des résultats entre les placements.

## Limitations des tests A/B crossplacement \{#crossplacement-ab-test-limitations\}

:::warning
Les tests A/B crossplacement ne peuvent pas inclure de placements d'onboarding. Un même test ne peut pas mélanger des placements de type flow et des placements de type paywall.
:::

Les tests A/B crossplacement garantissent que chaque utilisateur voit la même variante sur tous les placements inclus dans le test. Cela implique les limitations suivantes :

* Seuls les nouveaux utilisateurs peuvent y participer. Un nouvel utilisateur est quelqu'un qui n'a encore vu aucun flow ni paywall Adapty et dont l'application n'a jamais appelé `getFlow` ou `getPaywall`. Adapty ne peut pas garantir une chaîne cohérente de flows ou de paywalls pour les autres utilisateurs.

* Le premier placement rencontré par l'utilisateur détermine quel flow ou paywall Adapty affiche. Vous ne pouvez pas modifier l'assignation d'un utilisateur ni inscrire le même utilisateur dans plus d'un test A/B Crossplacement.

* Un appareil prend connaissance des assignations cross-placement effectuées ailleurs — par exemple, sur un autre appareil de l'utilisateur — uniquement lorsque l'application devient active, et au maximum une fois toutes les 60 secondes. Cette synchronisation ne peut pas être forcée, donc une assignation peut prendre jusqu'à une minute, ou jusqu'au prochain passage au premier plan, pour atteindre une session en cours d'exécution.

:::warning
Une fois qu'un utilisateur reçoit un flow ou un paywall Crossplacement, il le voit pendant 90 jours, même après l'arrêt du test. Pour modifier cette durée, dans les paramètres **General**, ajustez **[Cross-placement variation stickiness](general#9-cross-placement-variation-stickiness)**.
:::

## Priorité des tests A/B crossplacement \{#crossplacement-ab-test-priority\}

* Les tests A/B crossplacement ont toujours la priorité sur les tests A/B classiques et les tests A/B d'onboarding. Si un nouvel utilisateur est éligible à la fois pour un test crossplacement et un test classique sur le même placement, le test crossplacement est affiché.

* Lorsque plusieurs tests A/B crossplacement avec la même audience partagent le même placement, Adapty attribue automatiquement la priorité des tests selon l'ordre dans lequel ils ont été ajoutés. Le premier test obtient la priorité la plus élevée. Vous ne pouvez pas la modifier manuellement.

* Les tests ciblant des segments plus restreints de votre audience sont automatiquement prioritaires sur ceux ciblant le segment Tous les utilisateurs.

:::note
Dans Analytics, un test A/B Crossplacement apparaît sous la forme de plusieurs tests enfants, un par placement. Les tests enfants suivent le schéma de nommage `<test-name> child-0`, `<test-name> child-1`, et ainsi de suite. La numérotation correspond à l'ordre des placements sur la page de détails du test A/B. Pour afficher les résultats d'un placement spécifique, filtrez par **Placement**.
:::
