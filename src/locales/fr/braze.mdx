En tant que l'une des meilleures solutions d'engagement client, [Braze](https://www.braze.com/) propose une large gamme d'outils pour les notifications push, les e-mails, les SMS et la messagerie in-app. En intégrant Adapty avec Braze, vous pouvez facilement accéder à tous vos événements d'abonnement en un seul endroit, ce qui vous permet de déclencher des communications automatisées basées sur ces événements.

Adapty fournit un ensemble complet de données qui vous permet de suivre les [événements d'abonnement](events) de tous les stores en un seul endroit et peut être utilisé pour mettre à jour les profils de vos utilisateurs dans Braze. Avec Adapty, vous pouvez facilement observer le comportement de vos abonnés, comprendre ce qu'ils apprécient et utiliser ces informations pour communiquer avec eux de manière ciblée et efficace. Cette intégration vous permet ainsi de suivre les événements d'abonnement dans votre tableau de bord Braze et de les associer à vos [campagnes d'acquisition.](https://www.braze.com/product/journey-orchestration)

Adapty envoie les événements d'abonnement, les propriétés utilisateur et les achats à Braze, ce qui vous permet de créer des communications ciblées avec vos clients via les notifications push Braze après une intégration simple et rapide, comme décrit ci-dessous.

## Comment configurer l'intégration Braze \{#how-to-set-up-braze-integration\}

Pour connecter Adapty à Braze, ouvrez [**Integrations** → **Braze**](https://app.adapty.io/integrations/braze) dans l'Adapty Dashboard, activez le bouton bascule et renseignez les identifiants :

- **REST API key** et **Braze Instance ID** sont obligatoires.
- **iOS App ID** et **Android App ID** sont facultatifs.

1. Pour créer la **clé API REST**, dans le tableau de bord Braze, allez dans **Settings** → **APIs and Identifiers** et cliquez sur **Create API Key**. Dans les permissions de données utilisateur, sélectionnez `users.track`. Braze ne permet pas de modifier les permissions d'une clé après sa création, donc une clé sans `users.track` doit être remplacée par une nouvelle. Pour plus de détails, consultez [Creating REST API keys](https://www.braze.com/docs/api/basics#creating-rest-api-keys) dans la documentation Braze.
2. Pour trouver l'**ID d'instance Braze**, comparez l'URL de votre tableau de bord Braze avec le [tableau des instances](https://www.braze.com/docs/api/basics/#endpoints) dans la documentation Braze. L'ID d'instance a un format régional, tel que `US-03` ou `EU-01`. Par exemple, `dashboard-03.braze.com` correspond à `US-03`.
3. Pour trouver l'**ID d'application iOS** et l'**ID d'application Android**, dans le tableau de bord Braze, allez dans **Settings** → **APIs and Identifiers** → **App Identifiers**. Copiez la valeur dans la colonne **Identifier** pour chaque application. Pour plus de détails, consultez [App identifier](https://www.braze.com/docs/api/identifier_types#app-identifier) dans la documentation Braze.

## Événements, attributs utilisateur et achats \{#events-user-attributes-and-purchases\}

Sous les identifiants, vous trouverez trois groupes d'événements que vous pouvez envoyer à Braze depuis Adapty. Activez simplement ceux dont vous avez besoin. Vous pouvez également modifier les noms des événements selon vos besoins avant de les envoyer à Braze. Consultez la liste complète des événements proposés par Adapty [ici](events) :

Adapty enverra les événements d'abonnement et les attributs utilisateur à Braze via une intégration serveur à serveur, vous permettant de les consulter dans votre Braze Dashboard et de configurer des campagnes en conséquence.

Pour les événements comportant des revenus, tels que les conversions d'essai et les renouvellements, Adapty enverra ces informations à Braze sous forme d'achats.

:::warning
Adapty envoie les revenus à Braze uniquement sous forme d'événements d'achat legacy. Braze a placé les événements d'achat legacy en mode maintenance et ne les active pas pour les nouveaux clients. Si votre espace de travail Braze ne les accepte pas, Braze rejette chaque événement comportant des revenus avec un HTTP 400 et le message `Legacy purchase ingestion is disabled`. Ces événements, tels que les premiers achats, les renouvellements, les conversions d'essai et les remboursements, n'arrivent pas du tout dans Braze, pas seulement leurs revenus.

Avant d'activer l'intégration, assurez-vous que votre espace de travail Braze accepte les événements d'achat legacy. Pour plus de détails, consultez [Purchase events](https://www.braze.com/docs/user_guide/data/activation/events/purchase_events) dans la documentation Braze.
:::

[Ici](messaging#event-properties) vous trouverez les spécifications complètes des propriétés d'événements envoyées à Braze.

:::note
Attributs utilisateur utiles

Par défaut, Adapty envoie certains attributs utilisateur pour l'intégration Braze. Consultez la liste ci-dessous pour déterminer lesquels correspondent le mieux à vos besoins.
:::

| Attribut utilisateur | Type | Valeur |
|--------------|----|-----|
| `adapty_customer_user_id` | String | Contient la valeur de l'identifiant unique de l'utilisateur défini par le client. Peut être trouvé dans le [Dashboard](profiles-crm) Adapty et dans Braze. |
| `adapty_profile_id` | String | Contient la valeur de l'identifiant unique Adapty User Profile ID de l'utilisateur, qui peut être trouvé dans le [Dashboard](profiles-crm) Adapty. |
| `environment` | String | <p>Indique si l'utilisateur opère dans un environnement sandbox ou de production.</p><p></p><p>Les valeurs sont soit `Sandbox` soit `Production`</p> |
| `store` | String | <p>Contient le nom du Store utilisé pour effectuer l'achat.</p><p></p><p>Valeurs possibles :</p><p>`app_store` ou `play_store`.</p> |
| `vendor_product_id` | String | <p>Contient la valeur de l'ID produit dans le store Apple/Google.</p><p></p><p>ex. : org.locals.12345</p> |
| `subscription_expires_at` | String | <p>Contient la date d'expiration du dernier abonnement.</p><p></p><p>Le format de la valeur est :</p><p>YYYY-MM-DDTHH:mm:ss.SSS+TZ</p><p>ex. : 2023-02-15T17:22:03.000+0000</p> |
| `active_subscription` | String | La valeur sera définie sur `true` lors de tout événement d'achat ou de renouvellement, ou sur `false` si l'abonnement est expiré. |
| `period_type` | String | <p>Indique le dernier type de période pour l'achat ou le renouvellement.</p><p></p><p>Les valeurs possibles sont</p><p>`trial` pour une période d'essai ou `normal` pour le reste.</p> |

Toutes les valeurs float seront arrondies en int. Les chaînes de caractères restent inchangées.

En plus de la liste prédéfinie de tags disponibles, il est possible d'envoyer des [attributs personnalisés](segments#custom-attributes) via des tags. Cela offre plus de flexibilité sur le type de données pouvant être incluses dans le tag et peut être utile pour suivre des informations spécifiques liées à un produit ou un service. Tous les attributs utilisateur personnalisés sont envoyés automatiquement à Braze si l'utilisateur coche la case **Send user attributes** depuis [la page d'intégration](https://app.adapty.io/integrations/braze).

## Configuration du SDK \{#sdk-configuration\}

Pour lier les profils utilisateurs dans Adapty et Braze, vous devez soit configurer le SDK Braze avec le même identifiant utilisateur client qu'Adapty, soit utiliser sa méthode `.changeUser()` :

<Tabs groupId="current-os" queryString>
<TabItem value="swift" label="iOS (Swift)" default>
```swift showLineNumbers
let braze = Braze(configuration: configuration)
braze.changeUser(userId: "adapty_customer_user_id")
```
</TabItem>
<TabItem value="kotlin" label="Android (Kotlin)" default>
```kotlin showLineNumbers
Braze.getInstance(context).changeUser("adapty_customer_user_id")
```
</TabItem>
</Tabs>
