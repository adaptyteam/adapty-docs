Le [skill growth-advisor](export-analytics-with-ai) peut analyser votre application chaque semaine : vérifier si le chiffre d'affaires est au niveau habituel et si un test A/B en cours est prêt à être tranché. La vérification s'exécute comme une tâche planifiée dans votre agent IA. À chaque exécution, il lit vos données Adapty et signale ce qui a changé, soit dans votre agent, soit dans un endroit que votre équipe consulte déjà, comme un canal Slack. Une exécution ne modifie rien dans votre compte tant que vous n'avez pas répondu à son rapport.

:::note
Une vérification est une tâche dans le planificateur de votre agent IA, et non un paramètre dans Adapty. Elle s'exécute uniquement lorsque votre agent peut exécuter des tâches planifiées, par exemple lorsque votre ordinateur est allumé, ou dans le cloud si votre agent le prend en charge.
:::

## Vérifications que vous pouvez planifier \{#checks-you-can-schedule\}

| Vérification | Planning par défaut | Ce que dit le rapport |
|---|---|---|
| **Santé de votre application** | Chaque lundi à 9h00 | Comment les 7 derniers jours se comparent à une semaine normale : revenus, nouveaux abonnements payants, nouveaux essais, installations et remboursements, avec un verdict en tête. Il liste aussi tout ce qui est en attente dans votre [backlog](autopilot), comme un test terminé sans résultat. Une vérification mensuelle compare les 28 derniers jours aux 28 précédents. |
| **Un test A/B** | Chaque lundi et jeudi à 9h00 | Si le test est **Pas encore prêt**, **Prêt à décider**, ou si **Quelque chose a changé** depuis la mise en place de la vérification, comme une variante, un poids ou son audience. Pour chaque variante, à quelle distance elle se trouve d'environ 200 achats. Un leader n'est désigné qu'une fois qu'il s'est stabilisé. |
| **Tous les tests A/B en cours** | Chaque lundi à 9h00 | Un bloc par test A/B de paywall ou de flow actif, ceux prêts à décider en premier : son placement, le nombre de jours écoulés, les achats de chaque variante, et si un leader s'est dégagé. |

Vous choisissez le planning. Les valeurs par défaut sont celles que le skill suggère quand vous ne précisez rien.

Une vérification d'un test A/B se termine avec le test. Une fois le test arrêté et son hypothèse validée, le rapport indique que la vérification n'a plus rien à faire et nomme la tâche à supprimer.

## Configurer une vérification \{#set-up-a-check\}

Pour configurer une vérification, demandez à votre agent, par exemple :

```
Check my app every Monday and tell me if something is off.

Tell me when my onboarding A/B test is ready to decide.

Send a weekly report on my running A/B tests to the #growth channel in Slack.
```

Le skill propose également une vérification de sa propre initiative : après un [bilan de santé](export-analytics-with-ai#health-check), et après avoir lié un test A/B actif à son hypothèse. Si une vérification pour la même application existe déjà et que votre agent peut lister ses tâches, le skill propose de modifier cette vérification plutôt que d'en ajouter une deuxième.

Avant de créer la tâche, le skill pose deux questions :

1. **La fréquence** : conservez le planning par défaut ou définissez le vôtre.
2. **Où envoyer les rapports** : par défaut, un rapport s'affiche là où votre agent indique une exécution planifiée, comme son chat ou ses notifications. Pour publier les rapports ailleurs, connectez un outil capable d'envoyer un message ou d'écrire une page — Slack, e-mail, Teams, Notion ou Linear — dans les paramètres de connecteur ou MCP de votre agent. Indiquez ensuite le canal, l'adresse ou la page exact(e). Le skill ne fait jamais ce choix à votre place.

Le skill crée alors la tâche avec l'outil de planification de votre agent et la nomme d'après la vérification, par exemple `Adapty: health for Snapshot` ou `Adapty: tests for Snapshot`.

### Où s'exécute la vérification \{#where-the-check-runs\}

- **Sur votre ordinateur** : La vérification utilise votre connexion Adapty et vos connecteurs sur cet ordinateur.
- **Sur une autre machine ou dans le cloud** : Définissez la variable d'environnement `ADAPTY_TOKEN` avec votre [token CLI Adapty](developer-cli-authentication), et connectez-y aussi l'outil de reporting. Le skill ne place jamais de token dans le prompt de la tâche.

Si une exécution ne peut pas accéder à votre compte Adapty, son rapport complet se résume à une ligne vous demandant de vous reconnecter sur cet ordinateur ou de définir `ADAPTY_TOKEN` là où s'exécute la vérification.

### Si votre agent n'a pas de planificateur \{#if-your-agent-has-no-scheduler\}

Le skill vous donne l'invite de la vérification à enregistrer sous forme de fichier, ainsi qu'une ligne pour le planificateur de votre système, comme cron. Cette ligne exécute votre agent en mode non interactif avec cette invite et ajoute chaque rapport à un fichier de votre choix. Pour Claude Code, la ligne ressemble à ceci :

```bash
0 9 * * 1 cd ~/my-app && claude -p "$(cat adapty-weekly-health.txt)" --allowedTools "Bash" >> ~/adapty-checks.md
```

D'autres agents disposent de leur propre mode non interactif, comme `codex exec` ou `gemini -p`. L'exécution nécessite la permission de lancer des commandes shell sans demande de confirmation, et chaque agent nomme cette permission différemment : consultez la documentation de votre agent.

## Agir sur un rapport \{#act-on-a-report\}

Une exécution se contente de lire. Elle ne suggère aucune nouvelle hypothèse et ne modifie rien tant que vous ne répondez pas. Chaque action que l'agent peut effectuer pour vous figure dans **Prochaines étapes** sous forme de question à laquelle vous pouvez répondre par oui, par exemple « Arrêter le test et conserver Annual 2 ? ». Les étapes que seul vous pouvez effectuer commencent par « Vous : ».

Pour agir sur un rapport, répondez-y dans votre agent : dans le chat de l'exécution planifiée elle-même, ou en collant le rapport dans un nouveau chat. Un rapport publié sur Slack ou par e-mail ne peut pas recevoir de réponse à cet endroit, aussi sa dernière ligne indique où répondre.

Une fois que vous avez répondu, l'agent fonctionne comme dans n'importe quelle conversation avec le skill. Il relit d'abord le test et le placement, car le rapport peut dater de plusieurs jours. Chaque modification attend votre confirmation : arrêter un test, marquer une hypothèse comme gagnante, perdante ou non concluante, ou associer un nouveau test.

## Modifier ou arrêter une vérification \{#change-or-stop-a-check\}

Pour modifier la fréquence d'une vérification ou la destination de ses rapports, demandez à l'agent qui l'a configurée. Pour arrêter une vérification, supprimez la tâche correspondante dans le planificateur de votre agent, ou retirez la ligne cron.
