Pour mettre à jour votre application depuis Adapty Android SDK 4.1, 4.2, ou 4.3 vers la version 4.4, définissez la version `adapty-bom` sur `4.4.0` et remplacez le fichier de secours dans le même build. Les versions 4.1 à 4.3 du SDK rejettent le nouveau fichier. Si votre code Java appelle `AdaptyFlowView.showFlow`, ajoutez un argument à chaque appel. Une application sur la version 4.0 doit d'abord appliquer les [modifications v4.1](migration-to-android-sdk-41).

:::warning
Le format du fichier de secours a changé dans la version 4.4, et le compilateur ne peut pas détecter un fichier obsolète. Sans un [nouveau fichier de secours](#replace-the-fallback-file), chaque placement perd son paywall de secours.
:::

## Remplacer le fichier de secours

Pour télécharger à nouveau le [fichier de secours](fallback-flows), dans **[Placements](https://app.adapty.io/placements)**, cliquez sur **Fallbacks** > **Download Android Fallback**. Dans la ligne **Adapty SDK v4.4.0 and higher**, cliquez sur **Download**. Intégrez le fichier dans votre application.

Le fichier téléchargé s'appelle `android_4_4_0_fallback.json`. Donnez-lui le nom du fichier chargé par votre application, ou mettez à jour le nom dans l'appel qui le charge :

- **`FileLocation.fromAsset`** : le nom du fichier, par exemple `android_fallback.json`.
- **`FileLocation.fromResId`** : le nom de la ressource, par exemple `android_fallback` dans `R.raw.android_fallback`.

Avec un fichier obsolète, `Adapty.setFallback` passe une `AdaptyError` à son callback, avec le message « The fallback file version is not correct. Download a new one from the Adapty Dashboard. » Pour vérifier le nouveau fichier, lancez l'application et assurez-vous que ce callback ne reçoit aucune erreur. Le callback est optionnel. Sans lui, définissez la propriété [`Adapty.logLevel`](sdk-installation-android#logging) sur `AdaptyLogLevel.ERROR` ou un niveau plus détaillé. Vérifiez ensuite que Logcat n'affiche pas cette erreur.

## Ajouter un argument aux appels showFlow en Java \{#add-an-argument-to-showflow-calls-in-java\}

Dans la version 4.4, `AdaptyFlowView.showFlow` dispose d'un nouveau dernier paramètre, `customElementsResolver`. Le code Java doit passer tous les paramètres de `showFlow`, donc un appel avec huit arguments ne compile pas. Passez `null` comme dernier argument :

```diff showLineNumbers
  flowView.showFlow(flowConfiguration, products, eventListener, insets,
-         customAssets, tagResolver, timerResolver, observerModeHandler);
+         customAssets, tagResolver, timerResolver, observerModeHandler, null);
```

Kotlin calls to `showFlow` and all calls to `AdaptyUI.getFlowView` compile without changes.
