Si votre paywall actuel a été créé dans le Paywall Builder legacy, vous pouvez le convertir en flow. En un seul clic, l'action **Move to new builder** recrée votre paywall sous forme de draft flow modifiable.

La conversion copie :

- **Mise en page et design** : les écrans, les éléments et le style du paywall d'origine.
- **Texte** : tous les textes, dans chaque langue que vous avez ajoutée.
- **Produits** : chaque produit, avec les prix et les remises sous forme de variables plutôt que de valeurs codées en dur.

Le paywall d'origine reste actif et inchangé, ce qui vous permet de personnaliser et de tester le flow avant de faire la bascule. Ce que la conversion ne transfère pas, c'est le placement du paywall : un flow est un type de contenu différent, il a donc besoin de son propre [placement de flow](#serve-your-flow).

:::warning
Certaines fonctionnalités de l'ancien Paywall Builder n'ont pas d'équivalent dans les flows, donc un paywall converti peut ne pas correspondre exactement à l'original. Le panneau [Révision de l'import](#import-review) vous guide à travers chaque différence et explique comment la corriger.
:::

## Convertir votre paywall \{#convert-your-paywall\}

Pour convertir un paywall en flow, ouvrez la page de présentation du paywall et cliquez sur **Move to new builder**. Ce bouton n'apparaît que pour les paywalls créés dans le Paywall Builder pour le SDK Adapty 3.x — le convertisseur a besoin de la configuration de ce builder. Pour convertir un paywall plus ancien, commencez par le migrer vers le Paywall Builder SDK 3.x.

<ZoomImage id="move-to-new-builder.webp" width="700px" alt="Bouton Move to new builder dans la barre d'actions du paywall" />

Adapty ouvre le brouillon du flow dans l'éditeur, où vous pouvez le modifier avant de le publier. Si quelque chose ne s'est pas transféré exactement, le builder lance une [Révision d'import](#import-review).

<ZoomImage id="paywall-imported-toast.webp" width="500px" alt="Paywall imported toast in the flow editor after conversion" />

## Vérification de l'import \{#import-review\}

Le panneau **Import review** liste tout ce que la conversion n'a pas pu reproduire, et propose une correction pour chaque écart.

<ZoomImage id="import-review.webp" width="500px" alt="Panneau Import review listant ce que la conversion n'a pas pu reproduire exactement, avec une case à cocher pour chaque élément" />

Parcourez le panneau, puis [prévisualisez le flow sur un vrai appareil](migrate-to-flows#preview-on-device) avant de publier.

## Diffuser votre flow \{#serve-your-flow\}

:::link
Article principal : [Migrer vers les flows](migrate-to-flows)
:::

Un flow converti démarre en tant que brouillon et ne remplace pas le placement sur lequel le paywall d'origine est diffusé. Pour le proposer à vos utilisateurs :

1. [Publiez le flow](builder-save-publish).
2. Créez un nouveau placement de flow et ajoutez-y le flow.
3. Récupérez ce placement de flow dans votre application avec le SDK Adapty v4.

:::warning
Le flow ne peut pas être placé sur le placement d'un paywall, et il ne peut pas non plus utiliser l'ID de placement d'un paywall. Les flows et les paywalls sont des types de contenu différents, chacun vivant sur son propre type de placement, et le type d'un placement est fixé au moment de sa création. Les ID de placement sont uniques dans toute votre application, donc le nouveau placement de flow doit avoir un ID qu'aucun autre placement n'utilise — y compris le paywall que ce flow remplace. Voir [Créer un nouveau placement pour votre flow](migrate-to-flows#create-a-new-placement-for-your-flow).
:::

Conservez le placement du paywall actif tant que les anciennes versions de l'application l'appellent encore — ces utilisateurs ont son identifiant compilé dans l'application et ne peuvent pas accéder au flow avant de mettre à jour.

## Convertir plusieurs paywalls à la fois \{#convert-many-paywalls-at-once\}

**Move to new builder** convertit un seul paywall à la fois, et chaque flow produit nécessite toujours son propre placement. Quand vous migrez une application entière plutôt qu'un seul paywall, la [compétence agent migrate-placements](migrate-placements-skill) liste tous les placements de paywalls de votre application, les regroupe par paywall associé pour que vous sachiez combien de conversions vous attendent, vous indique quels paywalls ont déjà un flow, et crée les nouveaux placements de flows une fois les flows publiés.

Le clic de conversion vous appartient. Il n'existe pas de commande CLI pour **Move to new builder**, et le panneau [Import review](#import-review) est à vous de parcourir — la compétence attend, puis relit votre compte et trouve les flows que la conversion a produits.
