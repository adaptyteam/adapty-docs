Le fil d'événements vous permet de suivre visuellement les [événements](events) générés par Adapty et de vérifier le statut de leur export vers des intégrations tierces, y compris le webhook.

<ZoomImage id="event-status.webp" width="700px" alt="Fil d'événements affichant le statut de livraison de chaque événement" />

:::note
Le statut d'envoi pour AppsFlyer, Facebook Ads et Branch peut être inexact, car ces plateformes ne retournent pas toujours les erreurs quand elles se produisent.
:::

Pour consulter le profil de l'utilisateur qui a initié la transaction, cliquez sur le bouton **View Profile** dans les détails de l'événement.

## Un événement est absent du fil \{#an-event-is-missing-from-the-feed\}

Trois raisons peuvent expliquer l'absence d'un événement dans le fil.

- **Adapty ne l'a jamais créé.** Pour la plupart des événements, désactiver un type pour une intégration crée quand même l'événement — mais avec le [statut gris](event-statuses). Il existe cependant deux exceptions :

1. Adapty ne crée pas d'événement `access_level_updated` sauf si l'[intégration webhook](webhook) est configurée et activée.
   2. Adapty ne crée pas d'[événements synthétiques](events#synthetic-events) sauf si l'essai ou l'abonnement est toujours en cours au moment de la vérification par Adapty. Voir [Un événement synthétique n'est jamais arrivé](handle-integration-errors#a-synthetic-event-never-arrived).

- **L'événement existe, mais le flux ne l'affiche pas.** Les transactions de l'API server-side v1 n'apparaissent jamais — utilisez l'[API server-side (version 2)](api-adapty/operations/setTransaction) à la place. Il en va de même pour les événements sans profil : les transactions reçues avant que le SDK n'ait identifié un utilisateur, comme les notifications serveur du store. Pour les inclure dans les exports, activez **Include events without profile** dans l'intégration [S3](s3-exports) ou [Google Cloud Storage](google-cloud-storage). Les renouvellements horodatés à l'avance par Apple n'apparaissent pas non plus — ils [s'affichent une fois l'horodatage dépassé](how-profiles-work), même si Adapty les transmet immédiatement à vos intégrations.

- **L'événement a plus de deux semaines.** Le flux ne conserve les événements que pendant deux semaines. Un [événement synthétique](events#synthetic-events) avec un long délai peut donc apparaître sans l'événement `trial_started` ou `subscription_started` qui a lancé son minuteur.
