Grâce aux éléments personnalisés du Flow & Paywall Builder, vous pouvez ajouter une vue native à un écran de flow. Il peut s'agir d'une animation Lottie / Rive, d'un graphique interactif, d'une carte, d'un aperçu caméra — ou de n'importe quelle autre vue que votre application peut afficher. Les utilisateurs ne voient la vue native que dans les applications utilisant le SDK Adapty v4.4+.

<DocVideo id="custom-elements-examples.mp4" alt="Trois écrans de flow avec des vues natives : un anneau Lottie qui se remplit jusqu'à 4 jours sur 7, un graphique de poids que l'utilisateur fait glisser, et une carte des centres de fitness à proximité." />

Pour afficher une vue native sur un écran de flow :

1. [Ajoutez un élément personnalisé](#add-and-configure) à l'écran et renseignez son **Type** et son **ID**.
2. [Ajoutez du contenu de secours](#set-fallback-content) à l'intérieur de l'élément personnalisé. Les utilisateurs le voient si votre app n'affiche pas la vue.
3. [Configurez la vue native dans votre app](#set-up-your-app-code). Utilisez le SDK Adapty pour lui attribuer le même Type et le même ID.
4. [Publiez le flow](#publish-and-test) et testez-le sur un appareil.
5. [Publiez la mise à jour de l'app avec la vue native](#what-changes-require-an-app-release). Les utilisateurs des versions de l'app sans la vue native voient le contenu de secours.

:::tip
Pour afficher une image ou une vidéo animée, utilisez plutôt un élément [**Image**](custom-media#image) ou [**Vidéo**](custom-media#video) à la place d'un élément personnalisé. Aucun des deux ne nécessite de code dans votre application, et vous pouvez remplacer le fichier sans publier de mise à jour.
:::

## 1. Ajouter un élément personnalisé à l'écran \{#add-and-configure\}

1. Ouvrez le panneau **Add element**. Dans le groupe **Media**, cliquez sur **Custom element**.

   <ZoomImage id="flow-custom-element-card.webp" width="200px" alt="Élément personnalisé dans le groupe Media du panneau Add element" />

2. Si la vue native réagit au toucher, ne placez pas l'élément personnalisé dans des conteneurs qui réagissent également au toucher, comme un carrousel. Ainsi, un glissement dans la vue native ne fera pas défiler le carrousel.
3. Dans le champ **Type**, saisissez un Type pour le type de vue native, par exemple `lottie_animation` :
   - **Règles de nommage** : Utilisez uniquement des lettres minuscules, des chiffres et des underscores.
   - **Correspondance exacte** : Le Type doit correspondre exactement à celui de votre application, lettre pour lettre. Toute autre orthographe affichera le fallback aux utilisateurs.
   - **Suggestions** : Le champ suggère les Types déjà utilisés dans ce flow, pas ceux de votre application.
4. Dans le champ **ID**, remplacez la valeur préremplie, par exemple `custom_1`, par un ID de votre choix, comme `welcome_wave`. L'ID permet de distinguer les éléments personnalisés du même Type.

   <ZoomImage id="flow-custom-element-type-id.webp" width="500px" alt="Champs Type et ID dans la section Element des paramètres de l'élément personnalisé" />

5. Pour réserver un espace fixe à la vue native, conservez la hauteur **Fixed** par défaut et définissez-la selon les besoins de la vue.
   - **Shared area** : La vue native et le contenu de secours partagent le même espace.
   - **Alignment** : Si la vue native est plus petite que cet espace, elle apparaît par défaut dans le coin supérieur gauche. Pour la déplacer, modifiez l'alignement dans la section **Layout** de l'élément personnalisé.

   :::important
   Avec une hauteur **Hug**, une vue native sans hauteur propre, comme une carte ou une liste défilante, se réduit à une hauteur quasi nulle.
   :::

6. (Optionnel) Pour rogner la vue native selon les **Corners** arrondis de l'élément personnalisé, dans la section **Layout**, cochez la case **Clip content**.

### Utiliser des vues natives dans plusieurs éléments personnalisés \{#use-native-views-in-several-custom-elements\}

Les règles suivantes s'appliquent au Type et à l'ID des éléments personnalisés :

- **Type** : saisissez un Type par type de vue native, par exemple `lottie_animation` pour un lecteur Lottie et `map` pour une carte.
- **ID** : pour un même Type, attribuez un ID unique à chaque contenu, par exemple `streak_ring` et `welcome_wave` pour deux animations Lottie. Votre application lit l'ID pour choisir le contenu. Si deux éléments personnalisés sur un même écran ont le même Type et le même ID, le champ **ID** affiche un avertissement : *Same type and ID as another element on this screen.* Vous pouvez tout de même publier le flow.
- **Copies d'éléments** : lorsque vous dupliquez ou collez un élément, ou que vous ajoutez un [onglet](builder-tabs), le builder renomme chaque ID copié déjà utilisé dans l'écran ou le composant. Par exemple, `custom_1` devient `custom_2`, et `hero` devient `hero_2`. Vérifiez que le code de votre application référence bien l'ID correct.

## 2. Ajouter un contenu de secours \{#set-fallback-content\}

Les utilisateurs voient le contenu de secours à la place de la vue native dans les cas suivants :

- La version de leur application ne contient pas le code de la vue.
- Votre application utilise une version du SDK Adapty antérieure à 4.4.
- Le Type et l'ID de l'élément personnalisé ne correspondent à aucune vue dans le code de votre application.
- Le code de votre application correspond au Type et à l'ID, mais ne renvoie aucune vue. Par exemple, la vue nécessite un fichier absent de l'appareil, ou une permission que l'utilisateur a refusée.

Pour définir le contenu de secours, ajoutez des éléments au conteneur d'éléments personnalisés. Lorsque la vue native n'apparaît pas, un élément personnalisé sans contenu de secours reste vide.

Le Flow & Paywall Builder ne peut pas exécuter le code de votre application, donc son canevas affiche uniquement le contenu de secours. L'[aperçu dans l'application mobile Adapty](paywall-device-compatibility-preview#preview-on-devices) affiche également le contenu de secours. Pour prévisualiser la vue native, [testez le flow sur un appareil](#publish-and-test) dans une version de votre application.

<ZoomImage id="flow-custom-element-placeholder.webp" width="400px" alt="Élément personnalisé vide sur le canevas avec le texte Add elements here comme fallback" />

:::important
Gardez les boutons de navigation, les boutons d'achat et les autres éléments essentiels de l'interface en dehors de l'élément personnalisé. Les utilisateurs voient soit la vue native, soit le fallback, jamais les deux.
:::

Vous ne pouvez pas ajouter de **Footer**, de **Sliding sheet** ni de **Bottom Sheet** à l'intérieur d'un élément personnalisé.

## 3. Configurer la vue native dans votre application \{#set-up-your-app-code\}

Lorsqu'un écran avec un élément personnalisé s'ouvre, le SDK Adapty transmet le Type et l'ID de l'élément à une fonction de résolution dans le code de votre application. La fonction de résolution renvoie l'un des éléments suivants :

- **La vue correspondant au Type et à l'ID** : les utilisateurs voient la vue native. Dans le code, saisissez le Type et l'ID exactement comme dans le builder.
- **Aucune vue** : les utilisateurs voient le fallback. Par exemple, ne renvoyez aucune vue si le fichier nécessaire à la vue n'est pas présent sur l'appareil.

Pour prendre en charge les éléments personnalisés dans votre application, suivez les guides spécifiques à chaque plateforme : [iOS](ios-flow-custom-elements), [Android](android-flow-custom-elements), [React Native](react-native-flow-custom-elements), [Flutter](flutter-flow-custom-elements) et [Capacitor](capacitor-flow-custom-elements).

:::tip
Une vue native peut visualiser les données utilisateur, comme les réponses d'un flow précédent. Voir <InlineTooltip tooltip="Afficher un graphique d'objectif de poids interactif dans un paywall">[iOS](custom-element-interactive-chart), [Android](android-custom-element-interactive-chart), [React Native](react-native-custom-element-interactive-chart), [Flutter](flutter-custom-element-interactive-chart), [Capacitor](capacitor-custom-element-interactive-chart)</InlineTooltip>.
:::

## 4. Publier et tester le flow \{#publish-and-test\}

Pour [publier le flow](builder-save-publish), assurez-vous que chaque élément personnalisé possède un Type qui respecte les [règles de nommage](#add-and-configure). Vous pouvez publier le flow avant de déployer l'application. Tant que les utilisateurs n'ont pas mis à jour l'application, ils voient le paywall de secours.

Une erreur dans la vue native peut faire planter l'application. Avant de publier l'application, testez chaque écran contenant un élément personnalisé dans un build avec la vue native. Pour tester un flow que les vrais utilisateurs ne voient pas encore, ajoutez-le à un [placement](create-placement) que ce build sollicite mais que votre application publiée ne sollicite pas. Pour voir le dernier flow publié plutôt qu'une version en cache, enregistrez l'appareil comme [appareil de test](test-devices). Pour la procédure complète, suivez les guides spécifiques à chaque plateforme : [iOS](ios-flow-custom-elements#test-on-a-device), [Android](android-flow-custom-elements#test-on-a-device), [React Native](react-native-flow-custom-elements#test-on-a-device), [Flutter](flutter-flow-custom-elements#test-on-a-device) et [Capacitor](capacitor-flow-custom-elements#test-on-a-device).

## Quelles modifications nécessitent une mise à jour de l'application \{#what-changes-require-an-app-release\}

Les vues natives font partie du code de votre application. Pour modifier une vue native, publiez une mise à jour de l'application. Pour modifier le contenu de secours ou tout paramètre d'un élément personnalisé, à l'exception de son Type et de son ID, publiez le flow.

| Contenu modifié | Ce que vous faites | Ce que voient les utilisateurs n'ayant pas mis à jour l'app |
|---|---|---|
| La vue native d'un élément personnalisé existant, par exemple une animation différente | Publiez une mise à jour de l'app avec la nouvelle vue native | La vue native précédente, si leur version de l'app la contient |
| Une vue native pour un nouvel élément personnalisé | Publiez une mise à jour de l'app avec la nouvelle vue native. Ajoutez un élément personnalisé avec le nouveau Type et ID, et publiez le flow | Le contenu de secours |
| Une vue native existante sur un autre écran, dans un autre flow ou dans un test A/B | Ajoutez un élément personnalisé avec le même Type et ID, et publiez le flow. Aucune mise à jour de l'app nécessaire si votre <InlineTooltip tooltip="app-wide resolver">[iOS](ios-flow-custom-elements#set-an-app-wide-resolver), [Android](android-flow-custom-elements#display-views-in-every-flow), [React Native](react-native-flow-custom-elements#pass-the-resolver-to-the-sdk), [Flutter](flutter-flow-custom-elements#pass-the-resolver-to-the-sdk), [Capacitor](capacitor-flow-custom-elements#pass-the-resolver-to-the-sdk)</InlineTooltip> renvoie la vue | La vue native, si leur version de l'app la contient |
| Le Type ou l'ID d'un élément personnalisé | Publiez une mise à jour de l'app avec une vue native pour le nouveau Type et ID, et publiez le flow | Le contenu de secours |
| Le contenu de secours ou d'autres paramètres d'un élément personnalisé | Publiez le flow. Aucune mise à jour de l'app nécessaire | Le contenu mis à jour |

## Dépannage \{#troubleshooting\}

- **Les utilisateurs voient le paywall de secours au lieu de la vue native** : Vérifiez que le Type et l'ID correspondent exactement à ceux de votre application, lettre pour lettre. Les utilisateurs des versions de l'application sans la vue voient le paywall de secours jusqu'à ce qu'ils mettent l'application à jour. Pour identifier la cause dans le code, suivez les guides spécifiques à chaque plateforme : [iOS](ios-flow-custom-elements#test-on-a-device), [Android](android-flow-custom-elements#test-on-a-device), [React Native](react-native-flow-custom-elements#test-on-a-device), [Flutter](flutter-flow-custom-elements#test-on-a-device) et [Capacitor](capacitor-flow-custom-elements#test-on-a-device).
- **Les utilisateurs voient une zone vide** : [Ajoutez un contenu de secours](#set-fallback-content) et publiez le flow. Si vous voyez toujours une zone vide sur un [appareil de test](test-devices), la vue native s'affiche sans son contenu. Assurez-vous que le resolver ne renvoie aucune vue lorsque le contenu est manquant, comme dans <InlineTooltip tooltip="Définir les conditions du contenu de secours">[iOS](ios-flow-custom-elements#set-conditions-for-fallback-content), [Android](android-flow-custom-elements#set-conditions-for-fallback-content), [React Native](react-native-flow-custom-elements#set-conditions-for-fallback-content), [Flutter](flutter-flow-custom-elements#set-conditions-for-fallback-content), [Capacitor](capacitor-flow-custom-elements#set-conditions-for-fallback-content)</InlineTooltip>.
- **La vue native ne s'adapte pas à l'élément personnalisé** : Vérifiez que votre application adapte la vue à la zone de l'élément personnalisé. Pour rogner la vue sur les **Corners** arrondis, dans la section **Layout**, cochez la case **Clip content**.
