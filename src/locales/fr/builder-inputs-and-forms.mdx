Utilisez les champs de saisie pour collecter des données auprès des utilisateurs — comme un nom, une adresse e-mail ou une date de naissance. Enregistrez les réponses et référencez-les ailleurs dans le flow, par exemple pour s'adresser à l'utilisateur par son nom sur un écran ultérieur.

## Ajouter une entrée \{#add-an-input\}

<ZoomImage id="add-input.webp" width="400px" float="right" alt="Ajouter une entrée" />

1. Ouvrez le panneau **Add element**.
2. Dans la catégorie **Forms & Quiz**, cliquez sur **Input**.
3. Choisissez le type de saisie :
   - **Text :** Toute saisie de texte court.
   - **E-mail :** Adresses e-mail, avec validation de format optionnelle.
   - **Password :** Saisie de texte sécurisée, avec des exigences configurables.
   - **Number :** Valeurs numériques, avec un format configurable.
   - **Phone number :** Numéros de téléphone.
   - **Date :** Ouvre un sélecteur de date.
   - **Time :** Ouvre un sélecteur d'heure.
   - **Date & Time :** Ouvre un sélecteur combiné.
   - **[Number picker](builder-number-picker) :** Vous définissez la valeur minimale et la valeur maximale d'une molette. Les utilisateurs choisissent un nombre entre les deux.

## Configurer une entrée \{#configure-an-input\}

:::link
Pour plus de détails sur les paramètres visuels — disposition, style et visibilité — voir [Styles et apparence](builder-styling).
:::

Pour tous les types d'entrée, vous pouvez configurer les éléments suivants dans l'onglet **Design** :

- **Type :** Basculez un champ texte entre Text, E-mail, Password, Number et Phone number. Basculez un sélecteur de date ou d'heure entre Date, Time et Date & Time.
- **Element ID :** Identifiant utilisé pour référencer la valeur du champ ailleurs dans le flow. Voir [Utiliser les valeurs des champs](#use-input-values) ci-dessous.
- **Placeholder :** Texte indicatif affiché dans le champ vide.
- **State :** Définissez l'apparence du champ dans différentes situations. Basculez entre **Default**, **Active**, **Invalid** et **Disabled** et appliquez des visuels différents à chacun.
- **Typography :** Style de texte pour la valeur affichée dans le champ.
- **Leading and trailing icons :** Ajoutez des icônes à l'intérieur du champ de saisie. Pour un champ Password, vous ne pouvez ajouter qu'une icône de gauche (leading icon).

Un [sélecteur de nombre](builder-number-picker) ne dispose que des paramètres **Element ID** et **Typography** de cette liste.

## Utiliser les valeurs de saisie \{#use-input-values\}

:::tip
Votre application peut aussi recevoir des valeurs de saisie. Pour les collecter, [gérez le callback analytique du SDK](ios-flow-input). Chaque fois qu'un utilisateur quitte un champ de saisie, le callback transmet la valeur saisie et votre application peut la traiter en interne.

Pour un sélecteur numérique, le callback transmet la valeur lorsque l'utilisateur appuie sur un bouton qui ouvre un autre écran. Un appui sur une option de quiz ou un basculement sur le même écran la transmet également.
:::

Chaque saisie est automatiquement disponible en tant que variable — aucune configuration ni action **On Submit** n'est requise. La valeur est référencée via l'**Element ID** de la saisie, que vous définissez dans **Input Settings** ou **Picker Settings**.

Pour utiliser une valeur saisie ailleurs dans le flow (par exemple, pour personnaliser le texte, remplir un autre champ ou gérer une navigation conditionnelle), insérez une variable et sélectionnez :

**Element > Screen > `<elementId>.value`**

:::link
Consultez les guides correspondants pour comprendre comment utiliser les valeurs d'entrée enregistrées :
- [Navigation conditionnelle](onboarding-navigation-branching)
- [Variables](onboarding-variables)
:::

## Validation des saisies \{#input-validation\}

Le comportement de validation dépend du type de saisie. Chaque saisie, à l'exception du sélecteur numérique, expose une variable booléenne en lecture seule, `<elementId>.isValid`. Elle indique si la valeur saisie respecte les règles de validation de la saisie. Utilisez-la dans des actions conditionnelles ou une visibilité conditionnelle — par exemple, pour masquer un bouton Suivant tant que le format d'un e-mail n'est pas valide.

:::note
- La variable `isValid` est en lecture seule — vous ne pouvez pas la modifier.
- Une saisie vide est toujours considérée comme valide.
- Les saisies de texte n'ont pas de règles de validation. `textInput.isValid` renvoie toujours `True`.
:::

| Type d'entrée | Comportement de validation |
|---|---|
| Texte | Aucune règle de validation intégrée. |
| E-mail | Facultatif. Activez **Validate email format** dans le panneau **Design** pour vérifier que la valeur saisie respecte le format e-mail. |
| Numéro de téléphone | Vérification intégrée du format de numéro de téléphone. Non configurable dans le Builder — la règle est évaluée à l'exécution. |
| Mot de passe | Configurable. Voir [Exigences relatives au mot de passe](#password-requirements) ci-dessous. |
| Nombre | Basé sur le format. La valeur saisie doit correspondre au format de nombre sélectionné. Voir [Format de nombre](#number-format) ci-dessous. |
| Date, Heure, Date & Heure | Intégré. Le sélecteur n'accepte que des valeurs de date ou d'heure valides. |

L'[état visuel](builder-styling#input-states) **Invalid** s'active lorsque l'utilisateur soumet le formulaire — par exemple en appuyant sur Entrée ou sur Terminé sur le clavier. Jusqu'à ce moment, le champ affiche l'état **Active** ou **Default**.

### Exigences relatives au mot de passe \{#password-requirements\}

Les champs de mot de passe prennent en charge des règles de validation configurables. Cliquez sur **Edit password requirements** dans le panneau **Design** pour ouvrir l'éditeur de règles. Les règles activées s'affichent sous forme de liste de contrôle dynamique sous le champ — chaque élément est coché dès que sa règle est satisfaite.

Règles disponibles :

- **Min length** — nombre minimum de caractères. Par défaut : 8.
- **Max length** — nombre maximum de caractères. Par défaut : 32.
- **Uppercase letter** — au moins une lettre A–Z.
- **Lowercase letter** — au moins une lettre a–z.
- **Number** — au moins un chiffre.
- **Special character** — au moins un caractère non alphanumérique (par exemple, `!@#$%`).

Le mot de passe est valide uniquement lorsque toutes les règles activées sont respectées.

### Format des nombres \{#number-format\}

Le menu déroulant **Format** dans les paramètres de saisie **Number** détermine comment la valeur saisie est interprétée :

- **Integer** — nombres entiers uniquement (par exemple, `4`).
- **Decimal (Point)** — décimaux avec un point comme séparateur (par exemple, `4.89`).
- **Decimal (Comma)** — décimaux avec une virgule comme séparateur (par exemple, `4,89`).

Les valeurs qui ne correspondent pas au format sélectionné sont considérées comme invalides.

## Déclencher des actions sur les événements de saisie \{#trigger-actions-on-input-events\}

:::link
Article principal : [Actions](onboarding-actions)
:::

Vous pouvez exécuter des actions en réponse aux saisies de l'utilisateur via le panneau **Interactions** :

- **On changed** — se déclenche lorsque l'utilisateur modifie la valeur du champ. Disponible pour tous les types de champs.
- **On submit** — se déclenche lorsque l'utilisateur valide une saisie de texte en appuyant sur Entrée ou Terminé sur le clavier. Les sélecteurs de date, d'heure et de nombre ne disposent pas de ce déclencheur.
