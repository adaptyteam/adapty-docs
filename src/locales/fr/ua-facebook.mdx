L'intégration d'Adapty Attribution avec Meta vous permet de suivre et d'optimiser les performances de vos campagnes sur Facebook, Instagram, Messenger et le réseau d'audience.

:::tip
Consultez notre [guide de configuration des publicités dans Meta Ads Manager](meta-create-campaign).
:::

## Étape 1. Connecter votre compte Facebook \{#step-1-connect-your-facebook-account\}

Pour connecter Meta Ads à Adapty Attribution, accédez à **Integrations > Meta** depuis la barre latérale gauche. Vous avez deux options :

- **Continue with Facebook** : connexion via OAuth. Utilisez cette option si vous vous connectez à Meta Ads Manager avec votre compte Facebook personnel ou professionnel.
- **Add system token** : connexion via un jeton système permanent. Utilisez cette option si votre organisation gère des comptes publicitaires via un utilisateur système Meta Business.

<Tabs>
<TabItem value="oauth" label="Continue with Facebook">

:::important
Assurez-vous que votre compte Facebook a accès aux campagnes et pixels dont vous avez besoin.
:::

1. Cliquez sur **Continue with Facebook**.

<ZoomImage id="ua-connect-meta.webp" width="700px" />

2. Connectez-vous avec votre compte Facebook et cliquez sur **Continue**.

<ZoomImage id="ua-fb-sign.webp" width="500px" />

3. Vérifiez les autorisations demandées et cliquez sur **Save**.

:::note
Meta peut déconnecter l'intégration lorsque le compte Facebook associé atteint un point de contrôle de sécurité, et les dépenses cessent alors d'apparaître dans Adapty Attribution. Pour rétablir la connexion, connectez-vous sur [facebook.com](https://www.facebook.com), complétez le point de contrôle, puis reconnectez-vous dans **Integrations > Meta**.
:::

</TabItem>
<TabItem value="system" label="Add system token">

Générez un [jeton d'accès utilisateur système](https://developers.facebook.com/documentation/ads-commerce/marketing-api/collaborative-ads/managed-partner-ads/api-guide/prerequisites/generate-access-token-system-user) dans Meta Business Settings, puis ajoutez-le à Adapty Attribution.

:::important
Avant de commencer, vous avez besoin d'un [utilisateur système](https://www.facebook.com/business/help/503306463479099) dans votre portefeuille Meta Business, avec les comptes publicitaires que vous souhaitez suivre déjà assignés. Vous devez également avoir une application ajoutée au portefeuille — vous sélectionnez cette application lors de la génération du jeton.
:::

**Dans Meta Business Settings, générez le token :**

1. Accédez à **Business Settings**.
2. Sous **Users**, sélectionnez **System users**.
3. Sélectionnez votre utilisateur système, puis cliquez sur **Generate new token**.
4. Sélectionnez votre application dans le menu déroulant.
5. Dans la liste des permissions, activez `ads_read`. C'est la seule permission dont Adapty Attribution a besoin pour lire les données de vos campagnes et annonces.
6. Cliquez sur **Generate token**.
7. Copiez le token et conservez-le en lieu sûr. Meta ne l'affiche qu'une seule fois.

:::note
Le paramètre **Token expiration** contrôle la durée d'activité de la connexion. Un token avec une date d'expiration doit être régénéré et reconnecté avant son expiration, sinon l'attribution s'arrête. Un token sans expiration évite ce problème, mais constitue un identifiant de longue durée. Conservez-le en lieu sûr et révoquez-le s'il venait à être exposé.
:::

**Dans Adapty Attribution, ajoutez le token :**

1. Cliquez sur **Add system token**.

<ZoomImage id="ua-add-meta-system-token.webp" width="700px" alt="Bouton Add system token sur la page d'intégration Meta dans Adapty Attribution" />

2. Collez le token et cliquez sur **Connect**.

<ZoomImage id="ua-connect-meta-system-token.webp" width="700px" alt="Champ de saisie du jeton système sur la page d'intégration Meta dans Adapty Attribution" />

</TabItem>
</Tabs>

Après cela, tous vos comptes publicitaires seront ajoutés à Adapty Attribution. Vous pouvez poursuivre en ajoutant des campagnes.

## Étape 2. Ajouter des campagnes \{#step-2-add-campaigns\}

Une seule campagne peut couvrir l'App Store, Google Play et votre funnel web en même temps. Deux éléments permettent d'établir la connexion :

- **Lien de suivi** : Ce lien est intégré à votre publicité. Quand un utilisateur appuie sur la publicité, Adapty enregistre le clic, redirige l'utilisateur vers la destination, puis attribue l'installation et les achats à cette publicité. Chaque destination dispose de son propre lien.
- **Pixel** : Sélectionné dans la campagne, parmi les pixels de votre compte Meta. Il renvoie les conversions à Meta, afin que Meta puisse optimiser la campagne sur la base d'achats réels. Un seul pixel peut couvrir les trois destinations, ou chaque destination peut avoir le sien.

Pour ajouter une nouvelle campagne Meta à Adapty Attribution :

1. Accédez à l'onglet **Web Campaigns** et cliquez sur **Create configuration**.

   <ZoomImage id="ua-new-campaign.webp" width="500px" />

2. Dans l'onglet **General**, développez la section **iOS** et/ou **Android** et collez les URL de l'application App Store et/ou Google Play.

   <ZoomImage id="ua-url.webp" width="900px" />

3. Copiez la valeur du champ **Click link**. Puis, dans Meta Ads Manager, ouvrez votre annonce et collez ce lien. Cela permettra à Adapty de relier les installations et les achats aux annonces dans Meta.

   <ZoomImage id="ua-lnk.webp" width="900px" />

4. Pour renvoyer les événements de conversion vers Meta, vous pouvez également associer vos pixels Meta à des campagnes dans Adapty Attribution. Pour cela, sélectionnez l'un de vos pixels existants dans le menu déroulant **Pixel**. Après avoir sélectionné un pixel, vous pouvez cliquer sur **Send test event** pour vérifier la connexion.

La section **Web funnel** fonctionne de la même façon. Les achats effectués sur un web funnel se font en dehors de votre application, donc Meta n'en est informé que via le pixel que vous sélectionnez ici. Cette même section vous fournit le snippet pour [installer le pixel sur votre funnel](ua-web-pixel) et les paramètres pour [taguer vos URLs publicitaires](ua-tag-ad-urls).

Un pixel différent par destination permet de séparer les achats iOS, Android et web pour l'optimisation et le reporting ; le même pixel partout les regroupe. La liste **Web Campaigns** affiche ce choix par configuration, sous **Pixel (iOS)**, **Pixel (Android)** et **Pixel (Web)**, avec le nom et l'identifiant du pixel. Une section sans pixel affiche un tiret, et un pixel sélectionné dans les trois sections apparaît trois fois.

## Étape 3. Mapper les événements \{#step-3-map-events\}

Pour renvoyer des événements de conversion à Meta et optimiser vos campagnes, configurez le mappage des événements dans la section **Events mapping**. Cela permet à Adapty d'envoyer automatiquement les événements d'abonnement lorsque les utilisateurs effectuent des actions dans votre application.

Dans la section **Events mapping**, activez les événements que vous souhaitez suivre dans Meta Ads Manager. Pour chaque événement activé, sélectionnez l'événement Meta correspondant dans le menu déroulant ou définissez-en un personnalisé. Par défaut, Adapty associe ses événements aux événements standard de Meta.

Cliquez sur **Save** pour appliquer la configuration de mappage des événements.

## Configuration supplémentaire \{#additional-configuration\}

### Paramètres supplémentaires \{#additional-parameters\}

Le champ **Additional parameter** vous permet d'ajouter des données personnalisées pour les analyses effectuées en dehors d'Adapty. C'est utile lorsque vous devez transmettre des informations spécifiques sur une campagne ou un utilisateur à des outils d'analyse externes ou à des partenaires d'attribution.

Dans le champ **Additional parameter**, saisissez les données personnalisées que vous souhaitez inclure dans votre suivi d'attribution. Ce paramètre supplémentaire sera intégré à toutes les données d'attribution envoyées à Meta et pourra être utilisé pour une analyse et une optimisation avancées des campagnes.

Par exemple, si vous exécutez plusieurs variations de la même campagne, vous pouvez ajouter `variant=A` ou `variant=B` pour distinguer différentes approches créatives.

:::important
Les paramètres supplémentaires modifient le **Click link** que vous collez dans Meta Ads Manager. Si vous avez déjà copié ce lien et ajouté un paramètre personnalisé ultérieurement, assurez-vous de copier et coller un lien de clic mis à jour contenant le paramètre personnalisé.
:::

### Paramètres \{#settings\}

L'onglet **Settings** détermine comment Adapty associe les actions des utilisateurs à vos campagnes Meta Ads. Ces paramètres définissent les fenêtres temporelles pour la correspondance d'attribution déterministe et probabiliste.

Pour les configurer, accédez à l'onglet **Settings** dans la configuration de votre campagne. Vous y trouverez deux paramètres principaux à ajuster :

- **Fenêtre de correspondance déterministe** : cette méthode utilise des identifiants d'appareil exacts (comme l'IDFA sur iOS ou l'Advertising ID sur Android) pour associer les utilisateurs aux campagnes avec une grande précision. Réglez-la sur 168 heures (7 jours) pour une précision d'attribution maximale — c'est la valeur par défaut et recommandée. Lorsqu'un utilisateur clique sur votre annonce Meta et installe votre application dans cette fenêtre, Adapty peut attribuer l'installation de façon certaine à ce clic publicitaire précis grâce aux identifiants d'appareil.

- **Probabilistic matching window** : utilise la modélisation statistique et le fingerprinting d'appareil pour associer les utilisateurs lorsque la correspondance déterministe n'est pas possible. Réglez ce paramètre sur 6 heures pour la plupart des campagnes — c'est la valeur par défaut et elle convient à la majorité des cas d'usage. Pour les campagnes à fort volume de clics, vous pouvez le réduire à 1-2 heures. Pour les utilisateurs ne pouvant pas être associés de façon déterministe (en raison de paramètres de confidentialité ou d'autres facteurs), Adapty utilise la correspondance probabiliste dans cette fenêtre réduite.

Cliquez sur **Save** pour appliquer vos paramètres.

<ZoomImage id="ua-meta-attribution-settings.webp" width="900px" />

### Remplacement des revenus \{#revenue-override\}

Si vous suivez les événements d'essai et souhaitez que Meta leur attribue des revenus, utilisez la section **Revenue override**. Elle apparaît lorsque l'événement **Trial started** est activé. Le remplacement s'applique uniquement à **Trial started** — **Trial converted** et **Subscription started** conservent toujours leurs revenus réels.

Pour chaque cible d'événement d'essai, définissez le pourcentage du prix de l'abonnement à déclarer comme revenu. Par exemple, à 30 %, Adapty envoie 30 % du prix de l'abonnement comme valeur de conversion pour les événements d'essai.

Pour ajouter un remplacement :

1. Activez **Trial started** dans la section **Events mapping**.
2. Dans **Revenue override**, cliquez sur **Add override**.
3. Sélectionnez l'événement cible et entrez un pourcentage de revenus (0–100).
4. Cliquez sur **Save**.

<ZoomImage id="revenue-override.webp" width="500px" />

### Essai qualifié \{#qualified-trial\}

:::warning
Adapty Attribution retarde l'événement d'essai jusqu'à 24 heures et ne l'envoie que si l'utilisateur n'a pas annulé. Si un MMP transfère également `trial_started` ou [`trial_active`](events#synthetic-events), Meta reçoit le même essai plus d'une fois.
:::

Un essai est qualifié une fois qu'il a survécu un nombre d'heures donné sans être annulé. Utilisez la section **Qualified trial** pour retenir les événements d'essai jusqu'à ce qu'ils soient qualifiés, afin que Meta ne reçoive que les essais que les utilisateurs ont conservés.

Pour chaque événement d'essai cible, définissez le nombre d'heures à attendre. Adapty compte les heures à partir du début de l'essai et envoie l'événement une fois le délai écoulé. Si l'utilisateur désactive le renouvellement automatique avant le délai, Adapty n'envoie jamais l'événement. Si l'utilisateur réactive le renouvellement automatique avant le délai, Adapty envoie l'événement comme prévu.

Pour retenir un événement d'essai jusqu'à sa qualification :

1. Activez **Trial started** dans la section **Events mapping**.
2. Dans **Qualified trial**, cliquez sur **Add event**.
3. Sélectionnez l'événement cible et saisissez le nombre d'heures à attendre, de 1 à 24.
4. Cliquez sur **Save**.

<ZoomImage id="qualified-trial.webp" width="700px" alt="Section d'essai qualifié avec l'événement cible StartTrial retenu pendant deux heures dans une configuration de campagne" />

Adapty envoie l'événement qualifié avec l'heure de début d'essai d'origine, de sorte que Meta le signale le jour où l'essai a commencé.

:::important
Adapty associe les essais qualifiés à leur transaction App Store ou Google Play, donc la rétention s'applique uniquement aux essais intégrés. Les événements d'essai provenant d'achats web, comme [FunnelFox](ua-funnelfox), sont envoyés immédiatement.
:::

**Revenue override** et **Qualified trial** fonctionnent indépendamment, et vous pouvez appliquer les deux au même événement d'essai. Revenue override modifie la valeur que Meta reçoit ; Qualified trial modifie le moment où Meta la reçoit. Avec les deux, Adapty retient l'événement jusqu'à ce que l'essai soit qualifié, puis l'envoie avec le revenu modifié. Aucune des deux options n'est recommandée par rapport à l'autre — testez ce qui fonctionne pour vos campagnes.

### LTV Prédit \{#predicted-ltv\}

La fonction Value Optimization de Meta mise sur la valeur d'une conversion, mais elle ne voit par défaut que le paiement reporté — un essai mensuel et un abonnement annuel se ressemblent donc presque au moment de l'enchère. Utilisez la section **Predicted LTV** pour envoyer à Meta une [valeur vie client prédite](https://developers.facebook.com/documentation/ads-commerce/conversions-api/guides/predicted-lifetime-value) avec la conversion, afin que Meta enchérisse sur ce que l'utilisateur est susceptible de rapporter sur l'horizon que vous choisissez.

Adapty génère la prédiction à partir des revenus réels de votre application, regroupés par pays, store, appareil et locale, puis l'associe à une conversion déjà envoyée.

Le LTV prédit se déverrouille pour une application une fois que ses données permettent de formuler une prédiction pertinente. Adapty recalcule cela quotidiennement et affiche la position actuelle de l'application dans la section **Predicted LTV**. **Trial started** et **Subscription started** sont mesurés séparément, et l'un ou l'autre suffit à déverrouiller l'application en remplissant les deux barres :

- Au moins 100 conversions attribuées à Meta pour cet événement sur chacune des 4 dernières semaines complètes.
- Au moins 5 valeurs prédites distinctes, la plus haute étant au moins 3× la plus basse.

Meta ajoute deux exigences qu'Adapty ne peut pas vérifier pour vous : le dataset doit être sorti du Core Setup, et le compte publicitaire doit avoir un modèle de valeur validé en cours d'utilisation.

Pour envoyer des valeurs prédites pour une campagne :

1. Dans **Events mapping**, activez **Trial started** ou **Subscription started** et associez-le à un événement Meta.
2. Dans **Predicted LTV**, activez **Send predicted LTV to Meta**.
3. Dans **Anchor event**, sélectionnez l'événement que vous avez associé à l'étape 1.
4. Dans **Prediction horizon**, choisissez la période de prévision : 30, 90, 180 ou 365 jours.
5. Dans **Target event**, sélectionnez l'événement Meta auquel la valeur prédite sera attachée. La liste affiche uniquement les événements auxquels cette campagne associe l'ancre. Meta n'accepte les valeurs prédites que pour **Purchase**, **Subscribe**, **StartTrial**, **CompleteRegistration**, **AddPaymentInfo** et les événements personnalisés.
6. Cliquez sur **Save**.
7. Pour permettre à Meta d'utiliser ces valeurs, dans Events Manager, ouvrez votre jeu de données et sélectionnez l'événement cible dans **Value and Currency Metrics**. Cliquez sur **Set up pLTV** et choisissez **After [Event Name] events**, car Adapty transmet la valeur après la conversion, et non avec elle.

<ZoomImage id="ua-meta-pltv.webp" width="900px" alt="Section LTV prédit avec le bouton activé, Trial started comme événement d'ancrage, un horizon de 180 jours et StartTrial comme événement cible" />

:::warning
Meta apprend à partir de l'événement d'ancrage et de l'horizon que vous avez choisis. Modifier l'un ou l'autre sur une configuration active redémarre la phase d'apprentissage de Meta, et le ROAS avant et après le changement n'est pas comparable. Meta calcule également le ROAS différemment pour chaque paramètre d'optimisation : comparez donc une campagne pLTV uniquement avec d'autres campagnes pLTV.
:::

Meta n'accepte qu'un seul événement d'ancrage et un seul horizon par dataset, donc les campagnes qui partagent un pixel doivent envoyer la même paire. L'enregistrement d'une campagne dont la paire diffère de celle d'une autre campagne active sur ce pixel est refusé, et l'erreur indique la campagne avec laquelle s'aligner.

Adapty prépare la valeur prédite au moment où il envoie la conversion d'ancrage, puis transmet la valeur 24 heures plus tard — dans la fenêtre de 7 jours de Meta pour associer une valeur à une conversion. Trois cas modifient ce que Meta reçoit :

- Lorsque l'événement d'ancrage est détenu par un [essai qualifié](#qualified-trial), les 24 heures démarrent une fois que l'événement d'essai parvient à Meta. Un essai annulé avant d'être qualifié n'envoie ni la conversion ni une valeur prédite.
- Lorsqu'Adapty ne dispose d'aucune prédiction pour le groupe de cet utilisateur — un pays dans lequel vous avez commencé à acheter récemment, par exemple — la conversion est tout de même envoyée, sans valeur prédite.
- Désactiver **Send predicted LTV to Meta** supprime également les valeurs prédites encore en attente d'envoi.

Adapty envoie les valeurs prédites en USD.

Une fois qu'Events Manager n'affiche plus aucun problème ouvert pour l'intégration, Meta a besoin d'environ deux semaines pour entraîner son modèle avant de lancer votre première campagne pLTV. Pour consulter les résultats, dans Ads Manager, ajoutez la colonne pLTV pour l'événement cible, par exemple **StartTrial pLTV**, via **Columns > Customize columns > Results ROAS**. Adapty transmet chaque valeur le lendemain de la conversion, donc attendez un jour après la fin d'une campagne avant de lire ses chiffres définitifs.

### Envoyer tous les événements \{#send-all-events\}

Par défaut, Adapty ne remonte que les événements des utilisateurs provenant de l'une de vos campagnes Meta. L'option **Send all events** remonte à la place chaque installation et transaction, y compris celles des utilisateurs organiques ou non attribués.

Nous ne le recommandons pas, sauf si vos campagnes envoient trop peu de conversions à Meta pour pouvoir optimiser dessus, car mélanger des événements organiques et non attribués avec vos événements de campagne réduit la précision de l'optimisation Meta.

Si vous décidez de l'activer, dans les paramètres de la campagne, sélectionnez **Send all events (forward organic/non-attributed events to this pixel)** et cliquez sur **Save**.
