Avec l'intégration Meta d'Adapty Attribution, vous pouvez suivre et optimiser vos campagnes sur Facebook, Instagram, Messenger et Audience Network.

:::tip
Consultez notre [guide sur la configuration des publicités dans Meta Ads Manager](meta-create-campaign).
:::

## Étape 1. Connecter votre compte Facebook \{#step-1-connect-your-facebook-account\}

Pour connecter Meta Ads à Adapty Attribution, accédez à **Integrations > Meta** depuis la barre latérale gauche. Vous avez deux options :

- **Continue with Facebook** : connexion via OAuth. Utilisez cette option si vous vous connectez à Meta Ads Manager avec votre compte Facebook personnel ou professionnel.
- **Add system token** : connexion via un jeton système permanent. Utilisez cette option si votre organisation gère des comptes publicitaires via un utilisateur système Meta Business.

:::important
Assurez-vous que votre compte Facebook a accès aux campagnes et pixels dont vous avez besoin.
:::

1. Cliquez sur **Continue with Facebook**.

<ZoomImage id="ua-connect-meta.webp" width="700px" />

2. Connectez-vous avec votre compte Facebook et cliquez sur **Continue**.

<ZoomImage id="ua-fb-sign.webp" width="500px" />

3. Vérifiez les autorisations demandées et cliquez sur **Save**.

:::note
Meta peut déconnecter l'intégration lorsque le compte Facebook associé atteint un point de contrôle de sécurité, et les dépenses cessent alors d'apparaître dans Adapty Attribution. Pour rétablir la connexion, connectez-vous sur [facebook.com](https://www.facebook.com), complétez le point de contrôle, puis reconnectez-vous dans **Integrations > Meta**.
:::

</TabItem>
<TabItem value="system" label="Add system token">

Générez un [jeton d'accès utilisateur système](https://developers.facebook.com/documentation/ads-commerce/marketing-api/collaborative-ads/managed-partner-ads/api-guide/prerequisites/generate-access-token-system-user) dans Meta Business Settings, puis ajoutez-le à Adapty Attribution.

:::important
Avant de commencer, vous avez besoin d'un [utilisateur système](https://www.facebook.com/business/help/503306463479099) dans votre portefeuille Meta Business, avec les comptes publicitaires que vous souhaitez suivre déjà assignés. Vous devez également avoir une application ajoutée au portefeuille — vous sélectionnez cette application lors de la génération du jeton.
:::

**Dans Meta Business Settings, générez le token :**

1. Accédez à **Business Settings**.
2. Sous **Users**, sélectionnez **System users**.
3. Sélectionnez votre utilisateur système, puis cliquez sur **Generate new token**.
4. Sélectionnez votre application dans le menu déroulant.
5. Dans la liste des permissions, activez `ads_read`. C'est la seule permission dont Adapty Attribution a besoin pour lire les données de vos campagnes et annonces.
6. Cliquez sur **Generate token**.
7. Copiez le token et conservez-le en lieu sûr. Meta ne l'affiche qu'une seule fois.

:::note
Le paramètre **Token expiration** contrôle la durée d'activité de la connexion. Un token avec une date d'expiration doit être régénéré et reconnecté avant son expiration, sinon l'attribution s'arrête. Un token sans expiration évite ce problème, mais constitue un identifiant de longue durée. Conservez-le en lieu sûr et révoquez-le s'il venait à être exposé.
:::

**Dans Adapty Attribution, ajoutez le token :**

1. Cliquez sur **Add system token**.

<ZoomImage id="ua-add-meta-system-token.webp" width="700px" alt="Bouton Add system token sur la page d'intégration Meta dans Adapty Attribution" />

2. Collez le token et cliquez sur **Connect**.

<ZoomImage id="ua-connect-meta-system-token.webp" width="700px" alt="Champ de saisie du token système sur la page d'intégration Meta dans Adapty Attribution" />

## Étape 2. Ajouter des campagnes \{#step-2-add-campaigns\}

Une seule campagne peut couvrir l'App Store, Google Play et votre funnel web en même temps. Deux éléments permettent d'établir la connexion :

- **Lien de suivi** : S'intègre dans votre annonce. Quand un utilisateur appuie sur l'annonce, Adapty enregistre le clic, redirige l'utilisateur vers la destination, puis attribue l'installation et les achats à cette annonce. Chaque destination possède son propre lien.
- **Pixel** : Sélectionné dans la campagne, parmi les pixels de votre compte Meta. Renvoie ces conversions vers Meta pour que Meta puisse optimiser la campagne sur la base des achats réels. Un seul pixel peut couvrir les trois destinations, ou chaque destination peut avoir le sien.

Pour ajouter une nouvelle campagne Meta à Adapty Attribution :

1. Basculez vers l'application que vous souhaitez promouvoir.

2. Ouvrez l'onglet **Web Campaigns** et cliquez sur **Create configuration**. Cette configuration ne comptabilise que les installations de l'application vers laquelle vous avez basculé.

   <ZoomImage id="ua-new-campaign.webp" width="500px" />

3. Dans l'onglet **General**, développez la section **iOS** et/ou **Android** et collez les URLs de l'application App Store et/ou Google Play.

   <ZoomImage id="ua-url.webp" width="900px" />

4. Copiez la valeur du champ **Click link**. Ensuite, dans Meta Ads Manager, ouvrez votre annonce et répartissez le lien entre les champs **Website URL** et **URL parameters**, comme décrit dans [Créer des annonces](meta-create-campaign#step-5-create-ads). Cela permettra à Adapty d'associer les installations et les achats aux annonces dans Meta. Adapty n'associe les installations à votre annonce que lorsque les utilisateurs accèdent directement depuis celle-ci vers le store via ce lien.

   <ZoomImage id="ua-lnk.webp" width="900px" />

   Insérez le lien dans les publicités des campagnes avec l'objectif **Sales**. Adapty Attribution ne suit pas les campagnes **App promotion** : il affiche leurs dépenses, mais pas les installations ni les revenus.

5. (Facultatif) Pour renvoyer les événements de conversion vers Meta, associez vos pixels Meta à cette configuration :
   1. Dans le menu déroulant **Pixel**, sélectionnez le pixel utilisé par votre ensemble de publicités comme source de données. Si vous n'avez pas encore de pixel, [créez-en un dans Meta](meta-create-campaign#step-2-add-meta-pixel).
   2. Pour vérifier la connexion, cliquez sur **Send test event**.

6. Si vos annonces mènent à un funnel web, développez la section **Web funnel** de la configuration :
   1. (Optionnel) Dans le menu déroulant **Pixel**, sélectionnez le pixel pour les achats web. Meta n'est informé des achats sur votre funnel que via ce pixel.
   2. Pour installer le [pixel web Adapty](ua-web-pixel), collez le **Pixel snippet** sur chaque page de votre funnel.
   3. Pour [tagger vos URL d'annonces](ua-tag-ad-urls), copiez les **Ad URL parameters**.

   Si votre funnel fonctionne sur [FunnelFox](ua-funnelfox), ignorez ce snippet. Adapty n'envoie pas les achats FunnelFox à Meta. Pour les envoyer, configurez l'[intégration Meta Pixel](https://funnelfox.com/docs/integrations/tracking/meta-pixel) dans FunnelFox.

Pour configurer vos pixels correctement :

- **Faites correspondre les pixels à vos campagnes** : Si une campagne couvre l'App Store, Google Play et votre funnel web, sélectionnez le même pixel dans les trois sections. Si vous gérez une campagne séparée pour chacun, sélectionnez un pixel distinct pour chacune, afin que chaque campagne optimise sur ses propres achats. La liste **Web Campaigns** affiche les pixels de chaque configuration dans les colonnes **Pixel (iOS)**, **Pixel (Android)** et **Pixel (Web)**.
- **Modifiez la configuration existante pour changer de pixel** : Les publicités en cours conservent le lien de clic de leur configuration, donc leurs conversions sont attribuées aux pixels de cette configuration. Pour changer le pixel de publicités en cours, sélectionnez un autre pixel dans cette configuration. Une nouvelle configuration ne modifie pas l'attribution de leurs conversions.
- **Renseignez l'URL source de l'événement** : Si vous avez connecté votre pixel à votre site web dans Meta, saisissez l'adresse du site dans le champ **Event source URL** de la configuration. Sinon, Meta risque de considérer les conversions provenant d'Adapty comme issues d'un site web inconnu. Ce champ ne modifie pas l'adresse de vos liens de suivi.

## Étape 3. Mapper les événements \{#step-3-map-events\}

Adapty envoie les événements que vous sélectionnez, comme les essais démarrés, aux pixels de la configuration. Meta utilise ces événements pour trouver des personnes susceptibles de démarrer un essai ou d'acheter un abonnement.

Pour sélectionner les événements, dans la section **Events mapping** de la configuration :

1. Activez chaque événement qu'Adapty doit envoyer à Meta.
2. Pour chaque événement, sélectionnez un événement Meta dans le menu déroulant, ou saisissez un événement personnalisé. Par défaut, Adapty sélectionne les événements standard de Meta. **Install** ne peut être envoyé qu'en tant que **Lead**.
3. Cliquez sur **Save**.

Adapty envoie le nom de l'événement exactement tel que vous le saisissez. Pour que Meta comptabilise un événement comme événement standard, sélectionnez-le dans la liste déroulante plutôt que de le saisir manuellement. Un nom saisi qui ne correspond pas au nom standard, comme `Add to wishlist` au lieu de `AddToWishlist`, parvient à Meta en tant qu'événement personnalisé, et un ensemble de publicités optimisé pour l'événement standard ne le comptabilise pas. Si vous utilisez un événement personnalisé, créez une conversion personnalisée pour celui-ci dans Meta Events Manager et optimisez l'ensemble de publicités sur cette conversion.

## Configuration supplémentaire \{#additional-configuration\}

### Paramètres supplémentaires \{#additional-parameters\}

Le champ **Additional parameter** vous permet d'ajouter des données personnalisées pour les analyses effectuées en dehors d'Adapty. C'est utile lorsque vous devez transmettre des informations spécifiques sur une campagne ou un utilisateur à des outils d'analyse externes ou à des partenaires d'attribution.

Dans le champ **Additional parameter**, saisissez les données personnalisées que vous souhaitez inclure dans votre suivi d'attribution. Ce paramètre supplémentaire sera intégré à toutes les données d'attribution envoyées à Meta et pourra être utilisé pour une analyse et une optimisation avancées des campagnes.

Par exemple, si vous exécutez plusieurs variations de la même campagne, vous pouvez ajouter `variant=A` ou `variant=B` pour distinguer différentes approches créatives.

:::important
Les paramètres supplémentaires modifient le **Click link** que vous collez dans Meta Ads Manager. Si vous avez déjà copié ce lien et ajouté un paramètre personnalisé ultérieurement, assurez-vous de copier et coller un lien de clic mis à jour contenant le paramètre personnalisé.
:::

### Paramètres \{#settings\}

L'onglet **Settings** d'une configuration définit comment Adapty associe les installations aux clics sur vos publicités Meta. Adapty utilise l'une des deux méthodes suivantes :

| Méthode | Installations | Comment Adapty attribue l'installation | Délai maximum entre le clic et l'installation |
|---|---|---|---|
| Correspondance par ID de clic | Installations Android avec un ID de clic | Au clic dont l'ID est transmis à votre application par Google Play | 168 heures (7 jours) par défaut, jusqu'à 720 heures |
| Correspondance probabiliste | Installations iOS, et installations Android sans ID de clic | Au clic récent le plus probable depuis la même plage d'adresses IP et le même système d'exploitation | 6 heures par défaut, jusqu'à 24 heures |

Pour une correspondance probabiliste, Adapty sélectionne le clic qui obtient le meilleur score en fonction du temps écoulé depuis le clic, de la langue du système et du pays. Adapty n'utilise pas l'IDFA ni le Google Advertising ID, donc la correspondance probabiliste couvre les utilisateurs iOS qui n'autorisent pas le suivi.

Adapty ne peut pas associer une installation de manière probabiliste si l'appareil change de réseau entre le clic et l'installation, par exemple en passant du Wi-Fi à la connexion cellulaire. Sur les réseaux partagés par de nombreux appareils, comme les réseaux des opérateurs mobiles, Adapty associe moins d'installations de manière probabiliste.

Pour modifier les limites de temps, dans la section **New user attribution** de l'onglet **Settings**, saisissez chaque limite en heures :

- **Deterministic Matching Window** : Pour une correspondance par identifiant de clic.
- **Probabilistic Matching Window** : Pour une correspondance probabiliste. Une limite plus longue correspond à davantage d'installations, mais davantage de ces correspondances sont incorrectes. Pour les campagnes à fort volume de clics, réduisez-la à 1–2 heures. Si vous définissez plus de 6 heures, les clics survenus plus de 6 heures avant l'installation doivent également correspondre au modèle d'appareil et à la version d'OS de l'installation.

Laissez les deux champs activés. Sans la correspondance probabiliste, Adapty ne peut pas associer les installations iOS aux liens de cette configuration.

<ZoomImage id="ua-meta-attribution-settings.webp" width="900px" alt="Section d'attribution des nouveaux utilisateurs dans l'onglet Paramètres, avec les fenêtres de correspondance déterministe et probabiliste et leurs interrupteurs d'activation/désactivation" />

### Revenus envoyés à Meta \{#revenue-sent-to-meta\}

Meta utilise la valeur de chaque événement pour calculer le ROAS et optimiser les campagnes basées sur la valeur. Pour choisir quels revenus Adapty envoie à Meta en tant que valeur, dans le menu déroulant **Revenue sent to Meta**, sélectionnez un type de revenu et cliquez sur **Save**. Pour comparer le ROAS dans Meta avec le ROAS dans Adapty, sélectionnez le type que vous [affichez dans les analyses Adapty](controls-filters-grouping-compare-proceeds#display-gross-or-net-revenue).

<ZoomImage id="ua-revenue-sent-meta.webp" width="700px" alt="Menu déroulant Revenus envoyés à Meta ouvert, avec les options Revenus bruts, Produits après commission du store, et Produits après commission du store et taxes" />

| Type de revenus | Valeur d'un achat sur l'App Store ou Google Play |
|---|---|
| **Revenus bruts** (par défaut) | Le prix total payé par l'utilisateur, avant la commission du store et les taxes. |
| **Revenus après commission du store** | Le prix moins la commission de l'App Store ou Google Play. Les taxes sont toujours incluses. |
| **Revenus après commission du store et taxes** | Le prix moins la commission du store et les taxes. |

Pour savoir comment Adapty calcule la commission et les taxes, consultez [Commissions et taxes](how-adapty-analytics-works#commissions-and-taxes).

Comment ce type s'applique dans les autres cas :

- **Achats web** : Pour les achats Stripe et Paddle, les deux types de revenus envoient la même valeur, comme dans les analyses d'attribution Adapty : le prix moins 4,5 % pour Stripe, et le prix total pour Paddle. Adapty ne déduit pas les taxes des achats web.
- **Remboursements** : Meta reçoit un remboursement sous forme de valeur négative du type sélectionné.
- **Événements d'essai** : Le pourcentage de [Remplacement de revenus](#revenue-override) s'applique au prix d'abonnement du type sélectionné.
- **Achats sans montant pour le type sélectionné** : Adapty envoie à Meta le revenu brut de l'achat.

Un nouveau type de revenus prend effet dans les 5 minutes suivant la sauvegarde et s'applique uniquement aux nouveaux événements. Adapty ne renvoie pas les événements déjà envoyés, et un événement d'essai qu'Adapty conserve déjà pour le [Qualified trial](#qualified-trial) est envoyé avec le type sélectionné au moment où la mise en attente a commencé.

Si plusieurs configurations envoient des événements au même pixel, sélectionnez le même type de revenus dans toutes, afin que les valeurs dans ce pixel soient d'un seul type.

:::warning
Les recettes sont inférieures au chiffre d'affaires brut. Si vous passez de **Gross revenue** à cette option et qu'un ensemble de publicités a un objectif ROAS minimum, réduisez l'objectif dans Meta, sinon l'ensemble de publicités risque de cesser d'être diffusé.
:::

### Remplacement des revenus \{#revenue-override\}

Par défaut, Adapty envoie l'événement **Trial started** à Meta sans valeur de revenu, car aucun paiement n'a lieu au démarrage d'un essai. Avec un remplacement des revenus, Adapty envoie la valeur que vous définissez : un pourcentage du prix de l'abonnement. Adapty applique ce pourcentage au prix selon le type sélectionné dans [Revenus envoyés à Meta](#revenue-sent-to-meta). Par exemple, à 30 %, Adapty envoie 30 % du prix de l'abonnement. **Trial converted** et **Subscription started** conservent toujours leur revenu réel.

Un remplacement de revenus modifie la valeur que Meta reçoit pour un essai. Un [essai qualifié](#qualified-trial) modifie le moment où Meta le reçoit. Vous pouvez utiliser les deux pour le même événement.

Pour signaler des revenus à Meta pour les essais démarrés :

1. Dans la section **Events mapping**, activez l'événement **Trial started**. La section **Revenue override** apparaît.
2. Dans la section **Revenue override**, cliquez sur **Add event**.
3. Sélectionnez l'événement Meta que vous avez associé à **Trial started**, par exemple **StartTrial**.
4. Saisissez le pourcentage du prix de l'abonnement à envoyer, de 0 à 100.
5. Cliquez sur **Save**.

<ZoomImage id="revenue-override.webp" width="500px" />

### Essai qualifié \{#qualified-trial\}

:::important
Les rapports d'essais qualifiés nécessitent les [App Store Server Notifications](enable-app-store-server-notifications) pour iOS et les [Real-time Developer Notifications](enable-real-time-developer-notifications-rtdn) pour Android. L'App Store et Google Play signalent les annulations d'essai à Adapty via ces canaux.
:::

Par défaut, Adapty envoie chaque essai commencé à Meta immédiatement, même si l'utilisateur l'annule peu après. Avec un essai qualifié, Meta ne comptabilise que les essais que les utilisateurs conservent — si le renouvellement automatique n'est pas désactivé un certain nombre d'heures après le début de l'essai. Adapty envoie l'événement avec l'heure de début d'essai d'origine, afin que Meta le rapporte le jour où l'essai a commencé. Si l'événement comporte également un remplacement de revenu, Adapty l'envoie avec le revenu remplacé.

Pour n'envoyer à Meta que les essais que les utilisateurs conservent :

1. Dans la section **Events mapping**, activez l'événement **Trial started**.
2. Dans la section **Qualified trial**, cliquez sur **Add event**.
3. Sélectionnez l'événement Meta que vous avez associé à **Trial started**, par exemple **StartTrial**.
4. Indiquez le nombre d'heures à attendre, de 1 à 24. Adapty envoie l'événement environ 45 minutes après la fin de l'attente.
5. Cliquez sur **Save**.

<ZoomImage id="qualified-trial.webp" width="700px" alt="Section Qualified trial avec l'événement cible StartTrial mis en attente pendant deux heures dans une configuration de campagne" />

Si l'utilisateur réactive le renouvellement automatique avant la fin du délai, Adapty envoie l'événement comme prévu. Les trials qualifiés s'appliquent uniquement aux trials issus de l'App Store et de Google Play.

#### Trials qualifiés vs. l'événement Trial still active \{#qualified-trials-vs-the-trial-still-active-event\}

Adapty propose deux façons de ne signaler que les trials que les utilisateurs conservent. Pour Meta, utilisez un trial qualifié : Adapty Attribution ne peut pas envoyer l'événement [Trial still active](events#synthetic-events) à Meta. Si une autre intégration, comme AppsFlyer, envoie également des trials à Meta, Meta reçoit le même trial plus d'une fois.

| | Essai qualifié | Événement **Trial still active** |
|---|---|---|
| Où le configurer | Dans Adapty Attribution, dans une configuration Meta, TikTok ou Google Ads | Dans Adapty, dans des intégrations comme AppsFlyer, Adjust, Firebase, ou le webhook |
| Ce que ça fait | Retarde l'événement **Trial started** | Ajoute un événement distinct après **Trial started** |
| Délai d'attente | 1 à 24 heures | 1 heure à 90 jours |
| Si l'utilisateur désactive le renouvellement automatique avant la fin du délai | Adapty n'envoie pas l'événement | Adapty n'envoie pas l'événement |
| Envoyé à Meta par Adapty Attribution | Oui | Non |

### LTV Prédit \{#predicted-ltv\}

La fonction Value Optimization de Meta mise sur la valeur d'une conversion, mais elle ne voit par défaut que le paiement reporté — un essai mensuel et un abonnement annuel se ressemblent donc presque au moment de l'enchère. Utilisez la section **Predicted LTV** pour envoyer à Meta une [valeur vie client prédite](https://developers.facebook.com/documentation/ads-commerce/conversions-api/guides/predicted-lifetime-value) avec la conversion, afin que Meta enchérisse sur ce que l'utilisateur est susceptible de rapporter sur l'horizon que vous choisissez.

Adapty génère la prédiction à partir des revenus réels de votre application, regroupés par pays, store, appareil et locale, puis l'associe à une conversion déjà envoyée.

Le LTV prédit se déverrouille pour une application une fois que ses données permettent de formuler une prédiction pertinente. Adapty recalcule cela quotidiennement et affiche la position actuelle de l'application dans la section **Predicted LTV**. **Trial started** et **Subscription started** sont mesurés séparément, et l'un ou l'autre suffit à déverrouiller l'application en remplissant les deux barres :

- Au moins 100 conversions attribuées à Meta pour cet événement sur chacune des 4 dernières semaines complètes.
- Au moins 5 valeurs prédites distinctes, la plus haute étant au moins 3× la plus basse.

Meta ajoute deux exigences qu'Adapty ne peut pas vérifier pour vous : le dataset doit être sorti du Core Setup, et le compte publicitaire doit avoir un modèle de valeur validé en cours d'utilisation.

Pour envoyer des valeurs prédites pour une campagne :

1. Dans **Events mapping**, activez **Trial started** ou **Subscription started** et associez-le à un événement Meta.
2. Dans **Predicted LTV**, activez **Send predicted LTV to Meta**.
3. Dans **Anchor event**, sélectionnez l'événement que vous avez associé à l'étape 1.
4. Dans **Prediction horizon**, choisissez la période de prévision : 30, 90, 180 ou 365 jours.
5. Dans **Target event**, sélectionnez l'événement Meta auquel la valeur prédite sera attachée. La liste affiche uniquement les événements auxquels cette campagne associe l'ancre. Meta n'accepte les valeurs prédites que pour **Purchase**, **Subscribe**, **StartTrial**, **CompleteRegistration**, **AddPaymentInfo** et les événements personnalisés.
6. Cliquez sur **Save**.
7. Pour permettre à Meta d'utiliser ces valeurs, dans Events Manager, ouvrez votre jeu de données et sélectionnez l'événement cible dans **Value and Currency Metrics**. Cliquez sur **Set up pLTV** et choisissez **After [Event Name] events**, car Adapty transmet la valeur après la conversion, et non avec elle.

<ZoomImage id="ua-meta-pltv.webp" width="900px" alt="Section LTV prédit avec le bouton activé, Trial started comme événement d'ancrage, un horizon de 180 jours et StartTrial comme événement cible" />

:::warning
Meta apprend à partir de l'événement d'ancrage et de l'horizon que vous avez choisis. Modifier l'un ou l'autre sur une configuration active redémarre la phase d'apprentissage de Meta, et le ROAS avant et après le changement n'est pas comparable. Meta calcule également le ROAS différemment pour chaque paramètre d'optimisation : comparez donc une campagne pLTV uniquement avec d'autres campagnes pLTV.
:::

Meta n'accepte qu'un seul événement d'ancrage et un seul horizon par dataset, donc les campagnes qui partagent un pixel doivent envoyer la même paire. L'enregistrement d'une campagne dont la paire diffère de celle d'une autre campagne active sur ce pixel est refusé, et l'erreur indique la campagne avec laquelle s'aligner.

Adapty prépare la valeur prédite au moment où il envoie la conversion d'ancrage, puis transmet la valeur 24 heures plus tard — dans la fenêtre de 7 jours de Meta pour associer une valeur à une conversion. Trois cas modifient ce que Meta reçoit :

- Lorsque l'événement d'ancrage est détenu par un [essai qualifié](#qualified-trial), les 24 heures démarrent une fois que l'événement d'essai parvient à Meta. Un essai annulé avant d'être qualifié n'envoie ni la conversion ni une valeur prédite.
- Lorsqu'Adapty ne dispose d'aucune prédiction pour le groupe de cet utilisateur — un pays dans lequel vous avez commencé à acheter récemment, par exemple — la conversion est tout de même envoyée, sans valeur prédite.
- Désactiver **Send predicted LTV to Meta** supprime également les valeurs prédites encore en attente d'envoi.

Adapty envoie les valeurs prédites en USD.

Une fois qu'Events Manager n'affiche plus aucun problème ouvert pour l'intégration, Meta a besoin d'environ deux semaines pour entraîner son modèle avant de lancer votre première campagne pLTV. Pour consulter les résultats, dans Ads Manager, ajoutez la colonne pLTV pour l'événement cible, par exemple **StartTrial pLTV**, via **Columns > Customize columns > Results ROAS**. Adapty transmet chaque valeur le lendemain de la conversion, donc attendez un jour après la fin d'une campagne avant de lire ses chiffres définitifs.

### Envoyer des événements depuis tous les utilisateurs \{#send-events-from-all-users\}

Par défaut, Adapty ne remonte que les événements des utilisateurs qu'il attribue à cette configuration. L'option **Send events from all users** reporte les événements de tous les utilisateurs de votre application, y compris les utilisateurs organiques, les utilisateurs provenant d'autres réseaux publicitaires et les utilisateurs issus de vos autres configurations Meta. Les achats effectués via les funnels FunnelFox font exception : Adapty les utilise uniquement dans les analyses d'attribution Adapty. Pour les envoyer à Meta, configurez l'[intégration Meta Pixel](https://funnelfox.com/docs/integrations/tracking/meta-pixel) dans FunnelFox. Meta décide ensuite quelles conversions attribuer à ses publicités. Cette option ne modifie pas l'attribution dans Adapty.

Nous ne le recommandons pas, sauf si vos campagnes envoient trop peu de conversions à Meta pour être optimisées, car mélanger des événements organiques et non attribués avec vos événements de campagne rend l'optimisation de Meta moins précise.

Si vous décidez de l'activer, dans les paramètres de configuration sélectionnez **Send events from all users** et cliquez sur **Save**.

## Lire correctement les données Meta Ads dans Adapty Attribution \{#read-meta-ads-data-correctly-in-adapty-attribution\}

Pour comparer les dépenses Meta avec vos installations et revenus dans [Adapty Attribution analytics](ua-analytics) :

- **Les dépenses récentes peuvent changer** : Meta continue d'ajuster les dépenses, les impressions et les clics pour les jours récents. Toutes les 4 heures, Adapty actualise ces chiffres pour les 3 derniers jours, aujourd'hui compris.
- **Les dépenses quotidiennes et les revenus peuvent utiliser des fuseaux horaires différents** : Adapty Attribution affiche les dépenses Meta par jour dans le fuseau horaire de votre compte publicitaire. Les installations et les revenus sont affichés par jour en UTC. Si les deux fuseaux horaires diffèrent, les dépenses quotidiennes et les revenus quotidiens couvrent des heures différentes. Pour afficher les installations et les revenus dans un autre fuseau horaire, contactez le [support Adapty](mailto:support@adapty.io).
