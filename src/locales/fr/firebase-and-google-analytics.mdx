Adapty peut transmettre les événements d'abonnement — achats, renouvellements, remboursements, démarrages d'essai — vers Firebase et Google Analytics, de sorte qu'une seule intégration envoie les données aux deux.

:::warning
Vous avez besoin à la fois d'un projet Firebase et d'une propriété Google Analytics associée — même si vous n'en utilisez qu'un seul. Firebase et Google Analytics présentent les mêmes données dans deux consoles distinctes.
:::

Les événements d'achat et de remboursement arrivent avec les informations de revenus, de devise et de détails produit associées. Ces mêmes données alimentent les outils mobiles de Firebase (Audiences, Remote Config, etc.) ainsi que les rapports dans Google Analytics.

Il s'agit d'une intégration analytique, pas d'un outil d'attribution Google Ads — voir [Limitations](#limitations).

## Ce que vous pouvez faire avec cette intégration \{#what-you-can-do-with-this-integration\}

Adapty regroupe les utilisateurs par `subscription_state` (`subscribed`, `active_trial`, `never_subscribed`, etc.) et transmet les événements du cycle de vie des abonnements à Firebase et Google Analytics.

- **Audiences** : Créez des audiences d'abonnés dans Firebase et Google Analytics pour des canaux externes — reciblage Google Ads, campagnes FCM, modélisation par sosies.
- **Conversions Google Ads** *(Google Analytics)* : Utilisez `purchase` et `refund` comme objectifs de conversion Google Ads.
- **Firebase Remote Config** : Modifiez les limites d'utilisation, les textes ou les feature flags sans mise à jour de l'application — conditionnez-les à l'état de l'abonnement. (À ne pas confondre avec [Adapty Remote Config](customize-paywall-with-remote-config), qui configure le contenu des flows/paywalls.)
- **Cloud Messaging** : Notifications push aux abonnés inactifs lorsque l'application est fermée.
- **Suivi multi-appareils** *(Google Analytics)* : Adapty envoie `customer_user_id` à Google Analytics afin que Google Ads puisse suivre la même personne sur plusieurs appareils.
- **Entonnoirs de conversion** *(Google Analytics)* : Voyez ce que les utilisateurs ont fait dans votre application avant de convertir ou de se désabonner.
- **Prédictions** : Anticipez le churn et les dépenses à partir de l'historique d'achats.
- **A/B Testing** : Testez des fonctionnalités de l'application sur des cohortes d'abonnés — par exemple, déployez un nouveau schéma de navigation auprès des utilisateurs en période d'essai et mesurez la durée des sessions. (Pour les variantes de paywalls, utilisez les [tests A/B Adapty](ab-tests).)

## Fonctionnement de l'intégration \{#how-the-integration-works\}

1. Lorsqu'un utilisateur ouvre votre application pour la première fois, le SDK Firebase crée un identifiant unique pour l'installation — le **Firebase App Instance ID**. Firebase et Google Analytics utilisent cet identifiant pour identifier l'installation à l'origine de chaque événement.
2. Votre application transmet le Firebase App Instance ID au SDK d'Adapty. Adapty associe le profil de l'utilisateur à cette installation Firebase.
3. Lorsque l'utilisateur effectue un achat, les serveurs d'Adapty transmettent l'événement à Firebase avec le Firebase App Instance ID joint. Les données sont échangées de serveur à serveur, en dehors de l'application.
4. Firebase associe l'achat à l'installation, ce qui vous permet de visualiser les achats aux côtés de tout ce que l'utilisateur a fait dans l'application.

:::note
Un Firebase App Instance ID est spécifique à l'appareil. Lorsqu'un même utilisateur Adapty ouvre l'application sur un autre appareil, le nouvel ID Firebase écrase le précédent. Utilisez un [customer user ID](identifying-users) pour maintenir l'identité de l'utilisateur sur tous les appareils.
:::

### Achats Stripe \{#stripe-purchases\}

Un achat Stripe n'atteint Firebase que si l'acheteur a **d'abord** lancé votre application mobile. L'App Instance ID Firebase doit être défini **avant** que l'achat Stripe ne soit déclenché.

Pour les achats App Store et Play Store, cela se produit automatiquement. Ils sont initiés depuis votre application mobile, en même temps que l'appel [`setIntegrationIdentifier`](#configure-your-app-code). L'identifiant Firebase est présent au moment où l'achat est déclenché.

Les achats Stripe proviennent de l'extérieur de l'application, sur votre serveur. Votre application mobile doit appeler `setIntegrationIdentifier` au lancement — avant tout achat Stripe. Sans cela, Adapty n'a aucun identifiant à associer, et l'achat Stripe n'atteint jamais Firebase.

### Limitations \{#limitations\}

- **Pas un outil d'attribution Google Ads.** Cette intégration envoie les événements Adapty dans Firebase et Google Analytics à des fins d'analyse. Elle n'attribue pas les installations de l'application aux campagnes Google Ads (UAC / Universal App Campaigns) et ne distingue pas le trafic payant du trafic organique. Pour l'attribution des installations, utilisez [l'attribution Adapty](adapty-user-acquisition) intégrée.
- **Pas de remplissage historique.** Adapty transmet les événements à partir du moment où vous activez l'intégration — les achats, renouvellements et remboursements passés n'arrivent jamais dans Firebase. (Les données passées sont disponibles dans les exports [S3](s3-exports) / [GCS](google-cloud-storage) d'Adapty, mais leur importation dans Firebase ne fait pas partie de cette intégration.)
- **Les acheteurs uniquement web n'atteignent pas Firebase.** Adapty transmet les achats à Firebase via le Firebase App Instance ID défini par votre application mobile. Les acheteurs qui n'ont jamais installé l'application n'ont pas d'identifiant — leurs achats n'atteignent pas Firebase. Consultez la section [Achats Stripe](#stripe-purchases) ci-dessus pour plus de détails, et envisagez [l'intégration Firebase de FunnelFox](https://funnelfox.com/docs/integrations/subscription-management/adapty) ou un flux de données web Google Analytics pour le suivi web.
- **Les achats Paddle ne sont pas inclus.** Cette intégration ne prend pas en charge Paddle pour l'instant. Les achats Paddle restent dans Adapty Analytics et n'atteignent pas Firebase via ce chemin.
- **Les achats Stripe héritent des limitations spécifiques à Stripe.** Voir [les limitations de l'intégration Stripe](stripe#current-limitations).

## Instructions de configuration \{#setup-instructions\}

### Configurer Firebase \{#configure-firebase\}

1. Ouvrez la [Firebase Console](https://console.firebase.google.com/) et sélectionnez ou créez un projet. Pour garder vos analyses de production à l'écart des événements sandbox, utilisez un projet Firebase séparé pour les builds de développement.
2. Associez le projet à une propriété Google Analytics. Firebase vous y invite lors de la création du projet, ou vous pouvez l'ajouter ultérieurement via **Project settings** > **Integrations** > **Google Analytics**.

    <ZoomImage id="firebase-analytics-integration-settings.webp" width="700px" alt="Adapty Dashboard Firebase integration settings page" />

3. Dans **Project settings** > **General** > **Your apps**, ajoutez une entrée pour chaque plateforme sur laquelle vous publiez (iOS / Android / Web). Pour Stripe, ajoutez une entrée d'application Web — il n'existe pas de type d'application Stripe natif. Chaque entrée génère un **Firebase App ID** unique et un flux de données correspondant dans Google Analytics. Vous collerez cet identifiant dans les paramètres d'intégration Firebase d'Adapty lors de la configuration.

    <ZoomImage id="firebase-app-id.webp" width="700px" alt="Firebase Console affichant l'App ID pour une entrée d'application iOS" />

### Configurer Adapty \{#configure-adapty\}

1. Ouvrez [**Integrations** > **Firebase**](https://app.adapty.io/integrations/firebase) dans l'Adapty Dashboard.

2. Activez le bouton **Firebase integration**.

3. Saisissez les identifiants pour chaque plateforme sur laquelle vous publiez. Adapty a besoin d'un **Firebase App ID** et d'un **Google Analytics secret** pour chaque plateforme — chaque valeur diffère entre iOS, Android et Stripe.

| Adapty Dashboard | Google Analytics | Où le trouver |
   | --- | --- | --- |
   | **Firebase App ID** | **App ID** | Firebase Console > **Project settings** > **General** > **Your apps** |
   | **Google Analytics secret** | **Measurement Protocol API secret** | Google Analytics > **Admin** > **Data streams** > **Measurement Protocol API secrets** > **Create** |

   <ZoomImage id="ga4-firebase-secret.webp" width="700px" alt="Écran de création du secret Measurement Protocol API de Google Analytics" />

4. Configurez la façon dont Adapty transmet les données de revenus et d'utilisateurs. Les quatre paramètres partagent une même ligne dans le tableau de bord :

- Menu déroulant **Revenue definition** : Revenus bruts, Revenus après commission du store, ou [Revenus après commission du store et taxes](controls-filters-grouping-compare-proceeds#display-gross-or-net-revenue).
   - Bouton **Send user properties** : Quand il est activé, les événements incluent `subscription_state` et `subscription_product_id`. Pour les utiliser dans des rapports ou des audiences, consultez [Utiliser les données d'abonnement dans les rapports](#use-subscription-data-in-reports-and-audiences).
   - Bouton **Report user's currency** : Quand il est activé, Adapty signale chaque vente dans la devise utilisée par l'acheteur. Quand il est désactivé, les rapports sont en USD.
   - Bouton **Send trial price** : Les démarrages d'essai ont de la valeur — la plupart des utilisateurs payants commencent par un essai. Mais l'optimisation des enchères de Google Ads ne considère comme pertinents que les événements avec des revenus. Activez cette option pour attribuer un prix fictif à chaque essai, afin que Google les considère comme des conversions et optimise les dépenses publicitaires vers l'acquisition de nouveaux utilisateurs en essai. Quand il est activé, le champ **Trial price percentage** apparaît. Définissez-y la part du prix d'abonnement complet que Google doit attribuer à chaque essai — par exemple, `50%` signale la moitié du prix de l'abonnement pendant l'essai.

  <ZoomImage id="revenue-data-options-firebase.webp" width="700px" alt="Firebase integration revenue data row with the four controls" />

5. Associez les événements Adapty aux noms d'événements Firebase/Google Analytics. Adapty propose des mappages d'événements distincts pour **iOS** et **Android**, ce qui vous permet d'utiliser des noms différents selon la plateforme. **Les achats Stripe utilisent le mappage d'événements iOS** — il n'existe pas de mappage Stripe séparé.

Google Analytics impose des limites strictes au niveau du protocole de mesure — 40 caractères pour les noms d'événements, 24 pour les noms de propriétés utilisateur et 36 pour les valeurs. Google Analytics supprime silencieusement les événements personnalisés qui dépassent ces limites.

   :::warning
   Certains événements utilisent le vocabulaire e-commerce réservé dans Firebase et Google Analytics — `purchase` et `refund`. L'import des conversions Google Ads, les rapports de revenus Google Analytics et les audiences prédictives dépendent de ces chaînes exactes. Ne modifiez les valeurs par défaut que si vous n'avez pas besoin de ces fonctionnalités.
   :::

<ZoomImage id="ios-event-map-firebase.webp" width="700px" alt="Adapty Dashboard Firebase event names configuration" />

6. Cliquez sur **Save**. Adapty commence à transmettre les événements à Firebase en quelques minutes.

### Vérifier l'intégration \{#verify-the-integration\}

Le moyen le plus rapide de confirmer que les événements arrivent est Firebase DebugView :

1. Sur un appareil de test, lancez votre application avec [le mode debug Firebase activé](https://firebase.google.com/docs/analytics/debugview#enable_debug_mode).
2. Déclenchez un achat sandbox ou n'importe quel événement que vous avez activé dans l'Adapty Dashboard.
3. Ouvrez Firebase Console > **Analytics** > **DebugView**. Les événements apparaissent en quelques secondes, avec tous leurs paramètres.

Les rapports standards — Realtime, Reports, audiences — se mettent à jour en quelques minutes à 24 heures, selon le rapport. DebugView est le seul endroit où vous pouvez confirmer en temps réel.

## Utiliser les données d'abonnement dans les rapports et les audiences \{#use-subscription-data-in-reports-and-audiences\}

Activez **Send user properties** dans l'Adapty Dashboard ([Configurer Adapty](#configure-adapty), étape 4). Sans cela, Adapty ne transmet ni `subscription_state` ni `subscription_product_id` — et le reste de cette section ne servira à rien.

Par défaut, Firebase et Google Analytics n'exposent pas les propriétés utilisateur. Enregistrez chacune d'elles comme dimension personnalisée pour rendre `subscription_state` et `subscription_product_id` disponibles dans les rapports, les Explorations et les audiences. Configurez les dimensions dans Google Analytics Admin. Vous pouvez ensuite les interroger dans Firebase et Google Analytics — ils partagent le même backend.

Utile pour créer des audiences Google Ads d'utilisateurs payants ou alimenter des modèles prédictifs.

Une fois la configuration terminée, Adapty renseignera ces propriétés pour les événements à venir. Les événements existants ne seront pas mis à jour.

1. Dans Google Analytics, ouvrez **Admin** > **Custom definitions**.
    <ZoomImage id="firebase-ga4-custom-definitions.webp" width="700px" alt="Google Analytics Custom Definitions" />
2. Cliquez sur **Create custom dimensions**.
3. Pour chaque propriété, définissez :
   - **Dimension name** : N'importe quel nom lisible, par exemple « Subscription state ».
   - **Scope** : **User**.
   - **User property** : `subscription_state` ou `subscription_product_id`. Le nom doit correspondre exactement — Google Analytics est sensible à la casse.

   <ZoomImage id="ga4-new-custom-dimension.webp" width="500px" alt="Google Analytics New Custom Definition" />

## Dépannage \{#troubleshooting\}

### Les événements n'apparaissent pas dans Firebase \{#events-dont-appear-in-firebase\}

- Confirmez que le Firebase App Instance ID est défini **avant** le premier achat. Les événements sans identifiant Firebase n'atteignent pas Firebase et génèrent une erreur.
- Confirmez que la propriété Google Analytics liée dans la Firebase Console correspond au flux de données.
- Confirmez que les identifiants (ID + secret) renseignés dans Adapty correspondent bien à la plateforme.

### Les événements sandbox polluent les données de production \{#sandbox-events-pollute-production-data\}

Adapty transmet les transactions sandbox et de production au même projet Firebase. Consultez [Configurer Firebase](#configure-firebase) — utiliser un projet Firebase distinct pour les builds de développement permet d'éviter complètement ce problème.

### Firebase sous-estime les revenus des applications StoreKit 2 \{#firebase-undercounts-revenue-for-storekit-2-apps\}

Firebase enregistre automatiquement un événement `in_app_purchase` pour chaque achat StoreKit 1 — sans aucun code nécessaire. StoreKit 2 utilise une API différente. Firebase ne voit jamais ces transactions.

Les conséquences : les applications utilisant principalement SK2 sans pipeline de revenus séparé sous-déclarent de moitié ou plus — dans Firebase, dans Google Analytics, et dans chaque campagne Google Ads en aval. L'optimisation des enchères tourne avec de mauvais chiffres. Les rapports de revenus ne montrent que la moitié de la réalité.

Le correctif : passer `firebase_app_instance_id` à Adapty (voir [Configurer le code de votre application](#configure-your-app-code)). Adapty transmet chaque achat via le Measurement Protocol — revenus, devise et produit inclus.

### Les chiffres d'Adapty Analytics et de Firebase divergent \{#adapty-analytics-and-firebase-numbers-diverge\}

- **StoreKit 2** : de loin la cause principale. Voir [Firebase sous-compte les revenus pour les apps StoreKit 2](#firebase-undercounts-revenue-for-storekit-2-apps).
- **Adoption du SDK** : Firebase ne comptabilise que les événements des utilisateurs dont l'app envoie un Firebase App Instance ID. Les versions plus anciennes de l'app n'effectuent pas cet appel. Adapty continue de comptabiliser ces utilisateurs ; Firebase non.
- **Événements sandbox** : Adapty transfère également les transactions sandbox vers Firebase. Utilisez un projet Firebase distinct pour les builds de développement afin de les séparer.
- **Échantillonnage** : Google Analytics Explorations échantillonne les grands jeux de données. Pour des comptages sans échantillonnage, consultez la vue Temps réel ou les rapports standard.

### Les noms d'événements personnalisés sont rejetés par Google Analytics \{#custom-event-names-are-rejected-by-google-analytics\}

Google Analytics limite les noms d'événements à 40 caractères, composés uniquement de caractères alphanumériques et de tirets bas, et devant commencer par une lettre. Renommez dans le tableau de bord tout événement Adapty personnalisé qui ne respecte pas ces contraintes.
