Chaque fois qu'un utilisateur demande un remboursement, Apple mène une enquête. Pour décider **si le remboursement est justifié**, Apple demande au développeur des informations sur l'activité de cet utilisateur. Sans ces preuves, même un abonnement très utilisé sera probablement remboursé.

Le **Refund Saver** répond automatiquement aux demandes de consommation d'Apple [de façon automatique](https://developer.apple.com/documentation/appstoreserverapi/send-consumption-information-v1), protégeant ainsi vos revenus et **augmentant les chances de refus** pour les demandes abusives. Il fonctionne pour tous les types d'achats intégrés Apple — abonnements à renouvellement automatique, abonnements ponctuels, consommables et non-consommables (y compris les produits à vie).

## Fonctionnement du Refund Saver \{#how-refund-saver-works\}

1. Lorsqu'un utilisateur initie une demande de remboursement, l'App Store envoie une notification demandant les détails de la transaction et de l'utilisation.

    Si vous **ignorez** ou **retardez** la réponse, Apple approuvera très probablement le remboursement.

2. Le Refund Saver d'Adapty traite ces notifications automatiquement en fournissant à Apple les données nécessaires.

    Cette automatisation réduit les remboursements injustifiés tout en vous faisant gagner du temps et en protégeant vos revenus.

3. Adapty enregistre chaque résultat — remboursé ou refusé. Ces données alimentent les analyses du Refund Saver dans le Dashboard.

:::info

Avec Refund Saver, vous pouvez récupérer jusqu'à 40 % des revenus issus des demandes de remboursement.

:::

## Prérequis pour utiliser Refund Saver \{#requirements-to-use-refund-saver\}

Pour utiliser cette fonctionnalité, assurez-vous de remplir les conditions suivantes :

1. **Mettez à jour votre Politique de confidentialité dans App Store Connect :**
   La Politique de confidentialité de votre application doit mentionner la collecte et l'utilisation des données de consommation. Cela garantit que les utilisateurs comprennent les pratiques de confidentialité de votre application avant de la télécharger. Consultez [App Privacy Details d'Apple](https://developer.apple.com/app-store/app-privacy-details/) pour plus d'informations.
2. **Obtenez le consentement de l'utilisateur pour le partage de données dans votre application :**
   Apple exige que vous obteniez le consentement valide de l'utilisateur avant de partager ses données personnelles avec Apple. En tant que développeur, vous êtes responsable de l'obtention de ce consentement, car c'est vous qui partagez les données utilisateur avec Apple. Consultez les [directives](https://developer.apple.com/documentation/appstoreserverapi/send-consumption-information) d'Apple pour plus de détails.
3. **Activez les notifications serveur V2 :**
   Assurez-vous que les notifications serveur V2 sont activées dans votre compte Apple Developer et correctement configurées dans Adapty, car les notifications V1 ne sont pas prises en charge. Si elles ne sont pas encore activées, suivez les étapes du guide [Activer les notifications serveur App Store](enable-app-store-server-notifications).

## Activer Refund Saver \{#turn-on-refund-saver\}

1. Ouvrez la section [Refund Saver](https://app.adapty.io/refund-saver) dans l'Adapty Dashboard.

<ZoomImage id="refund-off.webp" width="700px" alt="Section Refund Saver dans l'Adapty Dashboard avec la fonctionnalité désactivée" />

2. Cliquez sur **Turn on Refund Saver** pour activer la fonctionnalité.

## Définir un comportement de remboursement par défaut \{#set-a-default-refund-behavior\}

Apple permet aux développeurs de spécifier un résultat préférentiel pour chaque demande de remboursement lors de leur réponse. Ce paramètre vise à trouver le bon équilibre entre le refus et l'acceptation des demandes de remboursement, afin que seuls les remboursements légitimes soient accordés. Notez que ce paramètre sert uniquement à influencer le résultat, mais la décision finale appartient toujours à Apple.

Adapty permet de définir cette préférence, mais la même valeur sera appliquée à toutes les demandes de remboursement.

1. Pour modifier votre préférence, cliquez sur **Edit refund preference**.
   <ZoomImage id="refund-saver-preference.webp" width="700px" alt="Boîte de dialogue Edit refund preference dans la section Refund Saver" />

2. Dans la fenêtre **Edit refund preference**, choisissez votre option **Default refund request preference** :

   | Option                                       | Description                                                  |
   | -------------------------------------------- | ------------------------------------------------------------ |
   | Always decline                               | (par défaut) Il s'agit de l'option par défaut, qui donne généralement les meilleurs résultats pour minimiser les remboursements. |
   | Decline first refund request, grant all next | Pour chaque transaction rencontrée par Refund Saver, il demandera d'abord à Apple de refuser le remboursement. Cependant, si la même transaction réapparaît, Refund Saver recommandera toujours d'accorder le remboursement. Cette approche permet de minimiser la frustration des utilisateurs face à des refus injustes — ils peuvent simplement renouveler leur demande et l'obtenir. |
   | Always refund                                | Suggère qu'Apple approuve chaque demande de remboursement.   |
   | No preference                                | N'envoie aucune recommandation à Apple. Dans ce cas, Apple déterminera le résultat du remboursement en fonction de ses politiques internes et de l'historique de l'utilisateur, sans aucune influence de vos paramètres. Cette option offre l'approche la plus neutre. |


## Définir le comportement de remboursement pour un utilisateur spécifique dans le tableau de bord \{#set-refund-behavior-for-a-specific-user-in-the-dashboard\}

Même si vous avez configuré le comportement par défaut de Refund Saver pour l'ensemble de l'application, vous pouvez définir des préférences individuelles pour des utilisateurs spécifiques. Dans l'Adapty Dashboard, vous pouvez le faire depuis le profil de l'utilisateur. Utilisez la section **Refund Saver Preferences** située en bas à gauche.

:::note
Les préférences par utilisateur remplacent le comportement par défaut au niveau de l'application — y compris le comportement « Decline first refund request, grant all next ».
:::

## Obtenir le consentement de l'utilisateur \{#obtain-user-consent\}

La façon dont vous collectez le consentement de l'utilisateur pour le partage de données vous appartient, mais Apple exige un consentement valide avant de partager des données personnelles avec eux. Apple recommande une **approche opt-in**, qui implique des invites dans l'application expliquant comment les données seront utilisées et nécessitant une action explicite de l'utilisateur pour donner son consentement. Si un utilisateur ignore ou refuse l'invite, il n'est pas considéré comme ayant consenti. Pour plus de détails, consultez les [directives](https://developer.apple.com/documentation/appstoreserverapi/send-consumption-information) d'Apple.

Si le consentement explicite n'est pas pratique pour votre application, vous pouvez envisager une **approche opt-out**. Cela implique d'inclure une clause de partage de données dans vos Conditions d'utilisation, expliquant que les utilisateurs acceptent le partage de données en acceptant les conditions. Veillez à indiquer clairement comment les utilisateurs peuvent révoquer leur consentement.

Voici un exemple de clause pour l'approche opt-out, incluant les types de données que vous pourriez partager. Il s'agit uniquement d'un exemple pour vous guider dans la rédaction de votre propre texte. Vous êtes responsable de vous assurer que votre version finale est conforme à toutes les lois applicables et aux exigences d'Apple.

*« Si nous recevons une demande de remboursement pour un achat intégré, nous pouvons fournir à Apple des informations sur l'activité d'achat intégré de l'utilisateur. Cela peut inclure des détails tels que le temps écoulé depuis l'installation de l'application, le temps d'utilisation total de l'application, un identifiant de compte anonyme, si l'achat intégré a été entièrement consommé, s'il incluait une période d'essai, le montant total dépensé et le montant total remboursé. »*

Selon l'approche choisie, définissez l'option **Default consent policy** dans le menu **Edit refund preferences** :

<ZoomImage id="refund-saver-consent.webp" width="700px" alt="Paramètre Default consent policy dans la boîte de dialogue Edit refund preferences" />

<p> </p>

| Option  | Description                                                  |
| ------- | ------------------------------------------------------------ |
| Opt-out | (par défaut) Si Adapty ne connaît pas le statut de consentement de l'utilisateur, il suppose que le consentement **a été donné** et Refund Saver **partagera** les données liées aux remboursements avec Apple. |
| Opt-in  | Si Adapty ne connaît pas le statut de consentement de l'utilisateur, il suppose que le consentement **n'a pas été donné** et Refund Saver **ne partagera aucune** donnée avec Apple. Il s'agit de l'approche recommandée par Apple. |

## Limitations \{#limitations\}

- **App Store d'Apple uniquement :** Refund Saver n'est disponible que pour les demandes de remboursement effectuées auprès de l'App Store d'Apple. Google Play ne propose pas d'analyse des données de consommation pour les remboursements. Les décisions de remboursement sur Google Play sont basées uniquement sur les politiques de Google et les informations fournies par l'utilisateur.
- **Nécessite les notifications serveur V2 :** Refund Saver n'est pas compatible avec les notifications serveur App Store V1. Si vous utilisez actuellement V1 dans Adapty, vous devez passer à V2 — consultez le guide [Envoyer des notifications serveur App Store à Adapty](enable-app-store-server-notifications) pour plus de détails. Passer à V2 améliorera également vos analyses dans Adapty en fournissant des données plus précises et complètes.
