Le skill growth-advisor répond à la question « que devrais-je tester ensuite ? » à partir de vos propres chiffres d'abonnement. Votre outil de développement IA lit vos analytics, placements, paywalls et produits via l'[Adapty CLI](developer-cli-analytics), suit le signal le plus fort jusqu'à sa cause, puis vous retourne une courte liste d'hypothèses à tester en A/B, classées selon le nombre d'achats en jeu.

:::note
growth-advisor ne modifie rien dans votre compte sans votre accord. Chaque lecture d'analytics est en lecture seule, et chaque écriture — une nouvelle copie de flow, un nouveau segment, un test A/B, une modification de placement — attend votre confirmation.
:::

## Ce que vous pouvez demander \{#what-you-can-ask\}

Posez vos questions comme vous le feriez avec un collègue. Inutile de nommer le skill :

```
Audit my app. What should I test next to grow revenue?

Revenue dropped last month. Why?

My A/B test on the onboarding paywall ended and the new version won. What now?

I have three ideas: a weekly plan, a trial on annual, and a second placement.
Which one should I test first?

Which country refunds the most, and do people who start a trial renew better?

We launch next month and have no data yet. Where should we start?
```

Une question sur vos chiffres obtient une réponse basée sur vos chiffres, sans audit joint. Une application sans données encore obtient un plan de départ construit à partir des médianes du marché issues du rapport State of Paywalls 2026 d'Adapty, avec chaque chiffre étiqueté comme une estimation.

## Avant de commencer \{#before-you-start\}

- **Un compte Adapty avec des données** : le skill lit les mêmes analyses que votre tableau de bord. Sans données, il ne peut que vous proposer un plan de départ.
- **Un outil IA capable d'exécuter des commandes en terminal** : par exemple Claude Code, Codex, Copilot CLI ou Gemini CLI. Les outils de chat comme claude.ai ou ChatGPT ne peuvent pas exécuter la CLI, donc ils n'ont pas accès à votre compte Adapty.

## Comment fonctionne l'audit \{#how-the-audit-works\}

Quand vous demandez quoi faire sans question précise, le skill lance un audit. Il lit vos chiffres et la configuration de vos placements, identifie ce que vous avez déjà testé, et remonte la variation la plus significative jusqu'au store, au canal, au pays ou au placement qui l'explique. Avant de dire quoi que ce soit sur un écran, il examine le flow en production, ou vous demande une capture d'écran d'un paywall que votre app affiche elle-même.

## Ce que vous obtenez en retour \{#what-you-get-back\}

Le skill vous répond brièvement, puis vous fournit une liste d'hypothèses regroupées par placement, dans l'ordre à tester. Chaque hypothèse explique pourquoi votre application en a besoin, quel résultat espérer et d'où vient cette estimation, combien de temps le test A/B prendrait, et qui fait quoi. Une hypothèse peut cibler tous les utilisateurs d'un placement ou un seul [segment](segments), comme les anciens abonnés.

## De l'hypothèse au test A/B \{#from-hypothesis-to-ab-test\}

Pour chaque hypothèse, le skill propose un test A/B et offre de le configurer. Avant de procéder, il vérifie que tout ce dont le test a besoin existe, et indique ce qui manque et qui doit le créer :

| Le test nécessite | Qui le crée |
|---|---|
| Un flow modifié : nouveau design, texte ou ensemble de produits | Le skill crée une copie du flow via le [skill flow-generator](flow-generator-skill), avec une seule modification par hypothèse, afin que le test montre l'impact de ce changement. Avant de publier la copie, le skill propose de la vérifier avec le [skill flow-audit](flow-audit-skill). Un flow ne rejoint un test qu'une fois publié. |
| Une nouvelle durée de plan, période d'essai ou offre | Vous créez le produit dans App Store Connect ou Google Play Console et l'ajoutez à Adapty. Sur l'App Store, une période d'essai nécessite un nouveau produit ; sur Google Play, c'est une offre sur le plan existant. Vous définissez le prix. |
| Un paywall avec des produits déjà dans Adapty | Le skill le crée. |
| Un paywall avec un nouveau design | Vous le créez dans le [Paywall Builder](adapty-paywall-builder). |
| Un segment | Le skill le crée via le skill audiences. |
| Un nouveau placement | Le skill le crée après que vous avez approuvé son identifiant développeur. Votre application nécessite une modification du code et une mise à jour pour le récupérer. |

Chaque élément créé par le skill attend votre validation. Lorsqu'un élément est à votre charge, la liste **Next steps** du skill l'indique, et le skill configure le test dès que vous lui confirmez que l'élément est prêt. Il ne configure jamais un test avec un élément qui n'existe pas encore.

Une fois tous les éléments en place, le [skill ab-tests](ab-tests-skill) crée le test en tant que brouillon. Avant de le démarrer, il vous montre précisément qui voit quoi. Un [test A/B](ab-tests) est l'option par défaut, et le seul moyen de mesurer l'impact du changement.

Pour appliquer un changement sans test, demandez-le. Le skill peut l'afficher sur un nouveau placement, ou pour une partie ou la totalité des utilisateurs d'un placement existant. Avant de modifier un placement existant, le skill enregistre ce placement dans un fichier pour vous permettre de le restaurer. Il indique également le nom de tout test A/B en cours sur ce placement. Le changement n'affecte pas ce test.

Quand un test A/B se termine, indiquez au skill quelle version a gagné. Il propose d'arrêter le test avec ce gagnant si le test est toujours actif. Ensuite, il suggère la prochaine hypothèse.

## Limites \{#limits\}

- **Pas d'analyse des prix pour l'instant** : le skill ne lit pas, ne compare pas et ne suggère pas de prix. Quand vos données pointent vers les prix, il l'indique et précise que l'analyse des prix n'est pas encore prise en charge.
- **Pas de résultats de test A/B** : le skill ne lit pas les résultats des tests A/B. Il déduit les tests passés à partir des paywalls qui ont tourné en parallèle, et compte sur vous pour indiquer quelle version a gagné.
- **Pas de dépenses publicitaires** : le skill peut ventiler les installations, les essais et les revenus par canal d'attribution, mais pas les dépenses ni le ROAS. Pour cela, utilisez le [skill adapty-attribution](developer-cli-attribution-skill).

Pour interroger vos analyses vous-même, sans le skill, consultez la [référence CLI analytics](developer-cli-analytics). Pour récupérer des analyses depuis un serveur ou une tâche planifiée, là où personne ne peut se connecter via un navigateur, utilisez l'[API Export Analytics](export-analytics-api) avec une clé API secrète.
