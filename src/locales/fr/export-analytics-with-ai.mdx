Le skill growth-advisor répond à la question « que devrais-je tester ensuite ? » à partir de vos propres chiffres d'abonnement. Votre outil de codage IA lit vos analytics, prix, placements, flows et tests A/B passés, évalue chaque partie de votre business par rapport au marché, et vous retourne une courte liste d'hypothèses classées selon les revenus que chacune met en jeu. Quand vous en choisissez une, le skill crée tout ce dont le test A/B a besoin et configure le test.

:::note
growth-advisor ne modifie rien dans votre compte sans votre accord. Toutes les lectures sont en lecture seule, et chaque écriture — une copie de flow, un segment, un produit, un prix, un test A/B, une modification de placement — attend votre confirmation.
:::

## Ce que vous pouvez demander \{#what-you-can-ask\}

Posez vos questions comme vous le feriez avec un collègue. Inutile de nommer le skill :

```
Audit my app. What should I test next to grow revenue?

Revenue dropped last month. Why?

Is our annual plan too cheap in Germany?

My A/B test on the onboarding paywall ended. What now?

Where do users leave our onboarding?

I have three ideas: a weekly plan, a trial on annual, and a second placement.
Which one should I test first?

Which country refunds the most, and do people who start a trial renew better?

Here's our App Store link. Where are we losing money?
```

Une question sur vos chiffres obtient une réponse basée sur vos chiffres, sans audit joint. Une application sans données encore obtient un plan de départ construit à partir des médianes du marché issues du rapport State of Paywalls 2026 d'Adapty, avec chaque chiffre étiqueté comme une estimation.

## Avant de commencer \{#before-you-start\}

- **Un compte Adapty avec des données** : le skill lit les mêmes analytics que votre tableau de bord. Sans données, il vous fournit un plan de départ. Sans compte, il travaille à partir de ce que vous lui envoyez (voir [Sans compte Adapty](#without-an-adapty-account)).
- **Un outil IA connecté à votre compte Adapty** : le skill fonctionne via le [CLI Adapty](developer-cli-analytics) ou le [serveur Adapty MCP](adapty-mcp). Il préfère le CLI, car l'audit effectue ses lectures via celui-ci. Utilisez un agent de code tel que Claude Code, Codex, Copilot CLI ou Gemini CLI, ou bien claude.ai, où le CLI nécessite une [configuration à chaque conversation](developer-cli-cowork). Avec MCP uniquement, le skill propose de configurer le CLI ; si vous refusez, il effectue les lectures via MCP et indique celles qui n'ont pas pu s'exécuter.

## Comment fonctionne l'audit \{#how-the-audit-works\}

Quand vous demandez quoi faire sans poser de question précise, le skill lance un audit. Il examine l'ensemble de l'activité sur les six derniers mois, pas uniquement ce qui a changé récemment : une faiblesse persistante coûte plus cher qu'un simple creux récent.

1. **Comment votre application génère des revenus** : le skill identifie le store qui rapporte le plus, votre marché principal, votre produit phare par chiffre d'affaires, et ce que chaque placement affiche actuellement.
2. **Ce que vous avez déjà testé** : le skill liste vos tests A/B passés sur les paywalls et flows avec leurs dates, audiences et résultats, et repère les paywalls qui ont tourné en parallèle sans test. Pas besoin de ressaisir votre historique de tests ; la réponse les énonce comme des faits, vous n'avez qu'à corriger ce qui est inexact.
3. **Un tableau de bord** : le skill évalue chaque aspect de votre activité comme fort, dans la moyenne, ou faible : d'où vient l'argent, l'entonnoir de l'installation au paiement, la répartition des formules, les renouvellements, les remboursements et la configuration de vos placements. Les conversions sont comparées à la grille de référence du marché pour votre formule, région et catégorie d'après le State of Paywalls 2026 d'Adapty, et les renouvellements et remboursements d'après le State of In-App Subscriptions 2026 d'Adapty. Les points faibles sont classés par pertes mensuelles estimées en dollars.
4. **La cause** : le skill remonte le signal le plus fort par store, canal d'attribution, durée de formule, pays ou semaine jusqu'à ce qu'un groupe l'explique. Avant d'incriminer le trafic ou un changement précis, il vérifie les autres causes possibles.
5. **Les écrans** : avant de formuler le moindre avis sur un écran, le skill affiche le flow en direct et, pour un flow, lit son entonnoir pour trouver l'écran où les utilisateurs décrochent. Un paywall dessiné par votre application elle-même nécessite une capture d'écran. L'audit liste les captures d'écran dont il a besoin sous **Send me screenshots** et indique quelle hypothèse chacune permet de vérifier.

## Ce que vous obtenez en retour \{#what-you-get-back\}

Le skill répond avec une courte synthèse et le tableau de bord, puis une liste d'hypothèses regroupées par placement, dans l'ordre où les tester. Chaque hypothèse indique pourquoi votre application en a besoin, quel résultat attendre et d'où vient cette estimation, ce que le changement représente en dollars par mois, combien de temps le test A/B prendrait avec votre volume d'achats, et qui fait quoi. Une hypothèse peut cibler tous les utilisateurs d'un placement ou un [segment](segments) spécifique, comme les anciens abonnés.

## Prix \{#prices\}

Le skill lit le prix de chaque produit dans chaque pays et store, tel que le store le facture, en devise locale. Il compare ensuite chaque prix à l'indice de prix d'Adapty issu du rapport State of In-App Subscriptions : du 10e au 90e percentile pour votre catégorie et votre offre, dans 22 pays. Pour les autres pays, le skill compare avec la région ou avec l'historique du pays lui-même.

À partir de là, le skill peut suggérer ces hypothèses de prix dans la même liste que les autres :

- **Augmenter ou baisser le prix de base** de votre offre principale sur votre marché principal.
- **Augmenter ou baisser le prix dans un pays** dont le tarif est décalé par rapport à votre marché principal. Pour un écart sur un seul marché, le skill vérifie d'abord que le paywall est dans la langue de ce marché.
- **Modifier la hiérarchie des offres** lorsque le tarif annuel est trop élevé ou trop bas par rapport aux tarifs hebdomadaires ou mensuels.

Le skill ne suggère une hausse de prix que sur les marchés de niveau 1, comme les États-Unis, le Royaume-Uni, l'Allemagne ou le Japon : dans la bibliothèque de tests A/B d'Adapty, la même hausse s'est révélée perdante ailleurs. Le nouveau prix part du tarif actuel appliqué par le store et vise un point de prix familier aux acheteurs, comme 38,99 €. Le skill ne consulte pas les prix des concurrents.

Le test A/B s'exécute sur une copie du produit, pas sur le produit en production. Le skill crée la copie, la pousse vers le store, configure ses prix, construit la copie du flow qui la vend, et met en place un segment de pays ainsi que le test A/B. Un prix gagnant est ensuite appliqué au produit original. Les abonnés existants conservent leur prix, sauf si vous demandez à les migrer.

Pour modifier un prix en production sans test, demandez-le explicitement. Le skill sauvegarde les prix actuels dans un fichier pour permettre leur restauration, prévisualise les nouveaux prix et vous indique quand chaque store les applique.

:::warning
Les prix ne peuvent être lus que pour un store connecté à Adapty. Sur l'App Store, cela nécessite la [clé API App Store Connect](app-store-connection-configuration), et pas seulement la clé d'achat intégré.
:::

## De l'hypothèse au test A/B \{#from-hypothesis-to-ab-test\}

Pour chaque hypothèse, le skill propose un test A/B et offre de le configurer. Avant de procéder, il vérifie que tout ce dont le test a besoin existe, et indique ce qui manque et qui doit le créer :

| Le test nécessite | Qui le réalise |
|---|---|
| Un flow modifié : nouveau design, nouveaux textes ou nouvelle sélection de produits | Le skill crée une copie du flow via le [skill flow-generator](flow-generator-skill), avec un seul changement par hypothèse, afin que le test montre l'effet de cette modification. Avant de publier la copie, le skill propose de la vérifier avec le [skill flow-audit](flow-audit-skill). Un flow ne rejoint un test qu'une fois publié. |
| Une nouvelle durée de plan | Le skill crée le produit et le pousse vers App Store Connect et Google Play Console, après que vous ayez confirmé ses identifiants de produit en store et son prix en USD. |
| Une copie de produit pour un test de prix | Le skill crée la copie, la pousse et fixe ses prix. Vous approuvez le nouvel identifiant de produit en store. |
| Un essai ou une offre | Vous le créez dans App Store Connect ou Google Play Console. Sur l'App Store, un essai nécessite un nouveau produit ; sur Google Play, c'est une offre sur le plan existant. Une fois que vous donnez au skill l'identifiant d'offre du store, il ajoute l'offre au produit dans Adapty. |
| Un paywall à partir de produits déjà dans Adapty | Le skill le crée. |
| Un paywall avec un nouveau design | Vous le créez dans le [Paywall Builder](adapty-paywall-builder). |
| Un segment | Le skill le crée via le skill audiences. |
| Un nouveau placement | Le skill le crée après que vous ayez approuvé son identifiant développeur. Votre application nécessite une modification du code et une mise en production pour le récupérer. |

Chaque élément créé par le skill attend votre validation. Lorsqu'un élément est à votre charge, la liste **Next steps** du skill l'indique, et le skill configure le test dès que vous lui confirmez que l'élément est prêt. Il ne configure jamais un test avec un élément qui n'existe pas encore.

Une fois tous les éléments en place, le [skill ab-tests](ab-tests-skill) crée le test en tant que brouillon. Avant de le démarrer, il vous montre précisément qui voit quoi. Un [test A/B](ab-tests) est l'option par défaut, et le seul moyen de mesurer l'impact du changement.

Pour afficher le changement sans test, demandez-le. Le skill peut l'afficher sur un nouveau placement, ou pour certains ou tous les utilisateurs d'un placement existant. Avant de modifier un placement existant, le skill sauvegarde le placement dans un fichier pour vous permettre de le restaurer. Il nomme également tout test A/B qui s'exécute sur le placement. Le changement n'affecte pas ce test.

## Quand un test A/B se termine \{#when-an-ab-test-ends\}

Indiquez au skill qu'un test est terminé. Il retrouve le test, affiche les revenus et la probabilité d'être le meilleur pour chaque variante, puis vous demande quelle variante a gagné. La variante en tête n'est pas déclarée gagnante tant que vous ne le confirmez pas : avec moins d'environ 200 achats par variante, le test n'est pas encore concluant. Si le test est toujours actif, le skill propose de l'arrêter avec votre gagnant, puis suggère la prochaine hypothèse pour ce placement.

Tant qu'un test est en cours, le skill indique combien d'achats il manque à chaque variante pour atteindre environ 200, sans jamais révéler laquelle est en tête.

## Sans compte Adapty \{#without-an-adapty-account\}

Envoyez un lien App Store ou Google Play, le code de l'application, ou des captures d'écran de votre onboarding et de votre paywall, et demandez comment générer plus de revenus. Le skill répond en détail à partir de ce que vous avez envoyé, des médianes du marché et de la bibliothèque de tests A/B d'Adapty :

- **Un lien vers le store** : le skill lit la catégorie, les abonnements dans la liste des achats intégrés, les langues et ce que les avis disent sur le paiement.
- **Des captures d'écran** : le skill lit les durées des formules, la formule présélectionnée, l'essai gratuit et le bouton d'achat.
- **Le code de l'application** : le skill lit les identifiants de produits, les écrans de paywall et d'onboarding, leur contenu dans chaque langue et les autres endroits où le paywall s'ouvre.

La skill analyse les écrans avec les skills paywall-teardown et onboarding-teardown. Les prix et la conversion nécessitent vos propres chiffres, c'est pourquoi la dernière étape suivante propose de configurer Adapty dans l'application. Une fois la configuration effectuée, la prochaine réponse s'appuiera sur vos propres données.

## Limites \{#limits\}

- **Pas de données de dépenses publicitaires** : le skill peut répartir les installations, les essais et les revenus par canal d'attribution, mais pas les dépenses ni le ROAS. Pour cela, utilisez le [skill adapty-attribution](developer-cli-attribution-skill).
- **Pas de résultats pour certains types de tests** : le skill lit les résultats des tests A/B de paywalls et de flows classiques. Pour les tests portant sur plusieurs placements et les tests d'onboarding, il indique le nom du test et vous consultez les résultats dans le tableau de bord.
- **Pas de catégorie propre** : la catégorie de votre application n'est pas incluse dans vos données Adapty. Le skill la déduit du nom de l'application et du paywall, et vous indique laquelle il a utilisée pour que vous puissiez la corriger.

Pour interroger vos analyses vous-même, sans le skill, consultez la [référence CLI analytics](developer-cli-analytics). Pour récupérer des analyses depuis un serveur ou une tâche planifiée, là où personne ne peut se connecter via un navigateur, utilisez l'[API Export Analytics](export-analytics-api) avec une clé API secrète.
