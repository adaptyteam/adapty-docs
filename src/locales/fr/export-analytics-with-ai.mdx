Le skill growth-advisor répond à la question « que devrais-je tester ensuite ? » à partir de vos propres chiffres d'abonnement. Votre outil de codage IA lit vos analyses, placements, paywalls et produits via l'[Adapty CLI](developer-cli-analytics), suit le signal le plus fort jusqu'à sa cause, et renvoie une liste courte d'hypothèses à tester en A/B, classées par le nombre d'achats en jeu.

:::note
growth-advisor ne modifie rien dans votre compte sans votre accord. Chaque lecture d'analyse est en lecture seule, et chaque écriture — une nouvelle copie de flow, un nouveau segment, un changement de placement — attend votre confirmation.
:::

## Ce que vous pouvez demander \{#what-you-can-ask\}

Posez vos questions comme vous le feriez avec un collègue. Inutile de nommer le skill :

```
Audit my app. What should I test next to grow revenue?

Revenue dropped last month. Why?

My A/B test on the onboarding paywall ended and the new version won. What now?

I have three ideas: a weekly plan, a trial on annual, and a second placement.
Which one should I test first?

Which country refunds the most, and do people who start a trial renew better?

We launch next month and have no data yet. Where should we start?
```

Une question sur vos chiffres obtient une réponse à partir de vos chiffres, sans audit joint. Une application sans données reçoit un plan de départ construit à partir des médianes du marché issues du rapport State of Paywalls 2026 d'Adapty, avec chaque chiffre identifié comme une estimation.

## Avant de commencer \{#before-you-start\}

- **Un compte Adapty avec des données** : le skill lit les mêmes analyses que votre tableau de bord. Sans données, il ne peut que vous proposer un plan de départ.
- **Un outil IA capable d'exécuter des commandes en terminal** : par exemple Claude Code, Codex, Copilot CLI ou Gemini CLI. Les outils de chat comme claude.ai ou ChatGPT ne peuvent pas exécuter la CLI, donc ils n'ont pas accès à votre compte Adapty.

## Installer le skill \{#install-the-skill\}

growth-advisor fait partie du [plugin `adapty-skills`](https://github.com/adaptyteam/adapty-skills). Pour installer le plugin, exécutez dans votre terminal :

```bash
npx adapty skills install
```

Redémarrez votre agent pour charger les skills. Pour d'autres méthodes d'installation, consultez le [README du plugin](https://github.com/adaptyteam/adapty-skills/blob/main/plugin/README.md#install).

## Comment fonctionne l'audit \{#how-the-audit-works\}

Quand vous demandez quoi faire sans question précise, le skill lance un audit. Il lit vos chiffres et la configuration de vos placements, identifie ce que vous avez déjà testé, et remonte la variation la plus significative jusqu'au store, au canal, au pays ou au placement qui l'explique. Avant de dire quoi que ce soit sur un écran, il examine le flow en production, ou vous demande une capture d'écran d'un paywall que votre app affiche elle-même.

## Ce que vous obtenez en retour \{#what-you-get-back\}

Le skill répond par une courte synthèse, puis une liste d'hypothèses regroupées par placement, dans l'ordre où les tester. Chaque hypothèse explique pourquoi votre application en a besoin, le résultat attendu et l'origine de cette estimation, la durée nécessaire pour le test A/B, et qui fait quoi. Une hypothèse peut cibler tous les utilisateurs d'un placement ou un [segment](segments) spécifique, comme d'anciens abonnés.

C'est vous qui choisissez par quelle hypothèse commencer. En cas de doute, le skill indique son propre choix et en explique la raison. Le skill ne conserve aucun backlog, donc sauvegardez la réponse si vous souhaitez revenir aux autres hypothèses plus tard.

## De l'hypothèse au test A/B \{#from-hypothesis-to-ab-test\}

Une fois l'hypothèse choisie, le skill met en place les éléments accessibles via la CLI, après confirmation de votre part :

- **Un nouveau design de flow ou un nouvel ensemble de produits** : Le skill crée une copie du flow via le [skill flow-generator](flow-generator-skill), avec un seul changement par hypothèse, afin que le test A/B montre l'impact de cette modification. Avant de publier la copie, il propose de la faire auditer par le [skill flow-audit](flow-audit-skill).
- **Une audience différente** : Le skill crée le segment et ajoute son audience au placement via le skill `audiences`.

Vous choisissez ensuite comment les utilisateurs reçoivent ce changement. Un [test A/B](ab-tests) dans le tableau de bord est l'option par défaut, et le seul moyen de mesurer l'impact de la modification. Vous pouvez aussi l'afficher immédiatement, via un nouveau placement ou auprès d'une partie ou de la totalité des utilisateurs d'un placement existant.

Avant que le skill modifie un placement existant, il enregistre le placement dans un fichier afin que vous puissiez l'annuler, et il vous demande si un test A/B est en cours à cet endroit. La CLI ne peut pas voir les audiences des tests A/B, et une mise à jour de placement remplace toutes les audiences — un test en cours serait donc supprimé sans erreur. Avant de confirmer, ouvrez la page du placement dans le tableau de bord pour vérifier si un test est en cours.

Nouveaux plans, essais et tests A/B, tout reste entre vos mains. Pour chacun, le skill vous indique les étapes à suivre dans App Store Connect, Google Play Console ou l'Adapty Dashboard. Sur l'App Store, un essai nécessite un nouveau produit ; sur Google Play, c'est une offre sur le plan existant. Vous fixez le prix de tout nouveau produit.

Quand un test A/B se termine, indiquez au skill ce qui a été testé et ce qui a gagné. Il vous suggère la prochaine hypothèse à partir de là.

## Limites \{#limits\}

- **Pas d'analyse de prix** : Le skill ne lit pas, ne compare pas et ne suggère pas de prix. Quand vos données pointent vers le prix, il le signale et indique que l'analyse de prix n'est pas encore prise en charge.
- **Pas d'historique de tests A/B** : La CLI ne retourne pas les résultats des tests A/B passés. Le skill déduit les tests précédents à partir des paywalls qui ont été diffusés simultanément, et compte sur vous pour indiquer quelle version a gagné.
- **Pas de données de dépenses publicitaires** : Le skill peut ventiler les installations, les essais et les revenus par canal d'attribution, mais pas les dépenses ni le ROAS. Pour cela, utilisez le [skill adapty-attribution](developer-cli-attribution-skill).

Pour interroger vos analyses vous-même, sans le skill, consultez la [référence CLI analytics](developer-cli-analytics). Pour récupérer des analyses depuis un serveur ou une tâche planifiée, là où personne ne peut se connecter via un navigateur, utilisez l'[API Export Analytics](export-analytics-api) avec une clé API secrète.
