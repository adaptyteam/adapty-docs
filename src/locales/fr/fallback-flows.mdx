Pour maintenir une expérience utilisateur fluide, il est important de configurer des **versions de secours** de vos [flows](adapty-flow-builder).

Lorsque votre application demande un flow, le SDK Adapty contacte nos serveurs pour en récupérer la configuration. Si le SDK ne parvient pas à obtenir le flow depuis l'API principale d'Adapty (problème réseau, panne serveur), il se rabat sur d'autres sources :

- Si l'utilisateur a déjà vu le flow une fois, le SDK sert la copie en cache.
- Si l'API principale d'Adapty ne répond pas, le SDK demande le flow à un serveur de secours Adapty.
- Si aucune des deux options ne fonctionne, le SDK charge un fichier de configuration de secours inclus dans l'application.

:::important
Le serveur de sauvegarde et le fichier de secours servent uniquement l'audience **All Users** et ignorent les segments. Si vous divisez les audiences par plateforme, utilisez des produits contenant à la fois des identifiants App Store et Google Play dans le flow All Users. Sinon, le flow de secours n'aura aucun produit pour les utilisateurs de l'autre store.
:::

Adapty génère automatiquement ces fichiers de secours. Le bundle de secours du flow est partagé avec les paywalls — un seul fichier JSON par plateforme contient les variantes de secours pour les deux. Le SDK lit la section dont il a besoin.

:::important
Les fallbacks de flow sont inclus dans le bundle **Adapty SDK 4.0+**. Si vous sélectionnez une version antérieure du SDK dans la fenêtre de téléchargement, le fichier ne contient que des variantes de paywall et d'onboarding — sans flows. Assurez-vous que votre application utilise une version du SDK compatible avec les flows avant de vous appuyer sur un fallback de flow.
:::

## Avant de commencer \{#before-you-start\}

1. Créez un [flow](adapty-flow-builder) dans le Flow & Paywall Builder.
2. [Créez un placement](create-placement) pour le flow.

## Télécharger le fichier de secours \{#download-the-fallback-file\}

1. Ouvrez la page **[Placements](https://app.adapty.io/placements)**.
2. Cliquez sur le bouton **Fallbacks** en haut à droite.
3. Sélectionnez votre plateforme cible dans le menu déroulant.
4. Sélectionnez l'option correspondant à la version du SDK Adapty dans votre application, par exemple **Adapty SDK v4.4.0 and higher**.

Le navigateur télécharge un fichier JSON par plateforme — par exemple, `ios_4_0_0_fallback.json`.

:::tip
Pour télécharger le fichier depuis le terminal, utilisez la [CLI développeur](developer-cli). Indiquez la version du SDK Adapty avec laquelle votre application est compilée :

```bash
adapty fallbacks get --app <app-id> --platform ios --sdk-version <sdk-version> --output ios_fallback.json
```

Exécutez cette commande une fois par store, avec `--platform ios` ou `--platform android`. Consultez [`adapty fallbacks get`](developer-cli-fallbacks) pour les options disponibles.
:::

## Après le téléchargement \{#after-the-download\}

Ajoutez le fichier à votre code applicatif, puis suivez le guide de configuration propre à votre plateforme. Les mêmes APIs qui chargent les paywalls de secours chargent également les flows de secours dès lors que votre application utilise une version du SDK compatible avec les flows :

- [iOS](ios-use-fallback-paywalls)
- [Android](android-use-fallback-paywalls)
- [React Native](react-native-use-fallback-paywalls)
- [Flutter](flutter-use-fallback-paywalls)
- [Unity](unity-use-fallback-paywalls)
- [Kotlin Multiplatform](kmp-use-fallback-paywalls)
- [Capacitor](capacitor-use-fallback-paywalls)

## Limitations \{#limitations\}

Les flows de secours sont codés en dur et stockés localement, ils ne bénéficient donc pas de toutes les capacités dynamiques des flows en direct :

- **Une audience par placement.** Si un placement comporte plusieurs [audiences](audience), le fichier de secours n'utilise que l'audience **All users**.
- **Pas de tests A/B en cours.** Si l'audience **All users** exécute un test A/B, le fichier contient toutes les variantes du test avec leurs poids respectifs. Le SDK répartit les utilisateurs entre ces variantes selon leur poids. Pour mettre à jour le fichier de secours après avoir arrêté le test, téléchargez le fichier à nouveau et ajoutez-le à une nouvelle version de l'application.
- **Pas de tests A/B Crossplacement.** Le fichier de secours n'inclut jamais un [test A/B Crossplacement](ab-test-types), même s'il s'exécute sur l'audience **All users**. Pour un placement faisant partie d'un tel test, le fichier contient le contenu **All users** habituel du placement : son flow ou son test A/B classique.
- **Pas de mises à jour à distance.** Mettre à jour le fichier de secours nécessite une nouvelle version de l'application. Pour les mises à jour à l'exécution que vous effectueriez normalement via Remote Config, envoyez-les plutôt via le flow en direct.
