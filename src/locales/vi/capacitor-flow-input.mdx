Khi người dùng nhập vào trường input, trả lời câu hỏi trắc nghiệm, hoặc bật/tắt một toggle trong một [flow](adapty-flow-builder), SDK sẽ truyền giá trị đó đến ứng dụng của bạn thông qua analytics callback.

Các ứng dụng thường sử dụng dữ liệu đó để:

- **Đăng ký người dùng trên backend riêng**: Lấy địa chỉ email và tên người dùng đã nhập trong flow onboarding, rồi tạo tài khoản cho họ khi flow đóng lại.
- **Lưu câu trả lời và tùy chọn**: Theo dõi những gì người dùng đã chọn để ứng dụng có thể sử dụng sau — ví dụ, [ghi vào hồ sơ người dùng Adapty](capacitor-setting-user-attributes) dưới dạng các thuộc tính tùy chỉnh.
- **Tùy chỉnh các flow sau**: Lưu câu trả lời từ quiz dưới dạng thuộc tính tùy chỉnh, rồi nhắm mục tiêu một placement sau để mỗi phân khúc nhận được một flow khác nhau, hoặc một paywall khác bên trong đó.
- **Chuyển dữ liệu sang nền tảng analytics bên thứ ba**: Chuyển tiếp câu trả lời đến Amplitude, Mixpanel, hoặc bất kỳ nền tảng product analytics nào bạn đang sử dụng.

Các input và nhóm có thể chọn tự động báo cáo giá trị của chúng. Để phân biệt các input trong code của bạn, hãy đặt cho mỗi input một **Element ID** có ý nghĩa và mỗi nhóm có thể chọn một **Group ID** trong builder.

## Nhận giá trị đầu vào \{#receive-input-values\}

Giá trị đầu vào được gửi đến cùng một handler như mọi sự kiện analytics khác từ một flow, với tên sự kiện là `flow_user_input`. Đăng ký `onAnalytics` cùng với các handler sự kiện flow khác của bạn:

```typescript showLineNumbers title="Capacitor"
view.setEventHandlers({
  onAnalytics(name, params) {
    handleFlowInput(name, params);
    return false; // keep the flow open
  },
});
```

Callback `onAnalytics` truyền tất cả các sự kiện analytics từ một flow, bao gồm cả [lượt xem màn hình](capacitor-flow-screen-views).
- Tham số `name` chứa tên sự kiện. Để lọc các sự kiện nhập liệu của người dùng, hãy so sánh `name` với `flow_user_input`.
- Tham số `element_type` cho biết danh mục của phần tử.
- Giá trị đầu vào được lưu ở các tham số khác nhau tùy theo loại phần tử:
     - Text field, picker và toggle lưu dữ liệu nhập của người dùng trong `value`
     - Nhóm có thể chọn (selectable group) báo cáo các tùy chọn đang được chọn trong `item_ids` và `item_titles`

```typescript showLineNumbers title="Capacitor"
function handleFlowInput(name: string, params: Record<string, unknown>) {
  if (name !== 'flow_user_input') return;

  // The screen the input sits on. Pair it with element_id to tell apart
  // two fields that share an Element ID on different screens.
  const screenId = params.instanceId as string;

  switch (params.element_type) {
    case 'text_input':
    case 'email_input':
    case 'number_input':
    case 'phone_input': {
      const text = params.value as string;
      break;
    }
    case 'date_picker':
    case 'time_picker':
    case 'date_time_picker': {
      // Unix time in milliseconds.
      const date = new Date(params.value as number);
      break;
    }
    case 'single_choice': {
      const optionId = (params.item_ids as string[])[0];
      break;
    }
    case 'multi_choice': {
      const optionIds = params.item_ids as string[];
      break;
    }
    case 'toggle': {
      const isOn = params.value as boolean;
      break;
    }
  }
}
```

## Gửi dữ liệu và những hạn chế \{#delivery-and-limitations\}

<FlowInputLimitations />

Lưu từng giá trị đầu vào khi handler nhận được, rồi gửi toàn bộ dữ liệu khi flow đóng lại. Để bắt được thời điểm đó, hãy đăng ký handler `onDisappeared` cùng với `onAnalytics`. Handler này chạy khi view của flow bị đóng, dù người dùng hoàn thành flow hay thoát ra giữa chừng.

## Các trường hợp sử dụng \{#use-cases\}

### Đăng ký người dùng trên backend của bạn \{#register-users-on-your-backend\}

Thu thập các giá trị khi chúng xuất hiện và gửi chúng đi một lần sau khi flow đóng lại, để một request duy nhất mang đầy đủ tất cả các câu trả lời.

Flow sẽ biến mất dù người dùng đã hoàn thành hay bỏ dở giữa chừng. Hãy kiểm tra các trường bạn cần trước khi gọi backend.

Flow không thể hiển thị lỗi từ backend của bạn. Giá trị trả về của handler chỉ đóng view flow lại, và SDK không có phương thức nào gửi dữ liệu vào một flow đang chạy. Nếu việc đăng ký thất bại, ví dụ như do email đã được sử dụng, hãy hiển thị lỗi trong giao diện của chính bạn sau khi flow đóng lại.

```typescript showLineNumbers title="Capacitor"
const flowAnswers: Record<string, string> = {};

view.setEventHandlers({
  onAnalytics(name, params) {
    if (name === 'flow_user_input' && typeof params.value === 'string') {
      flowAnswers[params.element_id as string] = params.value;
    }
    return false;
  },
  onDisappeared() {
    if (flowAnswers.email) {
      // Send flowAnswers to your backend here to create the account.
    }
    return false;
  },
});
```

### Làm phong phú thêm hồ sơ người dùng với dữ liệu \{#enrich-user-profiles-with-data\}

Để liên kết thông tin người dùng đã nhập vào hồ sơ của họ và tránh hỏi lại những thông tin đã có, hãy [cập nhật hồ sơ người dùng](capacitor-setting-user-attributes) ngay khi nhận được giá trị.

Ví dụ: nếu flow của bạn có ô nhập văn bản với Element ID là `name` và ô nhập email với Element ID là `email`:

```typescript showLineNumbers title="Capacitor"
function handleFlowInput(name: string, params: Record<string, unknown>) {
  if (name !== 'flow_user_input') return;
  if (typeof params.value !== 'string') return;

  const profileParams: Partial<AdaptyProfileParameters> = {};

  switch (params.element_id) {
    case 'name':
      profileParams.firstName = params.value;
      break;
    case 'email':
      profileParams.email = params.value;
      break;
    default:
      return;
  }

  adapty.updateProfile(profileParams).catch((error) => {
    // handle the error
  });
}
```

### Tùy chỉnh các flow được hiển thị sau này \{#customize-flows-shown-later\}

Câu trả lời trong quiz cũng có thể quyết định những gì người dùng thấy ở một [placement](placements) sau — một flow khác, hoặc một paywall khác bên trong nó.

Ví dụ: hỏi người dùng về kinh nghiệm tập thể thao của họ trong flow onboarding, sau đó hiển thị cho mỗi nhóm một flow riêng với các sản phẩm và nội dung khác nhau.

1. Thêm một [quiz](onboarding-quizzes) vào flow của bạn. Đặt [nhóm có thể chọn](flow-selectable-elements) với Group ID là `experience`, và mỗi tùy chọn có một Element ID có ý nghĩa.
2. Xử lý các câu trả lời và [thiết lập thuộc tính tùy chỉnh](capacitor-setting-user-attributes) cho người dùng.

```typescript showLineNumbers title="Capacitor"
function handleFlowInput(name: string, params: Record<string, unknown>) {
  if (name !== 'flow_user_input') return;
  if (params.element_id !== 'experience') return;

  const optionId = (params.item_ids as string[])[0];

  adapty
    .updateProfile({
      // Set the custom attribute 'experience' to the option the user selected
      // (beginner, amateur, or pro).
      codableCustomAttributes: { experience: optionId },
    })
    .catch((error) => {
      // handle the error
    });
}
```

3. [Tạo một phân khúc](segments) cho mỗi giá trị thuộc tính tùy chỉnh.
4. Tạo một [placement](placements) và thêm một [đối tượng](audience) cho mỗi phân khúc.
5. [Hiển thị flow](capacitor-present-paywalls) cho placement đó trong ứng dụng của bạn.
