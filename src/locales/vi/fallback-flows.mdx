Để duy trì trải nghiệm người dùng mượt mà, bạn cần thiết lập **phiên bản dự phòng** cho các [flow](adapty-flow-builder) của mình.

Khi ứng dụng của bạn yêu cầu một flow, SDK Adapty sẽ liên hệ với máy chủ của chúng tôi để lấy cấu hình của nó. Nếu SDK không thể lấy flow từ API Adapty chính (sự cố mạng, máy chủ gián đoạn), nó sẽ chuyển sang các nguồn khác:

- Nếu người dùng đã xem flow đó một lần rồi, SDK sẽ phục vụ bản sao đã được lưu trong cache.
- Nếu API Adapty chính không phản hồi, SDK sẽ yêu cầu flow từ máy chủ dự phòng của Adapty.
- Nếu cả hai đều không hoạt động, SDK sẽ tải tệp cấu hình dự phòng được đóng gói bên trong ứng dụng.

:::important
Máy chủ dự phòng và file dự phòng chỉ phục vụ đối tượng **All Users** và bỏ qua các phân khúc. Nếu bạn chia đối tượng theo nền tảng, hãy sử dụng các sản phẩm có cả ID App Store và Google Play trong flow All Users. Nếu không, flow dự phòng sẽ không có sản phẩm nào cho người dùng của cửa hàng còn lại.
:::

Adapty tự động tạo các file dự phòng này. Gói dự phòng của flow được chia sẻ chung với các paywall — một file JSON duy nhất cho mỗi nền tảng chứa các biến thể dự phòng cho cả hai. SDK sẽ đọc phần nào cần thiết tương ứng.

:::important
Flow fallback được tích hợp trong gói **Adapty SDK 4.0+**. Nếu bạn chọn phiên bản SDK cũ hơn trong hộp thoại tải xuống, file sẽ chỉ chứa các biến thể paywall và onboarding — không có flow. Hãy đảm bảo ứng dụng của bạn đang dùng phiên bản SDK hỗ trợ flow trước khi sử dụng flow fallback.
:::

## Trước khi bắt đầu \{#before-you-start\}

1. Tạo một [flow](adapty-flow-builder) trong Flow & Paywall Builder.
2. [Tạo một placement](create-placement) cho flow.

## Tải xuống file fallback \{#download-the-fallback-file\}

1. Mở trang **[Placements](https://app.adapty.io/placements)**.
2. Nhấn nút **Fallbacks** ở góc trên bên phải.
3. Chọn nền tảng mục tiêu từ danh sách thả xuống.
4. Chọn tùy chọn phù hợp với phiên bản Adapty SDK trong ứng dụng của bạn, chẳng hạn như **Adapty SDK v4.4.0 and higher**.

Trình duyệt sẽ tải xuống một file JSON cho mỗi nền tảng — ví dụ: `ios_4_0_0_fallback.json`.

:::tip
Để tải file từ terminal thay vì trình duyệt, hãy dùng [Developer CLI](developer-cli). Truyền vào phiên bản Adapty SDK mà ứng dụng của bạn đang sử dụng:

```bash
adapty fallbacks get --app <app-id> --platform ios --sdk-version <sdk-version> --output ios_fallback.json
```

Chạy một lần cho mỗi cửa hàng, với `--platform ios` hoặc `--platform android`. Xem [`adapty fallbacks get`](developer-cli-fallbacks) để biết các flag.
:::

## Hạn chế \{#limitations\}

Các flow dự phòng được mã hóa cứng và lưu trữ cục bộ, do đó chúng không mang đầy đủ khả năng động của các flow trực tiếp:

- **Mỗi placement chỉ có một đối tượng.** Nếu một placement có nhiều [đối tượng](audience), file dự phòng chỉ sử dụng đối tượng **All users**.
- **Không có A/B test đang chạy.** Nếu đối tượng **All users** đang chạy một A/B test, file sẽ chứa tất cả các biến thể của test đó kèm theo trọng số tương ứng. SDK phân chia người dùng vào các biến thể này theo trọng số. Để cập nhật file dự phòng sau khi dừng test, hãy tải file xuống lại và thêm vào bản phát hành ứng dụng mới.
- **Không có Crossplacement A/B test.** File dự phòng không bao giờ bao gồm [Crossplacement A/B test](ab-test-types), kể cả test đang chạy trên đối tượng **All users**. Đối với placement trong test đó, file sẽ chứa nội dung **All users** thông thường của placement: flow hoặc A/B test thông thường của nó.
- **Không có cập nhật từ xa.** Việc cập nhật file dự phòng yêu cầu phát hành ứng dụng mới. Với các cập nhật runtime mà bạn thường thực hiện qua Remote Config, hãy đẩy chúng thông qua flow trực tiếp.
