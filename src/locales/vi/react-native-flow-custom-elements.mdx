## Trước khi bắt đầu \{#before-you-start\}

:::important
Trong một dự án Expo, các phần tử tùy chỉnh chỉ hoạt động nếu bạn giữ các thư mục `ios` và `android` trong Git và không chạy `npx expo prebuild --clean`. Nếu không, Expo sẽ tái tạo các thư mục này và xóa mã từ trang này. Các dự án Expo mới giữ các thư mục này ngoài Git, vì vậy EAS Build sẽ tái tạo chúng cho mỗi lần build.
:::

Bạn cần:

- **Adapty React Native SDK 4.4 trở lên**: Các phiên bản cũ hơn sẽ hiển thị paywall dự phòng cho mọi custom element.
- **Code native cho iOS và Android**: Bạn không thể hiển thị component React Native trong custom element. Hãy viết code này bằng Swift cho iOS và Kotlin cho Android. Thêm code Swift vào app target trong Xcode, và code Kotlin vào thư mục chứa `MainApplication.kt`. Bắt đầu mỗi file Kotlin mới bằng dòng `package` của `MainApplication.kt`.
- **Quy tắc đặt tên cho custom element**: Đặt cho mỗi native view một Type, ví dụ như `lottie_animation`. Chỉ dùng chữ thường, số và dấu gạch dưới trong Type. Để phân biệt các custom element cùng Type, đặt cho mỗi cái một ID, ví dụ như `welcome_wave`. Các Type và ID trong code của bạn phải khớp với những gì đã cấu hình trong [Flow & Paywall Builder](flow-custom-elements#add-and-configure).

Sử dụng cùng một Types và IDs trong code iOS và Android của bạn. Trừ khi bạn thiết lập một [đối tượng](audience) riêng cho từng nền tảng, người dùng iOS và Android sẽ thấy các flow giống nhau.

## Thiết lập dự án Android của bạn \{#set-up-your-android-project\}

Dự án iOS của bạn không cần thiết lập thêm gì. Trong dự án Android, hãy thêm thư viện Adapty UI. Để xây dựng native views dưới dạng composable, hãy thiết lập thêm Jetpack Compose.

### Thêm thư viện Adapty UI

Trong `android/app/build.gradle`, thêm `io.adapty:android-ui` vào block `dependencies`, không kèm phiên bản. `react-native-adapty` sẽ tự thiết lập phiên bản. Nếu chỉ định phiên bản `android-ui` khác có thể làm hỏng các flow.

```groovy showLineNumbers title="android/app/build.gradle"
dependencies {
    implementation("io.adapty:android-ui")
}
```

Thư viện này yêu cầu `compileSdkVersion` 35 trở lên: nếu `android/build.gradle` đang đặt phiên bản thấp hơn, hãy nâng lên 35.

### Thiết lập Jetpack Compose \{#set-up-jetpack-compose\}

Template React Native không [thiết lập Compose](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler) trong module app. Một Android `View` không cần thiết lập Compose. Để xây dựng native view dưới dạng composable, hãy thiết lập Compose compiler phù hợp với phiên bản Kotlin của app, tức là `kotlinVersion` trong `android/build.gradle`:

<Tabs groupId="kotlin-version" queryString>
<TabItem value="kotlin-2" label="Kotlin 2.0 and later" default>

Các template của React Native 0.77 trở lên sử dụng Kotlin 2.0 hoặc cao hơn. Thêm plugin Compose compiler Gradle vào dependencies của `buildscript`:

```groovy showLineNumbers title="android/build.gradle"
buildscript {
    dependencies {
        classpath("org.jetbrains.kotlin:compose-compiler-gradle-plugin:$kotlinVersion")
    }
}
```

Sau đó áp dụng plugin vào module app và đặt `compose true` trong block `buildFeatures`:

```groovy showLineNumbers title="android/app/build.gradle"
apply plugin: "org.jetbrains.kotlin.plugin.compose"

android {
    buildFeatures {
        compose true
    }
}
```

</TabItem>
<TabItem value="kotlin-1-9" label="Kotlin 1.9">

Các template của React Native 0.75 và 0.76 sử dụng Kotlin 1.9. Trong block `android`, hãy đặt `compose true` và phiên bản Compose compiler tương thích với phiên bản Kotlin của bạn. React Native 0.75 và 0.76 build với Kotlin 1.9.24, cần Compose compiler 1.5.14. Với các phiên bản Kotlin khác, xem [bảng tương thích Compose và Kotlin](https://developer.android.com/jetpack/androidx/releases/compose-kotlin).

```groovy showLineNumbers title="android/app/build.gradle"
android {
    buildFeatures {
        compose true
    }
    composeOptions {
        kotlinCompilerExtensionVersion "1.5.14"
    }
}
```

### Yêu cầu và các phương pháp tốt nhất \{#requirements-and-best-practices\}

- **Kích thước**:
  - **Padding và căn chỉnh**: Đảm bảo native view vừa khít với container bạn đã phân bổ trong Flow & Paywall Builder, trừ đi padding. Nếu view không chiếm toàn bộ khu vực đó, nó sẽ xuất hiện ở góc trên bên trái theo mặc định. Để di chuyển nó, thay đổi căn chỉnh trong phần **Layout** của custom element.
  - **Chiều cao Hug**: Nếu chiều cao của custom element được đặt thành **Hug**, một view kéo giãn để lấp đầy không gian có sẵn (như bản đồ hoặc lazy list) sẽ bị thu gọn hoặc kéo giãn đến chiều cao của màn hình. Hãy đặt [chiều cao **Fixed**](flow-custom-elements#add-and-configure) cho custom element thay thế.
- **Theme**: Native view không kế thừa styles của các React Native component. Hãy đặt màu sắc và font trong code native.
- **Flow action**: Native view không thể chạy các flow action, chẳng hạn như chuyển sang màn hình tiếp theo. Element context có thể gửi tin nhắn đến flow, với `sendMessage` trên iOS và `send` trên Android, nhưng chúng được dành cho các tính năng Flow & Paywall Builder trong tương lai. Hãy để các nút điều hướng, nút mua hàng và các nút khác có flow action bên ngoài custom element.
- **Phần tử có thể chọn**: Giữ custom element bên ngoài các thẻ sản phẩm và các [phần tử có thể chọn](flow-selectable-elements) khác. Khi lựa chọn thay đổi, native view có thể mất trạng thái của nó.
- **Xử lý điều hướng**: Khi người dùng chuyển sang màn hình tiếp theo, SDK xóa native view khỏi màn hình. Hãy dừng những gì view đã khởi động, chẳng hạn như camera session, player và cập nhật vị trí:
  - **SwiftUI view**: Sử dụng action `onDisappear`. Với các tác vụ bất đồng bộ, dùng `.task`: SwiftUI hủy nó khi view biến mất.
  - **Composable**: Sử dụng block `onDispose` của `DisposableEffect`. Với các tác vụ bất đồng bộ, dùng `LaunchedEffect`: Compose hủy nó khi composable rời khỏi composition.
  - **Android `View`**: Override `onDetachedFromWindow` trong subclass `View` của bạn, hoặc thêm `View.OnAttachStateChangeListener` vào `View`.

  Khi người dùng quay lại, SDK sẽ gọi resolver lại và native view bắt đầu mà không có trạng thái của view trước đó. Trên Android, trong một flow mà bạn mở bằng `present()`, việc xoay màn hình sẽ khiến SDK gọi resolver lại. Trong một `AdaptyFlowView` nhúng, native view vẫn giữ nguyên trạng thái sau khi xoay màn hình.
- **UIKit views**: Trên iOS, hãy bọc chúng trong `UIViewRepresentable`.
- **Carousels**: Trên Android, trong một [carousel](builder-containers#carousel), các native view trên tất cả các slide đều giữ trạng thái hoạt động trong khi màn hình đang mở, không chỉ view trên slide đang hiển thị. Hãy tránh đặt camera preview và trình phát có âm thanh vào trong carousel.

## Viết resolver để khớp các phần tử tùy chỉnh với view \{#write-a-resolver-to-match-custom-elements-and-views\}

Viết một resolver cho từng nền tảng. Resolver nhận vào Type và ID của một phần tử tùy chỉnh, rồi trả về view native tương ứng.

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

Để viết một resolver, hãy cho một type tuân theo protocol `AdaptyUICustomElementsResolver` và implement phương thức `view(forType:id:context:)`.

Với Type `lottie_animation`, resolver sau đây trả về `LottieElementView`. ID là tên file animation trong app bundle, chẳng hạn như `welcome_wave`:

```swift showLineNumbers title="Swift"

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "lottie_animation":
            // the ID names the animation file, such as welcome_wave.json
            guard let animation = LottieAnimation.named(id) else {
                return nil // no file for this ID: show the fallback
            }
            return AnyView(LottieElementView(animation: animation))
        default:
            return nil
        }
    }
}
```

Trong trường hợp `default`, trả về `nil`.

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

Để viết resolver, hãy implement interface `AdaptyCustomElementsResolver`. Phương thức `resolve` của nó trả về view phù hợp theo một trong các dạng sau:

- **Một composable**: Trả về `AdaptyCustomElementContent.compose`, với composable bên trong lambda của nó.
- **Một `View` Android**: Trả về `AdaptyCustomElementContent.view`, với một hàm tạo `View`. Đặt tên cho tham số `factory`: `AdaptyCustomElementContent.view(factory = { context, _ -> ChartView(context) })`. Nếu không đặt tên, Kotlin sẽ truyền trailing lambda vào tham số `update` tùy chọn và code sẽ không biên dịch được.

Đối với Loại `lottie_animation`, resolver sau đây trả về [Lottie view](#create-views-for-custom-elements). ID đặt tên cho tệp animation trong thư mục `assets`, `android/app/src/main/assets`, chẳng hạn như `welcome_wave` cho `welcome_wave.json`:

```kotlin showLineNumbers title="Kotlin"

class CustomElementsResolver(context: Context) : AdaptyCustomElementsResolver {
    // the animation files in the assets folder, listed once
    private val animationFiles: Set<String> = try {
        context.assets.list("").orEmpty().toSet()
    } catch (e: IOException) {
        emptySet() // no list of files: every Lottie element shows the fallback
    }

    override fun resolve(type: String, id: String): AdaptyCustomElementContent? =
        when (type) {
            "lottie_animation" -> {
                // the ID names the animation file, such as welcome_wave.json
                val file = "$id.json"
                if (file in animationFiles) {
                    AdaptyCustomElementContent.compose { LottieElement(file) }
                } else {
                    null // no file for this ID: show the fallback
                }
            }
            else -> null
        }
}
```

Với bất kỳ Type nào khác, hãy trả về `null`.

</TabItem>
</Tabs>

Nếu bạn [thêm một phần tử tùy chỉnh với Type mới](flow-custom-elements#what-changes-require-an-app-release) sau khi phát hành ứng dụng, người dùng của phiên bản đã phát hành sẽ thấy fallback của phần tử đó.

Resolver có các yêu cầu sau:

- **Dữ liệu mạng và player**: Giữ dữ liệu mạng và player trong trạng thái của [native view](#create-views-for-custom-elements), không phải trong resolver. SDK gọi resolver nhiều lần trong khi màn hình đang mở. Code trong resolver chạy lại mỗi lần được gọi, do đó các yêu cầu mạng sẽ lặp lại và player sẽ bắt đầu lại từ đầu. Native view giữ nguyên trạng thái giữa các lần gọi này, nên dữ liệu chỉ tải một lần và player tiếp tục phát. Tạo player, session và yêu cầu mạng bên trong native view:
  - **SwiftUI view**: Tạo player, session và yêu cầu mạng trong `.task` hoặc `@StateObject`, không phải trong giá trị khởi tạo của thuộc tính `@State`. Swift đánh giá lại giá trị khởi tạo đó mỗi khi resolver tạo view.
  - **Composable**: Tạo player và session trong `remember`, và yêu cầu mạng trong `LaunchedEffect`.
  - **Android `View`**: Tạo player, session và yêu cầu mạng trong `onAttachedToWindow`.
- **Một native view cho mỗi custom element**: Một số native view thay đổi khi màn hình đang mở, ví dụ khi dữ liệu được tải hoặc khi người dùng nhấn vào chúng. Hãy triển khai logic này trong chính native view, không phải trong resolver. Nếu resolver trả về một view khác cho cùng một custom element, view đó sẽ mất trạng thái.
- **Một `View` mới cho mỗi lần hiển thị**: Trên Android, hãy tạo một `View` mới trong mỗi lần gọi `factory`. SDK gọi `factory` mỗi khi custom element xuất hiện, chẳng hạn khi màn hình mở, khi người dùng quay lại màn hình, hoặc trong một flow mà bạn mở bằng `present()`, sau khi xoay màn hình.
- **Dữ liệu ứng dụng**: Lưu trữ một đối tượng chứa dữ liệu, chẳng hạn như `ObservableObject` hoặc `StateFlow` với [daily streak](react-native-custom-element-lottie-animation), trong một thuộc tính của resolver. Truyền đối tượng đó vào native view và quan sát đối tượng ở đó:
  - **SwiftUI view**: Quan sát `ObservableObject` bằng `@ObservedObject`.
  - **Composable**: Thu thập `StateFlow` bằng `collectAsState`, hoặc quan sát `LiveData` bằng `observeAsState`.
  - **Android `View`**: Quan sát đối tượng trong `onAttachedToWindow`, và dừng trong `onDetachedFromWindow`.

  Giá trị bạn sao chép vào resolver, chẳng hạn như số ngày streak, sẽ giữ nguyên như khi bạn tạo resolver. Nếu code JavaScript của bạn có dữ liệu, chẳng hạn như streak hàng ngày, hãy gửi từng giá trị mới sang code native thông qua [Turbo Native Module](https://reactnative.dev/docs/turbo-native-modules-introduction), rồi cập nhật đối tượng ở đó.

### Đặt điều kiện cho nội dung dự phòng \{#set-conditions-for-fallback-content\}

<FlowCustomElementsFallbackConditions />

Đối với quyền truy cập, chỉ trả về no view khi người dùng đã từ chối trước khi màn hình mở ra. Trên Android, `ContextCompat.checkSelfPermission` trả về cùng một giá trị, `PERMISSION_DENIED`, trong hai trường hợp: trước khi ứng dụng lần đầu hỏi người dùng về quyền đó, và sau khi người dùng từ chối. Để phân biệt hai trường hợp này, hãy lưu kết quả của yêu cầu quyền và đọc kết quả đã lưu trong resolver. Nếu ứng dụng chưa yêu cầu quyền, hãy trả về native view và yêu cầu quyền bên trong view đó. Ví dụ: yêu cầu quyền truy cập vị trí khi [map view](react-native-custom-element-map#3-match-the-map-to-the-custom-element) xuất hiện, và hiển thị bản đồ ngay khi người dùng cấp quyền. Nếu bạn trả về no view và người dùng cấp quyền sau đó, họ vẫn thấy fallback. Việc thay đổi quyền không khiến SDK gọi resolver lại. Native view chỉ xuất hiện sau khi SDK gọi resolver lại, chẳng hạn khi người dùng quay lại màn hình.

## Truyền resolver vào SDK \{#pass-the-resolver-to-the-sdk\}

Đặt resolver một lần cho mỗi nền tảng, ngay khi khởi động ứng dụng. SDK sẽ gọi nó trong mọi flow, kể cả flow được nhúng bằng `AdaptyFlowView`. Người dùng sẽ thấy các native view của bạn trong các flow và A/B test mới mà không cần phát hành lại ứng dụng. Các view này vẫn hiển thị đúng dữ liệu của từng người dùng, chẳng hạn như [chuỗi ngày liên tiếp](react-native-custom-element-lottie-animation), vì chúng đọc dữ liệu đó từ ứng dụng của bạn.

### iOS

<Tabs groupId="ios-app-delegate" queryString>
<TabItem value="swift" label="AppDelegate.swift" default>

Trong `AppDelegate.swift`, import `AdaptyUI` và gọi `AdaptyUI.setCustomElementsResolver(_:)` trong phương thức `application(_:didFinishLaunchingWithOptions:)`. Các dòng được tô sáng cho thấy những gì cần thêm. Giữ nguyên phần còn lại của class `AppDelegate`:

```swift showLineNumbers title="ios/YourApp/AppDelegate.swift" {1,10}

@main
class AppDelegate: UIResponder, UIApplicationDelegate {
  func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]? = nil
  ) -> Bool {
    AdaptyUI.setCustomElementsResolver(CustomElementsResolver())
    // the rest of your launch code
    return true
  }
}
```

Nếu bạn viết resolver trong `AppDelegate.swift`, hãy import thêm `AdaptyUIBuilder` ở đó.

If `application(_:didFinishLaunchingWithOptions:)` ends with a bare `true`, as in the React Native 0.88 template, change `true` to `return true`.

</TabItem>
<TabItem value="objc" label="AppDelegate.mm">

Đặt resolver thông qua một lớp Swift, vì `AdaptyUI.setCustomElementsResolver(_:)` chỉ dành cho Swift:

1. Thêm một file Swift chứa lớp đó vào app target của bạn:

   ```swift showLineNumbers title="CustomElementsSetup.swift"
   import AdaptyUI

   @objc final class CustomElementsSetup: NSObject {
     @MainActor @objc static func register() {
       AdaptyUI.setCustomElementsResolver(CustomElementsResolver())
     }
   }
   ```

2. Trong `AppDelegate.mm`, import header Swift mà Xcode tạo ra cho target của bạn, `<YourApp>-Swift.h`. Gọi `[CustomElementsSetup register]` ở đầu `application:didFinishLaunchingWithOptions:`. Trong dự án Expo, import `<ExpoModulesCore/ExpoModulesCore-Swift.h>` trước header của target.

   ```objectivec showLineNumbers title="ios/YourApp/AppDelegate.mm" {1,5}
   #import "YourApp-Swift.h"

   - (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions
   {
     [CustomElementsSetup register];
     // the rest of your launch code
   }
   ```

### Android

Trong `MainApplication.kt`, import `AdaptyUI` và gọi `AdaptyUI.setCustomElementsResolver` trong phương thức `onCreate`. Các dòng được tô sáng cho thấy những gì cần thêm. Giữ nguyên phần còn lại của class `MainApplication`:

```kotlin showLineNumbers title="MainApplication.kt" {1,8}

class MainApplication : Application(), ReactApplication {
  // the other members of your MainApplication class

  override fun onCreate() {
    super.onCreate()
    AdaptyUI.setCustomElementsResolver(CustomElementsResolver(this))
    // the rest of your onCreate code
  }
}
```

:::tip
Để hiển thị cùng một view trong mọi custom element của một Type, hãy truyền một map gồm các Type và view thay vì dùng resolver. Với map, bạn viết ít code hơn so với resolver, nhưng không thể [đặt điều kiện cho nội dung dự phòng](#set-conditions-for-fallback-content).

```swift showLineNumbers title="Swift"
AdaptyUI.setCustomElementsResolver([
    "lottie_animation": .init { _, id, _ in LottieElementView(animation: .named(id)) },
```

Bạn không thể gắn resolver vào một flow. Để hiển thị dữ liệu từ code JavaScript của mình, hãy gửi dữ liệu đó sang code native trước khi flow mở. Sau đó đọc dữ liệu trong resolver. Ví dụ: một paywall hiển thị [cân nặng mà người dùng đã nhập trong một flow trước đó](react-native-custom-element-interactive-chart).

## Kiểm tra trên thiết bị thực \{#test-on-a-device\}

Flow & Paywall Builder không thể chạy code của ứng dụng, vì vậy canvas chỉ hiển thị fallback. Lỗi trong native view có thể làm crash ứng dụng. Trước khi phát hành ứng dụng, hãy kiểm tra mọi màn hình có custom element trên thiết bị iOS và thiết bị Android:

1. Để xem phiên bản mới nhất đã phát hành của từng flow thay vì phiên bản được lưu trong bộ nhớ đệm, hãy đăng ký thiết bị làm [thiết bị thử nghiệm](test-devices).
2. Để xem các cảnh báo của Adapty SDK trong Xcode console và Logcat, hãy đặt [log level](sdk-installation-react-native-pure#logging) thành `warn` hoặc mức chi tiết hơn.
3. Trên thiết bị, chạy một bản build có chứa resolver. Mở từng màn hình có custom element và xác minh rằng native view hiển thị đúng và vừa khít với custom element đó. Nếu view có thể cuộn hoặc phản hồi thao tác kéo, hãy kiểm tra các thao tác đó.
4. Nếu fallback hiển thị thay vì native view, hãy tìm cảnh báo này trong Xcode console hoặc Logcat: `custom element <type>:<id> is not served by a resolver`. Sau đó xác minh rằng:
   - Type và ID trong cảnh báo khớp chính xác với những gì trong code của bạn, từng chữ cái một.
   - Ứng dụng của bạn có file, dữ liệu hoặc quyền mà view cần.
   - Ứng dụng của bạn thiết lập resolver khi khởi chạy: trong class `AppDelegate` trên iOS và trong class `MainApplication` trên Android.

   Nếu cảnh báo không xuất hiện, hãy kiểm tra xem ứng dụng có đang dùng Adapty React Native SDK 4.4 trở lên không.
5. Trên Android, nếu custom element vẫn trống, hãy tìm một trong các cảnh báo sau trong Logcat:
   - `custom element <type>:<id> is not served by a resolver`: Custom element không có nội dung dự phòng và không có resolver nào trả về view cho nó. Hãy kiểm tra lại từng bước trong bước 4.
   - `content does not report its size`: Composable không có chiều cao riêng. Hãy đặt chiều cao [**Fixed** (cố định)](flow-custom-elements#add-and-configure) cho custom element.

   The SDK chỉ ghi log cảnh báo kích thước cho composable. Nếu một `View` Android vẫn trống mà không có cảnh báo, hãy đặt chiều cao **Fixed** cho phần tử tùy chỉnh đó.
6. Để xem trước paywall dự phòng, không trả về view nào cho Type đó và mở lại màn hình.
