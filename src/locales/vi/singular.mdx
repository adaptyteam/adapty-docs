[Singular](https://www.singular.net/) là nền tảng Mobile Measurement Partner (MMP) thu thập và trình bày dữ liệu từ các chiến dịch marketing.

Adapty gửi các [sự kiện gói đăng ký](events) mà bạn chọn đến Singular. Trong dashboard của Singular, bạn có thể xem mỗi chiến dịch tạo ra bao nhiêu doanh thu và đánh giá hiệu quả quảng cáo của mình.

## Thiết lập tích hợp \{#set-up-integration\}

### Kết nối Adapty với Singular

Để thiết lập tích hợp với Singular, hãy vào [Integrations > Singular](https://app.adapty.io/integrations/singular) trong Adapty Dashboard, bật toggle và điền thông tin vào các trường.

<ZoomImage id="singular-creds.webp" />

Các thông tin xác thực sau đây có sẵn:

- **Singular SDK Key**: Bắt buộc. SDK key cho môi trường production của ứng dụng Singular.
- **Singular SDK Key (Sandbox)**: Tùy chọn. SDK key cho ứng dụng Singular trong môi trường sandbox. Nếu không được thiết lập, các sự kiện sandbox sẽ không được gửi đến Singular.

Cả hai khóa đều có thể tìm thấy trong Singular dashboard tại **Developer tools -> SDK Keys -> SDK Key (**không phải** SDK Secret)**:

### Kết nối ứng dụng với Singular \{#connect-your-app-to-singular\}

Singular bật Singular Device ID (SDID) theo mặc định cho các tài khoản được tạo từ ngày 15 tháng 7 năm 2026 trở đi. Các tài khoản này chỉ chấp nhận sự kiện qua v2 Event API, và Adapty chỉ gửi sự kiện đến v2 khi hồ sơ người dùng có SDID. Để gửi sự kiện đến tài khoản như vậy, hãy truyền SDID vào Adapty từ ứng dụng của bạn.

Nếu tài khoản Singular của bạn được tạo trước ngày 15 tháng 7 năm 2026 và SDID chưa được bật, hãy bỏ qua bước này. Adapty sẽ gửi sự kiện của bạn đến v1 Event API và không cần thay đổi code trong ứng dụng.

1. Kích hoạt Adapty, sau đó khởi động Singular SDK với callback SDID: `sdidReceivedHandler` trên iOS, `SDIDAccessorHandler` trên Android, `sdidReceivedCallback` trên React Native và Flutter, và `SingularSdidAccessorHandler` trên Unity.
2. Chờ Singular gọi callback. SDID được gửi đến ứng dụng của bạn theo cách bất đồng bộ, sau khi Singular SDK khởi động. Singular gọi callback mỗi lần khởi chạy, kể cả khi SDID đã được lưu trên thiết bị.
3. Trong callback, truyền SDID vào Adapty bằng `setIntegrationIdentifier()` với key `singular_sdid`. Không có Adapty SDK nào có hằng số định sẵn cho key này, vì vậy hãy viết key dưới dạng chuỗi ký tự.
4. Chỉ gọi `Adapty.identify()` sau khi `setIntegrationIdentifier()` hoàn tất. Adapty tạo một hồ sơ người dùng ẩn danh lúc kích hoạt, sau đó chuyển sang hồ sơ người dùng đã xác định khi `identify()` hoàn thành. SDID được đặt trong quá trình chuyển đổi đó có thể bị mất.

## Cấu trúc sự kiện \{#event-structure\}

Adapty chọn phiên bản Singular Event API cho từng sự kiện dựa trên việc hồ sơ người dùng có SDID hay không:

- **Có SDID**: Adapty gửi yêu cầu `POST` đến `https://s2s.singular.net/api/v2/evt` với body dạng form-urlencoded. Tham số `sdid` thay thế các định danh thiết bị `idfa`, `idfv`, `aifa`, `andi`, và `asid`. Giá trị boolean được gửi dưới dạng `true` hoặc `false`.
- **Không có SDID**: Adapty gửi yêu cầu `GET` đến `https://s2s.singular.net/api/v1/evt` với các query parameter.

Cả hai phiên bản đều mang các tham số giống nhau. Một sự kiện v1 có cấu trúc như sau:

```json
{
  "n": "subscription_renewed",
  "a": "singular_sdk_key_123",
  "p": "iOS",
  "i": "com.example.app",
  "ip": "192.168.100.1",
  "idfa": "00000000-0000-0000-0000-000000000000",
  "idfv": "00000000-0000-0000-0000-000000000000",
  "ve": "17.0.1",
  "att_authorization_status": 3,
  "custom_user_id": "user_12345",
  "utime": 1709294400,
  "partner": "adapty",
  "use_ip": false,
  "is_revenue_event": true,
  "amt": 9.99,
  "cur": "USD",
  "purchase_product_id": "yearly.premium.6999",
  "purchase_transaction_id": "GPA.3383...",
  "e": "{\"is_revenue_event\":true,\"amt\":9.99,\"cur\":\"USD\",\"purchase_product_id\":\"yearly.premium.6999\",\"purchase_transaction_id\":\"GPA.3383...\"}"
}
```

Trong đó:

| Tham số                    | Kiểu    | Mô tả                                                |
|:---------------------------|:--------|:-----------------------------------------------------|
| `n`                        | String  | Tên sự kiện (được ánh xạ từ sự kiện Adapty).         |
| `a`                        | String  | Singular SDK Key của bạn.                            |
| `p`                        | String  | Nền tảng ("iOS" hoặc "Android").                     |
| `i`                        | String  | Store App ID (Bundle ID).                            |
| `ip`                       | String  | Địa chỉ IP của người dùng.                           |
| `sdid`                     | String  | **Chỉ v2**. Singular Device ID, lấy từ integration identifier `singular_sdid`. |
| `idfa`                     | String  | **iOS, chỉ v1**. ID for Advertisers (chữ hoa).       |
| `idfv`                     | String  | **iOS, chỉ v1**. ID for Vendors (chữ hoa).           |
| `aifa`                     | String  | **Android, chỉ v1**. Google Advertising ID (chữ thường). |
| `andi`                     | String  | **Android, chỉ v1**. Android ID (chữ thường).        |
| `asid`                     | String  | **Android, chỉ v1**. App Set ID (chữ thường).        |
| `ve`                       | String  | Phiên bản OS.                                        |
| `att_authorization_status` | Integer | **Chỉ iOS**. Trạng thái ATT (ví dụ: `3` là đã ủy quyền). |
| `custom_user_id`           | String  | Customer User ID của người dùng.                     |
| `utime`                    | Long    | UNIX timestamp của sự kiện tính bằng giây.           |
| `partner`                  | String  | Luôn là `adapty`. Xác định sự kiện được gửi bởi Adapty. |
| `use_ip`                   | Boolean | `true` khi Adapty không có địa chỉ IP của người dùng. |
| `is_revenue_event`         | Boolean | `true` nếu sự kiện có chứa doanh thu. Chỉ gửi kèm các sự kiện có doanh thu. |
| `amt`                      | Float   | Số tiền doanh thu.                                   |
| `cur`                      | String  | Mã tiền tệ (ví dụ: "USD").                           |
| `purchase_product_id`      | String  | Product ID từ cửa hàng.                              |
| `purchase_transaction_id`  | String  | Transaction ID gốc.                                  |
| `e`                        | String  | Chuỗi JSON chứa chi tiết sự kiện (xem bên dưới).    |

Tham số `e` (dữ liệu sự kiện tùy chỉnh) là một chuỗi được mã hóa JSON chứa:

| Parameter                 | Type    | Description                           |
|:--------------------------|:--------|:--------------------------------------|
| `is_revenue_event`        | Boolean | `true` nếu sự kiện có chứa doanh thu. |
| `amt`                     | Float   | Số tiền doanh thu.                    |
| `cur`                     | String  | Mã tiền tệ.                           |
| `purchase_product_id`     | String  | ID sản phẩm từ cửa hàng.              |
| `purchase_transaction_id` | String  | ID giao dịch gốc.                     |

## Khắc phục sự cố \{#troubleshooting\}

### Sự kiện thất bại với lỗi `invalid api version: v1` \{#events-fail-with-invalid-api-version-v1\}

Tài khoản Singular của bạn được tạo vào hoặc sau ngày 15 tháng 7 năm 2026, và chỉ chấp nhận sự kiện thông qua Event API v2. Adapty đã gửi sự kiện đến v1 vì hồ sơ người dùng không có SDID. Để khắc phục, hãy truyền SDID vào Adapty từ ứng dụng của bạn, như được mô tả trong [Kết nối ứng dụng của bạn với Singular](#connect-your-app-to-singular). Các sự kiện từ người dùng đang dùng phiên bản ứng dụng chưa có lệnh gọi `setIntegrationIdentifier()` sẽ tiếp tục thất bại cho đến khi những người dùng đó cập nhật ứng dụng.
