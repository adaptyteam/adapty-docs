Sau khi [bạn đã thiết kế flow của mình](adapty-flow-builder), bạn có thể hiển thị nó trong ứng dụng di động. Bước đầu tiên là lấy flow hoặc paywall được liên kết với placement và cấu hình giao diện của nó như mô tả bên dưới.

## Lấy flow/paywall \{#fetch-flowpaywall\}

Nếu bạn đã thiết kế một flow hoặc paywall trong builder, bạn không cần lo lắng về việc render nó trong code ứng dụng di động để hiển thị cho người dùng. Flow hoặc paywall đó đã bao gồm cả nội dung hiển thị lẫn cách thức hiển thị. Tuy nhiên, bạn vẫn cần lấy ID của nó thông qua placement, cấu hình view, rồi mới trình bày nó trong ứng dụng di động của bạn.

Tải flow hoặc paywall và tạo [view](flutter-get-pb-paywalls#fetch-the-view-configuration) của nó càng sớm càng tốt — lý tưởng nhất là trước khi hiển thị. Phương thức `createFlowView` tải cấu hình view và bắt đầu tải xuống cũng như lưu cache ảnh ở nền. Bạn gọi nó càng sớm, các ảnh càng có nhiều thời gian để tải xong. Đến khi hiển thị flow hoặc paywall, cấu hình và ảnh của nó có thể đã được cache sẵn sàng để hiển thị.

:::tip
Để làm ấm nhiều placement cùng lúc, hãy gọi [`preloadFlows`](flutter-optimize-paywall-fetching#preload-placements) (Flutter SDK 4.3.0+). Nó chỉ cache JSON của placement, vì vậy `createFlowView` vẫn cần tải layout và hình ảnh.
:::

Để lấy flow hoặc paywall, sử dụng phương thức `getFlow`:

```dart showLineNumbers
try {
  final flow = await Adapty().getFlow(placementId: 'YOUR_PLACEMENT_ID');
  // the requested flow/paywall
} on AdaptyError catch (adaptyError) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Các tham số:

| Tham số | Bắt buộc | Mô tả |
|---------|--------|-----------|
| **placementId** | bắt buộc | Định danh của [Placement](placements) mong muốn. Đây là giá trị bạn đã chỉ định khi tạo placement trong Adapty Dashboard. |
| **fetchPolicy** | mặc định: `AdaptyFlowFetchPolicy.reloadRevalidatingCacheData` | <p>`fetchPolicy` xác định tầng nào SDK đọc trước, không phải liệu SDK có thể dùng cache hay không. Theo mặc định, SDK sẽ gọi lên server trước và trả về dữ liệu từ cache nếu yêu cầu đó thất bại. Chúng tôi khuyến nghị tùy chọn này vì nó đảm bảo người dùng luôn nhận được dữ liệu mới nhất.</p><p></p><p>Tuy nhiên, nếu bạn cho rằng người dùng của mình thường xuyên gặp tình trạng kết nối internet không ổn định, hãy cân nhắc dùng `AdaptyFlowFetchPolicy.returnCacheDataElseLoad` — tùy chọn này đảo ngược thứ tự đó: đọc cache trước và chỉ gọi server khi không có gì trong cache. Người dùng có thể không nhận được dữ liệu mới nhất tuyệt đối, nhưng thời gian tải sẽ nhanh hơn bất kể kết nối internet có kém đến đâu. Cache được cập nhật thường xuyên, vì vậy hoàn toàn an toàn khi sử dụng trong phiên để tránh các yêu cầu mạng không cần thiết.</p><p></p><p>Chính sách thứ ba, `AdaptyFlowFetchPolicy.returnCacheDataIfNotExpiredElseLoad(maxAge)`, nằm giữa hai tùy chọn trên: nó đọc cache trước khi bản cache còn trẻ hơn `Duration` bạn truyền vào, và gọi server khi cache đã cũ hơn giá trị đó.</p><p></p><p>Lưu ý rằng cache vẫn được giữ nguyên khi khởi động lại ứng dụng và chỉ bị xóa khi gỡ cài đặt ứng dụng hoặc thông qua việc dọn dẹp thủ công.</p><p></p><p>Adapty SDK lưu paywall cục bộ ở hai tầng: cache được cập nhật thường xuyên như mô tả ở trên và [paywall dự phòng](fallback-paywalls). Chúng tôi cũng sử dụng CDN để tải paywall nhanh hơn và một server dự phòng độc lập trong trường hợp CDN không thể truy cập. Hệ thống này được thiết kế để đảm bảo bạn luôn nhận được phiên bản paywall mới nhất đồng thời đảm bảo độ tin cậy ngay cả khi kết nối internet yếu.</p> |
| **loadTimeout** | mặc định: 5 giây | <p>`Duration` giới hạn thời gian chờ cho phương thức này. Nếu server Adapty không phản hồi kịp thời hoặc trả về lỗi, SDK sẽ trả về flow từ cache. Nếu không có gì trong cache và server đã hết thời gian chờ hoặc trả về lỗi server, SDK sẽ yêu cầu flow từ server dự phòng (bản sao CDN chỉ phục vụ đối tượng **All Users** của placement). Là phương án cuối cùng, SDK sẽ trả về flow từ [tệp dự phòng](flutter-use-fallback-paywalls) của bạn.</p><p>Lưu ý rằng trong một số trường hợp hiếm gặp, phương thức này có thể hết thời gian chờ muộn hơn một chút so với giá trị được chỉ định trong `loadTimeout`, vì thao tác có thể bao gồm nhiều yêu cầu khác nhau ở bên dưới.</p> |

Tham số phản hồi:

| Parameter | Description                                                                                                                                                                            |
| :-------- |:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Flow   | Đối tượng `AdaptyFlow` chứa các định danh của flow (`instanceIdentity`, `variationId`), tên, placement, các biến thể paywall (`paywalls`) và bất kỳ Remote Config nào (`remoteConfigs`). |

## Lấy cấu hình view \{#fetch-the-view-configuration\}

:::important
Hãy đảm bảo bạn đã [xuất bản flow](builder-save-publish). Một flow có chỉnh sửa chưa xuất bản sẽ có trạng thái **Dirty**, và placement của nó sẽ tiếp tục phục vụ phiên bản đã xuất bản lần cuối.
:::

Nếu placement được thiết kế trong **Flow & Paywall Builder** hoặc **old Paywall Builder**, Adapty sẽ tự render giao diện cho bạn — thuộc tính `hasViewConfiguration` của flow được tải về sẽ là `true`. Tạo view bằng `createFlowView`, sau đó [hiển thị flow hoặc paywall](flutter-present-paywalls). Nếu placement là một paywall tùy chỉnh không có giao diện Builder (`hasViewConfiguration` là `false`), hãy [tự render nó](present-remote-config-paywalls-flutter).

:::warning
Mặc định, việc đóng kết quả của phương thức `createFlowView` sẽ giải phóng nó, vì vậy bạn không thể hiển thị lại. Nếu cần hiển thị lại flow hoặc paywall, hãy gọi lại phương thức `createFlowView`, hoặc [đóng mà không giải phóng](flutter-present-paywalls#dismiss-the-flow-or-paywall) trên SDK 4.1 trở lên.
:::

```dart showLineNumbers

try {
  final view = await AdaptyUI().createFlowView(flow: flow);
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Tham số:

| Tham số              | Bắt buộc | Mô tả                                                        |
| :------------------- | :------- | :----------------------------------------------------------- |
| **flow**             | bắt buộc | Đối tượng `AdaptyFlow` để lấy view cho flow/paywall mong muốn. |
| **locale**           | tùy chọn | Mã định danh của [bản địa hóa flow](add-paywall-locale-in-adapty-paywall-builder) để render view — ví dụ: `en` hoặc `pt-BR`. Nếu bỏ qua, view sẽ render bằng `en`, hoặc bằng bản địa hóa mặc định của flow nếu flow không có `en`. Xem [Bản địa hóa và mã ngôn ngữ](flutter-localizations-and-locale-codes). |
| **customLayoutId**   | <p>tùy chọn</p><p>mặc định: `null`</p><p>SDK 4.1+</p> | ID tùy chỉnh của một layout trong cấu hình layout của flow. Truyền vào để render layout cụ thể đó thay vì layout mà SDK tự động chọn dựa trên loại thiết bị và kích thước màn hình. Nếu không có layout nào khớp với ID, lệnh gọi sẽ thất bại với `AdaptyError`. Flow & Paywall Builder chưa hỗ trợ gán ID layout tùy chỉnh, vì vậy hãy để trống tùy chọn này. |
| **customTags**       | tùy chọn | Các giá trị của ứng dụng cho [custom tags](flow-custom-tags) của flow, trong một map với key là tên đầy đủ của từng tag. Xem chi tiết tại [Truyền dữ liệu vào flow](flutter-flow-custom-tags). |
| **customTimers**     | tùy chọn | Ngày kết thúc của các timer **Developer defined** trong flow, trong một map từ Timer ID sang giá trị `DateTime`. Xem chi tiết tại [Thiết lập timer do developer định nghĩa](#set-up-developer-defined-timers). |
| **preloadProducts** | tùy chọn | Bật tùy chọn này để tối ưu thời điểm hiển thị sản phẩm trên màn hình. Khi đặt là `true`, AdaptyUI sẽ tự động tải các sản phẩm cần thiết. Mặc định: `false`. |
| **loadTimeout** | tùy chọn | Giá trị `Duration` giới hạn thời gian tải cấu hình view. Nếu hết thời gian chờ, dữ liệu đã cache hoặc fallback cục bộ sẽ được sử dụng. |

:::note
Nếu bạn đang sử dụng nhiều ngôn ngữ, hãy tìm hiểu cách thêm [bản địa hóa flow](add-paywall-locale-in-adapty-paywall-builder) và cách sử dụng mã ngôn ngữ đúng cách [tại đây](flutter-localizations-and-locale-codes).
:::

Sau khi có view, hãy [hiển thị flow/paywall](flutter-present-paywalls).

## Lấy flow hoặc paywall cho đối tượng mặc định để tải nhanh hơn \{#get-a-flow-or-paywall-for-a-default-audience-to-fetch-it-faster\}

Thông thường, flow và paywall được tải gần như ngay lập tức, nên bạn không cần lo lắng về việc tăng tốc quá trình này. Tuy nhiên, trong trường hợp bạn có nhiều đối tượng và placement, và người dùng có kết nối internet yếu, việc tải flow hoặc paywall có thể mất nhiều thời gian hơn mong muốn. Trong những tình huống như vậy, bạn có thể muốn hiển thị flow hoặc paywall mặc định để đảm bảo trải nghiệm người dùng mượt mà thay vì không hiển thị gì cả.

Để giải quyết vấn đề này, bạn có thể sử dụng phương thức `getFlowForDefaultAudience`, phương thức này sẽ lấy flow hoặc paywall của placement được chỉ định cho đối tượng **All Users**. Tuy nhiên, điều quan trọng cần hiểu là cách tiếp cận được khuyến nghị là lấy flow hoặc paywall bằng phương thức `getFlow`, như đã trình bày chi tiết trong phần [Lấy flow/paywall](#fetch-flowpaywall) ở trên.

:::warning
Lý do chúng tôi khuyến nghị sử dụng `getFlow`

Phương thức `getFlowForDefaultAudience` có một số hạn chế đáng kể:

- **Các vấn đề tương thích ngược tiềm ẩn**: Nếu bạn cần hiển thị các paywall khác nhau cho các phiên bản ứng dụng khác nhau (hiện tại và tương lai), bạn có thể gặp khó khăn. Bạn sẽ phải thiết kế các paywall hỗ trợ phiên bản hiện tại (cũ) hoặc chấp nhận rằng người dùng với phiên bản hiện tại (cũ) có thể gặp sự cố với các paywall không được hiển thị.
- **Mất khả năng targeting**: Tất cả người dùng sẽ thấy cùng một paywall được thiết kế cho đối tượng **All Users**, nghĩa là bạn mất đi khả năng targeting cá nhân hóa (bao gồm theo quốc gia, attribution marketing hoặc các thuộc tính tùy chỉnh của riêng bạn).

Nếu bạn chấp nhận những hạn chế này để đổi lấy tốc độ tải flow hoặc paywall nhanh hơn, hãy sử dụng phương thức `getFlowForDefaultAudience` như sau. Nếu không, hãy tiếp tục dùng `getFlow` đã mô tả [ở trên](#fetch-flowpaywall).
:::

```dart showLineNumbers
try {
  final flow = await Adapty().getFlowForDefaultAudience(placementId: 'YOUR_PLACEMENT_ID');
  // the requested flow/paywall
} on AdaptyError catch (adaptyError) {
  // handle error
} catch (e) {
  // handle unknown error
}
```

| Tham số | Bắt buộc | Mô tả |
|---------|--------|-----------|
| **placementId** | bắt buộc | Định danh của [Placement](placements). Đây là giá trị bạn đã chỉ định khi tạo placement trong Adapty Dashboard. |
| **fetchPolicy** | mặc định: `AdaptyFlowFetchPolicy.reloadRevalidatingCacheData` | <p>`fetchPolicy` xác định SDK đọc dữ liệu từ lớp nào trước, chứ không phải SDK có được phép dùng cache hay không. Theo mặc định, SDK sẽ gọi lên server trước và trả về dữ liệu từ cache nếu yêu cầu đó thất bại. Chúng tôi khuyến nghị dùng tùy chọn này vì nó đảm bảo người dùng luôn nhận được dữ liệu mới nhất.</p><p></p><p>Tuy nhiên, nếu bạn cho rằng người dùng của mình thường gặp kết nối internet không ổn định, hãy cân nhắc dùng `AdaptyFlowFetchPolicy.returnCacheDataElseLoad` — tùy chọn này đảo ngược thứ tự đó: đọc cache trước và chỉ gọi server khi không có dữ liệu nào trong cache. Người dùng có thể không nhận được dữ liệu mới nhất tuyệt đối, nhưng sẽ có trải nghiệm tải nhanh hơn dù kết nối mạng có kém đến đâu. Cache được cập nhật thường xuyên nên hoàn toàn an toàn khi dùng trong suốt phiên làm việc để tránh các yêu cầu mạng.</p><p></p><p>Chính sách thứ ba, `AdaptyFlowFetchPolicy.returnCacheDataIfNotExpiredElseLoad(maxAge)`, nằm giữa hai tùy chọn trên: đọc cache trước khi bản cache còn trẻ hơn giá trị `Duration` bạn truyền vào, và gọi server khi bản cache đã cũ hơn.</p><p></p><p>Lưu ý rằng cache vẫn được giữ nguyên sau khi khởi động lại ứng dụng và chỉ bị xóa khi ứng dụng được cài đặt lại hoặc thực hiện dọn dẹp thủ công.</p> |

## Tùy chỉnh asset \{#customize-assets\}

Để tùy chỉnh hình ảnh và video trong flow/paywall của bạn, hãy triển khai custom asset.

Hero image và video có ID được định sẵn: `hero_image` và `hero_video`. Trong một custom asset bundle, bạn nhắm đến các phần tử này bằng ID của chúng và tùy chỉnh hành vi của chúng.

Với các hình ảnh và video khác, bạn cần [đặt custom ID](custom-media) trong Adapty dashboard.

Ví dụ, bạn có thể:

- Hiển thị hình ảnh hoặc video khác nhau cho một số người dùng.
- Hiển thị hình ảnh xem trước cục bộ trong khi hình ảnh chính từ xa đang tải.
- Hiển thị hình ảnh xem trước trước khi phát video.
- Hiển thị media được đóng gói cùng ứng dụng, để màn hình đầu tiên hiển thị mà không cần tải xuống. Xem [Hiển thị media màn hình đầu từ app bundle](flutter-optimize-paywall-fetching#show-first-screen-media-from-the-app-bundle).

Dưới đây là ví dụ về cách bạn có thể cung cấp custom asset thông qua một dictionary đơn giản:

```dart

final customAssets = {
    // Show a local image using a custom ID
    'custom_image': AdaptyCustomAsset.localImageAsset(
        assetId: 'assets/images/image_name.png',
    ),

    // Show a local video with a preview image
    'hero_video': AdaptyCustomAsset.localVideoAsset(
        assetId: 'assets/videos/custom_video.mp4',
    ),
};

try {
  final view = await AdaptyUI().createFlowView(
    flow: flow,
    customAssets: customAssets,
  );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

:::note
Nếu không tìm thấy asset, flow/paywall sẽ trở về giao diện mặc định của nó.
:::

## Thiết lập bộ đếm thời gian do nhà phát triển định nghĩa \{#set-up-developer-defined-timers\}

Sử dụng phần này cho bộ đếm thời gian có hành vi **Developer defined** trong Flow & Paywall Builder. Trong builder, mỗi bộ đếm như vậy có một **Timer ID** (xem [Để app của bạn đặt ngày kết thúc](flow-timer#let-your-app-set-the-end-date)), và app của bạn sẽ đặt ngày kết thúc cho nó. Hãy sử dụng đúng Timer ID trong code như trong builder, từng ký tự một, bao gồm cả chữ hoa chữ thường và khoảng trắng. Nếu các ID không khớp, bộ đếm sẽ không nhận được ngày kết thúc từ app của bạn.

Để đặt ngày kết thúc, hãy truyền map `customTimers` vào phương thức `createFlowView`. Mỗi key trong map là một Timer ID, và giá trị của nó là đối tượng `DateTime` xác định thời điểm hết hạn của timer. Dưới đây là ví dụ:

```dart showLineNumbers

try {
  final view = await AdaptyUI().createFlowView(
    flow: flow,
    customTimers: {
      'CUSTOM_TIMER_6H': DateTime.now().add(const Duration(hours: 6)),
      'CUSTOM_TIMER_NY': DateTime(DateTime.now().year + 1), // next New Year's Day
    },
  );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Đối với flow được nhúng bằng `AdaptyUIFlowPlatformView`, hãy truyền cùng một map vào tham số `customTimers` của nó.

Trong ví dụ này, `CUSTOM_TIMER_NY` và `CUSTOM_TIMER_6H` là Timer ID của hai bộ hẹn giờ **Developer defined** trong builder:

- `CUSTOM_TIMER_NY`: Thời gian còn lại cho đến Năm Mới tiếp theo.
- `CUSTOM_TIMER_6H`: Thời gian còn lại trong khoảng thời gian 6 giờ bắt đầu khi app của bạn tạo view.

SDK đọc `customTimers` một lần duy nhất khi tạo view, vì vậy ngày được tính như `CUSTOM_TIMER_6H` sẽ bắt đầu tính từ thời điểm đó, kể cả khi người dùng mở lại màn hình. Nếu ngày đã qua, bộ đếm hiển thị về không ngay lập tức và trigger **On timer end** sẽ chạy. Nếu `customTimers` không có key cho Timer ID, bộ đếm sẽ đếm ngược một giờ kể từ khi mở màn hình.

## Lấy paywall được thiết kế bằng Paywall Builder \{#fetch-paywall-designed-with-paywall-builder\}

Nếu bạn đã [thiết kế paywall bằng Paywall Builder](adapty-paywall-builder), bạn không cần lo lắng về việc render nó trong code ứng dụng để hiển thị cho người dùng. Paywall như vậy đã bao gồm cả nội dung hiển thị lẫn cách hiển thị. Tuy nhiên, bạn vẫn cần lấy ID của nó thông qua placement, cấu hình giao diện, rồi mới trình bày nó trong ứng dụng.

Để đảm bảo hiệu suất tối ưu, bạn cần lấy paywall và [cấu hình view](flutter-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder) của nó càng sớm càng tốt, nhằm đảm bảo đủ thời gian tải hình ảnh trước khi hiển thị cho người dùng.

Để lấy một paywall, hãy sử dụng phương thức `getPaywall`:

```dart showLineNumbers

} on AdaptyError catch (adaptyError) {
  // handle the error
} catch (e) {
}
```

## Lấy paywall cho đối tượng mặc định để tải nhanh hơn \{#get-a-paywall-for-a-default-audience-to-fetch-it-faster\}

Thông thường, paywall được tải gần như ngay lập tức, vì vậy bạn không cần lo lắng về việc tăng tốc quá trình này. Tuy nhiên, trong trường hợp bạn có nhiều đối tượng và paywall, và người dùng của bạn có kết nối internet yếu, việc tải paywall có thể mất nhiều thời gian hơn mong muốn. Trong những tình huống như vậy, bạn có thể muốn hiển thị một paywall mặc định để đảm bảo trải nghiệm người dùng mượt mà thay vì không hiển thị paywall nào cả.

Để giải quyết vấn đề này, bạn có thể sử dụng phương thức `getPaywallForDefaultAudience`, phương thức này sẽ lấy paywall của placement được chỉ định cho đối tượng **All Users**. Tuy nhiên, điều quan trọng cần hiểu là cách tiếp cận được khuyến nghị là lấy paywall bằng phương thức `getPaywall`, như được mô tả chi tiết trong phần [Lấy thông tin Paywall](flutter-get-pb-paywalls#fetch-paywall-designed-with-paywall-builder) ở trên.

:::warning
Lý do chúng tôi khuyến nghị sử dụng `getPaywall`

Phương thức `getPaywallForDefaultAudience` có một số hạn chế đáng kể:

- **Các vấn đề tương thích ngược tiềm ẩn**: Nếu bạn cần hiển thị các paywall khác nhau cho các phiên bản ứng dụng khác nhau (hiện tại và tương lai), bạn có thể gặp khó khăn. Bạn sẽ phải thiết kế các paywall hỗ trợ phiên bản hiện tại (legacy) hoặc chấp nhận rằng người dùng có phiên bản hiện tại (legacy) có thể gặp sự cố với các paywall không được hiển thị.
- **Mất khả năng nhắm mục tiêu**: Tất cả người dùng sẽ thấy cùng một paywall được thiết kế cho đối tượng **All Users**, có nghĩa là bạn mất đi khả năng nhắm mục tiêu cá nhân hóa (bao gồm theo quốc gia, attribution marketing hoặc các thuộc tính tùy chỉnh của riêng bạn).

Nếu bạn chấp nhận những hạn chế này để đổi lấy tốc độ tải paywall nhanh hơn, hãy sử dụng phương thức `getPaywallForDefaultAudience` như sau. Nếu không, hãy dùng `getPaywall` được mô tả [ở trên](#fetch-paywall-designed-with-paywall-builder).
:::

```dart showLineNumbers
try {
    final paywall = await Adapty().getPaywallForDefaultAudience(placementId: 'YOUR_PLACEMENT_ID');
} on AdaptyError catch (adaptyError) {
    // handle error
} catch (e) {
    // handle unknown error
}
```

:::note
Phương thức `getPaywallForDefaultAudience` khả dụng từ Flutter SDK phiên bản 3.2.0 trở lên.
:::

## Tùy chỉnh tài nguyên \{#customize-assets\}

Để tùy chỉnh hình ảnh và video trong paywall của bạn, hãy triển khai custom assets.

Hero image và video có ID được định sẵn: `hero_image` và `hero_video`. Trong một custom asset bundle, bạn nhắm đến các phần tử này theo ID của chúng và tùy chỉnh hành vi của chúng.

Đối với các hình ảnh và video khác, bạn cần [đặt ID tùy chỉnh](custom-media) trong Adapty dashboard.

Ví dụ, bạn có thể:

- Hiển thị hình ảnh hoặc video khác cho một số người dùng.
- Hiển thị hình ảnh xem trước cục bộ trong khi hình ảnh chính từ xa đang tải.
- Hiển thị hình ảnh xem trước trước khi phát video.

:::important
Để sử dụng tính năng này, hãy cập nhật Adapty Flutter SDK lên phiên bản 3.8.0 trở lên.
:::

Dưới đây là ví dụ về cách bạn có thể cung cấp các asset tùy chỉnh thông qua một dictionary đơn giản:

```dart

final customAssets = {
    // Show a local image using a custom ID
    'custom_image': AdaptyCustomAsset.localImageAsset(
        assetId: 'assets/images/image_name.png',
    ),

    // Show a local video with a preview image
    'hero_video': AdaptyCustomAsset.localVideoAsset(
        assetId: 'assets/videos/custom_video.mp4',
    ),
};

try {
  final view = await AdaptyUI().createPaywallView(
    paywall: paywall,
    customAssets: customAssets,
  );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

:::note
Nếu không tìm thấy asset, paywall sẽ trở về giao diện mặc định của nó.
:::

## Thiết lập bộ đếm thời gian do nhà phát triển định nghĩa \{#set-up-developer-defined-timers\}

Để sử dụng bộ đếm thời gian tùy chỉnh trong ứng dụng di động của bạn, hãy truyền một map `customTimers` vào phương thức `createPaywallView`. Mỗi key trong map là một timer ID, và giá trị của nó là một đối tượng `DateTime` xác định thời điểm bộ đếm kết thúc. Dưới đây là ví dụ:

```dart showLineNumbers

try {
  final view = await AdaptyUI().createPaywallView(
        paywall: paywall,
        customTimers: {
          'CUSTOM_TIMER_6H': DateTime.now().add(const Duration(seconds: 3600 * 6)),
          'CUSTOM_TIMER_NY': DateTime(2025, 1, 1), // New Year 2025
        },
      );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Trong ví dụ này, `CUSTOM_TIMER_NY` và `CUSTOM_TIMER_6H` là các **Timer ID** của các timer do developer định nghĩa mà bạn đã cài đặt trong Adapty Dashboard. Map `customTimers` đảm bảo ứng dụng của bạn tự động cập nhật mỗi timer với giá trị chính xác. Ví dụ:

- `CUSTOM_TIMER_NY`: Thời gian còn lại cho đến khi timer kết thúc, chẳng hạn như Ngày đầu năm mới.
- `CUSTOM_TIMER_6H`: Thời gian còn lại trong khoảng thời gian 6 giờ bắt đầu khi người dùng mở paywall.

</SDKv3>
