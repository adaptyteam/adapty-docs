Интеграция Adapty с Amazon S3 позволяет безопасно хранить данные о событиях и посещениях пейволов в одном месте. Вы сможете сохранять [события подписок](events) в свой бакет Amazon S3 в виде .csv-файлов.  
Для настройки интеграции потребуется выполнить несколько простых шагов в AWS Console и дашборде Adapty.

:::note
Расписание

Adapty отправляет данные каждые **24 часа** в 4:00 UTC.

Каждый файл содержит данные о событиях, созданных за предыдущий календарный день по UTC. Например, данные, автоматически экспортированные в 4:00 UTC 8 марта, будут содержать все события, созданные 7 марта с 00:00:00 до 23:59:59 по UTC.
:::

## Как настроить интеграцию с Amazon S3 \{#how-to-set-up-amazon-s3-integration\}

Для получения данных вам понадобятся следующие учётные данные:

1. Access key ID
2. Secret access key
3. S3 bucket name
4. Folder name inside the S3 bucket

:::note
Вложенные директории

В поле имени бакета Amazon S3 можно указывать вложенные директории, например: adapty-events/com.sample-app
:::

Чтобы подключить Amazon S3, перейдите в [**Integrations** -> **Amazon S3**](https://app.adapty.io/integrations/s3), включите переключатель и заполните поля.

Сначала укажите учётные данные для установки соединения между Amazon S3 и профилями Adapty.

В дашборде Adapty для настройки подключения нужны следующие поля:

| Поле                         | Описание                                                     |
| :--------------------------- | :----------------------------------------------------------- |
| **Access Key ID**            | Уникальный идентификатор для аутентификации пользователя или приложения при доступе к сервису AWS. Найдите этот идентификатор в загруженном [csv-файле](s3-exports#how-to-create-amazon-s3-credentials). |
| **Secret Access Key**        | Приватный ключ, используемый совместно с Access Key ID для аутентификации при доступе к сервису AWS. Найдите этот ключ в загруженном [csv-файле](s3-exports#how-to-create-amazon-s3-credentials). |
| **S3 Bucket Name**           | Глобально уникальное имя, идентифицирующее конкретный S3-бакет в облаке AWS. S3-бакеты — это простой сервис хранения, позволяющий хранить и получать объекты данных (файлы, изображения и т. д.) в облаке. |
| **Folder Inside the Bucker** | Название папки, которую вы хотите создать внутри выбранного S3-бакета. Обратите внимание: S3 имитирует папки с помощью префиксов ключей объектов, которые по сути и являются именами папок. |

```json showLineNumbers title="Json"
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowListObjectsInBucket",
            "Effect": "Allow",
            "Action": "s3:ListBucket",
            "Resource": "arn:aws:s3:::adapty-s3-integration-test"
        },
        {
            "Sid": "AllowAllObjectActions",
            "Effect": "Allow",

        {
            "Sid": "AllowBucketLocation",
            "Effect": "Allow",
            "Action": "s3:GetBucketLocation",

        }
    ]
}
```

## Структура таблицы \{#table-structure\}

В интеграции с AWS S3 Adapty предоставляет таблицу для хранения исторических данных о транзакционных событиях и посещениях пейвола. Таблица содержит информацию о профиле пользователя, выручке и чистом доходе, источнике стора и других параметрах. По сути, эти таблицы фиксируют все транзакции, сгенерированные приложением за определённый период времени.

:::warning
Обратите внимание, что эта структура может расширяться со временем — по мере добавления новых данных нами или третьими сторонами, с которыми мы работаем. Убедитесь, что ваш код, обрабатывающий её, достаточно устойчив и опирается на конкретные поля, а не на структуру в целом.
:::

Чтобы добавить столбцы **source**, **flow_id**, **flow_name** и **screen_id**, на вкладке **Paywall visits** в настройках интеграции установите флажок **Add Flow columns to paywalls export**. Эти столбцы будут добавлены в конец файла.

## Транзакции виртуальной валюты \{#virtual-currency-transactions\}

Экспорт виртуальной валюты отправляет каждое изменение баланса [виртуальной валюты](virtual-currencies) в ваш бакет Amazon S3. Используйте его, чтобы загрузить полную историю начислений, списаний, истечений срока и возвратов в собственное хранилище данных.

Этот экспорт не зависит от экспорта событий и посещений пейвола. У него отдельный переключатель, отдельные учётные данные и собственные настройки бакета и папки.

### Включение экспорта \{#turn-on-the-export\}

1. Перейдите в [**Integrations** -> **Amazon S3**](https://app.adapty.io/integrations/s3) и откройте вкладку **Virtual currency**.
2. Включите **Export virtual currency transactions to Amazon S3**.
3. Введите [учётные данные](#how-to-create-amazon-s3-credentials): идентификатор ключа доступа, секретный ключ доступа, имя S3-бакета и папку. Поля те же, что и на вкладке **Paywall visits**.

Чтобы экспортировать транзакции виртуальной валюты за прошлые дни, воспользуйтесь [ручным экспортом данных](#manual-data-export).

### Файл и расписание

Каждый день Adapty загружает 1 файл с транзакциями виртуальной валюты за предыдущий календарный день по UTC. Транзакция относится к тому дню, который соответствует её времени `created_at` по UTC.

Имя файла — `<app_id>_virtual_currency_<date>.csv`, где `<date>` — это дата, следующая за днём транзакций, в формате `YYYY-MM-DD`. Например, файл `<app_id>_virtual_currency_2026-03-08.csv` содержит транзакции за 7 марта 2026 года. У каждого экспорта своё имя файла. Храните каждый экспорт в отдельной папке, чтобы таблица или загрузчик, читающий всю папку, получал только один тип файлов. Если экспорты находятся в общей папке, выбирайте файлы этого экспорта по имени: `<app_id>_virtual_currency_*.csv`.

Файл представляет собой UTF-8 `.csv`-файл со строкой заголовка. Если за день не было транзакций, файл содержит только строку заголовка.

Каждая строка соответствует одному изменению баланса одной валюты. Транзакция, затрагивающая 2 валюты — например, обмен золота на кристаллы, — даёт 2 строки с одинаковым `vc_transaction_id`. Транзакции из песочницы также включены в файл: для них поле `is_sandbox` имеет значение `true`.

При сохранении настроек Adapty проверяет учётные данные каждого активного экспорта. Если учётные данные виртуальной валюты недействительны, Adapty не сохранит настройки. Кнопка **Save** сохраняет настройки всех вкладок, поэтому изменения на остальных вкладках тоже не будут сохранены.

Экспорт виртуальной валюты использует собственные учётные данные. Если ежедневная загрузка завершится ошибкой, загрузка событий и посещений пейвола в приложении продолжит работу в штатном режиме.

### Столбцы

В файле есть следующие столбцы, расположенные в указанном порядке. Adapty добавляет новые столбцы только в конец файла.

| Столбец | Описание |
| :----- | :---------- |
| **vc_transaction_id** | Adapty ID транзакции виртуальной валюты. Все строки одной транзакции имеют одинаковый ID. Это не `Idempotency-Key` вашего API-запроса. |
| **created_at** | Время транзакции в UTC в формате `YYYY-MM-DD HH:MM:SS.ffffff+00:00`, например `2026-03-07 14:05:09.000000+00:00`. |
| **profile_id** | Adapty ID профиля. |
| **customer_user_id** | Customer user ID профиля на момент экспорта. Пустое, если у профиля нет customer user ID или он больше не существует. |
| **operation** | [Операция](virtual-currencies#operation) транзакции: `top_up`, `refund`, `spend`, `spend_reversal`, `reward`, `reward_reversal`, `exchange`, `expiry`, `migration` или `adjustment`. Пустое для транзакции через серверный API, отправленной без `operation`. |
| **transaction_type** | Способ записи транзакции в Adapty, например `store_purchase`, `subscription_renewal`, `trial_start` или `api_transaction`. `subscription_renewal` используется для каждого оплаченного периода подписки, включая первый. |
| **currency_code** | Код виртуальной валюты. |
| **amount** | Изменение баланса в виде целого числа. Положительное для пополнения, отрицательное для списания. |
| **balance_after** | Баланс данной валюты в профиле после этого изменения в виде целого числа. Никогда не бывает ниже 0. |
| **store** | Стор транзакции: `app_store`, `play_store`, `stripe`, `paddle`, `adapty` или название кастомного стора. Пустое, если транзакция не связана ни с каким стором. |
| **store_transaction_id** | ID транзакции покупки в сторе. Совпадает с **transaction_id** в таблице событий для данной покупки. Пустое, если транзакция не связана с покупкой в сторе. |
| **store_original_transaction_id** | Оригинальный ID транзакции покупки в сторе. Одинаковый для всех продлений подписки. Заполняется в строках покупки в сторе, её возврата и истечения срока действия. |
| **product_id** | ID продукта в сторе для данной покупки. Пустое, если у строки нет транзакции в сторе или если у Adapty нет записи об этой покупке. |
| **expires_at** | Время истечения срока действия зачисленной суммы в UTC в формате `YYYY-MM-DD HH:MM:SS.ffffff+00:00`, например `2026-04-07 14:05:09.000000+00:00`. Заполняется только в строках кредита с ограниченным сроком действия. |
| **feature** | Параметр [`feature`](virtual-currencies#feature) транзакции. |
| **reference_id** | Параметр `reference_id` транзакции. |
| **customer_placement_id** | Параметр `customer_placement_id` транзакции. |
| **is_sandbox** | `true` для транзакции в песочнице, `false` для продакшн-транзакции. |
| **metadata** | Параметр `metadata` транзакции в виде одного JSON-значения в одной ячейке. Пустое, если у транзакции нет метаданных. |

### Объединение с таблицей событий \{#join-with-the-events-table\}

В файле виртуальной валюты нет цен. Чтобы получить цену покупки, которая начислила валюту, объедините строку начисления с таблицей событий:

- Сопоставьте **store_transaction_id** с **transaction_id** таблицы событий.
- Сопоставьте также **store**, но только для `app_store`, `play_store`, `stripe` и `paddle`. Для `adapty` и кастомных сторов поле **store** в таблице событий пустое.

В этом примере запроса предполагается, что вы загрузили файлы виртуальной валюты в таблицу `vc_transactions`, а файлы событий — в таблицу `events`:

```sql title="SQL"
SELECT
  vc.vc_transaction_id,
  vc.created_at,
  vc.profile_id,
  vc.currency_code,
  vc.amount,
  e.event_type,
  e.product_id,
  e.revenue_usd,
  e.currency,
  e.revenue_local
FROM vc_transactions AS vc
LEFT JOIN events AS e
  ON e.transaction_id = vc.store_transaction_id
  AND (
    e.store = vc.store
    OR vc.store NOT IN ('app_store', 'play_store', 'stripe', 'paddle')
  )
  AND e.event_type IN (
    'subscription_initial_purchase',
    'subscription_started',
    'subscription_renewed',
    'trial_started',
    'trial_converted',
    'non_subscription_purchase'
  )
WHERE vc.amount > 0
  AND COALESCE(vc.store_transaction_id, '') <> '';
```

Запрос использует стандартные названия событий. Начало подписки обозначается как `subscription_initial_purchase` в интеграциях, созданных с середины сентября 2025 года, и как `subscription_started` — в более ранних. Если вы изменили названия событий в настройках экспорта событий, используйте в запросе свои названия.

Строка кредита не имеет соответствующего события, если экспорт событий отключён, если настройки экспорта исключают или переименовывают тип события для данной покупки, либо если событие исключено параметром **Exclude Historical Events**.

Одна покупка может зачислить сразу несколько валют. Для каждой валюты создаётся отдельная строка зачисления, и все эти строки относятся к одному событию. Чтобы подсчитать выручку, считайте каждый **store_transaction_id** только один раз.

### Ограничения \{#limitations\}

- **Нет цен и сумм возврата**: в файле виртуальной валюты нет цены покупки и суммы возврата. Чтобы получить цену, [объедините строку кредита с таблицей событий](#join-with-the-events-table).
- **Не суммируйте кредиты из двух файлов**: столбец **virtual_currency_credits** файла [событий](#table-structure) и строки кредитов файла виртуальной валюты отображают одни и те же кредиты покупок. Для подсчёта кредитов используйте один из них, но не оба. Их итоговые значения могут различаться: файл событий содержит только кредиты покупок и только для тех событий, которые заданы в настройках экспорта, тогда как файл виртуальной валюты содержит все изменения баланса, включая начисления через API и ручные корректировки в дашборде.
- **Нет связи между расходом и его кредитами**: файл не показывает, какие именно кредиты были использованы при расходе — купленные или начисленные.
- **Строки возврата содержат только возвращённые кредиты**: строка возврата отображает кредиты, которые Adapty вернул с баланса. Значение **amount** может быть меньше кредитов, начисленных при покупке, — например, если пользователь уже потратил часть из них. Если кредитов не осталось, строка возврата в файле отсутствует.
- **Нет строки возврата при апгрейде подписки**: возврат, возникающий при переходе на более дорогую подписку, не забирает кредиты. Строка возврата для него в файле не создаётся.

## События и теги \{#events-and-tags\}

Вы можете управлять тем, какие данные передаются в рамках интеграции. Доступны следующие параметры настройки:

| Настройка | Описание |
| :--------------------------------- | :----------------------------------------------------------- |
| **Exclude Historical Events** | Позволяет исключить события, произошедшие до того, как пользователь установил приложение с Adapty SDK. Это предотвращает дублирование событий и обеспечивает точность отчётов. Например, если пользователь активировал ежемесячную подписку 10 января, а обновил приложение с Adapty SDK 6 марта, Adapty пропустит события до 6 марта и сохранит последующие. |
| **Include events without profile** | Позволяет включить транзакции, не привязанные к профилю пользователя в Adapty. Это могут быть покупки, совершённые до установки Adapty SDK, или транзакции, полученные из серверных уведомлений стора, которые невозможно сразу связать с конкретным пользователем. |
| **Send User Attributes** | Если вы хотите передавать атрибуты пользователей, например языковые предпочтения, и ваш тарифный план OneSignal поддерживает более 10 тегов, выберите этот параметр. Включение этой опции позволяет передавать дополнительную информацию сверх стандартных 10 тегов. Обратите внимание: превышение лимита тегов может привести к ошибкам. |
| **Add virtual currency credits** | Добавляет столбец **virtual_currency_credits** в конец каждой строки файла событий (см. [Структура таблицы](#table-structure)). Параметр также применяется к [ручному экспорту данных](#manual-data-export), так что вы можете повторно экспортировать прошедшие дни, чтобы получить этот столбец. |
