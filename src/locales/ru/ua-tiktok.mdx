С интеграцией TikTok for Business в Adapty Attribution вы можете отслеживать и оптимизировать свои рекламные кампании в TikTok.

:::tip
Смотрите наш [гайд по настройке рекламы в TikTok for Business](tiktok-create-campaign).
:::

## Шаг 1. Подключите аккаунт TikTok \{#step-1-connect-your-tiktok-account\}

1. Перейдите в **Integrations > TikTok Ads** в левом сайдбаре и нажмите **Continue with TikTok**.

<ZoomImage id="ua-connect-tiktok.webp" width="700px" />

2. Войдите в аккаунт TikTok и нажмите **Continue**.

3. Ознакомьтесь с запрашиваемыми разрешениями и нажмите **Save**.

<ZoomImage id="ua-tiktok-sign.webp" width="500px" />

После этого все ваши рекламные аккаунты будут добавлены в Adapty UA. Можно переходить к добавлению кампаний.

## Шаг 2. Добавьте кампании \{#step-2-add-campaigns\}

Одна кампания может охватывать App Store, Google Play и ваш веб-воронку одновременно. Соединение обеспечивают два элемента:

- **Ссылка для отслеживания**: Используется в объявлении. Когда пользователь нажимает на рекламу, Adapty фиксирует клик, перенаправляет пользователя на целевую страницу и впоследствии связывает установку и покупки с этим объявлением. Для каждого назначения создаётся отдельная ссылка.
- **Пиксель**: Выбирается в кампании из пикселей в вашем аккаунте TikTok. Передаёт данные о конверсиях обратно в TikTok, чтобы TikTok мог оптимизировать кампанию на основе реальных покупок. Один пиксель может обслуживать все три назначения, или для каждого назначения можно использовать отдельный пиксель.

Чтобы добавить кампанию TikTok for Business в Adapty Attribution и отслеживать результаты ваших TikTok-объявлений в Adapty:

1. Переключитесь на приложение, которое хотите рекламировать.

2. Откройте вкладку **Web Campaigns** и нажмите **Create configuration**. Эта конфигурация учитывает только установки того приложения, на которое вы переключились.

   <ZoomImage id="ua-new-campaign-tiktok.webp" width="500px" />

3. На вкладке **General** раскройте раздел **iOS** и/или **Android** и вставьте URL-адреса приложения из App Store и/или Google Play.

   <ZoomImage id="ua-url.webp" width="900px" />

4. Скопируйте значение поля **Click link**. Затем в TikTok Ads Manager при создании объявления вставьте это значение в поле **Destination URL**, как описано в [Добавление контента объявления](tiktok-create-campaign#step-5-add-ad-content). Это позволит Adapty связывать установки и покупки с объявлениями в TikTok. Adapty связывает установки с объявлением только тогда, когда пользователи переходят напрямую из него в стор по этой ссылке.

   <ZoomImage id="ua-lnk.webp" width="900px" />

5. (Опционально) Чтобы отправлять события конверсии обратно в TikTok, привяжите пиксели TikTok к этой конфигурации:
   1. В раскрывающемся списке **Pixel** выберите пиксель, который используется в вашей кампании в TikTok Ads Manager. Если у вас ещё нет пикселя, [создайте его в TikTok](tiktok-create-campaign#step-2-create-a-pixel).
   2. Чтобы проверить соединение, нажмите **Send test event**.

6. Если ваши объявления ведут в веб-воронку, раскройте раздел **Web funnel** конфигурации:
   1. (Опционально) В выпадающем списке **Pixel** выберите пиксель для веб-покупок. TikTok узнаёт о покупках в вашей воронке только через этот пиксель.
   2. Чтобы установить [веб-пиксель Adapty](ua-web-pixel), вставьте **Pixel snippet** на каждую страницу вашей воронки.
   3. Чтобы [пометить URL ваших объявлений](ua-tag-ad-urls), скопируйте **Ad URL parameters**.

   Если ваша воронка работает на [FunnelFox](ua-funnelfox), пропустите этот фрагмент. Adapty не отправляет покупки FunnelFox в TikTok. Чтобы отправлять их, настройте [интеграцию TikTok Pixel](https://funnelfox.com/docs/integrations/tracking/tiktok-pixel) в FunnelFox.

Чтобы правильно настроить пиксели:

- **Совместите пиксели с кампаниями**: если одна кампания охватывает App Store, Google Play и ваш веб-фанел, выберите один и тот же пиксель во всех трёх разделах. Если для каждого канала запущена отдельная кампания, выберите отдельный пиксель для каждой — тогда каждая кампания будет оптимизироваться по своим покупкам. В списке **Web Campaigns** пиксели каждой конфигурации отображаются в столбцах **Pixel (iOS)**, **Pixel (Android)** и **Pixel (Web)**.
- **Редактируйте существующую конфигурацию, чтобы сменить пиксель**: активные объявления используют ссылку отслеживания своей конфигурации, поэтому их конверсии передаются в пиксели именно этой конфигурации. Чтобы сменить пиксель для работающих объявлений, выберите другой пиксель в той же конфигурации. Создание новой конфигурации не изменит, куда идут конверсии текущих объявлений.
- **Заполните поле Event source URL**: если вы привязали пиксель к своему сайту в TikTok, введите адрес сайта в поле **Event source URL** конфигурации. В противном случае TikTok может пометить конверсии из Adapty как поступающие с неизвестного сайта. Это поле не влияет на адрес ваших ссылок отслеживания.

## Шаг 3. Настройте маппинг событий \{#step-3-map-events\}

Adapty отправляет выбранные вами события, например запуск триалов, в пиксели конфигурации. TikTok использует эти события, чтобы находить пользователей, которые с высокой вероятностью запустят триал или оформят подписку.

Чтобы выбрать события, в разделе **Events mapping** конфигурации:

1. Включите каждое событие, которое Adapty должен отправлять в TikTok.
2. Для каждого события выберите событие TikTok из выпадающего списка или введите собственное. По умолчанию Adapty выбирает стандартные события TikTok. **Install** можно отправить только как **Lead**.
3. Нажмите **Save**.

## Дополнительная настройка \{#additional-configuration\}

### Дополнительные параметры \{#additional-parameters\}

Поле **Additional parameter** позволяет добавлять пользовательские данные для анализа за пределами Adapty. Это полезно, когда нужно передать конкретные данные о кампании или пользователе во внешние инструменты аналитики или партнёрам по атрибуции.

В поле **Additional parameter** введите любые пользовательские данные, которые хотите включить в отслеживание атрибуции. Дополнительный параметр будет передаваться во всех данных атрибуции, отправляемых в TikTok, и может использоваться для углублённого анализа и оптимизации кампаний.

Например, если вы запускаете несколько вариаций одной кампании, можно добавить `variant=A` или `variant=B`, чтобы различать разные креативные подходы.

:::important
Дополнительные параметры изменяют **Click link**, который вы вставляете в TikTok Ads Manager. Если вы уже скопировали эту ссылку туда и добавили пользовательский параметр позже, обязательно скопируйте и вставьте обновлённую click link, содержащую этот параметр.
:::

### Настройки \{#settings\}

Вкладка **Settings** в конфигурации определяет, как Adapty сопоставляет установки с кликами по вашим рекламным объявлениям в TikTok. Adapty использует один из двух методов:

| Метод | Установки | Как Adapty засчитывает установку | Лимит времени между кликом и установкой |
|---|---|---|---|
| Совпадение по ID клика | Установки на Android с ID клика | К клику с ID, который Google Play передаёт в ваше приложение | 168 часов (7 дней) по умолчанию, до 720 часов |
| Вероятностное совпадение | Установки на iOS и установки на Android без ID клика | К наиболее вероятному недавнему клику с того же диапазона IP-адресов и операционной системы | 6 часов по умолчанию, до 24 часов |

Для вероятностного совпадения Adapty выбирает клик с наилучшим значением по времени с момента клика, языку устройства и стране. Adapty не использует IDFA или Google Advertising ID, поэтому вероятностное совпадение охватывает пользователей iOS, которые не разрешили отслеживание.

Adapty не может вероятностно сопоставить установку, если устройство сменило сеть между кликом и установкой — например, перешло с Wi-Fi на мобильную сеть. В сетях, которые используют сразу много устройств (например, в сетях мобильных операторов), Adapty сопоставляет меньше установок вероятностным способом.

Чтобы изменить временны́е ограничения, в разделе **New user attribution** вкладки **Settings** укажите каждое ограничение в часах:

- **Deterministic Matching Window**: для сопоставления по ID клика.
- **Probabilistic Matching Window**: для вероятностного сопоставления. Более длинное ограничение охватывает больше установок, но увеличивает долю ошибочных совпадений. Для кампаний с высоким объёмом кликов сократите его до 1–2 часов. Если задать более 6 часов, клики, произошедшие за 6 и более часов до установки, должны также совпадать по модели устройства и версии ОС.

Оставьте переключатели обоих полей включёнными. Без вероятностного сопоставления Adapty не сможет сопоставить iOS-установки из ссылок этой конфигурации.

<ZoomImage id="ua-meta-attribution-settings.webp" width="900px" alt="Раздел атрибуции новых пользователей на вкладке Settings с окнами детерминированного и вероятностного сопоставления и их переключателями вкл/выкл" />

### Выручка, передаваемая в TikTok \{#revenue-sent-to-tiktok\}

TikTok использует сумму каждого события для расчёта ROAS и оптимизации на основе ценности. Чтобы выбрать, какую выручку Adapty будет передавать в TikTok в качестве этого значения, в выпадающем списке **Revenue sent to TikTok** выберите тип выручки и нажмите **Save**. Чтобы сравнить ROAS в TikTok с ROAS в Adapty, выберите тот тип, который вы [отображаете в аналитике Adapty](controls-filters-grouping-compare-proceeds#display-gross-or-net-revenue).

<ZoomImage id="ua-revenue-sent-tiktok.webp" width="700px" alt="Раскрытый список Revenue sent to TikTok с вариантами Gross revenue, Proceeds after store commission и Proceeds after store commission and taxes" />

| Тип выручки | Значение покупки в App Store или Google Play |
|---|---|
| **Gross revenue** (по умолчанию) | Полная цена, которую заплатил пользователь, до вычета комиссии стора и налогов. |
| **Proceeds after store commission** | Цена за вычетом комиссии App Store или Google Play. Налоги по-прежнему включены. |
| **Proceeds after store commission and taxes** | Цена за вычетом комиссии стора и налогов. |

О том, как Adapty рассчитывает комиссию и налоги, читайте в разделе [Комиссии и налоги](how-adapty-analytics-works#commissions-and-taxes).

Применение типа в других случаях:

- **Веб-покупки**: Для покупок через Stripe и Paddle оба типа выручки отправляют одно и то же значение, как в аналитике атрибуции Adapty: цена за вычетом 4,5% для Stripe и полная цена для Paddle. Adapty не вычитает налоги из веб-покупок.
- **Возвраты**: TikTok получает события возврата без значения, независимо от типа.
- **Триальные события**: Процент [переопределения дохода](#revenue-override) применяется к цене подписки выбранного типа.
- **Покупки без суммы выбранного типа**: Adapty отправляет в TikTok валовую выручку от покупки.

Новый тип выручки вступает в силу в течение 5 минут после сохранения и применяется только к новым событиям. Adapty не переотправляет уже отправленные события, а событие пробного периода, которое Adapty уже удерживает для [Qualified trial](#qualified-trial), отправляется с типом, который был выбран в момент начала удержания.

Если несколько конфигураций отправляют события в один и тот же пиксель, выберите одинаковый тип выручки во всех из них, чтобы значения в этом пикселе были одного типа.

:::warning
Proceeds ниже, чем валовая выручка. Если вы переключитесь с **Gross revenue**, а кампания использует минимальный ROAS, снизьте минимальный ROAS в TikTok, иначе кампания может перестать показываться.
:::

### Переопределение выручки \{#revenue-override\}

По умолчанию Adapty отправляет событие **Trial started** в TikTok без значения выручки, поскольку при старте пробного периода оплата не происходит. С переопределением выручки Adapty отправляет значение, которое вы задаёте: процент от цены подписки. Adapty берёт этот процент от цены в том типе, который выбран в разделе [Revenue sent to TikTok](#revenue-sent-to-tiktok). Например, при 30% Adapty отправляет 30% от цены подписки. Для событий **Trial converted** и **Subscription started** всегда отправляется фактическая выручка.

Переопределение дохода изменяет значение, которое TikTok получает для триала. [Квалифицированный триал](#qualified-trial) изменяет момент, когда TikTok его получает. Вы можете использовать оба варианта для одного и того же события.

Чтобы передать доход в TikTok для начатых триалов:

1. В разделе **Events mapping** включите событие **Trial started**. Появится раздел **Revenue override**.
2. В разделе **Revenue override** нажмите **Add event**.
3. Выберите событие TikTok, которое вы сопоставили с **Trial started**, например **StartTrial**.
4. Введите процент от стоимости подписки для передачи — от 0 до 100.
5. Нажмите **Save**.

### Квалифицированный триал \{#qualified-trial\}

:::important
Для отчётов о квалифицированных триалах необходимо настроить [App Store Server Notifications](enable-app-store-server-notifications) для iOS и [Real-time Developer Notifications](enable-real-time-developer-notifications-rtdn) для Android. App Store и Google Play сообщают Adapty об отменах триалов через эти каналы.
:::

По умолчанию Adapty отправляет каждый начатый триал в TikTok сразу, даже если пользователь отменяет его вскоре после начала. При использовании квалифицированного триала TikTok учитывает только те триалы, которые пользователи сохраняют — если автопродление не отключается в течение заданного количества часов после начала триала. Adapty отправляет событие с оригинальным временем начала триала, поэтому TikTok отображает его на дату начала триала. Если для события также задан параметр переопределения дохода, Adapty отправляет его с переопределённым значением дохода.

Чтобы отправлять в TikTok только те триалы, которые пользователи сохраняют:

1. В разделе **Events mapping** включите событие **Trial started**.
2. В разделе **Qualified trial** нажмите **Add event**.
3. Выберите событие TikTok, которое вы привязали к **Trial started**, например **StartTrial**.
4. Укажите количество часов ожидания — от 1 до 24. Adapty отправляет событие примерно через 45 минут после окончания ожидания.
5. Нажмите **Save**.

<ZoomImage id="qualified-trial.webp" width="700px" alt="Раздел Qualified trial с целевым событием с задержкой в два часа в настройках кампании" />

Если пользователь повторно включает автопродление до истечения ожидания, Adapty отправляет событие в запланированное время. Qualified trials применяются только к триалам из App Store и Google Play.

#### Qualified trials и событие Trial still active \{#qualified-trials-vs-the-trial-still-active-event\}

В Adapty есть два способа отправлять только те триалы, которые пользователи оставляют. Для TikTok используйте qualified trial: Adapty Attribution не может отправить событие [Trial still active](events#synthetic-events) в TikTok. Если другая интеграция, например AppsFlyer, также отправляет триалы в TikTok, TikTok получит один и тот же триал несколько раз.

| | Qualified trial | Событие **Trial still active** |
|---|---|---|
| Где настраивается | В Adapty Attribution, в настройках Meta, TikTok или Google Ads | В Adapty, в интеграциях AppsFlyer, Adjust, Firebase или вебхуке |
| Что делает | Задерживает событие **Trial started** | Добавляет отдельное событие после **Trial started** |
| Время ожидания | От 1 до 24 часов | От 1 часа до 90 дней |
| Если пользователь отключает автопродление до окончания ожидания | Adapty не отправляет событие | Adapty не отправляет событие |
| Отправляется в TikTok через Adapty Attribution | Да | Нет |

### Отправка событий от всех пользователей \{#send-events-from-all-users\}

По умолчанию Adapty отправляет события только тех пользователей, которых относит к данной конфигурации. Опция **Send events from all users** позволяет отправлять события всех пользователей вашего приложения — включая органических, пользователей из других рекламных сетей и других конфигураций TikTok. Исключение составляют покупки из воронок FunnelFox: Adapty использует их только в аналитике Adapty Attribution. Чтобы передавать их в TikTok, настройте [интеграцию TikTok Pixel](https://funnelfox.com/docs/integrations/tracking/tiktok-pixel) в FunnelFox. TikTok самостоятельно решает, какие из этих конверсий засчитать своей рекламе. Данная опция не влияет на атрибуцию в Adapty.

Мы не рекомендуем это делать, если только ваши кампании не получают слишком мало конверсий из TikTok для оптимизации — смешивание органических и неатрибутированных событий с событиями кампании снижает точность оптимизации в TikTok.

Если вы всё же решите включить эту опцию, в настройках конфигурации выберите **Send events from all users** и нажмите **Save**.

## Корректное чтение данных TikTok Ads в атрибуции Adapty \{#read-tiktok-ads-data-correctly-in-adapty-attribution\}

Чтобы сопоставить расходы в TikTok с установками и выручкой в [аналитике атрибуции Adapty](ua-analytics):

- **Ожидайте изменений в недавних расходах**: TikTok постоянно корректирует расходы, показы и клики за последние дни. Каждые 4 часа Adapty обновляет эти данные за последние 3 дня, включая сегодняшний.
- **Ожидайте, что дневные расходы и выручка используют разные часовые пояса**: Adapty Attribution показывает расходы TikTok по дням в часовом поясе вашего рекламного аккаунта. Установки и выручка отображаются по дням в UTC. Если часовые пояса различаются, дневные расходы и дневная выручка охватывают разные часы. Чтобы отображать установки и выручку в другом часовом поясе, обратитесь в [службу поддержки Adapty](mailto:support@adapty.io).
