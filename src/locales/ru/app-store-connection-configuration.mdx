Чтобы подключить iOS-приложение к Adapty, введите учётные данные App Store в **App settings** > **iOS SDK**. После этого Adapty:

- Проверяет покупки.
- Получает события подписок.
- Синхронизирует ваши продукты с App Store Connect.

Если покупки или события подписки перестали поступать в Adapty, [проверьте каждый из реквизитов](#check-each-credential).

<YouTube id="VJQbzoTCkqs" />

Прежде чем начать:

- Вам нужен доступ к целевому приложению в App Store Connect. Если приложения там ещё нет, [настройте App Store Connect](set-up-app-store-connect). Если у вас нет доступа к платформе, запросите его.
- Вашей команде нужен доступ к API App Store Connect — он необходим для генерации нужного ключа доступа. Если у вашей команды его ещё нет, попросите Account Holder [запросить его](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api). Apple проверяет каждый запрос.
- Откройте две вкладки браузера: ваше приложение в [App Store Connect](https://appstoreconnect.apple.com/apps) в одной и [**App settings** > **iOS SDK**](https://app.adapty.io/settings/ios-sdk) в Adapty в другой. В ходе этого гайда вы будете копировать значения между вкладками.

## Обзор \{#overview\}

Каждый из учётных данных в этом гайде обязателен. Adapty использует каждый из них для [определённой части обмена данными с App Store](store-sync#if-updates-stop-arriving). Чтобы завершить настройку, выполните следующие семь шагов:

1. Введите [Bundle ID и Apple App ID](#enter-the-bundle-id-and-apple-app-id)
2. Введите [app-specific shared secret](#enter-the-app-specific-shared-secret)
3. Включите [уведомления сервера App Store](#enable-app-store-server-notifications) с URL-адресом из Adapty
4. Добавьте [ключ In-App Purchase](#add-the-in-app-purchase-key)
5. Добавьте [ключ App Store Connect API](#add-the-app-store-connect-api-key)
6. Установите [SDK Adapty и совершите тестовую покупку в песочнице](#check-each-credential)
7. [Проверьте все данные](#check-each-credential)

## Введите Bundle ID и Apple App ID \{#enter-the-bundle-id-and-apple-app-id\}

Два значения идентифицируют ваше приложение в App Store Connect: Bundle ID и Apple ID, который в Adapty называется **Apple App ID**. Bundle ID необходим Adapty для обработки покупок. Apple ID позволяет Adapty:

- Находит ваши продукты в App Store Connect и [создаёт новые там](create-product#create-product-and-push-to-store).
- Показывает статус и цены ваших продуктов в App Store.
- Доставляет сообщения в реальном времени для [Retention Messaging](retention-messaging-setup).
- Запускает анализ [AI Growth Advisor](autopilot).
- Идентифицирует ваше приложение для интеграций атрибуции, например AppsFlyer.

Apple присваивает Apple ID при добавлении приложения в App Store Connect, поэтому вводите его даже до того, как приложение появится в App Store.

## Введите app-specific shared secret \{#enter-the-app-specific-shared-secret\}

Adapty нужен app-specific shared secret для валидации чеков покупок и создания продуктов в App Store Connect.

1. В [App Store Connect](https://appstoreconnect.apple.com/apps) откройте страницу **App Information** вашего приложения. В разделе **App-Specific Shared Secret** нажмите **Manage**.

   <ZoomImage id="asc-app-information-shared-secret.webp" width="700px" alt="Раздел App-Specific Shared Secret на странице App Information в App Store Connect" />

2. Скопируйте секрет. Если у приложения ещё нет секрета, сначала нажмите **Generate**. Для генерации секрета необходима роль Account Holder или Admin в App Store Connect. Если у вас нет ни одной из этих ролей, попросите того, у кого она есть, сгенерировать секрет и передать его вам.

   Если вы не получали приложение через [передачу приложения](transfer-apps#app-store-ios-transfer), не нажимайте **Regenerate**: текущий секрет перестанет работать везде, где он используется.

   <ZoomImage id="asc-shared-secret-dialog.webp" width="700px" alt="App-Specific Shared Secret window with the secret" />

3. В Adapty вставьте секрет в поле **App Store Connect shared secret**.

   <ZoomImage id="app-settings-shared-secret.webp" width="700px" alt="App Store Connect shared secret field in Adapty" />

4. Нажмите **Save**.

## Включите серверные уведомления App Store с URL от Adapty \{#enable-app-store-server-notifications\}

:::link
Основная статья: [Включение серверных уведомлений App Store](enable-app-store-server-notifications)
:::

Apple отправляет серверные уведомления в Adapty о продлениях, возвратах средств и других событиях подписки в режиме реального времени. Adapty записывает эти события даже тогда, когда приложение не сообщает ни о каких транзакциях.

Если Apple уже отправляет эти уведомления на ваш сервер, настройте переадресацию на него до того, как замените URL в App Store Connect. В Adapty укажите URL этого сервера в поле **URL for forwarding raw Apple events** и нажмите **Save**. После этого Adapty будет [пересылать полученные от Apple уведомления](enable-app-store-server-notifications#raw-events-forwarding) на ваш сервер.

Если ваш бэкенд должен сохранить свой URL в App Store Connect, [передавайте уведомления в Adapty со стороны бэкенда](forwarding-events-to-adapty).

## Добавьте ключ API App Store Connect \{#add-the-app-store-connect-api-key\}

:::link
Основная статья: [Добавление ключа API App Store Connect в Adapty](app-store-connect-api-key)
:::

Adapty использует ключ API App Store Connect для [создания продуктов в App Store Connect](create-product#create-product-and-push-to-store) и синхронизации их статуса и цен. Это отдельный ключ, не связанный с ключом In-App Purchase, хотя оба используют одни и те же названия полей: **Issuer ID** и **Key ID**.

Adapty требует командный ключ с доступом **Admin**. Если у вас его ещё нет, сначала [создайте его в App Store Connect](app-store-connect-api-key#generate-a-team-key-in-app-store-connect). Чтобы подключить ключ в Adapty:

## Проверьте, что каждый ключ работает \{#check-each-credential\}

Чтобы убедиться, что Adapty корректно валидирует покупки, [установите SDK](installation-of-adapty-sdks) в своё приложение и [совершите тестовую покупку в песочнице](test-purchases-in-sandbox).

При тестовой покупке в песочнице используются не все ключи. Проверьте каждый из них после покупки, а также каждый раз, когда покупки или события подписки перестают поступать в Adapty:

- **Bundle ID**, **Apple App ID** и **App Store Connect shared secret**: сравните эти три значения с **Bundle ID**, **Apple ID** и секретом в разделе **App-Specific Shared Secret** на странице **App Information** в App Store Connect.
- **App Store server notifications**: статус в этом разделе отображается как **Active**, когда Adapty получает уведомление о покупке или продлении подписки. Если отображается другой статус, [проверьте URL сервера](enable-app-store-server-notifications#check-that-notifications-reach-adapty).
- **In-app purchase API (StoreKit 2)**: Adapty проверяет ключ через Apple при сохранении. Если покупки в приложении перестали открывать доступ, ключ мог перестать работать — [замените его](generate-in-app-purchase-key#replace-the-key).
- **App Store promotional offers**: убедитесь, что **Subscription key ID** совпадает с **Key ID** в разделе **In-app purchase API (StoreKit 2)**. Если они отличаются, [введите одинаковый ключ в оба раздела](generate-in-app-purchase-key#add-the-key-to-adapty).
- **App Store Connect API key**: для каждого продукта App Store на странице **Products** в столбце **App Store status** отображается статус. Если для продукта стоит прочерк или статус **Not Connected**, [проверьте ключ и Apple App ID](troubleshoot-app-store-integration#products-dont-appear-or-show-no-app-store-status).

Сразу после настройки Analytics может показывать больше триалов и покупок, чем установок, и больше, чем отображается в Event Feed. Разница — это [транзакции без профилей](how-profiles-work#transactions-without-profiles): покупки пользователей, которые ещё не открывали версию приложения с Adapty SDK.

Другие расхождения между отчётами Adapty и стора объясняются [тем, как каждый из них считает покупки](discrepancies-and-troubleshooting), а не настройками учётных данных.
