Переменные позволяют отображать динамический контент во флоу — цены продуктов, детали оферов и другие данные, которые меняются в зависимости от контекста каждого пользователя. Используйте их для управления видимостью элементов и персонализации экранов.

Чтобы открыть интерфейс управления переменными, нажмите <Inline id="variables.svg" alt="Variables" /> на левой панели. Интерфейс включает три вкладки:

- **[Пользовательские](#custom-variables)**: Переменные флоу и [пользовательские теги](flow-custom-tags) — переменные, которые вы задаёте из своего приложения.
- **[Продукт](#product-variables)**: Встроенные переменные, которые подтягивают локализованные данные о продукте и офере из стора.
- **[Элемент](#element-variables)**: Переменные элементов на холсте, например ответ на вопрос квиза или состояние переключателя.

## Пользовательские переменные \{#custom-variables\}

### Создание пользовательской переменной \{#create-a-custom-variable\}

1. Откройте панель <Inline id="variables.svg" alt="Variables" /> Variables в конструкторе флоу.
2. Добавьте новую переменную — нажмите <Inline id="plus.svg" alt="Plus" />.
3. Укажите **Name** переменной.
4. (Необязательно) Чтобы различать переменные между собой, заполните поле **Description**. При наведении курсора на имя переменной в конструкторе вы увидите это описание.
5. Выберите **Value Type**: **String**, **Number**, **Boolean**, **Array**, **Date** или **Formula**. Вставить переменную в текстовый элемент можно только если её тип — String, Number, Date или Formula.
   - **Date**: Календарная дата, например дата начала пробного периода. Введите начальное значение в формате `DD.MM.YYYY` или выберите его в календаре. В выпадающем списке **Date format** укажите, как текстовые элементы будут отображать дату. См. [Формулы](flow-formulas#show-a-date-in-a-text-element).
   - **Formula**: Число или дата, которые флоу вычисляет на основе ответов пользователя, других переменных и цен продуктов. Формула всегда зависит от других значений, поэтому у неё нет начального значения. Вместо этого введите формулу в поле **Expression**. См. [Формулы](flow-formulas).

   <ZoomImage id="flow-variable-value-type.webp" width="300px" alt="Выпадающее меню «Value Type» с типами String, Number, Boolean, Array, Date и Formula" />

6. В поле **Initial value** введите значение, которое переменная принимает при запуске флоу. Для переменной типа Date значение Initial value необязательно. У Formula значения Initial value нет.
7. (Необязательно, только для переменных типа **String**) Чтобы задавать значение переменной из кода приложения, установите флажок **Value comes from outside the app**. Это действие необратимо и фиксирует **Value Type**. Переменная становится [кастомным тегом](flow-custom-tags) — приложение должно устанавливать её значение при загрузке флоу. Если значение не передано, пользователи видят начальное значение в качестве резервного.
8. Нажмите **Create variable**.

Переменные привязаны к конкретному флоу. Чтобы использовать переменную в другом флоу, создайте её там тоже.

Если вы удаляете кастомную переменную, которую используют условия, билдер сначала спрашивает подтверждение. В диалоге — например, **Delete "user.goal"?** — перечислены все условия, использующие эту переменную. Если нажать **Delete**, эти условия сломаются, и опубликовать флоу не получится, пока вы их не исправите: выберите существующую переменную в каждом условии или удалите условие.

:::tip
Используйте точки в именах, чтобы группировать связанные переменные — например, `user.score` или `user.goal`.
:::

<ZoomImage id="create-variable.webp" width="500px" alt="Создание пользовательской переменной" />

### Обновление переменной через взаимодействие \{#update-a-variable-via-an-interaction\}

:::link
Подробнее см. в статье [Действия](onboarding-actions).
:::

Вы можете обновить значение переменной во время выполнения, добавив действие **Set variable** к любому элементу.

1. Выберите элемент на холсте.
2. На вкладке **Interactions** нажмите **Add trigger**.
3. Выберите **On tap** и нажмите **Add action**. В выпадающем списке **Action type** выберите **Set variable**.
4. Нажмите **Add variable**. Выберите переменную и задайте новое значение.

:::tip
Например, можно присвоить разные значения переменной `user.goal` в зависимости от ответа пользователя в квизе, а затем использовать эту переменную для перехода на нужный экран.
:::

## Переменные продукта \{#product-variables\}

Переменные продукта получают локализованные данные напрямую из сторов. Используйте их в текстовых полях для отображения локализованных цен, названий и деталей офферов — или в условиях, чтобы показывать или скрывать контент в зависимости от доступности оффера. Когда вы вставляете переменную для конкретного продукта, билдер добавляет этот продукт в список экрана на панели [**Products**](paywall-product-block#add-products-to-a-screen).

| Переменная | Описание | Пример |
| :--- | :--- | :--- |
| `prod_title` | Локализованное название продукта | Premium Subscription |
| `prod_price` | Локализованная цена за один расчётный период | $9.99 |
| `prod_price_per_day` | Цена подписки в пересчёте на один день. Пусто для разовых покупок. | $0.33 |
| `prod_price_per_week` | Цена подписки в пересчёте на одну неделю. Пусто для разовых покупок. | $2.33 |
| `prod_price_per_month` | Цена подписки в пересчёте на один месяц. Пусто для разовых покупок. | $9.99 |
| `prod_price_per_year` | Цена подписки в пересчёте на один год. Пусто для разовых покупок. | $119.88 |
| `prod_billing_price` | Локализованная цена одного платежа. Отличается от `prod_price` только для [12-месячного тарифного плана](#12-month-commitment-plan). | $9.99 |
| `prod_billing_period` | Локализованный период одного платежа. Отличается от периода подписки только для 12-месячного тарифного плана. Пусто для разовых покупок. | 1 month |
| `offer_price` | Локализованная цена introductory offer или promotional offer. Пусто, если пользователь не имеет права ни на одно предложение. | $0.99 |
| `offer_billing_period` | Локализованный расчётный период предложения. Совпадает с `offer_full_duration` для trial и pay-upfront предложений. Пусто, если пользователь не имеет права. | 1 week |
| `offer_full_duration` | Локализованная полная длительность предложения. Пусто, если пользователь не имеет права. | 1 month |
| `offer_price_per_day`, `offer_price_per_week`, `offer_price_per_month`, `offer_price_per_year` | Цена предложения в пересчёте на один день, неделю, месяц или год. Цена pay-up-front предложения распределяется по всей его длительности; бесплатный trial возвращает нулевую цену. Пусто, если пользователь не имеет права. | $4.24 (`offer_price_per_month`) |
| `intro_price` | Локализованная цена первой платной фазы предложения. Отличается от `offer_price` только для предложения, которое начинается с бесплатного trial. Пусто, если у предложения нет платной фазы. См. [Бесплатный trial с последующей вводной ценой](#free-trial-followed-by-an-intro-price). | $2.99 |
| `intro_billing_period` | Локализованный расчётный период первой платной фазы предложения. Пусто, если у предложения нет платной фазы. | 1 month |
| `intro_full_duration` | Локализованная полная длительность первой платной фазы предложения. Пусто, если у предложения нет платной фазы. | 3 months |
| `is_free_trial` | Возвращает `true`, если пользователь имеет право на предложение с бесплатным trial. | true |
| `is_pay_up_front` | Возвращает `true`, если пользователь имеет право на pay-up-front предложение. | true |
| `is_pay_as_you_go` | Возвращает `true`, если пользователь имеет право на pay-as-you-go предложение. | true |
| `has_intro_price` | Возвращает `true`, если пользователь имеет право на предложение с платной фазой: pay-as-you-go или pay-up-front ценой. | true |
| `is_monthly_plan` | Возвращает `true`, если пользователь приобретает продукт по 12-месячному тарифному плану. | true |

Переменные `prod_price_per_*` конвертируют цену продукта из его расчётного периода в нужный вам период. При конвертации используются фиксированные длины периодов, а не календарные даты:

- 1 неделя = 7 дней
- 1 месяц = 30 дней
- 1 год = 12 месяцев, 52 недели или 365 дней

Для ежемесячной подписки за $59,99 переменная `prod_price_per_week` вернёт $14,00: $59,99 × 7 ÷ 30 = $13,9977, округлённых для отображения. В месяце 30 / 7 ≈ 4,2857 недели, поэтому умножение недельного значения на 4 не вернёт исходную цену.

:::tip
Используйте `is_free_trial`, `is_pay_up_front` и `is_pay_as_you_go` с условной видимостью, чтобы показывать или скрывать элементы в зависимости от того, какой оффер доступен пользователю. Например, показывайте таймлайн бесплатного пробного периода только когда `is_free_trial` равно `true`.
:::

Значения переменных оффера зависят от типа оффера, на который имеет право пользователь. Для примера рассмотрим недельную подписку «Premium Subscription» за $5 с тремя возможными офферами:

- **Pay As You Go**: Первые 3 недели за $3 (списывается еженедельно), затем $5/неделю.
- **Pay Up Front**: Первые 3 недели за $8 (списывается сразу), затем $5/неделю.
- **Free Trial**: Первая неделя бесплатно, затем $5/неделю.

В этом примере `prod_title` возвращает «Premium Subscription», а `prod_price` возвращает $5. Значения переменных оффера зависят от того, на какой оффер имеет право пользователь:

| Переменная | Pay As You Go | Pay Upfront | Free Trial |
| :--- | :--- | :--- | :--- |
| `offer_price` | $3 | $8 | $0 |
| `offer_billing_period` | 1 неделя | 3 недели | 1 неделя |
| `offer_full_duration` | 3 недели | 3 недели | 1 неделя |

Для офферов Pay Upfront и Free Trial `offer_billing_period` и `offer_full_duration` возвращают одинаковое значение. Для Pay As You Go они различаются, поскольку расчётный период составляет одну неделю, а полная длительность — три недели.

Все эти значения поступают из стора, поэтому предпросмотр в билдере разрешает только часть из них: значения офферов остаются неразрешёнными на канвасе, а `is_free_trial`, `is_pay_up_front`, `is_pay_as_you_go` и `has_intro_price` соответствуют офферу, выбранному на карточке продукта. Чтобы просмотреть каждый тип оффера в процессе работы, см. раздел [Предпросмотр продуктов и офферов](paywall-device-compatibility-preview#preview-products-and-offers).

:::note
Подробнее об офферах и их настройке — в разделе [Офферы](offers).
:::

### Бесплатный пробный период с последующей вводной ценой \{#free-trial-followed-by-an-intro-price\}

[Google Play offer](google-play-offers) может состоять из двух фаз: бесплатный пробный период, а затем сниженная цена. Переменные `offer_*` считывают первую фазу предложения, поэтому для такого оффера они описывают бесплатный пробный период. Переменные `intro_*` считывают первую платную фазу, поэтому они описывают сниженную цену.

Например, возьмём подписку за $9,99 в месяц с Google Play offer: первая неделя бесплатно, затем $2,99 в месяц на 3 месяца. Для пользователя, который имеет право на это предложение, переменные возвращают:

| Переменная | Значение |
| :--- | :--- |
| `offer_price` | $0 |
| `offer_full_duration` | 1 week |
| `intro_price` | $2.99 |
| `intro_billing_period` | 1 month |
| `intro_full_duration` | 3 months |
| `is_free_trial` | `true` |
| `has_intro_price` | `true` |

Оффер в App Store состоит из одной фазы. Для платного оффера App Store переменные `intro_*` возвращают те же значения, что и переменные `offer_*`. Для бесплатного пробного периода App Store переменные `intro_*` пустые, а `has_intro_price` равно `false`.

Чтобы показывать сниженную цену только тем пользователям, которые её получают, поместите текст с переменными `intro_*` в элемент, [видимый](onboarding-element-visibility) только при значении `has_intro_price` равном `true`. Тогда пользователи, у которых нет платного периода в их предложении, не увидят предложение с пустыми значениями.

:::important
Для Google Play offer, начинающегося с бесплатного пробного периода, переменные `intro_*` требуют Adapty Android SDK v4.4.2 или выше, React Native SDK v4.4.0 или выше, либо Flutter SDK v4.4.1 или выше. В более старых версиях SDK во флоу передаётся только первая фаза оффера, поэтому переменные `intro_*` пусты, а `has_intro_price` равно `false`. Если оффер не включает бесплатный пробный период, у него одна платная фаза, и переменные `intro_*` возвращают её значения на всех версиях SDK.
:::

### План с 12-месячным обязательством \{#12-month-commitment-plan\}

С [планом с 12-месячным обязательством](set-up-12-month-commitment) подписчики оплачивают годовой продукт 12 ежемесячными платежами. Apple требует, чтобы на пейволе отображалась как сумма ежемесячного платежа, так и общая годовая стоимость до совершения покупки. Для отображения обоих значений вставьте `prod_billing_price` и `prod_billing_period` для ежемесячного платежа и `prod_price` для общей годовой стоимости. Например: «$9.99 в месяц на протяжении 12 месяцев, итого $119.88».

Значения зависят от того, может ли пользователь приобрести план с обязательством:

| Переменная | Тариф с обязательством применяется | Тариф с обязательством не применяется или предоплатный тариф |
| :--- | :--- | :--- |
| `prod_billing_price` | $9.99 | То же, что и `prod_price` |
| `prod_billing_period` | 1 месяц | 1 год |
| `prod_price` | $119.88 | $99.99 |
| `is_monthly_plan` | `true` | `false` |

Пользователи, которые [не могут приобрести тариф с обязательством](set-up-12-month-commitment#4-add-to-a-flow-or-custom-paywall), получают предоплатный тариф — например, на устройствах Apple ранее iOS 26.4 или в странах, где этот тариф недоступен.

:::important
`prod_billing_price` и `prod_billing_period` требуют Adapty SDK версии 4.3.1 или выше для iOS, или версии 4.3.0 или выше для React Native, Flutter, Unity или Capacitor. На более ранних версиях SDK вместо этих переменных отображаются `prod_price` и период подписки. Для покупки с планом обязательств на Adapty iOS SDK v4.3.0 это будет общая сумма за год и «1 year».
:::

## Переменные элементов \{#element-variables\}

Переменные элементов фиксируют выборы пользователя — что он выбрал в викторинах, на какой вкладке находится и включён ли переключатель.

Типы переменных элементов зависят от группы:
- **Single choice**: Квизы с одиночным выбором, вкладки и переключатели:
    - `selectedOptionId`: ID элемента для использования в условиях
    - `selectedOptionTitle`: Заголовок элемента для использования в динамическом тексте
- **Multi-choice**: Квизы с множественным выбором:
    - `selectedOptionIds`: ID элементов для использования в условиях
    - `selectedOptionTitles`: Заголовки элементов для использования в динамическом тексте
- **Toggle**: Элементы, переключающиеся между включённым и выключенным состоянием:
    - `isActive`: Булево значение
- **Product**: Карточки продуктов:
    - `selectedProduct`: Выбранный продукт для использования в условиях

Распространённые сценарии использования:
- Отображение разного контента в зависимости от того, включён ли переключатель пробного периода.
- [Переход пользователей на разные экраны](onboarding-navigation-branching) в зависимости от их ответов в квизе

## Используйте переменные в тексте \{#use-variables-in-text\}

Чтобы вставить переменную в текстовый элемент:

1. Выберите текстовый элемент на холсте.
2. На вкладке **Design** найдите поле **Content** и введите текст.
3. Нажмите <Inline id="variables.svg" alt="Variables" /> в поле.
4. Выберите переменную. На вкладке **Product** продукты, уже добавленные в панель **Products**, отображаются первыми. Остальной каталог находится в разделе **Other products**.

:::tip
Переменные можно использовать и в других элементах:
- Используйте переменные в ссылках и уведомлениях, чтобы сделать их динамическими
- Создавайте динамические условия на основе переменных. Например, условие может выглядеть так: `if experience.current > experience.target, navigate to...`
:::

<ZoomImage id="insert-var.webp" width="500px" alt="Вставка переменной в текстовый элемент" />

### Переменные стилей \{#style-variables\}

Применить форматирование к отдельной переменной нельзя. Если выделить переменную в поле **Content** и попытаться сделать её жирной, курсивной, подчёркнутой, зачёркнутой или изменить её цвет — ничего не произойдёт.

Форматирование применяется только ко всему текстовому блоку целиком. Чтобы стилизовать текст, используйте раздел **Typography** на вкладке **Design** или выберите сохранённый [стиль текста](onboarding-text#set-up-text-styles).

### Повторное использование контента на разных экранах \{#reuse-content-across-screens\}

Некоторый контент повторяется на нескольких экранах флоу — например, подпись кнопки «Продолжить», призыв к действию или дисклеймер, который показывается на нескольких экранах. То же касается более длинных текстов — например, описания функции, которое используется на нескольких экранах. Вместо того чтобы вводить этот контент в каждый элемент вручную, сохраните его в кастомной переменной. Это удобно, когда вы направляете разных пользователей на разные экраны, но хотите, чтобы формулировки везде были одинаковыми.

1. [Создайте пользовательскую переменную](#create-a-custom-variable) типа String и задайте её начальное значение как текст, который хотите переиспользовать. Например, назовите её `button.navigation` и установите значение `Continue`.
   <ZoomImage id="reuse-create-variable.webp" width="500px" alt="Creating a custom variable with its initial value set to the reusable text" />
2. Вставьте эту переменную в поле **Content** каждого элемента, где должен появляться этот текст.

Чтобы изменить текст везде сразу, достаточно один раз обновить начальное значение переменной. Все элементы, использующие её, обновятся автоматически — редактировать каждый экран вручную не нужно.

<ZoomImage id="reuse-insert-variable.webp" width="500px" alt="Одна и та же пользовательская переменная, вставленная в поле Content сразу в нескольких элементах" />

Значения пользовательских переменных не поддерживают локализацию: переменная отображает одно и то же значение во всех локалях. Чтобы перевести повторно используемый текст, в [панели **Localizations**](add-paywall-locale-in-adapty-paywall-builder#translate-strings-manually) замените переменную переводом в каждой строке, где она встречается.
