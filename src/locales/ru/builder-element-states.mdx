Интерактивные элементы флоу меняют внешний вид в зависимости от действий пользователя: нажатый вариант квиза становится **Selected**, сфокусированное поле ввода — **Active**. Стилизуйте каждое состояние отдельно, чтобы давать пользователям визуальную обратную связь без написания кода.

Некоторые состояния зависят от условия, которое вы задаёте, — например, от значения переменной или состояния другого элемента:

- [**Disabled**](#add-the-disabled-state): пользователи не могут взаимодействовать с элементом.
- [Пользовательские состояния](#add-a-custom-state): вы сами называете состояние, задаёте его условие и оформляете элемент для него. Никакое действие не переключает элемент в пользовательское состояние напрямую. Вместо этого [измените пользовательскую переменную по нажатию](#switch-an-element-to-a-custom-state-on-tap) и привяжите условие состояния к этой переменной.

Элемент [находится только в одном состоянии одновременно](#when-several-states-apply-to-one-element).

## Доступные состояния по типу элемента \{#available-states-by-element-kind\}

| Тип элемента | Встроенные состояния | Добавляемые состояния |
|---|---|---|
| [Выбираемые элементы](#selectable-element-states) | **Default**, **Selected** | **Disabled**, **custom** states (кроме заголовков вкладок) |
| [Поля ввода](#input-states) | **Default**, **Active**, **Invalid** | **Disabled**, **custom** states (кроме пикеров) |
| [Любой элемент с взаимодействием по нажатию](#add-a-state) — кнопки, изображения, контейнеры и т.д. (кроме текстовых элементов и иконок) | **Default** | **Disabled**, **custom** states (кроме нижних листов) |
| [Шаги индикатора прогресса](#step-states-for-progress-indicators) | **Completed**, **Current**, **Upcoming** | — |

Состояния **Addable** не отображаются у элемента, пока вы их не [добавите](#add-a-state). Каждое из них зависит от условия, которое вы настраиваете.

Условия других элементов тоже могут учитывать состояния элементов. Например, можно [объяснить, почему кнопка недоступна](element-states-in-conditions#explain-why-a-button-is-disabled).

## Настройка стиля для состояния \{#style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="Раздел States в правой панели выбранного элемента" float="right" />


1. Выберите элемент. В разделе **States** правой панели отображаются вкладки для каждого состояния, которое есть у элемента.
2. В разделе **States** активируйте нужное состояние. Если вкладки для этого состояния нет — [добавьте его](#add-a-state).
3. Измените любое свойство — заливку, рамку, типографику и т. д. Изменение применится только к этому состоянию.

    Вложенные элементы становятся состоятельными вместе с родителем. Любое изменение дочернего элемента ограничено активным состоянием родителя.

4. SDK Adapty применяет соответствующий стиль во время выполнения.

## Состояния выбираемого элемента \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Selectable element with Selected state activated and a style override applied" />

Выбираемые элементы — варианты ответов в квизе, продукты, вкладки, переключатели и чекбоксы, а также любой [пользовательский выбираемый элемент](flow-selectable-elements#make-an-element-selectable) — имеют два состояния по умолчанию:

- **Default**: Обычный вид элемента в состоянии покоя.
- **Selected**: Активируется, когда пользователь нажимает на элемент. Элемент возвращается в состояние **Default**, когда пользователь снимает выбор.

В группе с одиночным выбором выбор одного элемента снимает выделение с остальных. Группы с множественным выбором позволяют выбирать несколько элементов одновременно. Переключатели независимы — выбор одного не влияет на соседние. См. [типы групп](flow-selectable-elements#group-types).

:::tip
Чтобы повторно использовать стили для конкретных состояний, добавьте их к одному элементу, например к карточке продукта. Затем попросите [AI Editor](flow-ai-editor) применить их к остальным элементам. Стили для состояний не переносятся между соседними элементами автоматически.
:::

## Состояния поля ввода \{#input-states\}

- **Default**: Вид поля в состоянии покоя.
- **Active**: Применяется, пока поле в фокусе.
- **Invalid**: Применяется, когда содержимое поля не проходит валидацию — например, если в поле email нет символа `@`. См. [Валидация поля ввода](builder-inputs-and-forms#input-validation).
- **Disabled**: Поле недоступно для взаимодействия. [Добавьте это состояние](#add-the-disabled-state) вручную.

Стилизация каждого состояния работает так же, как у выбираемого элемента: активируйте нужное состояние, затем измените свойства.

## Состояния шагов для индикаторов прогресса \{#step-states-for-progress-indicators\}

:::link
Основная статья: [Индикаторы прогресса](builder-loaders-and-progress-bars#step-states)
:::

Индикаторы прогресса показывают пользователям, какую часть онбординга они уже прошли. Каждый шаг имеет три состояния:

- **Completed**: Пройденные шаги.
- **Current**: Текущий шаг пользователя.
- **Upcoming**: Шаги, до которых пользователь ещё не дошёл.

## Когда к одному элементу применяется несколько состояний \{#when-several-states-apply-to-one-element\}

К одному элементу могут применяться сразу несколько состояний. Например:

- Пользователь вводит некорректный адрес в поле email, затем снова нажимает на поле, чтобы исправить его. Поле в фокусе, значит применяется **Active**. Адрес по-прежнему некорректен, значит применяется и **Invalid**.
- Пользователь включает переключатель пробного периода, значит применяется **Selected**. Затем он выбирает тариф без пробного периода. Для этого тарифа у переключателя задано условие **Disabled**, значит применяется и **Disabled**.

Элемент одновременно находится только в одном состоянии. Если применяется несколько состояний, элемент находится в том, которое стоит последним в этом списке:

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. Пользовательские состояния в том порядке, в котором вы их добавили

В примерах поле email находится в состоянии **Active**, а переключатель пробного периода — в состоянии **Disabled**. Элемент выглядит так, как вы настроили это состояние. Условие, проверяющее состояние элемента, совпадает только с этим состоянием. Если ни одно состояние из списка не применяется, элемент находится в состоянии **Default**.

Пользовательское состояние влияет только на внешний вид. Если при этом активно состояние **Disabled**, элемент находится в пользовательском состоянии, но пользователи не могут с ним взаимодействовать.

## Добавьте состояние \{#add-a-state\}

### Добавьте состояние Disabled \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="Меню добавления состояния кнопки с вариантами Disabled и Custom state" />

Чтобы запретить пользователю взаимодействовать с элементом, добавьте состояние **Disabled**:

1. Выберите целевой элемент.
2. Если в разделе **States** нет вкладки **Disabled**, нажмите **Add state** и выберите **Disabled**. Если у элемента уже есть состояния, кроме **Default**, перед **Add state** нажмите **Settings** <Inline id="settings.svg" alt="Settings" />.
3. Наведите курсор на **Disabled** и нажмите **Set conditions**.
4. Добавьте условие. Если нужно заблокировать кнопку **submit** до тех пор, пока ввод не пройдёт валидацию, сравните переменную `isValid` поля ввода со значением `false`. Чтобы состояние **Disabled** применилось, заполните все поля **Value**.
5. Оформите состояние Disabled визуально, чтобы показать ограничение (например, уменьшите прозрачность).

<ZoomImage id="element-states-disabled-condition.webp" width="400px" alt="The Edit conditional state popover with the condition email.isValid = False" />

SDK Adapty вычисляет условие в рантайме и применяет состояние Disabled при необходимости — никакого кода приложения не нужно.

Условие **Disabled** также может оценивать состояние другого элемента. Например, вы можете [отключить два элемента вместе](element-states-in-conditions#synchronize-element-states).

### Добавление пользовательского состояния \{#add-a-custom-state\}

Если встроенные состояния не подходят, добавьте пользовательское: оно может зависеть от ответа, нажатия или состояния другого элемента. Например:

- Выделить карточку годового плана, пока включён переключатель пробного периода.
- Изменить цвет кнопки **Remind me** после нажатия. Чтобы настроить это, [переключите кнопку в пользовательское состояние по нажатию](#switch-an-element-to-a-custom-state-on-tap).

Пользовательское состояние меняет только внешний вид. Чтобы запретить пользователям взаимодействовать с элементом, [добавьте состояние **Disabled**](#add-the-disabled-state).

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="The States list with the Custom state option off and the caption Add a tap action to use custom states" />

Эти элементы могут иметь пользовательские состояния:

- **Кнопки, изображения, контейнеры, видео, таймеры и карусели**: им нужно [действие по нажатию](onboarding-actions#set-up-interactions). Если удалить действие по нажатию, пользователи перестанут видеть пользовательские состояния.
- **Выбираемые элементы**: им нужна группа или действие по нажатию.
- **Поля ввода**: текст, email, пароль, число и телефон.

Эти элементы не могут иметь пользовательские состояния:

- Заголовки вкладок и содержимое вкладок
- Пикеры
- Нижние шторки
- Шаги индикатора прогресса

У элемента может быть до 5 пользовательских состояний. При достижении лимита опция **Custom state** отключается с подписью «Up to 5 custom states». Конфиг из Adapty CLI или AI-инструмента может содержать больше состояний — их всё равно можно редактировать.

1. Выберите целевой элемент.
2. В разделе **States** нажмите **Add state** и выберите **Custom state**. Если у элемента уже есть состояния, кроме **Default**, нажмите **Settings** <Inline id="settings.svg" alt="Settings" /> перед **Add state**.
3. В поле **Name** введите название состояния, например **Locked**. Пока название нарушает одно из правил, под полем отображается ошибка, а **Save** остаётся неактивной:

    - **Имя обязательно**: имя не может быть пустым.
   - **Максимум 30 символов**: имя не может быть длиннее 30 символов.
   - **Это имя зарезервировано**: имя не может быть **Default**, `focused` или совпадать с именем встроенного состояния: **Selected**, **Active**, **Invalid**, **Disabled**, **Completed**, **Current** или **Upcoming**.
   - **Состояние с таким именем уже существует**: каждое пользовательское состояние элемента должно иметь уникальное имя. Регистр букв не делает имена разными.

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="The Edit state panel with the name Locked and the condition plan = free" />

4. Добавьте условие, например `plan` = `free`. Чтобы добавить больше строк, нажмите **Add Condition**. Если достаточно одной истинной строки, нажмите **all**, чтобы переключить на **any**. Чтобы состояние применилось, заполните каждое поле **Value**.
5. Нажмите **Save**.
6. Чтобы оформить состояние, активируйте его вкладку в разделе **States** и [измените свойства элемента](#style-a-state). Для текстового поля пользовательское состояние изменяет только заливку, рамку и скругление углов.

Конструктор не предупреждает о пустом поле **Value**. Если в строке указано значение, но не выбрана переменная, опубликовать флоу не получится: диалог **Can't publish yet** отобразит эту строку в разделе **Broken references**. Adapty CLI и API вернут ошибку [**Invalid State Condition**](flow-common-issues#a-flow-wont-preview-or-publish) для такой строки.

На видео или карусели смена состояния может перезапустить видео или вернуть карусель к первому слайду.

Условие кастомного состояния также может [учитывать состояние другого элемента](element-states-in-conditions#add-an-element-state-to-a-condition), например, является ли переключатель **Selected**.

### Переключение элемента в пользовательское состояние по нажатию \{#switch-an-element-to-a-custom-state-on-tap\}

Ни одно действие не переключает элемент непосредственно в пользовательское состояние. Вместо этого измените пользовательскую переменную по нажатию, а условие состояния задайте на основе этой переменной.

1. [Создайте пользовательскую переменную](onboarding-variables#create-a-custom-variable) типа **Boolean** с начальным значением `false`.
2. Выберите элемент, который нажимают пользователи. На вкладке **Interactions** [добавьте действие **Set variable**](onboarding-variables#update-a-variable-via-an-interaction) к триггеру **On Tap** и установите значение переменной равным `true`.
3. [Добавьте пользовательское состояние](#add-a-custom-state) к элементу, который переключается. В условии выберите переменную на вкладке **Custom** поля **Variable**. Установите в поле **Value** значение `true`.

<ZoomImage id="element-states-custom-variable-picker.webp" width="500px" alt="Вкладка Custom поля Variable, где переменная reminder.set выбрана в условии пользовательского состояния" />

### Редактирование и удаление пользовательского состояния \{#edit-or-delete-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="The tooltip of the Locked tab with the Edit state button" />

Чтобы переименовать пользовательское состояние или изменить его условие, выберите элемент. В разделе **States** правой панели наведите курсор на вкладку состояния и нажмите **Edit state**. Либо нажмите **Settings** <Inline id="settings.svg" alt="Settings" /> в этом разделе и кликните по названию состояния. Стили состояния сохранятся, а условия, которые его используют, отобразят новое название.

Чтобы удалить пользовательское состояние, выберите элемент. В разделе **States** на правой панели нажмите **Settings** <Inline id="settings.svg" alt="Settings" />, затем нажмите значок корзины в строке нужного состояния. Если состояние используется в условиях, диалог сначала покажет их список. После нажатия **Delete** эти условия сломаются, и публикация флоу будет недоступна до их исправления. Чтобы вернуть состояние вместе со стилями, отмените удаление.
