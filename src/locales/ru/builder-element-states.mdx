Интерактивные элементы флоу меняют внешний вид в зависимости от действий пользователя: нажатая опция в квизе переходит в состояние **Selected**, а сфокусированный ввод — в **Active**. Некоторые состояния определяются условиями: можно **отключить** кнопку или добавить [кастомное состояние](#custom-states) с собственным именем и условием. Настройте стиль каждого состояния отдельно, чтобы обеспечить визуальную обратную связь без кода в приложении.

## Доступные состояния по типу элемента \{#available-states-by-element-kind\}

| Вид элемента | Встроенные состояния | Добавляемые состояния |
|---|---|---|
| [Выбираемые элементы](#selectable-element-states) | **Default**, **Selected** | **Disabled**, [пользовательские состояния](#custom-states) |
| [Поля ввода](#input-states) | **Default**, **Active**, **Invalid** | **Disabled**; [пользовательские состояния](#custom-states) для текстовых, email, password, number и phone полей |
| [Любой элемент с взаимодействием по нажатию](#condition-driven-disabled-state) — кнопки, изображения, иконки, контейнеры и т. д. | **Default** | **Disabled**, [пользовательские состояния](#custom-states) для [поддерживаемых элементов](#elements-that-support-custom-states) |
| [Шаги индикатора прогресса](#step-states-for-progress-indicators) | **Completed**, **Current**, **Upcoming** | — |

Состояния типа **Addable** не отображаются по умолчанию — откройте **States settings** <Inline id="settings.svg" alt="Settings" />, чтобы добавить их. Они работают на основе условий: вы определяете, когда они активируются. См. [Состояние Disabled на основе условий](#condition-driven-disabled-state) и [Пользовательские состояния](#custom-states).

Условия других элементов также могут оценивать состояния элементов. Например, можно [объяснить, почему кнопка неактивна](element-states-in-conditions#explain-why-a-button-is-disabled).

## Когда к одному элементу применяется несколько состояний \{#when-several-states-apply-to-one-element\}

К одному элементу можно применить несколько состояний одновременно. Например:

- Пользователь вводит некорректный адрес в поле email, затем снова нажимает на это поле, чтобы исправить его. Поле в фокусе — применяется **Active**. Адрес всё ещё некорректен — применяется **Invalid**.
- Пользователь включает переключатель пробного периода — применяется **Selected**. Затем выбирает план без пробного периода. Для переключателя задано условие **Disabled** для этого плана — применяется и **Disabled**.
- У кнопки **Continue** есть состояние **Disabled** и пользовательское состояние **Locked**. Оба условия истинны — применяются оба состояния.

Элемент может находиться только в одном состоянии одновременно. Если применимо несколько состояний, элемент находится в том, которое стоит последним в этом списке:

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. [Пользовательское состояние](#custom-states)

Если применимо несколько пользовательских состояний, элемент находится в том, которое стоит последним в списке настроек **States**.

В примерах поле email находится в состоянии **Active**, переключатель trial — в состоянии **Disabled**, а кнопка **Continue** — в состоянии **Locked**. Элемент выглядит так, как вы настроили это состояние. Условие, проверяющее состояние элемента, срабатывает только при соответствующем состоянии. Если ни одно из этих состояний не применяется, элемент находится в состоянии **Default**.

Пользовательское состояние задаёт только внешний вид элемента. Элемент в состоянии **Disabled** по-прежнему не реагирует на нажатия, даже если пользовательское состояние меняет его внешний вид.

## Как настроить стиль состояния \{#how-to-style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="Раздел States в правой панели выбранного элемента" float="right" />


1. Выберите элемент. Раздел **States** в правой панели отображает поддерживаемые этим элементом состояния.
2. В разделе **States** активируйте нужное состояние. При необходимости добавьте [состояние Disabled на основе условий](#condition-driven-disabled-state) или [пользовательское состояние](#custom-states).
3. Измените любое свойство — заливку, рамку, типографику и т. д. Изменение применится только к этому состоянию.

    Вложенные элементы становятся состоятельными вместе с родительским. Любое изменение дочернего элемента применяется только в рамках активного состояния родителя.

4. Builder применяет подходящий стиль во время выполнения.

## Состояния выбираемого элемента \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Selectable element with Selected state activated and a style override applied" />

Выбираемые элементы — варианты ответов в квизе, продукты, вкладки, переключатели и чекбоксы, а также любые [пользовательские выбираемые элементы](flow-selectable-elements#make-an-element-selectable) — имеют два состояния по умолчанию:

- **Default**: Исходный внешний вид элемента.
- **Selected**: Применяется, когда пользователь нажимает на элемент. Builder возвращается к Default, когда пользователь снимает выбор.

В группе с единственным выбором выбор одного элемента снимает выделение с остальных. Группы с множественным выбором позволяют выбирать несколько элементов одновременно. Переключатели независимы — выбор одного не влияет на соседние. Подробнее о [типах групп](flow-selectable-elements#group-types).

:::tip
Чтобы повторно использовать стили для конкретных состояний, добавьте их к одному элементу, например к карточке продукта. Затем попросите [AI Editor](flow-ai-editor) применить их к остальным элементам. Стили для конкретных состояний не переносятся между соседними элементами автоматически.
:::

## Состояния ввода \{#input-states\}

- **Default**: Стандартный вид поля в состоянии покоя.
- **Active**: Применяется, пока поле находится в фокусе.
- **Invalid**: Применяется, когда содержимое поля не проходит валидацию. Например, если в поле email нет символа `@`. См. [Валидация полей](builder-inputs-and-forms#input-validation).
- **Disabled**: Поле недоступно для взаимодействия. Добавьте это состояние вручную; см. [Состояние Disabled на основе условий](#condition-driven-disabled-state).
- **Custom states**: Только для полей типа text, email, password, number и phone. В кастомном состоянии изменяются только заливка, граница и скругление углов поля. См. [Кастомные состояния](#custom-states).

Стилизуйте каждое состояние так же, как селектируемый элемент: активируйте нужное состояние, измените свойства.

## Состояние Disabled на основе условий \{#condition-driven-disabled-state\}

Состояние Disabled запрещает пользователю взаимодействовать с элементом. В отличие от Default, Selected, Active или Invalid, состояние Disabled не активируется само по себе — для него нужно задать условие-триггер вручную.

Disabled доступно для:

- **Поля ввода**: Любое [поле ввода](builder-inputs-and-forms) — текст, email, пароль, число, телефон, дата и/или время.
- **Выбираемые элементы**: Варианты квиза, продукты, вкладки, переключатели и чекбоксы, а также любой [пользовательский выбираемый элемент](flow-selectable-elements#make-an-element-selectable).
- **Любой элемент с действием по нажатию**: Например, кнопка, изображение или иконка, запускающая навигационное действие.

### Добавьте состояние Disabled \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="States section with the Add state menu open and the Disabled option" />

Чтобы добавить и настроить состояние Disabled:

1. Выберите целевой элемент.
2. В разделе **States** нажмите **Add state** и выберите **Disabled**. Если у элемента уже есть состояния, сначала нажмите **Settings** <Inline id="settings.svg" alt="Settings" />: **Add state** находится под списком состояний. Для элемента, который не поддерживает пользовательские состояния, управление осуществляется через кнопку **Disabled state**.
3. Состояние Disabled появится в разделе **States**.
4. Рядом с новым состоянием Disabled нажмите **Edit conditional state** <Inline id="visibility-conditional.svg" alt="Edit conditional state" />.
5. Добавьте условие. Если нужно заблокировать кнопку **submit**, пока ввод не пройдёт валидацию, сравните переменную `isValid` элемента ввода со значением `false`.
6. Настройте стиль состояния Disabled так, чтобы визуально обозначить ограничение (например, уменьшите прозрачность).

{ <ZoomImage id="set-disabled-condition.webp" width="700px" alt="Set condition for disabled state " />}

SDK Adapty вычисляет условие во время выполнения и применяет состояние Disabled, когда это необходимо — без изменений в коде приложения.

Условие **Disabled** также может оценивать состояние другого элемента. Например, можно [отключить два элемента одновременно](element-states-in-conditions#synchronize-element-states).

## Пользовательские состояния \{#custom-states\}

Пользовательское состояние — это состояние с вашим именем и вашим условием. Например, состояние **Locked** может делать кнопку серой, пока пользователь использует бесплатный план. Элемент находится в пользовательском состоянии, пока его условие истинно.

Каждый элемент может иметь до 5 пользовательских состояний.

### Элементы, поддерживающие пользовательские состояния \{#elements-that-support-custom-states\}

- **Элементы с действием по нажатию**: кнопки, контейнеры, изображения, видео, таймеры и карусели. Сначала добавьте триггер [**On Tap**](onboarding-actions#set-up-interactions) хотя бы с одним действием на вкладке **Interactions**.
- **Выбираемые элементы**: элементы в группе выбора и выбираемые элементы с действием по нажатию.
- **Поля ввода**: текстовые, email, пароль, числовые и телефонные поля ввода.

Остальные элементы — иконки, нижние листы, элементы вкладок, содержимое вкладок, пикеры и шаги индикатора прогресса — не поддерживают пользовательские состояния.

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="Add state menu with the Custom state option turned off and the caption Add a tap action to use custom states" />

Чтобы добавить пользовательское состояние для кнопки, контейнера, изображения, видео, таймера или карусели, сначала добавьте триггер **On Tap** хотя бы с одним действием. До тех пор в разделе **States** не будет элемента управления **Add state**. Если у элемента уже есть состояния, параметр **Custom state** будет отключён с подписью «Add a tap action to use custom states». После добавления действия по нажатию параметр станет активным.

### Добавление пользовательского состояния \{#add-a-custom-state\}

<ZoomImage id="custom-state-add-menu.webp" width="300px" float="right" alt="Раздел States с открытым меню Add state, в котором перечислены Disabled и Custom state" />

1. Выберите элемент.
2. В разделе **States** нажмите **Add state**. Если у элемента уже есть состояния, сначала нажмите **Settings** <Inline id="settings.svg" alt="Settings" />: **Add state** находится под списком состояний.
3. Выберите **Custom state**. Откроется панель **Edit state**.

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="Панель редактирования состояния с именем Locked и условием plan equals free" />

4. В поле **Name** введите название состояния, например **Locked**. Название должно соответствовать [правилам именования](#name-rules).
5. Добавьте условие. Например, сравните переменную `plan` со значением `free`. Чтобы добавить больше условий, нажмите **Add Condition** и выберите, должны ли выполняться **all** или **any** из них.
6. Нажмите **Save**. Новое состояние появится в виде вкладки в разделе **States**.
7. Перейдите на вкладку нового состояния и [настройте его стили](#how-to-style-a-state). Стили вложенных элементов, например текста в кнопке, также применяются на устройстве.

Чтобы закрыть панель **Edit state** без изменений, нажмите **Cancel**, кнопку закрытия, клавишу **Escape** или кликните за пределами панели.

Если у элемента уже есть 5 пользовательских состояний, опция **Custom state** становится неактивной с подписью «Up to 5 custom states». Чтобы добавить ещё одно состояние, сначала удалите одно из существующих. Если конфигурация флоу загружена из JSON или сгенерирована с помощью ИИ-инструмента и содержит более 5 пользовательских состояний на элемент, они сохраняются и доступны для редактирования.

### Правила именования \{#name-rules\}

Регистр букв в билдере не учитывается: **Locked** и **locked** — это одно и то же имя. Кроме того, при сохранении пробелы в начале и конце имени удаляются автоматически. Если имя нарушает правило, кнопка **Save** становится неактивной, а под полем появляется сообщение об ошибке:

| Правило | Ошибка |
|---|---|
| Название не пустое. | **Name is required** |
| Название содержит не более 30 символов. | **Max 30 characters** |
| Название не совпадает с **Default** и встроенными состояниями: **Selected**, **Active**, **Invalid**, **Disabled**, **Completed**, **Current**, **Upcoming** или `focused`. | **This name is reserved** |
| Название отличается от названий других пользовательских состояний элемента. | **A state with this name already exists** |

### Редактирование пользовательского состояния \{#edit-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="Tooltip of the Locked state tab with the Edit state button" />

Чтобы изменить название или условие пользовательского состояния, откройте панель **Edit state** одним из следующих способов:

- В списке настроек **States** нажмите на строку нужного состояния или на значок условия <Inline id="visibility-conditional.svg" alt="Condition" /> в этой строке.
- Наведите курсор на вкладку состояния и нажмите **Edit state** в подсказке.

После сохранения стейт сохраняет свои стили. Условия других элементов, которые обращаются к этому стейту, отображают новое имя.

### Удаление пользовательского состояния \{#delete-a-custom-state\}

В списке настроек **States** нажмите значок корзины в строке нужного состояния. Если условия других элементов обращаются к этому состоянию, сначала появится диалоговое окно с их перечнем. После нажатия **Delete** эти условия перестанут работать, и опубликовать флоу не получится, пока вы их не исправите. См. раздел [Устранение неполадок](element-states-in-conditions#troubleshooting).

Билдер удалит состояние вместе с его стилями. Если вкладка удалённого состояния была активна, активной станет вкладка **Default**.

Чтобы восстановить состояние, отмените удаление. Состояние вернётся на то же место в списке вместе со своими стилями.

### Неполные условия \{#incomplete-conditions\}

Строка условия считается неполной, если одна из её сторон не заполнена. Например, вы добавили строку и не заполнили её, или выбрали переменную, но не ввели значение. Условие с неполной строкой никогда не становится истинным — даже если остальные строки истинны. Элемент не переходит в это состояние, и устройство отображает стиль **Default**. Это правило распространяется и на условия **Disabled**: элемент остаётся интерактивным.

Конструктор не предупреждает о незаполненных строках, поэтому перед публикацией заполните или удалите каждую строку. Строка со значением или **is empty**, но без переменной, блокирует публикацию с ошибкой [**Invalid State Condition**](flow-common-issues#a-flow-wont-preview-or-publish).

### Ограничения \{#limitations\}

<ZoomImage id="custom-state-device-warning.webp" width="300px" float="right" alt="States settings list with the warning Not shown on the device. Add a tap action to the element. under two custom states" />

- **Элементы, которые не отображают состояние на устройстве**: На холсте кастомное состояние отображается на любом элементе. На устройстве оно отображается только на [поддерживаемых элементах](#elements-that-support-custom-states). Неподдерживаемый элемент может иметь кастомное состояние, например, из JSON или AI-инструмента, либо после удаления действия по нажатию.

    В этом случае в списке настроек **States** и в подсказке вкладки появляется предупреждение: «Not shown on the device. Add a tap action to the element.» или «Not shown on the device for this element type.» При этом состояние по-прежнему можно редактировать, удалять и публиковать.
- **Поля ввода**: В пользовательском состоянии для поля ввода меняются только заливка, рамка и радиус скругления. Остальные свойства, например цвет текста, сохраняют значения из состояния **Default**. На панели **Edit state** поля ввода отображается подпись «Only fill, border and corner radius change in a custom state».
- **Видео и карусели**: Когда видео или карусель меняют состояние на устройстве, видео начинает воспроизводиться сначала, а карусель возвращается к первому слайду. Не добавляйте пользовательские состояния к видео или карусели, если нужно сохранить позицию воспроизведения или текущий слайд.

## Состояния шагов для индикаторов прогресса \{#step-states-for-progress-indicators\}

:::link
Основная статья: [Индикаторы прогресса](builder-loaders-and-progress-bars#step-states)
:::

Индикаторы прогресса показывают пользователю, насколько далеко он продвинулся в флоу онбординга. Каждый шаг имеет три состояния:

- **Completed**: Шаги, которые пользователь уже прошёл.
- **Current**: Текущий шаг пользователя.
- **Upcoming**: Шаги, до которых пользователь ещё не дошёл.
