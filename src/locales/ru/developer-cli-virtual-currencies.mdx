Adapty CLI управляет [виртуальными валютами](virtual-currencies) из терминала в рамках топика `adapty virtual-currencies`. Вы можете просматривать список валют приложения, создавать валюту, изменять её название и описание, а также добавлять, изменять или удалять *маппинги* — [привязанные продукты](create-virtual-currency#link-products) валюты с указанием количества кредитов, которые каждый из них начисляет. Также можно читать историю транзакций с кредитами для приложения или отдельного пользователя и просматривать балансы конкретного пользователя. В выводе CLI кредиты называются *coins*.

Используйте это, чтобы агент ИИ мог настраивать валюты, или чтобы выяснить, почему у пользователя есть баланс, не открывая дашборд. Команды для валют и маппинга делают то же самое, что вкладка **Virtual currency** страницы **Products**. Команды для чтения транзакций и баланса показывают те же данные, что и профиль пользователя в дашборде, но не изменяют баланс. Чтобы скорректировать его, [измените баланс в дашборде](virtual-currency-balance#adjust-a-balance-manually).

## Перед началом работы \{#before-you-start\}

Топик `virtual-currencies` использует ту же установку и авторизацию, что и остальная часть CLI. Если вы ещё не настроили это, выполните шаги 1 и 2 [гайда по быстрому старту](developer-cli-quickstart). Чтобы проверить, доступен ли топик в вашем CLI, выполните:

```bash
adapty virtual-currencies --help
```

Каждая команда принимает UUID приложения в параметре `--app`. Чтобы найти его, выполните:

```bash
adapty apps list
```

Маппинг идентифицирует продукт по его Adapty product ID, а не по store product ID. Чтобы найти идентификаторы продуктов, выполните:

```bash
adapty products list --app <app-id>
```

## Просмотр списка валют и отдельных валют \{#list-and-read-currencies\}

```bash
adapty virtual-currencies list --app <app-id>
```

Список показывает каждую валюту с её кодом, названием и количеством продуктов, которые её начисляют. Команда поддерживает параметры `--page` и `--page-size`, как и другие списки CLI.

Чтобы получить одну валюту со всеми её маппингами, выполните:

```bash
adapty virtual-currencies get <currency-id> --app <app-id>
```

Валюта содержит следующие поля:

| Поле | Значение |
|---|---|
| `virtual_currency_id` | Идентификатор валюты. Используется как аргумент другими командами. |
| `code` | Код, используемый серверным API, SDK и фильтрами аналитики. Изменить его нельзя. |
| `name`, `description` | Отображаемое название и необязательное описание. |
| `products_count` | Количество продуктов, начисляющих валюту. |
| `updated_at` | Время последнего изменения в миллисекундах. Передаётся в `--expected-updated-at`, как описано в разделе [Защита от потери изменений](#protection-against-lost-changes). |
| `mappings` | Только в `get`: продукты, начисляющие валюту, с указанием количества кредитов для каждого продукта. |

Маппинг определяет, сколько кредитов начисляет каждый продукт:

- **`one-time`**: `credit_per_purchase` кредитов за каждую покупку продукта.
- **`subscription`**: `credit_per_cycle` кредитов за каждый оплаченный период. `expiring: true` делает кредиты периода истекающими при обновлении или окончании подписки. `credit_on_trial_start` задаёт кредиты при начале пробного периода или `null`, если не нужно.

Маппинг начисляет кредиты при следующей покупке или продлении продукта — как в продакшне, так и в песочнице. Текущие подписчики получат их при следующем продлении. Чтобы выдать кредиты существующим пользователям прямо сейчас, [пополните баланс](grant-initial-balance) через server-side API. Описание каждого параметра см. в разделе [Создание виртуальной валюты](create-virtual-currency#link-products).

## Создание валюты \{#create-a-currency\}

:::warning
Удалить валюту или изменить её код невозможно. В одном приложении может быть не более 20 валют.
:::

```bash
adapty virtual-currencies create --app <app-id> --code GEMS --name "Gems" \
  --description "Spent on hints" --file mappings.json
```

`--code` принимает буквы, цифры и `_`, до 32 символов, и должен быть уникальным в приложении. CLI сохраняет регистр в том виде, в котором вы вводите, в отличие от дашборда, который переводит коды в верхний регистр: `gems` и `GEMS` — это два разных кода. Чтобы совпадать с валютами, созданными в дашборде, используйте верхний регистр. API на стороне сервера, а также фильтры транзакций и аналитики требуют кода в том же регистре. `--name` принимает до 64 символов, `--description` — до 256. `--file` необязателен: без него у валюты не будет маппингов.

Файл маппингов — это JSON-список. Каждый элемент представляет собой полный маппинг:

```json title="mappings.json"
[
  {
    "product_id": "<one-time-product-id>",
    "product_type": "one-time",
    "credit_per_purchase": 100
  },
  {
    "product_id": "<subscription-product-id>",
    "product_type": "subscription",
    "credit_per_cycle": 500,
    "expiring": true,
    "credit_on_trial_start": 50
  }
]
```

В `create` можно не указывать `credit_on_trial_start`: тогда trial не начисляет кредиты. CLI проверяет файл перед отправкой. Если файл не является JSON-списком хотя бы с одним элементом, CLI завершается с кодом 2.

Перед созданием валюты CLI отображает код, сопоставленные продукты и предупреждение о том, что удалить валюту или изменить её код нельзя. Затем запрашивается подтверждение, как описано в разделе [Подтверждение в скриптах и агентах](#confirmation-in-scripts-and-agents).

## Изменение названия или описания \{#change-the-name-or-the-description\}

```bash
adapty virtual-currencies update <currency-id> --app <app-id> --name "Gold gems"
```

Укажите хотя бы один из флагов `--name`, `--description` или `--clear-description`. Значение, которое вы не передаёте, остаётся прежним: CLI сначала считывает валюту и отправляет её текущее значение. `--clear-description` удаляет описание. Нельзя использовать его вместе с `--description`.

`update` не запрашивает подтверждения, потому что второй вызов update откатывает изменения.

## Добавить или изменить маппинги \{#add-or-change-mappings\}

```bash
adapty virtual-currencies mappings upsert <currency-id> --app <app-id> --file mappings.json
```

Файл имеет ту же структуру, что и при [создании файла](#create-a-currency), и содержит от 1 до 200 элементов. У валюты может быть не более 200 маппингов в общей сложности. Каждый элемент заменяет маппинг своего продукта или добавляет маппинг для продукта, у которого его ещё нет. Указывайте все поля каждого элемента, включая `credit_on_trial_start` (для отсутствующего значения — `null`). Adapty не объединяет элемент с текущим маппингом: если в элементе отсутствует или неизвестно поле, команда вернёт код завершения 4 и ничего не изменится. Маппинги, не упомянутые в файле, остаются без изменений. `mappings upsert` никогда не удаляет маппинги.

До отправки изменений CLI считывает валюту и отображает каждый изменяемый продукт:

- Новый маппинг: `new` и его кредиты.
- Изменённый маппинг: кредиты до и после, например `30 → 50` для каждой покупки или каждого периода. Изменение `expiring` или `credit_on_trial_start` также отображает значение до и после. Значение `product_type` элемента должно соответствовать типу его продукта: Adapty отклоняет маппинг, у которого изменяется `product_type`, с кодом выхода 4.

## Удалить маппинг \{#remove-a-mapping\}

```bash
adapty virtual-currencies mappings delete <currency-id> --app <app-id> --product <product-id>
```

После удаления покупки продукта больше не начисляют кредиты этой валюты, и Adapty не записывает транзакции по ним. Кредиты, которые продукт уже начислил, остаются на балансах пользователей. Если у продукта нет маппинга, Adapty вернёт ошибку 404 с кодом выхода 4.

## Просмотр кредитных транзакций \{#read-credit-transactions\}

Чтобы просмотреть кредитные транзакции приложения, выполните:

```bash
adapty virtual-currencies transactions list --app <app-id> \
  --date-from 2026-11-01 --date-to 2026-11-07 --timezone Europe/Berlin
```

Период обязателен, максимум 366 дней, оба дня включительно. Дни отсчитываются по часовому поясу из `--timezone` (название в формате IANA) или по часовому поясу приложения, если параметр не указан. Для фильтрации транзакций используйте `--currency-code`, `--operation`, `--feature`, а также `--sandbox` или `--no-sandbox`. Значения операций см. в разделе [Operation](virtual-currencies#operation).

Чтобы прочитать транзакции одного пользователя, укажите его с помощью одного из параметров: `--profile` (Adapty profile ID) или `--customer-user-id` (ваш собственный ID пользователя):

```bash
adapty virtual-currencies profiles transactions list --app <app-id> --customer-user-id <user-id>
```

Период транзакций пользователя указывать необязательно. Без него CLI читает всю историю пользователя. Принимает те же фильтры и `--timezone`.

Транзакции выводятся от новых к старым, по одной странице за каждую команду. По умолчанию страница содержит 20 транзакций, флаг `--page-size` позволяет задать значение от 1 до 100. Если за указанный период транзакций больше, таблица заканчивается строкой `More rows:` и командой для перехода на следующую страницу: те же флаги плюс `--cursor` с курсором текущей страницы. Следующую страницу нужно запрашивать с теми же периодом, фильтрами и часовым поясом. Курсор с другими фильтрами завершается ошибкой `cursor_filters_mismatch`. При использовании `--json` вывод представляет собой ответ Adapty в исходном виде: `data` и `meta`, а курсор находится в `meta.pagination.next_cursor`.

В CLI нет опции для получения всех страниц. Чтобы загрузить все транзакции в хранилище данных, используйте ежедневный экспорт в [Amazon S3](s3-exports#virtual-currency-transactions) или [Google Cloud Storage](google-cloud-storage#virtual-currency-transactions).

:::note
Для просмотра итогов и трендов используйте графики виртуальной валюты из [`adapty analytics`](developer-cli-analytics), а не сумму транзакций. Чтобы найти названия графиков, выполните `adapty analytics catalog`. График исключает пользователей с транзакциями в песочнице, а список транзакций — нет. Поэтому сумма транзакций может отличаться от значения на графике.
:::

## Просмотр баланса пользователя \{#read-the-balances-of-a-user\}

```bash
adapty virtual-currencies profiles balances get --app <app-id> --profile <profile-id>
```

Укажите пользователя с помощью одного из флагов: `--profile` или `--customer-user-id`. В балансе для каждой валюты отображаются: `balance`, кредиты `held` и `available`, а также разбивка по срокам действия — кредиты без срока действия, кредиты с наиближайшим сроком истечения и время их истечения, сумма кредитов с более поздним сроком, а также уже истёкшие кредиты.

Чтобы понять, почему у пользователя такой баланс, изучите транзакции и балансы пользователя вместе. Дашборд отображает те же данные на [профиле пользователя](virtual-currency-balance).

## Защита от потерянных изменений \{#protection-against-lost-changes\}

Кто-то может изменить валюту в дашборде, или другой агент может изменить её — между вашим чтением и записью. Чтобы сохранить это изменение, команды `mappings upsert` и `mappings delete` передают `expected_updated_at` — значение `updated_at` той валюты, которую вы прочитали. Если валюта изменилась после этого чтения, Adapty отклоняет запись с ошибкой `virtual_currency_conflict`, кодом выхода 4, и ничего не меняет. Прочитайте валюту снова и примите решение заново.

| Как выполняется команда | Значение `expected_updated_at`, которое отправляет CLI |
|---|---|
| С флагом `--yes` | Значение `--expected-updated-at`. Без этого флага CLI ничего не отправляет и завершается с кодом 6. |
| В терминале, с флагом `--expected-updated-at` | Значение флага — после того, как вы ответите `y`. |
| В терминале, без флага `--expected-updated-at` | Значение `updated_at` из собственного чтения CLI — после того, как вы ответите `y`. |

Скрипт читает `updated_at` через `get --json` и передаёт его после подтверждения:

```bash
updated_at=$(adapty virtual-currencies get <currency-id> --app <app-id> --json | jq .updated_at)
# Show the change to the person who approves it. After their yes:
adapty virtual-currencies mappings upsert <currency-id> --app <app-id> \
  --file mappings.json --yes --expected-updated-at "$updated_at"
```

## Подтверждение в скриптах и агентах \{#confirmation-in-scripts-and-agents\}

Эти команды показывают результат и запрашивают подтверждение перед отправкой изменений:

- `create`
- `mappings upsert`
- `mappings delete`

Способ запроса зависит от того, как запускается команда:

| Способ запуска команды | Что происходит |
|---|---|
| В терминале, без `--yes` и без `--json` | CLI показывает эффект и спрашивает `Apply? [y/N]`. Если ответить `y` или `yes`, CLI отправляет запрос. При любом другом ответе CLI завершается с кодом 1 и ничего не отправляет. |
| С `--yes` | CLI отправляет запрос без подтверждения. Операции записи маппинга также требуют [`--expected-updated-at`](#protection-against-lost-changes). |
| Без `--yes`, с `--json`, в пайпе или без терминала | CLI ничего не отправляет и завершается с кодом 6. В сообщении об ошибке показывается эффект. |

Скрипт считывает `updated_at` через `get --json`, показывает изменение и выполняет команду с `--yes --expected-updated-at` после подтверждения. Агент также может выполнить команду без `--yes` и показать результат из ошибки.

`list`, `get`, `update` и операции чтения транзакций и баланса выполняются без запроса подтверждения.

## Ошибки \{#errors\}

| Код выхода | Причина | Что делать |
|---|---|---|
| 1 | Вы ввели что-то, кроме `y` или `yes` в ответ на запрос. Ничего не было отправлено. | Запустите команду заново, если хотели продолжить. |
| 2 | CLI отклонил ввод до отправки: неверный флаг, файл маппингов, не являющийся JSON-списком хотя бы с одним элементом, `update` без изменений, `--description` вместе с `--clear-description`, или указан только один из `--profile` и `--customer-user-id` (либо ни один). | Исправьте то, что указано в сообщении об ошибке. |
| 3 | Вы не авторизованы, или Adapty отклонил доступ со статусом HTTP 403: приложение принадлежит другому аккаунту, либо ваша учётная запись может читать данные приложения, но не изменять их. При использовании `--json` ошибка содержит `status: 403`. | Войдите с помощью `adapty auth login` и найдите ID приложения в `adapty apps list`. Если чтение работает, а запись нет — попросите владельца аккаунта предоставить права на изменения. |
| 4 | Adapty отклонил запрос. Ошибка содержит причину, а `--json` — HTTP-статус и `error_code`. Серверная ошибка (5xx) при записи также даёт код 4, и результат операции неизвестен. | См. [Сообщения от Adapty](#messages-from-adapty). После серверной ошибки при записи см. [Если запись не получила ответа](#if-a-write-gets-no-answer). |
| 5 | CLI не смог подключиться к Adapty. | Убедитесь, что подключение к интернету есть. После записи см. [Если запись не получила ответа](#if-a-write-gets-no-answer). |
| 6 | Команда, требующая подтверждения, была запущена без `--yes` и без возможности ответить, либо запись маппингов выполнена с `--yes`, но без `--expected-updated-at`. Ничего не было отправлено. | Покажите ожидаемый эффект из сообщения об ошибке тому, кто одобряет изменение. После получения подтверждения запустите команду снова, как описано в разделе [Защита от потери изменений](#protection-against-lost-changes). |
| 130 | Вы нажали Ctrl+C на запрос подтверждения. Ничего не было отправлено. | — |

### Сообщения от Adapty

С флагом `--json` ошибка возвращает `error_code`:

| `error_code` | Причина | Что делать |
|---|---|---|
| `virtual_currency_conflict` | Валюта изменилась после чтения, чей `updated_at` был отправлен при записи. Ничего не изменилось. | Прочитайте валюту с помощью `get` и примите решение снова. |
| `invalid_date_range` | Период `transactions list` превышает 366 дней, или период списка транзакций заканчивается раньше, чем начинается. | Используйте более короткий период или укажите `--date-from`, который не позже `--date-to`. |
| `cursor_filters_mismatch` | Курсор принадлежит странице с другим периодом, другими фильтрами или другим часовым поясом. | Запустите следующую страницу с теми же флагами, что и первую. |
| `invalid_cursor` | Значение `--cursor` не является курсором от Adapty. | Скопируйте курсор из строки `More rows:` или из `meta.pagination.next_cursor`. |
| `profile_does_not_exist` | В приложении нет пользователя с таким ID профиля или customer user ID. Удалённого пользователя нельзя найти по customer user ID. | Убедитесь, что ID указан верно. Для удалённого пользователя используйте `--profile`. |
| `throttled` | Более 2 обращений к одной и той же транзакции или балансу в секунду для одного приложения. | Подождите и выполните команду снова. CLI автоматически ждёт и повторяет попытку чтения до 3 раз. |

Adapty также отклоняет 21-ю валюту в приложении и код, который приложение уже использует, с кодом выхода 4.

### Если на запись нет ответа \{#if-a-write-gets-no-answer\}

Если CLI не получает ответа на запись из-за сетевой ошибки или ошибки сервера (код выхода 4 или 5), он не может определить, сохранил ли Adapty изменение. CLI не отправляет запись повторно. Прежде чем запустить команду снова, проверьте, что Adapty сохранил: после `create` выполните `list` и найдите код. После любой другой записи прочитайте валюту с помощью `get`. Повторная запись может завершиться неудачей, даже если первая прошла успешно: с ошибкой `virtual_currency_conflict`, с 404 для маппинга, который уже удалён, или с использованным кодом после create.

## Справочник команд \{#command-reference\}

## Работа через AI-ассистент \{#work-from-an-ai-assistant\}

[MCP-сервер Adapty](adapty-mcp) предоставляет те же действия в виде инструментов `virtual_currencies_*`, например `virtual_currencies_mappings_upsert` для `mappings upsert`. Инструменты работают так же, как команды, с этими отличиями:

- **Защита от потери изменений**: `virtual_currencies_update`, `virtual_currencies_mappings_upsert` и `virtual_currencies_mappings_delete` требуют `expected_updated_at` — значение `updated_at` из последнего чтения. После ошибки `virtual_currency_conflict` ассистент заново читает валюту.
- **Описание**: В `virtual_currencies_update` пустое `description` удаляет описание.
- **Страницы**: Когда `meta.pagination.has_more` равно true, ассистент передаёт `meta.pagination.next_cursor` в `cursor` с теми же фильтрами и часовым поясом для следующей страницы.
- **Подтверждение**: Инструменты не запрашивают подтверждения и не имеют флага `--yes`. Перед `virtual_currencies_create`, `virtual_currencies_mappings_upsert` и `virtual_currencies_mappings_delete` ассистент показывает вам изменение и ждёт вашего согласия.
- **Ограничение запросов**: После ошибки `throttled` инструменты не повторяют запрос. В ошибке указано, сколько нужно подождать.
