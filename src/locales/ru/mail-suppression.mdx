Adapty Mail прекращает отправку пользователю в двух случаях:

- **Подавление**: пользователь исключается из всех будущих отправок в рамках проекта (отписался, получил bounce, пожаловался, отклонён или превышен лимит).
- **Стоп-условие**: текущая последовательность отменяется, потому что пользователь совершил конверсию. Подавления нет — пользователь остаётся доступен для других кампаний.

Оба механизма действуют в рамках одного проекта. Подавление в одном проекте Adapty не влияет на другой.

## Отписка \{#unsubscribe\}

У получателя есть два способа отписаться, и оба работают на хосте `go.` вашего [домена отправки](mail-sending-domain#which-records-you-add), а не на URL Adapty.

**Ссылка в футере.** Она есть в каждом письме. При клике открывается страница подтверждения, и после подтверждения профиль получает метку `suppression_reason = 'unsubscribe'`, оставшаяся последовательность отменяется, а профиль исключается из всех будущих рассылок в проекте. Шаг подтверждения сделан намеренно: спам-сканеры и префетчеры почтовых клиентов переходят по ссылкам в теле письма, и промежуточная страница защищает от случайной отписки тех, кто на самом деле ни на что не нажимал.

**Кнопка отписки в интерфейсе почтового клиента.** Adapty Mail отправляет заголовок `List-Unsubscribe: <URL>, <mailto:>` вместе с `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. Gmail и Yahoo требуют этого от массовых отправителей (RFC 8058), а почтовые клиенты, поддерживающие эти заголовки, показывают кнопку отписки рядом с именем отправителя. У этого URL нет страницы подтверждения: первый же запрос к нему подавляет профиль — независимо от метода: RFC 8058 предписывает POST, однако некоторые провайдеры отправляют GET.

Оба ссылки содержат зашифрованный токен, идентифицирующий получателя и письмо, из которого пришёл запрос, поэтому для отписки не нужны ни вход в аккаунт, ни ручной поиск.

:::note
Отписка от [тестового письма](mail-testing) ни на что не влияет — тестовые рассылки не попадают в список подавления.
:::

## Автоматическое подавление \{#automatic-suppression\}

Adapty Mail прослушивает события доставки AWS SES через SNS и немедленно подавляет пользователя при любом из следующих событий:

| Событие   | Код причины | Что означает                                                                    |
| --------- | ----------- | ------------------------------------------------------------------------------- |
| Bounce    | `bounce`    | Адрес электронной почты недействителен, почтовый ящик переполнен или домен не существует. |
| Complaint | `complaint` | Пользователь пометил письмо как спам.                                           |
| Reject    | `reject`    | SES отклонил сообщение до отправки.                                             |
| Throttle  | `throttle`  | Превышен безопасный лимит отправки для домена.                                  |

Для каждого события результат одинаков: пользователь добавляется в список подавления, оставшаяся последовательность отменяется, и пользователь исключается из будущих отправок в проекте.

:::important
Adapty Mail **не** различает постоянные и временные bounce. Любой bounce — включая временные ситуации вроде переполненного ящика — немедленно подавляет пользователя. Повторных попыток нет.
:::

## Стоп-условие \{#stop-condition\}

Когда пользователь совершает конверсию в середине последовательности, Adapty Mail отменяет оставшиеся письма с причиной `stop_condition`. Конверсия означает, что статус подписки пользователя достиг **Subscribed** или статус разовой покупки достиг **Purchased**.

Стоп-условие отличается от подавления:

- **Подавление**: исключает пользователя из всех будущих отправок в проекте.
- **Стоп-условие**: отменяет только текущую последовательность. Пользователь остаётся доступен для других кампаний — например, для потока продления или win-back, нацеленного на активных подписчиков.

Отмены по стоп-условию отображаются в аналитике кампаний вместе с подавлениями.

## Управление подавлением \{#managing-suppression\}

В дашборде Adapty Mail нет интерфейса для просмотра или удаления подавленных пользователей. Чтобы снять подавление с профиля — например, если кто-то случайно пометил тестовое письмо как спам — обратитесь в поддержку Adapty.

## Что Adapty Mail берёт на себя в плане соответствия требованиям \{#what-adapty-mail-handles-for-compliance\}

Adapty Mail поставляется со следующим:

- **Ссылка для отписки**: включается в футер каждого письма и обрабатывается сразу после подтверждения получателем.
- **Заголовки List-Unsubscribe**: отправляются с каждым письмом для отписки в один клик прямо из почтового клиента (RFC 8058) — по URL, который выполняет отписку при первом обращении.
- **Автоматическое подавление**: срабатывает при событиях SES bounce, complaint, reject и throttle.

Части, за которые отвечаете вы:

- **Физический почтовый адрес**: CAN-SPAM требует его в футере письма. Adapty Mail не добавляет его автоматически — укажите его в дизайне кампании.
- **Явное согласие на подписку**: Получите его до того, как передавать email пользователя в Adapty. См. [Подключение Adapty к Adapty Mail](mail-collect-emails). Чтобы каждый новый получатель дополнительно подтверждал свой адрес перед отправкой маркетинговых писем, включите [двойное подтверждение](mail-double-opt-in).
- **Запросы на удаление по GDPR**: Отправьте идентификаторы профиля на эндпоинт [Delete profile](api-mail/operations/deleteProfile) API Adapty Mail. Adapty Mail удалит личные данные профиля и отменит запланированные письма. Удаление необратимо: повторное сохранение с теми же идентификаторами не восстановит профиль.
