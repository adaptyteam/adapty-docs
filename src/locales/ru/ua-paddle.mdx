Подключите свой аккаунт Paddle к Adapty Attribution, чтобы атрибутировать покупки в вашей веб-воронке к рекламе, которая их привлекла. После подключения покупки, продления, возвраты и чарджбэки из Paddle отображаются в аналитике Adapty Attribution, а события конверсий можно отправлять обратно в рекламные сети для оптимизации кампаний.

## Как это работает \{#how-it-works\}

1. [Веб-пиксель Adapty](ua-web-pixel) присваивает каждому посетителю воронки идентификатор клика и захватывает данные об объявлении из URL посадочной страницы.
2. При оформлении заказа ваша воронка прикрепляет идентификатор клика к транзакции Paddle.
3. Adapty получает транзакцию через вебхук, созданный в вашем аккаунте Paddle, и сопоставляет её с кликом по объявлению.

:::note
Веб-покупки не имеют события установки приложения, поэтому Adapty использует дату первого списания средств по подписке в качестве даты когорты.
:::

## Прежде чем начать \{#before-you-start\}

[Настройте веб-пиксель Adapty](ua-web-pixel) для вашей воронки. Без пикселя не будет click ID для привязки, и транзакции не смогут быть приписаны рекламе.

## Шаг 1. Передайте click ID при оформлении заказа \{#step-1-attach-the-click-id-at-checkout\}

Когда вы открываете checkout или создаёте транзакцию, считайте click ID и добавьте его в `customData` Paddle под ключом `adpt_click_id`:

```js
const adptClickId = window.adaptyPixel.getClickId();

customData: { adpt_click_id: adptClickId }
```

Передавайте click ID только в первой транзакции. Paddle автоматически копирует `customData` подписки на транзакции продления, поэтому Adapty атрибутирует продления, возвраты и чарджбэки автоматически.

`click_id` — это короткий случайный идентификатор, не являющийся секретом или персональными данными. Он отображается в вашем дашборде Paddle, что является ожидаемым поведением.

## Шаг 2. Подключите ваш аккаунт Paddle \{#step-2-connect-your-paddle-account\}

Сначала создайте ключ в Paddle. В дашборде Paddle перейдите в **Developer Tools → Authentication** и создайте API-ключ со следующими разрешениями:

| Ресурс | Доступ |
|---|---|
| Transactions | Read |
| Adjustments | Read |
| Notification settings | Write |

Права на запись в настройки уведомлений позволяют Adapty создать webhook-назначение, которое доставляет данные о платежах — вручную в Paddle ничего настраивать не нужно. Все остальные разрешения остаются только для чтения: Adapty никогда не изменяет данные о платежах. Ключ без обязательного разрешения отклоняется при подключении с ошибкой, в которой указано недостающее разрешение.

:::warning
Используйте боевой ключ. Ключи Paddle привязаны к окружению, а Adapty отбрасывает события из песочницы сразу при получении: ключ от песочницы успешно подключается и отображается как **Valid**, но данные так и не появляются. Чтобы проверить интеграцию, подключите боевой ключ и совершите реальную покупку.
:::

Затем добавьте ключ в Adapty:

1. В Adapty Attribution перейдите в [**Integrations > Paddle**](https://app.adapty.io/ua/integrations/paddle).
2. Вставьте ключ в поле **API key**. При желании укажите **Name**, чтобы различать аккаунты — по умолчанию Adapty использует последние 4 символа ключа.
3. Нажмите **Connect**.

<ZoomImage id="ua-paddle-connect.webp" width="500px" alt="Connect a Paddle account form with API key and Name fields on the Paddle integration page in Adapty Attribution" />

После подключения аккаунт появится в таблице с указанием среды, статуса ключа и состояния вебхука. Подключение применяется к приложению, которое вы настраиваете. Чтобы получать платежи того же аккаунта Paddle в другом приложении, добавьте туда тот же ключ.

Adapty импортирует транзакции с момента подключения аккаунта. Чтобы загрузить более ранние транзакции, напишите нам на [support@adapty.io](mailto:support@adapty.io).

## Проверьте интеграцию \{#verify-the-integration\}

Совершите реальную покупку через вашу воронку — Adapty не учитывает покупки из песочницы. Покупка должна появиться в [Adapty Attribution analytics](ua-analytics) в течение нескольких часов. Если ваш визит был совершён по рекламной ссылке с [тегированными URL](ua-web-pixel), покупка будет атрибутирована к соответствующей кампании, группе объявлений и объявлению; в противном случае она будет засчитана как органическая.

## Отправка событий конверсии в рекламную сеть \{#send-conversion-events-to-the-ad-network\}

Атрибутированные веб-покупки следуют той же схеме маппинга событий, что и остальная часть кампании: события, которые вы включаете в разделе **Events names** конфигурации кампании, отправляются обратно в пиксель, привязанный к кампании. Подробнее о настройке маппинга — в разделах [Meta Ads](ua-facebook) и [TikTok for Business](ua-tiktok).
