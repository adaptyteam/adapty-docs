Надёжная загрузка флоу или пейвола в Capacitor решает три задачи: быстрый рендеринг, возврат варианта для нужной аудитории и корректный фолбэк при медленной сети. Правила ниже охватывают тайминг, кэширование и резервные паттерны для достижения этих целей.

:::tip
Предполагается, что `adapty.activate()` и `adapty.identify()` уже выполнены. См. [Порядок вызовов в Capacitor SDK](capacitor-sdk-call-order).
:::

## Правила и подводные камни \{#rules-and-pitfalls\}

| Делайте так | Не делайте так | Почему |
|---|---|---|
| Загружайте плейсмент, который собираетесь показать, или прогрейте кэш с помощью [`preloadFlows`](#preload-placements) (SDK 4.3.0+). | Не запускайте параллельные вызовы `getFlow` при старте приложения. | Самодельная пакетная загрузка блокирует главный поток и вызывает чёрный экран. `preloadFlows` создан именно для этого и отправляет пакет в нативный SDK одним вызовом. |
| Вызывайте `getFlow` после того, как атрибуция успела разрешиться — например, через 1–2 секунды после `activate` или после срабатывания слушателя `onLatestProfileLoad`. | Не вызывайте `getFlow` при запуске приложения в `App.tsx`. | Атрибуция ещё не получена. Флоу разрешается против аудитории по умолчанию и незаметно обходит сегменты и персонализацию ASA. |
| Оставьте значение `loadTimeoutMs` по умолчанию (5000 миллисекунд) или задайте другое, и настройте [резервный пейвол](fallback-paywalls) для каждого плейсмента. | Не передавайте в `getFlow` такое большое значение `loadTimeoutMs`, при котором таймаут никогда не срабатывает. | Если таймаут никогда не срабатывает, пользователи с плохим соединением видят пустой экран до восстановления сети — или закрывают приложение. |

Смотрите раздел [Получение пейволов и продуктов](fetch-paywalls-and-products-capacitor), где описаны параметры `fetchPolicy` и `loadTimeoutMs`, а также [Плейсменты](placements) — для выбора подходящего плейсмента.

## Предзагрузка плейсментов \{#preload-placements\}

:::info
`preloadFlows` и `preloadFlowsForDefaultAudience` доступны начиная с версии SDK 4.3.0.
:::

`preloadFlows` заранее кэширует JSON флоу. Дальше всё работает как обычно: `getFlow` — для получения флоу, `createFlowView` — для его отображения.

`fetchPolicy` определяет, из какого слоя `getFlow` будет читать данные в первую очередь, но не ограничивает доступ к кэшу:

- `'return_cache_data_else_load'` сначала читает предзагруженную копию и обращается к сети только при отсутствии кэша. `'return_cache_data_if_not_expired_else_load'` делает то же самое, пока копия моложе `maxAgeSeconds`.
- По умолчанию используется `'reload_revalidating_cache_data'` — сначала идёт запрос в сеть, а при его неудаче или таймауте используется предзагруженная копия.

Предзагрузка окупается в любом случае, но по-разному: политика cache-first устраняет запрос, тогда как стандартная оставляет его, получая готовую копию в качестве резерва. На [тестовом устройстве](test-devices) `getFlow` обходит кэш при любой политике и использует предзагруженную копию только в случае сбоя сетевого запроса.

Используйте предзагрузку, когда вы знаете, какие плейсменты понадобятся в сессии, но не хотите показывать их сразу — например, для флоу, скрытого за кнопкой, которую пользователь ещё не нажал.

:::warning
Предзагрузка определяет аудиторию в момент выполнения. Если запустить предзагрузку до получения данных атрибуции, а затем вызвать `getFlow` с `fetchPolicy` cache-first, пользователь получит вариант, выбранный без атрибуции, что обходит сегменты и персонализацию ASA. Выполняйте предзагрузку после того, как атрибуция успела разрешиться — например, после срабатывания слушателя `onLatestProfileLoad` — или оставьте `fetchPolicy` по умолчанию.
:::

```typescript showLineNumbers

try {
  await adapty.preloadFlows({
    placementIds: ['onboarding', 'main_paywall'],
    params: { loadTimeoutMs: 5000 },
  });
} catch (error) {
  // at least one placement failed to preload
}

// Later, when the user reaches the paywall:
const flow = await adapty.getFlow({
  placementId: 'main_paywall',
  params: { fetchPolicy: 'return_cache_data_else_load' },
});
```

**Параметры:**

- `placementIds` (обязательный): плейсменты для предзагрузки.
- `params.loadTimeoutMs` (необязательный): общий лимит времени для предзагрузки в миллисекундах. По умолчанию — 5000; значения ниже 1000 автоматически повышаются до 1000. Плейсменты, которые не успели загрузиться в отведённое время, получают пейвол для аудитории по умолчанию.

**Важные особенности поведения:**

- Вызов завершается ошибкой только после того, как были предприняты попытки загрузить все плейсменты, и возвращается один `AdaptyError`, охватывающий все неудавшиеся плейсменты. Ошибка для одного плейсмента не останавливает остальные, а загруженные плейсменты остаются в кэше.
- Предзагрузка всегда обращается к сети: у неё нет собственного `fetchPolicy`.
- Предзагрузка только прогревает кэш. Она не возвращает контент — для отображения вы по-прежнему вызываете `getFlow`.

### Что охватывает предзагрузка \{#what-a-preload-covers\}

Флоу отображается на экране послойно. Предзагрузка охватывает первый слой — точно так же, как `getFlow`:

| Слой | Запрашивается | Прогревается предзагрузкой |
|---|---|---|
| Flow JSON — выбранный вариант, идентификаторы продуктов и Remote Config | `getFlow` | Да |
| UI-макет — структура, стили и текст экрана | `createFlowView` | Нет |
| Изображения, включая статичный кадр-заглушку для видеоэлемента | `createFlowView`, в фоне | Нет |
| Продукты | `createFlowView` или `getPaywallProducts` | Нет |
| Видеофайлы | Системный плеер, по мере рендеринга экрана | SDK не кэширует |

`createFlowView` ищет макет в трёх местах в следующем порядке:

1. Дисковый кэш нативного SDK, который сохраняется между перезапусками приложения.
2. Ваш [резервный файл](capacitor-use-fallback-paywalls) для SDK 4.4 или выше, если вы скачали его после последней публикации флоу.
3. Adapty через сеть. Это требует отдельного запроса, даже после предзагрузки. При первом отображении каждой опубликованной версии флоу нативный SDK делает этот запрос, а затем сохраняет макет в дисковый кэш.

Когда срабатывает `loadTimeoutMs` в `createFlowView`, нативный SDK не переключается на резервный вариант: он повторно запрашивает макет у Adapty API. `loadTimeoutMs` не ограничивает этот повторный запрос.

### Пропуск сегментации аудитории \{#skip-audience-segmentation\}

Чтобы прогреть кэш без ожидания сегментации аудитории, используйте вариант для аудитории по умолчанию. Он не требует таймаута:

```typescript showLineNumbers
await adapty.preloadFlowsForDefaultAudience({ placementIds: ['main_paywall'] });
```

Последующий вызов `getFlowForDefaultAudience` читает копию так же, как `getFlow` читает копию `preloadFlows`.

## Показ медиафайлов первого экрана из бандла приложения \{#show-first-screen-media-from-the-app-bundle\}

Флоу загружает изображения и видео с серверов Adapty. Чтобы медиафайлы первого экрана отображались мгновенно, подключите их из бандла приложения. Это удобно, если вы уже поставляете нужные материалы вместе с приложением — например, визуалы существующего нативного онбординга.

1. В Flow & Paywall Builder установите [пользовательский медиа-ID](custom-media#custom-media-id) для изображения или видео. Загруженный там файл останется резервным.
2. Добавьте файл в нативные проекты: в бандл iOS-приложения и в папку `assets` Android.
3. При создании представления флоу передайте локальный файл для этого ID в `customAssets`:

```typescript showLineNumbers

// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
const bundledAssets: Record<string, AdaptyCustomAsset> = {
  'welcome_video': {
    type: 'video',
    fileLocation: {
      ios: { fileName: 'welcome.mp4' },
      android: { relativeAssetPath: 'videos/welcome.mp4' },
    },
  },
};

const view = await createFlowView(flow, { customAssets: bundledAssets });
```

Встроенные файлы увеличивают размер загрузки приложения, поэтому добавляйте в бандл только те медиафайлы, которые пользователь видит первыми.

Встроенное изображение отображается мгновенно, но SDK в фоне всё равно скачивает загруженное изображение.

Медиа без бандлинга тоже появляется сразу: во флоу хранится небольшая копия каждого изображения в низком разрешении, включая стоп-кадр видео, — она и показывается до загрузки полного файла.

Полный справочник по `customAssets` см. в разделе [Настройка ассетов](capacitor-get-pb-paywalls#customize-assets).

## Настройка для нестабильного соединения \{#tune-for-poor-connectivity\}

Для рынков с постоянно плохим качеством связи (сельская местность, транзитные зоны, регионы с проблемами маршрутизации):

- Задайте `fetchPolicy: 'return_cache_data_else_load'` для каждого запроса, кроме самого первого.
- Настройте [резервный пейвол](fallback-paywalls) для каждого плейсмента в дашборде Adapty.
- Подберите баланс `loadTimeoutMs` между скоростью и таргетингом. При меньшем таймауте пользователи быстрее увидят резервный вариант. При большем — таргетированный флоу получит больше времени на загрузку.
- [Делайте флоу лёгким](flow-size), чтобы его разметка загружалась быстрее.
- Не блокируйте отображение флоу на `adapty.getProfile()`. Вызывайте `getFlow` независимо, чтобы медленный профиль не задерживал интерфейс.
