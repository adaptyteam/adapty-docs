Как одно из ведущих решений для взаимодействия с клиентами, [Braze](https://www.braze.com/) предоставляет широкий набор инструментов для push-уведомлений, email, SMS и сообщений внутри приложения. Интегрировав Adapty с Braze, вы получите доступ ко всем событиям подписки в одном месте и сможете запускать автоматические коммуникации на основе этих событий.

Adapty предоставляет полный набор данных, позволяющий отслеживать [события подписок](events) из всех сторов в одном месте, и может использоваться для обновления профилей пользователей в Braze. С Adapty вы легко увидите, как ведут себя ваши подписчики, поймёте их предпочтения и сможете использовать эту информацию для целевой и эффективной коммуникации. Интеграция позволяет отслеживать события подписок в вашем дашборде Braze и связывать их с вашими [рекламными кампаниями.](https://www.braze.com/product/journey-orchestration)

Adapty отправляет события подписки, свойства пользователей и покупки в Braze, чтобы вы могли выстраивать целевые коммуникации с клиентами через push-уведомления Braze после простой и быстрой интеграции, описанной ниже.

## Как настроить интеграцию с Braze \{#how-to-set-up-braze-integration\}

Чтобы подключить Adapty к Braze, откройте [**Integrations** → **Braze**](https://app.adapty.io/integrations/braze) в дашборде Adapty, включите переключатель и заполните учётные данные:

- **REST API key** и **Braze Instance ID** — обязательные поля.
- **iOS App ID** и **Android App ID** — необязательные поля.

1. Чтобы создать **REST API key**, перейдите в дашборде Braze в **Settings** → **APIs and Identifiers** и нажмите **Create API Key**. В разделе разрешений для данных пользователей выберите `users.track`. Braze не позволяет изменять разрешения ключа после его создания, поэтому ключ без `users.track` придётся заменить новым. Подробнее см. в документации Braze: [Creating REST API keys](https://www.braze.com/docs/api/basics#creating-rest-api-keys).
2. Чтобы найти **Braze Instance ID**, сопоставьте URL вашего дашборда Braze с [таблицей инстансов](https://www.braze.com/docs/api/basics/#endpoints) в документации Braze. ID инстанса имеет региональный формат, например `US-03` или `EU-01`. Так, `dashboard-03.braze.com` соответствует `US-03`.
3. Чтобы найти **iOS App ID** и **Android App ID**, перейдите в дашборде Braze в **Settings** → **APIs and Identifiers** → **App Identifiers**. Скопируйте значение из столбца **Identifier** для каждого приложения. Подробнее см. в документации Braze: [App identifier](https://www.braze.com/docs/api/identifier_types#app-identifier).

Adapty отправляет события подписки и атрибуты пользователей в Braze через серверную интеграцию, что позволяет просматривать их в дашборде Braze и настраивать кампании на их основе.

Для событий, содержащих информацию о доходе, — таких как конверсии пробного периода и продления, — Adapty будет отправлять эти данные в Braze в виде покупок.

:::warning
Adapty отправляет данные о доходах в Braze только в виде устаревших событий покупки (legacy purchase events). Braze перевёл legacy purchase events в режим обслуживания и не включает их для новых клиентов. Если ваше рабочее пространство Braze не принимает такие события, Braze отклоняет каждое событие с доходом с кодом HTTP 400 и сообщением `Legacy purchase ingestion is disabled`. Такие события, как первые покупки, продления, конверсии пробного периода и возвраты, не поступают в Braze вообще — не только их данные о доходах.

Прежде чем включить интеграцию, убедитесь, что ваш воркспейс Braze принимает legacy purchase events. Подробнее см. раздел [Purchase events](https://www.braze.com/docs/user_guide/data/activation/events/purchase_events) в документации Braze.
:::

[Здесь](messaging#event-properties) вы найдёте полную спецификацию свойств событий, отправляемых в Braze.

:::note
Полезные атрибуты пользователя

По умолчанию Adapty отправляет в Braze ряд атрибутов пользователя. Ознакомьтесь со списком ниже, чтобы выбрать наиболее подходящие для ваших задач.
:::

| Атрибут пользователя | Тип | Значение |
|--------------|----|-----|
| `adapty_customer_user_id` | String | Содержит уникальный идентификатор пользователя, заданный клиентом. Доступен как в [дашборде](profiles-crm) Adapty, так и в Braze. |
| `adapty_profile_id` | String | Содержит уникальный идентификатор профиля пользователя Adapty, который можно найти в [дашборде](profiles-crm) Adapty. |
| `environment` | String | <p>Указывает, работает ли пользователь в среде песочницы или в продакшене.</p><p></p><p>Возможные значения: `Sandbox` или `Production`</p> |
| `store` | String | <p>Содержит название стора, через который была совершена покупка.</p><p></p><p>Возможные значения:</p><p>`app_store` или `play_store`.</p> |
| `vendor_product_id` | String | <p>Содержит идентификатор продукта в Apple/Google стор.</p><p></p><p>Например: org.locals.12345</p> |
| `subscription_expires_at` | String | <p>Содержит дату истечения последней подписки.</p><p></p><p>Формат значения:</p><p>YYYY-MM-DDTHH:mm:ss.SSS+TZ</p><p>Например: 2023-02-15T17:22:03.000+0000</p> |
| `active_subscription` | String | Принимает значение `true` при любом событии покупки или продления, или `false`, если подписка истекла. |
| `period_type` | String | <p>Указывает последний тип периода для покупки или продления.</p><p></p><p>Возможные значения:</p><p>`trial` для пробного периода или `normal` для остальных случаев.</p> |

Все значения типа float округляются до int. Строки передаются без изменений.

Помимо предопределённого набора тегов, можно также отправлять [пользовательские атрибуты](segments#custom-attributes) с помощью тегов. Это даёт дополнительную гибкость в выборе типов данных и полезно для отслеживания специфической информации о продукте или сервисе. Все пользовательские атрибуты пользователей автоматически отправляются в Braze, если на [странице интеграции](https://app.adapty.io/integrations/braze) отмечен чекбокс **Send user attributes**.

## Настройка SDK \{#sdk-configuration\}

Чтобы связать профили пользователей в Adapty и Braze, необходимо либо настроить Braze SDK с тем же идентификатором пользователя, что и в Adapty, либо использовать метод `.changeUser()`:

<Tabs groupId="current-os" queryString>
<TabItem value="swift" label="iOS (Swift)" default>
```swift showLineNumbers
let braze = Braze(configuration: configuration)
braze.changeUser(userId: "adapty_customer_user_id")
```
</TabItem>
<TabItem value="kotlin" label="Android (Kotlin)" default>
```kotlin showLineNumbers
Braze.getInstance(context).changeUser("adapty_customer_user_id")
```
</TabItem>
</Tabs>
