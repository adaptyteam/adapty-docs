В этой статье перечислены команды Adapty CLI для настройки аккаунта — приложений, уровней доступа, продуктов, пейволов, флоу, плейсментов и сегментов — с их аргументами, флагами и допустимыми значениями. Для кампаний Apple Ads см. [команды Ads Manager](developer-cli-ads-manager-reference).

:::link
Настройка аутентификации и управление токенами описаны в разделе [Аутентификация](developer-cli-authentication).
:::

## Глобальные флаги \{#global-flags\}

Эти флаги доступны во всех командах.

| Флаг | Описание |
|---|---|
| `--json` | Вывод в формате JSON вместо форматированного текста |
| `--help` | Показать справку по команде |

Все команды `list` также принимают флаги пагинации:

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--page` | `1` | Номер страницы |
| `--page-size` | `20` | Элементов на странице (макс.: 100) |

## Приложения \{#apps\}

Управление приложениями в вашем аккаунте Adapty. Настройка через дашборд описана в разделе [Настройки приложения](general).

### adapty apps list \{#adapty-apps-list\}

Список всех приложений в вашем аккаунте Adapty.

```bash
adapty apps list
```

Принимает [флаги пагинации](#global-flags).

### adapty apps get \{#adapty-apps-get\}

Получить подробную информацию о конкретном приложении.

```bash
adapty apps get <app-id>
```

| Аргумент | Описание |
|---|---|
| `app-id` | ID приложения (UUID) |

### adapty apps create \{#adapty-apps-create\}

Создать новое приложение.

```bash
adapty apps create --title "My App" --platform ios --apple-bundle-id com.example.app
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--title` | Да | Название приложения |
| `--platform` | Да | Платформа: `ios` или `android`. Повторите для обеих: `--platform ios --platform android` |
| `--apple-bundle-id` | Обязателен с `--platform ios` | Apple bundle ID |
| `--google-bundle-id` | Обязателен с `--platform android` | Google bundle ID |

### adapty apps update \{#adapty-apps-update\}

Обновить существующее приложение.

```bash
adapty apps update <app-id> --title "New Name"
```

| Аргумент | Описание |
|---|---|
| `app-id` | ID приложения (UUID) |

| Флаг | Описание |
|---|---|
| `--title` | Новое название приложения |
| `--apple-bundle-id` | Новый Apple bundle ID |
| `--google-bundle-id` | Новый Google bundle ID |

Требуется хотя бы один флаг. `--platform` нельзя изменить после создания.


| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

### adapty products create \{#adapty-products-create\}

Создать новый [продукт](product).

:::important
ID продукта и цены в сторе нельзя изменить после создания. Чтобы использовать другие ID стора, создайте новый продукт.
:::

```bash
adapty products create --app <app-id> --title "Monthly" --access-level-id <access-level-id> --period monthly --ios-product-id com.example.monthly
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |
| `--title` | Да | Название продукта |
| `--access-level-id` | Да | ID [уровня доступа](access-level) (UUID), который открывает этот продукт |
| `--period` | Да | Период подписки: `weekly`, `monthly`, `two_months`, `trimonthly`, `semiannual`, `annual`, `lifetime` |
| `--ios-product-id` | Требуется хотя бы один стор | ID продукта из App Store Connect |
| `--android-product-id` | Требуется хотя бы один стор | ID продукта из Google Play Console |
| `--android-base-plan-id` | Обязателен с `--android-product-id`, если не указан `--period lifetime` | ID базового плана из Google Play Console |
| `--stripe-product-id` | Требуется хотя бы один стор | ID продукта из Stripe |
| `--stripe-price-id` | Обязателен с `--stripe-product-id` | ID цены из Stripe |
| `--paddle-product-id` | Требуется хотя бы один стор | ID продукта из Paddle |
| `--paddle-price-id` | Обязателен с `--paddle-product-id` | ID цены из Paddle |

У каждого продукта должен быть хотя бы один стор: `--ios-product-id`, `--android-product-id`, `--stripe-product-id` или `--paddle-product-id`. Один продукт может содержать ID сразу нескольких сторов.

Чтобы продавать продукт в интернете через Stripe или Paddle, сначала подключите платёжный провайдер к Adapty: см. [Stripe](stripe) и [Paddle](paddle). Для каждого из этих сторов передайте ID продукта и ID цены вместе. Команда завершится с ошибкой, если передать только один из пары.

```bash
adapty products create --app <app-id> --title "Monthly" --access-level-id <access-level-id> --period monthly --stripe-product-id prod_xxx --stripe-price-id price_xxx
```

Продукт только для веба допустим: можно создать продукт с ID Stripe или Paddle и без ID App Store или Google Play.

## Флоу \{#flows\}

[Флоу](adapty-flow-builder) — это пейволы и онбординги, которые вы создаёте в Flow & Paywall Builder. CLI управляет записью флоу, его конфигом билдера и публикацией. Конфиг билдера — это большой JSON-документ, который обычно создаёт Flow & Paywall Builder; CLI его не генерирует. Чтобы создать или отредактировать конфиг из терминала, используйте [скилл flow-generator](flow-generator-skill), который управляет этими командами за вас. Перед публикацией [скилл flow-audit](flow-audit-skill) проверяет готовность флоу к продакшену. Команды приведены здесь в качестве справки.

### adapty flows list \{#adapty-flows-list\}

Список всех флоу для приложения.

```bash
adapty flows list --app <app-id>
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

Принимает [флаги пагинации](#global-flags).

### adapty flows get \{#adapty-flows-get\}

Получить подробную информацию о конкретном флоу.

```bash
adapty flows get --app <app-id> <flow-id>
```

| Аргумент | Описание |
|---|---|
| `flow-id` | ID флоу (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

Ответ содержит `id`, `name`, `status` и `updated_at`. Статус принимает одно из значений:

| Статус | Значение |
|---|---|
| `draft` | Флоу ни разу не публиковался |
| `published` | Текущая версия активна |
| `dirty` | Флоу публиковался раньше, и в текущей версии есть неопубликованные изменения. Пользователи видят последнюю опубликованную версию |
| `publishing` | Публикация в процессе |
| `publication_failed` | Последняя публикация завершилась с ошибкой. Исправьте конфиг и опубликуйте снова |
| `archived` | Флоу заархивирован |

### adapty flows create \{#adapty-flows-create\}

Создать флоу. Новый флоу имеет название и не имеет конфига. Чтобы добавить конфиг, используйте [`flows config update`](#adapty-flows-config-update).

### adapty flows publish \{#adapty-flows-publish\}

Опубликовать текущую версию флоу для пользователей.

```bash
adapty flows publish --app <app-id> <flow-id>
```

| Аргумент | Описание |
|---|---|
| `flow-id` | ID флоу (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |
| `--yes`, `-y` | Нет | Опубликовать без запроса подтверждения. Обязателен при перенаправлении вывода или при использовании `--json` |

Поскольку публикация меняет то, что видят пользователи, команда выводит название флоу и запрашивает подтверждение. Любой ответ, кроме `y`, отменяет команду с кодом выхода 1. При использовании `--json` или в пайпе команда завершается с кодом 2 вместо ожидания ответа, поэтому в скриптах и агентских сессиях передавайте `--yes`.

Публикация асинхронная: ответ сообщает `status: publishing`, и флоу ещё не активен. Опрашивайте [`flows get`](#adapty-flows-get), пока статус не станет `published` или `publication_failed`. При `publication_failed` команда [`flows config get`](#adapty-flows-config-get) сообщит причину.

Публикация завершается с HTTP 400, если у флоу нет конфига, конфиг не готов к публикации или текущая версия уже активна. Чтобы проверить конфиг перед публикацией, используйте [`flows config validate`](#adapty-flows-config-validate).

### adapty flows config get \{#adapty-flows-config-get\}

Прочитать конфиг билдера флоу.

```bash
adapty flows config get --app <app-id> <flow-id>
```

| Аргумент | Описание |
|---|---|
| `flow-id` | ID флоу (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

Ответ содержит `config`, `remote_configs`, `status` и `updated_at`. `updated_at` — временная метка последнего изменения конфига в миллисекундах. Передайте её в [`flows config update`](#adapty-flows-config-update) как `--expected-updated-at`, чтобы не затереть параллельное изменение. Если конфиг флоу ни разу не записывался, возвращается 404.

После попытки публикации ответ также содержит три поля, описывающих её результат. Читайте их, когда [`flows get`](#adapty-flows-get) сообщает `publication_failed`:

| Поле | Описание |
|---|---|
| `publication_status` | На каком этапе остановилась публикация этой версии флоу: `transforming`, `transformed`, `uploading`, `uploaded`, `published` или `failed` |
| `transform_error` | Необработанная ошибка трансформации — JSON-payload со списком проблем или итоговая строка |
| `publication_error` | Читаемое сообщение об ошибке публикации |

### adapty flows config update \{#adapty-flows-config-update\}

Записать конфиг билдера флоу.

```bash
adapty flows config update --app <app-id> <flow-id> --config-file config.json
```

| Аргумент | Описание |
|---|---|
| `flow-id` | ID флоу (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |
| `--config` | Один из двух | Конфиг билдера в виде JSON-строки |
| `--config-file` | Один из двух | Путь к JSON-файлу с конфигом билдера или `-` для чтения из stdin |
| `--remote-configs` | Нет | JSON-массив записей `{locale, data}`, где `data` — Remote Config в виде строки |
| `--expected-updated-at` | Нет | Значение `updated_at` из предыдущего вызова `flows config get`. Если конфиг изменился после этого чтения, команда завершится с ошибкой вместо перезаписи. Пропустите, чтобы перезаписать безусловно |

Запись конфига сохраняет черновик и не публикует его. Для опубликованного флоу запись создаёт новую версию: статус флоу становится `dirty`, и пользователи продолжают видеть опубликованную версию до запуска [`flows publish`](#adapty-flows-publish).

### adapty flows config validate \{#adapty-flows-config-validate\}

Проверить, готов ли конфиг билдера к публикации, не сохраняя его.

```bash
adapty flows config validate --app <app-id> <flow-id> --config-file config.json
```

| Аргумент | Описание |
|---|---|
| `flow-id` | ID флоу (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |
| `--config` | Один из двух | Конфиг билдера в виде JSON-строки |
| `--config-file` | Один из двух | Путь к JSON-файлу с конфигом билдера или `-` для чтения из stdin |

Ответ содержит `valid` и список `issues`. Если конфиг не готов к публикации, команда завершается с кодом 1, что позволяет использовать её в скриптах как условие.

### adapty flows config preview \{#adapty-flows-config-preview\}

Отобразить локальный файл конфига в браузере. Эта команда не выполняет API-вызов и не принимает флаг `--app`.

```bash
adapty flows config preview ./config.json --screen <screen-id> --device iphone-14 --orientation portrait
```

| Аргумент | Описание |
|---|---|
| `config-file` | Путь к локальному JSON-файлу конфига билдера |

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--screen` | Первый экран флоу | ID экрана для отображения |
| `--device` | `iphone-14` | Фрейм устройства для рендеринга |
| `--orientation` | `portrait` | `portrait` или `landscape` |

В терминале команда открывает предпросмотр в браузере. При перенаправлении вывода или с `--json` выводит URL. URL содержит весь конфиг и может быть длинным: лучше передать его в инструмент для скриншотов, а не выводить в консоль. Конфиги объёмом примерно более 32 КБ рендерятся медленно.

### adapty flows media upload \{#adapty-flows-media-upload\}

Загрузить изображение для использования в конфиге флоу.

```bash
adapty flows media upload --app <app-id> ./hero.png
```

| Аргумент | Описание |
|---|---|
| `file` | Путь к файлу изображения |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

Поддерживаемые форматы: GIF, HEIC, JPEG, PNG, SVG и WebP. Ответ содержит `id`, `name` и CDN `url` для ссылки из конфига.

## Плейсменты \{#placements\}

[Плейсменты](placements) — это точки, через которые флоу, пейволы и онбординги достигают пользователей. Тип контента плейсмента фиксируется при создании, поэтому переход приложения с пейволов на флоу требует создания новых плейсментов, а не обновления существующих — [скилл migrate-placements](migrate-placements-skill) управляет этими командами для массового выполнения.

### adapty placements list \{#adapty-placements-list\}

Список всех [плейсментов](placements) для приложения.

```bash
adapty placements list --app <app-id>
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

Принимает [флаги пагинации](#global-flags).

Каждый элемент содержит `id`, `developer_id`, `title` и `is_active`. `is_active` равен `true` для активного плейсмента и `false` для неактивного.

### adapty placements get \{#adapty-placements-get\}

Получить подробную информацию о конкретном [плейсменте](placements).

```bash
adapty placements get --app <app-id> <placement-id>
```

| Аргумент | Описание |
|---|---|
| `placement-id` | ID плейсмента (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |

Ответ содержит `id`, `developer_id`, `title`, `is_active` и массив `audiences`. `is_active` равен `true` для активного плейсмента и `false` для неактивного. Каждая запись аудитории содержит `content_type` (`paywall` или `flow`), `segment_ids`, `priority` и `paywall_id` или `flow_id`. Аудитория по умолчанию имеет `segment_ids: []` и наибольшее значение приоритета (вычисляется последней). См. [Структура audiences](#audiences-shape).

### adapty placements create \{#adapty-placements-create\}

Создать новый [плейсмент](placements).

```bash
adapty placements create --app <app-id> --title "Main" --developer-id "main" --audiences '[{"content_type":"paywall","segment_ids":[],"paywall_id":"<paywall-id>","priority":0}]'
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |
| `--title` | Да | Название плейсмента |
| `--developer-id` | Да | Строковый идентификатор, используемый в коде приложения для запроса этого [плейсмента](placements) |
| `--audiences` | Один из двух | JSON-массив записей аудиторий, каждая с явным `content_type`. См. [Структура audiences](#audiences-shape) |
| `--paywall-id` | Один из двух | **Устарел.** ID [пейвола](paywalls) (UUID). На стороне клиента оборачивается в единую аудиторию по умолчанию |

Передайте ровно один из флагов `--audiences` или `--paywall-id`. Передача обоих или ни одного приведёт к ошибке.

:::warning
`--paywall-id` устарел и будет удалён. При передаче CLI выводит предупреждение в stderr и преобразует значение в аудиторию по умолчанию. Используйте `--audiences` для новой автоматизации.
:::

### adapty placements update \{#adapty-placements-update\}

Заменить все поля существующего [плейсмента](placements).

```bash
adapty placements update --app <app-id> <placement-id> --title "Main" --developer-id "main" --audiences '[{"content_type":"paywall","segment_ids":[],"paywall_id":"<paywall-id>","priority":0}]'
```

Эта команда заменяет все поля плейсмента, включая полный список аудиторий.

| Аргумент | Описание |
|---|---|
| `placement-id` | ID плейсмента (UUID) |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--app` | Да | ID приложения (UUID) |
| `--title` | Да | Название плейсмента |
| `--developer-id` | Да | Строковый идентификатор, используемый в коде приложения для запроса этого [плейсмента](placements) |
| `--audiences` | Один из двух | JSON-массив записей аудиторий, каждая с явным `content_type`. См. [Структура audiences](#audiences-shape) |
| `--paywall-id` | Один из двух | **Устарел.** ID [пейвола](paywalls) (UUID). Заменяет все аудитории единой аудиторией по умолчанию |

:::warning
Передача `--paywall-id` перезаписывает все аудитории плейсмента. Аудитории для конкретных сегментов будут удалены. Чтобы сохранить их, используйте `--audiences` и включите все нужные записи.
:::

#### Структура audiences \{#audiences-shape\}

Флаг `--audiences` принимает JSON-массив. Каждая запись содержит:

| Поле | Тип | Описание |
|---|---|---|
| `content_type` | `string` | `"paywall"` или `"flow"`. Обязательно для каждой записи. Все записи в одном плейсменте должны иметь одинаковое значение |
| `segment_ids` | `string[]` | ID [сегментов](segments), на которые нацелена эта аудитория. Длина 0 или 1. Пустой массив обозначает **аудиторию по умолчанию** — резервную для пользователей, не попавших ни в один другой сегмент |
| `paywall_id` | `string` | ID [пейвола](paywalls) (UUID), показываемого пользователям этой аудитории. Обязателен, если `content_type` равен `"paywall"` |
| `flow_id` | `string` | ID [флоу](adapty-flow-builder) (UUID), показываемого пользователям этой аудитории. Обязателен, если `content_type` равен `"flow"` |
| `priority` | `number` | Нумерация с 0, уникальная в рамках плейсмента. Аудитории вычисляются от меньшего к большему; аудитория по умолчанию должна иметь наибольшее значение |

Плейсмент должен иметь ровно одну аудиторию по умолчанию.

Тип контента плейсмента фиксируется при создании, поэтому `placements update` не может переключить пейвол-плейсмент на флоу или наоборот. Подключите флоу к отдельному плейсменту — см. [Создание нового плейсмента для флоу](migrate-to-flows#create-a-new-placement-for-your-flow).

CLI проверяет каждую запись перед отправкой запроса. Запись с отсутствующим или неизвестным `content_type`, или без ID, требуемого для указанного `content_type`, завершает выполнение с кодом 2, и ничего не отправляется.

Флоу можно прикрепить только после его публикации. Флоу в статусе `draft` или ожидающий первой публикации будет отклонён сервером; CLI распознаёт этот отказ и завершается с кодом 2, выводя команду `flows publish` для этого флоу. Чтобы опубликовать флоу, используйте [`flows publish`](#adapty-flows-publish) или [Flow & Paywall Builder](builder-save-publish), затем дождитесь, пока статус достигнет `published`.

Пример с одной целевой аудиторией и одной аудиторией по умолчанию:

```bash
adapty placements update <placement-id> --app <app-id> --title "Main" --developer-id "main" \
  --audiences '[{"content_type":"paywall","segment_ids":["<vip-segment-id>"],"paywall_id":"<vip-paywall-id>","priority":0},{"content_type":"paywall","segment_ids":[],"paywall_id":"<default-paywall-id>","priority":1}]'
```

Пример плейсмента, который показывает опубликованный флоу всем пользователям:

```bash
adapty placements create --app <app-id> --title "Onboarding" --developer-id "onboarding" \
  --audiences '[{"content_type":"flow","segment_ids":[],"flow_id":"<flow-id>","priority":0}]'
```

Чтобы заменить пейвол в нескольких плейсментах, не потеряв маршрутизацию по сегментам:

1. Найдите затронутые плейсменты:

   ```bash
   adapty paywalls placements --app <app-id> <old-paywall-id>
   ```

2. Для каждого прочитайте полный массив `audiences`:

   ```bash
   adapty placements get --app <app-id> <placement-id> --json
   ```

3. Замените нужные значения `paywall_id` на стороне клиента.

4. Запишите изменённый payload обратно:

   ```bash
   adapty placements update --app <app-id> <placement-id> --title "<title>" --developer-id "<developer-id>" --audiences '<modified-payload>'
   ```

|---|---|---|

### adapty segments get \{#adapty-segments-get\}

```bash
adapty segments get --app <app-id> <segment-id>
```
