[Флоу](adapty-flow-builder) может запрашивать у пользователей разрешение на отправку push-уведомлений с помощью действия **Request permission** — например, на экране онбординга, где объясняется, для чего нужны уведомления. SDK не показывает системный диалог разрешений напрямую. Вместо этого он передаёт запрос в обработчик `onRequestPermission` в вашем приложении. Приложение показывает диалог и возвращает ответ пользователя, после чего флоу продолжает работу.

## Прежде чем начать \{#before-you-start\}

Вам потребуется:

- **Adapty Capacitor SDK 4.1.0 или выше**: Версия 4.1.0 — первый стабильный релиз с обработчиком `onRequestPermission`.
- **Флоу с действием Request permission**: В Flow & Paywall Builder добавьте действие **Request permission** к триггеру **On Tap** или **On Screen Appear** элемента. В разделе **After response** добавьте действия, которые выполняются после ответа пользователя, например **Navigate Next**. Описание настроек действия см. в разделе [Request permission](onboarding-actions#request-permission).
- **Библиотека, которая показывает диалог уведомлений**: В примере используется плагин [`@capacitor/push-notifications`](https://capacitorjs.com/docs/apis/push-notifications). Подойдёт любой другой плагин, отображающий этот диалог.
- **Разрешение `POST_NOTIFICATIONS` в Android-манифесте и `targetSdk` 33 или выше**: Android 13 и новее показывают диалог разрешения уведомлений только приложениям, которые объявляют это разрешение и нацелены на Android 13 или выше:

  ```xml title="android/app/src/main/AndroidManifest.xml"
  <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
  ```

## Как флоу запрашивает разрешение \{#how-the-flow-requests-a-permission\}

1. Флоу доходит до действия **Request permission**: пользователь нажимает на элемент или появляется экран.
2. SDK Adapty вызывает ваш обработчик `onRequestPermission` с разрешением `push`.
3. Ваше приложение показывает системный диалог и возвращает из промиса хендлера `{ status: 'granted' }` или `{ status: 'denied' }`.
4. Флоу выполняет действия **After response**. Они одинаковы для обоих ответов.

Флоу ожидает на экране, пока промис вашего обработчика не завершится. Если промис никогда не завершается, флоу остаётся на экране. Если ОС не показывает диалог — например, потому что пользователь уже ответил на него — `PushNotifications.requestPermissions()` немедленно возвращает текущий статус, и флоу сразу выполняет действия **After response**. На Android 12 и более ранних версиях приложениям не нужно запрашивать разрешение на уведомления во время выполнения, поэтому плагин возвращает `granted` без показа диалога. Если действия **After response** уводят с экрана, пользователь видит экран запроса разрешения лишь на мгновение.

С **On Screen Appear** флоу не отправляет запрос повторно, когда пользователь возвращается на экран с помощью действия **Navigate back**. С **On Tap** каждое нажатие отправляет новый запрос, кроме нажатий во время ожидания ответа.

## Реализуйте обработчик \{#implement-the-handler\}

Обработчик `onRequestPermission` асинхронный. Он возвращает промис, который разрешается объектом с ответом пользователя:

```typescript showLineNumbers title="permissions.ts"

export const onRequestPermission: FlowEventHandlers['onRequestPermission'] = async (permission) => {
  if (permission !== 'push') {
    // Answer every request: the flow waits on the screen until it gets the answer.
    return { status: 'denied' };
  }

  // Shows the system dialog, or returns the current status without showing it.
  const { receive } = await PushNotifications.requestPermissions();
  return { status: receive === 'granted' ? 'granted' : 'denied' };
};
```

`onRequestPermission` получает:

- **`permission`**: Разрешение, которое запрашивает флоу. Действие **Request permission** передаёт `push`. Возвращайте `denied` для любого другого значения, чтобы флоу продолжился.
- **`customArgs`**: Пользовательские аргументы запроса. Действие **Request permission** не передаёт ни одного, поэтому объект пустой.

Резолвите промис со значением `{ status: 'granted' }` только когда пользователь разрешил уведомления. SDK возвращает `denied`, если ваш обработчик выбросил ошибку или его промис был отклонён.

Предоставленное разрешение позволяет приложению отображать уведомления. Чтобы получать push-уведомления, зарегистрируйте устройство у своего провайдера push-уведомлений — так же, как ваше приложение делает это вне флоу.

## Зарегистрируйте обработчик \{#register-the-handler\}

:::warning
**Без обработчика `onRequestPermission` запрос пользователю никогда не отправляется.** Если обработчик не задан, Adapty SDK отвечает `denied` без показа диалога, записывает предупреждение в лог и сразу выполняет действия блока **After response**.
:::

Установите обработчик для каждого представления флоу, которое создаёт ваше приложение, вместе с остальными [обработчиками событий флоу](capacitor-handling-events), до отображения этого представления. Авторы флоу могут добавить действие **Request permission** в любой флоу позже, без обновления приложения, а представление флоу без обработчика вернёт `denied`, не запрашивая разрешения у пользователя.

```typescript showLineNumbers title="Capacitor"

const view = await createFlowView(flow);

await view.setEventHandlers({
  onRequestPermission,
});

await view.present();
```

## Тестирование запроса разрешения \{#test-the-permission-request\}

iOS показывает диалог запроса уведомлений только один раз после установки приложения. Android перестаёт показывать его после того, как пользователь разрешил уведомления или дважды отказал. Чтобы увидеть диалог снова во время тестирования флоу, удалите приложение с устройства и установите заново. Затем откройте флоу и дойдите до действия **Request permission**. Если флоу продолжается без диалога, убедитесь, что у флоу-вью есть обработчик `onRequestPermission`, а приложение на Android объявляет `POST_NOTIFICATIONS` и нацелено на Android 13 или выше.
