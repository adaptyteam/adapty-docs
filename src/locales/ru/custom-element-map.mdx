Следуйте этому рецепту, чтобы добавить интерактивную карту во флоу. Приложение отображает карту как нативный вид MapKit в [пользовательском элементе](flow-custom-elements). Приложение запрашивает доступ к местоположению на экране флоу.

:::tip
Этот рецепт распространяется только на iOS-приложения. В приложениях на других фреймворках пользовательские элементы отображают только [резервный контент](flow-custom-elements#set-fallback-content). Поддержка Android и кросс-платформенных фреймворков появится позже.
:::

## Прежде чем начать \{#before-you-start\}

- Обновите приложение до Adapty iOS SDK 4.4 или выше. В более ранних версиях SDK для каждого кастомного элемента отображается [резервный контент](flow-custom-elements#set-fallback-content).
- Настройте приложение для [получения](get-pb-paywalls) и [отображения](ios-present-paywalls) флоу.
- Чтобы запросить у пользователей доступ к геолокации, добавьте ключ `NSLocationWhenInUseUsageDescription` в файл `Info.plist` вашего приложения. Укажите в качестве значения текст запроса, например: «Найдите фитнес-центры рядом с вами».

## 1. Добавьте пользовательский элемент на экран \{#1-add-the-custom-element-to-the-screen\}

В Flow & Paywall Builder [добавьте пользовательский элемент](flow-custom-elements#add-and-configure) на экран флоу и настройте его для карты:

- **Type**: `map`.
- **ID**: `fitness_centers`.
- **Height**: Оставьте высоту по умолчанию — **Fixed**. Карта заполняет пользовательский элемент.

Не помещайте пользовательский элемент в контейнеры, реагирующие на касание, например в карусель. Иначе при перетаскивании карты будет двигаться и карусель.

Внутри пользовательского элемента добавьте [**Image**](custom-media#image) с картинкой карты. Пользователи видят её как [резервный контент](flow-custom-elements#set-fallback-content) в следующих случаях:

- Версия приложения пользователя не отображает карту.
- Пользователь отказал в доступе к геолокации до открытия экрана.
- Устройство работает на iOS 16.

Если пользователь ещё не ответил на запрос доступа к геолокации, iOS покажет его при появлении карты. Чтобы объяснить пользователям, зачем приложению нужна их геолокация, добавьте текстовый элемент над пользовательским элементом, например: «Найдите фитнес-центры рядом с вами».

## 2. Создайте представление карты \{#create-the-map-view\}

Создайте модель для доступа к местоположению и представление SwiftUI с картой. Представление запрашивает доступ к местоположению, находит фитнес-центры в радиусе 2 км от пользователя и отображает маркер для каждого из них:

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// One location manager for the resolver and the map view
@MainActor
final class LocationAccess: NSObject, ObservableObject, CLLocationManagerDelegate {
    @Published private(set) var status: CLAuthorizationStatus = .notDetermined
    var isMapOnScreen = false
    private let manager = CLLocationManager()

    var isDenied: Bool { status == .denied || status == .restricted }

    override init() {
        super.init()
        manager.delegate = self
        status = manager.authorizationStatus
    }

    // Shows the prompt only if the user hasn't answered it yet
    func requestAccess() {
        manager.requestWhenInUseAuthorization()
    }

    nonisolated func locationManagerDidChangeAuthorization(_ manager: CLLocationManager) {
        let status = manager.authorizationStatus
        Task { @MainActor in self.status = status }
    }
}

@available(iOS 17.0, *)
struct NearbyFitnessCentersMap: View {
    @ObservedObject var access: LocationAccess
    @State private var position: MapCameraPosition = .userLocation(fallback: .automatic)
    @State private var places: [MKMapItem] = []

    var body: some View {
        ZStack {
            if access.isDenied {
                ContentUnavailableView(
                    "Location access is off",
                    systemImage: "location.slash",
                    description: Text("To see fitness centers near you, allow location access in Settings.")
                )
            } else {
                Map(position: $position) {
                    UserAnnotation()
                    ForEach(places, id: \.self) { place in
                        Marker(item: place)
                    }
                }
                .task {
                    access.requestAccess()
                    do {
                        for try await update in CLLocationUpdate.liveUpdates() {
                            guard let location = update.location else { continue }
                            places = try await fitnessCenters(around: location.coordinate)
                            withAnimation {
                                position = .automatic // zoom to fit the user and the places
                            }
                            break
                        }
                    } catch {
                        // the map still shows the location of the user
                    }
                }
            }
        }
        // Tells the resolver that the map is on the screen
        .onAppear { access.isMapOnScreen = true }
        .onDisappear { access.isMapOnScreen = false }
    }

    private func fitnessCenters(around center: CLLocationCoordinate2D) async throws -> [MKMapItem] {
        let request = MKLocalPointsOfInterestRequest(center: center, radius: 2_000) // meters
        request.pointOfInterestFilter = MKPointOfInterestFilter(including: [.fitnessCenter])
        return try await MKLocalSearch(request: request).start().mapItems
    }
}
```

</TabItem>
</Tabs>

Представление карты требует iOS 17 или выше. На iOS 16 пользователи видят резервный пейвол. Если пользователь отклоняет запрос доступа к геолокации, вместо карты отображается сообщение с инструкцией, как разрешить доступ в настройках.

## 3. Свяжите карту с кастомным элементом \{#3-match-the-map-to-the-custom-element\}

В вашем [общем резолвере приложения](ios-flow-custom-elements#set-an-app-wide-resolver) добавьте свойство для модели `LocationAccess`. Затем добавьте case, который возвращает вью с картой для Type `map` и ID `fitness_centers`. Добавляемые строки выделены. Если у вашего приложения ещё нет [резолвера](ios-flow-custom-elements#write-a-resolver-to-match-custom-elements-and-views), скопируйте весь код целиком:

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift" {5,13-20}

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    let locationAccess = LocationAccess()

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "map" where id == "fitness_centers":
            guard #available(iOS 17.0, *) else {
                return nil // iOS 16: show the fallback
            }
            if locationAccess.isDenied, !locationAccess.isMapOnScreen {
                return nil // access denied before the screen opened: show the fallback
            }
            return AnyView(NearbyFitnessCentersMap(access: locationAccess))
        // the other cases of your resolver
        default:
            return nil
        }
    }
}
```

</TabItem>
</Tabs>

SDK вызывает резолвер при открытии экрана и повторно во время его работы — например, когда загружаются продукты. Результат каждого вызова зависит от доступа к геолокации:

- **Ещё не отвечено**: Вид карты, чтобы вид мог запросить доступ.
- **Разрешено**: Вид карты, который показывает фитнес-центры рядом с пользователем.
- **Отказано до открытия экрана**: `nil`, чтобы пользователи видели резервный вариант вместо сообщения о настройках.
- **Отказано на экране**: Вид карты, потому что вид устанавливает `isMapOnScreen`, пока находится на экране. Если бы резолвер вернул здесь `nil`, SDK заменил бы сообщение о настройках на резервный вариант при следующем вызове.

Если в вашем приложении ещё не задан глобальный резолвер, вызовите `AdaptyUI.setCustomElementsResolver(_:)` один раз — например, при запуске приложения:

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// keep this instance: a resolver for one flow can reuse it
@MainActor let customElementsResolver = CustomElementsResolver()

AdaptyUI.setCustomElementsResolver(customElementsResolver)
```

## 4. Протестируйте на устройстве \{#4-test-on-a-device\}

Во Flow & Paywall Builder нельзя запустить код вашего приложения, поэтому на холсте отображается только резервный вариант. Чтобы просмотреть карту:

1. [Опубликуйте флоу](builder-save-publish). Чтобы увидеть последнюю опубликованную версию вместо кэшированной, зарегистрируйте устройство как [тестовое](test-devices).
2. Запустите сборку приложения с включённым резолвером на iOS 17 или более новой версии. Откройте экран и разрешите доступ к местоположению. Убедитесь, что на карте отображается ваше местоположение и маркеры ближайших фитнес-центров.

Чтобы протестировать резервный вариант, запретите доступ к геолокации: в приложении **Settings** перейдите в **Privacy & Security** > **Location Services** > *ваше приложение* и выберите **Never**. Затем снова откройте экран.

Чтобы разобраться, почему вместо карты отображается резервный вариант, следуйте инструкциям в разделе [Тест на устройстве](ios-flow-custom-elements#test-on-a-device) руководства по iOS.
