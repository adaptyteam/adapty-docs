Adapty SDK передаёт в ваше приложение каждый просмотр экрана и каждый ответ пользователя. Каждое событие содержит ID экрана или элемента, из которого оно пришло — именно эти ID отображает ваша аналитика. По умолчанию ID экрана выглядит как `scr_oAPBHPa7`, поэтому воронка в Amplitude или Mixpanel превращается в столбец кодов, и кому-то приходится вручную вести таблицу соответствия кодов и названий.

Вы можете задать эти ID самостоятельно. Поля ввода и группы выбора именуются в Flow Builder. ID экранов задаются через [скилл flow-generator](flow-generator-skill), который переименовывает экран во всех местах флоу, где на него есть ссылки.

:::important
Переименование экранов — часть скилла flow-generator, так что ничего дополнительно устанавливать не нужно: выполните [шаги по установке flow-generator](flow-generator-skill#install-the-skill), и скилл уже доступен. Он сохраняет изменения во флоу прямо в дашборде, поэтому сначала запустите его на черновике и проверьте результат в Flow Builder, прежде чем публиковать.
:::

## Для чего это нужно \{#what-its-for\}

- **Воронка, понятная команде**: Последовательность `welcome → signup → paywall` говорит сама за себя. Три сгенерированных кода — нет.
- **Единый словарь для всех инструментов**: Имя, которое вы даёте экрану, — это то же имя в метриках флоу Adapty и в вашей собственной аналитике, поэтому данные совпадают без таблицы соответствия.
- **Ответы, по которым можно делать запросы**: Вариант квиза с именем `beginner` — это значение, по которому аналитик может фильтровать. Сгенерированный ID сначала нужно расшифровать.

## Какие ID видит ваша аналитика \{#which-ids-your-analytics-sees\}

ID содержат два события. [`flow_screen_showed`](ios-flow-screen-views) срабатывает, когда пользователь открывает экран, а [`flow_user_input`](ios-flow-input) — когда пользователь заполняет поле ввода, выбирает вариант в квизе или переключает тогл. Каждый гайд документирует все параметры своего события. В этой таблице представлены только параметры, идентифицирующие экран или элемент.

| Параметр события | Что содержит | Где задаётся |
| :--- | :--- | :--- |
| `instanceId` | ID экрана | Скилл flow-generator |
| `element_id` | **Element ID** поля ввода или **Group ID** группы выбора | Flow Builder |
| `item_ids` | **Element ID** выбранных вариантов | Flow Builder |

## Именование полей ввода и вариантов квиза \{#name-inputs-and-quiz-options\}

Поля ввода и группы выбора имеют поля для ID в Flow Builder. **Element ID** поля ввода находится в **Input settings** — это тот же ID, который используется для ссылки на значение в других частях флоу (см. [Поля ввода и формы](builder-inputs-and-forms)). **Group ID** группы находится в **Screen settings > Selectable groups**, а каждый вариант внутри группы имеет собственный **Element ID**.

Давайте каждому из них осмысленное имя, которое понятно само по себе — именно эту строку и отображает ваша аналитика. `birthday` и `beginner` не требуют пояснений. `el_024F` требует таблицы соответствия.

Задавайте ID при добавлении элемента, а не позже. Условия и текстовые переменные ссылаются на **Element ID**, и при его изменении они не обновляются автоматически — они перестают разрешаться без каких-либо ошибок. Чтобы переименовать ID в уже работающем флоу, обновите каждое условие и каждую переменную, которые его используют. См. [Условия и переменные перестают работать после изменения Element ID](flow-common-issues#conditions-and-variables-break-after-an-element-id-change).

Скилл flow-generator задаёт эти имена автоматически для любого флоу, который он строит. [Скилл flow-audit](flow-audit-skill) сообщает о тех, которые отсутствуют.

## Переименование экранов \{#rename-screens\}

В Flow Builder нет поля для ID экрана, поэтому обратитесь к скиллу:

```
Give the screens in my onboarding flow readable IDs.
```

Скилл предлагает имя для каждого экрана, затем переименовывает его во всех местах флоу, где на него есть ссылки: сам экран, каждое навигационное действие, ведущее к нему, и привязанные к нему продукты. Все они переименовываются вместе, потому что экран, переименованный в одном месте и не переименованный в другом, — это флоу, который не будет опубликован.

Скилл сообщает, какие имена были изменены и сколько ссылок было перемещено, и не выполнит переименование, которое конфликтует с уже существующим экраном. ID экрана безопасно переименовывать в уже работающем флоу — в отличие от Element ID: скилл перемещает все ссылки вместе с ним.

## На что обратить внимание \{#what-to-check\}

- **Переименовывайте до публикации флоу**: События, уже собранные, сохраняют старый ID — в метриках флоу Adapty и в вашей аналитике. Воронка, охватывающая момент изменения, покажет два наполовину заполненных экрана, и обратное переименование их не объединит.
- **Каждый вариант в группе должен иметь свой Element ID**: Если у варианта нет ID, если два варианта делят один ID или если **Group ID** повторно используется на другом экране, вся группа ничего не репортит — не только этот вариант. Flow Builder это никак не сигнализирует, поэтому проверяйте группу после добавления нового варианта.
- **ID попадают в аналитику именно в том виде, в котором набраны**: Выберите один стиль, например `plan_selection` или `planSelection`, и используйте его во всём флоу. Смешанные стили сложнее фильтровать, чем сгенерированные коды.

## Ограничения \{#limitations\}

- **ID экранов переименовываются только через скилл**: В Flow Builder нет поля для их изменения.
- **Переименование не переносит историю**: Старые события сохраняют старый ID.
- **Некоторые элементы не отправляют событие ввода**: Поля для паролей, выборы продуктов и переключатели вкладок никогда не репортят. Именование такого элемента влияет на флоу, но не на аналитику.
