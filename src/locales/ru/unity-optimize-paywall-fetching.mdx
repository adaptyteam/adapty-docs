Надёжная загрузка флоу или пейвола в Unity решает три задачи: быстрый рендеринг, возврат варианта, соответствующего аудитории, и корректный откат при медленном соединении. Правила ниже охватывают таймингm кэширование и резервные паттерны для достижения этих целей.

:::tip
Подразумевается, что `Adapty.Activate()` и `Adapty.Identify()` уже выполнены. См. [Порядок вызовов в Unity SDK](unity-sdk-call-order).
:::

## Правила и подводные камни \{#rules-and-pitfalls\}

| Делайте так | Не делайте так | Почему |
|---|---|---|
| Загружайте плейсмент, который собираетесь показать, или прогрейте кэш с помощью [`PreloadFlows`](#preload-placements) (SDK 4.3.0+). | Не запускайте конкурентные вызовы `GetFlow` при запуске самостоятельно. | Самодельный prefetch-пакет блокирует главный поток и вызывает чёрный экран. `PreloadFlows` создан именно для этого и отправляет пакет в нативный SDK одним вызовом. |
| Вызывайте `GetFlow` после того, как атрибуция успела разрешиться — например, через 1–2 секунды после `Activate` или после срабатывания `OnLoadLatestProfile`. | Не вызывайте `GetFlow` в `Awake()`. | Атрибуция ещё не получена. Флоу разрешается по дефолтной аудитории и незаметно обходит сегменты и персонализацию ASA. |
| Оставьте значение `loadTimeout` по умолчанию (5 секунд) или задайте другое, и настройте [резервный пейвол](fallback-paywalls) для каждого плейсмента. | Не передавайте в `GetFlow` такой большой `loadTimeout`, что он никогда не срабатывает. | Если таймаут никогда не срабатывает, пользователи с плохим соединением видят пустой экран, пока сеть не восстановится, — или закрывают приложение. |

Смотрите [Получение кастомных пейволов и продуктов](fetch-paywalls-and-products-unity) для справки по параметрам `fetchPolicy` и `loadTimeout`, а также [Плейсменты](placements) для выбора подходящего плейсмента.

## Предварительная загрузка плейсментов

:::info
`Adapty.PreloadFlows` и `Adapty.PreloadFlowsForDefaultAudience` доступны начиная с версии SDK 4.3.0.
:::

`Adapty.PreloadFlows` заранее кэширует JSON флоу. Затем вы используете его как обычно: `GetFlow` для получения флоу, `CreateFlowView` — для его представления.

`fetchPolicy` определяет, из какого источника `GetFlow` будет читать данные в первую очередь, но не ограничивает доступ к кэшу:

- `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` сначала читает предзагруженную копию и обращается к сети только если кэш пуст. `AdaptyPlacementFetchPolicy.ReturnCacheDataIfNotExpiredElseLoad(maxAge)` делает то же самое, пока копия не старше `maxAge`.
- По умолчанию используется `AdaptyPlacementFetchPolicy.Default` — сначала идёт запрос к сети, и только если он завершился ошибкой или превысил время ожидания, используется предзагруженная копия.

Предзагрузка окупается в любом случае, но по-разному: политика cache-first исключает запрос, тогда как политика по умолчанию сохраняет его, но уже с тёплой копией на случай сбоя. На [тестовом устройстве](test-devices) `GetFlow` при любой политике обходит кеш и использует предзагруженную копию только при ошибке сети.

Используйте предзагрузку, когда заранее знаете, какие плейсменты понадобятся в сессии, но ещё не готовы их показывать — например, сразу после завершения `Activate` и `Identify`, для флоу, который скрывается за кнопкой, до которой пользователь ещё не дошёл.

```csharp showLineNumbers title="C#"
Adapty.PreloadFlows(
    new List<string> { "onboarding", "main_paywall" },
    TimeSpan.FromSeconds(5),
    (error) => {
        if (error != null) {
            // at least one placement failed to preload
        }
    }
);

// Later, when the user reaches the paywall:
Adapty.GetFlow(
    "main_paywall",
    AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad,
    TimeSpan.FromSeconds(5),
    (flow, error) => {
        // create the flow view
    }
);
```

**Параметры:**

- `placementIds` (обязательный): плейсменты для предзагрузки.
- `loadTimeout` (опциональный): сколько времени отводится на предзагрузку флоу, нацеленных на аудиторию. По умолчанию — 5 секунд, если передать `null` или использовать перегрузку без этого параметра. По истечении таймаута SDK может загрузить флоу для аудитории по умолчанию.

**Важные особенности поведения:**

- Вызов завершается ошибкой только после того, как были попытки загрузить все плейсменты, с одной ошибкой `NetworkFailed`, в которой перечислены все неудачные плейсменты. Ошибка для одного плейсмента не останавливает остальные, а загруженные плейсменты остаются в кэше.
- Предзагрузка всегда обращается к сети: у неё нет собственного `fetchPolicy`.
- Предзагрузка только прогревает кэш. Она не возвращает контент — для отображения вы всё равно вызываете `GetFlow`.
- Кэш привязан к текущему профилю. Флоу, предзагруженные до `Identify` или `Logout`, не будут найдены после этих вызовов, поэтому выполняйте предзагрузку после смены профиля.

### Что включает предзагрузка \{#what-a-preload-covers\}

Флоу появляется на экране послойно. Предзагрузка охватывает первый слой — точно так же, как `GetFlow`:

| Слой | Загружается кем | Прогревается предзагрузкой |
|---|---|---|
| Flow JSON — выбранный вариант, идентификаторы продуктов и Remote Config | `GetFlow` | Да |
| UI-макет — структура, стили и текст экрана | `CreateFlowView` | Нет |
| Изображения, включая статичный кадр-заглушку для видеоэлемента | `CreateFlowView`, в фоновом режиме | Нет |
| Продукты | `CreateFlowView` или `GetPaywallProducts` | Нет |
| Видеофайлы | Системный плеер, по мере рендеринга экрана | Не кешируется SDK |

`CreateFlowView` ищет макет в трёх местах, в следующем порядке:

1. Дисковый кэш нативного SDK, который сохраняется между перезапусками приложения.
2. Ваш [резервный файл](unity-use-fallback-paywalls) для SDK 4.4 и выше, если вы загрузили его после последней публикации флоу.
3. Adapty через сеть. Это требует сетевого запроса, даже после предзагрузки. При первом отображении каждой опубликованной версии флоу нативный SDK выполняет этот запрос, а затем сохраняет макет в дисковый кэш.

Когда срабатывает `LoadTimeout` у `CreateFlowView`, нативный SDK не переключается на резервный вариант: он повторно запрашивает макет у Adapty API. `LoadTimeout` не ограничивает этот повторный запрос.

### Пропуск сегментации аудитории \{#skip-audience-segmentation\}

Чтобы прогреть кеш без ожидания сегментации аудитории, используйте вариант для аудитории по умолчанию. Он не требует таймаута:

```csharp showLineNumbers title="C#"
Adapty.PreloadFlowsForDefaultAudience(
    new List<string> { "main_paywall" },
    (error) => {
        // handle the error
    }
);
```

Последующий вызов `GetFlowForDefaultAudience` читает копию так же, как `GetFlow` читает копию из `PreloadFlows`.

## Показ медиафайлов первого экрана из бандла приложения \{#show-first-screen-media-from-the-app-bundle\}

Флоу загружает изображения и видео из Adapty. Чтобы медиафайлы первого экрана отображались мгновенно, загружайте их из бандла приложения. Это удобно, если вы уже используете те же визуальные материалы, например, в нативном онбординге.

1. В Flow & Paywall Builder задайте [пользовательский медиа-ID](custom-media#custom-media-id) для изображения или видео. Загруженный файл останется резервным вариантом.
2. Добавьте файл в ваш проект Unity.
3. При создании представления флоу передайте файл из бандла для этого ID через `SetCustomAssets`:

```csharp showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
var bundledAssets = new Dictionary<string, AdaptyCustomAsset>
{
    { "welcome_video", AdaptyCustomAsset.LocalVideoFile("custom_assets/videos/welcome.mp4") }
};

var parameters = new AdaptyUICreateFlowViewParameters()
    .SetCustomAssets(bundledAssets);

AdaptyUI.CreateFlowView(flow, parameters, (view, error) => {
    // handle the result
});
```

Бандлованные файлы увеличивают размер загрузки приложения, поэтому добавляйте в бандл только те медиафайлы, которые пользователь видит первыми.

Встроенное изображение отображается мгновенно, однако SDK в фоне всё равно скачивает загруженную версию.

Медиафайлы без бандлинга тоже появляются сразу: в макете флоу содержится небольшая копия каждого изображения в низком разрешении, включая стоп-кадр видео, — она отображается до полной загрузки файла.

Полный справочник по `customAssets` см. в разделе [Настройка ассетов](unity-get-pb-paywalls#customize-assets).

## Настройка для нестабильного соединения \{#tune-for-poor-connectivity\}

Для рынков с постоянно нестабильным соединением (сельские районы, общественный транспорт, регионы с проблемами маршрутизации):

- Установите `fetchPolicy` в `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` при каждом запросе, кроме самого первого.
- Настройте [резервный пейвол](fallback-paywalls) для каждого плейсмента в дашборде Adapty.
- Подберите `loadTimeout` с учётом баланса между скоростью и точностью таргетинга. При коротком таймауте пользователь быстрее видит резервный пейвол. При длинном — целевой флоу успевает загрузиться.
- [Держите флоу лёгким](flow-size), чтобы его макет загружался быстрее.
- Не блокируйте отображение флоу вызовом `GetProfile`. Вызывайте `GetFlow` независимо, чтобы медленный профиль не задерживал интерфейс.
