Надёжная загрузка флоу или пейвола в Kotlin Multiplatform решает три задачи: быстрый рендеринг, возврат варианта, соответствующего аудитории, и корректный фолбэк при медленной сети. Правила ниже охватывают тайминг, кеширование и резервные паттерны для достижения этих целей.

:::tip
Предполагается, что `Adapty.activate()` и `Adapty.identify()` уже выполнены. См. [Порядок вызовов в Kotlin Multiplatform SDK](kmp-sdk-call-order).
:::

## Правила и подводные камни \{#rules-and-pitfalls\}

| Делайте так | Не делайте так | Почему |
|---|---|---|
| Загружайте только тот плейсмент, который собираетесь показать.                                                                                                                | Не загружайте все плейсменты разом при старте приложения.        | Массовая загрузка блокирует главный поток и во время пика запросов показывает чёрный экран.                                  |
| Вызывайте `getFlow` после того, как атрибуция успела разрешиться — например, через 1–2 секунды после `activate` или после срабатывания `setOnProfileUpdatedListener`. | Не вызывайте `getFlow` при запуске приложения.                       | Атрибуция ещё не получена. Флоу будет разрешён по аудитории по умолчанию и незаметно проигнорирует сегменты и персонализацию ASA. |
| Оставьте `loadTimeout` по умолчанию — 5 секунд — или задайте другое значение, и настройте [резервный пейвол](fallback-paywalls) для каждого плейсмента. | Не передавайте в `getFlow` такой большой `loadTimeout`, что он никогда не срабатывает. | Если таймаут никогда не срабатывает, пользователи с плохим подключением видят пустой экран, пока сеть не ответит, — или закрывают приложение. |

Подробнее о параметрах `fetchPolicy` и `loadTimeout` читайте в разделе [Получение пейволов и продуктов](fetch-paywalls-and-products-kmp), а о выборе подходящего плейсмента — в разделе [Плейсменты](placements).

## Показ медиафайлов первого экрана из бандла приложения \{#show-first-screen-media-from-the-app-bundle\}

Флоу загружает изображения и видео из Adapty. Чтобы медиафайлы первого экрана отображались мгновенно, используйте бандл приложения вместо загрузки. Это удобно, если вы уже используете те же визуальные материалы — например, в существующем нативном онбординге.

1. В Flow & Paywall Builder задайте [пользовательский медиа-ID](custom-media#custom-media-id) для изображения или видео. Загруженный там файл остаётся резервным.
2. Добавьте файл в ресурсы приложения, в `commonMain/composeResources/files/`.
3. При создании представления флоу передайте встроенный файл для этого ID в `customAssets`:

```kotlin showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
val bundledAssets: Map<String, AdaptyCustomAsset> = mapOf(
    "welcome_video" to AdaptyCustomAsset.localVideoResource(
        path = Res.getUri("files/videos/welcome.mp4")
    ),
)

AdaptyUI.createFlowView(
    flow = flow,
    customAssets = bundledAssets,
).onSuccess { view ->
    view.present()
}.onError { error ->
    // handle the error
}
```

Встроенные файлы увеличивают размер загружаемого приложения, поэтому встраивайте только те медиафайлы, которые пользователь видит первыми.

Встроенное изображение отображается мгновенно, однако SDK продолжает загружать оригинал с сервера в фоне.

Медиафайлы без встраивания тоже появляются сразу: макет флоу содержит небольшую низкокачественную копию каждого изображения, включая превью видео, и показывает её до полной загрузки файла.

Полный справочник по `customAssets` см. в разделе [Настройка ресурсов](kmp-get-pb-paywalls#customize-assets).

## Настройка для нестабильного соединения \{#tune-for-poor-connectivity\}

Для рынков с постоянно нестабильным интернет-соединением (сельская местность, транспорт, регионы с проблемной маршрутизацией):

- Установите `fetchPolicy = AdaptyPaywallFetchPolicy.ReturnCacheDataElseLoad` для каждого запроса, кроме самого первого.
- Настройте [резервный пейвол](fallback-paywalls) для каждого плейсмента в дашборде Adapty.
- Подбирайте `loadTimeout` так, чтобы соблюдать баланс между скоростью и точностью таргетинга. При коротком таймауте пользователь быстрее увидит резервный вариант; при длинном — у целевого флоу больше времени на загрузку.
- [Делайте флоу лёгким](flow-size), чтобы его разметка загружалась быстрее.
- Не блокируйте отображение флоу на `Adapty.getProfile()`. Вызывайте `getFlow` независимо, чтобы медленный запрос профиля не задерживал интерфейс.
