В режиме Observer Adapty SDK не может самостоятельно отслеживать покупки, совершённые через вашу существующую систему покупок. Вам нужно передавать транзакции из стора вашего приложения. Важно настроить это **до** публикации приложения, чтобы избежать ошибок в аналитике.

Используйте `reportTransaction`, чтобы явно сообщать Adapty о каждой транзакции.

:::warning

**Не пропускайте отчёт о транзакции!**
Если не вызвать `reportTransaction`, Adapty не распознает транзакцию, она не появится в аналитике и не будет отправлена в интеграции.

:::

Если вы используете флоу и пейволы Adapty, передавайте `variationId` при отчёте о транзакции. Это связывает покупку с флоу или пейволом, который её вызвал, и обеспечивает точность аналитики.

```typescript showLineNumbers
const variationId = paywall.variationId;

try {
    await adapty.reportTransaction(transactionId, variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```

Параметры:

| Параметр      | Наличие  | Описание                                                     |
| ------------- | -------- | ------------------------------------------------------------ |
| transactionId | required | <ul><li> Для iOS: идентификатор транзакции.</li><li> Для Android: строковый идентификатор (`purchase.getOrderId`) покупки, где покупка — это экземпляр класса [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) из библиотеки биллинга.</li></ul> |
| variationId   | optional | Строковый идентификатор варианта. Его можно получить через свойство `variationId` объекта `AdaptyPaywall`. |

В режиме Observer Adapty SDK не может самостоятельно отслеживать покупки, совершённые через вашу существующую систему покупок. Вам нужно сообщать о транзакциях из стора или восстанавливать их. Очень важно настроить это **до** выпуска приложения, чтобы избежать ошибок в аналитике.

Используйте `reportTransaction` на обеих платформах, чтобы явно сообщать о каждой транзакции, и `restorePurchases` на Android как дополнительный шаг, чтобы Adapty её распознал.

:::warning

**Не пропускайте отчёт о транзакции!**
Если не вызвать эти методы, Adapty не распознает транзакцию: она не появится в аналитике и не будет отправлена в интеграции.

:::

Если вы используете флоу и пейволы Adapty, передавайте `variationId` при отчёте о транзакции. Это связывает покупку с флоу или пейволом, который её инициировал, и обеспечивает точную аналитику.

```typescript showLineNumbers
if (Platform.OS === 'android') {
    try {
        await adapty.restorePurchases();
    } catch (error) {
        // handle the error
    }
}

...

const variationId = paywall.variationId;

try {
    await adapty.reportTransaction(transactionId, variationId);

}
```

**Привязка флоу и пейволов к транзакциям**

SDK Adapty не может определить источник покупок, поскольку вы сами их обрабатываете. Поэтому, если вы планируете использовать флоу, пейволы и/или A/B-тесты в режиме Observer, вам нужно связать транзакцию из стора с соответствующим флоу или пейволом в коде мобильного приложения. Это важно сделать правильно до релиза приложения, иначе это приведёт к ошибкам в аналитике.

```typescript 
const variationId = paywall.variationId;

try {
    await adapty.setVariationId('transactionId', variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```
