Включите интеграцию с Google Cloud Storage, чтобы безопасно хранить [события подписок](events) и [данные о посещениях пейволов](paywall-metrics) в одном месте — в вашем бакете Google Cloud Storage.

Каждый день в 4:00 UTC Adapty загружает .csv-файлы с данными за предыдущий день в ваши бакеты. Вы можете выбрать, какие данные получать: **событий**, **посещений пейвола** или **оба варианта**. Также можно экспортировать данные [вручную](#manual-data-export) в любое время за любой период.

Чтобы настроить интеграцию, [создайте ключ доступа к бакету](#create-google-cloud-storage-credentials) в Google Cloud Console и [добавьте его в настройки Adapty](#set-up-google-cloud-storage-integration).

## Расписание и продолжительность загрузки \{#upload-schedule-and-duration\}

Adapty загружает данные в Google Cloud Storage каждые 24 часа в 04:00 UTC.

Файлы содержат данные о событиях, созданных в течение предыдущего календарного дня (UTC). Файл, загруженный 8 марта, будет содержать все события, созданные 7 марта с 00:00:00 до 23:59:59 UTC.

Процесс может занять несколько часов — в зависимости от общего числа файлов в очереди и объёма запрошенных вами данных. Если Adapty включает в первую загрузку исторические данные, это займёт больше времени, чем последующие ежедневные загрузки.

## Настройка интеграции с Google Cloud Storage \{#set-up-google-cloud-storage-integration\}

Вам понадобится действующий ключ сервисного аккаунта Google Cloud с правами **записи**. Чтобы его создать, следуйте инструкциям в разделе [создание учётных данных](#create-google-cloud-storage-credentials).

:::warning
Для событий, посещений пейвола и транзакций виртуальной валюты можно использовать разные бакеты и учётные данные. При сохранении настроек Adapty проверяет учётные данные каждого активного экспорта. Если хотя бы один набор окажется недействительным, Adapty не сохранит настройки ни одной из вкладок. См. раздел [Устранение неполадок](#troubleshooting).
:::

Перейдите в [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage) и откройте нужную вкладку (**Events** или **Paywall visits**). Включите интеграцию.

Загрузите файл с вашим **ключом сервисного аккаунта Google Cloud**. Укажите целевой **бакет** и **папку**. Сохраните изменения.

## Создание учётных данных Google Cloud Storage \{#create-google-cloud-storage-credentials\}

Это руководство поможет вам создать необходимые учётные данные в Google Cloud Platform Console.

Чтобы Adapty мог загружать отчёты с необработанными данными в указанный бакет, требуется ключ сервисного аккаунта и права на запись в соответствующий бакет. Предоставив ключ сервисного аккаунта и выдав права на запись, вы позволяете Adapty безопасно и эффективно передавать отчёты с необработанными данными из своей платформы в ваше хранилище.

:::warning
Обратите внимание, что поддерживается только авторизация через HMAC-ключ сервисного аккаунта. Убедитесь, что вашему HMAC-ключу присвоены роли «Storage Object Viewer», «Storage Legacy Bucket Writer» и «Storage Object Creator» — это необходимо для корректного доступа к Google Cloud Storage.
:::

1. Для начала перейдите в раздел [IAM](https://console.cloud.google.com/projectselector2/iam-admin/serviceaccounts) вашего аккаунта Google Cloud и выберите нужный проект или создайте новый.

  <ZoomImage id="30a81ef-CleanShot_2023-03-17_at_15.22.142x.webp" width="700px" />

1. Затем создайте новый сервисный аккаунт для Adapty, нажав кнопку "+ CREATE SERVICE ACCOUNT".

    <ZoomImage id="98f8ebf-CleanShot_2023-03-17_at_15.40.062x.webp" width="700px" />

2. Заполните поля на первом шаге — доступ будет предоставлен позже. Подробнее об этой странице читайте в [документации](https://docs.cloud.google.com/iam/docs/service-accounts-create).

    <ZoomImage id="2190c50-CleanShot_2023-03-17_at_15.48.552x.webp" width="700px" />

3. Чтобы создать и скачать [приватный JSON-ключ](https://docs.cloud.google.com/iam/docs/keys-create-delete), перейдите в раздел KEYS и нажмите кнопку "ADD KEY".

    <ZoomImage id="8a45468-CleanShot_2023-03-17_at_15.58.092x.webp" width="700px" />

4. В разделе DETAILS найдите значение Email, связанное с только что созданным сервисным аккаунтом, и скопируйте его. Эта информация потребуется на следующих шагах для авторизации аккаунта и предоставления прав на запись в бакет.

    <ZoomImage id="6ccd0f0-CleanShot_2023-03-17_at_16.03.162x.webp" width="700px" />
    

5. Перейдите на страницу [Buckets](https://console.cloud.google.com/storage/browser) в Google Cloud Storage, выберите существующий бакет или создайте новый для хранения отчётов о событиях или посещениях из Adapty. Затем перейдите в раздел PERMISSIONS и выберите [GRANT ACCESS](https://docs.cloud.google.com/identity/docs/how-to?hl=en).

    <ZoomImage id="3cdd937-CleanShot_2023-03-17_at_16.14.232x.webp" width="700px" />

6. В разделе PERMISSIONS введите Email сервисного аккаунта, полученный на пятом шаге, выберите роль Storage Object Creator и нажмите SAVE для сохранения изменений.

    <ZoomImage id="62801f4-CleanShot_2023-03-17_at_16.17.312x.webp" width="700px" />

    Запомните название бакета — оно понадобится в будущем.

## Ручной экспорт данных \{#manual-data-export\}

Помимо автоматического экспорта данных о событиях в Google Cloud Storage, Adapty поддерживает ручной экспорт файлов. С его помощью вы можете выбрать конкретный временной интервал и экспортировать данные о событиях в бакет GCS вручную. Это даёт вам больше контроля над тем, какие данные и когда экспортировать.

Указанный диапазон дат используется для экспорта событий, созданных с Даты А 00:00:00 UTC до Даты Б 23:59:59 UTC.

<ZoomImage id="e347308-CleanShot_2023-03-17_at_17.39.452x.webp" width="700px" />

## Структура данных \{#data-structure\}

Adapty использует файлы `.csv` для экспорта данных в табличном формате.

:::warning
Состав событий может меняться со временем — мы или наши партнёры можем добавлять новые данные. Убедитесь, что ваш код, обрабатывающий эти данные, достаточно гибок и опирается на конкретные поля, а не на структуру в целом.
:::

## Транзакции виртуальной валюты \{#virtual-currency-transactions\}

Экспорт виртуальной валюты отправляет каждое изменение баланса [виртуальной валюты](virtual-currencies) в ваш бакет Google Cloud Storage. Используйте его, чтобы загрузить полную историю начислений, списаний, истечений срока действия и возвратов в своё хранилище данных.

Этот экспорт не зависит от экспорта событий и посещений пейволов. У него есть отдельный переключатель, отдельные учётные данные, а также собственные настройки бакета и папки.

### Включение экспорта \{#turn-on-the-export\}

1. Перейдите в [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage) и откройте вкладку **Virtual currency**.
2. Включите **Export virtual currency transactions to Google Cloud Storage**.
3. Загрузите файл с [ключом сервисного аккаунта Google Cloud](#create-google-cloud-storage-credentials), укажите бакет и папку. Поля те же, что и на вкладке **Paywall visits**.

Чтобы экспортировать транзакции виртуальной валюты за прошлые дни, воспользуйтесь [ручным экспортом данных](#manual-data-export).

### Файл и расписание

Каждый день Adapty загружает 1 файл с транзакциями виртуальной валюты за предыдущий календарный день по UTC. Транзакция относится к тому дню, в который приходится её время `created_at` по UTC.

Имя файла: `<app_id>_virtual_currency_<date>.csv`, где `<date>` — это дата, следующая за днём транзакций, в формате `YYYY-MM-DD`. Например, файл `<app_id>_virtual_currency_2026-03-08.csv` содержит транзакции за 7 марта 2026 года. У каждого экспорта своё имя файла. Храните каждый экспорт в отдельной папке, чтобы таблица или загрузчик, читающий всю папку, получал только один тип файлов. Если экспорты находятся в одной папке, выбирайте файлы этого экспорта по имени: `<app_id>_virtual_currency_*.csv`.

Файл представляет собой UTF-8 `.csv`-файл со строкой заголовка. Если за день не было транзакций, файл содержит только строку заголовка.

Каждая строка соответствует одному изменению баланса одной валюты. Транзакция, затрагивающая 2 валюты, — например, обмен золота на кристаллы, — даёт 2 строки с одинаковым `vc_transaction_id`. Транзакции из песочницы также включены в файл: для них `is_sandbox` имеет значение `true`.

При сохранении настроек Adapty проверяет учётные данные каждого активного экспорта. Если учётные данные виртуальной валюты недействительны, Adapty не сохранит настройки. Кнопка **Save** сохраняет настройки всех вкладок, поэтому изменения на остальных вкладках тоже не будут сохранены.

Экспорт виртуальной валюты использует собственные учётные данные. Если ежедневная загрузка завершится ошибкой, загрузка событий и посещений пейволов приложения продолжит работу в штатном режиме.

| :----- | :---------- |

| **created_at** | Время транзакции в UTC в формате `YYYY-MM-DD HH:MM:SS.ffffff+00:00`, например `2026-03-07 14:05:09.000000+00:00`. |
| **profile_id** | Adapty ID профиля. |
| **customer_user_id** | Customer user ID профиля на момент экспорта. Пустое, если у профиля нет customer user ID или профиль больше не существует. |
| **operation** | [Операция](virtual-currencies#operation) транзакции: `top_up`, `refund`, `spend`, `spend_reversal`, `reward`, `reward_reversal`, `exchange`, `expiry`, `migration` или `adjustment`. Пустое для серверной API-транзакции, отправленной без `operation`. |
| **transaction_type** | Способ, которым Adapty зафиксировал транзакцию, например `store_purchase`, `subscription_renewal`, `trial_start` или `api_transaction`. `subscription_renewal` используется для каждого оплаченного периода подписки, включая первый. |
| **currency_code** | Код виртуальной валюты. |

| **store** | Стор транзакции: `app_store`, `play_store`, `stripe`, `paddle`, `adapty` или название пользовательского стора. Пустое, если у транзакции нет стора. |
| **store_transaction_id** | ID транзакции покупки в сторе. Совпадает с **transaction_id** в таблице событий для этой покупки. Пустое, если транзакция не связана с покупкой в сторе. |
| **store_original_transaction_id** | Оригинальный ID транзакции покупки в сторе. Все продления подписки имеют одинаковое значение. Заполняется в строках покупки в сторе, её возврата и истечения. |
| **product_id** | ID продукта в сторе для покупки. Пустое, если у строки нет транзакции в сторе или если у Adapty нет записи о покупке. |

| **feature** | Параметр [`feature`](virtual-currencies#feature) транзакции. |
| **reference_id** | Параметр `reference_id` транзакции. |

### Объединение с таблицей событий \{#join-with-the-events-table\}

В файле виртуальной валюты нет цен. Чтобы узнать цену покупки, которая начислила валюту, объедините строку начисления с таблицей событий:

- Сопоставьте **store_transaction_id** с полем **transaction_id** таблицы событий.
- Также сопоставьте **store**, но только для `app_store`, `play_store`, `stripe` и `paddle`. Для `adapty` и кастомных сторов поле **store** в таблице событий будет пустым.

В этом примере запроса предполагается, что вы загрузили файлы виртуальной валюты в таблицу `vc_transactions`, а файлы событий — в таблицу `events`:

```sql title="SQL"
SELECT
  vc.vc_transaction_id,
  vc.created_at,
  vc.profile_id,
  vc.currency_code,
  vc.amount,
  e.event_type,
  e.product_id,
  e.revenue_usd,
  e.currency,
  e.revenue_local
FROM vc_transactions AS vc
LEFT JOIN events AS e
  ON e.transaction_id = vc.store_transaction_id
  AND (
    e.store = vc.store
    OR vc.store NOT IN ('app_store', 'play_store', 'stripe', 'paddle')
  )
  AND e.event_type IN (
    'subscription_initial_purchase',
    'subscription_started',
    'subscription_renewed',
    'trial_started',
    'trial_converted',
    'non_subscription_purchase'
  )
WHERE vc.amount > 0
  AND COALESCE(vc.store_transaction_id, '') <> '';
```

Запрос использует стандартные названия событий. Начало подписки обозначается как `subscription_initial_purchase` в интеграциях, созданных после середины сентября 2025 года, и как `subscription_started` — в более ранних. Если вы изменили названия событий в настройках экспорта событий, используйте в запросе свои названия.

Строка кредита не имеет соответствующего события, если экспорт событий отключён, если настройки экспорта событий исключают или переименовывают тип события для данной покупки, или если **Exclude historical events** исключает это событие.

Одна покупка может зачислить сразу несколько валют. Каждая валюта получает отдельную строку зачисления, и все эти строки относятся к одному событию. Чтобы подсчитать выручку, считайте каждый **store_transaction_id** один раз.

### Ограничения \{#limitations\}

- **Нет цен или сумм возврата**: В файле виртуальной валюты нет цены покупки и суммы возврата. Чтобы получить цену, [объедините строку кредита с таблицей событий](#join-with-the-events-table).
- **Не суммируйте кредиты из двух файлов**: Столбец **virtual_currency_credits** файла [событий](#events) и строки кредитов файла виртуальной валюты отражают одни и те же кредиты покупок. Для подсчёта кредитов используйте один из них, а не оба. Их итоги могут различаться: файл событий содержит только кредиты покупок и только для тех событий, которые экспортируются согласно его настройкам, тогда как файл виртуальной валюты содержит каждое изменение баланса, включая начисления через API и ручные корректировки в дашборде.
- **Нет связи между расходом и его кредитами**: Файл не показывает, какие кредиты были использованы при расходе — например, купленные или начисленные.
- **Строки возврата показывают только возвращённые кредиты**: Строка возврата отображает кредиты, которые Adapty вернул с баланса. Её значение **amount** может быть меньше кредитов, начисленных при покупке, — например, если пользователь уже потратил часть из них. Если кредитов не осталось, строка возврата в файле отсутствует.
- **Нет строки возврата при апгрейде подписки**: Возврат, связанный с апгрейдом подписки, не снимает кредиты с баланса. Строка возврата для него в файле не создаётся.

## Устранение неполадок \{#troubleshooting\}

При сохранении настроек Adapty проверяет ключ каждого активного экспорта. Если хотя бы один ключ недействителен, Adapty не сохраняет настройки ни на одной вкладке и показывает ошибку.

Каждый экспорт загружает файлы с собственным ключом, поэтому истёкший ключ останавливает загрузку только этого экспорта. Чтобы загрузки не прерывались, обновляйте ключи до истечения срока их действия. Если несколько вкладок используют один и тот же ключ, замените его на каждой из них: **Events**, **Paywall visits** и **Virtual currency**.
