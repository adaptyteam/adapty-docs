В этой статье собраны наиболее частые проблемы, возникающие при создании флоу в [Flow & Paywall Builder](adapty-flow-builder), с указанием их причин и способов решения.

## Флоу не отображается в предпросмотре или не публикуется \{#a-flow-wont-preview-or-publish\}

Проблемы с продуктами отображаются в [панели **Issues**](builder-save-publish#fix-issues-before-publishing). Нажмите на проблему, чтобы перейти к настройке, которую нужно исправить.

При попытке открыть предпросмотр или опубликовать флоу могут появиться следующие ошибки:

| Сообщение | Причина и решение |
|---|---|
| **No product selected** | В карточке продукта не выбран продукт. Выберите продукт или удалите карточку. |
| **This product no longer exists**, **This offer no longer exists** | Продукт или предложение было удалено из дашборда. Выберите другой продукт там, где он используется, или воспользуйтесь **Replace in N places** для записи **Missing** в панели **Products**, чтобы исправить все упоминания на экране сразу. |
| **This product is off this screen**, **This offer is off this screen** | Текстовая переменная, условие или действие ссылается на продукт, которого нет в списке экрана, — например, после его удаления в панели **Products**. Добавьте продукт обратно в панель или измените ссылку. |
| **Product reference is invalid** | Ссылка на продукт некорректна. Выберите продукт заново. |
| **Purchase action has no product to buy** | Действие **Purchase** не имеет продукта: поле пустое или указывает на удалённую карточку. На вкладке **Interactions** элемента установите **Product** на конкретный продукт или на `products.selectedProduct`. |
| **Select product action has no product to select** | Карточка, на которую указывало действие **Select product**, исчезла: удалена, перемещена из группы продуктов или находится на другом экране. На вкладке **Interactions** элемента укажите действие на карточку текущего экрана. |
| **Flow has no screens**, **Screen "…" has no elements** | Добавьте контент на пустой экран или удалите его. Флоу, содержащий только Remote Config, является исключением. |
| **Invalid interaction action** | Действие заполнено не до конца: **Open URL** без URL, **Navigate to screen** без назначения, **Set variable** без присвоения, **Custom** без Action ID, **Show alert** без заголовка и сообщения, **Show** или **Hide** без элемента, веб-платёжный **Purchase** без Web Paywall URL. Откройте вкладку Interactions элемента и заполните или удалите действие. |
| **"…" has no link to open**, **"…" runs a custom action without an ID**, **"…" shows an alert with no text**, **"…" has an unfinished condition**, **Complete the selected action before publishing.** | Действие не настроено: действие **Open URL** без ссылки, **Custom Action** без ID, **Show alert** без заголовка или сообщения, либо действие **Conditional** с незаполненным условием. Панель **Issues** перечисляет каждый такой случай. При нажатии **Publish to Live** билдер открывает вкладку **Interactions** первого проблемного элемента. Заполните или удалите действие. Для действия **Conditional** заполните все условия или удалите соответствующую ветку. |
| **Missing navigation target** | Действие **Navigate to screen** указывает на удалённый экран. Выберите существующий экран или удалите действие. |
| **Missing product target**, **Invalid product target**, **Product target on another screen**, **Ambiguous product target**, **Select Product inside a component** | Действие **Select product** указывает на карточку, которая была удалена, не входит в группу продуктов, находится на другом экране, имеет тот же ID элемента, что и элемент на другом экране, или расположена внутри общего для экранов футера или хедера. Укажите действие на карточку в группе продуктов на том же экране с уникальным ID. |
| **Missing selectable group** | Элемент указывает на выбираемую группу, которой больше не существует. Переподключите её или создайте заново. |
| **Invalid visibility condition** | Правило условной видимости заполнено не полностью. Заполните его в конструкторе условий. |
| **Broken references**, **Fix the broken reference before publishing.**, **Fix N broken references before publishing.** | При нажатии **Publish to Live** диалог **Can't publish yet** перечисляет условия, которые используют элемент, состояние или переменную, которых больше нет, — например, после удаления или вставки экрана из другого флоу. В том же списке отображаются строки условий со значением, но без переменной. Нажмите **Go to screen**, чтобы перейти к первому такому случаю. Затем откройте условие и выберите существующий элемент, состояние или переменную либо удалите условие. |
| **Condition uses a deleted element or state**, **Condition uses a deleted variable** | Публикация не удалась, потому что условие использует элемент, состояние или переменную, которых больше нет. Откройте условие и выберите существующий элемент, состояние или переменную либо удалите условие. Затем опубликуйте снова. |
| **Invalid State Condition**, `invalid_state_condition` | Adapty CLI или API не смог опубликовать флоу: строка в условии состояния **Disabled** или **custom** содержит значение или **Is empty**, но не содержит переменной. Выберите переменную для этой строки или удалите строку. Затем опубликуйте снова. |
| **Circular state conditions** | Условия состояний **Disabled** или **custom** нескольких элементов зависят друг от друга по кругу. В разделе **States** одного из этих элементов измените или удалите условие, которое замыкает цикл. |
| Имя формулы в разделе **Variables** с текстом ошибки, например **This variable no longer exists. Pick another one.** | В [формуле](flow-formulas) есть ошибка. В панели Variables строка формулы отмечена значком ошибки. Откройте переменную и исправьте формулу согласно разделу [Troubleshooting](flow-formulas#troubleshooting). |
| **Formula "…" has a syntax error** | Формула не соответствует правилам синтаксиса: например, отсутствует скобка, число содержит запятую или имя функции неизвестно. Откройте переменную и исправьте формулу. |
| **Formula "…" has a wrong number of arguments** | Функция в формуле принимает слишком много или слишком мало аргументов. Используйте аргументы из списков [числовых функций](flow-formulas#number-functions) и [функций дат](flow-formulas#date-functions). |
| **Formula "…" uses a value of the wrong type** | Формула использует текст, логическое значение или дату там, где нужно число, или число там, где нужна дата. Откройте переменную и исправьте формулу. |
| **Formula "…" uses a deleted value** | Формула обращается к переменной, ответу или группе продуктов, которых нет во флоу. Замените ссылку в формуле. |
| **Formula "…": the product "…" has no Products row with no offer and no plan on any screen of the flow**, `formula_undeclared_product` | Adapty CLI или API не смог опубликовать флоу: текстовый элемент или условие использует [формулу](flow-formulas#read-the-price-of-any-product), которая считывает цену продукта из каталога Adapty, но ни один экран флоу не содержит этот продукт без offer и billing plan. Flow & Paywall Builder добавляет такой продукт автоматически, поэтому ошибка возникает только в флоу, созданном вне билдера. Добавьте продукт без offer и billing plan в список продуктов каждого экрана, использующего формулу. Затем опубликуйте снова. |
| **Formula "…" uses a name with two meanings** | Переменная формулы имеет то же имя, что и ответ элемента или поле продукта. Переименуйте переменную. |
| **Formula "…" uses itself in a loop** | Формулы флоу ссылаются друг на друга по кругу, из-за чего флоу не может их вычислить. Удалите одну из ссылок. |
| **Set Variable writes the formula "…"** | Действие **Set variable** изменяет формулу. Формула всегда зависит от других значений, поэтому действие не может её задать. Выберите другую переменную в действии. |
| **Variable "…" cannot show in an action** | Переменная типа Date или [формула](flow-formulas) используется в заголовке или сообщении действия **Show alert**, в адресе действия **Open URL** или в текстовом значении действия **Set variable**. Эти тексты не могут отображать дату или вычисленное число на устройстве. Удалите переменную из действия. Чтобы показать значение, вставьте его в текстовый элемент. |
| **Missing Default Locale Content** | Действие **Open URL** содержит URL для другой локали, но не содержит URL для локали по умолчанию. Добавьте URL по умолчанию в [панели **Localizations**](add-paywall-locale-in-adapty-paywall-builder). |
| **Missing product reference** | Старый флоу использует продукт, который не зарегистрирован на экране. Откройте экран и добавьте продукт в панели **Products**. |

[Регулярно просматривайте флоу в приложении Adapty](paywall-device-compatibility-preview) во время разработки. Если флоу не публикуется, он не загрузится и там — а сообщение об ошибке укажет на конкретную проблему.

:::tip
Чтобы проверить, готов ли флоу к продакшну, запустите [скилл flow-audit](flow-audit-skill). Он проверяет то, что не покрывают ошибки публикации: нерабочие кнопки, соответствие требованиям стора, незаконченные тексты и покрытие переводов. В отчёте для каждой проблемы указан элемент и экран.
:::

## Публикация завершается ошибкой «Something went wrong» без подробностей \{#publishing-fails-with-something-went-wrong-and-no-details\}

<ZoomImage id="flow-publish-error.webp" width="300px" alt="Уведомление «Something went wrong» после неудачной публикации с адресом поддержки и Request ID для копирования" float="right" />

Запрос на публикацию завершился ошибкой на стороне Adapty, а не из-за вашего флоу. Опубликованная версия осталась без изменений. Подождите несколько минут и попробуйте опубликовать снова. Если ошибка повторится, скопируйте **Request ID** из уведомления и отправьте его на [support@adapty.io](mailto:support@adapty.io) — команда поддержки сможет найти упавший запрос.

## Скидка не применяется при покупке \{#an-offer-doesnt-apply-at-purchase\}

Builder проверяет только то, что предложение всё ещё существует в Adapty. Применяется ли скидка — решает стор в момент покупки: introductory offer зависит от того, есть ли у пользователя право на него, а для App Store promotional offer нужен действующий ключ In-App Purchase Key. Оба случая описаны в разделе [Расхождения продуктов и цен](store-sync#product-and-price-discrepancies).

## Цена предложения пустая в предпросмотре \{#an-offer-price-is-empty-in-the-preview\}

Предпросмотр в билдере не имеет доступа к сторам, поэтому `offer_price`, `offer_billing_period`, `offer_full_duration` и переменные `intro_*` показывают имя переменной в фигурных скобках вместо значения. Они раскрываются, когда SDK рендерит флоу в вашем приложении. Чтобы просмотреть условия, зависящие от типа предложения, см. [Предпросмотр продуктов и предложений](paywall-device-compatibility-preview#preview-products-and-offers).

## Публикация завершается с ошибкой после ввода сокращённого hex-цвета \{#publishing-fails-after-entering-a-shorthand-hex-color\}

Вводите каждый цвет ровно шестью hex-символами, например `#FFFFFF`. Поле цвета принимает более короткое значение, но не разворачивает его, поэтому сокращение вроде `#FFF` попадает в конфигурацию SDK в некорректном виде и публикация отклоняется. Прозрачность тут ни при чём — то же значение ломается и при 100% прозрачности. Исключение, которое обходится дороже всего, — четырёхзначное значение: оно публикуется, но отображает совсем не тот цвет, который вы выбирали.

## Изменения типографики не применяются к состоянию элемента \{#typography-edits-dont-reach-an-element-state\}

Если у состояния, например **Selected**, есть собственные настройки типографики, изменения типографики в состоянии **Default** — включая применение другого текстового стиля — не влияют на это состояние. Редактируйте типографику состояния напрямую.

## Для элемента отсутствуют элементы управления позицией, размером и отступами \{#position-size-and-spacing-controls-are-missing-for-an-element\}

Элемент и его контейнер используют направление **Free**. Это оставляет только один возможный вариант позиции и размера: **Absolute** с фиксированными шириной и высотой. Adapty скрывает все остальные элементы управления — переключатель **Position**, раздел **Spacing**, а также опции **Fill** и **Hug**. Чтобы вернуть их, измените [**Direction**](manage-paywall-ui-elements#direction) элемента на **Vertical** или **Horizontal**.

## Условие перестаёт срабатывать после изменения Element ID варианта ответа в квизе \{#a-condition-stops-matching-after-you-change-the-element-id-of-a-quiz-option\}

Условие, сравнивающее выбранный пользователем вариант с каким-либо значением, например `quiz.selectedOptionId` `=` `option_1`, содержит **Element ID** варианта в виде простого текста. При изменении **Element ID** билдер не обновляет этот текст автоматически, поэтому условие перестаёт срабатывать. Задавайте **Element ID** каждого варианта ответа до того, как использовать его в условии. Если вы изменили его позже — обновите все условия, которые сравниваются со старым ID.

Конструктор автоматически обновляет все остальные ссылки: переменные полей ввода, идентификаторы групп, состояния элементов и сегменты индикатора прогресса.

## Условие или переменная принимает пустое значение \{#a-condition-or-variable-resolves-to-an-empty-value\}

В списке переменных отображаются поля со всех экранов, поэтому условие или текстовая переменная может ссылаться на поле, которое пользователь ещё не заполнил. Во время выполнения такая ссылка принимает пустое значение. Используйте только те поля, которые были собраны раньше по ходу флоу.

Переменная [Number picker](builder-number-picker) никогда не бывает пустой: она равна числу по умолчанию до тех пор, пока пользователь не повернёт колесо. Условие, которое вычисляется до того, как пользователь доходит до этого элемента, может совпасть с ответом, который пользователь фактически не давал.

## Пользователи видят начальное значение кастомного тега вместо значения из вашего приложения \{#users-see-a-custom-tags-initial-value-instead-of-your-apps-value\}

Пользователи видят начальное значение [кастомного тега](flow-custom-tags) в следующих случаях:

- **Приложение не передаёт значение**: код, открывающий флоу, не передаёт значение для тега, или пользователь не обновил приложение до версии, которая это делает.
- **Имя не совпадает**: имя тега в коде приложения отличается от имени тега в билдере. Имена чувствительны к регистру и включают группу. Например, если группа `user` содержит тег `streak`, полное имя тега — `user.streak`.
- **Другой тег в том же текстовом элементе не имеет значения**: если хотя бы один пользовательский тег в текстовом элементе не имеет значения, все теги в этом элементе показывают начальное значение. Передавайте значения для всех пользовательских тегов в текстовом элементе.

SDK мобильного приложения не передаёт значения для пользовательских тегов, поэтому в предпросмотре отображаются только начальные значения. Чтобы увидеть значения, которые передаёт ваше приложение, откройте флоу в сборке вашего приложения.

## Пользователи видят пустое место вместо пользовательского тега \{#users-see-nothing-in-place-of-a-custom-tag\}

Пользователи видят пустое место вместо [пользовательского тега](flow-custom-tags) в следующих случаях:

- **Ваше приложение передаёт пустую строку**: Adapty воспринимает пустую строку как значение, поэтому начальное значение не используется в качестве запасного. Чтобы отобразить начальное значение, не передавайте никакого значения для тега.
- **У тега нет начального значения**: Чтобы отображать запасное значение, когда приложение не передаёт никакого значения, укажите начальное значение для тега.

## Действие «Set variable» не меняет выбранный продукт \{#a-set-variable-action-doesnt-change-the-selected-product\}

Выбранный продукт — это не переменная, поэтому **Set variable** не может изменить выбор. Используйте вместо этого действие [**Select product**](onboarding-actions#select-product).

## Флоу не выполняет действия, заданные для результата покупки \{#the-flow-doesnt-run-the-actions-set-for-a-purchase-result\}

Флоу запускает [действия по итогам](respond-to-purchase-outcomes#add-actions-for-a-result) покупки или восстановления покупки, когда стор возвращает результат. В этот момент пользователь должен находиться на экране, где была начата покупка. Флоу пропускает их в следующих случаях:

- **Ваше приложение закрывает флоу**: Когда покупка или восстановление завершается, приложение закрывает флоу в своём колбэке. Чтобы флоу продолжил работу, [не закрывайте флоу в этих колбэках](respond-to-purchase-outcomes#before-you-start).
- **Навигация выполняется раньше результата**: Действие **Navigate to Screen**, **Navigate Next**, **Navigate back** или **Close Flow** следует за **Purchase** или **Restore purchases** в том же триггере. Это действие выполняется по нажатию, то есть пользователь покидает экран до того, как стор вернёт результат. Перенесите действие в исход, например в **When succeeded**.
- **Пользователь уходит с экрана**: Пользователь переходит на другой экран до того, как стор вернёт результат, — например, нажав кнопку «Назад».
- **Покупка является Web Payment**: Флоу не получает результат покупки через **Web Payment**, поэтому у действия **Purchase** с типом **Web Payment** нет исходов. Когда вы переключаете действие на **Web Payment**, Flow & Paywall Builder удаляет связанные с ним действия исходов.

Вы не можете совершать реальные покупки в предпросмотре в мобильном приложении Adapty. Чтобы протестировать действия по результату, [совершите покупку в песочнице](test-purchases-in-sandbox) в сборке вашего приложения.

## Кнопка «Купить» не реагирует на нажатие на Android \{#a-purchase-button-does-nothing-on-android\}

На Android нажатие кнопки **Purchase** не вызывает никакой реакции, если пользователь нажал её до того, как Google Play вернул список продуктов. После загрузки продуктов кнопка работает нормально. На iOS то же раннее нажатие завершает покупку с ошибкой и запускает действия ветки **When failed**.

Кнопка не работает ни при каких условиях в следующих случаях:

- **Google Play не возвращает продукт**: убедитесь, что продукт активен в Google Play Console и что продукт в Adapty использует тот же идентификатор продукта Google Play. Чтобы проверить продукт в Adapty, см. [Создание продукта](create-product).
- **Продукты не загружаются**: в нативном Android-приложении SDK по умолчанию не повторяет загрузку продуктов. Для повторной попытки верните `true` из [`onLoadingProductsFailure`](android-handling-events#product-loading-errors).
- **Приложение передаёт во флоу продукты без этого**: когда приложение передаёт [`products`](android-present-paywalls) во флоу, SDK не загружает их из Google Play. Добавьте каждый продукт флоу в этот список.
- **Предыдущая покупка не была завершена**: SDK игнорирует новые покупки, пока не завершена предыдущая. В режиме Observer вызывайте `onFinishPurchase()` после каждой покупки. В [`onAwaitingPurchaseParams`](android-handling-events#upgrade-subscription) всегда вызывайте `onPurchaseParamsReceived`.

На iOS, если App Store не возвращает продукт, каждое нажатие завершает покупку с ошибкой и флоу выполняет действия **When failed**. Чтобы найти причину, см. [Продукты не отображаются](troubleshoot-app-store-integration#products-dont-appear).

## Изображение или видео не загружается \{#an-image-or-video-wont-upload\}

Файл, выходящий за пределы ограничений медиафайлов Flow & Paywall Builder, не загрузится. Проверьте файл на соответствие требованиям для [изображений](custom-media#image) и [видео](custom-media#video):

| Элемент | Форматы | Максимальный размер файла | Другие ограничения |
| :--- | :--- | :--- | :--- |
| Изображение | `.JPG`, `.PNG`, `.WEBP` | 20 МБ | — |
| Видео | `.MP4`, `.WEBM` | 50 МБ | Не более 30 секунд; минимум 640×640 пикселей |

Следующие форматы не поддерживаются:

- **Анимированные GIF и анимированные WEBP**: для добавления анимации используйте элемент Video.
- **SVG**: экспортируйте файл в формате PNG или WEBP. Для иконок ничего загружать не нужно — элемент Icon берёт иконки из встроенной библиотеки [Tabler Icons](custom-media#icon).

## Нижний колонтитул не отображается \{#a-footer-doesnt-render\}

Нижний колонтитул отображается только на экране с включённой опцией **Vertical scroll**. Включите **Vertical scroll** в [**Screen settings** > **Scroll**](paywall-layout-and-products#scroll).
