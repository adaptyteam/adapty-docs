В этой статье собраны наиболее частые проблемы при создании флоу в [Flow & Paywall Builder](adapty-flow-builder) — с описанием причин и способов их устранения.

## Флоу не открывается в предпросмотре и не публикуется \{#a-flow-wont-preview-or-publish\}

<ZoomImage id="flow-publish-error.webp" width="300px" alt="Publish error message in the Flow & Paywall Builder web UI when a flow has incomplete actions" float="right" />

Опубликовать или открыть флоу в предпросмотре невозможно, если в нём есть хотя бы одна из следующих проблем.

- Взаимодействие с незаконченной настройкой. Частые случаи:
    - Действие **Open URL** без указания целевого URL.
    - Действие **Navigate to screen** без указания экрана назначения — также возникает, если экран назначения был удалён после настройки действия.
    - **Условное действие** без оператора или значения.
    - Действие **Set variable** без назначения переменной/значения.
    - Действие **Purchase** без продукта (встроенный стор) или без URL Web Paywall (оплата через веб).
    - Действие **Custom** без Action ID.
    - Действие **Show alert** с пустым полем Title или Message.
    - Действие **Show** или **Hide** без выбранного элемента.
    - Действие **Select product** без выбранного продукта — также возникает, если целевой элемент продукта был удалён, перемещён из своей группы продуктов или оказался на другом экране.
    - Действие **Select product**, сохранённое внутри переиспользуемого компонента, или действие, которое ссылается на ID элемента, используемый на нескольких экранах.
- **Экран без элементов**.
- Элемент продукта **без привязанного продукта** — может возникнуть после удаления ссылочного продукта.
- Недействительный **Remote Config** в формате JSON нарушает весь процесс доставки — в таком случае невозможно даже сохранить черновик.

Чтобы выявить проблемы до публикации, [откройте флоу в предпросмотре в приложении Adapty](paywall-device-compatibility-preview). Если флоу не загружается, сообщение об ошибке содержит дополнительные сведения.

Этот список касается только того, что мешает сохранить флоу. Флоу может пройти все эти проверки и при этом оставаться небезопасным для реального пользователя — например, без действия для восстановления покупок, с нерабочей кнопкой покупки или без переводов. Скилл [flow-audit](flow-audit-skill) проверяет именно это и выдаёт результат в формате «пройдено / не пройдено» вместо сообщения об ошибке.

## Публикация завершается ошибкой «Something went wrong» \{#publishing-fails-with-something-went-wrong\}

Эта ошибка означает, что запрос на публикацию завершился неудачей на стороне Adapty, а не то, что флоу настроен неверно — именно поэтому сообщение такое общее. Ваша опубликованная версия не изменится. Скопируйте **Request ID** из сообщения об ошибке и отправьте его на [support@adapty.io](mailto:support@adapty.io), чтобы команда смогла найти неудавшийся запрос.

## Offer не применяется при покупке \{#an-offer-doesnt-apply-at-purchase\}

Builder проверяет, что у каждого элемента продукта есть продукт, но не проверяет оффер продукта. Если оффер впоследствии изменён или удалён — в сторе или в Adapty — флоу всё равно публикуется, и покупка проходит без оффера. После изменения офферов откройте флоу, заново выберите оффер для каждого затронутого элемента продукта и переопубликуйте флоу.

## Цена оффера пустая в предпросмотре \{#an-offer-price-is-empty-in-the-preview\}

Предпросмотр в Builder не обращается к сторам, поэтому `offer_price`, `offer_billing_period` и `offer_full_duration` показывают имя переменной в фигурных скобках вместо значения. Они подставляются, когда SDK отрисовывает флоу в вашем приложении. Чтобы проверить условия, зависящие от типа оффера, см. [Предпросмотр продуктов и офферов](paywall-device-compatibility-preview#preview-products-and-offers).

## Публикация завершается ошибкой после ввода сокращённого hex-цвета \{#publishing-fails-after-entering-a-shorthand-hex-color\}

Указывайте каждый цвет ровно в шесть hex-цифр, например `#FFFFFF`. Поле цвета принимает более короткое значение и никогда не раскрывает его, поэтому сокращённое значение вроде `#FFF` попадает в конфигурацию SDK в некорректном виде и публикация отклоняется. Прозрачность здесь ни при чём — то же значение не проходит и при 100% непрозрачности. Исключение, которое обходится дороже всего: четырёхзначное значение — оно публикуется, но отображает не тот цвет, который вы выбрали.

## Правки типографики не применяются к состоянию элемента \{#typography-edits-dont-reach-an-element-state\}

Если у состояния, например **Selected**, есть собственные настройки типографики, изменения типографики состояния **Default** — в том числе применение другого стиля текста — не влияют на это состояние. Редактируйте типографику состояния напрямую.

## Элементы теряют оформление после удаления стиля текста \{#elements-lose-their-styling-after-a-text-style-is-deleted\}

Удаление [стиля текста](builder-styling#text-styles) не копирует его настройки в элементы, которые его используют: эти элементы возвращаются к типографике по умолчанию. Перед удалением стиля переназначьте затронутые элементы на другой стиль или задайте их типографику вручную.

## Условия и переменные перестают работать после изменения ID элемента \{#conditions-and-variables-break-after-an-element-id-change\}

Условия и текстовые переменные ссылаются на элементы по **Element ID**, и изменение ID не обновляет эти ссылки — они просто перестают работать без каких-либо предупреждений. Задавайте Element ID до того, как ссылаться на него. Если всё же нужно изменить ID, обновите все соответствующие ссылки в условиях и переменных. Исключение — сегменты прогресс-бара: переименование сегмента обновляет его ссылки автоматически.

## Условие или переменная возвращает пустое значение \{#a-condition-or-variable-resolves-to-an-empty-value\}

Выбор переменных показывает поля со всех экранов, поэтому условие или текстовая переменная могут ссылаться на поле ввода, которое пользователь ещё не заполнил. В рантайме такая ссылка возвращает пустое значение. Ссылайтесь только на поля, которые собираются раньше в флоу.

## Действие Set variable не меняет выбранный продукт \{#a-set-variable-action-doesnt-change-the-selected-product\}

Выбранный продукт — не переменная, которую можно назначить, поэтому **Set variable** не может переключить выбор. Вместо этого используйте действие [**Select product**](onboarding-actions#select-product).

## Изображение или видео не загружается \{#an-image-or-video-wont-upload\}

Файл, не соответствующий ограничениям Flow & Paywall Builder, не загрузится. Проверьте файл по требованиям для [изображений](custom-media#image) и [видео](custom-media#video):

| Элемент | Форматы | Максимальный размер файла | Прочие ограничения |
| :--- | :--- | :--- | :--- |
| Изображение | `.JPG`, `.PNG`, `.WEBP` | 20 МБ | — |
| Видео | `.MP4`, `.WEBM` | 50 МБ | Максимум 30 секунд; минимум 640×640 пикселей |

Следующие форматы не поддерживаются:

- **Анимированные GIF и анимированные WEBP**: чтобы добавить анимацию, используйте элемент Video.
- **SVG**: экспортируйте файл в формате PNG или WEBP. Для иконок загружать ничего не нужно — элемент Icon использует встроенную библиотеку [Tabler Icons](custom-media#icon).

## Нижний колонтитул не отображается \{#a-footer-doesnt-render\}

Нижний колонтитул отображается только на экране, где включена **вертикальная прокрутка**. Включите **Vertical scroll** в разделе [**Screen settings** > **Scroll**](paywall-layout-and-products#scroll).
