Если вы создали флоу или пейвол в старом Paywall Builder, вам не нужно беспокоиться о его отображении в коде мобильного приложения. Такой флоу или пейвол содержит как то, что должно отображаться, так и то, как это должно отображаться.

:::warning

Этот гайд охватывает флоу и пейволы, отображаемые Adapty. Для кастомных пейволов и [Observer mode](observer-vs-full-mode) процесс отличается.

- Чтобы показывать кастомные пейволы, см. [Показ кастомных пейволов](present-remote-config-paywalls-unity).
- Чтобы показывать флоу в режиме **Observer mode**, см. [Показ флоу в Observer mode](unity-present-flows-in-observer-mode).

:::

Чтобы получить объект `view`, используемый ниже, см. [Получение флоу и пейволов](unity-get-pb-paywalls).

Чтобы отобразить флоу или пейвол, вызовите метод `view.Present()` на объекте `view`, созданном методом [`CreateFlowView`](unity-get-pb-paywalls#fetch-the-view-configuration). По умолчанию закрытый `view` уничтожается. Чтобы отобразить флоу снова, вызовите `CreateFlowView` ещё раз для создания нового экземпляра `view` или [сохраните view](#keep-the-view-to-present-it-again) при закрытии.

:::warning
Повторное использование уничтоженного `view` приводит к ошибке.
:::

```csharp showLineNumbers title="Unity"
view.Present((error) => {
    // handle the error
});
```

## Сохраните представление для повторного показа \{#keep-the-view-to-present-it-again\}

:::info
Сохранённые представления доступны начиная с версии SDK 4.3.0.
:::

`view.Dismiss()` освобождает представление из памяти. Чтобы сохранить его, передайте `false` в качестве параметра `destroy`:

```csharp showLineNumbers title="Unity"
view.Dismiss(false, (error) => {
    // handle the error
});
```

Покажите это представление снова — и пользователь вернётся к тому экрану, на котором остановился, с тем состоянием, которое флоу успело накопить. Представление сохраняет свой `Id`, поэтому его события по-прежнему будут приходить в ваш слушатель с тем же `view.Id`.

Представление хранится в памяти, пока вы его не освободите. Когда оно больше не нужно, вызовите `view.Destroy()`:

```csharp showLineNumbers title="Unity"
view.Destroy((error) => {
    // handle the error
});
```

`Destroy()` сначала скрывает представление, если оно ещё отображается на экране. Также освобождает представление, которое вы создали, но так и не показали, и представление в виде page-sheet, которое пользователь смахнул вниз на iOS. Не вызывайте его после обычного `Dismiss()`: такое представление уже освобождено, и вызов завершится ошибкой.

Чтобы сохранить экран при нажатии пользователем кнопки **Close**, вызовите dismiss с `destroy: false` в обработчике [действия `Close`](unity-handle-paywall-actions#close-flows-and-paywalls). Метод `FlowViewDidPerformAction` вызывается для каждого флоу и пейвола в приложении, поэтому сравнивайте `view.Id`, чтобы сохранить только тот экран, который планируете показать снова. Сохраните экран в поле при его создании, чтобы затем сравнивать с ним и отображать его повторно:

```csharp showLineNumbers title="Unity"
private AdaptyUIFlowView keptView;

void CreateKeptView(AdaptyFlow flow) {
    AdaptyUI.CreateFlowView(flow, new AdaptyUICreateFlowViewParameters(), (view, error) => {
        if (error != null) {
            // handle the error
            return;
        }
        keptView = view;
    });
}

public void FlowViewDidPerformAction(
    AdaptyUIFlowView view,
    AdaptyUIUserAction action
) {
    switch (action.Type) {
        case AdaptyUIUserActionType.Close:
            view.Dismiss(view.Id != keptView?.Id, null);
            break;
        default:
            // handle other events
            break;
    }
}
```

Сохраняйте ссылку на `view`: она нужна, чтобы снова показать флоу или пейвол и освободить его через `Destroy()`. После вызова `keptView.Destroy()` установите `keptView` в `null`, чтобы приведённое выше сравнение не совпало с уже освобождённым объектом. Любой другой вызов `view.Dismiss()` также освобождает объект, включая вызов в [`FlowViewDidReceiveError`](unity-handling-events#rendering-and-runtime-errors). После ошибки объекта создайте новый с помощью `CreateFlowView`.

## Показ диалогов \{#show-dialog\}

Используйте этот метод вместо нативных диалоговых окон, когда флоу или пейвол отображается на Android. На Android стандартные алерты появляются позади флоу, из-за чего пользователи их не видят. Этот метод обеспечивает корректное отображение диалога поверх флоу на всех платформах.

```csharp showLineNumbers title="Unity"
var dialog = new AdaptyUIDialogConfiguration()
    .SetTitle("Close this screen?")
    .SetContent("You will lose access to exclusive offers.")
    .SetDefaultActionTitle("Stay")
    .SetSecondaryActionTitle("Close");

AdaptyUI.ShowDialog(view, dialog, (action, error) => {
    if (error == null) {
        if (action == AdaptyUIDialogActionType.Secondary) {
            // User confirmed - close the flow
            view.Dismiss((error) => {
                // handle the error
            });
        }
        // If primary - do nothing, user stays
    }
});
```

## Настройка стиля презентации на iOS \{#configure-ios-presentation-style\}

Настройте способ отображения флоу или пейвола на iOS, передав параметр `iosPresentationStyle` в метод `Present()`. Параметр принимает значения `AdaptyUIIOSPresentationStyle.FullScreen` (по умолчанию) или `AdaptyUIIOSPresentationStyle.PageSheet`.

```csharp showLineNumbers title="Unity"
view.Present(AdaptyUIIOSPresentationStyle.PageSheet, (error) => {
    // handle the error
});
```

Пользователь может смахнуть листок страницы вниз, чтобы закрыть его. После этого представление остаётся в памяти без вызова `Dismiss()`: вы можете показать его снова или, начиная с SDK 4.3.0, освободить с помощью [`Destroy()`](#keep-the-view-to-present-it-again).

Если вы настроили пейвол с помощью Paywall Builder, вам не нужно беспокоиться об его отрисовке в коде мобильного приложения для показа пользователю. Такой пейвол содержит как то, что должно отображаться внутри него, так и то, как именно это должно отображаться.

:::warning

Этот гайд посвящён **старому Paywall Builder**, который требует Adapty SDK 3.3.0 или более новой версии.

Чтобы отображать кастомные пейволы, см. [Отображение кастомных пейволов](present-remote-config-paywalls-unity).

:::

Для отображения пейвола используйте метод `view.Present()` на объекте `view`, созданном методом [`CreatePaywallView`](unity-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder). Каждый `view` можно использовать только один раз. Если нужно показать пейвол снова, вызовите `CreatePaywallView` ещё раз, чтобы создать новый экземпляр `view`.

:::warning

Повторное использование одного и того же `view` без его пересоздания может привести к ошибке `AdaptyUIError.viewAlreadyPresented`.
:::

```csharp showLineNumbers title="Unity"
view.Present((error) => {
  // handle the error
});
```

## Показ диалога \{#show-dialog\}

Используйте этот метод вместо стандартных диалоговых окон, когда на Android отображается пейвол. На Android обычные алерты появляются позади пейвола и становятся невидимы для пользователей. Этот метод гарантирует корректное отображение диалога поверх пейвола на всех платформах.

```csharp showLineNumbers title="Unity"
var dialog = new AdaptyUIDialogConfiguration()
    .SetTitle("Close paywall?")
    .SetContent("You will lose access to exclusive offers.")
    .SetDefaultActionTitle("Stay")
    .SetSecondaryActionTitle("Close");

AdaptyUI.ShowDialog(view, dialog, (action, error) => {
    if (error == null) {
        if (action == AdaptyUIDialogActionType.Secondary) {
            // User confirmed - close the paywall
            view.Dismiss();
        }
        // If primary - do nothing, user stays
    }
});
```
