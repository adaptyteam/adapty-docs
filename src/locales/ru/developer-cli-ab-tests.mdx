Adapty CLI запускает обычные [A/B-тесты](ab-tests) пейволов или флоу из терминала в рамках команды `adapty ab-tests`. Вы можете создать тест как черновик, запустить его на плейсменте для одной аудитории, остановить с указанием победителя, заменить активный тест изменённым и архивировать старые тесты.

Используйте это, чтобы AI-агент мог запускать ваши тесты, а также для автоматизации работы с тестами в нескольких приложениях или запуска и остановки теста без открытия дашборда.

Обычный тест разделяет пользователей одной аудитории на одном плейсменте между двумя или более пейволами, либо между двумя или более флоу. Чтобы запустить тест сразу на нескольких плейсментах, используйте [crossplacement-тест](ab-test-types) в дашборде. Команды `ab-tests` не возвращают результаты теста. Чтобы увидеть результаты, например вероятность победы, используйте дашборд: [Результаты и метрики A/B-теста](results-and-metrics). Чтобы просмотреть аналитику по пользователям конкретного теста, отфильтруйте [команды аналитики](developer-cli-analytics) по измерению **A/B tests** из `adapty analytics catalog`.

## Прежде чем начать \{#before-you-start\}

Топик `ab-tests` использует те же настройки установки и авторизации, что и остальные команды CLI. Если вы ещё не настроили их, выполните шаги 1 и 2 из [руководства по быстрому старту](developer-cli-quickstart). Для работы с топиком требуется CLI версии 0.14.0 или выше. Чтобы узнать вашу версию, выполните `adapty --version`.

Каждая команда принимает UUID приложения через флаг `--app`. Чтобы его найти, выполните:

```bash
adapty apps list
```

Тест использует уже существующий контент:

- **Флоу**: Флоу участвует в тесте только после публикации. Черновик флоу или флоу с неопубликованными изменениями не будет принят. Чтобы опубликовать флоу, выполните `adapty flows publish`.
- **Пейволы**: Чтобы создать пейвол из продуктов, которые уже есть в Adapty, выполните `adapty paywalls create`. Чтобы задать пейволу новый дизайн, используйте [Paywall Builder](adapty-paywall-builder).
- **Плейсменты**: Тест пейвола запускается на плейсменте для пейволов, тест флоу — на плейсменте для флоу. Чтобы создать плейсмент, выполните `adapty placements create`. Приложение ничего не покажет из нового плейсмента, пока в коде не будет реализовано его получение.
- **Сегменты**: Чтобы запустить тест только для части пользователей, сначала создайте [сегмент](segments) с помощью `adapty segments create`.

Для получения информации об этих командах см. [справочник команд](developer-cli-reference).

## Список и просмотр тестов \{#list-and-read-tests\}

`list` показывает флоу-тесты, если не передать `--type paywall`. Чтобы увидеть все тесты приложения, выполните команду отдельно для каждого типа:

```bash
adapty ab-tests list --app <app-id> --type flow --page-size 100
```

```bash
adapty ab-tests list --app <app-id> --type paywall --page-size 100
```

Тест может находиться в одном из следующих состояний: `draft`, `live`, `completed`, `inactive` или `archived`.

Чтобы посмотреть один тест вместе с его вариантами, выполните:

```bash
adapty ab-tests get --app <app-id> <test-id>
```

В `get --json`, `segment_ids` — это аудитория теста: `[]` означает «Все пользователи», а `null` — аудитория ещё не задана. У каждого варианта есть `weight` и ID пейвола или флоу. Чтобы идентифицировать вариант, используйте `paywall_title` или `flow_name`. Поле `title` у варианта остаётся пустым, если вы его не задали.

## Создайте A/B-тест \{#create-a-test\}

Новый тест — это черновик. Черновик не виден пользователям, поэтому создавать и изменять его можно в любое время.

1. **Найдите ID** контента для теста с помощью `adapty paywalls list` или `adapty flows list`.

2. **Создайте черновик** с двумя или более вариантами. Каждый вариант — это один пейвол или флоу с весом. Вес — это процент пользователей, которые видят данный вариант; сумма весов должна равняться 100:

   ```bash
   adapty ab-tests create --app <app-id> --title "Annual vs monthly" \
     --goal "More revenue per user" --placement <placement-id> \
     --paywalls '[{"paywall_id":"<paywall-a>","weight":50},{"paywall_id":"<paywall-b>","weight":50}]'
   ```

   `--placement` обязателен. Для теста пейвола нужен плейсмент пейвола, для теста флоу — плейсмент флоу. Для теста флоу передайте `--flows` с `flow_id` в каждом варианте. У варианта также может быть `title`, например `"title":"A"`.

3. **Проверьте черновик** с помощью `ab-tests get`.

Плейсмент черновика только планируется. `create` также может принять плановую аудиторию с помощью `--segment` или `--all-users`. Плановые значения не влияют на пользователей. Когда вы запускаете тест, передайте плейсмент и аудиторию в `start` снова.

## Запустить тест \{#start-a-test\}

:::warning
Запуск нельзя отменить. С момента старта тест пользователи указанной аудитории больше не видят прежний пейвол или флоу.
:::

Чтобы запустить черновик, укажите плейсмент и одну аудиторию: `--all-users` или `--segment` с идентификатором сегмента:

```bash
adapty ab-tests start --app <app-id> <test-id> --placement <placement-id> --segment <segment-id>
```

CLI выводит описание действия и запрашивает `Apply? [y/N]` перед отправкой. То, где запустится тест, зависит от аудиторий плейсмента:

- **Плейсмент имеет аудиторию для этого сегмента** (или для всех пользователей): тест запускается на этой аудитории. Текущий тест на этой аудитории останавливается и переходит в состояние `completed`.
- **Плейсмент не имеет аудитории для этого сегмента**: `start` добавляет новую аудиторию с наивысшим приоритетом в плейсменте. Пользователи этого сегмента, которые в данный момент соответствуют другой аудитории, переходят в тест.

Чтобы тест имел более низкий приоритет, чем другая аудитория, сначала добавьте сегмент как аудиторию с этим приоритетом. Назначьте ей пейвол или флоу, которые пользователи видят сейчас, а затем запустите тест на этой аудитории. См. [Изменение приоритета аудитории](change-audience-priority).

Изменение в аудитории на основе сегмента может занять до 20 минут, чтобы дойти до каждого пользователя.

Запускается только черновой тест. Чтобы запустить тест повторно, создайте новый: прочитайте старый тест с помощью `get`, затем создайте тест с теми же группами с помощью `create`.

## Изменение теста \{#change-a-test\}

`update` отправляет весь тест заново. Указывайте все флаги каждый раз, включая обязательный `--placement`. Если не передать какой-либо флаг, Adapty сбросит его значение: например, цель или запланированную аудиторию.

```bash
adapty ab-tests update --app <app-id> <test-id> --title "Annual vs monthly, Q4" \
  --goal "More revenue per user" --placement <placement-id> \
  --paywalls '[{"paywall_id":"<paywall-a>","weight":70},{"paywall_id":"<paywall-b>","weight":30}]'
```

На живом тесте `update` меняет только название и цель. Передавайте варианты, плейсмент и аудиторию точно так, как возвращает `get`; другие варианты или другой плейсмент будут отклонены. Тест сохраняет время старта, а пользователи остаются в своих вариантах. Завершённый или архивированный тест изменить нельзя.

Чтобы изменить варианты или их веса у живого теста, замените его. `replace` — это действие **Modify** в дашборде:

```bash
adapty ab-tests replace --app <app-id> <test-id> --title "Annual vs monthly v2" \
  --placement <placement-id> \
  --paywalls '[{"paywall_id":"<paywall-a>","weight":80},{"paywall_id":"<paywall-b>","weight":20}]'
```

Запущенный тест останавливается и переходит в состояние `completed`, а его результаты сохраняются под его ID. Новый тест с новым ID запускается на той же аудитории, и Adapty заново распределяет всех пользователей аудитории по вариантам. Если передать другой плейсмент в `--placement`, Adapty перенесёт аудиторию в этот плейсмент. Тест типа All users переместить нельзя.

## Остановить тест \{#stop-a-test\}

`stop` завершает тест. Вы выбираете, что будут видеть пользователи его аудитории после остановки. Передайте ровно один из этих флагов:

| Флаг | После остановки |
|---|---|
| `--winner <id>` | Вся аудитория видит один вариант теста. Передайте ID пейвола или ID флоу этого варианта. |
| `--other <id>` | Вся аудитория видит пейвол или флоу, которого не было в тесте, того же типа, что и тест. |
| `--no-content` | Аудитория покидает плейсмент, и её пользователи попадают в следующую подходящую им аудиторию. Недопустимо для теста «Все пользователи». |

```bash
adapty ab-tests stop --app <app-id> <test-id> --winner <paywall-b>
```

Тест переходит в состояние `completed`. Чтобы повторно протестировать те же варианты, создайте новый тест, как описано в [Запуск теста](#start-a-test). Подробнее о выборе победителя — в разделе [Результаты и метрики A/B-тестов](results-and-metrics).

## Архивирование теста \{#archive-a-test\}

Можно архивировать любой тест, который не запущен. Чтобы архивировать активный тест, сначала остановите его. Восстановить архивированный тест невозможно.

```bash
adapty ab-tests archive --app <app-id> <test-id>
```

## Подтверждение в скриптах и агентах \{#confirmation-in-scripts-and-agents\}

`start`, `stop`, `replace` и `archive` нельзя отменить, поэтому каждая из них показывает, что произойдёт, прежде чем что-либо отправить. Способ запроса подтверждения зависит от того, как выполняется команда:

| Как выполняется команда | Что происходит |
|---|---|
| В терминале | CLI выводит описание действия и спрашивает `Apply? [y/N]`. Если вы ответите `y` или `yes`, CLI отправит запрос. При любом другом ответе CLI завершится с кодом 1 и ничего не отправит. |
| С флагом `--yes` | CLI отправляет запрос без подтверждения. |
| С флагом `--json`, в пайпе или без терминала | CLI ничего не отправляет и завершается с кодом 6. Сообщение об ошибке описывает выполняемое действие. |

Таким образом, скрипт или агент может сначала ознакомиться с результатом команды: запустить её без `--yes`, прочитать сообщение и повторно запустить с `--yes` только после того, как кто-то одобрит этот результат.

## Ошибки \{#errors\}

| Код выхода | Причина | Что делать |
|---|---|---|
| 1 | Вы ответили что-то отличное от `y` на запрос. Ничего не отправлено. | Запустите команду снова, если хотели продолжить. |
| 2 | CLI отклонил входные данные до отправки: неверный UUID, варианты не в формате JSON-массива, вариант без ID или с нецелым весом, указаны оба флага или ни одного из `--paywalls` и `--flows`, либо два варианта остановки. | Исправьте флаг, указанный в сообщении. |
| 3 | Вы не вошли в систему, или у вашего пользователя Adapty нет доступа к приложению. | Войдите с помощью `adapty auth login` и найдите ID приложения в `adapty apps list`. |
| 4 | Adapty отклонил запрос. Причина указана в сообщении. | См. [Сообщения от Adapty](#messages-from-adapty). |
| 5 | CLI не смог связаться с Adapty. | Убедитесь, что есть подключение к интернету, и запустите команду снова. |
| 6 | Команда, которую нельзя отменить, была запущена без `--yes` и без возможности ответить на запрос. Ничего не отправлено. | Ознакомьтесь с описанием действия в сообщении, затем запустите команду снова с `--yes`. |
| 130 | Вы нажали Ctrl+C на запросе. Ничего не отправлено. | — |

### Сообщения от Adapty

| Сообщение | Что делать |
|---|---|
| `The sum of the weights must equal 100, but has N.` | Измените веса так, чтобы их сумма равнялась 100. |
| `Flow(<id>) must be published before adding to AB test.` | Опубликуйте флоу, затем выполните команду снова. |
| `Paywalls cannot be changed in non-draft ab tests.` или `Placement cannot be changed in non-draft ab tests.` | Передайте варианты и плейсмент в том виде, в котором их возвращает `get`, или используйте `replace`. |
| `AB Test from default audience can not be stopped.` | Для остановки A/B-теста на аудитории «Все пользователи» нужно указать пейвол или флоу: используйте `--winner` или `--other`. |
| `AB Test to stop must be live.` | Остановить или заменить можно только активный тест. |
| `Live Ab Test can not be deleted.` | Сначала остановите тест, затем архивируйте его. |

## Справочник команд \{#command-reference\}

Каждая команда принимает `--app` — UUID приложения из `adapty apps list`. Каждая команда, кроме `list`, принимает ID теста в качестве аргумента.

### `ab-tests list`

| Flag | Required | Description |
|---|---|---|
| `--type` | No | `flow` (по умолчанию) или `paywall`. |
| `--state` | No | `live`, `draft`, `completed`, `inactive` или `archived`. |
| `--placement` | No | Только тесты для указанного плейсмента (ID). Повторите флаг для нескольких плейсментов. |
| `--segment` | No | Только тесты, которые выполняются именно для этого сегмента (ID). Повторите флаг для нескольких сегментов. |
| `--search` | No | Только тесты, в названии которых содержится указанный текст. |
| `--page` | No | Номер страницы. По умолчанию: 1. |
| `--page-size` | No | Тестов на странице, не более 100. По умолчанию: 20. |

### `ab-tests get`

Возвращает тест вместе с его вариантами. Дополнительных флагов не принимает.

### `ab-tests create`

| Флаг | Обязательный | Описание |
|---|---|---|
| `--title` | Да | Название теста. |
| `--paywalls` | Один из двух | Варианты пейвол-теста в формате JSON: `[{"paywall_id":"<id>","weight":50,"title":"A"}, …]`. `title` необязателен. |
| `--flows` | Один из двух | Варианты флоу-теста в формате JSON, с `flow_id` вместо `paywall_id`. |
| `--goal` | Нет | Что должен показать тест. |
| `--placement` | Да | Плейсмент, для которого планируется тест (ID). Пейвол-тест требует плейсмент типа paywall, флоу-тест — плейсмент типа flow. |
| `--segment` | Нет | Запланировать тест для одного сегмента (ID). Нельзя использовать вместе с `--all-users`. |
| `--all-users` | Нет | Запланировать тест для всех пользователей. |

### `ab-tests update`

Принимает те же флаги, что и `create`, флаг `--placement` обязателен. Флаг, который вы не указываете, очищается. В активном тесте можно изменить только `--title` и `--goal`. Передавайте тот же плейсмент и аудиторию снова.

### `ab-tests start`

| Флаг | Обязательный | Описание |
|---|---|---|
| `--placement` | Да | Плейсмент для запуска теста (ID). |
| `--segment` | Один из двух | Запустить тест для одного сегмента (ID). |
| `--all-users` | Один из двух | Запустить тест для всех пользователей. |
| `--yes`, `-y` | Нет | Запустить без подтверждения. Обязателен при использовании `--json` или в пайпе. |

### `ab-tests stop`

| Флаг | Обязательный | Описание |
|---|---|---|
| `--winner` | Один из трёх | Показывать пейвол или флоу этого варианта (ID) всей аудитории. |
| `--other` | Один из трёх | Показывать пейвол или флоу, которого не было в тесте (ID). |
| `--no-content` | Один из трёх | Удалить аудиторию из плейсмента. Недоступно для теста «Все пользователи». |
| `--yes`, `-y` | Нет | Остановить без подтверждения. Обязательно при `--json` или в пайпе. |

### `ab-tests replace`

| Флаг | Обязательный | Описание |
|---|---|---|
| `--title` | Да | Заголовок нового теста. |
| `--placement` | Да | Плейсмент нового теста (ID). Другой плейсмент переносит аудиторию на этот плейсмент. |
| `--paywalls` или `--flows` | Да | Варианты нового теста, как в `create`. |
| `--goal` | Нет | Что должен показать новый тест. |
| `--yes`, `-y` | Нет | Заменить без запроса подтверждения. Обязателен при использовании `--json` или в пайпе. |

Новый тест перенимает аудиторию заменяемого теста, поэтому `replace` не принимает флаг аудитории.

### `ab-tests archive`

| Flag | Required | Description |
|---|---|---|
| `--yes`, `-y` | Нет | Архивировать без подтверждения. Обязательно при использовании `--json` или в пайпе. |
