[Flow & Paywall Builder](adapty-flow-builder) разделяет сохранение и публикацию. Черновики сохраняют вашу работу в дашборде Adapty, а публикация делает текущую версию доступной пользователям через SDK. В этой статье описаны оба действия и когда их использовать.

## Сохранение флоу как черновика \{#save-a-flow-as-a-draft\}

:::warning
Невалидный [Remote Config](customize-flow-with-remote-config) не позволяет сохранить черновик.
:::

Flow & Paywall Builder автоматически сохраняет прогресс раз в минуту.

Чтобы сохранить черновик вручную, нажмите **Save draft** в правом верхнем углу Flow & Paywall Builder или используйте сочетание клавиш **Cmd/Ctrl + S**.

Черновики видны только в дашборде. Они не влияют на то, что видят пользователи в приложении, даже если флоу уже добавлен в [плейсмент](placements).

## Публикация флоу \{#publish-a-flow\}

Публикация делает текущую версию флоу доступной пользователям через SDK. После публикации новая версия заменяет любую ранее опубликованную версию того же флоу.

:::note
Чтобы добавить флоу в [плейсмент](placements), сначала его нужно опубликовать. Флоу со статусом Draft нельзя добавить в плейсмент.
:::

Чтобы опубликовать флоу, нажмите **Publish to Live** в правом верхнем углу Flow & Paywall Builder.

Дальнейшее поведение зависит от того, назначен ли флоу в плейсмент:

- **Флоу уже в плейсменте**: пользователи начнут видеть новую версию при следующем обращении к этому плейсменту.
- **Флоу не в плейсменте**: добавьте флоу в [плейсмент для флоу](create-placement), чтобы начать показывать его пользователям. Флоу требует собственного плейсмента — его нельзя добавить в плейсмент, который уже используется для пейвола или онбординга.

:::tip
Флоу готов к публикации, когда каждое действие, экран и элемент продукта полностью настроены. Типичные проблемы описаны в разделе [Устранение неполадок](#troubleshooting).
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Кнопка Publish to Live на верхней панели инструментов Flow & Paywall Builder" />

:::warning
[Пользовательские шрифты](using-custom-fonts-in-flow-builder) не включаются в флоу — каждый файл шрифта нужно добавить в бандл приложения вручную. Без файла пользователи увидят системный шрифт.

Чтобы изменить шрифт в опубликованном флоу, не сломав старые версии: [скопируйте флоу](copy-flows), измените шрифт в копии и назначьте её в [аудиторию](add-audience-paywall-ab-test) для версий приложения, в которые включён нужный шрифт.
:::

## Статус флоу \{#flow-status\}

Каждый флоу отображает статус в [списке флоу](filter-flows). Статус отражает, на каком этапе жизненного цикла сохранения и публикации находится флоу.

| Статус | Значение |
| :----- | :------ |
| **Draft** | Флоу никогда не публиковался. Существует только черновик, поэтому пользователи его пока не видят. Сначала нужно опубликовать черновик, чтобы добавить его в [плейсмент](placements). |
| **Dirty** | Флоу был опубликован, но содержит сохранённые правки, которые ещё не опубликованы. Пользователи по-прежнему видят последнюю опубликованную версию, пока вы не выполните повторную публикацию. |
| **Publishing** | Выполняется публикация. |
| **Failed** | Последняя попытка публикации завершилась ошибкой. Пользователи продолжают видеть последнюю опубликованную версию (если она есть). |
| **Published** | Последняя сохранённая версия опубликована. Неопубликованных изменений нет. |
| **Archived** | Флоу был [заархивирован](archive-flows#archive-a-flow) и недоступен для редактирования, пока вы его не [восстановите](archive-flows#restore-a-flow). |

## Устранение неполадок \{#troubleshooting\}

Незавершённое действие, пустой экран, элемент продукта без привязанного продукта или невалидный JSON в Remote Config блокирует предпросмотр и публикацию. Полный список проблем и способы их решения см. в разделе [Типичные проблемы](flow-common-issues#a-flow-wont-preview-or-publish).

Проверьте флоу в [приложении Adapty](paywall-device-compatibility-preview) перед публикацией, чтобы выявить возможные ошибки заранее. Если флоу не загружается в режиме предпросмотра, посмотрите сообщение об ошибке для получения подробностей.

Флоу может пройти все эти проверки и при этом быть не готовым к публикации — сломанная кнопка восстановления, отсутствующая ссылка на пользовательское соглашение, непереведённый экран. Скилл [flow-audit](flow-audit-skill) проверяет именно это — из терминала — и выдаёт итоговый вердикт, а не просто список.
