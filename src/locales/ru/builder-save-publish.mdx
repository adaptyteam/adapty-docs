[Flow & Paywall Builder](adapty-flow-builder) разделяет сохранение и публикацию. Черновики сохраняют вашу работу в дашборде Adapty, а публикация делает текущую версию доступной пользователям через SDK. В этой статье описаны оба действия и когда использовать каждое из них.

## Сохранение флоу как черновика \{#save-a-flow-as-a-draft\}

:::warning
Недействительный [Remote Config](customize-flow-with-remote-config) не позволит сохранить черновик.
:::

Flow & Paywall Builder автоматически сохраняет прогресс раз в минуту.

Чтобы сохранить черновик вручную, нажмите **Save draft** в правом верхнем углу Flow & Paywall Builder или используйте сочетание клавиш **Cmd/Ctrl + S**.

Черновики видны только в дашборде. Они не влияют на то, что видят пользователи в приложении, даже если флоу уже привязан к [плейсменту](placements).

## Публикация флоу \{#publish-a-flow\}

Публикация делает текущую версию вашего флоу доступной пользователям через SDK. После публикации новая версия заменяет любую ранее опубликованную версию того же флоу.

:::note
Чтобы добавить флоу в [плейсмент](placements), сначала опубликуйте его. Флоу в статусе Draft нельзя добавить.
:::

Чтобы опубликовать флоу, нажмите **Publish to Live** в правом верхнем углу Flow & Paywall Builder.

Дальнейшие действия зависят от того, назначен ли флоу уже какому-либо плейсменту:

- **Флоу уже привязан к плейсменту**: пользователи увидят новую версию при следующем обращении к этому плейсменту.
- **Флоу не привязан к плейсменту**: добавьте флоу в [плейсмент флоу](create-placement), чтобы начать показывать его пользователям. Для флоу нужен отдельный плейсмент — нельзя использовать тот, который уже занят пейволом или онбордингом.

:::tip
Флоу готов к публикации, когда все действия, экраны и элементы продуктов полностью настроены. Типичные ошибки описаны в разделе [Устранение неполадок](#troubleshooting).
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Кнопка Publish to Live в верхней панели инструментов Flow & Paywall Builder" />

:::warning
[Кастомные шрифты](using-custom-fonts-in-flow-builder) не поставляются вместе с флоу — каждый файл шрифта нужно добавить в бандл приложения вручную. Без файла пользователи увидят системный шрифт по умолчанию.

Чтобы изменить шрифт в опубликованном флоу, не сломав более старые версии: [скопируйте флоу](copy-flows), измените шрифт в копии и нацельте копию на [аудиторию](add-audience-paywall-ab-test), которая использует версии приложения с этим шрифтом.
:::

## Статус флоу \{#flow-status\}

Каждый флоу отображает статус в [списке флоу](filter-flows). Статус отражает, на каком этапе жизненного цикла сохранения и публикации находится флоу.

| Статус | Значение |
| :----- | :------ |
| **Draft** | Флоу никогда не публиковался. Существует только черновик, поэтому пользователи его ещё не видят. Сначала нужно опубликовать черновик, чтобы добавить его в [плейсмент](placements). |
| **Dirty** | Флоу был опубликован, но содержит сохранённые правки, которые ещё не опубликованы. Пользователи по-прежнему видят последнюю опубликованную версию, пока вы не опубликуете снова. |
| **Publishing** | Публикация выполняется. |
| **Failed** | Последняя попытка публикации завершилась ошибкой. Пользователи продолжают видеть последнюю опубликованную версию, если она есть. |
| **Published** | Последняя сохранённая версия активна. Неопубликованных правок нет. |
| **Archived** | Флоу был [заархивирован](archive-flows#archive-a-flow) и недоступен для редактирования, пока вы его не [восстановите](archive-flows#restore-a-flow). |

## Устранение неполадок \{#troubleshooting\}

Незавершённое действие, пустой экран, элемент продукта без привязанного продукта или невалидный JSON в Remote Config блокируют как предпросмотр, так и публикацию. Полный список проблем и способы их решения — в разделе [Распространённые ошибки](flow-common-issues#a-flow-wont-preview-or-publish).

Проверьте флоу в [приложении Adapty](paywall-device-compatibility-preview) перед публикацией, чтобы выявить возможные проблемы. Если флоу не загружается в предпросмотре, подробности можно найти в сообщении об ошибке.

Флоу может пройти все проверки и всё равно оказаться небезопасным для публикации — неработающая кнопка восстановления, отсутствующая ссылка на условия использования, непереведённый экран. [Навык flow-audit](flow-audit-skill) проверяет именно это, прямо из терминала, и выдаёт вердикт, а не список.
