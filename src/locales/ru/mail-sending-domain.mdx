Adapty Mail отправляет кампании с вашего собственного домена, а не с общего адреса — так репутация отправителя остаётся под вашим контролем. Для запуска достаточно одного верифицированного домена, а в рамках одного проекта их можно добавить до пяти.

Чтобы верифицировать домен с минимумом шагов, воспользуйтесь руководством [Начало работы с Adapty Mail](mail-get-started#4-set-up-your-sending-domain). Эта статья — полный справочник: настройка, верификация, прогрев и отправка с нескольких доменов.

## Требования и ограничения \{#requirements-and-limitations\}

- **Корневой домен**: Укажите корневой домен. У него должен быть суффикс верхнего уровня (`yourapp.com`). Adapty Mail не принимает поддомены (`app.yourapp.com`) и домены с суффиксами второго уровня (`yourapp.co.uk`, `yourapp.com.br`).
- **Только ASCII**: Punycode и интернационализированные доменные имена не поддерживаются.
- **Активные NS-записи**: Домен должен резолвиться. Adapty Mail выполняет DNS-запрос при настройке и отклоняет домены без валидных NS-записей.
- **Один проект на домен**: Домен нельзя использовать сразу в нескольких проектах. Если он уже добавлен в какой-либо проект — ваш или чужой — настройка завершится ошибкой.
- **Доменное имя, соответствующее вашему бренду**: Имя должно однозначно ассоциироваться с вашим приложением. `yourapp.com` подходит для приложения под названием Yourapp; посторонний `anotherapp.com` — нет. Adapty использует название приложения из [бренда](mail-brand), его описание и слоган в качестве ориентира. Если бренд в проекте не настроен, проверка пропускается.
- **Домен с хорошей репутацией**: Adapty Mail отклоняет домен, который [Blacklist Master](https://www.blacklistmaster.com/) отмечает как включённый в спам-блэклист.
- **До пяти доменов на проект**: Каждый проходит верификацию и прогрев самостоятельно.
- **Удаление необратимо**: Отправка прекращается немедленно, а прогресс верификации домена, DNS-записи и прогревочный почтовый ящик удаляются. Вы можете добавить домен снова, но верификация начнётся с нуля с новыми записями — сохранится только дневной лимит отправки. Ваши собственные DNS-записи остаются там, где вы их разместили; удалите их самостоятельно.

## 1. Добавьте домен \{#1-add-the-domain\}

В Adapty Mail откройте **Settings** > **DNS** и перейдите в раздел **Email domains**.

1. В поле **Domain** введите ваш корневой домен, например `yourapp.com`.
2. В поле **Sending subdomain** укажите поддомен для отправки писем. Оставьте поле пустым, чтобы использовать `mail`. Подсказка под полем показывает полное имя хоста: *Emails will be sent from mail.yourapp.com*.
3. В поле **Link subdomain** укажите *другой поддомен* для ссылок и изображений внутри писем. Оставьте поле пустым, чтобы использовать `go`. Подсказка также показывает этот хост: *Links and images in emails will be served from go.yourapp.com*.
4. Нажмите **Add domain**. Adapty Mail проверит введённые данные, добавит домен в ваш проект и отобразит карточку со всеми DNS-записями, которые нужно настроить для домена.

<ZoomImage id="mail-email-domains.webp" width="500px" alt="Форма добавления домена с полями Domain, Sending subdomain и Link subdomain" />

5. При желании [добавьте ещё домены](#multiple-domains), чтобы увеличить суточный лимит отправки писем.

### Используйте собственные поддомены \{#use-custom-subdomains\}

Префикс отправителя отображается в поле «От» у каждого получателя, а префикс ссылки — в каждой ссылке, по которой они переходят. Большинство проектов оставляют значения по умолчанию; если вы вводите своё, оба поля подчиняются одним и тем же правилам:

- Используйте строчные буквы, цифры и дефисы; без дефиса в начале или конце, не длиннее 63 символов.
- Зарезервированные значения: `www`, `smtp`, `admin`, `api`, `mx` и `dkim`.
- Оскорбительные лейблы и лейблы, имитирующие известный бренд — например, `paypal` — будут отклонены. Обычные маркетинговые слова вроде `news`, `offers` или `hello` допустимы.
- Оба префикса не могут совпадать друг с другом.
- После добавления домена оба префикса зафиксированы. Чтобы отправлять письма с другого хоста, удалите домен и добавьте его снова или добавьте второй домен.

## 2. Добавьте DNS-записи \{#add-the-dns-records\}

Добавьте в ваш DNS все записи с карточки — точно так, как они показаны. Чтобы перенести весь набор сразу, нажмите **Export** и выберите **CSV**, **GoDaddy zone file**, **Cloudflare zone file** или **Route 53 zone file**.

:::warning
**В Cloudflare каждая запись CNAME должна быть только DNS** — проксированная запись резолвится на адрес Cloudflare и никогда не проходит верификацию. Экспорт **Cloudflare zone file** настраивает это автоматически.
:::

Первые три раздела обязательны — настройка считается незавершённой, пока записи не резолвятся. Запись DMARC для корневого домена необязательна.

| Раздел | Хост | Что делает |
| --- | --- | --- |
| **Sending infrastructure** | Sending subdomain | Подписывает ваши кампании и направляет возвраты обратно в Adapty Mail |
| **Warmup mailbox** | Sending subdomain | Запускает почтовый ящик, который формирует репутацию отправителя в процессе [прогрева](#warm-up-and-daily-limits) |
| **Media & redirects** | Link subdomain | Обслуживает изображения и отслеживаемые ссылки в ваших письмах с вашего собственного домена |
| **DMARC policy** (опционально) | Root domain | Указывает принимающим провайдерам, как обрабатывать письма, не прошедшие аутентификацию |

Если для вашего корневого домена уже настроены записи SPF и DMARC для корпоративной почты, они остаются без изменений — все необходимые записи добавляются на поддоменах.

<Details>
<summary>Справочник DNS-записей</summary>

**DKIM — 3 записи CNAME.** Криптографические подписи, подтверждающие, что письмо не было изменено при передаче.

| Поле  | Формат                                |
| ----- | ------------------------------------- |
| Type  | CNAME                                 |
| Name  | `{token}._domainkey.mail.yourapp.com` |
| Value | `{token}.dkim.amazonses.com`          |

**MAIL FROM — 1 запись MX.** Обрабатывает отказы доставки.

| Поле     | Формат                                                   |
| -------- | -------------------------------------------------------- |
| Type     | MX                                                       |
| Name     | `hello.mail.yourapp.com`                                 |
| Priority | `10`                                                     |
| Value    | `feedback-smtp.{region}.amazonses.com`                   |

**MAIL FROM — 1 TXT-запись.** Разрешает Adapty отправлять письма от вашего имени.

| Field | Format                                 |
| ----- | -------------------------------------- |
| Type  | TXT                                    |
| Name  | `hello.mail.yourapp.com`               |
| Value | `"v=spf1 include:amazonses.com ~all"`  |

**DMARC — 1 TXT-запись для вашего корневого домена.** Необязательно, но рекомендуется.

| Field | Format                |
| ----- | --------------------- |
| Type  | TXT                   |
| Name  | `_dmarc.yourapp.com`  |
| Value | `v=DMARC1; p=reject`  |

Записи для прогрева почтового ящика и `go.yourapp.com` имеют такую же структуру — имена и значения выдаёт почтовый провайдер и хостинг, которыми пользуется Adapty Mail. Токены, регионы, хостнеймы и значения для подтверждения владения генерируются при настройке — копируйте их из карточки домена или экспорта, а не из этого справочника.

</Details>

## 3. Проверьте записи \{#verify-the-records\}

<ZoomImage id="email-domains.webp" width="700px" alt="Expanded domain card showing DNS record groups and verification progress" />

 Распространение DNS обычно занимает несколько минут — в редких случаях до 48 часов. Чтобы проверить записи, Adapty Mail самостоятельно опрашивает DNS через регулярные промежутки времени, пока записи не будут найдены или не пройдёт 7 дней. Нажмите **Check** на карточке, чтобы запустить проверку вручную (с задержкой в 10 секунд), или возобновите автоматические проверки, если они остановились.

Запись считается верифицированной, если она существует в DNS, её значение совпадает с тем, которое указал Adapty Mail, и провайдер это подтверждает. Неверифицированная запись отображается с чипом, указывающим, чего именно не хватает:

| Чип | Что означает |
| --- | --- |
| **Missing** | Записи нет в DNS. Добавьте её точно так, как указано на карточке. |
| **Wrong value** | Запись существует, но её значение отличается. Обновите его в соответствии с указанным. |
| **Differs from suggested** | На вашем корневом домене уже есть запись DMARC с другим значением. Предложение Adapty Mail не обязательно — заменяйте своё только если хотите. |
| **Provider check failed** | Провайдер отклонил запись. Проверьте значение и нажмите **Check**. |
| **Awaiting provider** | Запись корректна в DNS, но провайдер ещё не подтвердил её. Нажмите **Check**, чтобы обновить статус. |

Adapty Mail не выполняет плановые проверки для подтверждения актуальности уже верифицированных записей. Запустите проверку вручную, нажав **Check**, или перейдите в **Settings** > **DNS**.

Оставляйте записи на месте всё время, пока планируете отправлять письма — если DKIM-записи исчезнут, Amazon SES прекратит подписывать вашу почту по истечении льготного периода, и домен придётся верифицировать заново с нуля.

## 4. Укажите имя отправителя \{#set-the-sender-name\}

После верификации домена на его карточке появляется поле **Email sender name**. Adapty Mail подставляет туда название вашего проекта и отправляет письма с адреса `hello@` вашего поддомена, поэтому в подсказке поля отображается полная строка From — *Your Company &lt;hello@mail.yourapp.com&gt;*. Имя задаётся отдельно для каждого домена: если проект отправляет письма с двух доменов, нужно заполнить оба поля.

## Прогрев домена и дневные лимиты \{#warm-up-and-daily-limits\}

У новых доменов нет репутации у почтовых провайдеров вроде Gmail или Yahoo, поэтому массовая рассылка с нового домена рискует попасть в спам. Adapty Mail прогревает каждый домен самостоятельно двумя способами, которые работают одновременно. Настройка не требуется.

- **Прогревочный ящик**: Как только DNS подтверждается, Adapty Mail создаёт почтовый ящик на вашем отправляющем поддомене и передаёт его сервису прогрева, который обменивается через него обычными письмами. На карточке домена отображается текущая фаза прогрева. Прогрев не начнётся, пока не будут проверены записи [**Warmup mailbox**](#2-add-the-dns-records).
- **Дневной лимит отправки**: Ваши кампании тарифицируются отдельно от прогревочного ящика и разбиты на 20 уровней. Лимит удерживает объём отправки ниже порога, при котором новый домен помечается как спам, и повышается по мере отправки.

### Как работают уровни \{#how-tiers-work\}

Ваш домен начинает с **Уровня 1** (100 отправок/день). Лимит увеличивается на один уровень за раз, когда текущий дневной лимит превышен (учитываются как отправки, так и заблокированные попытки). Новый лимит вступает в силу на следующий день.

В первый день нового уровня лимит распределяется постепенно в течение дня, а не выдаётся сразу. Продвижение определяется только объёмом, и уровни движутся исключительно вверх: автоматического понижения не происходит. После достижения максимального уровня домен отправляет письма без дневного ограничения.

### Влияние на запуск в зависимости от размера аудитории \{#impact-on-launch-by-audience-size\}

| Размер аудитории  | Эффект при запуске                           |
| ----------------- | -------------------------------------------- |
| Менее 100 человек | Вся аудитория охватывается в первый день     |
| 100–2 000 человек | Рассылка растягивается на несколько дней     |
| 2 000+ человек    | Рассылка растягивается на 1–2 недели         |

Запустите первую кампанию сразу после завершения верификации DNS. Чем раньше вы начнёте отправку, тем быстрее домен пройдёт все уровни и достигнет максимального дневного лимита.
:::

## Доставляемость \{#deliverability\}

Для каждого домена в разделе **Settings** > **DNS** отображается **Deliverability score** из 100 баллов. Нажмите **Details**, чтобы увидеть полную картину — настройка показывает, что домен сконфигурирован, а этот показатель говорит о том, доходит ли почта до получателей.

- **Deliverability score**: Общая оценка, складывающаяся из трёх показателей ниже.
- **Bounces**: Количество возвратов и их доля. 2% — предупреждение, 5% — критично.
- **Inbox placement**: Куда реально попадают принятые письма.
- **Send tiers**: На каком этапе [прогрева](#warm-up-and-daily-limits) находится домен и каков дневной лимит отправки.

Жалобы весят куда больше, чем отказы: 0,1% отправлений — это уже предупреждение, 0,5% — критический уровень. Жалоба также немедленно [подавляет получателя](mail-suppression#delivery-failed-or-the-recipient-marked-it-as-spam).

## Несколько доменов \{#multiple-domains\}

Пока ваши домены проходят прогрев, Adapty [ограничивает](#warm-up-and-daily-limits) количество писем, которое каждый из них может отправлять в день. Поэтому использование нескольких доменов увеличивает общий объём отправки.

Adapty использует следующую логику для выбора домена, с которого будет отправлено письмо:

- **Один домен на получателя в рамках кампании.** Чтобы кампания оставалась последовательной, Adapty Mail использует один и тот же адрес электронной почты для отправки писем одному получателю. Если вы удалите этот домен или прекратите отправку с него, следующее письмо будет отправлено с самого нового домена, на котором ещё есть свободные места.
- **Более новые домены имеют приоритет.** Домен, добавленный позже, предпочтительнее более старого.
- **Для старых профилей используется ваш самый старый домен.** Все, чьи профили были созданы до 23 июля 2026 года, получают письма именно с него, какие бы домены вы ни добавили позже.

Когда все домены превышают лимит, Adapty Mail откладывает отправку письма — в разделе [Throttle](mail-suppression#throttle-temporary-delays-and-cancellations) описано, что происходит с получателем дальше.

## Остановка и возобновление отправки \{#stop-and-resume-sending\}

Чтобы приостановить домен без повторной верификации, нажмите **Stop sending** на его карточке. Карточка покажет **Sending off**, и Adapty Mail будет пропускать этот домен при выборе адреса отправки. Нажмите **Resume sending**, чтобы вернуть его в работу.

## Устранение неполадок \{#troubleshooting\}

| Проблема | Решение |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| «Enter a valid domain (e.g. example.com)» | Проверьте ввод: корневой домен с суффиксом верхнего уровня (`yourapp.com`), только ASCII, без дефисов в начале и конце. Домен с суффиксом второго уровня вида `yourapp.co.uk` не принимается. |
| «Domain does not have valid DNS records» | Корневой домен должен резолвиться. Убедитесь, что NS-записи активны, прежде чем повторить попытку. |
| «Domain is already registered to another project» | Выберите другой домен или обратитесь в поддержку, если считаете регистрацию ошибкой. |
| «This subdomain cannot be used» | Метка зарезервирована или отклонена при проверке. Выберите другую — см. [Использование пользовательских поддоменов](#use-custom-subdomains). |
| «This link subdomain cannot be used» | Поддомен ссылки подчиняется тем же правилам, что и поддомен отправки, и не может совпадать с ним — см. [Использование пользовательских поддоменов](#use-custom-subdomains). |
| «Please wait before checking again» | Делайте паузу 10 секунд между проверками вручную. Автоматический опрос продолжается в фоне. |
| Записи остаются непроверенными | Убедитесь, что они совпадают точно — без точек в конце, правильные цели CNAME, одно значение на запись. Распространение DNS может занимать до 48 часов. |
| CNAME-записи не проходят проверку в Cloudflare | Записи находятся в режиме **Proxied**. Переключите каждую в **DNS only**, затем нажмите **Check**. |
| Прогрев не начался | MX-, DKIM- и SPF-записи почтового ящика для прогрева ещё не подтверждены. Добавьте или исправьте их, затем нажмите **Check**. |
| Записи поддомена ссылки не проходят проверку | В карточке указана причина под именем хоста. Проверьте его CNAME- и TXT-записи, затем нажмите **Check** — домен не будет полностью настроен, пока этот хост не станет активным. |
| «Cannot delete: some identities are verified» | Домен был настроен до появления автоматического прогрева и не может быть удалён через дашборд. Обратитесь в поддержку. |
| Письма попадают в спам | Убедитесь, что DMARC-запись опубликована. Новым доменам нужно время на прогрев — ознакомьтесь с разделом [прогрев и дневные лимиты](#warm-up-and-daily-limits). |
| Высокий процент отказов | Убедитесь, что список аудитории содержит действительные адреса с подтверждённым согласием. В разделе [Причины остановки доставки](mail-suppression) описано, что происходит с адресом, от которого пришёл отказ. |
| Высокий процент жалоб | Удерживайте долю жалоб на спам ниже 0,1% от числа отправлений. Одна жалоба весит намного больше, чем отказ, а получатель сразу попадает в список подавления. |
