Поля ввода позволяют собирать данные от пользователей — имя, адрес электронной почты или дату рождения. Ответы сохраняются и могут использоваться в других местах флоу, например чтобы обращаться к пользователю по имени на следующем экране.

## Добавление поля ввода \{#add-an-input\}

<ZoomImage id="add-input.webp" width="400px" float="right" alt="Добавить поле ввода" />

1. Откройте панель **Add element**.
2. В категории **Forms & Quiz** нажмите **Input**.
3. Выберите тип поля ввода:
   - **Text:** Любой короткий текст.
   - **E-mail:** Адрес электронной почты с опциональной проверкой формата.
   - **Password:** Защищённый ввод текста с настраиваемыми требованиями.
   - **Number:** Числовые значения с настраиваемым форматом.
   - **Phone number:** Номера телефонов.
   - **Date:** Открывает выбор даты.
   - **Time:** Открывает выбор времени.
   - **Date & Time:** Открывает комбинированный выбор.
   - **[Number picker](builder-number-picker):** Вы задаёте минимальное и максимальное значение для колёсика. Пользователь выбирает число в этом диапазоне.

## Настройка поля ввода \{#configure-an-input\}

:::link
Подробнее о визуальных настройках — макете, стиле и видимости — читайте в разделе [Стили и оформление](builder-styling).
:::

Для всех типов полей ввода в вкладке **Design** доступны следующие настройки:

- **Type:** Переключите текстовое поле между режимами Text, E-mail, Password, Number и Phone number. Переключите выбор даты или времени между Date, Time и Date & Time.
- **Element ID:** Идентификатор для обращения к значению поля в других частях флоу. См. [Использование значений полей ввода](#use-input-values) ниже.
- **Placeholder:** Подсказка, отображаемая внутри пустого поля.
- **State:** Задайте внешний вид поля ввода в разных ситуациях. Переключайтесь между **Default**, **Active**, **Invalid** и **Disabled** и применяйте разные стили к каждому. Если ни одно из этих состояний не подходит, [добавьте пользовательское состояние](builder-element-states#add-a-custom-state): оно может зависеть от ответа, нажатия или состояния другого элемента.
- **Typography:** Стиль текста для значения, отображаемого в поле.
- **Leading and trailing icons:** Добавьте иконки внутри поля ввода. Для поля Password можно добавить только leading-иконку.

[Number picker](builder-number-picker) имеет только настройки **Element ID** и **Typography** из этого списка.

<ZoomImage id="input-settings.webp" width="700px" alt="Add input" />

Некоторые настройки характерны только для определённых типов полей ввода:

| Настройка                        | Типы полей ввода              |
|----------------------------------|-------------------------------|
| Кнопка очистки                   | Текст, E-mail                 |
| Проверка формата email           | E-mail                        |
| Иконка показа пароля             | Пароль                        |
| Редактирование требований к паролю | Пароль                      |
| Формат числа                     | Число                         |
| Формат даты/времени              | Дата, Время, Дата и время     |
| Минимальная и максимальная дата  | Дата, Дата и время            |

## Используйте входные значения \{#use-input-values\}

:::tip
Ваше приложение тоже может получать входные значения. Чтобы собирать их, [обработайте аналитический колбэк SDK](ios-flow-input). Каждый раз, когда пользователь покидает поле ввода, колбэк передаёт его значение, и ваше приложение может обработать его внутри.

Для числового выбора (Number picker) колбэк передаёт значение, когда пользователь нажимает кнопку, открывающую другой экран. Нажатие на вариант в квизе или переключение тоггла на том же экране тоже его передаёт.
:::

Каждый инпут автоматически становится переменной — никакой настройки или действия **On Submit** не требуется. Значение доступно через **Element ID** инпута, который задаётся в **Input Settings** или **Picker Settings**.

Чтобы использовать значение инпута в другом месте флоу (например, для персонализации текста, заполнения другого поля или условной навигации), вставьте переменную и выберите:

**Element > Screen > `<elementId>.value`**

:::link
Ознакомьтесь с соответствующими гайдами, чтобы понять, как использовать сохранённые значения ввода:
- [Условная навигация](onboarding-navigation-branching)
- [Переменные](onboarding-variables)
:::

## Валидация ввода \{#input-validation\}

Поведение валидации зависит от типа поля. Каждое поле, кроме числового, предоставляет переменную только для чтения типа Boolean — `<elementId>.isValid`. Она отражает, соответствует ли введённое значение правилам валидации поля. Используйте её в условных действиях или условной видимости — например, чтобы скрыть кнопку «Далее», пока формат email не будет корректным.

:::note
- Переменная `isValid` доступна только для чтения — задать её значение нельзя.
- Пустое поле всегда считается валидным.
- Для текстовых полей правила валидации отсутствуют. `textInput.isValid` всегда возвращает `True`.
:::

| Тип ввода | Поведение валидации |
|---|---|
| Текст | Встроенных правил валидации нет. |
| E-mail | Опционально. Включите **Validate email format** в панели **Design**, чтобы проверять введённое значение на соответствие формату email. |
| Номер телефона | Встроенная проверка формата номера телефона. Не настраивается в Builder — правило применяется во время выполнения. |
| Пароль | Настраивается. См. [Требования к паролю](#password-requirements) ниже. |
| Число | На основе формата. Введённое значение должно соответствовать выбранному числовому формату. См. [Числовой формат](#number-format) ниже. |
| Дата, Время, Дата и время | Встроенная. Пикер принимает только корректные значения даты или времени. |

**Invalid** [визуальное состояние](builder-styling#input-states) активируется, когда пользователь отправляет форму — например, нажимая Enter или Done на клавиатуре. До этого момента поле находится в другом состоянии, например **Active** или **Default**.

### Требования к паролю \{#password-requirements\}

Поля для ввода пароля поддерживают настраиваемые правила валидации. Нажмите **Edit password requirements** на панели **Design**, чтобы открыть редактор правил. Активные правила отображаются в виде живого списка под полем ввода — каждый пункт отмечается галочкой, как только соответствующее условие выполнено.

Доступные правила:

- **Min length** — минимальное количество символов. По умолчанию: 8.
- **Max length** — максимальное количество символов. По умолчанию: 32.
- **Uppercase letter** — хотя бы одна заглавная буква A–Z.
- **Lowercase letter** — хотя бы одна строчная буква a–z.
- **Number** — хотя бы одна цифра.
- **Special character** — хотя бы один неалфавитно-цифровой символ (например, `!@#$%`).

Пароль считается действительным только при соблюдении всех включённых правил.

### Формат числа \{#number-format\}

Выпадающий список **Format** в настройках поля **Number** определяет, как интерпретируется введённое значение:

- **Integer** — только целые числа (например, `4`).
- **Decimal (Point)** — десятичные дроби с точкой в качестве разделителя (например, `4.89`).
- **Decimal (Comma)** — десятичные дроби с запятой в качестве разделителя (например, `4,89`).

Значения, не соответствующие выбранному формату, считаются недопустимыми.

## Запуск действий по событиям ввода \{#trigger-actions-on-input-events\}

:::link
Основная статья: [Действия](onboarding-actions)
:::

Вы можете запускать действия в ответ на пользовательский ввод через панель **Interactions**:

- **On changed** — срабатывает, когда пользователь изменяет значение поля ввода. Доступно для всех типов полей.
- **On submit** — срабатывает, когда пользователь подтверждает текстовый ввод нажатием Enter или Done на клавиатуре. Для выбора даты, времени и числа этот триггер недоступен.
