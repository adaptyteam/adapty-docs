Adapty CLI позволяет настроить конфигурацию приложения полностью из командной строки. Используйте его как альтернативу [быстрому старту через дашборд](integrate-payments), если вы предпочитаете работать в терминале или с [MCP-клиентами](https://github.com/adaptyteam/adapty-cli/tree/main/skills/adapty-cli).

:::note
Подключение Adapty к App Store Connect и Google Play по-прежнему требует однократной настройки в дашборде — это описано в шаге 3.
:::

По завершении ваше приложение, уровень доступа, продукт, флоу или пейвол и плейсмент будут видны в [дашборде Adapty](https://app.adapty.io).

Если вы запускаете CLI в Claude Cowork, сначала настройте его в Claude — см. [Настройка Adapty CLI в Claude Cowork](developer-cli-cowork).

## 1. Установите CLI \{#1-install-the-cli\}

Требуется [Node.js](https://nodejs.org/en/download) 18 или выше.

Чтобы установить CLI, выполните команду:

```bash
npm install -g adapty
```

Или напрямую:

```bash
npx adapty auth login
```

## 2. Аутентификация \{#2-authenticate\}

Выполните команду входа, чтобы подключить CLI к вашему аккаунту Adapty.

```bash
adapty auth login
```

CLI открывает вкладку браузера. Сопоставьте код, отображённый в терминале, с кодом в браузере, затем нажмите **Authorize**. Терминал подтвердит завершение аутентификации.

## 3. Создайте приложение \{#3-create-your-app\}

Приложение в Adapty представляет ваше мобильное приложение. Одно приложение Adapty подключается одновременно к App Store и Google Play — вам нужно создать только одно, независимо от того, в скольких сторах вы публикуетесь.

<Tabs>
  <TabItem value="ios-android" label="iOS + Android">
    ```bash
    adapty apps create --title "My App" --platform ios --platform android --apple-bundle-id com.example.app --google-bundle-id com.example.app
    ```
  </TabItem>
  <TabItem value="ios" label="iOS only">
    ```bash
    adapty apps create --title "My App" --platform ios --apple-bundle-id com.example.app
    ```
  </TabItem>
  <TabItem value="android" label="Android only">
    ```bash
    adapty apps create --title "My App" --platform android --google-bundle-id com.example.app
    ```
  </TabItem>
</Tabs>

Команда возвращает `<app-id>`. Используйте этот ID во всех последующих командах.

:::important
Прежде чем продолжить, подключите ваше приложение к App Store Connect и Google Play в дашборде Adapty. ID продуктов из обоих сторов потребуются на шаге 5.

- [Подключить App Store Connect](app-store-connection-configuration)
- [Подключить Google Play](google-play-store-connection-configuration)
:::

## 4. Создайте уровень доступа (необязательно) \{#4-create-an-access-level-optional\}

[Уровни доступа](access-level) определяют, к чему пользователи получают доступ после покупки. Вместо того чтобы проверять, купил ли пользователь конкретный продукт, ваше приложение проверяет, есть ли у пользователя определённый уровень доступа. Это отделяет логику приложения от конкретных ID продуктов.

Уровень доступа `premium` создаётся автоматически с каждым новым приложением. **Для большинства приложений этот шаг можно пропустить.** Используйте `premium` как ID уровня доступа на шаге 5.

Выполняйте эту команду только в том случае, если разные продукты открывают разные функции для разных групп пользователей — например, если подписчик «Basic» и подписчик «Pro» получают доступ к разным частям приложения.

```bash
adapty access-levels create --app <app-id> --sdk-id "pro" --title "Pro"
```

- `--sdk-id` — идентификатор, который вы будете использовать в коде приложения для проверки доступности функции для пользователя (например, `if user.hasAccessLevel("pro")`). Если вы пропускаете этот шаг и используете уровень доступа по умолчанию, его `--sdk-id` равен `premium`.
- `--title` — отображаемое название для вашего удобства в дашборде Adapty.

Команда возвращает `<access-level-id>`.

## 5. Создайте продукт \{#5-create-a-product\}

В Adapty [продукт](product) — это всё, что ваше приложение продаёт: подписка или разовая покупка. Товары из App Store Connect и Google Play можно объединить в один продукт Adapty и управлять ими из одного места.

Вам понадобятся ID продуктов из каждого стора: Apple product ID из App Store Connect, а также Android product ID и base plan ID из Google Play Console. Подробнее о том, где их найти, см. в разделе [Продукты](quickstart-products).

Если вы пропустили шаг 4, используйте `default_access_level.id`, возвращённый командой `apps create` на шаге 3, в качестве `<access-level-id>`.

:::important
ID продуктов стора, которые вы привязываете здесь, нельзя изменить после создания. Чтобы использовать другие ID продуктов стора, создайте новый продукт.
:::

<Tabs>
  <TabItem value="ios-android" label="iOS + Android">
    ```bash
    adapty products create --app <app-id> --title "My Product" --access-level-id <access-level-id> --period monthly --ios-product-id <your.apple.id> --android-product-id <your.google.id> --android-base-plan-id <your.base-plan.id>
    ```
  </TabItem>
  <TabItem value="ios" label="iOS only">
    ```bash
    adapty products create --app <app-id> --title "My Product" --access-level-id <access-level-id> --period monthly --ios-product-id <your.apple.id>
    ```
  </TabItem>
  <TabItem value="android" label="Android only">
    ```bash
    adapty products create --app <app-id> --title "My Product" --access-level-id <access-level-id> --period monthly --android-product-id <your.google.id> --android-base-plan-id <your.base-plan.id>
    ```
  </TabItem>
</Tabs>

Команда возвращает `<product-id>`.

Если вы также продаёте этот продукт в интернете через Stripe или Paddle, добавьте соответствующие ID в ту же команду. См. [products create](developer-cli-reference#adapty-products-create) в справочнике команд.

## 6. Создайте флоу или пейвол \{#6-create-a-flow-or-paywall\}

Каждый продукт должен находиться внутри флоу или пейвола, прежде чем он сможет появиться в вашем приложении. Выберите один из вариантов:

- **Флоу** — это экран или последовательность экранов, которые вы проектируете в визуальном редакторе [Flow & Paywall Builder](adapty-flow-builder) и которые Adapty SDK отображает нативно: экран пейвола, онбординг, квиз. Выбирайте флоу, если хотите, чтобы Adapty отображал экран покупки. Для флоу требуется Adapty SDK 4.0 или выше.
- **Пейвол** — это набор продуктов без прикреплённого дизайна. Выбирайте пейвол, если вы отображаете экран покупки в собственном коде приложения и вам нужно только, чтобы Adapty передавал продукты, опционально с [Remote Config](customize-paywall-with-remote-config).

Плейсмент обслуживает один тип контента, поэтому определитесь до шага 7.

### 6a. Создайте флоу \{#6a-create-a-flow\}

CLI создаёт запись флоу. Его экраны хранятся в конфигурации — JSON-документе, который CLI не генерирует. Чтобы создать конфигурацию из терминала, используйте [скилл flow-generator](flow-generator-skill), который управляет CLI за вас.

Создайте флоу:

```bash
adapty flows create --app <app-id> --name "Onboarding"
```

Команда возвращает `<flow-id>`.

Создайте его экраны с помощью [скилла flow-generator](flow-generator-skill) или в [Flow & Paywall Builder](adapty-flow-builder). В любом случае результатом будет сохранённый черновик, который пользователи пока не видят.

Опубликуйте флоу:

```bash
adapty flows publish --app <app-id> <flow-id>
```

Команда запрашивает подтверждение. Публикация выполняется в фоновом режиме, поэтому проверяйте статус с помощью `adapty flows get --app <app-id> <flow-id>` до тех пор, пока не появится значение `published`. При статусе `publication_failed` команда [`flows config get`](developer-cli-reference#adapty-flows-config-get) сообщит о причине. Плейсмент принимает только опубликованный флоу.

### 6b. Создайте пейвол \{#6b-create-a-paywall\}

[Пейвол](paywalls) — это контейнер, в котором хранятся ваши продукты.

:::important
После привязки пейвола к плейсменту его продукты нельзя изменить. Чтобы использовать другие продукты, создайте новый пейвол и обновите плейсмент так, чтобы он указывал на него.
:::

<Tabs>
  <TabItem value="single" label="Один продукт">
    ```bash
    adapty paywalls create --app <app-id> --title "My Paywall" --product-id <product-id>
    ```
  </TabItem>
  <TabItem value="multiple" label="Несколько продуктов">
    ```bash
    adapty paywalls create --app <app-id> --title "My Paywall" --product-id <product-id-1> --product-id <product-id-2>
    ```
  </TabItem>
</Tabs>

Команда возвращает `<paywall-id>`.

## 7. Создайте плейсмент \{#7-create-a-placement\}

[Плейсмент](placements) — это точка в вашем приложении, где отображается флоу или пейвол. Единственное, что вы жёстко задаёте в коде приложения, — это ID плейсмента. Всё остальное — какой флоу или пейвол показывать и каким пользователям — управляется в дашборде без выпуска новой версии приложения.

`--developer-id` — это строка, на которую вы будете ссылаться в коде приложения, когда спрашиваете Adapty, что показать в данной точке. Выбирайте что-то описывающее расположение, например `"main"`, `"onboarding"` или `"settings"`.

<Tabs>
  <TabItem value="flow" label="Flow">
    ```bash
    adapty placements create --app <app-id> --title "Onboarding" --developer-id "onboarding" --audiences '[{"content_type":"flow","segment_ids":[],"flow_id":"<flow-id>","priority":0}]'
    ```
  </TabItem>
  <TabItem value="paywall" label="Paywall">
    ```bash
    adapty placements create --app <app-id> --title "Main" --developer-id "main" --audiences '[{"content_type":"paywall","segment_ids":[],"paywall_id":"<paywall-id>","priority":0}]'
    ```
  </TabItem>
</Tabs>

Флаг `--audiences` определяет, какой флоу или пейвол показывается каким пользователям. Приведённые выше примеры задают единую аудиторию по умолчанию: все пользователи в этом плейсменте видят одинаковый контент. Плейсмент обслуживает один тип контента, поэтому каждая запись аудитории должна содержать одинаковый `content_type`. Для таргетинга по сегментам см. раздел [Формат audiences](developer-cli-reference#audiences-shape) в справочнике команд.

## Что дальше \{#whats-next\}

Все сущности теперь видны в [дашборде Adapty](https://app.adapty.io). Следующие шаги:

- Изменить флоу позже — опишите изменение [скиллу flow-generator](flow-generator-skill) или откройте флоу в [Flow & Paywall Builder](adapty-flow-builder).
- Отобразить пейвол в приложении — [получите пейвол и его продукты](fetch-paywalls-and-products) с помощью SDK и создайте экран в собственном коде.
- [Интегрировать Adapty SDK](quickstart-sdk) — добавьте SDK в приложение для получения и отображения плейсмента.
- Направить разные [сегменты](segments) пользователей к разным флоу или пейволам — см. [`placements update`](developer-cli-reference#adapty-placements-update) и [`segments list`](developer-cli-reference#adapty-segments-list) в справочнике команд.
