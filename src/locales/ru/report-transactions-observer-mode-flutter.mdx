<SDKv4>

В режиме Observer Adapty SDK не может самостоятельно отслеживать покупки, совершённые через вашу существующую систему покупок. Вам нужно сообщать о транзакциях из вашего стора. Настройте это **до** релиза приложения, чтобы избежать ошибок в аналитике.

Используйте `reportTransaction`, чтобы явно сообщать Adapty о каждой транзакции.

:::warning

**Не пропускайте отчёты о транзакциях!**
Если вы не вызываете `reportTransaction`, Adapty не распознает транзакцию, она не появится в аналитике и не будет отправлена в интеграции.

:::

Если вы используете флоу и пейволы Adapty, передавайте `variationId` при регистрации транзакции. Это свяжет покупку с флоу или пейволом, который её инициировал, и обеспечит точную аналитику.

:::warning
- На Android используйте Adapty Flutter SDK 4.4.0 или более позднюю версию. Более ранние версии могут не отправлять `variationId` в Adapty, из-за чего покупка не будет привязана к флоу.
- Передавайте `paywallVariationId` того `AdaptyPaywallProduct`, который купил пользователь, а не `AdaptyFlow.variationId`. Собственный variation ID флоу не связывает покупку с флоу.
:::

```dart showLineNumbers
try {
    // every time when calling transaction.finish()
    await Adapty().reportTransaction(
        transactionId: "YOUR_TRANSACTION_ID",
        variationId: "PAYWALL_VARIATION_ID", // optional
    );
} on AdaptyError catch (adaptyError) {
    // handle the error
} catch (e) {
    // handle the error
}
```

Параметры:

| Параметр     | Наличие | Описание                                                  |
| ------------- | -------- | ------------------------------------------------------------ |
| transactionId | required | <ul><li> Для iOS: идентификатор транзакции.</li><li> Для Android: строковый идентификатор `purchase.getOrderId` покупки, где покупка — это экземпляр класса [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) из библиотеки биллинга.</li></ul> |
| variationId   | optional | Строковый идентификатор варианта. Передайте `paywallVariationId` продукта `AdaptyPaywallProduct`, который купил пользователь. Это то же значение, что и `variationId` объекта [AdaptyFlowPaywall](https://pub.dev/documentation/adapty_flutter/latest/adapty_flutter/AdaptyFlowPaywall-class.html), содержащего этот продукт. |
| appleJwsTransaction | optional | Только для iOS, SDK 4.3.0 и выше. Подписанная транзакция StoreKit 2: `jwsRepresentation` результата её верификации для той же транзакции, что и `transactionId`. SDK передаёт её в Adapty без изменений. Android игнорирует этот параметр. |

На iOS, если ваша система покупок предоставляет транзакцию StoreKit 2, передайте её JWS-представление в `appleJwsTransaction`:

```dart showLineNumbers
await Adapty().reportTransaction(
    transactionId: "YOUR_TRANSACTION_ID",
    variationId: "PAYWALL_VARIATION_ID", // optional
    appleJwsTransaction: jwsRepresentation, // iOS only, optional
);
```

В режиме Observer Mode SDK не может самостоятельно отслеживать покупки, совершённые через вашу существующую систему покупок. Вам нужно сообщать о транзакциях из вашего стора или восстанавливать их. Крайне важно настроить это **до** релиза приложения, чтобы избежать ошибок в аналитике.

Используйте `reportTransaction` на обеих платформах, чтобы явно сообщать о каждой транзакции, и `restorePurchases` на Android как дополнительный шаг для того, чтобы Adapty её распознала.

:::warning

**Не пропускайте отчёт о транзакции и восстановление покупок!**
Если вы не вызываете эти методы, Adapty не распознает транзакцию — она не появится в аналитике и не будет отправлена в интеграции.

:::

Если вы используете флоу и пейволы Adapty, передавайте `variationId` при отчёте о транзакции. Это связывает покупку с флоу или пейволом, который её инициировал, и обеспечивает корректную аналитику.

```dart showLineNumbers
// every time when calling transaction.finish()
if (Platform.isAndroid) {
    try {
        await Adapty().restorePurchases();
    } on AdaptyError catch (adaptyError) {
        // handle the error
    } catch (e) {
    }
}

try {
    // every time when calling transaction.finish()
    await Adapty().reportTransaction(
        transactionId: "YOUR_TRANSACTION_ID",
        variationId: "PAYWALL_VARIATION_ID", // optional
    );
} on AdaptyError catch (adaptyError) {
    // handle the error
} catch (e) {
    // handle the error
}
```

Параметры:

| Параметр      | Наличие  | Описание                                                     |
| ------------- | -------- | ------------------------------------------------------------ |
| transactionId | обязательный | <ul><li> Для iOS, StoreKit 1: объект [SKPaymentTransaction](https://developer.apple.com/documentation/storekit/skpaymenttransaction).</li><li> Для iOS, StoreKit 2: объект [Transaction](https://developer.apple.com/documentation/storekit/transaction).</li><li> Для Android: строковый идентификатор (purchase.getOrderId покупки, где покупка является экземпляром класса [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) библиотеки биллинга).</li></ul> |
| variationId   | необязательный | Строковый идентификатор варианта. Его можно получить через свойство `variationId` объекта [AdaptyPaywall](https://pub.dev/documentation/adapty_flutter/3.17.2/adapty_flutter/AdaptyPaywall-class.html). |

**Привязка флоу и пейволов к транзакциям**

Adapty SDK не может определить источник покупок, так как их обрабатываете вы. Поэтому, если вы планируете использовать флоу, пейволы и/или A/B-тесты в режиме Observer, вам нужно в коде мобильного приложения связать транзакцию из стора с соответствующим флоу или пейволом. Это важно сделать правильно до релиза приложения, иначе это приведёт к ошибкам в аналитике.

```dart
final transactionId = transaction.transactionIdentifier
final variationId = paywall.variationId

try {
  await Adapty().setVariationId('transactionId', variationId);
} on AdaptyError catch (adaptyError) {
  // handle the error
} catch (e) {
}
```
