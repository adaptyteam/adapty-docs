<SDKv4>

Если вы создали флоу или пейвол в старом Paywall Builder, вам не нужно беспокоиться о том, как отрендерить его в коде мобильного приложения — флоу уже содержит всё необходимое: и то, что должно отображаться, и то, как именно это должно выглядеть.

Прежде чем начать, убедитесь, что:

1. Вы создали [флоу](paywall-builder-templates) или [пейвол](create-paywall).
2. Вы добавили его в [плейсмент](placements).
3. Вы [получили флоу и подготовили представление](capacitor-get-pb-paywalls).

   <CapacitorFlowsRequireIos16 />

:::warning

Этот гайд предназначен **только для флоу и пейволов, отображаемых Adapty**, для которых требуется SDK v4.0 или более поздней версии. Процесс отображения флоу отличается для кастомных пейволов.

- Чтобы отобразить кастомные пейволы, см. [Отображение кастомных пейволов](present-remote-config-paywalls-capacitor).

:::

Чтобы отобразить флоу или пейвол как отдельный экран, вызовите метод `view.present()` на объекте `view`, созданном методом [`createFlowView`](capacitor-get-pb-paywalls#fetch-the-view-configuration). По умолчанию закрытый `view` уничтожается. Чтобы показать флоу снова, вызовите `createFlowView` ещё раз для создания нового экземпляра `view` или [сохраните закрытый флоу](#keep-a-closed-flow-for-later) при закрытии.

:::warning
Повторное использование уничтоженного `view` приведёт к ошибке.
:::

```typescript showLineNumbers

const view = await createFlowView(flow);

// Optional: handle flow events (close, purchase, restore, etc)
// await view.setEventHandlers({ ... });

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

:::important
Повторный вызов `setEventHandlers` переопределит обработчики, которые вы передаёте, заменив как обработчики по умолчанию, так и ранее установленные обработчики для указанных событий.
:::

## Настройка стиля представления на iOS \{#configure-ios-presentation-style\}

Настройте способ отображения флоу на iOS, передав параметр `iosPresentationStyle` в метод `present()`. Параметр принимает значения `'full_screen'` (по умолчанию) или `'page_sheet'`. На Android флоу всегда отображается на весь экран внутри Activity вашего приложения.

```typescript showLineNumbers
try {
  await view.present({ iosPresentationStyle: 'page_sheet' });
} catch (error) {
  // handle the error
}
```

## Сохраните закрытый флоу для дальнейшего использования \{#keep-a-closed-flow-for-later\}

:::info
Опция `destroy` и метод `destroy()` доступны начиная с SDK версии 4.3.0.
:::

Сохраняйте флоу, если пользователь может вскоре снова его открыть — например, пейвол за кнопкой на экране настроек — чтобы он открывался мгновенно, без повторной загрузки, и с того места, где пользователь остановился.

По умолчанию `view.dismiss()` закрывает флоу и уничтожает его нативный вид, поэтому повторно показать `view` не получится. Чтобы иметь возможность открыть тот же флоу позже, передайте `destroy: false`. Следующий вызов `present()` откроет флоу на том экране, где пользователь его закрыл, с тем же состоянием, а обработчики событий останутся привязанными:

```typescript showLineNumbers
// Close the flow and keep its native view in memory
await view.dismiss({ destroy: false });

// Later: open the flow again on the same screen
await view.present();
```

Нативное представление остаётся в памяти, пока вы его не освободите. Когда флоу больше не нужен, вызовите `destroy()`:

```typescript showLineNumbers
await view.dismiss({ destroy: false });
// ...
await view.destroy();
```

`destroy()` сначала скрывает представление, если оно ещё отображается на экране, а затем очищает его обработчики событий. Вызывайте его только для представления, закрытого с `destroy: false`: обычный `dismiss()` освобождает представление самостоятельно, а вызов `destroy()` после него завершится ошибкой.

Освобождайте удерживаемое представление, когда уничтожается владеющий им компонент — в `ngOnDestroy` у Angular, в функции очистки `useEffect` у React или в `onUnmounted` у Vue. Иначе нативное представление останется в памяти до конца сессии. Перехватывайте ошибку: представление может быть уже освобождено, например если обработчик события вернул `true`.

```typescript showLineNumbers
// For example, in a React useEffect cleanup
return () => {
  view.destroy().catch(() => {
    // the view was already released
  });
};
```

Обработчик события, возвращающий `true`, закрывает флоу обычным `dismiss()`, который уничтожает нативный вид, даже если вы его сохранили ранее. Стандартные обработчики `onCloseButtonPress` и `onError` возвращают `true`. То же самое относится к любому обработчику, который вы настроили на возврат `true`, например `onAndroidSystemBack`. Чтобы сохранить флоу при закрытии пользователем, закройте флоу самостоятельно и верните `false`:

```typescript showLineNumbers
await view.setEventHandlers({
  onCloseButtonPress() {
    view.dismiss({ destroy: false }).catch(error => {
      // handle the error
    });
    return false;
  },
});
```

## Используйте таймер, управляемый разработчиком \{#use-developer-defined-timer\}

Используйте этот раздел для таймера с поведением **Developer defined** в Flow & Paywall Builder. В билдере каждый такой таймер имеет **Timer ID** (см. [Позвольте вашему приложению задать дату окончания](flow-timer#let-your-app-set-the-end-date)), а ваше приложение устанавливает для него дату окончания. Используйте в коде тот же Timer ID, что и в билдере, символ в символ, включая регистр букв и пробелы. Если идентификаторы различаются, таймер не получит дату окончания от вашего приложения.

Чтобы задать даты окончания, передайте параметр `customTimers` в `createFlowView`: объект, который сопоставляет каждый Timer ID с `Date` — датой окончания таймера.

```typescript showLineNumbers

const customTimers = {
  CUSTOM_TIMER_NY: new Date(new Date().getFullYear() + 1, 0, 1), // next New Year's Day
};

try {
  const view = await createFlowView(flow, { customTimers });
  await view.present();
} catch (error) {
  // handle the error
}
```

В этом примере `CUSTOM_TIMER_NY` — это Timer ID таймера типа **Developer defined** в билдере. Таймер показывает время до следующего Нового года, например `13d 09h 03m 34s`.

SDK считывает `customTimers` один раз при создании вью, поэтому дата, вычисленная динамически (например, «через 6 часов»), отсчитывается именно с этого момента. Если дата уже в прошлом, таймер сразу показывает ноль и срабатывает триггер **On timer end**. Если в `customTimers` нет ключа для данного Timer ID, таймер отсчитывает один час с момента открытия экрана.

## Показ диалогового окна \{#show-dialog\}

Используйте этот метод вместо нативных диалогов-алертов, когда на Android отображается флоу. На Android обычные алерты появляются за флоу и становятся невидимы для пользователей. Этот метод гарантирует корректное отображение диалогового окна поверх флоу на всех платформах.

```typescript showLineNumbers
try {
  const action = await view.showDialog({
    title: 'Close paywall?',
    content: 'You will lose access to exclusive offers.',
    primaryActionTitle: 'Stay',
    secondaryActionTitle: 'Close',
  });

  if (action === 'secondary') {
    // User confirmed - close the flow
    await view.dismiss();
  }
  // If primary - do nothing, user stays
} catch (error) {
  // handle error
}
```

## Отправка сообщений во флоу \{#send-messages-to-a-flow\}

Метод `sendAppMessage` объекта представления флоу отправляет во флоу сообщение в виде JSON-объекта. Этот метод зарезервирован для будущих возможностей Flow & Paywall Builder. Флоу игнорируют такие сообщения, поэтому вызывать этот метод не нужно.

## Замена одной подписки на другую \{#replace-one-subscription-with-another\}

Когда пользователь пытается купить новую подписку при наличии активной на Android, вы можете управлять тем, как должна обрабатываться новая покупка, передав параметры обновления подписки при создании представления флоу. Чтобы заменить текущую подписку на новую, используйте `productPurchaseParams` в `createFlowView` с параметрами `oldSubVendorProductId` и `prorationMode`.

```typescript showLineNumbers

const productPurchaseParams = flow.paywalls
  .flatMap((paywall) => paywall.productIdentifiers)
  .map((productId) => {
    const params: MakePurchaseParamsInput = {};
    if (Capacitor.getPlatform() === 'android') {
      params.android = {
        subscriptionUpdateParams: {
          oldSubVendorProductId: 'PRODUCT_ID_OF_THE_CURRENT_ACTIVE_SUBSCRIPTION',
          prorationMode: 'with_time_proration',
        },
      };
    }
    return { productId, params };
  });

const view = await createFlowView(flow, { productPurchaseParams });
```

<SDKv3>

Если вы настроили пейвол с помощью Paywall Builder, вам не нужно беспокоиться о его рендеринге в коде мобильного приложения для отображения пользователю. Такой пейвол содержит как то, что должно быть показано, так и то, как это должно быть показано.

:::warning
Этот гайд предназначен только для пейволов, созданных в старом Paywall Builder. Для отображения кастомных пейволов см. [Отображение кастомных пейволов](present-remote-config-paywalls-capacitor).
:::

Чтобы отобразить пейвол, используйте метод `view.present()` на объекте `view`, созданном методом [`createPaywallView`](capacitor-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder). Каждый `view` можно использовать только один раз. Если нужно показать пейвол повторно, вызовите `createPaywallView` ещё раз, чтобы создать новый экземпляр `view`.

:::warning

Повторное использование одного и того же `view` без его пересоздания может привести к ошибке.
:::

```typescript showLineNumbers

const view = await createPaywallView(paywall);

view.setEventHandlers({
  onUrlPress(url) {
    window.open(url, '_blank');
    return false;
  },
});

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

## Использование таймера, заданного разработчиком \{#use-developer-defined-timer\}

Чтобы использовать таймеры, заданные разработчиком, в своём мобильном приложении, укажите `timerId` — в данном примере `CUSTOM_TIMER_NY`, **Timer ID** таймера, который вы задали в дашборде Adapty. Это гарантирует, что приложение будет динамически обновлять таймер с правильным значением — например, `13d 09h 03m 34s` (рассчитывается как время окончания таймера, например Новый год, минус текущее время).

```typescript showLineNumbers
const customTimers = { 'CUSTOM_TIMER_NY': new Date(2025, 0, 1) };

const view = await createPaywallView(paywall, { customTimers });
```

В этом примере `CUSTOM_TIMER_NY` — это **Timer ID** таймера, заданного разработчиком в дашборде Adapty. Таймер обеспечивает динамическое обновление значения в приложении — например, `13d 09h 03m 34s` (вычисляется как разница между временем окончания таймера, например Новым годом, и текущим временем).
