В каждом профиле пользователя в [Profiles/CRM](profiles-crm) отображается баланс виртуальной валюты и история всех изменений.

## Просмотр балансов в профиле пользователя \{#view-balances-in-a-user-profile\}

<ZoomImage id="virtual-currency-balance.webp" width="300px" alt="Страница профиля пользователя с карточкой виртуальной валюты, где перечислены балансы пользователя" float="right" />

Откройте [профиль](https://app.adapty.io/profiles/users) пользователя. Карточка **Virtual currency** отображает все валюты, которыми владеет пользователь.

Каждая строка содержит:

- **Код** валюты, например `COINS`.
- Текущий **баланс** в виде целого числа.

Балансы обновляются по мере того, как пользователь зарабатывает, тратит или получает кредиты. Баланс не может опуститься ниже 0: транзакция, пытающаяся потратить больше, чем есть у пользователя, завершается ошибкой `insufficient_balance` и ничего не меняет. У профиля без балансов отображается пустая карточка.

Чтобы считать баланс из собственного кода, вызовите [List virtual currency balances](api-adapty/operations/listVirtualCurrencyBalances) в серверном API.

## Просмотр изменений баланса в истории событий \{#review-balance-changes-in-the-event-history\}

Каждое изменение баланса отображается в истории событий профиля — сначала самые новые. Каждая запись содержит название изменения и список затронутых валют.

Adapty называет каждую запись по тому, что изменило баланс:

- **Начисление виртуальной валюты**: Покупка, продление или начало пробного периода привели к начислению кредитов.
- **Истечение виртуальной валюты**: Истекающие кредиты сбрасываются в конце расчётного периода или при завершении подписки.
- **Транзакция виртуальной валюты**: Серверная API [транзакция](api-adapty/operations/createVirtualCurrencyTransaction), отправленная без `operation`.

Серверная API транзакция, отправленная с `operation`, получает название по этой операции:

| `operation` | Название записи |
|---|---|
| `top_up` | Виртуальная валюта зачислена |
| `refund` | Виртуальная валюта отозвана |
| `spend` | Виртуальная валюта списана |
| `spend_reversal` | Списание виртуальной валюты отменено |
| `reward` | Виртуальная валюта начислена в награду |
| `reward_reversal` | Начисление виртуальной валюты в награду отменено |
| `exchange` | Виртуальная валюта обменяна |
| `expiry` | Виртуальная валюта истекла |
| `migration` | Виртуальная валюта мигрирована |
| `adjustment` | Виртуальная валюта скорректирована |

Иконка рядом с записью соответствует знаку суммы, а не типу операции: иконка зачисления, списания или нейтральная — когда одна транзакция одновременно зачисляет и списывает.

Каждая запись содержит информацию по каждой валюте, баланс которой изменился:

- **Виртуальная валюта**: название и код валюты, например `Gold Coins (COINS)`.
- **Сумма**: изменение со знаком — положительное при зачислении, отрицательное при списании.
- **Баланс после**: баланс валюты после применения изменения.

Одно событие может изменять несколько валют одновременно — например, одна [транзакция](api-adapty/operations/createVirtualCurrencyTransaction) может списывать одну валюту и зачислять другую для конвертации между ними.

### Детали транзакции \{#transaction-details\}

Чтобы узнать, за что было изменено сальдо, разверните блок **Details** под записью. В нём отображаются только поля, у которых есть значение:

<ZoomImage id="virtual-currency-transaction-details.webp" width="500px" alt="A Virtual currency debited entry in the user history with the Details block expanded, showing the operation, feature, reference ID, customer placement ID, and metadata" />

- **Store**: Стор, из которого получены кредиты.
- **Operation**: Поле `operation` транзакции — то, что прислал ваш бэкенд или установил Adapty.
- **Feature**: На что потрачены или за что начислены кредиты — из поля `feature`.
- **Reference ID**: ID связанного объекта в вашей системе, например генерации — из поля `reference_id`.
- **Customer placement ID**: Экран или место в приложении, где произошла транзакция — из поля `customer_placement_id`. Это ваш собственный ID, а не [плейсмент](placements) Adapty.
- **Sandbox**: **Yes** для тестовой транзакции, отправленной с `is_sandbox: true`.
- **Metadata**: Пары ключ-значение, переданные вашим бэкендом в `metadata`. Метаданные отображаются только для транзакций через server-side API.

Ваш бэкенд задаёт эти поля при [создании транзакции](api-adapty/operations/createVirtualCurrencyTransaction). Транзакции, записанные до того, как Adapty начал хранить эти поля, содержат меньше данных или вовсе не имеют блока **Details**.

## Балансы, профили и устройства \{#balances-profiles-and-devices\}

Баланс всегда принадлежит ровно одному [профилю](profiles-crm) и никогда не переходит к другому. Adapty не делится балансами между профилями и не переносит их — в отличие от возможности [делиться уровнями доступа между аккаунтами](profiles-crm#sharing-paid-access-between-user-accounts).

На практике это означает:

- **Идентифицированные пользователи**: пользовательский ID всегда связан с одним и тем же профилем, поэтому пользователь видит одинаковый баланс на всех устройствах, где выполнен вход, и сохраняет его после переустановки приложения.
- **Анонимные пользователи**: анонимный профиль может накапливать и тратить кредиты, но привязан к одной установке приложения на одном устройстве. Если тот же пользователь переустановит приложение или откроет его на другом устройстве без входа в систему, Adapty создаст новый анонимный профиль с нулевым балансом. Кредиты останутся на предыдущем профиле, к которому пользователь больше не сможет получить доступ.

Чтобы виртуальная валюта работала корректно на всех устройствах и после переустановки, необходимо идентифицировать пользователей. Это можно сделать в коде приложения через SDK (см. [Идентификация пользователей](ios-quickstart-identify) в quickstart-гайде) или со стороны бэкенда через [серверный API](getting-started-with-server-side-api).

Позднее определение пользователя имеет свою особенность: если пользователь получает кредиты анонимно, а затем входит с customer user ID, который уже принадлежит другому профилю, устройство переключится на тот профиль с его балансом. Кредиты, накопленные анонимно, останутся на старом профиле и станут недоступны. Если customer user ID новый, он привязывается к текущему профилю, и пользователь сохраняет баланс. Для надёжности идентифицируйте пользователей до того, как они смогут зарабатывать или покупать кредиты.

В вызовах [серверного API](getting-started-with-server-side-api) укажите профиль с помощью заголовка `adapty-profile-id` или `adapty-customer-user-id` — оба указывают на один и тот же профиль. Для анонимных профилей используйте `adapty-profile-id`.
