Подключите ваш аккаунт Stripe к Adapty Attribution, чтобы связывать покупки в вашей веб-воронке с рекламными кампаниями, которые их привлекли. После подключения покупки, продления, возвраты и чарджбэки из Stripe отображаются в аналитике Adapty Attribution, а события конверсий можно отправлять обратно в рекламные сети для оптимизации кампаний.

## Как это работает \{#how-it-works\}

1. [Веб-пиксель Adapty](ua-web-pixel) назначает каждому посетителю воронки идентификатор клика и захватывает данные об объявлении из URL посадочной страницы.
2. При оформлении заказа ваша воронка прикрепляет идентификатор клика к транзакции Stripe.
3. Adapty получает транзакцию через вебхук, который создаётся в вашем аккаунте Stripe, и сопоставляет её с кликом по объявлению.

:::note
Для веб-покупок нет события установки приложения, поэтому Adapty использует дату первого списания по подписке в качестве даты когорты.
:::

## Прежде чем начать \{#before-you-start\}

[Настройте веб-пиксель Adapty](ua-web-pixel) на своей воронке. Без пикселя нет идентификатора клика для привязки, и транзакции не смогут быть атрибуции к рекламе.

## Шаг 1. Передайте click ID при оформлении платежа \{#step-1-attach-the-click-id-at-checkout\}

Когда вы создаёте транзакцию, считайте click ID и добавьте его в `metadata` Stripe под ключом `adpt_click_id`:

```js
const adptClickId = window.adaptyPixel.getClickId();
```

Значение должно попасть в **PaymentIntent** для разовых платежей или в **Subscription** для регулярных — именно эти объекты читает Adapty. Если вы создаёте их напрямую:

```js
metadata: { adpt_click_id: adptClickId }
```

Если вы используете Stripe Checkout, задавайте метаданные во вложенных объектах. Метаданные самой Checkout Session не копируются в PaymentIntent или Subscription, поэтому click ID, указанный там, никогда не попадёт в Adapty:

```js
stripe.checkout.sessions.create({
  // ...
  payment_intent_data: { metadata: { adpt_click_id: adptClickId } }, // one-off payments
  subscription_data:   { metadata: { adpt_click_id: adptClickId } }, // subscriptions
})
```

:::warning
Задавайте метаданные при создании PaymentIntent, а не обновляя их после. Stripe копирует метаданные на платёж в момент его создания, поэтому click_id, добавленный позже, никогда не попадёт в Adapty.
:::

`click_id` — это короткий случайный идентификатор, а не секрет и не персональные данные. Он виден в вашем дашборде Stripe, что является ожидаемым поведением.

## Шаг 2. Подключите аккаунт Stripe \{#step-2-connect-your-stripe-account\}

Сначала создайте ключ в Stripe. В дашборде Stripe перейдите в **Developers → API keys** и создайте ограниченный ключ со следующими правами:

| Ресурс | Доступ |
|---|---|
| Charges | Read |
| Refunds | Read |
| Invoices | Read |
| Balance transactions | Read |
| Disputes | Read |
| Webhook endpoints | Write |

Разрешение на запись для вебхук-эндпоинтов позволяет Adapty создать вебхук для передачи платёжных данных — ничего настраивать вручную в Stripe не нужно. Всё остальное доступно только на чтение: Adapty никогда не изменяет ваши платёжные данные. Ключ без необходимого разрешения будет отклонён при подключении с указанием недостающего разрешения.

:::warning
Используйте боевой ключ. Adapty отбрасывает тестовые платежи по мере их поступления, поэтому тестовый ключ (`rk_test_...`) успешно подключится и будет отображаться как **Valid**, однако данные так и не появятся. Чтобы проверить интеграцию, подключите боевой ключ и совершите реальную покупку.
:::

Затем добавьте ключ в Adapty:

1. В Adapty Attribution перейдите в [**Integrations > Stripe**](https://app.adapty.io/ua/integrations/stripe).
2. Вставьте ключ в поле **API key**. При необходимости укажите **Name**, чтобы различать аккаунты — по умолчанию Adapty использует последние 4 символа ключа.
3. Нажмите **Connect**.

<ZoomImage id="ua-stripe-connect.webp" width="500px" alt="Форма подключения аккаунта Stripe с полями API key и Name на странице интеграции со Stripe в Adapty Attribution" />

Подключённый аккаунт появится в таблице с указанием среды, статуса ключа и состояния вебхука. Подключение действует для приложения, которое вы настраиваете. Чтобы получать платежи того же Stripe-аккаунта в другом приложении, добавьте туда тот же ключ.

Adapty импортирует транзакции начиная с момента подключения аккаунта. Чтобы загрузить более ранние транзакции, напишите нам на [support@adapty.io](mailto:support@adapty.io).

## Проверьте интеграцию \{#verify-the-integration\}

Совершите реальную покупку через свою воронку — Adapty отбрасывает покупки в тестовом режиме. Покупка должна появиться в [аналитике атрибуции Adapty](ua-analytics) в течение нескольких часов. Если визит был получен через рекламу с [тегированными URL](ua-web-pixel), покупка будет атрибутирована соответствующей кампании, группе объявлений и объявлению; в противном случае она засчитывается как органическая.

## Отправка событий конверсии в рекламную сеть \{#send-conversion-events-to-the-ad-network\}

Атрибутированные веб-покупки следуют той же схеме маппинга событий, что и остальная часть кампании: события, которые вы включаете в разделе **Events names** в настройках кампании, отправляются обратно в пиксель, связанный с кампанией. Подробнее о настройке маппинга — в разделах [Meta Ads](ua-facebook) и [TikTok for Business](ua-tiktok).
