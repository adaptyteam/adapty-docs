Категория **Progress** предоставляет два типа элементов — один для пошагового прогресса по многоэкранному флоу, второй для индикаторов занятости на месте.

## Индикаторы прогресса \{#progress-indicators\}

<ZoomImage id="builder-progress-indicator.webp" width="700px" alt="Индикатор прогресса в верхней части экрана с открытой панелью настроек" />

### Стили индикатора \{#indicator-styles\}

<ZoomImage id="flow-indicators.webp" width="300px" alt="Варианты индикатора прогресса" float="right" />

Элемент **Progress** показывает, на каком экране многошагового флоу находится пользователь. Категория предоставляет три визуальных варианта:

- **Linear** — Одна полоса, которая заполняется по мере продвижения пользователя.
- **Segmented** — Отдельные полосы для каждого шага, заполняющиеся одна за другой.
- **Connectors** — Подписанные круги, соединённые линиями (например, Шаг 1, Шаг 2, Шаг 3 по порядку).

### Сопоставление шагов с экранами \{#match-steps-to-screens\}

<ZoomImage id="builder-progress-indicator-settings.webp" width="280px" float="right" alt="Панель настроек индикатора прогресса с переключателем вариантов, тоглом «One segment per screen» и выпадающим списком Screens" />

По умолчанию индикатор прогресса отслеживает каждый экран во флоу. Чтобы ограничить его подмножеством, выберите нужные экраны в выпадающем списке **Screens**. Либо откройте экран, который хотите исключить, и снимите флажок **Include screen in progress indicator**.

Отключите тогл **One segment per screen**, если вам нужен более точный контроль над количеством шагов.

:::warning
Позиция шага следует за списком экранов, а не за реальным порядком, в котором их видит пользователь. В нелинейных флоу отображаемый шаг индикатора может перескакивать вперёд или возвращаться назад.
:::

### Состояния шагов \{#step-states\}

<ZoomImage id="builder-progress-indicator-step-settings.webp" width="280px" float="right" alt="Панель настроек на уровне шага с полями ID, Screens и вкладками состояний Completed/Current/Upcoming" />

У каждого шага три состояния — **Completed**, **Current** и **Upcoming**. Выберите шаг внутри индикатора прогресса, чтобы отредактировать стили состояния в правой панели. Используйте **Apply changes to all states**, чтобы применить изменения ко всем трём состояниям.

Редактирование одного шага затрагивает все шаги в одном индикаторе.

### Макет и позиционирование \{#layout-and-positioning\}

Индикатор прогресса — это глобальный элемент, поэтому его нельзя разместить внутри [контейнера](builder-containers). Также нельзя задать его позицию вручную — по умолчанию используется абсолютное позиционирование. Когда пользователь прокручивает экран, индикатор остаётся на месте, а контент прокручивается под ним.

Чтобы управлять отступами вокруг индикатора, используйте элементы управления **Margin** и **Padding** в разделе **Spacing**, а не пытайтесь перемещать сам элемент. Если макет выглядит неправильно, скорректируйте отступы как у индикатора, так и у соседнего элемента.

## Загрузчики \{#loaders\}

<ZoomImage id="flow-loaders.webp" width="220px" alt="The Loaders templates in the Add element panel: Spinner, Spinner with label, Progress bar, and Progress bar with label" float="right" />

**Загрузчик** — это анимированный элемент, который сигнализирует о том, что что-то происходит: например, обрабатываются ответы пользователя на вопросы квиза для подготовки персонального плана.

Категория предоставляет четыре шаблона:

- **Spinner** — Круглый индикатор загрузки.
- **Spinner with label** — Круглый индикатор загрузки с подписью (например, «Загрузка...»).
- **Progress bar** — Горизонтальная полоса, заполняющаяся от 0 до 100%.
- **Progress bar with label** — Горизонтальная полоса с подписью и процентом (например, «Анализ... 47%»).

### Спиннеры \{#spinners\}

Спиннер вращается всё время, пока открыт его экран. Чтобы изменить внешний вид, выберите один из шести стилей в разделе **Spinner**. В разделе **Animation** параметр **Duration** задаёт время одного полного оборота.

Параметр **Duration** у спиннера не задаёт время отображения экрана. Триггер **On screen appear** с действием **Navigate to Screen** переходит на следующий экран немедленно. Чтобы экран загрузки оставался открытым до 5 секунд, добавьте **Delay** к [переходу между экранами](flow-screen-transitions#move-users-to-another-screen-automatically) этого действия. Если нужно ждать дольше — добавьте [Timer](flow-timer) с триггером **On timer end**, который переходит на следующий экран, или используйте [прогресс-бар](#run-actions-when-a-progress-bar-is-full).

### Индикаторы прогресса \{#progress-bars\}

<ZoomImage id="builder-loader-settings.webp" width="280px" float="right" alt="Loader settings with Type set to Radial, Show percentage on, and the Typography, Progress color, and Animation sections" />

Индикатор прогресса заполняется от 0 до 100% каждый раз при открытии экрана. В разделе **Loader** выберите **Type**: **Linear** — для полосы, **Radial** — для кольца. Для кольца параметр **Thickness** задаёт толщину линии.

В разделе **Animation**:

- **Duration** — время, за которое индикатор заполняется.
- **Easing** — характер ускорения и замедления заполнения.

Чтобы задать цвет заполненной части, используйте раздел **Progress color**. Чтобы задать цвет незаполненного трека, используйте раздел **Fill**.

На холсте прогресс-бар отображается полным. Чтобы увидеть его заполнение, запустите анимации холста.

### Показать процент \{#show-the-percentage\}

Чтобы показать процент внутри полосы или кольца, в разделе **Loader** включите **Show percentage**. Чтобы изменить шрифт и цвет, используйте раздел **Typography**.

Чтобы показать процент в отдельном тексте, например рядом с подписью:

1. В разделе **Loader** прогресс-бара введите **Element ID**, например `analysis`.
2. Вставьте в текст переменную `analysis.progress` и добавьте после неё `%`.

Текст при этом отсчитывается вместе с полосой. Шаблон **Progress bar with label** настроен именно так. Текстовый элемент, отображающий эту переменную, не может отображать другие переменные или значения продукта.

### Запуск действий при заполнении прогресс-бара \{#run-actions-when-a-progress-bar-is-full\}

Триггер **On Load Complete** срабатывает один раз, когда прогресс-бар достигает 100%. Например:

- Чтобы перевести пользователей на следующий экран при заполнении бара, добавьте действие **Navigate to Screen**.
- Чтобы кнопка **Next** оставалась недоступной до заполнения бара, создайте булеву переменную с начальным значением `false` и добавьте действие **Set Variable**, которое устанавливает её в `true`. Затем [добавьте состояние **Disabled**](builder-element-states#condition-driven-disabled-state) для кнопки, которое применяется, пока переменная равна `false`.

### Запуск полосок прогресса поочерёдно \{#play-progress-bars-one-after-another\}

<ZoomImage id="builder-loader-start-loader.webp" width="500px" alt="Триггер On Load Complete с действием Start loader, которое запускает второй лоадер" />

Чтобы заполнять несколько полосок прогресса последовательно — например, по одной на каждый шаг анализа:

1. Выберите все полосы прогресса, кроме первой. В разделе **Loader** отключите **Autostart**. Эти полосы будут оставаться на 0 при открытии экрана.
2. Выберите первую полосу прогресса. В разделе **On Load Complete** добавьте действие **Start loader** и выберите вторую полосу.
3. Повторите шаг 2 для второй полосы, чтобы запустить третью, и так далее.

**Start loader** отображает только те полосы прогресса на том же экране, у которых отключён **Autostart**. Вы можете выбрать несколько полос в одном действии, чтобы заполнять их одновременно.

### Задержка отображения или скрытие лоадера \{#delay-or-hide-a-loader\}

Чтобы показать спиннер или прогресс-бар через некоторое время после открытия экрана, в разделе **Animation** укажите значение **Show after delay** в миллисекундах. Прогресс-бар начинает заполняться по окончании задержки.

Чтобы лоадер появлялся только при нажатии на элемент, установите для него значение **Visibility** → **Hide**. Затем выберите элемент, который должен показывать лоадер, и [добавьте действие **Show element** с триггером **On Tap**](flow-show-hide-animations#show-or-hide-an-element). Скрытый прогресс-бар начинает заполняться в момент появления, а не при открытии экрана.

### Когда пользователи покидают экран \{#when-users-leave-the-screen\}

- Если пользователи возвращаются на экран после того, как прогресс-бар заполнился, он остаётся на 100%. Действия **On Load Complete** повторно не запускаются.
- Если пользователи уходят с экрана до того, как прогресс-бар заполнился, он останавливается. При возвращении заполнение начинается заново с 0.

Прогресс-бар, входящий в состав [переиспользуемого компонента](reuse-flow-elements), не может иметь действия **On Load Complete** внутри bottom sheet, открываемого каким-либо действием. Флоу с таким баром не публикуется.
