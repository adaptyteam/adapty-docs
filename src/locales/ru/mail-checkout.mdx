Каждое письмо, которое отправляет Adapty Mail, содержит уникальную ссылку на чекаут для конкретного получателя. При переходе пользователь попадает в воронку веб-чекаута, которая идентифицирует его по профилю, показывает ваше предложение и обрабатывает оплату. Воронки чекаута находятся в разделе **Web Paywalls** внутри Adapty Mail и редактируются во встроенном **web paywall builder**.

## Требования \{#requirements\}

- Провайдер веб-платежей с настроенными продуктами подписки. **Generate with AI** поддерживает только Stripe и подключается прямо в билдере. **Use your own hosted paywall** принимает любого провайдера — Stripe, Paddle, PayPal или другого — так как оплата обрабатывается на вашей стороне.

Для работы с веб-редактором пейволов отдельный аккаунт не нужен. Он входит в состав Adapty Mail: рабочее пространство создаётся автоматически при первом входе, а авторизация в редакторе выполняется с теми же учётными данными Adapty. Это никак не связано с веб-пейволами, которые вы могли настроить на странице пейволов основного дашборда Adapty — веб-пейволы Adapty Mail являются отдельными сущностями и управляются исключительно из Adapty Mail.

## Настройте воронку оформления подписки \{#set-up-your-checkout-funnel\}

В Adapty Mail перейдите в **Web Paywalls → Create**. Вам доступны два варианта:

- **Generate with AI**: встроенный конструктор веб-пейволов Adapty Mail создаст воронку за вас. Только для Stripe — для Paddle или PayPal используйте второй вариант.
- **Use your own hosted paywall**: подключите пейвол, который вы уже размещаете на своём хостинге, с любым платёжным провайдером.

### Создание с помощью AI

:::warning
Доступно **только в проектах, связанных с приложением Adapty** — тех, которые Adapty создала автоматически, когда вы открыли Mail из дашборда. В проекте, созданном вручную в Adapty Mail на любом аккаунте, используется **Use your own hosted paywall**.
:::

На странице создания вверху отображается панель **Prerequisites** с кнопками действий прямо в строках — они проведут вас через каждое предварительное условие: готовность бренда, вход в конструктор, подключение Stripe, настройка продуктов и финальная проверка с публикацией. Пройдите все шаги; панель обновляется по мере выполнения каждого из них.

<ZoomImage id="mail-checkout-prerequisites.webp" width="500px" alt="Prerequisites panel on the Web Paywall Create page with checklist items and inline action buttons" />

Когда все предварительные условия отмечены зелёным, нажмите **Generate**, чтобы открыть диалог генерации. Нужно сделать два выбора:

- **Environment**: Выберите **Production** или **Sandbox**. Sandbox использует тестовые продукты Stripe и является безопасным вариантом по умолчанию для разработки и локальных окружений — его аккаунт изолирован от production, поэтому тестовые транзакции никогда не затрагивают рабочие данные.
- **Plans**: Выберите до **3 планов Stripe**. Каждый план — это комбинация продукта и цены. Пейвол отображает их как предложения при оформлении заказа. Если вы выберете меньше 3 планов, пейвол покажет только выбранные.

<ZoomImage id="mail-checkout-generation-dialog.webp" width="500px" alt="Диалог генерации web-пейвола с переключателем Environment и выбором тарифного плана Stripe" />

Нажмите **Generate**, чтобы запустить сборку. Когда она завершится, откройте редактор в билдере, проверьте результат и опубликуйте его. Затем нажмите **Save**.

:::important
Пейвол должен быть опубликован до того, как он начнёт обслуживать трафик из чекаута. Неопубликованные пейволы возвращают ошибку, когда пользователи переходят по ссылкам email-чекаута.
:::

Для получения информации о параметрах платёжного провайдера в конструкторе (аккаунты Stripe, тестовый и боевой режимы, настройка продуктов) см. [Настройка веб-пейвола](web-paywall-configuration).

### Используйте собственный пейвол на своём хостинге \{#use-your-own-hosted-paywall\}

На этом пути Adapty Mail отправляет получателей на страницу, которую вы хостите, и подставляет значения для каждого получателя в URL. Всё, что происходит после клика — оффер, оплата, персонализация — происходит на вашей стороне с любым платёжным провайдером.

1. В **Web Paywalls → Create** выберите **Enter URL manually**.
2. Вставьте URL вашего пейвола с плейсхолдерами в качестве параметров запроса. Adapty Mail подставляет их для каждого получателя, чтобы страница могла идентифицировать посетителя. Пример:

  ```
   https://example.com/paywall?email={email}&adapty_profile_id={adapty.external_profile_id}
   ```
3. Дайте пейволу **Name** и сохраните его. После этого его можно прикрепить к кампаниям.

На странице создания перечислены доступные плейсхолдеры, и каждый найденный в введённом URL отмечается галочкой:

| Плейсхолдер | Значение |
| --- | --- |
| `{email}` | Email-адрес получателя. |
| `{adapty.external_profile_id}` | ID профиля получателя в Adapty. |
| `{funnelfox.external_profile_id}` | ID профиля получателя в FunnelFox. |
| `{custom.external_profile_id}` | ID пользователя, переданный через [Adapty Mail API](mail-send-data-via-api). |
| `{scheduled_email_id}` | ID письма, содержащего ссылку. |

Три заполнителя profile-ID соответствуют разным источникам, из которых профиль может поступить — страница перечисляет все из них вне зависимости от того, используете ли вы их в своём проекте. Выбирайте тот, который соответствует способу передачи данных: `{adapty.external_profile_id}` — для [интеграции с Adapty](mail-collect-emails), `{custom.external_profile_id}` — для [API](mail-send-data-via-api). Заполнитель, для которого у получателя нет значения, превращается в пустую строку, поэтому на странице он никогда не отображается буквально — а заполнитель, который Adapty Mail не распознаёт, передаётся в том виде, в каком вы его ввели.

#### Что должна делать ваша страница \{#what-your-page-has-to-do\}

Adapty Mail выполняет свою часть работы до редиректа. Два шага остаются за вами:

- **Идентифицируйте посетителя до начала оформления заказа**: считайте ID профиля или email из строки запроса и привяжите их к покупке, чтобы платёж был зачислен именно тому клиенту, которому отправлялось письмо.
- **Сообщите о покупке обратно**: Adapty Mail не видит платежи, совершённые через ваш собственный провайдер, а покупка, о которой он не знает, не засчитывается ни как конверсия, ни как атрибутированный доход в [Аналитике](mail-analytics) — хуже того, остаток цепочки продолжит отправляться тому, кто уже купил. Передайте данные через любой путь, который уже используется для ваших данных: [интеграцию с Adapty](mail-collect-emails) или [событие транзакции](mail-send-data-via-api#send-transaction-events) через Adapty Mail API.

#### Протестируйте перед запуском \{#test-it-before-launching\}

**Send test email** проверяет, что письмо отображается корректно и ваша страница принимает платежи, однако **Sandbox** недоступен для пейвола, добавленного по URL — модальное окно сообщит: *«This paywall has no sandbox products, so only production is available.»* Поэтому тест будет проходить на вашей боевой странице с реальными продуктами: используйте настоящую карту и сделайте возврат, либо укажите в URL собственную тестовую среду на время проверки. См. [Тестирование настройки](mail-testing#test-the-email-and-checkout-on-their-own).

## Как выглядит чекаут \{#what-the-checkout-looks-like\}

Когда пользователь переходит по ссылке на чекаут, он попадает на **Main conversion page**. После попытки оплаты он увидит либо **Payment success**, либо **Payment failed** — только одну из двух страниц за одну попытку.

**Main conversion page**
Полноценная страница продаж. ИИ генерирует текст и изображения для каждого раздела:

| Раздел | Что генерирует ИИ |
|---|---|
| Заголовок | Жирный заголовок, акцент на пользе |
| Подзаголовок | Поддерживающее ценностное предложение |
| Бейдж акции | Бейдж срочности (без придуманных цен — использует размытые промо-формулировки) |
| Кнопка CTA | Призыв к действию, 2–5 слов |
| Преимущества | 3–6 карточек преимуществ с эмодзи и текстом |
| Функции | 3–8 описаний функций с названием и подзаголовком |
| Тарифы | Заголовок выбора плана и текст таймера акции |
| Социальное доказательство | Текст о сообществе и 3–5 реалистичных отзывов пользователей |
| FAQ | 3–6 часто задаваемых вопросов с ответами |
| Гарантия | Текст гарантии возврата денег или удовлетворённости |

**Успешная оплата**
Праздничное сообщение с дальнейшими шагами и изображением, сгенерированным ИИ.

**Ошибка оплаты**
Дружелюбное сообщение с предложением попробовать снова. Состояние чекаута сохраняется.

## Как работает персонализация \{#how-personalization-works\}

Ссылка CTA в каждом письме ведёт на URL checkout, сформированный специально для получателя. Перед отправкой Adapty Mail заменяет все плейсхолдеры в URL пейвола на значения конкретного получателя:

```
https://example.com/paywall?email=jane@example.com&adapty_profile_id=6f2a...c91
```

Сгенерированный пейвол получает эти параметры автоматически — никаких настроек в веб-редакторе пейволов не требуется. Для пейвола, добавленного по URL, вы сами выбираете, какие плейсхолдеры включить. Когда пользователь кликает, страница оформления заказа считывает параметры для его идентификации. После завершения покупки Adapty привязывает выручку к конкретному email, который привёл к конверсии. Эти данные отображаются в [аналитике кампаний](mail-analytics).

## Устранение неполадок \{#troubleshooting\}

| Проблема | Решение |
|---|---|
| Ссылка на оформление заказа не открывается | Убедитесь, что пейвол опубликован в конструкторе веб-пейвола |
| Пользователь не идентифицирован при оформлении заказа | Убедитесь, что `Adapty.identify()` был вызван с корректным ID пользователя до отправки письма |
| Покупка не атрибутирована к письму | Атрибуция привязывается к клику по CTA-кнопке в письме: получатель должен перейти к оформлению заказа именно по этой ссылке, а сама покупка должна поступить в Adapty Mail на том же профиле. Покупка, уже атрибутированная к более раннему письму, сохраняет эту атрибуцию |
