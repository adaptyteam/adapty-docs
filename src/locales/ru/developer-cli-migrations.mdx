Перенесите проект RevenueCat в Adapty: его каталог, а также (по желанию) стор-события и историю транзакций. Adapty выполняет каждую миграцию в виде последовательности шагов и сообщает, какие действия доступны следующими, — поэтому перед каждым действием запускайте `status`. Полная процедура описана в разделе [Миграция с RevenueCat](migration-from-revenuecat).

Все команды, кроме `list`, `create`, `use`, `current` и `unuse`, принимают флаг миграции:

| Флаг | Обязательный | Описание |
|---|---|---|
| `-m`, `--migration` | Нет | ID миграции. Если не указан, CLI использует переменную окружения `ADAPTY_MIGRATION`, затем миграцию, сохранённую командой `create` или `use`. |

## adapty migrations list

Список ваших миграций и флоу миграций, которые можно запустить, сгруппированных по приложению.

```bash
adapty migrations list
```

## adapty migrations create \{#adapty-migrations-create\}

Запустить миграцию и сохранить её как текущую.

```bash
adapty migrations create --name <app-name>
adapty migrations create --flow <flow> --app <app-id>
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--name` | Один из `--name` или `--flow` | Название нового приложения Adapty. Запускает миграцию каталога. Нельзя использовать вместе с `--flow` или `--app`. |
| `--flow` | Один из `--name` или `--flow` | Флоу для запуска в существующем приложении — в том виде, в котором он отображается в `adapty migrations list`. Требует `--app`. |
| `--app` | С `--flow` | ID приложения (UUID) |
| `--no-select` | Нет | Создать миграцию без сохранения её как текущей |

Флоу, доступные для существующего приложения после миграции каталога:

| Флоу | Описание |
|---|---|
| `transactions` | Импорт истории транзакций из ежедневного облачного экспорта RevenueCat |
| `transactions_support` | Импорт истории транзакций через поддержку RevenueCat и поддержку Adapty — для тарифных планов RevenueCat без облачного экспорта |
| `apple_events` | Перенаправление уведомлений App Store в Adapty с сохранением их получения в RevenueCat |
| `google_events` | Подписка Adapty на Pub/Sub-топик, который RevenueCat использует для уведомлений Google Play |
| `code` | Замена SDK RevenueCat в кодовой базе приложения с помощью вашего агента |
| `integrations` | Поиск инструментов аналитики, атрибуции и рассылок в коде приложения для настройки в Adapty с помощью вашего агента |
| `paywall_design` | Воссоздание дизайнов пейволов RevenueCat во флоу, созданных при миграции каталога, с помощью вашего агента |

## adapty migrations use \{#adapty-migrations-use\}

Сохраняет миграцию как текущую, чтобы остальные команды не требовали флага `-m`.

```bash
adapty migrations use <migration-id>
```

| Аргумент | Описание |
|---|---|
| `migration-id` | ID миграции из `adapty migrations list` |

Перед сохранением CLI проверяет, что у вас есть доступ к этой миграции. Сохранённая миграция привязана к текущему токену и действует во всех терминалах.

## adapty migrations current \{#adapty-migrations-current\}

Показывает текущую миграцию и источник её выбора: переменная окружения `ADAPTY_MIGRATION` или сохранённое значение.

```bash
adapty migrations current
```

## adapty migrations unuse

Очищает сохранённую миграцию. Значение `ADAPTY_MIGRATION`, заданное в оболочке, остаётся активным до тех пор, пока вы его не сбросите.

```bash
adapty migrations unuse
```

## adapty migrations status

Показывает состояние миграции, её проблемы и доступные следующие действия.

```bash
adapty migrations status
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--wait` | Нет | Опрашивает сервер до тех пор, пока миграция не изменится, затем возвращает актуальное состояние |
| `--timeout` | Нет | Время опроса для `--wait`: от 1 до 600 секунд, по умолчанию 120. Принимает `300`, `300s` или `5m`. Требует `--wait`. |

При использовании `--json` поля `next_actions` и `available_actions` содержат ID каждого действия, читаемые им ресурсы, его `input_schema` и текст `confirm`.

Код завершения `0` означает, что запрос выполнен успешно, а не что миграция прошла. Проверьте `migration.state` в ответе.

## Шаги миграции adapty \{#adapty-migrations-steps\}

Показывает чеклист миграции и статус каждого шага.

```bash
adapty migrations steps
```

## adapty migrations show

Выводит список доступных ресурсов или просматривает конкретный из них.

```bash
adapty migrations show [resource]
```

| Аргумент | Описание |
|---|---|
| `resource` | Имя ресурса, например `apps`, `mapping`, `report` или `export-config`. Не указывайте его, чтобы получить список ресурсов, доступных на текущем шаге. |

## adapty migrations run

Выполняет действие из `adapty migrations status`.

```bash
adapty migrations run <action-id>
```

| Аргумент | Описание |
|---|---|
| `action-id` | ID действия из `next_actions` или `available_actions` в `adapty migrations status` |

| Флаг | Обязательный | Описание |
|---|---|---|
| `--input` | Нет | Входные данные для действия в виде JSON-объекта, соответствующего `input_schema` действия. Без входных данных CLI отправляет `{}`. |
| `--input-file` | Нет | Путь к файлу с входными данными или `-` для чтения из stdin. Нельзя использовать вместе с `--input`. |
| `-y`, `--yes` | Для действий с текстом `confirm` | Подтверждает действие после ознакомления с текстом `confirm`. Интерактивный запрос не используется. |
| `--open` | Нет | Открывает ссылку действия даже при использовании пайпа или `--json` |
| `--no-browser` | Нет | Выводит ссылку действия без открытия браузера |

Действия бывают трёх видов:

- **Входные действия** отправляют ваши данные в Adapty — например, приложения RevenueCat для миграции или ваши решения по маппингу.
- **Внешние действия** открывают страницу в дашборде Adapty — например, чтобы вставить секретный API-ключ RevenueCat. Заполните страницу, затем проверьте `status`.
- **Действия агента**, например `migrate_code`, — это задачи для вашего агента. Запускайте их из git-репозитория приложения: CLI сохраняет данные миграции в `.git/adapty/<migration-id>/` и печатает инструкции для агента. Агент сообщает о результате, повторно запустив действие с флагом `--input`.

## adapty migrations close

Завершите или отмените миграцию. После этого её нельзя будет открыть снова.

```bash
adapty migrations close --outcome finish --yes
```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--outcome` | Да | `finish` помечает миграцию как завершённую; `cancel` — отменяет её |
| `-y`, `--yes` | Да | Подтвердите закрытие |
