Чтобы обеспечить бесперебойный пользовательский опыт, важно настроить **резервные версии** ваших [флоу](adapty-flow-builder).

Когда приложение запрашивает флоу, SDK Adapty обращается к нашим серверам за его конфигурацией. Если SDK не может получить флоу из основного API Adapty (проблемы с сетью, недоступность сервера), он переключается на другие источники:

- Если пользователь уже видел этот флоу, SDK отдаёт закешированную копию.
- Если основной API Adapty не отвечает, SDK запрашивает флоу с резервного сервера Adapty.
- Если ни один из вариантов не сработал, SDK загружает резервный конфигурационный файл, встроенный в приложение.

:::important
Резервный сервер и резервный файл обслуживают только аудиторию **All Users** и игнорируют сегменты. Если вы разделяете аудитории по платформам, используйте продукты с идентификаторами как App Store, так и Google Play во флоу **All Users**. Иначе в резервном флоу не окажется продуктов для пользователей другого стора.
:::

Adapty автоматически генерирует эти резервные файлы. Резервный бандл флоу используется совместно с пейволами — один JSON-файл на платформу содержит резервные варианты для обоих. SDK считывает нужный раздел по мере необходимости.

:::important
Резервные флоу входят в состав **Adapty SDK 4.0+**. Если в диалоге загрузки выбрать более раннюю версию SDK, файл будет содержать только варианты пейволов и онбордингов — без флоу. Убедитесь, что ваше приложение использует версию SDK с поддержкой флоу, прежде чем полагаться на резервный флоу.
:::

## Перед началом работы \{#before-you-start\}

1. Создайте [флоу](adapty-flow-builder) в Flow & Paywall Builder.
2. [Создайте плейсмент](create-placement) для флоу.

## Скачайте резервный файл \{#download-the-fallback-file\}

1. Откройте страницу **[Placements](https://app.adapty.io/placements)**.
2. Нажмите кнопку **Fallbacks** в правом верхнем углу.
3. Выберите целевую платформу из выпадающего списка.
4. Выберите вариант, соответствующий версии Adapty SDK в вашем приложении, например **Adapty SDK v4.4.0 and higher**.

Браузер скачает JSON-файл для каждой платформы — например, `ios_4_0_0_fallback.json`.

:::tip
Чтобы скачать файл из терминала, воспользуйтесь [Developer CLI](developer-cli). Укажите версию Adapty SDK, с которой собрано ваше приложение:

```bash
adapty fallbacks get --app <app-id> --platform ios --sdk-version <sdk-version> --output ios_fallback.json
```

Запустите команду отдельно для каждого стора — с флагом `--platform ios` или `--platform android`. Подробнее о флагах см. в [`adapty fallbacks get`](developer-cli-fallbacks).
:::

## После загрузки \{#after-the-download\}

Добавьте файл в код приложения, а затем следуйте платформенному гайду по настройке. Те же API, которые загружают резервные пейволы, также загружают резервные флоу, если ваше приложение работает на SDK-релизе с поддержкой флоу:

- [iOS](ios-use-fallback-paywalls)
- [Android](android-use-fallback-paywalls)
- [React Native](react-native-use-fallback-paywalls)
- [Flutter](flutter-use-fallback-paywalls)
- [Unity](unity-use-fallback-paywalls)
- [Kotlin Multiplatform](kmp-use-fallback-paywalls)
- [Capacitor](capacitor-use-fallback-paywalls)

## Ограничения \{#limitations\}

Резервные флоу жёстко закодированы и хранятся локально, поэтому они не обладают всеми динамическими возможностями живых флоу:

- **Одна аудитория на плейсмент.** Если у плейсмента несколько [аудиторий](audience), в резервном файле используется только аудитория **All users**.
- **Без активных A/B-тестов.** Если аудитория **All users** участвует в A/B-тесте, файл содержит все варианты теста с их весами. SDK распределяет пользователей по вариантам согласно весам. Чтобы обновить резервный файл после остановки теста, скачайте его заново и добавьте в новый релиз приложения.
- **Без Crossplacement A/B-тестов.** Резервный файл никогда не включает [Crossplacement A/B-тест](ab-test-types), даже если он запущен для аудитории **All users**. Для плейсмента в таком тесте файл содержит обычный контент **All users**: флоу или обычный A/B-тест.
- **Без удалённых обновлений.** Для обновления резервного файла требуется новый релиз приложения. Если вам нужно вносить изменения в реальном времени — делайте это через живой флоу.
