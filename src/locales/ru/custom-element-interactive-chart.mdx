Следуйте этому рецепту, чтобы отобразить прогнозируемый вес пользователя в виде графика в пейволе флоу. Пользователь вводит текущий и целевой вес в онбординге. Приложение собирает оба значения. График показывает еженедельный прогресс, которого пользователь может ожидать от вашего приложения, — от одного значения до другого. Приложение отображает график как нативный вид в [кастомном элементе](flow-custom-elements). Вид использует Swift Charts.

## 3. Сохраните текущий и целевой вес в приложении \{#3-save-the-current-and-goal-weight-in-your-app\}

Собирайте текущий и целевой вес из событий `flow_user_input` онбординг-флоу, как описано в [Обработка данных из флоу](ios-flow-input). Чтобы определить, что пользователь дошёл до последнего экрана, отслеживайте событие `flow_screen_showed` с `is_last_screen`, равным `true`. Когда онбординг-флоу закрывается после этого экрана, передайте оба значения веса в `showWeightPaywall` — функцию, которая [открывает пейвол-флоу с графиком](#5-match-the-chart-to-the-custom-element).

Следующий код предназначен для UIKit. Один view controller является делегатом обоих флоу. Чтобы добавить методы покупки и восстановления, которые реализует каждый `AdaptyFlowControllerDelegate`, следуйте инструкции [Отображение флоу и пейволов в UIKit](ios-present-paywalls#present-flows-and-paywalls-in-uikit).

```swift showLineNumbers title="Swift"
private var enteredWeights: [String: String] = [:]
private var reachedLastScreen = false

func flowController(
    _ controller: AdaptyFlowController,
    didReceiveAnalyticEvent name: String,
    params: [String: any Sendable]
) {
    if name == "flow_screen_showed", params["is_last_screen"] as? Bool == true {
        reachedLastScreen = true
        return
    }
    guard name == "flow_user_input",
          let elementId = params["element_id"] as? String,
          let value = params["value"] as? String
    else { return }

    enteredWeights[elementId] = value
}

func flowControllerDidDisappear(_ controller: AdaptyFlowController) {
    // This delegate receives events from both flows. Reset the entered
    // weights whenever a flow disappears, so that the paywall doesn't open
    // again when the user closes it.
    let weights = enteredWeights
    let finished = reachedLastScreen
    enteredWeights.removeAll()
    reachedLastScreen = false

    // Number inputs send their values as strings
    guard finished,
          let currentWeight = weights["weight"].flatMap({ Double($0) }),
          let goalWeight = weights["goal_weight"].flatMap({ Double($0) })
    else { return }

    Task {
        await showWeightPaywall(currentWeight: currentWeight, goalWeight: goalWeight)
    }
}
```

В SwiftUI используйте замыкания `didReceiveAnalyticEvent` и `didDisappear` модификатора `.flow` вместо методов делегата. Отображайте флоу пейвола с помощью второго модификатора `.flow`.

## 4. Создайте представление с графиком \{#4-create-the-chart-view\}

Создайте модель плана снижения веса и представление с графиком. Пlan содержит по одной записи на каждую неделю — от текущего веса до целевого. Когда пользователь проводит пальцем по графику, представление отмечает неделю в точке касания и отображает прогнозируемый вес для этой недели:

```swift showLineNumbers title="Swift"

struct WeightPlan {
    let entries: [WeightEntry]

    // One entry per week, from the current weight to the goal weight
    init(currentWeight: Double, goalWeight: Double) {
        let weeklyChange = 0.5 // kg per week
        let startDate = Date.now
        let weeks = Int((abs(goalWeight - currentWeight) / weeklyChange).rounded(.up))
        let step = goalWeight < currentWeight ? -weeklyChange : weeklyChange
        entries = (0...weeks).map { week in
            WeightEntry(
                date: startDate.addingTimeInterval(Double(week) * 7 * 24 * 60 * 60),
                kilograms: week == weeks ? goalWeight : currentWeight + step * Double(week)
            )
        }
    }
}

struct WeightEntry: Identifiable {
    let date: Date
    let kilograms: Double
    var id: Date { date }
}

@available(iOS 16.0, *) // Swift Charts needs iOS 16
struct WeightGoalChart: View {
    let entries: [WeightEntry]
    @State private var selectedDate: Date?

    // The entry closest to the date that the user drags to
    private var selectedEntry: WeightEntry? {
        guard let selectedDate else { return nil }
        return entries.min {
            abs($0.date.timeIntervalSince(selectedDate)) < abs($1.date.timeIntervalSince(selectedDate))
        }
    }

    var body: some View {
        if #available(iOS 17.0, *) {
            chart.chartXSelection(value: $selectedDate)
        } else {
            chart // iOS 16: no drag selection
        }
    }

    private var chart: some View {
        Chart {
            ForEach(entries) { entry in
                LineMark(
                    x: .value("Date", entry.date),
                    y: .value("Weight", entry.kilograms)
                )
            }
            if let selectedEntry {
                RuleMark(x: .value("Date", selectedEntry.date))
                    .foregroundStyle(.gray.opacity(0.3))
                PointMark(
                    x: .value("Date", selectedEntry.date),
                    y: .value("Weight", selectedEntry.kilograms)
                )
                .annotation(position: .top) {
                    Text("\(selectedEntry.kilograms, specifier: "%.1f") kg")
                        .font(.caption.bold())
                }
            }
        }
        .chartYScale(domain: .automatic(includesZero: false))
    }
}
```

Перетаскивание по графику требует iOS 17 или новее. На iOS 16 линия отображается, но перетаскивание недоступно.

## 5. Привяжите график к кастомному элементу \{#match-the-chart-to-the-custom-element\}

Напишите [резолвер](ios-flow-custom-elements#write-a-resolver-to-match-custom-elements-and-views), который возвращает вью с графиком для Type `line_chart` и ID `weight_goal`. Сохраните план веса в свойстве резолвера:

```swift showLineNumbers title="Swift"

@available(iOS 16.0, *) // the chart needs iOS 16
struct WeightChartResolver: AdaptyUICustomElementsResolver {
    let plan: WeightPlan

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        guard type == "line_chart", id == "weight_goal" else {
            return nil // another custom element: show the fallback
        }
        return AnyView(WeightGoalChart(entries: plan.entries))
    }
}
```

Attach the resolver to the paywall flow when you fetch its configuration. Create the resolver with the weight plan from the current and goal weight:

```swift showLineNumbers title="Swift"
func showWeightPaywall(currentWeight: Double, goalWeight: Double) async {
    let plan = WeightPlan(currentWeight: currentWeight, goalWeight: goalWeight)
    do {
        let flow = try await Adapty.getFlow(placementId: "weight_paywall")
        let flowConfiguration = try await AdaptyUI.getFlowConfiguration(
            forFlow: flow,
            customElementsResolver: WeightChartResolver(plan: plan)
        )
        let flowController = try AdaptyUI.flowController(
            with: flowConfiguration,
            delegate: self
        )
        present(flowController, animated: true)
    } catch {
        // handle the error
    }
}
```

Если в вашем приложении задан [общий резолвер](ios-flow-custom-elements#set-an-app-wide-resolver), этот резолвер заменяет его во флоу пейвола. `WeightChartResolver` не возвращает никакого представления для любых других Type и ID, поскольку флоу пейвола в этом рецепте не содержит других пользовательских элементов. Если ваш флоу пейвола содержит другие пользовательские элементы, передайте общий резолвер в этот. Затем вызывайте общий резолвер для их Type и ID, как описано в разделе [Прикрепить резолвер к одному флоу](ios-flow-custom-elements#attach-a-resolver-to-one-flow).

## 6. Протестируйте на устройстве \{#6-test-on-a-device\}

Flow & Paywall Builder не может выполнять код вашего приложения, поэтому на холсте отображается только резервный вариант. Чтобы посмотреть график:

1. [Опубликуйте оба флоу](builder-save-publish). Чтобы видеть последние опубликованные версии вместо кэшированных, зарегистрируйте устройство как [тестовое](test-devices).
2. Соберите приложение с подключённым резолвером. Используйте устройство с iOS 17 или новее. Пройдите онбординг, указав текущий и целевой вес. Убедитесь, что линия на графике начинается с текущего веса и заканчивается на целевом.
3. Проведите пальцем по графику и убедитесь, что прогнозируемый вес для недели под пальцем отображается над линией.

Чтобы проверить резервный вариант, удалите аргумент `WeightChartResolver` в `showWeightPaywall` и снова откройте флоу пейвола.

Чтобы разобраться, почему вместо графика отображается резервный вариант, следуйте инструкциям в разделе [Тест на устройстве](ios-flow-custom-elements#test-on-a-device) руководства для iOS.
