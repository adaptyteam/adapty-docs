Чтобы обновить приложение с Adapty Android SDK 4.1, 4.2 или 4.3 до версии 4.4, установите версию `adapty-bom` на `4.4.0` и замените резервный файл в том же билде. SDK версий 4.1–4.3 не принимают новый файл. Если ваш Java-код вызывает `AdaptyFlowView.showFlow`, добавьте аргумент в каждый такой вызов. Если приложение работает на версии 4.0, сначала выполните [изменения из v4.1](migration-to-android-sdk-41).

:::warning
Формат резервного файла изменился в версии 4.4, и компилятор не обнаружит устаревший файл. Без [нового резервного файла](#replace-the-fallback-file) каждый плейсмент лишится своего резервного пейвола.
:::

## Замените резервный файл \{#replace-the-fallback-file\}

Чтобы скачать [резервный файл](fallback-flows) повторно, в разделе **[Placements](https://app.adapty.io/placements)** нажмите **Fallbacks** > **Download Android Fallback**. В строке **Adapty SDK v4.4.0 and higher** нажмите **Download**. Добавьте файл в своё приложение.

Скачанный файл называется `android_4_4_0_fallback.json`. Переименуйте его в соответствии с именем файла, который загружает ваше приложение, или обновите имя в вызове, который его загружает:

- **`FileLocation.fromAsset`**: Имя файла, например `android_fallback.json`.
- **`FileLocation.fromResId`**: Имя ресурса, например `android_fallback` в `R.raw.android_fallback`.

При использовании устаревшего файла `Adapty.setFallback` передаёт в коллбэк `AdaptyError` с сообщением "The fallback file version is not correct. Download a new one from the Adapty Dashboard." Чтобы проверить новый файл, запустите приложение и убедитесь, что коллбэк не возвращает ошибку. Коллбэк необязателен. Если вы его не используете, установите свойству [`Adapty.logLevel`](sdk-installation-android#logging) значение `AdaptyLogLevel.ERROR` или более подробный уровень, затем убедитесь, что Logcat не показывает эту ошибку.

## Добавьте аргумент в вызовы showFlow в Java \{#add-an-argument-to-showflow-calls-in-java\}

В версии 4.4 метод `AdaptyFlowView.showFlow` получил новый последний параметр — `customElementsResolver`. Java-код обязан передавать все параметры `showFlow`, поэтому вызов с восемью аргументами не компилируется. Передайте `null` в качестве последнего аргумента:

```diff showLineNumbers
  flowView.showFlow(flowConfiguration, products, eventListener, insets,
-         customAssets, tagResolver, timerResolver, observerModeHandler);
+         customAssets, tagResolver, timerResolver, observerModeHandler, null);
```

Kotlin calls to `showFlow` and all calls to `AdaptyUI.getFlowView` compile without changes.
