Когда игрок нажимает кнопку во флоу «нет энергии», код вашего приложения обращается к бэкенду, чтобы потратить алмазы на выбранный вариант. Код приложения не может передать трату в Adapty напрямую, потому что запрос требует секретного API-ключа. Ваш бэкенд вызывает [Create virtual currency transaction](api-adapty/operations/createVirtualCurrencyTransaction) с отрицательным значением `amount`, как описано в руководстве [Virtual currency quickstart](virtual-currency-quickstart). Отправляйте трату без предварительного запроса баланса: Adapty проверяет баланс в рамках самой операции.

Храните стоимость каждого варианта на бэкенде: 10 алмазов за восстановление энергии и 30 за час безлимитной энергии. Код приложения отправляет бэкенду только выбранный вариант, поэтому модифицированная версия приложения не сможет снизить стоимость.

```bash title="Spend diamonds"
curl -X POST https://api.adapty.io/api/v2/server-side-api/vc/transactions/ \
  -H "Authorization: Api-Key {your secret key}" \
  -H "adapty-customer-user-id: player-42" \
  -H "Idempotency-Key: 5221577a-8b4c-419a-a0f5-028e4598b265" \
  -H "Content-Type: application/json" \
  -d '{
        "items": [{"currency_code": "DIAMONDS", "amount": -30}],
        "operation": "spend",
        "feature": "unlimited_energy",
        "customer_placement_id": "out_of_energy",
        "reference_id": "energy_order_7781"
      }'
```

Запрос идентифицирует трату, игрока и выбранный вариант:

- **`Idempotency-Key`**: UUID v4, который код приложения генерирует для каждой новой траты, чтобы защитить пользователя от повторного списания за одну и ту же транзакцию. Если нужно повторить транзакцию (например, из-за сетевого сбоя), используйте ключ из исходного запроса. Ключ действителен в течение 1 часа. Если транзакция с этим ключом уже выполнена успешно, последующие запросы с тем же ключом вернут исходную транзакцию и не изменят баланс.
- **`adapty-customer-user-id`**: Customer user ID авторизованного пользователя. На бэкенде считывайте его из сессии входа.
- **`feature`**: [Метка](virtual-currencies#feature) для варианта, например `unlimited_energy`. По этой метке в [истории событий](virtual-currency-balance#review-balance-changes-in-the-event-history) игрока видно, на что была потрачена каждая сумма.

Два необязательных поля помогут позже отследить трату. Оба отображаются в [деталях транзакции](virtual-currency-balance#transaction-details) истории событий:

- **`customer_placement_id`**: ID экрана в приложении, с которого была совершена трата. Позволяет видеть, с какого экрана пришла каждая трата. В этом рецепте используйте ID плейсмента флоу «нет энергии» — `out_of_energy`.
- **`reference_id`**: ID связанной записи в вашем бэкенде, например заказа энергии, который оплачивает эта трата. По нему команда поддержки может сопоставить трату с тем, что получил пользователь.

Если трата прошла успешно, начислите игроку энергию со своего бэкенда: Adapty хранит баланс алмазов, а не энергию. Начисляйте энергию один раз за каждый `transaction_id` из ответа, потому что повторный запрос с тем же `Idempotency-Key` вернёт исходную транзакцию. Массив `balances` в ответе содержит значение `available` для `DIAMONDS` — количество алмазов, которые игрок может потратить прямо сейчас. Верните это значение в код приложения.

Если баланса не хватает для покрытия стоимости, запрос завершается с HTTP-статусом 400 и баланс не изменяется. Чтобы определить эту ошибку, сравните `error_code` со значением `insufficient_balance`. Затем рассчитайте, сколько алмазов не хватает игроку: запросите баланс через [List virtual currency balances](api-adapty/operations/listVirtualCurrencyBalances) и вычтите значение `available` для `DIAMONDS` из стоимости. Верните результат и значение `available` в код приложения.

Если результат равен 0 или меньше, значит Adapty добавил алмазы на баланс после того, как трата не прошла, — например, при продлении подписки. В таком случае повторите запрос с тем же `Idempotency-Key` и верните результат повторного запроса. Adapty не сохраняет ключ неудавшейся траты, поэтому принимает второй запрос.

Если первый запрос с тем же `Idempotency-Key` ещё выполняется, повторный запрос завершится с HTTP-статусом 409 и кодом ошибки `idempotency_in_flight`. Подождите количество секунд, указанное в заголовке `Retry-After` ответа, и повторите запрос с тем же ключом.

Запросы на трату от всех ваших пользователей суммируются и учитываются в одном лимите: по умолчанию 600 запросов в минуту для вашего приложения. Запрос сверх лимита завершается с HTTP-статусом 429 и кодом ошибки `rate_limited`. Если в пиковое время ожидается больше запросов на трату, уточните в поддержке, какой [лимит запросов](ss-authorization#rate-limits) применяется к вашему приложению.

На бэкенде добавьте эндпоинт для баланса: вызовите List virtual currency balances и верните значение `available` для `DIAMONDS`. Код приложения в этом рецепте обращается к этому эндпоинту перед открытием флоу «нет энергии» и после каждой покупки.

<Callout type="tip">
Если вы [включите истечение кредитов](create-virtual-currency#link-products) для подписки, напоминайте пользователям тратить кредиты вовремя. Массив `expiry.expiring` в ответе [List virtual currency balances](api-adapty/operations/listVirtualCurrencyBalances) показывает, сколько кредитов и когда истекает. Отображайте ближайшую сумму во флоу с [кастомным тегом](flow-custom-tags), например: «30 алмазов истекут через 2 дня».
</Callout>
