Метрики пейволов, триалов и покупок можно группировать по двум разным датам:

- **Дата события** — когда был просмотрен пейвол, начат триал или совершена покупка.
- **Дата установки** — когда пользователь впервые открыл приложение.

Оба представления могут показывать очень разные цифры для одного и того же диапазона дат. Флажок **Filter metrics by install date** определяет, какое из них использует дашборд:

- **Не установлен (по умолчанию)**: метрики группируются по дате события.
- **Установлен**: метрики группируются по дате установки.

**Пример.** Вы задаёте диапазон дат 1–30 апреля и смотрите на триалы.

- **Не установлен**: показывает триалы, которые *начались* в апреле, независимо от того, когда эти пользователи установили приложение.
- **Установлен**: показывает триалы пользователей, которые *установили* приложение в апреле, независимо от того, когда начались их триалы.

Представление по дате установки продолжает пополняться после окончания периода. Пользователь, установивший приложение в апреле и начавший триал в июле, добавляется к апрелю в момент начала триала — поэтому апрельские метрики растут каждый раз, когда вы их открываете. Представление по дате события так не меняется — каждое событие засчитывается в тот день, когда оно произошло.

Используйте представление по дате установки для оценки эффективности привлечения пользователей для конкретной когорты. Используйте представление по дате события для измерения активности пейвола или онбординга в конкретный период.
