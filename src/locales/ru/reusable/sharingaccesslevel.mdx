**Enabled (default)**

Идентифицированные пользователи (те, у кого есть [Customer User ID](identifying-users#set-customer-user-id-on-configuration)) могут иметь общий [уровень доступа](access-level) от Adapty, если их устройство привязано к одному и тому же Apple/Google ID. Это удобно, когда пользователь переустанавливает приложение и входит с другим email — он по-прежнему сохранит доступ к своей предыдущей покупке. При этой опции несколько идентифицированных пользователей могут иметь общий уровень доступа.

Даже если уровень доступа является общим, все прошлые и будущие транзакции фиксируются как события в исходном Customer User ID — для корректной аналитики и сохранения полной истории транзакций: пробных периодов, покупок подписок, продлений и прочего, привязанных к одному профилю.

**Transfer access to new user**

Идентифицированные пользователи могут сохранять доступ к [уровню доступа](access-level) от Adapty даже при входе с другим [Customer User ID](identifying-users#set-customer-user-id-on-configuration) или переустановке приложения — при условии, что устройство привязано к одному и тому же Apple/Google ID.

В отличие от предыдущей опции, Adapty переносит покупку между идентифицированными пользователями. Это гарантирует доступность купленного контента, но одновременно им может пользоваться только один пользователь. Например, если UserA купил подписку, а UserB вошёл с того же устройства и восстановил транзакции, UserB получит доступ к подписке, а у UserA он будет отозван.

Если один из пользователей (новый или прежний) не идентифицирован, уровень доступа по-прежнему будет общим для этих профилей в Adapty.

Несмотря на то что уровень доступа переносится, все прошлые и будущие транзакции фиксируются как события в исходном Customer User ID — для корректной аналитики и сохранения полной истории транзакций: пробных периодов, покупок подписок, продлений и прочего, привязанных к одному профилю.

После переключения на **Transfer access to new user** уровни доступа не переносятся между профилями немедленно. Перенос для каждого конкретного уровня доступа происходит только при получении Adapty события от стора — например, продления подписки, восстановления или при валидации транзакции.

**Disabled**

Первый идентифицированный профиль пользователя, получивший уровень доступа, сохранит его навсегда. Это лучший вариант, если ваша бизнес-логика предполагает привязку покупок к единственному Customer User ID.

Обратите внимание, что уровни доступа по-прежнему являются общими для анонимных пользователей.

Вы можете «отвязать» покупку, [удалив профиль владельца](https://adapty.io/docs/ru/api-adapty/operations/deleteProfile). После удаления уровень доступа становится доступен первому профилю, который его запросит, — анонимному или идентифицированному.

Отключение общего доступа влияет только на новых пользователей. Подписки, уже ставшие общими, продолжат оставаться таковыми даже после отключения этой опции.

<Callout type="warning">
Apple и Google требуют, чтобы встроенные покупки были общими или переносились между пользователями, поскольку они привязывают покупку к Apple/Google ID. Без общего доступа восстановление покупок может не работать при последующих переустановках.

Отключение общего доступа может помешать пользователям восстановить доступ после входа в систему.

Рекомендуем отключать общий доступ только в том случае, если пользователи **обязаны войти** перед совершением покупки. В противном случае идентифицированный пользователь может купить подписку, войти в другой аккаунт и навсегда потерять доступ.
</Callout>

### Какую настройку выбрать? \{#which-setting-should-i-choose\}

| Моё приложение...                                                    | Какую опцию выбрать                                             |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| Не имеет системы входа и использует только анонимные идентификаторы профилей Adapty. | Используйте опцию по умолчанию: уровни доступа всегда являются общими для анонимных идентификаторов профилей при всех трёх вариантах. |
| Имеет необязательную систему входа и позволяет совершать покупки до создания аккаунта. | Выберите **Transfer access to new user**, чтобы пользователи, купившие без аккаунта, могли восстановить транзакции позднее. |
| Требует создания аккаунта перед покупкой, но разрешает привязывать покупки к нескольким Customer User ID. | Выберите **Transfer access to new user**: в любой момент доступ будет только у одного Customer User ID, при этом пользователи смогут входить с другим Customer User ID, не теряя оплаченный доступ. |
| Требует создания аккаунта перед покупкой и жёстко привязывает покупки к единственному Customer User ID. | Выберите **Disabled**, чтобы транзакции никогда не переносились между аккаунтами. |
