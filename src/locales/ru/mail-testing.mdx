Прежде чем запускать кампанию для реальных пользователей, проведите одного тестового пользователя через всю цепочку: email-адрес попадает в Adapty Mail, кампания отправляется, получатель переходит по ссылке в чекаут, оплата проходит, и приложение предоставляет доступ.

У вас есть два способа протестировать. Живая цепочка запускает автоматизацию и требует реального платежа, который вы потом возвращаете. Тестовая отправка пропускает автоматизацию и позволяет использовать тестовую карту Stripe. Запустите живую цепочку хотя бы один раз перед запуском.

## Прежде чем начать \{#before-you-start\}

Цепочка работает от начала до конца только при выполнении всех следующих условий:

- **Sending domain**: Ваш домен верифицирован в **Settings → Email Domains**. См. [Настройка домена отправки](mail-sending-domain).
- **Checkout**: Ваш веб-пейвол создан и опубликован. Неопубликованный пейвол возвращает ошибку при открытии по CTA. См. [Настройка checkout](mail-checkout).
- **Campaign attached to a flow**: Кампания сама по себе остаётся черновиком и ничего не отправляет. Прикрепите её к строке флоу, чтобы она заработала. См. [Создание флоу](mail-create-flow).
- **Adapty integration**: Интеграция включена в **Settings → Integrations**, чтобы события подписок поступали в Adapty Mail.

## Протестируйте живую цепочку \{#test-the-live-chain\}

Этот путь запускает вашу кампанию точно так же, как её видит реальный пользователь, — то есть CTA открывает ваш продуктовый чекаут, и оплата настоящая.

1. **Сократите первую задержку.** В редакторе кампании установите для первого письма **Delay** в одну-две минуты, чтобы не ждать реального расписания. После теста восстановите исходные задержки.

   <ZoomImage id="mail-campaign-email-delay.webp" width="600px" alt="The Delay field on the first email, set to 0 days, 0 hours, and 1 minute" />

2. **Создайте тестового пользователя.** В приложении зарегистрируйтесь с адресом электронной почты, которого ещё нет в проекте. Для каждого запуска нужен новый адрес: профиль, уже прошедший через кампанию, повторно в неё не попадёт.

3. **Дождитесь первого письма.** Adapty Mail планирует отправку по времени триггера плюс заданная вами задержка, затем каждую минуту забирает письма, готовые к отправке. Доставка занимает ещё несколько минут.

4. **Откройте письмо и нажмите CTA.** Вы попадёте на страницу оформления заказа с уже заполненным адресом электронной почты.

5. **Завершите оплату.** Оплатите реальной картой, затем оформите возврат в Stripe.

## Протестируйте письмо и чекаут отдельно \{#test-the-email-and-checkout-on-their-own\}

Чтобы просмотреть письмо и чекаут, не дожидаясь запуска автоматизации, воспользуйтесь кнопкой **Send test email** в редакторе кампании. Кнопка остаётся неактивной до тех пор, пока не верифицирован домен отправки и в кампании не выбран web-пейвол.

В модальном окне есть две настройки:

- **Environment**: **Production** открывает настоящий чекаут с реальными продуктами. **Sandbox** открывает тестовую версию, где тестовая карта Stripe `4242 4242 4242 4242` работает с любой будущей датой истечения и любым CVC. Sandbox доступен только для пейвола, созданного с sandbox-продуктами — для пейвола, добавленного по URL, отображается *«This paywall has no sandbox products, so only production is available.»*
- **Profile**: Необязательно. Выберите профиль, чтобы отправить письмо на адрес этого профиля и заполнить CTA его идентификаторами. Оставьте поле пустым, чтобы отправить письмо на адрес вашего собственного аккаунта с placeholder-идентификатором профиля.

Тестовая отправка — это отдельное письмо, не связанное с живой цепочкой. Она подтверждает, что письмо корректно отображается и что чекаут принимает оплату, но ничего не говорит о том, срабатывает ли автоматизация. Чтобы проверить автоматизацию, запустите [живую цепочку](#test-the-live-chain).

## Подтвердите доступ в приложении \{#confirm-access-in-your-app\}

После прохождения оплаты подписка появляется в профиле пользователя в Adapty, и приложение получает уровень доступа.

Adapty записывает платёж в песочнице как транзакцию песочницы, поэтому убедитесь, что ваш уровень доступа принимает транзакции песочницы, прежде чем расценивать отсутствие уровня доступа как ошибку.

## Просмотр журнала событий \{#read-the-journey\}

Чтобы посмотреть, что зафиксировал Adapty Mail, перейдите в раздел **Profiles**, откройте тестовый профиль и просмотрите таймлайн **Journey**. Таймлайн отмечает каждое письмо чипами с указанием статуса доставки:

| Чип | Что означает |
| --- | --- |
| **Scheduled** | У письма задано время отправки, и Adapty Mail ещё не отправил его. |
| **Cancelled** | Письмо не будет отправлено. Покупка отменяет все оставшиеся письма в последовательности. |
| **Sent** | Adapty Mail отправил письмо, но подтверждения доставки пока нет. |
| **Delivered** | Принимающий почтовый сервер принял письмо. Этот чип заменяет **Sent**. |
| **Opened** | Пиксель отслеживания загрузился. |
| **Clicked** | Получатель перешёл по ссылке. Разверните письмо, чтобы увидеть, по каким ссылкам он кликал и какую покупку это повлекло. |
| **Bounced** | Доставка не удалась. |
| **Spam report** | Получатель отметил письмо как спам. |
| **Unsubscribed** | Получатель отписался. Adapty Mail исключает его из всех кампаний в проекте — см. [Отписка и подавление](mail-suppression). |

Успешный тест показывает, что первое письмо достигло статуса **Clicked**, покупка атрибутирована к нему, а остальные письма последовательности — **Cancelled**.

:::note
Открытия фиксируются по загрузке пикселя, а Apple Mail Privacy Protection предзагружает их заранее, поэтому чип **Opened** без вашего участия — это нормально. Подробнее о том, что считает каждая метрика, — в разделе [Аналитика кампаний](mail-analytics).
:::
