**Профиль** — это один пользователь в вашем проекте. Страница **Profiles** отображает всех, кого знает Adapty Mail, а также статус покупок каждого пользователя, его активность по email и полную историю действий.

Профили поступают автоматически — через любую [точку входа](mail-entry-points), которую вы настроили. Обязательное условие — наличие email-адреса: Adapty Mail не создаёт профиль для пользователя, который его не предоставил.

:::tip
Чтобы объединять профили в многократно используемые аудитории для флоу и A/B-тестов, см. [Сегменты](mail-segments).
:::

## Как профили попадают в Adapty Mail \{#how-profiles-get-into-adapty-mail\}

Adapty Mail создаёт профили автоматически из трёх источников:

- **Adapty**: SDK собирает email-адреса и покупки из вашего приложения. См. [Подключение Adapty к Adapty Mail](mail-collect-emails).
- **Adapty Mail API**: Ваш бэкенд отправляет профили и транзакции через server-to-server. См. [Отправка данных через API](mail-send-data-via-api).
- **FunnelFox**: Ваши веб-воронки передают email-адреса, покупки и события подписок. См. [Подключение FunnelFox к Adapty Mail](mail-funnelfox).

Adapty Mail сопоставляет людей по адресу электронной почты. Два источника с одинаковым адресом попадают в один профиль; два разных адреса создают отдельные профили, даже если `customer_user_id` совпадает. Каждый источник хранит собственный идентификатор пользователя, и на странице профиля все они перечислены в разделе **External Profile IDs**.

Если вы также используете Adapty, профиль здесь — это не ваш профиль в Adapty. Adapty Mail ведёт собственные записи и хранит ID профиля Adapty как один из внешних идентификаторов. Профилей здесь будет меньше, чем в Adapty, потому что профили Adapty без адреса электронной почты сюда не попадают.

Создавать и редактировать профили здесь нельзя — данные принадлежат источнику, который их передал, — но можно отписаться от рассылки и удалить их.

## Список профилей \{#the-profiles-list\}

Список отображает профили по одному в строке, начиная с новейших. Используйте строку поиска, чтобы найти профиль по email, ID профиля или внешнему ID профиля.

| Столбец | Содержимое |
| --- | --- |
| Profile | Email клиента и кампания, связанная с его последним email-событием. |
| Status | Статус покупки профиля. См. [Статус профиля](#profile-status). |
| Country | Страна клиента. |
| Open rate | Отношение открытых писем к отправленным. Прочерк означает, что письма ещё не отправлялись. |
| LTV | Lifetime value — суммарный доход от этого профиля по всем источникам. |
| Joined | Когда профиль впервые появился в Adapty Mail. |
| Last activity | Когда произошло последнее email-событие профиля. Учитывается отправка, а не только открытие или клик. |

:::important
**Joined** — это дата, когда профиль впервые появился в Adapty Mail; она используется как дата начала отношений с клиентом. Это время попадания в систему, а не исходная дата регистрации в вашем приложении.
:::

### Статус профиля \{#profile-status\}

Столбец **Status** отображает статус покупок профиля — что именно приобрёл пользователь и активна ли эта покупка. Этот статус не имеет отношения к тому, получает ли пользователь ваши письма.

| Статус | Значение |
| --- | --- |
| Never purchased | Пользователь ничего не купил. |
| Purchased | Пользователь совершил разовую покупку. |
| Active subscriber | Пользователь оформил платную подписку с автопродлением. |
| Renewal cancelled | Автопродление отключено; доступ сохраняется до конца текущего периода. |
| Billing issue | Платёж при продлении не прошёл. |
| Grace period | Платёж не прошёл, но доступ сохраняется в течение льготного периода стора. |
| Churned | Подписка истекла и доступ закрыт. |
| Refunded | Покупка возвращена. |

:::note
Профиль может быть **активным подписчиком** и при этом **отписанным** от ваших email-рассылок, или **отточившим** (churned) и при этом **подписанным**. Статус email отображается на странице профиля и определяет, может ли Adapty Mail отправлять письма этому профилю.
:::

## Детали профиля \{#profile-details\}

Нажмите на профиль, чтобы открыть страницу с его деталями.

### Заголовок профиля \{#the-profile-header\}

Заголовок идентифицирует пользователя: email, страна, пол, возраст, платформа и дата «клиент с». Он также содержит три бейджа:

- **Purchase status**: Статус покупки профиля, использующий значения из раздела [Статус профиля](#profile-status).
- **Open rate**: Процент открытий писем, отправленных этому профилю. [Аналитика](mail-analytics) считает получателей, открывших письмо хотя бы раз, а не сами письма, поэтому цифры различаются.
- **Subscribed** или **Unsubscribed**: Разрешение на отправку email для этого профиля, не связанное с платной подпиской в **Status**.

**Subscribed** означает, что отправке ничего не мешает — но не то, что что-то запланировано. Профиль всё равно должен соответствовать сегменту во флоу, а [двойное подтверждение](mail-double-opt-in) удерживает маркетинговые письма до тех пор, пока пользователь не подтвердит адрес. **Unsubscribed** охватывает все причины, по которым отправка прекратилась: отказ доставки или жалоба на спам отображаются тем же значком, что и обычная отписка; все случаи описаны в разделе [Причины остановки писем](mail-suppression).

### Метрики вовлечённости \{#engagement-metrics\}

Пять метрик отображаются в верхней части страницы:

- **Sent**: Письма, отправленные профилю.
- **Delivered**: Письма, принятые почтовым провайдером.
- **Opened**: Количество открытий письма получателем, включая повторные.
- **Clicked**: Количество кликов по ссылкам.
- **Revenue**: Два показателя — атрибутированный доход и пожизненная ценность.

:::note
**Атрибутированная выручка** — это выручка, полученная благодаря вашим письмам: покупки, совершённые пользователем после перехода по ссылке из письма. **Пожизненная ценность (LTV)** — это общая выручка профиля из всех источников, независимо от того, участвовала ли почта в её формировании. В заголовке сначала отображается атрибутированная выручка, затем LTV.
:::

### Карточка профиля \{#the-profile-card\}

Карточка **Profile** отображает атрибуты пользователя:

- **Platform**: Платформа последнего устройства пользователя, например iOS или Android.
- **Email provider**: Кто обслуживает почтовый ящик — **Google**, **iCloud**, **Proton** и т. д. — определяется по MX-записям домена. **Disposable** означает сервис одноразовых адресов: такие адреса [не проходят верификацию](mail-suppression#address-verification-failed) и сразу попадают в список подавления.
- **Country**: Страна пользователя.
- **Store country**: Страна аккаунта App Store или Google Play пользователя.
- **Gender**: Пол пользователя, если известен.
- **Age**: Возраст пользователя и дата рождения, переданная источником.
- **Profile ID**: Внутренний идентификатор профиля в Adapty Mail.

**External Profile IDs** содержит по одной записи для каждого источника — **Adapty**, **FunnelFox** или **Custom** — с идентификатором, который этот источник использует для данного пользователя, и временем первого появления. **Custom attributes** содержит пары ключ-значение, отправленные источником.

### Состояние покупки \{#purchase-state\}

Карточка **Purchase state** показывает доход от профиля и историю покупок. Вверху отображается пожизненная ценность клиента, ниже — повторяющийся доход, а затем до двух разделов:

- **Subscription**: цена, стор, дата начала, ID продукта и дата, помеченная **Renews** — пока доступ активен, или **Expired** — после его окончания.
- **One-time purchase**: цена, стор, дата покупки и ID продукта для последней разовой покупки.

Если у клиента есть и то, и другое, каждый раздел имеет собственный значок статуса. Если покупок ещё не было, карточка показывает **No purchase yet**.

### Сегменты \{#segments\}

Карточка **Segments** показывает, скольким сегментам соответствует профиль, и перечисляет их; нажмите на любой, чтобы открыть его. Если ни один не совпадает, карточка отображает **Not in any segment**. Adapty Mail заново применяет фильтры при каждом запросе, поэтому список всегда отражает актуальные данные профиля. В разделе [Сегменты](mail-segments) описано, как их создавать.

## История активности \{#the-activity-journey\}

Раздел **Journey** — это хронология всего, что происходило с профилем, начиная с события **Profile created**. События по email и транзакциям отображаются в одном общем списке.

### События электронной почты \{#email-events\}

Каждая запись — одно письмо, отправленное Adapty Mail. Раскройте её, чтобы увидеть ссылки, по которым перешёл получатель, и покупки, совершённые благодаря этому письму. Цветная метка показывает, на каком этапе находится письмо:

| Чип | Что означает |
| --- | --- |
| **Scheduled** | У письма установлено время отправки, и Adapty Mail ещё не отправил его. |
| **Sent** | Adapty Mail отправил письмо, но подтверждения доставки пока нет. |
| **Delivered** | Принимающий почтовый сервер принял письмо. Этот чип заменяет **Sent**. |
| **Opened** | Пиксель отслеживания загружен. |
| **Clicked** | Получатель нажал на ссылку. Разверните письмо, чтобы увидеть, на какие ссылки кликали и какая покупка была совершена. |
| **Confirmed** | Получатель подтвердил свой адрес из письма с [двойным подтверждением подписки](mail-double-opt-in). |
| **Bounced** | Принимающий почтовый сервер отклонил письмо и вернул его. |
| **Spam report** | Получатель отметил письмо как спам. |
| **Unsubscribed** | Получатель отписался. |
| **Delayed** | Принимающий почтовый сервер попросил Adapty Mail повторить попытку позже. |
| **Throttled** | Все отправляющие домены превысили [дневной лимит](mail-suppression#throttle-temporary-delays-and-cancellations), поэтому письмо ожидает отправки. |
| **Cancelled** | Письмо не будет отправлено. Покупка, отписка, bounce, жалоба на спам, удаление или повторный throttle отменяют все оставшиеся письма в последовательности — см. [Причины остановки писем](mail-suppression). |

### События транзакций \{#transaction-events\}

Каждая запись — это веха подписки или разовой покупки. В путешествии вместо сырого значения `event_type` отображается понятная метка:

| `event_type` | Метка Journey |
| --- | --- |
| `subscription_started` | Subscription started |
| `subscription_renewed` | Subscription renewed |
| `subscription_renewal_cancelled` | Renewal cancelled |
| `subscription_renewal_reactivated` | Renewal resumed |
| `billing_issue_detected` | Billing issue |
| `entered_grace_period` | Entered grace period |
| `subscription_expired` | Subscription expired |
| `subscription_refunded` | Subscription refunded |
| `non_subscription_purchase` | One-time purchase |
| `non_subscription_purchase_refunded` | Purchase refunded |

Эти события автоматически поступают в Adapty Mail через SDK Adapty, либо вы можете отправлять их самостоятельно через [API](mail-send-data-via-api#send-transaction-events).

## Отмена подписки профиля \{#unsubscribe-a-profile\}

Чтобы прекратить отправку писем профилю, откройте его страницу, нажмите **...** и выберите **Unsubscribe**. Adapty Mail помечает профиль как отписавшийся и добавляет его в список подавления, поэтому кампании и флоу будут его пропускать.

Если профиль попал в список подавления по любой причине, пункт меню отображается как **Unsubscribed** и становится недоступным. В статье [Причины остановки отправки писем](mail-suppression) описаны два способа, которыми получатели могут отписаться самостоятельно.

## Удаление профиля \{#delete-a-profile\}

Удалите профиль, чтобы стереть все данные о пользователе, хранящиеся в Adapty Mail, — например, в ответ на запрос об удалении данных.

Чтобы удалить профиль, откройте его страницу, нажмите **...**, выберите **Delete** и подтвердите действие. Adapty Mail при этом:

- Удалит email-адрес и все личные атрибуты: имя, пол, дату рождения, страну, страну стора, данные об устройстве и пользовательские атрибуты.
- Отменит все письма, запланированные для этого профиля.
- Удалит профиль со страницы Profiles.

Это действие необратимо. Записи о покупках сохраняются без каких-либо персональных данных, поэтому общие показатели выручки не изменятся.

Удаление не блокирует адрес. Если источник отправит его снова, Adapty Mail создаст новый профиль, не связанный с удалённым. Чтобы навсегда исключить пользователя, нужно остановить передачу его данных на стороне источника.

Ваш бэкенд также может удалять профили через эндпоинт [Delete profile](api-mail/operations/deleteProfile).
