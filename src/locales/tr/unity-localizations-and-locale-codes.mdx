## Bu neden önemli \{#why-this-is-important\}

Locale kodları, Adapty bir flow veya onboarding için yerelleştirme seçerken ve özel bir paywall için remote config okurken devreye girer.

Locale kodları karmaşık olabilir ve platformdan platforma farklılık gösterebilir; bu nedenle Adapty, desteklediği her platformda tek bir iç standarda dayanır. Bu standardı anlamak, bir kullanıcının hangi yerelleştirmeyi alacağını tahmin etmenize yardımcı olur.

## Adapty'deki yerel ayar kodu standardı \{#locale-code-standard-at-adapty\}

Adapty yerel ayar kodları [BCP 47 standardını](https://en.wikipedia.org/wiki/IETF_language_tag) takip eder: bir dil alt etiketi, ardından isteğe bağlı bir komut dosyası veya bölge alt etiketi, kısa çizgilerle ayrılmış olarak. Kodun nerede göründüğü, harf büyüklüğünü belirler:

- **Select languages** alanı tüm kodları küçük harfle gösterir: `pt-br`, `zh-hant`.
- Flow & Paywall Builder'dan yayınlanan flow'lar, büyük harfli bölge ve büyük harfle başlayan komut dosyası içeren kodlara sahiptir: `pt-BR`, `zh-Hant`.
- Eski Paywall Builder'dan gelen paywall'lar tüm kodları küçük harfle saklar: `pt-br`, `zh-hant`.

`en`, `pt` ve `es-419` gibi kodlar her yerde aynı görünür.

## Locale kod eşleştirme \{#locale-code-matching\}

SDK v4'te, flow'lar ve onboarding'ler locale kodlarını farklı şekilde eşleştirir: flow'lar cihazda SDK tarafından, onboarding'ler ise Adapty sunucusu tarafından yerelleştirilir.

### Flow'lar ve paywalllar \{#flows-and-paywalls\}

Adapty'nin render ettiği bir paywall, SDK v4'te flow olarak iletilir; dolayısıyla aşağıdaki kural her ikisi için de geçerlidir.

Eşleşme birebir yapılır. SDK, ilettiğiniz kodu flow'un yerelleştirme kodlarıyla karakter karakter karşılaştırır: büyük-küçük harf dönüşümü yapmaz, alt çizgileri (`_`) kısa çizgilerle (`-`) değiştirmez ve dil alt etiketine geri dönmez. `pt-BR` yerelleştirmesine sahip bir flow için yalnızca `pt-BR` eşleşir: `pt-br`, `pt_BR` ve `pt-PT` bunların hiçbiri eşleşmez.

Kod hiçbir yerelleştirmeyle eşleşmediğinde, flow sessizce [varsayılan yerel ayarında](add-paywall-locale-in-adapty-paywall-builder#set-the-default-locale) görüntülenir — SDK hata döndürmez ve uyarı kaydetmez.

Kod eşleştiğinde ise Adapty, bulunan yerelleştirmeyi varsayılan olanla birleştirir: eşleşen yerelleştirmede tanımlanmayan metin ve varlıklar varsayılan yerelleştirmeden alınır.

Yerel ayar kodunu belirtmemek, flow'un varsayılan yerelleştirmesini istemekle aynı şey değildir: SDK sabit olarak `en` kullanır. Varsayılan yerel ayarı `de` olan bir flow, `en` yerelleştirmesine sahipse `en` dilinde görüntülenir; yalnızca `en` yerelleştirmesi yoksa `de` diline geri döner.

:::warning
Yerel ayar kodunu, yayımlanmış flow'da **Select languages** alanında göründüğü şekliyle tam olarak girin: `pt-br` değil `pt-BR`. Eski Paywall Builder'dan gelen paywall'lar için `pt-br` gibi küçük harfli kodlar kullanın.

Sistem locale tanımlayıcısını olduğu gibi geçirmeyin. İngilizce (Amerika Birleşik Devletleri) olarak ayarlanmış bir cihazda `CultureInfo.CurrentCulture.Name`, `en-US` döndürür; bu da yalnızca `en` içeren bir flow'u kaçırır. Sistem locale tanımlayıcısını geçirmeden önce, flow'un sahip olduğu bir koda dönüştürün.
:::

### Onboarding'ler \{#onboardings\}

Onboarding'ler sunucu tarafında yerelleştirilir ve sunucu kuralları diğer formatları da kabul eder. [`GetOnboarding`](unity-get-onboardings) fonksiyonuna bir `Locale` geçtiğinizde:

1. Locale dizesi küçük harfe dönüştürülür ve tüm alt çizgiler (`_`) kısa çizgiyle (`-`) değiştirilir
2. Adapty, tam olarak eşleşen locale koduyla yerelleştirmeyi arar
3. Eşleşme bulunamazsa, Adapty ilk kısa çizgiden önceki alt dizeyi (`pt-br` için `pt`) alır ve eşleşen yerelleştirmeyi arar
4. Yine eşleşme bulunamazsa, Adapty onboarding'in varsayılan locale'i için içeriği döndürür

Bu sayede `pt_BR`, `pt-BR` ve `pt-br` hepsi aynı onboarding yerelleştirmesine çözümlenir.

## Yerelleştirmeleri Uygulama \{#implementing-localizations\}

SDK v4'te, SDK bir flow görünümü oluşturduğunuzda flow'un tüm yerelleştirmelerini yükler ve gösterilecek olanı aynı çağrıda seçersiniz.

- **Adapty tarafından render edilen flow'lar ve paywall'lar**: SDK cihazın dilini okumaz; bu nedenle uygulamanızda dili belirleyin ve [view oluştururken iletin](#choose-the-localization-of-a-flow). Dil kodu isteğe bağlıdır — belirtmezseniz flow `en` dilinde veya flow'un `en` yerelleştirmesi yoksa varsayılan dilinde render edilir.
- **Özel (remote config) paywall'lar**: `GetFlow`, `flow.RemoteConfigs` içinde yapılandırılmış tüm yerelleştirmeleri döndürür. Her giriş, bir `Locale` kodu ve bir `Dictionary` değerinden oluşan `AdaptyRemoteConfig` nesnesidir. Kullanıcıyla eşleşen girişi kendi yedek mantığınızla seçin:

```csharp showLineNumbers
using System.Linq;
using AdaptySDK;

Adapty.GetFlow("YOUR_PLACEMENT_ID", (flow, error) => {
    if (error != null) {
        // handle the error
        return;
    }

    var config = flow.RemoteConfigs.FirstOrDefault(c => c.Locale == "en")
        ?? flow.RemoteConfigs.FirstOrDefault();
    // read your values from config?.Dictionary
});
```

Adapty, `Locale` kodlarını [Adapty'deki Locale kodu standardı](#locale-code-standard-at-adapty) bölümünde açıklanan biçimde saklar. SDK, remote config'leri bir locale ile eşleştirmez; dolayısıyla hangi girişin uygulanacağına uygulamanız karar verir.

### Bir flow'un yerelleştirmesini seçme \{#choose-the-localization-of-a-flow\}

Bir flow veya paywall'ı belirli bir yerelleştirmeyle oluşturmak için, görünümü oluştururken `SetLocale` metoduna locale kodunu geçin:

```csharp showLineNumbers
var parameters = new AdaptyUICreateFlowViewParameters()
    .SetLocale("pt-BR");

AdaptyUI.CreateFlowView(flow, parameters, (view, error) => {
    if (error != null) {
        // handle the error
        return;
    }

    // view.Locale — the localization the view was built with
});
```

`view.Locale` ile görünüm, gerçekte hangi yerelleştirmeyle oluşturulduğunu raporlar: eğer istediğiniz yerelleştirme mevcutsa o yerelleştirmeyi, aksi takdirde flow'un varsayılan yerelleştirmesini kullanır.

## Bu Neden Önemli \{#why-this-is-important\}

Locale kodlarının devreye girdiği birkaç senaryo vardır — örneğin, uygulamanızın mevcut yerelleştirmesi için doğru paywall'ı çekmeye çalışırken.

Locale kodları karmaşık olabilir ve platformdan platforma farklılık gösterebileceğinden, desteklediğimiz tüm platformlar için dahili bir standarda güveniyoruz. Ancak bu kodlar karmaşık olduğu için, doğru yerelleştirmeyi almak adına sunucumuza tam olarak ne gönderdiğinizi ve bundan sonra ne olduğunu anlamanız son derece önemlidir; böylece her zaman beklediğinizi alırsınız.

## Adapty'de yerel ayar kodu standardı \{#locale-code-standard-at-adapty\}

Adapty, yerel ayar kodları için biraz değiştirilmiş bir [BCP 47 standardı](https://en.wikipedia.org/wiki/IETF_language_tag) kullanır: her kod, kısa çizgilerle ayrılmış küçük harf alt etiketlerden oluşur. Bazı örnekler: `en` (İngilizce), `pt-br` (Portekizce (Brezilya)), `zh` (Basitleştirilmiş Çince), `zh-hant` (Geleneksel Çince).

## Yerel ayar kodu eşleştirme \{#locale-code-matching\}

Adapty, istemci tarafı SDK'dan yerel ayar koduyla birlikte bir çağrı aldığında, paywall'a ait karşılıklı bir yerelleştirme aramaya başlar ve şu adımlar gerçekleşir:

1. Gelen yerel ayar dizesi küçük harfe dönüştürülür ve tüm alt çizgiler (`_`) kısa çizgiyle (`-`) değiştirilir
2. Ardından tam olarak eşleşen yerel ayar koduna sahip yerelleştirme aranır
3. Eşleşme bulunamazsa, ilk kısa çizgiden önceki alt dize alınır (`pt-br` için `pt`) ve eşleşen yerelleştirme aranır
4. Yine eşleşme bulunamazsa, paywall'un varsayılan yerel ayarındaki içerik döndürülür

Bu sayede `'pt_BR'` gönderen bir iOS cihazı, `pt-BR` gönderen bir Android cihazı ve `pt-br` gönderen başka bir cihaz aynı sonucu alır.

## Yerelleştirmeleri uygulama: önerilen yol \{#implementing-localizations-recommended-way\}

Yerelleştirmelerle ilgileniyorsanız, büyük ihtimalle projenizde zaten yerelleştirilmiş string dosyalarıyla çalışıyorsunuzdur. Bu durumda, her dosyanıza ilgili yerelleştirme için amaçlanan Adapty locale kodu ile birlikte bir anahtar-değer çifti eklemenizi öneririz. Ardından SDK'mızı çağırırken bu anahtarın değerini şu şekilde çıkarın:

```csharp showLineNumbers
// 1. Yerelleştirme dosyalarınızı düzenleyin (örneğin, Unity'nin Localization paketini kullanarak)

/*
en.json
*/
{
  "adapty_paywalls_locale": "en"
}

/*
es.json
*/
{
  "adapty_paywalls_locale": "es"
}

/*
pt-BR.json
*/
{
  "adapty_paywalls_locale": "pt-br"
}

// 2. Yerel ayar kodunu çıkarın ve kullanın
using UnityEngine;
using UnityEngine.Localization;
using UnityEngine.Localization.Settings;
using AdaptySDK;

public class PaywallManager : MonoBehaviour
{
    public async void FetchPaywall()
    {
        // Unity'nin Localization sisteminden mevcut yerel ayarı alın
        var locale = LocalizationSettings.SelectedLocale;
        var localeCode = GetAdaptyLocaleCode(locale);
        
        // Yerel ayar kodunu Adapty.GetPaywall veya Adapty.GetPaywallForDefaultAudience metoduna iletin
        Adapty.GetPaywall("placement_id", localeCode, (paywall, error) => {
            if (error != null) {
                // hatayı işle
                return;
            }
            // Paywall'ı kullan
        });
    }
    
    private string GetAdaptyLocaleCode(Locale locale)
    {
        // Unity yerel ayarını Adapty formatına dönüştür
        var localeIdentifier = locale.Identifier.Code;
        return localeIdentifier.ToLower().Replace('_', '-');
    }
}
```

Bu sayede, uygulamanızın her kullanıcısı için hangi yerelleştirmenin getirileceği üzerinde tam kontrole sahip olursunuz.

## Yerelleştirmeleri uygulama: alternatif yöntem \{#implementing-localizations-the-other-way\}

Her yerelleştirme için açıkça bir dil kodu tanımlamak zorunda kalmadan benzer (ama aynı değil) sonuçlar elde edebilirsiniz. Bu yaklaşımda, dil kodunu platformunuzun sunduğu başka nesnelerden çıkarabilirsiniz; örneğin:

```csharp showLineNumbers
using UnityEngine;
using System.Globalization;
using AdaptySDK;

public class PaywallManager : MonoBehaviour
{
    public void FetchPaywall()
    {
        var localeCode = GetSystemLocaleCode();
        
        // Locale kodunu Adapty.GetPaywall veya Adapty.GetPaywallForDefaultAudience metoduna geçirin
        Adapty.GetPaywall("placement_id", localeCode, (paywall, error) => {
            if (error != null) {
                // handle the error
                return;
            }
            // Use the paywall
        });
    }
    
    private string GetSystemLocaleCode()
    {
        // Sistemin mevcut kültür bilgisini al
        var culture = CultureInfo.CurrentCulture;
        var languageCode = culture.TwoLetterISOLanguageName;
        var regionCode = culture.Name.Contains('-') ? culture.Name.Split('-')[1] : null;
        
        if (!string.IsNullOrEmpty(regionCode))
        {
            return $"{languageCode}-{regionCode.ToLower()}";
        }
        
        return languageCode;
    }
}
```

Bu yaklaşımı birkaç nedenden dolayı önermediğimizi belirtmek gerekir:

1. iOS'ta tercih edilen diller ile mevcut yerel ayar (locale) aynı şey değildir. Yerelleştirmenin doğru seçilmesini istiyorsanız, ya yerelleştirilmiş string dosyalarıyla önerilen yaklaşımı kullandığınızda kutudan çıktığı gibi çalışan Apple'ın mantığına güvenmeniz ya da bunu kendiniz yeniden oluşturmanız gerekir.
2. Adapty'nin sunucusunun tam olarak ne alacağını tahmin etmek güçtür. Örneğin iOS'ta, bir cihazda `ar_OM@numbers='latn'` gibi bir yerel ayar elde edip sunucumuza gönderebilirsiniz. Bu durumda aradığınız `ar-om` yerelleştirmesini değil, büyük ihtimalle beklemediğiniz `ar` yerelleştirmesini alırsınız.

Bu yaklaşımı kullanmaya karar verseniz bile — tüm ilgili kullanım durumlarını kapsadığınızdan emin olun.
</SDKv3>
