<SDKv4>

Bir flow veya eski Paywall Builder'da bir paywall oluşturduysanız, bunu kullanıcıya göstermek için mobil uygulama kodunuzda ayrıca render etmenize gerek yoktur. Böyle bir flow, içinde ne gösterileceğini ve nasıl gösterileceğini zaten barındırır.

Başlamadan önce şunlardan emin olun:

1. Bir [flow](paywall-builder-templates) veya [paywall](create-paywall) oluşturdunuz.
2. Bunu bir [placement](placements)'a eklediniz.
3. [Flow'u getirdiniz ve görünümü hazırladınız](capacitor-get-pb-paywalls).

   <CapacitorFlowsRequireIos16 />

:::warning

Bu kılavuz yalnızca **Adapty tarafından render edilen flow'lar ve paywall'lar** içindir; bu özellik SDK v4.0 veya sonrasını gerektirir. Flow'ları sunma süreci, özel paywall'lar için farklıdır.

- Özel paywall'ları sunmak için bkz. [Özel paywall'ları sunma](present-remote-config-paywalls-capacitor).

:::

Bir flow veya paywall'ı bağımsız bir ekran olarak görüntülemek için [`createFlowView`](capacitor-get-pb-paywalls#fetch-the-view-configuration) metoduyla oluşturulan `view` üzerinde `view.present()` metodunu kullanın. Varsayılan olarak, kapatılan bir `view` yok edilir. Flow'u tekrar görüntülemek için `createFlowView`'ı bir kez daha çağırarak yeni bir `view` örneği oluşturun ya da kapatırken [kapatılan flow'u ileride kullanmak üzere saklayın](#keep-a-closed-flow-for-later).

:::warning
Yok edilmiş bir `view`'ı yeniden kullanmak hataya neden olur.
:::

```typescript showLineNumbers

const view = await createFlowView(flow);

// İsteğe bağlı: flow olaylarını yönetin (kapat, satın alma, geri yükleme, vb.)
// await view.setEventHandlers({ ... });

try {
  await view.present();
} catch (error) {
  // hatayı yönetin
}
```

:::important
`setEventHandlers` fonksiyonunu birden fazla kez çağırmak, sağladığınız işleyicilerin üzerine yazar; bu durum hem varsayılan hem de daha önce belirli olaylar için ayarlanmış işleyicilerin yerini alır.
:::

## iOS sunum stilini yapılandırma \{#configure-ios-presentation-style\}

Flow'un iOS'ta nasıl sunulacağını yapılandırmak için `present()` metoduna `iosPresentationStyle` parametresini geçirin. Parametre `'full_screen'` (varsayılan) veya `'page_sheet'` değerlerini kabul eder. Android'de flow'lar her zaman uygulamanızın Activity'si içinde tam ekran gösterilir.

```typescript showLineNumbers
try {
  await view.present({ iosPresentationStyle: 'page_sheet' });
} catch (error) {
  // handle the error
}
```

## Flow'u daha sonra kullanmak için kapalı tutun \{#keep-a-closed-flow-for-later\}

:::info
`destroy` seçeneği ve `destroy()` metodu, SDK 4.3.0 sürümünden itibaren kullanılabilir.
:::

Kullanıcının yakında yeniden açabileceği bir flow'u — örneğin ayarlar ekranınızdaki bir düğmenin arkasındaki paywall — yeniden yüklenmeden ve kaldığı yerden açılması için kapalı tutun.

Varsayılan olarak, `view.dismiss()` flow'u kapatır ve yerel görünümünü yok eder; bu nedenle `view` tekrar sunulamaz. Aynı flow'u daha sonra tekrar sunmak için `destroy: false` parametresini geçin. Bir sonraki `present()` çağrısı, flow'u kullanıcının kapattığı ekranda, bıraktığı durumuyla açar ve olay işleyicileriniz ayarlı kalmaya devam eder:

```typescript showLineNumbers
// Close the flow and keep its native view in memory
await view.dismiss({ destroy: false });

// Later: open the flow again on the same screen
await view.present();
```

Native view, siz serbest bırakana kadar bellekte kalır. Flow'a artık ihtiyacınız yoksa `destroy()` metodunu çağırın:

```typescript showLineNumbers
await view.dismiss({ destroy: false });
// ...
await view.destroy();
```

`destroy()`, view hâlâ ekrandaysa önce onu kapatır ve olay işleyicilerini temizler. Yalnızca `destroy: false` ile kapattığınız bir view için çağırın: normal bir `dismiss()` view'ı kendi başına serbest bırakır ve sonrasında `destroy()` çağırmak başarısız olur.

Sahip olduğu bileşen kaldırıldığında, tutulan view'ı serbest bırakın — Angular'ın `ngOnDestroy` metodunda, React'ın `useEffect` temizliğinde veya Vue'nun `onUnmounted` yaşam döngüsünde. Aksi takdirde native view, oturum boyunca bellekte kalmaya devam eder. Hata yakalamayı unutmayın: view daha önce serbest bırakılmış olabilir; örneğin bir olay işleyicisi `true` döndürdükten sonra.

```typescript showLineNumbers
// For example, in a React useEffect cleanup
return () => {
  view.destroy().catch(() => {
    // the view was already released
  });
};
```

`true` döndüren bir olay işleyicisi, flow'u normal `dismiss()` ile kapatır; bu, native view'ı daha önce korumuş olsanız bile yok eder. Varsayılan `onCloseButtonPress` ve `onError` işleyicileri `true` döndürür. `onAndroidSystemBack` gibi `true` döndürdüğünüz diğer işleyiciler için de aynısı geçerlidir. Kullanıcı kapattığında flow'u korumak istiyorsanız flow'u kendiniz kapatın ve `false` döndürün:

```typescript showLineNumbers
await view.setEventHandlers({
  onCloseButtonPress() {
    view.dismiss({ destroy: false }).catch(error => {
      // handle the error
    });
    return false;
  },
});
```

## Geliştirici tanımlı zamanlayıcıyı kullanma \{#use-developer-defined-timer\}

Bu bölümü, Flow & Paywall Builder'da **Developer defined** davranışına sahip bir zamanlayıcı için kullanın. Builder'da her böyle zamanlayıcının bir **Timer ID**'si vardır (bkz. [Uygulamanızın bitiş tarihini ayarlamasına izin verme](flow-timer#let-your-app-set-the-end-date)) ve uygulamanız bu zamanlayıcı için bitiş tarihini belirler. Kodunuzda, builder'dakiyle aynı Timer ID'yi kullanın; büyük-küçük harf ve boşluklar dahil, karakter karakter aynı olmalı. ID'ler farklıysa zamanlayıcı uygulamanızdan bitiş tarihi alamaz.

Bitiş tarihlerini ayarlamak için `customTimers` parametresini `createFlowView`'a geçirin: her Timer ID'sini bir `Date`'e, yani zamanlayıcının bitiş tarihine eşleyen bir nesnedir.

```typescript showLineNumbers

const customTimers = {
  CUSTOM_TIMER_NY: new Date(new Date().getFullYear() + 1, 0, 1), // next New Year's Day
};

try {
  const view = await createFlowView(flow, { customTimers });
  await view.present();
} catch (error) {
  // handle the error
}
```

Bu örnekte, `CUSTOM_TIMER_NY`, builder'da **Geliştirici tanımlı** bir zamanlayıcının Timer ID'sidir. Zamanlayıcı, bir sonraki Yılbaşı Günü'ne kalan süreyi gösterir; örneğin `13d 09h 03m 34s`.

SDK, `customTimers`'ı yalnızca bir kez, görünümü oluştururken okur; bu nedenle hesapladığınız bir tarih (örneğin şu andan 6 saat sonrası) o andan itibaren sayılmaya başlar. Tarih geçmişte kalırsa zamanlayıcı anında sıfırı gösterir ve **On timer end** tetikleyicisi çalışır. `customTimers`'da bir Timer ID için anahtar yoksa, zamanlayıcı ekran açılışından itibaren bir saat geri sayar.

## İletişim kutusunu göster \{#show-dialog\}

Android'de bir flow görünümü sunulduğunda, native uyarı iletişim kutuları yerine bu yöntemi kullanın. Android'de normal uyarılar, flow görünümünün arkasında görünür ve bu da kullanıcılar tarafından görülememelerine neden olur. Bu yöntem, tüm platformlarda flow'un üzerinde iletişim kutusunun doğru şekilde gösterilmesini sağlar.

```typescript showLineNumbers
try {
  const action = await view.showDialog({
    title: 'Close paywall?',
    content: 'You will lose access to exclusive offers.',
    primaryActionTitle: 'Stay',
    secondaryActionTitle: 'Close',
  });

  if (action === 'secondary') {
    // User confirmed - close the flow
    await view.dismiss();
  }
  // If primary - do nothing, user stays
} catch (error) {
  // handle error
}
```

## Flow'a mesaj gönderme \{#send-messages-to-a-flow\}

Bir flow view'ının `sendAppMessage` metodu, flow'a JSON nesnesi olarak mesaj gönderir. Bu metot, gelecekteki Flow & Paywall Builder özellikleri için ayrılmıştır. Flow'lar bu mesajları yok saydığından metodu çağırmanıza gerek yoktur.

## Bir aboneliği diğeriyle değiştirme \{#replace-one-subscription-with-another\}

Android'de bir kullanıcı aktif bir aboneliği varken yeni bir abonelik satın almaya çalıştığında, flow view oluşturulurken abonelik güncelleme parametreleri geçirerek yeni satın alma işleminin nasıl ele alınacağını kontrol edebilirsiniz. Mevcut aboneliği yenisiyle değiştirmek için `createFlowView` içinde `productPurchaseParams` kullanırken `oldSubVendorProductId` ve `prorationMode` parametrelerini belirtin.

```typescript showLineNumbers

const productPurchaseParams = flow.paywalls
  .flatMap((paywall) => paywall.productIdentifiers)
  .map((productId) => {
    const params: MakePurchaseParamsInput = {};
    if (Capacitor.getPlatform() === 'android') {
      params.android = {
        subscriptionUpdateParams: {
          oldSubVendorProductId: 'PRODUCT_ID_OF_THE_CURRENT_ACTIVE_SUBSCRIPTION',
          prorationMode: 'with_time_proration',
        },
      };
    }
    return { productId, params };
  });

const view = await createFlowView(flow, { productPurchaseParams });
```

<SDKv3>

Paywall Builder kullanarak bir paywall özelleştirdiyseniz, onu kullanıcıya göstermek için mobil uygulama kodunuzda ayrıca render etmeniz gerekmez. Bu tür bir paywall, hem paywall içinde neyin gösterileceğini hem de nasıl gösterileceğini içerir.

:::warning
Bu kılavuz yalnızca eski Paywall Builder ile oluşturulan paywall'lar içindir. Özel paywall'lar sunmak için bkz. [Özel paywall'ları sunma](present-remote-config-paywalls-capacitor).
:::

Bir paywall'ı görüntülemek için, [`createPaywallView`](capacitor-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder) metodu ile oluşturulan `view` üzerinde `view.present()` metodunu kullanın. Her `view` yalnızca bir kez kullanılabilir. Paywall'ı tekrar görüntülemeniz gerekiyorsa, yeni bir `view` örneği oluşturmak için `createPaywallView`'ı bir kez daha çağırın.

:::warning

Aynı `view`'ı yeniden oluşturmadan kullanmak hataya yol açabilir.
:::

```typescript showLineNumbers

const view = await createPaywallView(paywall);

view.setEventHandlers({
  onUrlPress(url) {
    window.open(url, '_blank');
    return false;
  },
});

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

## Geliştirici tanımlı zamanlayıcı kullanma \{#use-developer-defined-timer\}

Mobil uygulamanızda geliştirici tanımlı zamanlayıcıları kullanmak için `timerId` değerini, bu örnekte `CUSTOM_TIMER_NY`'yi kullanın; bu, Adapty kontrol panelinde ayarladığınız geliştirici tanımlı zamanlayıcının **Timer ID**'sidir. Bu sayede uygulamanız zamanlayıcıyı doğru değerle (örneğin, zamanlayıcının bitiş zamanı olan Yılbaşı gününden mevcut zamanın çıkarılmasıyla hesaplanan `13d 09h 03m 34s` gibi) dinamik olarak günceller.

```typescript showLineNumbers
const customTimers = { 'CUSTOM_TIMER_NY': new Date(2025, 0, 1) };

const view = await createPaywallView(paywall, { customTimers });
```

Bu örnekte `CUSTOM_TIMER_NY`, Adapty kontrol panelinde ayarladığınız geliştirici tanımlı zamanlayıcının **Timer ID**'sidir. Zamanlayıcı, uygulamanızın zamanlayıcıyı doğru değerle (örneğin, zamanlayıcının bitiş zamanı olan Yılbaşı gününden mevcut zamanın çıkarılmasıyla hesaplanan `13d 09h 03m 34s` gibi) dinamik olarak güncellemesini sağlar.
