<SDKv4>

Observer mode'da Adapty SDK, mevcut satın alma sisteminiz üzerinden gerçekleştirilen satın almaları kendi başına takip edemez. App store'dan gelen işlemleri kendiniz bildirmeniz gerekir. Analytics'te hata oluşmaması için bunu uygulamanızı yayınlamadan **önce** ayarlamanız kritik önem taşır.

Her işlemi Adapty'nin tanıması için `reportTransaction` kullanarak açıkça bildirin.

:::warning

**İşlem bildirmeyi atlama!**
`reportTransaction` çağrısı yapmazsanız Adapty işlemi tanımaz, işlem analytics'te görünmez ve entegrasyonlara gönderilmez.

:::

Adapty flow'ları ve paywallları kullanıyorsanız, bir işlemi raporlarken `variationId` değerini ekleyin. Bu, satın almayı tetikleyen flow veya paywall ile ilişkilendirir ve doğru analitik verisi sağlar.

:::warning
- Android'de Adapty React Native SDK 4.4.0 veya daha yeni bir sürümünü kullanın. Önceki sürümler `variationId` değerini Adapty'e göndermeyebilir; bu durumda satın alma flow ile ilişkilendirilmez.
- Kullanıcının satın aldığı `AdaptyPaywallProduct` nesnesinin `variationId` değerini geçirin, `AdaptyFlow.variationId` değerini değil. Bir flow'un kendi varyasyon ID'si, satın almayı flow ile ilişkilendirmez.
:::

```typescript showLineNumbers
const variationId = product.variationId; // kullanıcının satın aldığı AdaptyPaywallProduct

try {
    await adapty.reportTransaction(transactionId, variationId);
} catch (error) {
    // `AdaptyError` hatasını işle
}
```

Parametreler:

| Parametre     | Zorunluluk | Açıklama                                                  |
| ------------- | -------- | ------------------------------------------------------------ |
| transactionId | zorunlu | <ul><li> iOS için: İşlemin tanımlayıcısı.</li><li> Android için: Satın almanın string tanımlayıcısı (`purchase.getOrderId`); burada satın alma, billing library [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) sınıfının bir örneğidir.</li></ul> |
| variationId   | isteğe bağlı | Varyantın string tanımlayıcısı. Kullanıcının satın aldığı `AdaptyPaywallProduct`'ın `variationId` değerini geçin. Bu değer, ilgili ürünü içeren `AdaptyFlowPaywall`'ın `variationId` değeriyle aynıdır. |
| ios.jwsTransaction | isteğe bağlı | Yalnızca iOS, SDK 4.3.0 veya üzeri. İmzalı StoreKit 2 işlemi: doğrulama sonucunun `jwsRepresentation` değeri. SDK bunu olduğu gibi Adapty'ye gönderir. Android bu parametreyi yok sayar. |

iOS'ta, satın alma sisteminiz size StoreKit 2 transaction'ı veriyorsa, JWS temsilini üçüncü argümana geçirin:

```typescript showLineNumbers
await adapty.reportTransaction(transactionId, variationId, {
  ios: { jwsTransaction },
});
```

Gözlemci modunda, Adapty SDK kendi başına mevcut satın alma sisteminiz üzerinden gerçekleştirilen satın almaları takip edemez. App Store veya Google Play'den gelen işlemleri manuel olarak bildirmeniz ya da geri yüklemeniz gerekir. Analitik hatalarını önlemek için uygulamanızı yayına almadan **önce** bu yapılandırmayı tamamlamanız kritik önem taşır.

Her işlemi açıkça bildirmek için her iki platformda da `reportTransaction` kullanın; Adapty'nin işlemi tanımasını sağlamak için Android'de ek bir adım olarak `restorePurchases` kullanın.

:::warning

**İşlem raporlamayı atlama!**
Bu metodları çağırmazsanız, Adapty işlemi tanımaz, işlem analizlerde görünmez ve entegrasyonlara gönderilmez.

:::

Adapty flow'ları ve paywall'larını kullanıyorsanız, işlem raporlarken `variationId` değerini ekleyin. Bu, satın almayı tetikleyen flow veya paywall ile ilişkilendirir ve doğru analitik verisi sağlar.

```typescript showLineNumbers
if (Platform.OS === 'android') {
    try {
        await adapty.restorePurchases();
    } catch (error) {
        // handle the error
    }
}

...

const variationId = paywall.variationId;

try {
    await adapty.reportTransaction(transactionId, variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```

**Flow'ları ve paywall'ları işlemlerle ilişkilendirme**

Adapty SDK, satın almaların kaynağını belirleyemez; çünkü bunları işleyen sizsiniz. Bu nedenle, Observer modu'nda flow'lar, paywall'lar ve/veya A/B testleri kullanmayı planlıyorsanız, uygulama mağazanızdan gelen işlemi (transaction) mobil uygulama kodunuzda ilgili flow veya paywall ile ilişkilendirmeniz gerekir. Uygulamanızı yayınlamadan önce bunu doğru şekilde yapmak önemlidir; aksi takdirde analitikte hatalara yol açacaktır.

```typescript 
const variationId = paywall.variationId;

try {
    await adapty.setVariationId('transactionId', variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```
