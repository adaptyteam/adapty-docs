Observer mode'da, Adapty SDK mevcut satın alma sisteminiz üzerinden gerçekleştirilen satın almaları kendi başına takip edemez. App Store'daki işlemleri uygulamanızdan bildirmeniz gerekir. Analytics'te hata oluşmaması için bunu uygulamanızı yayına almadan **önce** ayarlamanız kritik önem taşır.

Her işlemi Adapty'nin tanıyabilmesi için açıkça bildirmek amacıyla `reportTransaction` kullanın.

:::warning

**İşlem raporlamayı atlamayın!**
`reportTransaction` çağırmazsanız Adapty işlemi tanımaz, işlem analizlerde görünmez ve entegrasyonlara gönderilmez.

:::

Adapty paywallları kullanıyorsanız, işlem raporlarken `variationId` değerini ekleyin. Bu, satın almayı tetikleyen paywalla bağlar ve paywall analizlerinin doğru olmasını sağlar.

```typescript showLineNumbers
const variationId = paywall.variationId;

try {
    await adapty.reportTransaction(transactionId, variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```

Parametreler:

| Parametre     | Zorunluluk | Açıklama                                                  |
| ------------- | -------- | ------------------------------------------------------------ |
| transactionId | zorunlu | <ul><li> iOS için: İşlemin tanımlayıcısı.</li><li> Android için: Satın alma işleminin string tanımlayıcısı (`purchase.getOrderId`); burada satın alma, billing library [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) sınıfının bir örneğidir.</li></ul> |
| variationId   | isteğe bağlı | Varyantın string tanımlayıcısı. Bunu `AdaptyPaywall` nesnesinin `variationId` özelliğini kullanarak alabilirsiniz. |

Observer modunda, Adapty SDK'sı mevcut satın alma sisteminiz aracılığıyla yapılan satın almaları kendi başına takip edemez. App Store veya uygulamanızdaki işlemleri raporlamanız ya da geri yüklemeniz gerekir. Analizlerde hata oluşmaması için bunu uygulamanızı yayınlamadan **önce** ayarlamanız kritik önem taşır.

Her işlemi açıkça raporlamak için her iki platformda da `reportTransaction` kullanın; Adapty'nin bunu tanıdığından emin olmak için ek bir adım olarak Android'de `restorePurchases` kullanın.

:::warning

**İşlem raporlamayı atlama!**
Bu metotları çağırmazsanız Adapty işlemi tanımaz, işlem analizlerde görünmez ve integrasyonlara gönderilmez.

:::

Adapty paywall'larını kullanıyorsanız, işlem raporlarken `variationId` değerini ekleyin. Bu, satın almayı tetikleyen paywall'a bağlar ve paywall analizlerinin doğru olmasını sağlar.

```typescript showLineNumbers
if (Platform.OS === 'android') {
    try {
        await adapty.restorePurchases();
    } catch (error) {
        // handle the error
    }
}

...

const variationId = paywall.variationId;

try {
    await adapty.reportTransaction(transactionId, variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```

Parametreler:

| Parametre     | Zorunluluk | Açıklama                                                  |
| ------------- | ---------- | ------------------------------------------------------------ |
| transactionId | zorunlu | <ul><li> iOS, StoreKit 1 için: bir [SKPaymentTransaction](https://developer.apple.com/documentation/storekit/skpaymenttransaction) nesnesi.</li><li> iOS, StoreKit 2 için: [Transaction](https://developer.apple.com/documentation/storekit/transaction) nesnesi.</li><li> Android için: satın almanın String tanımlayıcısı (`purchase.getOrderId`); burada satın alma, billing library [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) sınıfının bir örneğidir.</li></ul> |
| variationId   | isteğe bağlı | Varyantın string tanımlayıcısı. `AdaptyPaywall` nesnesinin `variationId` özelliğini kullanarak elde edebilirsiniz. |

**Paywallların işlemlerle ilişkilendirilmesi**

Adapty SDK, satın almaların kaynağını belirleyemez çünkü onları işleyen sizsiniz. Bu nedenle, Observer modunda paywall ve/veya A/B testi kullanmayı düşünüyorsanız, uygulama mağazanızdan gelen işlemi (transaction) mobil uygulama kodunuzda ilgili paywall ile ilişkilendirmeniz gerekir. Bu, uygulamanızı yayınlamadan önce doğru yapılması gereken önemli bir adımdır; aksi takdirde analizlerde hatalara yol açacaktır.

```typescript 
const variationId = paywall.variationId;

try {
    await adapty.setVariationId('transactionId', variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```

İstek parametreleri:

| Parametre     | Zorunluluk | Açıklama                                                  |
| ------------- | -------- | ------------------------------------------------------------ |
| transactionId | zorunlu | <p>iOS, StoreKit 1 için: bir [SKPaymentTransaction](https://developer.apple.com/documentation/storekit/skpaymenttransaction) nesnesi.</p><p>iOS, StoreKit 2 için: [Transaction](https://developer.apple.com/documentation/storekit/transaction) nesnesi.</p><p>Android için: String tanımlayıcı (satın almanın purchase.getOrderId değeri; burada purchase, billing library [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) sınıfının bir örneğidir).</p> |
| variationId   | zorunlu | Varyantın string tanımlayıcısı. `AdaptyPaywall` nesnesinin `variationId` özelliği kullanılarak elde edilebilir. |
