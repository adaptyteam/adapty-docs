Uygulama içi satın almaları etkinleştirmek için üç temel kavramı anlamanız gerekir:

- [**Ürünler**](product) – kullanıcıların satın alabileceği her şey (abonelikler, consumable'lar, süresiz erişim)
- [**Flow'lar & paywall'lar**](adapty-flow-builder) – ürünleri kullanıcılara sunan ekranlar; no-code Flow & Paywall Builder ile oluşturulur. SDK bunları `getFlow` aracılığıyla getirir. Arayüzü kendi kodunuzla oluşturmayı tercih ediyorsanız [Özel paywall uygulama](flutter-quickstart-manual) bölümüne bakın.
- [**Placement'lar**](placements) – uygulamanızda flow'ları & paywall'ları nerede ve ne zaman göstereceğiniz (`main`, `onboarding`, `settings` gibi). Bunları kontrol panelindeki placement'lara bağlar, ardından kodunuzda placement ID'siyle talep edersiniz. Bu sayede A/B testi yapmak ve farklı kullanıcılara farklı içerikler göstermek kolaylaşır.

Adapty, uygulamanızda satın almaları etkinleştirmek için size üç yol sunar. Uygulama gereksinimlerinize göre birini seçin:

| Uygulama         | Karmaşıklık | Ne zaman kullanılır                                                                                                                                                                                                                                |
|------------------------|------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Adapty Flow & Paywall Builder | ✅ Kolay     | No-code builder'da [eksiksiz, satın almaya hazır bir flow veya paywall oluşturursunuz](quickstart-paywalls). Adapty bunu otomatik olarak render eder ve tüm karmaşık satın alma mantığını, makbuz doğrulamasını ve abonelik yönetimini arka planda halleder. |
| Özel paywalllar | 🟡 Orta  | Paywall arayüzünüzü uygulama kodunuzda kendiniz oluşturursunuz, ancak ürün tekliflerinde esnekliği korumak için flow nesnesini Adapty'den alırsınız. [Kılavuza](flutter-quickstart-manual) bakın.                                                     |
| Observer mode              | 🔴 Zor    | Zaten kendi satın alma altyapınız var ve bunu kullanmaya devam etmek istiyorsunuz. Observer mode'un Adapty'de bazı kısıtlamaları olduğunu unutmayın. [Makaleye](observer-vs-full-mode) bakın.                                                 |

:::important
**Aşağıdaki adımlar, Adapty Flow & Paywall Builder'da oluşturulan bir flow veya paywall'ın nasıl uygulanacağını göstermektedir.**

Paywall arayüzünü kendiniz oluşturmayı tercih ediyorsanız, [Özel paywall'ları uygulama](flutter-quickstart-manual) sayfasına bakın.
:::

Adapty Flow & Paywall Builder'da oluşturulan bir flow veya paywall'ı uygulamanızda görüntülemek için yalnızca şunları yapmanız gerekir:

1. **Flow veya paywall'ı alın**: Adapty'den alın.
2. **Görüntüleyin, satın alma işlemlerini Adapty yönetir**: Görünümü uygulamanızda gösterin.
3. **Buton eylemlerini yönetin**: Kullanıcı etkileşimlerini uygulamanızın yanıtlarıyla ilişkilendirin. Örneğin, kullanıcılar butonlara tıkladığında bağlantıları açın veya paywall'ı kapatın.

## Başlamadan Önce \{#before-you-start\}

Başlamadan önce şu adımları tamamlayın:

1. Uygulamanızı Adapty Kontrol Paneli'nde [App Store](initial_ios) ve/veya [Google Play](initial-android) ile bağlayın.
2. Adapty'de [ürünlerinizi oluşturun](create-product).
3. [Bir flow veya paywall oluşturun](paywall-builder-templates) ve [ürünleri ekleyin](paywall-product-block).
4. [Bir placement oluşturun ve flow veya paywall'ınızı ekleyin](create-placement).
5. Uygulama kodunuza [Adapty SDK'yı yükleyin ve etkinleştirin](sdk-installation-flutter). Bu kılavuz Adapty Flutter SDK v4 API'lerini kullanır.

:::tip
Bu adımları tamamlamanın en hızlı yolu, [hızlı başlangıç kılavuzunu](quickstart) takip etmek veya [Developer CLI](developer-cli-quickstart) kullanarak paywall'lar ve placement'lar oluşturmaktır.
:::

## 1. Flow veya paywall'ı alın \{#1-get-the-flow-or-paywall\}

Flow'larınız ve paywall'larınız, kontrol panelinde yapılandırılmış placement'larla ilişkilendirilir. Placement'lar, farklı kitleler için farklı flow'lar veya paywall'lar çalıştırmanıza ya da [A/B testleri](ab-tests) yapmanıza olanak tanır.

Adapty Flow & Paywall Builder'da oluşturulmuş bir flow veya paywall almak için şunları yapmanız gerekir:

1. `getFlow` metodunu kullanarak [placement](placements) ID'sine göre `flow` nesnesini alın ve `hasViewConfiguration` özelliğini kullanarak bunun builder'da oluşturulup oluşturulmadığını kontrol edin.

2. `createFlowView` metodunu kullanarak flow view'ını oluşturun. View, görüntülenmesi için gereken UI elementlerini ve stilleri içerir.

:::important
View yapılandırmasını almak için [flow veya paywall'ı yayınlayın](builder-save-publish). Yayınlanmamış düzenlemeleri olan bir flow veya paywall **Dirty** statüsüne sahip olur ve placement'ı en son yayınlanan sürümü sunmaya devam eder.
:::

```dart showLineNumbers

try {
  // the requested flow
  final flow = await Adapty().getFlow(placementId: 'YOUR_PLACEMENT_ID');
  final view = await AdaptyUI().createFlowView(
    flow: flow,
  );
} on AdaptyError catch (adaptyError) {
  // handle the error
} catch (e) {
  // handle the error
}
```

## 2. Flow veya paywallı görüntüleme \{#display-the-flow-or-paywall\}

Artık flow view'ına sahip olduğunuzda, görüntülemek için yalnızca birkaç satır eklemeniz yeterli.

Flow'u görüntülemek için `createFlowView` metoduyla oluşturulan `view` üzerinde `view.present()` metodunu kullanın. Her `view` yalnızca bir kez gösterilebilir: kapattıktan sonra view bellekten serbest bırakılır. Flow'u tekrar görüntülemeniz gerekirse, yeni bir `view` örneği oluşturmak için `createFlowView` metodunu bir kez daha çağırın.

```dart showLineNumbers title="Flutter"
try {
  await view.present();
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

:::tip
Bir flow veya paywall'ı nasıl görüntüleyeceğiniz hakkında daha fazla bilgi için [kılavuzumuza](flutter-present-paywalls) bakın.
:::

## 3. Düğme eylemlerini yönetin \{#handle-button-actions\}

Kullanıcılar flow veya paywall içindeki düğmelere tıkladığında Flutter SDK; satın alma, geri yükleme, görünümü kapatma ve URL açma işlemlerini otomatik olarak yönetir. Ancak diğer düğmeler özel veya önceden tanımlanmış ID'lere sahiptir ve bu eylemlerin kodunuzda yönetilmesi gerekir.

Flow ekranındaki süreçleri kontrol etmek veya izlemek için `AdaptyUIFlowsEventsObserver` metodlarını uygulayın ve herhangi bir ekran gösterilmeden önce gözlemciyi ayarlayın. Kullanıcı bir eylem gerçekleştirirse `flowViewDidPerformAction` tetiklenir ve uygulamanızın eylem ID'sine göre yanıt vermesi gerekir.

Üç observer yöntemi **zorunludur**: `flowViewDidFinishPurchase`, `flowViewDidFinishRestore` ve `flowViewDidReceiveError` — bunlar olmadan sınıfınız derlenmez.

:::tip
Buton [aksiyonlarını](flutter-handle-paywall-actions) ve [olayları](flutter-handling-events) nasıl yöneteceğinize dair kılavuzlarımızı okuyun.
:::

Gözlemciyi, bir widget'a bağlamak yerine bağımsız ve uzun ömürlü bir nesne olarak uygulayın. Uygulama genelinde tek bir global gözlemci slotu paylaşıldığından, bunu bir `State`'e bağlamak ekranı sızdırır (SDK ona güçlü bir referans tutar) ve bir sonraki ekran kendini kaydettiğinde sessizce değiştirilir. `extends` kullanmak aynı zamanda SDK'nın varsayılan davranışını miras aldığından, üç zorunlu metodun yanı sıra yalnızca önem verdiğiniz callback'leri override etmeniz yeterlidir.

```dart showLineNumbers title="Flutter"
// A dedicated, long-lived handler for flow events.
// It does NOT live inside a Widget/State, so it never leaks and is never
// silently replaced when screens are pushed or popped.
class FlowEventsHandler extends AdaptyUIFlowsEventsObserver {
  // A single, app-wide instance — same idiom as Adapty() and AdaptyUI().
  static final FlowEventsHandler _instance = FlowEventsHandler._();
  factory FlowEventsHandler() => _instance;
  FlowEventsHandler._();

  // This method is called when user performs an action on the flow UI.
  // Overriding it replaces the default behavior (dismiss on close, open URLs),
  // so keep those cases if you want to preserve it.
  @override
  void flowViewDidPerformAction(AdaptyUIFlowView view, AdaptyUIAction action) {
    switch (action) {
      case const CloseAction():
      case const AndroidSystemBackAction(): // close the flow on the Android back button
        view.dismiss();
        break;
      case OpenUrlAction(:final url, :final openIn):
        AdaptyUI().openUrl(url, openIn: openIn);
        break;
      default:
        break;
    }
  }

  // Required: decide what happens after a purchase finishes
  @override
  void flowViewDidFinishPurchase(AdaptyUIFlowView view,
      AdaptyPaywallProduct product, AdaptyPurchaseResult purchaseResult) {
    if (purchaseResult is! AdaptyPurchaseResultUserCancelled) {
      view.dismiss();
    }
  }

  // Required: dismiss the flow once a restore succeeds
  @override
  void flowViewDidFinishRestore(AdaptyUIFlowView view, AdaptyProfile profile) {
    view.dismiss();
  }

  // Required: handle rendering and other view errors
  @override
  void flowViewDidReceiveError(AdaptyUIFlowView view, AdaptyError error) {
    print('Flow error: $error');
    view.dismiss();
  }
}
```

**Uygulama başlangıcında**, herhangi bir flow veya paywall gösterilmeden önce işleyiciyi **bir kez** kaydedin:

```dart showLineNumbers title="Flutter"
AdaptyUI().setFlowsEventsObserver(FlowEventsHandler());
```

## Tam örnek \{#full-example\}

Tüm bu adımların uygulamanızda birlikte nasıl entegre edileceğini aşağıda görebilirsiniz.

```dart

void main() {
  // Register a single, long-lived observer once, before any flow is shown.
  // It is intentionally a plain object (NOT a Widget/State): its lifetime is the
  // whole app, so it never leaks and is never silently replaced when screens are
  // pushed or popped.
  AdaptyUI().setFlowsEventsObserver(FlowEventsHandler());

  runApp(MaterialApp(home: FlowScreen()));
}

/// A dedicated handler for AdaptyUI flow events.
///
/// It `extends` [AdaptyUIFlowsEventsObserver] (rather than being implemented
/// by a `State`), which gives you two things for free:
///   * the SDK's sensible defaults for optional callbacks, so besides the three
///     required methods you only override what you actually care about;
///   * a lifecycle that is independent of the widget tree — there is no strong
///     reference back into a `Widget`, so nothing leaks and there is nothing to
///     unregister.
///
/// Every callback receives the [AdaptyUIFlowView] it relates to, so handling
/// flow actions never requires a `BuildContext` or widget state.
class FlowEventsHandler extends AdaptyUIFlowsEventsObserver {
  // A single, app-wide instance — same idiom as Adapty() and AdaptyUI().
  static final FlowEventsHandler _instance = FlowEventsHandler._();
  factory FlowEventsHandler() => _instance;
  FlowEventsHandler._();

  // Called when the user performs an action on the flow UI.
  @override
  void flowViewDidPerformAction(AdaptyUIFlowView view, AdaptyUIAction action) {
    switch (action) {
      case const CloseAction():
      case const AndroidSystemBackAction(): // close the flow on the Android back button
        view.dismiss();
        break;
      case OpenUrlAction(:final url, :final openIn):
        // Open the URL natively, honoring the dashboard browser setting.
        AdaptyUI().openUrl(url, openIn: openIn);
        break;
      default:
        break;
    }
  }

  // Required: decide what happens after a purchase finishes.
  @override
  void flowViewDidFinishPurchase(AdaptyUIFlowView view,
      AdaptyPaywallProduct product, AdaptyPurchaseResult purchaseResult) {
    if (purchaseResult is! AdaptyPurchaseResultUserCancelled) {
      view.dismiss();
    }
  }

  // Required: dismiss the flow once a restore succeeds.
  @override
  void flowViewDidFinishRestore(AdaptyUIFlowView view, AdaptyProfile profile) {
    view.dismiss();
  }

  // Required: handle rendering and other view errors.
  @override
  void flowViewDidReceiveError(AdaptyUIFlowView view, AdaptyError error) {
    print('Flow error: $error');
    view.dismiss();
  }
}

class FlowScreen extends StatefulWidget {
  const FlowScreen({super.key});

  @override
  State<FlowScreen> createState() => _FlowScreenState();
}

class _FlowScreenState extends State<FlowScreen> {
  @override
  void initState() {
    super.initState();
    _showFlowIfNeeded();
  }

  Future<void> _showFlowIfNeeded() async {
    try {
      final flow = await Adapty().getFlow(
        placementId: 'YOUR_PLACEMENT_ID',
      );

      if (!flow.hasViewConfiguration) return;

      final view = await AdaptyUI().createFlowView(flow: flow);

      await view.present();
    } catch (_) {
      // Handle any errors (network, SDK issues, etc.)
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Adapty Flow Example')),
      body: Center(
        // Add a button to re-trigger the flow for testing purposes.
        child: ElevatedButton(
          onPressed: _showFlowIfNeeded,
          child: const Text('Show Flow'),
        ),
      ),
    );
  }
}
```
