Adapty Unity SDK 4.1, 4.x serisinin ilk kararlı sürümüdür — 4.0 yalnızca beta olarak yayımlandığından, 3.x kullanıyorsanız doğrudan 4.1'e geçin. Bu kılavuz, 4.0'da sunulan flow'ları ve bunların üzerine gelen 4.1 değişikliklerinin tamamını kapsamaktadır.

4.x sürümü, flow'ları tanıtıyor ve paywall API'larını buna uygun şekilde yeniden adlandırıyor. Yeni API'lar hem yeni Flow Builder hem de mevcut Paywall Builder ile çalışıyor — Adapty Kontrol Paneli tarafında herhangi bir kurulum değişikliği gerekmiyor. Bunun yanı sıra 4.1, harici attribution API'larını yeniden adlandırıyor, Adapty Attribution'ı opt-in hale getiriyor, zorunlu bir listener metodu ekliyor ve yedek paywall dosya formatını değiştiriyor.

:::note
4.0 beta'dan mı geliyorsunuz? Sabitlenmiş beta etiketini [4.1.0 kurulumu](#installation) ile değiştirin; ardından yalnızca dört bölüm geçerlidir: [yeni listener metodu](#new-required-method-onreceivepromotedpurchase), [yeniden adlandırılmış harici attribution API'leri](#renamed-external-attribution-apis), [Adapty Attribution varsayılan olarak devre dışı](#adapty-attribution-is-disabled-by-default) ve [yedek dosyalar](#fallback-files).
:::

Satın alma ve profil API'leri (`MakePurchase`, `RestorePurchases`, `GetProfile`, `Identify`, `UpdateProfile`) değişmemiştir. `SetFallback` imzasını korur, ancak okuduğu dosyanın yeniden indirilmesi gerekir — bkz. [Yedek dosyalar](#fallback-files). Onboarding metodları hâlâ çalışır ancak kullanımdan kaldırılmıştır — bkz. [Onboarding API kullanımdan kaldırma](#onboarding-api-deprecation). Bazı varsayılan davranışlar değişti — bkz. [Varsayılan davranış değişiklikleri](#default-behavior-changes).

## Kurulum \{#installation\}

SDK 4.1'i Unity Package Manager aracılığıyla yüklemek için Git URL'sine versiyon etiketini ekleyin:

```
https://github.com/adaptyteam/AdaptySDK-Unity.git?path=/Packages/com.adapty.unity-sdk#4.1.0
```

Unity paketi aracılığıyla yüklemek istiyorsanız, `adapty-unity-plugin-4.1.0.unitypackage` dosyasını [4.1.0 sürümünden](https://github.com/adaptyteam/AdaptySDK-Unity/releases/tag/4.1.0) indirin. Tam kurulum için [Adapty SDK'yı Yükleyin](sdk-installation-unity#install-adapty-sdk) sayfasına bakın.

4.x ile birlikte iki derleme kurulumu değişikliği geldi:

- **iOS bağımlılıkları Swift Package Manager'a geçiyor.** Yerel Adapty iOS SDK'sı, bir CocoaPods pod'u yerine uzak bir Swift paketi olarak tanımlanıyor. [External Dependency Manager](https://github.com/googlesamples/unity-jar-resolver#getting-started)'ı **1.2.188 veya üzeri** bir sürüme güncelleyin — önceki sürümler Swift Package Manager bağımlılıklarını desteklemiyor. CocoaPods adımları (`iOS Resolver -> Install Cocoapods`, `Unity-iPhone.xcworkspace` açma) artık geçerli değil.
- **iOS deployment target 15.0 veya üzeri olmalıdır.** Unity Editor'daki yeni bir derleme doğrulayıcı, hedef daha düşükse iOS derlemesini durduruyor.

Altta yatan yerel Adapty SDK'ları her iki platformda da otomatik olarak 4.x sürümüne güncellenir; başka bir derleme değişikliğine gerek yoktur.

## Flow'ları çekme \{#fetching-flows\}

### GetPaywall → GetFlow

Döndürülen tür `AdaptyPaywall`'dan `AdaptyFlow`'a değişir ve `locale` parametresi kaldırılır — bir flow render ettiğinizde, locale otomatik olarak belirlenir; özel paywalllar için tüm locale'ler `flow.RemoteConfigs` içinde döndürülür:

```diff showLineNumbers
- Adapty.GetPaywall("YOUR_PLACEMENT_ID", "en", (paywall, error) => {
+ Adapty.GetFlow("YOUR_PLACEMENT_ID", (flow, error) => {
      if (error != null) {
          // handle the error
          return;
      }
-     // use the paywall
+     // use the flow
  });
```

`GetPaywallForDefaultAudience` aynı şekilde yeniden adlandırıldı:

```diff showLineNumbers
- Adapty.GetPaywallForDefaultAudience("YOUR_PLACEMENT_ID", "en", (paywall, error) => { /* ... */ });
+ Adapty.GetFlowForDefaultAudience("YOUR_PLACEMENT_ID", (flow, error) => { /* ... */ });
```

### GetPaywallProducts(paywall) → GetPaywallProducts(flow)

`GetPaywallProducts` adını korur ancak artık bir `AdaptyFlow` alır:

```diff showLineNumbers
- Adapty.GetPaywallProducts(paywall, (products, error) => {
+ Adapty.GetPaywallProducts(flow, (products, error) => {
      if (error != null) {
          // handle the error
          return;
      }
      // use the products
  });
```

## Veri modeli \{#data-model\}

`GetFlow`, bir `AdaptyPaywall` yerine `AdaptyFlow` döndürür ve nesne yapısı değişti:

| v3 `AdaptyPaywall` özelliği | v4 `AdaptyFlow` özelliği | İşlem |
|---|---|---|
| `RemoteConfig` (tekil, null olabilir) | `RemoteConfigs` (liste) | Bir flow, yapılandırılmış her dil için ayrı bir remote config taşır. `flow.RemoteConfigs` içinden kullanıcıya uyan olanı okuyun. `flow.RemoteConfig` kısayolu ilk girişi döndürür. |
| _(yeni)_ | `Paywalls` (`AdaptyFlowPaywall` listesi) | Her giriş, flow içindeki bir paywall varyasyonunu temsil eder; kendi `Name`, `VariationId` ve `ProductIdentifiers` değerlerine sahiptir. Web paywall metotları bir `AdaptyFlowPaywall` alır — bkz. [Web paywall metotları](#web-paywall-methods). |
| `ProductIdentifiers`, `VendorProductIds` | korundu | `AdaptyFlow` üzerinde bu değerler, tüm paywall varyasyonlarındaki ürünleri bir araya getirir. Her varyasyon kendi `ProductIdentifiers` ve `VendorProductIds` değerlerini de sunar. Ürünleri çekmek için `GetPaywallProducts(flow)` çağrısını kullanmaya devam edin. |
| `HasViewConfiguration` | kaldırıldı | Kodunuzdaki `HasViewConfiguration` kontrollerini kaldırın — bunun yerine `CreateFlowView` hata döndürür (bkz. [Flow'ları görüntüleme](#displaying-flows)). |
| `Products` (`AdaptyProductReference` listesi) | kaldırıldı | `AdaptyProductReference` artık herkese açık değil; bununla birlikte taşıdığı `PromotionalOfferId`, `WinBackOfferId` ve `AndroidOfferId` değerleri de kaldırıldı. `VendorProductId` ve yalnızca Android'e özgü `BasePlanId` (v3'teki `AndroidBasePlanId`) içeren `AdaptyProductIdentifier` listesi olan `ProductIdentifiers`'ı kullanın — ya da fiyatlar ve tekliflerle birlikte tam `AdaptyPaywallProduct` nesnelerine ihtiyaç duyduğunuzda `GetPaywallProducts(flow)` çağırın. |
| `RemoteConfigString` | kaldırıldı | Dizeyi doğrudan remote config'den okuyun: `flow.RemoteConfig?.Data` veya `flow.RemoteConfigs` içindeki ilgili giriş. |
| _(yeni)_ | `FlowVersionId` (null olabilir) | Flow'un sürüm tanımlayıcısı; mevcut olmadığında `null` döner. |

`AdaptyPaywallProduct` bir alan kazanır: `FlowProductId`, ürünün flow içindeki tanımlayıcısıdır; bir flow'a ait olmayan ürünler için `null` değerini alır.

## Web paywall metodları \{#web-paywall-methods\}

`OpenWebPaywall` ve `CreateWebPaywallUrl` isimlerini korur, ancak `paywall` argümanı artık `flow.Paywalls` içindeki varyantlardan biri olan bir `AdaptyFlowPaywall` alır. Bunun yerine yine de `AdaptyPaywallProduct` geçirebilirsiniz:

```diff showLineNumbers
- Adapty.OpenWebPaywall(paywall, AdaptyWebPresentation.ExternalBrowser, (error) => { /* ... */ });
+ var flowPaywall = flow.Paywalls.FirstOrDefault();
+ if (flowPaywall != null) {
+     Adapty.OpenWebPaywall(flowPaywall, AdaptyWebPresentation.ExternalBrowser, (error) => { /* ... */ });
+ }
```

## Flow görüntülemelerini takip etme \{#tracking-flow-views\}

### LogShowPaywall → LogShowFlow

`LogShowPaywall`, `LogShowFlow` olarak yeniden adlandırıldı ve artık bir `AdaptyFlow` alıyor. Olay hâlâ aynı varyasyona karşı kaydedildiğinden, mevcut dönüşüm hunisi ve A/B testi metrikleri kontrol panelinde herhangi bir değişiklik yapılmadan çalışmaya devam eder.

```diff showLineNumbers
- Adapty.LogShowPaywall(paywall, (error) => { /* ... */ });
+ Adapty.LogShowFlow(flow, (error) => { /* ... */ });
```

v3'te olduğu gibi, [Flow Builder](adapty-flow-builder) veya [Paywall Builder](adapty-paywall-builder) tarafından oluşturulan flow'ları ya da paywall'ları görüntülerken bu metodu çağırmanıza gerek yoktur — Adapty bu görüntülemeleri otomatik olarak takip eder.

## Flow'ları Görüntüleme \{#displaying-flows\}

### CreatePaywallView → CreateFlowView

Factory metodunu yeniden adlandırın ve `AdaptyFlow`'u iletin. Döndürülen view türü `AdaptyUIPaywallView`'dan `AdaptyUIFlowView`'a yeniden adlandırıldı, ancak metodları (`Present`, `Dismiss`) değişmedi ve isteğe bağlı parametreler nesnesi aynı alanları (`LoadTimeout`, `PreloadProducts`, `CustomTags`, `CustomTimers`, `CustomAssets`, `ProductPurchaseParameters`) yeni `AdaptyUICreateFlowViewParameters` adıyla korur, ayrıca iki yeni alan eklenmiştir — `Locale` ve `EnableSafeAreaPaddings`:

```diff showLineNumbers
- AdaptyUI.CreatePaywallView(paywall, parameters, (view, error) => {
+ AdaptyUI.CreateFlowView(flow, parameters, (view, error) => {
      if (error != null) {
          // handle the error
          return;
      }
      view.Present((error) => { /* handle the error */ });
  });
```

`CreateFlowView`, flow'da yapılandırılmış bir görünüm yoksa hata döndürür — bu, v3'teki `HasViewConfiguration` kontrolünün yerini alır:

```diff showLineNumbers
- if (paywall.HasViewConfiguration) {
-     AdaptyUI.CreatePaywallView(paywall, null, (view, error) => { /* ... */ });
- }
+ AdaptyUI.CreateFlowView(flow, (view, error) => {
+     if (error != null) {
+         // the flow has no view configured, or view creation failed
+         return;
+     }
+     view.Present((error) => { /* handle the error */ });
+ });
```

:::note
Flow view tek kullanımlıktır: `Dismiss` çağrıldıktan sonra view yok edilir; flow'u tekrar göstermek için `CreateFlowView` fonksiyonunu tekrar çağırmanız gerekir.
:::

### Android güvenli alan dolguları \{#android-safe-area-paddings\}

`AdaptyUICreateFlowViewParameters`, Android güvenli alan dolgularını çalışma zamanında kontrol eden `EnableSafeAreaPaddings` özelliğini ekler. iOS'ta yok sayılır ve varsayılan değeri `true`'dur:

```csharp showLineNumbers
var parameters = new AdaptyUICreateFlowViewParameters()
    .SetEnableSafeAreaPaddings(false);
```

## Olayları İşleme \{#handling-events\}

Dinleyici arayüzleri artık C# I- ön eki kuralını takip ediyor ve eski takma adlar korunmuyor — bunları uyguladığınız her yerde `AdaptyEventListener` yerine `IAdaptyEventListener`, `AdaptyOnboardingsEventsListener` yerine ise `IAdaptyOnboardingsEventsListener` olarak yeniden adlandırın.

Flow events listener, `AdaptyPaywallsEventsListener`'dan `IAdaptyFlowsEventsListener`'a yeniden adlandırıldı; kayıt metodu `SetPaywallsEventsListener`'dan `SetFlowsEventsListener`'a, callback'ler ise `PaywallView` önekinden `FlowView` önekine değiştirildi. Mevcut handler gövdelerinde kod değişikliği gerekmez — sadece arayüz ve metotları yeniden adlandırın:

```diff showLineNumbers
- public class MyListener : MonoBehaviour, AdaptyPaywallsEventsListener {
-     public void PaywallViewDidFinishPurchase(
-         AdaptyUIPaywallView view,
+ public class MyListener : MonoBehaviour, IAdaptyFlowsEventsListener {
+     public void FlowViewDidFinishPurchase(
+         AdaptyUIFlowView view,
          AdaptyPaywallProduct product,
          AdaptyPurchaseResult purchasedResult
      ) {
          // custom logic after purchase
      }
      // ...
  }

- Adapty.SetPaywallsEventsListener(myListener);
+ Adapty.SetFlowsEventsListener(myListener);
```

Bir callback yeniden adlandırıldı: `PaywallViewDidFailRendering`, `FlowViewDidReceiveError` oldu. Bu callback, önceki gibi rendering hatalarında tetiklenmeye devam eder; buna ek olarak satın alma dışındaki diğer çalışma zamanı hatalarında da tetiklenir:

```diff showLineNumbers
- public void PaywallViewDidFailRendering(AdaptyUIPaywallView view, AdaptyError error) { }
+ public void FlowViewDidReceiveError(AdaptyUIFlowView view, AdaptyError error) { }
```

Tüm callback listesi için [Flow & paywall olaylarını yönetme](unity-handling-events) bölümüne bakın.

### Yeni zorunlu metod: OnReceivePromotedPurchase \{#new-required-method-onreceivepromotedinappurchase\}

SDK 4.1 sürümünden itibaren `IAdaptyEventListener` arayüzüne yeni bir metod eklendiğinden, bunu uygulayan her sınıf aşağıdakini ekleyene kadar derlenmez:

```csharp showLineNumbers
public void OnReceivePromotedPurchase(AdaptyPromotedProduct product) {
    // The user tapped one of your in-app purchases on your App Store product page.
    // Complete the purchase through Adapty:
    Adapty.MakePromotedPurchase(product, (result, error) => { /* ... */ });
}
```

Bu yöntem, App Store'da tanıtılan uygulama içi satın almalar içindir ve Android'de hiçbir zaman çağrılmaz. SDK, tanıtılan satın almaları henüz kodunuza iletmiyor — bunun yerine otomatik olarak tamamlıyor — dolayısıyla boş bir gövde de geçerli bir uygulamadır. Bkz. [App Store'dan uygulama içi satın almalar](unity-making-purchases#in-app-purchases-from-the-app-store).

### Yeni API'lar

- `Adapty.SetObserverModeResolver(...)` ve `IAdaptyUIObserverModeResolver` — SDK [Observer mode](implement-observer-mode-unity)'da çalışırken flow'lardan başlatılan satın alma ve geri yükleme işlemlerini yönetir. Daha önce bu özellik yalnızca native iOS ve Android SDK'larında mevcuttu. Bkz. [Flow'ları Observer mode'da sunma](unity-present-flows-in-observer-mode).
- `Adapty.SetSystemRequestsHandler(...)` ve `IAdaptyUISystemRequestsHandler` — bir flow'dan gelen sistem istekleri için ayrılmıştır: İşletim sistemi izin istemleri (`FlowViewDidAskPermission`) ve uygulama değerlendirme istekleri (`FlowViewDidRequestAppReview`). Flow'lar henüz bu istekleri tetiklemediğinden bir handler kaydetmenize gerek yoktur.
- `AdaptyUICreateFlowViewParameters.Locale` (`SetLocale` ile ayarlanır) — bir flow veya paywall'ı, flow'un varsayılanı yerine belirli bir [Builder yerelleştirmesiyle](add-paywall-locale-in-adapty-paywall-builder) oluşturur. Bir flow, görünümü oluşturulduğunda yerelleştirilir; bu nedenle yerelleştirmeyi seçebileceğiniz tek yer burasıdır ve oluşturulan görünüm, yapılandırıldığı yerelleştirmeyi `view.Locale` aracılığıyla raporlar. Bkz. [Yerelleştirmeleri ve yerel ayar kodlarını kullanma](unity-localizations-and-locale-codes).
- `IAdaptyFlowsEventsListener` üzerindeki yeni `FlowViewDidReceiveAnalyticEvent` callback'i, bir flow'dan gelen analitik olaylarını raporlar; kullanıcının açtığı her ekran için ekran görüntüleme olayıyla başlar. Bkz. [Flow ekran görüntülemelerini izleme](unity-flow-screen-views).
- `AdaptyUI.OpenUrl(url, openIn, ...)` ve `AdaptyUI.RequestAppReview(...)` — `open_url` eylemleri ve uygulama değerlendirme isteklerinin arkasındaki native işleme. Varsayılan URL davranışını korumak için `FlowViewDidPerformAction` içinden `OpenUrl`'i çağırın; `RequestAppReview` ise henüz flow'ların tetiklemediği varsayılan uygulama değerlendirme istemini destekler.

## Yeniden adlandırılan harici attribution API'leri \{#renamed-external-attribution-apis\}

SDK sürüm 4.1'den itibaren, harici bir sağlayıcıdan (Adjust, AppsFlyer, Branch, Tenjin veya özel bir sağlayıcı) attribution verisi aktarmaya yarayan API'ler, native SDK'larla uyumlu olacak şekilde yeniden adlandırıldı. Eski adlar için herhangi bir deprecated alias bulunmadığından, mevcut çağrı noktaları yeniden adlandırılana kadar derleme hatası verir:

| 4.1 Öncesi | 4.1 |
|---|---|
| `Adapty.UpdateAttribution(data, source, ...)` | `Adapty.UpdateExternalAttribution(data, provider, ...)` |
| `AdaptyProfile.AppliedAttributionSources` | `AdaptyProfile.AppliedExternalAttributionProviders` |

Yalnızca isimler değişti. Sağlayıcı daha önce olduğu gibi aynı string'dir (`"adjust"`, `"appsflyer"`, `"branch"`, `"tenjin"`, `"apple_search_ads"`, `"custom"`), attribution verisi hâlâ bir sözlük veya JSON string olarak kabul edilir ve profil özelliği yine `IReadOnlyList<string>` türündedir:

```diff showLineNumbers
- Adapty.UpdateAttribution(attribution, "adjust", (error) => { /* ... */ });
+ Adapty.UpdateExternalAttribution(attribution, "adjust", (error) => { /* ... */ });
```

## Adapty Attribution varsayılan olarak devre dışıdır \{#adapty-attribution-is-disabled-by-default\}

:::warning
[Adapty Attribution](user-acquisition) kullanıyorsanız ve opt-in yapmadan SDK 4.1'e güncelleme yaparsanız, sessizce bozulur — kurulumlar kayıt edilmeyi durdurur ve sizi uyaran hiçbir şey olmaz.
:::

Önceki sürümlerde SDK, [Adapty Attribution](user-acquisition) için kurulumları otomatik olarak kaydediyordu. SDK 4.1 sürümünden itibaren bu özellik varsayılan olarak kapalıdır: SDK kurulumları kayıt etmez, `OnInstallationDetailsSuccess` ve `OnInstallationDetailsFail` dinleyici geri çağrıları hiçbir zaman tetiklenmez ve `GetCurrentInstallationStatus`, `NotAvailable` durumunu döndürür.

Adapty Attribution kullanıyorsanız, SDK'yı etkinleştirirken bunu etkinleştirin:

```csharp showLineNumbers
var builder = new AdaptyConfiguration.Builder("YOUR_PUBLIC_SDK_KEY")
    .SetAdaptyAttributionEnabled(true);
```

Adapty Attribution kullanmıyorsanız herhangi bir değişiklik yapmanıza gerek yoktur.

## Yedek dosyalar \{#fallback-files\}

[Yedek dosya](unity-use-fallback-paywalls) formatı SDK 4.1'de değişti. iOS ve Android yedek dosyalarını **[Placements](https://app.adapty.io/placements)** > **Fallbacks** bölümünden tekrar indirin ve `Assets/StreamingAssets` klasöründekilerin yerine koyun; daha önceki bir sürüm için indirmiş olsanız bile.

:::warning
Bu adım herhangi bir derleme hatası oluşturmaz. Atlarsanız `SetFallback`, `DecodingFailed` (`adapty_code: 2006`) hatası verir ve tüm placement'lar yedek paywall'ını kaybeder.
:::

## Varsayılan davranış değişiklikleri \{#default-behavior-changes\}

Bu değişiklikler derleme hatası oluşturmaz, dolayısıyla bunları çalışma zamanında test edin:

- **Satın alma tamamlama**: v3'te, başarılı bir satın almanın ardından görünüm otomatik olarak kapatılıyordu. v4'te, **bir flow satın alma veya hata sonrasında siz kapatana kadar açık kalır** — SDK herhangi bir varsayılan davranış uygulamaz. Kullanıcı erişim kazandıktan sonra `FlowViewDidFinishPurchase` içinde `view.Dismiss(...)` metodunu kendiniz çağırın.
- **Android sistem geri tuşu**: Sistem geri tuşu (veya geri kaydırma hareketi), `FlowViewDidPerformAction`'a `SystemBack` aksiyonu olarak iletilir ve artık flow'u kendiliğinden kapatmaz — bu durum iOS ile tutarlıdır; iOS'ta bir flow sistem hareketi ile kapatılamaz. Kullanıcılara açık bir çıkış yolu sunun (bir **Close** düğmesi veya `on_device_back` aksiyonu) ya da aksiyonu işlerken görünümü kendiniz kapatın.
- **Görünümler tek kullanımlıktır**: `Dismiss` çağrısından sonra görünüm yok edilir. Flow'u tekrar göstermek için `CreateFlowView` metodunu yeniden çağırın.
- **Observer mode işlemleri**: `ReportTransaction` artık başarı durumunda kod çözme hatası döndürmez — v3'te başarı yanıtı hatalı şekilde ayrıştırılıyordu, bu yüzden başarılı bir rapor her zaman hatayla tamamlanıyordu.

## Onboarding API'sinin kullanımdan kaldırılması \{#onboarding-api-deprecation\}

Eski onboarding API'si, v4'te [Flow Builder](adapty-flow-builder) lehine kullanımdan kaldırılmıştır. Hâlâ çalışmaya devam etmektedir, ancak gelecekteki bir sürümde kaldırılacaktır; bu nedenle onboarding'lerinizi Flow Builder'a taşımayı planlamanızı öneririz.

Kullanımdan kaldırılan semboller: `GetOnboarding`, `GetOnboardingForDefaultAudience`, `AdaptyUI.CreateOnboardingView`, `AdaptyUI.PresentOnboardingView`, `AdaptyUI.DismissOnboardingView` ve `Adapty.SetOnboardingsEventsListener`.
