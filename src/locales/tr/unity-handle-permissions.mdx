Bir [flow](adapty-flow-builder), örneğin bildirimlerin ne işe yaradığını açıklayan bir onboarding ekranında **Request permission** eylemiyle kullanıcıdan bildirim gönderme izni isteyebilir. Adapty SDK'sı sistem izin diyaloğunu kendisi göstermez. İsteği uygulamanızdaki bir `IAdaptyUISystemRequestsHandler`'a iletir. Uygulamanız diyaloğu gösterir ve kullanıcının yanıtını döndürür, ardından flow devam eder.

## Başlamadan önce \{#before-you-start\}

Şunlara ihtiyacınız var:

- **Adapty Unity SDK 4.1.0 veya üstü, Android'de 4.3.0 veya üstü**: Önceki sürümlerde bu imzaya sahip `IAdaptyUISystemRequestsHandler` bulunmaz. Android'de 4.1.x, flow kapandıktan sonra OS izin callback'inden gelen yanıtı iletir. 4.3.0 sürümü Unity 6 gerektirir.
- **Request permission eylemi içeren bir flow**: Flow & Paywall Builder'da bir öğenin **On Tap** veya **On Screen Appear** tetikleyicisine **Request permission** eylemini ekleyin. **After response** bölümüne, kullanıcı yanıt verdikten sonra çalışacak **Navigate Next** gibi eylemleri ekleyin. Eylem ayarları için bkz. [Request permission](onboarding-actions#request-permission).
- **iOS için**: Bu kılavuzdaki handler'ın iOS iletişim kutusunu göstermek için kullandığı [Mobile Notifications](https://docs.unity3d.com/Packages/com.unity.mobile.notifications@latest) paketi. **Project Settings > Mobile Notifications > iOS** bölümünde, iletişim kutusunun flow tarafından istendiğinde görünmesi için **Request Authorization on App Launch** seçeneğini kapatın.
- **Android için**: Android manifestinizde `android.permission.POST_NOTIFICATIONS` izni ve **Player Settings**'de 33 veya daha yüksek hedef API düzeyi. Android 13 ve üstü, bildirim izni iletişim kutusunu yalnızca izni bildiren ve Android 13 veya üstünü hedefleyen uygulamalara gösterir.

## Flow bir izin nasıl talep eder \{#how-the-flow-requests-a-permission\}

1. Flow, **Request permission** eylemine ulaşır: kullanıcı öğeye dokunur veya ekran görünür.
2. Adapty SDK, `push` izniyle birlikte handler'ınızdaki `FlowViewDidAskPermission` fonksiyonunu çağırır.
3. Uygulamanız OS'tan izni ister ve yanıtı `respond` ile bir kez bildirir.
4. Flow, **After response** eylemlerini çalıştırır. Bu eylemler her iki yanıt için de aynıdır.

Flow, uygulamanız `respond` metodunu çağırana kadar ekranda bekler. Uygulamanız hiç çağırmazsa flow ekranda kalmaya devam eder. İşletim sistemi diyaloğu göstermezse — örneğin kullanıcı zaten yanıt verdiyse — uygulamanız yanıtı hemen alır ve flow **After response** aksiyonlarını anında çalıştırır. Bu aksiyonlar ekrandan çıkılmasına neden olursa, kullanıcı izin isteyen ekranı yalnızca bir an için görür.

**Ekrana Gelince** seçeneğinde, kullanıcı **Geri git** eylemiyle ekrana geri döndüğünde flow yeniden istek göndermez. **Tıklamada** seçeneğinde ise bir istek yanıt beklerken yapılan tıklamalar hariç, her tıklama yeni bir istek gönderir.

## İşleyiciyi uygulayın \{#implement-the-handler\}

İzin isteklerine yanıt vermek için `IAdaptyUISystemRequestsHandler` arayüzünü uygulayın. Uygulamanızın talep etmediği izinler için `false` döndürün.

```csharp showLineNumbers title="Unity"
using System;
using System.Collections;
using System.Collections.Generic;
using AdaptySDK;
using UnityEngine;
#if UNITY_ANDROID
using UnityEngine.Android;
#endif
#if UNITY_IOS
using Unity.Notifications.iOS;
#endif

public class FlowSystemRequestsHandler : MonoBehaviour, IAdaptyUISystemRequestsHandler
{
    public void FlowViewDidAskPermission(
        AdaptyUIFlowView view,
        string permission,
        IReadOnlyDictionary<string, string> customArgs,
        Action<bool, string> respond
    ) {
        if (permission != "push") {
            // Answer every request, or the flow waits on the screen.
            respond(false, null);
            return;
        }

#if UNITY_IOS
        StartCoroutine(RequestPushOnIOS(respond));
#elif UNITY_ANDROID
        RequestPushOnAndroid(respond);
#else
        respond(false, null);
#endif
    }

    public void FlowViewDidRequestAppReview(AdaptyUIFlowView view)
    {
        // Shows the native store review prompt, as the SDK does without a handler.
        AdaptyUI.RequestAppReview(null);
    }

#if UNITY_IOS
    private IEnumerator RequestPushOnIOS(Action<bool, string> respond)
    {
        var options = AuthorizationOption.Alert | AuthorizationOption.Badge | AuthorizationOption.Sound;

        using (var request = new AuthorizationRequest(options, false))
        {
            while (!request.IsFinished) {
                yield return null;
            }
            respond(request.Granted, null);
        }
    }
#endif

#if UNITY_ANDROID
    private void RequestPushOnAndroid(Action<bool, string> respond)
    {
        const string postNotifications = "android.permission.POST_NOTIFICATIONS";

        using (var version = new AndroidJavaClass("android.os.Build$VERSION"))
        {
            if (version.GetStatic<int>("SDK_INT") < 33) {
                // Android 12 and earlier: no dialog; answer whether notifications are on.
                using (var player = new AndroidJavaClass("com.unity3d.player.UnityPlayer"))
                using (var activity = player.GetStatic<AndroidJavaObject>("currentActivity"))
                using (var managerClass = new AndroidJavaClass("androidx.core.app.NotificationManagerCompat"))
                using (var manager = managerClass.CallStatic<AndroidJavaObject>("from", activity))
                {
                    respond(manager.Call<bool>("areNotificationsEnabled"), null);
                }
                return;
            }
        }

        if (Permission.HasUserAuthorizedPermission(postNotifications)) {
            respond(true, null);
            return;
        }

        var callbacks = new PermissionCallbacks();
        callbacks.PermissionGranted += _ => respond(true, null);
        callbacks.PermissionDenied += _ => respond(false, null);
#if UNITY_6000_0_OR_NEWER
        callbacks.PermissionRequestDismissed += _ => respond(false, null);
#else
        callbacks.PermissionDeniedAndDontAskAgain += _ => respond(false, null);
#endif
        Permission.RequestUserPermission(postNotifications, callbacks);
    }
#endif
}
```

`FlowViewDidAskPermission` şunları alır:

- **`view`**: İsteği gönderen flow view.
- **`permission`**: Flow'un talep ettiği izin. **Request permission** eylemi `push` gönderir.
- **`customArgs`**: İsteğin özel argümanları. **Request permission** eylemi hiçbir şey göndermez; bu nedenle değer `null`'dur.
- **`respond`**: Flow'a yanıtı döndüren callback. Kullanıcı izin verdiyse `true`, aksi hâlde `false` geçin. İkinci argüman isteğe bağlı bir detay dizesidir ve `null` geçerli bir değerdir.

Her istek için `respond` fonksiyonunu tam olarak bir kez çağırın. Adapty SDK, ikinci bir çağrıyı yoksayar ve Unity konsoluna bir uyarı yazdırır. 4.3.0 sürümünden itibaren, `respond` fonksiyonunu OS izin callback'i de dahil olmak üzere herhangi bir thread'den çağırabilirsiniz.

`FlowViewDidAskPermission`, `respond` fonksiyonunu çağırmadan önce bir istisna fırlatırsa, Adapty SDK istisnayı günlüğe kaydeder ve yanıt göndermez; bu durumda flow ekranda kalmaya devam eder. İstisnaları yakalayın ve `respond(false, null)` çağrısı yapın.

Verilen izin, uygulamanızın bildirim göstermesine olanak tanır. Push bildirimleri almak için, uygulamanızın flow'lar dışında yaptığı gibi cihazı push sağlayıcınıza kaydedin.

`IAdaptyUISystemRequestsHandler` ayrıca `FlowViewDidRequestAppReview` gerektirir. Bir handler kayıtlıyken Adapty SDK, mağaza değerlendirmesini kendi başına talep etmez; bu nedenle örneğe bakarak native değerlendirme istemini korumak için içinde `AdaptyUI.RequestAppReview(null)` çağrısı yapın.

## İzin işleyicisini kaydedin \{#register-the-handler\}

:::warning
**İşleyici olmadan flow, izin isteğinde durur.** Uygulamanız herhangi bir işleyici kaydetmezse, Adapty SDK hem iOS'ta hem Android'de flow'a yanıt göndermez ve Unity konsolunda `System requests handler is not set` uyarısı görüntülenir. Flow, isteği gönderen ekranda kalır ve **After response** eylemlerini çalıştırmaz.
:::

Tüm flow'lardan gelen izin isteklerini handler'ınıza göndermek için, bir flow sunmadan önce `Adapty.SetSystemRequestsHandler()` ile handler'ı kaydedin. Bunu, [flow olayları dinleyicisini](unity-handle-paywall-actions#set-up-the-flows-events-listener) kaydettiğiniz yerde yapın. Handler'ı uygulamanız çalıştığı sürece yaşayan bir GameObject'e ekleyin ve şu metodları handler sınıfına ekleyin:

```csharp showLineNumbers title="Unity"
void Awake()
{
    DontDestroyOnLoad(gameObject);
    Adapty.SetSystemRequestsHandler(this);
}

void OnDestroy()
{
    Adapty.SetSystemRequestsHandler(null);
}
```

`Adapty.SetSystemRequestsHandler()`, uygulamadaki her flow için tek bir handler tutar. İkinci bir çağrı ilk handler'ın yerini alır; `null` ise handler'ı kaldırır.

## İzin isteğini test etme \{#test-the-permission-request\}

iOS, bildirim iletişim kutusunu uygulama başına yalnızca bir kez gösterir. Android ise kullanıcı bildirimlere izin verdiğinde ya da iki kez reddettiğinde artık göstermez. Flow'u test ederken iletişim kutusunu tekrar görmek için uygulamayı cihazdan silip yeniden yükleyin. Ardından flow'u açın ve **Request permission** eylemine ulaşın. Ekran kalıp hiçbir iletişim kutusu görünmüyorsa flow yanıt alamamış demektir: uygulamanızın flow'u göstermeden önce handler'ı kaydettiğinden emin olun. Flow bir iletişim kutusu olmadan ilerliyorsa Android uygulamasının `POST_NOTIFICATIONS` bildirdiğinden ve API düzeyi 33 veya üstünü hedeflediğinden emin olun; ayrıca **Request Authorization on App Launch** seçeneğinin kapalı olduğunu doğrulayın.
