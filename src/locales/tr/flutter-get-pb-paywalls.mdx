## Flow/paywall'ı getirme \{#fetch-flowpaywall\}

Builder'da bir flow veya paywall tasarladıysanız, onu kullanıcıya göstermek için mobil uygulama kodunuzda render etme konusunda endişelenmenize gerek yoktur. Böyle bir flow veya paywall, içinde neyin ve nasıl gösterileceğini zaten barındırır. Bununla birlikte, ID'sini placement aracılığıyla, görünüm yapılandırmasını ise ayrıca almanız ve ardından mobil uygulamanızda sunmanız gerekmektedir.

Flow veya paywall'ı mümkün olduğunca erken — tercihen göstermeden çok önce — alın ve [görünümünü](flutter-get-pb-paywalls#fetch-the-view-configuration) oluşturun. `createFlowView` metodu, görünüm yapılandırmasını yükler ve arka planda resim indirmeye ve önbelleğe almaya başlar. Ne kadar erken çağırırsanız, bu indirmelerin tamamlanması için o kadar fazla zaman olur. Flow veya paywall'ı gösterdiğinizde, yapılandırması ve resimleri zaten önbellekte hazır olabilir.

:::tip
Birden fazla placement'ı aynı anda ısıtmak için [`preloadFlows`](flutter-optimize-paywall-fetching#preload-placements) metodunu çağırın (Flutter SDK 4.3.0+). Bu yalnızca placement JSON'ını önbelleğe alır; dolayısıyla `createFlowView` yine de layout ve görselleri yükler.
:::

Bir flow veya paywall almak için `getFlow` metodunu kullanın:

```dart showLineNumbers
try {
  final flow = await Adapty().getFlow(placementId: 'YOUR_PLACEMENT_ID');
  // the requested flow/paywall
} on AdaptyError catch (adaptyError) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Parametreler:

| Parametre | Zorunluluk | Açıklama |
|---------|--------|-----------|
| **placementId** | zorunlu | İstenen [Placement](placements)'ın tanımlayıcısı. Bu, Adapty Kontrol Paneli'nde bir placement oluştururken belirttiğiniz değerdir. |
| **fetchPolicy** | varsayılan: `AdaptyFlowFetchPolicy.reloadRevalidatingCacheData` | <p>`fetchPolicy`, SDK'nın önce hangi katmanı okuyacağını belirler; önbelleği kullanıp kullanamayacağını değil. Varsayılan olarak SDK önce sunucuya gider, bu istek başarısız olursa önbelleğe alınan veriyi döndürür. Kullanıcılarınızın her zaman en güncel verileri almasını sağladığı için bu seçeneği tavsiye ederiz.</p><p></p><p>Ancak kullanıcılarınızın kararsız bir internet bağlantısıyla karşılaştığını düşünüyorsanız, bu sırayı tersine çeviren `AdaptyFlowFetchPolicy.returnCacheDataElseLoad` seçeneğini değerlendirin; önce önbelleği okur, yalnızca önbellekte hiçbir şey yoksa sunucuya gider. Kullanıcılar mutlak olarak en son verileri alamayabilir, ancak internet bağlantısı ne kadar düzensiz olursa olsun daha hızlı yükleme süreleriyle karşılaşırlar. Önbellek düzenli olarak güncellenir, bu nedenle ağ isteklerinden kaçınmak için oturum sırasında kullanmak güvenlidir.</p><p></p><p>Üçüncü bir politika olan `AdaptyFlowFetchPolicy.returnCacheDataIfNotExpiredElseLoad(maxAge)`, ikisi arasında yer alır: önbelleğe alınan kopya, ilettiğiniz `Duration` değerinden daha yeni olduğu sürece önce önbelleği okur; daha eski olduğunda ise sunucuya gider.</p><p></p><p>Önbelleğin uygulama yeniden başlatıldığında korunduğunu, yalnızca uygulama yeniden yüklendiğinde veya manuel temizleme yoluyla silindiğini unutmayın.</p><p></p><p>Adapty SDK, paywallları yerel olarak iki katmanda depolar: yukarıda açıklanan düzenli olarak güncellenen önbellek ve [yedek paywalllar](fallback-paywalls). Paywallları daha hızlı getirmek için CDN, CDN'e ulaşılamadığı durumlarda ise bağımsız bir yedek sunucu kullanıyoruz. Bu sistem, internet bağlantısının yetersiz olduğu durumlarda bile güvenilirliği sağlarken her zaman paywalllarınızın en son sürümünü almanızı garanti edecek şekilde tasarlanmıştır.</p> |
| **loadTimeout** | varsayılan: 5 sn | <p>Bu metodun zaman aşımını sınırlayan bir `Duration` değeri. Adapty sunucusu zamanında yanıt vermezse veya hata döndürürse SDK, önbelleğe alınan flow'u döndürür. Önbellekte hiçbir şey yoksa ve sunucu zaman aşımına uğramışsa ya da sunucu hatası döndürdüyse SDK, flow'u yedek sunucudan (yalnızca placement'ın **All Users** kitlesine hizmet eden bir CDN kopyası) ister. Son çare olarak SDK, flow'u [yedek dosyanızdan](flutter-use-fallback-paywalls) döndürür.</p><p>Nadir durumlarda bu metodun `loadTimeout` içinde belirtilenden biraz daha geç zaman aşımına uğrayabileceğini unutmayın; çünkü işlem arka planda farklı isteklerden oluşabilir.</p> |

## Görünüm yapılandırmasını getirme \{#fetch-the-view-configuration\}

:::important
[Flow'u yayınladığınızdan](builder-save-publish) emin olun. Yayınlanmamış düzenlemeleri olan bir flow **Dirty** durumuna sahiptir ve onun placement'ı son yayınlanan sürümü sunmaya devam eder.
:::

Placement **Flow & Paywall Builder** veya **eski Paywall Builder** ile tasarlandıysa, Adapty kullanıcı arayüzünü sizin için oluşturur — alınan flow'un `hasViewConfiguration` özelliği `true` olur. `createFlowView` ile view'ı oluşturun, ardından [flow veya paywall'ı gösterin](flutter-present-paywalls). Placement, Builder arayüzü olmayan özel bir paywall ise (`hasViewConfiguration` değeri `false`), bunun yerine [kendiniz render edin](present-remote-config-paywalls-flutter).

:::warning
Varsayılan olarak, `createFlowView` metodunun sonucunu kapatmak onu serbest bırakır; dolayısıyla tekrar gösteremezsiniz. Flow veya paywall'ı tekrar göstermeniz gerekiyorsa, `createFlowView` metodunu yeniden çağırın ya da SDK 4.1 ve sonrasında [serbest bırakmadan kapatın](flutter-present-paywalls#dismiss-the-flow-or-paywall).
:::

```dart showLineNumbers

try {
  final view = await AdaptyUI().createFlowView(flow: flow);
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Parametreler:

| Parametre            | Zorunluluk | Açıklama                                                  |
| :------------------- | :------- | :----------------------------------------------------------- |
| **flow**             | zorunlu | İstenen flow/paywall için görünüm elde etmek amacıyla kullanılan `AdaptyFlow` nesnesi. |
| **locale**           | opsiyonel | Görünümün render edileceği [flow yerelleştirmesinin](add-paywall-locale-in-adapty-paywall-builder) tanımlayıcısı; örneğin `en` veya `pt-BR`. Belirtilmezse görünüm `en` dilinde ya da flow'un `en` yerelleştirmesi yoksa varsayılan yerelleştirmesinde render edilir. Bkz. [Yerelleştirmeler ve yerel ayar kodları](flutter-localizations-and-locale-codes). |
| **customLayoutId**   | <p>opsiyonel</p><p>varsayılan: `null`</p><p>SDK 4.1+</p> | Flow'un layout yapılandırmasındaki bir layout'un özel kimliği. SDK'nın cihaz türü ve ekran boyutuna göre otomatik seçtiği layout yerine belirli bir layout'u render etmek için kullanılır. Kimlikle eşleşen layout bulunamazsa çağrı `AdaptyError` ile başarısız olur. Flow & Paywall Builder henüz özel layout kimliği atamadığından bu alanı boş bırakın. |
| **customTags**       | opsiyonel | Flow'un [özel etiketleri](flow-custom-tags) için uygulamanızın değerleri; her etiketin tam adıyla anahtarlanmış bir map olarak belirtilir. Ayrıntılar için bkz. [Flow'lara veri aktarma](flutter-flow-custom-tags). |
| **customTimers**     | opsiyonel | Flow'un **Geliştirici tarafından tanımlanan** zamanlayıcılarının bitiş tarihleri; Zamanlayıcı kimliklerinden `DateTime` değerlerine bir map olarak belirtilir. Ayrıntılar için bkz. [Geliştirici tanımlı zamanlayıcıları ayarlama](#set-up-developer-defined-timers). |
| **preloadProducts** | opsiyonel | Ekrandaki ürünlerin görüntülenme zamanlamasını optimize etmek için etkinleştirin. `true` olduğunda AdaptyUI gerekli ürünleri otomatik olarak getirir. Varsayılan: `false`. |
| **loadTimeout** | opsiyonel | Görünüm yapılandırması yükleme süresini sınırlayan `Duration` değeri. Zaman aşımına ulaşıldığında önbelleğe alınmış veriler veya yerel yedek kullanılır. |

:::note
Birden fazla dil kullanıyorsanız, [flow yerelleştirmesi](add-paywall-locale-in-adapty-paywall-builder) eklemeyi ve yerel ayar kodlarını doğru şekilde kullanmayı [burada](flutter-localizations-and-locale-codes) öğrenin.
:::

Görünümü edindikten sonra [flow/paywall'ı sunun](flutter-present-paywalls).

## Varsayılan kitle için flow veya paywall alarak daha hızlı yükleme sağlayın \{#get-a-flow-or-paywall-for-a-default-audience-to-fetch-it-faster\}

Genellikle flow'lar ve paywall'lar neredeyse anında yüklenir, bu nedenle bu süreci hızlandırmak için endişelenmenize gerek yoktur. Ancak çok sayıda kitle ve placement'a sahip olduğunuz durumlarda, kullanıcılarınızın internet bağlantısı zayıfsa, bir flow veya paywall'ın yüklenmesi istediğinizden daha uzun sürebilir. Bu tür durumlarda, hiçbir şey göstermek yerine sorunsuz bir kullanıcı deneyimi sağlamak amacıyla varsayılan bir flow veya paywall görüntülemek isteyebilirsiniz.

Bunu ele almak için, belirtilen placement'ın **All Users** kitlesi için flow veya paywall'ı getiren `getFlowForDefaultAudience` metodunu kullanabilirsiniz. Ancak önemli olan şu: önerilen yaklaşım, yukarıdaki [Flow/paywall getirme](#fetch-flowpaywall) bölümünde açıklandığı gibi `getFlow` metoduyla flow veya paywall'ı getirmektir.

:::warning
Neden `getFlow` kullanmanızı öneriyoruz

`getFlowForDefaultAudience` metodunun birkaç önemli dezavantajı vardır:

- **Olası geriye dönük uyumluluk sorunları**: Farklı uygulama sürümleri (mevcut ve gelecekteki) için farklı paywall'lar göstermeniz gerekiyorsa, zorluklarla karşılaşabilirsiniz. Ya mevcut (eski) sürümü destekleyen paywall'lar tasarlamanız ya da mevcut (eski) sürüme sahip kullanıcıların render edilemeyen paywall'larla sorun yaşayabileceğini kabul etmeniz gerekecektir.
- **Hedefleme kaybı**: Tüm kullanıcılar **All Users** kitlesi için tasarlanmış aynı paywall'ı görecektir; bu da ülkelere, pazarlama attribution'ına veya kendi özel özelliklerinize dayalı kişiselleştirilmiş hedeflemeyi kaybetmeniz anlamına gelir.

Bu dezavantajları kabul ederek daha hızlı flow veya paywall getirme işleminden yararlanmak istiyorsanız, `getFlowForDefaultAudience` metodunu aşağıdaki gibi kullanın. Aksi takdirde [yukarıda](#fetch-flowpaywall) açıklanan `getFlow` metodunu kullanmaya devam edin.
:::

```dart showLineNumbers
try {
  final flow = await Adapty().getFlowForDefaultAudience(placementId: 'YOUR_PLACEMENT_ID');
  // the requested flow/paywall
} on AdaptyError catch (adaptyError) {
  // handle error
} catch (e) {
  // handle unknown error
}
```

| Parametre | Zorunluluk | Açıklama |
|---------|--------|-----------|
| **placementId** | zorunlu | [Placement](placements) tanımlayıcısı. Adapty Kontrol Paneli'nde bir placement oluştururken belirttiğiniz değerdir. |
| **fetchPolicy** | varsayılan: `AdaptyFlowFetchPolicy.reloadRevalidatingCacheData` | <p>`fetchPolicy`, SDK'nın önce hangi katmanı okuyacağını belirler; önbelleği kullanıp kullanamayacağını değil. SDK varsayılan olarak önce sunucuya gider ve bu istek başarısız olursa önbelleğe alınan veriyi döndürür. Kullanıcılarınızın her zaman en güncel verilere ulaşmasını sağladığı için bu seçeneği öneriyoruz.</p><p></p><p>Ancak kullanıcılarınızın kararsız bir internet bağlantısıyla karşılaştığını düşünüyorsanız `AdaptyFlowFetchPolicy.returnCacheDataElseLoad` seçeneğini değerlendirin. Bu seçenek sırayı tersine çevirir: önce önbelleği okur, önbellekte hiçbir şey yoksa sunucuya gider. Kullanıcılar en son verilere ulaşamayabilir; ancak internet bağlantısı ne kadar kesintili olursa olsun daha hızlı yükleme süresi yaşarlar. Önbellek düzenli olarak güncellendiğinden, ağ isteklerinden kaçınmak için oturum boyunca güvenle kullanılabilir.</p><p></p><p>Üçüncü bir politika olan `AdaptyFlowFetchPolicy.returnCacheDataIfNotExpiredElseLoad(maxAge)` bu ikisi arasında yer alır: önbelleğe alınan kopya, ilettiğiniz `Duration` değerinden daha yeni olduğu sürece önce önbelleği okur; daha eski olduğunda ise sunucuya gider.</p><p></p><p>Önbelleğin uygulama yeniden başlatıldığında silinmediğini, yalnızca uygulama yeniden yüklendiğinde veya manuel temizleme yapıldığında temizlendiğini unutmayın.</p> |

## Varlıkları özelleştirme \{#customize-assets\}

Flow/paywall'unuzdaki görselleri ve videoları özelleştirmek için özel varlıkları uygulayın.

Hero görseller ve videolar önceden tanımlanmış ID'lere sahiptir: `hero_image` ve `hero_video`. Özel bir varlık paketinde, bu öğeleri ID'leriyle hedefler ve davranışlarını özelleştirirsiniz.

Diğer görseller ve videolar için Adapty kontrol panelinde [özel bir ID belirlemeniz](custom-media) gerekir.

Örneğin şunları yapabilirsiniz:

- Bazı kullanıcılara farklı bir görsel veya video gösterin.
- Uzak ana görsel yüklenirken yerel bir önizleme görseli gösterin.
- Video oynatılmadan önce bir önizleme görseli gösterin.
- Uygulamayla birlikte paketlenmiş medyayı gösterin; böylece ilk ekran indirme yapmadan render edilir. Bkz. [Uygulama paketinden ilk ekran medyasını gösterme](flutter-optimize-paywall-fetching#show-first-screen-media-from-the-app-bundle).

İşte özel asset'leri basit bir sözlük aracılığıyla nasıl sağlayabileceğinize dair bir örnek:

```dart

final customAssets = {
    // Show a local image using a custom ID
    'custom_image': AdaptyCustomAsset.localImageAsset(
        assetId: 'assets/images/image_name.png',
    ),

    // Show a local video with a preview image
    'hero_video': AdaptyCustomAsset.localVideoAsset(
        assetId: 'assets/videos/custom_video.mp4',
    ),
};

try {
  final view = await AdaptyUI().createFlowView(
    flow: flow,
    customAssets: customAssets,
  );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

:::note
Bir varlık bulunamazsa, flow/paywall varsayılan görünümüne geri döner.
:::

## Geliştirici tanımlı zamanlayıcıları ayarlama \{#set-up-developer-defined-timers\}

Bu bölümü, Flow & Paywall Builder'da **Developer defined** davranışına sahip bir zamanlayıcı için kullanın. Builder'da her böyle bir zamanlayıcının bir **Timer ID**'si vardır (bkz. [Uygulamanızın bitiş tarihini belirlemesine izin verin](flow-timer#let-your-app-set-the-end-date)) ve uygulamanız bu zamanlayıcı için bitiş tarihini belirler. Kodunuzda, builder'dakiyle aynı Timer ID'yi kullanın; büyük-küçük harf ve boşluklar dahil, karakter karakter aynı olmalıdır. ID'ler farklıysa zamanlayıcı, uygulamanızdan herhangi bir bitiş tarihi almaz.

Bitiş tarihlerini ayarlamak için `createFlowView` metoduna bir `customTimers` haritası geçirin. Her harita anahtarı bir Timer ID'dir ve değeri zamanlayıcının ne zaman biteceğini tanımlayan bir `DateTime` nesnesidir. İşte bir örnek:

```dart showLineNumbers

try {
  final view = await AdaptyUI().createFlowView(
    flow: flow,
    customTimers: {
      'CUSTOM_TIMER_6H': DateTime.now().add(const Duration(hours: 6)),
      'CUSTOM_TIMER_NY': DateTime(DateTime.now().year + 1), // next New Year's Day
    },
  );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

`AdaptyUIFlowPlatformView` ile gömülü bir flow için aynı map'i `customTimers` parametresine geçirin.

Bu örnekte, `CUSTOM_TIMER_NY` ve `CUSTOM_TIMER_6H`, builder'daki iki **Geliştirici tarafından tanımlanan** zamanlayıcının Timer ID'leridir:

- `CUSTOM_TIMER_NY`: Bir sonraki Yılbaşı'na kalan süre.
- `CUSTOM_TIMER_6H`: Uygulamanızın görünümü oluşturduğu andan itibaren başlayan 6 saatlik sürede kalan zaman.

SDK, görünümü oluştururken `customTimers` değerini bir kez okur; bu nedenle `CUSTOM_TIMER_6H` gibi hesaplanmış bir tarih, o andan itibaren sayılır ve kullanıcı ekranı tekrar açtığında da aynı şekilde çalışır. Tarih geçmişte kalıyorsa zamanlayıcı anında sıfırı gösterir ve **On timer end** tetikleyicisi çalışır. `customTimers` içinde bir Timer ID'ye karşılık gelen anahtar yoksa zamanlayıcı, ekran açılışından itibaren bir saat geri sayar.

## Paywall Builder ile tasarlanan paywallı getirme \{#fetch-paywall-designed-with-paywall-builder\}

[Paywall Builder kullanarak bir paywall tasarladıysanız](adapty-paywall-builder), onu kullanıcıya göstermek için mobil uygulama kodunuzda render etme konusunda endişelenmenize gerek yoktur. Bu tür bir paywall, hem ne gösterileceğini hem de nasıl gösterileceğini içerir. Yine de placement aracılığıyla ID'sini, görünüm yapılandırmasını almanız ve ardından mobil uygulamanızda sunmanız gerekir.

En iyi performansı sağlamak için, paywall'u ve [görünüm yapılandırmasını](flutter-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder) mümkün olduğunca erken almak kritik önem taşır; bu sayede görsellerin kullanıcıya sunulmadan önce indirilmesi için yeterli süre tanınmış olur.

Bir paywall almak için `getPaywall` metodunu kullanın:

```dart showLineNumbers
try {
  final paywall = await Adapty().getPaywall(placementId: "YOUR_PLACEMENT_ID", locale: "en");
  // istenen paywall
} on AdaptyError catch (adaptyError) {
  // hatayı işle
} catch (e) {
}
```

Parametreler:

| Parametre | Zorunluluk | Açıklama |
|---------|--------|-----------|
| **placementId** | zorunlu | İstenen [Placement](placements)'ın tanımlayıcısı. Bu, Adapty Kontrol Paneli'nde bir placement oluştururken belirttiğiniz değerdir. |

İlk alt etiket dil içindir, ikincisi ise bölge içindir.</p><p></p><p>Örnek: `en` İngilizce anlamına gelir, `pt-br` Brezilya Portekizcesini temsil eder.</p><p>Yerel ayar kodları ve bunların nasıl kullanılması gerektiği hakkında daha fazla bilgi için [Yerelleştirmeler ve yerel ayar kodları](flutter-localizations-and-locale-codes) bölümüne bakın.</p> |

## Paywall Builder ile tasarlanan paywallın görünüm yapılandırmasını getirme \{#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder\}

:::important
Paywall Builder'da **Show on device** geçişinin etkin olduğundan emin olun. Bu seçenek açık değilse görünüm yapılandırması getirilemez.
:::

Paywallı getirdikten sonra, Paywall Builder kullanılarak oluşturulduğunu gösteren bir `ViewConfiguration` içerip içermediğini kontrol edin. Bu, paywallı nasıl göstereceğiniz konusunda size rehberlik edecektir. `ViewConfiguration` mevcutsa Paywall Builder paywallı olarak değerlendirin; değilse [özel paywall olarak ele alın](present-remote-config-paywalls-flutter).

```dart showLineNumbers

try {
  final view = await AdaptyUI().createPaywallView(
        paywall: paywall,
      );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

View'i oluşturduktan sonra [paywall'ı gösterin](flutter-present-paywalls).

## Daha hızlı yüklemek için varsayılan kitle paywall'ını alın \{#get-a-paywall-for-a-default-audience-to-fetch-it-faster\}

Genellikle paywall'lar neredeyse anında yüklenir, bu nedenle bu süreci hızlandırmak için endişelenmenize gerek yoktur. Ancak çok sayıda kitle ve paywall'ınız olduğunda ve kullanıcılarınızın internet bağlantısı zayıf olduğunda, bir paywall'ın yüklenmesi istediğinizden daha uzun sürebilir. Bu tür durumlarda, hiç paywall göstermemek yerine sorunsuz bir kullanıcı deneyimi sağlamak için varsayılan bir paywall görüntülemek isteyebilirsiniz.

Bunu çözmek için, belirtilen placement'ın **All Users** kitlesi için paywall'u getiren `getPaywallForDefaultAudience` metodunu kullanabilirsiniz. Ancak, önerilen yaklaşımın yukarıdaki [Paywall Bilgisini Getir](flutter-get-pb-paywalls#fetch-paywall-designed-with-paywall-builder) bölümünde ayrıntılı olarak açıklandığı gibi `getPaywall` metoduyla paywall'u getirmek olduğunu anlamak önemlidir.

:::warning
Neden `getPaywall` kullanmanızı öneriyoruz

`getPaywallForDefaultAudience` metodunun birkaç önemli dezavantajı vardır:

- **Olası geriye dönük uyumluluk sorunları**: Farklı uygulama sürümleri (mevcut ve gelecekteki) için farklı paywall'lar göstermeniz gerekiyorsa, zorluklarla karşılaşabilirsiniz. Ya mevcut (eski) sürümü destekleyen paywall'lar tasarlamanız ya da mevcut (eski) sürüme sahip kullanıcıların render edilemeyen paywall'larla sorun yaşayabileceğini kabul etmeniz gerekecektir.
- **Hedefleme kaybı**: Tüm kullanıcılar **All Users** kitlesi için tasarlanmış aynı paywall'ı görecektir; bu da ülkelere, pazarlama attribution'ına veya kendi özel attribute'larınıza dayalı kişiselleştirilmiş hedeflemeyi kaybettiğiniz anlamına gelir.

Bu dezavantajları kabul edip daha hızlı paywall yükleme avantajından yararlanmak istiyorsanız, `getPaywallForDefaultAudience` metodunu aşağıdaki gibi kullanın. Aksi takdirde [yukarıda](#fetch-paywall-designed-with-paywall-builder) açıklanan `getPaywall` metodunu kullanmaya devam edin.
:::

```dart showLineNumbers
try {
    final paywall = await Adapty().getPaywallForDefaultAudience(placementId: 'YOUR_PLACEMENT_ID');
} on AdaptyError catch (adaptyError) {
    // handle error
} catch (e) {
    // handle unknown error
}
```

:::note
`getPaywallForDefaultAudience` metodu Flutter SDK 3.2.0 sürümünden itibaren kullanılabilir.
:::

| Parametre | Zorunluluk | Açıklama |
|---------|--------|-----------|
| **placementId** | zorunlu | [Placement](placements) tanımlayıcısı. Adapty Kontrol Paneli'nde bir placement oluştururken belirttiğiniz değerdir. |
| **locale** | <p>isteğe bağlı</p><p>varsayılan: `en`</p> | <p>[Paywall yerelleştirmesinin](add-remote-config-locale) tanımlayıcısı. İlk alt etiket dil, ikincisi ise bölge içindir.</p><p></p><p>Örnek: `en` İngilizce, `pt-br` ise Brezilya Portekizcesini temsil eder.</p><p></p><p>Yerel ayar kodları ve bunların kullanımına ilişkin önerilerimiz için [Yerelleştirmeler ve yerel ayar kodları](localizations-and-locale-codes) sayfasına bakın.</p> |
| **fetchPolicy** | varsayılan: `AdaptyPaywallFetchPolicy.reloadRevalidatingCacheData` | <p>`fetchPolicy`, SDK'nın önbelleği kullanıp kullanamayacağını değil, hangi katmanı önce okuyacağını belirler. Varsayılan olarak SDK önce sunucuya gider; bu istek başarısız olursa önbelleğe alınmış veriyi döndürür. Bu seçeneği öneriyoruz çünkü kullanıcılarınızın her zaman en güncel verilere erişmesini sağlar.</p><p></p><p>Ancak kullanıcılarınızın kararsız bir internet bağlantısıyla çalıştığını düşünüyorsanız `AdaptyPaywallFetchPolicy.returnCacheDataElseLoad` seçeneğini değerlendirin; bu seçenek sırayı tersine çevirir — önce önbelleği okur, önbellekte veri yoksa sunucuya başvurur. Kullanıcılar en yeni verilere ulaşamayabilir, ancak internet bağlantısı ne kadar kesintili olursa olsun daha hızlı yükleme süreleriyle karşılaşır. ## Varlıkları özelleştirme \{#customize-assets\}

Paywallinizdeki görselleri ve videoları özelleştirmek için özel varlıkları uygulayın.

Hero görseller ve videolar önceden tanımlanmış ID'lere sahiptir: `hero_image` ve `hero_video`. Özel bir varlık paketinde, bu öğeleri ID'leri ile hedefler ve davranışlarını özelleştirirsiniz.

Diğer görseller ve videolar için Adapty kontrol panelinde [özel bir ID belirlemeniz](custom-media) gerekir.

Örneğin şunları yapabilirsiniz:

- Bazı kullanıcılara farklı bir görsel veya video göstermek.
- Uzaktaki ana görsel yüklenirken yerel bir önizleme görseli göstermek.
- Video oynatılmadan önce bir önizleme görseli göstermek.

:::important
Bu özelliği kullanmak için Adapty Flutter SDK'yı 3.8.0 veya daha yüksek bir sürüme güncelleyin.
:::

Aşağıda, özel varlıkları basit bir sözlük aracılığıyla nasıl sağlayabileceğinize dair bir örnek bulunmaktadır:

```dart

final customAssets = {
    // Show a local image using a custom ID
    'custom_image': AdaptyCustomAsset.localImageAsset(
        assetId: 'assets/images/image_name.png',
    ),

    // Show a local video with a preview image
    'hero_video': AdaptyCustomAsset.localVideoAsset(
        assetId: 'assets/videos/custom_video.mp4',
    ),
};

try {
  final view = await AdaptyUI().createPaywallView(
    paywall: paywall,
    customAssets: customAssets,
  );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

:::note
Bir öğe bulunamazsa, paywall varsayılan görünümüne geri döner.
:::

## Geliştirici tanımlı zamanlayıcıları ayarlama \{#set-up-developer-defined-timers\}

Mobil uygulamanızda özel zamanlayıcılar kullanmak için `createPaywallView` metoduna bir `customTimers` haritası geçirin. Her harita anahtarı bir zamanlayıcı ID'sidir ve değeri zamanlayıcının ne zaman biteceğini tanımlayan bir `DateTime` nesnesidir. İşte bir örnek:

```dart showLineNumbers

try {
  final view = await AdaptyUI().createPaywallView(
        paywall: paywall,
        customTimers: {
          'CUSTOM_TIMER_6H': DateTime.now().add(const Duration(seconds: 3600 * 6)),
          'CUSTOM_TIMER_NY': DateTime(2025, 1, 1), // New Year 2025
        },
      );
} on AdaptyError catch (e) {
  // handle the error
} catch (e) {
  // handle the error
}
```

Bu örnekte, `CUSTOM_TIMER_NY` ve `CUSTOM_TIMER_6H`, Adapty Kontrol Paneli'nde ayarladığınız geliştirici tanımlı zamanlayıcıların **Timer ID**'leridir. `customTimers` map'i, uygulamanızın her zamanlayıcıyı doğru değerle dinamik olarak güncellemesini sağlar. Örneğin:

- `CUSTOM_TIMER_NY`: Yeni Yıl gibi zamanlayıcının bitiş anına kadar kalan süre.
- `CUSTOM_TIMER_6H`: Kullanıcının paywall'ı açtığı andan itibaren başlayan 6 saatlik sürede kalan zaman.
