CLI, Adapty API'sini çağırabilmek için kimlik doğrulaması gerektirir.

Tek bir giriş tüm CLI'ı kapsar. [Ads Manager komutları](developer-cli-ads-manager) farklı bir servise ulaşır, ancak aynı kayıtlı token'ı kullanır — ikinci bir giriş adımı yoktur.

## Giriş yapın \{#log-in\}

Giriş yapmak için:

1. Terminalinizde şu komutu çalıştırın:
   ```bash
   adapty auth login
   ```
2. CLI, `XXXX-XXXX` biçiminde bir doğrulama kodu yazdırır ve tarayıcınızda Adapty Kontrol Paneli'ni açar.
3. Yetkilendirme sayfasında kodun terminal çıktınızla eşleştiğini onaylayın.
4. **Authorize** düğmesine tıklayın. Tarayıcı "CLI authorized! You can close this tab." mesajını gösterir.
5. Terminale geri döndüğünüzde CLI, kimliğinizin doğrulandığını onaylar.

```bash
adapty auth login
```

## Kimlik doğrulamayı yönetme \{#manage-authentication\}

### Kimlik Doğrulama Durumunu Kontrol Etme \{#check-authentication-status\}

Mevcut kimlik doğrulama durumunuzu görmek için şu komutu çalıştırın:

```bash
adapty auth status
```

Kimlik doğrulandığında, çıktı adınızı, maskelenmiş bir token önekini ve yerel yapılandırma dosyasının yolunu gösterir:

```
User: Jane Doe
Token: abcd1234****
Config: ~/.config/adapty/config.json
```

CLI 0.9.1 ile birlikte, giriş yapıldığında adınız kaydedilir, e-posta adresi kaydedilmez. `Email:` satırı yalnızca daha eski bir sürümle kaydedilmiş oturumlarda görünür. `adapty auth status --json` komutunu okuyan scriptlerde, kullanıcıyı tanımlamak için `name` alanını kullanın.

Kimlik doğrulanmamış olduğunda:

```
Not authenticated. Run `adapty auth login`.
```

### Tokenınızı doğrulama \{#verify-your-token\}

Tokenınızın geçerli olduğunu onaylamak ve hesap bilgilerinizi görmek için şunu çalıştırın:

```bash
adapty auth whoami
```

`adapty auth status` komutunun aksine, bu komut tokenı doğrulamak için sunucuya canlı bir istek gönderir.

### Oturumu kapat \{#log-out\}

Yerel olarak saklanan kimlik bilgilerinizi temizlemek için şunu çalıştırın:

```bash
adapty auth logout
```

Bu işlem `~/.config/adapty/config.json` dosyasını ve `adapty migrations create` ya da `adapty migrations use` tarafından kaydedilen migration'ı temizler. Token, süresi dolana kadar sunucu tarafında geçerli kalmaya devam eder — hemen geçersiz kılmanız gerekiyorsa bunun yerine `adapty auth revoke` kullanın.

### Tokenınızı iptal edin \{#revoke-your-token\}

Token'ı sunucuda geçersiz kılmak ve yerel olarak temizlemek için şu komutu çalıştırın:

```bash
adapty auth revoke
```

Token'ın kaydedilmiş bir migration'ı varsa, CLI onu da temizler; ancak bunu yalnızca sunucu iptali onayladıktan sonra yapar. Bir token'ı tamamen geçersiz kılmak istediğinizde bunu kullanın — örneğin, kimlik bilgileriniz ele geçirilmiş olabilirse. İptal ettikten sonra yeniden kimlik doğrulamak için `adapty auth login` komutunu çalıştırın.

## Token hataları \{#token-errors\}

Bir token iptal edilirse veya geçersiz hale gelirse, CLI komutları 401 hatası döndürür. Yeniden kimlik doğrulaması yapmak için şunu çalıştırın:

```bash
adapty auth login
```
