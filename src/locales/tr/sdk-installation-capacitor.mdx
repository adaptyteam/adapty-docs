Adapty SDK, Capacitor uygulamanıza sorunsuz entegrasyon için iki temel modül içerir:

- **Core Adapty**: Bu modül, Adapty'nin uygulamanızda düzgün çalışması için gereklidir.
- **AdaptyUI**: Bu modül, eski builder paywalllarına ek olarak flow'ları da render eder. AdaptyUI, core modülüyle birlikte otomatik olarak etkinleştirilir.

:::tip
Adapty SDK'nın bir mobil uygulamaya nasıl entegre edildiğini gerçek bir örnekle görmek ister misiniz? Paywall gösterme, satın alma yapma ve diğer temel işlevler dahil tam kurulumu gösteren [örnek uygulamalarımıza](https://github.com/adaptyteam/AdaptySDK-Capacitor/tree/master/examples) göz atın.
:::

|--------------------|-------------------|-------------|
| 4.4+               | 8                 | Flow'lar için **16.0+**, diğer özellikler için 15.0+ |
| 4.1–4.3            | 8                 | 15.0+       |
| 3.16.0+            | 8                 | 15.0+       |
| 3.15               | 7                 | 14.0+       |

Capacitor 6 ve altı sürümler desteklenmemektedir.

iOS için geliştirme yaparken **Xcode 26** veya üzeri gereklidir — yerel iOS SDK'sı Swift tools 6.2 ile derlenmiştir. Android'de ise minimum SDK sürümü 24'tür.

### iOS projenizi kurun \{#set-up-your-ios-project\}

iOS'ta SDK, yerel Adapty SDK'larını (`Adapty`, `AdaptyUI`, `AdaptyPlugin`) uygulamanızın iOS projesinin paket yöneticisi aracılığıyla yükler:

- **Swift Package Manager (önerilen)**: Capacitor 8, yeni iOS projelerini varsayılan olarak SPM ile oluşturur ve SDK için ekstra bir kurulum gerekmez.
- **CocoaPods (SDK 4.2.0 ve sonrası)**: `Podfile`'ınız, native SDK'ları herkese açık CocoaPods spec repo'sundan değil, [Adapty'nin spec repo'sundan](https://github.com/adaptyteam/AdaptySDK-CocoaPods-Specs) pod olarak yükler. Herkese açık repo [Aralık 2026'da salt okunur hale gelecektir](https://blog.cocoapods.org/CocoaPods-Specs-Repo/). SDK 4.0 ve 4.1 CocoaPods'u desteklemiyor.

```ruby showLineNumbers title="ios/App/Podfile" {2-6,10}
require_relative '../../node_modules/@capacitor/ios/scripts/pods_helpers'
require Pod::Executable.execute_command('node', ['-p',
  'require.resolve(
    "@adapty/capacitor/ios/adapty_podfile.rb",
    {paths: [process.argv[1]]},
  )', __dir__]).strip

target 'App' do
  capacitor_pods
  adapty_pods!
  # Add your Pods here
end
```

`npx cap sync` komutu, `Podfile` dosyasındaki ilk `require_relative` satırından `pods_helpers` satırına kadar olan kısmı ve `def capacitor_pods` metodunun tamamını yeniden oluşturur. Bu bölümlerin herhangi birine eklenen `require` veya `adapty_pods!` çağrısı, bir sonraki sync işleminde kaybolur.

`adapty_pods!` çağrısı, `Adapty`, `AdaptyUI` ve `AdaptyPlugin` pod'larını tanımlar ve bunları Adapty'nin spec repo'suna bağlar; bu nedenle ayrıca bir `source` satırı eklemenize gerek yoktur. `Podfile` dosyanızdaki açık `pod 'Adapty'`, `pod 'AdaptyUI'` veya `pod 'AdaptyPlugin'` satırlarını kaldırın.

Ardından iOS projesini sync edin:

```sh
npx cap sync ios
```

`@adapty/capacitor` paketini daha sonra güncellediğinizde, `pod install` komutu Adapty'nin spec repo'sunu yenilemez. Yeni sürümün gerektirdiği native SDK sürümünü yüklemek için şunu çalıştırın:

```sh
cd ios/App && pod install --repo-update
```

## Adapty SDK'nın Adapty modülünü etkinleştirin \{#activate-adapty-module-of-adapty-sdk\}

:::note
Adapty SDK'nın uygulamanızda yalnızca bir kez etkinleştirilmesi yeterlidir.
:::

<GetKey />

Adapty'yi etkinleştirmek için aşağıdaki kodu herhangi bir uygulama dosyasına kopyalayın:

```typescript showLineNumbers

try {
  await adapty.activate({
    apiKey: 'YOUR_PUBLIC_SDK_KEY',
    params: {
      // verbose logging is recommended for the development purposes and for the first production release
        logLevel: 'verbose',
      // in the development environment, use this variable to avoid multiple activation errors. Set it to your development environment variable
      __ignoreActivationOnFastRefresh: true,
    }
  });
  console.log('Adapty activated successfully!');
} catch (error) {
  console.error('Failed to activate Adapty SDK:', error);
}
```

:::important
Diğer Adapty SDK metotlarını çağırmadan önce `activate` işleminin tamamlanmasını bekleyin. Tam sıra için [Capacitor SDK'da çağrı sırası](capacitor-sdk-call-order) bölümüne bakın.
:::

:::tip
Geliştirme ortamındaki aktivasyon hatalarını önlemek için [ipuçlarına](#development-environment-tips) bakın.
:::

Şimdi uygulamanızda paywallları ayarlayın:

- [Flow & Paywall Builder](adapty-flow-builder) kullanıyorsanız [hızlı başlangıç](capacitor-quickstart-paywalls) kılavuzunu takip edin.
- Kendi paywall arayüzünüzü oluşturuyorsanız [özel paywalllar için hızlı başlangıç](capacitor-quickstart-manual) kılavuzuna bakın.

[Flow & Paywall Builder](adapty-flow-builder) kullanmayı planlıyorsanız AdaptyUI modülüne ihtiyacınız var. Bu işlem, core modülü etkinleştirdiğinizde otomatik olarak gerçekleşir; başka bir şey yapmanıza gerek yoktur.

## İsteğe bağlı kurulum \{#optional-setup\}

### Günlükleme \{#logging\}

#### Günlük sistemini yapılandırın \{#set-up-the-logging-system\}

Adapty, neler olduğunu anlamanıza yardımcı olmak için hataları ve diğer önemli bilgileri günlüğe kaydeder. Aşağıdaki seviyeler kullanılabilir:

| Level      | Description                                                  |
| ---------- | ------------------------------------------------------------ |
| `error`    | Yalnızca hatalar loglanır                                    |
| `warn`     | Hatalar ve SDK'dan gelen, kritik hatalara yol açmayan ancak dikkat edilmesi gereken mesajlar loglanır |
| `info`     | Hatalar, uyarılar ve çeşitli bilgi mesajları loglanır |
| `verbose`  | Hata ayıklama sırasında işe yarayabilecek her türlü ek bilgi (fonksiyon çağrıları, API sorguları vb.) loglanır |
| `debug`    | Yukarıdakilerin tamamı, ayrıca native SDK'nın düşük seviyeli iç ayrıntıları. Android'in bunun için ayrı bir seviyesi yoktur ve `verbose` düzeyinde loglar. SDK 4.3.0 sürümünden itibaren kullanılabilir |

Adapty yapılandırmasından önce veya yapılandırma sırasında uygulamanızda log seviyesini ayarlayabilirsiniz:

```typescript showLineNumbers
// Set log level before activation
adapty.setLogLevel({ logLevel: 'verbose' });

// Or set it during configuration
await adapty.activate({
  apiKey: 'YOUR_PUBLIC_SDK_KEY',
  params: {
    logLevel: 'verbose',
  }
});
```

### Veri politikaları \{#data-policies\}

Adapty, kullanıcılarınızın kişisel verilerini siz açıkça göndermediğiniz sürece saklamaz; ancak mağaza veya ülke yönergelerine uymak için ek veri güvenlik politikaları uygulayabilirsiniz.

#### IP adresi toplama ve paylaşımını devre dışı bırakma \{#disable-ip-address-collection-and-sharing\}

Adapty modülünü etkinleştirirken, kullanıcı IP adresi toplama ve paylaşımını devre dışı bırakmak için `ipAddressCollectionDisabled` değerini `true` olarak ayarlayın. Varsayılan değer `false`'tur.

Bu parametreyi, kullanıcı gizliliğini artırmak, bölgesel veri koruma düzenlemelerine (GDPR veya CCPA gibi) uymak ya da IP tabanlı özellikler uygulamanız için gerekli değilse gereksiz veri toplamayı azaltmak amacıyla kullanabilirsiniz.

```typescript showLineNumbers
await adapty.activate({
  apiKey: 'YOUR_PUBLIC_SDK_KEY',
  params: {
    ipAddressCollectionDisabled: true,
  }
});
```

#### Reklam kimliği toplama ve paylaşımını devre dışı bırakma \{#disable-advertising-id-collection-and-sharing\}

Adapty modülünü etkinleştirirken, reklam tanımlayıcılarının toplanmasını devre dışı bırakmak için `ios.idfaCollectionDisabled` (iOS) veya `android.adIdCollectionDisabled` (Android) değerini `true` olarak ayarlayın. Varsayılan değer `false`'tur.

Bu parametreyi; App Store/Play Store politikalarına uymak, App Tracking Transparency istemini tetiklemekten kaçınmak veya uygulamanız reklam kimliklerine dayalı attribution ya da analitik gerektirmiyorsa kullanın.

```typescript showLineNumbers
await adapty.activate({
  apiKey: 'YOUR_PUBLIC_SDK_KEY',
  params: {
    ios: {
      idfaCollectionDisabled: true,
    },
    android: {
      adIdCollectionDisabled: true,
    },
  }
});
```

#### AdaptyUI için medya önbellek yapılandırmasını ayarlama \{#set-up-media-cache-configuration-for-adaptyui\}

AdaptyUI, performansı artırmak ve ağ kullanımını azaltmak için medyayı (resimler ve videolar gibi) varsayılan olarak önbelleğe alır. Özel bir yapılandırma sağlayarak önbellek ayarlarını özelleştirebilirsiniz.

Varsayılan önbellek ayarlarını geçersiz kılmak için `mediaCache` kullanın:

```typescript showLineNumbers
await adapty.activate({
  apiKey: 'YOUR_PUBLIC_SDK_KEY',
  params: {
    mediaCache: {
      memoryStorageTotalCostLimit: 200 * 1024 * 1024, // Optional: memory cache size in bytes
      memoryStorageCountLimit: 2147483647,            // Optional: max number of items in memory
      diskStorageSizeLimit: 200 * 1024 * 1024,       // Optional: disk cache size in bytes
    },
  }
});
```

| Parametre | Zorunlu | Açıklama |
|-----------|---------|----------|
| memoryStorageTotalCostLimit | isteğe bağlı | Bellekteki toplam önbellek boyutu (bayt cinsinden). Platform'a özgü varsayılan değer kullanılır. |
| memoryStorageCountLimit | isteğe bağlı | Bellek deposundaki öğe sayısı sınırı. Platform'a özgü varsayılan değer kullanılır. |
| diskStorageSizeLimit | isteğe bağlı | Diskteki dosya boyutu sınırı (bayt cinsinden). Platform'a özgü varsayılan değer kullanılır. |

### Yerel access level'ları etkinleştirin (Android) \{#enable-local-access-levels-android\}

Varsayılan olarak [yerel access level'lar](local-access-levels) iOS'ta etkin, Android'de devre dışıdır. Android'de de etkinleştirmek için `localAccessLevelAllowed` değerini `true` olarak ayarlayın:

```typescript showLineNumbers
await adapty.activate({
    apiKey: 'YOUR_PUBLIC_SDK_KEY',
    params: {
        android: {
            localAccessLevelAllowed: true,
        },
    }
});
```

### Yedekten geri yüklemede veriyi temizleme \{#clear-data-on-backup-restore\}

`clearDataOnBackup` `true` olarak ayarlandığında, SDK uygulamanın iCloud yedeğinden geri yüklendiğini algılar ve önbelleğe alınmış profil bilgileri, ürün ayrıntıları ve paywaller dahil olmak üzere yerel olarak depolanan tüm SDK verilerini siler. Ardından SDK temiz bir durumla başlatılır. Varsayılan değer `false`'tur.

:::note
Yalnızca yerel SDK önbelleği silinir. Apple'daki işlem geçmişi ve Adapty sunucularındaki kullanıcı verileri değişmeden kalır.
:::

```typescript showLineNumbers
await adapty.activate({
    apiKey: 'YOUR_PUBLIC_SDK_KEY',
    params: {
        ios: {
            clearDataOnBackup: true,
        },
    }
});
```

### Mağaza mesajlarının yönetimi \{#store-messages-handling\}

:::info
Bu parametre SDK 4.3.0 sürümünden itibaren kullanılabilir.
:::

Varsayılan olarak, StoreKit — fiyat artışı onay istekleri, fatura sorunları bildirimleri ve geri kazanma teklifleri gibi — App Store mesajlarını uygulamanız açıkken kendi başına gösterir; SDK ise `activate` sonrasında uygulamanızın bir `Activity`'si her başladığında Google Play mesajlarını (örneğin reddedilen ödeme bildirimleri) ister. Uygulamanızın bu mesajları ne zaman göstereceğini belirlemek için `storeMessagesHandling` değerini `'manual'` olarak ayarlayın. Varsayılan değer `'auto'`'dur.

```typescript showLineNumbers
await adapty.activate({
  apiKey: 'YOUR_PUBLIC_SDK_KEY',
  params: {
    storeMessagesHandling: 'manual',
  }
});
```

Manuel modda, mağazalar mesajları kendi başlarına göstermez; bu nedenle uygulamanızın `showStoreMessages` fonksiyonunu çağırması gerekir. Nasıl yapılacağını öğrenmek için [Mağaza mesajlarını kontrol etme](capacitor-store-messages) bölümüne bakın.

### Adapty Attribution'ı Etkinleştirin \{#enable-adapty-attribution\}

:::info
Bu parametre SDK 4.1 sürümünden itibaren kullanılabilir.
:::

[Adapty Attribution](user-acquisition) kullanıyorsanız, SDK'yı etkinleştirirken `adaptyAttributionEnabled` değerini `true` olarak ayarlayın. Varsayılan değer `false`'tur: bu parametre olmadan SDK, kurulumları kaydetmez veya kurulum ayrıntılarını uygulamanıza iletmez. SDK'nın 4.1'den önceki sürümlerinde Adapty Attribution otomatik olarak etkinleştirilir.

```typescript showLineNumbers
await adapty.activate({
  apiKey: 'YOUR_PUBLIC_SDK_KEY',
  params: {
    adaptyAttributionEnabled: true,
  }
});
```

## Geliştirme ortamı ipuçları \{#development-environment-tips\}

#### Capacitor'ın canlı yenileme özelliğinde SDK etkinleştirme hatalarını giderme \{#troubleshoot-sdk-activation-errors-on-capacitors-live-reload\}

Capacitor'da Adapty SDK ile geliştirme yaparken şu hatayla karşılaşabilirsiniz: `Adapty can only be activated once. Ensure that the SDK activation call is not made more than once.`

Bu hata, Capacitor'ın canlı yenileme özelliğinin geliştirme sırasında birden fazla etkinleştirme çağrısını tetiklemesinden kaynaklanır. Bunu önlemek için `__ignoreActivationOnFastRefresh` seçeneğini Capacitor'ın geliştirme modu bayrağına ayarlayın; kullandığınız pakete göre bu bayrak farklılık gösterebilir.

```typescript showLineNumbers
try {
  await adapty.activate({
    apiKey: 'YOUR_PUBLIC_SDK_KEY',
    params: {
        // Set your development environment variable
      __ignoreActivationOnFastRefresh: true,
    }
  });
} catch (error) {
  console.error('Failed to activate Adapty SDK:', error);
  // Handle the error appropriately for your app
}
```

:::note
Bu seçenek etkinleştirildiğinde, SDK bir kez aktive edildikten sonra aktivasyon çağrısının tamamını atlar; dolayısıyla aktivasyon parametrelerindeki değişiklikler canlı yeniden yüklemede geçerli olmaz. Yeni aktivasyon parametrelerini uygulamak için uygulamayı tamamen kapatıp yeniden başlatın.
:::

## Sorun Giderme \{#troubleshooting\}

#### iOS 15–17'de uygulama başlatılırken çöküyor \{#app-crashes-on-launch-on-ios-15-17\}

Uygulamanız iOS 15–17'de `Library not loaded: …/SwiftUICore.framework/SwiftUICore` hatasıyla başlatılırken çökerse, bunun nedeni `App` ürün adıdır. Capacitor'ın varsayılan adı olan bu isimle Xcode 26, uygulamayı doğrudan `SwiftUICore`'a bağlar ve iOS 15–17 bu kütüphaneyi yükleyemez.

Çökmesini önlemek için `App` hedefinin **Build Settings** bölümünde **Other Linker Flags** alanına şu değerleri ekleyin:

```
-Xlinker -ignore_auto_link_library -Xlinker SwiftUICore
```

#### Minimum iOS sürüm hatası \{#minimum-ios-version-error\}

:::note
Bu, CocoaPods tabanlı projeler için geçerlidir: **SDK 3.x**'te ve [CocoaPods](#set-up-your-ios-project) seçeneğiyle SDK 4.2.0 ve sonrasında. Swift Package Manager'da `Podfile` bulunmaz; bunun yerine deployment target'ı Xcode'da 15.0 olarak ayarlayın.
:::

Minimum iOS sürümü hatası alırsanız Podfile'ınızı güncelleyin:

```diff
-platform :ios, '14.0'
+platform :ios, '15.0'
```

#### Android'de başka bir uygulamadan döndükten sonra satın almalar başarısız oluyor \{#purchases-fail-after-returning-from-another-app-in-android\}

Satın alma akışını başlatan Activity, varsayılan olmayan bir `launchMode` kullanıyorsa Android, kullanıcı Google Play'den, bir bankacılık uygulamasından veya tarayıcıdan döndüğünde bu Activity'yi yanlış şekilde yeniden oluşturabilir veya yeniden kullanabilir. Bu durum, satın alma sonucunun kaybolmasına ya da iptal edilmiş olarak değerlendirilmesine yol açabilir.

Satın alma işlemlerinin doğru çalışması için, satın alma akışını başlatan Activity'de yalnızca `standard` veya `singleTop` başlatma modlarını kullanın; diğer modlardan kaçının.

`AndroidManifest.xml` dosyanızda, satın alma akışını başlatan Activity'nin `standard` veya `singleTop` olarak ayarlandığından emin olun:

```xml
<activity
    android:name=".MainActivity"
    android:launchMode="standard" />
```

#### Podfile SWIFT_VERSION geçersiz kılmasından kaynaklanan Swift 6 derleme hataları \{#swift-6-build-errors-caused-by-podfile-swift-version-override\}

:::note
Bu durum, yerel iOS SDK'ları CocoaPods pod'ları olarak kurulduğunda geçerlidir: **SDK 3.x**'te ve [CocoaPods](#set-up-your-ios-project) seçeneğiyle SDK 4.2.0 ve sonrasında. Swift paketleri olarak kurulduklarında, `post_install` içindeki `SWIFT_VERSION` geçersiz kılma işlemi onlara ulaşmaz.
:::

Capacitor uygulamanızı iOS için derlerken Adapty pod hedeflerinde Swift 6 derleme hatalarıyla karşılaşabilirsiniz. Tipik belirtiler arasında `AdaptyUIBuilderLogic` içinde `@Sendable` uyumsuzlukları, Adapty türlerinde eksik `Sendable` uyumu veya actor izolasyon hataları yer alır.

Adapty pod'ları `s.swift_version = '6.0'` bildirimi yapar ve derlenmek için Swift 6 gerektirir. Kendi uygulama kodunuz Swift 5'te kalabilir — yalnızca Adapty pod hedeflerinin (`Adapty`, `AdaptyUI`, `AdaptyUIBuilder`, `AdaptyLogger`, `AdaptyPlugin` ve SDK 4.2.0 ile sonrasında `AdaptyCodable`) Swift 6 ile derlenmesi gerekir.

En yaygın neden, `ios/App/Podfile` dosyasındaki her pod hedefi için `SWIFT_VERSION` değerini yeniden yazan bir `post_install` hook'udur:

```ruby showLineNumbers title="ios/App/Podfile"
post_install do |installer|
  installer.pods_project.targets.each do |target|
    target.build_configurations.each do |config|
      config.build_settings['SWIFT_VERSION'] = '5.9'
    end
  end
end
```

**Düzeltme**: Adapty pod hedeflerini bu geçersiz kılmanın dışında tutun:

```ruby showLineNumbers title="ios/App/Podfile"
post_install do |installer|
  installer.pods_project.targets.each do |target|
    next if %w[Adapty AdaptyUI AdaptyUIBuilder AdaptyLogger AdaptyPlugin AdaptyCodable].include?(target.name)
    target.build_configurations.each do |config|
      config.build_settings['SWIFT_VERSION'] = '5.9'
    end
  end
end
```

Ardından `npx cap sync ios` komutunu çalıştırın ve yeniden derleyin.

Doğrulamak için `ios/App/Pods/Pods.xcodeproj` dosyasını açın, `Adapty` pod hedefini seçin → **Build Settings** → **Swift Language Version**. Değerin **Swift 6** olması gerekir.
