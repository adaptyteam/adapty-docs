Bir RevenueCat projesini Adapty'ye taşıyın: önce kataloğunu, ardından isteğe bağlı olarak mağaza olaylarını ve işlem geçmişini. Adapty her migrasyonu bir dizi adım olarak çalıştırır ve ardından hangi işlemleri yapabileceğinizi söyler; bu nedenle her işlem öncesinde `status` komutunu çalıştırın. Prosedürün tamamı için bkz. [RevenueCat'ten Migrasyon](migration-from-revenuecat).

`list`, `create`, `use`, `current` ve `unuse` dışındaki tüm komutlar migration bayrağını kabul eder:

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `-m`, `--migration` | Hayır | Migration ID'si. Belirtilmezse CLI sırasıyla `ADAPTY_MIGRATION` ortam değişkenini, ardından `create` veya `use` tarafından kaydedilen migration'ı kullanır. |

## adapty migrations list

Geçişlerinizi ve başlatabileceğiniz migration flow'larını uygulamaya göre gruplandırılmış şekilde listeleyin.

```bash
adapty migrations list
```

## adapty migrations create \{#adapty-migrations-create\}

Bir migration başlatır ve mevcut migration olarak kaydeder.

```bash
adapty migrations create --name <app-name>
adapty migrations create --flow <flow> --app <app-id>
```

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--name` | `--name` veya `--flow`'dan biri | Yeni Adapty uygulamasının adı. Katalog migrasyonunu başlatır. `--flow` veya `--app` ile birleştirilemez. |
| `--flow` | `--name` veya `--flow`'dan biri | `adapty migrations list` komutunun gösterdiği şekliyle mevcut bir uygulamada başlatılacak flow. `--app` gerektirir. |
| `--app` | `--flow` ile | Uygulama kimliği (UUID) |
| `--no-select` | Hayır | Migrasyonu mevcut migrasyon olarak kaydetmeden oluşturur |

Mevcut bir uygulamanın katalog migrasyonundan sonra kullanılabilir flow'lar:

| Flow | Açıklama |
|---|---|
| `transactions` | Günlük RevenueCat Cloud Export'tan işlem geçmişini içe aktarır |
| `transactions_support` | Cloud Export olmayan RevenueCat planları için RevenueCat desteği ve Adapty desteği aracılığıyla işlem geçmişini içe aktarır |
| `apple_events` | RevenueCat almaya devam ederken App Store bildirimlerini Adapty'ye iletir |
| `google_events` | Adapty'yi RevenueCat'in Google Play bildirimleri için kullandığı Pub/Sub konusuna abone eder |
| `code` | Kodlama ajanınızın uygulamanın bir kod tabanındaki RevenueCat SDK'sını değiştirmesini sağlar |
| `integrations` | Kodlama ajanınızın Adapty'de kurulum için uygulama kodundaki analitik, attribution ve mesajlaşma araçlarını bulmasını sağlar |
| `paywall_design` | Kodlama ajanınızın katalog migrasyonunun oluşturduğu flow'larda RevenueCat paywall tasarımlarını yeniden oluşturmasını sağlar |

## adapty migrations use \{#adapty-migrations-use\}

Bir migration'ı geçerli olarak kaydeder; böylece diğer komutlarda `-m` kullanmanıza gerek kalmaz.

```bash
adapty migrations use <migration-id>
```

| Argüman | Açıklama |
|---|---|
| `migration-id` | `adapty migrations list` komutundan alınan migration ID'si |

CLI, ID'yi kaydetmeden önce migration'a erişiminizin olup olmadığını kontrol eder. Kaydedilen migration, geçerli token'a aittir ve her terminalde geçerlidir.

## adapty migrations current

Geçerli migration'ı ve kaynağını gösterir: `ADAPTY_MIGRATION` ortam değişkeni veya kaydedilmiş seçim.

```bash
adapty migrations current
```

## adapty migrations unuse

Kaydedilen migration'ı temizler. Shell'inizde ayarlanmış bir `ADAPTY_MIGRATION` değeri, siz kaldırana kadar geçerli kalmaya devam eder.

```bash
adapty migrations unuse
```

## adapty migrations status

Bir migration'ın durumunu, sorunlarını ve çalıştırabileceğiniz sonraki adımları gösterir.

```bash
adapty migrations status
```

| Flag | Zorunlu | Açıklama |
|---|---|---|
| `--wait` | Hayır | Migration değişene kadar yoklama yapar, ardından en güncel durumu döndürür |
| `--timeout` | Hayır | `--wait` için yoklama süresi: 1–600 saniye, varsayılan 120. `300`, `300s` veya `5m` biçiminde belirtilebilir. `--wait` gerektirir. |

`--json` ile `next_actions` ve `available_actions`, her action'ın ID'sini, okuduğu kaynakları, `input_schema`'sını ve `confirm` metnini listeler.

`0` çıkış kodu isteğin başarılı olduğu anlamına gelir, migration'ın başarılı olduğu anlamına gelmez. Yanıttaki `migration.state` alanını kontrol edin.

## Adapty migration adımları \{#adapty-migrations-steps\}

Migration kontrol listesini ve her adımın durumunu gösterir.

```bash
adapty migrations steps
```

## adapty migrations show

Şu anda okuyabileceğiniz kaynakları listeleyin veya birini okuyun.

```bash
adapty migrations show [resource]
```

| Argüman | Açıklama |
|---|---|
| `resource` | Kaynak adı, örneğin `apps`, `mapping`, `report` veya `export-config`. Mevcut adımda kullanılabilir kaynakları listelemek için atlayın. |

## adapty migrations run

`adapty migrations status` komutundan bir eylem çalıştırır.

```bash
adapty migrations run <action-id>
```

| Bağımsız Değişken | Açıklama |
|---|---|
| `action-id` | `adapty migrations status` komutundaki `next_actions` veya `available_actions` içindeki eylem ID'si |

| Bayrak | Gerekli | Açıklama |
|---|---|---|
| `--input` | Hayır | Eylemin `input_schema` ile eşleşen bir JSON nesnesi olarak eylem girdisi. Girdi olmadan CLI `{}` gönderir. |
| `--input-file` | Hayır | Eylem girdisini içeren bir dosyanın yolu ya da stdin'den okumak için `-`. `--input` ile birlikte kullanılamaz. |
| `-y`, `--yes` | `confirm` metni olan eylemler için | `confirm` metnini okuduktan sonra eylemi onaylayın. Etkileşimli bir istem yoktur. |
| `--open` | Hayır | Pipe veya `--json` ile bile eylemin bağlantısını açar |
| `--no-browser` | Hayır | Eylemin bağlantısını bir tarayıcı açmadan yazdırır |

Eylemler üç türde gelir:

- **Girdi eylemleri**, verilerinizi Adapty'ye gönderir; örneğin taşınacak RevenueCat uygulamaları veya eşleme kararlarınız.
- **Harici eylemler**, Adapty Kontrol Paneli'nde bir sayfa açar; örneğin RevenueCat gizli API anahtarını yapıştırmak için. Sayfayı tamamlayın, ardından `status`'u kontrol edin.
- **Agent eylemleri**, örneğin `migrate_code`, kodlama agent'ınız için yapılacak işlerdir. Bunları uygulamanın git deposundan çalıştırın: CLI, taşıma verilerini `.git/adapty/<migration-id>/` altına kaydeder ve agent için talimatları yazdırır. Agent, eylemi `--input` ile tekrar çalıştırarak sonucu bildirir.

## adapty migrations close

Bir migration'ı tamamlayın veya iptal edin. Sonrasında yeniden açamazsınız.

```bash
adapty migrations close --outcome finish --yes
```

| Flag | Gerekli | Açıklama |
|---|---|---|
| `--outcome` | Evet | `finish` migration'ı tamamlandı olarak işaretler; `cancel` ise iptal eder |
| `-y`, `--yes` | Evet | Kapatma işlemini onaylayın |
