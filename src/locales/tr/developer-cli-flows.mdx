[Flow'lar](adapty-flow-builder), Flow & Paywall Builder'da oluşturduğunuz paywall'lar ve onboarding'lerdir. CLI, flow kaydını, builder config'ini, yayını ve [versiyon geçmişini](flow-version-history) yönetir. Builder config, Flow & Paywall Builder'ın normalde ürettiği büyük bir JSON belgesidir; CLI bu belgeyi oluşturmaz. Terminalden bir config yazmak veya düzenlemek için bu komutları sizin adınıza çalıştıran [flow-generator skill](flow-generator-skill)'ini kullanın. Yayınlamadan önce [flow-audit skill](flow-audit-skill), flow'un production'a hazır olup olmadığını kontrol eder. `flows metrics` komutları [flow metrikleri](flow-metrics) sayfasındaki verileri okur ve CLI 0.15.0 veya üzeri bir sürüm gerektirir. `flows funnel` komutları ise [flow funnel](flow-funnel)'ını okur ve CLI 0.19.0 veya üzeri bir sürüm gerektirir. Komutlar burada referans olarak listelenmiştir.

## adapty flows list

Bir uygulamaya ait tüm flow'ları listeler.

```bash
adapty flows list --app <app-id>
```

| Flag | Gerekli | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |

[Sayfalandırma flag'lerini](developer-cli-reference#global-flags) kabul eder.

## adapty flows get

Belirli bir flow için ayrıntıları alır.

```bash
adapty flows get --app <app-id> <flow-id>
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Flag | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |

Yanıt; `id`, `name`, `status`, `published_flow_version_id` ve `updated_at` alanlarını içerir. `published_flow_version_id`, yayındaki sürümün ID'sidir; flow hiç yayınlanmamışsa `null` döner. Durum aşağıdakilerden biri olabilir:

| Durum | Anlam |
|---|---|
| `draft` | Flow hiç yayınlanmadı |
| `published` | Mevcut sürüm yayında |
| `dirty` | Flow daha önce yayınlandı ve mevcut sürümde yayınlanmamış değişiklikler var. Kullanıcılar son yayınlanan sürümü görmeye devam eder |
| `publishing` | Yayınlama işlemi devam ediyor |
| `publication_failed` | Son yayınlama başarısız oldu. Yapılandırmayı düzeltin ve tekrar yayınlayın |
| `archived` | Flow arşivlendi |

## adapty flows create \{#adapty-flows-create\}

Bir flow oluşturur. Yeni flow'un bir adı vardır ancak yapılandırması yoktur. Yapılandırma eklemek için [`flows config update`](#adapty-flows-config-update) komutunu kullanın.

```bash
adapty flows create --app <app-id> --name "Onboarding"
```

| Flag | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--name` | Evet | Flow adı |

## adapty flows publish

Flow'un mevcut sürümünü kullanıcılarınıza yayınlayın.

```bash
adapty flows publish --app <app-id> <flow-id>
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--yes`, `-y` | Hayır | Onay sormadan yayınlayın. Çıktı yönlendirildiğinde veya `--json` kullanıldığında zorunludur |

Değişiklikleri yayımlamak kullanıcılarınızın gördüğü içeriği etkilediğinden, komut flow adını ekrana yazdırır ve onay ister. `y` dışındaki her yanıt, komutu çıkış kodu 1 ile iptal eder. `--json` bayrağı kullanılırken veya bir pipe içinde çalıştırılırken komut, yanıt beklemek yerine çıkış kodu 2 ile reddeder; bu nedenle script'lerde ve agent oturumlarında `--yes` parametresini kullanın.

Yayımlama işlemi asenkrondur: yanıt `status: publishing` döner ve flow henüz yayında değildir. Durum `published` ya da `publication_failed` olana kadar [`flows get`](#adapty-flows-get) ile sorgulama yapın. `publication_failed` durumunda, [`flows config get`](#adapty-flows-config-get) nedenini raporlar.

Flow'un config'i yoksa, config yayımlanabilir değilse veya mevcut sürüm zaten yayındaysa yayımlama HTTP 400 hatasıyla başarısız olur. Yayımlamadan önce bir config'i kontrol etmek için [`flows config validate`](#adapty-flows-config-validate) kullanın.

## adapty flows config get

Bir flow'un builder config'ini okur.

```bash
adapty flows config get --app <app-id> <flow-id>
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID (UUID) |

Yanıt `config`, `remote_configs`, `status` ve `updated_at` alanlarını içerir. `updated_at`, son config değişikliğinin milisaniye cinsinden zaman damgasıdır. Eş zamanlı bir düzenlemenin üzerine yazmamak için bunu [`flows config update`](#adapty-flows-config-update) komutuna `--expected-updated-at` parametresi olarak geçirin. Config'i hiç yazılmamış bir flow için 404 döner.

Bir yayımlama girişiminin ardından yanıt, sürecin nasıl ilerlediğini açıklayan üç alan daha içerir. Bu alanları [`flows get`](#adapty-flows-get) komutu `publication_failed` döndürdüğünde okuyun:

| Alan | Açıklama |
|---|---|
| `publication_status` | Bu flow sürümünün yayınlanma aşaması: `transforming`, `transformed`, `uploading`, `uploaded`, `published` veya `failed` |
| `transform_error` | Ham dönüştürme hatası — sorunları listeleyen bir JSON yükü veya özet bir metin dizesi |
| `publication_error` | Başarısız yayın için okunabilir bir mesaj |

## adapty flows config update

Bir flow'un builder config'ini yazar.

```bash
adapty flows config update --app <app-id> <flow-id> --config-file config.json
```

| Argument | Description |
|---|---|
| `flow-id` | Flow ID (UUID) |

| Bayrak | Gerekli | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--config` | İkisinden biri | JSON dizesi olarak builder config |
| `--config-file` | İkisinden biri | Builder config içeren bir JSON dosyasının yolu veya stdin'den okumak için `-` |
| `--remote-configs` | Hayır | `{locale, data}` girişlerinden oluşan JSON dizisi; `data`, remote config'i dize olarak içerir |
| `--expected-updated-at` | Hayır | Önceki bir `flows config get` komutundan alınan `updated_at` değeri. Config bu okumadan sonra değiştirildiyse, komut değişikliğin üzerine yazmak yerine başarısız olur. Koşulsuz olarak üzerine yazmak için bu bayrağı atlayın |

Yapılandırmayı kaydetmek bir taslak oluşturur ve yayımlamaz. Yayımlanmış bir flow'da, yazma işlemi yeni bir sürüm oluşturur: flow'un durumu `dirty` olur ve siz [`flows publish`](#adapty-flows-publish) komutunu çalıştırana kadar kullanıcılar yayımlanmış sürümü görmeye devam eder.

## adapty flows config validate

Bir builder config'in kaydedilmeden yayınlanabilir olup olmadığını kontrol eder.

```bash
adapty flows config validate --app <app-id> <flow-id> --config-file config.json
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Flag | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--config` | İkisinden biri | JSON string olarak builder config |
| `--config-file` | İkisinden biri | Builder config içeren JSON dosyasının yolu veya stdin'den okumak için `-` |

`valid` yanıtı ve bir `issues` listesi içerir. Config yayınlanamaz durumda olduğunda, komut 1 koduyla çıkar; bu sayede scriptler bunu bir kontrol noktası olarak kullanabilir.

## adapty flows config preview

Yerel bir config dosyasını tarayıcıda görüntüler. Bu komut herhangi bir API çağrısı yapmaz ve `--app` bayrağı almaz.

```bash
adapty flows config preview ./config.json --screen <screen-id> --device iphone-14 --orientation portrait
```

| Argüman | Açıklama |
|---|---|
| `config-file` | Yerel bir builder config JSON dosyasının yolu |

| Bayrak | Varsayılan | Açıklama |
|---|---|---|
| `--screen` | Flow'un ilk ekranı | Görüntülenecek ekran ID'si |
| `--device` | `iphone-14` | Görüntüleneceği cihaz çerçevesi |
| `--orientation` | `portrait` | `portrait` veya `landscape` |

Terminalde komut, önizlemeyi tarayıcınızda açar. Bir pipe'a yönlendirildiğinde veya `--json` ile kullanıldığında URL'yi yazdırır. URL'nin tamamı config'i içerdiğinden oldukça uzundur: yazdırmak yerine bir ekran görüntüsü aracına pipe edin. Yaklaşık 32 KB'ı aşan config'ler yavaş render edilir.

## adapty flows versions list \{#adapty-flows-versions-list\}

Bir flow'un versiyonlarını, en yeniden en eskiye doğru listeler. Bunlar, Flow & Paywall Builder'daki [versiyon geçmişinin](flow-version-history) versiyonlarıdır.

```bash
adapty flows versions list --app <app-id> <flow-id>
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--search` | Hayır | Yalnızca başlığı bu metni içeren versiyonları gösterir. Büyük/küçük harf duyarsızdır ve kısmi eşleşme desteklenir: `friday` yazarak **Black Friday**'i bulabilirsiniz |

Her satır, bir sürümün başlığını, durumunu, tarihini ve kimliğini gösterir. Başlık, sürüm adıdır; sürümün adı yoksa **Version N** olarak görünür. Durum şunlardan biridir:

| Durum | Anlam |
|---|---|
| `draft` | Düzenlediğiniz sürüm. Bir flow'un bir taslağı olabilir ya da hiç olmayabilir. Taslak yayınlanırken satırın sonunda `Publishing…` ifadesi görünür; yayınlama başarısız olursa `Publish failed` ifadesi görünür |
| `live` | Kullanıcılarınızın gördüğü sürüm |
| `previous` | Daha önceki bir sürüm. Daha önce yayındaydı ya da yayına girmeden önce daha yeni bir sürüm tarafından yerini aldı |

Bir `live` veya `previous` versiyonun tarihi, yayınlanmaya başladığı tarihtir. Taslak için ve hiç yayınlanmamış bir `previous` versiyon için ise versiyonun oluşturulduğu tarihtir.

Hiç yayınlanmamış bir flow için komut `History will appear after the first publish.` mesajını ve altında taslak satırını yazdırır. Kontrol panelindeki [versiyon geçmişi](flow-version-history) böyle bir flow için herhangi bir satır göstermez. `--search` ile eşleşen versiyon bulunamadığında komut `No versions match the search.` mesajını yazdırır.

Komut her zaman tüm versiyonları listeler ve sayfalama bayrağı almaz.

`--json` ile komut, `data` içindeki satırlarla birlikte Adapty'den gelen `{data, meta}` çıktısını değiştirmeden yazdırır. Her satırda `flow_version_id`, `version`, `name`, `title`, `state`, `is_current`, `publication_status`, `published_at`, `created_at`, `updated_at` ve `last_edited_by` alanları bulunur. `updated_at`, versiyonun son içerik değişikliğinin milisaniye cinsinden zaman damgasıdır: taslağın `updated_at` değerini [`flows versions restore`](#adapty-flows-versions-restore) komutuna `--expected-updated-at` olarak geçirebilirsiniz. `last_edited_by`, versiyonu en son değiştiren kullanıcının adını içerir; Adapty kullanıcıyı tanıyamadığında `null` döner.

## adapty flows versions get

Bir flow'un bir sürümünü okur. Sürümü okumak hiçbir şeyi değiştirmez: taslak ve yayın sürümü olduğu gibi kalır.

Komut, sürümün başlığını, ID'sini, numarasını, durumunu ve tarihini, en son değişikliği yapan kullanıcıyı ve **Test on device** bağlantısını yazdırır. Sürümün tam içeriği — tüm düzenleri içeren builder config'i, remote config'leri ve paywallları — `--json` çıktısında ve `--output` dosyasında yer alır.

```bash
adapty flows versions get --app <app-id> <flow-id> <version-id> --output version.json
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID (UUID) |
| `version-id` | Versiyon ID (UUID), [`flows versions list`](#adapty-flows-versions-list) komutundan alınır |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID (UUID) |
| `--output` | Hayır | Versiyonun tam içeriğini JSON olarak bu dosyaya yazar |
| `--yes`, `-y` | Hayır | Mevcut `--output` dosyasının üzerine onay sormadan yazar. `--json` ile veya dosya mevcutken pipe kullanılıyorsa zorunludur |

`--output` dosyası yazılamazsa, örneğin klasörü mevcut değilse, komut `Could not write <path> (<errno>).` mesajını yazdırır ve 1 koduyla çıkar.

## adapty flows versions rename

```bash
adapty flows versions rename --app <app-id> <flow-id> <version-id> --name "Black Friday"
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID (UUID) |
| `version-id` | Versiyon ID (UUID) |

| Flag | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID (UUID) |

Komut, sürüm ID'sini ve yeni başlığı yazdırır. Adapty, adın sonundaki boşlukları kırpar. İki sürüm aynı ada sahip olabilir. Yeniden adlandırma işlemi sürümün içeriğini veya `updated_at` değerini değiştirmez; bu nedenle taslağın sonraki bir kaydıyla çakışmaz.

## adapty flows versions restore \{#adapty-flows-versions-restore\}

Aynı flow'un taslağı olarak bir sürümü geri yükler. Bu, [sürüm geçmişindeki](flow-version-history#restore-an-earlier-version) **Duplicate as draft** işlevidir. Geri yüklenen sürüm, [yayımlayana](#adapty-flows-publish) kadar kullanıcılarınıza ulaşmaz.

:::tip
Geri yükleme işlemi mevcut taslağın üzerine yazar. Taslağı korumak istiyorsanız önce [`flows duplicate`](#adapty-flows-duplicate) komutuyla yeni bir flow olarak çoğaltın.
:::

```bash
adapty flows versions restore --app <app-id> <flow-id> <version-id>
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID (UUID) |
| `version-id` | `live` veya `previous` sürümün Versiyon ID'si (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--expected-updated-at` | `--yes` ile birlikte, flow'un bir taslağı varsa | [`flows versions list --json`](#adapty-flows-versions-list) komutundan alınan taslağın `updated_at` değeri. Taslak bu okumadan sonra değiştirilmişse, değişikliğin üzerine yazmak yerine komut başarısız olur |
| `--yes`, `-y` | Hayır | Taslağın üzerine sormadan yazar. Flow'un bir taslağı varsa `--json` ile veya pipe içinde kullanıldığında zorunludur |

Bu komut önce flow'ların sürümlerini okur:

- **Flow'un taslağı yok**: Komut hiçbir şey sormaz. Adapty, bir sonraki sürüm numarasıyla, isimsiz ve o sürümün tüm içeriğiyle yeni bir taslak oluşturur. Canlı sürüm ve geri yüklediğiniz sürüm olduğu gibi kalır.
- **Flow'un taslağı var**: Komut şunu sorar: `Replace the draft '<draft>' (last change <time> by <user>) with '<version>'? To keep the draft, duplicate it to a new flow first.`, ardından `Apply? [y/N]`. `y` yanıtını verirseniz taslak kimliğini, numarasını ve adını korur; sürümün içeriğini alır. Herhangi bir sürüm eklenmez. Başka bir yanıt, kod 1 ile çıkar ve hiçbir şey göndermez.

`--json` ile, bir pipe içinde veya terminal olmadan komut soru soramaz. Flow'un bir taslağı olduğunda, `--yes` geçmediğiniz sürece hiçbir şey göndermez ve 6 koduyla çıkar. Mesajı soruyu sorar ve `To replace it, re-run with --yes --expected-updated-at <ms> (the draft's updated_at).` ifadesini ekler; burada `<ms>` yerine taslağın `updated_at` değeri gelir. `--yes` ile birlikte `--expected-updated-at` da geçmeniz gerekir: geçmezseniz komut 6 koduyla çıkar ve hiçbir şey göndermez. `--expected-updated-at` olmadan bir terminalde komut, size soruyu gösterirken taslağın `updated_at` değerini kendisi alır.

Bir geri yüklemeden sonra, komut şunu yazdırır: `Restored '<version>' as the draft '<draft>' (<draft-id>). Nothing is published.`

Adapty bu durumlarda geri yüklemeyi reddeder ve hiçbir şeyi değiştirmez. Komut Adapty'nin mesajını yazdırır, bazıları için ne yapılacağını ekler ve 4 koduyla çıkar:

| Mesaj | Ne yapmalı |
|---|---|
| `This flow version is already the current draft.` | Başka bir sürüm seçin. |
| `Flow version does not exist.` | Sürüm ID'si bu flow'un sürüm listesinde yok. ID'yi [`flows versions list`](#adapty-flows-versions-list) komutundan alın. |
| `Flow version is already being published.` | Yayımlama tamamlanana kadar bekleyin, ardından geri yüklemeyi tekrar deneyin. |
| `This flow version uses deleted products: …` | Bu ürünleri kullanmayan bir sürüm seçin. |
| `This flow configuration was already updated by …` | Siz okuduktan sonra bir ekip arkadaşı taslağı değiştirdi. Sürümleri tekrar listeleyin ve yeniden deneyin. |
| `Flow is deleted.` | Flow arşivlendi. Önce kontrol panelinden [arşivden geri yükleyin](archive-flows#restore-a-flow). |

## adapty flows duplicate \{#adapty-flows-duplicate\}

Bir flow'u veya flow'un versiyonlarından birini yeni bir flow olarak kopyalar. Bu işlem, Flow & Paywall Builder'ın üst çubuğundaki flow eylemler düğmesinde **Duplicate flow** olarak (bkz. [Flow'ları kopyalama](copy-flows)) ve [versiyon geçmişinde](flow-version-history#restore-an-earlier-version) ise **Duplicate as new flow** olarak yer alır.

```bash
adapty flows duplicate --app <app-id> <flow-id> --version <version-id>
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--version` | Hayır | Kopyalanacak sürüm ID'si (UUID); [`flows versions list`](#adapty-flows-versions-list) komutundan alınabilir. Herhangi bir sürüm kullanılabilir, taslak dahil. Belirtilmezse, komut taslağı kopyalar; flow'un taslağı yoksa canlı sürümü kopyalar |

Komut, `New flow '<name>' (<flow-id>), not published.` çıktısını yazdırır. Yeni flow, kaynak flow'un adından sonra `_copy` eklenerek adlandırılır. Yayınlanmamış olarak oluşturulur ve bu versiyonun içeriğini içeren bir taslak bulunur. Kaynak flow, taslağı ve geçmişi olduğu gibi kalır. Bir flow yayınlanırken de kopyalama yapılabilir.

Adapty, silinmiş bir ürün kullanan versiyonu ve arşivlenmiş bir flow'u kopyalamayı reddeder. Mesajlar [`flows versions restore`](#adapty-flows-versions-restore) ile aynıdır.

## adapty flows metrics list \{#adapty-flows-metrics-list\}

Birden fazla flow'un yaşam boyu metriklerini, her flow için bir satır olacak şekilde gösterir. Bu, kontrol panelindeki flow tablosunun verileridir.

```bash
adapty flows metrics list --app <app-id> --ids <flow-id>,<flow-id>
```

| Flag | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--ids` | Evet | Flow ID'leri (UUID'ler). Virgülle ayırın veya flag'i tekrarlayın |
| `--csv` | Hayır | CSV olarak yazdırır: her flow için bir satır, flow ID'si ve 27 metriğin tamamını içerir. `--json` ile birlikte kullanılamaz |

Her satır, flow ID'sini görüntüleme, satın alma, deneme ve gelir bilgileriyle birlikte gösterir. `--json` ve `--csv`, `unique_profiles_views`, `net_revenue` ve `conversion_rate_purchases` gibi [flow metrikleri](flow-metrics#metrics-definitions) sayfasındaki 27 metriğin tamamını içerir. Verisi olmayan bir metrik `null` değil, `0` olarak gösterilir. Hiç yayımlanmamış her flow için komut, tablonun altına `<flow-id>: No data: the flow was never published.` yazdırır. `--json` bu flow'un satırına `note: "never_published"` ekler; `--csv` ile notlar stderr'e yazılır, böylece CSV temiz kalır.

## adapty flows metrics values \{#adapty-flows-metrics-values\}

Bir flow'un filtre anahtarlarını ve değerlerini listeler: [`flows metrics get --filter`](#filter-the-metrics) için kabul edilen değerler.

```bash
adapty flows metrics values --app <app-id> <flow-id>
```

| Bağımsız Değişken | Açıklama |
|---|---|
| `flow-id` | Flow ID (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID (UUID) |

Her satır bir etiket ve parantez içinde geçirilecek değeri gösterir. Değerler, kontrol paneli filtrelerinin iç içe yapısına göre yuvalanmıştır:

```text
Country (country)
  Americas (Americas)
    United States (US)
  Europe (Europe)
    Germany (DE)
Store (store)
  App Store (app_store)
  Google Play (play_store)
```

Her grubun en üstteki değeri filtre anahtarıdır, en içteki değerler ise o anahtarın aldığı değerlerdir. Örnekte, `--filter country=US` yalnızca Amerika Birleşik Devletleri'ni tutar, `--filter store=play_store` ise yalnızca Google Play'i tutar.

## adapty flows metrics get

Belirtilen bir flow'un, [flow metrikleri](flow-metrics) sayfasındaki ağaç yapısında gösterildiği şekliyle belirli bir döneme ait metriklerini gösterir.

```bash
adapty flows metrics get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 --date-type purchase_date --based-on placement
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Bayrak | Zorunlu | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--based-on` | Evet | Ağacın ilk seviyesinin neye göre bölüneceği: `placement` veya `audience`. Bunlar, [flow metrikleri](flow-metrics#view-options-for-metrics-data) sayfasının placement tabanlı ve kitle tabanlı görünümleridir |
| `--date-type` | Evet | Dönemin hangi tarihe uygulanacağı: `purchase_date` veya [yükleme tarihine göre filtrelemek](flow-metrics#filter-metrics-by-install-date) için `profile_install_date` |
| `--date-from` | Hayır | Dönemin başlangıç günü, dahil (`YYYY-MM-DD`). `--date-to` ile birlikte kullanın |
| `--date-to` | Hayır | Dönemin bitiş günü, dahil (`YYYY-MM-DD`). `--date-from` ile birlikte kullanın |
| `--granularity` | Hayır | Dönemi noktalara bölün: `day`, `week`, `month`, `quarter` veya `year` |
| `--filter` | Hayır | Yalnızca bir filtre anahtarının bu değerlerine sahip verileri tutar. Tekrarlanabilir. Bkz. [Metrikleri filtrele](#filter-the-metrics) |
| `--timezone` | Hayır | Dönem noktalarının IANA zaman dilimi, örneğin `Europe/Berlin`. Belirtilmezse Adapty, uygulama zaman dilimini kullanır |
| `--depth` | Hayır | `Total` altında kaç seviye ağaç yazdırılacağı. Varsayılan: `1` |
| `--csv` | Hayır | CSV yazdırır: tüm ağacın her düğümü için bir satır. `--json` ile birlikte kullanılamaz |

Hiç yayınlanmamış bir flow için komut, sayıların üstüne `No data: the flow was never published.` notunu yazdırır; `--json` ise `note: "never_published"` ekler. `--csv` ile not stderr'e gider, böylece CSV temiz kalır.

Bir flow'un gelirini görmek için şunu çalıştırın: `adapty analytics chart --app <app-id> --chart revenue --date-from <YYYY-MM-DD> --date-to <YYYY-MM-DD> --filter flow_id=<flow-id>`. Bkz. [Analytics komutları](developer-cli-analytics).

CLI, `--based-on` veya `--date-type` eksik olduğunda ya da dönemin yalnızca bir ucu verildiğinde, kod 2 ile çıkış yapar ve hiçbir istek göndermez. Adapty, `--based-on`, `--date-type` ve `--granularity` değerlerini doğrular: yanlış bir değer kod 4 ile çıkışa neden olur ve hata mesajı kabul edilen değerleri listeler.

### Çıktıyı okuma \{#read-the-output\}

Komut bir `Total` satırı, ardından altındaki ağacın ilk seviyesini yazdırır. Her satırda görüntüleme, satın alma, deneme ve gelir bilgileri yer alır. `--granularity` kullanıldığında, dönemin noktaları doğrudan kendi düğümlerinin altında görünür:

```text
Total           views 19  purchases 7  trials 4  revenue 241.93
  Onboarding    views 10  purchases 7  trials 0  revenue 241.93
    2026-09-01  views  0  purchases 0  trials 0  revenue   0.00
    2026-10-01  views 10  purchases 0  trials 0  revenue 241.93
  Settings      views  0  purchases 0  trials 0  revenue   0.00
```

Ağacın seviyeleri, kontrol panelinin seviyeleridir: placement, kitle, A/B testi, flow varyasyonu, ekran ve ürün. `--based-on audience` kullanıldığında placement seviyesi dışarıda bırakılır. Daha fazla seviye yazdırmak için `--depth` parametresini kullanın, örneğin `--depth 3`.

Tüm 27 metriğe sahip tam ağaç için şu flag'lerden birini kullanın:

- `--json` sunucunun yanıtını değiştirmeden yazdırır.
- `--csv` her düğüm için bir satır yazdırır, dönem noktaları dahil. Sütunlar şunlardır: `path` (`Total`'dan düğüme kadar olan başlıklar, ` > ` ile ayrılmış), `level`, `title` ve ardından metrikler.

### Metrikleri Filtrele \{#filter-the-metrics\}

Her `--filter` değerini `key=value` formatında yazın; anahtarlar ve değerler için [`flows metrics values`](#adapty-flows-metrics-values) listesine bakın. Birden fazla değerden herhangi birini dahil etmek için bunları virgülle ayırın ya da aynı anahtarla bayrağı tekrarlayın. Farklı anahtarlara sahip filtreler birleşir, yani verilerin tümüyle eşleşmesi gerekir:

```bash
adapty flows metrics get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 \
  --date-type purchase_date --based-on placement --filter country=US,DE --filter store=app_store
```

CLI, her değeri tam olarak yazıldığı gibi gönderir. Bir değerin içine virgül koymak için `\,` yazın. Boş değer de bir değerdir: `attribution_channel=` kanalı olmayan veriyi tutar; `flows metrics values` bunu **No Data** olarak listeler.

## adapty flows funnel get \{#adapty-flows-funnel-get\}

Kullanıcıların bir flow'dan çıktığı ekranı gösterir: Tek bir flow versiyonunun adım adım ve ekran ekran hunisi, flow'un [Funnel](flow-funnel) sekmesindeki gibi.

```bash
adapty flows funnel get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 --date-type purchase_date
```

| Argüman | Açıklama |
|---|---|
| `flow-id` | Flow ID'si (UUID) |

| Bayrak | Gerekli | Açıklama |
|---|---|---|
| `--app` | Evet | Uygulama ID'si (UUID) |
| `--date-from` | Evet | Dönemin ilk günü, dahil (`YYYY-MM-DD`), `--timezone` bölgesinde veya uygulama saat diliminde |
| `--date-to` | Evet | Dönemin son günü, dahil (`YYYY-MM-DD`), `--timezone` bölgesinde veya uygulama saat diliminde |
| `--date-type` | Evet | Dönemin hangi tarihe uygulanacağı: `purchase_date` veya `profile_install_date` |
| `--flow-version-id` | Hayır | Okunacak flow versiyon ID'si (UUID). Belirtilmezse CLI yayımlanmış versiyonu okur |
| `--filter` | Hayır | Yalnızca belirli bir filtre anahtarının bu değerlerine sahip kullanıcıları tutar; `key=value` formatında. Tekrarlanabilir. Anahtarlar ve değerler [`flows funnel values`](#adapty-flows-funnel-values) komutundan gelir ve [Metrikleri filtreleme](#filter-the-metrics) bölümündeki gibi çalışır |
| `--timezone` | Hayır | Günlerin IANA saat dilimi, örneğin `Europe/Berlin`. Belirtilmezse Adapty uygulama saat dilimini kullanır |
| `--csv` | Hayır | Kontrol panelinin indirdiği CSV dosyasını yazdırır; toplam satır en başta gelir. `--json` ile birlikte kullanılamaz |

The command prints the flow version and the period, a summary line, and a table. The summary shows how many users entered the flow, how many completed it, the drop rate, and the revenue. The table has one row for each step, with the columns `Step`, `Type`, `Reached`, `Completed`, `Drop rate`, and `Revenue`. A step with more than one screen also gets one row for each of its screens. A value that doesn't apply, such as the revenue of an onboarding screen, is shown as `—`.

When no users entered the flow in the period, the table lists the screens of the version with zeros. For every field of the answer, use `--json`.
