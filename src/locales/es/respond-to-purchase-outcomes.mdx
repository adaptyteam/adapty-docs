Un flow puede continuar tras una pantalla de paywall: retomar el onboarding, mostrar una pantalla de agradecimiento a los nuevos suscriptores o dar la bienvenida a quienes restauren una compra anterior.

Debes configurar los resultados en la configuración de la acción, uno para cada condición de compra. Un resultado sin acciones mantiene a los usuarios en la pantalla del paywall.

- La acción **Purchase** tiene las siguientes condiciones: **When succeeded**, **When failed**, **When cancelled by user** y **When pending**.
- La acción **Restore purchases** tiene dos condiciones: **When restore completed** y **When restore failed**.

## Antes de comenzar \{#before-you-start\}

Asegúrate de que:

- Tu app usa Adapty SDK v4.0 o posterior.
- El flow tiene una pantalla de paywall. Para crearla, sigue la receta [Crear una pantalla de paywall básica](basic-paywall-screen).
- Un elemento de la pantalla de paywall, como un botón, tiene una [acción **Purchase**](paywall-product-block#trigger-a-purchase).
- Tu app mantiene el flow abierto en sus <InlineTooltip tooltip="callbacks de compra y restauración">[iOS](ios-handling-events), [Android](android-handling-events), [React Native](react-native-handling-events-1), [Flutter](flutter-handling-events), [Unity](unity-handling-events), [Kotlin Multiplatform](kmp-handling-events), y [Capacitor](capacitor-handling-events)</InlineTooltip>.

## Añadir acciones para un resultado \{#add-actions-for-a-result\}

:::important
El flow solo puede responder a compras de **In-App Store**. No recibe el resultado de una compra mediante **Web Payment**.
:::

1. Selecciona el elemento que tiene la acción **Purchase** o **Restore purchases**.
2. Haz clic en la acción **Purchase** o **Restore purchases**.
3. Para el resultado de compra o restauración que necesites, como **When succeeded**, haz clic en <Inline id="plus.svg" alt="Add action" />.
4. En el desplegable **Action**, selecciona la acción que quieres ejecutar en lugar de **Do nothing**.

:::note
Una acción de navegación o **Close Flow** que siga a **Purchase** o **Restore purchases** en el mismo disparador se ejecuta de inmediato, antes de conocer el resultado. Agrégala como acción de resultado en su lugar.
:::

:::tip
Cuando una acción **Purchase** tiene acciones de resultado, un doble toque no inicia una segunda compra. El flow ignora los toques adicionales sobre esa acción hasta que el store devuelva el resultado, durante un máximo de 60 segundos. **Restore purchases** funciona de la misma manera.
:::

Para ver las acciones de resultado en tu app, [realiza una compra en sandbox](test-purchases-in-sandbox).

No puedes realizar compras reales en la [previsualización en la app móvil de Adapty](paywall-device-compatibility-preview#preview-on-devices).

Si el flow omite las acciones de resultado en tu app, consulta [por qué el flow omite las acciones de resultado](flow-common-issues#the-flow-doesnt-run-the-actions-set-for-a-purchase-result).

:::tip
Para gestionar los resultados de compra en el código de tu app (por ejemplo, para abrir una pantalla nativa), utiliza los callbacks de compra y restauración del SDK de Adapty. Cada cambio en ese código requiere una nueva versión de la app. Si tu app abre un segundo flow después de una compra, puedes mover sus pantallas al flow que contiene el paywall.
:::

### Mostrar la siguiente pantalla tras una compra exitosa \{#show-the-next-screen-after-a-successful-purchase\}

Para continuar el onboarding o mostrar una pantalla de agradecimiento tras una compra exitosa, combina el resultado **When succeeded** con una acción [**Navigate to Screen**](onboarding-actions#navigate-to-screen) y selecciona esa pantalla como destino.

### Cierra el flow tras una compra exitosa \{#close-the-flow-after-a-successful-purchase\}

Para finalizar el flow después de una compra exitosa, añade [**Close Flow**](onboarding-actions#close-flow) en **When succeeded** en lugar de una navegación. El flow solo se cerrará cuando la compra se complete con éxito, por lo que el código de tu app no necesita cerrarlo.

### Responder a una compra fallida, cancelada o pendiente \{#respond-to-a-failed-canceled-or-pending-purchase\}

Para mostrar una alerta o una pantalla después de una compra fallida, cancelada o pendiente, añade acciones para estos resultados de la acción **Purchase**:

- **When failed**: Un error detuvo la compra. Por ejemplo, [muestra una alerta](onboarding-actions#show-alert) que pida al usuario volver a intentarlo más tarde.
- **When cancelled by user**: El usuario canceló la compra. Por ejemplo, muestra una pantalla con otra oferta.
- **When pending**: La compra está esperando aprobación, por ejemplo mientras el banco confirma el pago o mientras un padre la aprueba a través de Ask to Buy en iOS. El flow no responde cuando el banco o el padre aprueban la compra, así que muestra una pantalla que explique la espera.

:::tip
Para que los usuarios puedan reintentar una compra fallida, mantenlos en el paywall, por ejemplo con una alerta para **When failed**. No puedes añadir **Purchase** ni **Restore purchases** a un resultado.
:::

### Responder a una restauración de compra \{#respond-to-a-purchase-restoration\}

La acción [**Restore purchases**](paywall-product-block#restore-purchases) tiene dos resultados posibles: **When restore completed** y **When restore failed**.

**When restore completed** significa que la restauración finalizó sin errores, no que el usuario tenga acceso. No es posible verificar los niveles de acceso dentro de un flow. Para mostrar contenido que dependa del acceso, añade **Close Flow** en **When restore completed** y verifica el [nivel de acceso](access-level) en la app.
