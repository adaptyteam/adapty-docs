Mostrar paywalls en tu aplicación móvil es un paso esencial para ofrecer a los usuarios acceso a contenido o servicios premium. Sin embargo, presentar un paywall por sí solo solo admite compras cuando Adapty renderiza la pantalla, es decir, un [flow](adapty-flow-builder) o un paywall del [antiguo Paywall Builder](adapty-paywall-builder).

Si renderizas la pantalla en tu propio código, debes usar un método separado llamado `.makePurchase()` para completar una compra y desbloquear el contenido deseado. Este método es la puerta de entrada para que los usuarios interactúen con los paywalls y realicen las transacciones que deseen.

Si tu paywall tiene una oferta promocional activa para el producto que el usuario intenta comprar, Adapty la aplicará automáticamente en el momento de la compra.

:::warning
Ten en cuenta que la oferta introductoria se aplicará automáticamente solo si Adapty renderiza la pantalla.

En otros casos, tendrás que [verificar la elegibilidad del usuario para una oferta introductoria en iOS](fetch-paywalls-and-products#check-intro-offer-eligibility-on-ios). Omitir este paso puede provocar que tu app sea rechazada durante la revisión. Además, podría dar lugar a que se cobre el precio completo a usuarios que son elegibles para una oferta introductoria.
:::

Asegúrate de haber realizado la [configuración inicial](quickstart) sin saltarte ningún paso. Sin ella, no podemos validar las compras.

## Realizar una compra \{#make-purchase\}

:::note
**¿Adapty renderiza tu pantalla?** En un [flow](adapty-flow-builder) o un paywall creado con el [Paywall Builder](adapty-paywall-builder), las compras se procesan automáticamente; puedes saltarte este paso.

**¿Buscas instrucciones paso a paso?** Consulta la [guía de inicio rápido](ios-implement-paywalls-manually) para ver una implementación completa con todo el contexto.
:::

```swift showLineNumbers
do {
    let purchaseResult = try await Adapty.makePurchase(product: product)

    switch purchaseResult {
        case .userCancelled:
            // Handle the case where the user canceled the purchase
        case .pending:
            // Handle deferred purchases (e.g., the user will pay offline with cash)
        case let .success(profile, transaction):
            if profile.accessLevels["YOUR_ACCESS_LEVEL"]?.isActive ?? false {
            // Grant access to the paid features
            }
    }
} catch {
    // Handle the error
}
```

## Compras in-app promocionadas desde la App Store \{#in-app-purchases-from-the-app-store\}

Cuando un usuario inicia una compra en la App Store y la transacción llega a tu app, el SDK llama al método delegado `didReceivePromotedPurchase` con un objeto `AdaptyPromotedProduct`. Tienes dos opciones:

- **Procesar la transacción de inmediato:** No implementes `didReceivePromotedPurchase`. La implementación predeterminada inicia la compra de inmediato y la pantalla del sistema de compras de Apple se muestra automáticamente.
- **Guardar el objeto del producto para procesarlo más tarde:** Implementa `didReceivePromotedPurchase`, guarda el producto y luego llama a `makePurchase` con el producto guardado cuando lo necesites. Esto puede ser útil si necesitas mostrar algo personalizado al usuario antes de activar una compra.

Si el producto promocionado incluye una oferta de suscripción, el SDK la aplica automáticamente en la compra. La oferta se lee del intent de compra de App Store, que la expone en iOS 18.0 y versiones posteriores. En iOS 16.4–17.x, `subscriptionOffer` siempre es `nil` y la compra se realiza al precio base.

Este es el fragmento completo:

```swift showLineNumbers title="Swift"
final class YourAdaptyDelegateImplementation: AdaptyDelegate {
    // 1. Store the product object to defer the transaction.
    // To process the transaction immediately instead, don't implement this method —
    // the default implementation starts the purchase right away.
    nonisolated func didReceivePromotedPurchase(_ product: AdaptyPromotedProduct) {
        // store the product object
    }

    // 2. Continue the deferred purchase later on by passing the product to `makePurchase` when the timing is appropriate
    func continueDeferredPurchase() async {
        let storedProduct: AdaptyPromotedProduct = // get the product object from 1.
        do {
            let purchaseResult = try await Adapty.makePurchase(product: storedProduct)
            // process the purchase result
        } catch {
            // handle the error
        }
    }
}
```

:::warning
La API `didReceivePromotedPurchase` está disponible a partir de la versión 4.1 del SDK y requiere **iOS 16.4** o posterior. La versión 4.0 del SDK no admite compras in-app promocionadas en absoluto, y en dispositivos con iOS inferior a 16.4 el método nunca se activa. Si necesitas compras promocionadas en versiones anteriores de iOS, permanece en el SDK 3.x y utiliza `shouldAddStorePayment` tal como se muestra a continuación.
:::

<Details summary="¿Usas Adapty SDK 3.x?">

En el SDK 3.x, el SDK llama al método delegado `shouldAddStorePayment` en su lugar:

- **Procesar la transacción de inmediato:** Devuelve `true` en `shouldAddStorePayment`. Esto activará la pantalla de compra de Apple al instante.
- **Guardar el objeto del producto para procesarlo más tarde:** Devuelve `false` en `shouldAddStorePayment` y luego llama a `makePurchase` con el producto guardado cuando sea necesario.

```swift showLineNumbers title="Swift"
final class YourAdaptyDelegateImplementation: AdaptyDelegate {
    nonisolated func shouldAddStorePayment(for product: AdaptyDeferredProduct) -> Bool {
        // 1a.
        // Return `true` to continue the transaction in your app. The Apple purchase system screen will show automatically.

        // 1b.
        // Store the product object and return `false` to defer or cancel the transaction.
        false
    }
    
    // 2. Continue the deferred purchase later on by passing the product to `makePurchase` when the timing is appropriate
    func continueDeferredPurchase() async {
        let storedProduct: AdaptyDeferredProduct = // get the product object from 1b.
        do {
            try await Adapty.makePurchase(product: storedProduct)
        } catch {
            // handle the error
        }
    }
}
```

</Details>

## Canjear códigos de oferta en iOS \{#redeem-offer-codes-in-ios\}

<OfferCodesInfo />

Para mostrar la pantalla de canje de códigos en tu app:

```swift showLineNumbers
Adapty.presentCodeRedemptionSheet()
```

:::danger
Según nuestras observaciones, la pantalla de canje de códigos de oferta puede no funcionar de forma fiable en algunas apps. Te recomendamos redirigir al usuario directamente al App Store.

Para ello, debes abrir una URL con el siguiente formato:
`https://apps.apple.com/redeem?ctx=offercodes&id={apple_app_id}&code={code}`
:::
