Esta página cubre la gestión de errores en el SDK de Adapty para Kotlin Multiplatform.

## Conceptos básicos del manejo de errores \{#error-handling-basics\}

Los métodos del SDK de Adapty son funciones suspend que devuelven un `AdaptyResult`, que puede ser un éxito o un error. Gestiona ambos casos con `onSuccess` y `onError`:

```kotlin showLineNumbers

Adapty.getProfile()
    .onSuccess { profile ->
        // Handle success
    }
    .onError { error ->
        // Handle error
        println("Adapty error: ${error.message}")
    }
```

`AdaptyResult` es una clase sellada, por lo que también puedes ramificar directamente sobre ella cuando necesites el resultado como valor:

```kotlin showLineNumbers

when (val result = Adapty.getProfile()) {
    is AdaptyResult.Success -> {
        val profile = result.value
        // Handle success
    }
    is AdaptyResult.Error -> {
        val error = result.error
        // Handle error
    }
}
```

## Códigos de error comunes \{#common-error-codes\}

`AdaptyError.code` es un valor enum de tipo `AdaptyErrorCode`, no un número; compáralo contra la constante del enum, no contra el código numérico. Los números que aparecen a continuación se muestran únicamente porque son los que suele mostrar una línea de log o un ticket de soporte.

| Código de error | Número | Descripción | Solución |
|---|---|---|---|
| `AdaptyErrorCode.NO_PRODUCT_IDS_FOUND` | 1000 | Ninguno de los productos del paywall está disponible en el store. | Consulta [Solución para el error Code-1000 noProductIDsFound](InvalidProductIdentifiers-kmp). |
| `AdaptyErrorCode.CANT_MAKE_PAYMENTS` | 1003 | Las compras in-app no están permitidas en este dispositivo. | Consulta [Solución para el error Code-1003 cantMakePayments](cantMakePayments-kmp). |
| `AdaptyErrorCode.PRODUCT_NOT_FOUND` | 22 | El producto solicitado para la compra no está disponible en el store. | Comprueba que el producto esté configurado tanto en el store como en el Adapty Dashboard. |
| `AdaptyErrorCode.NETWORK_FAILED` | 2005 | La solicitud de red ha fallado. | Pide al usuario que compruebe su conexión o vuelve a intentar la llamada. |
| `AdaptyErrorCode.ADAPTY_NOT_INITIALIZED` | 20 | El SDK no se activó antes de realizar la llamada. | Espera a que `Adapty.activate` se complete antes de realizar cualquier otra llamada al SDK. |

Para ver la lista completa de códigos, consulta `AdaptyErrorCode` en la [referencia de modelos del SDK](https://kmp.adapty.io/adapty/).

## Gestión de errores específicos \{#handle-specific-errors\}

### Errores de red \{#network-errors\}

```kotlin showLineNumbers

Adapty.getFlow("YOUR_PLACEMENT_ID")
    .onSuccess { flow ->
        // Use the flow
    }
    .onError { error ->
        when (error.code) {
            AdaptyErrorCode.NETWORK_FAILED -> {
                // Network error - show offline message
                showOfflineMessage()
            }
            else -> {
                showErrorMessage(error.message)
            }
        }
    }
```

### Errores de compra \{#purchase-errors\}

`makePurchase` reporta fallos y resultados por separado. Un `AdaptyResult.Error` significa que la llamada falló; un resultado exitoso devuelve un `AdaptyPurchaseResult` que indica si el usuario completó la compra, la canceló o la dejó pendiente:

```kotlin showLineNumbers

Adapty.makePurchase(product)
    .onSuccess { purchaseResult ->
        when (purchaseResult) {
            is AdaptyPurchaseResult.Success -> showSuccessMessage()
            AdaptyPurchaseResult.UserCanceled -> {
                // The user dismissed the store sheet — not an error
            }
            AdaptyPurchaseResult.Pending -> {
                // Awaiting an out-of-band payment, such as a prepaid plan
                showPendingMessage()
            }
        }
    }
    .onError { error ->
        when (error.code) {
            AdaptyErrorCode.CANT_MAKE_PAYMENTS -> showPaymentNotAvailableMessage()
            AdaptyErrorCode.PRODUCT_NOT_FOUND -> showProductNotAvailableMessage()
            else -> showPurchaseErrorMessage(error.message)
        }
    }
```

## Estrategias de recuperación ante errores \{#error-recovery-strategies\}

### Reintentos ante errores de red \{#retry-on-network-errors\}

Dado que los métodos del SDK son funciones suspend, un bucle de reintentos es simplemente un bucle con `delay` entre intentos:

```kotlin showLineNumbers

suspend fun getFlowWithRetry(placementId: String, maxRetries: Int = 3): AdaptyFlow? {
    repeat(maxRetries) { attempt ->
        when (val result = Adapty.getFlow(placementId)) {
            is AdaptyResult.Success -> return result.value
            is AdaptyResult.Error -> {
                if (result.error.code != AdaptyErrorCode.NETWORK_FAILED) {
                    showErrorMessage(result.error.message)
                    return null
                }
                delay(1000L * (attempt + 1))
            }
        }
    }
    return null
}
```

### Usa datos en caché como respaldo \{#fall-back-to-cached-data\}

No necesitas gestionar la caché de los flows tú mismo. El SDK de Adapty los guarda en caché en el dispositivo y devuelve la copia en caché cuando falla la red, así que pasa una fetch policy en lugar de implementar tu propia caché:

```kotlin showLineNumbers

Adapty.getFlow(
    placementId = "YOUR_PLACEMENT_ID",
    fetchPolicy = AdaptyPaywallFetchPolicy.ReturnCacheDataElseLoad
)
    .onSuccess { flow ->
        // Use the flow
    }
    .onError { error ->
        showErrorMessage(error.message)
    }
```

Con `ReturnCacheDataElseLoad`, los usuarios con una conexión inestable obtienen un flow más rápido, aunque es posible que no vean la versión más reciente. Si ni la red ni la caché producen un flow, el SDK recurre al [archivo de respaldo](kmp-use-fallback-paywalls) que incluyes con la app.
