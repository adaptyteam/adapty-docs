Sigue esta receta para incluir un mapa interactivo en un flow. Tu app renderiza el mapa como una vista nativa de MapKit en un [elemento personalizado](flow-custom-elements). Tu app solicita acceso a la ubicación en la pantalla del flow.

:::tip
Esta receta solo cubre aplicaciones iOS. Las aplicaciones creadas con otros frameworks solo muestran el [contenido de respaldo](flow-custom-elements#set-fallback-content) de los elementos personalizados. El soporte para Android y frameworks multiplataforma está en camino.
:::

## Antes de empezar \{#before-you-start\}

- Actualiza tu app a Adapty iOS SDK 4.4 o posterior. Las versiones anteriores del SDK muestran el [contenido de respaldo](flow-custom-elements#set-fallback-content) para cada elemento personalizado.
- Configura tu app para [obtener](get-pb-paywalls) y [mostrar](ios-present-paywalls) flows.
- Para solicitar a los usuarios acceso a la ubicación, añade la clave `NSLocationWhenInUseUsageDescription` al archivo `Info.plist` de tu app. Establece su valor con el texto del mensaje, por ejemplo, "Encuentra centros de fitness cerca de ti."

## 1. Añade el elemento personalizado a la pantalla \{#1-add-the-custom-element-to-the-screen\}

En el Flow & Paywall Builder, [añade un elemento personalizado](flow-custom-elements#add-and-configure) a una pantalla del flow y configúralo para el mapa:

- **Type**: `map`.
- **ID**: `fitness_centers`.
- **Height**: Mantén la altura **Fixed** por defecto. El mapa ocupa todo el elemento personalizado.

No coloques el elemento personalizado dentro de contenedores que respondan al toque, como un carrusel. De lo contrario, al arrastrar el mapa también se moverá el carrusel.

Dentro del elemento personalizado, añade una [**Image**](custom-media#image) con una imagen de un mapa. Los usuarios la verán como [respaldo](flow-custom-elements#set-fallback-content) cuando:

- La versión de su app no muestre el mapa.
- Hayan denegado el acceso a la ubicación antes de abrir la pantalla.
- Su dispositivo use iOS 16.

Si el usuario aún no ha respondido al permiso de ubicación, iOS lo mostrará cuando aparezca el mapa. Para explicarles por qué tu app necesita su ubicación, añade un elemento de texto encima del elemento personalizado, como "Encuentra centros de fitness cerca de ti."

## 2. Crear la vista del mapa \{#2-create-the-map-view\}

Crea un modelo para el acceso a la ubicación y una vista SwiftUI con un mapa. La vista solicita acceso a la ubicación, busca gimnasios en un radio de 2 km del usuario y muestra un marcador por cada uno:

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// One location manager for the resolver and the map view
@MainActor
final class LocationAccess: NSObject, ObservableObject, CLLocationManagerDelegate {
    @Published private(set) var status: CLAuthorizationStatus = .notDetermined
    var isMapOnScreen = false
    private let manager = CLLocationManager()

    var isDenied: Bool { status == .denied || status == .restricted }

    override init() {
        super.init()
        manager.delegate = self
        status = manager.authorizationStatus
    }

    // Shows the prompt only if the user hasn't answered it yet
    func requestAccess() {
        manager.requestWhenInUseAuthorization()
    }

    nonisolated func locationManagerDidChangeAuthorization(_ manager: CLLocationManager) {
        let status = manager.authorizationStatus
        Task { @MainActor in self.status = status }
    }
}

@available(iOS 17.0, *)
struct NearbyFitnessCentersMap: View {
    @ObservedObject var access: LocationAccess
    @State private var position: MapCameraPosition = .userLocation(fallback: .automatic)
    @State private var places: [MKMapItem] = []

    var body: some View {
        ZStack {
            if access.isDenied {
                ContentUnavailableView(
                    "Location access is off",
                    systemImage: "location.slash",
                    description: Text("To see fitness centers near you, allow location access in Settings.")
                )
            } else {
                Map(position: $position) {
                    UserAnnotation()
                    ForEach(places, id: \.self) { place in
                        Marker(item: place)
                    }
                }
                .task {
                    access.requestAccess()
                    do {
                        for try await update in CLLocationUpdate.liveUpdates() {
                            guard let location = update.location else { continue }
                            places = try await fitnessCenters(around: location.coordinate)
                            withAnimation {
                                position = .automatic // zoom to fit the user and the places
                            }
                            break
                        }
                    } catch {
                        // the map still shows the location of the user
                    }
                }
            }
        }
        // Tells the resolver that the map is on the screen
        .onAppear { access.isMapOnScreen = true }
        .onDisappear { access.isMapOnScreen = false }
    }

    private func fitnessCenters(around center: CLLocationCoordinate2D) async throws -> [MKMapItem] {
        let request = MKLocalPointsOfInterestRequest(center: center, radius: 2_000) // meters
        request.pointOfInterestFilter = MKPointOfInterestFilter(including: [.fitnessCenter])
        return try await MKLocalSearch(request: request).start().mapItems
    }
}
```

La vista del mapa requiere iOS 17 o posterior. En iOS 16, los usuarios ven el paywall de respaldo. Si el usuario deniega el acceso a la ubicación en la pantalla, la vista reemplaza el mapa con un mensaje sobre cómo permitir el acceso en Ajustes.

## 3. Vincula el mapa al elemento personalizado \{#3-match-the-map-to-the-custom-element\}

En tu [resolver global](ios-flow-custom-elements#set-an-app-wide-resolver), añade una propiedad para el modelo `LocationAccess`. Luego añade un caso que devuelva la vista del mapa para el Type `map` y el ID `fitness_centers`. Las líneas resaltadas muestran qué debes añadir. Si tu app aún no tiene un [resolver](ios-flow-custom-elements#write-a-resolver-to-match-custom-elements-and-views) global, copia el código completo:

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift" {5,13-20}

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    let locationAccess = LocationAccess()

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "map" where id == "fitness_centers":
            guard #available(iOS 17.0, *) else {
                return nil // iOS 16: show the fallback
            }
            if locationAccess.isDenied, !locationAccess.isMapOnScreen {
                return nil // access denied before the screen opened: show the fallback
            }
            return AnyView(NearbyFitnessCentersMap(access: locationAccess))
        // the other cases of your resolver
        default:
            return nil
        }
    }
}
```

</TabItem>
</Tabs>

El SDK llama al resolver cuando se abre la pantalla, y de nuevo mientras está abierta, por ejemplo cuando se cargan los productos. El acceso a la ubicación determina lo que devuelve el resolver en cada llamada:

- **Sin respuesta aún**: la vista del mapa, para que la vista pueda solicitar acceso.
- **Permitido**: la vista del mapa, que muestra gimnasios cercanos al usuario.
- **Denegado antes de abrir la pantalla**: `nil`, para que los usuarios vean el respaldo en lugar del mensaje sobre Configuración.
- **Denegado en la pantalla**: la vista del mapa, porque la vista establece `isMapOnScreen` mientras está en pantalla. Si el resolver devolviera `nil` aquí, el SDK reemplazaría el mensaje sobre Configuración con el respaldo en la siguiente llamada.

Si tu app aún no tiene un resolver global, llama a `AdaptyUI.setCustomElementsResolver(_:)` una vez, por ejemplo al iniciar la app:

<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// keep this instance: a resolver for one flow can reuse it
@MainActor let customElementsResolver = CustomElementsResolver()

AdaptyUI.setCustomElementsResolver(customElementsResolver)
```

## 4. Prueba en un dispositivo \{#4-test-on-a-device\}

El Flow & Paywall Builder no puede ejecutar el código de tu app, por lo que el lienzo solo muestra el respaldo. Para previsualizar el mapa:

1. [Publica el flow](builder-save-publish). Para ver la última versión publicada en lugar de una en caché, registra el dispositivo como [dispositivo de prueba](test-devices).
2. Ejecuta una compilación de tu app que incluya el resolver, en iOS 17 o posterior. Abre la pantalla y permite el acceso a la ubicación. Comprueba que el mapa muestra tu ubicación y marcadores de los centros de fitness cercanos.

Para probar el respaldo, deniega el acceso a la ubicación: en la app **Settings**, ve a **Privacy & Security** > **Location Services** > *tu app* y selecciona **Never**. Luego vuelve a abrir la pantalla.

Para saber por qué aparece el respaldo en lugar del mapa, sigue las instrucciones en la sección [Probar en un dispositivo](ios-flow-custom-elements#test-on-a-device) de la guía de iOS.
