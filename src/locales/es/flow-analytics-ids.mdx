El SDK de Adapty reporta cada visualización de pantalla y cada respuesta a tu app. Cada evento incluye el ID de la pantalla o elemento del que proviene, y esos IDs son los que muestra tu propio sistema de analíticas. Por defecto, el ID de una pantalla tiene un aspecto como `scr_oAPBHPa7`, así que un funnel en Amplitude o Mixpanel aparece como una columna de códigos, y alguien tiene que mantener a mano un mapeo de código a nombre.

Puedes nombrar estos IDs tú mismo. Los inputs y grupos seleccionables se nombran en el Flow Builder. Los IDs de pantalla se configuran mediante la [skill flow-generator](flow-generator-skill), que renombra una pantalla en todos los lugares del flow donde se hace referencia a ella.

:::important
Renombrar pantallas forma parte de la habilidad del generador de flows, por lo que no necesitas instalar nada extra: sigue los [pasos de instalación del generador de flows](flow-generator-skill#install-the-skill) y ya lo tendrás. Guarda los cambios en los flows de tu dashboard, así que ejecútalo primero sobre un borrador y revisa el resultado en el Flow Builder antes de publicarlo.
:::

## Para qué sirve \{#what-its-for\}

- **Un funnel que tu equipo entiende**: La secuencia `welcome → signup → paywall` explica lo que ocurrió. Tres códigos generados automáticamente no.
- **Un vocabulario común en todas las herramientas**: El nombre que le das a una pantalla es el mismo que aparece en las métricas de flow de Adapty y en tus propios analytics, así que ambos coinciden sin necesidad de una tabla de correspondencias.
- **Respuestas que puedes consultar**: Una opción de quiz llamada `beginner` es un valor que un analista puede filtrar. Un ID generado automáticamente hay que decodificarlo primero.

## Qué IDs ve tu sistema de análisis \{#which-ids-your-analytics-sees\}

Dos eventos llevan IDs. [`flow_screen_showed`](ios-flow-screen-views) se dispara cuando un usuario abre una pantalla, y [`flow_user_input`](ios-flow-input) se dispara cuando un usuario rellena un campo, elige una respuesta en un cuestionario o activa un interruptor. Cada guía documenta todos los parámetros de su evento. Esta tabla cubre únicamente los parámetros que identifican una pantalla o un elemento.

| Parámetro del evento | Qué contiene | Dónde se configura |
| :--- | :--- | :--- |
| `instanceId` | El ID de la pantalla | La skill del generador de flows |
| `element_id` | El **Element ID** de un campo de entrada, o el **Group ID** de un grupo seleccionable | Flow Builder |
| `item_ids` | Los **Element IDs** de las opciones seleccionadas | Flow Builder |

## Nombres para inputs y opciones de quiz \{#name-inputs-and-quiz-options\}

Los inputs y los grupos seleccionables tienen campos de ID en el builder. El **Element ID** de un input está en **Input settings**, y es el mismo ID que usas para referenciar su valor en otras partes del flow — consulta [Inputs y formularios](builder-inputs-and-forms). El **Group ID** de un grupo está en **Screen settings > Selectable groups**, y cada opción dentro de él tiene su propio **Element ID**.

Dale a cada uno un nombre que tenga sentido por sí solo, porque esa es la cadena que verás en tus analytics. `birthday` y `beginner` no necesitan explicación. `el_024F` sí.

Establece el ID cuando añades el elemento, no después. Las condiciones y variables de texto apuntan a un **ID de elemento**, y cambiar ese ID no las actualiza — dejan de resolverse, sin ningún error. Para renombrarlo en un flow que ya funciona, actualiza cada condición y variable que lo utilice. Consulta [Las condiciones y variables se rompen tras cambiar el ID de un elemento](flow-common-issues#conditions-and-variables-break-after-an-element-id-change).

La skill de generación de flows los nombra automáticamente en cualquier flow que construye. La [skill de auditoría de flows](flow-audit-skill) reporta los que faltan.

## Cambiar nombre a las pantallas \{#rename-screens\}

El Flow Builder no tiene ningún campo para el ID de una pantalla, así que pídele a la habilidad:

```
Give the screens in my onboarding flow readable IDs.
```

La habilidad propone un nombre para cada pantalla y luego lo renombra en todos los lugares donde el flow hace referencia a ella: la propia pantalla, cada acción de navegación que lleva a ella y los productos vinculados a ella. Los renombra todos a la vez, porque una pantalla renombrada en un sitio pero no en otro es un flow que no se podrá publicar.

Te indica qué nombres cambió y cuántas referencias se movieron, y no ejecutará un cambio de nombre que colisione con una pantalla que ya existe. Renombrar un ID de pantalla es seguro en un flow que ya funciona, algo que no ocurre con un ID de elemento: la herramienta mueve todas las referencias junto con él.

## Qué verificar \{#what-to-check\}

- **Renombra antes de publicar el flow**: Los eventos ya recopilados conservan el ID anterior, tanto en las métricas del flow de Adapty como en tu propio sistema de analíticas. Un embudo que atraviesa el cambio mostrará dos pantallas a medio rellenar, y renombrar de vuelta no las fusiona.
- **Cada opción de un grupo necesita su propio Element ID**: Si a una opción le falta uno, si dos opciones comparten el mismo, o si el **Group ID** se reutiliza en otra pantalla, todo el grupo deja de registrar datos, no solo esa opción. El builder no avisa de esto, así que revisa el grupo cada vez que añadas una opción.
- **Los IDs llegan a tu sistema de analíticas exactamente como los escribes**: Elige un estilo, como `plan_selection` o `planSelection`, y úsalo en todo el flow. Los estilos mezclados son más difíciles de consultar que los códigos generados.

## Limitaciones \{#limitations\}

- **Los IDs de pantalla solo se renombran desde el skill**: No existe un campo para ellos en el Flow Builder.
- **Renombrar no migra el historial**: Los eventos anteriores conservan el ID antiguo.
- **Algunos elementos no envían eventos de entrada**: Los campos de contraseña, las selecciones de producto y los cambios de pestaña nunca los reportan. Nombrar uno afecta al flow, no a tus analíticas.
