Con un elemento personalizado en el Flow & Paywall Builder, puedes añadir una vista nativa a una pantalla de flow. Puede ser una animación Lottie / Rive, un gráfico interactivo, un mapa, una vista previa de cámara o cualquier otra vista que tu app pueda mostrar. Los usuarios solo ven la vista nativa en apps que utilizan el SDK de Adapty v4.4+ para iOS, Android, React Native o Flutter. Las apps desarrolladas con otros frameworks multiplataforma muestran el respaldo de cada elemento personalizado.

<DocVideo id="custom-elements-examples.mp4" alt="Tres pantallas de flow con vistas nativas: un anillo Lottie que se llena hasta 4 de 7 días, un gráfico de peso que el usuario arrastra y un mapa de gimnasios cercanos." />

Para mostrar una vista nativa en una pantalla de flow:

1. [Añade un elemento personalizado](#add-and-configure) a la pantalla e introduce su **Type** e **ID**.
2. [Añade contenido de respaldo](#set-fallback-content) dentro del elemento personalizado. Los usuarios lo ven cuando tu app no muestra la vista.
3. [Configura la vista nativa en tu app](#set-up-your-app-code). Usa el SDK de Adapty para asignarle el mismo Type e ID.
4. [Publica el flow](#publish-and-test) y pruébalo en un dispositivo.
5. [Lanza la actualización de la app con la vista nativa](#what-changes-require-an-app-release). Los usuarios de versiones de la app sin la vista nativa verán el contenido de respaldo.

:::tip
Para mostrar una imagen o un vídeo animado, utiliza un elemento [**Image**](custom-media#image) o [**Video**](custom-media#video) en lugar de un elemento personalizado. Ninguno de los dos requiere código en tu app, y puedes reemplazar el archivo sin necesidad de lanzar una nueva versión.
:::

## 1. Añade un elemento personalizado a la pantalla \{#add-and-configure\}

1. Abre el panel **Add element**. En el grupo **Media**, haz clic en **Custom element**.

   <ZoomImage id="flow-custom-element-card.webp" width="200px" alt="Elemento personalizado en el grupo Media del panel Add element" />

2. Si la vista nativa responde al toque, mantén el elemento personalizado fuera de contenedores que también respondan al toque, como un carrusel. Así, un deslizamiento en la vista nativa no mueve el carrusel.
3. En el campo **Type**, introduce un Type para el tipo de vista nativa, como `lottie_animation`:
   - **Reglas de nomenclatura**: Usa solo letras minúsculas, números y guiones bajos.
   - **Coincidencia exacta**: El Type debe coincidir exactamente con el de tu app, letra por letra. Con cualquier otra ortografía, los usuarios verán el fallback.
   - **Sugerencias**: El campo sugiere los Types ya usados en este flow, no los de tu app.
4. En el campo **ID**, reemplaza el valor predefinido, como `custom_1`, por un ID de tu elección, como `welcome_wave`. El ID distingue entre elementos personalizados del mismo Type.

   <ZoomImage id="flow-custom-element-type-id.webp" width="500px" alt="Campos Type e ID en la sección Element de la configuración del elemento personalizado" />

5. Para reservar un espacio fijo para la vista nativa, mantén la altura **Fixed** predeterminada. Ajústala a la altura que necesite la vista.
   - **Shared area**: La vista nativa y el contenido de respaldo comparten el mismo área.
   - **Alignment**: Si la vista nativa es más pequeña que esta área, aparece en la esquina superior izquierda de forma predeterminada. Para moverla, cambia la alineación en la sección **Layout** del elemento personalizado.

   :::important
   Con una altura **Hug**, una vista nativa sin altura propia, como un mapa o una lista de desplazamiento, se colapsa a una altura casi nula.
   :::

6. (Opcional) Para recortar la vista nativa a las **Corners** redondeadas del elemento personalizado, en la sección **Layout**, selecciona la casilla **Clip content**.

### Usar vistas nativas en varios elementos personalizados \{#use-native-views-in-several-custom-elements\}

Las siguientes reglas aplican al Tipo e ID de los elementos personalizados:

- **Type**: Introduce un único Type por cada tipo de vista nativa, como `lottie_animation` para un reproductor Lottie y `map` para un mapa.
- **ID**: Dentro de un mismo Type, asigna un ID único a cada contenido, como `streak_ring` y `welcome_wave` para dos animaciones Lottie. Tu app lee el ID para seleccionar el contenido. Si dos elementos personalizados en una misma pantalla tienen el mismo Type e ID, el campo **ID** muestra una advertencia: *Same type and ID as another element on this screen.* Puedes publicar el flow igualmente.
- **Copias de elementos**: Al duplicar o pegar un elemento, o al añadir una [pestaña](builder-tabs), el builder renombra cada ID copiado que ya exista en la pantalla o componente. Por ejemplo, `custom_1` pasa a ser `custom_2` y `hero` pasa a ser `hero_2`. Asegúrate de que el código de tu app hace referencia al ID correcto.

## 2. Añadir contenido de respaldo \{#set-fallback-content\}

Los usuarios ven el contenido de respaldo en lugar de la vista nativa cuando:

- Su versión de la app no incluye el código de la vista.
- La app está desarrollada con un framework multiplataforma que no es React Native ni Flutter.
- La app usa una versión del SDK de Adapty anterior a la 4.4.
- El Tipo e ID del elemento personalizado no coinciden con ninguna vista en el código de la app.
- El código de la app coincide con el Tipo e ID, pero no devuelve ninguna vista. Por ejemplo, la vista necesita un archivo que no está en el dispositivo, o un permiso que el usuario denegó.

Para configurar el respaldo, añade elementos al contenedor de elementos personalizados. Cuando la vista nativa no aparece, un elemento personalizado sin respaldo queda vacío.

El Flow & Paywall Builder no puede ejecutar el código de tu app, por lo que su canvas solo muestra el respaldo. La [vista previa en la app móvil de Adapty](paywall-device-compatibility-preview#preview-on-devices) también muestra el respaldo. Para previsualizar la vista nativa, [prueba el flow en un dispositivo](#publish-and-test) en una compilación de tu app.

<ZoomImage id="flow-custom-element-placeholder.webp" width="400px" alt="Empty custom element on the canvas with the text Add elements here as a fallback" />

:::important
Mantén los botones de navegación, los botones de compra y otros elementos esenciales de la interfaz fuera del elemento personalizado. Los usuarios ven la vista nativa o el contenido de respaldo, nunca ambos.
:::

No puedes añadir un **Footer**, una **Sliding sheet** ni una **Bottom Sheet** dentro de un elemento personalizado.

## 3. Configura la vista nativa en tu app \{#set-up-your-app-code\}

Cuando se abre una pantalla con un elemento personalizado, el SDK de Adapty pasa el Type y el ID del elemento a una función de resolución en el código de tu app. La función de resolución devuelve uno de los siguientes resultados:

- **La vista que coincide con el Type y el ID**: Los usuarios ven la vista nativa. En el código, escribe el Type y el ID exactamente como aparecen en el builder.
- **Ninguna vista**: Los usuarios ven el respaldo. Por ejemplo, devuelve ninguna vista cuando el archivo que necesita la vista no está en el dispositivo.

Para admitir elementos personalizados en tu app, consulta las guías específicas de cada plataforma: [iOS](ios-flow-custom-elements), [Android](android-flow-custom-elements), [React Native](react-native-flow-custom-elements) y [Flutter](flutter-flow-custom-elements).

:::tip
Una vista nativa puede visualizar datos del usuario, como las respuestas de un flow anterior. Consulta <InlineTooltip tooltip="Muestra un gráfico interactivo de objetivos de peso en un paywall">[iOS](custom-element-interactive-chart), [Android](android-custom-element-interactive-chart), [React Native](react-native-custom-element-interactive-chart), [Flutter](flutter-custom-element-interactive-chart)</InlineTooltip>.
:::

## 4. Publicar y probar el flow \{#publish-and-test\}

Para [publicar el flow](builder-save-publish), asegúrate de que cada elemento personalizado tenga un Type que siga las [reglas de nomenclatura](#add-and-configure). Puedes publicar el flow antes de lanzar la app. Hasta que los usuarios actualicen la app, verán el paywall de respaldo.

Un error en la vista nativa puede hacer que la app se bloquee. Antes de publicar la app, prueba todas las pantallas que tengan un elemento personalizado en una build con la vista nativa. Para probar un flow que los usuarios reales aún no ven, añádelo a un [placement](create-placement) que esta build solicite y que tu app publicada no use. Para ver el último flow publicado en lugar de uno en caché, registra el dispositivo como [dispositivo de prueba](test-devices). Para el procedimiento completo, sigue las guías específicas de cada plataforma: [iOS](ios-flow-custom-elements#test-on-a-device), [Android](android-flow-custom-elements#test-on-a-device), [React Native](react-native-flow-custom-elements#test-on-a-device) y [Flutter](flutter-flow-custom-elements#test-on-a-device).

## Qué cambios requieren una actualización de la app \{#what-changes-require-an-app-release\}

Las vistas nativas forman parte del código de tu app. Para modificar una vista nativa, publica una actualización de la app. Para cambiar el contenido de respaldo o cualquier ajuste de un elemento personalizado excepto su Tipo e ID, publica el flow.

| Contenido modificado | Qué hacer | Lo que ven los usuarios que no han actualizado la app |
|---|---|---|
| La vista nativa de un elemento personalizado existente, como una animación diferente | Publica una actualización de la app con la nueva vista nativa | La vista nativa anterior, si su versión de la app la incluye |
| Una vista nativa para un nuevo elemento personalizado | Publica una actualización de la app con la nueva vista nativa. Añade un elemento personalizado con el nuevo Type e ID, y publica el flow | Contenido de respaldo |
| Una vista nativa existente en otra pantalla, en otro flow o en una prueba A/B | Añade un elemento personalizado con el mismo Type e ID, y publica el flow. No es necesaria una actualización de la app si tu <InlineTooltip tooltip="app-wide resolver">[iOS](ios-flow-custom-elements#set-an-app-wide-resolver), [Android](android-flow-custom-elements#display-views-in-every-flow), [React Native](react-native-flow-custom-elements#pass-the-resolver-to-the-sdk), [Flutter](flutter-flow-custom-elements#pass-the-resolver-to-the-sdk)</InlineTooltip> devuelve la vista | La vista nativa, si su versión de la app la incluye |
| El Type o el ID de un elemento personalizado | Publica una actualización de la app con una vista nativa para el nuevo Type e ID, y publica el flow | Contenido de respaldo |
| El contenido de respaldo u otras configuraciones de un elemento personalizado | Publica el flow. No es necesaria ninguna actualización de la app | El contenido actualizado |

## Solución de problemas \{#troubleshooting\}

- **Los usuarios ven el paywall de respaldo en lugar de la vista nativa**: Asegúrate de que el Type y el ID coincidan con los de tu app, letra por letra. Los usuarios de versiones de la app sin la vista verán el paywall de respaldo hasta que actualicen la app. Para encontrar la causa en el código, consulta las guías específicas de cada plataforma: [iOS](ios-flow-custom-elements#test-on-a-device), [Android](android-flow-custom-elements#test-on-a-device), [React Native](react-native-flow-custom-elements#test-on-a-device) y [Flutter](flutter-flow-custom-elements#test-on-a-device).
- **Los usuarios ven un área vacía**: [Añade un contenido de respaldo](#set-fallback-content) y publica el flow. Si sigues viendo un área vacía en un [dispositivo de prueba](test-devices), la vista nativa aparece sin su contenido. Asegúrate de que el resolver no devuelva ninguna vista cuando falte el contenido, como se indica en <InlineTooltip tooltip="Establecer condiciones para el contenido de respaldo">[iOS](ios-flow-custom-elements#set-conditions-for-fallback-content), [Android](android-flow-custom-elements#set-conditions-for-fallback-content), [React Native](react-native-flow-custom-elements#set-conditions-for-fallback-content), [Flutter](flutter-flow-custom-elements#set-conditions-for-fallback-content)</InlineTooltip>.
- **La vista nativa no encaja en el elemento personalizado**: Asegúrate de que tu app ajuste la vista al área del elemento personalizado. Para recortar la vista según las **Corners** redondeadas, en la sección **Layout**, activa la casilla **Clip content**.
