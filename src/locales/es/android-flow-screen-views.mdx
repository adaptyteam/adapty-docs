Cada vez que un usuario abre una pantalla en un [flow](adapty-flow-builder), el SDK envía un evento `flow_screen_showed` a tu app. Reenvíalo a Amplitude, Mixpanel o la herramienta de analíticas de producto que uses, para analizar las pantallas del flow junto con el resto de los eventos de tu app.

:::tip
Para ver hasta qué punto llegan los usuarios en un flow, no necesitas ningún código: las [métricas de flow](flow-metrics) ya muestran vistas, finalizaciones y abandono por pantalla en el Adapty Dashboard. Usa esta guía cuando necesites esos mismos datos en tu propio sistema de analítica, combinados con eventos que Adapty no conoce.
:::

## Antes de empezar \{#before-you-start\}

Necesitas:

- **Adapty Android SDK v4 o posterior**: El callback de análisis de flows no existe en versiones anteriores.
- **Una versión del flow publicada después de que se lanzara esta funcionalidad**: Adapty genera los eventos de pantalla al publicar un flow, por lo que un flow publicado antes de eso no reportará nada. Si no llegan eventos a tu app, publica una nueva versión del flow e inténtalo de nuevo.

## Qué recibes \{#what-you-receive\}

<FlowScreenShowedParams />

Las visualizaciones de pantalla llegan al mismo callback de análisis que cualquier otro evento del flow. Consulta [Gestionar eventos de flow y paywall](android-handling-events) para saber dónde registrarlo.

## Reenvía cada vista de pantalla a tus analíticas \{#forward-every-screen-view-to-your-analytics\}

Comprueba el nombre del evento antes de leer cualquier otro dato, ya que un flow reporta otros eventos a través del mismo callback.

```kotlin showLineNumbers title="Kotlin"
override fun onAnalyticEvent(
    name: String,
    params: Map<String, Any?>,
    context: Context,
) {
    if (name != "flow_screen_showed") return

    val screenId = params["instanceId"]
    val screenOrder = params["screen_order"]

    // Send screenId and screenOrder to your analytics provider here.
}
```

## Ejecutar código cuando el usuario llega al final \{#run-code-when-a-user-reaches-the-end\}

`is_last_screen` es `true` en una pantalla desde la que el flow no puede avanzar. Úsalo para desbloquear contenido, marcar el onboarding como completado o enviar tu propio evento de finalización, sin necesidad de añadir una acción de botón en el builder.

```kotlin showLineNumbers title="Kotlin"
override fun onAnalyticEvent(
    name: String,
    params: Map<String, Any?>,
    context: Context,
) {
    if (name != "flow_screen_showed") return
    if (params["is_last_screen"] != true) return

    // The user reached the end of the flow.
}
```

Llegar a la última pantalla no es lo mismo que cerrar el flow. Un usuario puede ver la pantalla final y descartar el flow sin realizar ninguna acción, y un flow con bifurcaciones puede terminar en varias pantallas diferentes. Para saber que el flow en sí desapareció, usa `onFlowClosed` en su lugar.
