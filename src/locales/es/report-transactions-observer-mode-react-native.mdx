<SDKv4>

En el modo Observer, el SDK de Adapty no puede rastrear por sí solo las compras realizadas a través de tu sistema de compras existente. Necesitas reportar las transacciones desde tu store. Es fundamental configurar esto **antes** de publicar tu app para evitar errores en los análisis.

Usa `reportTransaction` para reportar explícitamente cada transacción y que Adapty pueda reconocerla.

:::warning

**¡No omitas el reporte de transacciones!**
Si no llamas a `reportTransaction`, Adapty no reconocerá la transacción, no aparecerá en los análisis y no se enviará a las integraciones.

:::

Si usas flows y paywalls de Adapty, incluye el `variationId` al reportar una transacción. Esto vincula la compra con el flow o el paywall que la originó y garantiza unas analíticas precisas.

:::warning
- En Android, usa el SDK de Adapty para React Native 4.4.0 o posterior. Las versiones anteriores pueden no enviar el `variationId` a Adapty, por lo que la compra no quedará vinculada al flow.
- Pasa el `variationId` del `AdaptyPaywallProduct` que compró el usuario, no el `AdaptyFlow.variationId`. El ID de variación propio de un flow no vincula la compra con el flow.
:::

```typescript showLineNumbers
const variationId = product.variationId; // el AdaptyPaywallProduct que el usuario compró

try {
    await adapty.reportTransaction(transactionId, variationId);
} catch (error) {
    // manejar el `AdaptyError`
}
```

Parámetros:

| Parámetro     | Presencia | Descripción                                                  |
| ------------- | --------- | ------------------------------------------------------------ |
| transactionId | requerido | <ul><li> Para iOS: Identificador de la transacción.</li><li> Para Android: Identificador de cadena (`purchase.getOrderId`) de la compra, donde la compra es una instancia de la clase [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) de la biblioteca de facturación.</li></ul> |
| variationId   | opcional | El identificador de cadena de la variante. Pasa el `variationId` del `AdaptyPaywallProduct` que el usuario compró. Es el mismo valor que el `variationId` del `AdaptyFlowPaywall` que contiene ese producto. |
| ios.jwsTransaction | opcional | Solo para iOS, SDK 4.3.0 o posterior. La transacción firmada de StoreKit 2: el `jwsRepresentation` de su resultado de verificación. El SDK lo envía a Adapty tal cual. Android ignora este parámetro. |

En iOS, si tu sistema de compras te proporciona la transacción StoreKit 2, pasa su representación JWS en el tercer argumento:

```typescript showLineNumbers
await adapty.reportTransaction(transactionId, variationId, {
  ios: { jwsTransaction },
});
```

</SDKv4>

**Asociar flows y paywalls a transacciones**

El SDK de Adapty no puede determinar el origen de las compras, ya que eres tú quien las procesa. Por ello, si tienes intención de usar flows, paywalls o pruebas A/B en modo Observer, necesitas asociar la transacción proveniente de tu store con el flow o paywall correspondiente en el código de tu app. Es importante hacerlo correctamente antes de publicar tu app, ya que de lo contrario generará errores en los análisis.

```typescript 
const variationId = paywall.variationId;

try {
    await adapty.setVariationId('transactionId', variationId);
} catch (error) {
    // handle the `AdaptyError`
}
```
