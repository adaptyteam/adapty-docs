<SDKv4>

En el modo Observer, el SDK de Adapty no puede registrar por sí solo las compras realizadas a través de tu sistema de compras existente. Debes informar las transacciones desde tu store. Es fundamental configurar esto **antes** de publicar tu app para evitar errores en los análisis.

Usa `reportTransaction` para informar explícitamente cada transacción y que Adapty pueda reconocerla.

:::warning

**¡No omitas el reporte de transacciones!**
Si no llamas a `reportTransaction`, Adapty no reconocerá la transacción, no aparecerá en los análisis y no se enviará a las integraciones.

:::

Si usas flows y paywalls de Adapty, incluye el `variationId` al reportar una transacción. Esto vincula la compra con el flow o paywall que la originó, garantizando unas analíticas precisas.

:::warning
Pasa el `variationId` del `AdaptyPaywallProduct` que compró el usuario, no el `AdaptyFlow.variationId`. El ID de variación propio de un flow no vincula la compra al flow.
:::

```typescript showLineNumbers

const variationId = product.variationId; // the AdaptyPaywallProduct the user bought

try {
  await adapty.reportTransaction({ 
    transactionId: 'your_transaction_id',
    variationId: variationId 
  });
} catch (error) {
  console.error('Failed to report transaction:', error);
}
```

Parámetros:

| Parámetro     | Presencia | Descripción                                                  |
| ------------- | --------- | ------------------------------------------------------------ |
| **transactionId** | obligatorio | <ul><li> Para iOS: Identificador de la transacción.</li><li> Para Android: Identificador de cadena (`purchase.getOrderId`) de la compra, donde la compra es una instancia de la clase [Purchase](https://developer.android.com/reference/com/android/billingclient/api/Purchase) de la biblioteca de facturación.</li></ul> |
| **variationId**   | opcional | El identificador de cadena de la variante. Pasa el `variationId` del `AdaptyPaywallProduct` que el usuario compró. Es el mismo valor que el `variationId` del `AdaptyFlowPaywall` que contiene este producto. | 
| **ios.jwsTransaction** | opcional | Solo iOS, SDK 4.3.0 o posterior. La transacción firmada de StoreKit 2: la `jwsRepresentation` de su resultado de verificación, para la misma transacción que `transactionId`. El SDK la envía a Adapty tal cual. Android ignora este parámetro. |

En iOS, si tu sistema de compras te proporciona la transacción de StoreKit 2, pasa su representación JWS en `ios.jwsTransaction`:

```typescript showLineNumbers
await adapty.reportTransaction({
  transactionId: 'your_transaction_id',
  variationId: variationId, // optional
  ios: { jwsTransaction: 'YOUR_JWS_REPRESENTATION' }, // iOS only, optional
});
```

</SDKv4>

<SDKv3>

En el modo Observer, el SDK de Adapty no puede rastrear las compras realizadas a través de tu sistema de compras existente por sí solo. Necesitas reportar las transacciones desde tu store. Es fundamental configurar esto **antes** de publicar tu app para evitar errores en los análisis.

Usa `reportTransaction` para reportar explícitamente cada transacción y que Adapty pueda reconocerla.

**¡No omitas el reporte de transacciones!**
Si no llamas a `reportTransaction`, Adapty no reconocerá la transacción, no aparecerá en los análisis y no se enviará a las integraciones.

:::

Si utilizas flows y paywalls de Adapty, incluye el `variationId` al reportar una transacción. Esto vincula la compra con el flow o paywall que la originó, garantizando unas analíticas precisas.

```typescript showLineNumbers

const variationId = paywall.variationId;

try {
  await adapty.reportTransaction({ 
    transactionId: 'your_transaction_id',
    variationId: variationId 
  });

  console.error('Failed to report transaction:', error);

```

Parámetros:

| Parámetro     | Presencia | Descripción                                                  |
