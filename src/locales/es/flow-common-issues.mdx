Este artículo recoge los problemas que surgen con más frecuencia al crear un flow en el [Flow Builder](adapty-flow-builder), cada uno con su causa y su solución.

## Un flow no se puede previsualizar ni publicar \{#a-flow-wont-preview-or-publish\}

<ZoomImage id="flow-publish-error.webp" width="300px" alt="Mensaje de error al publicar en la interfaz web del Flow Builder cuando un flow tiene acciones incompletas" float="right" />

No es posible publicar ni previsualizar tu flow si se da alguno de los siguientes problemas.

- Una interacción con una configuración incompleta. Casos habituales:
    - Una acción **Open URL** sin URL de destino.
    - Una acción **Navigate to screen** sin destino — también ocurre cuando se elimina la pantalla de destino después de configurar la acción.
    - Una **acción condicional** sin operador ni valor.
    - Una acción **Set variable** sin asignación de variable/valor.
    - Una acción **Purchase** sin producto (compra in-app) o sin URL de Web Paywall (pago web).
    - Una acción **Custom** sin ID de acción.
    - Una acción **Show alert** con el Título o el Mensaje vacíos.
    - Una acción **Show** o **Hide** sin ningún elemento seleccionado.
    - Una acción **Select product** sin producto de destino — también ocurre cuando el elemento de producto de destino se elimina, se mueve fuera de su grupo de productos o se deja en otra pantalla.
    - Una acción **Select product** guardada dentro de un componente reutilizable, o que apunta a un ID de elemento usado en más de una pantalla.
- Una **pantalla sin elementos**.
- Un elemento de producto **sin producto asociado** — puede ocurrir si eliminas el producto referenciado.
- Un JSON de **Remote Config** inválido interrumpe todo el proceso de entrega — ni siquiera es posible guardar el borrador.

Para detectar estos problemas antes de publicar, [previsualiza el flow en la app de Adapty](paywall-device-compatibility-preview). Si el flow no carga, el mensaje de error te dará más detalles.

Esta lista trata sobre lo que impide guardar un flow. Un flow puede superar todas estas comprobaciones y aun así ser inseguro para un usuario real: sin acción de restauración, un botón de compra que no funciona, traducciones que faltan. La [skill de auditoría de flows](flow-audit-skill) se encarga de eso en su lugar, y termina con un veredicto de aprobado/rechazado en vez de un mensaje de error.

## La publicación falla con "Something went wrong" \{#publishing-fails-with-something-went-wrong\}

Este error significa que la solicitud de publicación falló en el lado de Adapty, no que tu flow esté mal configurado — por eso el mensaje es genérico. Tu versión en producción no se ha modificado. Copia el **Request ID** del mensaje de error y envíalo a [support@adapty.io](mailto:support@adapty.io) para que el equipo pueda localizar la solicitud fallida.

## Una oferta no se aplica en la compra \{#an-offer-doesnt-apply-at-purchase\}

El Builder valida que cada elemento de producto tenga un producto asignado, pero no valida la oferta del producto. Si la oferta se modifica o elimina posteriormente en el store o en Adapty, el flow sigue publicándose y la compra se ejecuta sin la oferta. Tras cambiar las ofertas, vuelve a abrir el flow, vuelve a seleccionar la oferta para cada elemento de producto afectado y republícalo.

## El precio de una oferta está vacío en la vista previa \{#an-offer-price-is-empty-in-the-preview\}

La vista previa del builder no puede conectarse a los stores, por lo que `offer_price`, `offer_billing_period` y `offer_full_duration` muestran el nombre de la variable entre llaves en lugar del valor real. Se resolverán cuando el SDK renderice el flow en tu app. Para previsualizar las condiciones que dependen del tipo de oferta, consulta [Previsualizar productos y ofertas](paywall-device-compatibility-preview#preview-products-and-offers).

## La publicación falla al introducir un color hex abreviado \{#publishing-fails-after-entering-a-shorthand-hex-color\}

Introduce siempre los colores con exactamente seis dígitos hexadecimales, como `#FFFFFF`. El campo de color acepta valores más cortos pero nunca los expande, por lo que un valor abreviado como `#FFF` llega mal formado a la configuración del SDK y la publicación se rechaza. La opacidad no tiene relación: el mismo valor falla con opacidad al 100%. El caso más problemático es el de cuatro dígitos: se publica, pero muestra un color distinto al que seleccionaste.

## Las ediciones de tipografía no llegan a un estado de elemento \{#typography-edits-dont-reach-an-element-state\}

Una vez que un estado, como **Selected**, tiene su propia configuración de tipografía, las ediciones en la tipografía del estado **Default** —incluida la aplicación de un estilo de texto diferente— no afectan a ese estado. Edita la tipografía del estado directamente.

## Los elementos pierden su estilo al eliminar un estilo de texto \{#elements-lose-their-styling-after-a-text-style-is-deleted\}

Eliminar un [estilo de texto](builder-styling#text-styles) no copia su configuración en los elementos que lo usan: esos elementos vuelven a la tipografía predeterminada. Antes de eliminar un estilo, reasigna los elementos afectados a otro estilo o configura su tipografía manualmente.

## Las condiciones y variables se rompen al cambiar un ID de elemento \{#conditions-and-variables-break-after-an-element-id-change\}

Las condiciones y las variables de texto hacen referencia a los elementos por su **Element ID**, y cambiar el ID no actualiza las referencias — dejan de resolverse silenciosamente. Establece el Element ID antes de referenciarlo. Si tienes que cambiarlo, actualiza todas las referencias de condiciones y variables para que coincidan. La excepción son los segmentos de barra de progreso: renombrar un segmento actualiza sus referencias automáticamente.

## Una condición o variable se resuelve como un valor vacío \{#a-condition-or-variable-resolves-to-an-empty-value\}

El selector de variables muestra campos de todas las pantallas, por lo que una condición o variable de texto puede hacer referencia a un campo que el usuario aún no ha rellenado. En tiempo de ejecución, esa referencia se resuelve como un valor vacío. Referencia solo los campos recopilados en pantallas anteriores del flow.

## La acción Set variable no cambia el producto seleccionado \{#a-set-variable-action-doesnt-change-the-selected-product\}

El producto seleccionado no es una variable que puedas asignar, por lo que **Set variable** no puede cambiar la selección. Usa la acción [**Select product**](onboarding-actions#select-product) en su lugar.

## Una imagen o vídeo no se sube \{#an-image-or-video-wont-upload\}

Los archivos que estén fuera de los límites de medios del Flow Builder no se subirán. Verifica el archivo según los requisitos de [imagen](custom-media#image) y [vídeo](custom-media#video):

| Elemento | Formatos | Tamaño máximo de archivo | Otros límites |
| :--- | :--- | :--- | :--- |
| Imagen | `.JPG`, `.PNG`, `.WEBP` | 20 MB | — |
| Vídeo | `.MP4`, `.WEBM` | 50 MB | Máximo 30 segundos; mínimo 640×640 píxeles |

Estos formatos no son compatibles:

- **GIFs animados y WEBPs animados**: Para añadir movimiento, usa un elemento de vídeo en su lugar.
- **SVG**: Exporta el archivo como PNG o WEBP. Para los iconos, no necesitas subir nada — el elemento de icono usa la biblioteca [Tabler Icons](custom-media#icon) incluida.

## El pie de página no se renderiza \{#a-footer-doesnt-render\}

El pie de página solo se renderiza en una pantalla donde **Vertical scroll** está habilitado. Activa **Vertical scroll** en [**Screen settings** > **Scroll**](paywall-layout-and-products#scroll).
