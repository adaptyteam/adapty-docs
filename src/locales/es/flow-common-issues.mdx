Este artículo recoge los problemas más frecuentes al crear un flow en el [Flow & Paywall Builder](adapty-flow-builder), con su causa y su solución.

## Un flow no se puede previsualizar ni publicar \{#a-flow-wont-preview-or-publish\}

<ZoomImage id="flow-cant-publish-yet.webp" width="500px" alt="Diálogo «No se puede publicar aún» que indica que tres tarjetas de la pantalla todavía necesitan un producto" />

Puede que encuentres los siguientes errores al intentar previsualizar o publicar el flow:

| Mensaje | Causa y solución |
|---|---|
| **No product selected** | Una tarjeta de producto no tiene producto. Elige uno o elimina la tarjeta. |
| **This product no longer exists**, **This offer no longer exists** | El producto u oferta se eliminó del Dashboard. Elige otro donde se use, o utiliza **Replace in N places** en la entrada **Missing** del panel **Products** para corregir todos los usos en la pantalla de una vez. |
| **This product is off this screen**, **This offer is off this screen** | Una variable de texto, condición o acción hace referencia a un producto que no está en la lista de la pantalla, por ejemplo, después de eliminarlo en el panel **Products**. Vuelve a añadir el producto en el panel o edita la referencia. |
| **Offer required** | Se usa `offer_price`, `offer_billing_period` u `offer_full_duration` con un producto que no tiene oferta. Elige una oferta para el producto o utiliza una variable `prod_*` en su lugar. |
| **Product reference is invalid** | La referencia de producto está mal formada. Vuelve a seleccionar el producto. |
| **Purchase action has no product to buy** | Una acción **Purchase** no tiene producto: está vacía o apunta a una tarjeta eliminada. En la pestaña **Interactions** del elemento, establece **Product** como un producto o como `products.selectedProduct`. |
| **Select product action has no product to select** | La tarjeta a la que apuntaba una acción **Select product** ya no existe: fue eliminada, se sacó de su grupo de productos o está en otra pantalla. En la pestaña **Interactions** del elemento, apunta la acción a una tarjeta de esta pantalla. |
| **Flow has no screens**, **Screen "…" has no elements** | Añade contenido a la pantalla vacía o elimínala. Un flow que solo contiene contenido de Remote Config está exento. |
| **Invalid interaction action** | Una acción está incompleta: **Open URL** sin URL, **Navigate to screen** sin destino, **Set variable** sin asignación, **Custom** sin un Action ID, **Show alert** sin título ni mensaje, **Show** o **Hide** sin elemento, o un **Purchase** de pago web sin Web Paywall URL. Abre las interacciones del elemento y completa o elimina la acción. |
| **Missing navigation target** | Una acción **Navigate to screen** apunta a una pantalla que fue eliminada. Elige una pantalla existente o elimina la acción. |
| **Missing product target**, **Invalid product target**, **Product target on another screen**, **Ambiguous product target**, **Select Product inside a component** | Una acción **Select product** apunta a una tarjeta que fue eliminada, no está en un grupo de productos, está en otra pantalla, comparte su ID de elemento con un elemento de otra pantalla, o está dentro de un pie de página o encabezado compartido entre pantallas. Apunta la acción a una tarjeta de un grupo de productos en la misma pantalla, con un ID único. |
| **Missing selectable group** | Un elemento apunta a un grupo seleccionable que ya no existe. Reconéctalo o vuelve a crearlo. |
| **Invalid visibility condition** | Una regla de visibilidad condicional está incompleta. Complétala en el generador de condiciones. |
| **Broken references**, **Fix the broken reference before publishing.**, **Fix N broken references before publishing.** | Al hacer clic en **Publish to Live**, el diálogo **Can't publish yet** muestra las condiciones que usan un elemento, un estado o una variable que ya no existe, por ejemplo, después de eliminarlo o pegar una pantalla de otro flow. Las filas de condiciones con un valor pero sin variable aparecen en la misma lista. Haz clic en **Go to screen** para abrir la primera. Luego abre la condición y elige un elemento, estado o variable existente, o elimina la condición. |
| **Condition uses a deleted element or state**, **Condition uses a deleted variable** | La publicación falló porque una condición usa un elemento, un estado o una variable que ya no existe. Abre la condición y elige un elemento, estado o variable existente, o elimina la condición. Luego vuelve a publicar. |
| **Invalid State Condition**, `invalid_state_condition` | La CLI de Adapty o la API no pudo publicar el flow: una fila en la condición de un estado **Disabled** o **custom** tiene un valor o **Is empty** pero no tiene variable. Elige una variable para esa fila o elimina la fila. Luego vuelve a publicar. |
| **Circular state conditions** | Las condiciones de estado **Disabled** o **custom** de varios elementos dependen mutuamente entre sí formando un bucle. En la sección **States** de uno de estos elementos, cambia o elimina la condición que cierra el bucle. |
| Un nombre de fórmula bajo **Variables**, con un texto de error como **This variable no longer exists. Pick another one.** | Una [fórmula](flow-formulas) tiene un error. En el panel Variables, la fila de la fórmula muestra un icono de error. Abre la variable y corrige la fórmula como se indica en [Solución de problemas](flow-formulas#troubleshooting). |
| **Formula "…" has a syntax error** | La fórmula no sigue las reglas de sintaxis: por ejemplo, falta un paréntesis, un número tiene coma o el nombre de una función es desconocido. Abre la variable y corrige la fórmula. |
| **Formula "…" has a wrong number of arguments** | Una función de la fórmula tiene demasiados o muy pocos argumentos. Usa los argumentos de las listas de [funciones numéricas](flow-formulas#number-functions) y [funciones de fecha](flow-formulas#date-functions). |
| **Formula "…" uses a value of the wrong type** | La fórmula usa un texto, un valor sí/no o una fecha donde necesita un número, o un número donde necesita una fecha. Abre la variable y corrige la fórmula. |
| **Formula "…" uses a deleted value** | La fórmula lee una variable, una respuesta o un grupo de productos que ya no está en el flow. Reemplaza la referencia en la fórmula. |
| **Formula "…" uses a name with two meanings** | Una variable de la fórmula tiene el mismo nombre que una respuesta de elemento o un campo de producto. Renombra la variable. |
| **Formula "…" uses itself in a loop** | Las fórmulas del flow se leen entre sí en un bucle, por lo que el flow no puede calcularlas. Elimina una de las referencias. |
| **Set Variable writes the formula "…"** | Una acción **Set variable** modifica una fórmula. Una fórmula siempre depende de otros valores, por lo que una acción no puede establecerla. Selecciona otra variable en la acción. |
| **Variable "…" cannot show in an action** | Una variable de fecha o una [fórmula](flow-formulas) está en el título o el mensaje de una acción **Show alert**, en la dirección de una acción **Open URL**, o en el valor de texto de una acción **Set variable**. Estos textos no pueden mostrar una fecha o un número calculado en el dispositivo. Elimina la variable de la acción. Para mostrar el valor, insértalo en un elemento de texto. |
| **Missing Default Locale Content** | Una acción **Open URL** tiene una URL en otro idioma pero ninguna en el idioma predeterminado. Añade la URL predeterminada en el [panel **Localizations**](add-paywall-locale-in-adapty-paywall-builder). |
| **Missing product reference** | Un flow antiguo usa un producto que no está registrado en la pantalla. Abre la pantalla y añade el producto en el panel **Products**. |

[Previsualiza el flow en la app de Adapty](paywall-device-compatibility-preview) con regularidad mientras construyes. Un flow que no se puede publicar tampoco se cargará allí, y el mensaje de error indica el problema.

:::tip
Para saber si tu flow está listo para producción, ejecuta el [skill flow-audit](flow-audit-skill). Comprueba lo que los errores de publicación no detectan: botones sin función, cumplimiento con la store, textos incompletos y cobertura de traducciones. El informe identifica cada problema con el nombre del elemento y su pantalla.
:::

## La publicación falla con "Something went wrong" y sin detalles

<ZoomImage id="flow-publish-error.webp" width="300px" alt="Notificación de error tras un intento de publicación fallido, con la dirección de soporte y el Request ID para copiar" float="right" />

La solicitud de publicación falló en el lado de Adapty, no por culpa de tu flow. Tu versión en producción no ha cambiado. Espera unos minutos y vuelve a publicar. Si vuelve a fallar, copia el **Request ID** de la notificación y envíalo a [support@adapty.io](mailto:support@adapty.io) para que el equipo pueda localizar la solicitud fallida.

## Una oferta no se aplica en la compra \{#an-offer-doesnt-apply-at-purchase\}

El builder solo comprueba que la oferta siga existiendo en Adapty. Si el descuento se aplica o no lo decide el store en el momento de la compra: las ofertas introductorias dependen de la elegibilidad del cliente, y las ofertas promocionales de App Store necesitan una In-App Purchase Key válida. Ambos casos se tratan en [Discrepancias de productos y precios](store-sync#product-and-price-discrepancies).

## El precio de una oferta está vacío en la vista previa \{#an-offer-price-is-empty-in-the-preview\}

La vista previa del builder no puede conectarse a los stores, por lo que `offer_price`, `offer_billing_period` y `offer_full_duration` muestran el nombre de la variable entre llaves en lugar del valor real. Se resolverán cuando el SDK renderice el flow en tu app. Para previsualizar las condiciones que dependen del tipo de oferta, consulta [Previsualizar productos y ofertas](paywall-device-compatibility-preview#preview-products-and-offers).

## La publicación falla al introducir un color hex abreviado \{#publishing-fails-after-entering-a-shorthand-hex-color\}

Introduce siempre los colores con exactamente seis dígitos hexadecimales, como `#FFFFFF`. El campo de color acepta valores más cortos pero nunca los expande, por lo que un valor abreviado como `#FFF` llega mal formado a la configuración del SDK y la publicación se rechaza. La opacidad no tiene relación: el mismo valor falla con opacidad al 100%. El caso más problemático es el de cuatro dígitos: se publica, pero muestra un color distinto al que seleccionaste.

## Las ediciones de tipografía no llegan a un estado de elemento \{#typography-edits-dont-reach-an-element-state\}

Una vez que un estado, como **Selected**, tiene su propia configuración de tipografía, las ediciones en la tipografía del estado **Default** —incluida la aplicación de un estilo de texto diferente— no afectan a ese estado. Edita la tipografía del estado directamente.

## Faltan los controles de posición, tamaño y espaciado para un elemento \{#position-size-and-spacing-controls-are-missing-for-an-element\}

El elemento y su contenedor usan la dirección **Free**. Eso deja solo una posición y un tamaño posibles: **Absolute**, con ancho y alto fijos. Adapty oculta los controles para todo lo demás: el selector **Position**, la sección **Spacing**, y las opciones **Fill** y **Hug**. Para recuperar los controles, cambia la [**Direction**](manage-paywall-ui-elements#direction) del elemento a **Vertical** u **Horizontal**.

## Una condición deja de coincidir tras cambiar el Element ID de una opción de quiz \{#a-condition-stops-matching-after-you-change-the-element-id-of-a-quiz-option\}

Una condición que compara la opción seleccionada por el usuario con un valor, como `quiz.selectedOptionId` `=` `option_1`, contiene el **Element ID** de la opción como texto plano. Cuando cambias el **Element ID**, el builder no actualiza ese texto, por lo que la condición deja de coincidir. Define el **Element ID** de cada opción antes de usarla en una condición. Si lo cambias después, actualiza todas las condiciones que hagan referencia al ID anterior.

El builder actualiza automáticamente el resto de referencias: las variables de los campos de entrada, los IDs de grupo, los estados de los elementos y los segmentos de la barra de progreso.

## Una condición o variable se resuelve en un valor vacío \{#a-condition-or-variable-resolves-to-an-empty-value\}

El selector de variables muestra campos de todas las pantallas, por lo que una condición o variable de texto puede referenciar un campo que el usuario aún no ha rellenado. En tiempo de ejecución, esa referencia se resuelve en un valor vacío. Referencia solo los campos recopilados antes en el flow.

La variable de un [selector numérico](builder-number-picker) nunca está vacía: es igual al número predeterminado hasta que los usuarios giren la rueda. Una condición que evalúa la variable antes de que los usuarios lleguen al selector puede coincidir con una respuesta que nunca dieron.

## Los usuarios ven el valor inicial de una etiqueta personalizada en lugar del valor de tu app \{#users-see-a-custom-tags-initial-value-instead-of-your-apps-value\}

Los usuarios ven el valor inicial de una [etiqueta personalizada](flow-custom-tags) en los siguientes casos:

- **Tu app no pasa ningún valor**: El código que abre el flow no pasa ningún valor para el tag, o el usuario no ha actualizado tu app a la versión que lo hace.
- **El nombre no coincide**: El nombre en el código de tu app es diferente al nombre del tag en el builder. Los nombres distinguen mayúsculas de minúsculas e incluyen el grupo. Por ejemplo, si el grupo `user` contiene un tag `streak`, el nombre exacto del tag es `user.streak`.
- **Otro tag en el mismo elemento de texto no tiene valor**: Si un tag personalizado en un elemento de texto no tiene valor, todos los tags de ese elemento muestran su valor inicial. Pasa un valor para cada tag personalizado en el elemento de texto.

La app móvil de Adapty no pasa valores para las etiquetas personalizadas, por lo que la vista previa solo muestra los valores iniciales. Para ver los valores que pasa tu app, abre el flow en una build de tu app.

## Los usuarios no ven nada en lugar de una etiqueta personalizada \{#users-see-nothing-in-place-of-a-custom-tag\}

Los usuarios no ven nada en lugar de una [etiqueta personalizada](flow-custom-tags) en los siguientes casos:

- **Tu app envía una cadena vacía**: Adapty trata una cadena vacía como un valor, por lo que el valor inicial no aparece como alternativa. Para mostrar el valor inicial, no envíes ningún valor para la etiqueta.
- **La etiqueta no tiene valor inicial**: Para mostrar un valor alternativo cuando tu app no envía ningún valor, introduce un valor inicial para la etiqueta.

## La acción Set variable no cambia el producto seleccionado \{#a-set-variable-action-doesnt-change-the-selected-product\}

El producto seleccionado no es una variable que puedas asignar, por lo que **Set variable** no puede cambiar la selección. Usa la acción [**Select product**](onboarding-actions#select-product) en su lugar.

## El flow no ejecuta las acciones configuradas para el resultado de una compra \{#the-flow-doesnt-run-the-actions-set-for-a-purchase-result\}

El flow ejecuta las [acciones de resultado](respond-to-purchase-outcomes#add-actions-for-a-result) de una compra o restauración cuando el store devuelve el resultado. En ese momento, el usuario debe estar en la pantalla donde comenzó la compra. El flow las omite en los siguientes casos:

- **Tu app cierra el flow**: Cuando una compra o restauración finaliza, tu app cierra el flow en su callback. Para que el flow continúe, [mantén el flow abierto en estos callbacks](respond-to-purchase-outcomes#before-you-start).
- **Una navegación se ejecuta antes que el resultado**: Una acción **Navigate to Screen**, **Navigate Next**, **Navigate back** o **Close Flow** sigue a **Purchase** o **Restore purchases** en el mismo trigger. Esa acción se ejecuta al tocar, por lo que el usuario abandona la pantalla antes de que la store devuelva el resultado. Mueve la acción a un outcome, como **When succeeded**.
- **El usuario abandona la pantalla**: El usuario va a otra pantalla antes de que la store devuelva el resultado, por ejemplo con el botón de retroceso.
- **La compra es una compra Web Payment**: El flow no recibe el resultado de una compra **Web Payment**, por lo que una acción **Purchase** configurada como **Web Payment** no tiene outcomes. Cuando cambias la acción a **Web Payment**, el Flow & Paywall Builder elimina sus acciones de outcome.

No puedes realizar compras reales en la vista previa de la aplicación móvil de Adapty. Para probar las acciones resultantes, [realiza una compra en sandbox](test-purchases-in-sandbox) en una compilación de tu aplicación.

## El botón de compra no hace nada en Android \{#a-purchase-button-does-nothing-on-android\}

En Android, al pulsar el botón **Purchase** no ocurre nada si el usuario lo toca antes de que Google Play devuelva los productos. Una vez que los productos se cargan, el botón funciona correctamente. En iOS, ese mismo toque anticipado hace fallar la compra y el flow ejecuta las acciones de **When failed**.

El botón no funciona en ningún caso en las siguientes situaciones:

- **Google Play no devuelve el producto**: Asegúrate de que el producto está activo en Google Play Console y de que el producto en Adapty usa el mismo ID de producto de Google Play. Para revisar el producto en Adapty, consulta [Crear producto](create-product).
- **Los productos no se pudieron cargar**: En una app Android nativa, el SDK no vuelve a cargar los productos de forma predeterminada. Para reintentarlo, devuelve `true` desde [`onLoadingProductsFailure`](android-handling-events#product-loading-errors).
- **Tu app pasa productos al flow sin incluir este**: Cuando tu app pasa [`products`](android-present-paywalls) al flow, el SDK no carga ninguno desde Google Play. Añade cada producto del flow a esa lista.
- **Una compra anterior nunca se completó**: El SDK ignora las nuevas compras hasta que la anterior finalice. En modo Observer, llama a `onFinishPurchase()` después de cada compra. En [`onAwaitingPurchaseParams`](android-handling-events#upgrade-subscription), llama siempre a `onPurchaseParamsReceived`.

En iOS, si el App Store no devuelve el producto, cada tap fallará en la compra y el flow ejecutará las acciones de **When failed**. Para encontrar la causa, consulta [Los productos no aparecen](troubleshoot-app-store-integration#products-dont-appear).

## Una imagen o vídeo no se sube \{#an-image-or-video-wont-upload\}

Un archivo que supere los límites de medios del Flow & Paywall Builder no se subirá. Verifica el archivo según los requisitos de [Imagen](custom-media#image) y [Vídeo](custom-media#video):

| Elemento | Formatos | Tamaño máximo del archivo | Otros límites |
| :--- | :--- | :--- | :--- |
| Imagen | `.JPG`, `.PNG`, `.WEBP` | 20 MB | — |
| Vídeo | `.MP4`, `.WEBM` | 50 MB | 30 segundos máximo; 640×640 píxeles mínimo |

Estos formatos no son compatibles:

- **GIFs animados y WEBPs animados**: Para añadir movimiento, usa un elemento de vídeo en su lugar.
- **SVG**: Exporta el archivo como PNG o WEBP. Para los iconos, no necesitas subir nada — el elemento de icono usa la biblioteca [Tabler Icons](custom-media#icon) incluida.

## El pie de página no se renderiza \{#a-footer-doesnt-render\}

El pie de página solo se renderiza en una pantalla donde **Vertical scroll** está habilitado. Activa **Vertical scroll** en [**Screen settings** > **Scroll**](paywall-layout-and-products#scroll).
