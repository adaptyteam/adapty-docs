Para actualizar tu app del SDK de Android de Adapty 4.1, 4.2 o 4.3 a la versión 4.4, establece la versión de `adapty-bom` en `4.4.0` y reemplaza el archivo de respaldo en la misma compilación. Las versiones 4.1–4.3 del SDK rechazarán el nuevo archivo. Si tu app está en la versión 4.0, primero debes aplicar los [cambios de v4.1](migration-to-android-sdk-41).

:::warning
El formato del archivo de respaldo cambió en la versión 4.4, y el compilador no puede detectar un archivo desactualizado. Sin un [nuevo archivo de respaldo](#replace-the-fallback-file), cada placement perderá su respaldo.
:::

## Reemplazar el archivo de respaldo \{#replace-the-fallback-file\}

Para volver a descargar el [archivo de respaldo](fallback-flows), en **[Placements](https://app.adapty.io/placements)**, haz clic en **Fallbacks** > **Download Android Fallback**. En la fila **Adapty SDK v4.4.0 and higher**, haz clic en **Download**. Incluye el archivo en tu app.

El archivo descargado se llama `android_4_4_0_fallback.json`. Ponle el nombre del archivo que carga tu app, o actualiza el nombre en la llamada que lo carga:

- **`FileLocation.fromAsset`**: El nombre del archivo, como `android_fallback.json`.
- **`FileLocation.fromResId`**: El nombre del recurso, como `android_fallback` en `R.raw.android_fallback`.

Con un archivo desactualizado, `Adapty.setFallback` pasa un `AdaptyError` a su callback con el mensaje "The fallback file version is not correct. Download a new one from the Adapty Dashboard." Para verificar el nuevo archivo, ejecuta la app y asegúrate de que el callback no recibe ningún error. El callback es opcional. Sin él, establece el [nivel de log](sdk-installation-android#logging) en `AdaptyLogLevel.ERROR` o un nivel más detallado. Luego comprueba que Logcat no muestre este error.
