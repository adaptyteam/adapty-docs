El SDK de Adapty iOS 4.4 requiere iOS 16 para los flows. Para actualizar tu app de 4.3 a 4.4, aplica todos los cambios de esta guía. Si tu app está en 4.1 o 4.2, primero necesitas los [cambios de v4.3](migration-to-ios-sdk-43), y si está en 4.0, antes debes aplicar los [cambios de v4.1](migration-to-ios-sdk-41). Para continuar a 4.5, sigue [Migrar a v4.5](migration-to-ios-sdk-45).

:::warning
El formato del archivo de respaldo cambió en 4.4 y el compilador no puede detectar un archivo desactualizado. Sin un [nuevo archivo de respaldo](#fallback-files), cada placement perderá su fallback.
:::

## Referencia rápida \{#quick-reference\}

| Antes | Después |
|---|---|
| Los flows se abren en iOS 15 | Los flows requieren iOS 16 |
| `case let .custom(id)` | `case let .custom(id, _)` |
| `AdaptyUICustomAsset` | `AdaptyUIAsset`; `AdaptyCustomAsset` no cambia |
| `.color(.uiColor(x))` y `.color(.swiftUIColor(c))` | `.color(Color(uiColor: x))` y `.color(c)` |
| `AdaptyUICustomFontAsset(font:defaultColor:defaultLetterSpacing:defaultLineHeight:)` | `AdaptyUIFontAsset(font:color:letterSpacing:lineHeight:)` |
| Sin assets de datos | `AdaptyUIAsset` incluye `.data` para assets de datos |
| `AdaptyProduct.localizedBillingPeriod` | `subscriptionPricingTerms?.localizedBillingPeriod` |
| Archivo de respaldo descargado para 4.1–4.3 | Nuevo formato de archivo de respaldo; descarga el archivo de nuevo |

## Los flows requieren iOS 16 \{#flows-require-ios-16\}

A partir de la versión 4.4, los flows requieren iOS 16 o posterior. Otras funciones del SDK, como las compras y los paywalls personalizados, siguen funcionando en iOS 15.

Si tu app es compatible con iOS 15, el código que usa las APIs de flow dejará de compilar. Estas APIs incluyen `AdaptyUI.getFlowConfiguration`, `AdaptyFlowController` y el modificador `.flow` en SwiftUI. Para mantener la compatibilidad con iOS 15, marca los tipos que usan flows con `@available(iOS 16.0, *)` y abre el flow dentro de `if #available(iOS 16.0, *)`. En la rama `else`, muestra tu propio contenido, como un [paywall personalizado](ios-implement-paywalls-manually).

## AdaptyUI.Action.custom contiene dos valores \{#custom-actions\}

Cuando un usuario pulsa un botón con una acción personalizada, tu app recibe `AdaptyUI.Action.custom`. En la versión 4.4, contiene un segundo valor, `arguments`, después del ID de la acción. En el closure `didPerformAction` y en el método delegado `flowController(_:didPerform:)`, añade `_` para este segundo valor:

```diff showLineNumbers
  switch action {
- case let .custom(id):
+ case let .custom(id, _):
      if id == "openNewPaywall" {
          // Display another flow or paywall
      }
  default:
      break
  }
```

```swift
switch action.id {
case .system(let systemAction):
    return AdaptyUI.Action.system(systemAction)
case .custom(let id, _):
    return AdaptyUI.Action.custom(id: id)
}
```

## Activos personalizados \{#custom-assets\}

En la versión 4.4, `AdaptyUICustomAsset` pasa a llamarse `AdaptyUIAsset`. El nombre anterior genera una advertencia de obsolescencia.

Los activos de color, fuente y datos cambian en tres aspectos:

- **Activos de color**: `.color` acepta un `Color` de SwiftUI. `AdaptyUICustomColorAsset` ha sido eliminado. Envuelve un `UIColor` en `Color(uiColor:)` y pasa un `Color` de SwiftUI directamente:

  ```diff showLineNumbers
  - "brand_color": .color(.uiColor(brandColor)),
  + "brand_color": .color(Color(uiColor: brandColor)),
  ```

- **Recursos de fuentes**: `AdaptyUIFontAsset` usa `color:`, `letterSpacing:`, y `lineHeight:` en lugar de `defaultColor:`, `defaultLetterSpacing:`, y `defaultLineHeight:`. El parámetro `color:` acepta un `Color` de SwiftUI:

  ```diff showLineNumbers
  - "title_font": .font(AdaptyUICustomFontAsset(font: titleFont, defaultColor: .uiColor(.white), defaultLineHeight: 24)),
  + "title_font": .font(AdaptyUIFontAsset(font: titleFont, color: .white, lineHeight: 24)),
  ```

- **Recursos de datos**: `AdaptyUIAsset` incluye un nuevo tipo de recurso, `.data`. Una sentencia `switch` que lista todos los tipos de recurso sin rama `default` dejará de compilar. Solo los [elementos personalizados](ios-flow-custom-elements) leen recursos de datos, por lo que la nueva rama puede estar vacía: `case .data: break`.

## AdaptyProduct.localizedBillingPeriod está obsoleto \{#localizedbillingperiod-is-deprecated\}

`AdaptyProduct` tiene una propiedad [`subscriptionPricingTerms`](fetch-paywalls-and-products) que describe cada pago del producto: su precio y la frecuencia con que el usuario paga. En la versión 4.4, `localizedBillingPeriod`, el texto que indica la frecuencia de pago, se traslada de `AdaptyProduct` a `subscriptionPricingTerms`. `AdaptyProduct.localizedBillingPeriod` sigue funcionando, con una advertencia de deprecación: devuelve `subscriptionPricingTerms?.localizedBillingPeriod`. Para eliminar la advertencia, lee la propiedad desde los términos de precio:

```diff showLineNumbers
- let period = product.localizedBillingPeriod
+ let period = product.subscriptionPricingTerms?.localizedBillingPeriod
```

## Archivos de respaldo \{#fallback-files\}

El formato del [archivo de respaldo](fallback-flows) cambió en el SDK 4.4. Descarga el archivo de nuevo desde **[Placements](https://app.adapty.io/placements)** > **Fallbacks**, selecciona **Adapty SDK v4.4.0 and higher** y agrégalo a tu app.

El archivo descargado se llama `ios_4_4_0_fallback.json`. Dale el nombre que tu app pasa a `Bundle.main.url(forResource:withExtension:)`, o actualiza el nombre en esa llamada.

:::warning
Un archivo de respaldo desactualizado no produce ningún error de compilación. Cada placement pierde silenciosamente su paywall de respaldo. El log del SDK mostrará entonces: "The fallback paywalls version is not correct. Download a new one from the Adapty Dashboard."
:::
