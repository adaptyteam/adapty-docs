import Callout from '../../../components/Callout.astro';

:::important
Los campos, los selectores de fecha y hora, y los grupos seleccionables nunca envían su valor predeterminado a través de este callback. Si un usuario acepta la opción marcada como **Set as default** y continúa, no se dispara ningún evento. No interpretes la ausencia del evento como «sin respuesta»: el usuario simplemente dejó el valor predeterminado tal como estaba. Un [Number picker](builder-number-picker) envía su número predeterminado al código de tu app cuando el usuario pulsa un botón que abre otra pantalla.
:::

**Los siguientes elementos disparan este evento:**

- Campos de texto, email, número y teléfono
- Selectores de fecha, hora y fecha-hora
- Number pickers
- Grupos seleccionables de elección única y múltiple, y toggles

**Los siguientes no lo hacen:**

- Campos de contraseña, selecciones de productos y cambios de pestaña
- Entradas dentro de un elemento Header, que se comparte entre pantallas
- Grupos seleccionables con IDs de elemento de opción duplicados o ausentes, o con un Group ID reutilizado en otra pantalla. Ese tipo de grupo no envía nada en absoluto, en lugar de enviar parte de la respuesta.

**El evento se dispara cuando:**

- Un campo pierde el foco. Un campo vaciado reporta una cadena vacía; un campo que el usuario nunca editó no reporta nada. Un marcador de posición no es un valor. Si el usuario vuelve al campo, lo edita y lo abandona de nuevo, se genera un segundo evento.
- El usuario cierra un selector de fecha u hora tras elegir un nuevo valor. Cerrarlo sin cambios no reporta nada.
- En una pantalla con un Number picker, el usuario pulsa un botón que ejecuta una acción **Navigate to Screen**, **Navigate Next** o **Navigate back** [action](onboarding-actions). El Number picker también reporta su valor cuando el usuario pulsa una opción o un toggle en la misma pantalla. Si el usuario nunca giró la rueda, el valor es el número predeterminado. Un Number picker reporta su valor incluso cuando está oculto, por ejemplo en una pestaña que el usuario no abrió. No se genera un segundo evento hasta que el valor cambie.
- El usuario pulsa una opción o un toggle. Un evento de elección múltiple lista todas las opciones seleccionadas, por lo que deseleccionar la última envía dos arrays vacíos.

**El evento no se dispara cuando:**

- El usuario escribe. No existe un flujo de pulsaciones de teclas, solo el valor que contiene el campo cuando pierde el foco.
- El usuario envía o cierra el flow. Un valor que aún se está editando en ese momento puede perderse. Un botón que cierra el flow, inicia una compra o ejecuta una acción personalizada no reporta el valor de un Number picker. La sección de [limitaciones de entrega](#delivery-and-limitations) explica cómo diseñar la última pantalla teniendo en cuenta ambos casos.
- Se establece un valor sin interacción del usuario. Una opción marcada como **Set as default** queda preseleccionada cuando se abre la pantalla, y una acción **Set Variable** puede seleccionar una opción o rellenar un campo a partir de otra interacción. Ninguna de las dos envía un evento; un campo prerrellenado que no sea un Number picker solo se reporta una vez que el usuario lo edite.
