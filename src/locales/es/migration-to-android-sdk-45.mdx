Para actualizar tu app del SDK de Android de Adapty 4.4 a 4.5, establece la versión de `adapty-bom` en `4.5.0` y aplica todos los cambios de esta guía. Si tu app está en 4.3 o anterior, primero necesitas los [cambios de v4.4](migration-to-android-sdk-44).

En la versión 4.5, `getFlowConfiguration` requiere una lista de idiomas en `preferredLocales`, en lugar de un código de idioma opcional en `locale`. El SDK [selecciona una localización del flow a partir de esta lista](android-localizations-and-locale-codes).

:::warning
Actualiza todas las llamadas a `getFlowConfiguration` para que pasen [`preferredLocales`](#replace-locale-with-the-users-languages). Tras la actualización, el SDK 4.5 puede mostrar a los usuarios [una localización diferente del mismo flow](#what-users-see-after-the-update) a la que mostraba el SDK 4.4.
:::

## Referencia rápida \{#quick-reference\}

| Antes | Después |
|---|---|
| `getFlowConfiguration(flow, locale = "fr")` | `getFlowConfiguration(flow, preferredLocales)`, con `preferredLocales` de `LocaleListCompat.getAdjustedDefault()` |
| `locale`: opcional | `preferredLocales`: obligatorio |
| Sin `locale`: los usuarios ven `en`, aunque el idioma predeterminado del flow sea otro. Si el flow no incluye `en`, los usuarios ven el idioma predeterminado | `preferredLocales = emptyList()`: todos los usuarios ven el flow en su idioma predeterminado, independientemente de los idiomas del dispositivo |
| Sin parámetro de estrategia | `localizationStrategy`, opcional. El valor predeterminado, `AdaptyUiLocalizationStrategy.Auto`, es adecuado para la mayoría de las apps. |

## Reemplaza `locale` por los idiomas del usuario \{#replace-locale-with-the-users-languages\}

En la versión 4.5, `getFlowConfiguration` recibe una lista `preferredLocales` en lugar de `locale`. El parámetro `preferredLocales` es obligatorio. Si realizas una llamada en Kotlin con `locale` o sin ninguno de los dos parámetros, Android Studio mostrará un error con este mensaje:

```text
Pass preferredLocales: LocaleListCompat.getAdjustedDefault().toLanguageTags().split(",") to show the flow in the app's languages, or emptyList() to use the flow's default localization.
```

En Java, una llamada con `locale` o sin ninguno de los dos parámetros sigue compilando, con una advertencia de deprecación. Para una llamada en Java sin `locale`, los usuarios ven el flow en su locale predeterminado en lugar de `en`.

Actualiza cada llamada `getFlowConfiguration` en Kotlin y en Java. El parámetro `locale` de `getOnboarding` no cambia.

<Tabs groupId="current-os" queryString>
<TabItem value="kotlin" label="Kotlin" default>

```diff showLineNumbers
  AdaptyUI.getFlowConfiguration(
      flow,
-     locale = "fr",
+     preferredLocales = LocaleListCompat.getAdjustedDefault().toLanguageTags().split(","),
  ) { result ->
      // handle the result
  }
```

</TabItem>
<TabItem value="java" label="Java">

```diff showLineNumbers
- AdaptyUI.getFlowConfiguration(flow, "fr", result -> {
+ List<String> preferredLocales =
+     Arrays.asList(LocaleListCompat.getAdjustedDefault().toLanguageTags().split(","));
+ AdaptyUI.getFlowConfiguration(flow, preferredLocales, result -> {
      // handle the result
  });
```

</TabItem>
</Tabs>

Lo que tu app pasó en 4.4 determina qué pasar en 4.5:

- Si tu app pasaba un valor del dispositivo, como `Locale.getDefault().toLanguageTag()`, pasa en su lugar la lista de `LocaleListCompat.getAdjustedDefault()`. Elimina cualquier código que convirtiera el valor: en la versión 4.5 el formato de mayúsculas y los separadores no importan.
- Si tu app pasaba un idioma que el usuario seleccionaba en la app, ponlo primero: `listOf(selectedLanguage)`, seguido de la lista de `LocaleListCompat.getAdjustedDefault()`. Cuando un flow del Flow & Paywall Builder no tiene ese idioma, el SDK prueba con los idiomas del dispositivo.
- Si tu app llamaba a `getFlowConfiguration` sin `locale`, añade `preferredLocales` con la lista de `LocaleListCompat.getAdjustedDefault()`.

Para mostrar el flow en los idiomas del dispositivo, incluso cuando el usuario ha seleccionado otro idioma para tu app, pasa la lista de `LocaleManagerCompat.getSystemLocales(context)`. Para comparar las listas, consulta [Pasar los idiomas del usuario al SDK](android-localizations-and-locale-codes#pass-the-users-languages-to-the-sdk).

Para mostrar el flow a todos los usuarios en su configuración regional predeterminada, pasa una lista vacía: `preferredLocales = emptyList()`.

No es necesario pasar `localizationStrategy`. Sin él, el SDK usa `AdaptyUiLocalizationStrategy.Auto`, que es adecuado para flows del Flow & Paywall Builder y para paywalls del antiguo Paywall Builder. Las [otras estrategias](android-localizations-and-locale-codes#select-a-localization-strategy) cambian la forma en que el SDK hace coincidir los idiomas.

## Qué ven los usuarios tras la actualización \{#what-users-see-after-the-update\}

Con la `localizationStrategy` predeterminada, el SDK 4.5 puede mostrar a los usuarios una localización diferente del mismo flow que el SDK 4.4:

| La app pasa | El flow tiene | 4.4 | 4.5 |
|---|---|---|---|
| Sin idiomas: sin `locale` en 4.4, `emptyList()` en 4.5 | Cualquier idioma | `en`, si el flow lo tiene; si no, el idioma predeterminado | El idioma predeterminado |
| Un código con distinto uso de mayúsculas o separador, como `pt_BR` | `pt-BR` | El idioma predeterminado | `pt-BR` |
| Un código regional, como `pt-BR` | El idioma sin región, como `pt` | El idioma predeterminado | `pt` |
| Un código regional que implica un script, como `zh-TW` | El script, como `zh-hant` | El idioma predeterminado | `zh-hant`; en paywalls del antiguo Paywall Builder, el idioma predeterminado |
| Varios idiomas, como `fr` y luego `de` | Un idioma posterior, como `de`, pero no el primero | El idioma predeterminado | El idioma posterior; en paywalls del antiguo Paywall Builder, el idioma predeterminado |

Las versiones de la app con SDK 4.0–4.4 mantienen la coincidencia exacta con tus flows hasta que los usuarios actualicen la app. La estrategia `Legacy` no recupera la coincidencia exacta de la versión 4.4.

Para ver qué localización aparece en un dispositivo, establece el [nivel de registro](sdk-installation-android#logging) en `AdaptyLogLevel.VERBOSE` y busca la línea `getFlowConfiguration` en Logcat. Para un procedimiento de prueba, consulta [Probar qué localización ve un usuario](android-localizations-and-locale-codes#test-which-localization-a-user-sees).

## Revisa los idiomas de tus flows \{#review-the-locales-of-your-flows\}

SDK 4.5 muestra tus flows publicados con sus idiomas actuales. Para mostrar a los usuarios cada flow en su idioma, sigue estas tres reglas:

- Traduce el locale predeterminado por completo. Los usuarios lo ven cuando el flow no tiene ninguno de sus idiomas. Para verlo o cambiarlo, consulta [Establecer el locale predeterminado](add-paywall-locale-in-adapty-paywall-builder#set-the-default-locale).
- Para apps con cualquier versión del SDK de Adapty del 4.0 al 4.4, mantén todos los códigos de locale que envían. Esas apps hacen una coincidencia exacta del código.
- Para cubrir más usuarios, añade [los locales que 4.5 detecta mejor](android-localizations-and-locale-codes#select-which-locales-to-add-to-a-flow), como `zh-hans` y `zh-hant` además de `zh`.
