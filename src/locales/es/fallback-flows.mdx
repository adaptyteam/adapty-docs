Para mantener una experiencia de usuario fluida, es importante configurar **versiones de respaldo** de tus [flows](adapty-flow-builder).

Cuando tu aplicación solicita un flow, el SDK de Adapty contacta con nuestros servidores para obtener su configuración. Si el SDK no puede obtener el flow desde la API principal de Adapty (problema de red, caída del servidor), recurre a otras fuentes:

- Si el usuario ya ha visto el flow antes, el SDK sirve la copia en caché.
- Si la API principal de Adapty no responde, el SDK solicita el flow a un servidor de respaldo de Adapty.
- Si ninguna de las dos opciones funciona, el SDK carga un archivo de configuración de respaldo incluido en la app.

:::important
El servidor de respaldo y el archivo de respaldo solo sirven a la audiencia **All Users** e ignoran los segmentos. Si divides las audiencias por plataforma, usa productos con IDs tanto de App Store como de Google Play en el flow de All Users. De lo contrario, el flow de respaldo no tendrá productos para los usuarios de la otra store.
:::

Adapty genera automáticamente estos archivos de respaldo. El bundle de respaldo del flow se comparte con los paywalls: un único archivo JSON por plataforma contiene las variaciones de respaldo para ambos. El SDK lee la sección que necesita.

:::important
Los fallbacks de flow se incluyen en el paquete del **SDK de Adapty 4.0+**. Si seleccionas una versión anterior del SDK en el diálogo de descarga, el archivo solo contiene variaciones de paywall y onboarding, sin flows. Asegúrate de que tu app use una versión del SDK compatible con flows antes de depender de un flow de respaldo.
:::

## Antes de empezar \{#before-you-start\}

1. Crea un [flow](adapty-flow-builder) en el Flow & Paywall Builder.
2. [Crea un placement](create-placement) para el flow.

## Descargar el archivo de respaldo \{#download-the-fallback-file\}

1. Abre la página **[Placements](https://app.adapty.io/placements)**.
2. Haz clic en el botón **Fallbacks** en la parte superior derecha.
3. Selecciona tu plataforma de destino en el desplegable.
4. Selecciona la opción que coincida con la versión del SDK de Adapty de tu app, por ejemplo, **Adapty SDK v4.4.0 and higher**.

El navegador descarga un archivo JSON por plataforma; por ejemplo, `ios_4_0_0_fallback.json`.

:::tip
Para descargar el archivo desde la terminal, usa el [CLI para desarrolladores](developer-cli). Indica la versión del SDK de Adapty con la que está compilada tu app:

```bash
adapty fallbacks get --app <app-id> --platform ios --sdk-version <sdk-version> --output ios_fallback.json
```

Ejecútalo una vez por store, con `--platform ios` o `--platform android`. Consulta [`adapty fallbacks get`](developer-cli-fallbacks) para ver los flags.
:::

## Después de la descarga \{#after-the-download\}

Añade el archivo al código de tu app y sigue la guía de configuración específica de cada plataforma. Las mismas APIs que cargan los paywall de respaldo también cargan los flow de respaldo una vez que tu app esté en una versión del SDK compatible con flows:

- [iOS](ios-use-fallback-paywalls)
- [Android](android-use-fallback-paywalls)
- [React Native](react-native-use-fallback-paywalls)
- [Flutter](flutter-use-fallback-paywalls)
- [Unity](unity-use-fallback-paywalls)
- [Kotlin Multiplatform](kmp-use-fallback-paywalls)
- [Capacitor](capacitor-use-fallback-paywalls)

## Limitaciones \{#limitations\}

Los flows de respaldo están codificados y almacenados localmente, por lo que no cuentan con todas las capacidades dinámicas de los flows en vivo:

- **Una variación por placement.** Si un placement tiene más de un flow (distintas audiencias, variantes de prueba A/B), el archivo de respaldo usa la audiencia **All Users** y la variación con mayor peso en ella.
- **Sin pruebas A/B.** Una prueba A/B de flow en producción se resuelve en el servidor; el respaldo siempre sirve una única variación seleccionada.
- **Sin actualizaciones remotas.** Actualizar el respaldo requiere publicar una nueva versión de la app. Para las actualizaciones en tiempo de ejecución que harías normalmente mediante Remote Config, utiliza en su lugar el flow en producción.
