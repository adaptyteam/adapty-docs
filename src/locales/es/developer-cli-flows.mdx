Los [flows](adapty-flow-builder) son los paywalls y onboardings que construyes en el Flow & Paywall Builder. El CLI gestiona el registro del flow, su configuración del builder y la publicación. Una configuración del builder es un documento JSON extenso que normalmente genera el Flow & Paywall Builder; el CLI no la genera por sí solo. Para crear o editar una configuración desde la terminal, usa el [skill flow-generator](flow-generator-skill), que ejecuta estos comandos por ti. Antes de publicar, el [skill flow-audit](flow-audit-skill) comprueba si el flow está listo para producción. Los comandos `flows metrics` leen los datos de la página de [métricas de flows](flow-metrics) y requieren la versión 0.15.0 o posterior del CLI. Los comandos se incluyen aquí como referencia.

## adapty flows list \{#adapty-flows-list\}

Lista todos los flows de una aplicación.

```bash
adapty flows list --app <app-id>
```

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

Acepta [flags de paginación](developer-cli-reference#global-flags).

## adapty flows get

Obtén los detalles de un flow específico.

```bash
adapty flows get --app <app-id> <flow-id>
```

| Argument | Description |
|---|---|
| `flow-id` | Flow ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

La respuesta contiene `id`, `name`, `status` y `updated_at`. El status es uno de los siguientes:

| Estado | Significado |
|---|---|
| `draft` | El flow nunca ha sido publicado |
| `published` | La versión actual está activa |
| `dirty` | El flow fue publicado anteriormente y la versión actual tiene cambios sin publicar. Los usuarios siguen viendo la última versión publicada |
| `publishing` | La publicación está en curso |
| `publication_failed` | La última publicación falló. Corrige la configuración y vuelve a publicar |
| `archived` | El flow está archivado |

## adapty flows create

Crea un flow. El nuevo flow tiene un nombre y sin configuración. Para añadir una configuración, usa [`flows config update`](#adapty-flows-config-update).

```bash
adapty flows create --app <app-id> --name "Onboarding"
```

| Flag | Obligatorio | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |
| `--name` | Sí | Nombre del flow |

## adapty flows update

Renombra un flow.

```bash
adapty flows update --app <app-id> <flow-id> --name "Onboarding v2"
```

| Argument | Description |
|---|---|
| `flow-id` | ID del flow (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | ID de la app (UUID) |
| `--name` | Yes | Nuevo nombre del flow |

## adapty flows publish

Publica la versión actual de un flow para tus usuarios.

```bash
adapty flows publish --app <app-id> <flow-id>
```

| Argumento | Descripción |
|---|---|
| `flow-id` | ID del flow (UUID) |

| Flag | Obligatorio | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |
| `--yes`, `-y` | No | Publica sin pedir confirmación. Obligatorio cuando la salida se redirige o se usa `--json` |

Dado que publicar cambia lo que ven tus usuarios, el comando muestra el nombre del flow y pide confirmación. Cualquier respuesta distinta de `y` cancela el comando con código de salida 1. Con `--json` o en una tubería, el comando rechaza con código de salida 2 en lugar de esperar una respuesta, así que usa `--yes` en scripts y sesiones de agentes.

La publicación es asíncrona: la respuesta devuelve `status: publishing` y el flow aún no está activo. Consulta [`flows get`](#adapty-flows-get) hasta que el estado pase a `published` o `publication_failed`. Si ocurre `publication_failed`, [`flows config get`](#adapty-flows-config-get) indica el motivo.

La publicación falla con HTTP 400 cuando el flow no tiene configuración, cuando la configuración no es publicable o cuando la versión actual ya está activa. Para validar una configuración antes de publicarla, usa [`flows config validate`](#adapty-flows-config-validate).

## adapty flows config get

Lee la configuración del builder de un flow.

```bash
adapty flows config get --app <app-id> <flow-id>
```

| Argument | Description |
|---|---|
| `flow-id` | Flow ID (UUID) |

| Flag | Required | Description |
|---|---|---|
| `--app` | Yes | App ID (UUID) |

La respuesta contiene `config`, `remote_configs`, `status` y `updated_at`. `updated_at` es una marca de tiempo en milisegundos del último cambio de configuración. Pásala a [`flows config update`](#adapty-flows-config-update) como `--expected-updated-at` para evitar sobreescribir una edición concurrente. Un flow cuya configuración nunca se ha escrito devuelve 404.

Tras un intento de publicación, la respuesta también incluye tres campos que describen cómo fue. Léelos cuando [`flows get`](#adapty-flows-get) indique `publication_failed`:

| Campo | Descripción |
|---|---|
| `publication_status` | El estado de publicación de esta versión del flow: `transforming`, `transformed`, `uploading`, `uploaded`, `published` o `failed` |
| `transform_error` | El error de transformación sin procesar: puede ser un payload JSON con los problemas o una cadena de resumen |
| `publication_error` | Un mensaje legible para una publicación fallida |

## adapty flows config update

Escribe la configuración del builder de un flow.

```bash
adapty flows config update --app <app-id> <flow-id> --config-file config.json
```

| Argument | Description |
|---|---|
| `flow-id` | ID del flow (UUID) |

| Indicador | Requerido | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |
| `--config` | Uno de los dos | Configuración del Builder como cadena JSON |
| `--config-file` | Uno de los dos | Ruta a un archivo JSON con la configuración del Builder, o `-` para leer desde stdin |
| `--remote-configs` | No | Array JSON de entradas `{locale, data}`, donde `data` es el Remote Config como cadena |
| `--expected-updated-at` | No | El valor `updated_at` de un `flows config get` anterior. Si la configuración cambió después de esa lectura, el comando falla en lugar de sobrescribir el cambio. Omítelo para sobrescribir sin condiciones |

Al escribir la configuración se guarda un borrador sin publicarlo. En un flow publicado, la escritura crea una nueva versión: el estado del flow pasa a `dirty`, y los usuarios siguen viendo la versión publicada hasta que ejecutes [`flows publish`](#adapty-flows-publish).

## adapty flows config validate

Comprueba si una configuración del builder es publicable, sin guardarla.

```bash
adapty flows config validate --app <app-id> <flow-id> --config-file config.json
```

| Argumento | Descripción |
|---|---|
| `flow-id` | ID del flow (UUID) |

| Flag | Requerido | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |
| `--config` | Una de las dos | Configuración del builder como cadena JSON |
| `--config-file` | Una de las dos | Ruta a un archivo JSON con la configuración del builder, o `-` para leer desde stdin |

La respuesta contiene `valid` y una lista de `issues`. Cuando la configuración no es publicable, el comando termina con el código 1, por lo que los scripts pueden usarlo como condición de bloqueo.

## adapty flows config preview

Renderiza un archivo de configuración local en el navegador. Este comando no realiza ninguna llamada a la API y no acepta el flag `--app`.

```bash
adapty flows config preview ./config.json --screen <screen-id> --device iphone-14 --orientation portrait
```

| Argumento | Descripción |
|---|---|
| `config-file` | Ruta a un archivo JSON de configuración del builder local |

| Flag | Por defecto | Descripción |
|---|---|---|
| `--screen` | La primera pantalla del flow | ID de pantalla a renderizar |
| `--device` | `iphone-14` | Marco de dispositivo en el que renderizar |
| `--orientation` | `portrait` | `portrait` o `landscape` |

En la terminal, el comando abre la vista previa en tu navegador. Cuando se usa con pipes o con `--json`, imprime la URL en su lugar. La URL contiene toda la configuración y es larga: pásala por un pipe a una herramienta de capturas de pantalla en lugar de imprimirla. Las configuraciones de más de 32 KB aproximadamente se renderizan lentamente.

## adapty flows media upload

Sube una imagen para usarla en la configuración de un flow.

```bash
adapty flows media upload --app <app-id> ./hero.png
```

| Argumento | Descripción |
|---|---|
| `file` | Ruta al archivo de imagen |

| Flag | Obligatorio | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |

Formatos aceptados: GIF, HEIC, JPEG, PNG, SVG y WebP. La respuesta contiene el `id`, el `name` y la `url` del CDN de la imagen para referenciarla desde la configuración.

## adapty flows metrics list \{#adapty-flows-metrics-list\}

Muestra las métricas de por vida de varios flows, una línea por cada flow. Estos son los datos de la tabla de flows en el dashboard.

```bash
adapty flows metrics list --app <app-id> --ids <flow-id>,<flow-id>
```

| Flag | Obligatorio | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |
| `--ids` | Sí | IDs de los flows (UUIDs). Sepáralos con comas o repite el flag |
| `--csv` | No | Imprime CSV: una fila por cada flow, con el ID del flow y las 27 métricas. No se puede usar con `--json` |

Cada línea muestra el ID del flow con sus visualizaciones, compras, pruebas y revenue. `--json` y `--csv` incluyen las 27 métricas de la página de [métricas de flow](flow-metrics#metrics-definitions), como `unique_profiles_views`, `net_revenue` y `conversion_rate_purchases`. Una métrica sin datos es `0`, nunca `null`.

## Valores de métricas de flows de Adapty \{#adapty-flows-metrics-values\}

Lista las claves y valores de filtro de un flow: lo que acepta [`flows metrics get --filter`](#filter-the-metrics).

```bash
adapty flows metrics values --app <app-id> <flow-id>
```

| Argumento | Descripción |
|---|---|
| `flow-id` | ID del flow (UUID) |

| Flag | Requerido | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |

Cada línea muestra una etiqueta y, entre paréntesis, el valor a pasar. Los valores están anidados tal como los filtros del dashboard los anidan:

```text
Country (country)
  Americas (Americas)
    United States (US)
  Europe (Europe)
    Germany (DE)
Store (store)
  App Store (app_store)
  Google Play (play_store)
```

El valor superior de cada grupo es la clave del filtro, y los valores más internos son los que acepta esa clave. En el ejemplo, `--filter country=US` mantiene Estados Unidos, y `--filter store=play_store` mantiene Google Play.

## adapty flows metrics get \{#adapty-flows-metrics-get\}

Muestra las métricas de un flow para un período, como el árbol de la página de [métricas de flow](flow-metrics).

```bash
adapty flows metrics get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 --date-type purchase_date --based-on placement
```

| Argumento | Descripción |
|---|---|
| `flow-id` | ID del flow (UUID) |

| Flag | Requerido | Descripción |
|---|---|---|
| `--app` | Sí | ID de la app (UUID) |
| `--based-on` | Sí | Por qué se divide el primer nivel del árbol: `placement` o `audience`. Corresponden a las vistas basadas en placement y en audiencia de la página de [métricas de flow](flow-metrics#view-options-for-metrics-data) |
| `--date-type` | Sí | A qué fecha se aplica el período: `purchase_date` o `profile_install_date` para [filtrar por fecha de instalación](flow-metrics#filter-metrics-by-install-date) |
| `--date-from` | No | Primer día del período, inclusive (`YYYY-MM-DD`). Úsalo junto con `--date-to` |
| `--date-to` | No | Último día del período, inclusive (`YYYY-MM-DD`). Úsalo junto con `--date-from` |
| `--granularity` | No | Divide el período en puntos: `day`, `week`, `month`, `quarter` o `year` |
| `--filter` | No | Muestra solo los datos con estos valores de una clave de filtro. Se puede repetir. Ver [Filtrar las métricas](#filter-the-metrics) |
| `--timezone` | No | Zona horaria IANA de los puntos del período, por ejemplo `Europe/Berlin`. Sin este parámetro, Adapty usa la zona horaria de la app |
| `--depth` | No | Cuántos niveles del árbol se muestran bajo `Total`. Por defecto: `1` |
| `--csv` | No | Imprime CSV: una fila por cada nodo del árbol completo. No se puede usar con `--json` |

El CLI termina con código 2 y no envía ninguna solicitud cuando falta `--based-on` o `--date-type`, o cuando solo se proporciona un extremo del período. Adapty valida los valores de `--based-on`, `--date-type` y `--granularity`: un valor incorrecto termina con código 4, y el error lista los valores aceptados.

### Lee el resultado \{#read-the-output\}

El comando imprime una línea `Total` y, a continuación, el primer nivel del árbol. Cada línea muestra vistas, compras, trials y revenue. Con `--granularity`, los puntos del período aparecen justo debajo de su nodo:

```text
Total           views 19  purchases 7  trials 4  revenue 241.93
  Onboarding    views 10  purchases 7  trials 0  revenue 241.93
    2026-09-01  views  0  purchases 0  trials 0  revenue   0.00
    2026-10-01  views 10  purchases 0  trials 0  revenue 241.93
  Settings      views  0  purchases 0  trials 0  revenue   0.00
```

Los niveles del árbol son los niveles del dashboard: placement, audiencia, prueba A/B, variante de flow, pantalla y producto. Con `--based-on audience`, el nivel de placement se omite. Para mostrar más niveles, usa `--depth`, por ejemplo `--depth 3`.

Para el árbol completo con las 27 métricas, utiliza uno de estos flags:

- `--json` imprime la respuesta del servidor sin modificaciones.
- `--csv` imprime una fila por cada nodo, incluidos los puntos de período. Las columnas son `path` (los títulos desde `Total` hasta el nodo, separados por ` > `), `level`, `title` y luego las métricas.

### Filtrar las métricas \{#filter-the-metrics\}

Escribe cada `--filter` como `key=value`, con las claves y valores que lista [`flows metrics values`](#adapty-flows-metrics-values). Para conservar varios valores a la vez, sepáralos con comas o repite el flag con la misma clave. Los filtros con claves distintas se combinan, por lo que los datos deben cumplir todos ellos:

```bash
adapty flows metrics get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 \
  --date-type purchase_date --based-on placement --filter country=US,DE --filter store=app_store
```

La CLI envía cada valor exactamente como está escrito. Para incluir una coma dentro de un valor, escribe `\,`. Un valor vacío también es un valor: `attribution_channel=` conserva los datos sin canal, que `flows metrics values` muestra como **No Data**.
