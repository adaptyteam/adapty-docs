Adapty Mail 从您自己的域名发送营销活动，而非使用共享地址，因此发件人声誉始终由您掌控。只需验证一个域名即可开始发送，每个项目最多可添加五个域名。如需了解最简配置步骤，请参阅[开始使用 Adapty Mail](mail-get-started#2-set-up-your-sending-domain) 中的域名配置部分。本文涵盖完整配置流程、验证机制说明、自动预热行为，以及使用多个域名发送时的注意事项。

## 要求 \{#requirements\}

- **顶级域名**：填写您的根域名（例如 `yourapp.com`），不能填写子域名。`app.yourapp.com` 这类格式在验证时会被拒绝。Adapty Mail 会将发送主机创建为其子域名。
- **有效的 NS 记录**：域名必须能正常解析。Adapty Mail 在设置过程中会进行 DNS 查询，拒绝没有有效 NS 记录的域名。
- **每个项目一个域名**：域名不能在项目之间共享。如果某个域名已被任何项目注册（无论是您的项目还是其他人的），设置将会失败。
- **每个项目最多五个域名**：每个域名均独立完成验证和预热。

## 添加发送域名 \{#add-a-sending-domain\}

域名设置位于 **Settings → DNS** 的 **Email domains** 部分。

1. 要注册域名，请点击 **Add domain**。
2. 在 **Domain** 字段中，输入你的顶级域名，例如 `yourapp.com`。
3. 在 **Sending subdomain** 字段中，输入发送邮件所使用的前缀，或留空以使用 `mail`。字段下方的提示会显示最终的主机名：*Emails will be sent from mail.yourapp.com*。
4. 点击 **Add domain**。Adapty Mail 会验证输入、注册域名，并为其添加一张包含所有所需 DNS 记录的卡片。

<ZoomImage id="mail-email-domains.webp" width="500px" alt="Add domain form with Domain and Sending subdomain fields" />

5. 将卡片上的所有记录按原样添加到您的域名注册商的 DNS 中。卡片按用途对记录进行了分组——[您需要添加哪些记录](#which-records-you-add)详细介绍了每个分组及哪些记录是必填的。如需一次性导出全部记录，点击 **Export** 并选择 **CSV**、**GoDaddy zone file** 或 **Cloudflare zone file**。
6. 点击 **Check** 立即验证，或直接离开该卡片——Adapty Mail 会自动轮询 DNS。

<ZoomImage id="email-domains.webp" width="700px" alt="展开的域名卡片，显示 DNS 记录组和验证进度" />

卡片标题中的计数器和圆环会追踪已通过验证的必填记录数量，只有所有记录全部解析完成后才会填满。

### 选择发送子域名 \{#choosing-the-sending-subdomain\}

该前缀会成为每位收件人看到的发件人地址的一部分，因此 Adapty Mail 在注册域名之前会验证该标签：

- 使用小写字母、数字和连字符，不得以连字符开头或结尾，最多 63 个字符。
- `www`、`smtp`、`admin`、`api`、`mx` 和 `dkim` 为保留标签。
- 带有冒犯性内容或仿冒知名品牌的标签（例如 `paypal`）会被拒绝。常见营销词汇（如 `news`、`offers`、`hello`）则可正常使用。
- 域名注册后，前缀将固定不变。如需从其他主机发送邮件，请删除该域名后重新添加，或添加第二个域名。

## 添加哪些记录 \{#which-records-you-add\}

卡片将记录分为三组列出，根域名上还有一条可选记录。本节中的名称均以域名 `yourapp.com` 和默认前缀 `mail` 为例。

| 分组 | 记录 | 功能说明 |
| --- | --- | --- |
| `mail.yourapp.com` 上的**发送基础设施** | 3 条 DKIM CNAME，以及 `hello.mail.yourapp.com` 上的 MX 和 SPF TXT | 为你的营销活动签名，并将退信路由回 Adapty Mail |
| `mail.yourapp.com` 上的**预热邮箱** | DKIM CNAME、MX、域名验证 TXT、SPF TXT，以及 `_dmarc.mail.yourapp.com` 上的 DMARC TXT | 运行邮箱，在[预热](#domain-warm-up)期间建立你的发件人声誉 |
| `go.yourapp.com` 上的**媒体与重定向** | 主机 CNAME、`_cf-custom-hostname.go.yourapp.com` 所有权 TXT，以及 `_acme-challenge.go.yourapp.com` CNAME | 通过你自己的域名为邮件中的图片和追踪链接提供服务 |
| `yourapp.com` 上的 **DMARC 策略**（可选） | `_dmarc.yourapp.com` 上的一条 TXT 记录 | 告知收件方提供商如何处理未通过身份验证的邮件 |

前三组中的每条记录都是必填项，包括 `go.yourapp.com` 上的记录——只要该主机未完成验证，设置就处于未完成状态。根域名上的 DMARC 记录属于建议项，不计入卡片的进度。

所有身份验证记录均位于发送子域名下，因此根域名上为常规业务邮件已配置的 SPF 和 DMARC 记录不会受到任何影响。

<Details>
<summary>DNS 记录参考</summary>

**DKIM — 3 条 CNAME 记录。** 加密签名，用于证明邮件在传输过程中未被篡改。

| 字段 | 格式                              |
| ---- | --------------------------------- |
| 类型 | CNAME                             |
| 名称 | `{token}._domainkey.mail.yourapp.com` |
| 值   | `{token}.dkim.amazonses.com`      |

**MAIL FROM — 1 条 MX 记录。** 用于处理退信。

| 字段 | 格式 |
| -------- | -------------------------------------------------------- |
| Type     | MX                                                       |
| Name     | `hello.mail.yourapp.com`                                 |
| Priority | `10`                                                     |
| Value    | `feedback-smtp.{region}.amazonses.com`                   |

**MAIL FROM — 1 条 TXT 记录。** 授权 Adapty 代表您发送邮件。

| Field | Format                                 |
| ----- | -------------------------------------- |
| Type  | TXT                                    |
| Name  | `hello.mail.yourapp.com`               |
| Value | `"v=spf1 include:amazonses.com ~all"`  |

**DMARC — 根域名上的 1 条 TXT 记录。** 可选，推荐配置。

| Field | Format                |
| ----- | --------------------- |
| Type  | TXT                   |
| Name  | `_dmarc.yourapp.com`  |
| Value | `v=DMARC1; p=reject`  |

## 验证流程说明 \{#how-verification-works\}

记录配置完成后，Adapty Mail 会自动轮询 DNS，你也可以手动触发检查。

- **自动轮询**：添加域名后 1 分钟进行首次检查，之后间隔时间翻倍——2、4、8 分钟依次递增——最终稳定为每小时一次。轮询持续进行，直到记录解析成功或 7 天时间窗口关闭。
- **手动检查**：点击 **Check** 立即执行一次检查。两次手动检查之间有 10 秒冷却时间；操作过于频繁时，看板会提示 *"Please wait before checking again"*。
- **逐条记录结果**：每条记录都会与实时 DNS 进行比对，仅当返回结果与 Adapty Mail 签发的值一致时，才会标记为已验证。若记录已存在但值不匹配，与记录缺失一样，不会通过验证。
- **7 天截止期限**：如果验证未在 7 天内完成，该域名将被标记为失败。您的 DNS 记录仍保留在注册商处——请在 **Settings → DNS** 中重新添加域名，以开启新的验证窗口。
- **验证通过后**：若您后续删除或修改了这些记录，邮件服务提供商最终会降级该域名。请在计划发送邮件期间保持记录不变。
- **DNS 传播**：通常需要几分钟，极少数情况下最长可达 48 小时。

## 设置发件人名称 \{#set-the-sender-name\}

域名验证完成后，该域名的卡片会出现 **Email sender name** 字段。Adapty Mail 会以你的项目名称填充该字段，并从发送子域名的 `hello@` 地址发信，因此字段提示中会显示完整的发件人信息——*Your Company &lt;hello@mail.yourapp.com&gt;*。该名称按域名设置：若项目使用两个域名发送邮件，则需分别配置。

## 域名预热 \{#domain-warm-up\}

新域名在 Gmail 或 Yahoo 等邮件服务商那里没有任何信誉，因此从全新域名大量发送邮件容易进入垃圾邮件文件夹。Adapty Mail 会自动对每个域名进行预热，同时采用两种并行方式，无需任何配置。

**预热邮箱。** DNS 验证通过后，Adapty Mail 会在你的发送子域名上创建一个邮箱，并将其交给预热服务，由该服务从此邮箱发送普通的对话邮件。域名卡片会显示邮箱当前处于哪个预热阶段。预热流量需要预热组的 MX、DKIM 和 SPF 记录：只要其中任意一条未通过验证，卡片就会显示 *Awaiting DNS record verification*，且预热不会进行。

**每日发送上限逐步提升。** 你的推广活动与预热邮箱独立计量，共分 20 个档位。

### 层级如何运作 \{#how-tiers-work\}

您的域名从 **第 1 层**（每日发送 100 封）开始，每次自动升级一个层级。当域名的当日配额耗尽后，即可晋升至下一层级——实际发送量和因限流而未成功的尝试次数均计入配额——更高的限额将于次日生效。在某个层级的第一天，配额会在全天内逐步释放，而非一次性全部放开。晋升仅由发送量驱动，且层级只升不降：不会自动回退。超过最后一个层级后，该域名发送将不再受每日限额限制。

## 从多个域名发送 \{#send-from-more-than-one-domain\}

每个域名都有各自的等级、配额和信誉，因此添加第二个域名可以提高项目每天的发送上限。

要添加域名，请前往 **Settings → DNS**，在 **Email domains** 列表末尾（最后一个域名记录的下方）点击 **Add domain**。后续步骤与[添加第一个域名](#add-a-sending-domain)完全相同：选择域名及其发送子域名，添加系统列出的记录，然后完成验证。新域名从第一级开始，自行逐级提升，而已验证的域名仍按当前限额正常发送。

当有邮件需要发送时，Adapty Mail 会按顺序遍历项目中的所有域名，并从第一个仍有余量的域名发出：

- **最新优先。** 后添加的域名优先于较早添加的域名。
- **每个活动每位收件人只用一个域名。** 在一次活动中，第一个向某位收件人发送邮件的域名将持续负责向其发送该活动的所有邮件，确保序列中途 From 地址保持不变。此配对规则优先级高于上述顺序规则：邮件只会从已记录的域名发出，若该域名已超出配额，该邮件将被丢弃，即使其他域名仍有余量。
- **2026 年 7 月 23 日之前的用户画像将保留在您最早添加的域名上** — 即他们已经看到的 From 地址。
- **被丢弃的邮件视为退订，不会重试。** 只有当所有候选域名均超出每日发送上限时，该邮件才会被丢弃，这将取消该收件人的序列，并以限流原因退订该用户画像。详见[退订管理](mail-suppression)。

## 限制 \{#limitations\}
- **每个域名只能有一个发送前缀**：注册域名时选定，之后无法更改。
- **仅支持顶级域名**：子域名输入、末尾带点的域名以及单标签主机名均不被接受。
- **不支持国际化域名**：Punycode 和 IDN 均不受支持，域名必须为纯 ASCII 格式。
- **删除操作不可撤销**：从该域名发送邮件将立即停止，验证进度将被清除，预热邮箱及其积累的信誉也将一并消失。DNS 记录仍保留在您的域名注册商处——请自行手动删除。
- **跨项目唯一性**：已注册到其他项目的域名无法复用。如果您看到 *"Domain is already registered to another project"*，请选择其他域名或联系支持团队。

## 故障排查 \{#troubleshooting\}
| 问题 | 解决方案 |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| "Enter a valid domain (e.g. example.com)" | 检查输入内容：仅允许顶级域名（apex），仅限 ASCII 字符，顶级域名须包含 2 个以上字符，且首尾不得有连字符。 |
| "Domain does not have valid DNS records" | 顶级域名本身必须能够解析。请在重试前确认您的 NS 记录已生效。 |
| "Domain is already registered to another project" | 请选择其他域名，或如您认为该注册有误，请联系支持团队。 |
| "This subdomain cannot be used" | 该标签已被保留或未通过审核。请另选一个——参见[选择发送子域名](#choosing-the-sending-subdomain)。 |
| "Please wait before checking again" | 手动检查之间请等待 10 秒。后台自动轮询仍在继续。 |
| 记录始终未通过验证 | 请仔细核对记录是否完全匹配——无尾随点、CNAME 目标正确、每条记录仅含一个值。DNS 传播最长可能需要 48 小时。 |
| 预热状态显示"Awaiting DNS record verification" | 预热邮箱的 MX、DKIM 和 SPF 记录尚未通过验证。请添加或更正这些记录，然后点击 **Check**。 |
| `go.` 分组无法变为绿色 | 卡片中会在主机名下方显示原因。请确认其 CNAME 和 TXT 记录是否正确，然后点击 **Check**——在该主机激活之前，域名设置不算完成。 |
| "Cannot delete: some identities are verified" | 该域名是在自动预热功能上线前完成配置的，无法从看板中删除。请联系支持团队。 |
| 邮件被归入垃圾邮件 | 确认已发布 DMARC 记录。新域名需要经过预热——请查阅[域名预热](#domain-warm-up)。 |
| 退信率过高 | 请确认您的受众列表中包含有效且已选择接收邮件的地址。有关退信地址的处理方式，请参见[退信抑制](mail-suppression)。 |
