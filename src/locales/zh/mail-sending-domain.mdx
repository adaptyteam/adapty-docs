Adapty Mail 从您自己的域名发送营销活动，而非使用共享地址，因此发件人信誉完全由您掌控。只需验证一个域名即可开始发送，一个项目最多可添加五个域名。

如需以最少步骤完成域名验证，请参阅 [Adapty Mail 入门指南](mail-get-started#4-set-up-your-sending-domain)。本文是完整参考文档，涵盖设置、验证、预热以及使用多个域名发送的内容。

## 要求与限制 \{#requirements-and-limitations\}

- **根域名**：请填写您的根域名，必须带有顶级域名后缀（`yourapp.com`）。Adapty Mail 不接受子域名（`app.yourapp.com`）或带有二级后缀的域名（`yourapp.co.uk`、`yourapp.com.br`）。
- **仅限 ASCII**：不支持 Punycode 和国际化域名。
- **有效的 NS 记录**：域名必须可以正常解析。Adapty Mail 在设置过程中会进行 DNS 查询，无有效 NS 记录的域名将被拒绝。
- **每个项目仅限一个域名**：域名不能在多个项目之间共用。如果某个项目（无论是您的还是他人的）已使用该域名，设置将失败。
- **域名需与您的品牌相符**：域名必须能被识别为您的应用。`yourapp.com` 对于名为 Yourapp 的应用是合适的；与之无关的 `anotherapp.com` 则不行。Adapty 会参考您的[品牌](mail-brand)应用名称、描述和标语进行判断。若项目未设置品牌信息，则跳过此项检查。
- **域名信誉良好**：Adapty Mail 会拒绝被 [Blacklist Master](https://www.blacklistmaster.com/) 标记为垃圾邮件黑名单的域名。
- **每个项目最多五个域名**：每个域名单独进行验证和预热。
- **删除操作不可撤销**：删除后发送立即停止，域名的验证进度、DNS 记录和预热邮箱也将一并移除。您可以重新添加该域名，但需要从头开始验证并生成新记录。该域名在过去 30 天内通过营销活动发送的邮件仍会计入[送达率评分](mail-domain-health)。如果您保留相同的发送子域名，其每日发送上限将延续保留。您自己的 DNS 记录不会被自动清除，请手动删除。

## 1. 添加域名 \{#1-add-the-domain\}

在 Adapty Mail 中，依次打开 **Settings** > **DNS**，进入 **Email domains** 部分。

1. 在 **Domain** 字段中，输入你的根域名，例如 `yourapp.com`。
2. 在 **Sending subdomain** 字段中，指定用于发送邮件的子域名。留空则默认使用 `mail`。字段下方的提示会预览完整的主机名：*Emails will be sent from mail.yourapp.com*。
3. 在 **Link subdomain** 字段中，为邮件中的链接和图片指定*另一个子域名*。留空则默认使用 `go`。提示同样会显示该主机名：*Links and images in emails will be served from go.yourapp.com*。
4. 点击 **Add domain**。Adapty Mail 会验证输入内容，将域名添加到你的项目，并显示一张包含该域名所需全部 DNS 记录的卡片。

   <ZoomImage id="mail-email-domains.webp" width="500px" alt="包含域名、发送子域名和链接子域名字段的添加域名表单" />

5. 可选操作：[添加更多域名](#multiple-domains)，以提高每日可发送的邮件数量。

### 使用自定义子域名 \{#use-custom-subdomains\}

发送前缀会出现在每位收件人看到的发件人地址中，链接前缀则会出现在他们点击的每个链接里。大多数项目保持默认设置即可；如果你要自定义，两个字段遵循相同的规则：

- 使用小写字母、数字和连字符，不得以连字符开头或结尾，最多 63 个字符。
- `www`、`smtp`、`admin`、`api`、`mx` 和 `dkim` 为保留字。
- 冒犯性标签以及冒充知名品牌的标签（例如 `paypal`）将被拒绝。`news`、`offers`、`hello` 等普通营销词汇可以通过。
- 两个前缀不能相同。
- 域名添加后，两个前缀即固定不变。如需从其他主机发送，请删除该域名后重新添加，或添加第二个域名。

## 2. 添加 DNS 记录 \{#add-the-dns-records\}

将卡片上的每条记录按原样添加到您的 DNS 中。如需一次性导出全部记录，点击 **Export**，选择 **CSV**、**GoDaddy zone file**、**Cloudflare zone file** 或 **Route 53 zone file**。

:::warning
**在 Cloudflare 上，每条 CNAME 必须设置为"仅 DNS"模式** —— 启用代理后，记录会解析到 Cloudflare 的地址，导致验证始终无法通过。使用 **Cloudflare zone file** 导出时会自动为您完成此设置。
:::

:::tip
连接到 [Adapty Mail MCP 服务器](mail-mcp) 的 AI 助手可以读取这些记录，引导你在 DNS 提供商处发布它们，并自动重新验证。
:::

前三个部分是必填项——在记录解析成功之前，设置尚未完成。根域名上的 DMARC 记录是可选的。

| 功能区块 | 主机 | 作用 |
| --- | --- | --- |
| **发件基础设施** | 发件子域名 | 为您的营销活动签名并将退信路由回 Adapty Mail |
| **预热邮箱** | 发件子域名 | 运行邮箱以在[预热](#warm-up-and-daily-limits)期间建立您的发件人信誉 |
| **媒体与重定向** | 链接子域名 | 通过您自己的域名提供邮件中的图片和追踪链接 |
| **DMARC 策略**（可选） | 根域名 | 告知接收方如何处理未通过身份验证的邮件 |

如果您的根域名已经为企业邮箱配置了 SPF 和 DMARC 记录，这些记录无需改动——所有必要的记录都添加在子域名上。

<Details>
<summary>DNS 记录参考</summary>

**DKIM — 3 条 CNAME 记录。** 用于验证邮件在传输过程中未被篡改的加密签名。

| 字段 | 格式                              |
| ----- | ----------------------------------- |
| 类型  | CNAME                               |
| 名称  | `{token}._domainkey.mail.yourapp.com` |
| 值 | `{token}.dkim.amazonses.com`        |

**MAIL FROM — 1 条 MX 记录。** 用于处理退信。

| 字段 | 格式 |
| -------- | -------------------------------------------------------- |
| Type     | MX                                                       |
| Name     | `hello.mail.yourapp.com`                                 |
| Priority | `10`                                                     |
| Value    | `feedback-smtp.{region}.amazonses.com`                   |

**MAIL FROM — 1 条 TXT 记录。** 授权 Adapty 代表您发送邮件。

| Field | Format                                 |
| ----- | -------------------------------------- |
| Type  | TXT                                    |
| Name  | `hello.mail.yourapp.com`               |
| Value | `"v=spf1 include:amazonses.com ~all"`  |

**DMARC — 在根域名上添加 1 条 TXT 记录。** 可选，但建议配置。

| Field | Format                |
| ----- | --------------------- |
| Type  | TXT                   |
| Name  | `_dmarc.yourapp.com`  |
| Value | `v=DMARC1; p=reject`  |

预热邮箱和 `go.yourapp.com` 的记录格式相同，其名称和值由 Adapty Mail 使用的邮件及托管服务商生成。令牌、区域、主机名和所有权值均在设置时生成——请从域名卡片或导出文件中复制，切勿从本参考文档中复制。

</Details>

## 3. 验证记录 \{#3-verify-the-records\}

<ZoomImage id="email-domains.webp" width="700px" alt="展开的域名卡片，显示 DNS 记录组和验证进度" />

 DNS 传播通常需要几分钟，极少数情况下最多需要 48 小时。为了验证记录，Adapty Mail 会按固定间隔自动轮询 DNS，直到找到记录或 7 天后停止。点击卡片上的 **Check** 可立即触发一次检查（有 10 秒冷却时间），或在自动检查停止后重新启动。

当记录存在于 DNS 中、其值与 Adapty Mail 提供的值匹配，且服务商已确认时，该记录即通过验证。未通过验证的记录会显示一个标签，说明缺少哪项条件：

| 标签 | 含义 |
| --- | --- |
| **Missing** | DNS 中不存在该记录。请按照卡片上显示的内容添加。 |
| **Wrong value** | 记录已存在，但其值不匹配。请更新为正确的值。 |
| **Differs from suggested** | 您的根域名已有一条 DMARC 记录，但值不同。Adapty Mail 的建议并非强制要求——仅在您希望替换时更新即可。 |
| **Provider check failed** | 提供商拒绝了该记录。请确认记录值后点击 **Check**。 |
| **Awaiting provider** | 该记录在 DNS 中已正确配置，但提供商尚未确认。点击 **Check** 刷新状态。 |

Adapty Mail 不会定期自动检查已验证记录的有效性。如需手动触发检查，请点击 **Check**，或前往 **Settings** > **DNS**。

只要你计划继续发送邮件，就请保留这些记录——一旦 DKIM 记录消失，Amazon SES 将在宽限期结束后停止对邮件签名，届时需要从头重新验证域名。

## 4. 设置发件人名称和回复地址 \{#set-the-sender-name-and-reply-to-address\}

域名验证通过后，其卡片会新增一个 **Email sender name** 字段。Adapty Mail 会自动填入你的项目名称，并从发送子域名的 `hello@` 地址发送邮件，因此该字段的提示会显示完整的发件人行——*Your Company &lt;hello@mail.yourapp.com&gt;*。名称按域名设置：如果一个项目使用两个域名发送邮件，则需要分别设置两个名称。名称中不能包含 `+`、`{` 或 `}`。

要接收收件人的回复，请在同一域名卡片中的 **Reply-to address** 字段输入一个地址，例如 `support@yourapp.com`，然后点击 **Save**。`hello@` 地址是该域名的[预热邮箱](#warm-up-and-daily-limits)，无人查看，因此发送未设置回复地址的邮件时，收件人的回复将无法得到回应。回复地址可以使用任意域名，无需配置 DNS 记录。该设置仅对保存后发送的邮件生效。与发件人名称一样，回复地址按域名分别设置。

## 预热与每日发送限额 \{#warm-up-and-daily-limits\}

新域名在 Gmail 或 Yahoo 等邮件服务商那里没有任何声誉，因此从全新域名大量发送邮件很容易进入垃圾邮件。Adapty Mail 会自动为每个域名完成预热，同时采用两种并行机制，无需任何配置。

- **预热邮箱**：DNS 验证通过后，Adapty Mail 会在您的发送子域上创建一个邮箱。该邮箱会与各大邮件服务商的测试邮箱进行普通的往来通信，让服务商看到该域名在正常收发邮件，从而建立域名信誉。域名卡片会显示邮箱当前所处的阶段。在 [**Warmup mailbox** 记录](#2-add-the-dns-records)通过验证之前，预热不会开始。
- **每日发送上限**：您的营销活动与预热邮箱分开计量，共分为 20 个档位。该上限确保您的发送量不会超过导致新域名被标记为垃圾邮件的阈值，并随着发送量的增加逐步提升。

### 配额等级的工作原理 \{#how-tiers-work\}

您的域名从 **Tier 1**（每日 100 封）开始。当现有的每日限额被超出时，配额等级会逐级提升（已发送和被拦截的尝试均计入，每封邮件只计一次）。更高的限额将于次日生效。

每日配额会在全天均匀分配：任何一个小时内，某个域名最多发送其每日上限的约十六分之一。若某小时内有邮件被暂缓，Adapty Mail 会在后续某小时内补发。事务性邮件最多可使用上限的两倍，流程中的第一封邮件和二次确认订阅请求最多可额外使用 20%，因此在配额紧张时，这些邮件会优先于其他邮件发送。等级晋升仅由发送量驱动，且只升不降：不会自动回退到更低等级。达到最高等级后，该域名的每日发送量将不再受限。

### 受众规模对发送量的影响 \{#impact-on-launch-by-audience-size\}

| 受众规模         | 发送时的效果                        |
| ---------------- | ----------------------------------- |
| 100 人以下       | 第一天即可覆盖全部受众              |
| 100–2,000 人     | 发送量在数天内逐步提升              |
| 2,000 人以上     | 发送量在 1–2 周内逐步提升           |

:::tip
DNS 验证完成后立即启动您的第一个推广活动。越早开始发送，您的域名就能越快晋升至更高档位，达到更高的每日发送上限。
:::

## 送达率 \{#deliverability\}

:::link
主要文章：[监控域名健康状况](mail-domain-health)
:::

**Settings** > **DNS** 中的每个域名都会显示满分 100 分的**送达率评分**。点击 **Details** 查看完整情况——配置信息告诉你域名是否已设置好，而这里告诉你邮件是否真正送达。

该评分综合了三个信号：硬退信率、投诉率以及预热邮箱的收件箱到达率。硬退信率达到 2% 为警告，5% 为严重。投诉的权重远高于退信：发送量的 0.1% 为警告，0.5% 为严重。每次投诉都会立即[屏蔽该收件人](mail-suppression#delivery-failed-or-the-recipient-marked-it-as-spam)。

## 多个域名 \{#multiple-domains\}

在您的域名完成预热之前，Adapty 会对每个域名每天可发送的邮件数量进行[限制](#warm-up-and-daily-limits)。因此，使用多个域名可以提升您的邮件发送能力。

Adapty 按照以下逻辑决定由哪个域名发送邮件：

- **每个收件人每次营销活动只使用一个域名。** 为保持营销活动的一致性，Adapty Mail 会使用同一个电子邮件地址向同一收件人发送邮件。如果您删除该域名或停止从该域名发送邮件，下一封邮件将从还有余量的最新域名发出。
- **越新的域名优先级越高。** 后添加的域名优先于较早添加的域名。

当所有域名都超出限额时，Adapty Mail 会延迟发送邮件——具体对收件人的影响，请参阅[限流](mail-suppression#throttle-temporary-delays-and-cancellations)部分。

## 暂停与恢复发送 \{#stop-and-resume-sending\}

若要暂停某个域名而无需重新验证，请点击其卡片上的 **Stop sending**。卡片随即显示 **Sending off**，Adapty Mail 在选择发送域名时会跳过该域名。点击 **Resume sending** 可将其恢复。

| 链接子域名记录无法验证 | 卡片中会在主机名下方显示原因。请确认其 CNAME 和 TXT 记录，然后点击 **Check**——该主机未激活前域名无法完成设置。 |
| "Cannot delete: some identities are verified"                                  | 该域名在自动预热功能上线前完成设置，无法通过看板删除。请联系支持团队。                    |

| 收件人的回复未到达您这里 | 未设置回复地址时，回复会发送至 `hello@` 邮箱，而该邮箱无人查看。请在域名卡片上[设置回复地址](#4-set-the-sender-name-and-reply-to-address)。设置前已发送的邮件仍保留旧地址。 |
| 退信率偏高 | 确认您的受众列表中包含有效且已订阅的地址。[邮件停止发送的原因](mail-suppression)一文介绍了发生退信后地址的处理方式。如需查找退信最多的原因，请查阅送达率页面上的 [**Bounces** 卡片](mail-domain-health#bounces)。 |
| 投诉率偏高 | 将垃圾邮件举报率控制在发送量的 0.1% 以下。投诉的影响远大于退信，且收件人会立即被加入抑制名单。若要查看过去 30 天的投诉率，请打开[送达率页面](mail-domain-health#deliverability-score)。 |
