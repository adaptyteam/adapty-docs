Adapty Mail 从您自己的域名发送营销活动，而非使用共享地址，因此发件人信誉完全由您掌控。只需验证一个域名即可开始发送，一个项目最多可添加五个域名。

如需以最少步骤完成域名验证，请参阅 [Adapty Mail 入门指南](mail-get-started#4-set-up-your-sending-domain)。本文是完整参考文档，涵盖设置、验证、预热以及使用多个域名发送的内容。

## 要求与限制 \{#requirements-and-limitations\}

- **根域名**：提交您的根域名，必须带有顶级域名后缀（`yourapp.com`）。Adapty Mail 不接受子域名（`app.yourapp.com`）或带有二级后缀的域名（`yourapp.co.uk`、`yourapp.com.br`）。
- **仅限 ASCII**：不支持 Punycode 和国际化域名。
- **有效的 NS 记录**：域名必须能正常解析。Adapty Mail 在设置过程中会执行 DNS 查询，拒绝没有有效 NS 记录的域名。
- **每个项目仅限一个域名**：域名不能在项目间共享。如果任何项目（无论是您的还是他人的）已使用该域名，设置将失败。
- **与品牌匹配的域名**：域名必须能被识别为您应用的域名。对于名为 Yourapp 的应用，`yourapp.com` 可以通过；不相关的 `anotherapp.com` 则不行。Adapty 会参考您的[品牌](mail-brand)应用名称、描述和标语进行验证。未设置品牌的项目将跳过此检查。
- **信誉良好的域名**：如果 [Blacklist Master](https://www.blacklistmaster.com/) 报告该域名被列入垃圾邮件黑名单，Adapty Mail 将拒绝使用。
- **每个项目最多五个域名**：每个域名独立完成验证和预热。
- **删除操作不可撤销**：发送将立即停止，该域名的验证进度、DNS 记录和预热邮箱也将被移除。您可以重新添加该域名，但需要使用新记录从头验证——只有每日发送限额会保留。您自己的 DNS 记录不受影响，请手动删除。

## 1. 添加域名 \{#1-add-the-domain\}

在 Adapty Mail 中，依次打开 **Settings** > **DNS**，进入 **Email domains** 部分。

1. 在 **Domain** 字段中，输入你的根域名，例如 `yourapp.com`。
2. 在 **Sending subdomain** 字段中，指定用于发送邮件的子域名。留空则默认使用 `mail`。字段下方的提示会预览完整的主机名：*Emails will be sent from mail.yourapp.com*。
3. 在 **Link subdomain** 字段中，为邮件中的链接和图片指定*另一个子域名*。留空则默认使用 `go`。提示同样会显示该主机名：*Links and images in emails will be served from go.yourapp.com*。
4. 点击 **Add domain**。Adapty Mail 会验证输入内容，将域名添加到你的项目，并显示一张包含该域名所需全部 DNS 记录的卡片。

<ZoomImage id="mail-email-domains.webp" width="500px" alt="包含域名、发送子域名和链接子域名字段的添加域名表单" />

5. 可选操作：[添加更多域名](#multiple-domains)，以提高每日可发送的邮件数量。

### 使用自定义子域名 \{#use-custom-subdomains\}

发送前缀会出现在每位收件人看到的发件人地址中，链接前缀则会出现在他们点击的每个链接里。大多数项目保持默认设置即可；如果你要自定义，两个字段遵循相同的规则：

- 使用小写字母、数字和连字符，不得以连字符开头或结尾，最多 63 个字符。
- `www`、`smtp`、`admin`、`api`、`mx` 和 `dkim` 为保留字。
- 冒犯性标签以及冒充知名品牌的标签（例如 `paypal`）将被拒绝。`news`、`offers`、`hello` 等普通营销词汇可以通过。
- 两个前缀不能相同。
- 域名添加后，两个前缀即固定不变。如需从其他主机发送，请删除该域名后重新添加，或添加第二个域名。

## 2. 添加 DNS 记录 \{#add-the-dns-records\}

将卡片上的每条记录按原样添加到您的 DNS 中。如需一次性导出全部记录，点击 **Export** 并选择 **CSV**、**GoDaddy zone file**、**Cloudflare zone file** 或 **Route 53 zone file**。

:::warning
**在 Cloudflare 上，每条 CNAME 必须设置为 DNS only** — 启用代理的记录会解析到 Cloudflare 的地址，永远无法通过验证。使用 **Cloudflare zone file** 导出时会自动为您完成此设置。
:::

前三个部分是必填项——在记录解析完成之前，配置不会生效。根域名上的 DMARC 记录为可选项。

| 功能区块 | 主机 | 作用 |
| --- | --- | --- |
| **发件基础设施** | 发件子域名 | 为您的营销活动签名并将退信路由回 Adapty Mail |
| **预热邮箱** | 发件子域名 | 运行邮箱以在[预热](#warm-up-and-daily-limits)期间建立您的发件人信誉 |
| **媒体与重定向** | 链接子域名 | 通过您自己的域名提供邮件中的图片和追踪链接 |
| **DMARC 策略**（可选） | 根域名 | 告知接收方如何处理未通过身份验证的邮件 |

如果您的根域名已经为企业邮箱配置了 SPF 和 DMARC 记录，这些记录无需改动——所有必要的记录都添加在子域名上。

<Details>
<summary>DNS 记录参考</summary>

**DKIM — 3 条 CNAME 记录。** 用于验证邮件在传输过程中未被篡改的加密签名。

| 字段 | 格式                              |
| ----- | ----------------------------------- |
| 类型  | CNAME                               |
| 名称  | `{token}._domainkey.mail.yourapp.com` |
| 值 | `{token}.dkim.amazonses.com`        |

**MAIL FROM — 1 条 MX 记录。** 用于处理退信。

| 字段 | 格式 |
| -------- | -------------------------------------------------------- |
| Type     | MX                                                       |
| Name     | `hello.mail.yourapp.com`                                 |
| Priority | `10`                                                     |
| Value    | `feedback-smtp.{region}.amazonses.com`                   |

**MAIL FROM — 1 条 TXT 记录。** 授权 Adapty 代表您发送邮件。

| Field | Format                                 |
| ----- | -------------------------------------- |
| Type  | TXT                                    |
| Name  | `hello.mail.yourapp.com`               |
| Value | `"v=spf1 include:amazonses.com ~all"`  |

**DMARC — 在根域名上添加 1 条 TXT 记录。** 可选，但建议配置。

| Field | Format                |
| ----- | --------------------- |
| Type  | TXT                   |
| Name  | `_dmarc.yourapp.com`  |
| Value | `v=DMARC1; p=reject`  |

预热邮箱和 `go.yourapp.com` 的记录格式相同，其名称和值由 Adapty Mail 使用的邮件及托管服务商生成。令牌、区域、主机名和所有权值均在设置时生成——请从域名卡片或导出文件中复制，切勿从本参考文档中复制。

</Details>

## 3. 验证记录 \{#3-verify-the-records\}

<ZoomImage id="email-domains.webp" width="700px" alt="展开的域名卡片，显示 DNS 记录组和验证进度" />

 DNS 传播通常需要几分钟，极少数情况下最多需要 48 小时。为了验证记录，Adapty Mail 会按固定间隔自动轮询 DNS，直到找到记录或 7 天后停止。点击卡片上的 **Check** 可立即触发一次检查（有 10 秒冷却时间），或在自动检查停止后重新启动。

当记录存在于 DNS 中、其值与 Adapty Mail 提供的值匹配，且服务商已确认时，该记录即通过验证。未通过验证的记录会显示一个标签，说明缺少哪项条件：

| 标签 | 含义 |
| --- | --- |
| **Missing** | DNS 中不存在该记录。请按照卡片上显示的内容添加。 |
| **Wrong value** | 记录已存在，但其值不匹配。请更新为正确的值。 |
| **Differs from suggested** | 您的根域名已有一条 DMARC 记录，但值不同。Adapty Mail 的建议并非强制要求——仅在您希望替换时更新即可。 |
| **Provider check failed** | 提供商拒绝了该记录。请确认记录值后点击 **Check**。 |
| **Awaiting provider** | 该记录在 DNS 中已正确配置，但提供商尚未确认。点击 **Check** 刷新状态。 |

Adapty Mail 不会定期自动检查已验证记录的有效性。如需手动触发检查，请点击 **Check**，或前往 **Settings** > **DNS**。

只要你计划继续发送邮件，就请保留这些记录——一旦 DKIM 记录消失，Amazon SES 将在宽限期结束后停止对邮件签名，届时需要从头重新验证域名。

## 4. 设置发件人名称 \{#set-the-sender-name\}

域名验证通过后，其卡片会出现 **Email sender name** 字段。Adapty Mail 会用您的项目名称填充该字段，并从您的发送子域名的 `hello@` 地址发送邮件，因此字段提示会显示完整的发件人信息——*Your Company &lt;hello@mail.yourapp.com&gt;*。该名称按域名设置：若一个项目使用两个域名发送邮件，则需分别设置两个名称。

## 预热与每日发送限额 \{#warm-up-and-daily-limits\}

新域名在 Gmail 或 Yahoo 等邮件服务商那里没有任何声誉，因此从全新域名大量发送邮件很容易进入垃圾邮件。Adapty Mail 会自动为每个域名完成预热，同时采用两种并行机制，无需任何配置。

- **预热邮箱**：DNS 验证通过后，Adapty Mail 会在您的发送子域名上创建一个邮箱，并交由预热服务托管，由其收发普通的日常邮件。域名卡片会显示当前所处的预热阶段。在 [**Warmup mailbox** 记录](#2-add-the-dns-records)验证完成之前，预热不会开始。
- **每日发送限额**：您的活动发送量与预热邮箱分开计量，共分 20 个等级。该限额可将您的发送量控制在不会被标记为垃圾邮件的范围内，并随着您的持续发送而逐步提升。

### 分级机制的工作原理 \{#how-tiers-work\}

您的域名从 **第 1 级**（每天 100 次发送）开始。每次超出当天的发送限额时（实际发送次数和因限流而被拦截的尝试均计入），配额将逐级递增。更高的限额将于次日生效。

在某一级别的第一天，配额会在全天内逐步释放，而非一次性全部放开。级别的提升仅由发送量驱动，且只会向上晋级，不会自动回降。超过最高级别后，该域名的每日发送将不再受任何限制。

| 受众规模         | 发送时的效果                        |
| ---------------- | ----------------------------------- |
| 100 人以下       | 第一天即可覆盖全部受众              |

| 2,000 人以上     | 发送量在 1–2 周内逐步提升           |

DNS 验证完成后立即启动您的第一个推广活动。越早开始发送，您的域名就能越快晋升至更高档位，达到更高的每日发送上限。
:::

## 送达率 \{#deliverability\}

**Settings** > **DNS** 中的每个域名都会显示一个满分 100 分的**送达率评分**。点击 **Details** 可查看完整详情——配置状态告诉你域名是否设置正确，而送达率评分则告诉你邮件是否真正到达收件人。

- **送达率评分**：综合以下三项指标的总体评级。
- **退信（Bounces）**：发送失败的数量及比率。2% 为警告，5% 为严重。
- **收件箱到达率（Inbox placement）**：已接收的邮件实际落在哪个文件夹。
- **发送配额档位（Send tiers）**：域名在[预热](#warm-up-and-daily-limits)阶段的位置及当日发送上限。

投诉的影响远比退信严重：投诉率达到发送量的 0.1% 就需要警惕，0.5% 则是危险信号。一旦收到投诉，该收件人会立即被[加入抑制名单](mail-suppression#delivery-failed-or-the-recipient-marked-it-as-spam)。

## 多个域名 \{#multiple-domains\}

在您的域名完成预热之前，Adapty 会对每个域名每天可发送的邮件数量进行[限制](#warm-up-and-daily-limits)。因此，使用多个域名可以提升您的邮件发送能力。

Adapty 按照以下逻辑决定由哪个域名发送邮件：

- **每位收件人每次营销活动只使用一个域名。** 为保持营销活动的一致性，Adapty Mail 会使用同一个邮件地址向同一收件人发送邮件。如果您删除了该域名或停止从该域名发送邮件，下一封邮件将从仍有余量的最新域名发出。
- **越新的域名优先级越高。** 后添加的域名优先于较早添加的域名。
- **较早创建的用户画像使用最旧的域名。** 在 2026 年 7 月 23 日之前创建用户画像的用户，无论您后续添加了哪些域名，都将从最旧的域名收到邮件。

当所有域名都超出限制时，Adapty Mail 会延迟发送邮件——[限流](mail-suppression#throttle-temporary-delays-and-cancellations)部分介绍了后续收件人的处理方式。

## 暂停与恢复发送 \{#stop-and-resume-sending\}

若要暂停某个域名而无需重新验证，请点击其卡片上的 **Stop sending**。卡片随即显示 **Sending off**，Adapty Mail 在选择发送域名时会跳过该域名。点击 **Resume sending** 可将其恢复。

## 故障排查 \{#troubleshooting\}

| 问题 | 解决方案 |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| "Enter a valid domain (e.g. example.com)" | 检查输入内容：根域名需包含顶级后缀（`yourapp.com`），仅限 ASCII 字符，首尾不能有连字符。二级后缀（如 `yourapp.co.uk`）不被接受。 |
| "Domain does not have valid DNS records" | 根域名本身必须可解析。重试前请确认 NS 记录已生效。 |
| "Domain is already registered to another project" | 请选择其他域名，或联系支持团队确认注册是否有误。 |
| "This subdomain cannot be used" | 该标签已被保留或被筛选拒绝，请换一个——参见[使用自定义子域名](#use-custom-subdomains)。 |
| "This link subdomain cannot be used" | 链接子域名遵循与发件子域名相同的规则，且不能与其完全相同——参见[使用自定义子域名](#use-custom-subdomains)。 |
| "Please wait before checking again" | 手动检查之间请等待 10 秒，后台自动轮询仍会继续。 |
| 记录长期未通过验证 | 请仔细核对记录内容——不要有多余的点，CNAME 目标正确，每条记录只填一个值。DNS 传播最长可能需要 48 小时。 |
| Cloudflare 上的 CNAME 长期未通过验证 | 记录处于 **Proxied**（代理）状态。请将每条记录切换为 **DNS only**，然后点击 **Check**。 |
| 预热未启动 | 预热邮箱的 MX、DKIM 和 SPF 记录尚未通过验证。请添加或修正这些记录，然后点击 **Check**。 |
| 链接子域名的记录无法通过验证 | 卡片中会在主机名下方显示原因。请确认其 CNAME 和 TXT 记录，然后点击 **Check**——在该主机激活之前，域名无法完成配置。 |
| "Cannot delete: some identities are verified" | 该域名是在自动预热功能上线之前配置的，无法从看板中删除。请联系支持团队。 |
| 邮件进入垃圾箱 | 确认 DMARC 记录已发布。新域名需要预热时间——请参阅[预热与每日发送限制](#warm-up-and-daily-limits)。 |
| 退信率过高 | 请确认受众列表中的地址均有效且已获得授权。[邮件停止发送的原因](mail-suppression)介绍了地址退信后的处理方式。 |
| 投诉率过高 | 请将垃圾邮件举报率控制在发送量的 0.1% 以下。每条投诉的影响远大于退信，且收件人会立即被加入抑制名单。 |
