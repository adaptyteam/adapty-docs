事件动态可让你直观地追踪 Adapty 生成的[事件](events)，并查看这些事件导出到第三方集成（包括 webhook）的状态。

<ZoomImage id="event-status.webp" width="700px" alt="Event feed showing the delivery status of each event" />

:::note
AppsFlyer、Facebook Ads 和 Branch 的发送状态可能不准确，因为它们并不总是在发生错误时返回错误信息。
:::

要查看发起交易的用户画像，请在事件详情中点击 **View Profile** 按钮。

## 事件未出现在信息流中 \{#an-event-is-missing-from-the-feed\}

有三种情况会导致事件未出现在信息流中。

- **Adapty 从未创建该事件。** 对于大多数事件，即使某个集成关闭了该事件类型，事件仍会被创建——只是显示为[灰色状态](event-statuses)。但有两种例外情况：

1. 除非已配置并启用 [webhook 集成](webhook)，否则 Adapty 不会创建 `access_level_updated`。
   2. 除非在 Adapty 检查时试用或订阅仍在运行，否则 Adapty 不会创建[合成事件](events#synthetic-events)。请参阅[合成事件未到达](handle-integration-errors#a-synthetic-event-never-arrived)。

- **事件存在，但数据流中未显示。** 服务端 API v1 的交易记录永远不会出现——请改用[服务端 API（第 2 版）](api-adapty/operations/setTransaction)。没有用户画像的事件也不会显示：这类交易是在 SDK 识别用户之前到达的，例如来自商店服务器的通知。如需将这些事件包含在导出数据中，请在 [S3](s3-exports) 或 [Google Cloud Storage](google-cloud-storage) 集成中启用 **Include events without profile**。Apple 提前写入时间戳的续订记录同样不会显示——这些记录[要等到时间戳所指的时间点之后才会出现](how-profiles-work)，不过 Adapty 会立即将其转发给您的集成。

- **事件发生时间超过两周。** 事件列表仅保留两周内的数据。因此，延迟较长的[合成事件](events#synthetic-events)可能会在没有触发其计时器的 `trial_started` 或 `subscription_started` 事件的情况下出现。
