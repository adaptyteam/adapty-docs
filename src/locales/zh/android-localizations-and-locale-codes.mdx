<SDKv4>

要向每位用户展示其可阅读语言的流程，请将用户的语言偏好传递给 Adapty Android SDK 4.5 或更高版本。用户将看到流程中最符合其语言偏好的版本。如果流程中没有这些语言，则以默认语言环境显示。

在 SDK 4.0–4.4 中，您的应用向 `getFlowConfiguration` 传递一个语言区域代码，SDK [会精确匹配它](#pass-the-users-languages-to-the-sdk)。如需更新代码，请阅读[将 Adapty Android SDK 迁移至 v4.5](migration-to-android-sdk-45)。

在 SDK 4.5 或更高版本中，以下三种情况遵循其他规则：

- 在自有代码中选择流程本地化的应用，请[使用自定义解析器](#pick-a-flows-localization-in-your-own-code)。
- 旧版付费墙编辑工具创建的付费墙，仅[以最高优先级匹配用户语言](#select-a-localization-strategy)。
- 自定义付费墙和用户引导，[与 SDK 4.4 的处理方式相同](#localize-custom-paywalls-and-onboardings)。

## 将用户语言传递给 SDK \{#pass-the-users-languages-to-the-sdk\}

<Tabs groupId="android-sdk-version" queryString>
<TabItem value="4.5" label="SDK 4.5 or later" default>

[`AdaptyUI.getFlowConfiguration`](android-get-pb-paywalls#fetch-the-view-configuration) 需要 `preferredLocales` 参数。请按优先级从高到低传入用户的语言列表。由您的应用决定传入哪些语言，例如设备语言或用户在应用内语言选择器中选择的语言。

<Tabs groupId="current-os" queryString>
<TabItem value="kotlin" label="Kotlin" default>

```kotlin showLineNumbers
val preferredLocales = LocaleListCompat.getAdjustedDefault().toLanguageTags().split(",")

AdaptyUI.getFlowConfiguration(flow, preferredLocales) { result ->
    // handle the result
}
```

</TabItem>
<TabItem value="java" label="Java">

```java showLineNumbers
List<String> preferredLocales =
    Arrays.asList(LocaleListCompat.getAdjustedDefault().toLanguageTags().split(","));

AdaptyUI.getFlowConfiguration(flow, preferredLocales, result -> {
    // handle the result
});
```

</TabItem>
</Tabs>

以下三条规则决定用户看到哪种本地化语言：

- SDK 会按顺序尝试用户的语言列表，并匹配流程中第一个符合的语言。这里遵循 Android 资源匹配规则：即 Android 用于选择应用翻译的规则。SDK 会匹配语言的近似变体：`de-AT` 可匹配 `de`，`zh-TW` 可匹配 `zh-hant`。在 Android 6 及更早版本上，SDK 会匹配流程中与用户语言和文字相符的第一个本地化版本，不限地区。旧版付费墙编辑工具的付费墙仅使用优先级最高的用户语言。
- 大小写和分隔符不影响匹配：`pt_BR`、`pt-BR` 和 `pt-br` 匹配同一语言区域。请直接传入 Android 返回的值。
- 若列表为空，或列表中没有与流程语言区域匹配的项，SDK 将使用默认语言区域。

传入以下三种列表之一。该列表设定了 SDK 尝试语言的顺序，但无法添加该流程中不存在的语言。

| 值 | 流程显示语言 | 权衡 |
|---|---|---|
| `LocaleListCompat.getAdjustedDefault()` | 用户在 Android 设置或应用内为您的应用选择的语言。若未设置，则使用流程支持的第一个设备语言 | 在 Android 13 以下，通过 `AppCompatDelegate.setApplicationLocales` 为应用设置的语言仅在首个 `AppCompatActivity` 创建后才生效。请在此之后读取列表，而非在 `Application.onCreate` 中读取。 |
| `LocaleManagerCompat.getSystemLocales(context)` | 流程支持的第一个设备语言，即使用户为应用选择了其他语言 | 流程显示的语言可能与应用界面语言不一致 |
| `selectedLanguage`，然后 `LocaleListCompat.getAdjustedDefault()` | 应用内语言选择器所选语言，其次为设备语言 | — |

要传递列表，请将其转换为语言区域代码：

```kotlin showLineNumbers
// The language selected for your app, then the device languages
val appLocales = LocaleListCompat.getAdjustedDefault().toLanguageTags().split(",")

// The device languages
val deviceLocales = LocaleManagerCompat.getSystemLocales(context).toLanguageTags().split(",")

// The language from the language picker in your app, then the other languages
val pickerLocales = listOf(selectedLanguage) + appLocales
```

当设备语言设置为英语时，用户在应用内选择了西班牙语——以上前两个列表在这种情况下会返回不同的结果。使用 `getAdjustedDefault()` 时，该用户看到的是西班牙语；而使用 `getSystemLocales()` 时，看到的是英语。

如果语言选择器通过 `AppCompatDelegate.setApplicationLocales` 保存语言，则不需要第三个列表。此时，第一个列表会以所选语言开头。

:::tip
不要单独传入 `Locale.getDefault().toLanguageTag()`。它只包含一种语言，SDK 没有其他语言可以回退。
:::

大多数应用不会传入 `localizationStrategy`。不传时，SDK 默认使用 [`AdaptyUiLocalizationStrategy.Auto`](#select-a-localization-strategy)，适用于流程与付费墙编辑工具构建的流程以及旧版付费墙编辑工具构建的付费墙。

</TabItem>
<TabItem value="4.4" label="SDK 4.0–4.4">

在 [`AdaptyUI.getFlowConfiguration`](android-get-pb-paywalls#fetch-the-view-configuration) 的 `locale` 参数中传入一个语言区域代码。由应用决定传入哪个代码，例如设备的语言区域或应用内语言选择器中的语言。

```kotlin showLineNumbers
AdaptyUI.getFlowConfiguration(flow, locale = "pt-BR") { result ->
    // handle the result
}
```

匹配是精确的。SDK 会将你传入的代码与流程的本地化代码逐字符比对：不会转换大小写，不会将下划线（`_`）替换为连字符（`-`），也不会回退到语言子标签。对于包含 `pt-BR` 本地化的流程，只有 `pt-BR` 能匹配：`pt-br`、`pt_BR` 和 `pt-PT` 均无法匹配。

当代码与任何本地化语言都不匹配时，流程会静默地以其[默认语言](add-paywall-locale-in-adapty-paywall-builder#set-the-default-locale)渲染——SDK 不会返回错误，也不会记录警告。

省略语言代码与请求流程的默认本地化语言不同：SDK 会替换为固定的 `en`。如果某个流程的默认语言是 `de`，在有 `en` 本地化版本时仍会以 `en` 渲染，只有当没有 `en` 本地化版本时才会回退到 `de`。此行为适用于 Android SDK 4.0.1 及更高版本——在 4.0.0 中，省略代码会渲染流程的默认本地化语言。

:::warning
请严格按照已发布流程中的语言代码传入：从 **Select languages** 字段获取的是 `pt-BR`，而非 `pt-br`。对于旧版付费墙编辑工具创建的付费墙，请传入小写代码，例如 `pt-br`。

:::

不要直接传递系统语言区域标识符。在设置为葡萄牙语（巴西）的设备上，`Locale.getDefault().toString()` 返回 `pt_BR`，但这与任何本地化配置都不匹配。在设置为英语（美国）的设备上，`Locale.getDefault().toLanguageTag()` 返回 `en-US`，但这会遗漏只有 `en` 的流程。在传递系统语言区域标识符之前，请将其转换为流程中已有的代码。
:::

</TabItem>
</Tabs>

## 测试用户看到的本地化版本 \{#test-which-localization-a-user-sees\}

<Tabs groupId="android-sdk-version" queryString>
<TabItem value="4.5" label="SDK 4.5 or later" default>

当流程不包含用户语言时，SDK 会静默回退到默认语言，不会抛出错误。如需了解用户实际看到的本地化版本，请在设备上测试该流程：

1. 将[日志级别](sdk-installation-android#logging)设置为 `AdaptyLogLevel.VERBOSE`。
2. 在设备设置中，将测试语言移至语言列表顶部。
3. 在应用中打开流程。
4. 在 Logcat 中，找到包含 `getFlowConfiguration: preferredLocales` 的日志行。该行末尾会显示当前本地化的语言代码，例如 `strategy = Auto -> pt-BR`。看板中该代码以小写形式显示：`pt-BR` 对应 `pt-br`。

如需在不更改设备设置的情况下测试某种语言，可在调试构建中传入固定的 `preferredLocales` 列表，例如 `listOf("pt-PT")`。

</TabItem>
<TabItem value="4.4" label="SDK 4.0–4.4">

当你传入的代码与流程的任何本地化版本均不匹配时，SDK 会使用默认语言环境，既不会报错，也不会记录警告。要了解用户实际看到哪个本地化版本，请在设备上测试该流程：

1. 在设备设置中，选择测试所需的语言和地区。
2. 在你的应用中打开该流程。
3. 将设备上显示的流程与 Flow & Paywall Builder 中的各本地化版本进行对比。如果流程显示的是默认语言环境，说明没有与你传入的代码完全匹配的本地化版本。

要在不更改设备设置的情况下测试代码，请在调试构建中传入固定的 `locale`，例如 `"pt-BR"`。

</TabItem>
</Tabs>

如果流程中某些部分仍显示默认语言，说明当前本地化配置未包含这些部分的翻译。请在 Flow & Paywall Builder 中[补充缺失的翻译行](add-paywall-locale-in-adapty-paywall-builder#manage-localizations-and-translations)。

## 选择要添加到流程的语言区域 \{#select-which-locales-to-add-to-a-flow\}

要用最少的语言区域覆盖最多的用户，在 **Select languages** 字段中[添加语言区域](add-paywall-locale-in-adapty-paywall-builder#add-and-set-up-a-locale)时，请遵循以下三条规则：

- 添加不带地区的语言。例如，`de` 覆盖德国、奥地利和瑞士的德语使用者。
- 仅在同一语言已有第二种翻译时才添加区域语言环境，例如在 `fr` 之外再添加 `fr-ca`。
- 添加所有用户使用的语言。SDK 不会将一种语言映射到另一种语言，例如加泰罗尼亚语不会映射到西班牙语。加泰罗尼亚语使用者会看到该流程支持的下一个首选语言，或默认语言环境。

:::important
这些规则需要 Android 或 iOS SDK 4.5 或更高版本。使用 Adapty SDK 4.0 至 4.4 的应用只传递一个语言区域代码。这些应用的用户可能会看到与 SDK 4.5 用户不同的流程本地化版本。请保留这些应用传递的所有代码，例如现有的 `zh` 或 `pt-br`。
:::

### 为中文、西班牙语和葡萄牙语选择代码 \{#select-codes-for-chinese-spanish-and-portuguese\}

**Select languages** 字段中，中文、西班牙语和葡萄牙语各有多个代码。请从表格中添加相应代码：

| 语言 | 添加 | 用户看到的内容 |
|---|---|---|
| 中文 | `zh-hans` 和 `zh-hant`，而非新增 `zh`。仅在需要单独的香港翻译时添加 `zh-hk`。 | `zh-hans` 在中国大陆和新加坡显示，`zh-hant` 在台湾、香港和澳门显示。 |
| 粤语 | `yue`，始终与 `zh-hant` 一起添加 | `yue` 在设备语言设置为粤语时显示，`zh-hant` 在设备语言设置为繁体中文时显示。SDK 不会向设备语言为粤语的用户显示 `zh-hant`，也不会向设备语言为繁体中文的用户显示 `yue`。 |
| 西班牙语 | `es` 和 `es-419`，而非新增 `es-mx` | `es` 在西班牙显示，`es-419` 在拉丁美洲和美国显示。 |
| 葡萄牙语 | `pt-br` 用于巴西葡萄牙语，`pt` 用于欧洲葡萄牙语 | `pt-br` 在巴西显示，`pt` 在葡萄牙显示。 |

如果您的流程有同一语言的多个地区变体，例如 `es-ar` 和 `es-co`，请同时添加 `es-419`。这样，其他拉丁美洲国家（如墨西哥）的用户就会看到 `es-419`。

### 从推荐的语言区域集开始 \{#start-from-a-recommended-set-of-locales\}

如需分阶段规划翻译工作，可从以下三个集合中选择一个。每个集合均包含前一个集合的所有内容。

| 集合 | 语言区域 | 总计 |
|---|---|---|
| 最小集 | `en`, `es`, `pt-br`, `fr`, `de`, `it`, `ru`, `ja`, `ko`, `zh-hans`, `zh-hant` | 11 |
| 扩展集 | 最小集 + `tr`, `pl`, `nl`, `sv`, `da`, `no`, `fi`, `uk`, `ar`, `he`, `hi`, `id`, `th`, `vi`, `es-419`, `pt` | 27 |
| 广泛集 | 扩展集 + `cs`, `sk`, `hu`, `ro`, `el`, `bg`, `hr`, `sl`, `lt`, `lv`, `et`, `ca`, `kk`, `ms`, `fil`, `fa`, `ur`, `bn`, `ta`, `te`, `mr`, `fr-ca` | 49 |

在这些集合中，用户看到的语言区域如下：

- 在最小集合中，`es` 覆盖所有国家的西班牙语用户，`pt-br` 也覆盖葡萄牙的葡萄牙语用户。
- 在扩展集合中，`es-419` 和 `pt` 是第二套翻译。有了这两个区域设置，`es` 服务于西班牙，`pt` 服务于葡萄牙。请将 `pt` 翻译为欧洲葡萄牙语。
- 加泰罗尼亚语和马来语用户只会看到各自对应的语言区域：`ca` 或 `ms`。SDK 不会向他们显示西班牙语或印尼语。

### 选择默认语言区域 \{#select-the-default-locale\}

当流程中没有用户所使用的语言时，用户将看到默认语言区域的内容。新建流程默认仅包含 `en` 语言区域，并将其设为默认值。如需更改，请[将其他语言区域设为默认值](add-paywall-locale-in-adapty-paywall-builder#set-the-default-locale)。

默认语言区域需遵循以下三条规则：

- 对于没有匹配语言区域的用户，选择大多数人都能理解的语言。通常是英语，而不是你主要市场的语言。
- 完整翻译默认语言区域。没有匹配语言区域的用户将看到整个流程的默认语言区域内容。有匹配语言区域的用户将看到其对应语言的内容。任何未翻译的部分将以默认语言区域显示。
- 不要选择有两种书写脚本的语言，例如中文。使用另一种脚本的用户可能无法阅读默认语言区域内容。

## 选择本地化策略 \{#select-a-localization-strategy\}

大多数应用不传递 `localizationStrategy`，因此 SDK 默认使用 `AdaptyUiLocalizationStrategy.Auto`。该策略对 Flow & Paywall Builder 中的流程应用 Android 资源匹配规则，对旧版付费墙编辑工具中的付费墙则应用单语言规则。

在单语言规则下，SDK 只读取 `preferredLocales` 中优先级最高的语言。它会先尝试完整的语言代码，再尝试更短的代码（`pt-br`，然后 `pt`），否则显示默认语言。旧版付费墙编辑工具创建的付费墙在此规则下仍可正常使用，即使重新发布也不受影响。如需让 SDK 尝试 `preferredLocales` 中的每种语言，请[将付费墙迁移至 Flow & Paywall Builder](convert-paywall-to-flow)，然后通过流程版位提供新的流程。

要更改 SDK 将用户语言与流程语言环境进行匹配的方式，请在 `localizationStrategy` 参数中传入以下值之一：

- `AdaptyUiLocalizationStrategy.System`：每个流程均使用 Android 资源匹配，包括旧版付费墙编辑工具中的付费墙。
- `AdaptyUiLocalizationStrategy.Legacy`：每个流程均使用单语言规则，而非 SDK 4.4 的精确匹配。请勿对流程与付费墙编辑工具中的流程传入 `Legacy`：它会遗漏带有地区或脚本标签的语言设置，例如 `pt-BR`。
- `AdaptyUiLocalizationStrategy.Custom(resolver, fallbackResolver)`：[由您的代码选择本地化](#pick-a-flows-localization-in-your-own-code)。

### 在您自己的代码中选择流程的本地化 \{#pick-a-flows-localization-in-your-own-code\}

Android 资源匹配并不能覆盖所有文字系统。例如，当设备语言设置为西里尔文阿塞拜疆语（`az-Cyrl`）但没有拉丁文版本时，包含 `az` 的流程将以其默认语言显示。如果您希望显示 `az`，或者想按照自己的规则选择本地化，请实现 `AdaptyUiCustomLocalizationResolver`，然后通过 `localizationStrategy` 参数将其传入 `AdaptyUiLocalizationStrategy.Custom`。

其他 Adapty SDK 使用不同的规则来匹配语言，因此同一用户在 Android 和 iOS 上可能会看到不同语言版本的流程。若要在所有平台上显示相同的本地化内容，请编写一个解析器，使其返回与其他平台上的应用相同的语言区域代码。

以下规则适用于该解析器：

- 如果流程只有一种本地化语言，SDK 不会调用解析器，直接使用该本地化语言展示流程。
- SDK 会调用 `resolve`，并传入以下参数：你的应用提供的列表、包含流程 `locales` 和 `defaultLocale` 的 `AdaptyUiLocalizationSource`，以及一个 `callback`。`locales` 的顺序与流程本地化语言的顺序一致。
- 如需展示某种本地化语言，请将 `locales` 或 `defaultLocale` 中的语言代码原样传入 `callback`，注意大小写：例如应使用 `ar`，而非 `AR`。
- 如果 `callback` 收到其他代码或 `null`，SDK 会使用 `fallbackResolver` 中的解析器；若未设置 `fallbackResolver`，则使用 `AdaptyUiLocalizationResolver.Auto`。
- SDK 在主线程上调用 `resolve`。`callback` 只能调用一次，可在任意线程中调用。
- 请立即调用 `callback`，不要在此之前发起网络请求或执行其他耗时操作。SDK 会一直等待 `callback` 返回，流程只有在你的代码调用 `callback` 后才会显示。

## Adapty 中的语言代码标准 \{#locale-code-standard-at-adapty\}

Adapty 语言代码遵循 [BCP 47 标准](https://en.wikipedia.org/wiki/IETF_language_tag)：由语言子标签和可选的文字或地区子标签组成，以连字符分隔。**Select languages** 字段以小写形式显示代码：`en`（英语）、`pt-br`（葡萄牙语，巴西）、`zh-hans`（简体中文）和 `zh-hant`（繁体中文）。

## 本地化自定义付费墙和用户引导 \{#localize-custom-paywalls-and-onboardings\}

SDK 4.5 仅更改了流程的本地化规则。自定义付费墙和用户引导的工作方式与 SDK 4.4 相同。

### 按语言选择自定义付费墙的远程配置 \{#pick-a-custom-paywalls-remote-config-by-language\}

`getFlow` 没有 locale 参数。对于自定义付费墙，它会在 `flow.remoteConfigs` 中返回所有已配置的本地化内容。每个条目包含 `locale` 代码和配置内容（`jsonString` 或已解析的 `dataMap`）。请自行实现回退逻辑，选取与用户匹配的条目：

```kotlin showLineNumbers
Adapty.getFlow("YOUR_PLACEMENT_ID") { result ->
    when (result) {
        is AdaptyResult.Success -> {
            val flow = result.value
            val config = flow.remoteConfigs.firstOrNull { it.locale == "en" }
                ?: flow.remoteConfigs.firstOrNull()
            // read your values from config?.dataMap
        }
        is AdaptyResult.Error -> {
            // handle the error
        }
    }
}
```

Adapty 以[Adapty 的语言区域代码标准](#locale-code-standard-at-adapty)中描述的格式存储这些 `locale` 代码。SDK 不会将远程配置与语言区域进行匹配，因此具体应用哪个条目由您的应用自行决定。

### 向用户引导传递语言设置 \{#pass-a-locale-to-an-onboarding\}

<OnboardingDeprecation />

`getOnboarding` 在 SDK 4.5 中保留了 `locale` 参数。当你向 [`getOnboarding`](android-get-onboardings) 传递 `locale` 时，服务器会选取对应的本地化内容：

1. 语言区域字符串转换为小写，所有下划线（`_`）替换为连字符（`-`）
2. Adapty 查找与完整语言区域代码完全匹配的本地化内容
3. 如果未找到匹配项，Adapty 取第一个连字符之前的子字符串（例如 `pt-br` 对应 `pt`），并查找匹配的本地化内容
4. 如果仍未找到匹配项，Adapty 返回该用户引导默认语言区域的内容

这样，`pt_BR`、`pt-BR` 和 `pt-br` 都会解析到同一个用户引导本地化内容。

</SDKv4>

<SDKv3>

## 为什么这很重要 \{#why-this-is-important\}

语言区域代码在多种场景下都会用到——例如，当你需要根据应用当前的本地化设置获取对应的付费墙时。

由于语言区域代码比较复杂，且在不同平台之间可能存在差异，我们为所有支持的平台制定了一套统一的内部标准。但正因为这些代码较为复杂，你务必清楚自己向服务器发送的究竟是什么，以及服务器接下来会如何处理——这样才能始终获得预期的本地化内容。

## Adapty 的语言代码标准 \{#locale-code-standard-at-adapty\}

在语言代码方面，Adapty 使用略经调整的 [BCP 47 标准](https://en.wikipedia.org/wiki/IETF_language_tag)：每个代码由小写子标签组成，以连字符分隔。示例：`en`（英语）、`pt-br`（葡萄牙语（巴西））、`zh`（简体中文）、`zh-hant`（繁体中文）。

## 地区代码匹配 \{#locale-code-matching\}

当 Adapty 收到客户端 SDK 发来的地区代码请求并开始查找对应的付费墙本地化内容时，会依次执行以下步骤：

1. 将传入的地区代码字符串转为小写，并将所有下划线（`_`）替换为连字符（`-`）
2. 查找与完整地区代码完全匹配的本地化内容
3. 若未找到匹配项，则截取第一个连字符前的子字符串（例如 `pt-br` 取 `pt`），并再次查找匹配的本地化内容
4. 若仍未找到匹配项，则返回该付费墙默认地区的内容

这样，发送 `'pt_BR'` 的 iOS 设备、发送 `pt-BR` 的 Android 设备以及发送 `pt-br` 的其他设备都将获得相同的结果。

## 实现本地化：推荐方式 \{#implementing-localizations-recommended-way\}

如果你正在考虑本地化问题，很可能已经在项目中处理本地化字符串文件了。如果是这样，我们建议在每个本地化文件中添加一个键值对，将目标 Adapty 语言区域代码存入其中，然后在调用 SDK 时提取该键对应的值，如下所示：

```kotlin showLineNumbers
// 1. Modify your strings.xml files

/*
strings.xml - Spanish
*/
<string name="adapty_paywalls_locale">es</string>

/*
strings.xml - Portuguese (Brazil)
*/
<string name="adapty_paywalls_locale">pt-br</string>

// 2. Extract and use the locale code

val localeCode = context.getString(R.string.adapty_paywalls_locale)
// pass locale code to AdaptyUI.getViewConfiguration or Adapty.getPaywall method
```

这样，您可以完全掌控应用中每位用户所获取的本地化内容。

## 实现本地化的另一种方式 \{#implementing-localizations-the-other-way\}

你可以不为每个本地化显式定义语言区域代码，同样能得到类似（但不完全相同）的结果。这意味着从平台提供的其他对象中提取语言区域代码，如下所示：

```kotlin showLineNumbers
val locale = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.N)
    context.resources.configuration.locales[0]
else
    context.resources.configuration.locale

val localeCode = locale.toLanguageTag()
// pass locale code to AdaptyUI.getViewConfiguration or Adapty.getPaywall method
```

请注意，我们不建议使用这种方式，因为很难预测 Adapty 服务器最终会收到什么数据。

如果你仍决定采用此方式，请确保已覆盖所有相关的使用场景。

</SDKv3>
