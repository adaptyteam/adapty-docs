在 Kotlin Multiplatform 中，可靠的流程或付费墙获取需要做到三件事：快速渲染、返回面向目标受众的实验变体，以及在网络较慢时优雅降级。以下规则涵盖了实现这些目标所需的时机、缓存与备用方案。

:::tip
以下规则假设 `Adapty.activate()` 和 `Adapty.identify()` 已成功执行完毕。详情请参阅 [Kotlin Multiplatform SDK 的调用顺序](kmp-sdk-call-order)。
:::

## 规则与注意事项 \{#rules-and-pitfalls\}

| 应做 | 不应做 | 原因 |
|---|---|---|
| 仅获取即将展示的版位。                                                                                                                | 在启动时并发预获取所有版位。        | 批量预获取会阻塞主线程，并在请求爆发期间产生黑屏。                                                                  |
| 在归因有机会解析后再获取 `getFlow`——例如，在 `activate` 后 1–2 秒，或在 `setOnProfileUpdatedListener` 触发后。 | 在应用启动时调用 `getFlow`。                       | 归因数据尚未到达。流程将按默认目标受众解析，悄无声息地绕过市场细分和 ASA 个性化设置。 |
| 保留默认的 5 秒 `loadTimeout`（或设置其他值），并为每个版位配置[备用付费墙](fallback-paywalls)。 | 给 `getFlow` 传入一个永远不会触发的超大 `loadTimeout`。 | 如果超时永远不触发，网络较差的用户将看到空白屏幕直到网络恢复——或者直接关闭应用。 |

请参阅[获取自定义付费墙和产品](fetch-paywalls-and-products-kmp)以了解 `fetchPolicy` 和 `loadTimeout` 参数说明，以及[版位](placements)以选择合适的版位。

## 从应用包中加载首屏媒体 \{#show-first-screen-media-from-the-app-bundle\}

流程会从 Adapty 下载图片和视频。若想首屏媒体即时显示，可改为从应用包中加载。如果你已有原生用户引导的素材，这是复用现有资源的好方法。

1. 在 Flow & Paywall Builder 中，为图片或视频设置[自定义媒体 ID](custom-media#custom-media-id)。上传的文件将作为备用资源。
2. 将文件添加到应用资源目录 `commonMain/composeResources/files/` 中。
3. 创建 flow 视图时，在 `customAssets` 中为该 ID 传入已打包的文件：

```kotlin showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
val bundledAssets: Map<String, AdaptyCustomAsset> = mapOf(
    "welcome_video" to AdaptyCustomAsset.localVideoResource(
        path = Res.getUri("files/videos/welcome.mp4")
    ),
)

AdaptyUI.createFlowView(
    flow = flow,
    customAssets = bundledAssets,
).onSuccess { view ->
    view.present()
}.onError { error ->
    // handle the error
}
```

内置文件会增加应用的下载体积，因此只打包用户首屏看到的媒体资源。

捆绑的图片会立即显示，但 SDK 仍会在后台下载已上传的图片。

未捆绑的媒体文件同样会立刻显示：流程布局中包含每张图片（包括视频的静态帧）的低分辨率缩略图，并在完整文件加载完成前持续展示。

有关 `customAssets` 的完整参考，请参阅[自定义资源](kmp-get-pb-paywalls#customize-assets)。

## 针对弱网环境进行优化 \{#tune-for-poor-connectivity\}

对于网络连接持续较差的市场（农村地区、交通枢纽、受路由问题影响的地区）：

- 对除首次以外的所有请求设置 `fetchPolicy = AdaptyPaywallFetchPolicy.ReturnCacheDataElseLoad`。
- 在 Adapty 看板中为每个版位配置[备用付费墙](fallback-paywalls)。
- 在速度与精准定向之间合理权衡 `loadTimeout`。超时时间越短，用户越快看到备用内容；超时时间越长，定向流程就有更多时间加载。
- [保持流程轻量化](flow-size)，让布局更快完成下载。
- 不要将流程显示挂起在 `Adapty.getProfile()` 上。独立调用 `getFlow`，避免因用户画像加载缓慢而阻塞 UI。
