交互式流程元素会根据用户操作改变外观：点击测验选项后变为 **Selected**，聚焦输入框后变为 **Active**。为每种状态单独设置样式，无需编写应用代码即可为用户提供视觉反馈。

某些状态取决于你设置的条件，例如某个变量的值或另一个元素的状态：

- [**禁用**](#add-the-disabled-state)：用户无法与该元素交互。
- [自定义状态](#add-a-custom-state)：你为状态命名、设置条件，并为其设计样式。没有任何操作会将元素切换到自定义状态。你需要[在点击时更改自定义变量](#switch-an-element-to-a-custom-state-on-tap)，并以该变量为基础设置状态的条件。

一个元素[同一时刻只能处于一种状态](#when-several-states-apply-to-one-element)。

## 按元素类型划分的可用状态 \{#available-states-by-element-kind\}

| 元素类型 | 内置状态 | 可添加状态 |
|---|---|---|
| [可选择元素](#selectable-element-states) | **Default**、**Selected** | **Disabled**、**自定义**状态（标签页标题除外） |
| [输入框](#input-states) | **Default**、**Active**、**Invalid** | **Disabled**、**自定义**状态（选择器除外） |
| [任何带有点击交互的元素](#add-a-state)——按钮、图片、容器等（文本元素和图标除外） | **Default** | **Disabled**、**自定义**状态（底部弹出层除外） |
| [进度指示器步骤](#step-states-for-progress-indicators) | **Completed**、**Current**、**Upcoming** | — |

**可添加**状态不会自动出现在元素上，需要你[手动添加](#add-a-state)。每种状态都依赖于你设置的条件。

其他元素的条件也可以引用元素状态进行判断。例如，你可以[说明按钮为何被禁用](element-states-in-conditions#explain-why-a-button-is-disabled)。

## 为状态设置样式 \{#style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="States section in the right panel of a selected element" float="right" />


1. 选中一个元素。右侧面板中的 **States** 区域会显示该元素各个状态对应的标签页。
2. 在 **States** 区域中，激活目标状态。如果该区域没有对应的标签页，请[添加状态](#add-a-state)。
3. 修改任意属性——填充色、边框、排版等。所做的更改仅作用于该状态。

    嵌套元素会随父元素一起变为有状态。对子元素的任何更改都作用于父元素的激活状态。

4. Adapty SDK 在运行时应用匹配的样式。

## 可选元素状态 \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Selectable element with Selected state activated and a style override applied" />

可选元素——测验选项、产品、标签页、开关和复选框，以及任何[自定义可选元素](flow-selectable-elements#make-an-element-selectable)——开箱即带有两种状态：

- **Default**：元素的默认外观。
- **Selected**：用户点击元素时激活。当用户取消选择时，元素恢复为 **Default** 状态。

在单选组中，选择一个元素会取消其他元素的选中状态。多选组允许同时选中多个元素。切换项是独立的——选中一个切换项不会影响其兄弟元素。详见[组类型](flow-selectable-elements#group-types)。

:::tip
如需复用特定状态的样式，可先在某个元素（例如产品卡片）上设置好样式，然后请 [AI 编辑器](flow-ai-editor)将其应用到其他元素上。特定状态的样式不会自动在兄弟元素之间同步。
:::

## 输入框状态 \{#input-states\}

- **Default（默认）**：输入框的初始外观。
- **Active（激活）**：输入框获得焦点时应用。
- **Invalid（无效）**：输入框内容未通过验证时应用，例如邮箱字段中不包含 `@`。参见 [输入框验证](builder-inputs-and-forms#input-validation)。
- **Disabled（禁用）**：输入框不可交互。需[手动添加此状态](#add-the-disabled-state)。

每种状态的样式设置方式与可选元素相同：激活目标状态，然后修改属性。

## 进度指示器的步骤状态 \{#step-states-for-progress-indicators\}

:::link
主要文章：[进度指示器](builder-loaders-and-progress-bars#step-states)
:::

进度指示器向用户展示他们在用户引导流程中已完成的进度。每个步骤有三种状态：

- **已完成**：用户已经通过的步骤。
- **当前**：用户当前所在的步骤。
- **待完成**：用户尚未到达的步骤。

## 当多个状态同时作用于同一元素时 \{#when-several-states-apply-to-one-element\}

多个状态可以同时作用于同一个元素。例如：

- 用户在邮箱字段中输入了无效地址，然后再次点击该字段进行修改。由于字段获得了焦点，**Active** 状态生效；同时地址仍然无效，**Invalid** 状态也同样生效。
- 用户开启了试用开关，因此 **Selected** 状态生效。随后他们选择了一个不含试用期的套餐。该开关对此套餐设置了 **Disabled** 条件，因此 **Disabled** 状态也同样生效。

一个元素在同一时刻只能处于一种状态。当多个状态同时适用时，元素将处于列表中排名最后的状态：

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. 自定义状态，按你添加的顺序排列

在示例中，email 字段处于 **Active** 状态，试用开关处于 **Disabled** 状态。元素的外观与你为该状态设置的样式一致。评估元素状态的条件只匹配该状态。当列表中没有任何状态适用时，元素处于 **Default** 状态。

自定义状态只影响外观。如果同时启用了 **Disabled**，元素会呈现自定义状态的样式，但用户无法与其交互。

## 添加状态 \{#add-a-state\}

### 添加禁用状态 \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="按钮的“添加状态”菜单，包含禁用状态和自定义状态" />

要阻止用户与某个元素交互，请添加 **Disabled** 状态：

1. 选择目标元素。
2. 如果 **States** 部分没有 **Disabled** 标签页，点击 **Add state** 并选择 **Disabled**。如果该元素已有除 **Default** 以外的其他状态，请先点击 **Settings** <Inline id="settings.svg" alt="Settings" /> 再点击 **Add state**。
3. 将鼠标悬停在 **Disabled** 上，然后点击 **Set conditions**。
4. 添加条件。如果希望在输入内容未通过验证时禁用 **submit** 按钮，可将输入的 `isValid` 变量与 `false` 进行比较。要使 **Disabled** 状态生效，需填写所有 **Value** 字段。
5. 为 Disabled 状态设置样式，以直观地传达禁用限制（例如，降低不透明度）。

<ZoomImage id="element-states-disabled-condition.webp" width="400px" alt="The Edit conditional state popover with the condition email.isValid = False" />

Adapty SDK 会在运行时评估该条件，并在适当时应用"禁用"状态——无需任何应用代码。

**禁用**条件也可以评估另一个元素的状态。例如，你可以[同时禁用两个元素](element-states-in-conditions#synchronize-element-states)。

### 添加自定义状态 \{#add-a-custom-state\}

如果内置状态无法满足你的设计需求，可以添加自定义状态：它可以依赖于某个答案、点击操作或其他元素的状态。例如：

- 在试用开关开启时，突出显示年度计划卡片。
- 用户点击 **Remind me** 按钮后改变其颜色。要实现这一效果，请[将按钮切换为点击时的自定义状态](#switch-an-element-to-a-custom-state-on-tap)。

自定义状态仅改变外观。如需禁止用户与某个元素交互，请[添加 **Disabled** 状态](#add-the-disabled-state)。

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="The States list with the Custom state option off and the caption Add a tap action to use custom states" />

以下元素可以拥有自定义状态：

- **按钮、图片、容器、视频、计时器和轮播图**：它们需要配置[点击动作](onboarding-actions#set-up-interactions)。如果删除点击动作，用户将无法看到其自定义状态。
- **可选择元素**：它们需要一个分组或点击动作。
- **输入框**：文本、邮件、密码、数字和电话输入框。

以下元素无法拥有自定义状态：

- 选项卡标题和选项卡内容
- 选择器
- 底部表单
- 进度指示器步骤

每个元素最多可以添加 5 个自定义状态。达到上限后，**Custom state** 选项将关闭，并显示提示"Up to 5 custom states"。通过 Adapty CLI 或 AI 工具生成的配置可以包含更多状态，你仍然可以对其进行编辑。

1. 选择目标元素。
2. 在 **States** 部分，点击 **Add state**，然后选择 **Custom state**。如果该元素已有 **Default** 以外的状态，请在点击 **Add state** 之前先点击 **Settings** <Inline id="settings.svg" alt="Settings" />。
3. 在 **Name** 字段中，输入状态名称，例如 **Locked**。如果名称违反以下任意一条规则，字段下方会显示错误提示，**Save** 按钮也会保持禁用状态：

    - **名称不能为空**：名称不能为空。
   - **最多 30 个字符**：名称不能超过 30 个字符。
   - **此名称为保留名称**：名称不能是 **Default**、`focused`，也不能是内置状态的名称：**Selected**、**Active**、**Invalid**、**Disabled**、**Completed**、**Current** 或 **Upcoming**。
   - **已存在同名状态**：每个元素的自定义状态都需要有唯一的名称。名称不区分大小写。

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="The Edit state panel with the name Locked and the condition plan = free" />

4. 添加条件，例如 `plan` = `free`。如需添加更多行，点击 **Add Condition**。如果一个为真的行就足够，点击 **all** 切换为 **any**。若要使状态生效，请填写所有 **Value** 字段。
5. 点击 **Save**。
6. 若要为该状态设置样式，请在 **States** 区域激活其标签页，然后[修改元素的属性](#style-a-state)。在文本字段中，自定义状态仅更改填充、边框和圆角半径。

编辑工具不会对空的 **Value** 字段发出警告。如果某行有值但没有变量，则无法发布流程：**Can't publish yet** 对话框会在 **Broken references** 下列出该行。Adapty CLI 和 API 会针对此类行返回 [**Invalid State Condition** 错误](flow-common-issues#a-flow-wont-preview-or-publish)。

在视频或轮播图上，状态变更可能会重新播放视频或将轮播图返回到第一张幻灯片。

自定义状态的条件也可以[评估另一个元素的状态](element-states-in-conditions#add-an-element-state-to-a-condition)，例如某个切换按钮是否处于 **Selected** 状态。

### 点击切换元素到自定义状态 \{#switch-an-element-to-a-custom-state-on-tap\}

无法通过动作直接将元素切换到自定义状态。请改为在点击时更改自定义变量，并将状态的条件建立在该变量之上。

1. [创建一个自定义变量](onboarding-variables#create-a-custom-variable)，类型为 **Boolean**，初始值设为 `false`。
2. 选择用户点击的元素。在 **Interactions** 标签页中，[为其 **On Tap** 触发器添加 **Set variable** 动作](onboarding-variables#update-a-variable-via-an-interaction)，并将变量设置为 `true`。
3. 为切换的元素[添加自定义状态](#add-a-custom-state)。在条件中，从 **Variable** 字段的 **Custom** 标签页选择该变量，并将 **Value** 字段设置为 `true`。

<ZoomImage id="element-states-custom-variable-picker.webp" width="500px" alt="变量字段的自定义选项卡，在自定义状态的条件中已选中 reminder.set 变量" />

### 编辑或删除自定义状态 \{#edit-or-delete-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="The tooltip of the Locked tab with the Edit state button" />

要重命名自定义状态或更改其条件，请选中该元素。在右侧面板的 **States** 部分，将鼠标悬停在该状态的标签页上，然后点击 **Edit state**。或者，点击该部分中的 **Settings** <Inline id="settings.svg" alt="Settings" />，再点击状态名称。该状态会保留其样式，所有引用它的条件将显示新名称。

要删除自定义状态，请先选中元素。在右侧面板的 **States** 部分，点击 **Settings** <Inline id="settings.svg" alt="Settings" />，然后点击该状态所在行的垃圾桶图标。如果有条件正在使用该状态，系统会先弹出对话框列出这些条件。点击 **Delete** 后，这些条件将失效，在修复之前您将无法发布该流程。若想恢复该状态及其样式，请撤销本次删除操作。
