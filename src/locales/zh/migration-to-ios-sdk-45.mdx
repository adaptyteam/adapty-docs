若要将应用从 Adapty iOS SDK 4.4 升级到 4.5，请按本指南逐一应用所有变更。如果应用当前版本为 4.3 或更早，请先完成 [v4.4 的变更](migration-to-ios-sdk-44)。

在 4.5 版本中，`getFlowConfiguration` 需要在 `preferredLocales` 中传入语言列表，而不再是可选的 `locale` 语言代码参数。SDK [从该列表中选择流程的本地化版本](localizations-and-locale-codes)。

:::warning
在所有 `getFlowConfiguration` 调用都传入 [`preferredLocales`](#replace-locale-with-the-users-languages) 之前，构建会失败。修复构建后，SDK 4.5 可能会向用户展示[与 SDK 4.4 不同的流程本地化版本](#what-users-see-after-the-update)。
:::

## 快速参考 \{#quick-reference\}

| 修改前 | 修改后 |
|---|---|
| `getFlowConfiguration(forFlow: flow, locale: "fr")` | `getFlowConfiguration(forFlow: flow, preferredLocales: Locale.preferredLanguages)` |
| `locale`：可选 | `preferredLocales`：必填 |
| 不传 `locale`：用户看到的是 `en`，即使流程的默认语言是其他语言。若流程中没有 `en`，用户则看到默认语言 | `preferredLocales: []`：无论用户设备语言如何，所有用户均以流程的默认语言查看 |
| 无策略参数 | `localizationStrategy:`，可选。默认值 `.auto` 适用于大多数应用。 |

## 将 `locale` 替换为用户语言列表 \{#replace-locale-with-the-users-languages\}

在 4.5 版本中，`getFlowConfiguration` 的两个方法（异步版和 completion-handler 版）均使用 `preferredLocales` 列表取代了原来的 `locale` 参数。`preferredLocales` 参数为必填项。若调用时传入 `locale` 或两个参数都不传，Xcode 会报错：

```text
'getFlowConfiguration(forFlow:locale:…)' is unavailable: Pass preferredLocales: Locale.preferredLanguages to show the flow in the device's language, or [] to use the flow's default localization.
```

`getOnboarding` 的 `locale` 参数不受影响。

```diff showLineNumbers
  let flowConfiguration = try await AdaptyUI.getFlowConfiguration(
      forFlow: flow,
-     locale: "fr"
+     preferredLocales: Locale.preferredLanguages
  )
```

你的应用在 4.4 中传入的值决定了在 4.5 中应传入什么：

- 如果您的应用传递了设备值（例如 `Locale.current.identifier`），请改为传递 `Locale.preferredLanguages`。删除所有对该值进行转换的代码：在 4.5 版本中，大小写和分隔符均不影响结果。
- 如果您的应用传递了用户在应用内选择的语言，请将其放在首位：`[selectedLanguage] + Locale.preferredLanguages`。当 Flow & Paywall Builder 中的流程不支持该语言时，SDK 会依次尝试设备语言。
- 如果您的应用调用 `getFlowConfiguration` 时未传递 `locale`，请添加 `preferredLocales: Locale.preferredLanguages`。

要以应用程序 UI 的语言（而非设备语言）显示流程，请传入 `Bundle.main.preferredLocalizations`。如需比较这两个列表，请参阅[将用户语言传递给 SDK](localizations-and-locale-codes#pass-the-users-languages-to-the-sdk)。

要让所有用户都以默认语言查看流程，请传入空列表：`preferredLocales: []`。

您无需传递 `localizationStrategy`。其默认值 `.auto` 适用于流程与付费墙编辑工具中的流程，以及旧版付费墙编辑工具中的付费墙。[其他策略](localizations-and-locale-codes#select-a-localization-strategy)可改变 SDK 匹配语言的方式。

## 更新后用户看到的内容 \{#what-users-see-after-the-update\}

在默认 `localizationStrategy` 下，SDK 4.5 可能会向用户显示与 SDK 4.4 不同的流程本地化版本：

| 应用传入 | 流程包含 | 4.4 | 4.5 |
|---|---|---|---|
| 无语言：4.4 中无 `locale`，4.5 中为 `[]` | 任意语言 | `en`（若流程包含该语言）；否则为默认语言 | 默认语言 |
| 包含不同大小写或分隔符的代码，例如 `pt_BR` | `pt-BR` | 默认语言 | `pt-BR` |
| 地区代码，例如 `pt-BR` | 仅语言代码，例如 `pt` | 默认语言 | `pt` |
| 隐含文字的地区代码，例如 `zh-TW` | 文字代码，例如 `zh-hant` | 默认语言 | `zh-hant`；在旧版付费墙编辑工具创建的付费墙中，显示默认语言 |
| 多个语言，例如先 `fr`，再 `de` | 靠后的语言，例如 `de`，而非第一个 | 默认语言 | 靠后的语言；在旧版付费墙编辑工具创建的付费墙中，显示默认语言 |

使用 SDK 4.0–4.4 的应用版本将继续对您的流程执行精确匹配，直到用户更新应用。`.legacy` 策略不会恢复 4.4 版本的精确匹配行为。

如需查看设备上显示的语言版本，请读取 `flowConfiguration.locale`：SDK 不会记录此信息。如需了解测试流程，请参阅[测试用户看到的语言版本](localizations-and-locale-codes#test-which-localization-a-user-sees)。

## 检查流程的语言区域设置 \{#review-the-locales-of-your-flows\}

SDK 4.5 会以当前语言区域设置显示已发布的流程。要让用户看到其可读语言的流程，请遵循以下三条规则：

- 请务必翻译默认语言环境。当流程没有用户所使用的语言时，用户将看到默认语言环境的内容。如需查看或更改默认语言环境，请参阅[设置默认语言环境](add-paywall-locale-in-adapty-paywall-builder#set-the-default-locale)。
- 对于使用 SDK 4.0–4.4 的应用版本以及使用其他 Adapty SDK 的应用，请保留它们传入的每个语言环境代码。这些应用不使用 4.5 的匹配机制。
- 为了覆盖更多用户，请添加 [4.5 能更好匹配的语言环境](localizations-and-locale-codes#select-which-locales-to-add-to-a-flow)，例如在 `zh` 的基础上额外添加 `zh-hans` 和 `zh-hant`。

## 添加 AdaptyUIBuilder 模块 \{#add-the-adaptyuibuilder-module\}

在 4.5 版本中，AdaptyUI 的部分类型来自 AdaptyUIBuilder 模块，例如[自定义本地化解析器](localizations-and-locale-codes#pick-a-flows-localization-in-your-own-code)的协议。若要在代码中使用这些类型，请将 AdaptyUIBuilder 添加到你的应用中：

1. 在 Xcode 中，进入应用目标的 **General** 标签页，在 **Frameworks, Libraries, and Embedded Content** 下，从 AdaptySDK-iOS 包中添加 **AdaptyUIBuilder**。
2. 在每个使用这些类型的文件中，添加 `import AdaptyUIBuilder`。
