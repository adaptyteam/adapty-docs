## 开始之前 \{#before-you-start\}

你需要：

- **Adapty Flutter SDK 4.4 或更高版本**：旧版本会对每个自定义元素显示备用付费墙。
- **iOS 和 Android 的原生代码**：自定义元素中无法显示 Flutter widget。iOS 请使用 Swift 编写代码，Android 请使用 Kotlin 编写代码。将 Swift 代码添加到 Xcode 的 `Runner` target，将 Kotlin 代码添加到 `MainActivity.kt` 所在的文件夹中。每个新建的 Kotlin 文件开头须包含与 `MainActivity.kt` 相同的 `package` 行。
- **自定义元素命名规范**：为每个原生视图指定一个 Type，例如 `lottie_animation`。Type 中只能使用小写字母、数字和下划线。若要区分同一 Type 下的不同自定义元素，可为每个元素指定一个 ID，例如 `welcome_wave`。代码中的 Type 和 ID 必须与 [Flow & 付费墙编辑工具](flow-custom-elements#add-and-configure) 中的设置保持一致。

在你的 iOS 和 Android 代码中使用相同的类型和 ID。除非你为每个平台单独设置了[目标受众](audience)，否则 iOS 和 Android 用户会看到相同的流程。

## 配置你的 Android 项目 \{#set-up-your-android-project\}

iOS 项目无需额外配置。在 Android 项目中，添加 Adapty UI 库。若要将原生视图构建为可组合项，还需配置 Jetpack Compose。

### 添加 Adapty UI 库 \{#add-the-adapty-ui-library\}

在你的 Android 应用模块的 Gradle 文件（例如 `android/app/build.gradle.kts`）中，将 `implementation("io.adapty:android-ui")` 添加到 `dependencies` 块中。请勿添加版本号或 Adapty BOM：`adapty_flutter` 会设置版本，而更新的 `android-ui` 可能会破坏流程。

```kotlin showLineNumbers title="android/app/build.gradle.kts"
dependencies {
    implementation("io.adapty:android-ui")
}
```

### 设置 Jetpack Compose \{#set-up-jetpack-compose\}

Flutter 模板不会在 app 模块中[设置 Compose](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)。Android `View` 无需 Compose 配置。若要将原生视图构建为 composable，请将 Compose 编译器 Gradle 插件添加到 `android/settings.gradle.kts`，并指定 Kotlin 插件 `org.jetbrains.kotlin.android` 的版本：

```kotlin showLineNumbers title="android/settings.gradle.kts" {4}
plugins {
    // the other plugins of your project
    id("org.jetbrains.kotlin.android") version "2.1.0" apply false
    id("org.jetbrains.kotlin.plugin.compose") version "2.1.0" apply false
}
```

然后将插件应用到 app 模块，并在 `buildFeatures` 块中设置 `compose = true`：

```kotlin showLineNumbers title="android/app/build.gradle.kts" {4,8-10}
plugins {
    // the other plugins of your app module
    id("dev.flutter.flutter-gradle-plugin")
    id("org.jetbrains.kotlin.plugin.compose")
}

android {
    buildFeatures {
        compose = true
    }
}
```

如需在此页面使用 Lottie 视图，还需添加 `com.airbnb.android:lottie-compose`。

## 为自定义元素创建视图 \{#create-views-for-custom-elements\}

### 要求与最佳实践 \{#requirements-and-best-practices\}

- **尺寸**：
  - **内边距与对齐**：确保原生视图适配你在 Flow & Paywall Builder 中为其分配的容器（减去内边距）。如果视图未占满整个区域，默认显示在该区域的起始角落。若要移动它，请在自定义元素的 **Layout** 部分更改对齐方式。
  - **自适应高度**：如果自定义元素的高度设置为 **Hug**，一个会拉伸以填满可用空间的视图（如地图或懒加载列表）将会折叠，或拉伸至屏幕高度。请为自定义元素设置[**Fixed** 高度](flow-custom-elements#add-and-configure)。
- **主题**：原生视图不会继承 Flutter 主题的颜色和字体，需在原生代码中单独设置。
- **流程操作**：原生视图无法执行流程操作，例如跳转到下一屏。元素上下文可以通过 iOS 的 `sendMessage` 和 Android 的 `send` 向流程发送消息，但这些功能保留供未来的 Flow & Paywall Builder 能力使用。请将导航按钮、购买按钮及其他带有流程操作的按钮放在自定义元素之外。
- **可选择元素**：请将自定义元素放在产品卡片和其他[可选择元素](flow-selectable-elements)之外。当选择状态发生变化时，原生视图可能会丢失其状态。
- **导航处理**：当用户切换到下一屏时，SDK 会将原生视图从屏幕中移除。请停止视图启动的所有任务，例如相机会话、播放器和位置更新：
  - **SwiftUI 视图**：使用 `onDisappear` 操作。对于异步任务，使用 `.task`：视图消失时 SwiftUI 会自动取消它。
  - **Composable**：使用 `DisposableEffect` 的 `onDispose` 块。对于异步任务，使用 `LaunchedEffect`：Composable 离开组合时 Compose 会自动取消它。
  - **Android `View`**：在 `View` 子类中重写 `onDetachedFromWindow`，或为 `View` 添加 `View.OnAttachStateChangeListener`。

  当用户返回时，SDK 会再次调用解析器，原生视图将以全新状态启动，不保留之前的状态。在 Android 上，通过 `present()` 打开的流程中，旋转屏幕会触发 SDK 重新调用解析器。而在嵌入式 `AdaptyUIFlowPlatformView` 中，原生视图在旋转后会保留其状态。
- **UIKit 视图**：在 iOS 上，请将其包装在 `UIViewRepresentable` 中。
- **轮播图**：在 Android 上，[轮播图](builder-containers#carousel) 中所有幻灯片的原生视图在页面打开期间均保持活跃状态，而不仅限于当前可见幻灯片上的视图。请勿在轮播图中使用摄像头预览或带音频的播放器。

## 编写解析器以匹配自定义元素和视图 \{#write-a-resolver-to-match-custom-elements-and-views\}

为每个平台编写一个解析器。解析器接收自定义元素的 Type 和 ID，并返回对应的原生视图。

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

编写解析器时，需要让某个类型遵循 `AdaptyUICustomElementsResolver` 协议，并实现 `view(forType:id:context:)` 方法。

对于 `lottie_animation` Type，以下解析器返回 `LottieElementView`。ID 对应应用包中的动画文件名，例如 `welcome_wave`：

```swift showLineNumbers title="Swift"

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "lottie_animation":
            // the ID names the animation file, such as welcome_wave.json
            guard let animation = LottieAnimation.named(id) else {
                return nil // no file for this ID: show the fallback
            }
            return AnyView(LottieElementView(animation: animation))
        default:
            return nil
        }
    }
}
```

在 `default` 情况下，返回 `nil`。

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

To write a resolver, implement the `AdaptyCustomElementsResolver` interface. Its `resolve` method returns the matching view in one of the following forms:

- **一个 Composable**：返回 `AdaptyCustomElementContent.compose`，并在其 lambda 中传入 Composable。
- **一个 Android `View`**：返回 `AdaptyCustomElementContent.view`，并传入一个创建 `View` 的函数。务必为 `factory` 参数显式命名：`AdaptyCustomElementContent.view(factory = { context, _ -> ChartView(context) })`。若不命名，Kotlin 会将尾随 lambda 传给可选的 `update` 参数，导致代码无法编译。

对于 `lottie_animation` 类型，以下 resolver 返回 [Lottie 视图](#create-views-for-custom-elements)。ID 指定 `assets` 文件夹（`android/app/src/main/assets`）中的动画文件名，例如 `welcome_wave` 对应 `welcome_wave.json`：

```kotlin showLineNumbers title="Kotlin"

class CustomElementsResolver(context: Context) : AdaptyCustomElementsResolver {
    // the animation files in the assets folder, listed once
    private val animationFiles: Set<String> = try {
        context.assets.list("").orEmpty().toSet()
    } catch (e: IOException) {
        emptySet() // no list of files: every Lottie element shows the fallback
    }

    override fun resolve(type: String, id: String): AdaptyCustomElementContent? =
        when (type) {
            "lottie_animation" -> {
                // the ID names the animation file, such as welcome_wave.json
                val file = "$id.json"
                if (file in animationFiles) {
                    AdaptyCustomElementContent.compose { LottieElement(file) }
                } else {
                    null // no file for this ID: show the fallback
                }
            }
            else -> null
        }
}
```

对于任何其他 Type，返回 `null`。

</TabItem>
</Tabs>

如果你在发布应用后[添加了具有新 Type 的自定义元素](flow-custom-elements#what-changes-require-an-app-release)，已发布版本的用户将看到其备用内容。

解析器有以下要求：

- **网络数据与播放器**：将网络数据和播放器的状态保存在[原生视图](#create-views-for-custom-elements)中，而不是解析器中。SDK 在屏幕打开期间会多次调用解析器，解析器中的代码每次调用时都会重新执行，因此网络请求会重复发送，播放器也会重新开始。原生视图在多次调用之间保持其状态，所以数据只加载一次，播放器也能持续播放。请在原生视图内创建播放器、会话和网络请求：
  - **SwiftUI 视图**：在 `.task` 或 `@StateObject` 中创建播放器、会话和网络请求，而不是在 `@State` 属性的初始值中。Swift 在解析器每次创建视图时都会重新计算该初始值。
  - **Composable**：在 `remember` 中创建播放器和会话，在 `LaunchedEffect` 中发起网络请求。
  - **Android `View`**：在 `onAttachedToWindow` 中创建播放器、会话和网络请求。
- **每个自定义元素对应一个原生视图**：某些原生视图在屏幕打开期间会发生变化，例如数据加载完成时或用户点击时。请在原生视图内部实现这些逻辑，而不是在解析器中。如果解析器为同一个自定义元素返回不同的视图，该视图将丢失其状态。
- **每次出现时创建新的 `View`**：在 Android 上，每次调用 `factory` 时都要创建一个新的 `View`。SDK 在每次自定义元素出现时都会调用 `factory`，例如屏幕打开时、用户返回该屏幕时，或在通过 `present()` 打开的流程中发生旋转之后。
- **应用数据**：将保存数据的对象（例如 `ObservableObject` 或带有[每日连签](flutter-custom-element-lottie-animation)的 `StateFlow`）存储在解析器的属性中。将该对象传递给原生视图，并在原生视图中监听它：
  - **SwiftUI 视图**：使用 `@ObservedObject` 监听 `ObservableObject`。
  - **Composable**：使用 `collectAsState` 收集 `StateFlow`，或使用 `observeAsState` 监听 `LiveData`。
  - **Android `View`**：在 `onAttachedToWindow` 中开始监听对象，在 `onDetachedFromWindow` 中停止监听。

  您复制到解析器中的值（例如连续天数）会保持创建解析器时的状态。如果您的 Dart 代码中有相关数据（例如每日连续记录），请通过[平台通道](https://docs.flutter.dev/platform-integration/platform-channels)将每个新值发送到原生代码，并在那里更新对象。

### 设置备用内容的条件 \{#set-conditions-for-fallback-content\}

<FlowCustomElementsFallbackConditions />

仅在用户于屏幕打开前已拒绝某权限时，才返回无视图。在 Android 上，`ContextCompat.checkSelfPermission` 在两种情况下返回相同的值 `PERMISSION_DENIED`：应用首次向用户请求权限之前，以及用户拒绝后。为了区分这两种情况，请保存权限请求的结果，并在解析器中读取已保存的结果。如果应用尚未请求过该权限，则返回原生视图，并在视图内部发起权限请求。例如，在[地图视图](flutter-custom-element-map#3-match-the-map-to-the-custom-element)出现时请求位置访问权限，并在用户授权后立即显示地图。如果你返回无视图，而用户此后授予了权限，他们看到的仍是备用内容。权限变更不会触发 SDK 再次调用解析器。原生视图只有在 SDK 再次调用解析器时才会显示，例如用户返回该屏幕时。

## 将解析器传递给 SDK \{#pass-the-resolver-to-the-sdk\}

在应用启动时，为每个平台设置一次解析器。SDK 会在每个流程中调用它，包括通过 `AdaptyUIFlowPlatformView` 嵌入的流程。用户在新流程和 A/B 测试中无需发布应用更新即可看到您的原生视图。这些视图仍会为每位用户展示其专属数据（例如[每日连签记录](flutter-custom-element-lottie-animation)），因为这些数据直接从您的应用中读取。

### iOS

在 `ios/Runner/AppDelegate.swift` 中，导入 `AdaptyUI`，并在 `application(_:didFinishLaunchingWithOptions:)` 方法中调用 `AdaptyUI.setCustomElementsResolver(_:)`。保持 `AppDelegate` 类的其余部分不变：

```swift showLineNumbers title="ios/Runner/AppDelegate.swift"

// in application(_:didFinishLaunchingWithOptions:), before `return super.application(...)`
AdaptyUI.setCustomElementsResolver(CustomElementsResolver())
```

如果你也在 `AppDelegate.swift` 中编写解析器，还需要在那里导入 `AdaptyUIBuilder`。

### Android

在您的 `Application` 类的 `onCreate` 方法中调用 `AdaptyUI.setCustomElementsResolver`。如果您的应用还没有 `Application` 类，请先创建一个：

```kotlin showLineNumbers title="Kotlin"

class App : Application() {
    override fun onCreate() {
        super.onCreate()
        AdaptyUI.setCustomElementsResolver(CustomElementsResolver(this))
    }
}
```

在 `android/app/src/main/AndroidManifest.xml` 中，通过 `<application>` 的 `android:name` 属性指定你的 `Application` 类。Flutter 模板默认将该属性设为 `${applicationName}`，代表基础 `Application` 类：

```xml showLineNumbers title="AndroidManifest.xml" {2}
<application
    android:name=".App"
    android:label="your_app">
    <!-- the rest of your application element -->
</application>
```

:::tip
若要在某个 Type 的所有自定义元素中显示相同的视图，可以传入一个 Types 与视图的映射表，而不是使用解析器。使用映射表比使用解析器代码量更少，但无法[为备用内容设置条件](#set-conditions-for-fallback-content)。

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

该映射表是一个 `[String: AdaptyUICustomElementBuilder]` 字典。如果你在 `AppDelegate.swift` 中编写映射表，还需要在那里导入 `Lottie`。

```swift showLineNumbers title="Swift"
AdaptyUI.setCustomElementsResolver([
    "lottie_animation": .init { _, id, _ in LottieElementView(animation: .named(id)) },
])
```

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

将映射传递给 `AdaptyCustomElementsResolver.of`：

```kotlin showLineNumbers title="Kotlin"
val appWideViews = mapOf(
    "confetti" to AdaptyCustomElementContent.compose { LottieElement("confetti.json") },
)
AdaptyUI.setCustomElementsResolver(AdaptyCustomElementsResolver.of(appWideViews))
```

</TabItem>
</Tabs>
:::

您无法将 resolver 绑定到单个流程。要在流程中显示 Dart 代码中的数据，请在流程打开前将数据发送到原生代码，然后在 resolver 中读取该数据。例如，付费墙显示[用户在前一个流程中输入的体重](flutter-custom-element-interactive-chart)。

## 在设备上测试 \{#test-on-a-device\}

流程与付费墙编辑工具无法运行你的应用代码，因此画布中只显示备用内容。原生视图中的错误可能导致应用崩溃。在发布应用之前，请在 iOS 设备和 Android 设备上测试每个包含自定义元素的页面：

1. 若想查看每个流程的最新已发布版本而非缓存版本，请将设备注册为[测试设备](test-devices)。
2. 在设备上运行包含解析器的构建版本。打开每个带有自定义元素的页面，确认原生视图已正常显示且与自定义元素匹配。若视图支持滚动或拖拽手势，请一并测试这些交互。
3. 如果显示的是备用视图而非原生视图，请在 Xcode 控制台或 Logcat 中查找以下警告：`custom element <type>:<id> is not served by a resolver`。然后确认：
   - 警告中的 Type 和 ID 与代码中的完全一致，包括每一个字母的大小写。
   - 应用已具备该视图所需的文件、数据或权限。
   - 应用在启动时已设置解析器：iOS 在 `AppDelegate` 类中设置，Android 在 `AndroidManifest.xml` 指定的 `Application` 类中设置。

   如果警告未出现，请确认应用使用的是 Adapty Flutter SDK 4.4 或更高版本，且[日志级别](sdk-installation-flutter#logging)不是 `AdaptyLogLevel.error`。
4. 在 Android 上，如果自定义元素保持空白，请在 Logcat 中查找以下警告之一：
   - `custom element <type>:<id> is not served by a resolver`：该自定义元素没有备用内容，且没有任何解析器为其返回视图。请逐一核查步骤 3 中的每项内容。
   - `content does not report its size`：该可组合项自身没有高度。请为自定义元素设置[**固定**高度](flow-custom-elements#add-and-configure)。

   The SDK only logs the size warning for composables. If an Android `View` stays empty with no warning, give the custom element a **Fixed** height too.
5. To preview the fallback, return no view for the Type, and open the screen again.

## 示例 \{#examples\}

每个示例都展示了编辑工具中的配置以及应用的对应代码：

- [使用 Lottie 动画展示用户进度](flutter-custom-element-lottie-animation)：一个随连续打卡天数增长而填充的环形进度条。
- [在付费墙中展示可交互的体重目标图表](flutter-custom-element-interactive-chart)：付费墙流程中的体重目标图表，位于用户引导流程之后。
- [在流程中展示附近地点地图](flutter-custom-element-map)：展示每位用户附近健身中心的地图。

每个示例均包含完整的 resolver、`AppDelegate` 类和 `App` 类。如需同时使用多个示例，只需保留各一个：合并各 resolver 的 `case` 分支，以及 `AppDelegate` 和 `App` 类中的 store 和 channel。
