欢迎使用！我们致力于让应用内购买变得轻松便捷 🚀

我们构建了 Adapty Flutter SDK，让应用内购买不再令人头疼，让你专注于最擅长的事——打造出色的应用。以下是我们为你处理的一切：

- 开箱即用地处理购买、收据验证和订阅管理
- 无需更新应用即可创建和测试流程与付费墙
- 零配置获取详细的购买分析数据——包含同期群、LTV、流失率和漏斗分析
- 跨会话和设备始终保持用户订阅状态最新
- 只需一行代码即可将应用与营销归因和分析服务集成

:::note
在深入代码之前，你需要先将 Adapty 与 App Store Connect 和 Google Play Console 集成，然后在看板中配置产品。请先查看我们的[快速入门指南](quickstart)，完成所有必要配置。
:::

## 主要概念 \{#main-concepts\}

在深入代码之前，我们先来了解一下 Adapty 的核心概念。

Adapty 方案的妙处在于：只有版位是在应用中硬编码的，其他所有内容——产品、付费墙设计、定价和优惠——都可以在 Adapty 看板上灵活管理，无需更新应用：

1. [**产品**](product) - 应用中可供购买的任何内容——订阅、消耗型商品或永久授权。

2. **流程与付费墙** - 将产品与配置打包，挂载到版位。有两种构建方式，详见[流程与付费墙](flows-and-paywalls)：
   - **[流程与付费墙编辑工具](adapty-flow-builder)** - 可视化无代码界面。Adapty 负责渲染 UI 并处理购买流程。
   - **[自定义付费墙](paywalls)** - 无可视化配置；由你在代码中构建 UI 并自行调用 `makePurchase`。参见[实现自定义付费墙](flutter-quickstart-manual)。

   在 SDK 代码中，两种方式均通过同一个 `getFlow` 方法获取。

3. [**版位**](placements) - 用户旅程中展示流程或付费墙的关键节点，可以理解为变现策略的"在哪里"和"什么时候"。常见版位包括：
   - `main` - 主要付费墙位置
   - `onboarding` - 在用户引导流程中展示
   - `settings` - 从应用设置中进入

   初次集成时，从 `main` 或 `onboarding` 等基础版位入手，然后再[思考应用中还有哪些地方的用户可能已准备好进行购买](choose-meaningful-placements)。

4. [**用户画像**](profiles-crm) - 当用户购买产品后，其用户画像将被分配一个**访问等级**，您可以用它来定义对付费功能的访问权限。
