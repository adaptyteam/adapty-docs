CLI 需要通过身份验证才能调用 Adapty API。

一次登录即可覆盖整个 CLI。[Ads Manager 命令](developer-cli-ads-manager)访问的是不同的服务，但使用相同的已存储令牌——无需第二次登录。

## 登录 \{#log-in\}

登录步骤：

1. 在终端中运行：
   ```bash
   adapty auth login
   ```
2. CLI 会以 `XXXX-XXXX` 格式打印验证码，并在浏览器中打开 Adapty 看板。
3. 在授权页面，确认验证码与终端输出一致。
4. 点击 **Authorize**。浏览器显示"CLI authorized! You can close this tab."
5. 返回终端，CLI 会确认你已完成身份验证。

如果授权码在您完成授权前过期，或者您点击了 **Deny**，请再次运行以下命令重新启动流程：

```bash
adapty auth login
```

## 管理身份验证 \{#manage-authentication\}

### 检查认证状态 \{#check-authentication-status\}

要查看当前的认证状态，请运行：

```bash
adapty auth status
```

认证成功后，输出会显示你的姓名、经过掩码处理的令牌前缀，以及本地配置文件的路径：

```
User: Jane Doe
Token: abcd1234****
Config: ~/.config/adapty/config.json
```

从 CLI 0.9.1 开始，登录时只保存姓名，不保存邮箱。`Email:` 行仅在使用早期版本保存的会话中出现。在读取 `adapty auth status --json` 的脚本中，请使用 `name` 字段来标识用户。

未认证时：

```
Not authenticated. Run `adapty auth login`.
```

### 验证您的令牌 \{#verify-your-token\}

要确认令牌有效并查看您的账户详情，请运行：

```bash
adapty auth whoami
```

与 `adapty auth status` 不同，此命令会向服务器发起实时请求以验证令牌。

### 退出登录 \{#log-out\}

要清除本地存储的凭据，请运行：

```bash
adapty auth logout
```

这将清除 `~/.config/adapty/config.json` 以及由 `adapty migrations create` 或 `adapty migrations use` 保存的迁移记录。令牌在服务端仍然有效，直到其自然过期——如果需要立即使令牌失效，请改用 `adapty auth revoke`。

### 撤销令牌 \{#revoke-your-token\}

要在服务器端使令牌失效并清除本地令牌，请运行：

```bash
adapty auth revoke
```

如果该令牌保存了迁移记录，CLI 也会一并清除，但前提是服务器确认撤销成功。当你需要完全使令牌失效时（例如凭据可能已泄露），请使用此命令。撤销后，运行 `adapty auth login` 重新进行身份验证。

## 令牌错误 \{#token-errors\}

如果令牌被撤销或变为无效，CLI 命令将返回 401 错误。要重新进行身份验证，请运行：

```bash
adapty auth login
```
