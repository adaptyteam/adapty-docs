在 iOS 上可靠地获取流程或付费墙需要做到三点：渲染速度快、返回面向目标受众的实验变体，以及在网络较慢时能优雅地降级。以下规则涵盖了实现这些目标所需的时机、缓存与备用方案。

:::tip
以下规则假设 `Adapty.activate()` 和 `Adapty.identify()` 已完成调用。详见 [iOS SDK 调用顺序](ios-sdk-call-order)。
:::

## 规则与注意事项 \{#rules-and-pitfalls\}

| 做这个 | 不要做这个 | 原因 |
|---|---|---|
| 获取即将展示的版位，或通过 [`preloadFlows`](#preload-placements)（SDK 4.1+）预热缓存。 | 在启动时自行并发调用多个 `getFlow`。 | 手动批量预取会阻塞主线程并导致黑屏。`preloadFlows` 专为此场景设计，整批共享同一个超时预算。 |
| 在归因有机会完成解析后再调用 `getFlow`——例如，`activate` 之后 1–2 秒，或等 `didLoadLatestProfile` 触发之后。 | 在 `App.init()` 时调用 `getFlow`。 | 归因尚未到位。流程会按默认目标受众解析，悄无声息地绕过市场细分和 ASA 个性化。 |
| 保留默认的 5 秒 `loadTimeout`，或设置其他合理值，并为每个版位配置[备用付费墙](fallback-paywalls)。 | 给 `getFlow` 传入一个大到永远不会触发的 `loadTimeout`。 | 若超时永远不触发，网络较差的用户会看到空白屏幕，直到网络恢复——或者直接关闭应用。 |

当 `loadTimeout` 在 `getFlow` 中触发时，SDK 会返回已缓存的实验变体（若存在），否则在剩余时间内获取默认受众（**All Users**）的实验变体。该请求的定向功能将直接失效，而非延迟处理：市场细分和基于归因的目标受众不会作用于返回结果。

请参阅[获取自定义付费墙和产品](fetch-paywalls-and-products)了解 `fetchPolicy` 和 `loadTimeout` 参数说明，以及[版位](placements)以选择合适的版位。

## 预加载版位 \{#preload-placements\}

:::info
`preloadFlows` 和 `preloadFlowsForDefaultAudience` 从 SDK 版本 4.1 起可用。
:::

`preloadFlows` 会提前缓存流程 JSON——每个版位发起一次请求。之后按常规方式使用即可：`getFlow` 获取流程，`getFlowConfiguration` 获取其视图配置。

`fetchPolicy` 决定后续 `getFlow` 优先从哪一层读取数据，而不是决定是否能访问缓存：

- `.returnCacheDataElseLoad` 优先读取预加载的缓存副本，仅在缓存为空时才发起网络请求。`.returnCacheDataIfNotExpiredElseLoad(maxAge:)` 的逻辑相同，但额外要求缓存副本的存活时间不超过 `maxAge`。
- 默认策略 `.reloadRevalidatingCacheData` 优先走网络，仅在请求失败或超时时才回退到预加载的缓存副本。

两种策略都能从预加载中受益，但方式不同：缓存优先策略会直接省去网络请求，而默认策略则保留网络请求，同时将缓存作为兜底备份。

当你知道本次会话需要哪些版位、但暂时不想展示时，可以使用此方法——例如，在 `activate` 和 `identify` 完成后，提前预加载用户还未点击的按钮背后的流程。

<Tabs groupId="current-os" queryString>
<TabItem value="swift" label="Swift" default>

```swift showLineNumbers
try await Adapty.preloadFlows(
    placementIds: ["onboarding", "main_paywall"],
    loadTimeout: 5
)

// Later, when the user reaches the paywall:
let flow = try await Adapty.getFlow(
    placementId: "main_paywall",
    fetchPolicy: .returnCacheDataElseLoad
)
```

</TabItem>
<TabItem value="callback" label="Swift-Callback">

```swift showLineNumbers
Adapty.preloadFlows(placementIds: ["onboarding", "main_paywall"], loadTimeout: 5) { error in
    if let error {
        // at least one placement failed to preload
    }
}

// Later, when the user reaches the paywall:
Adapty.getFlow(placementId: "main_paywall", fetchPolicy: .returnCacheDataElseLoad) { result in
    // ...
}
```

</TabItem>
</Tabs>

**参数：**

- `placementIds`（必填）：需要预加载的版位。空白和重复的 ID 会被忽略。
- `loadTimeout`（可选）：整批请求的超时时间（单位：秒），而非单个版位的超时时间。默认为 5 秒，低于 1 秒的值会被自动调整为 1 秒。

**需要了解的行为：**

- 该方法仅在尝试所有版位后才会抛出异常，错误信息会汇总各版位的失败情况。某个版位失败不会影响其他版位的处理。
- 如果某个版位超时或遇到网络错误，SDK 会回退到该版位的默认目标受众变体。其他类型的失败则直接上报原始错误。
- 如果超时在面向特定目标受众的请求完成前触发，SDK 仍会在剩余时间内尝试获取默认目标受众的变体。
- 预加载仅用于预热缓存，不返回任何内容——你仍需调用 `getFlow` 来展示它。

### 预加载的覆盖范围 \{#what-a-preload-covers\}

一个流程到达屏幕需要经历多个层级。预加载与 `getFlow` 一样，只覆盖第一层：

| 层级 | 由谁获取 | 是否被预加载预热 |
|---|---|---|
| 流程 JSON — 所选实验变体、其产品 ID 及远程配置 | `getFlow` | 是 |
| UI 布局 — 屏幕的结构、样式和文本 | `getFlowConfiguration` | 否 |
| 图片，包括用于替代视频元素的静态帧 | `getFlowConfiguration`（后台处理）| 否 |
| 视频文件 | 系统播放器，在屏幕渲染时加载 | SDK 不缓存 |

`getFlowConfiguration` 会按以下顺序在三个地方查找布局：

1. SDK 的磁盘缓存，该缓存在应用重启后依然保留。
2. 适用于 SDK 4.4 及更高版本的[备用文件](ios-use-fallback-paywalls)，前提是该文件是在你最后一次发布流程之后下载的。
3. 通过网络请求 Adapty。即使已预加载，仍需一次网络往返。每当应用首次展示某个已发布版本的流程时，SDK 都会发起此请求，然后将布局保存到磁盘缓存。

一旦 SDK 获取到布局，就会在后台独立缓存图片，不会阻塞屏幕，也不会通过回调、代理方法或错误来报告缓存完成的时机。

当 `getFlowConfiguration` 的 `loadTimeout` 超时触发时，SDK 不会回退到备用方案，而是重新向 Adapty API 请求布局。`loadTimeout` 不会限制这次二次请求的时间。

### 查找失败的版位 \{#find-out-which-placement-failed\}

抛出的错误是一个覆盖整个批次的 `AdaptyError`，错误码为 `networkFailed`（2005）。如需查看各版位的具体失败信息，请读取其 `preloadErrors` 属性——这是一个以版位 ID 为键的字典：

```swift showLineNumbers
do {
    try await Adapty.preloadFlows(placementIds: ["onboarding", "main_paywall"])
} catch {
    for (placementId, placementError) in error.preloadErrors ?? [:] {
        // log or retry the individual placement
    }
}
```

`preloadErrors` 对于任何非预加载调用产生的错误均为 `nil`，因此将 `nil` 值视为"非预加载失败"而非"无失败"。

### 跳过目标受众细分 \{#skip-audience-segmentation\}

若要在完全不等待目标受众细分的情况下预热缓存，请使用默认受众实验变体：

```swift showLineNumbers
try await Adapty.preloadFlowsForDefaultAudience(placementIds: ["main_paywall"])
```

## 从应用包中加载首屏媒体资源 \{#show-first-screen-media-from-the-app-bundle\}

流程会从 Adapty 下载图片和视频。若要让首屏媒体资源立即显示，可以从应用包中直接提供。这样可以复用已随应用分发的媒体资源，例如现有原生用户引导中的视觉素材。

1. 在 Flow & Paywall Builder 中，为图片或视频设置[自定义媒体 ID](custom-media#custom-media-id)。您在那里上传的文件将作为备用资源。
2. 将该文件添加到应用包中。
3. 调用 `getFlowConfiguration` 时，通过 `assetsResolver` 为该 ID 传入应用包中的文件：

<Tabs groupId="ios-sdk-version" queryString>
<TabItem value="4.5" label="SDK 4.5 或更高版本" default>

```swift showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
let bundledAssets: [String: AdaptyCustomAsset] = [
    "welcome_video": .video(
        .file(
            url: Bundle.main.url(forResource: "welcome", withExtension: "mp4")!,
            preview: .uiImage(value: UIImage(named: "welcome_poster")!),
            resolution: CGSize(width: 1080, height: 1920)
        )
    ),
]

let flowConfig = try await AdaptyUI.getFlowConfiguration(
    forFlow: flow,
    preferredLocales: Locale.preferredLanguages,
    assetsResolver: bundledAssets
)
```

</TabItem>
<TabItem value="4.4" label="SDK 4.0–4.4">

```swift showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
let bundledAssets: [String: AdaptyCustomAsset] = [
    "welcome_video": .video(
        .file(
            url: Bundle.main.url(forResource: "welcome", withExtension: "mp4")!,
            preview: .uiImage(value: UIImage(named: "welcome_poster")!),
            resolution: CGSize(width: 1080, height: 1920)
        )
    ),
]

let flowConfig = try await AdaptyUI.getFlowConfiguration(
    forFlow: flow,
    assetsResolver: bundledAssets
)
```

</TabItem>
</Tabs>

打包的文件会增加应用的下载体积，因此只打包用户首屏可见的媒体资源。

打包的图片无需等待即可显示，但 SDK 仍会在后台下载已上传的图片。

未打包的媒体资源同样会立即显示：视图配置为每张图片（包括视频的静帧）携带一份低分辨率副本，并在完整文件加载完成前持续展示该副本。

完整的 `assetsResolver` 参考文档，请参阅[自定义资源](get-pb-paywalls#customize-assets)。

## 针对弱网环境进行调优 \{#tune-for-poor-connectivity\}

对于网络连接质量持续较差的市场（农村地区、交通沿线、受路由影响的地区）：

- 在除首次以外的所有请求中设置 `fetchPolicy: .returnCacheDataElseLoad`。
- 在 Adapty 看板中为每个版位配置[备用付费墙](fallback-paywalls)。
- 根据速度与精准定向之间的权衡来调整 `loadTimeout`。超时时间越短，用户越早看到备用内容；超时时间越长，目标流程就有更多时间加载。
- [保持流程轻量化](flow-size)，以便布局下载更快。
- 不要将流程展示与 `getProfile()` 绑定。独立调用 `getFlow`，避免因用户画像加载缓慢而阻塞 UI。
