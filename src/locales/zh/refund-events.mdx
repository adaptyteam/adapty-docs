退款事件数据图表展示了有多少购买和订阅发生了退款。Adapty 将每个退款事件关联到退款发起的日期，而非订阅开始的日期。

## 计算方式 \{#calculation\}

Adapty 统计所选时间段内所有已退款的购买或订阅。每笔退款按退款发生日期归因，而非订阅开始日期。试用期的退款不计入统计，因为试用期不产生收入。

在 App Store 中，升级操作也会被计为退款。当订阅者升级时，Apple 会退还旧订阅当前周期的未使用部分，Adapty 会以"升级"作为退款原因进行记录。如需排除升级产生的退款，请按 **Refund Reason** 筛选。同一产品在预付方案与 [12 个月承诺方案](app-store-12-month-commitment)之间切换也会计为退款，退款原因相同。若切换在当前计费周期结束时生效，此类退款的收入金额为零。

## 数据图表如何处理退款 \{#how-metrics-handle-refunds\}

不同的数据图表对退款的处理方式各不相同。同一笔退款事件，在某张图表中可能立即减少当期数值，在另一张图表中可能追溯修改历史数据，而在第三张图表中则完全不受影响。下表列出了各数据图表的处理规则。

| 数据图表 | 是否计入退款？ | 归因日期 | 是否可为负值？ | 备注 |
| --- | --- | --- | --- | --- |
| [Revenue](revenue) | 是 | 退款日期——而非原始购买日期 | 是——当某天退款金额超过新增收入时 | 收入 = 总交易额 − 退款金额。 |
| [MRR](mrr) | 是，追溯计算 | 订阅从其所有活跃周期中移除 | 否 | 发生退款后，历史周期的数值可能下降。 |
| [ARR](arr) | 是，追溯计算 | 同 MRR | 否 | 发生退款后，历史周期的数值可能下降。 |
| [ARPU](arpu) | 是 | 退款日期 | 是（退款较多的周期） | 退款会从收入分子中扣减。 |
| [ARPPU](arppu) | 是，仅分子部分 | 退款日期 | 是（退款较多的周期） | 退款会从收入分子中扣减。已退款用户仍计入付费用户分母，因此大量退款会使 ARPPU 下降幅度超出预期。 |
| [Active subscriptions](active-subscriptions) | 是，追溯计算 | 订阅从计数中移除 | 否 | |
| [New subscriptions](reactivated-subscriptions) | **否** | — | 否 | 计数包含后续被退款的订阅。可结合 [Refund events](refund-events) 评估净影响。 |
| [Refund money](refund-money) / [Refund events](refund-events) | 退款**即为**数据本身 | 退款日期 | 否（始终 ≥ 0） | |
| [Retention](analytics-retention) | **否** | — | 否 | 已退款用户仍保留在留存曲线中。这可能使留存率看起来高于同期群的 [Active subscriptions](active-subscriptions) 或 [Revenue](revenue)。 |
| [Cohort revenue](analytics-cohorts) | 是，累计计算 | 退款日期 | 否（累计扣减不会使同期群收入低于零） | 退款发生时从同期群收入中扣减。其他同期群数据图表的退款处理方式，请参阅 [Cohorts > Refund handling](analytics-cohorts#refund-handling)。 |
| [Custom paywall metrics](paywall-metrics) / [A/B test metrics](results-and-metrics)（计数） | **否** | — | 否 | 这些页面上的订阅者数、付费订阅者数和 ARPPU 计数不扣减退款。 |
| GCS / S3 导出 | 退款作为独立事件行 | `event_datetime` = 退款时间戳 | 聚合时净值列可为负数 | 退款行携带 `is_refund = true`（S3/GCS）或事件类型 `subscription_refunded`（Webhooks）。 |

### 负值 \{#negative-values\}

在聚合视图中（Revenue 数据图表、导出的自定义分析），当某个时间段或分组内的退款金额超过同期新增收入时，该数据图表可能显示为负值。这不是 bug，而是按设计逻辑正常运算的结果。

举例来说：某个国家/地区在周二没有新的购买记录，但当天处理了一笔 100 美元的退款（对应此前的旧订单）。那么该国家/地区周二的收入就会显示为 −$100。
