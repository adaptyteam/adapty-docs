**用户画像**代表项目中的一位用户。**Profiles** 页面列出了 Adapty Mail 中的所有用户，并展示每个人的购买结果、邮件互动情况以及完整的活动记录。

用户画像会通过你配置的任意[入口点](mail-entry-points)自动进入系统。电子邮件地址是必要条件：如果用户没有提供邮箱，Adapty Mail 不会为其创建用户画像。

:::tip
如需将用户画像归入可复用的目标受众以用于流程和 A/B 测试，请参阅[市场细分](mail-segments)。
:::

## 用户画像如何进入 Adapty Mail \{#how-profiles-get-into-adapty-mail\}

Adapty Mail 自动从三个来源创建用户画像：

- **Adapty**：Adapty SDK 从你的应用收集电子邮件和购买记录。请参阅[将 Adapty 连接至 Adapty Mail](mail-collect-emails)。
- **Adapty Mail API**：你的后端通过服务器间通信发送用户画像和交易数据。请参阅[通过 API 发送数据](mail-send-data-via-api)。
- **FunnelFox**：你的网页漏斗转发电子邮件、购买记录和订阅事件。请参阅[将 FunnelFox 连接至 Adapty Mail](mail-funnelfox)。

Adapty Mail 通过电子邮件地址匹配用户。两个来源报告相同的地址时，会归并到同一个用户画像；两个不同的地址则会创建独立的用户画像，即使 `customer_user_id` 相同也是如此。每个来源会保留各自的用户标识符，用户画像页面会在 **External Profile IDs** 下列出所有标识符。

如果您同时使用 Adapty，这里的用户画像并不等同于您的 Adapty 用户画像。Adapty Mail 维护独立的记录，并将 Adapty 用户画像 ID 作为外部 ID 之一存储。这里的用户画像数量通常少于 Adapty，因为没有电子邮件地址的 Adapty 用户画像不会同步过来。

您无法在此处创建或编辑用户画像——拥有这些数据的是发送它们的来源——但您可以取消订阅或删除它们。

## 用户画像列表 \{#the-profiles-list\}

列表按时间倒序显示，每行一个用户画像。可通过搜索框按邮箱、用户画像 ID 或外部用户画像 ID 查找用户画像。

| 列 | 显示内容 |
| --- | --- |
| Profile | 客户的邮箱地址，以及其最近一次邮件事件所关联的营销活动。 |
| Status | 用户画像的购买状态。详见[用户画像状态](#profile-status)。 |
| Country | 客户所在国家。 |
| Open rate | 邮件打开数除以邮件发送数。若尚未发送任何邮件，则显示短横线。 |
| LTV | 生命周期价值——该用户画像在所有来源的总收入。 |
| Joined | 用户画像首次进入 Adapty Mail 的时间。 |
| Last activity | 用户画像最近一次邮件事件的发生时间。发送行为即计入统计，不限于打开或点击。 |

:::important
**Joined** 是用户画像首次进入 Adapty Mail 的日期，用作"客户起始日期"。该日期为数据摄入时间，而非您应用中的原始注册日期。
:::

### 用户画像状态 \{#profile-status\}

**Status** 列显示用户画像的购买状态——用户购买了什么以及是否仍处于活跃状态。该列与用户是否接收您的邮件无关。

| 状态 | 含义 |
| --- | --- |
| Never purchased | 用户尚未购买任何内容。 |
| Purchased | 用户完成了一次性购买。 |
| Active subscriber | 用户拥有有效的付费订阅，且设置为自动续订。 |
| Renewal cancelled | 自动续订已关闭；访问权限在当前周期结束前有效。 |
| Billing issue | 续订付款失败。 |
| Grace period | 付款失败，但在商店的宽限期内仍可继续访问。 |
| Churned | 订阅已到期，访问权限已终止。 |
| Refunded | 购买已退款。 |

:::note
用户画像可以是**活跃订阅者**，但同时**退订**了你的邮件；也可以是**已流失**状态，但仍**订阅**了邮件。邮件状态显示在用户画像页面上，控制 Adapty Mail 是否可以向该用户画像发送邮件。
:::

## 用户画像详情 \{#profile-details\}

点击用户画像，打开其详情页。

### 用户画像头部信息 \{#the-profile-header\}

头部信息用于标识客户：电子邮件、国家/地区、性别、年龄、平台以及"成为客户日期"。此外还包含三个标签：

- **购买状态**：用户画像的购买状态，取值参见[用户画像状态](#profile-status)。
- **打开率**：该用户画像的邮件打开次数与已发送邮件数量之比。[Analytics](mail-analytics) 统计的是至少打开过一次的收件人数，而非邮件数，因此两个数字会有所不同。
- **已订阅** 或 **已退订**：该用户画像的邮件接收权限，与 **Status** 中的付费订阅状态无关。

**已订阅**表示没有任何障碍阻止发送——并不意味着已有任何内容被安排发送。用户画像仍需匹配流程中的某个市场细分，且[双重确认订阅](mail-double-opt-in)会在用户确认地址之前暂停发送营销邮件。**已取消订阅**涵盖所有导致停止发送的原因：退信或垃圾邮件举报与实际取消订阅显示相同的标记，[邮件停止发送的原因](mail-suppression)一文对此有详细说明。

### 参与度数据图表 \{#engagement-metrics\}

页面顶部显示五项数据图表：

- **已发送**：发送给用户画像的邮件数。
- **已送达**：邮件服务商成功接收的邮件数。
- **已打开**：收件人打开邮件的次数，包含重复打开。
- **已点击**：收件人点击链接的次数。
- **收入**：包含两项数值——归因收入和生命周期价值。

:::note
**归因收益**是由您的电子邮件驱动的收益：即客户点击邮件中的链接后完成的购买。**生命周期价值（LTV）**是该用户画像在所有渠道的总收益，无论电子邮件是否参与其中。标题栏先显示归因收益，再显示 LTV。
:::

### 用户画像卡片 \{#the-profile-card\}

**Profile** 卡片列出了客户的各项属性：

- **Platform**：客户最近使用设备的平台，如 iOS 或 Android。
- **Email provider**：通过域名 MX 记录识别的邮箱服务商——**Google**、**iCloud**、**Proton** 等。**Disposable** 表示一次性地址服务，此类地址会[验证失败](mail-suppression#address-verification-failed)，并在到达时即被屏蔽。
- **Country**：客户所在国家。
- **Store country**：客户 App Store 或 Google Play 账号所在国家。
- **Gender**：客户的性别（如已知）。
- **Age**：客户的年龄，以及来源发送的生日信息。
- **Profile ID**：Adapty Mail 为该用户画像分配的内部标识符。

**External Profile IDs** 每个来源（**Adapty**、**FunnelFox** 或 **Custom**）列出一条记录，包含该来源对此用户的标识符及首次接收时间。**Custom attributes** 列出来源发送的键值对。

<ZoomImage id="mail-profile-detail.webp" width="700px" alt="用户画像详情页，展示互动数据指标、用户画像卡片和购买状态卡片" />

### 购买状态 \{#purchase-state\}

**购买状态**卡片展示用户画像的收入和购买历史记录。顶部显示生命周期价值，其下为周期性收入，随后包含最多两个部分：

- **订阅**：价格、商店、开始日期、产品 ID，以及一个标签——访问有效期间显示**续订时间**，到期后显示**已过期**。
- **一次性购买**：最近一次一次性购买的价格、商店、购买日期和产品 ID。

如果用户同时拥有两者，每个部分都会显示各自的状态标签。如果用户尚未购买任何内容，卡片则显示**暂无购买记录**。

### 市场细分 \{#segments\}

**Segments** 卡片显示该用户画像当前匹配的市场细分数量，并列出具体内容；点击其中任意一个即可打开。如果没有匹配项，卡片将显示 **Not in any segment**。Adapty Mail 在每次请求时都会重新运行筛选条件，因此列表始终反映最新的用户画像数据。[市场细分](mail-segments)介绍了如何创建它们。

## 活动历程 \{#the-activity-journey\}

**Journey**（历程）部分以时间轴形式记录了该用户画像的所有活动，从 **Profile created**（用户画像创建）开始。电子邮件事件与交易事件交替显示在同一列表中。

### 邮件事件 \{#email-events\}

Adapty Mail 发送的每封邮件都会生成一条记录。展开条目可查看收件人点击的链接以及该邮件带来的购买情况。标签会显示邮件的投递进度：

| 状态标签 | 含义 |
| --- | --- |
| **Scheduled** | 该邮件已设置发送时间，Adapty Mail 尚未发送。 |
| **Sent** | Adapty Mail 已发送邮件，但尚未收到投递确认。 |
| **Delivered** | 接收方邮件服务器已接受该邮件。此标签将替换 **Sent**。 |
| **Opened** | 跟踪像素已加载。 |
| **Clicked** | 收件人点击了链接。展开邮件可查看具体点击的链接及其带来的购买记录。 |
| **Confirmed** | 收件人通过[双重确认](mail-double-opt-in)邮件完成了地址验证。 |
| **Bounced** | 接收方邮件服务器拒绝接收该邮件并将其退回。 |
| **Spam report** | 收件人将该邮件标记为垃圾邮件。 |
| **Unsubscribed** | 收件人已退订。 |
| **Delayed** | 接收方邮件服务器要求 Adapty Mail 稍后重试。 |
| **Throttled** | 所有发送域均已超出[每日限额](mail-suppression#throttle-temporary-delays-and-cancellations)，邮件正在等待发送。 |
| **Cancelled** | 该邮件不会被发送。购买行为、退订、退信、垃圾邮件举报、账号删除或二次限流均会取消序列中剩余邮件的发送——详见[邮件停止发送的原因](mail-suppression)。 |

### 事务事件 \{#transaction-events\}

每条记录代表一个订阅或一次性购买的里程碑节点。旅程视图会用通俗易懂的标签替代原始的 `event_type`：

| `event_type` | Journey 标签 |
| --- | --- |
| `subscription_started` | 订阅已开始 |
| `subscription_renewed` | 订阅已续费 |
| `subscription_renewal_cancelled` | 续费已取消 |
| `subscription_renewal_reactivated` | 续费已恢复 |
| `billing_issue_detected` | 扣款问题 |
| `entered_grace_period` | 已进入宽限期 |
| `subscription_expired` | 订阅已过期 |
| `subscription_refunded` | 订阅已退款 |
| `non_subscription_purchase` | 一次性购买 |
| `non_subscription_purchase_refunded` | 购买已退款 |

这些事件会通过 Adapty SDK 自动传递到 Adapty Mail，您也可以通过 [API](mail-send-data-via-api#send-transaction-events) 手动发送。

## 取消订阅用户画像 \{#unsubscribe-a-profile\}

要停止向某个用户画像发送邮件，打开其页面，点击 **...**，然后选择 **Unsubscribe**。Adapty Mail 会将该用户画像标记为已取消订阅，并将其添加到屏蔽名单，使其在营销活动和流程中被跳过。

一旦用户画像因任何原因被屏蔽，菜单项将显示为 **Unsubscribed** 且保持禁用状态。[邮件停发的原因](mail-suppression)介绍了收件人自行取消订阅的两种方式。

## 删除用户画像 \{#delete-a-profile\}

删除用户画像可清除 Adapty Mail 中该用户的所有存储信息——例如响应数据删除请求。

要删除用户画像，请打开其页面，点击 **...**，选择 **Delete**，然后确认。Adapty Mail 随后将：

- 清除电子邮件地址及所有个人属性：姓名、性别、生日、国家、商店国家、设备信息和自定义属性。
- 取消该用户画像中所有已排期的邮件。
- 从 Profiles 页面中移除该用户画像。

此操作无法撤销。购买记录会保留下来，但不再关联任何个人身份信息，因此收入统计数据不受影响。

删除并不会屏蔽该邮箱地址。如果数据源再次发送该地址，Adapty Mail 将创建一个全新的用户画像，与已删除的用户画像毫无关联。若需永久阻止某人，请从源头停止发送其数据。

您的后端也可以通过 [Delete profile](api-mail/operations/deleteProfile) 接口来删除用户画像。
