[growth-advisor 技能](export-analytics-with-ai)可以每周自动检查你的应用：收入是否处于正常水平，以及正在进行的 A/B 测试是否已准备好做出决策。检查以定时任务的形式在你的 AI 智能体中运行。每次运行都会读取你的 Adapty 数据并汇报变化情况，汇报位置可以是你的智能体，也可以是你的团队日常查看的地方，例如 Slack 频道。每次运行不会对你的账户做任何修改，直到你对报告做出回应。

:::note
检查是 AI 代理调度器中的一个任务，而不是 Adapty 中的设置。它只在代理能够运行计划任务时才会执行，例如当你的电脑开着，或者如果代理支持云端运行时在云端执行。
:::

## 可以定期执行的检查 \{#checks-you-can-schedule\}

| 检查 | 默认计划 | 报告内容 |
|---|---|---|
| **应用健康状况** | 每周一 9:00 | 过去 7 天与正常一周的对比：收入、新付费订阅、新试用、安装量和退款，并给出总体评价。同时列出[待办事项](autopilot)中的待处理项，例如已结束但未得出结论的测试。月度检查则对比最近 28 天与此前 28 天的数据。 |
| **单个 A/B 测试** | 每周一和周四 9:00 | 测试是否处于**尚未就绪**、**可以决策**状态，或者自设置检查以来是否发生了**变化**（如实验分组、流量权重或目标受众的变更）。显示每个分组距离约 200 次购买还差多少。只有在数据稳定后才会指定领先者。 |
| **所有运行中的 A/B 测试** | 每周一 9:00 | 每个正在运行的付费墙或流程 A/B 测试各占一个区块，优先显示可以决策的测试：包括其版位、已运行天数、各分组的购买量，以及是否已确定领先者。 |

您可以自行设置计划。以下默认值是在您未作说明时由技能建议的。

每次 A/B 测试检查在测试结束后即完成。一旦测试停止且其假设已得出结论，报告会说明检查任务已无需执行，并标注待删除的任务。

## 设置检查 \{#set-up-a-check\}

如需设置检查，可以这样向智能体发出指令，例如：

```
Check my app every Monday and tell me if something is off.

Tell me when my onboarding A/B test is ready to decide.

Send a weekly report on my running A/B tests to the #growth channel in Slack.
```

该技能也会主动发起检查：在完成[健康检查](export-analytics-with-ai#health-check)之后，以及将线上 A/B 测试与其假设关联之后。如果同一应用已存在检查任务，且智能体可以列出其任务列表，技能会建议修改现有检查，而不是新增第二个。

在创建任务之前，该技能会询问两件事：

1. **执行频率**：保持默认计划，或自行指定。
2. **报告发送位置**：默认情况下，报告会显示在代理执行定时任务的地方，例如其聊天界面或通知中心。如需将报告发送到其他地方，请在代理的连接器或 MCP 设置中接入支持发送消息或写入页面的工具，例如 Slack、邮件、Teams、Notion 或 Linear，然后指定具体的频道、地址或页面。该技能不会自动为你选择。

该技能随后使用你的代理自带的调度工具创建任务，并以检查项命名，例如 `Adapty: health for Snapshot` 或 `Adapty: tests for Snapshot`。

### 检查运行位置 \{#where-the-check-runs\}

- **在您的计算机上**：检查使用您在此计算机上的 Adapty 登录凭据和连接器。
- **在其他计算机或云端**：在那里将 `ADAPTY_TOKEN` 环境变量设置为您的 [Adapty CLI 令牌](developer-cli-authentication)，并在那里连接报告工具。技能不会将令牌写入任务提示中。

如果某次运行无法访问您的 Adapty 账户，其完整报告只有一行，提示您在该计算机上重新登录，或在检查运行的地方设置 `ADAPTY_TOKEN`。

### 如果你的 Agent 没有调度器 \{#if-your-agent-has-no-scheduler\}

该技能会提供一个检查提示，让你保存为文件，以及一行供你的系统调度器（如 cron）使用的命令。该命令会以非交互模式运行你的 agent，并将每次报告追加到你指定的文件中。对于 Claude Code，该命令如下所示：

```bash
0 9 * * 1 cd ~/my-app && claude -p "$(cat adapty-weekly-health.txt)" --allowedTools "Bash" >> ~/adapty-checks.md
```

其他代理有各自的非交互模式，例如 `codex exec` 或 `gemini -p`。运行时需要有权限在不询问的情况下执行 shell 命令，不同代理对该权限的命名方式各不相同：请查阅您所用代理的文档。

## 对报告进行操作 \{#act-on-a-report\}

运行只读取数据，不建议新的假设，在您回应之前不做任何更改。智能体可以为您执行的每个操作都以问题的形式列在**后续步骤**中，您可以回答"是"，例如"停止测试并保留 Annual 2？"。只有您才能执行的步骤以"You:"开头。

要对报告进行操作，请在您的智能体中回复：在定时运行的专属聊天中回复，或将报告粘贴到新聊天中进行回复。发布到 Slack 或电子邮件的报告无法在那里回复，因此最后一行会说明在哪里回复。

一旦你回复，AI 助手就会像执行其他技能时一样开始工作。它会重新读取测试和版位的当前状态，因为报告可能已经过时几天了。每一项操作都需要你确认后才会执行：停止测试、将假设标记为已验证、已否定或结论不明，或者关联新的测试。

## 修改或停止检查 \{#change-or-stop-a-check\}

如需更改检查的运行频率或报告发送位置，请联系设置该检查的代理。如需停止检查，请删除代理调度器中的相应任务，或移除对应的 cron 行。
