查看流程的版本历史，并可详细了解每个版本的内容。浏览历史版本时，当前草稿和当前已发布版本均保持不变。准备就绪后，还原你想要的版本并发布即可。

要打开版本列表，请在 Flow & Paywall Builder 顶部工具栏中点击 **Version history**。该列表将替换右侧面板。若要关闭，再次点击 **Version history**。

<ZoomImage id="flow-version-history-button.webp" width="450px" alt="编辑工具顶部工具栏中的 Version history 按钮（已按下），其下方显示 Version history 面板" />

## 找到所需版本 \{#find-the-version-you-need\}

如果你从未[发布当前流程](builder-save-publish#publish-a-flow)，则版本历史记录为空。

否则，已发布的版本将按时间顺序排列，最新版本显示在最上方。

<ZoomImage id="flow-version-history-panel.webp" width="320px" float="right" alt="The Version history panel with a Draft version and a Live version" />

列表会高亮显示当前打开的版本。查看标签以了解每个版本的状态：

- **Draft**：正在编辑的版本。
- **Publishing…**：正在发布的草稿。
- **Publish failed**：发布失败的草稿。[查找并修复原因](builder-save-publish#troubleshooting)，然后重新发布。
- **Live**：用户当前看到的版本。
- 无标签：曾经上线过的历史版本。

要在列表中查找特定版本，可以按名称搜索。发布重大更新时，建议为新版本取一个描述性名称，方便日后快速找到并恢复。要重命名某个版本，请打开该条目的右键菜单 <Inline id="context.svg" alt="Context menu" />，然后选择 **Rename**。

## 查看历史版本 \{#view-an-earlier-version\}

要预览某个版本，点击对应的行即可。该版本以只读方式打开：你可以浏览其中的屏幕和元素，但无法进行任何修改。

<ZoomImage id="flow-version-history-preview.webp" width="300px" alt="The Version history panel with the v2 version highlighted" />

如需查看元素属性，请关闭 **Version history** 面板，预览状态会保持不变。

如需在 [Adapty 移动应用](paywall-device-compatibility-preview#preview-on-devices)中打开该版本，点击 **Test on device**，然后扫描二维码或打开链接。

要返回最新草稿，请点击 **Back to current version**。

## 恢复早期版本 \{#restore-an-earlier-version\}

:::tip
在同一流程中恢复某个版本会替换当前草稿。若要保留草稿，请在恢复之前将其复制为新流程。
:::

恢复之前的流程版本有两种方式。找到所需的版本条目，打开其上下文菜单 <Inline id="context.svg" alt="Context menu" />，然后选择以下选项之一：

- **Duplicate as draft**：在同一流程中恢复该版本。如果该流程已有草稿，系统会提示你确认 **Replace draft**。恢复的版本不会立即上线，需要[重新发布](builder-save-publish#publish-a-flow)。适用于 **Live** 版本以及曾经上线过的历史版本。
- **Duplicate as new flow**：将该版本恢复为一个新流程。原流程保持不变，并保留其最新草稿。新流程会在新标签页中打开。

<ZoomImage id="flow-version-history-restore-menu.webp" width="400px" alt="版本条目的右键菜单，包含“复制为草稿”和“复制为新流程”选项" />

### 还原单个页面或元素 \{#restore-one-screen-or-element\}

如需还原某个单独的页面或元素，请先[预览](#view-an-earlier-version)早期版本，选中所需元素，然后用键盘快捷键（Cmd/Ctrl+C）复制它。返回最新草稿后粘贴即可。如果复制的内容引用了该版本之后被删除的资源（例如某种字体或文字样式），请替换这些引用——否则流程将无法发布。

## 通过 CLI 或 AI 助手管理版本 \{#work-with-versions-from-the-cli-or-an-ai-assistant\}

版本历史记录也可以在 Flow 与付费墙编辑工具之外访问：在 [Adapty CLI](developer-cli-flows#adapty-flows-versions-list) 中，以及通过 [Adapty MCP 服务器](adapty-mcp) 供 AI 助手使用。[flow-generator 技能](flow-generator-skill) 会用它来回滚更改。CLI 和 MCP 服务器与看板使用同一套版本历史记录，因此显示相同的版本和名称，并在 Adapty 拒绝某项操作时给出相同的提示信息。两者均使用 Adapty Developer API，该 API 支持相同的版本历史操作：列出、查看、重命名、还原和复制。

每个看板操作都对应一个 CLI 命令和一个 MCP 工具：

| 在看板中 | CLI 命令 | MCP 工具 |
|---|---|---|
| 版本列表及其搜索 | `adapty flows versions list`，附带 `--search` | `flows_versions_list` |
| 点击某个版本行 | `adapty flows versions get` | `flows_versions_get` |
| **Test on device** | `adapty flows versions preview` | `flows_versions_preview` |
| **Rename** | `adapty flows versions rename` | `flows_versions_rename` |
| **Duplicate as draft** | `adapty flows versions restore` | `flows_versions_restore` |
| **Duplicate as new flow**，以及顶栏流程操作按钮下的 [**Duplicate flow**](copy-flows) | `adapty flows duplicate` | `flows_duplicate` |

还原操作会替换草稿，与 **Duplicate as draft** 效果相同。如需保留草稿，请先将其复制为新的流程。当流程存在草稿时，CLI 和助手会在替换前向你确认。

替换草稿时，CLI 和助手会发送版本列表中该草稿的 `updated_at` 时间戳。如果队友在此次读取之后保存了草稿，Adapty 会拒绝还原并提示 `This flow configuration was already updated by …`，队友的草稿保持不变。请重新获取版本列表后再试。

对于从未发布过的流程，看板历史记录为空，但 CLI 会打印 `History will appear after the first publish.`，并在其下方显示草稿。

## 限制 \{#limitations\}

您无法：

- 恢复草稿的早期状态。若要撤销最近的编辑，请使用[撤销](builder-ui#project-controls-and-useful-shortcuts-top-toolbar)功能。若要丢弃自版本发布以来的所有更改，请[恢复 **Live** 版本](#restore-an-earlier-version)。
- 对已归档流程的版本执行重命名、恢复或复制操作。若要使用这些功能，请[先将流程设为活跃状态](archive-flows#restore-a-flow)。

## 故障排查 \{#troubleshooting\}

| 症状 | 原因 | 解决方法 |
| :------ | :---- | :-- |
| 发布还原版本时，出现 **Can't publish yet** 对话框。 | 新还原的版本使用了不再存在的产品或优惠。 | [替换产品引用](flow-common-issues#a-flow-wont-preview-or-publish)并修复所有其他现有问题。 |
| 还原早期版本时，出现错误 `This flow configuration was already updated by …`。 | 你打开流程后，团队成员修改了草稿。 | 刷新页面，然后[重新还原](#restore-an-earlier-version)。 |
