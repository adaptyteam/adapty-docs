## 开始之前 \{#before-you-start\}

:::important
在 Expo 项目中，自定义元素仅在你将 `ios` 和 `android` 文件夹保留在 Git 中且不运行 `npx expo prebuild --clean` 的情况下才能正常工作。否则，Expo 会重新生成这些文件夹并删除本页中的代码。新建的 Expo 项目默认不将这些文件夹纳入 Git 管理，因此 EAS Build 每次构建时都会重新生成它们。
:::

你需要：

- **Adapty React Native SDK 4.4 或更高版本**：更早的版本会对每个自定义元素显示备用付费墙。
- **iOS 和 Android 的原生代码**：自定义元素中无法显示 React Native 组件，需分别用 Swift（iOS）和 Kotlin（Android）编写。将 Swift 代码添加到 Xcode 中的 app target，将 Kotlin 代码添加到 `MainApplication.kt` 所在的文件夹。每个新建的 Kotlin 文件开头须包含与 `MainApplication.kt` 相同的 `package` 声明。
- **自定义元素命名规范**：为每个原生视图指定一个 Type，例如 `lottie_animation`。Type 只能包含小写字母、数字和下划线。若要区分相同 Type 的不同自定义元素，可为每个元素指定一个 ID，例如 `welcome_wave`。代码中使用的 Type 和 ID 必须与[流程与付费墙编辑工具](flow-custom-elements#add-and-configure)中的配置保持一致。

在您的 iOS 和 Android 代码中使用相同的 Types 和 IDs。除非您为每个平台单独设置[目标受众](audience)，否则 iOS 和 Android 用户将看到相同的流程。

## 配置您的 Android 项目 \{#set-up-your-android-project\}

您的 iOS 项目无需额外配置。在 Android 项目中，添加 Adapty UI 库。如需将原生视图构建为可组合项，还需配置 Jetpack Compose。

### 添加 Adapty UI 库 \{#add-the-adapty-ui-library\}

在 `android/app/build.gradle` 的 `dependencies` 块中添加 `io.adapty:android-ui`，无需指定版本号。版本由 `react-native-adapty` 统一管理，手动指定不同的 `android-ui` 版本可能导致流程异常。

```groovy showLineNumbers title="android/app/build.gradle"
dependencies {
    implementation("io.adapty:android-ui")
}
```

该库需要 `compileSdkVersion` 35 或更高版本：如果 `android/build.gradle` 中设置的版本低于 35，请将其提升至 35。

### 设置 Jetpack Compose \{#set-up-jetpack-compose\}

React Native 模板不会在 app 模块中[配置 Compose](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)。Android `View` 无需 Compose 配置。若要将原生视图构建为 composable，需要根据应用的 Kotlin 版本（即 `android/build.gradle` 中的 `kotlinVersion`）配置 Compose 编译器：

<Tabs groupId="kotlin-version" queryString>
<TabItem value="kotlin-2" label="Kotlin 2.0 and later" default>

React Native 0.77 及更高版本的模板使用 Kotlin 2.0 或更高版本。请将 Compose compiler Gradle 插件添加到 `buildscript` 依赖中：

```groovy showLineNumbers title="android/build.gradle"
buildscript {
    dependencies {
        classpath("org.jetbrains.kotlin:compose-compiler-gradle-plugin:$kotlinVersion")
    }
}
```

然后将该插件应用到 app 模块，并在 `buildFeatures` 块中设置 `compose true`：

```groovy showLineNumbers title="android/app/build.gradle"
apply plugin: "org.jetbrains.kotlin.plugin.compose"

android {
    buildFeatures {
        compose true
    }
}
```

</TabItem>
<TabItem value="kotlin-1-9" label="Kotlin 1.9">

React Native 0.75 和 0.76 的模板使用 Kotlin 1.9。在 `android` 块中，将 `compose true` 以及与你的 Kotlin 版本匹配的 Compose 编译器版本设置好。React Native 0.75 和 0.76 使用 Kotlin 1.9.24 构建，需要 Compose 编译器 1.5.14。其他 Kotlin 版本请参阅 [Compose 与 Kotlin 兼容性对照表](https://developer.android.com/jetpack/androidx/releases/compose-kotlin)。

```groovy showLineNumbers title="android/app/build.gradle"
android {
    buildFeatures {
        compose true
    }
    composeOptions {
        kotlinCompilerExtensionVersion "1.5.14"
    }
}
```

对于本页面的 Lottie 视图，还需添加 `com.airbnb.android:lottie-compose`。

## 为自定义元素创建视图 \{#create-views-for-custom-elements\}

对于每种 Type，分别为 iOS 和 Android 创建原生视图，或复用现有的原生代码中的视图。以下 `lottie_animation` Type 的视图用于播放 Lottie 动画。Android 视图是一个使用 `com.airbnb.android:lottie-compose` 库的 Composable：

struct LottieElementView: View {

    var body: some View {

            .looping()

### 要求与最佳实践 \{#requirements-and-best-practices\}

- **尺寸**：
  - **内边距与对齐**：确保原生视图能适配你在 Flow & Paywall Builder 中为其分配的容器（减去内边距后的区域）。如果视图未占满整个区域，默认会出现在该区域的起始角位置。如需移动，请在自定义元素的 **Layout** 部分更改对齐方式。
  - **自适应高度**：如果自定义元素的高度设置为 **Hug**，会自动拉伸填满可用空间的视图（如地图或懒加载列表）将会折叠，或拉伸至屏幕高度。请改为给自定义元素设置[**固定**高度](flow-custom-elements#add-and-configure)。
- **主题**：原生视图不会继承 React Native 组件的样式。请在原生代码中设置颜色和字体。
- **流程操作**：原生视图无法执行流程操作（例如跳转到下一屏）。元素上下文可以通过 iOS 的 `sendMessage` 和 Android 的 `send` 向流程发送消息，但这些功能保留供 Flow & Paywall Builder 未来的功能使用。请将导航按钮、购买按钮及其他带有流程操作的按钮放在自定义元素之外。
- **可选择元素**：请将自定义元素放在产品卡片和其他[可选择元素](flow-selectable-elements)之外。当选择状态发生变化时，原生视图可能会丢失其状态。
- **导航处理**：当用户切换到下一屏时，SDK 会将原生视图从屏幕中移除。请停止视图启动的任务，例如摄像头会话、播放器和位置更新：
  - **SwiftUI 视图**：使用 `onDisappear` 操作。对于异步任务，使用 `.task`：SwiftUI 会在视图消失时自动取消它。
  - **Composable**：使用 `DisposableEffect` 的 `onDispose` 块。对于异步任务，使用 `LaunchedEffect`：Compose 会在 composable 离开组合树时自动取消它。
  - **Android `View`**：在你的 `View` 子类中重写 `onDetachedFromWindow`，或向 `View` 添加 `View.OnAttachStateChangeListener`。

  当用户返回时，SDK 会再次调用 resolver，原生视图将以全新状态启动，不保留之前的状态。在 Android 上，通过 `present()` 打开的流程中，旋转屏幕会触发 SDK 再次调用 resolver；而在嵌入式 `AdaptyFlowView` 中，旋转后原生视图会保留其状态。
- **UIKit 视图**：在 iOS 上，请将其包装在 `UIViewRepresentable` 中。
- **轮播图**：在 Android 上，[轮播图](builder-containers#carousel)中所有幻灯片上的原生视图在屏幕打开期间均保持活跃状态，而不仅限于当前可见幻灯片上的视图。请勿在轮播图中使用摄像头预览或带声音的播放器。

## 编写解析器以匹配自定义元素和视图 \{#write-a-resolver-to-match-custom-elements-and-views\}

为每个平台编写一个解析器。解析器接收自定义元素的 Type 和 ID，并返回对应的原生视图。

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

要编写解析器，请让某个类型遵循 `AdaptyUICustomElementsResolver` 协议，并实现 `view(forType:id:context:)` 方法。

对于 `lottie_animation` Type，以下解析器返回 `LottieElementView`。ID 对应应用包中的动画文件名，例如 `welcome_wave`：

```swift showLineNumbers title="Swift"

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "lottie_animation":
            // the ID names the animation file, such as welcome_wave.json
            guard let animation = LottieAnimation.named(id) else {
                return nil // no file for this ID: show the fallback
            }
            return AnyView(LottieElementView(animation: animation))
        default:
            return nil
        }
    }
}
```

在 `default` 分支中，返回 `nil`。

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

要编写 resolver，请实现 `AdaptyCustomElementsResolver` 接口。其 `resolve` 方法以下列形式之一返回匹配的视图：

- **可组合项（Composable）**：返回 `AdaptyCustomElementContent.compose`，并在其 lambda 中传入可组合项。
- **Android `View`**：返回 `AdaptyCustomElementContent.view`，并传入一个创建 `View` 的函数。务必显式命名 `factory` 参数：`AdaptyCustomElementContent.view(factory = { context, _ -> ChartView(context) })`。如果不命名，Kotlin 会将尾随 lambda 传给可选的 `update` 参数，导致代码无法编译。

对于 `lottie_animation` 类型，以下解析器返回 [Lottie 视图](#create-views-for-custom-elements)。ID 对应 `assets` 文件夹（`android/app/src/main/assets`）中的动画文件名，例如 `welcome_wave` 对应 `welcome_wave.json`：

```kotlin showLineNumbers title="Kotlin"

class CustomElementsResolver(context: Context) : AdaptyCustomElementsResolver {
    // the animation files in the assets folder, listed once
    private val animationFiles: Set<String> = try {
        context.assets.list("").orEmpty().toSet()
    } catch (e: IOException) {
        emptySet() // no list of files: every Lottie element shows the fallback
    }

    override fun resolve(type: String, id: String): AdaptyCustomElementContent? =
        when (type) {
            "lottie_animation" -> {
                // the ID names the animation file, such as welcome_wave.json
                val file = "$id.json"
                if (file in animationFiles) {
                    AdaptyCustomElementContent.compose { LottieElement(file) }
                } else {
                    null // no file for this ID: show the fallback
                }
            }
            else -> null
        }
}
```

对于其他任何 Type，返回 `null`。

</TabItem>
</Tabs>

如果你在发布应用后[添加了具有新 Type 的自定义元素](flow-custom-elements#what-changes-require-an-app-release)，已发布版本的用户将看到其备用内容。

解析器有以下要求：

- **网络数据和播放器**：将网络数据和播放器保存在[原生视图](#create-views-for-custom-elements)的状态中，而不是保存在解析器里。SDK 在屏幕打开期间会多次调用解析器，解析器中的代码每次调用都会重新执行，导致网络请求重复发起、播放器从头开始。原生视图在这些调用之间会保留自身状态，因此数据只会加载一次，播放器也能持续播放。请在原生视图内创建播放器、会话和网络请求：
  - **SwiftUI 视图**：在 `.task` 或 `@StateObject` 中创建播放器、会话和网络请求，不要放在 `@State` 属性的初始值里。Swift 每次解析器创建视图时都会重新求值该初始值。
  - **Composable**：在 `remember` 中创建播放器和会话，在 `LaunchedEffect` 中发起网络请求。
  - **Android `View`**：在 `onAttachedToWindow` 中创建播放器、会话和网络请求。
- **每个自定义元素对应一个原生视图**：某些原生视图在屏幕打开期间会发生变化，例如数据加载完成时或用户点击时。请在原生视图本身中实现这些逻辑，而不是在解析器中。如果解析器为同一个自定义元素返回不同的视图，该视图将丢失其状态。
- **每次出现都创建新的 `View`**：在 Android 上，每次调用 `factory` 时都要创建一个新的 `View`。SDK 每次自定义元素出现时都会调用 `factory`，例如屏幕打开时、用户返回屏幕时，或者在通过 `present()` 打开的流程中发生旋转之后。
- **应用数据**：将持有数据的对象（例如 `ObservableObject` 或带有[每日连续登录](react-native-custom-element-lottie-animation)的 `StateFlow`）存储在解析器的属性中。将该对象传递给原生视图，并在视图中观察它：
  - **SwiftUI 视图**：使用 `@ObservedObject` 观察 `ObservableObject`。
  - **Composable**：使用 `collectAsState` 收集 `StateFlow`，或使用 `observeAsState` 观察 `LiveData`。
  - **Android `View`**：在 `onAttachedToWindow` 中开始观察对象，在 `onDetachedFromWindow` 中停止观察。

  您复制到解析器中的值（例如连续天数）会保持创建解析器时的原始值。如果您的 JavaScript 代码中有数据（例如每日连续天数），请通过 [Turbo Native Module](https://reactnative.dev/docs/turbo-native-modules-introduction) 将每个新值发送到原生代码，并在那里更新对象。

### 设置备用内容的条件 \{#set-conditions-for-fallback-content\}

<FlowCustomElementsFallbackConditions />

仅当用户在屏幕打开之前已拒绝权限时，才返回空视图。在 Android 上，`ContextCompat.checkSelfPermission` 在两种情况下会返回相同的值 `PERMISSION_DENIED`：应用首次请求权限之前，以及用户拒绝权限之后。要区分这两种情况，请保存权限请求的结果，并在解析器中读取已保存的结果。如果应用尚未请求过该权限，则返回原生视图，并在视图内部发起权限请求。例如，在[地图视图](react-native-custom-element-map#3-match-the-map-to-the-custom-element)出现时请求位置访问权限，并在用户授权后立即显示地图。如果你返回了空视图，而用户之后才授予权限，他们仍然会看到备用内容。权限变更不会触发 SDK 再次调用解析器。原生视图只有在 SDK 再次调用解析器时才会出现，例如用户返回该屏幕时。

## 将解析器传递给 SDK \{#pass-the-resolver-to-the-sdk\}

在应用启动时，为每个平台设置一次解析器。SDK 会在每个流程中调用它，包括通过 `AdaptyFlowView` 嵌入的流程。用户无需发布应用更新，即可在新流程和 A/B 测试中看到您的原生视图。这些视图仍会为每位用户显示其专属数据，例如[每日连续记录](react-native-custom-element-lottie-animation)，因为它们从您的应用中读取这些数据。

### iOS

<Tabs groupId="ios-app-delegate" queryString>
<TabItem value="swift" label="AppDelegate.swift" default>

在 `AppDelegate.swift` 中，导入 `AdaptyUI`，并在 `application(_:didFinishLaunchingWithOptions:)` 方法中调用 `AdaptyUI.setCustomElementsResolver(_:)`。高亮行显示了需要添加的内容。保持 `AppDelegate` 类的其余部分不变：

```swift showLineNumbers title="ios/YourApp/AppDelegate.swift" {1,10}

@main
class AppDelegate: UIResponder, UIApplicationDelegate {
  func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]? = nil
  ) -> Bool {
    AdaptyUI.setCustomElementsResolver(CustomElementsResolver())
    // the rest of your launch code
    return true
  }
}
```

如果你也在 `AppDelegate.swift` 中编写解析器，还需要在此处导入 `AdaptyUIBuilder`。

如果 `application(_:didFinishLaunchingWithOptions:)` 以裸 `true` 结尾（如 React Native 0.88 模板中），请将 `true` 改为 `return true`。

</TabItem>
<TabItem value="objc" label="AppDelegate.mm">

通过 Swift 类设置解析器，因为 `AdaptyUI.setCustomElementsResolver(_:)` 仅支持 Swift：

1. 将包含该类的 Swift 文件添加到您的 app target：

   ```swift showLineNumbers title="CustomElementsSetup.swift"
   import AdaptyUI

   @objc final class CustomElementsSetup: NSObject {
     @MainActor @objc static func register() {
       AdaptyUI.setCustomElementsResolver(CustomElementsResolver())
     }
   }
   ```

2. 在 `AppDelegate.mm` 中，导入 Xcode 为你的 target 自动生成的 Swift 头文件 `<YourApp>-Swift.h`。在 `application:didFinishLaunchingWithOptions:` 的开头调用 `[CustomElementsSetup register]`。如果是 Expo 项目，请在导入你的 target 头文件之前先导入 `<ExpoModulesCore/ExpoModulesCore-Swift.h>`。

   ```objectivec showLineNumbers title="ios/YourApp/AppDelegate.mm" {1,5}
   #import "YourApp-Swift.h"

   - (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions
   {
     [CustomElementsSetup register];
     // the rest of your launch code
   }
   ```

</TabItem>
</Tabs>

### Android

在 `MainApplication.kt` 中，导入 `AdaptyUI`，并在 `onCreate` 方法中调用 `AdaptyUI.setCustomElementsResolver`。高亮行为需要添加的内容。`MainApplication` 类的其余部分保持不变：

```kotlin showLineNumbers title="MainApplication.kt" {1,8}

class MainApplication : Application(), ReactApplication {
  // the other members of your MainApplication class

  override fun onCreate() {
    super.onCreate()
    AdaptyUI.setCustomElementsResolver(CustomElementsResolver(this))
    // the rest of your onCreate code
  }
}
```

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

该映射是一个 `[String: AdaptyUICustomElementBuilder]` 字典。如果在 `AppDelegate.swift` 中编写映射，还需要在该文件中导入 `Lottie`。

```swift showLineNumbers title="Swift"
AdaptyUI.setCustomElementsResolver([
    "lottie_animation": .init { _, id, _ in LottieElementView(animation: .named(id)) },

```

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

将 map 传入 `AdaptyCustomElementsResolver.of`：

```kotlin showLineNumbers title="Kotlin"

```

</TabItem>
</Tabs>

您无法将解析器附加到单个流程。如需在流程中显示 JavaScript 代码中的数据，请在流程打开之前将数据发送到原生代码，然后在解析器中读取该数据。例如，付费墙会显示[用户在前一个流程中输入的体重](react-native-custom-element-interactive-chart)。

## 在设备上测试 \{#test-on-a-device\}

流程与付费墙编辑工具无法运行你的应用代码，因此其画布只会显示备用内容。原生视图中的错误可能导致应用崩溃。在发布应用之前，请在 iOS 设备和 Android 设备上测试每个包含自定义元素的页面：

1. 若要查看每个流程的最新发布版本而非缓存版本，请将设备注册为[测试设备](test-devices)。
2. 若要在 Xcode 控制台和 Logcat 中查看 Adapty SDK 的警告信息，请将[日志级别](sdk-installation-react-native-pure#logging)设置为 `warn` 或更详细的级别。
3. 在设备上运行包含解析器的构建版本。打开每个包含自定义元素的界面，确认原生视图已正常显示并与自定义元素匹配。如果视图支持滚动或拖动手势，请对这些手势进行测试。
4. 如果显示的是备用内容而非原生视图，请在 Xcode 控制台或 Logcat 中查找以下警告：`custom element <type>:<id> is not served by a resolver`。然后确认：
   - 警告中的 Type 和 ID 与代码中的完全一致，包括每一个字母的大小写。
   - 应用已具备视图所需的文件、数据或权限。
   - 应用在启动时已注册解析器：iOS 在 `AppDelegate` 类中注册，Android 在 `MainApplication` 类中注册。

   如果未出现警告，请确认应用使用的是 Adapty React Native SDK 4.4 或更高版本。
5. 在 Android 上，如果自定义元素保持为空，请在 Logcat 中查找以下警告：
   - `custom element <type>:<id> is not served by a resolver`：该自定义元素没有备用内容，且没有任何解析器为其返回视图。请逐一核查步骤 4 中的每一项。
   - `content does not report its size`：该 composable 本身没有高度。请为自定义元素设置一个[**固定**高度](flow-custom-elements#add-and-configure)。

   6. 若要预览备用付费墙，请针对该 Type 不返回任何视图，然后重新打开页面。
