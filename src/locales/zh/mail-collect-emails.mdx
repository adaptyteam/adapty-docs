Adapty 是 Adapty Mail 的入口之一——如果您的应用已接入 Adapty SDK，可直接使用此方式。Adapty 会将用户画像、电子邮件地址和订阅事件传递给 Adapty Mail，Adapty Mail 再据此筛选收件人、将每位用户纳入相应流程，并将购买行为归因到驱动该订单的邮件。

如果您的应用未接入 Adapty SDK，可通过服务端发送相同数据——详见[通过 Adapty Mail API 发送邮件和交易记录](mail-send-data-via-api)。

:::important
Adapty Mail 是一款**独立产品**。即使你的付费墙、订阅或数据分析不由 Adapty 处理，你也可以使用它——无需迁移整个技术栈。

若要获取准确的收入数据，最低配置要求是以 observer 模式安装 Adapty SDK，并启用 App Store 服务器通知。
:::

Adapty Mail 需要你的应用提供三项内容：购买数据（用于将收入归因到促成转化的邮件）、稳定的用户标识符，以及用户邮箱地址。完成这三项配置后，即可开启发送功能。

## 1. 让 Adapty 追踪您的收入 \{#1-let-adapty-track-your-revenue\}

第一步取决于您是否已经实现了应用内购买：

- 如果您**已使用 Adapty 实现了应用内购买**，此阶段无需进行任何其他操作。
- 如果您**已在不使用 Adapty 的情况下实现了应用内购买**，且不打算迁移到 Adapty，请以观察者模式为您的平台安装 Adapty SDK。此阶段您只需将 SDK 添加到项目中，以观察者模式激活它，并上报交易记录。各平台指南：[iOS](implement-observer-mode)、[Android](implement-observer-mode-android)、[React Native](implement-observer-mode-react-native)、[Flutter](implement-observer-mode-flutter)、[Unity](implement-observer-mode-unity)、[Kotlin Multiplatform](implement-observer-mode-kmp)、[Capacitor](implement-observer-mode-capacitor)。
- 如果您**尚未实现应用内购买且希望使用 Adapty**，请按照[快速入门指南](quickstart)完成相关步骤，将购买处理委托给 Adapty。

然后[在 Adapty 中启用 App Store 服务器通知](enable-app-store-server-notifications)，以便直接从 App Store 接收与收入相关的更新。

## 2. 识别用户 \{#2-identify-your-users\}

传入一个稳定的 ID——后端用户 ID、Firebase UID 或类似标识——可以在 SDK 初始化时通过 `.activate()` 的 `customerUserId` 参数传入，也可以在之后（例如登录时）调用 `Adapty.identify()` 传入。无论哪种方式，都要在展示任何付费墙之前完成 ID 设置。`customer_user_id` 是 Adapty Mail 将营销活动、点击行为和购买记录关联回正确用户画像的依据。

平台指南：[iOS](identifying-users)、[Android](android-identifying-users)、[React Native](react-native-identifying-users)、[Flutter](flutter-identifying-users)、[Unity](unity-identifying-users)、[Kotlin Multiplatform](kmp-identifying-users)、[Capacitor](capacitor-identifying-users)。

## 3. 收集用户邮箱 \{#3-collect-user-emails\}

一旦用户在应用中提供了邮箱（例如在注册或结账时），请通过调用 `updateProfile` 并传入 `email` 属性，将其传递给 Adapty。每一位活动收件人都需要填写此值。

平台指南：[iOS](setting-user-attributes)、[Android](android-setting-user-attributes)、[React Native](react-native-setting-user-attributes)、[Flutter](flutter-setting-user-attributes)、[Unity](unity-setting-user-attributes)、[Kotlin Multiplatform](kmp-setting-user-attributes)、[Capacitor](capacitor-setting-user-attributes)。

:::important
- 始终传递**稳定的** `customer_user_id`，不要使用匿名标识符。如果用户卸载并重新安装了应用，Adapty 会使用此 ID 将重装行为与已有用户画像关联，并将购买记录归因到正确的用户。
- 在收集并向 Adapty 发送电子邮件地址之前，请先获得用户的明确同意。您有责任遵守 GDPR、CAN-SPAM 以及目标市场中的类似法规。如需让 Adapty Mail 在发送营销邮件前对每个新地址进行确认，请开启[双重确认订阅](mail-double-opt-in)。
:::

<Details>
<summary>验证您的邮件覆盖率</summary>

完成收集实现后，请在 Adapty 中检查覆盖情况：

1. 前往 **Customers → Profiles**。
2. 按已设置邮件的用户画像进行筛选。

在启动首个营销活动之前，目标是在活跃用户中至少达到 30–50% 的邮件覆盖率。无需等到 100%——达到 30% 即可启动。之后提供邮件的用户，在符合条件时会自动加入进行中的营销活动。

</Details>

### 邮件收集策略 \{#email-collection-strategies\}

大多数应用默认不收集邮箱。请根据你的应用现状选择合适的方案。

| 策略 | 最适用场景 | 工作原理 |
| ---------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **现有身份验证** | 任何形式的登录应用 | 您已有用户邮箱——在用户完成身份验证后将其传递给 Adapty。 |
| **付费墙前的邮箱门控** | 无身份验证的应用——健康、健身、占星、图片编辑器 | 在用户引导和付费墙之间添加一个邮箱输入页面。由于用户已投入了时间，转化率通常可达 70–90%。 |
| **网页付费墙编辑工具结账** | SDK 工作量最小；在网页端采集邮箱 | 网页付费墙编辑工具的第一个页面会采集邮箱并将其传递给 Adapty——适用于在应用内门控上线前通过活动链接进入的用户。 |
| **用户引导步骤** | 基于问卷的用户引导（健身、营养、教育） | 在用户引导的第 2–3 步放置邮箱输入。将其定位为价值传递（"我们将把您的个性化计划发送至邮箱"），并避免让该步骤可跳过。 |
| **Adapty Mail API** | 从您的服务器发送邮件，无需 Adapty SDK | 将用户画像发送至 Adapty Mail API 的 [保存用户画像](api-mail/operations/saveProfile) 端点。详见[通过 Adapty Mail API 发送邮件和事务数据](mail-send-data-via-api)。 |

## 4. 启用发送 \{#enable-sending\}

完成其余设置后，再回到这一步。在您至少创建一个流程之前，Adapty Mail 的 **Enable** 按钮将保持禁用状态，并显示提示信息 *"Set up at least one flow before enabling Adapty integration"*——因此请先完成发送域名、结账、活动和流程的配置。请参阅[Adapty Mail 入门](mail-get-started)。

开启集成是最后一步：事件开始流转，市场细分开始匹配，邮件开始发送。

1. 在 Adapty Mail 中，进入 **Settings → Project**，找到 **Adapty Integration** 部分。
2. 点击 **Enable Adapty integration**（如果之前已有集成配置，则点击 **Enable**）。

启用后，Adapty 会将每个订阅事件——新订阅、续订、试用、转化、退款、账单问题——推送到 Adapty Mail。这些事件驱动市场细分成员资格、营销活动路由，以及当用户完成转化时暂停序列的停止条件。

:::note
**Adapty Integration** 部分仅在项目已关联 Adapty 工作区时才会显示。如果你是直接注册 Adapty Mail 且项目未关联，则不会显示该部分——请改用 [Adapty Mail API](mail-send-data-via-api) 发送数据。

:::note
**Settings** 中的 **Adapty integration** 开关与登录 Adapty Mail 的 Adapty 合作伙伴工作区*不同*。合作伙伴工作区负责创建您的账户（如果您通过 Adapty 注册，还会创建您的品牌）。此处的集成开关控制事件同步功能——需要为每个项目单独开启。
:::

## 限制条件 \{#limitations\}

- **匿名用户**：没有稳定 `customer_user_id` 的用户无法接收推广活动。请在用户创建账户或登录时对其进行识别——从那时起，他们提供的任何邮箱都会与其 Adapty 用户画像进行匹配。
- **没有邮箱的用户**：没有邮箱的用户画像会被排除在推广活动之外，也不会出现在推广活动分析数据中。一旦他们提供了邮箱，便可参与后续推广活动。
