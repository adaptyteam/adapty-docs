growth-advisor 技能能根据你自己的订阅数据回答"下一步该测试什么？"。你的 AI 编程工具通过 [Adapty CLI](developer-cli-analytics) 读取你的分析数据、版位、付费墙和产品，沿着最大的信号追溯根因，最终返回一份按潜在购买量排序的 A/B 测试假设清单。

:::note
growth-advisor 不会在未经你确认的情况下对账户做任何修改。所有分析数据的读取均为只读操作，每一项写入操作——无论是新建流程副本、新建市场细分，还是修改版位——都需要你的确认才会执行。
:::

## 你可以问什么 \{#what-you-can-ask\}

像给同事做简报一样提问，不需要指明使用哪个技能：

```
审查一下我的应用，接下来测试什么能提升收入？

上个月收入下滑了，原因是什么？

用户引导付费墙的 A/B 测试结束了，新版本赢了，下一步怎么做？

我有三个想法：按周订阅、年度订阅加试用期，以及增加一个版位。
先测哪个？

哪个国家的退款最多？开始试用的用户续订率更高吗？

我们下个月上线，目前还没有数据，从哪里开始？
```

关于您数据的问题将直接从您的数据中得到解答，无需附加审核。尚无数据的应用将根据 Adapty 2026 年付费墙状态报告中的市场中位数，获得一份初始方案，所有数字均标注为估算值。

## 开始之前 \{#before-you-start\}

- **包含数据的 Adapty 账户**：该技能读取的是看板中显示的相同分析数据。没有数据时，它只能为你提供初步方案。
- **可以运行终端命令的 AI 工具**：例如 Claude Code、Codex、Copilot CLI 或 Gemini CLI。像 claude.ai 或 ChatGPT 这样的聊天工具无法运行 CLI，因此无法访问你的 Adapty 账户。

## 安装技能 \{#install-the-skill\}

growth-advisor 是 [`adapty-skills` 插件](https://github.com/adaptyteam/adapty-skills) 的一部分。在终端中运行以下命令安装插件：

```bash
npx adapty skills install
```

重启你的 agent 以加载技能。其他安装方式请参阅 [插件 README](https://github.com/adaptyteam/adapty-skills/blob/main/plugin/README.md#install)。

## 审计如何运作 \{#how-the-audit-works\}

当你没有具体问题、只是询问"该怎么做"时，技能会启动审计。它会读取你的数据和版位配置，梳理你已经尝试过的内容，并顺着最大的变化追溯到能解释该变化的商店、渠道、国家或版位。在对某个页面发表任何看法之前，它会先查看线上的流程，或请你提供一张由应用自行绘制的付费墙截图。

## 你会得到什么 \{#what-you-get-back\}

该技能会先给出一个简短的回答，然后列出按版位分组的假设列表，并按测试顺序排列。每条假设都会说明你的应用为何需要它、预期会产生什么结果以及该估算的依据、A/B 测试需要多长时间，以及各方需要做什么。一条假设可以针对某个版位的所有用户，也可以针对某个特定的[市场细分](segments)，例如曾经订阅过的用户。

## 从假设到 A/B 测试 \{#from-hypothesis-to-ab-test\}

确定假设后，该技能会逐步配置 CLI 可操作的各个部分，每一步都需要你确认：

- **新的流程设计或产品组合**：该技能通过 [flow-generator 技能](flow-generator-skill) 创建流程副本，每个假设只改动一处，从而在 A/B 测试中清晰呈现该改动的效果。在你发布副本之前，它会提议通过 [flow-audit 技能](flow-audit-skill) 对副本进行审查。
- **不同的目标受众**：该技能创建市场细分，并通过 `audiences` 技能将其目标受众添加到版位中。

然后，选择如何将变更推送给用户。在看板中创建 [A/B 测试](ab-tests) 是默认方式，也是唯一能衡量变更效果的方法。你也可以立即展示，可以新建一个版位，或者向现有版位的部分或全部用户展示。

在技能修改现有版位之前，它会将该版位保存到文件中以便回滚，并询问该版位是否正在运行 A/B 测试。CLI 无法查看 A/B 测试的目标受众，而更新版位会替换所有目标受众，因此正在运行的测试会被静默删除。确认操作前，请先在看板中打开该版位的页面，确认是否有测试正在运行。

新方案、试用期和 A/B 测试的决策权始终在你手中。针对每一项，技能会为你提供在 App Store Connect、Google Play Console 或 Adapty 看板中操作的具体步骤。在 App Store 上，试用期需要创建新产品；在 Google Play 上，则是在现有方案上添加优惠。新产品的价格由你自行设定。

A/B 测试结束后，将本次测试内容和获胜结果告知技能，它会据此为你提供下一个测试假设。

## 限制 \{#limits\}

- **暂不支持价格分析**：该技能不会读取、比较或建议定价。当数据指向价格问题时，它会指出这一点，并说明暂不支持价格分析。
- **无 A/B 测试历史**：CLI 不返回过去的 A/B 测试结果。该技能通过同期运行的付费墙来推断历史测试，并依赖你告知哪个版本获胜。
- **无广告支出数据**：该技能可以按归因渠道拆分安装量、试用量和收入，但不支持支出或 ROAS。如需这些数据，请使用 [adapty-attribution 技能](developer-cli-attribution-skill)。

如需不借助技能自行查询分析数据，请参阅 [CLI 分析数据参考文档](developer-cli-analytics)。如需从服务器或定时任务中拉取分析数据（无法通过浏览器登录的场景），请使用 [导出分析数据 API](export-analytics-api) 配合密钥。
