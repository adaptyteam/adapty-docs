:::important
字段、日期时间选择器和可选组永远不会通过此回调发送其默认值。如果用户接受标记为 **Set as default** 的选项并继续，不会触发任何事件。请勿将缺失的事件解读为"未作答"——用户只是保留了默认值。[数字选择器](builder-number-picker)会在用户点击打开另一个屏幕的按钮时，将其默认数字发送到您的应用代码。
:::

**以下元素会触发此事件：**

- 文本、电子邮件、数字和电话字段
- 日期、时间和日期时间选择器
- 数字选择器
- 单选和多选可选组，以及开关

**以下元素不会触发：**

- 密码字段、产品选择和标签页切换
- Header 元素内的输入项（该元素在各屏幕间共享）
- 包含重复或缺失选项元素 ID 的可选组，或在其他屏幕上复用了 Group ID 的可选组。此类可选组不会发送任何内容，而非部分答案。

**事件在以下情况触发：**

- 字段失去焦点时。已清空的字段报告空字符串；用户从未编辑过的字段不报告任何内容。占位符不是值。如果用户返回字段、编辑后再次离开，则会触发第二次事件。
- 用户在选择新值后关闭日期或时间选择器时。关闭时若未更改值，则不报告任何内容。
- 在包含数字选择器的屏幕上，用户点击执行 **Navigate to Screen**、**Navigate Next** 或 **Navigate back** [操作](onboarding-actions)的按钮时。用户点击同一屏幕上的选项或开关时，数字选择器也会上报其值。如果用户从未转动过滚轮，则该值为默认数字。数字选择器即使在隐藏状态下（例如用户未打开的标签页中）也会上报其值。在值发生变化之前，不会触发第二次事件。
- 用户点击选项或开关时。多选事件会列出所有已选中的选项，因此取消选中最后一个选项会发送两个空数组。

**事件在以下情况不触发：**

- 用户输入时。没有按键流，只有字段失去焦点时所保存的值。
- 用户提交或关闭流程时。此时仍在编辑中的值可能会丢失。关闭流程、发起购买或执行自定义操作的按钮不会上报数字选择器的值。[传递限制](#delivery-and-limitations)部分介绍了如何针对这两种情况设计最后一个屏幕。
- 值在没有用户交互的情况下被设置时。标记为 **Set as default** 的选项在屏幕打开时已预选，**Set Variable** 操作可以通过其他交互来选中选项或填充输入框。两者均不会发送事件；非数字选择器的预填充输入框只有在用户编辑后才会上报。
