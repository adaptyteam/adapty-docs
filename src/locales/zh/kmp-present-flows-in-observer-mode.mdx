如果你使用[观察者模式](observer-vs-full-mode)，则需要自行处理购买逻辑。但你可以将付费墙 UI 委托给 [Flow & 付费墙编辑工具](adapty-flow-builder)。

在编辑工具中设计屏幕，Adapty SDK 将其原生渲染。随时更新文案、布局和定价，无需发布新版本。

本指南介绍如何展示流程并处理购买回调。如果由 Adapty 为您完成购买，请参阅[展示流程与付费墙](kmp-present-paywalls)。

## 开始之前 \{#before-you-start\}

你需要:

- **Adapty Kotlin Multiplatform SDK 4.0（测试版）或更高版本**：早期版本无法渲染流程。如需迁移现有应用，请参阅[迁移指南](migration-to-kmp-sdk-v4)。
- **在配置构建器中调用 `withObserverMode(true)`**：请参阅 [Kotlin Multiplatform SDK 安装指南](sdk-installation-kotlin-multiplatform#activate-adapty-sdk)。
- **初始商店集成**：完成 Adapty 与 [App Store](initial_ios) 和 [Google Play](initial-android) 的集成配置。
- **已发布的含产品的流程**：在[流程与付费墙编辑工具](adapty-flow-builder)中构建，并为其分配[产品](create-product)。
- **流程版位**：[创建一个版位](create-placement)并将你的流程分配给它。
- **在应用中获取流程**：在展示流程之前，[获取流程及其配置](kmp-get-pb-paywalls)。

## 实现 \{#implementation\}

在 Observer 模式下，SDK 不会代替你发起购买。当用户点击 Adapty 渲染的流程中的购买或恢复按钮时，SDK 会调用你的 `AdaptyUIObserverModeResolver`——请在其中用你自己的代码执行购买或恢复操作。

1. 实现 `AdaptyUIObserverModeResolver` 接口：

   ```kotlin showLineNumbers
   import com.adapty.kmp.AdaptyUIObserverModeResolver
   import com.adapty.kmp.models.AdaptyPaywallProduct
   import com.adapty.kmp.models.AdaptyUIFlowView

   class MyObserverModeResolver : AdaptyUIObserverModeResolver {
       override fun observerModeDidInitiatePurchase(
           view: AdaptyUIFlowView,
           product: AdaptyPaywallProduct,
           onStartPurchase: () -> Unit,
           onFinishPurchase: () -> Unit
       ) {
           onStartPurchase() // the view shows its loading indicator
           // make the purchase with your own code,
           // then report the transaction to Adapty and call:
           onFinishPurchase() // the view hides the loading indicator
       }

       override fun observerModeDidInitiateRestore(
           view: AdaptyUIFlowView,
           onStartRestore: () -> Unit,
           onFinishRestore: () -> Unit
       ) {
           onStartRestore()
           // restore purchases with your own code, then:
           onFinishRestore()
       }
   }
   ```

`observerModeDidInitiatePurchase` 方法会在用户发起购买时通知您，`observerModeDidInitiateRestore` 则会在用户发起恢复购买时通知您。请在收到通知后触发您的自定义购买或恢复流程。

此外，请记得调用以下回调，以便将购买或恢复流程的进度通知给 AdaptyUI。这对于正确的流程行为（例如显示加载动画等）是必要的：

| 回调 | 描述 |
   | :----------------- | :------------------------------------------------------------------------------- |
   | onStartPurchase()  | 调用此回调以通知 AdaptyUI 购买已开始。  |
   | onFinishPurchase() | 调用此回调以通知 AdaptyUI 购买已完成。 |
   | onStartRestore()   | 调用此回调以通知 AdaptyUI 恢复已开始。   |
   | onFinishRestore()  | 调用此回调以通知 AdaptyUI 恢复已完成。  |

流程会保持打开状态，直到您的代码运行完毕——在购买或恢复成功后，请自行关闭它。

2. 在展示任何界面之前注册解析器：

   ```kotlin showLineNumbers
   import com.adapty.kmp.AdaptyUI

   AdaptyUI.setObserverModeResolver(MyObserverModeResolver())
   ```

   如果未注册解析器，流程视图将无法将购买请求传递给您的代码，用户点击购买按钮时也不会有任何响应。

3. 按常规方式创建并展示流程视图：[获取流程并创建其视图](kmp-get-pb-paywalls)，然后[展示它](kmp-present-paywalls)。无需额外参数——一旦注册了 resolver，每个由 Adapty 渲染的流程都会通过它来路由购买和恢复操作。

:::warning
不要忘记[上报交易并将其与付费墙关联](report-transactions-observer-mode-kmp)。否则，Adapty 将无法识别该交易，也无法确定购买来源的付费墙。
:::
