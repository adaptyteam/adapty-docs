将您的 Stripe 账户连接到 Adapty Attribution，即可将通过网页漏斗完成的购买归因到对应的广告来源。连接后，Stripe 产生的购买、续订、退款和退单记录将显示在 Adapty Attribution 的分析数据中，转化事件也可回传至广告网络，用于广告系列优化。

## 工作原理 \{#how-it-works\}

1. [Adapty 网页像素](ua-web-pixel) 为每位漏斗访客分配一个点击 ID，并从落地页 URL 中捕获广告数据。
2. 结账时，你的漏斗将点击 ID 附加到 Stripe 交易中。
3. Adapty 通过在你的 Stripe 账户中创建的 Webhook 接收交易，并将其与广告点击进行匹配。

:::note
网页购买没有应用安装事件，因此 Adapty 使用订阅的首次扣费日期作为同期群日期。
:::

## 开始之前 \{#before-you-start\}

在您的漏斗中[设置 Adapty Web Pixel](ua-web-pixel)。没有 pixel，就没有可关联的点击 ID，交易也就无法归因到广告。

## 步骤 1：在结账时附加点击 ID \{#step-1-attach-the-click-id-at-checkout\}

创建交易时，读取点击 ID 并将其添加到 Stripe `metadata` 的 `adpt_click_id` 键中：

```js
const adptClickId = window.adaptyPixel.getClickId();
```

该值必须最终出现在 **PaymentIntent**（一次性支付）或 **Subscription**（周期性支付）上，因为这些是 Adapty 读取的对象。如果直接创建它们：

```js
metadata: { adpt_click_id: adptClickId }
```

如果您使用 Stripe Checkout，请在嵌套对象中设置 metadata。Checkout Session 本身的 metadata 不会复制到 PaymentIntent 或 Subscription，因此留在那里的 click ID 永远无法传递到 Adapty：

```js
stripe.checkout.sessions.create({
  // ...
  payment_intent_data: { metadata: { adpt_click_id: adptClickId } }, // one-off payments
  subscription_data:   { metadata: { adpt_click_id: adptClickId } }, // subscriptions
})
```

:::warning
请在创建 PaymentIntent 时设置元数据，而不是事后更新。Stripe 在创建收费记录时会将元数据复制到该记录上，因此之后添加的 click ID 永远不会传达到 Adapty。
:::

`click_id` 是一个简短的随机标识符，既不是密钥，也不是个人数据。它会显示在你的 Stripe 看板中，这是正常现象。

## 步骤 2：连接你的 Stripe 账户 \{#step-2-connect-your-stripe-account\}

首先，在 Stripe 中创建密钥。进入你的 Stripe 看板，导航到 **Developers → API keys**，然后创建一个具有以下权限的受限密钥：

| 资源 | 访问权限 |
|---|---|
| Charges | Read |
| Refunds | Read |
| Invoices | Read |
| Balance transactions | Read |
| Disputes | Read |
| Webhook endpoints | Write |

对 Webhook 端点的写权限允许 Adapty 创建用于接收支付通知的 Webhook，无需手动配置 Stripe 中的任何设置。其他所有权限均为只读：Adapty 不会写入您的支付数据。如果密钥缺少必要权限，连接时会报错并提示缺失的权限名称。

:::warning
请使用正式环境密钥。Adapty 会丢弃测试模式的支付数据，因此使用测试密钥（`rk_test_...`）虽然能成功连接并显示为 **Valid**，但不会有任何数据出现。如需验证集成是否正常，请连接正式环境密钥并完成一笔真实购买。
:::

然后，在 Adapty 中添加密钥：

1. 在 Adapty Attribution 中，前往 [**Integrations > Stripe**](https://app.adapty.io/ua/integrations/stripe)。
2. 将密钥粘贴到 **API key** 字段。可选填 **Name**，用于区分不同账户——默认情况下，Adapty 使用密钥的最后 4 个字符。
3. 点击 **Connect**。

<ZoomImage id="ua-stripe-connect.webp" width="500px" alt="Connect a Stripe account form with API key and Name fields on the Stripe integration page in Adapty Attribution" />

连接的账户会显示在表格中，包含其环境、密钥状态和 webhook 状态。该连接仅适用于当前配置的应用。如需在其他应用中接收同一 Stripe 账户的付款，请在该应用中添加相同的密钥。

Adapty 从账户连接时刻起开始导入交易记录。如需导入更早的历史交易，请通过 [support@adapty.io](mailto:support@adapty.io) 联系我们。

## 验证集成 \{#verify-the-integration\}

通过漏斗进行一次真实购买——Adapty 会丢弃测试模式下的购买记录。购买记录应在几小时内出现在 [Adapty 归因分析](ua-analytics) 中。如果用户是通过带有[标记 URL](ua-web-pixel) 的广告访问的，则该购买会归因到对应的广告系列、广告组和广告；否则，将计为自然流量。

## 将转化事件发送至广告网络 \{#send-conversion-events-to-the-ad-network\}

归因的网页购买行为遵循与其他广告活动相同的事件映射规则：在广告活动配置的 **Events names** 部分启用的事件，将被回传至与该广告活动关联的像素。具体映射设置请参阅 [Meta Ads](ua-facebook) 和 [TikTok for Business](ua-tiktok)。
