在 Capacitor 中，可靠的流程或付费墙获取需要做到三件事：快速渲染、返回针对目标受众的实验变体，以及在网络较慢时优雅地降级到备用方案。以下规则涵盖了实现这些目标所需的时机、缓存和备用方案。

:::tip
以下规则假设 `adapty.activate()` 和 `adapty.identify()` 已完成调用。详见 [Capacitor SDK 调用顺序](capacitor-sdk-call-order)。
:::

## 规则与注意事项 \{#rules-and-pitfalls\}

| 推荐做法 | 避免做法 | 原因 |
|---|---|---|
| 获取即将展示的版位，或通过 [`preloadFlows`](#preload-placements)（SDK 4.3.0+）预热缓存。 | 在启动时自行并发调用多个 `getFlow`。 | 手动批量预取会阻塞主线程并导致黑屏。`preloadFlows` 专为此场景设计，只需一次调用即可将批量请求发送至原生 SDK。 |
| 在归因数据有机会解析后再调用 `getFlow`，例如在 `activate` 后等待 1–2 秒，或在 `onLatestProfileLoad` 监听器触发后调用。 | 在 `App.tsx` 的应用启动时调用 `getFlow`。 | 此时归因数据尚未到达，流程将按默认目标受众解析，悄无声息地绕过市场细分和 ASA 个性化设置。 |
| 保持默认的 `loadTimeoutMs` 5000 毫秒，或设置其他合理值，并为每个版位配置[备用付费墙](fallback-paywalls)。 | 给 `getFlow` 传入一个极大的 `loadTimeoutMs`，使其实际上永远不会触发。 | 如果超时永远不触发，网络较差的用户将看到空白屏幕，直到网络恢复——或者直接关闭应用。 |

有关 `fetchPolicy` 和 `loadTimeoutMs` 参数的说明，请参阅[获取自定义付费墙和产品](fetch-paywalls-and-products-capacitor)；有关选择合适版位的说明，请参阅[版位](placements)。

## 预加载版位 \{#preload-placements\}

:::info
`preloadFlows` 和 `preloadFlowsForDefaultAudience` 从 SDK 4.3.0 版本开始支持。
:::

`preloadFlows` 会提前缓存流程 JSON。之后按正常流程使用即可：`getFlow` 获取流程，`createFlowView` 创建对应的视图。

`fetchPolicy` 决定后续 `getFlow` 优先从哪一层读取数据，而不是决定是否能访问缓存：

- `'return_cache_data_else_load'` 优先读取预加载的副本，仅在无缓存时才请求网络。`'return_cache_data_if_not_expired_else_load'` 的行为相同，但仅在副本未超过 `maxAgeSeconds` 时有效。
- 默认值 `'reload_revalidating_cache_data'` 优先请求网络，当请求失败或超时时回退到预加载的副本。

预加载在两种情况下都有收益，但方式不同：缓存优先策略会直接省去网络请求，而默认策略则保留请求并以预热的副本作为备用。在[测试设备](test-devices)上，`getFlow` 在所有策略下都会跳过缓存，仅在网络请求失败时才使用预加载的副本。

适用场景：当你知道本次会话需要用到哪些版位，但暂时不想展示时——例如，用户尚未点击的按钮背后的流程。

:::warning
预加载在运行时就会确定目标受众。如果你在归因数据到达之前进行预加载，然后又以缓存优先的 `fetchPolicy` 调用 `getFlow`，用户将看到在没有归因数据的情况下所选的实验变体，从而绕过市场细分和 ASA 个性化。请在归因数据有机会解析之后再执行预加载——例如，在 `onLatestProfileLoad` 监听器触发之后——或者保持默认的 `fetchPolicy`。
:::

```typescript showLineNumbers

try {
  await adapty.preloadFlows({
    placementIds: ['onboarding', 'main_paywall'],
    params: { loadTimeoutMs: 5000 },
  });
} catch (error) {
  // at least one placement failed to preload
}

// Later, when the user reaches the paywall:
const flow = await adapty.getFlow({
  placementId: 'main_paywall',
  params: { fetchPolicy: 'return_cache_data_else_load' },
});
```

**参数：**

- `placementIds`（必填）：要预加载的版位。
- `params.loadTimeoutMs`（可选）：预加载的总体时间限制，单位为毫秒。默认值为 5000，低于 1000 的值将被提升为 1000。未在时限内加载完成的版位将按默认目标受众获取。

**以下行为值得注意：**

- 只有在所有版位都尝试失败后，调用才会失败，并返回一个覆盖所有失败版位的 `AdaptyError`。某个版位失败不会中断其他版位的加载，已成功加载的版位仍会保留在缓存中。
- 预加载始终走网络请求：它没有自己的 `fetchPolicy`。
- 预加载仅用于预热缓存，不返回内容——你仍需调用 `getFlow` 来展示内容。

### 预加载涵盖的内容 \{#what-a-preload-covers\}

流程到达屏幕需要经过多个层次。预加载覆盖第一层，与 `getFlow` 的作用完全相同：

| 层级 | 获取方式 | 是否通过预加载缓存 |
|---|---|---|
| Flow JSON — 选定的实验变体、其产品 ID 及远程配置 | `getFlow` | 是 |
| UI 布局 — 页面的结构、样式与文本 | `createFlowView` | 否 |
| 图片，包括代替视频元素显示的静态帧 | `createFlowView`，在后台执行 | 否 |
| 产品 | `createFlowView` 或 `getPaywallProducts` | 否 |
| 视频文件 | 系统播放器，在页面渲染时加载 | SDK 不缓存 |

`createFlowView` 按以下顺序在三个位置查找布局：

1. 原生 SDK 的磁盘缓存，在应用重启后仍然有效。
2. 如果您在最近一次发布流程后下载了 SDK 4.4 或更高版本的[备用文件](capacitor-use-fallback-paywalls)，则使用该文件。
3. 通过网络请求 Adapty。即使已预加载，每次仍需一次完整的网络往返。每当应用首次展示某个已发布版本的流程时，原生 SDK 会发起该请求，然后将布局保存到磁盘缓存中。

当 `createFlowView` 的 `loadTimeoutMs` 触发时，原生 SDK 不会回退到备用方案，而是再次向 Adapty API 请求布局。`loadTimeoutMs` 不限制第二次请求的时间。

### 跳过目标受众分群 \{#skip-audience-segmentation\}

如需完全跳过目标受众分群直接预热缓存，请使用 default-audience 变体。该方式无需超时设置：

```typescript showLineNumbers
await adapty.preloadFlowsForDefaultAudience({ placementIds: ['main_paywall'] });
```

后续调用 `getFlowForDefaultAudience` 读取缓存副本的方式，与 `getFlow` 读取 `preloadFlows` 缓存副本的方式相同。

## 从应用包中显示首屏媒体内容 \{#show-first-screen-media-from-the-app-bundle\}

流程会从 Adapty 下载图片和视频。若想让首屏媒体内容立即显示，可以改为从应用包中提供。这是复用已有资源的好方法，例如现有原生用户引导中的视觉素材。

1. 在流程和付费墙编辑工具中，为图片或视频设置[自定义媒体 ID](custom-media#custom-media-id)。上传的文件将作为备用资源。
2. 将文件添加到原生项目中：iOS 应用包和 Android `assets` 文件夹。
3. 创建流程视图时，在 `customAssets` 中为该 ID 传入对应的本地文件：

```typescript showLineNumbers

// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
const bundledAssets: Record<string, AdaptyCustomAsset> = {
  'welcome_video': {
    type: 'video',
    fileLocation: {
      ios: { fileName: 'welcome.mp4' },
      android: { relativeAssetPath: 'videos/welcome.mp4' },
    },
  },
};

const view = await createFlowView(flow, { customAssets: bundledAssets });
```

打包文件会增加应用的下载体积，因此只打包用户首先看到的媒体资源。

捆绑的图片会立即显示，无需等待，但原生 SDK 仍会在后台下载已上传的图片。

未捆绑的媒体文件同样能立即显示：流程布局中包含每张图片的低分辨率缩略图（包括视频的静态帧），并在完整文件加载完成前持续显示该缩略图。

有关 `customAssets` 的完整参考，请参阅[自定义资源](capacitor-get-pb-paywalls#customize-assets)。

## 针对弱网环境进行调优 \{#tune-for-poor-connectivity\}

对于网络连接持续较差的市场（农村地区、交通中转区域或受路由问题影响的地区）：

- 在除第一次之外的所有请求中设置 `fetchPolicy: 'return_cache_data_else_load'`。
- 在 Adapty 看板中为每个版位配置[备用付费墙](fallback-paywalls)。
- 在速度与精准定向之间合理权衡 `loadTimeoutMs`。超时时间越短，用户越快看到备用内容；超时时间越长，目标流程就有更多时间加载。
- [保持流程轻量化](flow-size)，以便布局文件更快下载完成。
- 不要将流程展示与 `adapty.getProfile()` 绑定。独立调用 `getFlow`，避免因用户画像加载缓慢而阻塞 UI。
