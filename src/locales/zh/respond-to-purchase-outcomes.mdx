付费墙屏幕之后，流程可以继续进行——恢复用户引导流程、向新订阅者展示感谢页面，或欢迎那些恢复早期购买的用户回归。

您可以在操作设置中为每种购买条件设置对应的结果。未设置操作的结果会让用户停留在付费墙页面。

- **Purchase** 操作包含以下条件：**When succeeded**、**When failed**、**When cancelled by user** 和 **When pending**。
- **Restore purchases** 操作包含两个条件：**When restore completed** 和 **When restore failed**。

## 开始之前 \{#before-you-start\}

确保已满足以下条件：

- 您的应用使用 Adapty SDK v4.0 或更高版本。
- 流程中包含一个付费墙页面。要创建该页面，请参照[创建基础付费墙页面](basic-paywall-screen)教程。
- 付费墙页面上的某个元素（例如按钮）配置了 [**Purchase** 动作](paywall-product-block#trigger-a-purchase)。
- 您的应用在流程保持开启状态时处理相关回调，可参考 <InlineTooltip tooltip="购买与恢复回调">[iOS](ios-handling-events)、[Android](android-handling-events)、[React Native](react-native-handling-events-1)、[Flutter](flutter-handling-events)、[Unity](unity-handling-events)、[Kotlin Multiplatform](kmp-handling-events) 和 [Capacitor](capacitor-handling-events)</InlineTooltip>。

## 为结果添加动作 \{#add-actions-for-a-result\}

:::important
流程只能响应 **In-App Store** 购买的结果，不支持 **Web Payment** 购买的结果。
:::

1. 选择已配置 **Purchase** 或 **Restore purchases** 动作的元素。
2. 点击 **Purchase** 或 **Restore purchases** 动作。
3. 找到您需要处理的购买或恢复结果（例如 **When succeeded**），点击 <Inline id="plus.svg" alt="Add action" />。
4. 在 **Action** 下拉菜单中，选择要执行的动作以替换 **Do nothing**。

:::note
在同一触发器中，位于 **Purchase** 或 **Restore purchases** 之后的导航或 **Close Flow** 动作会立即执行，而不会等待结果。请将其作为结果动作添加。
:::

:::tip
当 **Purchase** 动作包含结果动作时，双击不会触发第二次购买。在商店返回结果之前（最长 60 秒），流程会忽略对该动作的后续点击。**Restore purchases** 的行为与此相同。
:::

要在你的应用中查看结果动作，请[进行沙盒购买](test-purchases-in-sandbox)。

您无法在 [Adapty 移动应用的预览](paywall-device-compatibility-preview#preview-on-devices)中进行真实购买。

如果流程在您的应用中跳过了结果动作，请参阅[流程为什么跳过结果动作](flow-common-issues#the-flow-doesnt-run-the-actions-set-for-a-purchase-result)。

:::tip
如需在应用代码中处理购买结果（例如打开原生页面），请使用 Adapty SDK 的购买和恢复回调。每次修改相关代码都需要发布新版本。如果应用在购买后会打开第二个流程，可以将其页面合并到包含付费墙的流程中。
:::

### 购买成功后显示下一个页面 \{#show-the-next-screen-after-a-successful-purchase\}

若要在购买成功后继续用户引导流程或显示感谢页面，请将 **When succeeded** 结果与 [**Navigate to Screen**](onboarding-actions#navigate-to-screen) 动作配对，并将目标页面设置为跳转目标。

### 购买成功后关闭流程 \{#close-the-flow-after-a-successful-purchase\}

购买成功后如需结束流程，请在 **When succeeded** 中添加 [**Close Flow**](onboarding-actions#close-flow)，而不是使用导航操作。这样流程只会在购买成功时关闭，无需在应用代码中手动处理关闭逻辑。

### 响应失败、取消或待处理的购买 \{#respond-to-a-failed-canceled-or-pending-purchase\}

要在购买失败、取消或待处理后显示提示框或跳转页面，请为 **Purchase** 动作的以下结果添加相应操作：

- **When failed**: 发生错误导致购买失败。例如，[显示一个提示框](onboarding-actions#show-alert)，让用户稍后重试。
- **When cancelled by user**: 用户取消了购买。例如，可以展示另一个优惠页面。
- **When pending**: 购买正在等待审批，例如银行正在确认付款，或家长正在通过 iOS 的"购买申请"功能进行审批。当银行或家长完成审批后，流程不会自动响应，因此请显示一个页面，说明用户需要等待的原因。

:::tip
如需让用户在购买失败后重新尝试，请将其留在付费墙上，例如通过 **When failed** 配置一个提示。你无法将 **Purchase**、**Restore purchases** 或 [**Request permission**](onboarding-actions#request-permission) 添加到结果中。
:::

### 响应购买恢复 \{#respond-to-a-purchase-restoration\}

[**Restore purchases**](paywall-product-block#restore-purchases) 操作有两种结果：**When restore completed** 和 **When restore failed**。

**When restore completed** 表示恢复操作完成且未发生错误，并不代表用户已获得访问权限。在流程中无法验证访问等级。如需根据访问权限显示内容，请在 **When restore completed** 时添加 **Close Flow** 操作，然后在应用中验证[访问等级](access-level)。
