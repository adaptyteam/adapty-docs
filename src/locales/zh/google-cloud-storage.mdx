启用 Google Cloud Storage 集成，将[订阅事件](events)和[付费墙访问数据](paywall-metrics)安全地存储到同一个中心位置：你的 Google Cloud Storage 存储桶。

每天 UTC 时间凌晨 4 点，Adapty 会将前一天的数据以 .csv 文件形式上传到您的存储桶。您可以选择接收**事件**数据、**付费墙访问**数据，或**两者都要**。您也可以随时[手动导出](#manual-data-export)任意时间段的数据。

要设置集成，请先在 Google Cloud 控制台中[生成存储桶访问密钥](#create-google-cloud-storage-credentials)，然后[将其添加到 Adapty 设置中](#set-up-google-cloud-storage-integration)。

## 上传计划与时长 \{#upload-schedule-and-duration\}

Adapty 每 24 小时在 UTC 时间 04:00 向 Google Cloud Storage 上传数据。

文件包含在前一个日历日（UTC）内创建的事件数据。3 月 8 日上传的文件将包含 3 月 7 日 00:00:00 至 23:59:59 UTC 期间创建的所有事件。

该过程可能需要数小时，具体取决于队列中的文件总数以及您个人请求的数据量。如果 Adapty 在首次上传时包含历史数据，所需时间将长于后续的每日上传。

## 设置 Google Cloud Storage 集成 \{#set-up-google-cloud-storage-integration\}

您需要拥有具有**写入权限**的有效 Google Cloud 服务账号密钥。要生成该密钥，请按照[创建凭据](#create-google-cloud-storage-credentials)部分中的步骤操作。

:::warning
您可以为事件、付费墙访问记录和虚拟货币交易分别使用不同的存储桶和凭据。保存设置时，Adapty 会验证每个已启用导出项的凭据。如果任何一组凭据无效，Adapty 将不会保存任何标签页的设置。请参阅[故障排查](#troubleshooting)。
:::

前往 [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage)，打开所需的标签页（**Events** 或 **Paywall visits**），然后启用该集成。

上传包含 **Google Cloud service account key** 的文件，指定目标 **bucket** 和 **folder**，保存更改。

## 创建 Google Cloud Storage 凭据 \{#create-google-cloud-storage-credentials\}

本指南将帮助您在 Google Cloud Platform Console 中创建所需的凭据。

为了让 Adapty 将原始数据报告上传到您指定的存储桶，需要提供服务账号密钥，并授予对应存储桶的写入权限。通过提供服务账号密钥并授予存储桶写入权限，您可以允许 Adapty 安全、高效地将原始数据报告从其平台传输到您的存储环境中。

:::warning
请注意，我们仅支持服务账户 HMAC 密钥授权，因此必须确保您的服务账户 HMAC 密钥已添加"Storage Object Viewer"、"Storage Legacy Bucket Writer"和"Storage Object Creator"角色，以便正常访问 Google Cloud Storage。
:::

1. 第一步，前往您 Google Cloud 账户的 [IAM](https://console.cloud.google.com/projectselector2/iam-admin/serviceaccounts) 页面，选择相关项目或新建一个项目。

  <ZoomImage id="30a81ef-CleanShot_2023-03-17_at_15.22.142x.webp" width="700px" />


1. 接下来，点击"+ CREATE SERVICE ACCOUNT"按钮，为 Adapty 创建一个新的服务账号。

    <ZoomImage id="98f8ebf-CleanShot_2023-03-17_at_15.40.062x.webp" width="700px" />

2. 填写第一步中的字段，访问权限将在后续阶段授予。如需了解该页面的更多详情，请参阅[此处](https://docs.cloud.google.com/iam/docs/service-accounts-create)的文档。

    <ZoomImage id="2190c50-CleanShot_2023-03-17_at_15.48.552x.webp" width="700px" />

3. 要创建并下载[私有 JSON 密钥](https://docs.cloud.google.com/iam/docs/keys-create-delete)，请导航到 KEYS 部分，然后点击"ADD KEY"按钮。

    <ZoomImage id="8a45468-CleanShot_2023-03-17_at_15.58.092x.webp" width="700px" />

4. 在 DETAILS 部分，找到与刚刚创建的服务账号关联的 Email 值并复制。在后续步骤中，您需要用到此信息来授权该账号并允许其写入存储桶。

    <ZoomImage id="6ccd0f0-CleanShot_2023-03-17_at_16.03.162x.webp" width="700px" />
    

5. 接下来，前往 Google Cloud Storage 的 [Buckets](https://console.cloud.google.com/storage/browser) 页面，选择已有的存储桶或创建新存储桶，用于存储来自 Adapty 的 Event 或 Visits Data 报告。然后导航到 PERMISSIONS 部分，选择 [GRANT ACCESS](https://docs.cloud.google.com/identity/docs/how-to?hl=en) 选项。

    <ZoomImage id="3cdd937-CleanShot_2023-03-17_at_16.14.232x.webp" width="700px" />

6. 在 PERMISSIONS 部分，输入在第五步中获取的服务账户 Email，然后选择 Storage Object Creator 角色。最后，点击 SAVE 保存更改。

    <ZoomImage id="62801f4-CleanShot_2023-03-17_at_16.17.312x.webp" width="700px" />

    请记住存储桶的名称，以备后续使用。

## 手动数据导出 \{#manual-data-export\}

除了自动将事件数据导出到 Google Cloud Storage 之外，Adapty 还提供手动文件导出功能。使用此功能，您可以选择特定时间段的事件数据，并手动将其导出到您的 GCS 存储桶。这使您能够更好地控制导出哪些数据以及何时导出。

指定的日期范围将用于导出从日期 A 00:00:00 UTC 到日期 B 23:59:59 UTC 期间创建的事件。

## 虚拟货币交易 \{#virtual-currency-transactions\}

虚拟货币导出功能会将每次[虚拟货币](virtual-currencies)余额变动记录发送到您的 Google Cloud Storage 存储桶。您可以用它将积分、消耗、到期和退款的完整历史记录加载到自己的数据仓库中。

此导出功能与事件导出和付费墙访问导出相互独立，拥有各自的开关、凭据以及独立的存储桶和文件夹设置。

### 开启导出 \{#turn-on-the-export\}

1. 前往 [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage)，打开 **Virtual currency** 标签页。
2. 开启 **Export virtual currency transactions to Google Cloud Storage**。
3. 上传包含您的 [Google Cloud 服务账号密钥](#create-google-cloud-storage-credentials) 的文件，并指定存储桶和文件夹。这些字段与 **Paywall visits** 标签页中的字段相同。

如需导出过往日期的虚拟货币交易记录，请使用[手动数据导出](#manual-data-export)。

### 文件与时间安排 \{#file-and-schedule\}

Adapty 每天上传 1 个文件，包含前一个自然日（UTC 时间）的虚拟货币交易记录。每笔交易归属于其 `created_at` 时间（UTC）所在的日期。

文件名格式为 `<app_id>_virtual_currency_<date>.csv`，其中 `<date>` 是交易日期的次日，格式为 `YYYY-MM-DD`。例如，文件 `<app_id>_virtual_currency_2026-03-08.csv` 包含 2026 年 3 月 7 日的交易记录。每次导出都有独立的文件名。建议将每种导出数据存放在各自的文件夹中，这样读取整个文件夹的表格或加载器只会获取同一类型的文件。如果多种导出共用同一文件夹，可通过文件名筛选此导出的文件：`<app_id>_virtual_currency_*.csv`。

该文件是带有标题行的 UTF-8 `.csv` 文件。若某天没有交易，则文件中仅包含标题行。

每一行代表某种货币的一次余额变动。如果一笔交易涉及两种货币（例如用金币兑换宝石），则会生成两行数据，且这两行的 `vc_transaction_id` 相同。沙盒交易也会包含在文件中，其 `is_sandbox` 字段设置为 `true`。

保存设置时，Adapty 会验证所有已开启导出项的凭据。如果虚拟货币的凭据无效，Adapty 将不会保存设置。**Save** 按钮会保存所有标签页的设置，因此其他标签页的更改也不会被保存。

虚拟货币导出使用独立的凭据。如果当天的上传失败，应用的事件和付费墙访问记录的上传仍会正常运行。

### 列说明 \{#columns\}

文件包含以下列，按顺序排列。Adapty 仅在文件末尾追加新列。

| 列名 | 描述 |
| :----- | :---------- |
| **vc_transaction_id** | 虚拟货币交易的 Adapty ID。同一笔交易的所有行具有相同的 ID。这不是您 API 请求的 `Idempotency-Key`。 |
| **created_at** | 交易时间，UTC 时区，格式为 `YYYY-MM-DD HH:MM:SS.ffffff+00:00`，例如 `2026-03-07 14:05:09.000000+00:00`。 |
| **profile_id** | Adapty 用户画像 ID。 |
| **customer_user_id** | 导出时该用户画像的客户用户 ID。若用户画像没有客户用户 ID 或已不存在，则为空。 |
| **operation** | 交易的[操作类型](virtual-currencies#operation)：`top_up`、`refund`、`spend`、`spend_reversal`、`reward`、`reward_reversal`、`exchange`、`expiry`、`migration` 或 `adjustment`。若服务端 API 交易未传入 `operation`，则为空。 |
| **transaction_type** | Adapty 记录该交易的方式，例如 `store_purchase`、`subscription_renewal`、`trial_start` 或 `api_transaction`。`subscription_renewal` 用于订阅的每个付费周期，包括第一个周期。 |
| **currency_code** | 虚拟货币代码。 |
| **amount** | 余额变动量，以整数表示。入账为正值，扣款为负值。 |
| **balance_after** | 本次变动后该货币在用户画像中的余额，以整数表示，最低不低于 0。 |
| **store** | 交易所在商店：`app_store`、`play_store`、`stripe`、`paddle`、`adapty` 或自定义商店名称。若交易无关联商店，则为空。 |
| **store_transaction_id** | 购买行为的商店交易 ID。与事件表中该购买对应的 **transaction_id** 相同。若交易未关联商店购买，则为空。 |
| **store_original_transaction_id** | 购买行为的原始商店交易 ID。同一订阅的所有续订具有相同的值。在商店购买、退款及过期行对应的行中填充。 |
| **product_id** | 购买行为的商店产品 ID。若该行无商店交易，或 Adapty 未记录该购买，则为空。 |
| **expires_at** | 入账金额的过期时间，UTC 时区，格式为 `YYYY-MM-DD HH:MM:SS.ffffff+00:00`，例如 `2026-04-07 14:05:09.000000+00:00`。仅在会过期的入账行中填充。 |
| **feature** | 交易的 [`feature`](virtual-currencies#feature) 字段值。 |
| **reference_id** | 交易的 `reference_id` 字段值。 |
| **customer_placement_id** | 交易的 `customer_placement_id` 字段值。 |
| **is_sandbox** | 沙盒交易为 `true`，生产环境交易为 `false`。 |
| **metadata** | 交易的 `metadata` 字段，以单个 JSON 值存储在一个单元格中。若交易无元数据，则为空。 |

### 与事件表关联 \{#join-with-the-events-table\}

虚拟货币文件中不含价格信息。如需获取某次购买所充值虚拟货币的价格，请将充值记录与事件表进行关联：

- 用 **store_transaction_id** 匹配事件表中的 **transaction_id**。
- 同时匹配 **store** 字段，但仅适用于 `app_store`、`play_store`、`stripe` 和 `paddle`。对于 `adapty` 及自定义商店，事件表中的 **store** 字段为空。

以下示例查询假设你已将虚拟货币文件加载到 `vc_transactions` 表中，将事件文件加载到 `events` 表中：

```sql title="SQL"
SELECT
  vc.vc_transaction_id,
  vc.created_at,
  vc.profile_id,
  vc.currency_code,
  vc.amount,
  e.event_type,
  e.product_id,
  e.revenue_usd,
  e.currency,
  e.revenue_local
FROM vc_transactions AS vc
LEFT JOIN events AS e
  ON e.transaction_id = vc.store_transaction_id
  AND (
    e.store = vc.store
    OR vc.store NOT IN ('app_store', 'play_store', 'stripe', 'paddle')
  )
  AND e.event_type IN (
    'subscription_initial_purchase',
    'subscription_started',
    'subscription_renewed',
    'trial_started',
    'trial_converted',
    'non_subscription_purchase'
  )
WHERE vc.amount > 0
  AND COALESCE(vc.store_transaction_id, '') <> '';
```

该查询列出了默认事件名称。在 2025 年 9 月中旬之后创建的集成中，订阅开始事件为 `subscription_initial_purchase`；在此之前创建的集成中则为 `subscription_started`。如果你在事件导出设置中修改过事件名称，请在查询中使用你自定义的名称。

如果事件导出已关闭、事件导出设置中排除或重命名了该购买类型的事件，或者 **Exclude historical events** 将该事件排除在外，则账单行将没有对应的匹配事件。

一笔购买可以为多种货币记账。每种货币各自对应一行记录，所有这些行共同关联同一个事件。在统计收入时，每个 **store_transaction_id** 只计一次。

### 限制 \{#limitations\}

- **无价格或退款金额**：虚拟货币文件不含购买价格和退款金额。如需获取价格，请[将积分行与事件表关联](#join-with-the-events-table)。
- **不要将两个文件的积分相加**：[事件](#events)文件的 **virtual_currency_credits** 列与虚拟货币文件中的积分行显示的是同一笔购买积分。统计积分时，二选一即可，不要同时使用。两者的总量可能不同：事件文件仅包含购买行为产生的积分，且仅限于其设置导出的事件；而虚拟货币文件记录了所有余额变动，包括通过 API 发放的积分以及在看板中手动调整的金额。
- **消费与积分之间无关联**：文件不显示某次消费使用了哪些积分，例如无法区分是使用了购买积分还是赠送积分。
- **退款行仅显示被扣回的积分**：退款行显示 Adapty 从余额中扣回的积分数量。其 **amount** 可能小于该购买订单最初授予的积分，例如用户已消费了其中一部分。如果没有剩余积分可扣，文件中将不会出现退款行。
- **订阅升级不产生退款行**：由订阅升级触发的退款不会扣回任何积分，因此文件中不会有对应的退款行。

## 故障排查 \{#troubleshooting\}

保存设置时，Adapty 会验证所有已开启导出的密钥。如果某个密钥无效，Adapty 将不会保存任何标签页的设置，并显示错误提示。

每个导出使用各自的密钥上传文件，因此某个密钥过期只会导致该导出的上传中断。为确保上传持续正常运行，请在密钥过期前及时更换。如果多个标签页使用同一个密钥，请在每个标签页中分别更换：**Events**、**Paywall visits** 和 **Virtual currency**。
