这是 Adapty Analytics 中可用数据图表的概览。通过它可以了解每项数据图表的含义，以及它与相关数据图表的区别。

如需深入了解 Adapty 处理分析数据的方式，请参阅[Adapty 分析原理](how-adapty-analytics-works)。

:::note
本文不涵盖 [Adapty 归因](adapty-user-acquisition) 数据图表。请阅读 [Adapty 归因分析](ua-analytics)，了解广告活动相关指标（包括 Spend、CPI、ROAS、CTR 等）。
:::
## 全局数据图表 \{#global-metrics\}

全局数据图表用于追踪您整个应用在所有版位和付费墙中的表现。

### 营收 \{#revenue\}

这些数据图表衡量应用产生了多少收入以及收入来源。
| 数据图表 | 描述 | 主要区别 | <InlineTooltip tooltip="基于同期群？">基于同期群的数据图表按更早的事件（安装、付费墙查看、试用开始）对用户分组，然后持续跟踪这些用户后续的行为，因此某个过去日期的数值会持续增长。其他所有数据图表均按事件发生当天进行统计。</InlineTooltip> |
|--------|-------------|----------------|:---:|
| [Revenue](revenue) | 订阅和一次性购买的总收入，扣除退款 | 实际产生的收入。根据[数据图表控件](controls-filters-grouping-compare-proceeds)，可显示总收入、扣除平台佣金后的收入或扣除税费和佣金后的收入 | 否 |
| [MRR](mrr) | 来自活跃订阅的月度经常性收入 | 应用可预期的月度收入。不含一次性购买和非循环订阅。 | 否 |
| [ARR](arr) | 来自活跃订阅的年度经常性收入 | 计算方式与 MRR 相同，但以年为维度。适用于预测年度收入 | 否 |
| [ARPU](arpu) | 每用户平均收入 | 用收入除以用户总数（含付费与非付费用户），反映每位用户平均产生的收入 | 否 |
| [ARPPU](arppu) | 每付费用户平均收入 | 仅统计在所选周期内有过购买行为的用户（含已退款的交易）。始终高于 ARPU | 否 |
| [LTV（生命周期价值）](ltv) | 付费客户总收入除以同期群中付费客户数量 | 每位付费客户随时间累积的实际价值。与 ARPPU（单一周期）不同，LTV 展示整个客户关系周期内的总收入。可按续订次数或按日历天数查看 | 是 |
| [趋势预测 LTV](predicted-ltv-and-revenue) | 同期群中每位用户的预估生命周期价值 | 面向未来的预估值。与已实现的 LTV 不同，它根据历史同期群留存规律预测未来价值。支持 3、6、9、12、18 和 24 个月 | 是 |
| [趋势预测收入](predicted-ltv-and-revenue) | 同期群预计产生的总收入估算 | 面向未来的预估值。与已实现的 Revenue 不同，它预测同期群在所选时间范围内的总收入。每日更新 | 是 |
| [Non-subscriptions](non-subscriptions) | 应用内购买次数：消耗型商品、非消耗型商品及不可续期订阅 | 不含自动续期订阅。 | 否 |
| [退款事件](refund-events) | 退款购买或订阅的数量 | 按退款日期归因，而非原始购买日期。 | 否 |
| [退款金额](refund-money) | 所选周期内的退款总金额 | 退款的财务影响。在扣除平台费用前计算。与退款事件（计数）不同，此指标显示的是货币金额 | 否 |

### 订阅者与转化 \{#subscribers-and-conversion\}

以下数据图表用于追踪用户进入应用后在各漏斗阶段的流转情况。
| 数据图表 | 描述 | 关键区别 | <InlineTooltip tooltip="基于同期群？">基于同期群的数据图表按早期事件（安装、付费墙浏览、试用开始）对用户进行分组，然后持续统计这些用户后续的行为，因此过去某个日期的数值会持续增长。其他所有数据图表则统计事件发生当天的数量。</InlineTooltip> |
|--------|-------------|----------------|:---:|
| [安装量](installs) | 该时期内的应用安装次数 | 根据[安装定义](general#4-installs-definition-for-analytics)统计以下之一：<br /> • 设备安装次数（重新安装应用的用户会被再次计入）<br /> • 唯一用户数（仅统计设置了 `customer_user_id` 的用户。匿名用户完全排除在外——如果没有已识别用户，计数为 0） | 否 |
| [新增试用](new-trials) | 该时期内激活的试用 | 统计每次试用开始，即使查看数据图表时试用已到期或已转为付费 | 否 |
| [活跃试用](active-trials) | 尚未到期的试用数量 | 仅统计该时期结束时仍处于活跃状态的试用 | 否 |
| [新增订阅](reactivated-subscriptions) | 该时期内首次激活的订阅，包括无试用的直接购买和试用转付费 | 不含续订和重新激活。与集成事件 `subscription_started` 不同，该事件仅统计无试用的直接购买——试用转化会触发 `trial_converted` | 否 |
| [活跃订阅](active-subscriptions) | 尚未到期的付费订阅数量 | 不含试用和已取消续订的订阅 | 否 |
| [安装到试用转化率](analytics-conversion#install---trial) | 安装用户中开始试用的百分比 | 以安装日期为准。分母包含所有安装用户，而不仅是浏览付费墙的用户，因此该转化率可能低于付费墙浏览到试用转化率。如果应用未记录付费墙浏览，两个数据图表也可能出现差异。这可能发生在自定义付费墙未调用 `logShowFlow`（iOS SDK v4+）/ `logShowPaywall` 的情况下，或用户通过[推广应用内购买](https://developer.apple.com/documentation/storekit/supporting-promoted-in-app-purchases-in-your-app)开始试用时。 | 是 |
| [付费墙浏览到试用转化率](analytics-conversion#paywall-view---trial) | 浏览付费墙用户中开始试用的百分比 | 以付费墙浏览日期为准。仅统计浏览过付费墙的用户，因此该转化率可能高于安装到试用转化率 | 是 |
| [试用到付费转化率](analytics-conversion#trial---paid) | 试用用户中购买订阅的百分比 | 以试用开始日期为准，因此同一次试用在此处的日期与安装到试用转化率中的日期不同。衡量试用质量和转化效率。与安装到付费转化率不同，仅关注完成试用的用户 | 是 |
| [安装到付费转化率](analytics-conversion#install---paid) | 安装用户中购买首个订阅的百分比 | 以安装日期为准。统计所有安装用户，而不仅是浏览付费墙的用户。该转化率可能低于付费墙浏览到付费转化率。包含直接购买和试用转付费 | 是 |
| [付费墙浏览到付费转化率](analytics-conversion#paywall-view---paid) | 浏览付费墙用户中最终购买订阅的百分比 | 以付费墙浏览日期为准。仅统计浏览过付费墙的用户，因此该转化率可能高于安装到付费转化率。包含先完成试用后转付费的用户 | 是 |

### 留存与订阅续费 \{#retention-and-subscription-renewal\}

这些数据图表用于追踪应用留住付费用户的能力。它们均为 <InlineTooltip tooltip="基于同期群">基于同期群的数据图表按照较早发生的事件（如安装、付费墙查看、试用开始）对用户进行分组，然后持续统计这些用户后续的行为，因此历史日期的数值会随着每个同期群的续费而不断增长。其他数据图表则统计事件发生当天的数量。</InlineTooltip>，因此历史日期的数值会随着各同期群不断续费而持续增长。

| 数据图表 | 描述 | 关键区别 |
|--------|-------------|----------------|
| [留存率](analytics-retention) | 每个计费周期后仍保持订阅的原始订阅者比例——第 1 次续订、第 2 次续订，以此类推 | 从首次付款起追踪订阅者。与下方的周期间数据图表不同，始终与原始群体进行比较，因此可以一目了然地了解全貌 |
| [付费至第 2 个周期](analytics-conversion#paid---2nd-period) | 首次订阅者续订至第二个周期的百分比 | 衡量两个相邻特定周期之间的转化。与留存率不同，专注于最关键的单次续订——即第一次续订 |
| [第 2 至第 3 个周期](analytics-conversion#2nd-period---3rd-period) | 从第 2 个周期续订至第 3 个周期的百分比 | 反映初次续订后的早期留存稳定性 |
| [第 3 至第 4 个周期](analytics-conversion#3rd-period---4th-period) | 从第 3 个周期续订至第 4 个周期的百分比 | 中期留存指标 |
| [第 4 至第 5 个周期](analytics-conversion#4th-period---5th-period) | 从第 4 个周期续订至第 5 个周期的百分比 | 长期忠诚度指标 |
| [6 个月以上](analytics-conversion#6-months-) | 首次订阅者持续订阅超过 6 个月的百分比 | 以首次付款日期为起点，而非以 6 个月节点为准。衡量日历时间，而非续订次数——年度订阅者即使未发生续订，在 6 个月时也计为已留存 |
| [1 年以上](analytics-conversion#1-year-) | 首次订阅者持续订阅超过 12 个月的百分比 | 以首次付款日期为起点。年度留存里程碑 |
| [2 年以上](analytics-conversion#2-years-) | 首次订阅者持续订阅超过 24 个月的百分比 | 以首次付款日期为起点。长期留存里程碑 |

### 流失率 \{#churn\}

这些数据图表用于衡量应用流失的订阅者和试用用户数量。这些指标均非 <InlineTooltip tooltip="基于同期群">基于同期群的指标按更早的事件（安装、付费墙浏览、试用开始等）对用户进行分组，然后持续追踪这些用户后续的行为，因此过去某个日期的数值会持续增长。其他所有指标则按事件发生当天进行计数。</InlineTooltip> — 每个事件均按其发生当天计算。

| 数据图表 | 描述 | 主要区别 |
|--------|-------------|----------------|
| [取消续期的试用](trials-renewal-cancelled) | 用户关闭了自动续期的试用 | 用户保留试用访问权限直到到期，但不会自动转为付费。与取消续期的订阅不同，此指标适用于尚未付费的试用用户 |
| [已过期（已流失）的试用](expired-churned-trials) | 已过期的试用——用户失去了对高级功能的访问权限 | 用户已失去访问权限。归因于到期日期，即使用户在上一周期取消了续期也如此。可按原因分组（主动取消 vs. 账单问题） |
| [取消续期的订阅](cancelled-subscriptions) | 用户关闭了自动续期的订阅 | 用户在周期结束前仍有访问权限。表示流失风险，而非实际流失——用户可能在周期到期前重新开启自动续期 |
| [已流失（已过期）的订阅](churned-expired-subscriptions) | 已过期的订阅——用户失去了对高级功能的访问权限 | 实际流失。用户已失去访问权限。归因于到期日期，即使用户在上一周期取消了续期也如此。可按原因分组（主动取消 vs. 账单问题） |

| [账单问题转化收入](billing-issue-converted-revenue) | 来自账单问题恢复的收入 | 账单问题恢复的财务影响 | 否 |

## 付费墙、版位与用户引导数据图表 \{#paywall-placement-and-onboarding-metrics\}

这些数据图表分别针对各个[付费墙](paywall-metrics)、[版位](placement-metrics)和用户引导进行计算，衡量特定付费墙或版位的表现，而非应用整体的表现。**关联全局数据图表**列显示全局分析部分中对应的数据图表。

只有在开启**Filter metrics by install date**时，这些数据图表才基于同期群计算。默认情况下，每个事件按其发生的日期计入统计。

| 数据指标 | 描述 | 主要区别 | 关联全局指标 |
|--------|-------------|----------------|---------------|
| [收益](paywall-metrics#proceeds) | 扣除税费和佣金后，单个版位的收入 | 等同于扣除税费和佣金后的[收入](revenue) | [收入](revenue) |
| [ARPPU](paywall-metrics#arppu) | 该付费墙或版位的每付费用户平均收入 | 计算方式与全局 ARPPU 相同，但范围限定在单个付费墙或版位 | [ARPPU](arppu) |
| [ARPAS](paywall-metrics#arpas) | 收入除以活跃订阅者数量（含试用和付费用户） | 包含试用用户。与 ARPPU 不同，反映整个订阅用户群的收入潜力 | — |
| [浏览量](paywall-metrics#views) | 付费墙或版位的累计展示次数 | 统计每次展示。同一用户浏览同一付费墙两次计为 2 次浏览 | — |
| [独立浏览量](paywall-metrics#unique-views) | 浏览过付费墙或版位的独立用户数 | 每位用户仅计一次，无论浏览多少次。与浏览量不同，衡量的是覆盖范围而非互动频率 | — |
| [购买转化率](paywall-metrics#cr-to-purchases) | 购买次数除以总浏览量 | 分母使用总浏览量（含同一用户的重复浏览） | [付费墙浏览到付费](analytics-conversion#paywall-view---paid) |
| [独立用户购买转化率](paywall-metrics#unique-conversion-rate-cr-to-purchases) | 购买次数除以独立浏览量 | 分母使用独立浏览量。由于重复浏览者只计一次，转化率高于非独立转化率 | [付费墙浏览到付费](analytics-conversion#paywall-view---paid) |
| [试用转化率](paywall-metrics#unique-cr-to-trials) | 开始试用次数除以总浏览量 | 衡量付费墙将浏览转化为试用的效果 | [付费墙浏览到试用](analytics-conversion#paywall-view---trial) |
| [独立用户试用转化率](paywall-metrics#unique-cr-to-trials) | 开始试用次数除以独立浏览量 | 计算方式与试用转化率相同，但分母为独立浏览用户数 | [付费墙浏览到试用](analytics-conversion#paywall-view---trial) |
| [购买次数](paywall-metrics#purchases) | 该付费墙的总交易次数：包括新购、试用转化、升级、降级和续订恢复 | 不含续费。 | [收入](revenue) |
| [试用次数](paywall-metrics#trials) | 通过该付费墙激活的试用总次数 | 仅限该付费墙范围内 | [新增试用](new-trials) |
| [试用取消次数](paywall-metrics#trials-canceled) | 用户关闭自动续订的试用次数 | 仅限该付费墙的试用范围 | [试用续订已取消](trials-renewal-cancelled) |
| [退款率](paywall-metrics#refund-rate) | 退款次数除以首次购买次数（不含续费） | 为比率（%），非计数。将退款次数标准化为相对于购买量的比率 | [退款事件](refund-events)（计数，非比率） |
| 完成次数 | 用户从第一屏到最后一屏完成用户引导流程的总次数 | 仅适用于版位和用户引导。统计每次完成，包括同一用户的重复完成 | — |
| 独立用户完成次数 | 完成用户引导流程的独立用户数 | 仅适用于版位和用户引导。每位用户仅计一次。与完成次数不同，衡量实际完成流程的用户个数 | — |
| 独立用户完成率 | 独立用户完成次数除以独立浏览量 | 仅适用于版位和用户引导。衡量用户引导效果：开始引导的用户中有多少比例实际完成了引导 | — |
