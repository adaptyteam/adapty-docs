在 Unity 中可靠地获取流程或付费墙需要做到三点：快速渲染、返回针对目标受众的实验变体，以及在网络较慢时优雅地降级。以下规则涵盖实现这一目标所需的时机选择、缓存策略和备用方案。

:::tip
规则假设 `Adapty.Activate()` 和 `Adapty.Identify()` 已完成调用。请参阅 [Unity SDK 调用顺序](unity-sdk-call-order)。
:::

## 规则与注意事项 \{#rules-and-pitfalls\}

| 应该这样做 | 不要这样做 | 原因 |
|---|---|---|
| 获取即将展示的版位，或通过 [`PreloadFlows`](#preload-placements)（SDK 4.3.0+）预热缓存。 | 在启动时自行并发调用多个 `GetFlow`。 | 自行实现的预取批量请求会阻塞主线程并导致黑屏。`PreloadFlows` 专为此场景设计，只需一次调用即可将批量请求发送至原生 SDK。 |
| 在归因有机会完成解析后再调用 `GetFlow`——例如，在 `Activate` 之后等待 1–2 秒，或等待 `OnLoadLatestProfile` 触发后再调用。 | 在 `Awake()` 中调用 `GetFlow`。 | 此时归因数据尚未到达。流程将基于默认目标受众进行解析，悄无声息地跳过市场细分和 ASA 个性化设置。 |
| 保留默认的 5 秒 `loadTimeout`，或设置其他合适的值，并为每个版位配置[备用付费墙](fallback-paywalls)。 | 给 `GetFlow` 传入一个极大的 `loadTimeout`，使其永远不会触发。 | 如果超时永远不触发，网络状况较差的用户会一直看到空白屏幕，直到网络恢复——或者直接关闭应用。 |

有关 `fetchPolicy` 和 `loadTimeout` 参数的说明，请参阅[获取自定义付费墙与产品](fetch-paywalls-and-products-unity)；有关如何选择合适版位的说明，请参阅[版位](placements)。

## 预加载版位 \{#preload-placements\}

:::info
`Adapty.PreloadFlows` 和 `Adapty.PreloadFlowsForDefaultAudience` 从 SDK 4.3.0 版本开始支持。
:::

`Adapty.PreloadFlows` 会提前缓存流程 JSON。之后按正常流程使用即可：通过 `GetFlow` 获取流程，通过 `CreateFlowView` 创建其视图。

`fetchPolicy` 决定后续 `GetFlow` 优先从哪一层读取数据，而非决定是否能访问缓存：

- `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` 优先读取预加载的缓存副本，仅在无缓存时才请求网络。`AdaptyPlacementFetchPolicy.ReturnCacheDataIfNotExpiredElseLoad(maxAge)` 在此基础上增加了时效判断：缓存副本未超过 `maxAge` 时直接使用。
- 默认策略 `AdaptyPlacementFetchPolicy.Default` 优先请求网络，仅在请求失败或超时时才回退到预加载的缓存副本。

无论采用哪种策略，预加载都能带来收益，只是方式不同：缓存优先策略会直接省去请求，而默认策略则会保留请求，同时获得一份可回退的热缓存副本。在[测试设备](test-devices)上，所有策略下 `GetFlow` 都会跳过缓存，仅当网络请求失败时才使用预加载的副本。

当你知道本次会话需要用到哪些版位，但暂时不想展示时，可以使用此方法——例如，在 `Activate` 和 `Identify` 完成后立即调用，为用户尚未点击的按钮后面的流程提前加载。

```csharp showLineNumbers title="C#"
Adapty.PreloadFlows(
    new List<string> { "onboarding", "main_paywall" },
    TimeSpan.FromSeconds(5),
    (error) => {
        if (error != null) {
            // at least one placement failed to preload
        }
    }
);

// Later, when the user reaches the paywall:
Adapty.GetFlow(
    "main_paywall",
    AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad,
    TimeSpan.FromSeconds(5),
    (flow, error) => {
        // create the flow view
    }
);
```

**参数：**

- `placementIds`（必填）：需要预加载的版位。
- `loadTimeout`（可选）：等待目标受众流程加载的超时时间。传入 `null` 或使用不带该参数的重载时，默认值为 5 秒。超时后，SDK 可改为加载默认受众的流程。

**需要了解的行为：**

- 只有当所有版位都尝试失败后，调用才会失败，并返回一个 `NetworkFailed` 错误，其中列出所有失败的版位。某个版位的失败不会影响其他版位，已加载的版位会保留在缓存中。
- 预加载始终走网络请求：它没有自己的 `fetchPolicy`。
- 预加载仅用于预热缓存，不返回内容——显示时仍需调用 `GetFlow`。
- 缓存属于当前用户画像。在 `Identify` 或 `Logout` 之前预加载的流程，在切换后将无法找到，因此请在切换用户画像后再执行预加载。

### 预加载涵盖的内容 \{#what-a-preload-covers\}

流程到达屏幕需要经过多个层级。预加载涵盖第一个层级，与 `GetFlow` 的作用完全相同：

| 层级 | 由谁获取 | 是否通过预加载预热 |
|---|---|---|
| Flow JSON — 所选实验变体、其产品 ID 及远程配置 | `GetFlow` | 是 |
| UI 布局 — 屏幕的结构、样式与文本 | `CreateFlowView` | 否 |
| 图片，包括用于替代视频元素的静态帧 | `CreateFlowView`，在后台执行 | 否 |
| 产品 | `CreateFlowView` 或 `GetPaywallProducts` | 否 |
| 视频文件 | 系统播放器，在屏幕渲染时加载 | SDK 不缓存 |

`CreateFlowView` 按以下顺序在三个位置查找布局：

1. 原生 SDK 的磁盘缓存，应用重启后仍然有效。
2. 如果您在最后一次发布流程后才下载了备用文件，则适用于 SDK 4.4 或更高版本的[备用文件](unity-use-fallback-paywalls)。
3. 通过网络请求 Adapty。即使已预加载，也会产生一次网络往返。每次应用首次展示某个已发布版本的流程时，原生 SDK 都会发起该请求，然后将布局保存到磁盘缓存中。

当 `CreateFlowView` 的 `LoadTimeout` 触发时，原生 SDK 不会回退：它会再次向 Adapty API 请求布局。`LoadTimeout` 不会限制第二次请求的时间。

### 跳过目标受众细分 \{#skip-audience-segmentation\}

如需完全跳过目标受众细分来预热缓存，可使用默认目标受众变体。该方式无需超时设置：

```csharp showLineNumbers title="C#"
Adapty.PreloadFlowsForDefaultAudience(
    new List<string> { "main_paywall" },
    (error) => {
        // handle the error
    }
);
```

后续调用 `GetFlowForDefaultAudience` 读取缓存副本的方式与 `GetFlow` 读取 `PreloadFlows` 副本的方式相同。

## 从应用包中显示首屏媒体 \{#show-first-screen-media-from-the-app-bundle\}

流程会从 Adapty 下载图片和视频。若要让首屏媒体立即呈现，可改为从应用包中提供。这是复用已有素材的好方法，比如现有原生用户引导的视觉资源。

1. 在 Flow & Paywall Builder 中，为图片或视频设置[自定义媒体 ID](custom-media#custom-media-id)。你在那里上传的文件将作为备用资源。
2. 将文件添加到你的 Unity 项目中。
3. 创建流程视图时，使用 `SetCustomAssets` 为该 ID 传入打包的文件：

```csharp showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
var bundledAssets = new Dictionary<string, AdaptyCustomAsset>
{
    { "welcome_video", AdaptyCustomAsset.LocalVideoFile("custom_assets/videos/welcome.mp4") }
};

var parameters = new AdaptyUICreateFlowViewParameters()
    .SetCustomAssets(bundledAssets);

AdaptyUI.CreateFlowView(flow, parameters, (view, error) => {
    // handle the result
});
```

打包文件会增加应用的下载体积，因此只需打包用户首次看到的媒体资源。

捆绑的图片会立即显示，无需等待，但原生 SDK 仍会在后台下载已上传的图片。

未捆绑的媒体资源同样会立即呈现：流程布局中包含每张图片（包括视频的静帧）的低分辨率缩略图，在完整文件加载完成前会先显示该缩略图。

有关 `customAssets` 的完整参考，请参阅[自定义资源](unity-get-pb-paywalls#customize-assets)。

## 针对弱网环境进行调优 \{#tune-for-poor-connectivity\}

对于网络连接持续较差的市场（农村地区、交通沿线、受路由影响的地区）：

- 除首次请求外，每次请求均将 `fetchPolicy` 设置为 `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad`。
- 在 Adapty 看板中为每个版位配置[备用付费墙](fallback-paywalls)。
- 在速度与精准定向之间合理权衡 `loadTimeout`。超时时间越短，用户越早看到备用内容；超时时间越长，目标流程就有更多时间完成加载。
- [保持流程轻量化](flow-size)，以便布局能更快下载完成。
- 不要将流程显示与 `GetProfile` 耦合。独立调用 `GetFlow`，避免因用户画像加载缓慢而阻塞 UI。
