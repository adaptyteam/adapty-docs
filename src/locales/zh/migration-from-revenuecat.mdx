从 RevenueCat 迁移共分六个步骤。编码代理负责完成大部分工作：通过 [Adapty CLI](developer-cli) 运行迁移，并替换应用中的 RevenueCat SDK。需要人工处理的是代理无法访问的部分——密钥，以及 RevenueCat、App Store Connect 和 Google Cloud 中的相关设置。

1. [了解核心差异](#learn-the-core-differences)。
2. [将您的产品目录迁移至 Adapty](#move-your-catalog-to-adapty)。
3. 使用您的编程助手[替换 RevenueCat SDK](#replace-the-revenuecat-sdk)。
4. [将商店事件转发至 Adapty](#forward-store-events-to-adapty)。
5. [测试并发布新版本应用](#test-and-release-a-new-version-of-your-app)。
6. （可选）[导入您的交易历史记录](#optional-import-your-transaction-history)。

:::info
您的订阅用户将自动完成迁移

所有曾经激活过订阅的用户，一旦打开集成了 Adapty SDK 的新版本应用，就会立即迁移到 Adapty。订阅状态验证和高级权限访问将自动恢复。
:::

在发布集成了 Adapty SDK 的新版本应用之前，请务必查阅我们的[发布检查清单](release-checklist)。

## 了解核心差异 \{#learn-the-core-differences\}

Adapty 与 RevenueCat 的 SDK 设计思路相近。最大的区别在于网络使用方式和响应速度：Adapty SDK 的设计目标是在你需要时尽可能快地返回信息。例如，在请求付费墙时，你会先获取[远程配置](customize-paywall-with-remote-config)以预构建用户引导或付费墙，然后通过专门的请求来获取产品信息。

命名方式略有不同：

| RevenueCat  | Adapty          |
| :---------- | :-------------- |
| Package     | 产品         |
| Offering    | 付费墙         |
| Paywall     | 付费墙编辑工具 |
| Entitlement | 访问等级    |

Adapty 有一个[版位](placements)的概念。它是应用内用户可以进行购买的逻辑位置。大多数情况下，你会有一个或两个版位：

- 用户引导（因为 80% 的购买都发生在这里）；
- 通用版位（在用户引导结束后，在设置页面或应用内展示）。

## 将您的商品目录迁移至 Adapty \{#move-your-catalog-to-adapty\}

商品目录迁移会基于您的 RevenueCat 项目创建一个新的 Adapty 应用：将权益转换为访问等级，将软件包转换为产品，并为每个 offering 创建对应的付费墙和版位。

### 开始之前 \{#before-you-start\}

- 使用能够运行终端命令的编程智能体，例如 Claude Code、Codex 或 Cursor。
- 在智能体使用的终端中，[安装 Adapty CLI](developer-cli-quickstart) 并[登录](developer-cli-authentication)。
- 在 RevenueCat 中，为要迁移的项目[创建一个 Secret API Key（v2）](#create-a-revenuecat-secret-api-key)。
- 检查商店。迁移仅支持 App Store 和 Google Play 应用。

### 创建 RevenueCat 密钥 API \{#create-a-revenuecat-secret-api-key\}

Adapty 使用密钥 API 读取你要迁移的 RevenueCat 项目目录。由于密钥属于单个项目，请在对应项目中创建该密钥。

1. 要打开密钥列表，请在 RevenueCat 看板中打开项目，然后进入 **API keys**。
2. 要创建密钥，请点击 **New secret API key**。
3. 要配置密钥，输入一个名称（例如 `Adapty migration`），并在 **API version** 中选择 **V2**。
4. 要让 Adapty 读取目录，将 **Project configuration permissions** 设置为 **Read only**。Adapty 不需要其他权限。
5. 要创建密钥，请点击 **Generate**，然后复制它。

:::warning
请使用 secret API key，而不是 public key。Public app-specific key 无法读取项目配置。
:::

<ZoomImage id="rc-api-key.webp" width="600px" alt="RevenueCat secret API key form with API version V2 and Project configuration permissions set to Read only" />

当迁移工具要求提供密钥时，将其粘贴到打开的 Adapty 看板页面中。

### 运行目录迁移 \{#run-the-catalog-migration\}

1. 要开始迁移，请向您的智能体发出请求：

   ```text
   Migrate my RevenueCat project to a new Adapty app called "Acme Fitness" with the Adapty CLI.
   ```

2. 若要连接 RevenueCat，请将私密 API 密钥粘贴到代理打开的 Adapty 看板页面中。该密钥直接传输给 Adapty，不会经过代理或 CLI。
3. 若要选择迁移内容，请告知代理哪些 RevenueCat 应用属于同一产品，通常同一产品的每个平台对应一个应用。这些应用将合并为一个 Adapty 应用。
4. 若要确认映射关系，请回答代理就无法自动映射的实体所提出的问题。

:::warning
决策一旦确认便不可更改。当所有实体都有决策后，Adapty 会创建目录，之后无法修改映射关系。
:::

Adapty 会按顺序创建访问等级、产品、付费墙和版位。如果某些步骤失败，代理会告知原因。所有实体在 Adapty 中创建完成后，迁移即告完成。

5. 要让新应用能够验证购买，请在 Adapty 看板中将其连接到应用商店：[App Store](initial_ios) 和 [Google Play](initial-android)。

:::note
若不使用代理运行迁移，请使用[迁移命令](developer-cli-reference#migrations)。`adapty migrations status` 会显示下一步操作及其所需输入。
:::

### RevenueCat 实体与 Adapty 的对应关系 \{#how-revenuecat-entities-map-to-adapty\}

- 权益标识符对应访问等级 ID，即 `customerInfo.entitlements["premium"]` 对应 `profile.accessLevels["premium"]`。
- 未授予任何权益的产品将授予 `premium` 访问等级。
- 产品套餐标识符对应版位 ID。
- 产品套餐元数据对应付费墙的[远程配置](customize-paywall-with-remote-config)，最大支持 256 KB。

### 目录迁移不包含的内容 \{#what-the-catalog-migration-leaves-out\}

- **带有 Paywall Editor 付费墙的 Offerings**：Adapty 无法导入 RevenueCat Paywall Editor 的付费墙，因此这些 Offerings 不会生成付费墙，也不会创建版位。其版位 ID 仍可自由使用：请自行创建一个使用相同 ID 的流程或付费墙。
- 不含产品的 Offerings。
- App Store 产品 ID 被 Adapty 拒绝的产品，例如 ID 中包含冒号或空格。代理会告知你具体是哪些，无需手动处理。
- App Store 和 Google Play 以外的其他应用商店中的应用。
- **集成配置**：请按照[将集成迁移到 Adapty](migrate-integrations-to-adapty) 中的说明在 Adapty 中进行配置。

## 替换 RevenueCat SDK \{#replace-the-revenuecat-sdk\}

编码智能体使用 `adapty-integration` 技能，将你应用代码中的 RevenueCat SDK 替换为 Adapty SDK。请在完成目录迁移后再运行此步骤，以确保代码使用的是新 Adapty 应用的访问等级 ID 和版位 ID。

1. 按照 [SDK 集成技能](adapty-sdk-integration-skill) 中的说明，为你的工具安装该技能，以授予智能体相应权限。
2. 在智能体中打开你的应用项目，并输入以下内容以开始迁移：

```text
   Migrate this app from RevenueCat to Adapty with the adapty-integration skill. Use my existing Adapty app "Acme Fitness".
   ```

   技能会自动从项目文件中识别你的平台和 RevenueCat SDK，所以提示词无需包含这些信息。
3. 代码迁移完成后，请查看代理的修改，然后按照项目根目录中的 `ADAPTY_SETUP.md` 完成剩余步骤。该文件列出了需要你手动处理的事项，例如需要配置的集成。

## 将商店事件转发至 Adapty \{#forward-store-events-to-adapty\}

App Store 和 Google Play 通过通知将续订、取消和退款等事件上报至你的服务器，包括发生在应用外部的事件。两项迁移操作可将 Adapty 接入这些通知，同时 RevenueCat 仍会继续接收每一个事件，确保在用户迁移到新版应用期间，双方数据始终保持同步。

请在[目录迁移](#move-your-catalog-to-adapty)完成后再启动这两项操作。Adapty 将从你在该步骤中选择的 RevenueCat 应用中获取 bundle ID 和包名。

### 转发 App Store 事件 \{#forward-app-store-events\}

Adapty 接收 App Store 通知并将每条通知转发给 RevenueCat。

在开始之前，请在 App Store Connect 中创建一个 [In-App Purchase key](in-app-purchase-api-storekit-2)，并记录其 **Issuer ID** 和 **Key ID**。

1. 要开始转发，请向你的 agent 发送以下请求：

   ```text
   Forward App Store events for my Adapty app "Acme Fitness" to Adapty, and keep RevenueCat receiving them.
   ```

2. 为了让 Adapty 访问 App Store 事件，请在代理打开的 Adapty 看板页面中上传 `.p8` 文件，并填写 **Issuer ID** 和 **Key ID**。密钥将直接发送给 Adapty，不会经过代理或 CLI。
3. 为了让 RevenueCat 继续接收 App Store 事件，请将 RevenueCat 通知 URL 提供给代理。在 RevenueCat 中，打开你的 iOS 应用，然后从 **Apple Server to Server notification settings** 中复制 **Apple Server Notification URL**。该 URL 以 `https://api.revenuecat.com/v1/incoming-webhooks/` 开头。
4. 为了将 App Store 指向 Adapty，请在 App Store Connect 中打开你的应用，然后前往 **App Information** > **App Store Server Notifications**。将 **Production Server URL** 和 **Sandbox Server URL** 均设置为代理提供给你的 Adapty URL，并选择 **Version 2** 通知。详情请参阅[启用 App Store 服务器通知](enable-app-store-server-notifications)。此时转发至 RevenueCat 的功能已开启，不会丢失任何事件。
5. 要验证连接，请告知代理 URL 已设置完成。Adapty 将向 App Store 请求测试通知并等待接收。如果通知未能送达，代理会告诉你原因。

### 转发 Google Play 事件 \{#forward-google-play-events\}

Google Play 会将通知发送到 Pub/Sub 主题。Adapty 以第二订阅者的身份订阅 RevenueCat 已使用的主题，因此 RevenueCat 仍可继续接收事件。

:::warning
不要在 Google Play Console 中更改主题，也不要按照[启用 RTDN](enable-real-time-developer-notifications-rtdn) 中的步骤操作。创建新主题会导致 RevenueCat 停止接收通知。
:::

1. 如需开始转发，请向你的 Agent 发送以下请求：

   ```text
   Forward Google Play events for my Adapty app "Acme Fitness" to Adapty, and keep RevenueCat receiving them.
   ```

2. 要让 Adapty 访问该主题，请为 RevenueCat 使用的服务账号创建一个 JSON 密钥。在 Google Cloud 控制台中，前往 **IAM & Admin** > **Service Accounts**，打开该账号（通常为 `revenuecat-service-account`），然后依次点击 **Keys** > **Add key**，选择 **JSON**。新密钥不会影响 RevenueCat 的正常使用。详细步骤请参阅 Google 的指南：[创建服务账号密钥](https://cloud.google.com/iam/docs/keys-create-delete#creating)。
3. 要上传密钥，请在代理打开的 Adapty 看板页面中，将文件上传至 **Google Play service account key (JSON)**。密钥将直接发送至 Adapty，不会经过代理或 CLI。
4. 要让 Adapty 订阅该主题，请将主题 ID 提供给代理。在 RevenueCat 中打开您的 Google Play 应用设置，然后从 **Google developer notifications** 中复制 **Topic ID**。Google Play Console 在 **Monetize** > **Monetization setup** > **Topic name** 处也可看到相同的值。

Adapty 订阅该主题，然后发布一条测试通知并等待接收。如果未能收到，代理会告知原因。

5. 如果测试因权限问题失败，请在主题所在项目中为服务账号授予 **Pub/Sub Editor** 角色，或在该主题上授予 **Pub/Sub Subscriber** 角色并在密钥所在项目中授予 **Pub/Sub Editor** 角色。然后让代理重新检查。

## （可选）导入历史交易记录 \{#optional-import-your-transaction-history\}

导入操作会将用户的付款历史填充到[用户画像](profiles-crm)和[数据图表](charts)中，不会影响任何人的访问权限。

:::warning
不要急于导入历史数据

在发布包含 SDK 的版本后，至少等待一周再进行历史数据导入。这段时间内，我们将通过 SDK 获取所有购买价格信息，从而使导入的数据更加准确。
:::

通过两次迁移操作，可将历史记录导入到目录迁移所创建的应用中。如果您的 RevenueCat 套餐包含云导出功能，请使用云导出。

### 使用 RevenueCat 云端导出 \{#with-a-revenuecat-cloud-export\}

RevenueCat 每天将数据导出到 Adapty 为你的应用准备的存储桶中，Adapty 会导入收到的每个文件。

1. 要开始导入，请向你的 agent 发送请求：

   ```text
   Import the RevenueCat transaction history into my Adapty app "Acme Fitness" with a Cloud Export.
   ```

2. 要连接导出，请将 RevenueCat 的 External ID 提供给 agent。在 RevenueCat 中，打开 **Scheduled Data Exports** 设置，选择 **IAM Role (ARN)** 作为凭证类型，并复制 RevenueCat 显示的 **External ID**。External ID 不是保密信息。
3. 要完成导出设置，请在 RevenueCat 中输入 agent 提供的 bucket、region 和 role ARN。开启 **Receive new and updated transactions only**。否则，RevenueCat 每天会导出完整的历史记录，而 Adapty 会导入每一个文件。

RevenueCat 最多需要 24 小时才能交付第一个文件，Adapty 每小时检查一次存储桶中的新文件。迁移会在 Adapty 导入第一个文件后一周自动完成。每个导入用户画像的 Customer User ID 为 `rc_last_seen_app_user_id_alias`。

### 通过支持团队 \{#through-support\}

如果您的 RevenueCat 方案不包含云端导出功能，可使用此方式：由 RevenueCat 支持团队向您发送导出文件，再由 Adapty 支持团队负责导入。

1. 要开始导入，请向您的代理发送以下请求：

   ```text
   Import the RevenueCat transaction history into my Adapty app "Acme Fitness" through support.
   ```

2. 如需请求数据导出，请将智能助手给出的第一条消息发送给 RevenueCat 支持团队。
3. 如需导入数据，请将 RevenueCat 发送的文件转发给 Adapty 支持团队，并附上第二条消息。请原封不动地附上文件，不要打开、重新保存或合并——任何修改都会导致导入所需的列格式发生变化。

### 导入内容说明 \{#what-the-import-brings-over\}

以下数据将在每笔交易中导入到 Adapty：

| 参数                            | 描述                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| user_id                       | 客户用户 ID，即用户在 Adapty 和您系统中的主要标识符。         |
| apple_original_transaction_id | 对于订阅链，这是原始交易的购买日期，通过 `store_original_transaction_id` 关联。 |
| google_product_id             | Google Play 商店中的产品 ID。                                |
| google_purchase_token         | Google Play 为每笔交易提供的唯一标识符，用于验证。           |
| country                       | 用户所在国家/地区。                                          |
| created_at                    | 用户创建的日期和时间。                                       |
| subscription_expiration_date  | 订阅到期的日期和时间。                                       |
| email                         | 终端用户的电子邮件地址。                                     |
| phone_number                  | 终端用户的电话号码。                                         |
| idfa                          | 广告标识符（IDFA），由 Apple 分配给用户设备。                |
| idfv                          | 供应商标识符（IDFV），由同一开发者分配给其所有应用，并在该设备上的这些应用间共享。 |
| advertising_id                | Android 系统提供的唯一标识符，广告商可用于追踪。             |
| attribution_channel           | 营销渠道名称。                                               |
| attribution_campaign          | 营销活动名称。                                               |
| attribution_ad_group          | 归因广告组。                                                 |
| attribution_ad_set            | 归因广告集。                                                 |
| attribution_creative          | 归因素材关键词。                                             |

此外，以下集成的集成标识符也将被导入：Amplitude、Mixpanel、AppsFlyer、Adjust 和 FacebookAds。

### 哪些内容无法传达 \{#what-doesnt-come-across\}

- 导入时，每笔交易都会向应用商店重新验证，应用商店无法识别的记录将被丢弃。
- 没有真实应用商店交易 ID 的记录——例如 RevenueCat 的促销活动或手动授予的权益——将作为无交易的用户画像导入。如需恢复此类用户的访问权限，请通过[服务端 API](api-adapty/operations/grantAccessLevel) 为其授予访问等级。
- 退款和账单问题历史不会原样迁移：退款仅保留取消日期，订阅的账单问题状态以导入时的状态为准，而非历史日期。

## 常见问题 \{#faq\}

### 我已成功安装 Adapty SDK 并发布了包含它的新版本。那些没有更新到包含 Adapty SDK 版本的老订阅用户会怎样？\{#i-successfully-installed-adapty-sdk-and-released-a-new-app-version-with-it-what-will-happen-to-my-legacy-subscribers-who-did-not-update-to-a-version-with-adapty-sdk\}

大多数用户会在夜间充电时让手机自动更新所有应用，因此这通常不是问题。确实可能还有少量付费订阅用户没有升级，但他们仍然可以访问高级内容。你不需要为此担心，也无需强制他们更新。

### 我需要尽快从 RevenueCat 导出历史数据吗？还是说不导出就会丢失？

不需要那么着急，先发布集成了 Adapty SDK 的新版本，之后再导入历史数据即可。我们会还原用户的付款历史，并填充[用户画像](profiles-crm)和[数据图表](charts)。

### 我使用了 MMP（AppsFlyer、Adjust 等）和分析工具（Mixpanel、Amplitude 等），如何确保一切正常运行？\{#i-use-mmp-appsflyer-adjust-etc-and-analytics-mixpanel-amplitude-etc-how-do-i-make-sure-that-everything-will-work\}

您需要先通过我们的 SDK 将第三方服务的 ID 传给我们，这样我们才能向这些服务发送数据。请参阅[归因集成](attribution-integration)和[分析工具集成](analytics-integration)的相关指南。对于历史数据和存量用户，**请务必将您从 RevenueCat 导出的数据中提取出对应的 ID 传给我们。**
