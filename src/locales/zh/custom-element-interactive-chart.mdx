按照此方案，在付费墙流程中以数据图表形式展示每位用户的预计体重变化。用户在用户引导流程中输入当前体重和目标体重，你的应用会收集这两个值。数据图表将展示用户在你的应用帮助下每周的预期进展，从起始值到目标值。你的应用以原生 Swift Charts 视图的形式将数据图表渲染为[自定义元素](flow-custom-elements)。

:::tip
本教程仅适用于 iOS 应用。使用其他框架构建的应用只会显示自定义元素的[备用内容](flow-custom-elements#set-fallback-content)。Android 及跨平台框架的支持即将推出。
:::

## 开始之前 \{#before-you-start\}

- 将您的应用更新至 Adapty iOS SDK 4.4 或更高版本。早期 SDK 版本会为每个自定义元素显示[备用内容](flow-custom-elements#set-fallback-content)。
- 配置您的应用以[获取](get-pb-paywalls)和[展示](ios-present-paywalls)流程。
- 创建两个独立的流程——一个用于用户引导，另一个用于付费墙。将每个流程分别添加到一个[版位](placements)中。本示例中的代码从 ID 为 `weight_paywall` 的版位获取付费墙流程。

## 1. 在用户引导流程中询问当前体重和目标体重 \{#1-ask-for-the-current-and-goal-weight-in-the-onboarding-flow\}

在 Flow & Paywall Builder 中，向用户引导流程添加两个[**数字**输入框](builder-inputs-and-forms)：

- 一个用于填写当前体重（千克），**元素 ID** 设为 `weight`。
- 一个用于填写目标体重（千克），**元素 ID** 设为 `goal_weight`。

要让应用在所有语言环境中以相同方式读取体重值，请从两个输入框的 **Format** 下拉菜单中选择 **Integer**。输入框会将用户输入的内容原样以文本形式发送给应用。本示例中的代码对"70.5"和"70,5"的处理方式不同，而整数没有小数分隔符。

要确保应用能接收到所有输入值，请在用户引导流程的末尾添加一个不含任何输入框的屏幕。在该屏幕上，添加一个带有 [**Close flow**](onboarding-actions#close-flow) 操作的按钮。输入框会在失去焦点或用户切换到其他屏幕时发送其值。

## 2. 将自定义元素添加到付费墙屏幕 \{#2-add-the-custom-element-to-the-paywall-screen\}

在付费墙流程中，[添加一个自定义元素](flow-custom-elements#add-and-configure)到屏幕，并为数据图表进行如下配置：

- **Type**：`line_chart`。
- **ID**：`weight_goal`。
- **Height**：保持默认的 **Fixed** 高度。数据图表会填满整个自定义元素。

请勿将自定义元素放入响应触摸的容器中（例如轮播图）。否则，在图表上拖动也会同时移动轮播图。

在自定义元素内部，添加一个包含示例体重数据图表的 [**Image**](custom-media#image)。当用户使用的应用版本无法显示该数据图表时，他们会看到这张图片作为[备用内容](flow-custom-elements#set-fallback-content)。

## 3. 在应用中保存当前体重和目标体重 \{#3-save-the-current-and-goal-weight-in-your-app\}

从用户引导流程的 `flow_user_input` 事件中收集当前体重和目标体重，具体方式参见[处理流程中的数据](ios-flow-input)。要判断用户是否到达最后一屏，可监听 `flow_screen_showed` 事件，当其中的 `is_last_screen` 值为 `true` 时即表示已到达末屏。当用户引导流程在该屏关闭后，将两个体重值传入 `showWeightPaywall` 方法，该方法用于[打开带有数据图表的付费墙流程](#5-match-the-chart-to-the-custom-element)。

以下代码适用于 UIKit。一个视图控制器同时作为两个流程的委托。它还必须实现 `AdaptyFlowControllerDelegate` 协议的购买和恢复方法。本示例中省略了这些方法。如需查看，请参阅[在 UIKit 中展示流程和付费墙](ios-present-paywalls#present-flows-and-paywalls-in-uikit)。

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"
private var enteredWeights: [String: String] = [:]
private var reachedLastScreen = false

func flowController(
    _ controller: AdaptyFlowController,
    didReceiveAnalyticEvent name: String,
    params: [String: any Sendable]
) {
    if name == "flow_screen_showed", params["is_last_screen"] as? Bool == true {
        reachedLastScreen = true
        return
    }
    guard name == "flow_user_input",
          let elementId = params["element_id"] as? String,
          let value = params["value"] as? String
    else { return }

    enteredWeights[elementId] = value
}

func flowControllerDidDisappear(_ controller: AdaptyFlowController) {
    // This delegate receives events from both flows. Reset the entered
    // weights whenever a flow disappears, so that the paywall doesn't open
    // again when the user closes it.
    let weights = enteredWeights
    let finished = reachedLastScreen
    enteredWeights.removeAll()
    reachedLastScreen = false

    // Number inputs send their values as strings
    guard finished,
          let currentWeight = weights["weight"].flatMap({ Double($0) }),
          let goalWeight = weights["goal_weight"].flatMap({ Double($0) })
    else { return }

    Task {
        await showWeightPaywall(currentWeight: currentWeight, goalWeight: goalWeight)
    }
}
```

</TabItem>
</Tabs>

在 SwiftUI 中，使用 `.flow` 修饰符的 `didReceiveAnalyticEvent` 和 `didDisappear` 闭包代替委托方法。通过第二个 `.flow` 修饰符展示付费墙流程。

## 4. 创建数据图表视图 \{#create-the-chart-view\}

创建一个体重计划模型以及包含数据图表的 SwiftUI 视图。该计划按周记录数据，从当前体重到目标体重。当用户在图表上拖动时，视图会标记触点所在的周，并显示该周的预计体重：

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

struct WeightPlan {
    let entries: [WeightEntry]

    // One entry per week, from the current weight to the goal weight
    init(currentWeight: Double, goalWeight: Double) {
        let weeklyChange = 0.5 // kg per week
        let startDate = Date.now
        let weeks = Int((abs(goalWeight - currentWeight) / weeklyChange).rounded(.up))
        let step = goalWeight < currentWeight ? -weeklyChange : weeklyChange
        entries = (0...weeks).map { week in
            WeightEntry(
                date: startDate.addingTimeInterval(Double(week) * 7 * 24 * 60 * 60),
                kilograms: week == weeks ? goalWeight : currentWeight + step * Double(week)
            )
        }
    }
}

struct WeightEntry: Identifiable {
    let date: Date
    let kilograms: Double
    var id: Date { date }
}

@available(iOS 16.0, *) // Swift Charts needs iOS 16
struct WeightGoalChart: View {
    let entries: [WeightEntry]
    @State private var selectedDate: Date?

    // The entry closest to the date that the user drags to
    private var selectedEntry: WeightEntry? {
        guard let selectedDate else { return nil }
        return entries.min {
            abs($0.date.timeIntervalSince(selectedDate)) < abs($1.date.timeIntervalSince(selectedDate))
        }
    }

    var body: some View {
        if #available(iOS 17.0, *) {
            chart.chartXSelection(value: $selectedDate)
        } else {
            chart // iOS 16: no drag selection
        }
    }

    private var chart: some View {
        Chart {
            ForEach(entries) { entry in
                LineMark(
                    x: .value("Date", entry.date),
                    y: .value("Weight", entry.kilograms)
                )
            }
            if let selectedEntry {
                RuleMark(x: .value("Date", selectedEntry.date))
                    .foregroundStyle(.gray.opacity(0.3))
                PointMark(
                    x: .value("Date", selectedEntry.date),
                    y: .value("Weight", selectedEntry.kilograms)
                )
                .annotation(position: .top) {
                    Text("\(selectedEntry.kilograms, specifier: "%.1f") kg")
                        .font(.caption.bold())
                }
            }
        }
        .chartYScale(domain: .automatic(includesZero: false))
    }
}
```

</TabItem>
</Tabs>

该方案假设体重每周变化 0.5 kg。如需使用其他变化速率，请修改 `weeklyChange`。

图表上的拖动交互需要 iOS 17 或更高版本。在 iOS 16 上，用户可以看到折线，但无法拖动。

## 5. 将数据图表与自定义元素匹配 \{#5-match-the-chart-to-the-custom-element\}

编写一个[解析器](ios-flow-custom-elements#write-a-resolver-to-match-custom-elements-and-views)，使其为 `line_chart` 类型和 `weight_goal` ID 返回对应的数据图表视图。将体重计划存储在解析器的属性中：

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

@available(iOS 16.0, *) // the chart needs iOS 16
struct WeightChartResolver: AdaptyUICustomElementsResolver {
    let plan: WeightPlan

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        guard type == "line_chart", id == "weight_goal" else {
            return nil // another custom element: show the fallback
        }
        return AnyView(WeightGoalChart(entries: plan.entries))
    }
}
```

</TabItem>
</Tabs>

将解析器附加到付费墙流程，在获取其配置时使用。使用当前体重和目标体重的计划创建解析器：

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"
func showWeightPaywall(currentWeight: Double, goalWeight: Double) async {
    let plan = WeightPlan(currentWeight: currentWeight, goalWeight: goalWeight)
    do {
        let flow = try await Adapty.getFlow(placementId: "weight_paywall")
        let flowConfiguration = try await AdaptyUI.getFlowConfiguration(
            forFlow: flow,
            customElementsResolver: WeightChartResolver(plan: plan)
        )
        let flowController = try AdaptyUI.flowController(
            with: flowConfiguration,
            delegate: self
        )
        present(flowController, animated: true)
    } catch {
        // handle the error
    }
}
```

</TabItem>
</Tabs>

如果你的应用设置了[全局解析器](ios-flow-custom-elements#set-an-app-wide-resolver)，该解析器将在付费墙流程中被替换。`WeightChartResolver` 对任何其他 Type 和 ID 返回 `nil`，因为此示例的付费墙流程中没有其他自定义元素。如果你的付费墙流程还包含其他自定义元素，请将全局解析器传递给当前解析器，然后针对其他 Type 和 ID 调用全局解析器，具体方式请参考[将解析器附加到单个流程](ios-flow-custom-elements#attach-a-resolver-to-one-flow)。

## 6. 在设备上测试 \{#test-on-a-device\}

Flow & Paywall Builder 无法运行您的应用代码，因此画布中只会显示备用内容。要预览数据图表：

1. [发布两个流程](builder-save-publish)。若要查看最新发布版本而非缓存版本，请将设备注册为[测试设备](test-devices)。
2. 在 iOS 17 或更高版本上运行包含解析器的应用构建版本。完成包含当前体重和目标体重的用户引导流程，验证数据图表折线的起点为当前体重，终点为目标体重。
3. 在数据图表上拖动，验证手指所在周的预测体重是否显示在折线上方。

要测试备用付费墙，请从 `getFlowConfiguration` 调用中移除 `customElementsResolver` 参数，然后重新打开付费墙流程。

要了解为什么显示的是备用付费墙而不是数据图表，请参阅 iOS 指南中[在设备上测试](ios-flow-custom-elements#test-on-a-device)部分的说明。
