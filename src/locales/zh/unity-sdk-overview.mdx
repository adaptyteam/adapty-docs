- 开箱即用地处理购买、收据验证和订阅管理
- 无需发版即可创建和测试付费墙

- 跨会话、跨设备实时同步用户订阅状态

## 主要概念 \{#main-concepts\}

在深入代码之前，先来了解一下让 Adapty 运转起来的几个核心概念。

Adapty 的设计理念在于：只有版位需要硬编码到应用中。其他所有内容——产品、付费墙设计、定价和优惠——都可以在 Adapty 看板上灵活管理，无需更新应用：

1. [**产品**](product) - 应用内所有可购买的内容，包括订阅、消耗型商品和永久授权。
2. **流程或付费墙** - 将产品与配置打包，并关联到某个版位。有两种形式：
   - **[流程](adapty-flow-builder)** - 在 Flow Builder 中构建的可视化无代码界面。Adapty 负责渲染 UI 并处理购买流程。
   - **[付费墙](paywalls)** - 无可视化配置；你需要在自己的代码中构建 UI，并自行调用 `MakePurchase`。参见[手动实现付费墙](unity-quickstart-manual)。

   在 SDK 代码中，两者均通过同一个 `GetFlow` 方法获取。

3. [**版位**](placements) - 用户旅程中你希望展示流程或付费墙的关键节点。版位回答的是你的变现策略中"在哪里"和"什么时候"的问题。常见版位包括：
   - `main` - 主付费墙位置
   - `onboarding` - 在用户引导流程中展示
   - `settings` - 从应用设置中访问

   首次集成时，从 `main` 或 `onboarding` 等基础版位入手，然后[思考应用中还有哪些地方的用户可能已经准备好购买](choose-meaningful-placements)。

4. [**用户画像**](profiles-crm) - 当用户购买产品后，其用户画像会被分配一个**访问等级**，您可以通过它来定义对付费功能的访问权限。
