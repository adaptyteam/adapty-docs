在正式向真实用户发布之前，先对活动进行测试。

- **测试实时链路**：会触发整套自动化流程，并产生真实扣款。建议在正式上线前至少运行一次。
- **发送测试邮件**：跳过自动化流程，结账时可使用 Stripe 测试卡。

## 开始之前 \{#before-you-start\}

只有满足以下所有条件时，整个流程才能端到端正常运行：

- **您的发送域已验证**：打开 **Settings** > **DNS** 确认。请参阅[设置发送域](mail-sending-domain)。
- **Checkout**：您的网页付费墙已创建并发布。未发布的付费墙在 CTA 打开时会返回错误。请参阅[设置 checkout](mail-checkout)。
- **营销活动已附加到流程**：单独的营销活动只是草稿，不会发送任何内容。Adapty Mail 流程才能让它生效——[在流程中管理市场细分](mail-create-flow)介绍了具体方法。
- **已启用入口点**：用户数据实际上正在传入 Adapty Mail。无论您使用哪种[入口点](mail-entry-points)，检查方法相同：新注册用户会显示在 [Profiles](mail-profiles) 页面上。

## 测试上线流程 \{#test-the-live-chain\}

要在真实条件下测试营销活动，请以普通用户身份自行注册。营销活动将像对待其他用户一样向您发送邮件，您也需要在正式结账页面使用真实银行卡完成支付。按照以下步骤可以大幅缩短等待时间，整个测试只需几分钟而非数天。

1. **缩短首个延迟时间。** 在营销活动编辑器中，将第一封邮件的 **Delay** 设置为一两分钟，避免按真实计划等待。测试完成后记得恢复原来的延迟设置。

<ZoomImage id="mail-campaign-email-delay.webp" width="600px" alt="The Delay field on the first email, set to 0 days, 0 hours, and 1 minute" />

2. **创建测试用户。** 在你的应用中，用一个在该项目中尚无用户画像的邮箱地址注册。每次测试都需要使用新地址，因为已经执行过该活动的用户画像不会再次进入。

3. **等待第一封邮件。** Adapty Mail 会在触发时间加上你设置的延迟后安排发送，然后每分钟检查一次到期邮件。送达还需要再额外等待几分钟。

4. **打开邮件并点击 CTA。** 你将进入结账页面，且邮箱地址已自动填入。

5. **完成付款。** 使用真实银行卡付款，然后在 Stripe 中退款。

## 单独测试邮件与结账页面 \{#test-the-email-and-checkout-on-their-own\}

如需在不触发自动化流程的情况下预览邮件和结账页面，可在营销活动编辑器中使用 **Send test email**。在发送域名通过验证、且营销活动已选择[邮件目标地址](mail-destinations)之前，该按钮将保持禁用状态。

弹窗中包含三项设置：

- **Environment**：**Production** 使用真实产品打开正式结账页面。**Sandbox** 打开测试版，Stripe 测试卡 `4242 4242 4242 4242` 可配合任意未来到期日和任意 CVC 使用。只有通过沙盒产品生成的付费墙才能选择 Sandbox——通过 URL 添加的付费墙会显示 *"This paywall has no sandbox products, so only production is available."*
- **Profile**：可选。选择用户画像后，邮件将发送至该用户画像的地址，并用其 ID 填充 CTA。
- **Custom address**：可选。输入地址后，邮件将发送至该地址，并使用占位符用户画像 ID。选择用户画像会清除此字段，若两者同时设置，用户画像始终优先。

如果两者都未设置，邮件将发送到您自己的账户地址，并使用占位符用户画像 ID。

测试发送是一封独立的邮件，与正式链路分开。它可以确认邮件是否正常渲染以及结账是否能成功付款，但无法告诉您自动化流程是否触发。如需确认自动化流程，请[运行正式链路](#test-the-live-chain)。

<ZoomImage id="mail-send-test-email-modal.webp" width="600px" alt="Send test email modal with Sandbox unavailable and a profile selected" />

## 在应用中确认访问权限 \{#confirm-access-in-your-app\}

支付完成后，订阅将记录到用户的 Adapty 用户画像中，应用即可读取相应的访问等级。

Adapty 会将沙盒支付记录为沙盒交易，因此在将缺失的访问等级判断为失败之前，请先确认你的访问等级已开启对沙盒交易的支持。

## 查看结果 \{#check-the-result\}

在 [Profiles](mail-profiles) 中打开你的测试用户画像，查看其[journey](mail-profiles#the-activity-journey)。测试成功的标志是：第一封邮件状态变为 **Clicked**，购买行为归因于该邮件，序列中其余邮件显示为 **Cancelled**。

:::note
Adapty Mail 通过追踪像素的加载来记录打开事件，而 Apple Mail 隐私保护功能无论用户是否真正阅读邮件都会加载该像素。因此出现你并未主动触发的 **Opened** 标签是正常现象。[Campaign analytics](mail-analytics) 中详细说明了每项数据图表的统计口径。
:::
