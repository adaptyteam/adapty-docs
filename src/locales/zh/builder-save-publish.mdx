[流程与付费墙编辑工具](adapty-flow-builder) 将保存与发布分开处理。草稿会将您的工作保存在 Adapty 看板中，而发布则会通过 SDK 将当前版本提供给用户。本文介绍这两个操作及各自的适用场景。

## 将流程保存为草稿 \{#save-a-flow-as-a-draft\}

:::warning
无效的[远程配置](customize-flow-with-remote-config)会阻止你保存草稿。
:::

Flow & Paywall Builder 每分钟会自动保存一次你的进度。

如需手动保存草稿，请点击 Flow & Paywall Builder 右上角的 **Save draft**，或按 **Cmd/Ctrl + S**。

草稿仅在看板内可见，不会影响用户在应用中看到的内容，即使该流程已分配到某个[版位](placements)也是如此。

<ZoomImage id="flow-builder-save-draft.webp" width="700px" alt="流程与付费墙编辑工具顶部工具栏中的保存草稿按钮" />

## 发布流程 \{#publish-a-flow\}

发布操作会将当前版本的流程通过 SDK 提供给用户，替换之前已发布的版本。如需恢复旧版本，请参阅[恢复历史版本](flow-version-history#restore-an-earlier-version)。

:::note
若要将流程添加到[版位](placements)，需先发布该流程。处于草稿状态的流程无法添加。
:::

要发布流程，请点击 Flow & Paywall Builder 右上角的 **Publish to Live** 按钮。流程发布后，该按钮将保持禁用状态，直到你对流程进行编辑。

接下来发生的情况取决于该流程是否已分配到某个版位：

- **流程已在版位中**：用户在下次请求该版位时即可看到新版本。
- **流程尚未在版位中**：将流程添加到[流程版位](create-placement)，即可开始向用户展示。流程需要独立的版位——不能使用已用于付费墙或用户引导的版位。

:::tip
流程在所有操作、页面和产品都完整配置后即可发布。在此之前，你仍可保存草稿。如需查看待修复的问题，请[打开 **Issues** 面板](#fix-issues-before-publishing)。常见问题可参考[故障排查](#troubleshooting)。
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Publish to Live button in the Flow & Paywall Builder top toolbar" />

:::warning
[自定义字体](using-custom-fonts-in-flow-builder)不会随流程一起打包——你必须将每个字体文件添加到应用程序包中。如果缺少字体文件，用户将看到系统默认字体。

若要在不影响旧版本应用的情况下修改已发布流程中的字体：[复制该流程](copy-flows)，在副本中更改字体，并将副本通过[目标受众](add-audience-paywall-ab-test)定向到包含该字体的应用版本。
:::

## 发布前修复问题 \{#fix-issues-before-publishing\}

<ZoomImage id="flow-builder-issues-panel.webp" width="500px" alt="Issues panel with two issues under Blocks publishing, a flow size warning under Won't block publishing, and the flow size at the bottom" />

**Issues** 面板将流程中的所有问题汇总在一处。点击顶部栏中的 **Issues** 即可打开该面板。只有当流程存在问题时，该按钮才会显示。按钮会分别统计阻止发布的问题数量和警告数量。

该面板将问题分为两组：

- **阻止发布**：产品或产品操作未完整配置，例如产品卡片未关联产品，或产品/优惠已被删除。点击 **Publish to Live** 时若存在此类问题，编辑工具将不会发布流程，并显示 **Fix N issues before publishing** 提示信息。点击 **Show issues** 可打开问题面板。
- **不阻止发布**：关于产品缺少 App Store 或 Play Store 产品 ID 的警告，或关于[过大流程](flow-size)的警告。缺少 ID 时，该平台上的产品价格将显示为空；过大的流程加载速度较慢。

要修复某个问题，点击它即可。编辑工具会选中对应元素，并打开相关设置选项卡，例如针对 **Purchase** 操作打开 **Interactions** 选项卡。存在问题的设置项会以红色边框标注。

<ZoomImage id="flow-builder-issues-purchase-action.webp" width="400px" alt="Interactions tab with a Purchase action outlined in red and marked with a warning icon" />

其他问题（例如引用了已删除元素的条件）不会显示在面板中。当你发布流程时，**Can't publish yet** 对话框会列出这些问题。

## 流程状态 \{#flow-status\}

每个流程在[流程列表](filter-flows)中都会显示一个状态，反映该流程在保存和发布生命周期中所处的阶段。

| 状态 | 含义 |
| :----- | :------ |
| **Draft** | 该流程从未发布过。目前只存在草稿，用户尚未看到它。需要先发布草稿，才能将其添加到[版位](placements)。 |
| **Dirty** | 该流程已发布，但存在已保存但尚未发布的编辑内容。用户看到的仍是上次发布的版本，直到再次发布为止。 |
| **Publishing** | 正在发布中。 |
| **Failed** | 上次发布尝试失败。如果存在上次发布的版本，用户将继续看到该版本。 |
| **Published** | 最新保存的版本已上线，没有未发布的编辑内容。 |
| **Archived** | 该流程已被[归档](archive-flows#archive-a-flow)，在[恢复](archive-flows#restore-a-flow)之前无法编辑。 |

## 故障排查 \{#troubleshooting\}

操作不完整、屏幕为空、产品或优惠缺失或已删除、远程配置 JSON 无效，都会导致无法预览或发布。完整的问题列表及修复方法请参阅[常见问题](flow-common-issues#a-flow-wont-preview-or-publish)。

如果某个条件引用了已删除的元素、状态或变量，则无法发布流程。**Can't publish yet** 对话框会在 **Broken references** 下列出这些条件。要发布流程，请为每个条件选择一个现有的元素、状态或变量，或直接删除该条件。

在发布前，请通过 [Adapty 应用](paywall-device-compatibility-preview)预览你的流程，及时发现问题。如果流程在预览中加载失败，请查看错误信息了解详情。

流程通过以上所有检查，也不代表可以安全发布——失效的恢复按钮、缺失的条款链接、未翻译的页面，这些都可能是隐患。[flow-audit 技能](flow-audit-skill)专门用于检查这类问题，直接在终端运行，最终给出明确的审核结论，而不是一堆待办清单。
