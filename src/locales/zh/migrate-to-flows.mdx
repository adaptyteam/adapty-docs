在 Adapty 中，*流程*将用户引导和付费墙合并为一个整体，由单一版位统一管理。流程取代了原先需要单独构建和提供的独立用户引导与付费墙。

:::warning
从 2026 年 10 月 1 日起，您将无法在旧版编辑工具中创建新的付费墙和用户引导，相关支持也将停止。您已有的内容仍可正常使用和编辑——请参阅[该日期的具体变更内容](paywall-onboarding-builder-deprecation)。
:::

本指南介绍迁移到流程后会发生哪些变化，以及如何在不影响旧版本用户的情况下平稳完成切换。

:::important
流程需要 Adapty SDK v4.0 或更高版本。
:::

## 流程与用户引导及付费墙的对比 \{#flows-vs-onboardings-and-paywalls\}

分别管理用户引导和付费墙，意味着你需要维护两个编辑器和两个版位，还要在自己的代码中处理从用户引导到付费墙的跳转逻辑。

流程将这两者合并为一体——引导介绍页面、问卷测试和购买页面——在同一个编辑器中构建，从同一个版位提供服务。该版位是一个全新的版位：流程是独立的内容类型，无法在其替代的用户引导或付费墙版位上运行。

下表对比了各选项的特性：

| | 流程 | 付费墙编辑工具付费墙 | 用户引导 |
|---|---|---|---|
| 多屏幕支持 | 是 | 否——单屏幕 | 是 |
| 渲染方式 | 原生 | 原生 | WebView |
| 产品与版位 | 一个版位；直接在流程中添加产品 | 一个版位；直接在付费墙中添加产品 | 一个版位，但本身不含产品——如需销售，需单独创建付费墙并通过独立版位提供 |

## 是否需要迁移？\{#should-you-migrate\}

**如果你是在做长期产品，流程是更好的基础** —— 在合适的发布节点迁移即可。

## 如何迁移 \{#how-to-migrate\}

迁移分四个步骤。大部分工作是一次性的 SDK 升级——构建和预览流程无需编写代码。

1. **[构建流程](#build-your-flow)**：一键将现有付费墙转换为流程，或从模板创建流程；无需开发者介入。
2. **[在设备上预览](#preview-on-device)**：通过 Adapty 移动应用在真实设备上查看流程效果；无需构建应用。
3. **[为流程创建新版位](#create-a-new-placement-for-your-flow)**：创建具有唯一 ID 的新流程版位，并决定其与现有版位的共存方式。
4. **[更新 SDK](#update-the-sdk)**：升级至 Adapty SDK v4，从对应版位获取流程，并验证沙盒购买。这是开发者的主要任务。

### 构建流程 \{#build-your-flow\}

**如果你的付费墙是用旧版付费墙编辑工具构建的，请将其转换，而不是重新构建。** **Move to new builder** 操作只需一键即可将其重新创建为草稿流程——包括布局、每种语言的文案，以及以变量形式呈现的含价格产品——在你编辑和测试期间，原始版本仍保持上线状态。详情请参阅[将付费墙转换为流程](convert-paywall-to-flow)。

如果你想从头开始构建新内容，请根据实际情况选择以下路径：

- **[从模板开始](paywall-builder-templates)**：在流程与付费墙编辑工具中选用初始模板或空白流程，无需编写代码。
- **[使用 Agent Skill](flow-generator-skill)**：由你的 AI 编程工具在终端中创建和编辑流程，适用于问卷、分支逻辑以及批量添加语言版本。

构建时可参考以下内容：

- **[流程与付费墙编辑工具文档](adapty-flow-builder)**：带你了解编辑工具及其创作功能。
- **[常用流程示例](flow-builder-recipes)**：最常见页面的分步操作指南。
- **Ask AI**：遇到问题时，可在任意文档页面使用对话功能。

### 在设备上预览 \{#preview-on-device\}

您可以在真实设备上预览流程，无需修改应用代码。下载 Adapty 移动端应用（[iOS](https://apps.apple.com/us/app/adapty/id6739359219) 或 [Android](https://play.google.com/store/apps/details?id=io.adapty.dashboard)），然后在 Flow & Paywall Builder 中点击 **Test on device**，选择语言区域，并用设备扫描二维码。即可看到真实的界面、分支逻辑、文案和设计效果。

:::note
在预览模式下，Adapty 无法访问应用商店中的产品，因此预览中显示的价格并非真实价格。真实购买将在后续使用沙盒账户的 v4 版本中验证——请参阅[更新 SDK](#update-the-sdk)。
:::

### 为你的流程创建新版位 \{#create-a-new-placement-for-your-flow\}

流程、付费墙和用户引导是三种不同的内容类型，每种类型都有各自专属的数据图表——因此每个版位只服务于一种类型。版位的类型在创建时即已固定，无法将现有的用户引导版位或付费墙版位转换为流程版位（参见[版位类型](create-placement)）。每个流程都需要一个专属的新版位。

:::warning
请为新的流程版位设置一个全新且唯一的版位 ID。

版位 ID 在整个应用中是唯一的，而非按类型区分，因此流程版位不能复用付费墙或用户引导版位的 ID——即使是被该流程所替代的内容对应的版位 ID 也不行。这不是偏好问题：看板会直接拒绝重复的 ID。
:::

<ZoomImage id="flow_placements_diagram.png" width="700px" alt="Placements list with separate Flows, Paywalls, and Onboardings tabs" />

:::warning
过渡期间请保持旧版位处于运行状态

使用旧版应用的用户，其代码中已编译了用户引导和付费墙版位 ID。他们会持续调用用户引导和付费墙方法，并看到现有的用户引导和付费墙，直到更新应用为止。请等到 SDK v4 的采用率足够高后，再停用旧版位。
:::

你不必一次性将所有版位都迁移到流程。在 SDK v4 中，`getFlow` 方法同时支持从流程版位和付费墙版位拉取数据，因此应用可以在任何地方调用同一个方法。对于需要保留的版位，继续使用付费墙编辑工具中的付费墙；其余版位则改用流程。

在过渡期间，每种版位类型会分别追踪各自的数据图表。当新旧两个版本的应用同时运行时，数据会分散到两组版位中：旧版用户引导和付费墙版位涵盖旧版本，新版 flow 版位则对应 SDK v4 及以上版本。建议将这两组数据作为独立的同期群进行比较，随着用户陆续更新，flow 版位的占比将逐步提升。

您可以继续对流程进行 A/B 测试：在流程版位上针对不同流程实验变体运行[常规 A/B 测试](ab-tests)。跨版位 A/B 测试目前仅支持付费墙，暂不支持跨流程版位使用。若要将新流程与旧付费墙进行比较，属于同期群对比，而非单一测试——它们分属不同的版位类型。

#### 使用 Agent 技能创建版位 \{#create-the-placements-with-an-agent-skill\}

如果需要迁移的版位数量较多，可以使用 [migrate-placements 技能](migrate-placements-skill)，直接通过你的 AI 编程工具来完成创建。它会通过 [Adapty CLI](developer-cli-quickstart) 读取应用中的所有版位，按每个版位对应的付费墙进行分组，逐一询问每个付费墙的流程来源，然后为每个在迁移范围内的付费墙版位创建对应的流程版位，并返回新旧 ID 的映射关系以及应用需要接入的 `getFlow` 调用。

您的付费墙版位只读不改，因此在您工作期间始终正常投放，技能提议的每个版位 ID 都需等待您的确认。

### 更新 SDK \{#update-the-sdk\}

流程版位配置完成后，让应用指向它。流程仅在 Adapty SDK v4 及更高版本上渲染。升级 SDK 并通过 `getFlow` 从新版位获取流程。请参阅适用于您平台的 v4 迁移指南 — [iOS](migration-to-ios-sdk-v4)、[Android](migration-to-android-sdk-v4)、[React Native](migration-to-react-native-sdk-v4)、[Flutter](migration-to-flutter-sdk-v4)、[Unity](migration-to-unity-sdk-v4)、[Kotlin Multiplatform](migration-to-kmp-sdk-v4) 或 [Capacitor](migration-to-capacitor-sdk-v4) — 了解具体的升级步骤。

流程接入后，像测试其他购买流程一样进行验证：在设备或模拟器上运行，并完成一次沙盒购买，确认产品、购买和访问等级均正常工作。请参阅对应平台的测试指南：[iOS](ios-test)、[Android](testing-on-android)、[React Native](react-native-test)、[Flutter](flutter-test)、[Unity](unity-test)、[Kotlin Multiplatform](kmp-test) 或 [Capacitor](capacitor-test)。

:::note
用户只有在安装了基于 SDK v4+ 构建的应用后，才能看到流程。使用旧版应用的用户仍会看到原有的用户引导和付费墙，这也是为什么旧版版位在过渡期间需要保持上线状态。
:::
