[流程](adapty-flow-builder)可以通过 **Request permission** 操作请求用户授予推送通知权限，例如在用户引导页面上解释通知用途时。Adapty SDK 本身不会弹出系统权限对话框，而是将请求传递给应用中的 `IAdaptyUISystemRequestsHandler`。由应用负责显示对话框并返回用户的选择，流程随后继续执行。

## 开始之前 \{#before-you-start\}

您需要：

- **Adapty Unity SDK 4.1.0 或更高版本，Android 端需 4.3.0 或更高版本**：早期版本不支持此签名的 `IAdaptyUISystemRequestsHandler`。在 Android 上，4.1.x 只能在流程关闭后才能传递 OS 权限回调的结果。4.3.0 版本需要 Unity 6。
- **包含"请求权限"动作的流程**：在流程与付费墙编辑工具中，将 **Request permission** 动作添加到某个元素的 **On Tap** 或 **On Screen Appear** 触发器。在其 **After response** 部分，添加用户响应后需要执行的动作，例如 **Navigate Next**。有关动作设置，请参阅 [Request permission](onboarding-actions#request-permission)。
- **iOS 端**：[Mobile Notifications](https://docs.unity3d.com/Packages/com.unity.mobile.notifications@latest) 包，本指南中的处理程序使用该包来显示 iOS 对话框。在 **Project Settings > Mobile Notifications > iOS** 中，关闭 **Request Authorization on App Launch**，确保对话框在流程请求时才显示。
- **Android 端**：在 Android 清单中声明 `android.permission.POST_NOTIFICATIONS` 权限，并在 **Player Settings** 中将目标 API 级别设置为 33 或更高。Android 13 及更高版本仅对声明了该权限且目标版本为 Android 13 或更高的应用显示通知权限对话框。

## 流程如何申请权限 \{#how-the-flow-requests-a-permission\}

1. 流程触发 **Request permission** 动作：用户点击该元素，或屏幕出现。
2. Adapty SDK 以 `push` 权限为参数，在你的处理器上调用 `FlowViewDidAskPermission`。
3. 你的应用向系统申请权限，并调用一次 `respond` 返回结果。
4. 流程执行 **After response** 动作，两种回答的后续动作相同。

流程会停留在该界面，直到您的应用调用 `respond`。如果应用始终未调用，流程将保持在当前界面。如果操作系统没有弹出对话框（例如用户此前已作出回应），应用会立即获得答复，流程随即执行 **After response** 操作。如果这些操作导致页面跳转，用户只会看到权限请求界面一闪而过。

使用 **On Screen Appear** 时，当用户通过 **Navigate back** 操作返回该屏幕时，流程不会再次发送请求。使用 **On Tap** 时，每次点击都会发送新的请求，但在等待回复期间的点击除外。

## 实现处理程序 \{#implement-the-handler\}

要响应权限请求，请实现 `IAdaptyUISystemRequestsHandler` 接口。对于你的应用不需要请求的权限，返回 `false`。

```csharp showLineNumbers title="Unity"
using System;
using System.Collections;
using System.Collections.Generic;
using AdaptySDK;
using UnityEngine;
#if UNITY_ANDROID
using UnityEngine.Android;
#endif
#if UNITY_IOS
using Unity.Notifications.iOS;
#endif

public class FlowSystemRequestsHandler : MonoBehaviour, IAdaptyUISystemRequestsHandler
{
    public void FlowViewDidAskPermission(
        AdaptyUIFlowView view,
        string permission,
        IReadOnlyDictionary<string, string> customArgs,
        Action<bool, string> respond
    ) {
        if (permission != "push") {
            // Answer every request, or the flow waits on the screen.
            respond(false, null);
            return;
        }

#if UNITY_IOS
        StartCoroutine(RequestPushOnIOS(respond));
#elif UNITY_ANDROID
        RequestPushOnAndroid(respond);
#else
        respond(false, null);
#endif
    }

    public void FlowViewDidRequestAppReview(AdaptyUIFlowView view)
    {
        // Shows the native store review prompt, as the SDK does without a handler.
        AdaptyUI.RequestAppReview(null);
    }

#if UNITY_IOS
    private IEnumerator RequestPushOnIOS(Action<bool, string> respond)
    {
        var options = AuthorizationOption.Alert | AuthorizationOption.Badge | AuthorizationOption.Sound;

        using (var request = new AuthorizationRequest(options, false))
        {
            while (!request.IsFinished) {
                yield return null;
            }
            respond(request.Granted, null);
        }
    }
#endif

#if UNITY_ANDROID
    private void RequestPushOnAndroid(Action<bool, string> respond)
    {
        const string postNotifications = "android.permission.POST_NOTIFICATIONS";

        using (var version = new AndroidJavaClass("android.os.Build$VERSION"))
        {
            if (version.GetStatic<int>("SDK_INT") < 33) {
                // Android 12 and earlier: no dialog; answer whether notifications are on.
                using (var player = new AndroidJavaClass("com.unity3d.player.UnityPlayer"))
                using (var activity = player.GetStatic<AndroidJavaObject>("currentActivity"))
                using (var managerClass = new AndroidJavaClass("androidx.core.app.NotificationManagerCompat"))
                using (var manager = managerClass.CallStatic<AndroidJavaObject>("from", activity))
                {
                    respond(manager.Call<bool>("areNotificationsEnabled"), null);
                }
                return;
            }
        }

        if (Permission.HasUserAuthorizedPermission(postNotifications)) {
            respond(true, null);
            return;
        }

        var callbacks = new PermissionCallbacks();
        callbacks.PermissionGranted += _ => respond(true, null);
        callbacks.PermissionDenied += _ => respond(false, null);
#if UNITY_6000_0_OR_NEWER
        callbacks.PermissionRequestDismissed += _ => respond(false, null);
#else
        callbacks.PermissionDeniedAndDontAskAgain += _ => respond(false, null);
#endif
        Permission.RequestUserPermission(postNotifications, callbacks);
    }
#endif
}
```

`FlowViewDidAskPermission` 接收以下参数：

- **`view`**：发送请求的流程视图。
- **`permission`**：流程请求的权限类型。**Request permission** 操作会发送 `push`。
- **`customArgs`**：请求的自定义参数。**Request permission** 操作不发送任何自定义参数，因此该值为 `null`。
- **`respond`**：将结果返回给流程的回调函数。若用户授予了权限，传入 `true`，否则传入 `false`。第二个参数为可选的详情字符串，`null` 是合法值。

每次请求只能调用一次 `respond`。Adapty SDK 会忽略第二次调用，并在 Unity 控制台输出警告。从 4.3.0 版本起，可以在任意线程中调用 `respond`，包括操作系统权限回调。

如果 `FlowViewDidAskPermission` 在调用 `respond` 之前抛出异常，Adapty SDK 会记录该异常且不发送任何响应，流程页面将保持显示。请捕获异常并调用 `respond(false, null)`。

获得权限后，你的应用即可显示通知。若要接收推送通知，还需向推送服务提供商注册设备，处理方式与在流程之外注册设备时相同。

`IAdaptyUISystemRequestsHandler` 还需要实现 `FlowViewDidRequestAppReview`。注册处理器后，Adapty SDK 不会自动请求商店评价，因此请在其中调用 `AdaptyUI.RequestAppReview(null)` 以保留原生评价弹窗，如示例所示。

## 注册处理程序 \{#register-the-handler\}

:::warning
**如果未注册处理程序，流程将停在权限请求处。** 如果你的应用未注册任何处理程序，Adapty SDK 将不会向流程返回任何响应（iOS 和 Android 均如此），Unity 控制台会显示警告 `System requests handler is not set`。流程会停留在发出请求的屏幕上，不会执行 **After response** 操作。
:::

要将所有流程的权限请求发送到您的处理程序，请在展示流程之前调用 `Adapty.SetSystemRequestsHandler()` 进行注册，位置与注册[流程事件监听器](unity-handle-paywall-actions#set-up-the-flows-events-listener)相同。将处理程序附加到应用运行期间始终存在的 GameObject 上，并将以下方法添加到处理程序类中：

```csharp showLineNumbers title="Unity"
void Awake()
{
    DontDestroyOnLoad(gameObject);
    Adapty.SetSystemRequestsHandler(this);
}

void OnDestroy()
{
    Adapty.SetSystemRequestsHandler(null);
}
```

`Adapty.SetSystemRequestsHandler()` 在整个应用中只保留一个处理器，用于所有流程。第二次调用会替换第一个处理器，传入 `null` 则将其移除。

## 测试权限请求 \{#test-the-permission-request\}

iOS 每次应用安装只会显示一次通知权限弹窗。Android 在用户允许通知或拒绝两次后，不再显示该弹窗。如需在测试流程时再次看到弹窗，请从设备上删除应用并重新安装。然后打开流程并进入 **Request permission** 操作。如果屏幕停留但没有弹窗出现，说明流程未收到响应：请确保你的应用在展示流程之前已注册处理程序。如果流程直接跳过但没有弹窗，请确认 Android 应用已声明 `POST_NOTIFICATIONS` 权限、目标 API 等级为 33 或更高，以及 **Request Authorization on App Launch** 已关闭。
