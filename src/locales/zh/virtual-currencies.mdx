当用户购买产品或续订订阅时，向其发放虚拟货币——AI 代币、积分或金币。只需定义一种货币，将其关联到应授予奖励的产品，Adapty 便会自动为每位用户记账并维护其余额。您的应用可通过[服务端 API](getting-started-with-server-side-api) 读取和消耗该余额——例如，按每次生成收取代币。

:::tip
如需在 AI 编程工具（如 Claude Code 或 Codex）中管理虚拟货币，请[安装 Adapty 插件](virtual-currencies-skill#install-the-skill)，然后向你的 Agent 提问，例如"Give the Starter pack 50 gems."。[virtual-currencies 技能](virtual-currencies-skill)通过 [Adapty CLI](developer-cli-virtual-currencies) 或 [Adapty MCP 服务器](adapty-mcp) 运行，每次变更都会在你确认后才会执行。
:::

## 工作原理 \{#how-it-works\}

1. [创建虚拟货币](create-virtual-currency)：打开 **Products**，点击 **Virtual currency** 标签页，再点击 **New virtual currency**。设置货币代码、名称和可选的描述信息。
2. **将货币关联到产品**：将货币映射到一次性购买或订阅产品，并设置每次购买可获得的积分数量。
3. **积分自动发放**：用户购买关联该货币的产品后，Adapty 会自动将配置的积分添加到其余额中。对于订阅产品，每次续订时 Adapty 都会添加积分。用户开始免费试用时，仅当您设置了 **Credit on trial start** 选项，Adapty 才会添加积分。Adapty 发送到您的 [webhook](webhook-event-types-and-fields#virtual-currency-credits) 和分析集成的购买事件会在 `virtual_currency_credits` 字段中列出这些积分。
4. **读取和消费余额**：您的应用通过服务端 API 读取每位用户的余额，并授予或扣除积分。同一 API 还可用于为尚未购买任何产品的用户[授予初始余额](grant-initial-balance)。
5. **追踪每次变动**：每次余额变动都会记录在[用户画像](virtual-currency-balance)中。您的支持团队也可以直接在用户画像中[手动充值或扣除余额](virtual-currency-balance#adjust-a-balance-manually)。
6. **按货币统计收入**：要按货币查看收入及其他数据图表，可在分析图表中按 [**Virtual currency**](controls-filters-grouping-compare-proceeds#filter-and-group-data) 进行筛选。
7. **按余额定向用户**：若要向余额较低或较高的用户展示不同的付费墙或用户引导，可按[虚拟货币余额创建市场细分](segments#virtual-currency-balance)，并将其用作[目标受众](audience)。
8. **导出交易记录**：若要将所有余额变动加载到您的数据仓库，请开启每日导出功能，支持导出至 [Amazon S3](s3-exports#virtual-currency-transactions) 或 [Google Cloud Storage](google-cloud-storage#virtual-currency-transactions)。

完整的操作流程（从货币设置到通过 API 使用积分），请参阅[虚拟货币快速入门](virtual-currency-quickstart)。

## 使用场景 \{#use-cases\}

| 应用类型 | 如何使用虚拟货币 |
|----------|-------------------------------|
| **AI 应用**（图像、视频或文本生成） | 按次生成收取积分。订阅中包含每月积分额度，并以一次性产品形式出售积分包。 |
| **短剧和视频应用** | 用金币解锁剧集。向订阅用户提供循环金币额度，并以一次性产品形式出售金币包。 |
| **语言学习和教育应用** | 通过服务端 API 为免费用户提供有限的爱心或生命值额度。付费套餐可获得更大额度，或完全跳过余额检查。 |
| **手机游戏** | 同时运营软货币和硬货币：通过服务端 API 在游戏过程中发放金币，<InlineTooltip tooltip="用真实货币购买宝石">[iOS](ios-virtual-currency-top-up)</InlineTooltip>，并在单个原子事务中进行相互转换。 |
| **效率工具应用** | 用积分计量高成本操作（如 OCR 或导出）。免费用户获得少量额度，订阅后获得更多，并为批量工作出售积分包。 |

:::tip
对于订阅配额，请开启[积分有效期](create-virtual-currency#link-products)功能。开启后，用户无法跨计费周期累积积分。用户需续订才能获得新积分，重度用户则可以购买积分包。
:::

## 给交易打标签 \{#label-transactions\}

当你的后端通过 [Create virtual currency transaction](api-adapty/operations/createVirtualCurrencyTransaction) 授予或消耗积分时，为每笔交易添加标签，说明其含义以及积分的用途。通过 `operation`，你可以在交易历史中区分消耗、奖励、撤销和修正。通过 `feature`，你可以了解用户花积分买了什么，以及你为什么授予积分。

所有标签字段均为可选项。一旦 Adapty 保存交易后，就无法再为其添加标签，因此请在第一次调用时设置标签。未附带标签的交易将以 `operation: null` 保存。

```json title="Spend credits on a feature"
{
  "items": [{ "currency_code": "COINS", "amount": -10 }],
  "operation": "spend",
  "feature": "power_up.extra_life",
  "customer_placement_id": "level-complete",
  "reference_id": "session_7781"
}
```

### 操作 \{#operation\}

大多数集成需要用到以下 `operation` 值：

| 值 | 使用时机 |
|-------|----------------|
| `spend` | 用户消耗积分来使用某项功能或内容。 |
| `spend_reversal` | 因操作失败（例如生成失败）而退还积分。 |
| `reward` | 发放奖励、赠品或客服补偿积分。 |
| `reward_reversal` | 撤回已发放的奖励积分。 |

Adapty 在其创建的交易中设置 `operation`：购买、续订和试用获得 `top_up`，商店退款获得 `refund`，过期积分获得 `expiry`。完整的值列表，请参阅 [创建虚拟货币交易](api-adapty/operations/createVirtualCurrencyTransaction)。

### 功能 \{#feature\}

`feature` 表示积分的消耗用途或授予原因：由字母、数字和 `_` 组成的单个单词，后面可跟一个以点号分隔的子类型。Adapty 按原样存储该字段，且区分大小写，因此 `photoFilter` 和 `photofilter` 是两个不同的功能。

- ✅ `hint`, `power_up.extra_life`, `photo_filter.vintage`
- ❌ `photo filter`：包含空格。
- ❌ `photo_filter.vintage.v2`：有两层子类型。
- ❌ `pack_499`, `premium_tier`：在名称中包含价格或等级，当价格或等级变化时会将一个功能拆分为多个。请勿在 `feature` 中包含价格、等级、版本和变体信息。

对于奖励，请使用活动名称，例如 `welcome`、`daily_bonus`、`referral` 或 `support_compensation`。

### 其他字段 \{#other-fields\}

- **`reference_id`**：你系统中关联对象的 ID，最多 128 个字符。用于将 `spend_reversal` 与其对应的 `spend` 关联，或将 `reward` 与其对应的授予操作关联。请勿在此存放个人数据。
- **`customer_placement_id`**：操作发生时，应用内对应页面的 ID。这是你自己的 ID，不是 Adapty 的[版位](placements) ID。
- **`store` 和 `store_transaction_id`**：当你的后端为某次购买直接发放金币时，请将两者一起传入。Adapty 不会验证该购买是否存在。如果该购买在商店发生退款，Adapty 会收回通过此引用发放的金币。
- **`is_sandbox`**：测试期间发放的金币请传入 `true`。对于商店交易，Adapty 会根据购买的环境自动设置该字段。

:::warning
不要为已在 Adapty 中[关联货币](create-virtual-currency#link-products)的产品手动发放代币。Adapty 已自动为这类购买发放代币，若后端再次发放，用户将获得双倍代币。
:::

在标记功能上线（2026 年 11 月 12 日）之前创建的交易，其数据保持不变：Adapty 已对自身交易进行了追溯标记，而您在此日期之前通过 API 创建的交易仍保留 `operation: null`。`metadata` 不受影响，依然支持您所需的任意键名。

## 限制 \{#limitations\}

- **跨设备访问需要身份识别**：余额归属于某个用户画像。匿名用户的余额仅保留在获得该余额的安装设备上，重新安装应用或在其他设备上打开时，余额将会丢失。请识别用户身份，以便在所有设备上及每次重新安装后都能访问余额。参见[余额、用户画像与设备](virtual-currency-balance#balances-profiles-and-devices)。
- **仅支持服务端操作**：目前 SDK 还没有提供读取或消耗余额的方法，因此您的应用需要一个后端。通过服务端 API 读取余额，以及发放或消耗积分。
- **每个应用最多 20 种货币**：您可以在一个应用中创建最多 20 种虚拟货币。
- **部分购买不获得积分**：通过[自定义商店](custom-store)完成的购买、通过 [Apple 家人共享](apple-family-sharing)共享的购买，以及导入的历史购买记录，均不会发放积分。
- **沙盒与正式环境共享同一余额**：沙盒购买与真实购买使用同一个余额。请使用测试账号进行测试，不要使用真实用户的账号。
