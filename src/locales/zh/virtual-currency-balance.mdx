[Profiles/CRM](profiles-crm) 中的每个用户画像都会显示该用户的虚拟货币余额，以及所有变更历史记录。在同一个用户画像中，您的支持团队可以手动充值或扣减余额——例如，为生成失败的用户进行补偿。

## 在用户画像中查看余额 \{#view-balances-in-a-user-profile\}

<ZoomImage id="virtual-currency-balance.webp" width="300px" alt="用户画像页面，显示虚拟货币卡片，列出用户的余额（包含可花费金额）以及调整余额和变更历史链接" float="right" />

打开用户的[画像](https://app.adapty.io/profiles/users)。**Virtual currency** 卡片列出了该用户持有的所有货币。

每行显示：

- 货币**代码**，例如 `COINS`。
- 当前**余额**，以整数表示。
- 括号中的**可用**金额，例如 `1,200 (950 spendable)`，当用户当前无法使用全部余额时显示。已过期但 Adapty 尚未移除的积分，以及因待处理消费而被冻结的积分，计入余额但不计入可用金额。

余额会随着用户赚取、消费或获得积分而更新。余额不能低于 0：如果某笔交易尝试花费超过可用余额的金额，则会以 `insufficient_balance` 失败，且不会产生任何变化。没有余额的用户画像将显示空白卡片。

如需通过代码读取余额，请在服务端 API 中调用 [List virtual currency balances](api-adapty/operations/listVirtualCurrencyBalances)。

## 手动调整余额 \{#adjust-a-balance-manually\}

如需补偿用户、退还失败操作的积分或修正余额，可直接在用户画像中进行充值或扣款操作。单次调整无需使用服务端 API。

Owner、Admin 和 Support 成员均可调整余额。当您的应用至少配置了一种[虚拟货币](create-virtual-currency)时，**Adjust balance** 链接才会显示。

1. 在用户画像中，找到 **Virtual currency** 卡片，点击 **Adjust balance**。

   <ZoomImage id="virtual-currency-adjust-balance-form.webp" width="400px" alt="调整余额表单，包含 50 COINS 积分、奖励操作、support_compensation 功能、参考 ID 和备注" />

2. 选择 **Currency**。然后选择 **Credit** 来添加积分，或选择 **Debit** 来扣除积分。**Amount** 上方的行显示用户在该货币下的当前余额和可用金额。
3. 在 **Amount** 中，输入一个大于 0 的整数。扣除金额不能超过可用金额。
4. 在 **Operation** 中，选择此次变更的类型。若为充值，选择 **Reward**、**Spend reversal** 或 **Adjustment**；若为扣除，选择 **Spend**、**Reward reversal** 或 **Adjustment**。**Adjustment** 用于既非奖励也非冲正的修正操作。如需区分其他选项，请参阅 [Operation](virtual-currencies#operation)。
5. 在 **Feature** 中，输入积分的用途，例如 `support_compensation`。只能使用字母、数字和 `_`，最多允许一个点号。命名建议请参阅 [Feature](virtual-currencies#feature)。
6. 可选操作：在 **Reference ID** 中输入关联对象的 ID（如支持工单编号）；在 **Comment** 中用不超过 200 个字符说明此次变更原因。您的团队可在用户画像的事件历史记录和 **Change history** 中查看该备注。
7. 点击 **Continue**，确认变更前后的余额和可用金额，然后点击 **Confirm**。

   <ZoomImage id="virtual-currency-adjust-balance-confirm.webp" width="400px" alt="确认调整步骤，显示余额从 1,200 变为 1,250，可消费金额从 950 变为 1,000" />

卡片会显示新余额，变更记录也会出现在用户画像[事件历史](#review-balance-changes-in-the-event-history)的顶部。

如果表单无法确认结果，它会要求你再次点击 **Confirm**。点击即可：Adapty 不会重复执行同一笔调整。

Adapty 不会将手动调整发送至 webhook 或任何集成渠道。

### 查看余额调整记录 \{#see-who-adjusted-a-balance\}

要查看哪位团队成员调整了余额以及调整原因，请在 **Virtual currency** 卡片中点击 **Change history**。列表显示过去 3 个月的手动调整记录，按时间倒序排列。每行显示团队成员及其角色、变更内容、功能、参考 ID、备注以及调整后的余额。

新的调整记录大约需要 2 分钟才会出现在 **Change history** 中。

<ZoomImage id="virtual-currency-change-history.webp" width="700px" alt="变更历史窗口，显示手动调整记录，每条记录包含日期、团队成员、角色、变更内容、功能、参考 ID、备注及调整后余额" />

## 在事件历史记录中查看余额变化 \{#review-balance-changes-in-the-event-history\}

每次余额变化都会出现在用户画像的事件历史记录中，按时间倒序排列。每条记录会注明变化原因及所涉及的货币类型。

Adapty 根据引发余额变化的原因为每条记录命名：

- **虚拟货币已入账**：某次购买、续订或试用开始后授予了积分。
- **虚拟货币已过期**：到期积分在计费周期结束时或订阅终止时重置。
- **虚拟货币交易**：通过服务端 API 发送的不带 `operation` 的[交易](api-adapty/operations/createVirtualCurrencyTransaction)。

通过服务端 API 发送的带有 `operation` 的交易，以及[手动调整余额](#adjust-a-balance-manually)，均以其操作类型命名：

| `operation` | 条目名称 |
|---|---|
| `top_up` | 虚拟货币已充值 |
| `refund` | 虚拟货币已撤销 |
| `spend` | 虚拟货币已扣除 |
| `spend_reversal` | 虚拟货币扣除已回滚 |
| `reward` | 虚拟货币已奖励 |
| `reward_reversal` | 虚拟货币奖励已回滚 |
| `exchange` | 虚拟货币已兑换 |
| `expiry` | 虚拟货币已过期 |
| `migration` | 虚拟货币已迁移 |
| `adjustment` | 虚拟货币已调整 |

条目旁边的图标遵循金额的正负，而非操作类型：收入显示收入图标，支出显示支出图标，若一笔交易同时有收入和支出则显示中性图标。

每条条目会列出其涉及的每种货币的变动情况：

- **虚拟货币**：货币名称和代码，例如 `Gold Coins (COINS)`。
- **金额**：带符号的变动值——收入为正，支出为负。
- **变动后余额**：变动生效后该货币的余额。

一个事件可以同时更改多种货币——例如，一笔[交易](api-adapty/operations/createVirtualCurrencyTransaction)可以扣除一种货币并充值另一种货币，从而实现货币之间的兑换。

### 交易详情 \{#transaction-details\}

要查看余额变动的原因，请展开条目下方的 **Details** 区块。该区块仅显示有值的字段：

<ZoomImage id="virtual-currency-transaction-details.webp" width="500px" alt="A Virtual currency debited entry in the user history with the Details block expanded, showing the operation, feature, reference ID, customer placement ID, and metadata" />

- **Store**：授予积分的购买所在的应用商店。
- **Operation**：交易的 `operation`，由您的后端发送或 Adapty 设置。
- **Feature**：积分的消费或发放用途，来自 `feature`。
- **Reference ID**：您系统中相关对象的 ID，例如生成记录，来自 `reference_id`。
- **Customer placement ID**：应用中发生交易的页面或位置，来自 `customer_placement_id`。这是您自己的 ID，而非 Adapty 的[版位](placements)。
- **Sandbox**：测试交易（发送时带有 `is_sandbox: true`）以及手动调整测试用户余额时显示 **Yes**。
- **Metadata**：您的后端在 `metadata` 中发送的键值对，或手动调整的 `comment`。其他交易不显示元数据。

您的后端在[创建交易记录](api-adapty/operations/createVirtualCurrencyTransaction)时设置这些字段。对于手动调整，这些字段来自 **Adjust balance** 表单。在 Adapty 开始存储这些字段之前记录的交易，显示的字段较少，或者不显示 **Details** 区块。

## 余额、用户画像与设备 \{#balances-profiles-and-devices\}

余额始终归属于某一个[用户画像](profiles-crm)，且不会转移到其他用户画像。Adapty 不会像[在用户账户之间共享访问等级](profiles-crm#sharing-paid-access-between-user-accounts)那样，在用户画像之间共享或转移余额。

实际上，这意味着：

- **已识别用户**：客户用户 ID 始终对应同一个用户画像，因此用户在每台登录设备上看到的余额相同，重新安装应用后余额也会保留。
- **匿名用户**：匿名用户画像可以赚取和消费积分，但它与单台设备上的一次安装绑定。当同一用户重新安装应用，或在未登录的情况下在另一台设备上打开应用时，Adapty 会创建一个余额为零的新匿名用户画像。积分仍留在之前的用户画像中，用户将无法再访问它们。

[市场细分中的余额条件](segments#virtual-currency-balance)同样如此：新的匿名用户画像会以余额为 0 来匹配这些条件。

因此，若要在跨设备和重新安装的情况下维持虚拟货币经济，请为用户设置标识。你可以通过 SDK 在应用代码中标识用户（参见快速入门中的[识别用户](ios-quickstart-identify)），也可以通过[服务端 API](getting-started-with-server-side-api) 从后端完成。

晚期识别用户也有其自身的隐患：如果用户在匿名状态下积累了积分，随后使用已属于另一个用户画像的 customer user ID 登录，设备会切换到该用户画像及其余额，匿名状态下获得的积分将留在旧用户画像上，无法访问。如果 customer user ID 是新的，它会绑定到当前用户画像，用户可以保留其余额。为了安全起见，请在用户获得或购买积分之前完成身份识别。

在[服务端 API](getting-started-with-server-side-api) 调用中，使用 `adapty-profile-id` 或 `adapty-customer-user-id` 请求头来识别用户画像——两者都指向同一个用户画像。对于匿名用户画像，请使用 `adapty-profile-id`。
