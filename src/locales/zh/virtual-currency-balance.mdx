[Profiles/CRM](profiles-crm) 中的每个用户画像都会显示该用户的虚拟货币余额，以及每次变动的历史记录。

## 在用户画像中查看余额 \{#view-balances-in-a-user-profile\}

<ZoomImage id="virtual-currency-balance.webp" width="300px" alt="用户画像页面，显示虚拟货币卡片及用户的货币余额列表" float="right" />

打开用户的[用户画像](https://app.adapty.io/profiles/users)。**Virtual currency** 卡片列出了该用户持有的所有货币。

每行显示：

- 货币**代码**，例如 `COINS`。
- 当前**余额**，以整数表示。

余额会随着用户赚取、消费或获得积分而更新。余额不能低于 0：如果某笔交易试图消费超过用户持有量，则会以 `insufficient_balance` 失败，且不会产生任何变动。没有余额记录的用户画像将显示空白卡片。

如需在自己的代码中读取余额，请调用服务端 API 中的 [List virtual currency balances](api-adapty/operations/listVirtualCurrencyBalances)。

## 在事件历史记录中查看余额变化 \{#review-balance-changes-in-the-event-history\}

每次余额变化都会出现在用户画像的事件历史记录中，按时间倒序排列。每条记录会注明变化原因及所涉及的货币类型。

Adapty 根据引发余额变化的原因为每条记录命名：

- **虚拟货币已入账**：一次购买、续订或试用开始授予了积分。
- **虚拟货币已过期**：在计费周期结束时或订阅终止时，到期积分被重置。
- **虚拟货币交易**：通过服务端 API 发送的不带 `operation` 的[交易](api-adapty/operations/createVirtualCurrencyTransaction)。

通过服务端 API 发送的带有 `operation` 的交易，将以该操作命名：

| `operation` | 条目名称 |
|---|---|
| `top_up` | 虚拟货币已充值 |
| `refund` | 虚拟货币已撤销 |
| `spend` | 虚拟货币已扣除 |
| `spend_reversal` | 虚拟货币扣除已回滚 |
| `reward` | 虚拟货币已奖励 |
| `reward_reversal` | 虚拟货币奖励已回滚 |
| `exchange` | 虚拟货币已兑换 |
| `expiry` | 虚拟货币已过期 |
| `migration` | 虚拟货币已迁移 |
| `adjustment` | 虚拟货币已调整 |

条目旁边的图标遵循金额的正负，而非操作类型：收入显示收入图标，支出显示支出图标，若一笔交易同时有收入和支出则显示中性图标。

每条条目会列出其涉及的每种货币的变动情况：

- **虚拟货币**：货币名称和代码，例如 `Gold Coins (COINS)`。
- **金额**：带符号的变动值——收入为正，支出为负。
- **变动后余额**：变动生效后该货币的余额。

一个事件可以同时更改多种货币——例如，一笔[交易](api-adapty/operations/createVirtualCurrencyTransaction)可以扣除一种货币并充值另一种货币，从而实现货币之间的兑换。

### 交易详情 \{#transaction-details\}

要查看余额变动的原因，请展开条目下方的 **Details** 区块。该区块仅显示有值的字段：

<ZoomImage id="virtual-currency-transaction-details.webp" width="500px" alt="A Virtual currency debited entry in the user history with the Details block expanded, showing the operation, feature, reference ID, customer placement ID, and metadata" />

- **Store**：授予积分的购买所在的商店。
- **Operation**：交易的 `operation`，由您的后端发送或由 Adapty 设置。
- **Feature**：积分的消耗或授予用途，来自 `feature`。
- **Reference ID**：您系统中相关对象的 ID，例如某次生成的 ID，来自 `reference_id`。
- **Customer placement ID**：交易发生的应用内页面或位置，来自 `customer_placement_id`。这是您自定义的 ID，并非 Adapty 的[版位](placements)。
- **Sandbox**：测试交易（发送时附带 `is_sandbox: true`）显示为 **Yes**。
- **Metadata**：您的后端在 `metadata` 中发送的键值对。仅服务端 API 交易会显示元数据。

您的后端在[创建交易](api-adapty/operations/createVirtualCurrencyTransaction)时设置这些字段。在 Adapty 开始存储这些字段之前记录的交易，显示的字段会更少，或者没有 **Details** 模块。

## 余额、用户画像与设备 \{#balances-profiles-and-devices\}

余额始终归属于某一个[用户画像](profiles-crm)，且不会转移到其他用户画像。Adapty 不会像[在用户账户之间共享访问等级](profiles-crm#sharing-paid-access-between-user-accounts)那样，在用户画像之间共享或转移余额。

实际上，这意味着：

- **已识别用户**：客户用户 ID 始终对应同一个用户画像，因此用户在每台登录设备上看到的余额相同，重新安装应用后余额也会保留。
- **匿名用户**：匿名用户画像可以赚取和消费积分，但它与单台设备上的一次安装绑定。当同一用户重新安装应用，或在未登录的情况下在另一台设备上打开应用时，Adapty 会创建一个余额为零的新匿名用户画像。积分仍留在之前的用户画像中，用户将无法再访问它们。

因此，若要在多设备和重装场景下运行虚拟货币体系，需要识别您的用户。您可以通过 SDK 在应用代码中识别用户（参见快速入门中的[识别用户](ios-quickstart-identify)），也可以通过[服务端 API](getting-started-with-server-side-api) 从后端进行识别。

晚期识别用户也有其自身的隐患：如果用户在匿名状态下积累了积分，随后使用已属于另一个用户画像的 customer user ID 登录，设备会切换到该用户画像及其余额，匿名状态下获得的积分将留在旧用户画像上，无法访问。如果 customer user ID 是新的，它会绑定到当前用户画像，用户可以保留其余额。为了安全起见，请在用户获得或购买积分之前完成身份识别。

在[服务端 API](getting-started-with-server-side-api) 调用中，使用 `adapty-profile-id` 或 `adapty-customer-user-id` 请求头来识别用户画像——两者都指向同一个用户画像。对于匿名用户画像，请使用 `adapty-profile-id`。
