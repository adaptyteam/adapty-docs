**セグメント**は、共通の属性を持つユーザーをグループ化するフィルターの集合です。セグメントを使うと、ペイウォールや A/B テストのターゲティングをより効果的に行えます。

<SegmentViewDelay />

セグメントを作成したら、[プレースメントや A/B テストで**オーディエンス**として使用](audience)し、ユーザーに表示するペイウォール（単数または複数）を制御できます。使用例：

- 非サブスクリプションユーザーには標準のペイウォールを表示し、以前にサブスクリプションやトライアルをキャンセルしたユーザーには割引を提供する。
- 国ごとに異なるペイウォールを表示する。
- Apple Search Ads のアトリビューションデータに基づいてユーザーをターゲティングする。
- 古いバージョンのアプリを使用しているユーザーには既存のペイウォールを表示し続け、新しいバージョンのユーザーには更新されたペイウォールを表示する。
- [仮想通貨](#virtual-currency-balance)の残高が少ないユーザーにはコインパックを、多いユーザーにはサブスクリプションを提供する。
- [アナリティクス](controls-filters-grouping-compare-proceeds#filter-and-group-data)では、セグメントでフィルタリングして特定のユーザーグループのパフォーマンスを確認したり、セグメントでグループ化して **All users** 内のパフォーマンスや貢献度を比較したりできる。

## 作成 \{#creation\}

セグメントを作成するには、名前を入力し、フィルターを定義する属性を選択します。複数の属性を選択した場合、ユーザーはすべての条件を満たす必要があります。Adapty は属性間に AND 論理を適用します。

## 利用可能な属性 \{#available-attributes\}

:::note
**Country**（国）や **Calculated total revenue USD**（計算済み合計収益 USD）など多くのユーザー属性は自動的に設定されますが、**Age**（年齢）、**App user ID**（アプリユーザー ID）、**Attribution**（アトリビューション）データ、**Gender**（性別）、**Custom attributes**（カスタム属性）は自動的には設定されません。セグメント化に利用する場合は、[ユーザー属性を設定](setting-user-attributes)するか、[アトリビューションデータを渡す](attribution-integration)必要があります。
:::

:::tip
日付ベースの属性には、以下の方法でフィルタリングできます：

- **固定日付**: カレンダーから特定の日付を選択（例：ブラックフライデーからサイバーマンデーの間にインストールしたユーザーに特別オファーを表示）
- **相対範囲**: 「過去 7 日間」や「過去 3 ヶ月」などの動的な期間を設定（例：30 日以上前に最後に見られたユーザーを再エンゲージしたり、最近のインストールをターゲティングしたりする）

相対範囲は自動的に更新されるため、継続的なキャンペーンに最適です。固定日付は期間限定のプロモーションに最も適しています。
:::

| 属性 | フィルター条件 |
|---------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Age** | ユーザーの年齢。年齢はAdaptyが最初に受け取った時点で計算され、その後は更新されません。 |
| **App User ID** | アプリ内でのユーザー識別子（[customer_user_id](profiles-crm#user-attributes)）。存在するかどうかでフィルタリングできます。例えば、ログインしていないユーザーにのみペイウォールを表示する場合などに使えます。 |
| **App version (current)** | Adaptyが最後にイベントデータを受信した時点でユーザーのデバイスにインストールされているアプリの現在のバージョン。ユーザーがアップグレードするたびに**更新される**ため、現在実行中のバージョンを常に反映します。以前のバージョンからアップグレードしたユーザーを含め、特定のバージョンを実行しているすべてのユーザーに展開する場合に使用します。セグメント作成時に**App version**の横にある鉛筆アイコンを選択して新しいバージョンを追加すると、すぐに使用できます。<br/> **バージョン > X.X** の条件を使用すると、各バージョンを個別にリストアップすることなく、特定のバージョンより古いまたは新しいすべてのアプリバージョンのコンバージョンへの影響を測定できます。<br/><br/> **フォーマット:** バージョン文字列は[SemVer](https://semver.org/)形式に従う必要があります。いずれかの部分で先頭にゼロが付く場合は無効です。`26.03.4`はマッチしませんが、`26.3.4`はマッチします。無効なバージョンはセグメントから自動的に除外されます。 |
| **App version (on install)** | Adaptyが初めてイベントデータを受信した時点でユーザーのデバイスにインストールされていたアプリのバージョン。**インストール時に固定され、その後ユーザーがアップグレードしても更新されません。** 現在のバージョンではなく、最初にインストールしたバージョンでユーザーをターゲティングする場合に使用します。`App version (on install) = 1.5.7`は最初のインストールが1.5.7だったユーザーにのみマッチし、以前のバージョンから1.5.7にアップグレードしたユーザーは自動的に除外されます。アップグレードしたユーザーも対象にするには、代わりに**App version (current)**を使用してください。<br/><br/> **フォーマット:** バージョン文字列は[SemVer](https://semver.org/)形式に従う必要があります。いずれかの部分で先頭にゼロが付く場合は無効です。`26.3.04`はマッチしませんが、`26.3.4`はマッチします。無効なバージョンはセグメントから自動的に除外されます。 |
| **Attribution: Ad Group** | アトリビューションの広告グループ。 |
| **Attribution: Ad Set** | アトリビューションの広告セット。 |
| **Attribution: Campaign** | マーケティングキャンペーンの名前。 |
| **Attribution: Creative** | アトリビューションのクリエイティブキーワード。 |
| **Attribution: Channel** | マーケティングチャネルの名前。 |
| **Attribution: Source** | アトリビューションの発生元。 |
| **Attribution: Status** | アトリビューションのステータス。設定可能な値: <ul><li> **Organic** – ユーザーが有料マーケティングの影響なしにアプリをインストールした場合（例: App Store/Google Playでの直接検索、口コミ、オーガニックなソーシャルメディアリーチ）。</li><li> **Non-organic** – ユーザーが有料マーケティングチャネルを通じて獲得された場合（例: 広告、インフルエンサーキャンペーン、リファラルプログラム）。</li><li> **Unknown** – このユーザーのアトリビューションデータが利用できない場合。</li></ul> |
| **Calculated subscription state** | ユーザーの[現在のサブスクリプション状態](profiles-crm#subscription-state)。サブスクリプションがアクティブか、キャンセル済みか、未解決の請求問題があるかを示します。 |
| **Calculated total revenue USD** | このユーザーが生み出した総収益。 |
| **Country** | ユーザーの最初のリクエスト元のIPアドレスの国。Adaptyは一度設定すると以降のリクエストからは更新しないため、ユーザーが引越し・旅行・VPN使用後も元の国が保持されます。[サーバーサイドAPI](getting-started-with-server-side-api)経由で`ip_country`を送信した場合、その値で上書きされます。ユーザーのApp StoreまたはGoogle Playアカウントの国をターゲットにするには、代わりに**Country from store account**を使用してください。 |
| **Country from store account** | ユーザーのiOSまたはAndroidストアアカウントに関連付けられた国。AdaptyはiOS 13以降を実行しているiOSデバイスのみストアの国を収集します。 |
| **Creation date** | プロファイルが作成された日付（ユーザーのデバイスにアプリが最初にインストールされた日）。 |
| **Device** | メタデータに基づくデバイスの種類。例：「Samsung Galaxy」や「iPhone 13」など。デバイスはアプリユーザーがそのデバイスでアプリを起動すると一覧に表示されます。iOSアプリの場合、最新のAppleモデル（iPhone Duo、iPhone 18 ProおよびPro Max、iPhone 17シリーズ、2025年以降にリリースされたiPad）は最初からリストに含まれているため、いずれかのユーザーがアプリを開く前からターゲティングが可能です。 |
| **Gender** | ユーザーの性別。値は自分で設定します。 |
| **Installation date** | ユーザーがアプリをインストールした日付。 |
| **Language** | ユーザーのデバイスの言語。 <Callout type="warning">Adaptyは言語を2文字の`ISO 639-1`コードとして保存します。`zh-Hant-TW`や`pt-BR`のような拡張ロケールは使用しないでください。ドロップダウンに表示される場合がありますが、ユーザーにはマッチしません。</Callout> <Callout type="tip">言語ターゲティングをさらに絞り込むには、**Language**と**Country**を組み合わせてください。例えば、**簡体字中国語（`zh`）** + **Country = TW, HK, MO** で繁体字中国語スクリプトのユーザーをターゲットにできます。</Callout> |
| **Last seen** | ユーザーが最後にアプリを開いた日付。 |
| **OS** | ユーザーのデバイスのOSバージョン。 |
| **Paid access level** | ユーザーに付与されたアクセスレベル。 |
| **Platform** | ユーザーのデバイスプラットフォーム。設定可能な値: `iOS`、`macOS`、`iPadOS`、`visionOS`、`Android`。<br/> ユーザーが複数のプラットフォーム（例: iOSとAndroid）からアプリにアクセスしている場合、セグメントのメンバーシップはそれぞれのプラットフォームの最新データを使用して個別に評価されます。これにより、同じユーザープロファイルでもプラットフォーム固有のターゲティングが可能になります。 |
| **Subscription expiration date** | サブスクリプションの有効期限、またはその存在・不在。永続アクセス購入の場合は`none`と表示され、ユーザーがプロファイルを持っているがトライアル・サブスクリプション・永続アクセス購入のいずれも行ったことがない場合は空のままになります。 |
| **Subscription product** | 顧客のアクティブなサブスクリプションの最新プロダクトID。 |
| **Virtual currency: &lt;name&gt; (&lt;code&gt;)** | [バーチャル通貨](virtual-currencies)におけるユーザーの現在の残高（例: **Virtual currency: Coins (COINS)**）。アプリ内の各通貨に固有の属性があります。その通貨を一度も受け取っていないユーザーの残高は0です。[バーチャル通貨の残高](#virtual-currency-balance)を参照してください。 |
| **[カスタム属性](profiles-crm#custom-attributes)** | 独自の属性を定義して、アプリやビジネス固有のプロパティに基づく高度にターゲティングされたセグメントを作成できます。 |

## カスタム属性 \{#custom-attributes\}

カスタム属性を定義して、アプリやビジネスに固有のプロパティに基づいたより精度の高いセグメントを構築できます。

:::note
- カスタム属性は SDK または Adapty ダッシュボードで設定できます。SDK での設定手順は[こちら](setting-user-attributes#custom-user-attributes)をご覧ください。
- セグメントで使用後にカスタム属性を変更すると、[アナリティクス](controls-filters-grouping-compare-proceeds#filter-and-group-data)でそのセグメントとユーザーの同期が外れる場合があります。データは以前の値を反映します。
:::

### カスタム属性の設定方法 \{#how-to-configure-a-custom-attribute\}

Adapty ダッシュボードで、属性のドロップダウンメニューから **Create custom attributes** を選択します。

| フィールド | 説明 |
| ------ |--------------------------------------------------------------------------------------------------------------------------------------|
| **Name** | カスタム属性のラベル。Adapty ダッシュボード内でのみ使用されます。 |
| **Key** | 属性の一意の識別子。SDK で使用されるキーと一致している必要があります。 |
| **Type** | 以下から選択します：<ul><li>String：あらかじめ定義した値のリストが必要です。</li><li>Number：数値のみ受け付けます。</li></ul> |
| **Values** | `String` を選択した場合は、使用可能な値のリストを入力します。`Number` を選択した場合、属性は数値入力のみ受け付けます。数値属性は小数値をサポートし、比較演算子と組み合わせて使用できます。 |

カスタム属性を保存すると、**Key** と **Type** は変更できなくなります — 属性を再度開いて編集しようとしても、この2つのフィールドは無効化されています。別のキーまたはタイプを使用したい場合は、既存の属性を編集しようとするのではなく、新しいカスタム属性を作成してください。作成後に変更できるのは、**Name** と（String 属性の場合）**Values** のみです。

必須フィールドを入力したら、セグメント、[A/B テスト](ab-tests)などでカスタム属性を使用できます。

各プロファイルには最大30個のカスタム属性を設定できます。

### 演算子が存在しない属性をどう扱うか \{#how-operators-match-missing-attributes\}

**≠** 演算子は属性が設定されているプロファイルにのみマッチします。属性に値がないプロファイルは `attribute ≠ value` にマッチしません。比較演算子（`>`、`<`、`≥`、`≤`、`between`）も同様です。属性を持たないプロファイルにマッチさせるには、**is not set** 演算子を使用してください。特定の値を持つプロファイル以外のすべてをターゲットにするには、`≠` と **is not set** を組み合わせるか、すべてのプロファイルに明示的な値を設定した上で `≠` だけでフィルタリングしてください。

比較は型付きです。プロファイルに保存された属性の型がセグメントの比較条件と異なる場合（たとえば、セグメントが数値を期待しているところに文字列が格納されている場合）、そのプロファイルは属性を持っていないとみなされます。

## バーチャルカレンシー残高 \{#virtual-currency-balance\}

ユーザーが保有しているクレジット数に応じて異なるペイウォール、オンボーディング、またはA/B テストを表示するには、[バーチャルカレンシー](virtual-currencies)残高でセグメントをフィルタリングします。アプリ内の各カレンシーには独自の属性 **Virtual currency: &lt;name&gt; (&lt;code&gt;)** が追加されます（例: **Virtual currency: Coins (COINS)**）。コードは同じ名前を持つ2つのカレンシーを区別するために使用されます。

<ZoomImage id="segment-vc-balance-attribute.webp" width="700px" alt="セグメントエディターの属性リスト。他の属性の下に Virtual currency: Coins (COINS) と Virtual currency: Gems (GEMS) が表示されている" />

ユーザーが現時点で使用できる残高（現在の残高）でフィルタリングします：

- **オペレーター**: **=**（1つ以上の値）、**≠**、`>`、`<`、`≥`、`≤`、`between`。
- **値**: 0以上の整数。ダッシュボードでは小数や負の数は受け付けません。
- **残高なしは0とみなされる**: 一度もその通貨を受け取ったことのないユーザーの残高は0になるため、`Virtual currency: Coins (COINS) < 10` の条件に該当します。これは[他の属性](#how-operators-match-missing-attributes)とは異なる動作で、他の属性では値が存在しない場合はどの比較にも一致しません。同じ理由から、**is set** や **is not set** オペレーターはありません。

残高フィルターは他のフィルターと組み合わせることができ、1つのセグメントで複数の通貨を使用することもできます。たとえば、**Calculated subscription state** = active かつ **Virtual currency: Coins (COINS)** `< 10` と設定すると、コインが少なくなっているサブスクライバーをターゲットにできます。

<ZoomImage id="segment-vc-balance-filter.webp" width="700px" alt="Virtual currency: Coins (COINS) が 10 未満でフィルタリングされたセグメント。バーチャル通貨残高フィルターを使用しているセグメントではプロファイル数とプロファイルリストが利用できないというメッセージが表示されている" />

Adapty は、SDKがプロファイルまたはペイウォールを取得するたびに残高を読み取ります。そのため、購入、サブスクリプションの更新、[サーバーサイドAPI](getting-started-with-server-side-api)によるトランザクション、クレジットの有効期限切れなど、どのような方法で発生したクレジットやデビットもすぐに反映されます。他の属性に適用されるイベントフィードの遅延は、ここには適用されません。アプリがペイウォールを取得すると、SDKがまだプロファイルを更新していない場合でも、Adapty は現在の残高に基づいてオーディエンスを選択します。

残高フィルターが1つ以上含まれるセグメントには、次の制限があります：

- **ユーザー数やサンプルなし**：**Segments** リストには、ユーザー数の代わりに **—** が表示され、セグメントページには合計数や[ランダムサンプル](#total-number-and-random-sample)が表示されません。Adapty はフェッチ時にのみ残高を読み取るため、事前にユーザー数を集計することができません。
- **チャートには表示されない**：[アナリティクスチャート](controls-filters-grouping-compare-proceeds)をこのセグメントでフィルタリングまたはグループ化することはできません。**Virtual currency** チャートフィルターはその代替にはなりません。このフィルターはプロダクトが付与する通貨によって購入を選択するものであり、残高によってユーザーを選択するものではないためです。
- **クロスプレースメント A/B テストはユーザーを保持する**：このセグメントを通じてユーザーが[クロスプレースメント A/B テスト](ab-test-types#crossplacement-ab-test-limitations)に参加した後、残高がセグメントの条件に合わなくなっても、そのユーザーはバリアントを維持します。バリアントはテスト終了後の[固定期間](general#9-cross-placement-variation-stickiness)が終わるまで有効です。その他の A/B テストでは、フェッチのたびにセグメントに対してユーザーを再照合します。

<ZoomImage id="segment-vc-balance-list.webp" width="700px" alt="残高フィルターが設定されたセグメントがユーザー数の代わりにダッシュを表示しているセグメントリスト" />

残高は1つの[プロファイル](virtual-currency-balance#balances-profiles-and-devices)に属します。アプリを再インストールしたり別のデバイスで開いた匿名ユーザーは、残高0の新しいプロファイルを取得し、再び`< 10`に該当します。デバイスをまたいで残高セグメントを一貫させるには、ユーザーを識別してください。

Adapty がフェッチ中に残高を読み取れない場合、ユーザーはどの残高セグメントにも一致せず、[優先度](change-audience-priority)に従って次のオーディエンスに割り当てられます。

## セグメントの複製 \{#duplicate-segments\}

既存のセグメントに似たものが必要な場合は、最初から作り直す代わりに複製しましょう。ユーザーグループが重複する複数のキャンペーンや A/B テストを運用しているチームの作業時間を節約できます。

セグメントを複製すると、すべてのフィルターと説明を含むコピーが作成されます。新しいセグメントの名前には「(copy)」が追加されるので、元のものと区別できます。新しいセグメントは元のセグメントから独立しており、一方への変更は他方に影響しません。

Adapty ダッシュボードでセグメントを複製するには：

1. Adapty メインメニューの **Profiles & Segments** セクションを開き、[**Segments**](https://app.adapty.io/segments) タブに切り替えます。
2. セグメントの横にある **3-dot** ボタンをクリックし、**Duplicate** を選択します。

## セグメントの削除 \{#delete-segments\}

セグメントが不要になったら、完全に削除できます。

以下のいずれかでセグメントが現在オーディエンスとして使用されている場合、Adapty は削除をブロックします：

- **プレースメント**：削除されていないプレースメントの少なくとも 1 つがそのセグメントをオーディエンスとして使用している。
- **A/B テスト（ライブまたは完了済み）**：削除されていない A/B テストの少なくとも 1 つがそのセグメントをオーディエンスとして使用している。

セグメントの削除において、Adapty は**ライブ**と**完了済み**の A/B テストをどちらもアクティブとして扱います。完了済みのテストは、テスト後のペイウォールまたはオンボーディングを一致するユーザーに表示するために引き続きオーディエンスを使用しており、テストの過去の指標はそのセグメントにスコープされています。セグメントは A/B テスト自体が削除されて初めて解放されます。

:::warning
セグメントの削除は永続的です。削除されたセグメントは復元できません。
:::

Adapty ダッシュボードでセグメントを削除するには：

1. Adapty メインメニューの **Profiles & Segments** に移動し、[**Segments**](https://app.adapty.io/segments) タブに切り替えます。
2. セグメントの横にある **3-dot** ボタンをクリックし、**Delete** を選択します。
3. 確認フィールドにセグメント名を入力し、**Delete forever** をクリックします。

:::info
セグメントが使用中の場合、ダイアログにはそれを参照しているプレースメントと A/B テストの一覧が表示されます。

削除のブロックを解除するには、リストの各プレースメントまたは A/B テストを開き、オーディエンスからセグメントを削除するか、プレースメントまたは A/B テスト自体を削除してください。何もセグメントを参照していない状態になれば、削除できます。
:::
