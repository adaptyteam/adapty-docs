Adapty SDKをインストールしてアプリをリリースすると、[Profiles](profiles-crm)セクションでユーザーやサブスクライバーを確認できます。しかし、既存のインフラからAdaptyへの移行が必要だったり、既存のデータをAdaptyで確認したいという場合はどうすればよいでしょうか？

:::note
データのインポートは必須ではありません

Adapty SDKを統合したアプリをユーザーが開くと、過去のユーザーへのアクセスレベルの付与と購入イベントの復元が自動的に行われます。このケースでは、過去のデータをインポートする必要はありません。ただし、大量の過去のトランザクションがある場合は、データをインポートすることで正確な分析が可能になります。一般的には移行に必須ではありませんが、インポートによって分析精度が向上します。

サポートがトランザクションの `apple_original_transaction_id` または `google_purchase_token` をインポートすると、Adapty はその後に届く App Store および Play のサーバー通知を自動的に同じプロファイルに紐付けます。ユーザーがアプリを先に開く必要はありません。
:::

:::warning
Webhookやその他のインテグレーションがサブスクリプションイベントで報酬（例：仮想通貨）を付与する場合、インポートを開始する前に[インテグレーション設定](configuration)でそのインテグレーションの**Exclude Historical Events**を有効にしてください。有効にしないと、インポートされた過去の購入履歴がインテグレーションイベントを再発火させ、報酬付与のWebhookがユーザーがすでに持っている購入に対して報酬を二重に付与してしまいます。詳しくは[AdaptyへのインテグレーションのMigration](migrate-integrations-to-adapty#exclude-historical-events)をご覧ください。
:::

Adaptyにデータをインポートするには：

1. トランザクションをCSVファイルにエクスポートしてください（iOS、Android、Stripeは別々のファイルにしてください）。詳細な要件については、以下の[インポートファイル形式のセクション](importing-historical-data-to-adapty#import-file-format)を参照してください。
2. いずれかのファイルが1 GBを超える場合は、約100行のデータサンプルを用意してください。
3. すべてのファイルをGoogle Driveにアップロードしてください（圧縮しても構いませんが、ファイルは分けたままにしておいてください）。
4. iOSのトランザクションについては、StoreKit 1を使用している場合でも、[**App settings**](https://app.adapty.io/settings/ios-sdk)の**In-app purchase API**セクションに**Issuer ID**、**Key ID**、および**Private key**（.P8ファイル）が入力されていることを確認してください。詳しい手順については、[Adaptyにアプリ内課金キーを追加する](generate-in-app-purchase-key)を参照してください。
5. [メール](mailto:support@adapty.io)またはAdapty Dashboardのオンラインチャットを通じて、リンクをチームと共有してください。

既存のデータと重複する場合でも、過去のデータをインポートしても重複が作成されることはありません。ご安心ください。

## Androidの既知の制限事項 \{#known-limitations-for-android\}

1. アクティブなサブスクリプションのみが復元されます。期限切れのトランザクションは復元されません。
2. サブスクリプションの最新の更新のみが復元されます。購入の全チェーンは復元されません。
3. 購入後にプロダクト価格が変更された場合、現在の価格が使用されるため、価格が正しく表示されないことがあります。

:::note
Androidトランザクションの件数が多い場合、デフォルトのAPI制限を超えないよう、インポートを開始する前に[Google Play Developer APIのクォータ増加をリクエスト](google-play-quota-increase)する必要があるかもしれません。
:::

## インポートファイルの形式 \{#import-file-format\}

:::tip
RevenueCatから移行する場合、RevenueCatのエクスポートファイルをそのまま送信できます。変換は不要です。エクスポート手順については[RevenueCatのドキュメント](https://www.revenuecat.com/docs/integrations/scheduled-data-exports)を参照してください。
:::

以下のルールに従ったファイルでデータを準備してください：

- [ ] ファイル形式は .CSV です。
- [ ] Android、iOS、Stripe のインポートファイルはそれぞれ別のファイルです。
- [ ] すべてのインポートファイルに[必須カラム](importing-historical-data-to-adapty#required-fields)が含まれています。
- [ ] インポートファイルのカラムにはヘッダーがあります。
- [ ] カラムのヘッダーは、下の表の **Column name** カラムに記載されているとおりです。タイプミスがないか確認してください。
- [ ] 必須でないカラムはファイルから省略できます。データがない項目のために空のカラムを追加しないでください。
- [ ] インポートファイルには、表に記載されていない余分なカラムを含めないでください。含まれている場合は削除してください。
- [ ] 値はカンマで区切ってください。
- [ ] 値を引用符で囲まないでください。
- [ ] 1 人のユーザーに複数の **apple_original_transaction_id** がある場合は、**apple_original_transaction_id** ごとに別の行として追加してください。そうしないと、消耗型アイテムの購入を復元できない場合があります。

サンプルファイルとして、[iOS](https://raw.githubusercontent.com/adaptyteam/adapty-docs/refs/heads/main/Downloads/adapty_import_ios_sample.csv)および[Android](https://raw.githubusercontent.com/adaptyteam/adapty-docs/refs/heads/main/Downloads/adapty_import_android_sample.csv)のファイルをご利用ください。

### 必須フィールド \{#required-fields\}

各プラットフォームには、**user_id**と対応するプラットフォーム固有の購入を識別するデータという2つの必須フィールドグループがあります。プラットフォームごとの必須フィールドは下記の表を参照してください。

| プラットフォーム | 必須フィールド |
|--------|---------------|
| iOS | <p>user_id</p><p>apple_original_transaction_id</p> |
| Android | <p>user_id</p><p>google_product_id</p><p>google_purchase_token</p><p>google_is_subscription</p> |
| Stripe | <p>user_id</p><p>stripe_token</p> |

これらのフィールドがなければ、Adaptyはトランザクションを取得できません。

正確なコホートアナリティクスのために、`created_at`を指定してください。指定しない場合、インストール日は最初の購入日と同じとみなされます。

### データをAdaptyにインポートする \{#import-data-to-adapty\}

インポートファイルをご用意の上、[support@adapty.io](mailto:support@adapty.io) または [Adapty ダッシュボード](https://app.adapty.io/overview)のオンラインチャットよりお問い合わせください。
