CLIはAdapty APIを呼び出すために認証が必要です。

ログインは1回でCLI全体をカバーします。[Ads Managerコマンド](developer-cli-ads-manager)は異なるサービスにアクセスしますが、同じ保存済みトークンを使用するため、2回目のログインは不要です。EUサーバーのアカウントの場合は、ログイン時にリージョンを指定します。詳細は[EUアカウントへのログイン](#log-in-to-an-eu-account)をご覧ください。

## ログイン \{#log-in\}

ログインするには：

1. ターミナルで次のコマンドを実行します：
   ```bash
   adapty auth login
   ```
2. CLIが`XXXX-XXXX`形式の確認コードを表示し、Adapty ダッシュボードをブラウザで開きます。
3. 認証ページで、コードがターミナルの出力と一致していることを確認します。
4. **Authorize**をクリックします。ブラウザに「CLI authorized! You can close this tab.」と表示されます。
5. ターミナルに戻ると、CLIが認証済みであることを確認するメッセージが表示されます。

認証前にコードが期限切れになった場合、または**Deny**をクリックした場合は、次のコマンドを再度実行してフローを再開してください：

```bash
adapty auth login
```

### EUアカウントにログインする \{#log-in-to-an-eu-account\}

[EUサーバー](eu-cluster)のアカウントへのログインには、CLI 0.30.0以降が必要です。

EUアカウントにログインするには：

1. ターミナルで以下を実行します：
   ```bash
   ADAPTY_REGION=eu adapty auth login
   ```
2. [https://app.adapty.io/eu-login](https://app.adapty.io/eu-login) でサインイン済みのブラウザでリンクを開きます。サインインしていない場合、またはUSアカウントでサインイン中の場合は、先にそちらでサインインしてください。
3. コードを確認して **Authorize** をクリックします。詳細は[ログイン](#log-in)を参照してください。

CLIはログイン時にリージョンを保存するため、以降のコマンドは`ADAPTY_REGION`なしでもEUサーバーへ送信されます。`adapty auth status`の出力に`Region: eu`の行が表示されていれば確認できます。

`ADAPTY_TOKEN`を設定するスクリプトでは、`ADAPTY_REGION`も`us`または`eu`に設定してください。設定しない場合、コマンドはそのコンピューターに保存されているログインのリージョンを使用しますが、それが別のアカウントのものである可能性があります。

CLIがセッションファイルの破損を報告した場合は、アカウントのリージョンを`ADAPTY_REGION`に設定した上で、`adapty auth login`を再実行してください。新しいログインでファイルが上書きされます。

[Ads Manager](developer-cli-ads-manager) および [アトリビューション](developer-cli-attribution) コマンドは EU アカウントでは利用できません。リクエストを送信する前にエラーで停止します。例：`Apple Search Ads commands are not available for EU accounts.`

## 認証の管理 \{#manage-authentication\}

### 認証状態を確認する \{#check-authentication-status\}

現在の認証状態を確認するには、次のコマンドを実行します：

```bash
adapty auth status
```

認証済みの場合、出力には名前、マスクされたトークンのプレフィックス、およびローカル設定ファイルのパスが表示されます：

```
User: Jane Doe
Token: abcd1234****
Config: ~/.config/adapty/config.json
```

CLI 0.9.1 以降、ログイン時には名前のみが保存され、メールアドレスは保存されません。`Email:` の行は、旧バージョンで保存されたセッションにのみ表示されます。`adapty auth status --json` の出力を読み取るスクリプトでは、`name` フィールドでユーザーを識別してください。

未認証の場合：

```
Not authenticated. Run `adapty auth login`.
```

### トークンの検証 \{#verify-your-token\}

トークンが有効であることを確認し、アカウントの詳細を表示するには、次のコマンドを実行します：

```bash
adapty auth whoami
```

`adapty auth status`とは異なり、このコマンドはサーバーにリクエストを送信してトークンを検証します。

### ログアウト \{#log-out\}

ローカルに保存されている認証情報をクリアするには、次のコマンドを実行します：

```bash
adapty auth logout
```

これにより、`~/.config/adapty/config.json` と `adapty migrations create` または `adapty migrations use` によって保存されたマイグレーションがクリアされます。トークンはサーバー側では有効期限が切れるまで有効なままです。即座に無効化する必要がある場合は、代わりに `adapty auth revoke` を使用してください。

### トークンを無効化する \{#revoke-your-token\}

サーバー上のトークンを無効化してローカルから削除するには、次のコマンドを実行します：

```bash
adapty auth revoke
```

トークンに保存済みのマイグレーションがある場合、サーバーが無効化を確認した後にのみ、CLI がそれも削除します。認証情報が漏洩した可能性がある場合など、トークンを完全に無効化したいときに使用してください。無効化後は、`adapty auth login` を実行して再認証してください。

## トークンの有効期間 \{#token-lifetime\}

`adapty auth login` で発行されたトークンは、ログインから90日間有効です。トークンを使用しても有効期間は延長されず、CLIにはリフレッシュトークンもありません。トークンが期限切れになると、CLIコマンドは401エラーを返すため、ブラウザから再度ログインする必要があります。

ログイン承認のために人が介在できないスケジュールジョブでは、トークンを自動更新できません。そのようなジョブには、アプリのシークレットAPIキーで認証する[エクスポートアナリティクスAPI](export-analytics-api)を使用してください。

## トークンエラー \{#token-errors\}

トークンが失効、期限切れ、または無効になった場合、CLI コマンドは 401 エラーを返します。再認証するには、次のコマンドを実行してください：

```bash
adapty auth login
```
