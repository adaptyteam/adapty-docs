スクリーン間の遷移（あるスクリーンが消えて新しいスクリーンが現れる動き）をアニメーションで設定できます。利用可能なアニメーションは、使用するナビゲーションアクションによって異なります。

- [**Navigate to Screen**](onboarding-actions#navigate-to-screen): [アクション設定](#customize-a-transition)を開き、[アニメーションタイプの一覧](#animation-types)から選択します。ステップごとに異なるトランジションを使用できます。
- **Navigate Next**: デフォルトのプッシュアニメーションのみ使用できます。
- **Navigate back**: 現在の画面に遷移した際に使用したトランジションを逆再生し、遅延なしで実行します。到着時にアニメーションがなかった場合、戻る際もアニメーションはありません。
- **Close Flow**: 固有のアニメーションはありません。フローとネイティブ UI 間のトランジションはアプリ側で処理してください。

遅延実行の **Navigate to Screen** アクションを使うと、[スプラッシュ画面やローディング画面から自動的にユーザーを移動させる](#move-users-to-another-screen-automatically)ことができます。

## アニメーションの種類 \{#animation-types\}

**Navigate to Screen** アクションの **Animation** ドロップダウンには、5つのオプションがあります。

- **Push**: 新しい画面が一方の端から入ってきて、現在の画面をもう一方の端に押し出します。
- **Slide in**: 新しい画面が同じ方向に少し動く現在の画面の上にスライドしながらフェードインします。
- **Slide out**: 現在の画面がスライドしてフェードアウトし、その下にある新しい画面が現れます。
- **Fade through**: 新しい画面が現在の画面の上にフェードインします。
- **None**: 新しい画面が即座に現在の画面と置き換わります。

## トランジションをカスタマイズする \{#customize-a-transition\}

トランジションのアニメーションは、**Navigate to Screen** アクションでのみ変更できます。

<ZoomImage id="navigate-to-screen-settings.webp" width="300px" float="right" alt="Navigate to Screen のアクション編集ウィンドウ。移動先はペイウォール、Slide in upward with Ease out bounce、400ms の時間、ディレイなし" />

1. ナビゲーションアクションをトリガーする要素を選択します。
2. **Interactions** パネルで、ナビゲーションアクションをクリックします。
3. アクションが **Navigate Next** の場合は、**Action** ドロップダウンから **Navigate to Screen** を選択します。次に、**Destination** として次の画面を選択します。
4. **Animation** ドロップダウンからアニメーションを選択します。
5. アニメーションに **Direction**、**Easing**、**Duration** の設定がある場合は、それらを調整します。
6. アニメーション開始前に現在の画面を表示したままにするには、**Delay** フィールドに値を設定します。たとえば、遅延を使用して[ローディング画面](builder-loaders-and-progress-bars#loaders)を数秒間表示してから[自動的に次の画面に進む](#move-users-to-another-screen-automatically)ようにすることができます。[ナビゲーションの後に記載されているアクション](onboarding-actions#action-order)は、遅延を待ちません。
7. 実際の画面でトランジションを確認するには、[デバイスでフローをテスト](paywall-device-compatibility-preview#preview-on-devices)してください。

## 自動的に別のスクリーンへユーザーを移動させる \{#move-users-to-another-screen-automatically\}

スプラッシュ画面やローディング画面からユーザーを移動させるには、**Navigate to Screen** アクションに最大5秒の遅延を設定してください。

1. ローダーなど、画面上の任意の要素を選択します。
2. **Interactions** パネルで、**Navigate to Screen** アクションを持つ [**On Screen Appear** トリガーを追加](onboarding-actions#set-up-interactions)します。
3. **Destination** ドロップダウンで次の画面を選択します。
4. **Delay** フィールドは **Animation** を設定しないと表示されません。**None** 以外の任意の **Animation** を選択してください。アニメーションなしで画面を切り替えるには、**Duration** フィールドを 0 に設定します。
5. **Delay** フィールドで、画面が表示される時間を最大 5000 ms で設定します。整数秒を使用してください。iOS では遅延が整数秒に切り上げられます。
6. 画面が次に進むことを確認するには、[デバイスでフローをテスト](paywall-device-compatibility-preview#preview-on-devices)してください。キャンバス上ではアクションは実行されません。

画面が待機中に、次の操作を行うと遅延した **Navigate to Screen** アクションがキャンセルされます。

- ユーザーがナビゲーションボタンをタップすると、すぐに次の画面に移動します。
- 次のいずれかを行うと、画面はそのまま維持されます。
  - アラート、ボトムシート、日付ピッカー、またはウェブページを開く。
  - 購入または復元を開始する。

ユーザーがその画面でこれらの操作を行える場合は、次の画面に進めるよう、ナビゲーションボタンを追加してください。

ユーザーが画面に戻ると、遅延が再びスタートします。

5秒を超える遅延を設定する場合は、**On Timer End** トリガーを持つ[カウントダウンタイマー](flow-timer)を追加し、次の画面に遷移するよう設定してください。タイマーを非表示にするには、テキストを完全に透明にし、**Visibility** は **Show** のままにしておきます。これにより、トリガーが正しく発火します。
