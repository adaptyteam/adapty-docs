## 始める前に \{#before-you-start\}

必要なもの:

- **Adapty Flutter SDK 4.4 以降**: それより前のバージョンでは、すべてのカスタム要素にフォールバックが表示されます。
- **iOS および Android のネイティブコード**: カスタム要素に Flutter ウィジェットを表示することはできません。iOS では Swift、Android では Kotlin でビューとリゾルバーを記述してください。Swift コードは Xcode の `Runner` ターゲットに追加し、Kotlin コードは `android/app/src/main/kotlin` に追加します。
- **Android の Adapty UI ライブラリ**: `android/app/build.gradle.kts` などの Android アプリモジュールの Gradle ファイルで、`dependencies` ブロックに `implementation("io.adapty:android-ui")` を追加してください。バージョンや Adapty BOM は追加しないでください。バージョンは `adapty_flutter` が設定しており、新しい `android-ui` を指定するとフローが壊れる可能性があります。
- **Android でコンポーザブルを使用する場合の Jetpack Compose**: Flutter テンプレートはアプリモジュールに [Compose をセットアップ](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)しません。リゾルバーからコンポーザブルを返すには、Compose コンパイラーの Gradle プラグインを適用し、`buildFeatures` ブロックで `compose = true` を設定してください。Android の `View` には Compose のセットアップは不要です。このページの Lottie ビューの場合は、`com.airbnb.android:lottie-compose` も追加してください。
- **カスタム要素の命名規則**: 各ネイティブビューに `lottie_animation` のような Type を付けてください。Type には小文字、数字、アンダースコアのみ使用できます。同じ Type のカスタム要素を区別するために、`welcome_wave` のように各要素に ID を付けてください。コード内の Type と ID は、[フロー & ペイウォールビルダー](flow-custom-elements#add-and-configure)で設定したものと一致している必要があります。

iOSとAndroidのコードで同じTypeとIDを使用してください。各プラットフォーム向けに別々の[オーディエンス](audience)を設定しない限り、iOSとAndroidのユーザーには同じフローが表示されます。

## カスタム要素のビューを作成する \{#create-views-for-custom-elements\}

各 Type に対して、iOS と Android 用のネイティブビューを作成するか、既存のネイティブコードから再利用してください。以下の `lottie_animation` Type のビューは Lottie アニメーションを再生します。Android ビューは `com.airbnb.android:lottie-compose` ライブラリを使用する Composable です。

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

```swift showLineNumbers title="Swift"

struct LottieElementView: View {
    let animation: LottieAnimation?

    var body: some View {
        LottieView(animation: animation)
            .resizable()
            .looping()
    }
}
```

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

```kotlin showLineNumbers title="Kotlin"

@Composable
fun LottieElement(animationFile: String) {
    val composition by rememberLottieComposition(LottieCompositionSpec.Asset(animationFile))
    LottieAnimation(
        composition = composition,
        iterations = LottieConstants.IterateForever,
    )
}
```

</Tabs>

### 要件とベストプラクティス \{#requirements-and-best-practices\}

- **サイズ調整**:
  - **パディングと配置**: ネイティブビューが、フロー & ペイウォールビルダーで確保したコンテナにパディングを引いたサイズで収まるようにしてください。ビューがエリア全体を占有しない場合、デフォルトではそのエリアの左上隅に表示されます。位置を変更するには、カスタム要素の **Layout** セクションで配置を変更してください。
  - **Hug の高さ**: カスタム要素の高さが **Hug** に設定されている場合、利用可能なスペースいっぱいに広がるビュー（マップやレイジーリストなど）は縮小するか、画面の高さまで伸びてしまいます。代わりにカスタム要素に[**Fixed** の高さ](flow-custom-elements#add-and-configure)を設定してください。
- **テーマ**: ネイティブビューは Flutter テーマのカラーやフォントを継承しません。ネイティブコード内で設定してください。
- **フローアクション**: ネイティブビューは、次の画面への遷移などのフローアクションを実行できません。エレメントのコンテキストは iOS では `sendMessage`、Android では `send` を使用してフローにメッセージを送信できますが、これらは将来のフロー & ペイウォールビルダー機能のために予約されています。ナビゲーションボタン、購入ボタン、フローアクションを持つその他のボタンはカスタム要素の外に配置してください。
- **選択可能な要素**: カスタム要素をプロダクトカードやその他の[選択可能な要素](flow-selectable-elements)の外に配置してください。選択が変わると、ネイティブビューの状態が失われる可能性があります。
- **ナビゲーションの処理**: ユーザーが次の画面に移動すると、SDK はネイティブビューを画面から削除します。カメラセッション、プレーヤー、位置情報の更新など、ビューが開始したものを停止してください:
  - **SwiftUI ビュー**: `onDisappear` アクションを使用してください。非同期処理には `.task` を使用してください。ビューが非表示になると SwiftUI がキャンセルします。
  - **Composable**: `DisposableEffect` の `onDispose` ブロックを使用してください。非同期処理には `LaunchedEffect` を使用してください。コンポーザブルがコンポジションから離れると Compose がキャンセルします。
  - **Android `View`**: `View` サブクラスで `onDetachedFromWindow` をオーバーライドするか、`View` に `View.OnAttachStateChangeListener` を追加してください。

  ユーザーが戻ってきたとき、またはAndroidで画面回転などの設定変更が発生したとき、SDKはリゾルバーを再度呼び出し、ネイティブビューは以前の状態を引き継がずに新たに起動します。
- **UIKit ビュー**: iOS では `UIViewRepresentable` でラップしてください。
- **カルーセル**: Android では、[カルーセル](builder-containers#carousel)内のネイティブビューは、表示中のスライドだけでなく、すべてのスライドのビューが画面が開いている間アクティブな状態を保ちます。カメラプレビューや音声付きプレーヤーはカルーセル内に配置しないでください。

## カスタム要素とビューを対応付けるリゾルバーを作成する \{#write-a-resolver-to-match-custom-elements-and-views\}

各プラットフォーム向けにリゾルバーを作成します。リゾルバーはカスタム要素のTypeとIDを受け取り、対応するネイティブビューを返します。

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

リゾルバーを作成するには、`AdaptyUICustomElementsResolver` プロトコルに準拠した型を定義し、`view(forType:id:context:)` メソッドを実装します。

`lottie_animation` Typeに対して、以下のリゾルバーは `LottieElementView` を返します。IDにはアプリバンドル内のアニメーションファイル名（例：`welcome_wave`）を指定します。

```swift showLineNumbers title="Swift"

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "lottie_animation":
            // the ID names the animation file, such as welcome_wave.json
            guard let animation = LottieAnimation.named(id) else {
                return nil // no file for this ID: show the fallback
            }
            return AnyView(LottieElementView(animation: animation))
        default:
            return nil
        }
    }
}
```

`default` ケースでは、`nil` を返します。

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

リゾルバーを実装するには、`AdaptyCustomElementsResolver` インターフェースを実装します。その `resolve` メソッドは、以下のいずれかの形式でマッチングするビューを返します。

- **コンポーザブル**: `AdaptyCustomElementContent.compose` を返し、そのラムダ内にコンポーザブルを含めます。
- **Android の `View`**: `AdaptyCustomElementContent.view` を返し、`View` を作成する関数を指定します。`factory` パラメータには必ず名前を付けてください: `AdaptyCustomElementContent.view(factory = { context, _ -> ChartView(context) })`。名前を省略すると、Kotlin はトレーリングラムダをオプションの `update` パラメータとして解釈し、コンパイルエラーになります。

`lottie_animation` タイプでは、次のリゾルバーが [Lottie ビュー](#create-views-for-custom-elements)を返します。ID は `assets` フォルダー（`android/app/src/main/assets`）内のアニメーションファイル名を指定します。例えば `welcome_wave.json` の場合は `welcome_wave` となります。

```kotlin showLineNumbers title="Kotlin"

class CustomElementsResolver(context: Context) : AdaptyCustomElementsResolver {
    // the animation files in the assets folder, listed once
    private val animationFiles: Set<String> = try {
        context.assets.list("").orEmpty().toSet()
    } catch (e: IOException) {
        emptySet() // no list of files: every Lottie element shows the fallback
    }

    override fun resolve(type: String, id: String): AdaptyCustomElementContent? =
        when (type) {
            "lottie_animation" -> {
                // the ID names the animation file, such as welcome_wave.json
                val file = "$id.json"
                if (file in animationFiles) {
                    AdaptyCustomElementContent.compose { LottieElement(file) }
                } else {
                    null // no file for this ID: show the fallback
                }
            }
            else -> null
        }
}
```

その他のタイプの場合は `null` を返してください。

</TabItem>
</Tabs>

アプリをリリースした後に[新しいタイプを持つカスタム要素を追加した](flow-custom-elements#what-changes-require-an-app-release)場合、リリース済みバージョンのユーザーにはそのフォールバックが表示されます。

リゾルバには以下の要件があります：

- **ネットワークデータとプレイヤー**: ネットワークデータとプレイヤーは、リゾルバーではなく[ネイティブビュー](#create-views-for-custom-elements)の状態として保持してください。SDK は画面が開いている間にリゾルバーを何度も呼び出します。リゾルバー内のコードは呼び出しのたびに再実行されるため、ネットワークリクエストが繰り返され、プレイヤーが最初からやり直しになります。ネイティブビューはこれらの呼び出し間で状態を保持するため、データは一度だけ読み込まれ、プレイヤーは再生し続けます。プレイヤー、セッション、ネットワークリクエストはネイティブビュー内で作成してください。
  - **SwiftUI ビュー**: プレイヤー、セッション、ネットワークリクエストは `.task` または `@StateObject` 内で作成し、`@State` プロパティの初期値として作成しないでください。Swift はリゾルバーがビューを作成するたびにその初期値を再評価します。
  - **Composable**: プレイヤーとセッションは `remember` 内で、ネットワークリクエストは `LaunchedEffect` 内で作成してください。
  - **Android `View`**: プレイヤー、セッション、ネットワークリクエストは `onAttachedToWindow` 内で作成してください。
- **カスタム要素ごとに 1 つのネイティブビュー**: ネイティブビューによっては、データの読み込み時やユーザーのタップ時など、画面が開いている間に変化するものがあります。このロジックはリゾルバーではなくネイティブビュー自体に実装してください。リゾルバーが同じカスタム要素に対して異なるビューを返すと、ビューは状態を失います。
- **出現ごとに新しい `View` を作成**: Android では、`factory` の各呼び出しで新しい `View` を作成してください。SDK は、画面が開いたとき、ユーザーが画面に戻ったとき、画面が回転した後など、カスタム要素が表示されるたびに `factory` を呼び出します。
- **アプリデータ**: [デイリーストリーク](flutter-custom-element-lottie-animation)など、データを保持する `ObservableObject` や `StateFlow` のようなオブジェクトは、リゾルバーのプロパティとして保存してください。そのオブジェクトをネイティブビューに渡し、ネイティブビュー内でオブジェクトを監視してください。
  - **SwiftUI ビュー**: `ObservableObject` を `@ObservedObject` で監視してください。
  - **Composable**: `StateFlow` を `collectAsState` で収集するか、`LiveData` を `observeAsState` で監視してください。
  - **Android `View`**: `onAttachedToWindow` でオブジェクトの監視を開始し、`onDetachedFromWindow` で停止してください。

  あなたがリゾルバにコピーする値（ストリーク数など）は、リゾルバを作成した時点の値のまま固定されます。Dartコードにデータ（例えばデイリーストリーク）がある場合は、[プラットフォームチャンネル](https://docs.flutter.dev/platform-integration/platform-channels)を通じてネイティブコードに新しい値を送信し、そちらでオブジェクトを更新してください。

### フォールバックコンテンツの条件を設定する \{#set-conditions-for-fallback-content\}

<FlowCustomElementsFallbackConditions />

権限については、画面が開く前にユーザーが拒否した場合にのみ、ビューを返さないようにしてください。Android では、`ContextCompat.checkSelfPermission` は2つのケースで同じ値 `PERMISSION_DENIED` を返します。アプリが初めてユーザーに権限を要求する前と、ユーザーが拒否した後です。これらのケースを区別するには、権限リクエストの結果を保存し、リゾルバーでその保存された結果を読み取ってください。アプリがまだ権限を要求していない場合は、ネイティブビューを返し、ビューの中で権限を要求してください。たとえば、[マップビュー](flutter-custom-element-map#3-match-the-map-to-the-custom-element)が表示されたときに位置情報へのアクセスを要求し、ユーザーがアクセスを許可したらすぐにマップを表示します。ビューを返さない状態でユーザーが後からアクセスを許可しても、フォールバックが表示されたままになります。権限の変更によって SDK がリゾルバーを再度呼び出すことはありません。ネイティブビューが表示されるのは、ユーザーが画面に戻ったときなど、SDK がリゾルバーを再度呼び出したときのみです。

## リゾルバーをSDKに渡す \{#pass-the-resolver-to-the-sdk\}

各プラットフォームでアプリ起動時に一度だけリゾルバーを設定してください。SDKは`AdaptyUIFlowPlatformView`で埋め込まれたフローを含め、すべてのフローでリゾルバーを呼び出します。これらのビューはアプリのリリースなしで、新しいフローやA/B テストにユーザー独自のビューを表示できます。これらのビューは[デイリーストリーク](flutter-custom-element-lottie-animation)など、アプリからデータを読み取ることで各ユーザー固有のデータを表示します。

<Tabs groupId="platform" queryString>
<TabItem value="ios" label="iOS (Swift)" default>

`ios/Runner/AppDelegate.swift` にて `AdaptyUI` をインポートし、`application(_:didFinishLaunchingWithOptions:)` メソッド内で `AdaptyUI.setCustomElementsResolver(_:)` を呼び出してください。`AppDelegate` クラスのそれ以外の部分はそのままにしてください：

```swift showLineNumbers title="ios/Runner/AppDelegate.swift"

// in application(_:didFinishLaunchingWithOptions:), before `return super.application(...)`
AdaptyUI.setCustomElementsResolver(CustomElementsResolver())
```

`AppDelegate.swift` 内にリゾルバーも記述する場合は、`AdaptyUIBuilder` もインポートしてください。

</TabItem>
<TabItem value="android" label="Android (Kotlin)">

`Application`クラスの`onCreate`メソッド内で`AdaptyUI.setCustomElementsResolver`を呼び出してください。アプリに`Application`クラスがない場合は、新しく作成してください：

```kotlin showLineNumbers title="Kotlin"

class App : Application() {
    override fun onCreate() {
        super.onCreate()
        AdaptyUI.setCustomElementsResolver(CustomElementsResolver(this))
    }
}
```

`android/app/src/main/AndroidManifest.xml` で、`<application>` の `android:name` 属性に `Application` クラスを指定します。Flutter テンプレートでは、この属性はベースとなる `Application` クラスを表す `${applicationName}` に設定されています。

```xml showLineNumbers title="AndroidManifest.xml" {2}
<application
    android:name=".App"
    android:label="your_app">
    <!-- the rest of your application element -->
</application>
```

</TabItem>
</Tabs>

:::tip
カスタム要素の各 Type に同じビューを表示する場合は、リゾルバーの代わりに Type とビューのマップを渡してください。iOS では、マップは `[String: AdaptyUICustomElementBuilder]` ディクショナリです。Android では、`AdaptyCustomElementsResolver.of` にマップを渡します。マップはリゾルバーよりもコード量が少なくて済みますが、[フォールバックコンテンツの条件設定](#set-conditions-for-fallback-content)はできません。

```swift showLineNumbers title="Swift"
AdaptyUI.setCustomElementsResolver([
    "lottie_animation": .init { _, id, _ in LottieElementView(animation: .named(id)) },
])
```

```kotlin showLineNumbers title="Kotlin"
val appWideViews = mapOf(
    "confetti" to AdaptyCustomElementContent.compose { LottieElement("confetti.json") },
)
AdaptyUI.setCustomElementsResolver(AdaptyCustomElementsResolver.of(appWideViews))
```
:::

リゾルバーを特定のフローに紐付けることはできません。フローを開いたときにアプリが初めて取得できるデータを表示するには、フローを開く前にそのデータをネイティブコードに渡してください。その後、リゾルバー内でそのデータを読み取ります。たとえば、[ユーザーが前のフローで入力した体重をペイウォールに表示する](flutter-custom-element-interactive-chart)といった使い方ができます。

## デバイスでテストする \{#test-on-a-device\}

フロービルダー・ペイウォールビルダーはアプリのコードを実行できないため、キャンバスにはフォールバックのみが表示されます。ネイティブビューにエラーがあるとアプリがクラッシュする可能性があります。アプリをリリースする前に、カスタム要素を含むすべての画面を iOS デバイスと Android デバイスでテストしてください。

1. キャッシュではなく各フローの最新公開バージョンを確認するには、デバイスを[テストデバイス](test-devices)として登録してください。
2. デバイス上で、リゾルバーを含むビルドを実行します。カスタム要素があるすべての画面を開き、ネイティブビューが表示されてカスタム要素に正しく収まっていることを確認してください。ビューがスクロールやドラッグに対応している場合は、これらのジェスチャーもテストしてください。
3. ネイティブビューではなくフォールバックが表示される場合は、Xcode コンソールまたは Logcat で次の警告を確認してください: `custom element <type>:<id> is not served by a resolver`。その後、以下を確認してください:
   - 警告内の Type と ID が、コード内のものと一字一句一致していること。
   - アプリがビューに必要なファイル、データ、または権限を持っていること。
   - アプリが起動時にリゾルバーを設定していること: iOS では `AppDelegate` クラス内で、Android では `AndroidManifest.xml` に指定された `Application` クラス内で設定されていること。

   もし警告が表示されない場合は、アプリが Adapty Flutter SDK 4.4 以降を使用しており、[ログレベル](sdk-installation-flutter#logging) が `AdaptyLogLevel.error` になっていないことを確認してください。
4. Android で、カスタム要素が空のままになっている場合は、Logcat で以下のいずれかの警告を確認してください：
   - `custom element <type>:<id> is not served by a resolver`：カスタム要素にフォールバックコンテンツがなく、どのリゾルバーもビューを返していません。手順3の各項目を確認してください。
   - `content does not report its size`：コンポーザブルに独自の高さがありません。カスタム要素に[**Fixed** の高さ](flow-custom-elements#add-and-configure)を設定してください。

   SDKは、コンポーザブルのサイズ警告のみをログに出力します。Android の `View` が警告なしで空のまま表示される場合は、カスタム要素に**Fixed**の高さも設定してください。
5. フォールバックをプレビューするには、Type に対してビューを返さず、再度スクリーンを開いてください。

## 例 \{#examples\}

各レシピには、ビルダーでの設定とアプリ用のコードが含まれています：

- [Lottie アニメーションでユーザーの進捗を表示する](flutter-custom-element-lottie-animation): ストリークが伸びるにつれて満たされるリング。
- [ペイウォールにインタラクティブな体重目標チャートを表示する](flutter-custom-element-interactive-chart): オンボーディングフローに続くペイウォールフロー内の体重目標チャート。
