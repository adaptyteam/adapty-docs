[フロー](adapty-flow-builder)とは、Flow & Paywall Builder で作成するペイウォールやオンボーディングのことです。CLI はフローのレコード、ビルダーのコンフィグ、および公開を管理します。ビルダーのコンフィグは Flow & Paywall Builder が生成する大きな JSON ドキュメントであり、CLI 自体は生成しません。ターミナルからコンフィグを作成・編集するには、[flow-generator スキル](flow-generator-skill)を使用してください。このスキルがコマンドを代わりに実行します。公開前には、[flow-audit スキル](flow-audit-skill)でフローが本番環境に対応しているか確認します。`flows metrics` コマンドは[フロー指標](flow-metrics)ページの数値を読み取るため、CLI バージョン 0.15.0 以降が必要です。以下はコマンドのリファレンスです。

## adapty flows list \{#adapty-flows-list\}

アプリのすべてのフローを一覧表示します。

```bash
adapty flows list --app <app-id>
```

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリ ID (UUID) |

[ページネーションフラグ](developer-cli-reference#global-flags)を使用できます。

## adapty flows get

特定のフローの詳細を取得します。

```bash
adapty flows get --app <app-id> <flow-id>
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | Yes | アプリ ID（UUID） |

レスポンスには `id`、`name`、`status`、`updated_at` が含まれます。ステータスは次のいずれかです：

| ステータス | 意味 |
|---|---|
| `draft` | フローが一度も公開されていない |
| `published` | 現在のバージョンが公開中 |
| `dirty` | フローは以前に公開されており、現在のバージョンに未公開の変更がある。ユーザーには最後に公開されたバージョンが表示され続ける |
| `publishing` | 公開処理中 |
| `publication_failed` | 最後の公開が失敗した。設定を修正して再度公開してください |
| `archived` | フローがアーカイブされている |

## adapty flows create \{#adapty-flows-create\}

フローを作成します。新しいフローには名前があり、設定はありません。設定を追加するには、[`flows config update`](#adapty-flows-config-update) を使用してください。

```bash
adapty flows create --app <app-id> --name "Onboarding"
```

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | Yes | アプリ ID（UUID） |
| `--name` | Yes | フロー名 |

## adapty flows update

フローの名前を変更します。

```bash
adapty flows update --app <app-id> <flow-id> --name "Onboarding v2"
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | Yes | アプリ ID（UUID） |
| `--name` | Yes | 新しいフロー名 |

## adapty flows publish \{#adapty-flows-publish\}

フローの現在のバージョンをユーザーに公開します。

```bash
adapty flows publish --app <app-id> <flow-id>
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリ ID（UUID） |
| `--yes`, `-y` | いいえ | 確認なしで公開します。出力がパイプされている場合や `--json` を使用する場合に必要です |

変更を公開するとユーザーが見る内容が変わるため、このコマンドはフロー名を表示して確認を求めます。`y` 以外の回答を入力した場合、コマンドは終了コード 1 でキャンセルされます。`--json` オプションを指定した場合、またはパイプ経由で実行した場合は、回答を待たずに終了コード 2 で拒否されます。スクリプトやエージェントセッションでは `--yes` を渡してください。

公開は非同期で行われます。レスポンスには `status: publishing` が返され、フローはまだライブ状態ではありません。[`flows get`](#adapty-flows-get) をポーリングして、ステータスが `published` または `publication_failed` になるまで待ちます。`publication_failed` の場合、[`flows config get`](#adapty-flows-config-get) で原因を確認できます。

フローにコンフィグがない場合、コンフィグが公開可能な状態でない場合、または現在のバージョンがすでにライブの場合は、HTTP 400 で公開が失敗します。公開前にコンフィグを確認するには、[`flows config validate`](#adapty-flows-config-validate) を使用してください。

## adapty flows config get

フローのビルダー設定を読み取ります。

```bash
adapty flows config get --app <app-id> <flow-id>
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリ ID（UUID） |

レスポンスには `config`、`remote_configs`、`status`、`updated_at` が含まれます。`updated_at` は最後にコンフィグが変更されたときのミリ秒タイムスタンプです。同時編集による上書きを防ぐために、これを [`flows config update`](#adapty-flows-config-update) の `--expected-updated-at` として渡してください。コンフィグが一度も書き込まれていないフローは 404 を返します。

パブリッシュを試みた後、レスポンスにはその結果を示す 3 つのフィールドも含まれます。[`flows get`](#adapty-flows-get) が `publication_failed` を返した場合はこれらを確認してください：

| フィールド | 説明 |
|---|---|
| `publication_status` | このフローバージョンの公開がどの段階まで進んだか: `transforming`、`transformed`、`uploading`、`uploaded`、`published`、または `failed` |
| `transform_error` | 変換失敗の生データ — 問題を列挙した JSON ペイロード、またはサマリー文字列 |
| `publication_error` | 公開失敗時の読みやすいエラーメッセージ |

## adapty flows config update

フローのビルダー設定を書き込みます。

```bash
adapty flows config update --app <app-id> <flow-id> --config-file config.json
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリ ID（UUID） |
| `--config` | どちらか一方 | JSON 文字列としてのビルダー設定 |
| `--config-file` | どちらか一方 | ビルダー設定が記載された JSON ファイルへのパス。`-` を指定すると標準入力から読み込む |
| `--remote-configs` | いいえ | `{locale, data}` エントリの JSON 配列。`data` は文字列としてのリモートコンフィグ |
| `--expected-updated-at` | いいえ | 事前に `flows config get` を実行して取得した `updated_at` の値。その読み取り後に設定が変更されていた場合、上書きせずにコマンドが失敗する。無条件で上書きする場合は省略する |

コンフィグを書き込んでも下書きとして保存されるだけで、公開はされません。公開済みフローに対して書き込みを行うと、新しいバージョンが作成され、フローのステータスが `dirty` になります。[`flows publish`](#adapty-flows-publish) を実行するまで、ユーザーには公開済みバージョンが表示され続けます。

## adapty flows config validate

ビルダーコンフィグを保存せずに、公開可能かどうかを確認します。

```bash
adapty flows config validate --app <app-id> <flow-id> --config-file config.json
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリ ID（UUID） |
| `--config` | どちらか一方 | JSON 文字列としてのビルダーコンフィグ |
| `--config-file` | どちらか一方 | ビルダーコンフィグが記載された JSON ファイルへのパス、または標準入力から読み込む場合は `-` |

レスポンスには `valid` と `issues` のリストが含まれます。設定が公開できない状態の場合、コマンドはコード 1 で終了するため、スクリプトでゲート処理を行えます。

## adapty flows config preview

ローカルの設定ファイルをブラウザでレンダリングします。このコマンドはAPIコールを行わず、`--app` フラグも使用しません。

```bash
adapty flows config preview ./config.json --screen <screen-id> --device iphone-14 --orientation portrait
```

| 引数 | 説明 |
|---|---|
| `config-file` | ローカルのビルダー設定JSONファイルへのパス |

| フラグ | デフォルト | 説明 |
|---|---|---|
| `--screen` | フローの最初の画面 | レンダリングする画面ID |
| `--device` | `iphone-14` | レンダリングに使用するデバイスフレーム |
| `--orientation` | `portrait` | `portrait` または `landscape` |

ターミナルでこのコマンドを実行すると、ブラウザでプレビューが開きます。パイプや `--json` オプションを使うと、代わりに URL が出力されます。URL にはコンフィグ全体が含まれるため非常に長くなります。表示するのではなく、スクリーンショットツールにパイプして使用してください。コンフィグが約 32 KB を超えると、レンダリングが遅くなります。

## adapty flows media upload

フローコンフィグで使用する画像をアップロードします。

```bash
adapty flows media upload --app <app-id> ./hero.png
```

| 引数 | 説明 |
|---|---|
| `file` | 画像ファイルのパス |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | Yes | アプリ ID（UUID） |

対応フォーマット：GIF、HEIC、JPEG、PNG、SVG、WebP。レスポンスには画像の `id`、`name`、およびコンフィグから参照するための CDN `url` が含まれます。

## adapty flows metrics list

複数のフローのライフタイム指標を表示します（フローごとに1行）。これはダッシュボードのフローテーブルのデータです。

```bash
adapty flows metrics list --app <app-id> --ids <flow-id>,<flow-id>
```

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリID（UUID） |
| `--ids` | はい | フローID（UUID）。カンマ区切りで指定するか、フラグを繰り返し使用します |
| `--csv` | いいえ | CSVで出力します：フローIDと27個すべての指標を含む行をフローごとに1行出力します。`--json` と同時には使用できません |

各行には、フローIDとそのビュー数、購入数、トライアル数、収益が表示されます。`--json` と `--csv` では、`unique_profiles_views`、`net_revenue`、`conversion_rate_purchases` など、[フロー指標](flow-metrics#metrics-definitions) ページの27個すべての指標が取得できます。データがない指標は `null` ではなく `0` になります。

## adapty flows metrics values \{#adapty-flows-metrics-values\}

フローのフィルターキーと値の一覧です。[`flows metrics get --filter`](#filter-the-metrics) に渡す値を確認できます。

```bash
adapty flows metrics values --app <app-id> <flow-id>
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フロー ID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | Yes | アプリ ID（UUID） |

各行にはラベルと、括弧内に渡す値が表示されます。値はダッシュボードのフィルターと同じ階層構造になっています：

```text
Country (country)
  Americas (Americas)
    United States (US)
  Europe (Europe)
    Germany (DE)
Store (store)
  App Store (app_store)
  Google Play (play_store)
```

各グループの先頭の値がフィルターキーで、最も内側の値がそのキーに渡す値です。上の例では、`--filter country=US` でアメリカ合衆国を絞り込み、`--filter store=play_store` で Google Play を絞り込みます。

## adapty flows metrics get

指定した期間のフローの指標を、[フロー指標](flow-metrics)ページのツリー形式で表示します。

```bash
adapty flows metrics get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 --date-type purchase_date --based-on placement
```

| 引数 | 説明 |
|---|---|
| `flow-id` | フローID（UUID） |

| フラグ | 必須 | 説明 |
|---|---|---|
| `--app` | はい | アプリID（UUID） |
| `--based-on` | はい | ツリーの第1レベルの分割基準：`placement`または`audience`。[フローの指標](flow-metrics#view-options-for-metrics-data)ページのプレースメントベースおよびオーディエンスベースのビューに対応します |
| `--date-type` | はい | 期間に適用する日付の種類：`purchase_date`または`profile_install_date`（[インストール日でフィルター](flow-metrics#filter-metrics-by-install-date)する場合） |
| `--date-from` | いいえ | 期間の開始日（当日を含む）（`YYYY-MM-DD`）。`--date-to`と合わせて指定してください |
| `--date-to` | いいえ | 期間の終了日（当日を含む）（`YYYY-MM-DD`）。`--date-from`と合わせて指定してください |
| `--granularity` | いいえ | 期間を分割する単位：`day`、`week`、`month`、`quarter`、または`year` |
| `--filter` | いいえ | フィルターキーの値が一致するデータのみを表示します。複数回指定可能。[指標のフィルタリング](#filter-the-metrics)を参照してください |
| `--timezone` | いいえ | 期間ポイントのIANAタイムゾーン（例：`Europe/Berlin`）。指定しない場合、AdaptyはアプリのタイムゾーンをUseします |
| `--depth` | いいえ | `Total`の下に表示するツリーのレベル数。デフォルト：`1` |
| `--csv` | いいえ | CSV形式で出力します：ツリー全体の各ノードを1行で表示。`--json`と同時には使用できません |

`--based-on`、`--date-type` が指定されていない場合、または期間の片方のみが指定されている場合、CLIはリクエストを送信せずにコード2で終了します。Adaptyは `--based-on`、`--date-type`、`--granularity` の値を検証します。値が不正な場合はコード4で終了し、エラーメッセージに受け付け可能な値の一覧が表示されます。

### 出力を読む \{#read-the-output\}

コマンドは `Total` 行を表示した後、その下にツリーの第一レベルを表示します。各行にはビュー数、購入数、トライアル数、収益が表示されます。`--granularity` を指定すると、期間のデータポイントが対応するノードの直下に表示されます。

```text
Total           views 19  purchases 7  trials 4  revenue 241.93
  Onboarding    views 10  purchases 7  trials 0  revenue 241.93
    2026-09-01  views  0  purchases 0  trials 0  revenue   0.00
    2026-10-01  views 10  purchases 0  trials 0  revenue 241.93
  Settings      views  0  purchases 0  trials 0  revenue   0.00
```

ツリーの階層はダッシュボードの階層（プレースメント、オーディエンス、A/B テスト、フローバリアント、スクリーン、プロダクト）に対応しています。`--based-on audience` を指定した場合、プレースメントのレベルは省略されます。より多くの階層を表示するには `--depth` を渡してください。例：`--depth 3`。

27 指標すべてを含むツリー全体を取得するには、以下のいずれかのフラグを使用します：

- `--json` はサーバーのレスポンスをそのまま出力します。
- `--csv` は各ノードを 1 行で出力し、ピリオドのポイントも含まれます。カラムは `path`（`Total` からそのノードまでのタイトルを ` > ` で区切ったもの）、`level`、`title`、そして各指標です。

### 指標のフィルタリング \{#filter-the-metrics\}

`--filter` はそれぞれ `key=value` の形式で記述します。使用できるキーと値は [`flows metrics values`](#adapty-flows-metrics-values) を参照してください。複数の値のいずれかに一致させるには、値をカンマで区切るか、同じキーでフラグを繰り返します。異なるキーのフィルターは組み合わせて使用でき、データはすべての条件に一致する必要があります。

```bash
adapty flows metrics get --app <app-id> <flow-id> --date-from 2026-09-01 --date-to 2026-10-21 \
  --date-type purchase_date --based-on placement --filter country=US,DE --filter store=app_store
```

CLIは各値をそのまま送信します。値の中にカンマを含めるには、`\,` と記述してください。空の値も値として扱われます。`attribution_channel=` はチャンネルなしのデータを保持し、`flows metrics values` では **No Data** として表示されます。
