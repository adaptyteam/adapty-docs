:::important
始める前に、必要なAdapty SDKバージョンがインストールされていることを確認してください：
- **ペイウォールビルダーまたはカスタムペイウォール**: 3.6.1以降（iOS）、3.15以降（AndroidおよびクロスプラットフォームM）
- **フロー＆ペイウォールビルダー**: 4.0以降（全プラットフォーム）
:::

Adaptyを使えば、ユーザーをブラウザへリダイレクトして決済を行うボタンを備えたペイウォールや[フロー](adapty-flow-builder)を作成できます。購入が完了してアプリに戻ると、サブスクリプションが有効になります。
これにより、ストアの手数料を回避しながらユーザーの支払いを追跡できます。

<ZoomImage id="web_paywall.gif" width="700px" alt="Web paywall demo" />

:::tip
App Storeでは、外部決済オプションはアメリカと日本でのみ利用できます。

これらの市場専用のペイウォールを使用するには、現在のペイウォールを複製してWebペイウォールを設定してください。こうすることで、ほぼ同一のペイウォールが2つ使用できます：1つは米国と日本向け、もう1つはその他すべての国向けです。
:::

## 仕組み \{#how-it-works\}

Webペイウォールは、アプリ内ペイウォールごとに生成される固有のURLです。決済のためにブラウザで開き、Stripe、Paddleなどさまざまな決済プロバイダーに対応しています。Apple Payボタンのみのシンプルなページから、追加オファーを含む複雑なフローまでサポートします。

<ZoomImage id="web-paywall-promo.png" width="700px" alt="Webペイウォールの概要" />

ウェブペイウォールは以下の手順で動作します。

1. **ウェブペイウォールページの外観と動作を設定する** — ウェブペイウォールエディターで行います。
2. **ウェブペイウォールをリンクする** — ペイウォールの設定で行います。
3. アプリのペイウォールに、**ユーザーをブラウザへリダイレクトするボタンを追加する**。
4. ユーザーがボタンをタップすると、Adapty SDK がユーザーの Adapty プロファイル ID を含む**一意の URL を生成する**。
5. ユーザーが**ウェブペイウォールページにアクセスし**、外部決済方法を使ってサブスクリプションを**購入する**。
6. アプリに戻ると、Adapty SDK がサブスクリプションの有効化を確認するために**プロファイルの更新をポーリングする**。
7. Adapty が購入を記録し、更新やキャンセルなどのステータス変更についてサブスクリプションを監視する。

プロファイル IDはURL内に含まれており、Web上での購入とアプリユーザーを紐付けます。購入はアプリがすでに使用しているプロファイルに反映されるため、Web購入者に対して `Adapty.identify()` を呼び出す必要はありません。

## ステップ1：Webペイウォールを作成する \{#step-1-create-a-web-paywall\}

1. 操作対象のペイウォールを用意します。
   - 既存のペイウォールに外部決済を追加する場合は、[複製](duplicate-paywalls)してください。これにより、ターゲットセグメントにウェブペイウォールを表示し、それ以外のユーザーには元のペイウォールを表示できます。
   - 最初から作成する場合は、新しいペイウォールを[作成](create-paywall)してください。
2. ペイウォールページで **Web paywall** タブに切り替え、**Create web paywall** をクリックします。新しいページにリダイレクトされます。

<ZoomImage id="web-paywall-1.png" width="700px" alt="Web paywall tab in paywall settings" />

3. ウェブペイウォールを設定し、支払い方法を接続します。

:::tip
外部エディタのセットアップや決済プロバイダーの接続については、[クイックスタートガイド](web-paywall-configuration)を参照してください。
:::

4. **Web paywall** ページに戻り、ペイウォールのリンクを貼り付けます。

:::important
ペイウォールを本番環境にリリースする際は、ウェブペイウォールを公開した後に生成された正しいリンクを使用していることを確認してください。リンクの形式は `paywalls-....fnlfx.com` です。
:::

5. **Save** をクリックします。

<ZoomImage id="web-paywall-4.png" width="700px" alt="Pasting the web paywall link and saving" />

## ステップ2. ペイウォールをトリガーする \{#step-2-trigger-the-paywall\}

Webペイウォールを使用するには、それをトリガーする必要があります。方法はセットアップ内容によって異なります。

- Flow & ペイウォールビルダーを使用している場合は、[新しいボタンを追加する](#step-2a-add-a-web-purchase-button)だけです。このボタンが指定したリンクを使用して購入を追跡し、データをAdaptyに送り返します。
- SDKを使用している場合は、Webペイウォールを処理するために[`openWebPaywall`](#step-2b-call-the-sdk-method)メソッドを設定する必要があります。

### ステップ 2a. ウェブ購入ボタンを追加する \{#step-2a-add-a-web-purchase-button\}

**フロー & ペイウォールビルダー**を使用している場合は、ウェブペイウォールボタンを追加する必要があります。このボタンは、購入を追跡してデータを Adapty に送り返すために指定したリンクを使用します。

1. フローを開き、ボタンを追加します。

   テンプレートまたは既存のペイウォールを使用している場合は、既存の購入ボタンの隣にウェブペイウォールボタンを追加してください。同じ方法で設定できます。

2. 右側の **Interactions** パネルで **Add trigger** をクリックし、このトリガーに **Purchase** アクションを割り当てます。
   <ZoomImage id="on-tap-purchase.webp" width="500px" />
3. アクション設定で **Web payment** タブに切り替えます。そこで、Web購入ボタンに関連付けるプロダクトと（任意で）オファーを選択します。

4. **Web paywall URL** フィールドにWebペイウォールリンクを貼り付けます。

5. デフォルトでは、Webペイウォールはアプリ内ブラウザで開くため、ユーザーがアプリを離れる必要がありません。外部ブラウザで開きたい場合は、**Open in external browser** を選択してください。

<ZoomImage id="web-payment-action.webp" width="500px" />

### ステップ2b：SDKメソッドを呼び出す \{#step-2b-call-the-sdk-method\}

自分で開発したペイウォールを使用している場合は、SDKメソッドを使ってWebペイウォールを処理する必要があります。各フレームワークのガイドを参照してください：

## ステップ3：プレースメントを設定する \{#step-3-set-up-a-placement\}

App Storeは米国と日本のみで外部決済オプションを許可しているため、これらの市場のiOSユーザー向けに別のユーザーセグメントを作成し、異なるセグメントに異なるペイウォールをターゲットするプレースメントを設定します。Androidユーザーには地理的制限がないため、国フィルターなしで別のAndroidセグメントを作成してください。

1. 以下の属性を持つ[新しいセグメントを作成](segments)します：
   - **Country from store account**: United States、Japan
   - **Platform**: iOS and iPadOS
   - **App version**: Adapty SDKを使用している最新バージョン
<ZoomImage id="web-paywall-6.png" width="700px" alt="Segment attributes for web paywall targeting" />
2. プレースメントを[作成](create-placement)するか、既存のものを[編集](edit-placement)します。ウェブペイウォールと作成したセグメントを使って[新しいオーディエンスを追加](add-audience-paywall-ab-test)します。

## キャンセルファネルを追加する \{#add-a-cancellation-funnel\}

キャンセルファネルとは、サブスクリプションをキャンセルしようとしているユーザーが開くウェブページです。キャンセルが完了する前に、一時停止・割引プラン・無料期間などを提案することができます。ウェブペイウォールと同じエディタで作成し、アプリからURLで開く仕組みです。ファネルが決済プロバイダーとのサブスクリプションのキャンセル処理を担うため、アプリ側でキャンセル用のAPI呼び出しを行う必要はありません。

キャンセルファネルを作成するには、ウェブペイウォールエディタで **Cancellation** タブを開きます。リテンションアクションはキャンセルファネルでのみ利用可能なため、ウェブペイウォールを提供するファネルには追加できません。ファネル自体については、[FunnelFox のキャンセルファネルガイド](https://funnelfox.com/docs/dashboard/funnels#cancellation-funnels)を参照してください。

<ZoomImage id="cancellation-funnel.webp" width="700px" alt="ウェブペイウォールエディタのキャンセルタブ" />

### 購読者の FunnelFox プロファイル ID を取得する \{#get-the-subscribers-funnelfox-profile-id\}

キャンセルファネルは、FunnelFox プロファイル ID によって購読者を識別します。ウェブサブスクリプションの購入後、FunnelFox はその ID を `fnlfx_profile_id` カスタム属性として Adapty の[プロファイル](profiles-crm)に書き込みます。また同時に、`fnlfx_funnel_id`、`fnlfx_session_id`、`vendor_profile_id`、`vendor` も書き込まれます。

FunnelFox がこれらの属性を書き込むのは、最初のウェブサブスクリプション購入時のみです。それ以降の購入では、既存の値はそのまま保持されます。消耗型アイテムの購入の場合、FunnelFox はチェックアウト要素にカスタムアクセスレベルが設定されているときのみ、これらの属性を書き込みます。

アプリはユーザーのプロファイル上の `customAttributes` から `fnlfx_profile_id` を読み取ります。Adapty で同じ値を確認するには、**Profiles** を開いてユーザーのプロファイルを検索してください。

:::note
Adapty はプロファイルごとに最大30個のカスタム属性を保存します。プロファイルが上限に達すると、Adapty は余分な属性をエラーなく破棄し、FunnelFox はそれらを再送しません。アプリ独自のカスタム属性を設定している場合は、FunnelFox の5つの属性分のスペースを確保しておいてください。
:::

### アプリからファネルを開く \{#open-the-funnel-from-your-app\}

キャンセルURLはアプリ自身で組み立てます。このURLは **Web paywall URL** フィールドには入力しません。そのフィールドはプロダクトを販売するペイウォール用であり、Adaptyが付加するのは`fpid`ではなく`adapty_profile_id`です。

公開済みのキャンセルファネルURLと、サブスクライバーの`fnlfx_profile_id`を組み合わせてください：

```
https://<your-project>.fnlfx.com/cancel?fpid=<fnlfx_profile_id>
```

属性値はプレフィックスなしで、保存されている値をそのまま渡してください。ユーザーがキャンセルボタンをタップしたときにこのURLを開きます。

ユーザーはファネルのどの時点でも（サブスクリプションのキャンセル後も含め）ページを閉じることができます。ユーザーがアプリに戻ってきたことを確認とみなさないでください。プロファイルを取得して現在の状態を確認しましょう。キャンセルされたサブスクリプションは、有料期間が終了するまでアクセスレベルを維持します。
