Unityで信頼性の高いフローまたはペイウォールの取得には、3つの要素が必要です：素早い描画、オーディエンスターゲティングに基づくバリアントの返却、そしてネットワークが遅い場合のスムーズなフォールバック。以下のルールで、タイミング・キャッシング・フォールバックのパターンについて説明します。

:::tip
このルールは、`Adapty.Activate()` と `Adapty.Identify()` がすでに完了していることを前提としています。詳細は [Unity SDK の呼び出し順序](unity-sdk-call-order) を参照してください。
:::

## ルールと注意点 \{#rules-and-pitfalls\}

| これをやろう | やってはいけないこと | 理由 |
|---|---|---|
| 表示しようとしているプレースメントをフェッチするか、[`PreloadFlows`](#preload-placements)（SDK 4.3.0+）でキャッシュをウォームアップする。 | 起動時に独自の並列 `GetFlow` 呼び出しを一斉に行う。 | 自前のプリフェッチバーストはメインスレッドをブロックし、ブラックスクリーンを引き起こす。`PreloadFlows` はこの用途向けに設計されており、バッチをネイティブ SDK に一度の呼び出しで送信する。 |
| アトリビューションが解決される機会を得てから `GetFlow` をフェッチする。たとえば `Activate` の 1〜2 秒後、または `OnLoadLatestProfile` が発火した後など。 | `Awake()` で `GetFlow` を呼び出す。 | アトリビューションがまだ到達していないため、フローはデフォルトのオーディエンスに対して解決され、セグメントや ASA パーソナライズが暗黙的にバイパスされる。 |
| デフォルトの `loadTimeout`（5秒）をそのまま使うか別の値を設定し、すべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。 | `GetFlow` に非常に大きな `loadTimeout` を渡して実質的に発火しないようにする。 | タイムアウトが発火しない場合、接続状態の悪いユーザーはネットワークが解決するまで空白の画面を見続けることになり、アプリを閉じてしまう可能性がある。 |

カスタムペイウォールとプロダクトの取得については、`fetchPolicy`と`loadTimeout`パラメーターのリファレンスは[カスタムペイウォールとプロダクトの取得](fetch-paywalls-and-products-unity)を、適切なプレースメントの選び方は[プレースメント](placements)を参照してください。

## プレースメントのプリロード \{#preload-placements\}

:::info
`Adapty.PreloadFlows` と `Adapty.PreloadFlowsForDefaultAudience` は SDK バージョン 4.3.0 以降で利用できます。
:::

`Adapty.PreloadFlows` はフローの JSON を事前にキャッシュします。その後は通常どおり使用できます。フローの取得には `GetFlow`、ビューの作成には `CreateFlowView` を使います。

`fetchPolicy` は、後続の `GetFlow` がどのレイヤーを最初に読み取るかを決定するものであり、キャッシュにアクセスできるかどうかを決定するものではありません。

- `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` はキャッシュ済みのコピーを最初に読み込み、キャッシュがない場合のみネットワークにアクセスします。`AdaptyPlacementFetchPolicy.ReturnCacheDataIfNotExpiredElseLoad(maxAge)` は、コピーが `maxAge` より新しい間は同じ動作をします。
- デフォルトの `AdaptyPlacementFetchPolicy.Default` はまずネットワークにアクセスし、リクエストが失敗またはタイムアウトした場合にキャッシュ済みのコピーにフォールバックします。

プリロードはどのポリシーを選択しても有効ですが、効果の出方が異なります。キャッシュファースト（cache-first）ポリシーではリクエスト自体が不要になるのに対し、デフォルトポリシーではリクエストは発生するものの、ウォームコピーがフォールバックとして利用できます。[テストデバイス](test-devices)では、どのポリシーを設定していても `GetFlow` はキャッシュをスキップし、ネットワークリクエストが失敗した場合のみプリロード済みのコピーを使用します。

セッション中に必要なプレースメントがあらかじめわかっているが、すぐには表示したくない場合に活用してください。たとえば、`Activate` と `Identify` が完了した直後に、ユーザーがまだタップしていないボタンの背後にあるフローをプリロードしておく、といった使い方が典型的です。

```csharp showLineNumbers title="C#"
Adapty.PreloadFlows(
    new List<string> { "onboarding", "main_paywall" },
    TimeSpan.FromSeconds(5),
    (error) => {
        if (error != null) {
            // at least one placement failed to preload
        }
    }
);

// Later, when the user reaches the paywall:
Adapty.GetFlow(
    "main_paywall",
    AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad,
    TimeSpan.FromSeconds(5),
    (flow, error) => {
        // create the flow view
    }
);
```

**パラメーター：**

- `placementIds` (必須): プリロードするプレースメント。
- `loadTimeout` (オプション): オーディエンス対象フローのプリロード待機時間。`null` を渡すか、このパラメータを省略したオーバーロードを使用した場合、デフォルトは5秒です。タイムアウトに達すると、SDKはデフォルトオーディエンスのフローを代わりに読み込む場合があります。

**知っておくべき動作:**

- 呼び出しは、すべてのプレースメントが試行された後にのみ失敗します。失敗した場合は、すべての失敗したプレースメントを含む `NetworkFailed` エラーが1つ返されます。1つのプレースメントの失敗が他のプレースメントの処理を止めることはなく、読み込み済みのプレースメントはキャッシュに残ります。
- プリロードは常にネットワークにアクセスします。独自の `fetchPolicy` はありません。
- プリロードはキャッシュを温めるだけです。コンテンツを返すわけではないため、表示するには引き続き `GetFlow` を呼び出す必要があります。
- キャッシュは現在のプロファイルに紐付いています。`Identify` や `Logout` の前にプリロードしたフローは、その後には見つかりません。そのため、プロファイルの切り替え後にプリロードしてください。

### プリロードでカバーされる範囲 \{#what-a-preload-covers\}

フローは段階的に画面へ届きます。プリロードは最初の段階をカバーします。これは `GetFlow` が行う処理と全く同じです。

| レイヤー | 取得元 | プリロードによるウォームアップ |
|---|---|---|
| フロー JSON — 選択されたバリアント、プロダクト ID、リモートコンフィグ | `GetFlow` | あり |
| UI レイアウト — 画面の構造、スタイリング、テキスト | `CreateFlowView` | なし |
| 画像（動画要素の代わりに表示される静止フレームを含む） | `CreateFlowView`（バックグラウンド） | なし |
| プロダクト | `CreateFlowView` または `GetPaywallProducts` | なし |
| 動画ファイル | システムプレイヤー（画面レンダリング時） | SDK によるキャッシュなし |

`CreateFlowView` は、次の順序で 3 つの場所からレイアウトを検索します。

1. ネイティブ SDK のディスクキャッシュ（アプリの再起動後も保持されます）。
2. SDK 4.4 以降を使用している場合、フローを最後に公開した後にダウンロードした[フォールバックファイル](unity-use-fallback-paywalls)。
3. ネットワーク経由の Adapty。これはプリロード後でも往復通信が発生します。アプリがフローの公開済みバージョンを初めて表示するとき、ネイティブ SDK がこのリクエストを行い、その後レイアウトをディスクキャッシュに保存します。

`CreateFlowView`の`LoadTimeout`が発火した場合、ネイティブSDKはフォールバックしません。AdaptyのAPIに対してレイアウトを再リクエストします。`LoadTimeout`はその2回目のリクエストを制限しません。

### オーディエンスのセグメンテーションをスキップする \{#skip-audience-segmentation\}

オーディエンスのセグメンテーションを一切待たずにキャッシュをウォームアップするには、デフォルトオーディエンスのバリアントを使用します。タイムアウトは不要です：

```csharp showLineNumbers title="C#"
Adapty.PreloadFlowsForDefaultAudience(
    new List<string> { "main_paywall" },
    (error) => {
        // handle the error
    }
);
```

その後の `GetFlowForDefaultAudience` は、`GetFlow` が `PreloadFlows` のコピーを読み取るのと同じ方法でコピーを読み取ります。

## アプリバンドルから最初の画面のメディアを表示する \{#show-first-screen-media-from-the-app-bundle\}

フローは画像や動画を Adapty からダウンロードします。最初の画面のメディアを即座に表示するには、アプリバンドルから提供します。これは、既存のネイティブオンボーディングのビジュアルなど、すでに同梱しているメディアを再利用するのに適した方法です。

1. Flow & Paywall Builder で、画像または動画に[カスタムメディア ID](custom-media#custom-media-id) を設定します。そこでアップロードしたファイルはフォールバックとして残ります。
2. ファイルを Unity プロジェクトに追加します。
3. フロービューを作成する際、`SetCustomAssets` を使って該当 ID のバンドルファイルを渡します。

```csharp showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
var bundledAssets = new Dictionary<string, AdaptyCustomAsset>
{
    { "welcome_video", AdaptyCustomAsset.LocalVideoFile("custom_assets/videos/welcome.mp4") }
};

var parameters = new AdaptyUICreateFlowViewParameters()
    .SetCustomAssets(bundledAssets);

AdaptyUI.CreateFlowView(flow, parameters, (view, error) => {
    // handle the result
});
```

バンドルされたファイルはアプリのダウンロードサイズを増加させるため、最初に表示されるメディアのみをバンドルしてください。

バンドルされた画像は待ち時間なしに表示されますが、ネイティブSDKはアップロードされた画像を引き続きバックグラウンドでダウンロードします。

バンドルしていないメディアもすぐに表示されます。フローのレイアウトには、動画のスチルフレームを含む各画像の低解像度コピーが含まれており、フルファイルが読み込まれるまでその画像が表示されます。

`customAssets`の完全なリファレンスについては、[アセットのカスタマイズ](unity-get-pb-paywalls#customize-assets)を参照してください。

## 接続状況が悪い環境向けのチューニング \{#tune-for-poor-connectivity\}

接続状況が常に悪い市場（農村部、交通機関内、ルーティングの影響を受ける地域など）向けの設定：

- `fetchPolicy` を `AdaptyPlacementFetchPolicy.ReturnCacheDataElseLoad` に設定し、初回以外のすべてのフェッチで使用する。
- Adapty ダッシュボードですべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。
- `loadTimeout` をスピードとターゲティングのバランスを考慮して調整する。タイムアウトを短くするとフォールバックが早く表示され、長くするとターゲットされたフローの読み込み時間が増える。
- [フローを軽量に保つ](flow-size)ことで、レイアウトのダウンロードを早める。
- フローの表示を `GetProfile` に依存させない。`GetFlow` を独立して呼び出し、プロファイルの取得が遅くてもUIがブロックされないようにする。
