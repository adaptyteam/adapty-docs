Adapty CLI を使うと、アプリの設定をすべてコマンドラインから行えます。ターミナルツールや [MCP クライアント](https://github.com/adaptyteam/adapty-cli/tree/main/skills/adapty-cli)を好む方は、[ダッシュボードのクイックスタート](integrate-payments)の代わりにお使いください。

:::note
Adapty と App Store Connect・Google Play を連携するには、ダッシュボードでの初回セットアップが必要です — 手順 3 で説明します。
:::

完了すると、アプリ、アクセスレベル、プロダクト、フローまたはペイウォール、プレースメントがすべて [Adapty ダッシュボード](https://app.adapty.io)に表示されます。

Claude Cowork で CLI を実行する場合は、まず Claude でセットアップしてください — [Claude Cowork で Adapty CLI をセットアップする](developer-cli-cowork)を参照してください。

## 1. CLI をインストールする \{#1-install-the-cli\}

[Node.js](https://nodejs.org/en/download) 18 以降が必要です。

CLI をインストールするには、次のコマンドを実行します：

```bash
npm install -g adapty
```

または、直接実行する場合：

```bash
npx adapty auth login
```

## 2. 認証する \{#2-authenticate\}

ログインコマンドを実行して、CLI を Adapty アカウントに接続します。

```bash
adapty auth login
```

CLI がブラウザタブを開きます。ターミナルに表示されたコードとブラウザに表示されたコードが一致していることを確認し、**Authorize** をクリックします。認証が完了するとターミナルに確認メッセージが表示されます。

## 3. アプリを作成する \{#3-create-your-app\}

Adapty のアプリはモバイルアプリケーションを表します。1 つの Adapty アプリが App Store と Google Play の両方に接続されるため、公開するストアの数に関わらず、作成するのは 1 つで十分です。

<Tabs>
  <TabItem value="ios-android" label="iOS + Android">
    ```bash
    adapty apps create --title "My App" --platform ios --platform android --apple-bundle-id com.example.app --google-bundle-id com.example.app
    ```
  </TabItem>
  <TabItem value="ios" label="iOS only">
    ```bash
    adapty apps create --title "My App" --platform ios --apple-bundle-id com.example.app
    ```
  </TabItem>
  <TabItem value="android" label="Android only">
    ```bash
    adapty apps create --title "My App" --platform android --google-bundle-id com.example.app
    ```
  </TabItem>
</Tabs>

このコマンドは `<app-id>` を返します。以降のコマンドではすべてこの ID を使用します。

:::important
次の手順に進む前に、Adapty ダッシュボードでアプリを App Store Connect および Google Play に接続してください。手順 5 では両ストアのプロダクト ID が必要です。

- [App Store Connect を接続する](app-store-connection-configuration)
- [Google Play を接続する](google-play-store-connection-configuration)
:::

## 4. アクセスレベルを作成する（任意） \{#4-create-an-access-level-optional\}

[アクセスレベル](access-level)は、購入後にユーザーがアクセスできる内容を管理します。特定のプロダクトを購入したかどうかを確認する代わりに、アプリはユーザーが特定のアクセスレベルを持っているかどうかを確認します。これにより、アプリのロジックを特定のプロダクト ID から切り離すことができます。

`premium` アクセスレベルは新しいアプリとともに自動的に作成されます。**ほとんどのアプリではこの手順はスキップできます。** 手順 5 ではアクセスレベル ID として `premium` を使用してください。

異なるプロダクトが異なるユーザーグループの異なる機能をアンロックする場合 — たとえば「Basic」サブスクライバーと「Pro」サブスクライバーがアプリの異なる部分にアクセスできる場合 — にのみ、このコマンドを実行してください。

```bash
adapty access-levels create --app <app-id> --sdk-id "pro" --title "Pro"
```

- `--sdk-id` はアプリコード内でユーザーがその機能を利用できるかどうかを確認するために使う識別子です（例：`if user.hasAccessLevel("pro")`）。この手順をスキップしてデフォルトのアクセスレベルを使う場合、その `--sdk-id` は `premium` です。
- `--title` は Adapty ダッシュボードでの参照用に表示されるラベルです。

このコマンドは `<access-level-id>` を返します。

## 5. プロダクトを作成する \{#5-create-a-product\}

Adapty における[プロダクト](product)は、アプリが販売するもの — サブスクリプションや買い切り購入 — を表します。App Store Connect と Google Play のアイテムを 1 つの Adapty プロダクトにまとめて、一元管理できます。

各ストアのプロダクト ID が必要です：App Store Connect の Apple プロダクト ID、および Google Play Console の Android プロダクト ID とベースプラン ID。確認方法の詳細は[プロダクト](quickstart-products)を参照してください。

ステップ4をスキップした場合は、ステップ3の `apps create` コマンドで返された `default_access_level.id` を `<access-level-id>` として使用してください。

:::important
ここでリンクするストアのプロダクトIDは、作成後に変更できません。別のストアプロダクトIDを使用するには、新しいプロダクトを作成してください。
:::

<Tabs>
  <TabItem value="ios-android" label="iOS + Android">
    ```bash
    adapty products create --app <app-id> --title "My Product" --access-level-id <access-level-id> --period monthly --ios-product-id <your.apple.id> --android-product-id <your.google.id> --android-base-plan-id <your.base-plan.id>
    ```
  </TabItem>
  <TabItem value="ios" label="iOS only">
    ```bash
    adapty products create --app <app-id> --title "My Product" --access-level-id <access-level-id> --period monthly --ios-product-id <your.apple.id>
    ```
  </TabItem>
  <TabItem value="android" label="Android only">
    ```bash
    adapty products create --app <app-id> --title "My Product" --access-level-id <access-level-id> --period monthly --android-product-id <your.google.id> --android-base-plan-id <your.base-plan.id>
    ```
  </TabItem>
</Tabs>

コマンドは `<product-id>` を返します。

このプロダクトをStripeまたはPaddleを通じてウェブでも販売する場合は、同じコマンドにそれらのIDを追加してください。コマンドリファレンスの [products create](developer-cli-reference#adapty-products-create) を参照してください。

## 6. フローまたはペイウォールを作成する \{#6-create-a-flow-or-paywall\}

すべてのプロダクトは、アプリに表示される前にフローまたはペイウォールに含まれている必要があります。どちらか一方を選んでください。

- **フロー**とは、ノーコードの[フロー＆ペイウォールビルダー](adapty-flow-builder)でデザインし、Adapty SDKがネイティブにレンダリングする1つまたは複数の画面のことです。ペイウォール画面、オンボーディング、クイズなどが含まれます。購入画面のレンダリングをAdaptyに任せたい場合はフローを選択してください。フローにはAdapty SDK 4.0以降が必要です。
- **ペイウォール**とは、デザインが紐付いていないプロダクトの集合です。購入画面を自分のアプリコードでレンダリングし、Adaptyにはプロダクトの配信のみ（オプションで[リモートコンフィグ](customize-paywall-with-remote-config)も）を担当させたい場合はペイウォールを選択してください。

プレースメントは1つのコンテンツタイプを提供するため、ステップ7の前に決定してください。

### 6a. フローを作成する \{#6a-create-a-flow\}

CLIはフローレコードを作成します。フローのスクリーンはビルダーコンフィグ（CLIが生成しないJSONドキュメント）に格納されます。ターミナルからコンフィグを作成するには、CLIを代わりに操作してくれる[flow-generatorスキル](flow-generator-skill)を使用してください。

フローを作成します：

```bash
adapty flows create --app <app-id> --name "Onboarding"
```

コマンドは `<flow-id>` を返します。

スクリーンは[flow-generatorスキル](flow-generator-skill)または[Flow & Paywall Builder](adapty-flow-builder)でビルドします。どちらの方法でも、ユーザーにはまだ表示されない保存済みドラフトが作成されます。

フローを公開します:

```bash
adapty flows publish --app <app-id> <flow-id>
```

コマンドを実行すると確認を求められます。公開はバックグラウンドで行われるため、`adapty flows get --app <app-id> <flow-id>` でステータスが `published` になるまで確認してください。`publication_failed` の場合は、[`flows config get`](developer-cli-reference#adapty-flows-config-get) で原因を確認できます。プレースメントには公開済みのフローのみ設定できます。

### 6b. ペイウォールを作成する \{#6b-create-a-paywall\}

[ペイウォール](paywalls)は、プロダクトを保持するコンテナです。

:::important
ペイウォールがプレースメントに紐付けられると、そのプロダクトは変更できません。別のプロダクトを使用するには、新しいペイウォールを作成し、そのプレースメントが新しいペイウォールを指すように更新してください。
:::

<Tabs>
  <TabItem value="single" label="プロダクト1つ">
    ```bash
    adapty paywalls create --app <app-id> --title "My Paywall" --product-id <product-id>
    ```
  </TabItem>
  <TabItem value="multiple" label="複数のプロダクト">
    ```bash
    adapty paywalls create --app <app-id> --title "My Paywall" --product-id <product-id-1> --product-id <product-id-2>
    ```
  </TabItem>
</Tabs>

コマンドは `<paywall-id>` を返します。

## 7. プレースメントを作成する \{#create-a-placement\}

[プレースメント](placements)とは、アプリ内でフローやペイウォールを表示するポイントのことです。アプリのコードにハードコードするのはプレースメント ID だけです。どのフローやペイウォールをどのユーザーに表示するかは、新しいアプリバージョンをリリースすることなくダッシュボードで管理できます。

`--developer-id` は、Adapty にこのポイントで何を表示するかを問い合わせる際にアプリのコードで参照する文字列です。`"main"`、`"onboarding"`、`"settings"` のように、場所を説明する名前を付けましょう。

<Tabs>
  <TabItem value="flow" label="フロー">
    ```bash
    adapty placements create --app <app-id> --title "Onboarding" --developer-id "onboarding" --audiences '[{"content_type":"flow","segment_ids":[],"flow_id":"<flow-id>","priority":0}]'
    ```
  </TabItem>
  <TabItem value="paywall" label="ペイウォール">
    ```bash
    adapty placements create --app <app-id> --title "Main" --developer-id "main" --audiences '[{"content_type":"paywall","segment_ids":[],"paywall_id":"<paywall-id>","priority":0}]'
    ```
  </TabItem>
</Tabs>

`--audiences` フラグは、どのフローまたはペイウォールをどのユーザーに表示するかを制御します。上記の例では、単一のデフォルトオーディエンスを設定しています。つまり、このプレースメントにアクセスするすべてのユーザーが同じコンテンツを見ます。プレースメントが提供できるコンテンツタイプは1種類のみであるため、すべてのオーディエンスエントリに同じ `content_type` を指定する必要があります。セグメントによるターゲティングについては、コマンドリファレンスの[オーディエンスの形状](developer-cli-reference#audiences-shape)を参照してください。

## 次のステップ \{#whats-next\}

すべてのエンティティが [Adapty ダッシュボード](https://app.adapty.io) に表示されるようになりました。次のステップ：

- フローを後から変更する — [フロージェネレータースキル](flow-generator-skill)に変更内容を伝えるか、[フロー＆ペイウォールビルダー](adapty-flow-builder)でフローを開いてください。
- アプリでペイウォールを表示する — SDK で[ペイウォールとプロダクトを取得](fetch-paywalls-and-products)し、独自のコードで画面を構築してください。
- [Adapty SDK を統合する](quickstart-sdk) — SDK をアプリに追加して、プレースメントを取得・表示できるようにします。
- 異なる[セグメント](segments)のユーザーを異なるフローやペイウォールにルーティングする — コマンドリファレンスの [`placements update`](developer-cli-reference#adapty-placements-update) と [`segments list`](developer-cli-reference#adapty-segments-list) を参照してください。
