Adapty Mail はキャンペーンを共有アドレスではなく独自ドメインから送信するため、送信者のレピュテーションを自分で管理できます。起動するには認証済みドメインが1つあれば十分で、プロジェクトには最大5つまで登録できます。

最小手順でドメインを認証するには、[Adapty Mail を始める](mail-get-started#4-set-up-your-sending-domain)ガイドを参照してください。この記事はセットアップ、認証、ウォームアップ、複数ドメインからの送信を含む完全なリファレンスです。

## 要件と制限 \{#requirements-and-limitations\}

- **ルートドメイン**: ルートドメインを送信してください。トップレベルドメインのサフィックスが必要です（`yourapp.com`）。Adapty Mail はサブドメイン（`app.yourapp.com`）やセカンドレベルサフィックスのドメイン（`yourapp.co.uk`、`yourapp.com.br`）は受け付けません。
- **ASCII のみ**: Punycode および国際化ドメイン名はサポートされていません。
- **有効な NS レコード**: ドメインが解決できる必要があります。Adapty Mail はセットアップ時に DNS ルックアップを行い、有効な NS レコードがないドメインは拒否されます。
- **プロジェクトごとに 1 つのドメイン**: ドメインを複数のプロジェクトで共有することはできません。他のプロジェクト（自分のものか他の人のものかを問わず）がすでに使用している場合、セットアップは失敗します。
- **ブランドに合ったドメイン名**: ドメイン名はアプリと関連性のあるものである必要があります。Yourapp というアプリに対して `yourapp.com` は通過しますが、無関係な `anotherapp.com` は通過しません。Adapty は[ブランド](mail-brand)のアプリ名、説明、タグラインを参照します。ブランドが設定されていないプロジェクトでは、このチェックはスキップされます。
- **良好な評判を持つドメイン**: [Blacklist Master](https://www.blacklistmaster.com/) でスパムブラックリストに登録されていると報告されたドメインは、Adapty Mail に拒否されます。
- **プロジェクトあたり最大 5 つのドメイン**: それぞれが独立して認証とウォームアップを行います。
- **削除は元に戻せません**: 送信は即座に停止し、ドメインの認証進捗、DNS レコード、ウォームアップ用メールボックスが削除されます。ドメインを再追加することは可能ですが、新しいレコードで最初から認証が始まります。なお、1 日あたりの送信数上限のみ引き継がれます。自分の DNS レコードはそのまま残りますので、手動で削除してください。

## 1. ドメインを追加する \{#1-add-the-domain\}

Adapty Mail で **Settings** > **DNS** を開き、**Email domains** セクションに移動します。

1. **Domain** フィールドに、ルートドメインを入力します（例：`yourapp.com`）。
2. **Sending subdomain** フィールドに、メール送信に使用するサブドメインを指定します。空のままにすると `mail` が使用されます。フィールド下のヒントにはホスト名のプレビューが表示されます：*Emails will be sent from mail.yourapp.com*。
3. **Link subdomain** フィールドに、メール内のリンクや画像に使用する*別のサブドメイン*を指定します。空のままにすると `go` が使用されます。こちらもホスト名が表示されます：*Links and images in emails will be served from go.yourapp.com*。
4. **Add domain** をクリックします。Adapty Mail が入力内容を検証し、ドメインをプロジェクトに追加して、そのドメインに必要なすべての DNS レコードをカードで表示します。

<ZoomImage id="mail-email-domains.webp" width="500px" alt="ドメイン、送信サブドメイン、リンクサブドメインのフィールドを含むドメイン追加フォーム" />

5. 必要に応じて、[ドメインを追加する](#multiple-domains)と1日に送信できるメール数を増やせます。

### カスタムサブドメインを使用する \{#use-custom-subdomains\}

送信プレフィックスはすべての受信者が目にする送信元アドレスに表示され、リンクプレフィックスはクリックされるすべてのリンクに含まれます。多くのプロジェクトではデフォルト設定をそのまま使用しますが、独自の値を入力する場合、両フィールドとも同じルールに従います。

- 小文字、数字、ハイフンを使用し、先頭・末尾にハイフンを付けず、63文字以内にしてください。
- `www`、`smtp`、`admin`、`api`、`mx`、`dkim` は予約済みです。
- 不適切なラベルや有名ブランドを模倣するラベル（例：`paypal`）は拒否されます。`news`、`offers`、`hello` のような一般的なマーケティング用語は使用できます。
- 2つのプレフィックスは同じにできません。
- どちらもドメイン追加後は変更できません。別のホストから送信する場合は、ドメインを削除して再追加するか、2つ目のドメインを追加してください。

## 2. DNSレコードを追加する \{#add-the-dns-records\}

カードに表示されているすべてのレコードを、表示どおりにDNSへ追加してください。セット全体を一括で転送するには、**Export** をクリックして **CSV**、**GoDaddy zone file**、**Cloudflare zone file**、または **Route 53 zone file** を選択します。

:::warning
**Cloudflareでは、すべてのCNAMEをDNS onlyに設定する必要があります** — プロキシ設定のレコードはCloudflareのアドレスに解決されるため、認証が完了しません。**Cloudflare zone file** エクスポートを使用すると、この設定が自動的に行われます。
:::

最初の3つのセクションは必須です。レコードが解決されるまでセットアップは完了しません。ルートドメインのDMARCレコードはオプションです。

| セクション | ホスト | 役割 |
| --- | --- | --- |
| **送信インフラ** | 送信サブドメイン | キャンペーンに署名し、バウンスを Adapty Mail にルーティングします |
| **ウォームアップメールボックス** | 送信サブドメイン | [ウォームアップ](#warm-up-and-daily-limits)中に送信者レピュテーションを構築するメールボックスを運用します |
| **メディア & リダイレクト** | リンクサブドメイン | メール内の画像とトラッキングリンクを独自ドメインから配信します |
| **DMARC ポリシー**（任意） | ルートドメイン | 認証に失敗したメールをどう扱うかを受信プロバイダーに伝えます |

ルートドメインにビジネスメール用の SPF レコードや DMARC レコードがすでに設定されている場合でも、そのまま変更不要です — 必要なレコードはすべてサブドメインに設定します。

<Details>
<summary>DNS レコードリファレンス</summary>

**DKIM — CNAME レコード 3 件。** メールが転送中に改ざんされていないことを証明する暗号署名です。

| フィールド | 形式                              |
| ----- | ----------------------------------- |
| Type  | CNAME                               |
| Name  | `{token}._domainkey.mail.yourapp.com` |
| Value | `{token}.dkim.amazonses.com`        |

**MAIL FROM — MX レコード 1 件。** バウンスを処理します。

| フィールド | フォーマット                                             |
| ---------- | -------------------------------------------------------- |
| Type       | MX                                                       |
| Name       | `hello.mail.yourapp.com`                                 |
| Priority   | `10`                                                     |
| Value      | `feedback-smtp.{region}.amazonses.com`                   |

**MAIL FROM — 1 TXT レコード。** Adapty があなたの代わりにメールを送信することを承認します。

| フィールド | フォーマット                                 |
| ---------- | -------------------------------------- |
| Type  | TXT                                    |
| Name  | `hello.mail.yourapp.com`               |
| Value | `"v=spf1 include:amazonses.com ~all"`  |

**DMARC — ルートドメインに 1 つの TXT レコード。** 任意ですが、推奨されます。

| フィールド | フォーマット                |
| ---------- | --------------------- |
| Type  | TXT                   |
| Name  | `_dmarc.yourapp.com`  |
| Value | `v=DMARC1; p=reject`  |

メールウォームアップメールボックスと `go.yourapp.com` レコードは同じ形式に従っており、名前と値はAdapty Mailが使用するメールおよびホスティングプロバイダーによって発行されます。トークン、リージョン、ホスト名、所有権の値はすべてセットアップ時に生成されます。これらはドメインカードまたはエクスポートからコピーしてください。このリファレンスからは絶対にコピーしないでください。

</Details>

## 3. レコードを確認する \{#verify-the-records\}

<ZoomImage id="email-domains.webp" width="700px" alt="Expanded domain card showing DNS record groups and verification progress" />

 DNS の伝播には通常数分かかりますが、まれに最大 48 時間かかる場合があります。レコードの検証は、Adapty Mail が定期的に DNS をポーリングし、レコードが見つかるか 7 日間が経過するまで自動的に行われます。カードの **Check** をクリックするとオンデマンドで確認を実行できます（10 秒のクールダウンあり）。自動チェックが停止した場合は、再起動することもできます。

A レコードは、DNS に存在し、Adapty Mail から提供された値と一致し、プロバイダーによって確認された場合に検証済みとなります。未検証のレコードには、どの条件が満たされていないかを示すチップが表示されます:

| チップ | 意味 |
| --- | --- |
| **Missing** | DNSにレコードが存在しません。カードに表示された内容をそのまま追加してください。 |
| **Wrong value** | レコードは存在しますが、値が異なります。一致するように更新してください。 |
| **Differs from suggested** | ルートドメインにすでに別の値のDMARCレコードがあります。Adapty Mailの提案は必須ではありません。必要な場合のみ置き換えてください。 |
| **Provider check failed** | プロバイダーがレコードを拒否しました。値を確認してから **Check** をクリックしてください。 |
| **Awaiting provider** | DNSにレコードは正しく設定されていますが、プロバイダーがまだ確認していません。**Check** をクリックして更新してください。 |

Adapty Mail は、検証済みレコードの有効性を定期的にチェックする機能を持っていません。**Check** をクリックするか、**Settings** > **DNS** を開いて手動でチェックをトリガーしてください。

メールを送信する予定がある間は、レコードを削除しないでください。DKIM レコードが消えると、Amazon SES はグレース期間の後にメールへの署名を停止し、ドメインを最初から再検証する必要があります。

## 4. 送信者名を設定する \{#set-the-sender-name\}

ドメインが確認されると、そのカードに **Email sender name** フィールドが追加されます。Adapty Mail にはプロジェクト名が自動入力され、送信サブドメインの `hello@` から送信されます。そのため、フィールドのヒントには From 行全体（*Your Company &lt;hello@mail.yourapp.com&gt;*）が表示されます。この名前はドメインごとに設定するもので、2 つのドメインから送信するプロジェクトでは、それぞれ別々に設定する必要があります。

## ウォームアップとデイリー上限 \{#warm-up-and-daily-limits\}

Gmail や Yahoo などのメールプロバイダーに対して、新しいドメインにはまだ実績がありません。そのため、新規ドメインから一度に大量のメールを送信すると、スパムに分類されるリスクがあります。Adapty Mail は、同時並行で動作する2つの方法によって、すべてのドメインを自動的にウォームアップします。どちらも設定は不要です。

- **ウォームアップメールボックス**: DNSが確認されると、Adapty Mailは送信サブドメインにメールボックスを作成し、ウォームアップサービスに引き渡します。このサービスとの間で通常の会話形式のメールをやり取りします。ドメインカードには、メールボックスが現在どのフェーズにあるかが表示されます。[**Warmup mailbox** レコード](#2-add-the-dns-records)が確認されるまで、ウォームアップは開始されません。
- **1日の送信制限**: キャンペーンの送信量は、ウォームアップメールボックスとは別に計測され、20段階のティアで管理されます。この制限により、新しいドメインがスパムとして判定されるような送信量を超えないよう抑制され、送信するにつれて上限が上がっていきます。

### ティアの仕組み \{#how-tiers-work\}

ドメインは**ティア1**（1日100件の送信）からスタートします。既存の1日あたりの上限を超えると、1段階ずつティアが上がります（送信数とスロットリングされた試行数の両方がカウントされます）。上位の上限は翌日から有効になります。

あるティアの初日は、上限が一度にではなく、1日を通じて徐々に解放されます。昇格は送信量のみによって決まり、ティアは上がるだけで自動的に下がることはありません。最上位ティアを超えると、ドメインは1日の上限なしに送信できます。

| 2    | 200         |
| 3    | 300         |
| 4    | 500         |
| 5    | 750         |
| 6    | 1,000       |
| 7    | 1,500       |
| 8    | 2,500       |
| 9    | 3,500       |
| 10   | 5,000       |
| 11   | 7,000       |
| 12   | 9,000       |
| 13   | 12,000      |
| 14   | 15,000      |
| 15   | 19,000      |
| 16   | 24,000      |
| 17   | 30,000      |
| 18   | 37,000      |
| 19   | 46,000      |
| 20   | 57,000      |

### オーディエンスサイズが配信開始に与える影響 \{#impact-on-launch-by-audience-size\}

| オーディエンスサイズ | 配信開始時の効果                         |
| -------------------- | ---------------------------------------- |
| 100人未満            | 1日目にオーディエンス全員に配信される    |
| 100〜2,000人         | 配信が数日間にわたって分散される         |
| 2,000人以上          | 配信が1〜2週間にわたって分散される       |

:::tip
DNS認証が完了したらすぐに最初のキャンペーンを開始しましょう。送信を早く始めるほど、ドメインのティアが早く上がり、1日あたりの最大配信数に早く到達できます。
:::

## 到達性 \{#deliverability\}

**Settings** > **DNS** の各ドメインには、100点満点の**到達性スコア**が表示されます。**Details** をクリックすると全体像を確認できます — セットアップはドメインが設定済みかどうかを示しますが、ここではメールが実際に届いているかどうかを確認できます。

- **到達性スコア**: 以下の3つを組み合わせた総合評価です。
- **バウンス**: 何件の送信がバウンスしたか、およびその割合。2%で警告、5%でクリティカルです。
- **受信トレイ配置**: 受信されたメールが実際にどこに振り分けられるか。
- **送信ティア**: ドメインが[ウォームアップ](#warm-up-and-daily-limits)のどの段階にあるか、および本日の上限。

クレームはバウンスよりもはるかに重視されます。送信数の0.1%は警告レベル、0.5%は重大レベルです。クレームが発生すると、その受信者は即座に[配信停止](mail-suppression#delivery-failed-or-the-recipient-marked-it-as-spam)されます。

## 複数のドメイン \{#multiple-domains\}

ドメインのウォームアップが完了するまで、Adaptyは各ドメインが1日に送信できるメール数を[制限](#warm-up-and-daily-limits)します。そのため、複数のドメインを使用することで、メール送信容量を増やすことができます。

Adaptyがどのドメインからメールを送信するかは、以下のロジックに従って決定されます。

- **1つのキャンペーンにつき受信者ごとに1ドメイン。** キャンペーンの一貫性を保つため、Adapty Mail は同じ受信者へのメール送信に同じメールアドレスを使用します。そのドメインを削除したり、そこからの送信を停止したりすると、次のメールは空き容量のある最新のドメインから送信されます。
- **新しいドメインが優先されます。** 後から追加されたドメインは、古いドメインより優先されます。

すべてのドメインが上限に達している場合、Adapty Mail はメールの送信を遅らせます。受信者側でその後何が起こるかについては、[スロットリング](mail-suppression#throttle-temporary-delays-and-cancellations)をご覧ください。

## 送信の停止と再開 \{#stop-and-resume-sending\}

ドメインを再認証せずに一時停止するには、そのカードの **Stop sending** をクリックします。カードに **Sending off** と表示され、Adapty Mail は送信先を選ぶ際にそのドメインをスキップします。**Resume sending** をクリックすると元に戻ります。

## トラブルシューティング \{#troubleshooting\}

| 問題 | 解決策 |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| "Enter a valid domain (e.g. example.com)" | 入力内容を確認してください：トップレベルサフィックス付きのルートドメイン（`yourapp.com`）、ASCII のみ、先頭・末尾のハイフンは不可。`yourapp.co.uk` のようなセカンドレベルサフィックスは拒否されます。 |
| "Domain does not have valid DNS records" | ルートドメイン自体が解決できる必要があります。再試行する前に NS レコードが有効であることを確認してください。 |
| "Domain is already registered to another project" | 別のドメインを選択するか、登録が誤りだと思われる場合はサポートにお問い合わせください。 |
| "This subdomain cannot be used" | そのラベルは予約済みか、スクリーニングで拒否されました。別のものを選択してください — [カスタムサブドメインの使用](#use-custom-subdomains)を参照。 |
| "This link subdomain cannot be used" | リンクサブドメインは送信サブドメインと同じルールに従い、送信サブドメインと同一にはできません — [カスタムサブドメインの使用](#use-custom-subdomains)を参照。 |
| "Please wait before checking again" | 手動チェックの間隔は 10 秒以上空けてください。自動ポーリングはバックグラウンドで継続されます。 |
| レコードが未検証のまま | 完全に一致しているか確認してください — 末尾のドットなし、正しい CNAME ターゲット、レコードごとに 1 つの値。DNS の伝播には最大 48 時間かかる場合があります。 |
| Cloudflare で CNAME が未検証のまま | レコードが **Proxied** になっています。それぞれを **DNS only** に切り替えてから **Check** をクリックしてください。 |
| ウォームアップが開始されない | ウォームアップ用メールボックスの MX、DKIM、SPF レコードがまだ検証されていません。追加または修正してから **Check** をクリックしてください。 |
| リンクサブドメインのレコードが検証されない | カードにホスト名の下に理由が表示されます。CNAME と TXT レコードを確認してから **Check** をクリックしてください — このホストが有効になるまでドメインの設定は完了しません。 |
| "Cannot delete: some identities are verified" | このドメインは自動ウォームアップ以前にセットアップされており、ダッシュボードから削除できません。サポートにお問い合わせください。 |
| メールがスパムに入る | DMARC レコードが公開されているか確認してください。新しいドメインにはウォームアップ期間が必要です — [ウォームアップと1日あたりの上限](#warm-up-and-daily-limits)を参照してください。 |
| バウンス率が高い | オーディエンスリストに有効なオプトイン済みのアドレスが含まれているか確認してください。[メールが停止する理由](mail-suppression)では、バウンスしたアドレスへの対応について説明しています。 |
| 苦情率が高い | スパム報告を送信数の 0.1% 未満に抑えてください。苦情はバウンスよりもはるかに重大で、受信者は即座に抑制されます。 |
