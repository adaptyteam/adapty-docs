どのメッセージがリテンション向上に貢献し、どのメッセージがユーザーの離脱を招いているかを把握するには、Retention Messagingページでアナリティクスを確認してください。このテーブルでは、配信中の各メッセージが何人のサブスクライバーにリーチしたか、そのうち何人が留まったか、そしてどれだけの収益をもたらしたかが報告されます。

テーブルには日付範囲がなく、すべての指標は各メッセージのライフタイム全体を対象としています。**Sandbox mode** トグルで、テーブルの表示を本番環境とサンドボックスに切り替えられます。

## 各指標の意味 \{#what-each-metric-means\}

| 指標 | 計測内容 |
| --- | --- |
| **Shown** | サブスクリプションキャンセル画面でこのメッセージを表示されたサブスクライバーの回数。同一サブスクライバーが同一日に複数回閲覧しても、カウントは増加しません。 |
| **Retained users** | **Shown** コホートのうち、キャンセルまたはサブスクリプション失効前に次の期間の料金を支払った、またはメッセージで提示された切り替えプロダクトを購入したサブスクライバー。Adapty はプロダクトではなくサブスクリプションの元のトランザクションで照合するため、キャンセルせずに別のプランへ切り替えたサブスクライバーもリテンション済みとしてカウントされます。 |
| **Saved users** | **Shown** コホートのうち、メッセージを見てから24時間以内にキャンセルしなかったサブスクライバー。表示は24時間経過後にのみカウントされます。 |
| **Retention rate** | **Shown** コホートのうち、すでに支払い済み・キャンセル済み・失効済みのサブスクライバーに対する **Retained users** の割合。次回の支払いを待機中のサブスクライバーは除外されます。 |
| **Save rate** | 24時間以上経過したすべての表示に対する **Saved users** の割合。 |
| **Saved revenue** | リテンションされたユーザーがメッセージを見た後にAppleの手数料控除前に支払ったUSD金額。サブスクリプションがキャンセルまたは失効するまでの支払い合計が集計されます。 |

テーブル内のすべての件数はキャンセル試行の回数であり、ユーザー数ではありません。Adapty は、サブスクライバーごと・メッセージごと・1日1回の試行をカウントします。3日間にわたって戻ってきたユーザーは3回カウントされ、各試行にはその後のサブスクライバーの行動に基づく結果が記録されます。

## Adaptyが結果を判定する仕組み \{#how-adapty-decides-the-outcome\}

**Saved users** と **Retained users** はそれぞれ異なる問いに答えます：

- **Saved users**：サブスクライバーが閲覧後24時間以内に自動更新をオフにしなかった場合。Adaptyはビューの1日後に結果を把握します。
- **Retained users**：サブスクライバーがキャンセルや期限切れより前に支払いを完了した場合。Adaptyが結果を把握できるのは次の請求日以降であり、それは1か月後または1年後になることもあります。

サブスクライバーが「リテンション済み」としてカウントされるのは、有料トランザクションが最初に来た場合のみです。以下のケースはリテンション済みとして**カウントされません**：

- サブスクライバーがメッセージのオファーを承諾した後、最初の支払い前にキャンセルした場合。
- サブスクライバーの次の期間が無料の場合（例：無料のプロモーションオファーによるもの）。
- サブスクライバーがキャンセルし、自動更新を再度オンにして支払った場合。キャンセルが先に発生しているため、この試みはチャーンとしてカウントされます。
- サブスクリプションが失効し、サブスクライバーが後で新しいサブスクリプションを購入した場合。
- サブスクライバーがメッセージを確認する前に Apple が支払いを請求した場合。
- Apple が支払いを返金した場合。

**Saved revenue**には、保持された試みの支払いのみが含まれます。後のメッセージで同じサブスクライバーが保持された場合、Adaptyはその支払いを、支払い前にサブスクライバーが最後に見たメッセージに帰属させます。ファミリー共有メンバーからの支払いは**Retained users**に計上されますが、**Saved revenue**には計上されません。

## トラブルシューティング \{#troubleshooting\}

### 数字が合わない \{#the-numbers-dont-add-up\}

Adaptyはキャンセル画面で何が起きているかを把握できません。サブスクリプションのイベントをもとに、ユーザーが実際にキャンセルしたかどうかを判断しています。

- サブスクリプションがキャンセルまたは期限切れになった場合、そのユーザーはチャーンとしてカウントされます。
- サブスクリプションが更新された場合、そのユーザーは継続としてカウントされます。
- キャンセル画面を閉じたものの、キャンセルも更新もしなかったユーザーは、リテンション率に影響しません。

ユーザーがキャンセルした後に戻ってきた場合（例えば、プロモコードをメールで送った場合など）、そのユーザーは**リテンションとしてカウントされません**。

:::note
トライアルのキャンセルもリテンションメッセージングの対象となります。ユーザーがトライアルをキャンセルしなかった場合、そのトライアルは「リテンション済み」とカウントされ、有料サブスクライバーになります。
:::

### 保存されたユーザー数が維持されたユーザー数より多い \{#saved-users-is-higher-than-retained-users\}

**保存されたユーザー**は、24時間にわたって自動更新をオンにし続けたすべてのサブスクライバーをカウントします。**維持されたユーザー**は、次の期間の支払いを完了したサブスクライバーのみをカウントします。次の請求日がまだ来ていない保存済みサブスクライバーは維持されたとは見なされず、引き続きキャンセルすることができます。

### デフォルトメッセージのビュー数がプロモーションメッセージより少ない \{#a-default-message-shows-fewer-views-than-the-promo-message\}

同じプロダクトに、プロモーションメッセージとデフォルトメッセージ（フォールバック）の両方を設定できます。デフォルトメッセージのビュー数は、常にプロモーションメッセージより少なくなります。
