[フロー](adapty-flow-builder)では、**Request permission** アクションを使って、例えばプッシュ通知の目的を説明するオンボーディング画面などで、ユーザーにプッシュ通知の許可を求めることができます。Adapty SDK 自体はシステムの許可ダイアログを表示しません。代わりに、アプリ内の `AdaptyUISystemRequestsHandler` にリクエストを渡します。アプリがダイアログを表示してユーザーの回答を受け取ると、フローが続行されます。

## 始める前に \{#before-you-start\}

以下が必要です。

- **Adapty Kotlin Multiplatform SDK 4.1.0以降**: バージョン4.1.0は`AdaptyUISystemRequestsHandler`を含む最初の安定版リリースです。
- **Request permissionアクションを含むフロー**: フロー＆ペイウォールビルダーで、要素の**On Tap**または**On Screen Appear**トリガーに**Request permission**アクションを追加します。**After response**セクションに、ユーザーが回答した後に実行するアクション（**Navigate Next**など）を追加します。アクションの設定については、[Request permission](onboarding-actions#request-permission)を参照してください。
- **AndroidマニフェストへのPOST_NOTIFICATIONS権限の追加、およびtargetSdk 33以上**: Android 13以降では、権限を宣言してAndroid 13以降をターゲットにしているアプリにのみ通知権限ダイアログが表示されます:

  ```xml title="AndroidManifest.xml"
  <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
  ```

## フローがパーミッションをリクエストする仕組み \{#how-the-flow-requests-a-permission\}

1. フローが **Request permission** アクションに到達します（ユーザーが要素をタップするか、画面が表示されたとき）。
2. Adapty SDK がハンドラー上の `handlePermission` を `AdaptyUIPermission.PUSH` とともに呼び出します。
3. アプリが OS にパーミッションをリクエストし、`AdaptyUIPermissionResult.granted()` または `AdaptyUIPermissionResult.denied()` を返します。
4. フローが **After response** アクションを実行します。どちらの回答に対しても同じアクションが実行されます。

フローはあなたのアプリが応答を返すまで、画面上で待機します。アプリが応答しない場合、フローはそのまま画面に留まります。たとえばユーザーがすでに回答済みの場合など、OSがダイアログを表示しない場合は、ハンドラーがすぐに返り、フローは **After response** アクションをすぐに実行します。これらのアクションで画面が切り替わる場合、ユーザーはパーミッションをリクエストする画面が一瞬表示されるのを見ることになります。

**On Screen Appear** では、ユーザーが **Navigate back** アクションで画面に戻ったとき、フローはリクエストを再送しません。**On Tap** では、タップするたびに新しいリクエストが送信されますが、リクエストが回答待ちの間のタップは除きます。

## ハンドラーの実装 \{#implement-the-handler\}

パーミッションリクエストに応答するには、共通コードに `AdaptyUISystemRequestsHandler` を実装します。すべてのリクエストに対して結果を返してください。アプリがリクエストしないパーミッションには `denied` を返し、プラットフォームコードの例外はキャッチしてください。Adapty SDK は `handlePermission` からの例外をキャッチしません。キャッチされない例外はアプリをクラッシュさせ、フローは応答を受け取れなくなります。

```kotlin showLineNumbers title="commonMain"

class MySystemRequestsHandler : AdaptyUISystemRequestsHandler {
    override suspend fun handlePermission(
        view: AdaptyUIFlowView,
        permission: AdaptyUIPermission,
        customArgs: Map<String, String>?,
    ): AdaptyUIPermissionResult {
        if (permission != AdaptyUIPermission.PUSH) {
            return AdaptyUIPermissionResult.denied()
        }
        return try {
            if (requestPushPermission()) {
                AdaptyUIPermissionResult.granted()
            } else {
                AdaptyUIPermissionResult.denied()
            }
        } catch (e: CancellationException) {
            throw e
        } catch (e: Exception) {
            AdaptyUIPermissionResult.denied(e.message)
        }
    }
}
```

`requestPushPermission` はプラットフォーム固有のコードです。[各プラットフォームでの権限リクエスト](#request-the-permission-on-each-platform)を参照してください。

`handlePermission` が受け取る引数:

- **`view`**: リクエストを送信したフロービュー。
- **`permission`**: フローがリクエストするパーミッション。**Request permission** アクションは `AdaptyUIPermission.PUSH` を送信します。
- **`customArgs`**: リクエストのカスタム引数。**Request permission** アクションでは送信されないため、値は `null` です。

`granted` と `denied` に渡せる `detail` 文字列はオプションです。

アプリに通知を表示する許可が付与されます。プッシュ通知を受け取るには、フロー外で行うのと同様に、APNs や Firebase Cloud Messaging などのプッシュプロバイダーにデバイスを登録してください。

`AdaptyUISystemRequestsHandler` には `handleAppReviewRequest` もあります。デフォルトではネイティブのレビュープロンプトが表示されるため、オーバーライドする必要はありません。

## 各プラットフォームで権限をリクエストする \{#request-the-permission-on-each-platform\}

共通コードではシステムダイアログを表示できないため、`requestPushPermission` は各プラットフォームに `actual` 実装を持つ `expect` 関数です。すでに Kotlin Multiplatform の権限ライブラリを使用している場合は、`handlePermission` からそちらを呼び出してください。

```kotlin title="commonMain"
expect suspend fun requestPushPermission(): Boolean
```

iOS では、`UNUserNotificationCenter` に認証をリクエストします。

```kotlin showLineNumbers title="iosMain"

actual suspend fun requestPushPermission(): Boolean =
    suspendCancellableCoroutine { continuation ->
        UNUserNotificationCenter.currentNotificationCenter().requestAuthorizationWithOptions(
            UNAuthorizationOptionAlert or UNAuthorizationOptionBadge or UNAuthorizationOptionSound,
        ) { granted, _ ->
            continuation.resume(granted)
        }
    }
```

Android では、実行時の権限は Android 13 以降から存在します。それより前のバージョンでは、アプリの通知がオンになっているかどうかを返します。フローが表示されている間はフローのアクティビティがあるため、画面上に表示されているアクティビティから確認してください。この例では、`ResumedActivity` がそれを追跡します。`Application.onCreate` で `registerActivityLifecycleCallbacks(ResumedActivity)` を使用して登録してください。

```kotlin showLineNumbers title="androidMain"

object ResumedActivity : Application.ActivityLifecycleCallbacks {
    var current: ComponentActivity? = null
        private set

    override fun onActivityResumed(activity: Activity) {
        current = activity as? ComponentActivity
    }

    override fun onActivityPaused(activity: Activity) {
        if (current === activity) current = null
    }

    override fun onActivityCreated(activity: Activity, savedInstanceState: Bundle?) {}
    override fun onActivityStarted(activity: Activity) {}
    override fun onActivityStopped(activity: Activity) {}
    override fun onActivitySaveInstanceState(activity: Activity, outState: Bundle) {}
    override fun onActivityDestroyed(activity: Activity) {}
}

actual suspend fun requestPushPermission(): Boolean {
    val activity = ResumedActivity.current ?: return false
    if (Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU) {
        return NotificationManagerCompat.from(activity).areNotificationsEnabled()
    }
    val permission = Manifest.permission.POST_NOTIFICATIONS
    if (ContextCompat.checkSelfPermission(activity, permission) == PackageManager.PERMISSION_GRANTED) {
        return true
    }
    return suspendCancellableCoroutine { continuation ->
        lateinit var launcher: ActivityResultLauncher<String>
        launcher = activity.activityResultRegistry.register(
            "push_permission",
            ActivityResultContracts.RequestPermission(),
        ) { granted ->
            launcher.unregister()
            continuation.resume(granted)
        }
        launcher.launch(permission)
        continuation.invokeOnCancellation { launcher.unregister() }
    }
}
```

## ハンドラーを登録する \{#register-the-handler\}

:::warning
**ハンドラーがないと、フローはパーミッションリクエストの時点で停止します。** アプリにハンドラーが登録されていない場合、Adapty SDK は iOS および Android の両方で、フローに対して応答を返しません。フローはリクエストを送信した画面にとどまり、**After response** のアクションは実行されません。
:::

パーミッションリクエストをハンドラーに送信するには、アプリ起動時に一度だけ `AdaptyUI.setSystemRequestsHandler` を呼び出してください。最初のフローを表示する前に行う必要があります。たとえば、`AdaptyUI.setFlowsEventsObserver` を呼び出している箇所で一緒に呼び出すとよいでしょう。

```kotlin showLineNumbers title="Kotlin"

AdaptyUI.setSystemRequestsHandler(MySystemRequestsHandler())
```

## 権限リクエストをテストする \{#test-the-permission-request\}

iOS では、通知ダイアログはアプリのインストールにつき1回しか表示されません。Android では、ユーザーが通知を許可するか、2回拒否すると表示されなくなります。テスト中にダイアログを再表示するには、デバイスからアプリを削除して再インストールしてください。その後、フローを開いて **Request permission** アクションに進みます。画面が表示されたままダイアログが表示されない場合、フローが応答を受け取れていません。アプリがフローを表示する前にハンドラーを登録しているか確認してください。ダイアログが表示されずにフローが進んでしまう場合は、Android アプリが `POST_NOTIFICATIONS` を宣言しており、Android 13 以降をターゲットにしているか確認してください。
