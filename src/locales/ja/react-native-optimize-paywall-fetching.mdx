React Nativeで信頼性の高いフローまたはペイウォールの取得を実現するには、次の3つが必要です：高速なレンダリング、オーディエンスに基づくバリアントの返却、そしてネットワークが遅い場合のグレースフルなフォールバック。以下のルールでは、これを達成するためのタイミング、キャッシュ、フォールバックパターンを説明します。

:::tip
これらのルールは、`adapty.activate()` と `adapty.identify()` がすでに解決済みであることを前提としています。詳しくは[React Native SDKのコール順序](react-native-sdk-call-order)をご覧ください。
:::

## ルールと注意点 \{#rules-and-pitfalls\}

| こうする | こうしない | 理由 |
|---|---|---|
| 表示しようとしているプレースメントを取得するか、[`preloadFlows`](#preload-placements)（SDK 4.3.0+）でキャッシュをウォームアップする。 | 起動時に独自の並行 `getFlow` 呼び出しを展開する。 | 自前のプリフェッチバーストは JS スレッドをブロックしてブラックスクリーンを引き起こす。`preloadFlows` はこの用途向けに設計されており、バッチをネイティブ SDK に一度の呼び出しで送信する。 |
| アトリビューションが解決される機会を得た後に `getFlow` を取得する — たとえば、`activate` の 1〜2 秒後や `onLatestProfileLoad` が発火した後など。 | ルートコンポーネントのマウント時に `getFlow` を呼び出す。 | アトリビューションがまだ到達していない。フローはデフォルトのオーディエンスに対して解決され、セグメントや ASA パーソナライゼーションが通知なくスキップされる。 |
| デフォルトの `loadTimeoutMs` である 5000 ミリ秒をそのまま使うか別の値を設定し、すべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。 | `loadTimeoutMs` に非常に大きな値を渡して、タイムアウトが発火しないようにする。 | タイムアウトが発火しない場合、接続状態の悪いユーザーはネットワークが解決するまで空白画面を見続けるか、アプリを閉じてしまう。 |

カスタムペイウォールとプロダクトの取得方法については [カスタムペイウォールとプロダクトの取得](fetch-paywalls-and-products-react-native) を、適切なプレースメントの選び方については [プレースメント](placements) をご覧ください。

## プレースメントの事前読み込み \{#preload-placements\}

:::info
`preloadFlows` および `preloadFlowsForDefaultAudience` は SDK バージョン 4.3.0 以降で利用可能です。
:::

`preloadFlows` はフローの JSON をあらかじめキャッシュします（プレースメントごとに1リクエスト）。その後は通常通り、フローの取得には `getFlow`、ビューの作成には `createFlowView` を使用します。

`fetchPolicy` は後続の `getFlow` がどのレイヤーを優先して読み込むかを制御するものであり、キャッシュにアクセスできるかどうかを決めるものではありません：

- `'return_cache_data_else_load'` はプリロード済みのコピーを優先して読み込み、キャッシュに何もない場合のみネットワークにアクセスします。`'return_cache_data_if_not_expired_else_load'` は同じ動作をしつつ、コピーが `maxAgeSeconds` より新しい間はキャッシュを使い続けます。
- デフォルトの `'reload_revalidating_cache_data'` はまずネットワークにアクセスし、リクエストが失敗またはタイムアウトした場合にプリロード済みのコピーにフォールバックします。

プリロードはどちらの場合も効果がありますが、動作の仕方が異なります。キャッシュ優先ポリシーではリクエスト自体をなくし、デフォルトポリシーではリクエストを維持しつつフォールバック用のウォームコピーを確保します。

プレースメントが事前に分かっていて、まだ表示したくない場合（例：`activate` と `identify` が解決した直後、ユーザーがまだタップしていないボタンの背後にあるフローなど）に使用します。

```typescript showLineNumbers
try {
  await adapty.preloadFlows(['onboarding', 'main_paywall'], {
    loadTimeoutMs: 5000,
  });
} catch (error) {
  // at least one placement failed to preload
}

// Later, when the user reaches the paywall:
const flow = await adapty.getFlow('main_paywall', {
  fetchPolicy: 'return_cache_data_else_load',
});
```

**パラメーター：**

- `placementIds` (必須): プリロードするプレースメント。
- `loadTimeoutMs` (任意): タイムアウトをミリ秒で指定します。デフォルトは5000で、1000未満の値は1000に切り上げられます。iOSではタイムアウトはバッチ全体に適用され、Androidでは各プレースメントに適用されます。

**知っておくべき動作:**

- プロミスは全てのプレースメントの試行が完了した後にのみ拒否され、エラーにはプレースメントごとの失敗が集約されます。あるプレースメントの失敗が他のプレースメントの処理を止めることはなく、読み込みに成功したプレースメントはキャッシュに残ります。
- プレースメントがタイムアウトするかネットワークエラーで失敗した場合、SDK はそのプレースメントのデフォルトオーディエンスのバリアントにフォールバックします。その他の失敗はそのまま報告されます。
- プリロードはキャッシュをウォームアップするだけです。コンテンツを返すわけではないため、表示するには引き続き `getFlow` を呼び出す必要があります。

### プリロードがカバーする範囲 \{#what-a-preload-covers\}

フローは画面に複数のレイヤーに分けて表示されます。プリロードは `getFlow` と同様に、最初のレイヤーのみをカバーします。

| レイヤー | 取得元 | プリロードによるウォームアップ |
|---|---|---|
| フロー JSON — 選択されたバリアント、プロダクト ID、リモートコンフィグ | `getFlow` | あり |
| UI レイアウト — 画面の構造、スタイル、テキスト | `createFlowView` | なし |
| 画像（動画要素の代わりに表示される静止フレームを含む） | `createFlowView`（バックグラウンドで処理） | なし |
| 動画ファイル | システムプレーヤー（画面のレンダリング時） | SDK によるキャッシュなし |

`createFlowView` は、以下の順序で3か所からレイアウトを探します。

1. ネイティブ SDKのディスクキャッシュ（アプリの再起動後も保持されます）。
2. SDK 4.4 以降向けの[フォールバックファイル](react-native-use-fallback-paywalls)（フローを最後に公開した後にダウンロードしている場合）。
3. ネットワーク経由での Adapty（プリロード後でもラウンドトリップが発生します。アプリが各公開バージョンのフローを初めて表示する際、ネイティブ SDK がこのリクエストを送信し、その後レイアウトをディスクキャッシュに保存します）。

`createFlowView` の `loadTimeoutMs` がタイムアウトした場合、ネイティブ SDK はフォールバックを行いません。代わりに Adapty API に再度レイアウトをリクエストします。この2回目のリクエストに対して `loadTimeoutMs` は適用されません。

### オーディエンスのセグメンテーションをスキップする \{#skip-audience-segmentation\}

オーディエンスのセグメンテーションを一切待たずにキャッシュをウォームアップするには、デフォルトオーディエンスのバリアントを使用します。タイムアウトは不要です：

```typescript showLineNumbers
await adapty.preloadFlowsForDefaultAudience(['main_paywall']);
```

## アプリバンドルから最初の画面のメディアを表示する \{#show-first-screen-media-from-the-app-bundle\}

フローは画像や動画を Adapty からダウンロードします。最初の画面のメディアを即座に表示するには、アプリバンドルから配信してください。これは、既存のネイティブオンボーディングのビジュアルなど、すでにアプリに同梱しているメディアを再利用する便利な方法です。

1. フローまたはペイウォールビルダーで、画像や動画に[カスタムメディアID](custom-media#custom-media-id)を設定します。そこにアップロードしたファイルはフォールバックとして残ります。
2. ネイティブプロジェクトにファイルを追加します：iOSのアプリバンドルと、Androidの`assets`フォルダです。
3. フロービューを作成する際、`customAssets`でそのIDに対応するバンドル済みファイルを渡します：

```typescript showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
const bundledAssets: Record<string, AdaptyCustomAsset> = {
  'welcome_video': {
    type: 'video',
    fileLocation: {
      ios: { fileName: 'welcome.mp4' },
      android: { relativeAssetPath: 'videos/welcome.mp4' },
    },
  },
};

const view = await createFlowView(flow, { customAssets: bundledAssets });
```

バンドルファイルはアプリのダウンロードサイズを増やすため、ユーザーが最初に目にするメディアのみをバンドルしてください。

バンドルされた画像は待ち時間なしで表示されますが、ネイティブ SDKはアップロードされた画像をバックグラウンドでダウンロードし続けます。

バンドルしていないメディアもすぐに表示されます。フローのレイアウトには各画像の低解像度のコピー（動画のスチルフレームを含む）が含まれており、完全なファイルが読み込まれるまでそれが表示されます。

`customAssets` の完全なリファレンスについては、[アセットのカスタマイズ](react-native-get-pb-paywalls#customize-assets)を参照してください。

## 接続状態が悪い場合の調整 \{#tune-for-poor-connectivity\}

接続状態が常に悪い市場（農村部、交通機関内、ルーティングの問題が生じている地域など）向けに：

- 最初のフェッチ以外では、すべてのフェッチに `fetchPolicy: 'return_cache_data_else_load'` を設定する。
- Adapty ダッシュボードのすべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。
- `loadTimeoutMs` の値は速度とターゲティングのバランスを考慮して決定する。タイムアウトを短くすると、ユーザーに早くフォールバックが表示される。タイムアウトを長くすると、ターゲティングされたフローがロードされる時間が増える。
- [フローを軽量に保つ](flow-size)ことで、レイアウトのダウンロードを高速化する。
- `getProfile()` の完了をフロー表示の条件にしない。`getFlow` を独立して呼び出し、プロファイルの取得が遅くても UI がブロックされないようにする。
