Adapty Mail では、**フロー**がキャンペーンまたは A/B テストをユーザーの特定の**セグメント**に送信します。フローの**目的（purpose）**は、サブスクリプション期限切れや支払い失敗など、カスタマーライフサイクルのどの時点をカバーするかを示します。1 つの目的に対して複数のフローを設定でき、各フローは異なるセグメントに対応し、優先順位順に並びます。また、目的はフローの**トリガー**（フローがユーザーに対して開始されるきっかけ）も定義します。

このガイドでは、フローの作成・並べ替え・編集・削除の方法を説明します。目的、セグメント、優先順位の概要については、[フロー](mail-flows)を参照してください。

:::tip
[Adapty Mail MCPサーバー](mail-mcp)に接続されたAIアシスタントが、フローの作成や並べ替えを代わりに行ってくれます。フローを作成すると送信が開始されるため、承認する前にアシスタントのプランを必ず確認してください。[Adapty Mail スキル](mail-skill)では、保存前にすべての変更内容が表示されます。
:::

## フローを作成する \{#create-a-flow\}

:::important
フローにはドラフトがありません。**Create** をクリックした瞬間から、トリガーに該当するセグメント内のすべてのユーザーへの送信が始まります。事前にキャンペーンを確認し、テストユーザーで[フローをテスト](mail-testing)してください。
:::

1. Adapty Mail で **Flows** に移動します。マーケティングフローの場合は **Marketing** タブを、サービスメッセージの場合は **Transactional** タブを開きます。

   **Double opt-in** を目的とする場合は、代わりに[ダブルオプトイン](mail-double-opt-in)を有効にしてください。この設定でフローが作成され、オフにするとここで作成したものも含めてすべての Double opt-in フローが削除されます。

2. **Create** をクリックします。
3. **New marketing flow** または **New transactional flow** ダイアログで、フローの目的を選択し、**Continue** をクリックします。目的によって、フローの開始条件と送信可能なキャンペーンが決まります。

   <ZoomImage id="mail-flow-purpose-picker.webp" width="400px" alt="The New marketing flow dialog with the five marketing purposes and Never purchased selected" />

4. **New Flow** ページでフィールドを入力します：
   - **Segment**：セグメントを選択するか、全員に配信する場合は **All Users** を選択します。すでにこの目的のフローが存在するセグメントには **(has a flow already)** と表示され、選択できません。そのセグメントへの配信内容を変更するには、[フローの送信内容を変更する](#change-what-a-flow-sends)を参照してください。新しいセグメントを作成するには、リスト下部の **Create segment** をクリックします。これらのリストからセグメント、キャンペーン、A/B テストを作成した場合、Adapty Mail はこのページに入力した内容を保持し、元のページに戻ります。
   - **Content type**：セグメント全員に1つのキャンペーンを送る場合は **Campaign**、テストのキャンペーン間でセグメントを分割する場合は **A/B Test** を選択します。詳しくは [A/B テスト](mail-ab-testing) を参照してください。
   - **Campaign** または **A/B Test**：フローが送信する内容を選択します。リストには、この[キャンペーン目的](mail-create-campaign)に対応するキャンペーン、またはその目的を持つ下書きの A/B テストのみが表示されます。選択したテストは、このフローのセグメントで実行されます。新しいものを作成するには、リスト下部の **Create campaign** または **Create A/B test** をクリックします。

   <ZoomImage id="mail-flow-create.webp" width="600px" alt="「Never purchased」目的、「EU users」セグメント、キャンペーンが選択された「New Flow」ページ" />

5. **Create** をクリックします。

フローは作成した直後に有効になります。トリガーに該当し、セグメントに属するユーザーへのキャンペーン配信が始まります。最初のメールは設定した [**Delay**](mail-flows#email-delivery-timing) の後に届きます。

フローが A/B テストを送信する場合、テストはフローの作成時に開始されます。

新しいフローは、同じ目的を持つ他の番号付きフローの後に配置されます。その前にあるフローがより広いセグメントを持つ場合、そのフローが新しいフローで取得するはずのすべてのユーザーを引き受けてしまい、新しいフローにはユーザーが届きません。これを修正するには、[新しいフローを上に移動](#change-the-order-of-flows)してください。

## フローの順序を変更する \{#change-the-order-of-flows\}

1つのパーパスに複数のフローが存在する場合、Adapty Mail は優先度の順にフローを評価し、ユーザーが属するセグメントを持つ最初のフローを開始します。**Flows** ページの **Priority** 列に順序が表示されます。

順序を変更するには：

1. **Flows** ページでフローのタブを開き、**Change order** をクリックします。このボタンは、そのタブのパーパスに **All Users** フロー以外のフローが少なくとも2つある場合にアクティブになります。
2. **Purpose** ドロップダウンでパーパスを選択します。
3. フローを必要な順序にドラッグします。
4. **Save** をクリックします。このボタンはフローを移動した後にアクティブになります。

<ZoomImage id="mail-flow-change-order.webp" width="400px" alt="The Change order dialog for the Never purchased purpose, with two numbered flows and the All Users flow last" />

**Priority** 列では、**All Users** を持つフローが **Last** と表示されます。すべてのユーザーがそのセグメントに含まれるため、常に最後になります。

## フローの送信内容を変更する \{#change-what-a-flow-sends\}

1. **Flows** ページでフローを見つけます。その行の **Content** 列にあるキャンペーン名またはテスト名をクリックするか、行メニューを開いて **Edit flow** を選択します。

   <ZoomImage id="mail-flow-row-menu.webp" width="700px" alt="The Flows page with the row menu of a flow open: Edit flow, View in analytics, Finish A/B test, and Delete" />

2. **Content type** と **Campaign** または **A/B Test** を変更します。
3. **Save** をクリックします。**Save** は、フローの送信内容が現在の設定と異なる場合に表示されます。

トリガーを保存した後にトリガーを満たしたユーザーは、新しいキャンペーンまたは A/B テストを受け取ります。すでに以前のシーケンスに入っているユーザーは、引き続きそのメールを受け取ります。フローの行の数字は、新しいコンテンツから再スタートします。以前の数字を確認するには、[Analytics](mail-analytics) を使用してください。

フローがライブ A/B テストを実行している間は、コンテンツがロックされ、**Save** は表示されません。別のものを送信するには、先に[テストを終了](mail-ab-testing#finish-the-test)してください。

## 別のセグメントにフローを送信する \{#send-a-flow-to-another-segment\}

フローの目的やセグメントは変更できません。別のセグメントに送信するには、フローを置き換えてください。

1. 新しいセグメントで[フローを作成](#create-a-flow)する。
2. 古いフローの直前の位置に[移動させる](#change-the-order-of-flows)。
3. 古いフローを[削除する](#delete-a-flow)。

この順番で行うと、ユーザーが途中で別のフローに落ちることはありません。古いフローでライブの A/B テストが実行中の場合、フローを削除するとテストが終了します。

## フローを削除する \{#delete-a-flow\}

1. **Flows** ページで、フローの行メニューを開き、**Delete** を選択します。
2. **Delete flow** ダイアログで、**Delete** をクリックします。

フローを削除すると：

- **その後トリガーに到達したユーザー**：自分が属するセグメント（**All Users** など）の同じ目的の次のフローに入ります。どのフローのセグメントにも属していない場合は、どのフローにも入りません。
- **優先順位**：削除したフローより後ろのフローが1つずつ繰り上がります。
- **すでにフローに入っているユーザー**：残りのスケジュール済みメールを引き続き受信します。
- **実行中の A/B テスト**：フローが A/B テストを実行している場合、Adapty Mail はそのテストを完了させます。
