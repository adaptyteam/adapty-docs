Adapty Mail はMCPサーバーを実行しており、AIアシスタントがあなたのプロジェクト内でダッシュボード上と同じように作業できます。具体的には、キャンペーンの生成とローカライズ、フローの起動、送信ドメインの設定、プロファイルの検索、アナリティクスの閲覧などが可能です。アシスタントはあなた自身のAdapty Mailアカウントでサインインし、ダッシュボードで接続を承認すると権限が付与されます。APIキーは不要です。

| | |
|---|---|
| サーバー URL | `https://api-mail.adapty.io/mcp` |
| プロトコル | MCP over Streamable HTTP、OAuth 2.1 サインイン |
| 対応クライアント | Claude（web・デスクトップ）、ChatGPT、Claude Code、Codex CLI、GitHub Copilot CLI、Gemini CLI、Cursor、Windsurf、および OAuth 対応のリモート MCP サーバーをサポートするすべてのクライアント |

:::tip
コーディングエージェントで最良の結果を得るには、[Adapty Mail スキル](mail-skill)も追加してください。サーバーへの接続を代行し、実際のユーザーにメールを送信する前に確認を取り、配信結果・A/B テスト・未受信の原因分析など、リリース後の作業もサポートします。
:::

## アシスタントでできること \{#what-the-assistant-can-do\}

サーバーのツールはダッシュボードを反映しています：

| エリア | 例 |
|---|---|
| オリエンテーション | 会社とプロジェクトの確認、不足しているセットアップ手順の把握 |
| ブランド | ストアリストからブランドを構築し、内容を確認・編集する |
| 送信ドメイン | ドメインの追加、DNS レコードの取得、確認状況のチェック、ドメインの健全性の確認 |
| 送信先 | メールのリンク先ページを作成・更新する |
| キャンペーン | ブリーフからキャンペーンを生成し、メールの編集・翻訳・テスト送信を行う |
| フローとセグメント | セグメントの作成、フローの開始・変更 |
| A/B テスト | テストの作成・開始・終了 |
| プロファイル | プロファイルとそのジャーニーを検索し、配信停止を行う |
| アナリティクス | キャンペーンの指標の時系列推移、内訳、A/B テストのファネル |
| 設定 | 送信者名、返信先アドレス、ダブルオプトイン、画像アップロード |

ガイド付きワークフローは、対応クライアントでプロンプトとして利用できます。Claude Codeでは `/mcp__adaptymail__campaign_to_flow` のようなスラッシュコマンドとして表示されます。

- **campaign_to_flow**: ブリーフからキャンペーンを生成し、配信先とセグメントを選択して、フローを起動します。
- **campaign_localization**: 保存済みのキャンペーンを他の言語に翻訳します。
- **domain_onboarding**: 送信ドメインを追加し、DNSレコードを公開して確認します。

セットアップの一部はダッシュボードのみで行う手順です：[会社住所](mail-get-started#5-add-your-company-address)の設定、[Webチェックアウト](mail-checkout)の設定、[データ送信の有効化](mail-entry-points)です。

## 始める前に \{#before-you-start\}

- **プロジェクトのメンバーシップ**: Adapty Mail アカウントが、作業対象のプロジェクトのメンバーであること。アシスタントが参照できるのは、あなたのアカウントでアクセス可能な企業とプロジェクトのみです。
- **クライアントのサポート**: クライアントが OAuth 対応のリモート MCP サーバーをサポートしていること。

:::warning
アシスタントはあなたと同じ権限を持ち、その操作はすべて実際に反映されます。フローを保存すると、実際のユーザーへのメール送信が開始されます。サーバーは破壊的なツールにマークを付けており、テストしたアシスタントは実行前に確認を求めます。承認する前に、アシスタントの実行計画をよく確認してください。
:::

## アシスタントを接続する \{#connect-your-assistant\}

### Claude（claude.ai およびクロードデスクトップ）

1. サーバーを追加するには、**Settings → Connectors** を開き、**Add custom connector** をクリックします。
2. 名前（例：`Adapty Mail`）と URL `https://api-mail.adapty.io/mcp` を入力します。
3. **Authentication** は **Sign in now** のままにし、OAuth クライアントは検出されたデフォルトのままにして、**Add** をクリックします。
4. 開いた Adapty Mail タブでログインを求められた場合はログインし、**Approve** をクリックします。

ワークスペース管理者は、組織全体に対して一度だけコネクタを追加できます。各メンバーは初回使用時に自分の Adapty Mail アカウントでサインインします。

### ChatGPT

ChatGPT は **Settings** のコネクターページからカスタム MCP サーバーを追加します。ワークスペースで開発者モードが有効になっている必要があります。

1. サーバーを追加するには、**Create** をクリックします。
2. 名前（例：`Adapty Mail`）とサーバー URL `https://api-mail.adapty.io/mcp` を入力します。**Authentication** は **OAuth** のままにしてください。
3. カスタム MCP サーバーの警告に同意し、**Create** をクリックします。
4. ChatGPT から確認を求められたら、サーバーを接続します。表示された Adapty Mail タブで必要に応じてログインし、**Approve** をクリックします。

### Claude Code

```bash
claude mcp add --transport http --scope user adaptymail https://api-mail.adapty.io/mcp
```

サインインするには、Claude Code で `/mcp` を実行し、`adaptymail` を選択して **Authenticate** をクリックします。その後、ブラウザで Adapty Mail ダッシュボードにログインし、**Approve** をクリックします。

### Codex CLI

```bash
codex mcp add adaptymail --url https://api-mail.adapty.io/mcp
codex mcp login adaptymail
```

ログインコマンドを実行するとブラウザが開き、接続を承認できます。手動でサーバーを設定する場合は、`~/.codex/config.toml` に追加してからログインコマンドを実行してください：

```toml
[mcp_servers.adaptymail]
url = "https://api-mail.adapty.io/mcp"
```

### GitHub Copilot CLI

```bash
copilot mcp add --transport http adaptymail https://api-mail.adapty.io/mcp
```

サーバーへの初回接続時、ブラウザが開いてサインインを求められます。

### Gemini CLI

```bash
gemini mcp add --transport http --scope user adaptymail https://api-mail.adapty.io/mcp
```

新しいセッションを開始し、`/mcp auth adaptymail` を実行してブラウザで接続を承認してください。

### Cursor、Windsurf、その他のクライアント

クライアントの MCP 設定ファイル（例：`~/.cursor/mcp.json`）にサーバーを追加します：

```json
{
  "mcpServers": {
    "adaptymail": {
      "url": "https://api-mail.adapty.io/mcp"
    }
  }
}
```

初回接続時、クライアントがブラウザを開いてサインインを求めます。リモートサーバーへの OAuth に対応していないクライアントは Adapty Mail に接続できません。

## 接続を承認する \{#approve-the-connection\}

クライアントはすべて、Adapty Mail ダッシュボードの同じ画面で終了します。この画面には、アクセスを要求しているアプリケーション名と、そのアクセスを受け取るアドレスが表示されます。デスクトップツールの場合、そのアドレスはご自身のコンピューター上（`localhost`）にあるため、自分で開始した接続のみ承認してください。完了するには、**Approve** をクリックします。

接続リクエストは 10 分後に期限切れになります。画面に **This request has expired** と表示された場合は、クライアントから再度やり直してください。

## 作業を開始する \{#start-working\}

アシスタントにプロジェクトの一覧を表示するよう頼み、作業したいプロジェクトを指定してください。試してみるリクエストの例:

- 「プロジェクトのオンボーディングステータスを表示して、何が不足しているか教えて。」
- 「トライアルが期限切れになったユーザー向けのウィンバックキャンペーンを英語で生成して、最初のメールを見せて。」
- 「キャンペーン「Trial expired」をドイツ語とフランス語に翻訳して。」
- 「`mail.example.com` を送信ドメインとして追加して、DNS レコードを教えて。」
- 「過去30日間のライブキャンペーンの開封率とクリック率を比較して。」

## 切断 \{#disconnect\}

切断するには、クライアントの設定でコネクタを削除します。Claudeの場合は **Settings → Connectors**、ChatGPTの場合はコネクタのページから、Claude Codeの場合は `claude mcp remove adaptymail` を実行してください。

クライアントのアクセストークンは1時間以内に期限切れになります。リフレッシュトークンはクライアントが切断した時点で失効し、未使用の場合は90日後に期限切れになります。再度接続するには、サーバーを追加して接続を承認し直してください。

## トラブルシューティング \{#troubleshooting\}

| 問題 | 解決策 |
|---|---|
| ダッシュボードに接続リクエストが期限切れと表示される | クライアントから接続を再開し、10 分以内に承認してください。 |
| アシスタントにプロジェクトが見つからないと表示される | アカウントがそのプロジェクトのメンバーではありません。会社のオーナーにアクセスを依頼してください。 |
| アシスタントがログアウトされた | 長時間アイドル状態が続いた場合、または切断した後にアクセスが期限切れになります。クライアントから再接続してください。 |
| クライアントにツールが表示されない | クライアントがサインインせずに接続されています。サインインの手順を実行してください（例：Claude Code の `/mcp`）。 |
