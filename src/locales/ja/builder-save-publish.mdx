[フロー＆ペイウォールビルダー](adapty-flow-builder)では、保存と公開が別々に管理されます。ドラフトとして保存すると Adapty ダッシュボード上に作業内容が保持され、公開するとその時点のバージョンが SDK 経由でユーザーに届きます。この記事では、両方の操作とその使い分けについて説明します。

## フローをドラフトとして保存する \{#save-a-flow-as-a-draft\}

:::warning
無効な[リモートコンフィグ](customize-flow-with-remote-config)があると、ドラフトを保存できません。
:::

Flow & Paywall Builder は1分に1回、自動的に進捗を保存します。

手動でドラフトを保存するには、Flow & Paywall Builder の右上にある **Save draft** をクリックするか、**Cmd/Ctrl + S** を押してください。

ドラフトはダッシュボード内でのみ有効です。フローがすでに[プレースメント](placements)に割り当てられている場合でも、アプリ上でユーザーが見る内容には影響しません。

<ZoomImage id="flow-builder-save-draft.webp" width="700px" alt="フローおよびペイウォールビルダーの上部ツールバーにある「下書きを保存」ボタン" />

## フローを公開する \{#publish-a-flow\}

公開すると、フローの現在のバージョンが SDK を通じてユーザーに提供されます。一度公開すると、新しいバージョンが同じフローの以前に公開されたバージョンに置き換わります。

:::note
フローを[プレースメント](placements)に追加するには、まず公開してください。下書き状態のフローは追加できません。
:::

フローを公開するには、Flow & Paywall Builder の右上にある **Publish to Live** をクリックします。

次に何が起こるかは、フローがすでにプレースメントに割り当てられているかどうかによって異なります。

- **フローがすでにプレースメントに設定されている場合**：次のリクエスト時から新しいバージョンが表示されます。
- **フローがプレースメントに設定されていない場合**：[フロープレースメント](create-placement)にフローを追加してユーザーへの表示を開始します。フローには専用のプレースメントが必要で、ペイウォールやオンボーディングに使用中のプレースメントは使えません。

:::tip
フローは、すべてのアクション、スクリーン、プロダクトが完全に設定されると公開できます。そうでない場合は、**Can't publish yet** ダイアログに修正すべき箇所がスクリーンごとにまとめて表示されますが、ドラフトとして保存することは可能です。よくある問題点は[トラブルシューティング](#troubleshooting)を参照してください。
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Publish to Live button in the Flow & Paywall Builder top toolbar" />

:::warning
[カスタムフォント](using-custom-fonts-in-flow-builder)はフローに含まれません — 各フォントファイルをアプリバンドルに追加する必要があります。ファイルがない場合、ユーザーにはシステムのフォールバックが表示されます。

フォントの変更によって古いバージョンが壊れないように公開済みのフローのフォントを変更するには：[フローをコピー](copy-flows)し、コピー内でフォントを変更し、そのフォントを含むアプリバージョンの[オーディエンス](add-audience-paywall-ab-test)にコピーを適用してください。
:::

## フローのステータス \{#flow-status\}

各フローのステータスは、[フロー一覧](filter-flows)に表示されます。ステータスは、フローの保存・公開ライフサイクルにおける現在の状態を表します。

| ステータス | 意味 |
| :----- | :------ |
| **Draft** | フローはまだ一度も公開されていません。ドラフトのみ存在するため、ユーザーにはまだ表示されません。[プレースメント](placements)に追加するには、まずドラフトを公開する必要があります。 |
| **Dirty** | フローは公開済みですが、まだ公開されていない保存済みの編集があります。再度公開するまで、ユーザーには最後に公開したバージョンが表示されます。 |
| **Publishing** | 公開処理が進行中です。 |
| **Failed** | 最後の公開試行が失敗しました。公開済みバージョンがある場合は、引き続きそのバージョンがユーザーに表示されます。 |
| **Published** | 最新の保存済みバージョンが公開中です。未公開の編集はありません。 |
| **Archived** | フローは[アーカイブ](archive-flows#archive-a-flow)されており、[復元](archive-flows#restore-a-flow)するまで編集できません。 |

## トラブルシューティング \{#troubleshooting\}

未完成のアクション、空のスクリーン、欠落または削除されたプロダクトやオファー、無効なリモートコンフィグの JSON は、プレビューと公開のどちらも妨げます。問題の一覧と対処法については、[よくある問題](flow-common-issues#a-flow-wont-preview-or-publish) をご覧ください。

フローを [Adapty アプリ](paywall-device-compatibility-preview) でプレビューして、公開前に問題を確認してください。プレビューでフローの読み込みに失敗した場合は、エラーメッセージで詳細を確認してください。

フローがこれらすべてをクリアしていても、公開しても安全でない場合があります。たとえば、機能しないリストアボタン、利用規約リンクの欠落、未翻訳の画面などです。[flow-audit スキル](flow-audit-skill)はまさにその点を確認し、ターミナルから実行して、リストではなく判定結果として終了します。
