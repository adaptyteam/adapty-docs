[フロー＆ペイウォールビルダー](adapty-flow-builder)では、保存と公開が別々に管理されます。ドラフトとして保存すると Adapty ダッシュボード上に作業内容が保持され、公開するとその時点のバージョンが SDK 経由でユーザーに届きます。この記事では、両方の操作とその使い分けについて説明します。

## フローをドラフトとして保存する \{#save-a-flow-as-a-draft\}

:::warning
無効な[リモートコンフィグ](customize-flow-with-remote-config)があると、ドラフトを保存できません。
:::

Flow & Paywall Builder は1分に1回、自動的に進捗を保存します。

手動でドラフトを保存するには、Flow & Paywall Builder の右上にある **Save draft** をクリックするか、**Cmd/Ctrl + S** を押してください。

ドラフトはダッシュボード内でのみ有効です。フローがすでに[プレースメント](placements)に割り当てられている場合でも、アプリ上でユーザーが見る内容には影響しません。

<ZoomImage id="flow-builder-save-draft.webp" width="700px" alt="フローおよびペイウォールビルダーの上部ツールバーにある「下書きを保存」ボタン" />

## フローを公開する \{#publish-a-flow\}

公開すると、フローの現在のバージョンがSDKを通じてユーザーに提供され、以前に公開したバージョンが置き換えられます。以前のバージョンに戻したい場合は、[復元](flow-version-history#restore-an-earlier-version)してください。

:::note
フローを[プレースメント](placements)に追加するには、先に公開する必要があります。Draft（下書き）状態のフローは追加できません。
:::

フローを公開するには、Flow & Paywall Builderの右上にある **Publish to Live** をクリックしてください。公開後は、フローを編集するまでボタンは無効のままになります。

フローがすでにプレースメントに割り当てられているかどうかによって、次のステップが異なります。

- **フローがすでにプレースメントにある場合**: 次回そのプレースメントへのリクエスト時から、ユーザーに新しいバージョンが表示されます。
- **フローがプレースメントにない場合**: ユーザーへの表示を開始するには、フローを[フロープレースメント](create-placement)に追加してください。フローには専用のプレースメントが必要です。ペイウォールやオンボーディングに使用しているプレースメントには追加できません。

:::tip
フローは、すべてのアクション、スクリーン、プロダクトが完全に設定された時点で公開できます。それまでの間も、下書きとして保存できます。修正が必要な箇所を確認するには、[**Issues** パネルを開いてください](#fix-issues-before-publishing)。よくある問題は[トラブルシューティング](#troubleshooting)を参照してください。
:::

<ZoomImage id="flow-builder-publish-to-live.webp" width="500px" alt="Publish to Live button in the Flow & Paywall Builder top toolbar" />

:::warning
[カスタムフォント](using-custom-fonts-in-flow-builder)はフローに含まれません。各フォントファイルをアプリのバンドルに追加する必要があります。ファイルがない場合、ユーザーにはシステムのフォールバックが表示されます。

公開済みのフローのフォントを古いバージョンを壊さずに変更するには：[フローをコピー](copy-flows)して、コピーでフォントを変更し、そのフォントを含むアプリバージョンを対象とした[オーディエンス](add-audience-paywall-ab-test)にそのコピーを割り当ててください。
:::

## 公開前に問題を修正する \{#fix-issues-before-publishing\}

<ZoomImage id="flow-builder-issues-panel.webp" width="500px" alt="Issues panel with two issues under Blocks publishing, a flow size warning under Won't block publishing, and the flow size at the bottom" />

**Issues** パネルには、フローに関するすべての問題が一覧表示されます。パネルを開くには、トップバーの **Issues** をクリックします。このボタンはフローに問題がある場合にのみ表示されます。ボタンには、公開をブロックする問題の数と警告の数がそれぞれ表示されます。

パネルでは問題が2つのグループに分けられます：

- **公開をブロックする問題**: 設定が完了していないプロダクトやアクションです。たとえば、プロダクトが設定されていないプロダクトカード、削除されたプロダクトやオファー、リンクが設定されていない **Open URL** アクションなどが該当します。このような問題がある状態で **Publish to Live** をクリックすると、ビルダーはフローを公開しません。代わりに **Fix N issues before publishing** というメッセージが表示されます。メッセージから問題パネルを開くには、**Show issues** をクリックしてください。設定が完了していないアクションの場合、ビルダーはそのエレメントの **Interactions** タブを開き、**Complete the selected action before publishing.** というメッセージが表示されます。
- **公開をブロックしない問題**: App Store または Play Store のプロダクト ID が設定されていないプロダクトに関する警告、または[サイズが大きいフロー](flow-size)に関する警告です。ID がない場合、そのプラットフォームではプロダクトの価格が空欄のままになります。サイズが大きいフローは表示が遅くなります。

問題をクリックすると、ビルダーが該当要素を選択し、**Purchase** アクションであれば **Interactions** タブなど、その設定が含まれるタブを開きます。問題のある設定は赤枠で表示されます。

<ZoomImage id="flow-builder-issues-purchase-action.webp" width="400px" alt="Interactions tab with a Purchase action outlined in red and marked with a warning icon" />

削除済み要素を参照している条件など、一部の問題はパネルに表示されません。フローを公開しようとすると、**Can't publish yet** ダイアログにそれらが一覧表示されます。

## フローのステータス \{#flow-status\}

各フローのステータスは、[フロー一覧](filter-flows)に表示されます。ステータスは、フローの保存・公開ライフサイクルにおける現在の状態を表します。

| ステータス | 意味 |
| :----- | :------ |
| **Draft** | フローはまだ一度も公開されていません。ドラフトのみ存在するため、ユーザーにはまだ表示されません。[プレースメント](placements)に追加するには、まずドラフトを公開する必要があります。 |
| **Dirty** | フローは公開済みですが、まだ公開されていない保存済みの編集があります。再度公開するまで、ユーザーには最後に公開したバージョンが表示されます。 |
| **Publishing** | 公開処理が進行中です。 |
| **Failed** | 最後の公開試行が失敗しました。公開済みバージョンがある場合は、引き続きそのバージョンがユーザーに表示されます。 |
| **Published** | 最新の保存済みバージョンが公開中です。未公開の編集はありません。 |
| **Archived** | フローは[アーカイブ](archive-flows#archive-a-flow)されており、[復元](archive-flows#restore-a-flow)するまで編集できません。 |

## トラブルシューティング \{#troubleshooting\}

アクションが未完了の場合、画面が空の場合、プロダクトやオファーが見つからないか削除されている場合、またはリモートコンフィグのJSONが無効な場合は、プレビューも公開もできません。詳細な一覧と対処方法は[よくある問題](flow-common-issues#a-flow-wont-preview-or-publish)をご覧ください。

削除された要素・状態・変数を使用した条件が残っている場合、フローを公開できません。**Can't publish yet** ダイアログには、該当する条件が **Broken references** の下に一覧表示されます。フローを公開するには、各条件で既存の要素・状態・変数を選択するか、その条件を削除してください。

[Adapty アプリ](paywall-device-compatibility-preview)でフローをプレビューして、公開前に問題がないか確認しましょう。プレビューでフローが読み込めない場合は、エラーメッセージで詳細を確認してください。

フローがすべてのチェックをパスしても、安全に公開できるとは限りません。機能しない復元ボタン、リンク切れの利用規約、翻訳されていない画面など、見落としがちな問題があります。[flow-audit スキル](flow-audit-skill)を使えば、ターミナルからこれらをチェックでき、リストではなく最終的な判定を出力します。
