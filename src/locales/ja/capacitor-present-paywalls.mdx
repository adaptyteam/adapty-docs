<SDKv4>

フローまたは旧ペイウォールビルダーで作成したペイウォールがある場合、モバイルアプリのコードでレンダリングしてユーザーに表示する必要はありません。このようなフローには、表示する内容とその表示方法の両方が含まれています。

開始する前に、以下を確認してください：

1. [フロー](paywall-builder-templates)または[ペイウォール](create-paywall)を作成済みであること。
2. それを[プレースメント](placements)に追加済みであること。
3. [フローを取得してビューを準備](capacitor-get-pb-paywalls)済みであること。

   <CapacitorFlowsRequireIos16 />

:::warning

このガイドは、SDK v4.0 以降が必要な **Adapty がレンダリングするフローおよびペイウォール**専用です。カスタムペイウォールの表示方法は異なります。

- カスタムペイウォールを表示するには、[カスタムペイウォールの表示](present-remote-config-paywalls-capacitor)を参照してください。

:::

フローまたはペイウォールをスタンドアロン画面として表示するには、[`createFlowView`](capacitor-get-pb-paywalls#fetch-the-view-configuration) メソッドで作成した `view` に対して `view.present()` メソッドを呼び出します。デフォルトでは、閉じられた `view` は破棄されます。フローを再表示するには、`createFlowView` をもう一度呼び出して新しい `view` インスタンスを作成するか、閉じたフローを[後で再利用するために保持する](#keep-a-closed-flow-for-later)方法を使用してください。

:::warning
破棄された `view` を再利用するとエラーが発生します。
:::

```typescript showLineNumbers

const view = await createFlowView(flow);

// Optional: handle flow events (close, purchase, restore, etc)
// await view.setEventHandlers({ ... });

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

:::important
`setEventHandlers` を複数回呼び出すと、指定したハンドラーが上書きされ、そのイベントに対するデフォルトおよび以前に設定したハンドラーが置き換えられます。
:::

## iOSプレゼンテーションスタイルの設定 \{#configure-ios-presentation-style\}

`present()` メソッドに `iosPresentationStyle` パラメーターを渡すことで、iOS でのフローの表示スタイルを設定できます。このパラメーターには `'full_screen'`（デフォルト）または `'page_sheet'` を指定できます。Android では、フローは常にアプリの Activity 内でフルスクリーン表示されます。

```typescript showLineNumbers
try {
  await view.present({ iosPresentationStyle: 'page_sheet' });
} catch (error) {
  // handle the error
}
```

## フローをクローズ後も保持する \{#keep-a-closed-flow-for-later\}

:::info
`destroy` オプションと `destroy()` メソッドは、SDK バージョン 4.3.0 以降で利用できます。
:::

フローを保持しておくと、ユーザーがすぐに再度開けるようになります。たとえば設定画面のボタンからアクセスするペイウォールなど、再表示時にローディングなしで、離脱した場所から再開できます。

デフォルトでは、`view.dismiss()` はフローを閉じてネイティブビューを破棄するため、`view` を再表示することはできません。同じフローを後で再表示したい場合は、`destroy: false` を渡してください。次の `present()` 呼び出しは、ユーザーが閉じた画面の状態でフローを開き、イベントハンドラーもそのまま保持されます：

```typescript showLineNumbers
// Close the flow and keep its native view in memory
await view.dismiss({ destroy: false });

// Later: open the flow again on the same screen
await view.present();
```

ネイティブビューはリリースするまでメモリに保持されます。フローが不要になったら、`destroy()` を呼び出してください：

```typescript showLineNumbers
await view.dismiss({ destroy: false });
// ...
await view.destroy();
```

`destroy()` はビューがまだ画面に表示されている場合は先にそれを閉じ、イベントハンドラーもクリアします。`destroy: false` で閉じたビューにのみ呼び出してください。通常の `dismiss()` はビューを自動的にリリースするため、その後に `destroy()` を呼び出すと失敗します。

コンポーネントが破棄される際は、保持しているビューを必ず解放してください。Angularの`ngOnDestroy`、Reactの`useEffect`クリーンアップ、またはVueの`onUnmounted`で行います。これを怠るとネイティブビューがセッション中ずっとメモリに残り続けます。エラーも必ずキャッチしてください。たとえばイベントハンドラーが`true`を返した場合など、ビューがすでに解放済みである可能性があります。

```typescript showLineNumbers
// For example, in a React useEffect cleanup
return () => {
  view.destroy().catch(() => {
    // the view was already released
  });
};
```

`true` を返すイベントハンドラーは、通常の `dismiss()` でフローを閉じます。これにより、以前に保持していた場合でもネイティブビューが破棄されます。デフォルトの `onCloseButtonPress` と `onError` ハンドラーは `true` を返します。`onAndroidSystemBack` など、`true` を返すように設定したハンドラーも同様です。ユーザーがフローを閉じたときにフローを保持するには、自分でフローを閉じて `false` を返してください：

```typescript showLineNumbers
await view.setEventHandlers({
  onCloseButtonPress() {
    view.dismiss({ destroy: false }).catch(error => {
      // handle the error
    });
    return false;
  },
});
```

## デベロッパー定義タイマーを使用する \{#use-developer-defined-timer\}

このセクションは、Flow & ペイウォールビルダーで**Developer defined**動作を設定したタイマーを対象としています。ビルダーでは、各タイマーに**Timer ID**が設定されています（[アプリに終了日を設定させる](flow-timer#let-your-app-set-the-end-date)を参照）。アプリ側では、その終了日を設定します。コード内で使用するTimer IDは、ビルダーで設定したものと、大文字・小文字・スペースを含めて1文字も違わず一致させてください。IDが異なると、タイマーはアプリから終了日を受け取れません。

終了日を設定するには、`createFlowView` に `customTimers` パラメータを渡します。これは各タイマー ID を `Date`（タイマーの終了日）にマッピングするオブジェクトです。

```typescript showLineNumbers

const customTimers = {
  CUSTOM_TIMER_NY: new Date(new Date().getFullYear() + 1, 0, 1), // next New Year's Day
};

try {
  const view = await createFlowView(flow, { customTimers });
  await view.present();
} catch (error) {
  // handle the error
}
```

この例では、`CUSTOM_TIMER_NY` はビルダーで**開発者が定義した**タイマーの Timer ID です。このタイマーは、例えば `13d 09h 03m 34s` のように、次の元旦までの残り時間を表示します。

SDKは `customTimers` をビューの作成時に一度だけ読み取るため、「今から6時間後」のように計算した日付はその時点からカウントダウンが始まります。指定した日付が過去の場合、タイマーはすぐにゼロを表示し、**On timer end** トリガーが実行されます。`customTimers` に Timer ID のキーが存在しない場合、タイマーは画面を開いた時点から1時間のカウントダウンを行います。

## ダイアログを表示する \{#show-dialog\}

Android でフロービューが表示されている場合、ネイティブのアラートダイアログの代わりにこのメソッドを使用してください。Android では、通常のアラートがフロービューの後ろに表示されるため、ユーザーには見えません。このメソッドを使用することで、すべてのプラットフォームでフローの上に正しくダイアログが表示されます。

```typescript showLineNumbers
try {
  const action = await view.showDialog({
    title: 'Close paywall?',
    content: 'You will lose access to exclusive offers.',
    primaryActionTitle: 'Stay',
    secondaryActionTitle: 'Close',
  });

  if (action === 'secondary') {
    // User confirmed - close the flow
    await view.dismiss();
  }
  // If primary - do nothing, user stays
} catch (error) {
  // handle error
}
```

## フローにメッセージを送信する \{#send-messages-to-a-flow\}

フロービューの `sendAppMessage` メソッドは、JSON オブジェクトとしてフローにメッセージを送信します。このメソッドは、将来のフロー＆ペイウォールビルダー機能のために予約されています。フローはこれらのメッセージを無視するため、メソッドを呼び出す必要はありません。

## 別のサブスクリプションへの切り替え \{#replace-one-subscription-with-another\}

Android でユーザーが別のサブスクリプションを有効にした状態で新しいサブスクリプションを購入しようとする場合、フロービューを作成する際にサブスクリプション更新パラメータを渡すことで、新しい購入の処理方法を制御できます。現在のサブスクリプションを新しいものに切り替えるには、`createFlowView` の `productPurchaseParams` に `oldSubVendorProductId` と `prorationMode` パラメータを指定してください。

```typescript showLineNumbers

const productPurchaseParams = flow.paywalls
  .flatMap((paywall) => paywall.productIdentifiers)
  .map((productId) => {
    const params: MakePurchaseParamsInput = {};
    if (Capacitor.getPlatform() === 'android') {
      params.android = {
        subscriptionUpdateParams: {
          oldSubVendorProductId: 'PRODUCT_ID_OF_THE_CURRENT_ACTIVE_SUBSCRIPTION',
          prorationMode: 'with_time_proration',
        },
      };
    }
    return { productId, params };
  });

const view = await createFlowView(flow, { productPurchaseParams });
```

<SDKv3>

ペイウォールビルダーを使用してペイウォールをカスタマイズした場合、ユーザーに表示するためにモバイルアプリのコードでレンダリングを行う必要はありません。このようなペイウォールには、表示する内容と表示方法の両方が含まれています。

:::warning
このガイドは、旧ペイウォールビルダーで作成されたペイウォール専用です。カスタムペイウォールを表示するには、[カスタムペイウォールの表示](present-remote-config-paywalls-capacitor)を参照してください。
:::

ペイウォールを表示するには、[`createPaywallView`](capacitor-get-pb-paywalls#fetch-the-view-configuration-of-paywall-designed-using-paywall-builder) メソッドで作成した `view` に対して `view.present()` メソッドを呼び出します。各 `view` は一度しか使用できません。ペイウォールを再度表示する必要がある場合は、`createPaywallView` をもう一度呼び出して新しい `view` インスタンスを作成してください。

:::warning

同じ `view` を再作成せずに再利用すると、エラーが発生する場合があります。
:::

```typescript showLineNumbers

const view = await createPaywallView(paywall);

view.setEventHandlers({
  onUrlPress(url) {
    window.open(url, '_blank');
    return false;
  },
});

try {
  await view.present();
} catch (error) {
  // handle the error
}
```

## 開発者定義タイマーを使用する \{#use-developer-defined-timer\}

モバイルアプリで開発者定義タイマーを使用するには、`timerId`（この例では `CUSTOM_TIMER_NY`）を使用します。これは Adapty ダッシュボードで設定した開発者定義タイマーの **Timer ID** です。これにより、アプリはタイマーを正しい値（例：タイマーの終了時刻（元日など）から現在時刻を引いた `13d 09h 03m 34s`）で動的に更新できます。

```typescript showLineNumbers
const customTimers = { 'CUSTOM_TIMER_NY': new Date(2025, 0, 1) };

const view = await createPaywallView(paywall, { customTimers });
```

この例では、`CUSTOM_TIMER_NY` は Adapty ダッシュボードで設定した開発者定義タイマーの **Timer ID** です。タイマーを使うことで、アプリが正しい値（例: `13d 09h 03m 34s`、元日などのタイマー終了時刻から現在時刻を引いた値）を動的に表示できます。

## ダイアログの表示 \{#show-dialog\}

Android でペイウォールビューが表示されている場合は、ネイティブのアラートダイアログの代わりにこのメソッドを使用してください。Android では、通常のアラートがペイウォールビューの背後に表示されてしまい、ユーザーには見えなくなります。このメソッドを使用することで、すべてのプラットフォームでペイウォールの上に正しくダイアログを表示できます。

```typescript showLineNumbers title="Capacitor"
try {
  const action = await view.showDialog({
    title: 'Close paywall?',
    content: 'You will lose access to exclusive offers.',
    primaryActionTitle: 'Stay',
    secondaryActionTitle: 'Close',
  });

  if (action === 'secondary') {
    // User confirmed - close the paywall
    await view.dismiss();
  }
  // If primary - do nothing, user stays
} catch (error) {
  // handle error
}
```

`present()` メソッドに `iosPresentationStyle` パラメーターを渡すことで、iOSでのペイウォールの表示スタイルを設定できます。このパラメーターには `'full_screen'`（デフォルト）または `'page_sheet'` を指定できます。

```typescript showLineNumbers
await view.present({ iosPresentationStyle: 'page_sheet' });
```
