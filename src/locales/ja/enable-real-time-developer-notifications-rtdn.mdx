Google Playは、リアルタイムデベロッパーNotificationを通じて、更新・キャンセル・返金・支払い問題をAdaptyに報告します。これらのイベントはアプリが閉じている間に発生するため、Adapty SDKでは検知できません。

## 始める前に \{#before-you-start\}

[Google Play ストアの連携を設定する](google-play-store-connection-configuration)必要があります。Adapty はキーファイルからトピック名を生成するため、アップロードが完了するまでコピーするものはありません。

## 通知を有効にする \{#enable-notifications\}

1. Adapty ダッシュボードの [**App settings** > **Android SDK**](https://app.adapty.io/settings/android-sdk) を開き、**Google Play RTDN topic name** の下にあるトピック名をコピーします。これは `projects/` で始まります。

   <ZoomImage id="gp-adapty-topic-name.webp" width="700px" alt="Google Play RTDN topic name section in Adapty App settings, with the generated topic name" />

2. [Google Play Console](https://play.google.com/console/) を開き、アプリを選択して **Monetize with Play** > **Monetization setup** に移動します。

3. **Google Play Billing** セクションで、**Enable real-time notifications** チェックボックスをオンにします。

4. トピック名を **Topic name** に貼り付けます。

5. **Save changes** をクリックします。

   <ZoomImage id="gp-rtdn-monetization-setup.webp" width="700px" alt="Monetization setup page in Google Play Console, showing the Enable real-time notifications checkbox and Topic name field" />

## 接続を確認する \{#verify-the-connection\}

1. **Monetization setup** ページで、**Topic name** フィールドの下にある **Send test notification** ボタンをクリックします。

2. Adapty の [**App settings** > **Android SDK**](https://app.adapty.io/settings/android-sdk) に戻ります。Adapty が通知を受信すると、**Google Play RTDN topic name** セクションのステータスタグが **Active** と表示されます。

   <ZoomImage id="gp-adapty-rtdn-active.webp" width="700px" alt="Google Play RTDN topic name section in Adapty showing the Active status tag" />

## Google のイベントをそのまま転送する \{#forward-raw-google-events\}

Adapty は Google からの通知をデコードして独自のイベントに変換し、プロファイルやプロダクトと紐付け、収益情報も付加します。Google のオリジナルメッセージもそのまま受け取りたい場合は、**App settings** > **Android SDK** の **URL for forwarding raw Google events to your webhook** にエンドポイントを追加してください。

Adapty は、Google から受信したメッセージをそのまま Pub/Sub に投稿します。解析前の状態で、base64 エンコードされており、Google のフィールド名と数値通知タイプを使用し、Adapty プロファイルではなくトークンで購入を識別します。Google は、[RTDN リファレンス](https://developer.android.com/google/play/billing/rtdn-reference)にてフォーマットを説明しています。

## RTDNのトラブルシューティング \{#rtdn-troubleshooting\}

### トピック名が表示されていない \{#the-topic-name-is-missing\}

RTDNの設定はAdaptyからトピック名をコピーするところから始まります。トピック名が表示されていない場合は先に進めません。Play Consoleの**Topic name**は、Google PlayがイベントをどこへSendするかを知るための情報であり、そのトピック名はAdaptyからしか取得できません。

Adapty はキーファイルを保存すると、Cloud プロジェクトにトピックを作成します。有効な名前は `projects/` で始まり、`projects/your-project-id/topics/adapty-prod-3f7a1c2e-9b4d-4e8f-a1b2-c3d4e5f60718` のような形式です。作成に失敗した場合、セクションには名前の代わりに短いメッセージと **Recreate Pub/Sub topic** ボタンが表示され、何が問題だったかを確認できます。

| 表示内容 | 意味 | 対処方法 |
| --- | --- | --- |
| **To set the Google Play RTDN topic name first upload a valid service account key file above.** | このアプリのキーファイルが Adapty に登録されていない | [キーファイルをアップロードする](google-play-store-connection-configuration) |
| **Enable Pub/Sub API** | そのクラウドプロジェクトで Cloud Pub/Sub API が無効になっている | Adapty に表示されるリンクをクリックし、**Recreate Pub/Sub topic** をクリックする |
| **Grant permissions** | サービスアカウントにそのプロジェクトの **Pub/Sub Admin** ロールが付与されていない | [**IAM & Admin** > **IAM**](https://console.cloud.google.com/iam-admin/iam) でサービスアカウントを編集し、**Pub/Sub** > **Pub/Sub Admin** を追加してから **Recreate Pub/Sub topic** をクリックする |

トピックが存在しない間は、Play Consoleに貼り付けるものがないため、Google PlayはイベントをAdaptyに送信せず、更新・キャンセル・返金の情報が記録されません。

**Recreate Pub/Sub topic** は、すでにアップロード済みのキーファイルを使って設定を再実行するため、再度アップロードする必要はありません。

### トピックの再作成に失敗する \{#recreating-the-topic-fails\}

Google Play がトピックへパブリッシュするには権限が必要なため、Adapty は `google-play-developer-notifications@system.gserviceaccount.com` にその権限を付与します。このアカウントは Google に属するものであり、あなたの会社のものではありません。

多くの企業では、自社ドメインのアカウントにのみアクセスを許可するよう Google Cloud を設定しています。このような会社全体のルールは組織ポリシーと呼ばれており、そのうちの 2 つが外部アカウントへの権限付与を拒否するため、トピックが作成されません。

1. [Google Cloud Console](https://console.cloud.google.com/) を開き、キーファイルの元となったプロジェクトを選択します。

2. **IAM & Admin** > **Organization Policies** に移動します。

   <ZoomImage id="google-cloud-IAM-and-Admin.webp" width="700px" alt="IAM and Admin section in the Google Cloud Console navigation" />

3. **Domain restricted contacts** ポリシーを見つけ、その **Actions** メニューを開き、**Edit policy** をクリックします。

   <ZoomImage id="google-cloud-policy-action.webp" width="700px" alt="Organization policies list with the Actions menu open" />

4. **Override parent's policy** を選択し、**Policy enforcement** を **Replace** に設定して、**Add a rule** をクリックします。

   <ZoomImage id="google-cloud-edit-policy.webp" width="700px" alt="Policy editing page with the Override parent's policy option" />

5. **Policy values** で **Allow All** を選択し、**Set policy** をクリックします。

<ZoomImage id="google-cloud-allow-all-policy.webp" width="700px" alt="New rule section with Allow All selected as the policy value" />

6. **Domain restricted sharing** ポリシーに対して同じ手順を繰り返します。

7. Adapty でトピックを再作成します。

:::warning
トピックが作成されたら、両方のポリシーをすぐに **Inherit parent's policy** に戻してください。**Allow All** の状態では、このプロジェクトはGoogleの通知サービスだけでなく、ドメイン外の任意のGoogleアカウントからのアクセス付与や共有を受け入れてしまいます。
:::
