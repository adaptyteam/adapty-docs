[growth-advisor スキル](export-analytics-with-ai)を使えば、毎週アプリの状態を自動チェックできます。収益が通常のレベルかどうか、実行中の A/B テストに結論を出す準備ができているかどうかを確認します。チェックはAIエージェント内のスケジュールタスクとして実行されます。実行のたびに Adapty のデータを読み取り、変化した内容をエージェント内またはチームがすでに確認している場所（Slack チャンネルなど）に報告します。実行によってアカウントに変更が加えられることはなく、報告への返答を行った後に初めて変更が発生します。

:::note
チェックとは、Adapty の設定ではなく、AI エージェントのスケジューラーに登録されたタスクです。エージェントがスケジュールされたタスクを実行できる状態のときのみ動作します。たとえば、コンピューターが起動しているとき、またはエージェントがクラウド実行をサポートしている場合はクラウド上で動作します。
:::

## スケジュール可能なチェック \{#checks-you-can-schedule\}

| チェック | デフォルトのスケジュール | レポートの内容 |
|---|---|---|
| **アプリの健全性** | 毎週月曜日 9:00 | 直近7日間と通常の週との比較：収益、新規有料サブスクリプション、新規トライアル、インストール数、払い戻し、および総合判定。また、結果が出ずに終了したテストなど、[バックログ](autopilot)に残っている項目も一覧表示されます。月次チェックでは、直近28日間とその前の28日間を比較します。 |
| **個別のA/Bテスト** | 毎週月曜日・木曜日 9:00 | テストが **まだ準備中**、**判断可能**、またはチェック設定後にアーム、割合、オーディエンスなど **変更があった** かどうか。各アームについて、約200件の購入までの残り数。リーダーは結果が確定した時点で初めて表示されます。 |
| **すべての実行中のA/Bテスト** | 毎週月曜日 9:00 | 実行中のペイウォールまたはフローのA/Bテストを1テストにつき1ブロックで表示。判断可能なものを優先して表示します。内容には、プレースメント、実行日数、各アームの購入数、リーダーが確定しているかどうかが含まれます。 |

スケジュールはあなたが決めます。デフォルトはスキルが提案する値で、特に指定しない場合に使われます。

A/B テストのチェックはテストの終了とともに完了します。テストが停止され、仮説に結果が出ると、レポートにはチェックの役割が終わったことが示され、削除すべきタスク名が明記されます。

## チェックの設定 \{#set-up-a-check\}

チェックを設定するには、エージェントに次のように依頼します。

```
Check my app every Monday and tell me if something is off.

Tell me when my onboarding A/B test is ready to decide.

Send a weekly report on my running A/B tests to the #growth channel in Slack.
```

このスキルは自律的にチェックを提案することもあります。[ヘルスチェック](export-analytics-with-ai#health-check)の実行後や、実行中の A/B テストに仮説を紐付けた後がその例です。同じアプリに対するチェックがすでに存在し、エージェントがタスク一覧を取得できる場合は、新たなチェックを追加する代わりに既存のチェックを変更するよう提案します。

タスクを作成する前に、スキルは2つのことを確認します：

1. **頻度**：デフォルトのスケジュールをそのまま使うか、独自のスケジュールを指定するか。
2. **レポートの送信先**：デフォルトでは、レポートはエージェントのスケジュール実行が表示される場所（チャットや通知など）に表示されます。別の場所にレポートを送信するには、Slack、メール、Teams、Notion、Linearなど、メッセージの投稿やページへの書き込みができるツールをエージェントのコネクターまたはMCP設定で接続してください。その上で、正確なチャンネル、アドレス、またはページを指定します。スキルが送信先を自動で選ぶことはありません。

スキルはその後、エージェント独自のスケジューリングツールを使ってタスクを作成し、例えば `Adapty: health for Snapshot` や `Adapty: tests for Snapshot` のようにチェック名にちなんだ名前を付けます。

### チェックの実行場所 \{#where-the-check-runs\}

- **あなたのコンピュータ上**: チェックには、あなたのAdaptyログイン情報とこのコンピュータ上のコネクタが使用されます。
- **別のマシンまたはクラウド上**: そこで `ADAPTY_TOKEN` 環境変数に[Adapty CLI トークン](developer-cli-authentication)を設定し、レポートツールも接続してください。スキルはトークンをタスクのプロンプトに含めることはありません。

チェックがAdaptyアカウントに接続できない場合、レポートは1行だけ表示され、そのコンピュータで再度サインインするか、チェックを実行する場所で `ADAPTY_TOKEN` を設定するよう求めます。

### エージェントにスケジューラーがない場合 \{#if-your-agent-has-no-scheduler\}

スキルはチェック用のプロンプトをファイルとして保存し、cron などのシステムスケジューラー用の行を提供します。その行はエージェントを非インタラクティブモードで実行し、レポートを指定したファイルに追記します。Claude Code の場合、行は次のようになります：

```bash
0 9 * * 1 cd ~/my-app && claude -p "$(cat adapty-weekly-health.txt)" --allowedTools "Bash" >> ~/adapty-checks.md
```

他のエージェントにも、`codex exec` や `gemini -p` のような非インタラクティブモードがあります。実行時にシェルコマンドを許可なく実行できる権限が必要ですが、その権限の名称はエージェントによって異なります。詳しくは各エージェントのドキュメントをご確認ください。

## レポートへの対応 \{#act-on-a-report\}

実行は読み取りのみです。新しい仮説の提案や変更は、あなたが回答するまで行われません。エージェントがあなたのために実行できる各アクションは、**次のステップ**に「Annual 2 を維持してテストを停止しますか？」のような、「はい」と答えられる質問として表示されます。あなたのみが実行できるステップは「You:」で始まります。

レポートに対応するには、エージェントで回答してください。スケジュール実行のチャット内、または新しいチャットにレポートを貼り付けて回答します。Slack やメールに投稿されたレポートはそこでは回答できないため、最終行に回答場所が表示されます。

エージェントが回答すると、スキルを使った通常の会話と同様に動作します。レポートが数日前のものである可能性があるため、まずテストとプレースメントを再度読み込みます。テストの停止、仮説の勝ち・負け・判断不能のマーク付け、新しいテストのリンクなど、すべての変更はあなたの確認を待ってから実行されます。

## チェックの変更または停止 \{#change-or-stop-a-check\}

チェックの実行頻度や通知先を変更したい場合は、設定したエージェントに依頼してください。チェックを停止するには、エージェントのスケジューラからそのタスクを削除するか、cron の行を削除してください。
