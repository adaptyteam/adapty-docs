Adapty Mail の A/B テストでは、2 つ以上のメールキャンペーン全体を互いに比較します。各バリアントは独立した完全なキャンペーンです。ユーザーが[フロー](mail-flows)内のテストのセグメントに一致すると、Adapty Mail は設定されたウェイトに基づいてそのユーザーをいずれかのバリアントにルーティングし、バリアントごとの配信状況・エンゲージメント・収益を追跡します。

:::tip
[Adapty Mail MCP サーバー](mail-mcp)に接続された AI アシスタントは、テストの作成、フローへの適用、バリアントごとのファネル確認、勝者を決定してテストの終了を行うことができます。実行前には必ず確認を求めます。
:::

## バリアントとは \{#what-a-variation-is\}

各バリアントは1つの完全なキャンペーンです。バリアント間では、コピー、ヒーロー画像、トーン、メール数、メール間の送信間隔などを変えることができます。各バリアントには独自の[翻訳](mail-localization)があります。公平な比較のために、すべてのバリアントを同じ言語にローカライズしてください。

バリアントは、誰に・いつ送るかを変えることはできません。テスト全体を1つのセグメントがカバーします。テスト内のすべてのキャンペーンは、同じ[目的](mail-create-campaign)を持ちます。これはそのキャンペーンが対象とするライフサイクルの瞬間であり、[フローの目的](mail-flows#purposes)と同じ方法で名前が付けられます。目的によって、テストで使用できるフローが決まります。

各キャンペーンを個別に作成してから、バリアントとして追加します。

## A/B テストを作成する \{#create-an-ab-test\}

1. まず **Campaigns** でキャンペーンを作成します。各バリアントには専用のキャンペーンが必要で、すべて同じ目的を持つ必要があります。
2. Adapty Mail で **A/B Tests** に移動し、**Create** をクリックします。
3. 各キャンペーンをバリアントとして追加し、ウェイトを設定します。ウェイトの合計は **100%** になる必要があります。
4. セグメントを割り当てます。**A/B Tests** ページからテストを起動すると、そのセグメントと目的のフローで実行されます。
5. **Create** をクリックします。

テストは **下書き** として保存され、まだ何も送信されません。開始するには、起動してください。

## テストを開始する \{#launch-the-test\}

テストは1つのフローに対して実行されます。**A/B Tests** ページから起動した場合、テストはそのテストに設定されたセグメントのフローで実行され、フローが存在しない場合はAdapty Mailが自動的に作成します。フローを選択して起動した場合は、テストに保存されたセグメントではなく、そのフローのセグメントで実行されます。

どちらの方法で起動しても、テストのステータスは **draft** から **live** に変わります。それ以降、トリガーに該当し、かつセグメントに含まれるユーザーはバリアントに振り分けられます。最初のメールは設定した[**Delay**](mail-flows#email-delivery-timing)の後に送信されます。

### A/B テストページから \{#from-the-ab-tests-page\}

1. Adapty Mail で **A/B Tests** を開きます。
2. 下書きテストの行メニューを開き、**Launch** を選択します。または、テストを開いて変更を保存してから **Launch** をクリックします。
3. **Launch A/B test** ダイアログの内容を確認し、**Launch** をクリックします。

<ZoomImage id="mail-ab-testing-launch.webp" width="400px" alt="The Launch A/B test dialog, saying that a flow for the Never purchased purpose and the test's segment will be created" />

ダイアログには、フローに対して何が行われるかが表示されます：

- **フローが存在し、キャンペーンを送信している場合**: テストがそのキャンペーンを置き換えます。
- **その目的とセグメントのフローが存在しない場合**: Adapty Mail が他のフローの後に新しいフローを作成します。前のフローのセグメントが広い場合は、[新しいフローを上に移動して](mail-create-flow#change-the-order-of-flows)ください。そうしないと、テストにユーザーが割り当てられません。
- **フローが別の A/B テストを実行している場合**: テストを開始できません。先に別のテストを終了してください。

### フローから \{#from-a-flow\}

1. Adapty Mail で **Flows** に移動します。テストの目的に合わせた[フローを作成する](mail-create-flow#create-a-flow)か、既存のフローを開きます。
2. **Content type** を **A/B Test** に設定します。**A/B Test** フィールドで下書きのテストを選択します。リストにはその目的に対応するすべての下書きテストが表示されます。
3. 新しいフローの場合は **Create** を、既存のフローの場合は **Save** をクリックします。

:::note
テストはこのフローのセグメントで実行されます（フローに保存されたセグメントがそのまま使用されます）。独自のセグメントで実行するには、**A/B Tests** ページからテストを起動してください。
:::

## ルーティングの仕組み \{#how-routing-works\}

ユーザーがフローのトリガーに到達し、フローのセグメントに属している場合、Adapty Mail は**加重ランダム**選択によってバリアントを選びます。各バリアントのウェイトが抽選の比率を決定します。ルーティングはユーザーごとに決定論的ではありません。

## 結果を確認する \{#read-results\}

勝者を選ぶには、Analytics で各バリアントを比較します。**A/B Tests** ページでテストの行メニューを開き、**View in analytics** を選択してください。**Flows** ページのフローの行メニューにも同じ **View in analytics** オプションがあります。Analytics ページが開くと、テスト実施期間中の各バリアントに対応するグループが表示されます。判断を下す前に、すべてのバリアントのユーザーがシーケンス全体を受け取れるだけの時間を確保してください。

**Flows** ページと **A/B Tests** ページには、テストの合計値が表示されます（どのバリアントが優勢かは表示されません）。**Flows** ページでは、フローの行にすべてのバリアントの **Sent** と各レートの合計が表示されます。**A/B Tests** ページでは、各テストが1行で表示され、テスト開始以降のすべてのバリアントの合計値が集計されます。

- **Sent**: Adapty Mail が送信したメール数。
- **Rates**: プロジェクトの最初の3つのレートをレートリストの順番で表示します。変更するには、[レートの変更](mail-analytics#change-the-rates)を参照してください。
- **Revenue**: アトリビューション済み収益。

<ZoomImage id="mail-ab-tests-list.webp" width="700px" alt="1行ごとにテストを表示するA/B テストページ：Sent、開封率、クリック率、コンバージョン率の列、およびRevenue" />

[キャンペーン分析](mail-analytics)では、各指標のカウント方法と収益のアトリビューション方法について説明しています。

## テストを終了する \{#finish-the-test\}

:::warning
**Finish A/B test** ダイアログでは、**Winner** の初期値が **No winner, remove the flow** になっています。このまま変更せずに進むと、Adapty Mail はそのフローを削除します。後続のフローは繰り上がり、そのセグメントに属する新規ユーザーは、同じ目的の次のフローがあればそこに入ります。
:::

1. Adapty Mail で **Flows** を開きます。テストを実行中のフローの行メニューを開き、**Finish A/B test** を選択します。

   以下の場所からも操作できます。
   - **フローの編集ページ**: **Finish A/B test** をクリックします。
   - **A/B Tests ページ**: テストの行メニューで **Finish** を選択します。ライブ中のテスト専用ページにも **Finish** があります。

2. **Finish A/B test** ダイアログの **Winner** で、テスト終了後にフローが送信するキャンペーンを選択します。フローはその順番の位置を維持します。
3. **Finish** をクリックします。

<ZoomImage id="mail-ab-testing-finish.webp" width="400px" alt="The Finish A/B test dialog with a campaign selected in the Winner dropdown" />

:::note
いずれかのバリアントのシーケンス途中にいるユーザー（勝者・敗者を問わず）は、スケジュールされたメールを引き続き受信します。勝者バリアントに切り替えられることはありません。
:::

## ライフサイクル \{#lifecycle\}

A/B テストは4つの状態を経て進みます：

- **Draft**：作成済み、未起動。
- **Live**：フローで起動済み、ユーザーをルーティング中。
- **Finished**：**Finish A/B test** ダイアログから停止、またはフローを削除することで終了。
- **Archived**：下書きまたは終了済みテストの行メニューにある **Delete** で削除済み。実行中のテストは削除できません。先に終了してください。
