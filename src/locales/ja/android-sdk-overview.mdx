ようこそ！アプリ内課金をもっと簡単にするお手伝いをします 🚀

AdaptyのAndroid SDKを使えば、アプリ内課金の面倒な処理はすべておまかせ。あなたは素晴らしいアプリを作ることだけに集中できます。以下をまるごと対応します：

- 購入処理・レシート検証・サブスクリプション管理をすぐに使える状態で提供
- アプリのアップデートなしでフローとペイウォールを作成・テスト
- ゼロ設定で詳細な購買分析を取得 ― コホート、LTV、チャーン、ファネル分析も含む
- アプリセッションやデバイスをまたいでユーザーのサブスクリプションステータスを常に最新に保つ
- たった1行のコードでマーケティングアトリビューションや分析サービスとアプリを連携

:::note
コードに入る前に、AdaptyをGoogle Play Consoleと連携し、ダッシュボードでプロダクトを設定する必要があります。まずは[クイックスタートガイド](quickstart)を確認して、すべての設定を完了させてください。
:::

## 主な概念 \{#main-concepts\}

コードに入る前に、Adapty の仕組みを支える重要な概念を把握しておきましょう。

Adapty のアプローチの優れた点は、プレースメントだけがアプリにハードコードされていることです。それ以外のすべて（プロダクト、ペイウォールのデザイン、価格、オファーなど）は、アプリのアップデートなしに Adapty ダッシュボードから柔軟に管理できます。

1. [**プロダクト**](product) - アプリ内で購入できるもの全般。サブスクリプション、消耗型アイテム、永続アクセスなどが含まれます。

2. **フローとペイウォール** - プロダクトに設定をまとめてプレースメントに紐付けたものです。作成方法は2種類あり、[フローとペイウォール](flows-and-paywalls)で比較しています：
   - **[フロー & ペイウォールビルダー](adapty-flow-builder)** - ビジュアルなノーコードインターフェース。AdaptyがUIをレンダリングし、購入処理も行います。
   - **[カスタムペイウォール](paywalls)** - ビジュアル設定なし。独自のコードでUIを構築し、自分で`makePurchase`を呼び出します。[カスタムペイウォールの実装](android-quickstart-manual)を参照してください。

   SDKコードでは、どちらも同じ`getFlow`メソッドで取得できます。

3. [**プレースメント**](placements) - フローやペイウォールを表示したいユーザージャーニー上の戦略的なポイントです。プレースメントはマネタイズ戦略の「どこで」「いつ」を担います。代表的なプレースメントの例：
   - `main` - メインのペイウォール表示場所
   - `onboarding` - ユーザーのオンボーディングフロー中に表示
   - `settings` - アプリの設定画面からアクセス可能

   最初のインテグレーションでは `main` や `onboarding` といった基本的なものから始め、その後は[アプリ内でユーザーが購入を検討しそうな場所を考えてみましょう](choose-meaningful-placements)。

4. [**プロファイル**](profiles-crm) - ユーザーがプロダクトを購入すると、そのプロファイルに**アクセスレベル**が付与され、有料機能へのアクセスを管理できます。
