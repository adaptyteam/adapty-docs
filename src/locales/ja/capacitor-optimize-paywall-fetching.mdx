Capacitorで確実にフローやペイウォールを取得するには、3つのポイントがあります。高速な描画、オーディエンスに合ったバリアントの返却、そしてネットワークが遅いときのグレースフルなフォールバックです。以下のルールでは、これを実現するためのタイミング、キャッシュ、フォールバックのパターンを説明します。

:::tip
このルールは、`adapty.activate()` と `adapty.identify()` がすでに完了していることを前提としています。詳細は[Capacitor SDKの呼び出し順序](capacitor-sdk-call-order)を参照してください。
:::

## ルールと注意事項 \{#rules-and-pitfalls\}

| これをする | これをしない | 理由 |
|---|---|---|
| 表示しようとしているプレースメントをフェッチするか、[`preloadFlows`](#preload-placements)（SDK 4.3.0+）でキャッシュをウォームアップする。 | 起動時に独自の並行 `getFlow` 呼び出しをファンアウトする。 | 手作りのプリフェッチバーストはメインスレッドをブロックし、黒い画面を引き起こす。`preloadFlows` はこのために設計されており、バッチをネイティブ SDK に一度の呼び出しで送信する。 |
| アトリビューションが解決される機会を得た後に `getFlow` をフェッチする（例：`activate` から 1〜2 秒後、または `onLatestProfileLoad` リスナーが発火した後）。 | `App.tsx` のアプリ起動時に `getFlow` を呼び出す。 | アトリビューションがまだ到着していない。フローはデフォルトのオーディエンスに対して解決され、セグメントや ASA パーソナライゼーションが暗黙的にバイパスされる。 |
| デフォルトの `loadTimeoutMs` である 5000 ミリ秒を維持するか別の値を設定し、すべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。 | `loadTimeoutMs` に非常に大きな値を渡して、タイムアウトが発火しないようにする。 | タイムアウトが発火しないと、接続状態の悪いユーザーはネットワークが解決するまで空白の画面を見ることになるか、アプリを閉じてしまう。 |

カスタムペイウォールとプロダクトの取得に関する `fetchPolicy` と `loadTimeoutMs` パラメーターの説明は [カスタムペイウォールとプロダクトの取得](fetch-paywalls-and-products-capacitor) を、適切なプレースメントの選び方については [プレースメント](placements) を参照してください。

## プレースメントのプリロード \{#preload-placements\}

:::info
`preloadFlows` および `preloadFlowsForDefaultAudience` は SDK バージョン 4.3.0 以降で利用できます。
:::

`preloadFlows` はフローの JSON を事前にキャッシュします。その後は通常通り使用できます。フローの取得には `getFlow`、ビューの作成には `createFlowView` を使います。

`fetchPolicy` は、後続の `getFlow` がどのレイヤーを最初に参照するかを決定するものであり、キャッシュにアクセスできるかどうかを制御するものではありません：

- `'return_cache_data_else_load'` はまずプリロード済みのコピーを読み込み、キャッシュに何もない場合のみネットワークにアクセスします。`'return_cache_data_if_not_expired_else_load'` は、コピーが `maxAgeSeconds` より新しい間は同様に動作します。
- デフォルトの `'reload_revalidating_cache_data'` はまずネットワークにアクセスし、リクエストが失敗またはタイムアウトした場合にプリロード済みのコピーにフォールバックします。

プリロードはどちらのポリシーでも効果がありますが、動作は異なります。キャッシュファーストポリシーではリクエスト自体がなくなり、デフォルトポリシーではリクエストは維持されつつウォームコピーがフォールバックとして使われます。[テストデバイス](test-devices)では、どのポリシーを使っても `getFlow` はキャッシュをスキップし、ネットワークリクエストが失敗した場合にのみプリロード済みコピーを使用します。

セッションで必要になるプレースメントはわかっているが、まだ表示したくない場合に使用します。たとえば、ユーザーがまだタップしていないボタンの背後にあるフローなどが該当します。

:::warning
プリロードは実行時にオーディエンスを解決します。アトリビューションが届く前にプリロードを実行し、その後キャッシュ優先の `fetchPolicy` で `getFlow` を呼び出すと、アトリビューションなしで選ばれたバリアントがユーザーに表示されてしまい、セグメントやASAのパーソナライズが機能しません。アトリビューションが解決されるのを待ってからプリロードするようにしてください。たとえば `onLatestProfileLoad` リスナーが発火した後にプリロードするか、デフォルトの `fetchPolicy` をそのまま使用してください。
:::

```typescript showLineNumbers

try {
  await adapty.preloadFlows({
    placementIds: ['onboarding', 'main_paywall'],
    params: { loadTimeoutMs: 5000 },
  });
} catch (error) {
  // at least one placement failed to preload
}

// Later, when the user reaches the paywall:
const flow = await adapty.getFlow({
  placementId: 'main_paywall',
  params: { fetchPolicy: 'return_cache_data_else_load' },
});
```

**パラメーター：**

- `placementIds`（必須）：プリロードするプレースメント。
- `params.loadTimeoutMs`（任意）：プリロードの全体タイムアウト時間（ミリ秒）。デフォルトは5000で、1000未満の値は1000に切り上げられます。時間内に読み込めなかったプレースメントは、デフォルトのオーディエンス向けにフェッチされます。

**知っておくべき動作：**

- すべてのプレースメントの試行が完了してから初めて呼び出しが失敗し、失敗したすべてのプレースメントをまとめた1つの `AdaptyError` が返されます。1つのプレースメントが失敗しても他の処理は停止せず、ロードに成功したプレースメントはキャッシュに残ります。
- プリロードは常にネットワークへアクセスします。独自の `fetchPolicy` はありません。
- プリロードはキャッシュをウォームアップするだけです。コンテンツを返すわけではないので、表示するには引き続き `getFlow` を呼び出す必要があります。

### プリロードの対象範囲 \{#what-a-preload-covers\}

フローは段階的に画面に表示されます。プリロードは最初の段階をカバーし、`getFlow` と同じ処理を行います：

| レイヤー | 取得元 | プリロードによるウォームアップ |
|---|---|---|
| フロー JSON — 選択されたバリアント、プロダクト ID、リモートコンフィグ | `getFlow` | あり |
| UI レイアウト — 画面の構造、スタイリング、テキスト | `createFlowView` | なし |
| 画像（動画要素の代わりに表示される静止フレームを含む） | `createFlowView`（バックグラウンド） | なし |
| プロダクト | `createFlowView` または `getPaywallProducts` | なし |
| 動画ファイル | システムプレーヤー（画面レンダリング時） | SDK によるキャッシュなし |

`createFlowView` はレイアウトを次の 3 か所で順に検索します。

1. ネイティブSDKのディスクキャッシュ（アプリを再起動しても保持されます）。
2. SDK 4.4以降をご利用の場合、フローを最後に公開した後にダウンロードした[フォールバックファイル](capacitor-use-fallback-paywalls)。
3. ネットワーク経由でAdaptyから取得します。プリロード後でもラウンドトリップが発生します。アプリがフローの公開済みバージョンを初めて表示する際、ネイティブSDKがこのリクエストを送信し、その後レイアウトをディスクキャッシュに保存します。

`createFlowView`の`loadTimeoutMs`がタイムアウトすると、ネイティブSDKはフォールバックしません。AdapyのAPIに再度レイアウトをリクエストします。`loadTimeoutMs`は2回目のリクエストには適用されません。

### オーディエンスのセグメンテーションをスキップする \{#skip-audience-segmentation\}

オーディエンスのセグメンテーションを待たずにキャッシュをウォームアップするには、デフォルトオーディエンスのバリアントを使用します。タイムアウトは不要です：

```typescript showLineNumbers
await adapty.preloadFlowsForDefaultAudience({ placementIds: ['main_paywall'] });
```

その後の `getFlowForDefaultAudience` は、`getFlow` が `preloadFlows` のコピーを読み込む場合と同じ方法でコピーを読み込みます。

## アプリバンドルからファーストスクリーンのメディアを表示する \{#show-first-screen-media-from-the-app-bundle\}

フローは画像や動画を Adapty からダウンロードします。ファーストスクリーンのメディアを即座に表示するには、アプリバンドルから配信する方法があります。既存のネイティブオンボーディングのビジュアルなど、すでに同梱しているメディアを再利用するのに最適な方法です。

1. Flow & Paywall Builderで、画像または動画に[カスタムメディアID](custom-media#custom-media-id)を設定します。そこでアップロードしたファイルはフォールバックとして残ります。
2. ネイティブプロジェクトにファイルを追加します：iOSのアプリバンドルとAndroidの`assets`フォルダです。
3. フロービューを作成する際、`customAssets`にそのIDに対応するバンドル済みファイルを渡します：

```typescript showLineNumbers

// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
const bundledAssets: Record<string, AdaptyCustomAsset> = {
  'welcome_video': {
    type: 'video',
    fileLocation: {
      ios: { fileName: 'welcome.mp4' },
      android: { relativeAssetPath: 'videos/welcome.mp4' },
    },
  },
};

const view = await createFlowView(flow, { customAssets: bundledAssets });
```

バンドルされたファイルはアプリのダウンロードサイズを増加させるため、ユーザーが最初に目にするメディアのみバンドルしてください。

バンドルされた画像は待ち時間なしで表示されますが、ネイティブ SDK はバックグラウンドでアップロードされた画像のダウンロードを続けます。

バンドルしていないメディアもすぐに表示されます。フローのレイアウトには各画像の低解像度コピー（動画の場合はサムネイル）が含まれており、フルサイズのファイルが読み込まれるまでその低解像度版が表示されます。

`customAssets` の完全なリファレンスについては、[アセットのカスタマイズ](capacitor-get-pb-paywalls#customize-assets)を参照してください。

## 接続状態が悪い環境向けのチューニング \{#tune-for-poor-connectivity\}

接続状態が常に悪い市場（農村部、交通機関内、ルーティングの問題がある地域など）向け:

- 最初のフェッチ以外は、すべてのフェッチに `fetchPolicy: 'return_cache_data_else_load'` を設定する。
- Adapty ダッシュボードのすべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。
- `loadTimeoutMs` を速度とターゲティングのバランスを考えて設定する。タイムアウトを短くすると、ユーザーはフォールバックをより早く見ることができる。タイムアウトを長くすると、ターゲットされたフローがロードされる時間が増える。
- [フローを軽く保つ](flow-size)ことで、レイアウトのダウンロードが早くなる。
- フローの表示を `adapty.getProfile()` に依存させないようにする。`getFlow` を独立して呼び出すことで、プロファイルの遅延が UI をブロックしないようにする。
