Adapty AttributionのGoogle Ads連携は双方向で機能します。AdaptyはGoogle Adsアカウントからコスト、インプレッション、クリックを取得し、インストール数、トライアル、購入データをGoogleに送り返すことで、Googleが実際の収益をもとにキャンペーンを最適化できるようにします。

## 仕組み \{#how-it-works\}

Adapty は Google Ads の2種類のキャンペーンに接続します。それぞれアトリビューションの方法が異なり、専用のタブと設定が用意されています。

### アプリキャンペーン（Android）\{#app-campaigns-android\}

Adapty は、アプリの **App Link ID** を通じて、サードパーティのアプリ分析プロバイダーとして Google Ads に接続します。これらのキャンペーンにはトラッキングリンクは不要です。

1. ユーザーがアプリキャンペーンの広告からアプリをインストールし、初めて起動します。
2. Adapty は Google に対して、アプリキャンペーンがそのインストールを誘導したかどうかを照会します。
3. Google は、キャンペーン、広告グループ、広告、キーワードにインストールをアトリビュートします。
4. Adapty は同じリンク ID を通じて、ユーザーのトライアルおよび購入情報を Google に送信します。

### その他のキャンペーン（iOS・Android） \{#other-campaigns-ios-and-android\}

AdaptyのトラッキングテンプレートをGoogle Adsのキャンペーンに追加します。

1. ユーザーが広告をクリックすると、GoogleはそのクリックにクリックIDを付与します。
2. クリックはストアまたはWebファネルへの途中でAdaptyを経由します。
3. Adatyは、そのクリックに対してインストールまたはWeb購入をアトリビュートします。
4. AdaptyはクリックIDを照合して、選択したGoogle Adsアカウントにコンバージョンを送信します。

トラッキングを許可していないiOSユーザーに対しては、Googleは`gclid`の代わりにプライバシーセーフなクリックID（`gbraid`または`wbraid`）を使用します。Adatyはこの3つすべてに対応しています。

### SKAdNetwork

このインテグレーションでは、どちらの種類のキャンペーンもSKAdNetwork（SKAN）—ユーザーを特定せずに広告インストールをレポートするAppleのフレームワーク—を使用しません。そのため：

- SKANやSKANコンバージョン値を設定する必要はありません。
- Google Adsですでに使用しているSKAN設定は、AdaptyがGoogleに送信するイベントにも、Adaptyアトリビューションに表示されるデータにも影響しません。

## サポートされているキャンペーンタイプ \{#supported-campaign-types\}

| キャンペーンタイプ | 広告の掲載場所 | Adapty アトリビューションのタブ | プラットフォーム |
|---|---|---|---|
| アプリキャンペーン（インストール促進）(UAC) | Google 検索、Google Play、YouTube、ディスプレイネットワークでアプリのインストールを促進 | **App Campaigns** | Android |
| 検索 | 指定したキーワードに対応する Google 検索結果 | **Other Campaigns** | iOS, Android |
| P-MAX（最大リーチ） | 検索、YouTube、ディスプレイ、ファインド、Gmail、マップなど Google の全チャネルを1つのキャンペーンでカバー | **Other Campaigns** | iOS, Android |
| デマンドジェネレーション | YouTube インフィードとショート、ファインド、Gmail への画像・動画広告 | **Other Campaigns** | iOS, Android |
| ディスプレイ | Google ディスプレイネットワーク上のサイトやアプリへのバナー広告 | **Other Campaigns** | iOS, Android |
| 動画 | YouTube への動画広告 | **Other Campaigns** | iOS, Android |
| ショッピング | Google マーチャントセンターのフィードからのプロダクト広告 | **Other Campaigns** | iOS, Android |

iOSアプリのプロモーションには、Other campaignsを使用してください。Performance Maxキャンペーンも、目標がアプリインストールの場合は**Other Campaigns**タブに表示されます。これは、AdaptyがApp Link IDではなくトラッキングテンプレートで追跡するためです。

アプリエンゲージメントキャンペーンはサポートされていません。Adaptyは、Googleがアプリキャンペーンに帰属したインストールのイベントのみをGoogleに送信しますが、エンゲージメントキャンペーンはすでにアプリをインストールしているユーザーを対象とするためです。

## ステップ 1. Google アカウントを連携する \{#step-1-connect-your-google-account\}

1. Adapty Attribution で、左サイドバーの **Integrations** に移動し、**Google Ads** を選択します。
2. **Sign in with Google** をクリックします。

<ZoomImage id="ua-sign-in-google-ads.webp" width="700px" />

3. Google Ads アカウントへのアクセス権を持つ Google アカウントを選択し、**Continue** をクリックします。
4. 要求されたすべての権限を選択し、**Continue** をクリックします。

その後、Adaptylはお使いのGoogleアカウントがアクセスできるすべてのGoogle Adsアカウント（マネージャーアカウント配下のクライアントアカウントを含む）を同期します。別のGoogleアカウントがアクセスできる広告アカウントを追加するには、**Sign in with Google** を再度クリックしてください。

## ステップ 2. キャンペーンを追加する \{#step-2-add-campaigns\}

実行するキャンペーンの種類を設定します。Appキャンペーンとその他のキャンペーンは別々に設定でき、同じアプリで両方を使用することができます。

### アプリキャンペーン \{#app-campaigns\}

アプリ内イベントをGoogle アプリキャンペーンに送信するには、Adapty Attributionで設定を作成し、App Link IDを使ってGoogle AdsのAndroidアプリにリンクします。

**Adapty Attributionで設定を作成します：**

1. **Integrations > Google Ads** で **App Campaigns** タブに切り替え、**Create configuration** をクリックします。Adaptyが現在のアプリの設定を作成して開きます。

<ZoomImage id="google-ads-create-ad-campaign.webp" width="700px" />

2. **Provider ID** の値をコピーします。Google AdsでApp Link IDを作成する際に必要です。

**Google Ads でアプリリンク ID を作成します：**

1. **Tools** アイコンをクリックし、**Data manager** を選択します。
2. **+ Connect Product** をクリックし、**Third-party app analytics** を選択して、**Continue** をクリックします。
3. **Create link ID** をクリックします。
4. プロバイダーリストから **Other provider** を選択し、Adapty Attribution からコピーした **Provider ID** を貼り付けます。
5. プラットフォームとして **Android** を選択し、**Look up your app** フィールドでアプリを検索します。
6. **Create link ID** をクリックし、生成されたリンク ID をコピーします。

:::note
Google Ads では、Adapty から最初のイベントを受信するまで、リンク ID が **Unverified** と表示されます。
:::

**Adapty Attribution でリンク ID を追加する:**

1. 設定画面で、リンク ID を **Android App Link ID** フィールドに貼り付けます。各リンク ID は 1 つの設定にのみ属することができます。

<ZoomImage id="app-link-id.webp" width="700px" />

2. [イベントをマッピング](#step-3-map-events)して、**Save** をクリックします。
3. 接続を確認するには、**Send test event** をクリックしてイベントを選択し、送信します。Google は受信した各イベントをGoogle Ads のアプリのコンバージョンアクションに追加するため、キャンペーンの最適化目標として選択できます。

:::note
Google Ads が新しいリンク ID を認識するまでに約 24 時間かかるため、それまではテストイベントが失敗することがあります。失敗した場合は、[トラブルシューティング](#test-event-fails-for-a-new-link-id)を参照してください。
:::

<ZoomImage id="google-ads-test-event.webp" width="700px" />

:::note
欧州経済領域および英国のユーザーに対して、Adaptyは同意シグナルを「拒否」に設定したイベントを送信します。Adapty アトリビューションで同意を設定する必要はありません。
:::

### その他のキャンペーン \{#other-campaigns\}

iOS および Android のSearch、Display、Shopping などクリックベースのキャンペーンをトラッキングするには、Adapty Attribution でそれらの設定を作成し、そのトラッキングテンプレートを Google Ads のキャンペーンに追加します。広告を配信する Google Ads アカウントごとに、1 つの設定が必要です。

:::important
Google Ads アカウントの設定で自動タグ設定をオンにする必要があります。Adapty は自動タグ設定が付与するクリック ID を使ってコンバージョンを広告に紐付けるため、クリック ID がない場合はコンバージョンが送信されません。
:::

1. **Integrations > Google Ads** で **Other Campaigns** タブに切り替え、**Create configuration** をクリックします。

   <ZoomImage id="ua-google-ads-other-campaigns.webp" width="700px" alt="Other Campaigns tab of the Google Ads integration in Adapty Attribution with the Create configuration button" />

2. **Google Ads account** ドロップダウンで、広告を配信しているクライアントアカウントを選択します。Google はその広告を配信したアカウントにのみコンバージョンを受け付けます。マネージャーアカウントはコンバージョンを保持できないため、一覧には表示されません。

<ZoomImage id="ua-google-ads-account-select.webp" width="700px" alt="Other campaignsの設定にあるGoogle Adsアカウントのドロップダウンと、その下のトラッキングテンプレート" />

3. **Tracking template** の値をコピーします。次に、Google Ads でキャンペーン設定を開き、**Campaign URL options > Tracking template** に貼り付けます。1つのテンプレートで iOS と Android の両方に対応します。
4. 広告がウェブファネルにつながる場合は、**Web funnel** セクションを展開します：
   - **Pixel snippet** をコピーして、[ファネルにインストール](ua-web-pixel)します。
   - **Ad URL parameters** をコピーして、Google Ads のキャンペーン設定の **Campaign URL options > Final URL suffix** に貼り付けます。これがないと、Adapty は購入を Google Ads には紐付けますが、キャンペーン、広告グループ、または広告には紐付けられません。

<ZoomImage id="ua-google-ads-tracking-links.webp" width="700px" alt="Tracking links section of an Other campaigns configuration with the tracking template, pixel snippet, and ad URL parameters" />

5. [イベントをマッピングする](#step-3-map-events)し、**Save** をクリックします。

設定を保存すると、Adapty は選択した Google Ads アカウントに、有効にした各イベントのコンバージョンアクションを作成します。Google が拒否した場合、Adapty はエラーを表示し、設定を保存しません。編集可能なクライアントアカウントを選択するか、Google アカウントのアクセスが期限切れになっている場合は再接続してください。

:::note
2026年9月11日以前にGoogleアカウントを接続した場合は、Other campaignsを追加する前に再接続してください。それ以前に接続したアカウントには、これらのキャンペーンのコンバージョンを送信するためにAdaptyが必要とする権限が付与されていません。**Sign in with Google**をクリックして、要求されたすべての権限を選択してください。
:::

## ステップ3. イベントのマッピング \{#step-3-map-events\}

Google が受信するイベントを選択するには、**Events mapping** セクションで送信したいイベントをオンにし、Google Ads でのイベント名を選択または入力します。イベント名にカンマは使用できません。

<ZoomImage id="ua-google-ads-events.webp" width="700px" />

イベント名は、2種類のキャンペーンタイプで動作が異なります：

- **アプリキャンペーン**: **インストール**は常にオンになっており、デフォルトで `first_open` にマッピングされます。各イベントに対して、Googleの標準アプリイベントから選択できます: `first_open`、`session_start`、`in_app_purchase`、`ecommerce_purchase`、`view_item`、`view_item_list`、`add_to_cart`、または `view_search_results`。それ以外の名前を入力した場合、Adaptyはそれをカスタムアプリイベントとして送信します。
- **その他のキャンペーン**: 各イベントのデフォルト名は、`trial_started` のようなAdaptyのイベント名です。選択または入力した名前が、AdaptyがGoogle Adsで作成するコンバージョンアクションの名前になります（入力した通りの名前になります）。

**Save** をクリックします。

## 追加設定 \{#additional-configuration\}

### 収益オーバーライド \{#revenue-override\}

トライアルイベントをトラッキングし、Google にその収益を関連付けたい場合は、**Revenue override** セクションを使用します。このセクションは **Trial started** イベントが有効になっているときに表示されます。オーバーライドは **Trial started** にのみ適用されます。**Trial converted** と **Subscription started** は常に実際の収益を送信します。

各トライアルイベントターゲットに対して、収益としてレポートするサブスクリプション価格の割合を設定します。たとえば、30% に設定すると、Adapty はトライアルイベントのコンバージョン値としてサブスクリプション価格の 30% を送信します。

オーバーライドを追加するには：

1. **Events mapping** セクションで **Trial started** を有効にします。
2. **Revenue override** で **Add event** をクリックします。
3. 対象イベントを選択し、収益の割合（0〜100）を入力します。
4. **Save** をクリックします。

<ZoomImage id="revenue-override.webp" width="500px" />

### Qualified trial \{#qualified-trial\}

:::warning
Adapty Attributionは、トライアルイベントを最大24時間遅延させ、ユーザーがキャンセルしていない場合にのみ送信します。MMPが`trial_started`または[`trial_active`](events#synthetic-events)も転送している場合、Googleは同じトライアルを複数回受け取ることになります。
:::

トライアルは、指定された時間数をキャンセルされずに経過した場合に「有効」と見なされます。**Qualified trial** セクションを使用して、トライアルイベントが有効と見なされるまで保留することで、Googleはユーザーが継続したトライアルのみを受け取るようになります。このセクションは、App campaignsとOther campaignsの両方で利用できます。

各トライアルイベントターゲットに対して、待機する時間数を設定します。Adapty はトライアル開始時から時間をカウントし、期限が過ぎるとイベントを送信します。期限前にユーザーが自動更新をオフにした場合、Adapty はイベントを送信しません。期限前にユーザーが自動更新を再度オンにした場合、Adapty は予定どおりイベントを送信します。

トライアルイベントを条件を満たすまで保留するには：

1. **Events mapping** セクションで **Trial started** を有効にします。
2. **Qualified trial** で **Add event** をクリックします。
3. ターゲットイベントを選択し、待機する時間数（1〜24）を入力します。
4. **Save** をクリックします。

<ZoomImage id="qualified-trial-google-ads.webp" width="700px" alt="Qualified trial section with the in_app_purchase target event held for one hour in a Google Ads campaign configuration" />

**Revenue override** と **Qualified trial** は独立して動作するため、同じトライアルイベントに両方を適用することができます。Revenue override はGoogle が受け取る値を変更し、Qualified trial はGoogle がそれを受け取るタイミングを変更します。両方を使用した場合、Adapty はトライアルが条件を満たすまでイベントを保留し、その後オーバーライドされた収益値と共に送信します。

## Adapty アトリビューションにおける Google Ads データ \{#google-ads-data-in-adapty-attribution\}

Adapty は Google Ads の広告費、インプレッション数、クリック数を 4 時間ごとに更新します。直近のデータは Google 側で継続的に調整されるため、更新のたびに過去 3 日分のデータも再取得されます。

[Adapty アトリビューション アナリティクス](ua-analytics) では、Google Ads のデータをキャンペーン、広告グループ、広告、キーワードの 4 つのレベルで確認できます。キーワードレベルの広告費は検索キャンペーンのみ対象で、Performance Max キャンペーンはキャンペーンレベルのみのレポートとなります。国別の内訳はレベルによって異なります。

- **キャンペーンと広告グループ**: Google がレポートした通りの正確な値。
- **広告**: 推定値。Google は広告を国別にレポートしないため、Adapty は各広告の数値を、その広告グループの数値が国別に分割される割合と同じ方法で各国に割り当てます。
- **キーワード**: 利用不可。

接続済みの Google Ads アカウントのいずれのキャンペーンにも一致しない Google Ads クリック ID を持つインストールは、**Google Play** チャネルの下に表示されます。同じインストールを主張する Google Ads と他のソースの間で Adapty がどのように選択するかについては、[チャネル](adapty-user-acquisition#channels)を参照してください。

## トラブルシューティング \{#troubleshooting\}

### 新しいリンクIDのテストイベントが失敗する場合 \{#test-event-fails-for-a-new-link-id\}

Google Ads が新しいリンクIDを認識するまでに約24時間かかります。それまでの間、テストイベントは失敗し、Google はキャンペーンにイベントをアトリビュートしません。最初の24時間以内にテストイベントが失敗しても、設定が間違っているわけではありません。

24時間待ってから、再度テストイベントを送信してください。その間はリンクIDを置き換えないでください。新しいリンクIDに変更すると、待機時間がリセットされます。

24時間経過してもテストイベントが失敗する場合は、**Data manager** で作成したリンクIDを正しく貼り付けているか確認してください。他のGoogle Ads識別子を使用していないか確認してください。
