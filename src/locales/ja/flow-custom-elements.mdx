フロー & ペイウォールビルダーのカスタム要素を使うと、フロー画面にネイティブビューを追加できます。Lottie / Rive アニメーション、インタラクティブなチャート、マップ、カメラプレビューなど、アプリが表示できるあらゆるビューに対応しています。ネイティブビューが表示されるのは、iOS、Android、React Native、または Flutter 向けの Adapty SDK v4.4+ を使用しているアプリのみです。他のクロスプラットフォームフレームワークで構築されたアプリでは、カスタム要素ごとにフォールバックが表示されます。

<DocVideo id="custom-elements-examples.mp4" alt="ネイティブビューを表示した3つのフローの画面：4/7日まで埋まるLottieリング、ユーザーがドラッグできる体重チャート、ユーザー近くのフィットネスセンターの地図。" />

フローの画面にネイティブビューを表示するには：

1. [カスタム要素を画面に追加](#add-and-configure)し、**Type** と **ID** を入力します。
2. カスタム要素内に[フォールバックコンテンツを追加](#set-fallback-content)します。アプリがビューを表示しない場合、ユーザーにはこのコンテンツが表示されます。
3. [アプリコードでネイティブビューをセットアップ](#set-up-your-app-code)します。Adapty SDK を使って、同じ Type と ID を割り当てます。
4. [フローを公開](#publish-and-test)し、デバイスでテストします。
5. [ネイティブビューを含むアプリアップデートをリリース](#what-changes-require-an-app-release)します。ネイティブビューに対応していない旧バージョンのユーザーにはフォールバックが表示されます。

:::tip
画像やアニメーション動画を表示するには、カスタム要素の代わりに [**Image**](custom-media#image) または [**Video**](custom-media#video) 要素を使用してください。どちらもアプリ側のコードは不要で、アプリのリリースなしにファイルを差し替えることができます。
:::

## 1. スクリーンにカスタム要素を追加する \{#add-and-configure\}

1. **Add element** パネルを開きます。**Media** グループで **Custom element** をクリックします。

   <ZoomImage id="flow-custom-element-card.webp" width="200px" alt="Custom element in the Media group of the Add element panel" />

2. ネイティブビューがタッチに反応する場合は、カルーセルなど同様にタッチに反応するコンテナ内にカスタム要素を配置しないようにしてください。そうすることで、ネイティブビュー上のスワイプがカルーセルを動かさずに済みます。
3. **Type** フィールドに、`lottie_animation` のようなネイティブビューの種類を表す Type を入力します。
   - **命名規則**: 小文字、数字、アンダースコアのみ使用できます。
   - **完全一致**: Type はアプリ側の値と一字一句一致している必要があります。スペルが異なると、ユーザーにはフォールバックが表示されます。
   - **サジェスト**: フィールドには、アプリ内の Type ではなく、このフロー内ですでに使用されている Type が候補として表示されます。
4. **ID** フィールドで、`custom_1` などの事前入力された値を `welcome_wave` のような任意の ID に変更してください。ID は同じ Type のカスタム要素を区別するために使用します。

   <ZoomImage id="flow-custom-element-type-id.webp" width="500px" alt="カスタム要素設定の Element セクションにある Type と ID フィールド" />

5. ネイティブビュー用のスペースを固定サイズで確保するには、デフォルトの **Fixed** 高さをそのまま使用し、ビューに必要な高さを設定してください。
   - **Shared area**: ネイティブビューとフォールバックコンテンツが同じ領域を共有します。
   - **Alignment**: ネイティブビューがこの領域より小さい場合、デフォルトでは左上隅に表示されます。位置を変更するには、カスタム要素の **Layout** セクションで配置を変更してください。

   :::important
   **Hug** の高さでは、マップやスクロールリストなど、独自の高さを持たないネイティブビューはほぼゼロの高さに縮小されます。
   :::

6. （オプション）カスタム要素の角丸 **Corners** に合わせてネイティブビューをクリップするには、**Layout** セクションで **Clip content** チェックボックスを選択します。

### カスタム要素でネイティブビューを使用する \{#use-native-views-in-several-custom-elements\}

以下のルールは、カスタム要素の Type と ID に適用されます：

- **Type**: ネイティブビューの種類ごとに1つの Type を入力します（例：Lottie プレーヤーには `lottie_animation`、マップには `map`）。
- **ID**: 同じ Type 内で、コンテンツごとに一意の ID を割り当てます（例：2つの Lottie アニメーションに `streak_ring` と `welcome_wave`）。アプリはこの ID を読み取ってコンテンツを選択します。1つの画面上に同じ Type と ID を持つカスタム要素が2つある場合、**ID** フィールドに警告が表示されます：*Same type and ID as another element on this screen.* それでもフローは公開できます。
- **要素のコピー**: 要素を複製・貼り付けたり、[タブ](builder-tabs)を追加したりすると、ビルダーは画面またはコンポーネント内で既に使用されているコピー済み ID を自動的にリネームします。たとえば、`custom_1` は `custom_2` に、`hero` は `hero_2` になります。アプリのコードが正しい ID を参照していることを確認してください。

## 2. フォールバックコンテンツの追加 \{#set-fallback-content\}

以下の場合、ネイティブビューの代わりにフォールバックがユーザーに表示されます：

- ユーザーが使用しているアプリのバージョンにビューのコードが含まれていない。
- アプリが React Native や Flutter 以外のクロスプラットフォームフレームワークで構築されている。
- アプリが Adapty SDK バージョン 4.4 より古いものを使用している。
- カスタム要素の Type と ID がアプリコード内のビューと一致しない。
- アプリコードの Type と ID は一致しているが、ビューが返されない。たとえば、デバイスに必要なファイルがない場合や、ユーザーが権限を拒否した場合など。

フォールバックを設定するには、カスタム要素コンテナに要素を追加します。ネイティブビューが表示されない場合、フォールバックのないカスタム要素は空のままになります。

Flow & ペイウォールビルダーはアプリのコードを実行できないため、キャンバスにはフォールバックのみが表示されます。[Adapty モバイルアプリでのプレビュー](paywall-device-compatibility-preview#preview-on-devices)でもフォールバックが表示されます。ネイティブビューをプレビューするには、アプリのビルドで[デバイス上でフローをテスト](#publish-and-test)してください。

<ZoomImage id="flow-custom-element-placeholder.webp" width="400px" alt="フォールバックとして「Add elements here」というテキストが表示された、キャンバス上の空のカスタム要素" />

:::important
ナビゲーションボタン、購入ボタン、その他の重要なUI要素はカスタム要素の外に配置してください。ユーザーにはネイティブビューかフォールバックのどちらか一方のみが表示されます。
:::

カスタム要素の中に **Footer**、**Sliding sheet**、**Bottom Sheet** を追加することはできません。

## 3. アプリにネイティブビューを設定する \{#set-up-your-app-code\}

カスタム要素を含む画面が開かれると、Adapty SDK は要素の Type と ID をアプリコード内のリゾルバー関数に渡します。リゾルバーは次のいずれかを返します：

- **Type と ID に一致するビュー**: ユーザーにネイティブビューが表示されます。コード内では、ビルダーに入力した Type と ID を正確に記述してください。
- **ビューなし**: ユーザーにはフォールバックが表示されます。たとえば、ビューに必要なファイルがデバイス上にない場合はビューを返さないようにします。

アプリでカスタム要素をサポートするには、プラットフォームごとのガイドを参照してください: [iOS](ios-flow-custom-elements)、[Android](android-flow-custom-elements)、[React Native](react-native-flow-custom-elements)、[Flutter](flutter-flow-custom-elements)。

:::tip
フローの前の画面で収集したユーザーデータ（回答内容など）をネイティブビューで可視化できます。詳しくは <InlineTooltip tooltip="ペイウォールにインタラクティブな体重目標チャートを表示する">[iOS](custom-element-interactive-chart)、[Android](android-custom-element-interactive-chart)、[React Native](react-native-custom-element-interactive-chart)、[Flutter](flutter-custom-element-interactive-chart)</InlineTooltip> をご覧ください。
:::

## 4. フローを公開してテストする \{#publish-and-test\}

[フローを公開する](builder-save-publish)には、すべてのカスタム要素に[命名規則](#add-and-configure)に従ったTypeが設定されていることを確認してください。アプリをリリースする前にフローを公開することができます。ユーザーがアプリを更新するまでは、フォールバックが表示されます。

ネイティブビューのエラーはアプリをクラッシュさせる可能性があります。リリース前に、カスタム要素を含むすべての画面をネイティブビューを使ったビルドでテストしてください。実際のユーザーにまだ表示されていないフローをテストするには、このビルドがリクエストするがリリース済みアプリではリクエストしない[プレースメント](create-placement)にフローを追加してください。キャッシュされたものではなく最新の公開済みフローを確認するには、デバイスを[テストデバイス](test-devices)として登録してください。詳細な手順はプラットフォーム別ガイドを参照してください: [iOS](ios-flow-custom-elements#test-on-a-device)、[Android](android-flow-custom-elements#test-on-a-device)、[React Native](react-native-flow-custom-elements#test-on-a-device)、[Flutter](flutter-flow-custom-elements#test-on-a-device)。

## アプリのリリースが必要な変更 \{#what-changes-require-an-app-release\}

ネイティブビューはアプリのコードの一部です。ネイティブビューを変更するにはアプリのアップデートをリリースしてください。フォールバックコンテンツやカスタム要素の Type と ID 以外の設定を変更するには、フローを公開してください。

| 変更内容 | 対応方法 | アプリを更新していないユーザーに表示されるもの |
|---|---|---|
| 既存のカスタム要素のネイティブビュー（アニメーションの変更など） | 新しいネイティブビューを含むアプリアップデートをリリースする | そのアプリバージョンに含まれている場合は、以前のネイティブビュー |
| 新しいカスタム要素のネイティブビュー | 新しいネイティブビューを含むアプリアップデートをリリースする。新しい Type と ID を持つカスタム要素を追加し、フローを公開する | フォールバックコンテンツ |
| 別の画面、別のフロー、または A/B テスト内の既存のネイティブビュー | 同じ Type と ID を持つカスタム要素を追加し、フローを公開する。<InlineTooltip tooltip="app-wide resolver">[iOS](ios-flow-custom-elements#set-an-app-wide-resolver)、[Android](android-flow-custom-elements#display-views-in-every-flow)、[React Native](react-native-flow-custom-elements#pass-the-resolver-to-the-sdk)、[Flutter](flutter-flow-custom-elements#pass-the-resolver-to-the-sdk)</InlineTooltip> がビューを返す場合、アプリのアップデートは不要 | そのアプリバージョンに含まれている場合は、ネイティブビュー |
| カスタム要素の Type または ID | 新しい Type と ID に対応するネイティブビューを含むアプリアップデートをリリースし、フローを公開する | フォールバックコンテンツ |
| フォールバックコンテンツ、カスタム要素のその他の設定 | フローを公開する。アプリのアップデートは不要 | 更新されたコンテンツ |

## トラブルシューティング \{#troubleshooting\}

- **ユーザーにネイティブビューの代わりにフォールバックが表示される**: TypeとIDがアプリ内のものと一字一句一致しているか確認してください。そのビューに対応していないアプリバージョンのユーザーは、アップデートするまでフォールバックが表示されます。コード上の原因を調べるには、各プラットフォームのガイドを参照してください: [iOS](ios-flow-custom-elements#test-on-a-device)、[Android](android-flow-custom-elements#test-on-a-device)、[React Native](react-native-flow-custom-elements#test-on-a-device)、[Flutter](flutter-flow-custom-elements#test-on-a-device)。
- **ユーザーに空白のエリアが表示される**: [フォールバックを追加](#set-fallback-content)してフローを公開してください。[テストデバイス](test-devices)でも空白のエリアが表示される場合、ネイティブビューはコンテンツなしで表示されています。コンテンツがない場合にリゾルバーがビューを返さないようにしてください。詳細は <InlineTooltip tooltip="フォールバックコンテンツの条件を設定する">[iOS](ios-flow-custom-elements#set-conditions-for-fallback-content)、[Android](android-flow-custom-elements#set-conditions-for-fallback-content)、[React Native](react-native-flow-custom-elements#set-conditions-for-fallback-content)、[Flutter](flutter-flow-custom-elements#set-conditions-for-fallback-content)</InlineTooltip> を参照してください。
- **ネイティブビューがカスタム要素に収まらない**: アプリがビューをカスタム要素のエリアに合わせているか確認してください。ビューを角丸の **Corners** に合わせてクリッピングするには、**Layout** セクションで **Clip content** チェックボックスを選択してください。
