ようこそ！アプリ内課金をもっとかんたんに 🚀

アプリ内課金の面倒な処理はAdapty Unity SDKにお任せください。あなたは本来の仕事——素晴らしいゲームを作ること——に集中できます。Adaptyが代わりに行うことは次のとおりです：

- 購入処理、レシート検証、サブスクリプション管理をすぐに使える状態で提供
- アプリのアップデートなしでペイウォールの作成・テストが可能
- セットアップ不要で詳細な購入分析を提供——コホート、LTV、チャーン、ファネル分析を含む
- アプリセッションやデバイスをまたいでユーザーのサブスクリプション状態を常に最新の状態に維持
- たった1行のコードでマーケティングアトリビューションや分析サービスとアプリを連携

:::note
コードに入る前に、AdaptyをApp Store ConnectおよびGoogle Play Consoleと連携させ、ダッシュボードでプロダクトを設定する必要があります。まずはすべての設定を完了するために、[クイックスタートガイド](quickstart)をご確認ください。
:::

## 主要な概念 \{#main-concepts\}

コードに入る前に、Adapty の仕組みを支える重要な概念を理解しておきましょう。

Adapty のアプローチの優れた点は、アプリ内にハードコードするのはプレースメントだけという点です。プロダクト、ペイウォールのデザイン、価格、オファーなど、それ以外のすべては Adapty ダッシュボードからアプリのアップデートなしに柔軟に管理できます：

1. [**プロダクト**](product) - アプリ内で購入可能なすべてのもの――サブスクリプション、消耗型アイテム、永続アクセスなど。

2. **フローまたはペイウォール** - プロダクトに設定を紐付けてプレースメントに割り当てます。2種類あります：
   - **[フロー](adapty-flow-builder)** - フロービルダーで作成するビジュアルなノーコードインターフェース。AdaptyがUIを描画し、購入処理も自動で行います。
   - **[ペイウォール](paywalls)** - ビジュアル設定なし。UIは自分でコーディングし、`MakePurchase`を自分で呼び出します。[ペイウォールの手動実装](unity-quickstart-manual)を参照してください。

   SDKコード上では、どちらも同じ`GetFlow`メソッドで取得します。

3. [**プレースメント**](placements) - フローやペイウォールを表示したいユーザージャーニー上の戦略的なポイントです。プレースメントは収益化戦略の「どこで」「いつ」を定義するものと考えてください。代表的なプレースメントの例：
   - `main` - メインのペイウォール表示場所
   - `onboarding` - ユーザーオンボーディングフロー中に表示
   - `settings` - アプリの設定からアクセス可能

   最初の統合では `main` や `onboarding` などの基本的なものから始め、その後[アプリ内でユーザーが購入を検討しそうな場所](choose-meaningful-placements)を考えてみましょう。

4. [**プロファイル**](profiles-crm) - ユーザーがプロダクトを購入すると、そのプロファイルに**アクセスレベル**が付与され、有料機能へのアクセス制御に使用します。
