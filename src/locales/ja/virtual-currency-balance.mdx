[Profiles/CRM](profiles-crm) のすべてのユーザープロファイルには、そのユーザーのバーチャルカレンシー残高と、すべての変更履歴が表示されます。同じプロファイルから、サポートチームが手動で残高のクレジットやデビットを行うことも可能です。たとえば、生成に失敗したユーザーへの補償などに活用できます。

## ユーザープロファイルで残高を確認する \{#view-balances-in-a-user-profile\}

<ZoomImage id="virtual-currency-balance.webp" width="300px" alt="バーチャル通貨カードが表示されたユーザープロファイルページ。ユーザーの残高一覧があり、使用可能な金額と残高調整・変更履歴のリンクが表示されています" float="right" />

ユーザーの[プロファイル](https://app.adapty.io/profiles/users)を開いてください。**Virtual currency** カードには、そのユーザーが保有するすべての通貨が表示されます。

各行には以下が表示されます：

- 通貨の**コード**（例：`COINS`）。
- 現在の**残高**（整数）。
- **使用可能**な金額を括弧内に表示（例：`1,200 (950 spendable)`）。ユーザーが残高全額をすぐに使えない場合に表示されます。Adaptyがまだ削除していない期限切れクレジットや、保留中の支出のために保留されているクレジットは残高に含まれますが、使用可能金額には含まれません。

残高は、ユーザーがクレジットを獲得・消費・受け取るたびに更新されます。残高が0を下回ることはありません。消費可能な残高を超えて使おうとするトランザクションは`insufficient_balance`エラーで失敗し、何も変更されません。残高がないプロファイルには空のカードが表示されます。

残高を自分のコードから読み取るには、サーバーサイドAPIの[仮想通貨残高の一覧取得](api-adapty/operations/listVirtualCurrencyBalances)を呼び出してください。

## 残高を手動で調整する \{#adjust-a-balance-manually\}

ユーザーへの補償、失敗したアクションのクレジット返還、または残高の修正を行う場合は、ユーザーのプロファイルからクレジットの付与または引き落としを行います。単発の変更にはサーバーサイド API は不要です。

オーナー、管理者、サポートメンバーは残高を調整できます。アプリに少なくとも1つの[仮想通貨](create-virtual-currency)がある場合、**Adjust balance** リンクが表示されます。

1. ユーザーのプロファイルで、**Virtual currency** カードの **Adjust balance** をクリックします。

   <ZoomImage id="virtual-currency-adjust-balance-form.webp" width="400px" alt="残高調整フォーム（50 COINSのクレジット、報酬操作、support_compensation機能、参照ID、コメントあり）" />

2. **Currency** を選択します。次に、クレジットを追加するには **Credit** を、削除するには **Debit** を選択します。**Amount** の上の行には、その通貨におけるユーザーの現在の残高と使用可能な金額が表示されます。
3. **Amount** に0より大きい整数を入力します。使用可能な金額まで引き落とせます。
4. **Operation** で、変更の意味を選択します。クレジットの場合は **Reward**、**Spend reversal**、または **Adjustment** を選択します。デビットの場合は **Spend**、**Reward reversal**、または **Adjustment** を選択します。報酬でも取り消しでもない修正には **Adjustment** を使用します。その他の選択については [Operation](virtual-currencies#operation) を参照してください。
5. **Feature** に、`support_compensation` などのクレジットの用途を入力します。文字、数字、`_` を使用し、ドットは最大1つまでです。命名のアドバイスについては [Feature](virtual-currencies#feature) を参照してください。
6. 任意で、**Reference ID** にサポートチケットなど関連オブジェクトのIDを入力します。**Comment** には200文字以内で変更の説明を記入します。チームはプロファイルのイベント履歴および **Change history** でこのコメントを確認できます。
7. **Continue** をクリックします。変更前後の残高と使用可能な金額を確認し、**Confirm** をクリックします。

   <ZoomImage id="virtual-currency-adjust-balance-confirm.webp" width="400px" alt="The Confirm adjustment step, showing the balance changing from 1,200 to 1,250 and the spendable amount from 950 to 1,000" />

カードには新しい残高が表示され、変更内容はプロファイルの[イベント履歴](#review-balance-changes-in-the-event-history)の先頭に表示されます。

フォームが結果を確認できない場合、**Confirm** を再度クリックするよう求められます。クリックしてください。Adapty は同じ調整を二重に適用しません。

Adapty は手動による調整をウェブフックやインテグレーションには送信しません。

### 残高を調整したメンバーを確認する \{#see-who-adjusted-a-balance\}

残高を誰がどのような理由で調整したかを確認するには、**Virtual currency** カードの **Change history** をクリックします。一覧には過去3か月間の手動調整が新しい順に表示されます。各行には、チームメンバーとその役割、変更内容、機能、参照ID、コメント、および変更後の残高が表示されます。

新しい調整が **Change history** に反映されるまで、約2分かかる場合があります。

<ZoomImage id="virtual-currency-change-history.webp" width="700px" alt="変更履歴ウィンドウには手動調整が表示されており、それぞれの日付、チームメンバー、役割、変更内容、機能、参照ID、コメント、および調整後の残高が確認できます" />

## 残高変更をイベント履歴で確認する \{#review-balance-changes-in-the-event-history\}

残高の変更はすべて、プロファイルのイベント履歴に新しい順で表示されます。各エントリには変更内容と影響を受けた通貨が記載されています。

Adapty は各エントリに、残高を変更したものの名前を付けます。

- **仮想通貨のクレジット付与**: 購入、更新、またはトライアル開始によってクレジットが付与されました。
- **仮想通貨の有効期限切れ**: 有効期限のあるクレジットが請求サイクルの終了時、またはサブスクリプション終了時にリセットされました。
- **仮想通貨トランザクション**: `operation` なしで送信されたサーバーサイド API の[トランザクション](api-adapty/operations/createVirtualCurrencyTransaction)です。

`operation` を指定して送信されたサーバーサイド API トランザクション、および[手動調整](#adjust-a-balance-manually)は、その操作にちなんで名前が付けられます：

| `operation` | エントリー名 |
|---|---|
| `top_up` | バーチャル通貨がチャージされました |
| `refund` | バーチャル通貨が取り消されました |
| `spend` | バーチャル通貨が使用されました |
| `spend_reversal` | バーチャル通貨の使用が取り消されました |
| `reward` | バーチャル通貨が付与されました |
| `reward_reversal` | バーチャル通貨の付与が取り消されました |
| `exchange` | バーチャル通貨が交換されました |
| `expiry` | バーチャル通貨が期限切れになりました |
| `migration` | バーチャル通貨が移行されました |
| `adjustment` | バーチャル通貨が調整されました |

各エントリのアイコンは、操作の種類ではなく金額の符号に従います。クレジット、デビット、またはひとつのトランザクションがクレジットとデビットの両方を行う場合は中立アイコンが表示されます。

各エントリには、変更が生じたすべての通貨について次の情報が表示されます。

- **仮想通貨**: `Gold Coins (COINS)` のような通貨名とコード。
- **金額**: 符号付きの変化量 — クレジットの場合は正の値、デビットの場合は負の値。
- **変更後の残高**: 変化が適用された後の通貨残高。

1つのイベントで複数の通貨を同時に変更できます。たとえば、1つの[トランザクション](api-adapty/operations/createVirtualCurrencyTransaction)である通貨を引き落とし、別の通貨に入金することで通貨を変換できます。

### トランザクションの詳細 \{#transaction-details\}

残高変動の理由を確認するには、エントリの下にある **Details** ブロックを展開してください。値が入力されているフィールドのみ表示されます。

<ZoomImage id="virtual-currency-transaction-details.webp" width="500px" alt="A Virtual currency debited entry in the user history with the Details block expanded, showing the operation, feature, reference ID, customer placement ID, and metadata" />

- **Store**: クレジットを付与した購入のストア。
- **Operation**: バックエンドが送信した、またはAdaptyが設定したトランザクションの`operation`。
- **Feature**: `feature`から取得した、クレジットの使用目的または付与理由。
- **Reference ID**: `reference_id`から取得した、システム内の関連オブジェクト（生成物など）のID。
- **Customer placement ID**: `customer_placement_id`から取得した、トランザクションが発生したアプリ内の画面または場所。これはAdaptyの[プレースメント](placements)ではなく、あなた自身のIDです。
- **Sandbox**: `is_sandbox: true`で送信されたテストトランザクション、またはテストユーザーの残高を手動で調整した場合は**Yes**。
- **Metadata**: バックエンドが`metadata`で送信したキーと値のペア、または手動調整の`comment`。他のトランザクションにはメタデータは表示されません。

バックエンドがこれらのフィールドを設定するのは、[トランザクションを作成する](api-adapty/operations/createVirtualCurrencyTransaction)ときです。手動調整の場合は、**Adjust balance** フォームから入力されます。Adapty がこれらのフィールドを保存する前に記録されたトランザクションは、フィールドの表示数が少ないか、**Details** ブロックが表示されない場合があります。

## 残高、プロファイル、デバイス \{#balances-profiles-and-devices\}

残高は常に1つの[プロファイル](profiles-crm)にのみ属し、別のプロファイルに移動することはありません。Adapty は[ユーザーアカウント間でアクセスレベルを共有する](profiles-crm#sharing-paid-access-between-user-accounts)ような方法でプロファイル間の残高を共有・移転することはできません。

実際には、これは次のことを意味します：

- **識別済みユーザー**: カスタマーユーザーIDは常に同じプロファイルに紐付くため、ユーザーはログインしているすべてのデバイスで同じ残高を確認でき、アプリを再インストールしても残高が保持されます。
- **匿名ユーザー**: 匿名プロファイルはクレジットの獲得・消費が可能ですが、特定のデバイスの1つのアプリインストールに紐付いています。同じユーザーがアプリを再インストールしたり、ログインせずに別のデバイスで開いたりすると、Adaptyはゼロ残高の新しい匿名プロファイルを作成します。クレジットは以前のプロファイルに残ったまま、ユーザーはそこにアクセスできなくなります。

仮想通貨経済をデバイスをまたいで、また再インストール後も継続させるには、ユーザーを識別する必要があります。識別はアプリのコード内でSDKを使って行うか（クイックスタートの[ユーザーの識別](ios-quickstart-identify)を参照）、またはバックエンドから[サーバーサイドAPI](getting-started-with-server-side-api)を通じて行うことができます。

ユーザーの識別が遅れると、別の問題が生じます。ユーザーが匿名のままクレジットを獲得し、その後すでに別のプロファイルに紐付いているカスタマーユーザーIDでログインした場合、デバイスはそのプロファイルとその残高に切り替わります。匿名で獲得したクレジットは古いプロファイルに残ったままアクセスできなくなります。カスタマーユーザーIDが新規のものであれば、現在のプロファイルに紐付けられ、ユーザーは残高を引き継げます。安全のため、ユーザーがクレジットを獲得または購入できるようになる前に識別しておいてください。

[サーバーサイドAPI](getting-started-with-server-side-api)の呼び出しでは、`adapty-profile-id` または `adapty-customer-user-id` ヘッダーでプロファイルを識別します。どちらも同一のプロファイルに解決されます。匿名プロファイルの場合は `adapty-profile-id` を使用してください。
