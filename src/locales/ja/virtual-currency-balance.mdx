[Profiles/CRM](profiles-crm) のすべてのユーザープロファイルには、そのユーザーのバーチャル通貨残高と、すべての変更履歴が表示されます。

## ユーザープロファイルで残高を確認する \{#view-balances-in-a-user-profile\}

<ZoomImage id="virtual-currency-balance.webp" width="300px" alt="A user's profile page with the Virtual currency card, which lists the user's currency balances" float="right" />

ユーザーの[プロファイル](https://app.adapty.io/profiles/users)を開きます。**Virtual currency** カードには、そのユーザーが保有しているすべての通貨が一覧表示されます。

各行には以下の情報が表示されます：

- 通貨の**コード**（例：`COINS`）
- 整数で表示される現在の**残高**

残高は、ユーザーがクレジットを獲得・消費・受取するたびに更新されます。残高が0を下回ることはありません。保有量を超えて消費しようとするトランザクションは`insufficient_balance`で失敗し、何も変更されません。残高が存在しないプロファイルには空のカードが表示されます。

独自のコードから残高を読み取るには、サーバーサイドAPIの[仮想通貨残高の一覧取得](api-adapty/operations/listVirtualCurrencyBalances)を呼び出してください。

## 残高変更をイベント履歴で確認する \{#review-balance-changes-in-the-event-history\}

残高の変更はすべて、プロファイルのイベント履歴に新しい順で表示されます。各エントリには変更内容と影響を受けた通貨が記載されています。

Adapty は各エントリに、残高を変更したものの名前を付けます。

- **Virtual currency credited**: 購入、更新、またはトライアル開始によってクレジットが付与された場合。
- **Virtual currency expired**: 請求サイクルの終了時またはサブスクリプション終了時に、有効期限付きクレジットがリセットされた場合。
- **Virtual currency transaction**: `operation` なしで送信されたサーバーサイド API の[トランザクション](api-adapty/operations/createVirtualCurrencyTransaction)。

`operation` を指定してサーバーサイド API トランザクションを送信した場合、そのオペレーション名がイベント名になります：

| `operation` | エントリー名 |
|---|---|
| `top_up` | バーチャル通貨がチャージされました |
| `refund` | バーチャル通貨が取り消されました |
| `spend` | バーチャル通貨が使用されました |
| `spend_reversal` | バーチャル通貨の使用が取り消されました |
| `reward` | バーチャル通貨が付与されました |
| `reward_reversal` | バーチャル通貨の付与が取り消されました |
| `exchange` | バーチャル通貨が交換されました |
| `expiry` | バーチャル通貨が期限切れになりました |
| `migration` | バーチャル通貨が移行されました |
| `adjustment` | バーチャル通貨が調整されました |

各エントリのアイコンは、操作の種類ではなく金額の符号に従います。クレジット、デビット、またはひとつのトランザクションがクレジットとデビットの両方を行う場合は中立アイコンが表示されます。

各エントリには、変更が生じたすべての通貨について次の情報が表示されます。

- **仮想通貨**: `Gold Coins (COINS)` のような通貨名とコード。
- **金額**: 符号付きの変化量 — クレジットの場合は正の値、デビットの場合は負の値。
- **変更後の残高**: 変化が適用された後の通貨残高。

1つのイベントで複数の通貨を同時に変更できます。たとえば、1つの[トランザクション](api-adapty/operations/createVirtualCurrencyTransaction)である通貨を引き落とし、別の通貨に入金することで通貨を変換できます。

### トランザクションの詳細 \{#transaction-details\}

残高変動の理由を確認するには、エントリの下にある **Details** ブロックを展開してください。値が入力されているフィールドのみ表示されます。

<ZoomImage id="virtual-currency-transaction-details.webp" width="500px" alt="A Virtual currency debited entry in the user history with the Details block expanded, showing the operation, feature, reference ID, customer placement ID, and metadata" />

- **Store**: 付与されたクレジットのストア。
- **Operation**: あなたのバックエンドが送信した、またはAdaptyが設定したトランザクションの`operation`。
- **Feature**: クレジットが消費または付与された対象。`feature`から取得。
- **Reference ID**: あなたのシステム内の関連オブジェクトのID（ジェネレーションなど）。`reference_id`から取得。
- **Customer placement ID**: トランザクションが発生したアプリ内の画面または場所。`customer_placement_id`から取得。これはAdaptyの[プレースメント](placements)ではなく、あなた自身のIDです。
- **Sandbox**: テストトランザクションが`is_sandbox: true`で送信された場合は**Yes**。
- **Metadata**: バックエンドが`metadata`で送信したキーと値のペア。サーバーサイドAPIのトランザクションのみメタデータが表示されます。

バックエンドがこれらのフィールドを設定するのは、[トランザクションを作成する](api-adapty/operations/createVirtualCurrencyTransaction)ときです。Adapty がこれらのフィールドを保存する以前に記録されたトランザクションには、フィールドが少ないか、**Details** ブロックが表示されない場合があります。

## 残高、プロファイル、デバイス \{#balances-profiles-and-devices\}

残高は常に1つの[プロファイル](profiles-crm)にのみ属し、別のプロファイルに移動することはありません。Adapty は[ユーザーアカウント間でアクセスレベルを共有する](profiles-crm#sharing-paid-access-between-user-accounts)ような方法でプロファイル間の残高を共有・移転することはできません。

実際には、これは次のことを意味します：

- **識別済みユーザー**: カスタマーユーザーIDは常に同じプロファイルに紐付くため、ユーザーはログインしているすべてのデバイスで同じ残高を確認でき、アプリを再インストールしても残高が保持されます。
- **匿名ユーザー**: 匿名プロファイルはクレジットの獲得・消費が可能ですが、特定のデバイスの1つのアプリインストールに紐付いています。同じユーザーがアプリを再インストールしたり、ログインせずに別のデバイスで開いたりすると、Adaptyはゼロ残高の新しい匿名プロファイルを作成します。クレジットは以前のプロファイルに残ったまま、ユーザーはそこにアクセスできなくなります。

仮想通貨経済をデバイスをまたいで、また再インストール後も継続させるには、ユーザーを識別する必要があります。識別はアプリのコード内でSDKを使って行うか（クイックスタートの[ユーザーの識別](ios-quickstart-identify)を参照）、またはバックエンドから[サーバーサイドAPI](getting-started-with-server-side-api)を通じて行うことができます。

ユーザーの識別が遅れると、別の問題が生じます。ユーザーが匿名のままクレジットを獲得し、その後すでに別のプロファイルに紐付いているカスタマーユーザーIDでログインした場合、デバイスはそのプロファイルとその残高に切り替わります。匿名で獲得したクレジットは古いプロファイルに残ったままアクセスできなくなります。カスタマーユーザーIDが新規のものであれば、現在のプロファイルに紐付けられ、ユーザーは残高を引き継げます。安全のため、ユーザーがクレジットを獲得または購入できるようになる前に識別しておいてください。

[サーバーサイドAPI](getting-started-with-server-side-api)の呼び出しでは、`adapty-profile-id` または `adapty-customer-user-id` ヘッダーでプロファイルを識別します。どちらも同一のプロファイルに解決されます。匿名プロファイルの場合は `adapty-profile-id` を使用してください。
