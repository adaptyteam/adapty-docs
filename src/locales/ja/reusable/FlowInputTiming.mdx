:::important
フィールド、日時ピッカー、選択グループは、このコールバックでデフォルト値を送信しません。ユーザーが **Set as default** とマークされたオプションを選択してそのまま次へ進んでも、イベントは発火しません。イベントが発生しないからといって「未回答」とは解釈しないでください — ユーザーは単にデフォルト値のまま進んだだけです。[Number picker](builder-number-picker) は、別の画面を開くボタンをタップしたときに、デフォルト値のナンバーをアプリコードに送信します。
:::

**このイベントをトリガーする要素：**

- テキスト・メール・数値・電話フィールド
- 日付・時刻・日時ピッカー
- Number picker
- 単一選択・複数選択の選択グループ、およびトグル

**トリガーされない要素：**

- パスワードフィールド、プロダクト選択、タブ切り替え
- 画面をまたいで共有されるヘッダー要素内の入力
- オプションの要素IDが重複または欠落している選択グループ、あるいは別の画面でグループIDが再利用されている選択グループ。このようなグループは、一部の回答だけでなく、何も送信しません。

**イベントが発火するタイミング：**

- フィールドがフォーカスを失ったとき。クリアされたフィールドは空文字列を報告し、一度も編集されなかったフィールドは何も報告しません。プレースホルダーは値ではありません。ユーザーがフィールドに戻って編集し、再びフォーカスを外した場合は、2回目のイベントが発火します。
- ユーザーが新しい値を選択した後、日付または時刻ピッカーを閉じたとき。変更せずに閉じた場合は何も報告されません。
- Number picker がある画面で、ユーザーが **Navigate to Screen**、**Navigate Next**、または **Navigate back** [アクション](onboarding-actions)を実行するボタンをタップしたとき。同じ画面でオプションやトグルをタップした場合も、Number picker は値を報告します。ユーザーがホイールを一度も動かしていない場合、値はデフォルト値です。Number picker は非表示の場合（例：ユーザーが開かなかったタブ内）でも値を報告します。値が変化するまで2回目のイベントは発火しません。
- ユーザーがオプションまたはトグルをタップしたとき。複数選択のイベントは選択済みのすべてのオプションを列挙するため、最後のオプションの選択を外すと空の配列が2つ送信されます。

**イベントが発火しないタイミング：**

- ユーザーが入力しているとき。キーストロームは存在せず、フォーカスが外れた時点でフィールドが保持している値のみが送信されます。
- ユーザーがフローを送信または閉じるとき。その時点でまだ編集中の値は失われる可能性があります。フローを閉じるボタン、購入を開始するボタン、またはカスタムアクションを実行するボタンは、Number picker の値を報告しません。[配信の制限](#delivery-and-limitations)セクションでは、両方のケースを考慮した最終画面の設計方法について説明しています。
- ユーザー操作なしに値が設定されたとき。**Set as default** とマークされたオプションは画面が開いたときに事前選択されており、**Set Variable** アクションによって別のインタラクションからオプションを選択したり入力を埋めたりすることができます。いずれもイベントを送信しません。Number picker 以外の事前入力された入力は、ユーザーが編集した時点で一度だけ報告されます。
