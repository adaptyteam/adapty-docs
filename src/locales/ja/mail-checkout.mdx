各メールはブラウザ上のチェックアウトページにリンクしており、そこで購入が行われます。作成するには、Adapty Mailで **Email Destinations** に移動し、**Web Paywall** を選択して **Create** をクリックします。2つのオプションがあります。

| | AIで生成 | 自前でホスティング |
| --- | --- | --- |
| ページの作成者 | Adapty Mail（バンドルされたウェブペイウォールビルダー） | あなた |
| 決済プロバイダー | Stripeのみ | 任意 |
| プロジェクト | Adaptyアプリへの紐付けが必要 | 任意 |
| あなたの作業 | プランを選択し、確認後に公開 | ページを構築し、URLから受信者を読み取り、購入を報告 |

:::note
Adaptyのコアプロダクトには独自のウェブペイウォールがあります。それは別の機能であり、ここで説明する内容は適用されません。
:::

## AIで生成する \{#generate-with-ai\}

:::warning
AI生成を使用するには、プロジェクトが**Adaptyアプリにリンクされている**必要があります。これは、Adapty ダッシュボードからMailを初めて開いたときにAdaptyが作成したものです。Adapty Mailでプロジェクトをご自身で作成した場合（スタンドアロンアカウントまたはAdaptyアカウントで）、独自のペイウォールをホストしてください。
:::

### 生成されたペイウォールの構成 \{#what-a-generated-paywall-looks-like\}

生成によって4つのスクリーンが作成され、メールからアクセスしたユーザーは順番にそれぞれのスクリーンを目にします：

1. **Email** — 見出し、サブ見出し、メールフィールド。Adapty Mail はリンクからメールアドレスを自動入力するため、キャンペーン経由のトラフィックはそのまま進めます。別の方法でアクセスしたユーザーは手入力します。
2. **Paywall** — 販売ページ（以下参照）。
3. **Payment success** または **Payment failed** — どちらか一方が表示され、両方同時に表示されることはありません。

AIはブランド情報をもとに、ペイウォールスクリーンのすべての要素を生成します：

| セクション | 内容 |
| --- | --- |
| ヘッドラインとサブヘッドライン | 冒頭のキャッチコピー |
| オファーバッジ | 緊急性を示すテキスト（価格は自動生成されません） |
| ヒーロー画像 | ブランドから生成される画像 |
| プラン | タイトル、オファータイマー、選択したプラン |
| ベネフィット | 3〜6枚のカード |
| 機能 | 3〜8項目（各項目にタイトルとサブタイトル付き） |
| ソーシャルプルーフ | 証拠テキスト1行と3〜5件のレビュー |
| FAQ | 3〜6問の質問と回答 |
| 保証 | 返金保証または満足保証の一文 |

CTAとカウントダウンは常にトップに固定表示されます。**Payment success**では生成された画像と次のステップが表示され、**Payment failed**では再試行を促しながらチェックアウトの状態が維持されます。

## 独自にホストするペイウォールを使用する \{#use-your-own-hosted-paywall\}

このアプローチでは、Adapty Mail が受信者をあなたがホストするページに誘導します。URLには、ユーザー情報を転送する[プレースホルダー](#personalize-your-url-with-placeholders-and-hooks)が含まれます。クリック後のオファー・決済・パーソナライズはすべてあなた側で行われ、任意の決済プロバイダーを使用できます。

1. **Name**（名前）を入力します — キャンペーンに紐付ける際にこの名前で識別します。
2. ホスティング済みのペイウォールURLを**URL**に貼り付けます。HTTPSを使用する必要があり、受信者ごとに異なる値には[プレースホルダー](#personalize-your-url-with-placeholders-and-hooks)を使用できます。
3. **Save**をクリックします。これでデスティネーションがキャンペーンで使用できるようになります。

### プレースホルダーとフックでURLをパーソナライズする \{#personalize-your-url-with-placeholders-and-hooks\}

プレースホルダーとフックを使うと、ペイウォールのURLを受信者ごとに固有の値でパーソナライズできます。利用可能な一覧とルールについては、[プレースホルダー](mail-destinations#placeholders)をご覧ください。

### あなたのページがすべきこと

リダイレクト後、Adapty Mail は何も行いません。以下の処理はすべてあなたの責任です：

- **チェックアウト開始前に訪問者を特定する**: クエリ文字列からプロファイルIDまたはメールアドレスを読み取り、購入に紐付ける。これにより、メールの送信先である顧客に決済が正しく関連付けられる。
- **購入を報告する**: Adapty Mailは自社プロバイダーで処理された支払いを把握できない。Adapty Mailが知らない購入は、[Analytics](mail-analytics)でコンバージョンにも属性付き収益にもカウントされない。さらに悪いことに、すでに購入済みのユーザーに対してシーケンスの残りのメールが送り続けられる。既存のデータ送信経路を使って報告すること: [Adapty連携](mail-collect-emails)、またはAdapty Mail APIの[トランザクションイベント](mail-send-data-via-api#send-transaction-events)。

### ローンチ前にペイウォールをテストする \{#test-the-paywall-before-launching\}

**Send test email** を使えばメールのレンダリングと決済ページの動作を確認できますが、URL で追加されたペイウォールでは **Sandbox** を選択できません — モーダルには *「This paywall has no sandbox products, so only production is available.」* と表示されます。そのため、テストは本番ページおよび本番プロダクトに対して行われることになります。実際のカードを使って後で返金するか、配線を確認する間は URL を自分のテスト環境に向けるようにしてください。詳細は[設定のテスト](mail-testing#test-the-email-and-checkout-on-their-own)を参照してください。

## トラブルシューティング \{#troubleshooting\}

| 問題 | 解決策 |
|---|---|
| チェックアウトリンクが開かない | ペイウォールがウェブペイウォールビルダーで公開されていることを確認してください |
| チェックアウト時にユーザーが識別されない | URLにデータのソースに対応するプレースホルダーが含まれているか確認してください。誤ったソースのプレースホルダーは空文字列に解決されるため、パラメーターが空白で届きます |
| 購入がメールに紐付けられない | アトリビューションはメールのCTAクリックに基づくため、受信者はそのリンクからチェックアウトに到達し、購入が同じプロファイルでAdapty Mailに届く必要があります。既に以前のメールにアトリビュートされた購入はそのアトリビューションが維持されます |
