Adapty の各アナリティクスタブには、時間範囲、期間比較、フィルタリング、グループ化、チャートの表示形式といったデータを絞り込むためのコントロールが用意されています。利用できるコントロールはタブによって異なります。

**アナリティクスタブ別の利用可能なコントロール:**

| コントロール | チャート | コホート | ファネル | リテンション | コンバージョン | LTV |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| 日付範囲 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 期間比較 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| フィルター | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| グループ | ✅ | ❌ | ✅ | ✅ | ✅ | ✅ |
| チャート表示 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| テーブル表示 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| CSVエクスポート | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 手数料と税金 | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ |

### 日付範囲を設定する \{#set-the-date-range\}

各チャートの上にある **Date range** カレンダーを使って、期間を指定します。チャートはアプリの[レポートタイムゾーン](general#3-reporting-timezone)に従います。[概要ページ](overview)には独自に設定できるタイムゾーンがあります。サードパーティ連携は、設定に関わらず常に UTC を使用します。

#### プリセット範囲 \{#preset-ranges\}

<ZoomImage id="analytics-date-picker-presets.webp" width="500px" alt="Date range preset list in the Adapty analytics date picker" />

任意の開始日・終了日を指定するには **Custom** オプションを使用します。プリセットは次のとおりです：

| プリセット | 開始 | 終了 |
| --- | --- | --- |
| Last 7 days | 6日前 | 今日 |
| Last 28 days | 27日前 | 今日 |
| Last month | 前月の同日 | 今日 |
| Last 3 months | 3ヶ月前 | 今日 |
| Last 6 months | 6ヶ月前 | 今日 |
| Last year | 1年前 | 今日 |
| Previous month | 前月の初日 | 前月の末日 |
| This month | 当月1日 | 今日 |
| This quarter | 当四半期の初日 | 今日 |
| This year | 当年1月1日 | 今日 |

:::tip
週次サブスクリプションプロダクトを追跡するには **Last 28 days** を使用してください。この範囲は4週間分をカバーするため、週の途中で期間が切れてしまうことがありません。
:::

#### タイムスケール \{#time-scale\}

<ZoomImage id="analytics-date-picker.webp" width="500px" alt="Adapty analytics date picker with the time scale button row at the bottom" />

チャート上の各データポイントは一定の時間単位を表します。ドロップダウンから日、週、月、四半期、年を選択できます。日・週は短期的な増減を、月・四半期・年は長期的なトレンドを把握するのに適しています。

[コホート](analytics-cohorts)分析や [LTV](ltv) 分析では、同じ設定を **cohort length** と呼びます。詳細は各記事を参照してください。

### 2つの期間を比較する \{#compare-two-time-periods\}

カレンダーの隣にある比較オプションをクリックすると、現在の期間と直前の同じ長さの期間を重ねて表示できます。比較範囲を変更するには、オプションを再度クリックしてカスタム範囲を選択してください。

比較結果は以下の形式で表示されます:

- **チャート上** — グループが0または1つの場合、折れ線・エリア・カラムが重ねて表示されます。
- **数値** — 2つの期間の差分が、上昇時は緑、下降時は赤で表示されます。
- **ツールチップ** — データポイントにカーソルを合わせると、そのポイントの数値差分が表示されます。

### データをフィルタリング・グループ化する \{#filter-and-group-data\}

**フィルター** を使うと、1つ以上の属性（例: 特定の国やプロダクト）に一致するデータのみをチャートに表示できます。**グループ化** を使うと、チャートの合計を属性値ごとに別々の系列に分割できます。たとえば、収益を国別にグループ化すると、合算した総計の代わりに国ごとの収益ラインが表示されます。

**利用可能なフィルター・グループ化属性:**

| 属性 | フィルター | グループ | 説明 |
| --- | :---: | :---: | --- |
| Attribution | ✅ | ✅ | 報告者、ステータス、チャンネル、キャンペーン、広告グループ、広告セット、クリエイティブ（キーワード）。[アトリビューション連携](attribution-integration)が必要です。 |
| Audience | ✅ | ✅ | ユーザーが属する[オーディエンス](audience)。 |
| Renewal status | ❌ | ✅ | 次の期間にサブスクリプションが更新されるかどうか。 |
| Period | ✅ | ✅ | サブスクリプションのライフサイクルステージ：**Trial**、**Activation**（初回支払い）、**Renewal 1**～**Renewal 5**、**Renewals 6+**（以降の更新）。サブスクリプションチェーン単位でカウントされますが、プロダクトでフィルタリングまたはグループ化する場合はプロダクト単位でカウントされます。そのため、2つのプロダクト間を移動したユーザーは、前者では1回、後者ではプロダクトごとに1回カウントされます。 |
| Country | ✅ | ✅ | ユーザーのストア国。利用できない場合、AdaptyはIP国、次に購入通貨を使用します。[国の判定方法](#how-country-is-determined)を参照してください。 |
| Offer Type | ✅ | ✅ | トランザクションに適用されたオファー：<ul><li>**Introductory** — サブスクリプションの初期期間に対する初回オファー。有料の初回オファーと無料トライアルを区別するには**Offer Discount Type**を使用してください。</li><li>**Promotional** — App Storeのプロモーションオファーおよびそれに相当するもの。</li><li>**Offer Code** — 顧客がストアで入力するプロモコード。</li><li>**No offer** — オファーなし。</li></ul> |
| Offer ID | ✅ | ✅ | 特定のオファーID。 |
| Offer Discount Type | ✅ | ✅ | 初回オファーまたはプロモーションオファーの価格モデル：**Free Trial**、**Pay As You Go**、または**Pay Up Front**。たとえば無料トライアルの初回オファーと有料の初回オファーを区別するには、**Offer Type**と組み合わせて使用してください。 |
| Paywall | ✅ | ✅ | 購入に使用された[ペイウォール](paywalls)。[Flow Builder](adapty-flow-builder)で作成された画面もここに表示され、`Checkout flow: 9. Paywall A`のような名前でスクリーンごとに一覧表示されます。[フロー画面の命名規則](#how-flow-screens-are-named)を参照してください。 |
| Flow | ✅ | ✅ | 購入元の[フロー](adapty-flow-builder)。フロー全体を互いに比較する際に使用します。 |
| Flow screen | ✅ | ✅ | 購入元の個別のフロー画面。フロー内のどの画面が収益を上げているかを確認するために使用します。フィルターでは、画面はフローの下にネストされており、画面のみ選択可能です。グループ化すると各シリーズに`Checkout flow: 9. Paywall A`というラベルが付きます。 |
| A/B tests | ✅ | ❌ | 購入時にアクティブだった[A/B テスト](ab-tests)。 |
| Placement | ✅ | ✅ | 購入が発生した[プレースメント](placements)。 |
| Store | ✅ | ✅ | トランザクションを処理したストア：App Store、Google Play、Stripeなど。 |
| Product | ✅ | ✅ | [プロダクト](product) — サブスクリプションおよび買い切り購入。 |
| Duration | ✅ | ✅ | プロダクトの期間。 |
| Segment | ✅ | ✅ | ユーザーの[セグメント](segments)。セグメントでグループ化して、**All users**に対するセグメントのパフォーマンスを比較できます。<ul><li>ファネルはセグメントによるグループ化をサポートしていません。</li><li>セグメントが使用しているカスタム属性を後から変更すると、Adaptyがアナリティクスでそのユーザーをセグメントから除外する場合があります。データには以前の値が引き続き表示されます。</li></ul> |
| Refund Reason | ✅ | ✅ | トランザクションが払い戻された理由（例：**Refund**または**Upgraded**）。払い戻しおよび請求問題解決チャートで利用可能です。 |
| Expiration reason | ❌ | ✅ | サブスクリプションまたはトライアルが終了した理由：**Cancelled by customer**、**Billing issue**、**Customer hasn't agreed to price increase**、**Unknown**、または**Refund**。期限切れ（解約済み）サブスクリプションおよび期限切れ（解約済み）トライアルで利用可能です。 |
| Cohort（LTVのみ） | ❌ | ✅ | LTVチャートでは、コホートの長さでグループ化できます：**Day**、**Week**、**Month**、または**Year**。このチャートではGroup by Attributionの代わりに使用されます。 |

すべてのアナリティクスビューが上記のすべてのフィルターやグループ属性に対応しているわけではありません。**Charts**タブのARPUとInstallsは、アトリビューション、国、セグメント、ストア、および（フィルターのみ）A/Bテストに限定されています。これらはインストール数をカウントするものであり、フロー、フロースクリーン、ペイウォール、プレースメント、プロダクトはいずれも購入を表すものだからです。LTVにはフローやフロースクリーンのサポートもありません。LTV、コホート、ファネル、リテンション、コンバージョンの各タブはそれぞれ異なるサブセットをサポートしています。正確なサポート状況については、該当するチャートまたはタブの記事を参照してください。

:::note
フィルタードロップダウンには、Adaptyがすでに受信した値のみが表示されます。オプションは、その値を含む少なくとも1件のトランザクションをAdaptyが処理した後に表示されます。たとえば、広告ネットワークやMMPにキャンペーンが存在していても、アトリビューションされたトランザクションがAdaptyに届いていない場合、そのキャンペーンはリストに表示されません。セグメントは例外で、セグメント定義から取得されるため、トランザクションが発生する前から表示されます。
:::

### 国の判定方法 \{#how-country-is-determined\}

各トランザクションには、作成された時点で国情報が付与されます。国の判定に使用されるソースは、優先順に次のとおりです。

1. ユーザーの**ストアの国** — App Store または Google Play のアカウント国。
2. ユーザーの**IP の国**。
3. **購入通貨**の国。

ストアの国は、Web 決済（Stripe、Paddle）、手動で付与されたアクセス、またはストアが提供しなかったトランザクションでは利用できません。その場合、Adapty は IP の国にフォールバックします。

同じ国が、そのトランザクションの[App Store手数料率](how-adapty-analytics-works#app-store-commission-rates)を決定します。

国はトランザクションごとに記録されるため、インストール後にApp Storeの国を変更したユーザーは、変更前後のトランザクションで異なる国の値を持ちます。過去のトランザクションは元の国を保持します。

**GBとUnited Kingdom。** 国データはISO 3166-1 alpha-2コード（"United Kingdom"ではなく"GB"）として保存されます。ダッシュボードの表示レイヤーは、レガシーの`'UK' → 'United Kingdom'`エイリアスを含むルックアップテーブルを通じてコードをフル名称にマッピングします。そのため、セグメントを作成する際に両方がオプションとして表示される場合があります。

### フロースクリーンの命名方法 \{#how-flow-screens-are-named\}

フロースクリーンおよびペイウォール属性のスクリーン名は、フローの**公開済み**バージョンから取得され、`<position>. <screen name>` の形式（例：`9. Paywall A`）で表示されます。位置はビルダーのスクリーンリスト内での順番を示すため、フローを開いたときに表示される番号と一致します。

Adapty はトランザクションが発生した時点ではなく、チャートを実行した時点で名前を解決します：

- ビルダーでスクリーンの名前変更や並び替えを行うと、そのスクリーンの過去のデータにも新しい名前が反映されます。一度修正した名前は、履歴全体で正しく表示されます。
- 公開バージョンに存在しなくなったスクリーンも、そのスクリーンが生成したトランザクションのラベルは保持されますが、元の識別子（例：`scr_a1b2c3`）にフォールバックします。

各スクリーンは、フローを何回公開したかに関わらず1エントリとして表示されます。新しいバージョンを公開すると、バックグラウンドで全スクリーンの新しいコピーが作成されますが、Adapty はそれらのコピーを元のスクリーンにまとめてグループ化します。[ペイウォールビルダー](adapty-paywall-builder)で作成されたペイウォールは独自の名前を持ち、フロースクリーンとマージされることはありません。

フィルターやグループのリストには、少なくとも1件の取引があるスクリーンのみが表示されます。ユーザーが一度も購入していないスクリーンは、フロー自体がリストに表示されていても、スクリーンのリストには表示されません。

### チャートの表示形式を変更する \{#change-the-chart-visualization\}

表示形式ドロップダウンからチャートの表示方法を選択します:

- **Stacked column** — 各カラムに合計値をグループごとの色付きセグメントで表示します。
- **Stacked area** — 積み上げカラムと同様ですが、データポイントを結ぶ塗りつぶしエリアで表示します。
- **Line** — グループごとに1本の折れ線を表示し、塗りつぶしなし。
- **100% stacked column** — 各カラムがチャートの最大高さに達し、実際の値の代わりにグループごとの相対的な割合（パーセンテージ）を表示します。時系列での比率確認に便利です。
- **100% stacked area** — 100% 積み上げカラムと同様ですが、カラムの代わりに塗りつぶしエリアで表示します。

### テーブルでデータを確認する \{#view-data-as-a-table\}

各チャートの下には同じデータが日付を列としたテーブルで表示されます。Total 行と列にはチャート上では確認できない集計値が表示されます。

### データを CSV にエクスポートする \{#export-data-to-csv\}

**Export** ボタンをクリックすると、チャートの基礎データを CSV ファイルとしてダウンロードできます。

:::tip
プログラムによるアクセスや定期的なアクセスには、代わりに [Export API](export-analytics-api) を使用してください。CSV ダウンロードと同じデータを返します。
:::

### 収益の表示形式（総収益 / 純収益） \{#display-gross-or-net-revenue\}

収益関連のチャート（[Revenue](revenue)、[MRR](mrr)、[ARR](arr)、[ARPU](arpu)、[ARPPU](arppu)）には、3つの表示モードを切り替えるドロップダウンがあります:

- **Gross revenue** — 控除前の総収益。
- **Proceeds after store commission** — ストアの手数料を差し引いた収益（税金は含む）。
- **Proceeds after store commission and taxes** — 手数料と税金の両方を差し引いた収益。

手数料と税金の計算方法の詳細については、「*Adapty アナリティクスの仕組み*」の[手数料と税金](how-adapty-analytics-works#commissions-and-taxes)を参照してください。
