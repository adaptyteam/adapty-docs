実際のユーザーにキャンペーンを公開する前にテストを行いましょう。

- **ライブチェーンをテスト**: オートメーションが実行され、実際の支払いが発生します。公開前に少なくとも1回は実施してください。
- **テストメールを送信**: オートメーションをスキップし、チェックアウトではStripeのテストカードが使用できます。

## はじめる前に \{#before-you-start\}

以下のすべての条件が満たされている場合にのみ、チェーン全体がエンドツーエンドで動作します。

- **送信ドメインが確認済みであること**: **Settings** > **DNS** を開いて確認してください。[送信ドメインのセットアップ](mail-sending-domain)を参照してください。
- **チェックアウト**: ウェブペイウォールが作成・公開されていること。未公開のペイウォールは、CTAが開こうとするとエラーが発生します。[チェックアウトのセットアップ](mail-checkout)を参照してください。
- **フローに紐づいたキャンペーン**: キャンペーン単体ではドラフト状態のままで、メールは送信されません。Adapty Mail のフローがあって初めて有効になります。設定方法は[フローでのセグメント管理](mail-create-flow)を参照してください。
- **有効なエントリーポイント**: ユーザーデータが実際に Adapty Mail に届いていること。どの[エントリーポイント](mail-entry-points)を使う場合も、確認方法は同じです。新規登録ユーザーが[Profiles](mail-profiles)ページに表示されていれば問題ありません。

## ライブチェーンをテストする \{#test-the-live-chain\}

実際の条件でキャンペーンをテストするには、自分自身でユーザー登録します。すると、他のユーザーと同様にキャンペーンからメールが届き、本番環境のチェックアウトで実際のカードで支払いができます。以下の手順で待ち時間を短縮すれば、数日ではなく数分でテストが完了します。

1. **最初の遅延を短縮する。** キャンペーンエディターで、最初のメールの **Delay** を1〜2分に設定し、実際のスケジュールを待たなくて済むようにします。テスト後は遅延を元に戻してください。

<ZoomImage id="mail-campaign-email-delay.webp" width="600px" alt="The Delay field on the first email, set to 0 days, 0 hours, and 1 minute" />

2. **テストユーザーを作成する。** アプリ内で、まだプロジェクトにプロファイルが存在しないメールアドレスで登録してください。キャンペーンを一度実行したプロファイルは再度エントリーしないため、毎回新しいアドレスが必要です。

3. **最初のメールを待つ。** Adapty Mail はトリガー時刻に設定した遅延を加えた時刻に送信をスケジュールし、1分に1回の頻度で送信対象のメールを処理します。配信にはさらに数分かかります。

4. **メールを開き、CTAをクリックします。** メールアドレスが入力済みの状態でチェックアウトページが開きます。

5. **支払いを完了します。** 実際のカードで支払いを行い、その後Stripeで返金します。

## メールとチェックアウトを単独でテストする \{#test-the-email-and-checkout-on-their-own\}

メールとチェックアウトをオートメーションを待たずに確認するには、キャンペーンエディターの **Send test email** を使用します。このボタンは、送信ドメインが確認済みで、キャンペーンに[メール宛先](mail-destinations)が選択されるまで無効のままです。

モーダルには3つの設定があります。

- **Environment**: **Production** は本番環境のチェックアウト（本番プロダクト使用）を開きます。**Sandbox** はテスト版を開き、Stripe のテストカード `4242 4242 4242 4242` が任意の有効期限・CVC で使用できます。Sandbox は、サンドボックスプロダクトで生成されたペイウォールのみ選択可能です。URL で追加したペイウォールには *"This paywall has no sandbox products, so only production is available."* と表示されます。
- **Profile**: 任意項目。プロファイルを選択すると、そのプロファイルのメールアドレス宛に送信され、CTA にはそのプロファイルの ID が設定されます。
- **Custom address**: 任意項目。プレースホルダーのプロファイル ID を使用して、指定したアドレス宛に送信します。プロファイルを選択するとクリアされ、両方が設定されている場合はプロファイルが優先されます。

どちらも設定しない場合、メールはプレースホルダーのプロファイルIDとともに自分のアカウントのアドレスに送信されます。

テスト送信は、ライブチェーンとは別の単独のメールです。メールが正しくレンダリングされること、チェックアウトで決済が完了することを確認できますが、オートメーションが起動するかどうかは確認できません。オートメーションを確認するには、[ライブチェーンをテストする](#test-the-live-chain)を実行してください。

<ZoomImage id="mail-send-test-email-modal.webp" width="600px" alt="Send test email modal with Sandbox unavailable and a profile selected" />

## アプリ内でアクセスを確認する \{#confirm-access-in-your-app\}

支払いが完了すると、サブスクリプションがユーザーのAdaptyプロファイルに反映され、アプリからアクセスレベルを確認できるようになります。

Adaptyはサンドボックス決済をサンドボックストランザクションとして記録します。アクセスレベルが見つからない場合を失敗と判断する前に、アクセスレベルがサンドボックストランザクションを受け入れる設定になっているか確認してください。

## 結果を確認する \{#check-the-result\}

[Profiles](mail-profiles) でテスト用プロファイルを開き、その[ジャーニー](mail-profiles#the-activity-journey)を確認してください。テストが成功した場合、最初のメールが **Clicked** に達し、購入がそのメールに紐付けられ、残りのシーケンスが **Cancelled** になっています。

:::note
Adapty Mail はトラッキングピクセルが読み込まれたときに開封を記録しますが、Apple Mail プライバシー保護は実際にメールが読まれたかどうかに関わらずピクセルを読み込みます。意図せず表示された **Opened** チップは正常な動作です。各指標の計算方法については、[キャンペーン分析](mail-analytics)をご参照ください。
:::
