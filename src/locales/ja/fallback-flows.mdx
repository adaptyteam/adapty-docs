スムーズなユーザー体験を維持するために、[フロー](adapty-flow-builder)の**フォールバックバージョン**を設定することが重要です。

アプリケーションがフローをリクエストすると、Adapty SDK はサーバーに接続してその設定を取得します。メインの Adapty API からフローを取得できない場合（ネットワークの問題やサーバーの障害など）、SDK は他のソースにフォールバックします。

- ユーザーが既にそのフローを一度表示している場合、SDK はキャッシュされたコピーを使用します。
- メインの Adapty API が応答しない場合、SDK はバックアップの Adapty サーバーにフローをリクエストします。
- どちらも機能しない場合、SDK はアプリにバンドルされたフォールバック設定ファイルを読み込みます。

:::important
バックアップサーバーとフォールバックファイルは、**All Users** オーディエンスのみを対象とし、セグメントは無視されます。プラットフォーム別にオーディエンスを分けている場合は、All Users フローに App Store と Google Play の両方の ID を持つプロダクトを使用してください。そうしないと、もう一方のストアのユーザー向けプロダクトがフォールバックフローに含まれません。
:::

Adapty はこれらのフォールバックファイルを自動的に生成します。フローのフォールバックバンドルはペイウォールと共有されており、プラットフォームごとに 1 つの JSON ファイルに両方のフォールバックバリアントが含まれています。SDK は必要なセクションを読み取ります。

:::important
フローのフォールバックは **Adapty SDK 4.0以上** のバンドルに含まれています。ダウンロードダイアログで以前のSDKバージョンを選択した場合、ファイルにはペイウォールとオンボーディングのバリエーションのみが含まれ、フローは含まれません。フローのフォールバックを使用する前に、アプリがフロー対応のSDKリリースを使用していることを確認してください。
:::

## 始める前に \{#before-you-start\}

1. フロー＆ペイウォールビルダーで[フロー](adapty-flow-builder)を作成します。
2. フロー用の[プレースメントを作成](create-placement)します。

## フォールバックファイルのダウンロード \{#download-the-fallback-file\}

1. **[Placements](https://app.adapty.io/placements)** ページを開きます。
2. 右上の **Fallbacks** ボタンをクリックします。
3. ドロップダウンからターゲットプラットフォームを選択します。
4. アプリで使用している Adapty SDK のバージョンに合ったオプション（例：**Adapty SDK v4.4.0 and higher**）を選択します。

ブラウザがプラットフォームごとに JSON ファイル（例：`ios_4_0_0_fallback.json`）をダウンロードします。

:::tip
ターミナルからファイルをダウンロードする場合は、[Developer CLI](developer-cli) を使用してください。アプリに組み込まれている Adapty SDK のバージョンを指定します：

```bash
adapty fallbacks get --app <app-id> --platform ios --sdk-version <sdk-version> --output ios_fallback.json
```

ストアごとに1回実行し、`--platform ios` または `--platform android` を指定してください。フラグの詳細は [`adapty fallbacks get`](developer-cli-fallbacks) を参照してください。
:::

## ダウンロード後の手順 \{#after-the-download\}

ファイルをアプリのコードに追加したら、プラットフォームごとのセットアップガイドに従ってください。ペイウォールのフォールバックを読み込むAPIは、フローに対応したSDKリリース以降、フローのフォールバックも同様に読み込みます。

- [iOS](ios-use-fallback-paywalls)
- [Android](android-use-fallback-paywalls)
- [React Native](react-native-use-fallback-paywalls)
- [Flutter](flutter-use-fallback-paywalls)
- [Unity](unity-use-fallback-paywalls)
- [Kotlin Multiplatform](kmp-use-fallback-paywalls)
- [Capacitor](capacitor-use-fallback-paywalls)

## 制限事項 \{#limitations\}

フォールバックフローはハードコードされてローカルに保存されるため、ライブフローの完全な動的機能は利用できません。

- **プレースメントごとに1つのオーディエンス。** プレースメントに複数の[オーディエンス](audience)がある場合、フォールバックファイルは **All users** オーディエンスのみを使用します。
- **ライブA/Bテストは対象外。** **All users** オーディエンスでA/Bテストが実行されている場合、ファイルにはテストのすべてのバリアントとその重みが含まれます。SDKはこの重みに基づいてユーザーをバリアントに振り分けます。テスト終了後にフォールバックを更新するには、ファイルを再度ダウンロードして新しいアプリリリースに追加してください。
- **クロスプレースメントA/BテストはA/Bテストは対象外。** フォールバックファイルには[クロスプレースメントA/Bテスト](ab-test-types)は含まれません。**All users** オーディエンスで実行中のものも含みます。このようなテストに含まれるプレースメントについては、ファイルにはプレースメントの通常の **All users** コンテンツ（フロー、または通常のA/Bテスト）が含まれます。
- **リモート更新は不可。** フォールバックを更新するには新しいアプリリリースが必要です。リモートコンフィグ経由で行う予定の実行時の更新は、ライブフローを通じて配信してください。
