growth-advisor スキルは、あなた自身のサブスクリプション数から「次に何をテストすべきか？」という問いに答えます。AI コーディングツールが [Adapty CLI](developer-cli-analytics) を通じてアナリティクス、プレースメント、ペイウォール、プロダクトを読み込み、最も大きなシグナルを追って原因を特定し、A/B テストすべき仮説のリストを購入数の影響度順に返します。

:::note
growth-advisor はあなたの確認なしにアカウントを変更しません。アナリティクスの読み込みはすべて読み取り専用で、新しいフローのコピー、新しいセグメント、A/B テスト、プレースメントの変更といった書き込み操作はいずれもあなたの承認を待ちます。
:::

## 始める前に \{#before-you-start\}

- **データが入ったAdaptyアカウント**: スキルは、ダッシュボードに表示されているのと同じ分析データを読み取ります。データがない場合は、開始プランを提示することしかできません。
- **ターミナルコマンドを実行できるAIツール**: 例えば、Claude Code、Codex、Copilot CLI、Gemini CLIなどです。claude.aiやChatGPTのようなチャットツールはCLIを実行できないため、Adaptyアカウントにアクセスできません。

## スキルをインストールする \{#install-the-skill\}

growth-advisor は [`adapty-skills` プラグイン](https://github.com/adaptyteam/adapty-skills)の一部です。

## 監査の仕組み \{#how-the-audit-works\}

特定の質問なしに「何をすべきか」を尋ねると、スキルが監査を実行します。数値とプレースメントの設定を読み取り、すでに試みた内容を把握したうえで、最も大きな変化をストア、チャネル、国、またはプレースメント単位まで追跡します。画面について何か述べる前に、ライブのフローを確認するか、アプリが独自に描画しているペイウォールのスクリーンショットを求めます。

## 返ってくる結果 \{#what-you-get-back\}

スキルは簡潔な回答の後、プレースメントごとにグループ化された仮説のリストをテストすべき順番で返します。各仮説には、アプリにそれが必要な理由、期待される結果とその根拠、A/B テストに必要な期間、そして誰が何をするかが記載されています。仮説はプレースメントの全ユーザーを対象にすることも、元サブスクリプションユーザーのような特定の[セグメント](segments)を対象にすることもできます。

## 仮説からA/B テストへ \{#from-hypothesis-to-ab-test\}

各仮説に対して、スキルはA/B テストを提案し、そのセットアップを代行します。実行前に、テストに必要なものがすべて揃っているか確認し、不足しているものとその担当者を明示します：

| テストに必要なもの | 誰が作るか |
|---|---|
| 変更されたフロー（新しいデザイン、コピー、またはプロダクトセット） | スキルは [flow-generator スキル](flow-generator-skill) を通じてフローのコピーを作成し、仮説ごとに1つの変更を加えます。これにより、その変更の効果をテストで確認できます。コピーを公開する前に、スキルは [flow-audit スキル](flow-audit-skill) でコピーをレビューするよう提案します。フローは公開後にのみテストに参加できます。 |
| 新しいプランの期間、トライアル、またはオファー | App Store Connect または Google Play Console でプロダクトを作成し、Adapty に追加します。App Store ではトライアルに新しいプロダクトが必要で、Google Play では既存のプランへのオファーになります。価格はあなたが設定します。 |
| すでに Adapty にあるプロダクトを使ったペイウォール | スキルが作成します。 |
| 新しいデザインのペイウォール | [ペイウォールビルダー](adapty-paywall-builder) で作成します。 |
| セグメント | スキルがオーディエンススキルを通じて作成します。 |
| 新しいプレースメント | スキルが開発者 ID を承認後に作成します。フェッチするにはアプリのコード変更とリリースが必要です。 |

スキルが作成する各パーツは、あなたの確認を待ちます。あなたが作成すべきパーツがある場合、スキルの **Next steps** リストにその旨が表示され、パーツの準備ができたと伝えるとスキルがテストをセットアップします。まだ存在しないパーツでテストをセットアップすることはありません。

すべてのパーツが揃ったら、[ab-tests スキル](ab-tests-skill)がテストをドラフトとして作成します。テストを開始する前に、誰が何を見るかを正確に示します。[A/B テスト](ab-tests)はデフォルトであり、変更の効果を測定する唯一の方法です。

テストなしで変更を表示するには、スキルに依頼してください。スキルは新しいプレースメントに表示するか、既存のプレースメントの一部またはすべてのユーザーに表示することができます。スキルが既存のプレースメントを変更する前に、プレースメントをファイルに保存するので、復元することができます。また、そのプレースメントで実行中の A/B テストがあれば名前を表示します。変更はそのテストには影響しません。

A/B テストが終了したら、どのバージョンが勝ったかをスキルに伝えてください。テストがまだ有効な場合、スキルはその勝者でテストを停止することを提案します。その後、次の仮説を提案します。

## 制限事項 \{#limits\}

- **価格分析は未対応**: このスキルは価格の読み取り・比較・提案を行いません。数値が価格を示している場合はその旨を伝え、価格分析は現時点では未対応であることを明示します。
- **A/B テスト結果は非対応**: このスキルはA/B テストの結果を読み取りません。同時期に並行して存在したペイウォールからテスト履歴を推測し、どのバージョンが勝ったかはユーザーに確認します。
- **広告費用は非対応**: このスキルはインストール数・トライアル数・収益をアトリビューションチャネル別に分割できますが、広告費用やROASは対象外です。それらについては [adapty-attribution スキル](developer-cli-attribution-skill) を使用してください。

スキルを使わずに自分でアナリティクスをクエリするには、[CLI アナリティクスリファレンス](developer-cli-analytics)を参照してください。ブラウザでログインできないサーバーや定期実行ジョブからアナリティクスを取得するには、シークレット API キーを使用した[エクスポートアナリティクス API](export-analytics-api)をご利用ください。
