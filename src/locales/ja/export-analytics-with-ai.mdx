growth-advisor スキルは、あなたのサブスクリプションのデータをもとに「次に何をテストすべきか？」という問いに答えます。AIコーディングツールがあなたのアナリティクス、価格設定、プレースメント、フロー、過去のA/Bテストを読み込み、ビジネスの各部分を市場と照らし合わせてスコアリングし、金銭的インパクトの大きい順に並べた仮説リストを提示します。仮説を選ぶと、スキルがA/Bテストに必要なものを構築し、テストをセットアップします。

:::note
growth-advisorはあなたの確認なしにアカウントを変更しません。すべての読み取り操作は読み取り専用であり、フローのコピー、セグメント、プロダクト、価格、A/Bテスト、プレースメントの変更など、すべての書き込み操作はあなたの確認を待ちます。
:::

## 始める前に \{#before-you-start\}

- **データを持つ Adapty アカウント**: このスキルはダッシュボードに表示されるのと同じアナリティクスを読み取ります。データがない場合は出発点となるプランを提示します。アカウントがない場合は、あなたが送った情報をもとに動作します（[Adapty アカウントなしの場合](#without-an-adapty-account)を参照）。
- **Adapty アカウントにアクセスできる AI ツール**: このスキルは [Adapty CLI](developer-cli-analytics) または [Adapty MCP サーバー](adapty-mcp) を通じて動作します。監査はその CLI を通じて読み取りを行うため、CLI の方が適しています。Claude Code、Codex、Copilot CLI、Gemini CLI、または [CLI を設定した後](developer-cli-cowork)の Claude アプリを使用できます。MCP のみの場合、スキルは CLI のセットアップを提案し、断った場合は実行できなかった読み取り項目を列挙します。

## 監査の仕組み \{#how-the-audit-works\}

特定の質問なしに「何をすべきか」と尋ねると、スキルは監査を実行します。直近の変化だけでなく、過去6か月のビジネス全体を分析します。ずっと低迷している部分は、最近の一時的な落ち込みよりもコストがかかるからです。

1. **アプリの収益構造**: スキルは収益をもたらすストア、メインマーケット、収益上位のプロダクト、各プレースメントの現在の表示内容を特定します。
2. **これまでの試み**: スキルはペイウォールとフローの過去のA/B テストを日時・オーディエンス・結果とともにリストアップし、テストなしで並行稼働していたペイウォールも検出します。テスト履歴を手入力する必要はありません。回答が事実として記載するので、誤りがあれば修正するだけです。
3. **スコアカード**: スキルはビジネスの各部分を「強い」「標準的」「弱い」の3段階で評価します。収益源、インストールから課金までのファネル、プランの構成、更新率、返金率、プレースメントの設定を対象とします。コンバージョンはAdaptyの「State of Paywalls 2026」に基づくプラン・地域・カテゴリ別の市場グリッドと比較して評価され、更新率と返金率は「State of In-App Subscriptions 2026」と照合されます。弱い部分は月間の影響額の大きい順にランク付けされます。
4. **原因の特定**: スキルは最も大きなシグナルをストア・アトリビューションチャネル・プランの長さ・国・週単位で分解し、一つのグループで説明できるまで掘り下げます。トラフィックや特定の変更を原因と判断する前に、他の考えられる原因を検証します。
5. **画面の確認**: 画面について何かを述べる前に、スキルはライブのフローをレンダリングし、フローの場合はそのファネルを読み込んでユーザーが離脱する画面を特定します。アプリ側で描画するペイウォールにはスクリーンショットが必要です。監査で必要なスクリーンショットは **Send me screenshots** の下にリストアップされ、それぞれがどの仮説の検証に使われるかが示されます。

## 返ってくる内容 \{#what-you-get-back\}

スキルは短い回答とスコアカードを返した後、プレースメントごとにグループ化された仮説のリストを優先順位順に提示します。各仮説には、アプリにとってそれが必要な理由、期待される結果とその根拠、月間ドル換算での変更の価値、現在の購入ボリュームに基づいた A/B テストの所要期間、そして担当者の役割が含まれています。仮説はプレースメント全体を対象にする場合と、過去のサブスクリプション解約者などの特定の[セグメント](segments)を対象にする場合があります。

## 価格 \{#prices\}

このスキルは、各プロダクトがすべての国とストアでいくら請求されているかを現地通貨で読み取ります。次に、各価格をAdaptyの「State of In-App Subscriptions」レポートの価格インデックスと照合します。このインデックスには、22か国におけるあなたのカテゴリとプランの10〜90パーセンタイルが含まれています。それ以外の国については、地域全体または各国の過去データと比較します。

これをもとに、スキルは以下の価格仮説を他の仮説と同じリストで提案できます：

- **主要市場のメインプランの基本価格を引き上げる、または引き下げる。**
- **メイン市場と乖離している1カ国の価格を引き上げる、または引き下げる。** 1市場のギャップに対応する場合、スキルはまずペイウォールがその市場の言語になっているかを確認します。
- **年間プランが週次・月次プランに対して高すぎる、または安すぎる場合に、プランの段階構成を変更する。**

このスキルは、米国、英国、ドイツ、日本などのTier-1市場に限って値上げを提案します。Adaptyが保有するA/Bテストのデータライブラリでは、それ以外の市場で同様の値上げが効果を上げられなかったためです。新しい価格は現在のストア価格を起点とし、€38.99のような購入者が受け入れやすい価格帯に設定されます。このスキルは競合他社の価格を参照しません。

A/B テストはプロダクトのコピーに対して実行され、本番のプロダクトには影響しません。スキルはコピーを作成してストアに追加し、価格を設定し、そのコピーを販売するフローのコピーを作成し、国セグメントと A/B テストをセットアップします。勝利した価格は元のプロダクトに適用されます。既存のサブスクライバーは、移行を依頼しない限り現在の価格が維持されます。

テストなしで本番の価格を変更したい場合は、その旨を伝えてください。スキルは現在の価格をファイルに保存してリストアできるようにし、新しい価格をプレビューしたうえで、各ストアへの反映タイミングを通知します。

:::warning
価格を読み取れるのは、Adaptyに接続されたストアのみです。App Storeでは、In-App Purchase キーだけでなく、[App Store Connect APIキー](app-store-connection-configuration)が必要です。
:::

## 仮説からA/B テストへ \{#from-hypothesis-to-ab-test\}

各仮説に対して、スキルはA/B テストを提案し、そのセットアップを代行します。実行前に、テストに必要なものがすべて揃っているか確認し、不足しているものとその担当者を明示します：

| テストに必要なもの | 担当 |
|---|---|
| フローの変更（新しいデザイン、コピー、またはプロダクトセット） | スキルは [flow-generator スキル](flow-generator-skill) を通じてフローのコピーを作成します。仮説ごとに1つの変更を加えることで、その変更の効果がテストで明確になります。コピーを公開する前に、スキルは [flow-audit スキル](flow-audit-skill) でレビューを提案します。フローはいったん公開されてからテストに参加します。 |
| 新しいプラン期間 | スキルはプロダクトを作成し、ストアのプロダクト ID と USD 価格を確認後、App Store Connect および Google Play Console にプッシュします。 |
| 価格テスト用のプロダクトのコピー | スキルがコピーを作成してプッシュし、価格を設定します。新しいストアプロダクト ID を承認するのはあなたです。 |
| トライアルまたはオファー | App Store Connect または Google Play Console で作成してください。App Store ではトライアルに新しいプロダクトが必要で、Google Play では既存プランへのオファーとして追加します。ストアのオファー ID をスキルに渡すと、スキルが Adapty のプロダクトにオファーを追加します。 |
| Adapty に既存のプロダクトを使ったペイウォール | スキルが作成します。 |
| 新しいデザインのペイウォール | [ペイウォールビルダー](adapty-paywall-builder) で作成してください。 |
| セグメント | スキルはオーディエンススキルを通じて作成します。 |
| 新しいプレースメント | デベロッパー ID を承認後、スキルが作成します。フェッチするにはアプリのコード変更とリリースが必要です。 |

スキルが作成する各パーツは、あなたの確認を待ちます。あなたが作成すべきパーツがある場合、スキルの **Next steps** リストにその旨が表示され、パーツの準備ができたと伝えるとスキルがテストをセットアップします。まだ存在しないパーツでテストをセットアップすることはありません。

すべてのパーツが揃ったら、[ab-tests スキル](ab-tests-skill)がテストをドラフトとして作成します。テストを開始する前に、誰が何を見るかを正確に示します。[A/B テスト](ab-tests)はデフォルトであり、変更の効果を測定する唯一の方法です。

テストなしで変更を表示するには、その旨を伝えてください。スキルは新しいプレースメントに表示するか、既存のプレースメントの一部またはすべてのユーザーに表示することができます。スキルが既存のプレースメントを変更する前に、復元できるようにプレースメントをファイルに保存します。また、そのプレースメントで実行中のA/Bテストの名前も記録します。変更はそのテストには影響しません。

## A/B テストが終了したとき \{#when-an-ab-test-ends\}

テストが終了したことをスキルに伝えると、スキルはそのテストを見つけ、各バリアントの収益と「ベストである確率」を表示し、どのバリアントが勝者かを確認します。リードしているバリアントは、あなたが宣言するまで勝者ではありません。各バリアントの購入数が約 200 件に満たない場合、テストはまだ収束していません。テストがまだ進行中の場合、スキルは勝者を指定してテストを停止するか確認し、そのプレースメントに対する次の仮説を提案します。

テスト実行中、スキルは各バリアントが約 200 件の購入数までどれだけ離れているかを伝えるのみで、どちらがリードしているかは表示しません。

## Adapty アカウントなしで \{#without-an-adapty-account\}

App Store や Google Play のリンク、アプリのコード、またはオンボーディングとペイウォールのスクリーンショットを送り、収益を増やす方法を聞いてみましょう。スキルは、送信した内容、市場の中央値、Adapty の A/B テストライブラリをもとに、完全な回答を提供します。

- **ストアのリンク**: スキルはカテゴリー、アプリ内課金リストのサブスクリプション、対応言語、そして支払いに関するレビューの内容を読み取ります。
- **スクリーンショット**: スキルはプランの期間、あらかじめ選択されているプラン、トライアル、購入ボタンを読み取ります。
- **アプリのコード**: スキルはプロダクトID、ペイウォールとオンボーディングの画面、すべてのロケールのコピー、そしてペイウォールが開くその他の場所を読み取ります。

このスキルは、paywall-teardown および onboarding-teardown スキルを使って各画面をレビューします。価格とコンバージョンには実際の数値が必要なため、最後の「次のステップ」ではアプリへの Adapty のセットアップを提案します。セットアップが完了すると、次の回答は実際のデータをもとに実行されます。

## 制限 \{#limits\}

- **広告費は対象外**: このスキルはアトリビューションチャネル別にインストール数、トライアル数、収益を分析できますが、広告費やROASは対象外です。それらには [adapty-attribution スキル](developer-cli-attribution-skill)を使用してください。
- **一部のテストタイプは結果非対応**: このスキルは通常のペイウォールおよびフローのA/B テスト結果を読み取れます。複数プレースメントをまたぐテストやオンボーディングのテストについては、テスト名のみを返すため、ダッシュボードで結果を確認する必要があります。
- **カテゴリ情報なし**: アプリのカテゴリはAdaptyのデータには含まれていません。スキルはアプリ名とペイウォールからカテゴリを推測し、使用したカテゴリを明示するので、必要に応じて修正できます。

スキルを使わずに自分でアナリティクスをクエリするには、[CLI アナリティクスリファレンス](developer-cli-analytics)を参照してください。ブラウザでログインできないサーバーや定期実行ジョブからアナリティクスを取得するには、シークレット API キーを使用した[エクスポートアナリティクス API](export-analytics-api)をご利用ください。
