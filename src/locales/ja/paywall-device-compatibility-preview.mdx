フローをさまざまな画面タイプでプレビューする方法は2つあります：
- **デバイスでプレビュー**：開発のどの段階でも、実際のデバイスでフローの見た目を確認できます。
- **Adapty ダッシュボードでプレビュー**：デザイン中にフローをプレビューできます。

## 実機でプレビューする \{#preview-on-devices\}

実際のデバイスでフローをプレビューするには：

1. [iOS](https://apps.apple.com/us/app/adapty/id6739359219) または [Android](https://play.google.com/store/apps/details?id=io.adapty.dashboard) 向けの Adapty モバイルアプリをダウンロードし、ダッシュボードで使用している Adapty アカウントでサインインします。
2. Flow & Paywall Builder で **Test on device** をクリックします。

<ZoomImage id="flow-test-on-device.webp" width="700px" alt="Test on device button in the Flow & Paywall Builder" />

3. フローのロケールを選択します。
4. デバイスのカメラでQRコードをスキャンするか、リンクを開きます。これにより、Adapty モバイルアプリでフローが開きます。

:::note
Adaptyモバイルアプリのフロープレビューは、ストア内のプロダクトにアクセスできないため、サンプル価格を表示します。また、[カスタムタグ](flow-custom-tags)の値も渡されないため、各タグの初期値が表示されます。アプリコードを実行できないため、各[カスタム要素](flow-custom-elements)のネイティブビューではなくフォールバックが表示されます。ネイティブビューを確認するには、[アプリのビルドでフローを開いてください](flow-custom-elements#publish-and-test)。
:::

<ZoomImage id="flow-test-on-device-qr.webp" width="400px" alt="Locale selector and QR code in the Test on device dialog" />

プレビューでは実際の購入はできません。[購入結果のアクション](respond-to-purchase-outcomes)をテストするには、アプリのビルドで[サンドボックス購入](test-purchases-in-sandbox)を行ってください。

### トラブルシューティング \{#troubleshooting\}

フローのプレビューが開かない場合、原因として多いのは、未完了のアクション、空のスクリーン、またはプロダクトが紐付けられていないケースです。詳しいリストは[よくある問題](flow-common-issues#a-flow-wont-preview-or-publish)をご覧ください。

HTTP 401 エラーでプレビューが失敗する場合は、Adapty モバイルアプリにサインインしていません。ダッシュボードで使用している Adapty アカウントでサインインしてから、QR コードを再スキャンしてください。

## Adapty ダッシュボードでプレビューする \{#preview-in-the-adapty-dashboard\}

:::tip
フローを公開する前に、[実機でプレビュー](#preview-on-devices)してエラーなく表示されることを確認しましょう。
:::

Flow & Paywall Builder のプレビューエリアを使って、さまざまな画面タイプでフローをプレビューできます。これにより、各種デバイスや画面サイズでフローが正しく表示されるかを確認できます。

プレビュー下部のコントロールを使うと、次のことができます：
- プレビューするデバイスを選択する。
- 横向きと縦向きのプレビューモードを切り替える。
- ライトモードとダークモードを切り替える。
- ロケールを切り替える。

:::tip
- 言語によって文字の長さが異なり、画面レイアウトに影響することがあるため、必ず複数のロケールでプレビューしてください。
- 条件が[プラットフォーム](onboarding-element-visibility#show-an-element-on-one-platform-only)を参照している場合は、iOS デバイスと Android デバイスの両方でプレビューしてください。キャンバスは、選択中のデバイスのプラットフォームに応じて条件を評価します。
- iOS アプリの場合は、[1 つのレイアウトで両方のディスプレイに対応する必要がある](iphone-duo-support#design-one-layout-to-fit-both-displays)ため、**iPhone Duo** の閉じた状態と開いた状態の両方でプレビューしてください。
- ビルダーのプレビューエリアでは、各カスタム変数には初期値が表示されます（例：`name` 変数の場合は `Jane Doe`）。[カスタムタグ](flow-custom-tags)の場合は、サンプルデータを入力しないでください。アプリが値を渡さなかった場合、ユーザーにはその初期値がフォールバックとして表示されます。「Welcome back, friend!」の `friend` のように、すべてのユーザーに適した言葉を入力してください。
:::

### プロダクトとオファーのプレビュー \{#preview-products-and-offers\}

プレビューは、Adapty カタログから[プロダクト変数](onboarding-variables#product-variables)を読み込みますが、これはデバイスが解決する内容の一部のみをカバーしています。

- `prod_title` は Adapty に保存されているプロダクトのタイトルを表示します。`prod_price` と `prod_price_per_*` 変数は Adapty に保存されている価格を米ドルで表示しますが、ユーザーにはストアのローカライズされた価格が表示されます。
- `offer_price`、`offer_billing_period`、`offer_full_duration`、`offer_price_per_*` 変数、および `intro_*` 変数は解決されないため、プレビューには変数名が波括弧付きで表示されます（例: `{{products.selectedProduct.offer_price}}`）。これらの値は、SDK がアプリ内でフローをレンダリングするときに渡されます。
- `is_free_trial`、`is_pay_up_front`、`is_pay_as_you_go`、および `has_intro_price` は、プロダクトカードで選択されたオファーに従います。オファーがない場合、4 つすべてが `false` になります。オファーがある場合、プレビューはそれを従量課金として扱うため、`has_intro_price` が `true` になります。

オファータイプに関する条件はプレビューで切り替わりますが、デフォルトでは「Pay as you go（従量払い）」ブランチのみ表示されます。他のブランチを確認するには、支払いモードをシミュレートしてください。

1. キャンバス上で、オファーが設定されたプロダクトカードを選択します。
2. 右パネルの **Product** の下にあるオファードロップダウンを開きます。
3. **Preview as** の下で **Free trial**、**Pay up front**、または **Pay as you go** を選択します。この設定は現在のカードにのみ適用されます。
