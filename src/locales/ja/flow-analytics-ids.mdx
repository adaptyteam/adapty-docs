Adapty SDK はすべての画面表示とすべての回答をアプリに報告します。各イベントには、発生元の画面や要素の ID が含まれており、その ID がご自身のアナリティクスに表示されます。デフォルトでは画面の ID は `scr_oAPBHPa7` のような形式になるため、Amplitude や Mixpanel のファネルはコードの羅列になってしまい、コードと名前の対応表を手動で管理しなければなりません。

これらの ID は自分で名前を付けることができます。入力フィールドや選択グループはフローBuilder で命名します。画面 ID は [flow-generator スキル](flow-generator-skill) を通じて設定し、フロー内でその画面が参照されているすべての箇所で名前が変更されます。

:::important
スクリーン名の変更はフロージェネレータースキルの一部なので、追加のインストールは不要です。[フロージェネレーターのインストール手順](flow-generator-skill#install-the-skill)に従うだけで使えます。ダッシュボードのフローに変更を保存するため、まず下書きで実行し、公開する前にペイウォールビルダーで結果を確認してください。
:::

## 用途 \{#what-its-for\}

- **チームが読めるファネル**: `welcome → signup → paywall` というシーケンスを見れば何が起きたかが分かります。自動生成されたコードが3つ並んでいても伝わりません。
- **自社ツール全体で共通の語彙**: アプリが転送するすべてのイベントが同じ方法でスクリーンに名前を付けるため、ファネル、コホート、ダッシュボードフィルターがルックアップテーブルなしで一致します。
- **クエリできる回答**: `beginner` という名前のクイズ選択肢は、アナリストがフィルタリングできる値です。自動生成されたIDは先に解読する必要があります。

## アナリティクスで確認できるID \{#which-ids-your-analytics-sees\}

2つのイベントにIDが含まれています。[`flow_screen_showed`](ios-flow-screen-views) はユーザーが画面を開いたときに発火し、[`flow_user_input`](ios-flow-input) はユーザーが入力を行ったとき、クイズの回答を選択したとき、またはトグルを切り替えたときに発火します。[Number picker](builder-number-picker) の場合、`flow_user_input` はユーザーが別の画面を開くボタンをタップしたときに発火します。各ガイドにはイベントのすべてのパラメーターが記載されています。この表は、画面や要素を識別するパラメーターのみを対象としています。

| イベントパラメータ | 内容 | 設定場所 |
| :--- | :--- | :--- |
| `instanceId` | 画面のID | フロージェネレータースキル |
| `element_id` | 入力欄の **Element ID**、またはセレクタブルグループの **Group ID** | Flow Builder |
| `item_ids` | 選択されたオプションの **Element ID** | Flow Builder |

## 入力欄とクイズオプションの名前設定 \{#name-inputs-and-quiz-options\}

入力欄と選択可能なグループには、ビルダー上でIDフィールドが設定できます。入力欄の **Element ID** は **Input Settings** に、日付・時刻・[数値ピッカー](builder-number-picker)の場合は **Picker Settings** に表示されます。**Element ID** は、フロー内の他の場所でその値を参照するときに使うIDと同じです。詳しくは[入力欄とフォーム](builder-inputs-and-forms)を参照してください。グループの **Group ID** は **Screen settings > Selectable groups** にあり、グループ内の各オプションにはそれぞれ独自の **Element ID** を設定します。

すべての要素に、単体で意味が通る名前を付けましょう。アナリティクスに表示される文字列だからです。`birthday` や `beginner` はそのままで意味が伝わります。`el_024F` にはマッピングが必要です。

要素を追加するときにIDを設定してください。後からでは遅れます。入力の **Element ID** を変更すると、ビルダーはそのIDを使っているすべての条件と変数を更新します。クイズオプションの **Element ID** を変更すると、[古いIDと比較していた条件がマッチしなくなります](flow-common-issues#a-condition-stops-matching-after-you-change-the-element-id-of-a-quiz-option)。

flow-generator スキルは、作成するすべてのフローに対してこれらを自動的に命名します。[flow-audit スキル](flow-audit-skill)は、不足しているものを報告します。

## スクリーンの名前を変更する \{#rename-screens\}

フロービルダーにはスクリーンのIDを入力するフィールドがないため、スキルに依頼します：

```
Give the screens in my onboarding flow readable IDs.
```

スキルは各スクリーンの名前を提案し、フロー内でそのスクリーンを参照しているすべての箇所を一括で変更します。スクリーン自体、そこへ誘導するすべてのナビゲーションアクション、およびそれに紐付くプロダクトも含めて、まとめて変更します。一部だけ変更されたスクリーン名はフローを公開不能にしてしまうため、必ずすべて同時に変更します。

これにより、変更されたスクリーン名と移動されたリファレンスの数が表示されます。また、既存のスクリーンと名前が衝突するリネームは実行されません。スクリーン ID は、すでに動作しているフローでも安全にリネームできますが、エレメント ID はそうではありません。エレメント ID をリネームすると、すべてのリファレンスが一緒に移動します。

## 確認すべき内容 \{#what-to-check\}

- **フローが公開される前にリネームする**: すでに収集済みのイベントは古いIDを保持します。変更をまたぐファネルでは、2つの半分しか埋まっていない画面が表示され、元の名前に戻しても統合されません。AdaptyのフローメトリクスもIDで画面行をグループ化するため、同様に分割されます。リネームされた画面は同じラベルで2行目として追加されます。
- **グループ内のすべてのオプションに独自のElement IDが必要**: オプションのIDが欠けている場合、2つのオプションで同じIDを共有している場合、または **Group ID** が別の画面で再利用されている場合、オプション単体だけでなくグループ全体のレポートが機能しなくなります。ビルダー上では何もフラグを立てないため、オプションを追加した後はグループを確認してください。
- **IDはアナリティクスに入力したとおりに届く**: `plan_selection` や `planSelection` のようにスタイルを統一し、フロー全体で一貫して使用してください。スタイルが混在していると、生成されたコードよりもクエリが難しくなります。

## 制限事項 \{#limitations\}

- **スクリーン ID はスキルを通じてのみ変更可能**: フロービルダーにはそのためのフィールドがありません。
- **Adapty のフロー指標にはこれらの名前が表示されません**: [フロー指標](flow-metrics)では、フローの公開バージョンに基づいてスクリーンに `<position>. <caption>` というラベルが付与されるため、スクリーンの ID に関わらず `9. Paywall A` のように表示されます。ここでの ID は自社のアナリティクスにのみ反映されます。
- **名前の変更は履歴を移行しません**: 古いイベントは古い ID のまま保持されます。
- **一部の要素は入力イベントを送信しません**: パスワードフィールド、プロダクト選択、タブの切り替えはレポートされません。これらに名前を付けてもフローに影響するだけで、アナリティクスには反映されません。
