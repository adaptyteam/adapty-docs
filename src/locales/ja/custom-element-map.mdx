このレシピに従って、フローにインタラクティブなマップを組み込みましょう。アプリは[カスタム要素](flow-custom-elements)内でネイティブの MapKit ビューとしてマップをレンダリングします。フロースクリーンで位置情報へのアクセスをリクエストします。

:::tip
このレシピは iOS アプリのみを対象としています。他のフレームワークで構築されたアプリでは、カスタム要素の[フォールバックコンテンツ](flow-custom-elements#set-fallback-content)のみが表示されます。Android およびクロスプラットフォームフレームワークのサポートは近日対応予定です。
:::

## 始める前に \{#before-you-start\}

- アプリを Adapty iOS SDK 4.4 以降にアップデートしてください。それより古いバージョンの SDK では、すべてのカスタム要素に[フォールバックコンテンツ](flow-custom-elements#set-fallback-content)が表示されます。
- アプリでフローを[取得](get-pb-paywalls)および[表示](ios-present-paywalls)できるよう設定してください。
- ユーザーに位置情報へのアクセスを許可してもらうには、アプリの `Info.plist` ファイルに `NSLocationWhenInUseUsageDescription` キーを追加してください。その値には、「お近くのフィットネスセンターを探しましょう。」などのプロンプトのテキストを設定してください。

## 1. カスタム要素を画面に追加する \{#1-add-the-custom-element-to-the-screen\}

フロー & ペイウォールビルダーで、フロー画面に[カスタム要素を追加](flow-custom-elements#add-and-configure)し、マップ用に設定します。

- **Type**: `map`
- **ID**: `fitness_centers`
- **Height**: デフォルトの **Fixed** 高さを維持します。マップはカスタム要素いっぱいに広がります。

カスタム要素は、カルーセルのようなタッチ操作に反応するコンテナの中には配置しないでください。そうしないと、マップ上のドラッグ操作がカルーセルも動かしてしまいます。

カスタム要素の内部に、地図の画像を使った [**Image**](custom-media#image) を追加してください。次の場合、ユーザーにはこの画像が[フォールバック](flow-custom-elements#set-fallback-content)として表示されます：

- ユーザーのアプリバージョンが地図を表示できない場合
- 画面が開く前に位置情報へのアクセスを拒否していた場合
- iOS 16 のデバイスを使用している場合

ユーザーがまだ位置情報のアクセス許可プロンプトに回答していない場合、地図が表示されたときに iOS がプロンプトを表示します。アプリが位置情報を必要とする理由をユーザーに伝えるため、カスタム要素の上にテキスト要素（例：「近くのフィットネスセンターを探す」）を追加してください。

## 2. マップビューを作成する \{#2-create-the-map-view\}

ロケーションアクセスのモデルと、マップを含む SwiftUI ビューを作成します。このビューはロケーションアクセスをリクエストし、ユーザーから半径 2 km 以内のフィットネスセンターを検索して、それぞれにマーカーを表示します。

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift"

// One location manager for the resolver and the map view
@MainActor
final class LocationAccess: NSObject, ObservableObject, CLLocationManagerDelegate {
    @Published private(set) var status: CLAuthorizationStatus = .notDetermined
    var isMapOnScreen = false
    private let manager = CLLocationManager()

    var isDenied: Bool { status == .denied || status == .restricted }

    override init() {
        super.init()
        manager.delegate = self
        status = manager.authorizationStatus
    }

    // Shows the prompt only if the user hasn't answered it yet
    func requestAccess() {
        manager.requestWhenInUseAuthorization()
    }

    nonisolated func locationManagerDidChangeAuthorization(_ manager: CLLocationManager) {
        let status = manager.authorizationStatus
        Task { @MainActor in self.status = status }
    }
}

@available(iOS 17.0, *)
struct NearbyFitnessCentersMap: View {
    @ObservedObject var access: LocationAccess
    @State private var position: MapCameraPosition = .userLocation(fallback: .automatic)
    @State private var places: [MKMapItem] = []

    var body: some View {
        ZStack {
            if access.isDenied {
                ContentUnavailableView(
                    "Location access is off",
                    systemImage: "location.slash",
                    description: Text("To see fitness centers near you, allow location access in Settings.")
                )
            } else {
                Map(position: $position) {
                    UserAnnotation()
                    ForEach(places, id: \.self) { place in
                        Marker(item: place)
                    }
                }
                .task {
                    access.requestAccess()
                    do {
                        for try await update in CLLocationUpdate.liveUpdates() {
                            guard let location = update.location else { continue }
                            places = try await fitnessCenters(around: location.coordinate)
                            withAnimation {
                                position = .automatic // zoom to fit the user and the places
                            }
                            break
                        }
                    } catch {
                        // the map still shows the location of the user
                    }
                }
            }
        }
        // Tells the resolver that the map is on the screen
        .onAppear { access.isMapOnScreen = true }
        .onDisappear { access.isMapOnScreen = false }
    }

    private func fitnessCenters(around center: CLLocationCoordinate2D) async throws -> [MKMapItem] {
        let request = MKLocalPointsOfInterestRequest(center: center, radius: 2_000) // meters
        request.pointOfInterestFilter = MKPointOfInterestFilter(including: [.fitnessCenter])
        return try await MKLocalSearch(request: request).start().mapItems
    }
}
```

</TabItem>
</Tabs>

マップビューにはiOS 17以降が必要です。iOS 16では、フォールバックが表示されます。ユーザーが画面で位置情報へのアクセスを拒否した場合、マップの代わりにSettingsでアクセスを許可する方法を説明するメッセージが表示されます。

## 3. カスタム要素にマップを対応付ける \{#3-match-the-map-to-the-custom-element\}

[アプリ全体のリゾルバー](ios-flow-custom-elements#set-an-app-wide-resolver)に、`LocationAccess` モデルのプロパティを追加します。次に、`map` タイプと `fitness_centers` ID に対してマップビューを返すケースを追加します。ハイライトされた行が追加箇所です。アプリにまだアプリ全体の[リゾルバー](ios-flow-custom-elements#write-a-resolver-to-match-custom-elements-and-views)がない場合は、コード全体をコピーしてください：

<Tabs groupId="current-os" queryString>
<TabItem value="ios" label="iOS" default>

```swift showLineNumbers title="Swift" {5,13-20}

struct CustomElementsResolver: AdaptyUICustomElementsResolver {
    let locationAccess = LocationAccess()

    func view(
        forType type: String,
        id: String,
        context: AdaptyUICustomElementContext
    ) -> AnyView? {
        switch type {
        case "map" where id == "fitness_centers":
            guard #available(iOS 17.0, *) else {
                return nil // iOS 16: show the fallback
            }
            if locationAccess.isDenied, !locationAccess.isMapOnScreen {
                return nil // access denied before the screen opened: show the fallback
            }
            return AnyView(NearbyFitnessCentersMap(access: locationAccess))
        // the other cases of your resolver
        default:
            return nil
        }
    }
}
```

</TabItem>
</Tabs>

SDKは、画面が開いたとき、また画面が開いている間（プロダクトの読み込み時など）にリゾルバーを呼び出します。ロケーションへのアクセス状況によって、各呼び出し時にリゾルバーが返す値が決まります。

- **未回答**: マップビュー。ビューがアクセスを要求できるようにするため。
- **許可済み**: マップビュー。ユーザーの近くにあるフィットネスセンターを表示します。
- **画面が開く前に拒否済み**: `nil`。ユーザーに設定に関するメッセージではなくフォールバックが表示されます。
- **画面上で拒否済み**: マップビュー。ビューが画面に表示されている間は `isMapOnScreen` を設定するためです。ここでリゾルバーが `nil` を返した場合、SDK は次の呼び出し時に設定に関するメッセージをフォールバックに置き換えます。

アプリ全体のリゾルバーをまだ設定していない場合は、アプリ起動時などに `AdaptyUI.setCustomElementsResolver(_:)` を一度呼び出してください。

<TabItem value="ios" label="iOS" default>

## 4. デバイスでテストする \{#test-on-a-device\}

フロー & ペイウォールビルダーはアプリのコードを実行できないため、キャンバスにはフォールバックのみが表示されます。マップをプレビューするには:

1. [フローを公開します](builder-save-publish)。キャッシュされたバージョンではなく最新の公開バージョンを確認するには、デバイスを[テストデバイス](test-devices)として登録してください。
2. リゾルバーを含むアプリのビルドを iOS 17 以降で実行します。画面を開き、位置情報へのアクセスを許可してください。マップにあなたの現在地と近くのフィットネスセンターのマーカーが表示されることを確認します。

フォールバックをテストするには、位置情報へのアクセスを拒否します。**設定**アプリで **プライバシーとセキュリティ** > **位置情報サービス** > *お使いのアプリ* の順に進み、**しない** を選択してください。その後、画面を再度開いてください。

マップの代わりにフォールバックが表示される理由を調べるには、iOSガイドの[デバイスでテストする](ios-flow-custom-elements#test-on-a-device)セクションの手順に従ってください。
