インタラクティブなフロー要素は、ユーザーの操作に応じて外観が変化します。タップしたクイズの選択肢は **Selected** になり、フォーカスされた入力欄は **Active** になります。条件によって切り替わる状態もあります。ボタンを**無効化**したり、独自の名前と条件を持つ[カスタム状態](#custom-states)を追加したりできます。アプリのコードを書かずに、各状態のスタイルを個別に設定してユーザーに視覚的なフィードバックを提供しましょう。

## 要素の種類別で利用可能な状態 \{#available-states-by-element-kind\}

| 要素の種類 | 組み込みの状態 | 追加可能な状態 |
|---|---|---|
| [選択可能な要素](#selectable-element-states) | **Default**、**Selected** | **Disabled**、[カスタム状態](#custom-states) |
| [入力](#input-states) | **Default**、**Active**、**Invalid** | **Disabled**；テキスト、メール、パスワード、数値、電話番号入力での[カスタム状態](#custom-states) |
| [タップインタラクションを持つ任意の要素](#condition-driven-disabled-state)（ボタン、画像、アイコン、コンテナなど） | **Default** | **Disabled**、[対応要素](#elements-that-support-custom-states)での[カスタム状態](#custom-states) |
| [プログレスインジケーターのステップ](#step-states-for-progress-indicators) | **Completed**、**Current**、**Upcoming** | — |

**追加可能**な状態はデフォルトでは表示されません。**States settings** <Inline id="settings.svg" alt="Settings" /> を開いて追加してください。これらは条件駆動型です。つまり、いつ有効化されるかを自分で定義します。詳細は[条件駆動型のDisabled状態](#condition-driven-disabled-state)と[カスタム状態](#custom-states)を参照してください。

他の要素の条件も要素の状態を評価できます。たとえば、[ボタンが無効な理由を説明する](element-states-in-conditions#explain-why-a-button-is-disabled)こともできます。

## 複数の状態が1つの要素に適用される場合 \{#when-several-states-apply-to-one-element\}

複数の状態が1つの要素に同時に適用されることがあります。例えば：

- ユーザーがメールフィールドに無効なアドレスを入力し、修正するためにそのフィールドをタップします。フィールドにフォーカスがあるため、**Active** が適用されます。アドレスはまだ無効なので、**Invalid** も適用されます。
- ユーザーがトライアルトグルをオンにすると、**Selected** が適用されます。その後、トライアルなしのプランを選択します。そのプランではトグルに **Disabled** 条件が設定されているため、**Disabled** も適用されます。
- **Continue** ボタンに **Disabled** 状態と **Locked** というカスタム状態があります。両方の条件が真なので、両方の状態が適用されます。

要素は常に1つの状態にのみあります。複数の状態が該当する場合、要素はこのリストで最後に来る状態になります：

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. [カスタム状態](#custom-states)

複数のカスタム状態が該当する場合、要素は **States** 設定リストで最後に来るカスタム状態になります。

この例では、メールフィールドが **Active**、トライアルのトグルが **Disabled**、**Continue** ボタンが **Locked** になっています。各要素は、そのステートに対してスタイリングした通りの外観で表示されます。要素のステートを評価する条件は、そのステートに一致する場合のみ適用されます。いずれのステートも該当しない場合、要素は **Default** になります。

カスタムステートは要素の見た目を変えるだけです。**Disabled** の要素は、カスタムステートによって見た目が変わっても、タップを無視する動作はそのまま維持されます。

## 状態のスタイルを設定する方法 \{#how-to-style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="選択した要素の右パネルにある States セクション" float="right" />


1. 要素を選択します。右パネルの **States** セクションに、その要素がサポートする状態が一覧表示されます。
2. **States** セクションで対象の状態を有効にします。必要に応じて、[条件ベースの Disabled 状態](#condition-driven-disabled-state)または[カスタム状態](#custom-states)を追加します。
3. 塗りつぶし、ボーダー、タイポグラフィなどのプロパティを変更します。変更はその状態のみに適用されます。

    ネストされた要素は親と一緒にステートフルになります。子への変更は、親のアクティブな状態にスコープされます。

4. ビルダーは実行時に一致するスタイルを適用します。

## 選択可能な要素のステート \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Selectable element with Selected state activated and a style override applied" />

クイズのオプション、プロダクト、タブ、トグルとチェックボックス、そして[カスタムの選択可能な要素](flow-selectable-elements#make-an-element-selectable)を含む選択可能な要素には、あらかじめ2つのステートが用意されています。

- **Default**: 要素のデフォルトの表示状態。
- **Selected**: ユーザーが要素をタップしたときに適用されます。ユーザーが選択を解除すると、ビルダーは Default に戻ります。

シングルチョイスグループでは、1つの要素を選択すると他の要素の選択が解除されます。マルチチョイスグループでは、複数の要素を同時に選択できます。トグルは独立しており、1つを選択しても他の要素には影響しません。詳細は[グループタイプ](flow-selectable-elements#group-types)を参照してください。

:::tip
状態別のスタイルを再利用するには、まずプロダクトカードなど1つの要素にスタイルを追加します。その後、[AIエディター](flow-ai-editor)に他の要素にも適用するよう依頼してください。状態別のスタイルは、兄弟要素間で自動的に引き継がれません。
:::

## 入力状態 \{#input-states\}

- **Default**: 入力フィールドの通常時の外観。
- **Active**: 入力フィールドにフォーカスが当たっている間に適用される。
- **Invalid**: 入力内容がバリデーションに失敗したときに適用される。例えば、メールアドレスのフィールドに `@` が含まれていない場合など。[入力バリデーション](builder-inputs-and-forms#input-validation)を参照。
- **Disabled**: 入力フィールドが操作不可の状態。このステートは手動で追加する必要がある。[条件によるDisabledステート](#condition-driven-disabled-state)を参照。
- **Custom states**: テキスト、メール、パスワード、数値、電話番号の入力フィールドのみ対象。カスタムステートでは、入力フィールドの塗りつぶし、ボーダー、角の丸みのみが変化する。[カスタムステート](#custom-states)を参照。

スタイルは、選択可能な要素と同じ方法で各ステートに適用します。対象のステートをアクティブにして、プロパティを変更してください。

## 条件によるDisabledステート \{#condition-driven-disabled-state\}

Disabledステートは、ユーザーが要素を操作できないようにします。Default・Selected・Active・Invalidとは異なり、Disabledステートは自動的に有効になりません — ユーザーが定義したトリガー条件が必要です。

Disabledは以下で使用できます：

- **入力フィールド**: テキスト、メール、パスワード、数値、電話番号、日付・時刻など、あらゆる[入力フィールド](builder-inputs-and-forms)。
- **選択可能な要素**: クイズの選択肢、プロダクト、タブ、トグル、チェックボックス、および[カスタム選択可能要素](flow-selectable-elements#make-an-element-selectable)。
- **タップ操作のある要素**: ナビゲーションアクションをトリガーするボタン、画像、アイコンなど。

### 無効状態を追加する \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="States section with the Add state menu open and the Disabled option" />

無効状態を追加して設定するには：

1. ターゲット要素を選択します。
2. **States** セクションで **Add state** をクリックし、**Disabled** を選択します。要素にすでにステートがある場合は、先に **Settings** <Inline id="settings.svg" alt="Settings" /> をクリックしてください。**Add state** はステートのリストの下にあります。カスタムステートを持てない要素の場合、コントロールは **Disabled state** ボタンになります。
3. Disabled ステートが **States** セクションに表示されます。
4. 新しい Disabled ステートの横にある **Edit conditional state** <Inline id="visibility-conditional.svg" alt="Edit conditional state" /> をクリックします。
5. 条件を追加します。入力がバリデーションをパスしない限り **submit** ボタンを無効にしたい場合は、入力の `isValid` 変数を `false` と比較します。
6. Disabled ステートをスタイリングして、制限を視覚的に伝えます（例：不透明度を下げるなど）。

{ <ZoomImage id="set-disabled-condition.webp" width="700px" alt="Set condition for disabled state " />}

Adapty SDK は実行時に条件を評価し、必要に応じて Disabled 状態を適用します。アプリコードは不要です。

**Disabled** 条件は別の要素の状態を評価することもできます。たとえば、[2つの要素を同時に無効化する](element-states-in-conditions#synchronize-element-states)ことが可能です。

## カスタムステート \{#custom-states\}

カスタムステートとは、独自の名前と条件を持つステートのことです。たとえば、**Locked** ステートを使えば、ユーザーが無料プランの間はボタンをグレーにできます。条件が true の間、その要素はカスタムステートの状態になります。

各要素には、最大5つのカスタムステートを設定できます。

### カスタム状態をサポートする要素 \{#elements-that-support-custom-states\}

- **タップアクションを持つ要素**: ボタン、コンテナ、画像、動画、タイマー、カルーセル。まず、**Interactions** タブで少なくとも1つのアクションを設定した [**On Tap** トリガー](onboarding-actions#set-up-interactions) を追加してください。
- **選択可能な要素**: 選択可能グループ内の要素、およびタップアクションを持つ選択可能な要素。
- **入力フィールド**: テキスト、メール、パスワード、数値、電話番号の入力フィールド。

アイコン、ボトムシート、タブアイテム、タブコンテンツ、ピッカー、プログレスインジケーターのステップなど、その他の要素はカスタム状態を持つことができません。

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="カスタムステートオプションがオフになっており、「カスタムステートを使用するにはタップアクションを追加してください」というキャプションが表示されたステート追加メニュー" />

ボタン、コンテナ、画像、動画、タイマー、またはカルーセルにカスタムステートを追加するには、まず少なくとも1つのアクションを含む **On Tap** トリガーを追加してください。追加するまで、**States** セクションに **Add state** コントロールは表示されません。要素にすでにステートがある場合、**Custom state** オプションはオフになっており、「Add a tap action to use custom states」というキャプションが表示されます。タップアクションを追加すると、オプションがオンになります。

### カスタム状態を追加する \{#add-a-custom-state\}

<ZoomImage id="custom-state-add-menu.webp" width="300px" float="right" alt="States section with the Add state menu open, listing Disabled and Custom state" />

1. 要素を選択します。
2. **States** セクションで **Add state** をクリックします。要素にすでに状態がある場合は、先に **Settings** <Inline id="settings.svg" alt="Settings" /> をクリックしてください。**Add state** は状態リストの下にあります。
3. **Custom state** を選択します。**Edit state** パネルが開きます。

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="名前が「Locked」で条件がplan equals freeの状態編集パネル" />

4. **Name** に状態の名前（例：**Locked**）を入力します。名前は[命名規則](#name-rules)に従う必要があります。
5. 条件を追加します。たとえば、`plan` 変数を `free` と比較します。条件をさらに追加するには、**Add Condition** をクリックし、条件を **all**（すべて）または **any**（いずれか）にするかを選択します。
6. **Save** をクリックします。新しい状態が **States** セクションのタブとして表示されます。
7. 新しい状態のタブをアクティブにし、[スタイルを設定します](#how-to-style-a-state)。ボタン内のテキストなど、ネストされた要素のスタイルも端末上で適用されます。

**Edit state** パネルを変更せずに閉じるには、**Cancel** またはクローズボタンをクリックするか、**Escape** キーを押すか、パネルの外側をクリックしてください。

要素にカスタムステートが5つある場合、**Custom state** オプションはオフになり、「Up to 5 custom states」というキャプションが表示されます。さらにカスタムステートを追加するには、既存のものを1つ削除してください。JSONまたはAIツールのフローコンフィグで要素に5つ以上のカスタムステートが含まれている場合、そのステートはそのまま維持され、編集できます。

### 名前のルール \{#name-rules\}

ビルダーでは大文字と小文字を区別しません。**Locked** と **locked** は同じ名前として扱われます。また、保存時に名前の先頭と末尾のスペースは自動的に削除されます。名前がルールに違反している場合、**Save** ボタンが無効になり、フィールドの下にエラーが表示されます。

| ルール | エラー |
|---|---|
| 名前が空でないこと。 | **Name is required** |
| 名前が30文字以下であること。 | **Max 30 characters** |
| 名前が **Default** または組み込み状態の名前（**Selected**、**Active**、**Invalid**、**Disabled**、**Completed**、**Current**、**Upcoming**、`focused`）でないこと。 | **This name is reserved** |
| 名前が同じ要素の他のカスタム状態の名前と異なること。 | **A state with this name already exists** |

### カスタムステートを編集する \{#edit-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="ロック状態タブのツールチップと「Edit state」ボタン" />

カスタムステートの名前や条件を変更するには、次のいずれかの方法で **Edit state** パネルを開いてください：

- **States** 設定リストで、対象のステートの行をクリックするか、その行にある条件アイコン <Inline id="visibility-conditional.svg" alt="Condition" /> をクリックする。
- ステートのタブにカーソルを合わせ、ツールチップの **Edit state** をクリックする。

保存後も、ステートはそのスタイルを保持します。このステートを評価する他の要素の条件には、新しい名前が反映されます。

### カスタムステートを削除する \{#delete-a-custom-state\}

**States** 設定リストで、削除したいステートの行にあるゴミ箱アイコンをクリックします。他の要素の条件がそのステートを参照している場合、ダイアログにその一覧が表示されます。**Delete** をクリックすると、それらの条件が無効になり、修正するまでフローを公開できなくなります。詳しくは[トラブルシューティング](element-states-in-conditions#troubleshooting)を参照してください。

ビルダーはステートとそのスタイルを削除します。削除したステートのタブがアクティブだった場合、**Default** タブがアクティブになります。

ステートを元に戻すには、削除操作を取り消してください。ステートはリスト内の同じ位置にスタイルも含めて復元されます。

### 未完了の条件 \{#incomplete-conditions\}

条件の行は、どちらかの側が空の場合に「未完了」となります。たとえば、行を追加したまま入力しなかった場合や、変数を選んだのに値を入力しなかった場合がこれに当たります。未完了の行を含む条件は、他の行がすべて真であっても、決して真にはなりません。その要素は該当の状態に入らず、デバイスには**デフォルト**スタイルが表示されます。このルールは**Disabled**条件にも適用されます。つまり、要素はインタラクティブなままです。

ビルダーでは未完成の行に警告が表示されないため、公開前に各行を入力するか削除してください。値または **is empty** のみで変数が設定されていない行があると、[**Invalid State Condition** エラー](flow-common-issues#a-flow-wont-preview-or-publish)が発生して公開できなくなります。

### 制限事項 \{#limitations\}

<ZoomImage id="custom-state-device-warning.webp" width="300px" float="right" alt="States settings list with the warning Not shown on the device. Add a tap action to the element. under two custom states" />

- **デバイスに状態が表示されない要素**: キャンバスではカスタム状態をすべての要素に表示できます。デバイスでは[対応している要素](#elements-that-support-custom-states)にのみ表示されます。サポートされていない要素がカスタム状態を持つ場合があります（例: JSON や AI ツールによる設定、またはタップアクションを削除した後など）。

    この場合、**States**設定リストとタブのツールチップに「Not shown on the device. Add a tap action to the element.」または「Not shown on the device for this element type.」という警告が表示されます。ステートの編集、削除、公開は引き続き可能です。
- **インプット**: カスタムステートでは、インプットの塗りつぶし、ボーダー、コーナー半径のみが変化します。テキストカラーなどその他のプロパティは**Default**値を維持します。インプットの**Edit state**パネルには「Only fill, border and corner radius change in a custom state」というキャプションが表示されます。
- **動画とカルーセル**: デバイス上で動画やカルーセルがステートを変更すると、動画は最初から再生され直し、カルーセルは最初のスライドに戻ります。再生位置や現在のスライドを維持する必要がある動画やカルーセルにはカスタムステートを追加しないでください。

## プログレスインジケーターのステップ状態 \{#step-states-for-progress-indicators\}

:::link
メイン記事：[プログレスインジケーター](builder-loaders-and-progress-bars#step-states)
:::

プログレスインジケーターは、オンボーディングフローのどこまで進んだかをユーザーに示します。各ステップには3つの状態があります：

- **完了（Completed）**：ユーザーがすでに通過したステップ。
- **現在（Current）**：ユーザーが現在いるステップ。
- **未到達（Upcoming）**：まだ到達していないステップ。
