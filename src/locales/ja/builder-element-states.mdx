インタラクティブなフローエレメントは、ユーザーの操作に応じて見た目が変化します。タップされたクイズの選択肢は **Selected** になり、フォーカスされた入力欄は **Active** になります。各状態を個別にスタイル設定することで、アプリのコードなしにユーザーへ視覚的なフィードバックを提供できます。

一部のステートは、変数の値や他の要素のステートなど、設定した条件に依存します。

- [**無効（Disabled）**](#add-the-disabled-state)：ユーザーがその要素を操作できない状態です。
- [カスタムステート](#add-a-custom-state)：ステートに名前を付け、条件を設定し、その状態のスタイルを定義します。アクションによって要素をカスタムステートに切り替えることはできません。代わりに、[タップ時にカスタム変数を変更](#switch-an-element-to-a-custom-state-on-tap)し、その変数を基にステートの条件を設定します。

要素は[常に1つのステートのみ](#when-several-states-apply-to-one-element)になります。

## 要素の種類別で利用可能な状態 \{#available-states-by-element-kind\}

| 要素の種類 | 組み込みの状態 | 追加可能な状態 |
|---|---|---|
| [選択可能な要素](#selectable-element-states) | **Default**、**Selected** | **Disabled**、**カスタム**状態（タブヘッダーを除く） |
| [入力要素](#input-states) | **Default**、**Active**、**Invalid** | **Disabled**、**カスタム**状態（ピッカーを除く） |
| [タップインタラクションを持つすべての要素](#add-a-state) — ボタン、画像、コンテナなど（テキスト要素とアイコンを除く） | **Default** | **Disabled**、**カスタム**状態（ボトムシートを除く） |
| [プログレスインジケーターのステップ](#step-states-for-progress-indicators) | **Completed**、**Current**、**Upcoming** | — |

**追加可能**な状態は、[追加する](#add-a-state)まで要素に表示されません。それぞれ、設定した条件に依存します。

他の要素の条件も、要素の状態を評価できます。たとえば、[ボタンが無効な理由を説明する](element-states-in-conditions#explain-why-a-button-is-disabled)こともできます。

## 状態のスタイルを設定する \{#style-a-state\}

<ZoomImage id="element-states-panel.webp" width="300px" alt="選択した要素の右パネルにある States セクション" float="right" />


1. 要素を選択します。右パネルの **States** セクションに、その要素が持つ各状態のタブが表示されます。
2. **States** セクションで、対象の状態をアクティブにします。セクションにそのタブがない場合は、[状態を追加](#add-a-state)してください。
3. 塗りつぶし、ボーダー、タイポグラフィなど、任意のプロパティを変更します。変更はその状態にのみ適用されます。

    ネストされた要素は親と一緒にステートフルになります。子への変更は、親のアクティブな状態にスコープされます。

4. Adapty SDKは、実行時に一致するスタイルを適用します。

## 選択可能要素のステート \{#selectable-element-states\}

<ZoomImage id="selectable-state-demo.webp" width="600px" alt="Selectable element with Selected state activated and a style override applied" />

選択可能な要素（クイズの選択肢、プロダクト、タブ、トグル、チェックボックス、および[カスタム選択可能要素](flow-selectable-elements#make-an-element-selectable)）には、標準で2つのステートが用意されています：

- **Default**: 要素のデフォルト表示。
- **Selected**: ユーザーが要素をタップしたときに適用されます。ユーザーが選択を解除すると、要素は **Default** に戻ります。

単一選択グループでは、1つの要素を選択すると他の要素が非選択になります。複数選択グループでは、複数の要素を同時に選択できます。トグルは独立しており、トグルを選択しても他の兄弟要素には影響しません。[グループタイプ](flow-selectable-elements#group-types)を参照してください。

:::tip
状態固有のスタイルを再利用するには、プロダクトカードなど1つの要素にスタイルを追加し、[AIエディター](flow-ai-editor)に他の要素へ適用するよう依頼してください。状態固有のスタイルは、兄弟要素間で自動的には引き継がれません。
:::

## 入力状態 \{#input-states\}

- **Default**: 入力欄の通常時の表示。
- **Active**: 入力欄がフォーカスされている間に適用されます。
- **Invalid**: 入力内容がバリデーションに失敗した場合に適用されます（例：メールフィールドに `@` が含まれていない場合）。[入力のバリデーション](builder-inputs-and-forms#input-validation)を参照してください。
- **Disabled**: 入力欄が操作不可の状態です。[この状態を追加する](#add-the-disabled-state)には手動で設定が必要です。

各状態のスタイル設定は、選択可能な要素と同じ方法で行います：対象の状態をアクティブにして、プロパティを変更してください。

## プログレスインジケーターのステップ状態 \{#step-states-for-progress-indicators\}

:::link
メイン記事: [プログレスインジケーター](builder-loaders-and-progress-bars#step-states)
:::

プログレスインジケーターは、オンボーディングフローのどこまで進んだかをユーザーに示します。各ステップには3つの状態があります:

- **完了済み（Completed）**: ユーザーがすでに通過したステップ。
- **現在（Current）**: ユーザーの現在のステップ。
- **未到達（Upcoming）**: ユーザーがまだ到達していないステップ。

## 1つの要素に複数の状態が適用される場合 \{#when-several-states-apply-to-one-element\}

複数の状態が1つの要素に同時に適用されることがあります。例えば：

- ユーザーがメールフィールドに無効なアドレスを入力し、修正するために再度そのフィールドをタップした場合。フィールドはフォーカスされているため **Active** が適用されます。アドレスはまだ無効なため **Invalid** も適用されます。
- ユーザーがトライアルトグルをオンにすると **Selected** が適用されます。その後、トライアルのないプランを選択した場合、そのプランに対してトグルに **Disabled** の条件があるため **Disabled** も適用されます。

要素は一度に1つの状態にのみあります。複数の状態が適用される場合、要素はこのリストで最後に来る状態になります：

1. **Selected**
2. **Invalid**
3. **Active**
4. **Disabled**
5. カスタム状態（追加した順序）

例では、メールフィールドは **Active** で、トライアルトグルは **Disabled** です。要素はその状態に合わせてスタイルが適用されます。要素の状態を評価する条件は、その状態のみに一致します。リスト内のどの状態も適用されない場合、要素は **Default** になります。

カスタムステートは見た目のみを変更します。**Disabled** も適用されている場合、要素はカスタムステートの状態になりますが、ユーザーは操作できません。

## 状態を追加する \{#add-a-state\}

### Disabled状態を追加する \{#add-the-disabled-state\}

<ZoomImage id="add-disabled-state.webp" width="300px" float="right" alt="ボタンのAdd stateメニュー。DisabledとCustom stateが表示されている" />

ユーザーが要素を操作できないようにするには、**Disabled**状態を追加します：

1. ターゲット要素を選択します。
2. **States** セクションに **Disabled** タブがない場合は、**Add state** をクリックして **Disabled** を選択します。すでに **Default** 以外のステートがある場合は、**Add state** の前に **Settings** <Inline id="settings.svg" alt="Settings" /> をクリックします。
3. **Disabled** にカーソルを合わせ、**Set conditions** をクリックします。
4. 条件を追加します。入力がバリデーションを通過しない限り **submit** ボタンを無効にしたい場合は、入力の `isValid` 変数を `false` と比較します。**Disabled** ステートを適用するには、すべての **Value** フィールドを入力してください。
5. Disabled ステートに視覚的なスタイルを適用して制限を伝えます（例：不透明度を下げるなど）。

<ZoomImage id="element-states-disabled-condition.webp" width="400px" alt="The Edit conditional state popover with the condition email.isValid = False" />

Adapty SDK は実行時に条件を評価し、適切なタイミングで Disabled 状態を適用します — アプリのコードは不要です。

**Disabled** の条件では、別の要素の状態を評価することもできます。たとえば、[2 つの要素を同時に無効化する](element-states-in-conditions#synchronize-element-states)ことが可能です。

### カスタム状態を追加する \{#add-a-custom-state\}

組み込みの状態でカバーできない見た目にするには、カスタム状態を追加します。カスタム状態は、回答・タップ・他の要素の状態に応じて切り替えることができます。例：

- トライアルのトグルがオンのとき、年間プランカードを強調表示する。
- ユーザーがタップした後に **Remind me** ボタンの色を変える。設定するには、[タップ時にボタンをカスタム状態に切り替える](#switch-an-element-to-a-custom-state-on-tap)を参照してください。

カスタム状態は見た目のみを変更します。ユーザーが要素を操作できないようにするには、[**Disabled** 状態を追加する](#add-the-disabled-state)を参照してください。

<ZoomImage id="custom-state-needs-tap.webp" width="300px" float="right" alt="The States list with the Custom state option off and the caption Add a tap action to use custom states" />

カスタムステートを持てる要素は次のとおりです:

- **ボタン、画像、コンテナ、動画、タイマー、カルーセル**: [タップアクション](onboarding-actions#set-up-interactions)が必要です。タップアクションを削除すると、ユーザーはカスタムステートを確認できなくなります。
- **選択可能な要素**: グループまたはタップアクションが必要です。
- **入力フィールド**: テキスト、メール、パスワード、数値、電話番号の各入力フィールド。

カスタムステートを持てない要素は次のとおりです:

- タブヘッダーとタブコンテンツ
- ピッカー
- ボトムシート
- プログレスインジケーターのステップ

1つの要素に設定できるカスタム状態は最大5つです。5つになると、**Custom state** オプションがオフになり、「Up to 5 custom states」というキャプションが表示されます。Adapty CLI や AI ツールからのコンフィグにはそれ以上含まれる場合がありますが、編集は引き続き行えます。

1. ターゲット要素を選択します。
2. **States** セクションで **Add state** をクリックし、**Custom state** を選択します。要素にすでに **Default** 以外のステートがある場合は、**Add state** の前に **Settings** <Inline id="settings.svg" alt="Settings" /> をクリックしてください。
3. **Name** フィールドにステートの名前（例：**Locked**）を入力します。名前が以下のルールのいずれかに違反している間は、フィールドの下にエラーが表示され、**Save** は無効のままになります。

    - **名前は必須です**: 名前を空にすることはできません。
   - **最大30文字**: 名前は30文字を超えることはできません。
   - **この名前は予約済みです**: 名前に **Default**、`focused`、またはビルトインステートの名前（**Selected**、**Active**、**Invalid**、**Disabled**、**Completed**、**Current**、**Upcoming**）は使用できません。
   - **この名前のステートはすでに存在します**: 要素の各カスタムステートには固有の名前が必要です。大文字・小文字の違いは名前を区別しません。

    <ZoomImage id="custom-state-edit-panel.webp" width="400px" alt="The Edit state panel with the name Locked and the condition plan = free" />

4. `plan` = `free` のような条件を追加します。さらに行を追加するには、**Add Condition** をクリックします。1 つの条件が true であれば十分な場合は、**all** をクリックして **any** に切り替えます。状態を適用するには、すべての **Value** フィールドに値を入力してください。
5. **Save** をクリックします。
6. 状態をスタイルするには、**States** セクションのタブをアクティブにして、[要素のプロパティを変更します](#style-a-state)。テキストフィールドでは、カスタム状態はフィル、ボーダー、コーナー半径のみを変更します。

ビルダーでは、**Value**フィールドが空でも警告は表示されません。変数なしで値が入力されている行がある場合、フローを公開できません。**Can't publish yet**ダイアログの**Broken references**にその行が表示されます。Adapty CLIとAPIは、該当する行に対して[**Invalid State Condition**エラー](flow-common-issues#a-flow-wont-preview-or-publish)を返します。

動画やカルーセルの場合、状態の変更によって動画が最初から再生されたり、カルーセルが最初のスライドに戻ったりすることがあります。

カスタムステートの条件では、トグルが **Selected** 状態かどうかなど、[別の要素の状態を評価する](element-states-in-conditions#add-an-element-state-to-a-condition)こともできます。

### タップでカスタム状態に切り替える \{#switch-an-element-to-a-custom-state-on-tap\}

アクションを使って要素をカスタム状態に直接切り替えることはできません。代わりに、タップ時にカスタム変数を変更し、その変数の値に基づいて状態の条件を設定してください。

1. **Boolean** 型の[カスタム変数を作成](onboarding-variables#create-a-custom-variable)し、初期値を `false` に設定します。
2. ユーザーがタップする要素を選択します。**Interactions** タブで、**On Tap** トリガーに[**Set variable** アクションを追加](onboarding-variables#update-a-variable-via-an-interaction)し、変数を `true` に設定します。
3. 切り替わる要素に[カスタム状態を追加](#add-a-custom-state)します。条件では、**Variable** フィールドの **Custom** タブで変数を選択し、**Value** フィールドを `true` に設定します。

<ZoomImage id="element-states-custom-variable-picker.webp" width="500px" alt="カスタム状態の条件で reminder.set 変数が選択された、変数フィールドの「カスタム」タブ" />

### カスタム状態の編集または削除 \{#edit-or-delete-a-custom-state\}

<ZoomImage id="custom-state-tab-tooltip.webp" width="300px" float="right" alt="The tooltip of the Locked tab with the Edit state button" />

カスタム状態の名前を変更したり、条件を変更したりするには、対象の要素を選択します。右パネルの **States** セクションで、状態のタブにホバーして **Edit state** をクリックします。または、そのセクションの **Settings** <Inline id="settings.svg" alt="Settings" /> をクリックして、状態の名前をクリックします。スタイルはそのまま保持され、その状態を評価する条件には新しい名前が表示されます。

カスタムステートを削除するには、要素を選択します。右パネルの **States** セクションで **Settings** <Inline id="settings.svg" alt="Settings" /> をクリックし、ステートの行にあるゴミ箱アイコンをクリックします。そのステートを使用している条件がある場合は、ダイアログにそれらが表示されます。**Delete** をクリックすると、これらの条件が無効になり、修正するまでフローを公開できなくなります。スタイルごとステートを元に戻すには、削除を取り消してください。
