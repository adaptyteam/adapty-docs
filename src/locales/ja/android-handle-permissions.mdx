[フロー](adapty-flow-builder)では、**Request permission** アクションを使って、たとえばオンボーディング画面で通知の目的を説明しながら、プッシュ通知の許可をユーザーに求めることができます。Adapty SDK はシステムの許可ダイアログを自動的に表示しません。代わりに、フローのイベントリスナーの `onShowRequestPermission` メソッドにリクエストを渡します。アプリがダイアログを表示してユーザーの回答を受け取り、フローが続行されます。

## 始める前に \{#before-you-start\}

必要なもの:

- **Adapty Android SDK 4.0.0 以降**: それ以前のバージョンには `onShowRequestPermission` がありません。
- **Request permission アクションを含むフロー**: フロー＆ペイウォールビルダーで、要素の **On Tap** または **On Screen Appear** トリガーに **Request permission** アクションを追加します。**After response** セクションに、ユーザーが回答した後に実行するアクション（**Navigate Next** など）を追加します。アクションの設定については、[Request permission](onboarding-actions#request-permission) を参照してください。
- **Android マニフェストへの `POST_NOTIFICATIONS` 権限の追加と `targetSdk` 33 以上**: Android 13 以降では、権限を宣言し Android 13 以降をターゲットにしているアプリに対してのみ、通知権限ダイアログが表示されます。

  ```xml title="AndroidManifest.xml"
  <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
  ```

## フローがパーミッションをリクエストする仕組み \{#how-the-flow-requests-a-permission\}

1. フローが **Request permission** アクションに到達します: ユーザーが要素をタップするか、画面が表示されます。
2. Adapty SDK は、フロービューのイベントリスナー上で `onShowRequestPermission` を呼び出し、`permission` を `"push"` に設定します。
3. アプリが Android にパーミッションをリクエストし、`callback` を使って結果を返します。
4. フローが **After response** アクションを実行します。これはどちらの回答に対しても同じです。

フローは、アプリが`callback`を呼び出すまで画面上で待機します。アプリが`callback`を呼び出さない場合、フローは画面に留まり続けます。Android がダイアログを表示しない場合、アプリはすぐに応答を受け取り、フローは **After response** アクションを即座に実行します。それらのアクションによって画面が遷移する場合、ユーザーはパーミッションをリクエストする画面を一瞬だけ目にすることになります。Android が次のいずれかの場合にダイアログを表示しません：

- **Android 12 以前**: 通知に実行時の権限が不要なため、ダイアログは表示されません。
- **ユーザーがすでに通知を許可している場合**: 権限はすでに付与されています。
- **ユーザーが2回ダイアログを拒否した場合**: Android はアプリへのダイアログ表示を停止し、以降のリクエストはすべて拒否されます。

**On Screen Appear** を使用した場合、**Navigate back** アクションで画面に戻ってきたときにフローはリクエストを再送しません。**On Tap** を使用した場合、リクエストの返答待ち中のタップを除き、タップのたびに新しいリクエストが送信されます。

## onShowRequestPermissionのオーバーライド \{#override-onshowrequestpermission\}

:::warning
**デフォルトのリスナーはユーザーに確認しません。** `AdaptyFlowDefaultEventListener`はすべての権限リクエストに`false`で応答し、ダイアログを表示しません。リスナーが`AdaptyFlowDefaultEventListener`を継承しており、`onShowRequestPermission`をオーバーライドしていない場合、フローは**After response**アクションをすぐに実行します。
:::

権限リクエストに応答するには、イベントリスナーで`onShowRequestPermission`をオーバーライドしてください。次の例では、フローを表示するアクティビティが権限ダイアログ用のランチャーを登録しています：

```kotlin showLineNumbers title="Kotlin"

class FlowActivity : ComponentActivity() {

    // The flow waits for this callback while the system dialog is open.
    private var pendingPermissionCallback: AdaptyFlowEventListener.PermissionCallback? = null

    private val notificationPermissionLauncher =
        registerForActivityResult(ActivityResultContracts.RequestPermission()) { granted ->
            pendingPermissionCallback?.invoke(granted, null)
            pendingPermissionCallback = null
        }

    private val eventListener = object : AdaptyFlowDefaultEventListener() {
        override fun onShowRequestPermission(
            permission: String?,
            customArgs: Map<String, String>?,
            callback: AdaptyFlowEventListener.PermissionCallback,
            context: Context,
        ) {
            if (permission != "push") {
                callback(false, null)
                return
            }
            if (Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU) {
                // Android 12 and earlier: return whether notifications are turned on for the app.
                callback(NotificationManagerCompat.from(context).areNotificationsEnabled(), null)
                return
            }
            pendingPermissionCallback = callback
            notificationPermissionLauncher.launch(Manifest.permission.POST_NOTIFICATIONS)
        }
    }

    // Pass eventListener to the flow view.
}
```

`onShowRequestPermission` が受け取る値:

- **`permission`**: フローがリクエストするパーミッション。**Request permission** アクションは `"push"` を送信します。
- **`customArgs`**: リクエストのカスタム引数。**Request permission** アクションでは送信されないため、値は `null` です。
- **`callback`**: フローに回答を返すコールバック。第1引数 `granted` は、ユーザーがパーミッションを許可した場合は `true`、拒否した場合は `false` です。第2引数 `detailResult` は、回答の詳細を示すオプションの文字列です。詳細がない場合は `null` を渡してください。

`callback` をリクエストごとに1回呼び出してください。アプリがリクエストしていない権限には `false` を返してください。Adapty SDKは `onShowRequestPermission` からの例外をキャッチしないため、オーバーライド内で例外をキャッチし、`callback(false, null)` を呼び出してください。

Jetpack Composeでは、`registerForActivityResult` の代わりに `rememberLauncherForActivityResult` でランチャーを登録してください。ダイアログが開いている間に画面回転などでアクティビティが再生成される可能性がある場合は、保留中のコールバックを `ViewModel` に保持し、新しいアクティビティからそれを呼び出せるようにしてください。

付与された権限により、アプリが通知を表示できるようになります。プッシュ通知を受信するには、フロー外でアプリが行うのと同様に、Firebase Cloud Messaging などのプッシュプロバイダーにデバイスを登録してください。

## リスナーをフローに渡す \{#pass-the-listener-to-the-flow\}

Adapty SDK は、フロービューのイベントリスナーにパーミッションリクエストを送信します。ビューを作成する際に、オーバーライドしたリスナーを `eventListener` として渡してください。渡す先は `AdaptyUI.getFlowView()`、`AdaptyFlowView.showFlow()`、または `AdaptyFlowScreen()` です。これらの呼び出しについては[フロー＆ペイウォールの表示](android-present-paywalls)を、その他のリスナーメソッドについては[フロー＆ペイウォールイベントの処理](android-handling-events)を参照してください。

## 通知権限リクエストのテスト \{#test-the-permission-request\}

Android 13以降のデバイスでテストしてください。それ以前のバージョンでは通知ダイアログは表示されません。また、ユーザーが通知を許可するか、2回拒否した後は、Androidはダイアログを表示しなくなります。テスト中にフローを再確認するためにダイアログを再度表示させるには、デバイスからアプリを削除して再インストールしてください。その後、フローを開いて **Request permission** アクションに到達してください。ダイアログが表示されずにフローが進んだ場合は、リスナーが `onShowRequestPermission` をオーバーライドしているか、アプリが `POST_NOTIFICATIONS` を宣言してAndroid 13以降をターゲットにしているかを確認してください。
