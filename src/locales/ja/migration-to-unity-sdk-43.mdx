Adapty Unity SDK 4.3 は Unity 6 を必須とし、`Adapty.GetLogLevel` を削除し、Google Play アプリ内メッセージをデフォルトで表示するようになり、Android 上の一部のフローイベントデータの C# 型が変更されました。アプリの動作を維持するために、このガイドで各変更点を確認してください。

3.x をお使いの場合は、まず [v4.1 への移行](migration-to-unity-sdk-v4) を行ってから、このガイドに従ってください。

## クイックリファレンス \{#quick-reference\}

| v4.1 | v4.3 |
|---|---|
| Unity 2022.3 以降 | Unity 6.0 (6000.0) 以降 |
| `Adapty.GetLogLevel(...)` | 削除 — `builder.LogLevel` または `Adapty.SetLogLevel` で設定したレベルは自分で管理してください |
| Google Play メッセージはリクエストされない | Android ではデフォルトで Google Play メッセージが表示される（フロー上でも） |
| フローイベントの整数パラメーターは Android では `double` で届く | 両プラットフォームで `long` で届く |

## インストール \{#installation\}

Adapty Unity SDK 4.3 には **Unity 6.0 (6000.0)** 以降が必要です。プロジェクトが Unity 2022.3 の場合は、先にプロジェクトをアップグレードするか、Adapty SDK 4.1.x を使い続けてください。

:::warning
Adapty SDK 4.1.x は、Unity 6 の新規プロジェクトでデフォルトの Android エントリーポイントである GameActivity では動作しません。コンプリーションハンドラーとイベントが C# に届かなくなります。SDK より先に Unity をアップグレードする場合は、Adapty SDK 4.3 に移行するまで **Application Entry Point** を **Activity** に設定したままにしてください。SDK 4.3 は両方のエントリーポイントに対応しています。
:::

Unity Package Manager 経由で SDK 4.3 をインストールするには、次の Git URL を使用してください。

```
https://github.com/adaptyteam/AdaptySDK-Unity.git?path=/Packages/com.adapty.unity-sdk#4.3.0-beta.1
```

Unity パッケージからインストールする場合は、[4.3.0-beta.1 リリース](https://github.com/adaptyteam/AdaptySDK-Unity/releases/tag/4.3.0-beta.1) から `adapty-unity-plugin-4.3.0-beta.1.unitypackage` をダウンロードしてください。インポートする前に `Assets/AdaptySDK/Plugins/Android/Local` フォルダを削除してください。SDK 4.3 では、このフォルダに含まれる Android Java の内部ラッパーが同梱されなくなりました。`.unitypackage` のインポートではファイルが削除されないため、削除しないと古いラッパーがプロジェクトに残り続けます。

その他の要件は4.1と変わりません：**iOS 15.0**および**Xcode 26**。完全なセットアップについては[Adapty SDKのインストール](sdk-installation-unity)を参照してください。

## `GetLogLevel` の削除 \{#getloglevel-is-removed\}

`Adapty.GetLogLevel` は使用できなくなりました。ログレベルは、SDK をアクティベートする際に `builder.LogLevel` で設定した値、または後から `Adapty.SetLogLevel` で設定した値が使用されます。コード内でログレベルを読み取っている場合は、設定した値を変数に保存して使用してください：

```diff showLineNumbers
- Adapty.GetLogLevel((level, error) => {
-     // use level
- });
+ var logLevel = AdaptyLogLevel.Verbose;
+ builder.LogLevel = logLevel;
+ // use logLevel
```

## Google Playのメッセージはデフォルトで表示されます \{#google-play-messages-are-shown-by-default\}

4.3以降、SDKはアクティベーション後にアプリの`Activity`が起動するたびに、支払い拒否通知などのGoogle Playアプリ内メッセージをリクエストします。これには、アプリがフォアグラウンドに戻るときや、フローやオンボーディングが開閉するときも含まれるため、ペイウォールの上にメッセージが表示される場合があります。

アプリの動作としてこれで問題なければ、変更は不要です。メッセージの表示タイミングを制御したい場合は、Androidで手動処理を有効にしてSDKをアクティベートし、適切なタイミングで`Adapty.ShowStoreMessages`を呼び出してください。

```csharp showLineNumbers title="C#"
var builder = new AdaptyConfiguration.Builder("YOUR_PUBLIC_SDK_KEY");
#if UNITY_ANDROID
builder.SetStoreMessagesHandling(AdaptyStoreMessagesHandling.Manual);
#endif

Adapty.Activate(builder.Build(), (error) => {
    // handle the error
});
```

Androidのみ手動処理を設定することで、iOSの動作は変わりません。iOS 16以降では、手動処理を有効にすると、アプリが`Adapty.ShowStoreMessages`を呼び出すまでApp Storeのメッセージが保留されます。APIの詳細については、[ストアメッセージの制御](unity-store-messages)を参照してください。

:::warning
手動モードでは、ストアは独自にメッセージを表示しません。アプリが `Adapty.ShowStoreMessages` を呼び出さない場合、ユーザーは支払い拒否の通知を受け取れません。
:::

## Androidでは、フローイベントのパラメーターが数値の場合は`long`型になります \{#numeric-flow-event-parameters-are-long-on-android\}

Androidでは、`FlowViewDidReceiveAnalyticEvent`の整数パラメーターがこれまで`double`として渡されていました。4.3から、iOSと同様に`long`として渡されるようになりました。これには[フロー入力](unity-flow-input)イベントの日時値も含まれます。

`double`へのキャストはAndroidでは例外をスローするようになりました。キャストの代わりに数値パラメーターを変換してください：

```diff showLineNumbers
- var timestamp = (double)parameters["value"];
+ var timestamp = Convert.ToInt64(parameters["value"]);
```

## 4.3 の新機能 \{#new-in-43\}

これらの追加機能はオプトインです。既存のコードはそのまま動作します。

- **[ストアメッセージを制御する](unity-store-messages)**：App Store と Google Play のメッセージが表示されるタイミングを選択します。
- **[プレースメントをプリロードする](unity-optimize-paywall-fetching#preload-placements)**：`Adapty.PreloadFlows` と `Adapty.PreloadFlowsForDefaultAudience` でフローキャッシュをウォームアップします。
- **[フロービューを保持する](unity-present-paywalls#keep-the-view-to-present-it-again)**：`view.Dismiss(false, ...)` はビューを保持して再表示できるようにし、`view.Destroy(...)` はビューを解放します。
- **[12ヶ月コミットメントプラン](set-up-12-month-commitment)**：`AdaptySubscription.PricingTerms` プロパティは iOS でのプランを表し、アクセスレベルとサブスクリプションは `BillingPlan` と `CommitmentInfo` を報告します。
- **新しいエラーコード**：`AdaptyErrorCode.BillingPlanUnavailable`（1060、iOS のみ）。`MakePurchase` は、プロダクトがデバイスまたはストアフロントで要求された請求プランを提供していない場合にこれを返します。すべての `AdaptyErrorCode` の値を switch で処理している場合は、この新しいコードを追加してください。
- **[オブザーバーモード](report-transactions-observer-mode-unity)**：`Adapty.ReportTransaction` は iOS でオプションの `appleJWSTransaction` を受け取ります。
- **バリエーション名**：`AdaptyFlow.VariationName` は、Adapty ダッシュボードで設定したバリエーション名を返します。
