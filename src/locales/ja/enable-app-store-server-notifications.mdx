Adapty SDK はアプリ内で行われた購入を報告します。サーバー通知は、アプリの外部で発生した変更を報告します。例えば：

- サブスクリプションが更新される。
- ユーザーが自動更新をオフにする。
- 請求の問題により支払いが失敗する。
- サブスクリプションが期限切れになる。
- ユーザーが返金をリクエストする。[Refund Saver](refund-saver) がリクエストに応答する。
- Apple が購入を返金する。

Adapty の通知 URL を App Store Connect に入力し、通知が Adapty に届いていることを確認してください。

## App Store Connect に通知URLを入力する \{#enter-the-notification-url-in-app-store-connect\}

別のサーバーがすでにアプリの通知を受信している場合は、URLを置き換える前に[そちらへの転送を設定](#raw-events-forwarding)してください。

## 通知がAdaptyに届いていることを確認する \{#check-that-notifications-reach-adapty\}

通知がAdaptyに届いていることを確認するには、[サンドボックス購入](test-purchases-in-sandbox)を行ってください。その後、Adaptyで **App Store server notifications** セクションのステータスを確認します。購入自体はSDKが報告するため、通知がなくてもAdaptyに表示されます。Appleから購入に関する通知が送信されると、Adaptyはステータスを **Waiting** から **Active** に変更します。Appleからのテスト通知ではステータスは変わりません。

ステータスには、最後に通知が届いてからの経過時間が表示されます：

- **Active**：24時間以内。
- **Delayed**：24〜72時間前。
- **Stalled**：72時間以上前。

**Delayed** と **Stalled** は必ずしも設定が壊れていることを意味するわけではありません。サブスクライバーが少ないアプリでは、通知が来ない日が続くこともあります。**Active** は単に、URLに通知が届いていることを示しているにすぎません。

通知が自分のアプリに関するものであることを確認するには、設定を検証してください：

1. App Store Connect で、アプリの **App Information** ページを開きます。
2. **Production Server URL** と **Sandbox Server URL** の両方が Adapty の URL と一致していることを確認します。
3. もう一度サンドボックス購入を行い、ステータスが **Active** になっていることを確認します。

## 別のサーバーへの通知の転送 \{#raw-events-forwarding\}

Appleからの通知を別のサーバーにも送る必要がある場合、Adaptyはその通知を転送できます。Adaptyで [**App settings** > **iOS SDK**](https://app.adapty.io/settings/ios-sdk) に移動してください。**App Store server notifications** セクションの **URL for forwarding raw Apple events** フィールドに転送先サーバーのURLを入力し、**Save** をクリックします。

<ZoomImage id="app-settings-forwarding-url.webp" width="700px" />

Adaptyは、Appleから受信した通知を別のサーバーに転送します。App Store ConnectでAdaptyの通知URLを**Sandbox Server URL**に入力すると、Adaptyはサンドボックス通知も転送します。転送されるボディはAppleの署名済みペイロードをそのまま保持するため、別のサーバーが署名を検証できます。なお、AdaptyはAppleからのリクエストヘッダーは転送しません。

Adaptyが転送しないケース：

- SDKがAppleからの通知なしにレポートした購入。
- Appleからのテスト通知。
- 過去1時間以内にAdaptyがすでに受信した通知。

ループを防ぐため、転送された通知を通知URLに再投稿しないでください。**URL for forwarding raw Apple events** フィールドにAdaptyのURLを入力しないでください。

バックエンドのURLをApp Store Connectに保持する必要がある場合は、代わりに[バックエンドからAdaptyに通知を渡す](forwarding-events-to-adapty)ようにしてください。

## 通知の信頼性 \{#notification-authenticity\}

通知URLはクレデンシャルとして扱ってください。AdaptyはURLのみでアプリを識別するため、URLを知っている人なら誰でもペイロードを送信できます。

テスト通知は、送信者を問わず[イベントフィード](event-feed)にイベントを作成しません。
