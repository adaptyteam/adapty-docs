このクイックスタートでは、トークン通貨をエンドツーエンドでセットアップします。月次サブスクリプションにより、ユーザーは請求期間ごとに 1000 トークンを受け取り、アプリ内の有料アクションはトークンを消費します。Adapty がすべての残高を管理するため、バックエンドは残高の読み取りと消費のみを行うだけで済みます。

1. [仮想通貨を作成する](create-virtual-currency)ガイドに従って、`TOKENS` 通貨を作成します。Pro サブスクリプションにリンクし、**Credit per cycle** を 1000 に設定します。Adapty はサブスクリプションの請求サイクルごとに **Credit per cycle** を付与します（月次サブスクリプションなら毎月、週次なら毎週）。追加トークンを販売するには、買い切りのトークンパックプロダクトもリンクしてください。

   <ZoomImage id="new-currency-combined.webp" width="700px" alt="New virtual currency creation screens" />

2. [仮想通貨の残高一覧取得](api-adapty/operations/listVirtualCurrencyBalances)を呼び出して、たとえば生成開始前にユーザーの残高を確認します：

   ```bash title="Read balances"
   curl https://api.adapty.io/api/v2/server-side-api/vc/balances/ \
     -H "Authorization: Api-Key {your secret key}" \
     -H "adapty-customer-user-id: user-42"
   ```

   レスポンスには、残高が0の通貨も含め、アプリ内のすべての通貨が一覧表示されます。たとえば、1000 `TOKENS`の場合：

   ```json title="Response"
   {
     "response_created_at": 1794477600123,
     "data": [
       {
         "code": "TOKENS",
         "name": "Tokens",
         "balance": 1000,
         "held": 0,
         "available": 1000,
         "expiry": { "non_expiring": 1000, "expiring": [], "expiring_later": 0, "expired": 0 }
       }
     ]
   }
   ```
3. ユーザーが生成を実行したら、負の `amount` を指定して [Create virtual currency transaction](api-adapty/operations/createVirtualCurrencyTransaction) を呼び出してトークンを消費します。この例では、1回の画像生成に100トークンかかります。トークンの使用目的を示すために、リクエストでは `operation` を `spend`、`feature` を `image_generation` に設定しています（[トランザクションにラベルを付ける](virtual-currencies#label-transactions)を参照）：

   ```bash title="Spend tokens"
   curl -X POST https://api.adapty.io/api/v2/server-side-api/vc/transactions/ \
     -H "Authorization: Api-Key {your secret key}" \
     -H "adapty-customer-user-id: user-42" \
     -H "Content-Type: application/json" \
     -d '{
           "items": [{"currency_code": "TOKENS", "amount": -100}],
           "operation": "spend",
           "feature": "image_generation"
         }'
   ```

   トランザクションはアトミックであり、更新された残高を返します。1回のトランザクションで最大20種類の通貨を変更でき、それぞれ`items`に1回ずつ記載します。ユーザーが残高不足の場合、リクエストは`insufficient_balance`を返し、何も変更されません。リクエストを安全にリトライするには、`Idempotency-Key`ヘッダーを含めてください。残高が不足しているときにチャージフローを開くには、[iOS](ios-virtual-currency-top-up)のレシピを参照してください。
4. ウィンバックプロモを実施するには、同じエンドポイントで正の`amount`を指定してトークンを付与します。この方法で付与したクレジットは有効期限がありません。ユーザーの初回購入前に残高を付与するには、[初期残高の付与](grant-initial-balance)を参照してください。
5. ユーザーの[プロファイル](virtual-currency-balance)または[トランザクション履歴](api-adapty/operations/listVirtualCurrencyTransactions)で変更内容をすべて確認し、いつでも経済状況を監査できるようにしてください。
