サブスクライバーがリテンションメッセージを受け取れるようにするには、ユーザーがキャンセルしたときにAppleがAdaptyに通知できる仕組みが必要です。この記事では、まずサンドボックスモードで接続を設定し、その後本番環境に切り替える手順を説明します。

## 始める前に \{#before-you-begin\}

- AdaptyにApp Store Connect APIキーを[追加](app-store-connection-configuration)してください。Adaptyはこれを使ってリアルタイムURLの登録とAppleとの通信を行います。
- [AppleのRetention Messagingプログラム](https://developer.apple.com/documentation/retentionmessaging)へのアクセスをリクエストし、Appleの承認を待ってください。承認なしでは、Appleが接続を拒否します。

## サンドボックスのセットアップ \{#sandbox-setup\}

Appleは本番環境でメッセージを送信する前に、まずサンドボックス環境で接続をテストして信頼性を確認するよう求めています。

### サンドボックス URL の設定 \{#configure-sandbox-url\}

**Configure Sandbox URL** をクリックして設定を開始します。

<ZoomImage id="retention-messaging-configure-sandbox-url.webp" width="700px" alt="Sandbox setup card with the Point your Sandbox URL to Adapty step and the Configure URL button" />

Adapty は App Store Connect アカウントを独自のリアルタイムエンドポイントに接続します。App Store Connect にすでに別の URL が設定されている場合、ボタンは **Replace URL** と表示されます。

接続が成功すると、Adapty は「Sandbox URL has been configured.」と表示して確認します。

### 接続のテスト \{#test-the-connection\}

プロダクションメッセージを送信する前に、AppleはAdaptyがリクエストに迅速に応答するかどうかを確認するテストを実施します。

1. [サンドボックスアカウント](test-purchases-in-sandbox)でプロダクトを購入します。テストにはキャンセルするトランザクションが必要です。
2. **Start Test** をクリックします。テストには数分かかります。失敗した場合は再試行できます。

<ZoomImage id="retention-messaging-test-sandbox-url.webp" width="700px" alt="Sandbox URL performance test running in the dashboard" />

## 本番環境への切り替え \{#switch-to-production\}

サンドボックス環境の設定が完了したら、Adapty の **Sandbox mode** トグルをオフにして本番モードに切り替えることができます。

<ZoomImage id="retention-messaging-sandbox-mode-toggle.webp" width="700px" alt="The Sandbox mode toggle above the messages table" />

**Configure URL** をクリックします。Adapty が本番環境用のエンドポイントを Apple に登録し、「Production URL has been configured.」と表示されて確認が完了します。App Store Connect にすでに別の本番 URL が設定されている場合は、代わりに **Replace URL** をクリックしてください。
