バーチャル通貨のクレジットを販売するには、まずバーチャル通貨を一度定義し、プロダクトにリンクします。

この記事で説明する2つのステップで設定します。プロダクトをリンクすると、購入または更新のたびに自動的にクレジットが付与されます。

## バーチャル通貨を作成する \{#create-a-virtual-currency\}

Adapty ダッシュボードで **Products** > [**Virtual currency**](https://app.adapty.io/virtual-currency) を開きます。

<ZoomImage id="virtual-currency-tab.webp" width="700px" alt="The Virtual currency tab under Products, showing the empty state and the New virtual currency button" />

バーチャル通貨を作成するには：

1. **New virtual currency** をクリックします。ドロワーが **General** ステップで開きます。
2. 通貨の詳細を入力します：
    - **Code**：アプリ内で使用する、`COINS` のような一意の**固定**識別子です。サーバーサイド API で通貨を識別し、各ユーザーの残高を追跡します。
    
        ラテン文字、数字、アンダースコアを使用し、最大32文字まで入力できます。小文字は自動的に大文字に変換されます。
    - **Name**: `Gold` のような表示名です。後から変更できます。
    - **Description**: 通貨に関する任意のメモです。
3. **Continue** をクリックして **Link Products** ステップに進みます。

:::important
通貨の **Code** は作成後に変更できません。**Name** は後から編集できます。
:::

新しい通貨を作成すると、すべてのユーザープロファイルの初期残高は0になります。購入前にユーザーへ残高を付与するには、[初期残高を付与する](grant-initial-balance)を参照してください。

<ZoomImage id="new-currency-step-1.webp" width="500px" alt="新しい仮想通貨ドロワーの「General」ステップ。Code、Name、Descriptionのフィールドが表示されている" />

## プロダクトをリンクする \{#link-products\}

バーチャル通貨にプロダクトをリンクすると、購入またはサブスクリプションの更新時にその通貨のクレジットが付与されます。1つのプロダクトを複数の通貨にリンクしたり、1つの通貨を複数のプロダクトにリンクしたりすることができます。プロダクトは **Link Products** ステップで今すぐリンクするか、後から通貨を編集する際に追加することもできます。

**Link Products** ステップでは、**Associated products** セクションにその通貨を付与するプロダクトの一覧が表示されます。プロダクトを追加するには、**Add associated products** をクリックしてプロダクトを選択してください。

各付与は残高を置き換えるのではなく加算されるため、異なるプロダクトからのクレジットが累積されます。クレジットの設定はプロダクトタイプによって異なります：

- **サブスクリプションプロダクト**には3つのクレジット設定があります：
    - **Credit per cycle**（必須）：初回の有料購入時および各更新時（トライアルから有料への移行更新を含む）に付与されるクレジット。
    - **Credit on trial start**（任意）：無料トライアル開始時に一度だけ付与される別枠のクレジット。
    - **Credits expire at the end of each billing cycle**（チェックボックス）：選択すると、サブスクリプションは1請求期間分のクレジットを付与します。期間終了時に未使用のクレジットは失効します。他のサブスクリプション、買い切り購入、およびサーバーサイドAPIのクレジットは残高に残ります。選択しない場合、クレジットはサイクルをまたいで累積され、失効しません。
- **買い切り購入プロダクト**：**Credit amount**（購入ごとに付与されるクレジット数）を設定します。買い切り購入のクレジットは失効しません。

**Save** をクリックして、プロダクトリンクとともに通貨を作成します。

プロダクトリンクは今後の購入にのみ適用されます。新しくリンクされたプロダクトは、次回の購入または更新時にクレジットを付与します。Adapty は現在のサブスクライバーに対して自動的にクレジットを付与しません。サブスクライバーがサブスクリプションを更新する必要があります。リンクを削除すると、以降のクレジット付与は停止しますが、すでに付与されたクレジットはそのまま残ります。

**Credits expire at the end of each billing cycle** チェックボックスが選択されている場合、有効期限のあるクレジットはサブスクリプションのライフサイクルに従います：

- 更新時の支払いが失敗した場合、未使用のクレジットはグレース期間中もアクセスが継続されていても、支払い済み期間の終了時に失効します。Adaptyは支払いが成功した後に新しいクレジットを付与します。
- キャンセル後、クレジットは支払い済み期間の終了まで維持されます。
- サブスクリプションが失効すると、Adaptyはそのサブスクリプションが付与した残りのクレジットを0にリセットします。
- ストアが支払い済み期間の終了後に報告する遅延更新では、クレジットは付与されません。付与してもすぐに失効してしまうためです。

ストアが購入を返金した場合、Adaptyはその購入分のクレジットを残高から差し引きます：

- **買い切り購入**: その購入で付与されたすべてのクレジット。
- **サブスクリプション**: 返金された金額の割合に応じたクレジットの一部。

Adapty は、ユーザーがまだ使っていないクレジットのみを回収するため、残高が 0 を下回ることはありません。プロファイルの[イベント履歴](virtual-currency-balance#review-balance-changes-in-the-event-history)では、この変更が **Virtual currency revoked** と表示されます。

App Store でユーザーがアップグレードした場合：

- ユーザーは上位プロダクトの**クレジット/サイクル**を全額受け取ります（日割り計算なし）。
- App Store が下位プロダクトの未使用分を返金しても、ユーザーはその下位プロダクトのクレジットを保持します。
- 下位プロダクトの**各請求サイクル終了時にクレジットを失効させる**チェックボックスが選択されている場合、アップグレード時点で未使用のクレジットが失効します。

## 混合残高の消費方法 \{#how-a-mixed-balance-is-spent\}

通貨の残高は、複数のソースからのクレジットを同時に保持できます。たとえば、有効期限のあるサブスクリプション付与と、有効期限のない買い切り購入付与を同時に持つことができます。消費によって残高が引き落とされる際、Adapty はまず有効期限のあるクレジットから消費し、古い付与から順番に消費します。有効期限のあるクレジットがすべてなくなって初めて、有効期限のないクレジットへと移ります。これが、サブスクリプションが失効したときに未消費分のうちそのサブスクリプションから付与された部分のみがリセットされる理由です。買い切り購入で付与されたクレジットは残高にそのまま残ります。

## 次のステップ \{#next-steps\}

通貨を作成してプロダクトをリンクすると、購入時に自動的にクレジットが付与されます。ここからできること：

- 各ユーザーの残高は [仮想通貨残高](virtual-currency-balance) ページで追跡できます。
- サーバーサイドAPIを通じて実行時に残高の付与・消費・読み取りを行えます: [仮想通貨トランザクションの作成](api-adapty/operations/createVirtualCurrencyTransaction) および [仮想通貨残高の一覧取得](api-adapty/operations/listVirtualCurrencyBalances)。実例については [仮想通貨クイックスタート](virtual-currency-quickstart) を参照してください。
- 残高が消費額に不足している場合にチャージフローを開く方法は、[iOS](ios-virtual-currency-top-up) のレシピを参照してください。
