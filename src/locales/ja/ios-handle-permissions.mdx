[フロー](adapty-flow-builder)は、**Request permission** アクションを使って、プッシュ通知の送信許可をユーザーに求めることができます。たとえば、通知の内容を説明するオンボーディング画面などで活用できます。Adapty SDK 自体はシステムの許可ダイアログを表示しません。リクエストをアプリ内の `AdaptySystemRequestsHandler` に渡し、アプリ側でダイアログを表示してユーザーの回答を返すと、フローが続行されます。

## 始める前に \{#before-you-start\}

必要なもの：

- **Adapty iOS SDK 4.0.0 以降**：それより古いバージョンには `AdaptySystemRequestsHandler` がありません。
- **Request permission アクションを含むフロー**：Flow & Paywall Builder で、要素の **On Tap** または **On Screen Appear** トリガーに **Request permission** アクションを追加します。**After response** セクションに、ユーザーが回答した後に実行するアクション（**Navigate Next** など）を追加します。アクションの設定については、[Request permission](onboarding-actions#request-permission) を参照してください。

## フローがパーミッションをリクエストする仕組み \{#how-the-flow-requests-a-permission\}

1. フローが **Request permission** アクションに到達します（ユーザーが要素をタップするか、画面が表示されたとき）。
2. Adapty SDK がハンドラーの `handlePermission(_:withCustomArgs:)` を `.push` とともに呼び出します。
3. アプリが iOS にパーミッションをリクエストし、`.granted` または `.denied` を返します。
4. フローが **After response** アクションを実行します。両方の回答で同じアクションが実行されます。

フローは、アプリが応答を返すまで画面上で待機します。アプリが応答しない場合、フローは画面上に留まります。たとえばユーザーがすでに回答済みの場合など、iOS がダイアログを表示しないときは、アプリが即座に応答を返し、フローは **After response** アクションをすぐに実行します。これらのアクションによって画面が遷移する場合、ユーザーには権限をリクエストする画面が一瞬だけ表示されます。

**On Screen Appear** では、ユーザーが **Navigate back** アクションで画面に戻ってきたとき、フローは再度リクエストを送信しません。**On Tap** では、タップのたびに新しいリクエストが送信されますが、リクエストが回答待ちの間のタップは除きます。

## ハンドラーを実装する \{#implement-the-handler\}

パーミッションリクエストに応答するには、`AdaptySystemRequestsHandler` に準拠するクラスを作成し、`handlePermission(_:withCustomArgs:)` を実装します。アプリがリクエストしないパーミッションには `.denied` を返してください。

```swift showLineNumbers title="Swift"

@MainActor
final class PushPermissionHandler: AdaptySystemRequestsHandler {
    func handlePermission(
        _ permission: AdaptyPermission,
        withCustomArgs customArgs: [String: String]?
    ) async -> AdaptyPermissionResult {
        guard permission == .push else { return .denied(nil) }

        do {
            let granted = try await UNUserNotificationCenter.current()
                .requestAuthorization(options: [.alert, .badge, .sound])
            return granted ? .granted(nil) : .denied(nil)
        } catch {
            return .denied(error.localizedDescription)
        }
    }
}
```

`handlePermission(_:withCustomArgs:)` が受け取る引数:

- **`permission`**: フローがリクエストするパーミッション。**Request permission** アクションは `.push` を送信します。
- **`customArgs`**: リクエストのカスタム引数。**Request permission** アクションは何も送信しないため、値は `nil` になります。

`.granted` と `.denied` は、詳細を含むオプショナルな文字列を受け取ります。`nil` を渡すこともできます。

パーミッションが許可されると、アプリは通知を表示できるようになります。プッシュ通知を受信するには、デバイスを APNs に登録し、デバイストークンをプッシュプロバイダーに送信してください。これは、フロー外でアプリが通常行う処理と同じです。

`AdaptySystemRequestsHandler` は `handleAppReviewRequest()` も宣言しています。デフォルト実装でApp Storeのレビュープロンプトが表示されるため、実装は不要です。

## ハンドラーをフロー設定に渡す \{#pass-the-handler-to-the-flow-configuration\}

:::warning
**ハンドラーがない場合、フローは権限リクエストの時点で停止します。** `systemRequestsHandler` を渡さないと、iOS はダイアログを表示しません。フローはリクエストを送信した画面に留まり、**After response** アクションが実行されません。
:::

フローの権限リクエストをハンドラーに送るには、`AdaptyUI.getFlowConfiguration` の `systemRequestsHandler` パラメーターにハンドラーを渡してください：

<Tabs groupId="ios-sdk-version" queryString>
<TabItem value="4.5" label="SDK 4.5 or later" default>

```swift showLineNumbers title="Swift"
let flowConfiguration = try await AdaptyUI.getFlowConfiguration(
    forFlow: flow,
    preferredLocales: Locale.preferredLanguages,
    systemRequestsHandler: PushPermissionHandler()
)
```

</TabItem>
<TabItem value="4.4" label="SDK 4.0–4.4">

```swift showLineNumbers title="Swift"
let flowConfiguration = try await AdaptyUI.getFlowConfiguration(
    forFlow: flow,
    systemRequestsHandler: PushPermissionHandler()
)
```

</TabItem>
</Tabs>

フロー設定はハンドラーへの強参照を保持するため、ハンドラーを別途保存する必要はありません。SwiftUI と UIKit のどちらもこの設定を使ってフローを表示するため、ハンドラーはどちらでも機能します。詳細については、[フローとペイウォールの表示](ios-present-paywalls)を参照してください。

## 権限リクエストをテストする \{#test-the-permission-request\}

iOS では、通知ダイアログはアプリのインストールごとに1回しか表示されません。テスト中にダイアログを再表示するには、デバイスからアプリを削除して再インストールしてください。その後、フローを開いて **Request permission** アクションに進んでください。画面がそのまま表示されてダイアログが表示されない場合、フローが応答を受け取れていません。`systemRequestsHandler` を `AdaptyUI.getFlowConfiguration` に渡していることを確認してください。
