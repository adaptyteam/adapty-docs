AppleとGoogleは、[App Store サーバー通知](enable-app-store-server-notifications)と[リアルタイムデベロッパー通知](enable-real-time-developer-notifications-rtdn)を通じて、サブスクリプションイベントをAdaptyサーバーに直接報告します。これにより、ユーザーがコンバート、更新、または解約したことを把握できます。

これらのイベントを転送するには、Adapty でデスティネーションを設定します。サードパーティプラットフォーム（MMP、アナリティクス、メッセージングツール）はそれぞれ専用のインテグレーションページがあります。自社のバックエンドへは[ウェブフック](webhook)でイベントを受け取れます。

すべてのイベントは共通の構造を持ちますが、フィールドはイベントタイプ、ストア、設定によって異なります。[ウェブフックイベントタイプとフィールド](webhook-event-types-and-fields)ではウェブフックのペイロードを説明しており、各インテグレーション記事ではそのデスティネーションが受け取るフォーマットを説明しています。[イベントステータス](event-statuses)では配信ステータスの見方を説明しています。

## 例 \{#examples\}

ほとんどのイベントは、最初の課金から有効期限切れまでのユーザーの購入に沿って発生します。

### ユーザーがトライアル中にキャンセルする場合 \{#the-user-cancels-during-the-trial\}

_ユーザーが4月1日に7日間のトライアル付き月額サブスクリプションを有効化し、4日目にサブスクリプションを解除した場合。_

この場合、以下のイベントが送信されます：

1. 4月1日に `trial_started`
2. 4月4日に `trial_renewal_cancelled`
3. 4月7日に `trial_expired`

### ユーザーがコンバージョン後にキャンセルした場合 \{#the-user-cancels-after-converting\}

_ユーザーは4月1日に7日間のトライアル付き月次サブスクリプションを有効化し、10日目に解約しました。_

この場合、以下のイベントが送信されます：

1. `trial_started`：4月1日
2. `trial_converted`：4月7日
3. `subscription_renewal_cancelled`：4月10日
4. `subscription_expired`：5月1日

各シナリオでどのイベントが発生するかの詳細については、[イベントフロー](event-flows)をご覧ください。

## イベントリスト \{#event-list\}

各インテグレーションが受け取るイベントを制御できます。ほとんどのイベントはすべてのインテグレーションで利用できますが、以下の3つは例外です。

- **Access level updated** は、[webhook インテグレーション](webhook)が設定されており、かつイベントが有効になっている場合にのみトリガーされます。[Event Feed](https://app.adapty.io/event-feed) に表示され、webhook に送信されますが、他のインテグレーションには届きません。webhook インテグレーションが設定されていない場合、またはイベントタイプが有効になっていない場合、Adapty はイベントを作成せず、Event Feed にも表示されません。
- **Trial still active** と **Subscription still active** は[合成イベント](#synthetic-events)であり、一部のインテグレーションのみが受信します。

## 合成イベント \{#synthetic-events\}

ほとんどのイベントは、購入・更新・解約などの変化をトリガーにして発火します。**Trial still active** と **Subscription still active** イベントはその逆です。タイマーを設定しておくと、タイマーが切れたタイミングで Adapty がトライアルまたはサブスクリプションのステータスを確認します。トライアルやサブスクリプションが**終了していなかった**場合、Adapty が対応するイベントを発火します。

これらの合成イベントは、Adjust、Amplitude、AppMetrica、AppsFlyer、Branch、Facebook Analytics、Firebase、Mixpanel、OneSignal、PostHog、Singular、SplitMetrics、および Webhook で利用できます。手動で有効にする必要があります。

ユーザーがタイマーの期限が切れる前に自動更新をオフにした場合、Adapty は送信をスキップします。アクセスが支払い済み期間の終わりまで続いているにもかかわらず、そのユーザーを離脱済みとしてカウントします。

このイベントをオフにすると、Adapty は新しいタイマーの開始を停止します。すでに実行中のタイマーは期限が切れると送信されるため、設定した遅延時間の分だけ、送信先がイベントを受け取り続ける場合があります。

:::note
Adapty アトリビューションでは、Meta および TikTok キャンペーン向けに同様の機能を提供しています。[クオリファイドトライアル](ua-facebook#qualified-trial)はトライアルイベントを1〜24時間保留します。`trial_active` は1〜90日間待機します。どちらも、ユーザーが自動更新をオフにした場合はイベントの送信をスキップします。それぞれ異なる場所で設定し、互いに影響しません。
:::

### トライアルが進行中の場合 \{#the-trial-is-still-running\}

- **インテグレーション**: AppsFlyer
- **イベント**: トライアルがアクティブ
- **遅延**: 3日
- **トライアル開始**: 4月1日
- **トライアル終了**: 4月7日

AppsFlyer が受信するイベント:

1. 4月1日に `trial_started`
2. 4月4日に `trial_active`
3. 4月7日に `trial_converted`

次の点に注意してください:
- トライアルがコンバートされているため、`subscription_active` イベントは受信されません。
- 遅延を7日に設定した場合、`trial_active` はまったく届きません。その時点では、ユーザーはすでにコンバートしているためです。

### サブスクリプションが継続中の場合 \{#the-subscription-is-still-running\}

- **インテグレーション**: Webhook
- **イベント**: サブスクリプションがアクティブ
- **遅延**: 7日間
- **サブスクリプション開始日**: 4月1日（トライアルなし）
- **更新日**: 5月1日

Webhookが受け取るイベント:

1. 4月1日に `subscription_started`
2. 4月8日に `subscription_active`
3. 5月1日に `subscription_renewed`

- サブスクリプションはトライアルなしで開始する必要があります。トライアルから変換された場合は `trial_converted` が送信され、タイマーはスタートしません。
- ユーザーが4月3日に自動更新をオフにした場合、アクセス期限が5月1日まであるにもかかわらず、`subscription_active` は届きません。
- 5月の更新では2回目のタイマーはスタートしません。`subscription_active` は1つのサブスクリプションにつき1回だけ受信します。
