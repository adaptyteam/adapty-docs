ユーザーがプロダクトを購入したりサブスクリプションを更新したりすると、AIトークン、クレジット、コインなどのバーチャル通貨を付与できます。通貨を一度定義してプロダクトと紐付けるだけで、Adaptyが自動的に各ユーザーの残高を管理します。アプリは[サーバーサイドAPI](getting-started-with-server-side-api)を通じて残高の読み取りと消費ができます。たとえば、生成ごとにトークンを消費するといった使い方が可能です。

## 仕組み \{#how-it-works\}

1. [仮想通貨を作成する](create-virtual-currency): **Products** を開き、**Virtual currency** タブをクリックします。**New virtual currency** をクリックし、コード、名前、任意で説明を設定して通貨を定義します。
2. **通貨をプロダクトに紐付ける**: 通貨を買い切り購入またはサブスクリプションプロダクトにマッピングし、各購入で付与されるクレジット数を設定します。
3. **クレジットは自動的に付与される**: ユーザーが紐付けられた買い切りプロダクトを購入するか、紐付けられたサブスクリプションが更新されると、Adaptyは設定されたクレジットをユーザーの残高に追加します。
4. **残高の確認と消費**: アプリはサーバーサイドAPIを通じて各ユーザーの残高を参照し、クレジットの付与や消費を行います。同じAPIを使って、まだ何も購入していないユーザーに[初期残高を付与](grant-initial-balance)することもできます。
5. **すべての変更を追跡する**: 残高の変更はそれぞれ[ユーザーのプロファイル](virtual-currency-balance)に一覧表示されます。

通貨の設定からAPIを使ったクレジット消費まで、すべての手順を確認するには、[バーチャル通貨クイックスタート](virtual-currency-quickstart)を参照してください。

## ユースケース \{#use-cases\}

| アプリの種類 | バーチャル通貨の活用方法 |
|----------|-------------------------------|
| **AI アプリ**（画像・動画・テキスト生成） | 生成ごとにクレジットを消費。サブスクリプションに毎月のクレジット付与を含め、クレジットパックを買い切り商品として販売する。 |
| **ショートドラマ・動画アプリ** | エピソードのアンロックにコインを消費。サブスクライバーには定期的なコイン付与を行い、コインパックを買い切り商品として販売する。 |
| **語学学習・教育** | サーバーサイド API を通じて無料ユーザーにハートやライフの限定付与を行う。有料プランではより多く付与するか、残高チェック自体をスキップする。 |
| **モバイルゲーム** | ソフト通貨とハード通貨を併用：サーバーサイド API でゲームプレイ報酬としてゴールドを付与し、ジェムは課金販売し、単一のアトミックトランザクションで相互交換できるようにする。 |
| **生産性アプリ** | OCR やエクスポートなどコストの高い操作をクレジットで計量。無料ユーザーには少量を付与し、サブスクリプションではより多く付与し、まとめ作業向けにクレジットパックを販売する。 |

:::tip
サブスクリプションの利用枠には、[クレジットの有効期限](create-virtual-currency#link-products)を有効にしてください。未使用のクレジットが更新のたびにリセットされることで、利用枠がサブスクリプションを継続する動機になり、ヘビーユーザーはストックを使い切るのではなく、クレジットパックを購入するようになります。
:::

## トランザクションにラベルを付ける \{#label-transactions\}

バックエンドが[仮想通貨トランザクションの作成](api-adapty/operations/createVirtualCurrencyTransaction)を通じてクレジットを付与または消費する際は、各トランザクションにその意味と用途をラベルとして付けてください。`operation` を使うと、トランザクション履歴の中で消費・ボーナス・返金・修正を区別できます。`feature` を使うと、ユーザーが何に消費しているか、また何に対して付与しているかを把握できます。

すべてのラベルフィールドはオプションです。Adapty がトランザクションを保存した後にラベルを追加することはできないため、最初の呼び出し時にラベルを設定してください。ラベルなしで送信されたトランザクションは `operation: null` として保存されます。

```json title="Spend credits on a feature"
{
  "items": [{ "currency_code": "COINS", "amount": -10 }],
  "operation": "spend",
  "feature": "power_up.extra_life",
  "customer_placement_id": "level-complete",
  "reference_id": "session_7781"
}
```

### オペレーション \{#operation\}

ほとんどのインテグレーションで必要な `operation` の値は以下の通りです：

| 値 | 使用するタイミング |
|-------|----------------|
| `spend` | ユーザーが機能またはコンテンツにクレジットを使う。 |
| `spend_reversal` | 生成失敗などの失敗したアクションに対してクレジットを返却する。 |
| `reward` | ボーナス、報酬、またはサポート補償としてクレジットを付与する。 |
| `reward_reversal` | 報酬を取り消す。 |

Adaptyは、作成するトランザクションに`operation`を設定します。購入、更新、トライアルには`top_up`、ストアの返金には`refund`、期限切れのクレジットには`expiry`が設定されます。値の完全なリストについては、[仮想通貨トランザクションの作成](api-adapty/operations/createVirtualCurrencyTransaction)をご覧ください。

### 機能 \{#feature\}

`feature` は、クレジットの消費または付与の対象となった機能を示します。英字・数字・`_` からなる1単語で、ドットの後にサブタイプを1つ付けることもできます。Adapty は送信された値をそのまま（大文字・小文字を区別して）保存するため、`photoFilter` と `photofilter` は異なる機能として扱われます。

- ✅ `hint`, `power_up.extra_life`, `photo_filter.vintage`
- ❌ `photo filter`: スペースが含まれています。
- ❌ `photo_filter.vintage.v2`: サブタイプが2階層になっています。
- ❌ `pack_499`, `premium_tier`: 名前に価格やティアが含まれると、価格やティアが変わるたびに1つの機能が複数に分裂してしまいます。`feature` には価格・ティア・バージョン・バリアントを含めないでください。

ボーナスには、`welcome`、`daily_bonus`、`referral`、`support_compensation` のようにプログラム名を使用してください。

### その他のフィールド \{#other-fields\}

- **`reference_id`**: 関連オブジェクトのID（最大128文字）。`spend_reversal` をそれが取り消す `spend` に紐付けたり、`reward` をその付与のきっかけとなったアクションに紐付けたりする際に使用します。個人情報は含めないでください。
- **`customer_placement_id`**: 操作が発生したアプリ内画面のID。Adapty の[プレースメント](placements) IDではなく、独自のIDを指定します。
- **`store` と `store_transaction_id`**: バックエンドが購入に対してコインを付与する場合は、両方を一緒に送信してください。Adapty は購入の存在を検証しません。ストアで購入が払い戻された場合、Adapty はこの参照で付与されたコインを回収します。
- **`is_sandbox`**: テスト中に付与するクレジットには `true` を送信してください。ストアトランザクションの場合、Adapty は購入環境に基づいて自動的に設定します。

:::warning
[通貨にリンクされている](create-virtual-currency#link-products)プロダクトに対してコインを付与しないでください。Adapty はそれらの購入をすでに付与しているため、バックエンドから付与すると、ユーザーに二重でクレジットされてしまいます。
:::

ラベリングが利用可能になった2026年11月12日より前に作成されたトランザクションはデータを保持しています。Adapty は自社のトランザクションに遡ってラベルを付与しており、それ以前の日付の API トランザクションは `operation: null` のままになります。`metadata` は変更されておらず、必要なキーを引き続き受け付けます。

## 制限事項 \{#limitations\}

- **デバイス間でのアクセスには識別が必要**: 残高は1つのプロファイルに紐付きます。匿名ユーザーは、残高を獲得したインストール環境でのみ残高を保持するため、アプリを再インストールしたり別のデバイスで開いたりすると残高が失われます。すべてのデバイスおよび再インストール後も残高を利用できるようにするには、ユーザーを識別してください。詳しくは[残高、プロファイル、デバイス](virtual-currency-balance#balances-profiles-and-devices)をご覧ください。
- **サーバーサイドのみ**: 残高の読み取りや消費を行うSDKメソッドはまだないため、アプリにはバックエンドが必要です。バックエンドでは、サーバーサイドAPIを通じて残高を読み取り、クレジットの付与や消費を行います。
- **アプリごとに最大20通貨**: 1つのアプリで最大20種類のバーチャル通貨を作成できます。
