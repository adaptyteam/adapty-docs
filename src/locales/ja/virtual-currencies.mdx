ユーザーがプロダクトを購入したりサブスクリプションを更新したりするたびに、AIトークン、クレジット、コインなどの仮想通貨を付与できます。通貨を一度定義してプロダクトに紐付けるだけで、Adaptyが各ユーザーへの付与と残高管理を自動で行います。アプリ側は[サーバーサイドAPI](getting-started-with-server-side-api)を通じて残高の読み取りや消費ができます（例：生成ごとにトークンを消費するなど）。

:::tip
Claude CodeやCodexなどのAIコーディングツールから仮想通貨を管理するには、[Adaptyプラグインをインストール](virtual-currencies-skill#install-the-skill)して、エージェントに「スターターパックに50ジェムを付与して」などと指示してください。[virtual-currencies スキル](virtual-currencies-skill)は[Adapty CLI](developer-cli-virtual-currencies)または[Adapty MCPサーバー](adapty-mcp)を通じて動作し、各変更はあなたの確認後にのみ実行されます。
:::

## 仕組み \{#how-it-works\}

1. [仮想通貨を作成する](create-virtual-currency): **Products** を開き、**Virtual currency** タブをクリックします。**New virtual currency** をクリックします。コード、名前、オプションの説明を設定して通貨を定義します。
2. **通貨をプロダクトにリンクする**: 通貨を買い切り購入またはサブスクリプションのプロダクトにマッピングし、各購入で付与するクレジット数を設定します。
3. **クレジットは自動的に付与される**: ユーザーが通貨にリンクされたプロダクトを購入すると、Adapty は設定されたクレジットを残高に追加します。サブスクリプションの場合、Adapty は更新のたびにクレジットを追加します。ユーザーが無料トライアルを開始した場合、**Credit on trial start** を設定した場合のみクレジットが追加されます。Adapty が [webhook](webhook-event-types-and-fields#virtual-currency-credits) とアナリティクス連携に送信する購入イベントには、これらのクレジットが `virtual_currency_credits` に含まれます。
4. **残高を読み取り・消費する**: アプリはサーバーサイド API を通じて各ユーザーの残高を読み取り、クレジットを付与または消費します。同じ API を使用して、まだ何も購入していないユーザーに[初期残高を付与](grant-initial-balance)することもできます。
5. **すべての変更を追跡する**: 残高の変更はすべて[ユーザーのプロファイル](virtual-currency-balance)に記録されます。サポートチームも、プロファイルから[手動で残高をクレジットまたはデビット](virtual-currency-balance#adjust-a-balance-manually)できます。
6. **通貨別に収益を計測する**: 通貨別の収益やその他の指標を確認するには、アナリティクスチャートを[**Virtual currency**](controls-filters-grouping-compare-proceeds#filter-and-group-data)でフィルタリングします。
7. **残高によるユーザーターゲティング**: 残高が低いまたは高いユーザーに異なるペイウォールやオンボーディングを表示するには、[仮想通貨残高によるセグメント](segments#virtual-currency-balance)を作成し、[オーディエンス](audience)として使用します。
8. **トランザクション履歴をエクスポートする**: すべての残高変更をデータウェアハウスに読み込むには、[Amazon S3](s3-exports#virtual-currency-transactions) または [Google Cloud Storage](google-cloud-storage#virtual-currency-transactions) への日次エクスポートを有効にします。

通貨の設定からAPIを使ったクレジット消費まで、すべての手順を確認するには、[バーチャル通貨クイックスタート](virtual-currency-quickstart)を参照してください。

## ユースケース \{#use-cases\}

| アプリの種類 | バーチャル通貨の活用方法 |
|----------|-------------------------------|
| **AIアプリ**（画像・動画・テキスト生成） | 生成ごとにクレジットを消費。サブスクリプションに月次クレジット枠を含め、クレジットパックを買い切り購入として販売。 |
| **ショートドラマ・動画アプリ** | エピソードのアンロックにコインを消費。サブスクライバーには定期的なコイン枠を付与し、コインパックを買い切り購入として販売。 |
| **語学学習・教育** | サーバーサイドAPIを通じて無料ユーザーにハートやライフの限定枠を付与。有料プランではより多くの枠を付与するか、残高チェック自体をスキップ。 |
| **モバイルゲーム** | ソフト通貨とハード通貨を並行運用：サーバーサイドAPIを通じてゲームプレイでゴールドを付与し、<InlineTooltip tooltip="ジェムを販売">[iOS](ios-virtual-currency-top-up)</InlineTooltip>、そして単一のアトミックトランザクションで相互変換。 |
| **生産性アプリ** | OCRやエクスポートなどコストのかかるアクションをクレジットで計量。無料ユーザーには少量の枠を付与し、サブスクリプションでより多くを付与、バッチ作業向けにはクレジットパックを販売。 |

:::tip
サブスクリプション特典に関しては、[クレジット有効期限](create-virtual-currency#link-products)をオンにすることをおすすめします。有効期限を設定することで、ユーザーは請求期間をまたいでクレジットを貯めることができなくなります。新しいクレジットを受け取るにはサブスクリプションを更新する必要があり、ヘビーユーザーはクレジットパックを購入できます。
:::

## トランザクションにラベルを付ける \{#label-transactions\}

バックエンドが[仮想通貨トランザクションの作成](api-adapty/operations/createVirtualCurrencyTransaction)を通じてクレジットを付与または消費する際は、各トランザクションにその意味と用途をラベルとして付けてください。`operation` を使うと、トランザクション履歴の中で消費・ボーナス・返金・修正を区別できます。`feature` を使うと、ユーザーが何に消費しているか、また何に対して付与しているかを把握できます。

すべてのラベルフィールドはオプションです。Adapty がトランザクションを保存した後にラベルを追加することはできないため、最初の呼び出し時にラベルを設定してください。ラベルなしで送信されたトランザクションは `operation: null` として保存されます。

```json title="Spend credits on a feature"
{
  "items": [{ "currency_code": "COINS", "amount": -10 }],
  "operation": "spend",
  "feature": "power_up.extra_life",
  "customer_placement_id": "level-complete",
  "reference_id": "session_7781"
}
```

### オペレーション \{#operation\}

ほとんどのインテグレーションで必要な `operation` の値は以下の通りです：

| 値 | 使用するタイミング |
|-------|----------------|
| `spend` | ユーザーが機能またはコンテンツにクレジットを使う。 |
| `spend_reversal` | 生成失敗などの失敗したアクションに対してクレジットを返却する。 |
| `reward` | ボーナス、報酬、またはサポート補償としてクレジットを付与する。 |
| `reward_reversal` | 報酬を取り消す。 |

Adaptyは、作成するトランザクションに`operation`を設定します。購入、更新、トライアルには`top_up`、ストアの返金には`refund`、期限切れのクレジットには`expiry`が設定されます。値の完全なリストについては、[仮想通貨トランザクションの作成](api-adapty/operations/createVirtualCurrencyTransaction)をご覧ください。

### 機能 \{#feature\}

`feature` は、クレジットの消費または付与の対象となった機能を示します。英字・数字・`_` からなる1単語で、ドットの後にサブタイプを1つ付けることもできます。Adapty は送信された値をそのまま（大文字・小文字を区別して）保存するため、`photoFilter` と `photofilter` は異なる機能として扱われます。

- ✅ `hint`, `power_up.extra_life`, `photo_filter.vintage`
- ❌ `photo filter`: スペースが含まれています。
- ❌ `photo_filter.vintage.v2`: サブタイプが2階層になっています。
- ❌ `pack_499`, `premium_tier`: 名前に価格やティアが含まれると、価格やティアが変わるたびに1つの機能が複数に分裂してしまいます。`feature` には価格・ティア・バージョン・バリアントを含めないでください。

ボーナスには、`welcome`、`daily_bonus`、`referral`、`support_compensation` のようにプログラム名を使用してください。

### その他のフィールド \{#other-fields\}

- **`reference_id`**: 関連オブジェクトのID（最大128文字）。`spend_reversal` をそれが取り消す `spend` に紐付けたり、`reward` をその付与のきっかけとなったアクションに紐付けたりする際に使用します。個人情報は含めないでください。
- **`customer_placement_id`**: 操作が発生したアプリ内画面のID。Adapty の[プレースメント](placements) IDではなく、独自のIDを指定します。
- **`store` と `store_transaction_id`**: バックエンドが購入に対してコインを付与する場合は、両方を一緒に送信してください。Adapty は購入の存在を検証しません。ストアで購入が払い戻された場合、Adapty はこの参照で付与されたコインを回収します。
- **`is_sandbox`**: テスト中に付与するクレジットには `true` を送信してください。ストアトランザクションの場合、Adapty は購入環境に基づいて自動的に設定します。

:::warning
[通貨にリンクされている](create-virtual-currency#link-products)プロダクトに対してコインを付与しないでください。Adapty はそれらの購入をすでに付与しているため、バックエンドから付与すると、ユーザーに二重でクレジットされてしまいます。
:::

ラベリングが利用可能になった2026年11月12日より前に作成されたトランザクションはデータを保持しています。Adapty は自社のトランザクションに遡ってラベルを付与しており、それ以前の日付の API トランザクションは `operation: null` のままになります。`metadata` は変更されておらず、必要なキーを引き続き受け付けます。

## 制限事項 \{#limitations\}

- **クロスデバイスのアクセスには識別が必要**: 残高は1つのプロファイルに紐づいています。匿名ユーザーは、クレジットを獲得したインストール環境でのみ残高を保持できるため、アプリを再インストールしたり別のデバイスで開いたりすると残高が失われます。すべてのデバイスおよび再インストール後も残高を利用できるようにするには、ユーザーを識別してください。詳細は[残高、プロファイル、デバイス](virtual-currency-balance#balances-profiles-and-devices)を参照してください。
- **サーバーサイドのみ**: 残高の読み取りや消費を行うSDKメソッドはまだないため、アプリにはバックエンドが必要です。バックエンドはサーバーサイドAPIを通じて残高を読み取り、クレジットの付与や消費を行います。
- **アプリごとに最大20通貨**: 1つのアプリで最大20種類の仮想通貨を作成できます。
- **一部の購入ではクレジットが付与されない**: [カスタムストア](custom-store)での購入、[Apple ファミリー共有](apple-family-sharing)で共有された購入、およびインポートされた過去の購入にはクレジットが付与されません。
- **サンドボックスと本番環境で共通の残高**: サンドボックスでの購入は、実際の購入と同じ残高にクレジットとして追加されます。実際のユーザーのアカウントではなく、テストアカウントを使用してテスト購入を行ってください。
