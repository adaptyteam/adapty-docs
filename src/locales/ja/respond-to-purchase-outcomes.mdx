ペイウォール画面の後もフローを継続できます。オンボーディングを再開したり、新規サブスクライバーにサンキュー画面を表示したり、以前の購入を復元したユーザーを歓迎したりすることが可能です。

アクションの設定では、購入条件ごとにアウトカムを設定します。アクションを設定しないアウトカムは、ユーザーをペイウォール画面に留まらせます。

- **Purchase** アクションには次の条件があります：**When succeeded**、**When failed**、**When cancelled by user**、**When pending**。
- **Restore purchases** アクションには **When restore completed** と **When restore failed** の2つの条件があります。

## 始める前に \{#before-you-start\}

以下を確認してください：

- アプリが Adapty SDK v4.0 以降を使用している。
- フローにペイウォール画面がある。作成方法は [基本的なペイウォール画面の作成](basic-paywall-screen) レシピを参照。
- ペイウォール画面のボタンなどの要素に [**Purchase** アクション](paywall-product-block#trigger-a-purchase) が設定されている。
- アプリがフローを開いたままの状態で <InlineTooltip tooltip="購入と復元のコールバック">[iOS](ios-handling-events)、[Android](android-handling-events)、[React Native](react-native-handling-events-1)、[Flutter](flutter-handling-events)、[Unity](unity-handling-events)、[Kotlin Multiplatform](kmp-handling-events)、[Capacitor](capacitor-handling-events)</InlineTooltip> を処理している。

## 結果に対するアクションを追加する \{#add-actions-for-a-result\}

:::important
フローが応答できるのは **In-App Store** での購入のみです。**Web Payment** での購入結果は受け取れません。
:::

1. **Purchase** または **Restore purchases** アクションが設定された要素を選択します。
2. **Purchase** または **Restore purchases** アクションをクリックします。
3. **When succeeded** など、必要な購入または復元の結果に対して、<Inline id="plus.svg" alt="Add action" /> をクリックします。
4. **Action** ドロップダウンから、**Do nothing** の代わりに実行するアクションを選択します。

:::note
**Purchase** または **Restore purchases** の後に同じトリガーで**Close Flow** アクションを続けると、結果が返る前にすぐ実行されてしまいます。代わりにアウトカムアクションとして追加してください。
:::

:::tip
**Purchase** アクションにアウトカムアクションが設定されている場合、ダブルタップしても2回目の購入は開始されません。ストアが結果を返すまで（最大60秒）、そのアクションへの追加タップはフローによって無視されます。**Restore purchases** も同様に動作します。
:::

アプリでアウトカムアクションを確認するには、[サンドボックス購入を行ってください](test-purchases-in-sandbox)。

[Adaptyモバイルアプリでのプレビュー](paywall-device-compatibility-preview#preview-on-devices)では、実際の購入はできません。

フローがアプリ内で結果アクションをスキップする場合は、[フローが結果アクションをスキップする理由](flow-common-issues#the-flow-doesnt-run-the-actions-set-for-a-purchase-result)をご覧ください。

:::tip
購入結果をアプリのコードで処理したい場合（例：ネイティブ画面を開くなど）は、Adapty SDK の購入コールバックや復元コールバックを使用してください。そのコードを変更するたびにアプリのリリースが必要になります。購入後に別のフローを開いている場合は、そのスクリーンをペイウォールを含むフローに移動することもできます。
:::

### 購入成功後に次の画面を表示する \{#show-the-next-screen-after-a-successful-purchase\}

購入成功後にオンボーディングを続けたり、サンクスページを表示するには、**When succeeded** のアウトカムと [**Navigate to Screen**](onboarding-actions#navigate-to-screen) アクションを組み合わせ、遷移先としてその画面を選択してください。

### 購入成功後にフローを閉じる \{#close-the-flow-after-a-successful-purchase\}

購入が成功した後にフローを終了するには、ナビゲーションの代わりに **When succeeded** に [**Close Flow**](onboarding-actions#close-flow) を追加します。これにより、フローは購入が成功したときのみ閉じられるため、アプリのコードでフローを閉じる処理は不要です。

### 失敗・キャンセル・保留中の購入に対応する \{#respond-to-a-failed-canceled-or-pending-purchase\}

**Purchase** アクションの各結果に対してアクションを追加することで、失敗・キャンセル・保留中の購入後にアラートや画面を表示できます。

- **When failed**: エラーが発生して購入が失敗しました。たとえば、後でもう一度お試しくださいとユーザーに伝える[アラートを表示](onboarding-actions#show-alert)します。
- **When cancelled by user**: ユーザーが購入をキャンセルしました。たとえば、別のオファーを表示する画面を表示します。
- **When pending**: 銀行が支払いを確認している間や、iOS の「承認購入を依頼」で保護者が承認するのを待っている間など、購入が承認待ちになっています。銀行や保護者が承認してもフローは応答しないため、待機中であることを説明する画面を表示します。

:::tip
失敗した購入を再試行できるようにするには、たとえば **When failed** にアラートを設定するなど、ユーザーをペイウォールにとどめてください。アウトカムに **Purchase** や **Restore purchases** を追加することはできません。
:::

### 購入の復元に応答する \{#respond-to-a-purchase-restoration\}

[**Restore purchases**](paywall-product-block#restore-purchases) アクションには、**When restore completed** と **When restore failed** の2つの結果があります。

**When restore completed** は、復元がエラーなく完了したことを意味し、ユーザーがアクセス権を持っていることを意味するわけではありません。フロー内でアクセスレベルを確認することはできません。アクセスに依存するコンテンツを表示するには、**When restore completed** に **Close Flow** を追加し、アプリ内で[アクセスレベル](access-level)を確認してください。
