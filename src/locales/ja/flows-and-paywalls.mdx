ペイウォール画面はプロダクトを表示し、ユーザーが購入できるようにします。Adaptyでは、以下の2つの方法で作成できます：

- **フローとペイウォール**: [フロー＆ペイウォールビルダー](adapty-flow-builder)でスクリーンをデザインすると、Adapty SDK がアプリ内にネイティブでレンダリングします。単独のペイウォールを作ることも、ペイウォールで締めくくるオンボーディング全体を作ることもできます。
- **カスタムペイウォール**: 自分のアプリコードでスクリーンを実装し、販売するプロダクトを Adapty に[カスタムペイウォール](paywalls)として保存します。購入処理は Adapty が行います。

## フローとペイウォールをカスタムペイウォールと比較する \{#compare-flows--paywalls-with-custom-paywalls\}

| | フロー & ペイウォール | カスタムペイウォール |
|---|---|---|
| **UIを作るのは誰か** | あなた自身が、ビジュアルなノーコードエディターで作成します。SDKはWebビューなしでネイティブにレンダリングします。 | あなたの開発者が、アプリのコード内で作成します。 |
| **開始方法** | [テンプレート](paywall-builder-templates)、白紙のキャンバス、または[Figmaインポート](import-from-figma)から始められます。 | 既存の画面とデザインシステムを使用します。 |
| **ダッシュボードでAIを使って作成** | [AIエディター](flow-ai-editor)が、テキストによる指示や参考スクリーンショットをもとに、画面のスタイル変更・テキスト書き直し・レイアウト変更を行います。 | 利用不可。 |
| **AIコーディングツールで作成** | [flow-generatorスキル](flow-generator-skill)が説明文やスクリーンショットからフローまたはペイウォールを作成し、コピー・ロケール・画面を編集します。[flow-auditスキル](flow-audit-skill)は公開前に問題がないかレビューします。 | [SDKインテグレーションスキル](adapty-sdk-integration-skill)が[Developer CLI](developer-cli-paywalls#adapty-paywalls-create)経由でカスタムペイウォールを作成し、アプリの購入コードを記述します。 |
| **アプリリリースなしで変更できる範囲** | デザイン、コピー、画面、ロジック、プロダクト。 | コードが読み取る[リモートコンフィグ](customize-paywall-with-remote-config)の値。レイアウト変更にはアプリリリースが必要です。 |
| **オーディエンスごとに異なるデザイン** | 作成したフローをプレースメントのオーディエンスに割り当てられます。 | ユーザーが実行しているアプリバージョンに組み込まれたデザインのみ。 |
| **マルチ画面ジャーニー** | ペイウォールの前にオンボーディング画面、[クイズ](onboarding-quizzes)、[分岐](onboarding-navigation-branching)を配置でき、ユーザーの回答を[アプリに渡す](ios-flow-input)こともできます。 | コードで構築するものすべて。 |
| **ローカライゼーション** | ビルダー内で画面ごとの[ロケール](add-paywall-locale-in-adapty-paywall-builder)を設定。 | ロケールごとの[リモートコンフィグ](add-remote-config-locale)で、ダッシュボード上でAI翻訳も利用可能。 |
| **A/B テスト** | フロープレースメント上のフローまたはペイウォール間で実施。 | ペイウォールプレースメント上のカスタムペイウォール間で実施。 |
| **アナリティクス** | [フロー指標](flow-metrics)で、収益が各画面に紐付けられます。ビューは自動的に追跡されます。 | [カスタムペイウォール指標](paywall-metrics)。コードでAdaptyに各ビューを報告します。 |
| **Web購入** | [Webペイウォール](web-paywall)を使用して対応。 | [Webペイウォール](web-paywall)を使用して対応。 |
| **アプリサイズ** | アプリがフローを取得する際にAdaptyから画面と画像が読み込まれるため、新しいペイウォールをアプリバンドルに追加する必要はありません。 | すべての画面、画像、文字列がアプリバンドルに含まれます。 |
| **プレースメントタイプ** | [フロープレースメント](create-placement)。 | [ペイウォールプレースメント](create-placement)。 |
| **Adapty SDK** | v4.0以降。 | すべてのバージョン。 |

ペイウォールビルダーで作成したペイウォールとカスタムペイウォールは、それぞれ異なるプレースメントタイプが必要なため、同じ A/B テストで使用することはできません。比較したい場合は、ビルダーで作成したペイウォールを専用のプレースメントで[段階的にロールアウト](flow-gradual-rollout)してください。

## どちらを選ぶべきか \{#which-one-to-choose\}

- **フローとペイウォールを選ぶ場合**：UI コードを書いたりアプリをリリースしたりせずに購入画面をデザイン・テスト・変更したいとき、またはペイウォールをオンボーディングの一部として使用したいとき。
- **カスタムペイウォールを選ぶ場合**：自分のコードで画面を構築したいとき（例：アプリのコンポーネントを再利用する場合など）。

アプリがスクリーンを表示するとき、Adaptyのカスタムペイウォールは、週次プランや月次プランなど、そのスクリーンで販売するプロダクトの固定セットです。Adaptyはペイウォールごとにコンバージョンと収益をレポートするため、どのプロダクトセットがより売れているかを比較できます。1つのプレースメントで異なるオーディエンスに異なるペイウォールを表示し、それらをA/Bテストで比較することも可能です。別のプロダクトを販売するには、ダッシュボードのプレースメント上のペイウォールを入れ替えるだけで、アプリのリリースは不要です。

どちらも Adapty メインメニューの **Flows & Paywalls** にあります。フローとペイウォールは **Flow & Paywall builder** タブに、カスタムペイウォールは **Custom Paywalls** タブにあります。

[旧ペイウォールビルダー](adapty-paywall-builder)で作成したペイウォールは **Custom Paywalls & Legacy** タブで引き続き編集できますが、新規作成はできません。Adapty SDK 3.x 向けに作成したペイウォールをドラフトのフローとして再作成しながら元のペイウォールを公開したまま維持するには、**Move to new builder** アクションを使用してください（[ペイウォールをフローに変換する](convert-paywall-to-flow)を参照）。プレースメントや SDK アップグレードを含む完全な移行については、[フローへの移行](migrate-to-flows)を参照してください。
