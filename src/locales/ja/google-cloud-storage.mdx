Google Cloud Storage 連携を有効にすると、[サブスクリプションイベント](events)と[ペイウォール訪問データ](paywall-metrics)を Google Cloud Storage バケットに一元的かつ安全に保存できます。

毎日UTC午前4時に、Adaptは前日のデータを含む.csvファイルをあなたのバケットにアップロードします。**イベント**データ、**ペイウォール訪問**データ、または**両方**を受信するかどうかを選択できます。また、任意の期間のデータを[手動](#manual-data-export)でエクスポートすることもできます。

インテグレーションを設定するには、Google CloudコンソールでBucketアクセスキーを[生成](#create-google-cloud-storage-credentials)し、それをAdaptyの設定に[追加](#set-up-google-cloud-storage-integration)します。

## アップロードスケジュールと所要時間 \{#upload-schedule-and-duration\}

AdapyはUTC 04:00に24時間ごとにGoogle Cloud Storageへデータをアップロードします。

ファイルには前の暦日（UTC）に作成されたイベントのデータが含まれます。3月8日にアップロードされるファイルには、3月7日の00:00:00〜23:59:59 UTCに作成されたすべてのイベントが含まれます。

キュー内のファイルの総数やご自身がリクエストしたデータ量によっては、処理に数時間かかる場合があります。初回アップロードに過去のデータが含まれる場合、以降の毎日のアップロードより時間がかかります。

## Google Cloud Storage連携のセットアップ \{#set-up-google-cloud-storage-integration\}

**書き込みアクセス権**を持つ有効なGoogle Cloudサービスアカウントキーが必要です。生成方法については、[認証情報の作成](#create-google-cloud-storage-credentials)セクションの手順に従ってください。

:::warning
イベント、ペイウォール訪問、バーチャル通貨トランザクションに対して、それぞれ異なるバケットと認証情報を使用できます。設定を保存すると、Adaptyは有効になっている各エクスポートの認証情報を検証します。いずれかのセットが無効な場合、Adaptyはいずれのタブの設定も保存しません。[トラブルシューティング](#troubleshooting)を参照してください。
:::

[**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage) に移動し、必要なタブ（**Events** または **Paywall visits**）を開きます。連携を有効にします。

**Google Cloudサービスアカウントキー**を含むファイルをアップロードします。対象の**バケット**と**フォルダー**を指定します。変更を保存します。

## Google Cloud Storageの認証情報の作成 \{#create-google-cloud-storage-credentials\}

このガイドでは、Google Cloud Platform コンソールで必要な認証情報を作成する方法を説明します。

Adaptyが指定のバケットに生データレポートをアップロードするには、サービスアカウントのキーと、対応するバケットへの書き込みアクセス権が必要です。サービスアカウントのキーを提供してバケットへの書き込みアクセスを付与することで、AdaptyがプラットフォームからストレージEnvironmentへ生データレポートを安全かつ効率的に転送できるようになります。

:::warning
サービスアカウントのHMACキー認証のみをサポートしています。Google Cloud Storageへの適切なアクセスを有効にするため、サービスアカウントのHMACキーに「Storage Object Viewer」「Storage Legacy Bucket Writer」「Storage Object Creator」のロールが追加されていることを確認してください。
:::

1. まず、Google CloudアカウントのIAMセクション（[IAM](https://console.cloud.google.com/projectselector2/iam-admin/serviceaccounts)）に移動し、関連するプロジェクトを選択するか、新しいプロジェクトを作成します。

  <ZoomImage id="30a81ef-CleanShot_2023-03-17_at_15.22.142x.webp" width="700px" />


1. 次に、「+ CREATE SERVICE ACCOUNT」ボタンをクリックしてAdapty用の新しいサービスアカウントを作成します。

    <ZoomImage id="98f8ebf-CleanShot_2023-03-17_at_15.40.062x.webp" width="700px" />

2. 最初のステップのフィールドに入力します（アクセス権は後の段階で付与されます）。このページの詳細については、[こちら](https://docs.cloud.google.com/iam/docs/service-accounts-create)のドキュメントをご覧ください。

    <ZoomImage id="2190c50-CleanShot_2023-03-17_at_15.48.552x.webp" width="700px" />

3. [プライベートJSONキー](https://docs.cloud.google.com/iam/docs/keys-create-delete)を作成してダウンロードするには、KEYSセクションに移動し、「ADD KEY」ボタンをクリックします。

    <ZoomImage id="8a45468-CleanShot_2023-03-17_at_15.58.092x.webp" width="700px" />

4. DETAILSセクションで、作成したサービスアカウントに紐付くEmail値を見つけてコピーします。この情報は、アカウントを認証してバケットへの書き込みを許可するための後続手順で必要になります。

    <ZoomImage id="6ccd0f0-CleanShot_2023-03-17_at_16.03.162x.webp" width="700px" />
    

5. 次に、Google Cloud Storageの[Buckets](https://console.cloud.google.com/storage/browser)ページに移動し、既存のバケットを選択するか、AdapyのイベントまたはVisitsデータレポートを保存するための新しいバケットを作成します。次にPERMISSIONSセクションに移動し、[GRANT ACCESS](https://docs.cloud.google.com/identity/docs/how-to?hl=en)オプションを選択します。

    <ZoomImage id="3cdd937-CleanShot_2023-03-17_at_16.14.232x.webp" width="700px" />

6. PERMISSIONSセクションで、手順5で取得したサービスアカウントのEmailを入力し、Storage Object Creatorロールを選択します。最後にSAVEをクリックして変更を適用します。


    <ZoomImage id="62801f4-CleanShot_2023-03-17_at_16.17.312x.webp" width="700px" />

    バケット名は後で使用するので控えておいてください。

## 手動データエクスポート \{#manual-data-export\}

Google Cloud Storageへの自動イベントデータエクスポートに加えて、Adaptyでは手動ファイルエクスポート機能も提供しています。この機能を使用すると、イベントデータの特定の時間範囲を選択して、GCSバケットに手動でエクスポートできます。エクスポートするデータとタイミングをより細かく制御できます。

指定した日付範囲は、日付A 00:00:00 UTCから日付B 23:59:59 UTCまでに作成されたイベントのエクスポートに使用されます。

<ZoomImage id="e347308-CleanShot_2023-03-17_at_17.39.452x.webp" width="700px" />

## バーチャルカレンシーのトランザクション \{#virtual-currency-transactions\}

バーチャルカレンシーエクスポートは、[バーチャルカレンシー](virtual-currencies)の残高が変化するたびに、その変更内容を Google Cloud Storage バケットに送信します。クレジット、使用、有効期限切れ、払い戻しの全履歴を自社のデータウェアハウスに取り込む際にご利用ください。

このエクスポートは、イベントエクスポートやペイウォール訪問エクスポートとは独立しています。専用のスイッチと認証情報、および専用のバケットとフォルダの設定があります。

### エクスポートを有効にする \{#turn-on-the-export\}

1. [**Integrations** -> **Google Cloud Storage**](https://app.adapty.io/integrations/google-cloud-storage) に移動し、**Virtual currency** タブを開きます。
2. **Export virtual currency transactions to Google Cloud Storage** をオンにします。
3. [Google Cloud サービスアカウントキー](#create-google-cloud-storage-credentials)のファイルをアップロードし、バケットとフォルダーを指定します。フィールドの内容は **Paywall visits** タブと同じです。

過去の日付の仮想通貨トランザクションをエクスポートするには、[手動データエクスポート](#manual-data-export)を使用してください。

### ファイルとスケジュール

Adapty は毎日、前日（UTC）の仮想通貨トランザクションを含む 1 つのファイルをアップロードします。トランザクションは、UTC での `created_at` 時刻に基づいて該当日に分類されます。

ファイル名は `<app_id>_virtual_currency_<date>.csv` という形式で、`<date>` はトランザクションが発生した日の翌日を `YYYY-MM-DD` 形式で表したものです。たとえば、`<app_id>_virtual_currency_2026-03-08.csv` というファイルには2026年3月7日のトランザクションが含まれています。エクスポートごとに独自のファイル名が付きます。フォルダ全体を読み込むテーブルやローダーが1種類のファイルのみを取得できるよう、エクスポートはそれぞれ専用のフォルダに保存してください。複数のエクスポートが同じフォルダを共有する場合は、`<app_id>_virtual_currency_*.csv` というファイル名パターンでこのエクスポートのファイルを選択してください。

このファイルは、ヘッダー行を含む UTF-8 エンコードの `.csv` ファイルです。トランザクションがない日は、ヘッダー行のみが含まれます。

各行は、1つの通貨の残高変化を表します。ゴールドをジェムに交換するなど、2つの通貨を変化させるトランザクションは、同じ `vc_transaction_id` を持つ2行として記録されます。サンドボックストランザクションも `is_sandbox` が `true` に設定された状態でファイルに含まれます。

設定を保存すると、Adapty はオンになっている各エクスポートの認証情報を検証します。バーチャル通貨の認証情報が無効な場合、Adapty は設定を保存しません。**Save** ボタンはすべてのタブの設定を保存するため、他のタブへの変更も保存されません。

バーチャル通貨エクスポートは独自の認証情報を使用します。日次アップロードが失敗しても、アプリのイベントおよびペイウォール訪問のアップロードは引き続き実行されます。

### カラム \{#columns\}

ファイルには以下のカラムが、この順序で含まれています。Adapty が新しいカラムを追加する場合は、常にファイルの末尾に追加されます。

| カラム | 説明 |
| :----- | :---------- |
| **vc_transaction_id** | バーチャル通貨トランザクションの Adapty ID。同一トランザクションのすべての行は同じ ID を持ちます。これは API リクエストの `Idempotency-Key` ではありません。 |
| **created_at** | トランザクションの時刻（UTC）。形式は `YYYY-MM-DD HH:MM:SS.ffffff+00:00`（例：`2026-03-07 14:05:09.000000+00:00`）。 |
| **profile_id** | Adapty プロファイル ID。 |
| **customer_user_id** | エクスポート時点のプロファイルのカスタマーユーザー ID。プロファイルにカスタマーユーザー ID がない場合、またはプロファイルが存在しない場合は空欄。 |
| **operation** | トランザクションの[オペレーション](virtual-currencies#operation)：`top_up`、`refund`、`spend`、`spend_reversal`、`reward`、`reward_reversal`、`exchange`、`expiry`、`migration`、または `adjustment`。`operation` なしで送信されたサーバーサイド API トランザクションの場合は空欄。 |
| **transaction_type** | Adapty がトランザクションを記録した方法。例：`store_purchase`、`subscription_renewal`、`trial_start`、`api_transaction`。`subscription_renewal` はサブスクリプションの各支払い期間（最初の期間を含む）に使用されます。 |
| **currency_code** | バーチャル通貨のコード。 |
| **amount** | 残高の変動量（整数）。クレジットの場合は正の値、デビットの場合は負の値。 |
| **balance_after** | この変動後のプロファイルにおけるこの通貨の残高（整数）。0 未満にはなりません。 |
| **store** | トランザクションのストア：`app_store`、`play_store`、`stripe`、`paddle`、`adapty`、またはカスタムストアの名前。ストアが紐付いていない場合は空欄。 |
| **store_transaction_id** | 購入のストアトランザクション ID。イベントテーブルの **transaction_id** と同一の値です。ストア購入に紐付いていない場合は空欄。 |
| **store_original_transaction_id** | 購入のオリジナルストアトランザクション ID。サブスクリプションのすべての更新で同じ値になります。ストア購入、その払い戻し、および有効期限切れの行に入力されます。 |
| **product_id** | 購入のストアプロダクト ID。ストアトランザクションがない行、または Adapty に購入の記録がない場合は空欄。 |
| **expires_at** | クレジットされた金額の有効期限（UTC）。形式は `YYYY-MM-DD HH:MM:SS.ffffff+00:00`（例：`2026-04-07 14:05:09.000000+00:00`）。有効期限のあるクレジット行のみに入力されます。 |
| **feature** | トランザクションの[`feature`](virtual-currencies#feature)。 |
| **reference_id** | トランザクションの `reference_id`。 |
| **customer_placement_id** | トランザクションの `customer_placement_id`。 |
| **is_sandbox** | サンドボックストランザクションの場合は `true`、本番トランザクションの場合は `false`。 |
| **metadata** | トランザクションの `metadata`（1 つのセル内に 1 つの JSON 値として格納）。トランザクションにメタデータがない場合は空欄。 |

### イベントテーブルとの結合 \{#join-with-the-events-table\}

仮想通貨ファイルには価格情報が含まれていません。通貨をクレジットした購入の価格を取得するには、クレジット行をイベントテーブルと結合します：

- **store_transaction_id** をイベントテーブルの **transaction_id** と照合します。
- **store** も照合しますが、`app_store`、`play_store`、`stripe`、`paddle` の場合のみです。`adapty` およびカスタムストアの場合、イベントテーブルの **store** は空になります。

以下のクエリ例は、仮想通貨ファイルを `vc_transactions` テーブルに、イベントファイルを `events` テーブルにロード済みであることを前提としています：

```sql title="SQL"
SELECT
  vc.vc_transaction_id,
  vc.created_at,
  vc.profile_id,
  vc.currency_code,
  vc.amount,
  e.event_type,
  e.product_id,
  e.revenue_usd,
  e.currency,
  e.revenue_local
FROM vc_transactions AS vc
LEFT JOIN events AS e
  ON e.transaction_id = vc.store_transaction_id
  AND (
    e.store = vc.store
    OR vc.store NOT IN ('app_store', 'play_store', 'stripe', 'paddle')
  )
  AND e.event_type IN (
    'subscription_initial_purchase',
    'subscription_started',
    'subscription_renewed',
    'trial_started',
    'trial_converted',
    'non_subscription_purchase'
  )
WHERE vc.amount > 0
  AND COALESCE(vc.store_transaction_id, '') <> '';
```

このクエリにはデフォルトのイベント名が記載されています。サブスクリプションの開始は、2025年9月中旬以降に作成されたインテグレーションでは `subscription_initial_purchase`、それ以前のインテグレーションでは `subscription_started` となります。イベントのエクスポート設定でイベント名を変更した場合は、クエリ内でその名前を使用してください。

イベントのエクスポートがオフの場合、エクスポート設定で購入のイベントタイプが除外または名前変更されている場合、または **Exclude historical events** によってイベントが除外されている場合、クレジット行に一致するイベントが存在しません。

1回の購入で複数の通貨が付与される場合があります。通貨ごとにクレジット行が作成され、それらの行はすべて同じイベントに紐付きます。収益を合計するには、各 **store_transaction_id** を1回だけカウントしてください。

### 制限事項 \{#limitations\}

- **価格・返金額なし**：バーチャル通貨ファイルには購入価格も返金額も含まれません。価格を取得するには、[クレジット行をイベントテーブルと結合してください](#join-with-the-events-table)。
- **2つのファイルのクレジットを合算しないでください**：[events](#events) ファイルの **virtual_currency_credits** 列と、バーチャル通貨ファイルのクレジット行は、同じ購入クレジットを示しています。クレジットを集計する場合は、どちらか一方を使用し、両方は使用しないでください。合計値が異なる場合があります。イベントファイルには購入のクレジットのみが含まれ、かつエクスポート設定の対象となるイベントのみが対象ですが、バーチャル通貨ファイルにはAPI経由の付与やダッシュボードでの手動調整を含む、すべての残高変動が記録されます。
- **支出とクレジットの紐付けなし**：ファイルには、ある支出がどのクレジット（購入済みか付与済みかなど）を使用したかが示されていません。
- **返金行には回収されたクレジットのみ表示**：返金行には、Adaptyが残高から回収したクレジットが表示されます。その **amount** は、購入時に付与されたクレジットより少ない場合があります（例：ユーザーが一部を使用した場合）。残高がゼロだった場合、返金行はファイルに存在しません。
- **サブスクリプションアップグレードによる返金行なし**：サブスクリプションのアップグレードに伴う返金ではクレジットの回収が行われないため、ファイルに返金行は存在しません。

## トラブルシューティング \{#troubleshooting\}

設定を保存すると、Adapty は有効になっている各エクスポートのキーを検証します。いずれかのキーが無効な場合、Adapty はいずれのタブの設定も保存せず、エラーを表示します。

各エクスポートは独自のキーを使用してファイルをアップロードするため、期限切れのキーはそのエクスポートのアップロードのみを停止します。アップロードを継続するには、キーが期限切れになる前に更新してください。複数のタブで同じキーを使用している場合は、それぞれのタブ（**Events**、**Paywall visits**、**Virtual currency**）で個別に更新してください。
