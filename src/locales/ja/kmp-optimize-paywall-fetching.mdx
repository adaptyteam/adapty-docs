Kotlin Multiplatformで確実にフローやペイウォールを取得するには、次の3つが必要です：高速なレンダリング、オーディエンスに合ったバリアントの返却、そしてネットワークが遅い場合のグレースフルなフォールバック。以下のルールでは、これを実現するためのタイミング、キャッシュ、フォールバックパターンを説明します。

:::tip
このルールは、`Adapty.activate()` と `Adapty.identify()` がすでに完了していることを前提としています。詳細は [Kotlin Multiplatform SDK の呼び出し順序](kmp-sdk-call-order) を参照してください。
:::

## ルールと注意点 \{#rules-and-pitfalls\}

| すること | しないこと | 理由 |
|---|---|---|
| 表示しようとしているプレースメントのみを取得する。                                                                                                                | 起動時にすべてのプレースメントを並列でプリフェッチする。        | 一括プリフェッチはメインスレッドをブロックし、バースト中に黒い画面が表示される。                                                  |
| アトリビューションが解決される機会を得た後（例: `activate` から 1〜2 秒後、または `setOnProfileUpdatedListener` が発火した後）に `getFlow` を取得する。 | アプリ起動時に `getFlow` を呼び出す。                       | アトリビューションがまだ届いていない。フローはデフォルトのオーディエンスに対して解決され、セグメントや ASA のパーソナライズが静かにバイパスされる。 |
| デフォルトの `loadTimeout`（5 秒）をそのまま使うか別の値を設定し、すべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。 | `getFlow` に非常に大きな `loadTimeout` を渡して実質的に発火しないようにする。 | タイムアウトが発火しない場合、接続が悪いユーザーはネットワークが解決するまで空白の画面を見続けるか、アプリを閉じてしまう。 |

カスタムペイウォールとプロダクトの取得方法については、[カスタムペイウォールとプロダクトの取得](fetch-paywalls-and-products-kmp)で `fetchPolicy` および `loadTimeout` パラメータのリファレンスを、[プレースメント](placements)で適切なプレースメントの選び方をご確認ください。

## アプリバンドルから最初の画面のメディアを表示する \{#show-first-screen-media-from-the-app-bundle\}

フローは画像や動画を Adapty からダウンロードします。最初の画面のメディアを即座に表示するには、アプリバンドルから提供してください。これは、既存のネイティブオンボーディングのビジュアルなど、すでにアプリに同梱しているメディアを再利用するのに最適な方法です。

1. フロービルダーまたはペイウォールビルダーで、画像または動画に[カスタムメディアID](custom-media#custom-media-id)を設定します。そこでアップロードしたファイルはフォールバックとして使用されます。
2. アプリのリソースに`commonMain/composeResources/files/`というパスでファイルを追加します。
3. フロービューを作成する際、`customAssets`でそのIDにバンドルされたファイルを渡します。

```kotlin showLineNumbers
// "welcome_video" is the custom media ID set in the Flow & Paywall Builder
val bundledAssets: Map<String, AdaptyCustomAsset> = mapOf(
    "welcome_video" to AdaptyCustomAsset.localVideoResource(
        path = Res.getUri("files/videos/welcome.mp4")
    ),
)

AdaptyUI.createFlowView(
    flow = flow,
    customAssets = bundledAssets,
).onSuccess { view ->
    view.present()
}.onError { error ->
    // handle the error
}
```

バンドルされたファイルはアプリのダウンロードサイズに影響するため、最初に表示されるメディアのみをバンドルしてください。

バンドルされた画像は待ち時間なしで表示されますが、SDKはアップロードされた画像を引き続きバックグラウンドでダウンロードします。

バンドルされていないメディアもすぐに表示されます。フローのレイアウトには各画像の低解像度のコピー（動画のスチルフレームを含む）が含まれており、フルファイルが読み込まれるまでその低解像度版が表示されます。

`customAssets` の完全なリファレンスについては、[アセットのカスタマイズ](kmp-get-pb-paywalls#customize-assets) を参照してください。

## 接続性の低い環境への対応 \{#tune-for-poor-connectivity\}

接続状況が常に悪い市場（農村部、交通機関内、ルーティングの問題が生じている地域など）向けの対応：

- 最初のフェッチを除き、すべてのフェッチで `fetchPolicy = AdaptyPaywallFetchPolicy.ReturnCacheDataElseLoad` を設定する。
- Adapty ダッシュボードのすべてのプレースメントに[フォールバックペイウォール](fallback-paywalls)を設定する。
- 速度とターゲティングのバランスを考慮して `loadTimeout` を調整する。タイムアウトを短くすると、ユーザーはフォールバックをより早く目にする。長くすると、ターゲット指定されたフローの読み込み時間が増える。
- [フローを軽量に保つ](flow-size)ことで、レイアウトのダウンロードを高速化する。
- `Adapty.getProfile()` の完了をフロー表示の条件にしない。`getFlow` を独立して呼び出し、プロファイルの取得が遅くても UI がブロックされないようにする。
