To show a spinner and then a checkmark in the button that users tap, add both buttons as custom elements. Users see neither a spinner nor a checkmark in a builder button with a [custom action](onboarding-actions#what-custom-actions-cant-do). A custom action is one-way: your app code can't return the result of the spend to the flow. The text and look of the buttons come from your app code. To change the text or look, [release an app update](flow-custom-elements#what-changes-require-an-app-release).

1. [Add a custom element](flow-custom-elements#add-and-configure) for the energy refill, and enter its **Type** and **ID**:
   - **Type**: `spend_button`.
   - **ID**: `energy_refill`.
2. Add a second custom element for unlimited energy, with the same Type and the ID `unlimited_energy`.

   The code in [step 2](#connect-the-buttons-to-your-backend) matches one button view to both custom elements by their Type. The code reads the option of each button from its ID.

   <ZoomImage id="vc-top-up-spend-button.webp" width="700px" alt="Custom element settings in the Flow & Paywall Builder, with spend_button in the Type field and unlimited_energy in the ID field" />

3. Lower the **Fixed** height of each custom element from 200 to the height that the button needs.
4. Inside each custom element, add a text element, and enter the words for its option:
   - Energy refill: "Update the game to refill energy."
   - Unlimited energy: "Update the game to get unlimited energy."

   In app versions without the button view, users see this text as the [fallback](flow-custom-elements#set-fallback-content), with no button to tap.
