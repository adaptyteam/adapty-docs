The flow runs the actions of one outcome section. Your app's answer and its status decide which one:

| Your app's answer | Section the flow runs |
|:------------------|:----------------------|
| Granted, with or without a status | **When allowed** |
| Not granted, with the status `denied`, `restricted`, or `permanently_denied` | **When denied** |
| Any other answer, for example not granted without a status, or with the status `unsupported` | **After response** |

When the section that matches the answer has no actions, the flow runs **After response** instead. If **After response** has no actions either, the flow stays on the screen.

Pass one of these statuses with every answer:

- **With a granted answer**: `granted`. Use `limited` if the user allowed part of the access, such as a selection of photos. Use `provisional` for provisional notifications on iOS.
- **With a refusal**: `denied`. Use `restricted` if a device policy, such as parental controls, blocks the permission. Use `permanently_denied` if the system no longer shows the dialog to the user.
- **For a permission your app doesn't request**: `unsupported`, with a refusal and without a dialog.

Without a status, a refusal runs **After response**, not **When denied**. A handler written before the **When denied** section existed answers without a status, so its refusals keep running **After response**. To run **When denied**, pass the status.
