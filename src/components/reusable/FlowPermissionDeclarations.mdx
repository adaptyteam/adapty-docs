| Permission in the builder | Value | iOS: `Info.plist` key | Android: manifest permission |
|:--------------------------|:------|:----------------------|:-----------------------------|
| Push notifications | `push` | None. To receive push notifications, the app needs the Push Notifications capability. | `POST_NOTIFICATIONS`, on Android 13 and later |
| App tracking (ATT) | `tracking` | `NSUserTrackingUsageDescription` | — |
| Location while using the app | `location_when_use` | `NSLocationWhenInUseUsageDescription` | `ACCESS_FINE_LOCATION` or `ACCESS_COARSE_LOCATION` |
| Location always | `location_always` | `NSLocationAlwaysAndWhenInUseUsageDescription` and `NSLocationWhenInUseUsageDescription` | `ACCESS_BACKGROUND_LOCATION`, after `ACCESS_FINE_LOCATION` or `ACCESS_COARSE_LOCATION` |
| Precise location | `location_full_accuracy` | `NSLocationTemporaryUsageDescriptionDictionary` | `ACCESS_FINE_LOCATION` |
| Camera | `camera` | `NSCameraUsageDescription` | `CAMERA` |
| Microphone | `microphone` | `NSMicrophoneUsageDescription` | `RECORD_AUDIO` |
| Photos | `photos` | `NSPhotoLibraryUsageDescription` | `READ_MEDIA_IMAGES` |
| Media library | `media_library` | `NSAppleMusicUsageDescription` | `READ_MEDIA_AUDIO` |
| Apple Music | `music` | `NSAppleMusicUsageDescription` | — |
| Speech recognition | `speech` | `NSSpeechRecognitionUsageDescription` | `RECORD_AUDIO` |
| Contacts | `contacts` | `NSContactsUsageDescription` | `READ_CONTACTS` |
| Calendar | `calendar` | `NSCalendarsFullAccessUsageDescription`, and `NSCalendarsUsageDescription` before iOS 17 | `READ_CALENDAR` |
| Reminders | `reminders` | `NSRemindersFullAccessUsageDescription`, and `NSRemindersUsageDescription` before iOS 17 | — |
| Health data | `health` | `NSHealthShareUsageDescription`, and `NSHealthUpdateUsageDescription` to write health data | — |
| Motion & Fitness | `motion` | `NSMotionUsageDescription` | `ACTIVITY_RECOGNITION` |
| Bluetooth | `bluetooth` | `NSBluetoothAlwaysUsageDescription` | `BLUETOOTH_CONNECT` |
| Local network | `local_network` | `NSLocalNetworkUsageDescription` | — |
| HomeKit | `homekit` | `NSHomeKitUsageDescription` | — |
| Focus status | `focus_status` | `NSFocusStatusUsageDescription` | — |
| Siri | `siri` | `NSSiriUsageDescription` | — |

Health data, HomeKit, and Siri also need their capability in Xcode.

Some Android permissions exist only from a given Android version: `ACTIVITY_RECOGNITION` from Android 10, `BLUETOOTH_CONNECT` from Android 12, `READ_MEDIA_IMAGES` and `READ_MEDIA_AUDIO` from Android 13. On earlier versions, Android shows no dialog for them, so answer `unsupported` there, or request the older permission that your app uses instead. On Android 12 and later, request `ACCESS_FINE_LOCATION` together with `ACCESS_COARSE_LOCATION`: Android ignores a request for precise location alone.

A dash means that the action has no Android permission for the value: on Android, answer these requests with the status `unsupported`. For `health`, Health Connect permissions are outside the **Request permission** action.

For `health`, iOS doesn't tell your app whether the user allowed it to read health data, so your app decides which answer to report.
