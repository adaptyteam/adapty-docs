:::important
Fields, date and time pickers, and selectable groups never send their default value through this callback. If a user accepts the option marked **Set as default** and moves on, no event fires. Don't read the missing event as "no answer" — the user simply left the default value in place. A [Number picker](builder-number-picker) sends its default number to your app code when the user taps a button that opens another screen.
:::

**The following elements trigger this event:**

- Text, email, number, and phone fields
- Date, time, and date-time pickers
- Number pickers
- Single-choice and multi-choice selectable groups, and toggles

**The following don't:**

- Password fields, product selections, and tab switches
- Inputs inside a Header element, which is shared across screens
- Selectable groups with duplicate or missing option Element IDs, or with a Group ID reused on another screen. Such a group sends nothing at all, rather than part of the answer.

**The event is triggered when:**

- A field loses focus. A cleared field reports an empty string; a field the user never edited reports nothing. A placeholder is not a value. If the user returns to the field, edits it, and leaves it again, a second event follows.
- The user closes a date or time picker after picking a new value. Closing it unchanged reports nothing.
- On a screen with a Number picker, the user taps a button that runs a **Navigate to Screen**, **Navigate Next**, or **Navigate back** [action](onboarding-actions). The Number picker also reports its value when the user taps an option or a toggle on the same screen. If the user never turned the wheel, the value is the default number. A Number picker reports its value even when it's hidden, such as in a tab that the user didn't open. No second event follows until the value changes.
- The user taps an option or a toggle. A multi-choice event lists every selected option, so deselecting the last one sends two empty arrays.

**The event is not triggered when:**

- The user types. There is no keystroke stream, only the value the field holds when focus leaves it.
- The user submits or closes the flow. A value still being edited at that moment can be lost. A button that closes the flow, starts a purchase, or runs a custom action doesn't report the value of a Number picker. The [delivery limitations](#delivery-and-limitations) section covers how to design the last screen around both cases.
- A value is set without user interaction. An option marked **Set as default** is pre-selected when the screen opens, and a **Set Variable** action can select an option or fill an input from another interaction. Neither sends an event; a pre-filled input other than a Number picker is reported only once the user edits it.
