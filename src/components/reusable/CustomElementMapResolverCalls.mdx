The SDK calls the resolver when the screen opens, and again each time it redraws the custom element while the screen is open. Location access determines what the resolver returns on each call:

- **Not answered yet**: The map view, so that the view can request access.
- **Allowed**: The map view, which shows your places near the user.
- **Denied before the screen opened**: No view, so users see the fallback instead of the message about Settings.
- **Denied on the screen**: The map view, because the view sets `isMapOnScreen` while it's on the screen. If the resolver returned no view here, the SDK would replace the message about Settings with the fallback at the next call.
