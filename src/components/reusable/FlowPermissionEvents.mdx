The flow reports each permission request to your app's flow analytics callback in these events:

- **`flow_permission_requested`**: The flow sent the permission request to your app. Its parameters:
  - `instanceId`: The ID of the screen that sent the request.
  - `permission`: The permission value.
  - `with_outcome`: `true` if **When allowed**, **When denied**, or **After response** triggers an action other than **Do nothing**.
- **`flow_permission_answered`**: Your app passed the result to the flow. Its parameters:
  - `instanceId`: The ID of the screen that sent the request.
  - `permission`: The permission value.
  - `result`: `true` if your app passed a granted result.
  - `detail_result`: The string that your app passed with the result, if any.
  - `outcome`: One value for the result and its string, from `result` and `detail_result`. See the table after this list.
- **`flow_permission_unanswered`**: Your app didn't pass a result within 60 seconds after the permission request. The flow sends this event once per request. It doesn't send the event if the flow was closed before then. If your app passes the result later, the flow still sends `flow_permission_answered`. Its parameters:
  - `instanceId`: The ID of the screen that sent the request. With `left_screen`, it is still that screen, not the screen the user is on.
  - `permission`: The permission value.
  - `with_outcome`: `true` if **When allowed**, **When denied**, or **After response** triggers an action other than **Do nothing**.
  - `outcome`: `on_screen` if the user is still on the screen that sent the request, or `left_screen` if the user left that screen.

The `outcome` property of `flow_permission_answered` reports the result that your app passed, not the actions that the flow ran:

| Result | `outcome` |
|:------------------|:----------|
| Granted, with `limited` or `provisional` | That string |
| Granted, with any other string or without a string | `granted` |
| Not granted, with `denied`, `restricted`, `permanently_denied`, or `unsupported` | That string |
| Not granted, with any other string | `other` |
| Not granted, without a string. Some Adapty SDKs pass this result when your app has no handler | `no_status` |

If `outcome` is `no_status` where you expected `denied`, make sure that your app passes `denied` with a not-granted result. If `outcome` is `other`, read the `detail_result` parameter: it contains a typo or another string, such as an error message. If you see `flow_permission_unanswered`, make sure that your app sets up the handler for the flow, and that the handler passes a result for every permission request, including after an exception or a timeout.
