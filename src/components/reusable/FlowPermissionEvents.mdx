The flow reports each permission request to your app's flow analytics callback in these events:

- **`flow_permission_requested`**: The flow sent the request to your app. Its parameters:
  - `instanceId`: The ID of the screen that sent the request.
  - `permission`: The permission value.
  - `with_outcome`: Whether the action has actions in its outcome sections.
- **`flow_permission_answered`**: Your app answered. Its parameters:
  - `instanceId`: The ID of the screen that sent the request.
  - `permission`: The permission value.
  - `result`: Your app's answer, `true` for granted.
  - `detail_result`: The status your app passed, if any.
  - `outcome`: How the user answered, from `result` and `detail_result`. See the table after this list.
- **`flow_permission_unanswered`**: Your app didn't answer within 60 seconds after the request. The flow sends this event once per request. It doesn't send the event if the flow was closed before then. If your app answers later, the flow still sends `flow_permission_answered`. Its parameters:
  - `instanceId`: The ID of the screen that sent the request. With `left_screen`, it is still that screen, not the screen the user is on.
  - `permission`: The permission value.
  - `with_outcome`: Whether the action has actions in its outcome sections.
  - `outcome`: `on_screen` if the user is still on the screen that sent the request, or `left_screen` if the user left that screen.

The `outcome` of `flow_permission_answered` reports the user's answer, not the outcome section that ran:

| Your app's answer | `outcome` |
|:------------------|:----------|
| Granted, with the status `limited` or `provisional` | The status |
| Granted, with any other status or without a status | `granted` |
| Not granted, with the status `denied`, `restricted`, `permanently_denied`, or `unsupported` | The status |
| Not granted, with any other status | `other` |
| Not granted, without a status. For example, the default answer of the Android, React Native, and Capacitor SDKs when your app has no handler | `no_status` |

The flow compares the status with the strings `limited`, `provisional`, `denied`, `restricted`, `permanently_denied`, and `unsupported` exactly, in lowercase. A refusal with any other string, such as `Denied` or `user declined`, has the `outcome` `other`, and the flow runs **After response** for it, not **When denied**.

If `outcome` is `no_status` where you expected `denied`, make sure that your app passes a status, such as `denied`, with the refusal. If `outcome` is `other`, look for a typo in the status string. If you see `flow_permission_unanswered`, make sure that your app registers the handler and that the handler answers every request.
